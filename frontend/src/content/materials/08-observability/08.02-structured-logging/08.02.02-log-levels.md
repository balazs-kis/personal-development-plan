# Lesson 2: Log Levels and When to Use Them

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand the standard log levels (TRACE, DEBUG, INFO, WARN, ERROR, FATAL)
- Know when to use each log level appropriately
- Configure log levels for different environments
- Avoid common logging mistakes
- Balance verbosity with usefulness

---

## Introduction

Log levels are critical for managing log volume and signal-to-noise ratio. Using the wrong level creates either too much noise (everything at INFO) or missing information (only ERROR). Production systems need the right balance: enough information to debug issues, but not so much that logs become overwhelming. This lesson teaches you to use log levels effectively.

## Key Concepts Summary

### Standard Log Levels

**Hierarchy (least to most severe):**
```
TRACE   → Very detailed debugging
DEBUG   → Diagnostic information
INFO    → General information
WARN    → Warning messages
ERROR   → Error events
FATAL   → Critical failures
```

**Typical filtering:**
```
Development:  DEBUG and above
Staging:      INFO and above
Production:   WARN and above (or INFO)
Incident:     DEBUG temporarily
```

### TRACE Level

**Purpose:**
```
Extremely verbose debugging
Step-by-step execution flow
Variable values at each step
Performance profiling
```

**When to use:**
```
✓ Tracing execution flow
✓ Deep debugging
✓ Performance profiling
✓ Temporary investigation
```

**Example:**
```csharp
_logger.LogTrace("Entering method ProcessPayment");
_logger.LogTrace("Validating card number: {MaskedCard}", MaskCard(cardNumber));
_logger.LogTrace("Calling payment gateway");
_logger.LogTrace("Gateway response received: {ResponseTime}ms", responseTime);
_logger.LogTrace("Exiting method ProcessPayment");
```

**Production:**
```
❌ Never enable in production
Generates massive log volume
Impacts performance
Only for local debugging
```

### DEBUG Level

**Purpose:**
```
Detailed diagnostic information
Helpful for troubleshooting
Shows internal state
Not needed in normal operation
```

**When to use:**
```
✓ Detailed variable values
✓ Complex logic flow
✓ Integration points
✓ Temporary debugging
✓ Development environment
```

**Example:**
```csharp
_logger.LogDebug(
    "Processing order: {OrderId}, Items: {ItemCount}, Total: {Total}",
    orderId,
    items.Count,
    total);

_logger.LogDebug(
    "Cache lookup for key {CacheKey}: {Found}",
    cacheKey,
    found ? "HIT" : "MISS");

_logger.LogDebug(
    "Database query executed: {Query}, Parameters: {@Parameters}",
    query,
    parameters);
```

**Production:**
```
⚠️ Generally disabled in production
Enable temporarily for troubleshooting
Can generate high volume
Useful for investigating issues
```

### INFO Level

**Purpose:**
```
General operational information
Normal system behavior
Significant business events
Confirmations
```

**When to use:**
```
✓ Application startup/shutdown
✓ Configuration loaded
✓ Service state changes
✓ Important business events
✓ Successful operations
✓ External API calls
```

**Example:**
```csharp
_logger.LogInformation(
    "Application started: version {Version}, environment {Environment}",
    appVersion,
    environment);

_logger.LogInformation(
    "User {UserId} logged in successfully",
    userId);

_logger.LogInformation(
    "Order {OrderId} placed: {Amount} items, total ${Total}",
    orderId,
    itemCount,
    totalAmount);

_logger.LogInformation(
    "Configuration reloaded from {Source}",
    configSource);
```

**Production:**
```
✓ Standard production level
Provides operational visibility
Should be meaningful
Avoid "chatty" logs
```

**What NOT to log at INFO:**
```
✗ Every request (too verbose)
✗ "I'm alive" messages
✗ Routine operations
✗ Debugging details
```

### WARN Level

**Purpose:**
```
Something unexpected happened
System continues functioning
Should be investigated
Potential problem indicators
```

**When to use:**
```
✓ Deprecated API usage
✓ Retry attempts
✓ Performance degradation
✓ Configuration issues
✓ Non-critical errors
✓ Recoverable failures
```

**Example:**
```csharp
_logger.LogWarning(
    "API call to {Endpoint} took {Duration}ms, exceeding threshold {Threshold}ms",
    endpoint,
    duration,
    threshold);

_logger.LogWarning(
    "Retrying failed operation: attempt {Attempt} of {MaxAttempts}",
    attemptNumber,
    maxAttempts);

_logger.LogWarning(
    "Deprecated method {Method} called by {Caller}",
    methodName,
    callerInfo);

_logger.LogWarning(
    "Cache unavailable, using fallback: {Reason}",
    reason);
```

**Production:**
```
✓ Always enabled
Indicates potential issues
Requires investigation
Should trigger alerts if frequent
```

### ERROR Level

**Purpose:**
```
Serious problem occurred
Function could not complete
Requires attention
System still functioning
```

**When to use:**
```
✓ Unhandled exceptions
✓ Failed operations
✓ Data validation failures
✓ External service failures
✓ Database errors
✓ Security violations
```

**Example:**
```csharp
_logger.LogError(
    ex,
    "Payment processing failed for order {OrderId}: {Error}",
    orderId,
    ex.Message);

_logger.LogError(
    "Database connection failed: {ConnectionString}, retry in {RetryDelay}s",
    MaskConnectionString(connectionString),
    retryDelay);

_logger.LogError(
    "Authentication failed for user {UserId}: {Reason}",
    userId,
    reason);

_logger.LogError(
    ex,
    "External API call failed: {Endpoint}, Status: {StatusCode}",
    endpoint,
    statusCode);
```

**Production:**
```
✓ Always enabled
Should trigger alerts
Requires immediate investigation
Include full exception details
```

### FATAL/CRITICAL Level

**Purpose:**
```
Unrecoverable error
System cannot continue
Application crash
Immediate action required
```

**When to use:**
```
✓ Application startup failure
✓ Critical resource unavailable
✓ Data corruption
✓ Security breach
✓ System instability
```

**Example:**
```csharp
_logger.LogCritical(
    "Application startup failed: unable to connect to database after {Attempts} attempts",
    maxAttempts);

_logger.LogCritical(
    ex,
    "Unhandled exception in request pipeline, application shutting down");

_logger.LogCritical(
    "Critical configuration missing: {ConfigKey}, cannot start service",
    configKey);

_logger.LogCritical(
    "Security violation detected: {Details}, system entering safe mode",
    details);
```

**Production:**
```
✓ Always enabled
Should page on-call engineer
Requires immediate response
Rare occurrences
```

### Environment-Specific Configuration

**Development:**
```csharp
{
  "Logging": {
    "LogLevel": {
      "Default": "Debug",
      "Microsoft": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}

Benefits:
- See detailed information
- Debug complex issues
- Understand flow
- Performance acceptable
```

**Staging:**
```csharp
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft": "Warning"
    }
  }
}

Benefits:
- Production-like
- Important events visible
- Reduced noise
- Performance tested
```

**Production:**
```csharp
{
  "Logging": {
    "LogLevel": {
      "Default": "Warning",
      "Application": "Information",
      "Microsoft": "Error"
    }
  }
}

Benefits:
- Minimal noise
- Important events captured
- Errors visible
- Good performance
```

### Common Mistakes

**Mistake 1: Everything at INFO**
```csharp
// Bad
_logger.LogInformation("Entering method");  // Too verbose
_logger.LogInformation("Variable x = {X}", x);  // Debug info
_logger.LogInformation("Loop iteration {I}", i);  // Noise

// Good
_logger.LogTrace("Entering method");  // Trace level
_logger.LogDebug("Variable x = {X}", x);  // Debug level
// Don't log every iteration
```

**Mistake 2: Everything at ERROR**
```csharp
// Bad
_logger.LogError("User not found");  // Not an error
_logger.LogError("Cache miss");  // Normal operation
_logger.LogError("Validation failed");  // Expected behavior

// Good
_logger.LogWarning("User not found: {UserId}", userId);
_logger.LogDebug("Cache miss for key {Key}", key);
_logger.LogInformation("Validation failed: {Errors}", errors);
```

**Mistake 3: Wrong level for event**
```csharp
// Bad
_logger.LogDebug("Payment failed");  // Critical error!
_logger.LogError("User logged in");  // Normal operation
_logger.LogInformation(ex, "Database down");  // Critical!

// Good
_logger.LogError(ex, "Payment failed for order {OrderId}", orderId);
_logger.LogInformation("User {UserId} logged in", userId);
_logger.LogCritical(ex, "Database connection lost");
```

**Mistake 4: Logging exceptions at multiple levels**
```csharp
// Bad
try {
    await ProcessOrderAsync(order);
} catch (Exception ex) {
    _logger.LogError(ex, "Error processing");  // Logged here
    throw;  // Logged again at caller
}

// Good
try {
    await ProcessOrderAsync(order);
} catch (Exception ex) {
    // Log once at top-level handler
    throw;
}
```

### Decision Tree

**Use this to choose level:**
```
Question 1: Is it an error?
Yes → Go to Q2
No → Go to Q3

Question 2: Can application continue?
Yes → ERROR
No → FATAL

Question 3: Is it important for operations?
Yes → Go to Q4
No → Go to Q5

Question 4: Is it expected behavior?
Yes → INFO
No → WARN

Question 5: Is it for debugging?
Yes → Go to Q6
No → Don't log

Question 6: Very detailed?
Yes → TRACE
No → DEBUG
```

### Best Practices

**Do:**
```
✓ Use appropriate level
✓ Be consistent
✓ Include context
✓ Configure per environment
✓ Log exceptions with stack traces
✓ Review logs regularly
✓ Adjust levels as needed
```

**Don't:**
```
✗ Log everything at one level
✗ Log too much at high levels
✗ Log passwords/secrets
✗ Log PII without masking
✗ Log in tight loops
✗ Ignore warnings
```

### Production Guidelines

**What to log:**
```
FATAL:    System crashes, critical failures
ERROR:    Exceptions, failed operations
WARN:     Unexpected events, degradation
INFO:     Important business events, state changes
DEBUG:    Disabled (enable for debugging)
TRACE:    Disabled
```

**Frequency:**
```
FATAL:    Rare (should be alerts)
ERROR:    Occasional (investigate quickly)
WARN:     Moderate (review regularly)
INFO:     Common (normal operations)
```

**Volume target:**
```
High traffic system:
- INFO: ~10-100 logs/second
- WARN: ~1-10 logs/minute
- ERROR: <1 log/minute
- FATAL: Rare

Adjust based on system
Monitor log volume
Alert on sudden increases
```
