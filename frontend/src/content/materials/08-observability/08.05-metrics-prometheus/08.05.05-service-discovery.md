By the end of this lesson, you will be able to:

- Choose appropriate service discovery mechanisms for different environments

---

## Introduction

Service discovery is crucial for monitoring dynamic environments where targets come and go frequently. Instead of manually updating Prometheus configuration every time a service is deployed or scaled, service discovery automatically detects targets and keeps the configuration up to date. This is especially important in containerized environments like Kubernetes.

## Key Concepts Summary

### What is Service Discovery?

**Service discovery** is the process of automatically detecting and configuring monitoring targets without manual intervention.

**The Problem:**
```
Static Configuration:
scrape_configs:
  - job_name: 'web-app'
    static_configs:
      - targets:
        - 'web-1:8080'
        - 'web-2:8080'
        - 'web-3:8080'

Issues:
❌ Manual updates when adding/removing instances
❌ Doesn't scale with auto-scaling
❌ Error-prone
❌ Delayed monitoring of new instances
```

**The Solution:**
```
Dynamic Discovery:
scrape_configs:
  - job_name: 'web-app'
    kubernetes_sd_configs:
      - role: pod
        namespaces:
          names: ['production']

Benefits:
✓ Automatic target discovery
✓ Works with auto-scaling
✓ Immediate monitoring of new instances
✓ Self-maintaining configuration
```

Cloud Platforms:

### Static Configuration

**Basic static configuration:**

```yaml
scrape_configs:
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']
  
  - job_name: 'node-exporters'
    static_configs:
      - targets:
        - 'node1:9100'
        - 'node2:9100'
        - 'node3:9100'
        labels:
          environment: 'production'
          datacenter: 'us-east'
```

**When to use static configuration:**
- Small, stable environments
- Servers with fixed IP addresses
- Development/testing
- Legacy infrastructure

### Kubernetes Service Discovery

Kubernetes is the most common use case for service discovery. Prometheus can discover:

**Discovery Roles:**
```
node      → Kubernetes nodes
service   → Kubernetes services
pod       → Kubernetes pods
endpoints → Kubernetes endpoints
ingress   → Kubernetes ingresses
```

#### Discovering Pods

**Basic pod discovery:**

```yaml
scrape_configs:
  - job_name: 'kubernetes-pods'
    kubernetes_sd_configs:
      - role: pod
```

**This discovers ALL pods**, but we usually want to filter:

```yaml
scrape_configs:
  - job_name: 'kubernetes-pods'
    kubernetes_sd_configs:
      - role: pod
        namespaces:
          names:
            - default
            - production
    
    relabel_configs:
      # Only scrape pods with annotation prometheus.io/scrape=true
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
      
      # Use prometheus.io/path annotation for metrics path
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_path]
        action: replace
        target_label: __metrics_path__
        regex: (.+)
      
      # Use prometheus.io/port annotation for port
      - source_labels: [__address__, __meta_kubernetes_pod_annotation_prometheus_io_port]
        action: replace
        regex: ([^:]+)(?::\d+)?;(\d+)
        replacement: $1:$2
        target_label: __address__
```

**Pod annotations:**

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp
  annotations:
    prometheus.io/scrape: "true"    # Enable scraping
    prometheus.io/port: "8080"      # Port to scrape
    prometheus.io/path: "/metrics"  # Metrics endpoint path
spec:
  containers:
    - name: myapp
      image: myapp:latest
```

#### Discovering Services

**Service discovery:**

```yaml
scrape_configs:
  - job_name: 'kubernetes-services'
    kubernetes_sd_configs:
      - role: service
    
    relabel_configs:
      # Only keep services with annotation
      - source_labels: [__meta_kubernetes_service_annotation_prometheus_io_scrape]
        action: keep
        regex: true
      
      # Set metrics path from annotation
      - source_labels: [__meta_kubernetes_service_annotation_prometheus_io_path]
        action: replace
        target_label: __metrics_path__
        regex: (.+)
      
      # Use service port
      - source_labels: [__address__, __meta_kubernetes_service_annotation_prometheus_io_port]
        action: replace
        regex: ([^:]+)(?::\d+)?;(\d+)
        replacement: $1:$2
        target_label: __address__
```

#### Discovering Nodes

**Node discovery with node-exporter:**

```yaml
scrape_configs:
  - job_name: 'kubernetes-nodes'
    kubernetes_sd_configs:
      - role: node
    
    relabel_configs:
      # Use internal IP
      - source_labels: [__address__]
        regex: '(.*):10250'
        replacement: '${1}:9100'
        target_label: __address__
      
      # Add node labels
      - action: labelmap
        regex: __meta_kubernetes_node_label_(.+)
```

### Relabeling

**Relabeling** is the process of filtering and transforming discovered targets before scraping.

#### Relabel Actions

**`keep`** - Keep only matching targets:
```yaml
- source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
  action: keep
  regex: true
```

**`drop`** - Drop matching targets:
```yaml
- source_labels: [__meta_kubernetes_pod_name]
  action: drop
  regex: 'test-.*'
```

**`replace`** - Replace label values:
```yaml
- source_labels: [__meta_kubernetes_pod_name]
  target_label: pod
  action: replace
```

**`labelmap`** - Map labels using regex:
```yaml
- action: labelmap
  regex: __meta_kubernetes_pod_label_(.+)
```

**`labeldrop`** - Drop labels matching regex:
```yaml
- action: labeldrop
  regex: '__meta_kubernetes_pod_label_(pod_template_.*)'
```

**`labelkeep`** - Keep only matching labels:
```yaml
- action: labelkeep
  regex: '(job|instance|__address__|pod|namespace)'
```

#### Common Relabeling Patterns

**1. Extract namespace and pod name:**
```yaml
- source_labels: [__meta_kubernetes_namespace]
  target_label: namespace
  action: replace

- source_labels: [__meta_kubernetes_pod_name]
  target_label: pod
  action: replace
```

**2. Use custom port from annotation:**
```yaml
- source_labels: [__address__, __meta_kubernetes_pod_annotation_prometheus_io_port]
  action: replace
  regex: ([^:]+)(?::\d+)?;(\d+)
  replacement: ${1}:${2}
  target_label: __address__
```

**3. Filter by namespace:**
```yaml
- source_labels: [__meta_kubernetes_namespace]
  action: keep
  regex: (default|production|staging)
```

**4. Map all pod labels:**
```yaml
- action: labelmap
  regex: __meta_kubernetes_pod_label_(.+)
```

### Prometheus Operator Approach

**Prometheus Operator** uses Custom Resource Definitions (CRDs) for easier configuration:

#### ServiceMonitor

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: myapp-monitor
  namespace: monitoring
spec:
  selector:
    matchLabels:
      app: myapp
  endpoints:
    - port: metrics
      interval: 30s
      path: /metrics
```

**Corresponding Service:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp
  labels:
    app: myapp
spec:
  ports:
    - name: metrics
      port: 8080
  selector:
    app: myapp
```

#### PodMonitor

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PodMonitor
metadata:
  name: myapp-pod-monitor
  namespace: monitoring
spec:
  selector:
    matchLabels:
      app: myapp
  podMetricsEndpoints:
    - port: metrics
      interval: 30s
```

### File-Based Service Discovery

**Useful for hybrid environments:**

```yaml
scrape_configs:
  - job_name: 'file-sd'
    file_sd_configs:
      - files:
        - '/etc/prometheus/targets/*.json'
        - '/etc/prometheus/targets/*.yaml'
        refresh_interval: 5m
```

**Target file (targets.json):**
```json
[
  {
    "targets": ["host1:9100", "host2:9100"],
    "labels": {
      "environment": "production",
      "datacenter": "us-east"
    }
  },
  {
    "targets": ["host3:9100"],
    "labels": {
      "environment": "staging",
      "datacenter": "us-west"
    }
  }
]
```

**Benefits:**
- External systems can generate target files
- Supports dynamic updates
- No Prometheus restart needed
- Works with any infrastructure

### DNS Service Discovery

**Discover targets via DNS:**

```yaml
scrape_configs:
  - job_name: 'dns-sd'
    dns_sd_configs:
      - names:
        - 'web-servers.example.com'
        - 'api-servers.example.com'
        type: 'A'
        port: 9100
```

**DNS record types:**
- `A` - IPv4 address records
- `AAAA` - IPv6 address records
- `SRV` - Service records (includes port)

### Complete Kubernetes Example

**Comprehensive Kubernetes monitoring:**

```yaml
scrape_configs:
  # 1. API Server
  - job_name: 'kubernetes-apiservers'
    kubernetes_sd_configs:
      - role: endpoints
    scheme: https
    tls_config:
      ca_file: /var/run/secrets/kubernetes.io/serviceaccount/ca.crt
    bearer_token_file: /var/run/secrets/kubernetes.io/serviceaccount/token
    relabel_configs:
      - source_labels: [__meta_kubernetes_namespace, __meta_kubernetes_service_name, __meta_kubernetes_endpoint_port_name]
        action: keep
        regex: default;kubernetes;https

  # 2. Nodes (via kubelet)
  - job_name: 'kubernetes-nodes'
    scheme: https
    tls_config:
      ca_file: /var/run/secrets/kubernetes.io/serviceaccount/ca.crt
    bearer_token_file: /var/run/secrets/kubernetes.io/serviceaccount/token
    kubernetes_sd_configs:
      - role: node
    relabel_configs:
      - action: labelmap
        regex: __meta_kubernetes_node_label_(.+)

  # 3. Pods
  - job_name: 'kubernetes-pods'
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_path]
        action: replace
        target_label: __metrics_path__
        regex: (.+)
      - source_labels: [__address__, __meta_kubernetes_pod_annotation_prometheus_io_port]
        action: replace
        regex: ([^:]+)(?::\d+)?;(\d+)
        replacement: $1:$2
        target_label: __address__
      - action: labelmap
        regex: __meta_kubernetes_pod_label_(.+)
      - source_labels: [__meta_kubernetes_namespace]
        action: replace
        target_label: namespace
      - source_labels: [__meta_kubernetes_pod_name]
        action: replace
        target_label: pod
```

### Best Practices

**1. Use appropriate discovery mechanisms:**
```
Kubernetes → kubernetes_sd_configs
AWS → ec2_sd_config
Consul → consul_sd_config
Static infra → file_sd_configs
```

**2. Filter aggressively:**
```yaml
# Only scrape annotated pods
- source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
  action: keep
  regex: true
```

**3. Add meaningful labels:**
```yaml
- source_labels: [__meta_kubernetes_namespace]
  target_label: kubernetes_namespace
- source_labels: [__meta_kubernetes_pod_name]
  target_label: kubernetes_pod_name
```

**4. Monitor discovery itself:**
```promql
# Number of active targets per job
count by (job) (up)

# Targets down
count by (job) (up == 0)
```

**5. Use ServiceMonitor with Prometheus Operator:**
```yaml
# Simpler than raw Prometheus config
# Better Kubernetes integration
# Automatic updates
```

## Key Takeaways

- **Service discovery** automatically detects monitoring targets
- **Kubernetes** is the most common service discovery mechanism
- Use **relabeling** to filter and transform discovered targets
- **`keep` action** filters targets; **`replace` action** modifies labels
- **Prometheus Operator** simplifies configuration with ServiceMonitor/PodMonitor
- Always **filter aggressively** to avoid scraping unnecessary targets
- Use **annotations** to control which pods are scraped
- **File-based discovery** works for hybrid/legacy environments
