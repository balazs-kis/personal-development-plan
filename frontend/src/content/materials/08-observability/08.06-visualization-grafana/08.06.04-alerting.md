---

## Introduction

Grafana Alerting enables proactive monitoring by notifying you when metrics cross defined thresholds or meet specific conditions. Instead of constantly watching dashboards, you can configure alerts to notify the right people at the right time. Grafana's unified alerting system works with all data sources and provides flexible routing through notification policies and contact points. Effective alerting ensures you're aware of issues before they impact users.

## Key Concepts Summary

### Three Steps to Creating Alerts

**1. Define Alert Rules**

Alert rules specify:
- **Data source and query:** What metric to monitor
- **Condition:** When to trigger (threshold, comparison)
- **Evaluation interval:** How often to check
- **For duration:** How long condition must be true before alerting
- **Labels and annotations:** Metadata for routing and context

Example conditions:
- When CPU usage > 80% for 5 minutes
- When error rate > 5% 
- When API latency p95 > 500ms

**2. Set Up Contact Points**

Contact points define where notifications go:
- **Email:** SMTP configuration
- **Slack:** Webhook or app integration
- **PagerDuty:** Integration key
- **Webhook:** Custom HTTP endpoint
- **OnCall:** Grafana OnCall integration
- **And 20+ other integrations**

Each contact point can have multiple notification channels.

**3. Configure Notification Policies**

Notification policies control alert routing:
- **Matching labels:** Route alerts based on labels (team, severity, service)
- **Grouping:** Combine related alerts to reduce noise
- **Repeat interval:** How often to resend notifications
- **Mute timings:** Silence alerts during maintenance windows

The default notification policy catches all alerts not matched by specific policies.

### Alert States

**Normal:** Condition is not met
**Pending:** Condition met but waiting for "for duration"
**Alerting:** Condition met for required duration, notifications sent
**No Data:** Query returns no data
**Error:** Alert rule evaluation failed

### Alert Rule Types

**Grafana-Managed Alerts**
- Created and stored in Grafana
- Can query any configured data source
- Support multi-dimensional alerts
- Evaluated by Grafana's alerting engine

**Data Source-Managed Alerts**
- Created in tools like Prometheus or Loki
- Managed by the data source's alerting system
- Displayed in Grafana for visibility

### Best Practices for Alerting

**Alert on Symptoms, Not Causes**
- ✅ Alert: "API response time > 1s"
- ❌ Alert: "Database CPU > 80%"
- Users experience slow APIs, not high database CPU

**Reduce Alert Fatigue**
- Set appropriate thresholds based on SLOs
- Use "for duration" to avoid flapping
- Group related alerts
- Implement proper severity levels

**Provide Context**
- Use annotations to include runbook links
- Add relevant labels for routing
- Include query values in notifications
- Link to related dashboards

**Test Your Alerts**
- Verify contact points work
- Test notification routing
- Simulate alert conditions
- Document escalation procedures

### Viewing Alerts in Dashboards

Add alert indicators to panels:
- Alert state appears on time series graphs
- Red/orange markers show alert periods
- Click to see alert details
- Navigate to alert rule configuration

Create alert list panels:
- Show all active alerts
- Filter by labels
- Group by state or severity
- Useful for NOC/operations dashboards
