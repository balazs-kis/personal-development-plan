## Learning Objectives

By the end of this lesson, you will be able to:

- Add events and exceptions to spans
- Use automatic instrumentation for common frameworks

---

## Introduction

Instrumentation is the process of adding tracing code to your application. In .NET, this is done using the `Activity` API from `System.Diagnostics`, which is the native distributed tracing API that integrates seamlessly with OpenTelemetry. This lesson covers both automatic instrumentation (for frameworks) and manual instrumentation (for custom code).

## Key Concepts Summary

### The Activity API

In .NET, distributed tracing uses the `Activity` class from `System.Diagnostics`:

```csharp
using System.Diagnostics;

// Activity = Span in OpenTelemetry terminology
// Activity.Current = the current active span
```

**Key concepts:**
- `Activity` = A span (unit of work)
- `ActivitySource` = Creates activities (like a tracer)
- `Activity.Current` = The current active activity/span
- Activities are hierarchical (parent-child relationships)

### Setting Up OpenTelemetry in ASP.NET Core

**1. Install packages:**

```bash
dotnet add package OpenTelemetry.Extensions.Hosting
dotnet add package OpenTelemetry.Instrumentation.AspNetCore
dotnet add package OpenTelemetry.Exporter.Console
```

**2. Configure in Program.cs:**

```csharp
using OpenTelemetry.Resources;
using OpenTelemetry.Trace;

var builder = WebApplication.CreateBuilder(args);

// Add OpenTelemetry
builder.Services.AddOpenTelemetry()
    .ConfigureResource(resource => resource
        .AddService(
            serviceName: "MyService",
            serviceVersion: "1.0.0"))
    .WithTracing(tracing => tracing
        .AddAspNetCoreInstrumentation()  // Automatic HTTP tracing
        .AddHttpClientInstrumentation()  // Automatic outbound HTTP
        .AddSource("MyCompany.MyService") // Listen to our custom spans
        .AddConsoleExporter());          // Export to console

var app = builder.Build();
app.Run();
```

### Automatic Instrumentation

OpenTelemetry provides automatic instrumentation for common frameworks:

```csharp
.WithTracing(tracing => tracing
    // ASP.NET Core (incoming HTTP requests)
    .AddAspNetCoreInstrumentation(options =>
    {
        // Customize behavior
        options.RecordException = true;
        options.Filter = (httpContext) =>
        {
            // Skip health checks
            return !httpContext.Request.Path.StartsWithSegments("/health");
        };
    })
    
    // HttpClient (outgoing HTTP requests)
    .AddHttpClientInstrumentation(options =>
    {
        options.RecordException = true;
    })
    
    // SQL Client (database queries)
    .AddSqlClientInstrumentation(options =>
    {
        options.SetDbStatementForText = true;
        options.RecordException = true;
    })
    
    // Entity Framework Core
    .AddEntityFrameworkCoreInstrumentation(options =>
    {
        options.SetDbStatementForText = true;
    }))
```

**What gets traced automatically:**
- ✓ HTTP requests (incoming and outgoing)
- ✓ Database queries (SQL, EF Core)
- ✓ gRPC calls
- ✓ Redis operations
- ✓ Message queue operations

### Manual Instrumentation

For custom code, create spans manually using `ActivitySource`:

**1. Create an ActivitySource:**

```csharp
public class OrderService
{
    // Create ActivitySource at class level
    private static readonly ActivitySource ActivitySource = new(
        "MyCompany.OrderService", // Name (must match AddSource config)
        "1.0.0");                 // Version
    
    // Your methods...
}
```

**2. Create activities (spans):**

```csharp
public async Task<Order> ProcessOrder(int orderId)
{
    // Start an activity
    using var activity = ActivitySource.StartActivity("ProcessOrder");
    
    // Add attributes
    activity?.SetTag("order.id", orderId);
    activity?.SetTag("service.name", "OrderService");
    
    try
    {
        // Your business logic
        var order = await _repository.GetOrder(orderId);
        activity?.SetTag("order.total", order.Total);
        activity?.SetTag("order.items", order.Items.Count);
        
        // Process the order
        await ValidateOrder(order);
        await ChargePayment(order);
        await CreateShipment(order);
        
        // Mark success
        activity?.SetStatus(ActivityStatusCode.Ok);
        return order;
    }
    catch (Exception ex)
    {
        // Record exception
        activity?.SetStatus(ActivityStatusCode.Error, ex.Message);
        activity?.RecordException(ex);
        throw;
    }
}
```

### Activity Kinds

Specify the type of operation using `ActivityKind`:

```csharp
// Internal operation (default)
using var activity = ActivitySource.StartActivity(
    "ProcessOrder",
    ActivityKind.Internal);

// Client making an outbound call
using var activity = ActivitySource.StartActivity(
    "CallPaymentAPI",
    ActivityKind.Client);

// Server receiving a request
using var activity = ActivitySource.StartActivity(
    "HandleRequest",
    ActivityKind.Server);

// Producer sending a message
using var activity = ActivitySource.StartActivity(
    "PublishEvent",
    ActivityKind.Producer);

// Consumer receiving a message
using var activity = ActivitySource.StartActivity(
    "ConsumeEvent",
    ActivityKind.Consumer);
```

### Adding Attributes (Tags)

Attributes provide context about the operation:

```csharp
activity?.SetTag("user.id", userId);
activity?.SetTag("tenant.id", tenantId);
activity?.SetTag("order.type", "express");
activity?.SetTag("payment.method", "credit_card");
activity?.SetTag("inventory.available", isAvailable);
```

**Use semantic conventions when possible:**

```csharp
// HTTP attributes
activity?.SetTag("http.method", "POST");
activity?.SetTag("http.url", "/api/orders");
activity?.SetTag("http.status_code", 201);

// Database attributes
activity?.SetTag("db.system", "postgresql");
activity?.SetTag("db.name", "ecommerce");
activity?.SetTag("db.statement", "SELECT * FROM orders WHERE id = $1");

// Messaging attributes
activity?.SetTag("messaging.system", "rabbitmq");
activity?.SetTag("messaging.destination", "orders.queue");
activity?.SetTag("messaging.operation", "publish");
```

### Adding Events

Events are timestamped logs within a span:

```csharp
using var activity = ActivitySource.StartActivity("ProcessOrder");

// Add events at key points
activity?.AddEvent(new ActivityEvent("Order validation started"));

await ValidateOrder(order);
activity?.AddEvent(new ActivityEvent("Order validated successfully"));

await ProcessPayment(order);
activity?.AddEvent(new ActivityEvent("Payment processed", 
    tags: new ActivityTagsCollection
    {
        ["payment.amount"] = order.Total,
        ["payment.status"] = "success"
    }));
```

### Recording Exceptions

Always record exceptions in spans:

```csharp
try
{
    await ProcessPayment(order);
}
catch (PaymentException ex)
{
    // Record the exception
    activity?.RecordException(ex);
    
    // Set error status
    activity?.SetStatus(ActivityStatusCode.Error, ex.Message);
    
    // Add context
    activity?.SetTag("error.type", ex.GetType().Name);
    activity?.SetTag("payment.failure_reason", ex.FailureReason);
    
    throw;
}
```

### Creating Child Spans

Activities automatically form parent-child relationships:

```csharp
public async Task ProcessOrder(int orderId)
{
    using var parentActivity = ActivitySource.StartActivity("ProcessOrder");
    parentActivity?.SetTag("order.id", orderId);
    
    // Child span 1
    await ValidateOrder(orderId);  // Creates child span
    
    // Child span 2
    await ProcessPayment(orderId); // Creates child span
    
    // Child span 3
    await CreateShipment(orderId); // Creates child span
}

private async Task ValidateOrder(int orderId)
{
    // This automatically becomes a child of the parent activity
    using var activity = ActivitySource.StartActivity("ValidateOrder");
    activity?.SetTag("order.id", orderId);
    
    // Validation logic...
}
```

### Best Practices for Instrumentation

**1. Name Activities Clearly:**

```csharp
// Good - descriptive names
"OrderService.ProcessOrder"
"PaymentGateway.ChargeCard"
"Inventory.CheckStock"

// Bad - vague names
"Process"
"DoWork"
"Execute"
```

**2. Add Meaningful Attributes:**

```csharp
// Good - provides context
activity?.SetTag("order.id", orderId);
activity?.SetTag("order.total", order.Total);
activity?.SetTag("user.id", order.UserId);
activity?.SetTag("payment.method", order.PaymentMethod);

// Bad - too little information
activity?.SetTag("id", orderId);
```

**3. Don't Over-Instrument:**

```csharp
// Good - trace meaningful operations
using var activity = ActivitySource.StartActivity("ProcessOrder");

// Bad - too granular
using var activity1 = ActivitySource.StartActivity("ValidateOrderId");
using var activity2 = ActivitySource.StartActivity("CheckOrderFormat");
using var activity3 = ActivitySource.StartActivity("ParseOrderData");
```

**4. Always Handle Exceptions:**

```csharp
try
{
    // Your code
    activity?.SetStatus(ActivityStatusCode.Ok);
}
catch (Exception ex)
{
    activity?.SetStatus(ActivityStatusCode.Error, ex.Message);
    activity?.RecordException(ex);
    throw;
}
```

**5. Use Null-Conditional Operator:**

```csharp
// Activity might be null if not sampled
activity?.SetTag("key", "value");
activity?.AddEvent(new ActivityEvent("message"));
```

### Complete Example

Here's a complete example of a well-instrumented service:

```csharp
using System.Diagnostics;
using OpenTelemetry.Resources;
using OpenTelemetry.Trace;

// Startup configuration
builder.Services.AddOpenTelemetry()
    .ConfigureResource(resource => resource
        .AddService("OrderService", "1.0.0"))
    .WithTracing(tracing => tracing
        .AddSource("MyCompany.OrderService")
        .AddAspNetCoreInstrumentation()
        .AddHttpClientInstrumentation()
        .AddSqlClientInstrumentation()
        .AddOtlpExporter(options =>
        {
            options.Endpoint = new Uri("http://jaeger:4317");
        }));

// Service class
public class OrderService
{
    private static readonly ActivitySource ActivitySource = 
        new("MyCompany.OrderService", "1.0.0");
    
    private readonly IOrderRepository _repository;
    private readonly IPaymentService _paymentService;
    private readonly ILogger<OrderService> _logger;
    
    public OrderService(
        IOrderRepository repository,
        IPaymentService paymentService,
        ILogger<OrderService> logger)
    {
        _repository = repository;
        _paymentService = paymentService;
        _logger = logger;
    }
    
    public async Task<Order> ProcessOrder(int orderId, string userId)
    {
        using var activity = ActivitySource.StartActivity(
            "ProcessOrder",
            ActivityKind.Internal);
        
        // Add identifying attributes
        activity?.SetTag("order.id", orderId);
        activity?.SetTag("user.id", userId);
        activity?.SetTag("service.operation", "process_order");
        
        try
        {
            _logger.LogInformation(
                "Processing order {OrderId} for user {UserId}",
                orderId, userId);
            
            // Retrieve order (automatic DB tracing)
            activity?.AddEvent(new ActivityEvent("Fetching order from database"));
            var order = await _repository.GetOrder(orderId);
            
            if (order == null)
            {
                activity?.SetTag("order.found", false);
                activity?.SetStatus(ActivityStatusCode.Error, "Order not found");
                throw new OrderNotFoundException(orderId);
            }
            
            activity?.SetTag("order.found", true);
            activity?.SetTag("order.total", order.Total);
            activity?.SetTag("order.items_count", order.Items.Count);
            
            // Validate order
            activity?.AddEvent(new ActivityEvent("Validating order"));
            await ValidateOrder(order);
            
            // Process payment
            activity?.AddEvent(new ActivityEvent("Processing payment"));
            var paymentResult = await _paymentService.ChargeCard(
                order.Total,
                order.PaymentMethod);
            
            activity?.SetTag("payment.transaction_id", paymentResult.TransactionId);
            activity?.SetTag("payment.status", paymentResult.Status);
            
            // Update order status
            order.Status = OrderStatus.Confirmed;
            await _repository.UpdateOrder(order);
            
            activity?.SetStatus(ActivityStatusCode.Ok);
            activity?.AddEvent(new ActivityEvent("Order processed successfully"));
            
            return order;
        }
        catch (PaymentException ex)
        {
            activity?.SetStatus(ActivityStatusCode.Error, "Payment failed");
            activity?.RecordException(ex);
            activity?.SetTag("error.payment.code", ex.ErrorCode);
            _logger.LogError(ex, "Payment failed for order {OrderId}", orderId);
            throw;
        }
        catch (Exception ex)
        {
            activity?.SetStatus(ActivityStatusCode.Error, ex.Message);
            activity?.RecordException(ex);
            _logger.LogError(ex, "Failed to process order {OrderId}", orderId);
            throw;
        }
    }
    
    private async Task ValidateOrder(Order order)
    {
        using var activity = ActivitySource.StartActivity("ValidateOrder");
        activity?.SetTag("order.id", order.Id);
        
        // Validation logic
        if (order.Items.Count == 0)
        {
            activity?.SetStatus(ActivityStatusCode.Error, "Order has no items");
            throw new ValidationException("Order must have at least one item");
        }
        
        activity?.SetTag("validation.passed", true);
        activity?.SetStatus(ActivityStatusCode.Ok);
    }
}
```

## Key Takeaways

- Use the **`Activity` API** for distributed tracing in .NET
- **`ActivitySource`** creates activities (spans)
- **Automatic instrumentation** handles HTTP, database, and gRPC tracing
- **Manual instrumentation** is needed for custom business logic
- Always **add meaningful attributes** to provide context
- **Record exceptions** with `activity?.RecordException(ex)`
- Use **semantic conventions** for standard attributes
- Activities automatically form **parent-child relationships**
- Set **activity status** (Ok or Error) based on outcome
