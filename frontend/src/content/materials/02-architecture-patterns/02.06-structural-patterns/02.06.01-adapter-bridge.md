# Lesson 1: Adapter and Bridge Patterns

## Learning Objectives
- Implement Adapter pattern for interface compatibility
- Use Bridge pattern for abstraction-implementation separation
- Apply these patterns in .NET applications
- Understand when to use each pattern

---

## Introduction

Adapter and Bridge are structural patterns that deal with composition and relationships between classes. While they may seem similar, they serve different purposes: Adapter makes incompatible interfaces work together, while Bridge separates abstraction from implementation.

## Key Concepts Summary

### Adapter Pattern

**Problem:** You have two incompatible interfaces that need to work together.

```csharp
// Existing interface your code expects
public interface IPaymentProcessor
{
    PaymentResult ProcessPayment(decimal amount, string currency);
}

// Third-party payment service with different interface
public class StripePaymentService
{
    public StripeResponse Charge(int amountInCents, string currencyCode, string token)
    {
        // Stripe-specific implementation
        return new StripeResponse { Success = true, TransactionId = "txn_123" };
    }
}

// Adapter makes them compatible
public class StripePaymentAdapter : IPaymentProcessor
{
    private readonly StripePaymentService _stripeService;
    
    public StripePaymentAdapter(StripePaymentService stripeService)
    {
        _stripeService = stripeService;
    }
    
    public PaymentResult ProcessPayment(decimal amount, string currency)
    {
        // Adapt: Convert dollars to cents
        int amountInCents = (int)(amount * 100);
        
        // Call adapted method
        var response = _stripeService.Charge(amountInCents, currency, GetToken());
        
        // Convert response
        return new PaymentResult
        {
            Success = response.Success,
            TransactionId = response.TransactionId
        };
    }
}
```

### Object Adapter vs Class Adapter

```csharp
// Object Adapter (uses composition - preferred)
public class PayPalAdapter : IPaymentProcessor
{
    private readonly PayPalApi _paypal;  // Composition
    
    public PayPalAdapter(PayPalApi paypal)
    {
        _paypal = paypal;
    }
    
    public PaymentResult ProcessPayment(decimal amount, string currency)
    {
        var result = _paypal.MakePayment(amount, currency);
        return new PaymentResult { Success = result.IsSuccess };
    }
}

// Class Adapter (uses inheritance - less flexible)
public class PayPalAdapterByInheritance : PayPalApi, IPaymentProcessor
{
    public PaymentResult ProcessPayment(decimal amount, string currency)
    {
        var result = base.MakePayment(amount, currency);
        return new PaymentResult { Success = result.IsSuccess };
    }
}
```

### Two-Way Adapter

```csharp
// Adapter that works in both directions
public interface IModernLogger
{
    void Log(LogLevel level, string message);
}

public interface ILegacyLogger
{
    void WriteInfo(string message);
    void WriteError(string message);
}

public class TwoWayLoggerAdapter : IModernLogger, ILegacyLogger
{
    private readonly IModernLogger _modernLogger;
    
    public TwoWayLoggerAdapter(IModernLogger modernLogger)
    {
        _modernLogger = modernLogger;
    }
    
    // Modern interface implementation
    public void Log(LogLevel level, string message)
    {
        _modernLogger.Log(level, message);
    }
    
    // Legacy interface implementation
    public void WriteInfo(string message)
    {
        _modernLogger.Log(LogLevel.Information, message);
    }
    
    public void WriteError(string message)
    {
        _modernLogger.Log(LogLevel.Error, message);
    }
}
```

### Real-World Example: Legacy Database Adapter

```csharp
// Modern interface using async/await
public interface ICustomerRepository
{
    Task<Customer> GetByIdAsync(int id);
    Task<IEnumerable<Customer>> GetAllAsync();
    Task AddAsync(Customer customer);
}

// Legacy database class (synchronous, different naming)
public class LegacyCustomerDatabase
{
    public CustomerRecord FetchCustomer(int customerId)
    {
        // Legacy synchronous implementation
        return new CustomerRecord();
    }
    
    public List<CustomerRecord> FetchAllCustomers()
    {
        return new List<CustomerRecord>();
    }
    
    public void InsertCustomer(CustomerRecord record)
    {
        // Legacy insert logic
    }
}

// Adapter bridges the gap
public class LegacyCustomerAdapter : ICustomerRepository
{
    private readonly LegacyCustomerDatabase _legacyDb;
    
    public LegacyCustomerAdapter(LegacyCustomerDatabase legacyDb)
    {
        _legacyDb = legacyDb;
    }
    
    public Task<Customer> GetByIdAsync(int id)
    {
        // Adapt sync to async
        return Task.Run(() =>
        {
            var record = _legacyDb.FetchCustomer(id);
            return MapToCustomer(record);
        });
    }
    
    public Task<IEnumerable<Customer>> GetAllAsync()
    {
        return Task.Run(() =>
        {
            var records = _legacyDb.FetchAllCustomers();
            return records.Select(MapToCustomer);
        });
    }
    
    public Task AddAsync(Customer customer)
    {
        return Task.Run(() =>
        {
            var record = MapToRecord(customer);
            _legacyDb.InsertCustomer(record);
        });
    }
    
    private Customer MapToCustomer(CustomerRecord record)
    {
        return new Customer
        {
            Id = record.CustomerId,
            Name = record.CustomerName,
            Email = record.EmailAddress
        };
    }
    
    private CustomerRecord MapToRecord(Customer customer)
    {
        return new CustomerRecord
        {
            CustomerId = customer.Id,
            CustomerName = customer.Name,
            EmailAddress = customer.Email
        };
    }
}
```

### Adapter with Dependency Injection

```csharp
// Third-party service interfaces
public interface IExternalEmailService
{
    void SendEmail(string to, string subject, string body);
}

public class SendGridService : IExternalEmailService
{
    public void SendEmail(string to, string subject, string body)
    {
        // SendGrid implementation
    }
}

// Your application's interface
public interface IEmailSender
{
    Task SendAsync(EmailMessage message);
}

// Adapter
public class SendGridAdapter : IEmailSender
{
    private readonly IExternalEmailService _sendGrid;
    private readonly ILogger<SendGridAdapter> _logger;
    
    public SendGridAdapter(
        IExternalEmailService sendGrid,
        ILogger<SendGridAdapter> logger)
    {
        _sendGrid = sendGrid;
        _logger = logger;
    }
    
    public Task SendAsync(EmailMessage message)
    {
        return Task.Run(() =>
        {
            try
            {
                _sendGrid.SendEmail(
                    message.To,
                    message.Subject,
                    message.Body);
                    
                _logger.LogInformation(
                    "Email sent to {Recipient}", message.To);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, 
                    "Failed to send email to {Recipient}", message.To);
                throw;
            }
        });
    }
}

// Registration
services.AddSingleton<IExternalEmailService, SendGridService>();
services.AddSingleton<IEmailSender, SendGridAdapter>();
```

### Bridge Pattern

**Problem:** You have multiple dimensions of variation and want to avoid explosion of subclasses.

```csharp
// Without Bridge - Combinatorial explosion
// EmailNotificationSMS, EmailNotificationPush, SMSNotificationEmail, etc.

// With Bridge - Separate abstraction from implementation

// Abstraction
public abstract class Notification
{
    protected IMessageSender _sender;
    
    protected Notification(IMessageSender sender)
    {
        _sender = sender;
    }
    
    public abstract void Send(string message, string recipient);
}

// Refined abstractions
public class UrgentNotification : Notification
{
    public UrgentNotification(IMessageSender sender) : base(sender) { }
    
    public override void Send(string message, string recipient)
    {
        string urgentMessage = $"URGENT: {message}";
        _sender.SendMessage(urgentMessage, recipient);
        _sender.SendMessage("Please respond immediately", recipient);
    }
}

public class RegularNotification : Notification
{
    public RegularNotification(IMessageSender sender) : base(sender) { }
    
    public override void Send(string message, string recipient)
    {
        _sender.SendMessage(message, recipient);
    }
}

// Implementation interface
public interface IMessageSender
{
    void SendMessage(string message, string recipient);
}

// Concrete implementations
public class EmailSender : IMessageSender
{
    public void SendMessage(string message, string recipient)
    {
        Console.WriteLine($"Email to {recipient}: {message}");
    }
}

public class SmsSender : IMessageSender
{
    public void SendMessage(string message, string recipient)
    {
        Console.WriteLine($"SMS to {recipient}: {message}");
    }
}

// Usage - mix and match
var urgentEmail = new UrgentNotification(new EmailSender());
urgentEmail.Send("Server is down!", "admin@example.com");

var regularSms = new RegularNotification(new SmsSender());
regularSms.Send("Meeting reminder", "+1234567890");
```

### Advanced Bridge: Remote Control System

```csharp
// Abstraction - Remote Control
public abstract class RemoteControl
{
    protected IDevice _device;
    
    protected RemoteControl(IDevice device)
    {
        _device = device;
    }
    
    public virtual void TogglePower()
    {
        if (_device.IsEnabled())
            _device.Disable();
        else
            _device.Enable();
    }
    
    public virtual void VolumeUp()
    {
        _device.SetVolume(_device.GetVolume() + 10);
    }
    
    public virtual void VolumeDown()
    {
        _device.SetVolume(_device.GetVolume() - 10);
    }
}

// Refined Abstraction
public class AdvancedRemoteControl : RemoteControl
{
    public AdvancedRemoteControl(IDevice device) : base(device) { }
    
    public void Mute()
    {
        _device.SetVolume(0);
    }
    
    public void SetChannel(int channel)
    {
        // Additional functionality
        Console.WriteLine($"Setting channel to {channel}");
    }
}

// Implementation Interface
public interface IDevice
{
    bool IsEnabled();
    void Enable();
    void Disable();
    int GetVolume();
    void SetVolume(int percent);
}

// Concrete Implementations
public class Television : IDevice
{
    private bool _on;
    private int _volume = 50;
    
    public bool IsEnabled() => _on;
    public void Enable() { _on = true; Console.WriteLine("TV turned on"); }
    public void Disable() { _on = false; Console.WriteLine("TV turned off"); }
    public int GetVolume() => _volume;
    public void SetVolume(int percent) 
    { 
        _volume = Math.Clamp(percent, 0, 100);
        Console.WriteLine($"TV volume: {_volume}%");
    }
}

public class Radio : IDevice
{
    private bool _on;
    private int _volume = 30;
    
    public bool IsEnabled() => _on;
    public void Enable() { _on = true; Console.WriteLine("Radio turned on"); }
    public void Disable() { _on = false; Console.WriteLine("Radio turned off"); }
    public int GetVolume() => _volume;
    public void SetVolume(int percent)
    {
        _volume = Math.Clamp(percent, 0, 100);
        Console.WriteLine($"Radio volume: {_volume}%");
    }
}

// Usage - any remote can control any device
var tv = new Television();
var basicRemote = new RemoteControl(tv);
basicRemote.TogglePower();
basicRemote.VolumeUp();

var radio = new Radio();
var advancedRemote = new AdvancedRemoteControl(radio);
advancedRemote.TogglePower();
advancedRemote.Mute();
```

### Real-World Bridge: Data Export System

```csharp
// Abstraction - Report
public abstract class Report
{
    protected IDataExporter _exporter;
    protected string _title;
    
    protected Report(IDataExporter exporter, string title)
    {
        _exporter = exporter;
        _title = title;
    }
    
    public abstract Task<byte[]> Generate();
}

// Refined Abstractions
public class SalesReport : Report
{
    private readonly ISalesDataService _dataService;
    
    public SalesReport(
        IDataExporter exporter,
        ISalesDataService dataService,
        string title = "Sales Report") 
        : base(exporter, title)
    {
        _dataService = dataService;
    }
    
    public override async Task<byte[]> Generate()
    {
        var data = await _dataService.GetSalesData();
        return await _exporter.Export(_title, data);
    }
}

public class InventoryReport : Report
{
    private readonly IInventoryDataService _dataService;
    
    public InventoryReport(
        IDataExporter exporter,
        IInventoryDataService dataService,
        string title = "Inventory Report")
        : base(exporter, title)
    {
        _dataService = dataService;
    }
    
    public override async Task<byte[]> Generate()
    {
        var data = await _dataService.GetInventoryData();
        return await _exporter.Export(_title, data);
    }
}

// Implementation Interface
public interface IDataExporter
{
    Task<byte[]> Export(string title, object data);
}

// Concrete Implementations
public class PdfExporter : IDataExporter
{
    public async Task<byte[]> Export(string title, object data)
    {
        // PDF generation logic
        Console.WriteLine($"Generating PDF: {title}");
        await Task.Delay(100);
        return new byte[0];
    }
}

public class ExcelExporter : IDataExporter
{
    public async Task<byte[]> Export(string title, object data)
    {
        // Excel generation logic
        Console.WriteLine($"Generating Excel: {title}");
        await Task.Delay(100);
        return new byte[0];
    }
}

public class CsvExporter : IDataExporter
{
    public async Task<byte[]> Export(string title, object data)
    {
        // CSV generation logic
        Console.WriteLine($"Generating CSV: {title}");
        await Task.Delay(100);
        return new byte[0];
    }
}

// Usage - easily combine any report type with any format
var salesPdf = new SalesReport(new PdfExporter(), salesDataService);
var salesExcel = new SalesReport(new ExcelExporter(), salesDataService);
var inventoryCsv = new InventoryReport(new CsvExporter(), inventoryDataService);

await salesPdf.Generate();
await salesExcel.Generate();
await inventoryCsv.Generate();
```

### Bridge with Dependency Injection

```csharp
// Registration
services.AddTransient<IDataExporter, PdfExporter>();
services.AddTransient<IDataExporter, ExcelExporter>();

// Factory for selecting exporter
public interface IReportExporterFactory
{
    IDataExporter CreateExporter(ExportFormat format);
}

public class ReportExporterFactory : IReportExporterFactory
{
    private readonly IServiceProvider _serviceProvider;
    
    public ReportExporterFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }
    
    public IDataExporter CreateExporter(ExportFormat format)
    {
        return format switch
        {
            ExportFormat.Pdf => _serviceProvider.GetRequiredService<PdfExporter>(),
            ExportFormat.Excel => _serviceProvider.GetRequiredService<ExcelExporter>(),
            ExportFormat.Csv => _serviceProvider.GetRequiredService<CsvExporter>(),
            _ => throw new ArgumentException($"Unknown format: {format}")
        };
    }
}

// Usage in service
public class ReportService
{
    private readonly IReportExporterFactory _exporterFactory;
    private readonly ISalesDataService _salesData;
    
    public ReportService(
        IReportExporterFactory exporterFactory,
        ISalesDataService salesData)
    {
        _exporterFactory = exporterFactory;
        _salesData = salesData;
    }
    
    public async Task<byte[]> GenerateSalesReport(ExportFormat format)
    {
        var exporter = _exporterFactory.CreateExporter(format);
        var report = new SalesReport(exporter, _salesData);
        return await report.Generate();
    }
}
```

### Adapter vs Bridge Comparison

| Aspect | Adapter | Bridge |
|--------|---------|--------|
| **Intent** | Make incompatible interfaces work together | Separate abstraction from implementation |
| **When applied** | After code is written (retrofit) | During design (upfront) |
| **Interfaces** | Adapts existing interface to target | Creates new abstraction and implementation hierarchies |
| **Flexibility** | Adapts one class | Enables multiple abstractions and implementations |
| **Structure** | Single adapter wraps adaptee | Abstraction holds reference to implementation |

### Common Mistakes

**Adapter Anti-Pattern:**
```csharp
// BAD - Adapter doing too much
public class BadAdapter : ITarget
{
    private readonly Adaptee _adaptee;
    
    public void Request()
    {
        // Adapter should NOT add business logic!
        ValidateInput();
        LogRequest();
        _adaptee.SpecificRequest();
        CacheResult();
        SendNotification();
    }
}

// GOOD - Adapter only translates
public class GoodAdapter : ITarget
{
    private readonly Adaptee _adaptee;
    
    public void Request()
    {
        // Only translation, no business logic
        _adaptee.SpecificRequest();
    }
}
```

**Bridge Over-Engineering:**
```csharp
// BAD - Bridge when not needed (only one dimension varies)
// If you only have different export formats but one report type,
// just use Strategy pattern instead

// GOOD - Bridge when multiple dimensions vary
// Multiple report types × Multiple export formats = Bridge
```

## Self-Check Questions

1. **What's the main difference between Adapter and Bridge?**
   - Adapter: Makes existing incompatible interfaces work together (retrofit)
   - Bridge: Separates abstraction from implementation (design upfront)

2. **When would you choose Adapter over Bridge?**
   - Adapter: Integrating third-party libraries or legacy code
   - Bridge: When you have multiple orthogonal dimensions of variation

3. **How does Bridge prevent class explosion?**
   - Separates two independent hierarchies (abstraction and implementation)
   - N abstractions × M implementations = N + M classes instead of N × M

4. **Can you use both patterns together?**
   - Yes! Adapter can adapt a third-party class to fit into Bridge pattern
   - Example: Adapt external API to your IImplementation interface

5. **What's an Object Adapter vs Class Adapter?**
   - Object: Uses composition (preferred, more flexible)
   - Class: Uses inheritance (less flexible, not always possible)

6. **When is Bridge overkill?**
   - When only one dimension varies (use Strategy instead)
   - For simple scenarios with few variations
   - When flexibility isn't needed
