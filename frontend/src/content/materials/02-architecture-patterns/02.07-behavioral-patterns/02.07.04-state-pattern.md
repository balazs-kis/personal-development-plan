## Introduction

The State pattern allows an object to alter its behavior when its internal state changes, making the object appear to change its class. This pattern is essential for implementing state machines and managing complex state-dependent behavior without large conditional statements. It promotes the Open-Closed Principle by encapsulating state-specific behavior in separate classes.

State machines are fundamental to many business processes: order processing, approval workflows, ticket management, and more.

```csharp
// BAD - Complex conditionals
public class Order
```

### Solution: State Pattern

```csharp
// State interface
public interface IOrderState
{
    void Process(Order order);
    void Ship(Order order);
    void Cancel(Order order);
    void Complete(Order order);
    OrderStatus Status { get; }
}

// Context
public class Order
{
    private IOrderState _state;
    
    public Guid Id { get; }
    public decimal TotalAmount { get; }
    public OrderStatus Status => _state.Status;
    
    public Order(Guid id, decimal totalAmount)
    {
        Id = id;
        TotalAmount = totalAmount;
        _state = new PendingState();  // Initial state
    }
    
    public void SetState(IOrderState state)
    {
        _state = state;
        Console.WriteLine($"Order state changed to: {state.Status}");
    }
    
    public void Process() => _state.Process(this);
    public void Ship() => _state.Ship(this);
    public void Cancel() => _state.Cancel(this);
    public void Complete() => _state.Complete(this);
}
```

### State Machine with Dependency Injection

```csharp
// State factory
public interface IOrderStateFactory
{
    IOrderState CreateState(OrderStatus status);
}

public class OrderStateFactory : IOrderStateFactory
{
    private readonly IServiceProvider _serviceProvider;
    
    public OrderStateFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }
    
    public IOrderState CreateState(OrderStatus status)
    {
        return status switch
        {
            OrderStatus.Pending => _serviceProvider.GetRequiredService<PendingState>(),
            OrderStatus.Processing => _serviceProvider.GetRequiredService<ProcessingState>(),
            OrderStatus.Shipped => _serviceProvider.GetRequiredService<ShippedState>(),
            OrderStatus.Completed => _serviceProvider.GetRequiredService<CompletedState>(),
            OrderStatus.Cancelled => _serviceProvider.GetRequiredService<CancelledState>(),
            _ => throw new ArgumentException($"Unknown status: {status}")
        };
    }
}

// Enhanced state with dependencies
public class ProcessingState : IOrderState
{
    private readonly IInventoryService _inventoryService;
    private readonly ILogger<ProcessingState> _logger;
    
    public ProcessingState(
        IInventoryService inventoryService,
        ILogger<ProcessingState> logger)
    {
        _inventoryService = inventoryService;
        _logger = logger;
    }
    
    public OrderStatus Status => OrderStatus.Processing;
    
    public async Task Process(Order order)
    {
        throw new InvalidOperationException("Already processing");
    }
    
    public async Task Ship(Order order)
    {
        _logger.LogInformation("Preparing order {OrderId} for shipment", order.Id);
        
        await _inventoryService.ReserveItems(order.Id);
        
        order.SetState(new ShippedState());
    }
    
    // ... other methods
}
```

```csharp
public enum DocumentState
{
    Draft,
    PendingReview,
    Approved,
    Rejected,
    Published
}

public interface IDocumentState
{
    DocumentState State { get; }
    void SubmitForReview(Document document);
    void Approve(Document document);
    void Reject(Document document, string reason);
    void Publish(Document document);
}

public class Document
{
    private IDocumentState _state;
    
    public Guid Id { get; }
    public string Title { get; }
    public string Content { get; private set; }
    public DocumentState State => _state.State;
    
    public Document(string title, string content)
    {
        Id = Guid.NewGuid();
        Title = title;
        Content = content;
        _state = new DraftState();
    }
    
    public void SetState(IDocumentState state)
    {
        _state = state;
    }
    
    public void UpdateContent(string content)
    {
        if (_state.State != DocumentState.Draft)
            throw new InvalidOperationException("Can only edit draft documents");
        
        Content = content;
    }
    
    public void SubmitForReview() => _state.SubmitForReview(this);
    public void Approve() => _state.Approve(this);
    public void Reject(string reason) => _state.Reject(this, reason);
    public void Publish() => _state.Publish(this);
}

public class DraftState : IDocumentState
{
    public DocumentState State => DocumentState.Draft;
    
    public void SubmitForReview(Document document)
    {
        document.SetState(new PendingReviewState());
    }
    
    public void Approve(Document document)
    {
        throw new InvalidOperationException("Cannot approve draft");
    }
    
    public void Reject(Document document, string reason)
    {
        throw new InvalidOperationException("Cannot reject draft");
    }
    
    public void Publish(Document document)
    {
        throw new InvalidOperationException("Cannot publish draft");
    }
}
```

### State Machine with Event-Driven Transitions

```csharp
// State machine with events
public class StateMachine<TState> where TState : Enum
{
    private TState _currentState;
    private readonly Dictionary<TState, List<StateTransition<TState>>> _transitions = new();
    
    public event EventHandler<StateChangedEventArgs<TState>>? StateChanged;
    
    public TState CurrentState => _currentState;
    
    public StateMachine(TState initialState)
    {
        _currentState = initialState;
    }
    
    public void AddTransition(TState from, TState to, Func<bool> condition)
    {
        if (!_transitions.ContainsKey(from))
        {
            _transitions[from] = new List<StateTransition<TState>>();
        }
        
        _transitions[from].Add(new StateTransition<TState>(to, condition));
    }
    
    public bool TryTransition(TState targetState)
    {
        if (!_transitions.ContainsKey(_currentState))
            return false;
        
        var transition = _transitions[_currentState]
            .FirstOrDefault(t => t.TargetState.Equals(targetState) && t.Condition());
        
        if (transition == null)
            return false;
        
        var oldState = _currentState;
        _currentState = targetState;
        
        StateChanged?.Invoke(this, new StateChangedEventArgs<TState>(oldState, targetState));
        
        return true;
    }
}

public record StateTransition<TState>(TState TargetState, Func<bool> Condition);

public class StateChangedEventArgs<TState> : EventArgs
{
    public TState OldState { get; }
    public TState NewState { get; }
    
    public StateChangedEventArgs(TState oldState, TState newState)
    {
        OldState = oldState;
        NewState = newState;
    }
}

// Usage
public enum OrderState
{
    Pending,
    Processing,
    Shipped,
    Delivered
}

var stateMachine = new StateMachine<OrderState>(OrderState.Pending);

// Define transitions
stateMachine.AddTransition(
    OrderState.Pending,
    OrderState.Processing,
    () => _order.IsPaid);

stateMachine.AddTransition(
    OrderState.Processing,
    OrderState.Shipped,
    () => _order.HasTrackingNumber);

// Listen to state changes
stateMachine.StateChanged += (sender, e) =>
{
    Console.WriteLine($"State changed: {e.OldState} → {e.NewState}");
};

// Attempt transition
if (stateMachine.TryTransition(OrderState.Processing))
{
    // Transition successful
}
```

### Stateless Library Integration

```csharp
// Install: dotnet add package Stateless

public class OrderStateMachine
{
    private readonly StateMachine<OrderState, OrderTrigger> _machine;
    private readonly Order _order;
    
    public OrderStateMachine(Order order)
    {
        _order = order;
        _machine = new StateMachine<OrderState, OrderTrigger>(
            () => _order.Status,
            s => _order.Status = s);
        
        ConfigureStateMachine();
    }
    
    private void ConfigureStateMachine()
    {
        _machine.Configure(OrderState.Pending)
            .Permit(OrderTrigger.Process, OrderState.Processing)
            .Permit(OrderTrigger.Cancel, OrderState.Cancelled)
            .OnEntry(() => Console.WriteLine("Order is pending"));
        
        _machine.Configure(OrderState.Processing)
            .Permit(OrderTrigger.Ship, OrderState.Shipped)
            .Permit(OrderTrigger.Cancel, OrderState.Cancelled)
            .OnEntry(() => ProcessOrder())
            .OnExit(() => Console.WriteLine("Leaving processing state"));
        
        _machine.Configure(OrderState.Shipped)
            .Permit(OrderTrigger.Deliver, OrderState.Delivered)
            .OnEntry(() => ShipOrder());
        
        _machine.Configure(OrderState.Delivered)
            .OnEntry(() => CompleteOrder());
        
        _machine.Configure(OrderState.Cancelled)
            .OnEntry(() => CancelOrder());
    }
    
    public async Task ProcessAsync()
    {
        await _machine.FireAsync(OrderTrigger.Process);
    }
    
    public async Task ShipAsync()
    {
        await _machine.FireAsync(OrderTrigger.Ship);
    }
    
    public bool CanProcess() => _machine.CanFire(OrderTrigger.Process);
    public bool CanShip() => _machine.CanFire(OrderTrigger.Ship);
    
    private void ProcessOrder() { /* Processing logic */ }
    private void ShipOrder() { /* Shipping logic */ }
    private void CompleteOrder() { /* Completion logic */ }
    private void CancelOrder() { /* Cancellation logic */ }
}

public enum OrderTrigger
{
    Process,
    Ship,
    Deliver,
    Cancel
}
```

### State Pattern with Async Operations

```csharp
// Async state interface
public interface IAsyncOrderState
{
    OrderStatus Status { get; }
    Task ProcessAsync(Order order);
    Task ShipAsync(Order order);
    Task CancelAsync(Order order);
}

public class AsyncProcessingState : IAsyncOrderState
{
    private readonly IInventoryService _inventory;
    private readonly IPaymentService _payment;
    private readonly ILogger _logger;
    
    public OrderStatus Status => OrderStatus.Processing;
    
    public async Task ProcessAsync(Order order)
    {
        throw new InvalidOperationException("Already processing");
    }
    
    public async Task ShipAsync(Order order)
    {
        _logger.LogInformation("Shipping order {OrderId}", order.Id);
        
        // Reserve inventory
        await _inventory.ReserveItemsAsync(order.Items);
        
        // Process payment
        var paymentResult = await _payment.ChargeAsync(order.TotalAmount);
        
        if (!paymentResult.Success)
        {
            await _inventory.ReleaseItemsAsync(order.Items);
            throw new PaymentFailedException();
        }
        
        order.SetState(new ShippedState());
    }
    
    public async Task CancelAsync(Order order)
    {
        await _inventory.ReleaseItemsAsync(order.Items);
        order.SetState(new CancelledState());
    }
}
```

### Hierarchical State Machine

```csharp
// State machine with nested states
public abstract class CompositeState : IOrderState
{
    protected List<IOrderState> _substates = new();
    protected IOrderState _currentSubstate;
    
    public abstract OrderStatus Status { get; }
    
    public virtual void Process(Order order)
    {
        _currentSubstate?.Process(order);
    }
    
    protected void TransitionToSubstate(IOrderState substate)
    {
        _currentSubstate?.OnExit();
        _currentSubstate = substate;
        _currentSubstate.OnEntry();
    }
}

public class FulfillmentState : CompositeState
{
    public override OrderStatus Status => OrderStatus.Fulfilling;
    
    public FulfillmentState()
    {
        _substates.Add(new PackingSubstate());
        _substates.Add(new QualityCheckSubstate());
        _substates.Add(new LabelingSubstate());
        _currentSubstate = _substates.First();
    }
    
    public override void Process(Order order)
    {
        _currentSubstate.Process(order);
        
        // Move to next substate if current is complete
        var currentIndex = _substates.IndexOf(_currentSubstate);
        if (currentIndex < _substates.Count - 1)
        {
            TransitionToSubstate(_substates[currentIndex + 1]);
        }
        else
        {
            // All substates complete, transition to shipped
            order.SetState(new ShippedState());
        }
    }
}
```

## Common Pitfalls

**1. Too Many States**
```csharp
// BAD - State explosion
public class OrderStateMachine
{
    // States for every minor variation
    PendingWithPayment, PendingWithoutPayment,
    ProcessingStandardShipping, ProcessingExpressShipping,
    // ... 50 more states
}

// GOOD - Use state data instead
public class ProcessingState
{
    private readonly ShippingMethod _shippingMethod;
    // State behavior adapts based on data
}
```

**2. State Logic in Context**
```csharp
// BAD - Context has state logic
public class Order
{
    public void Ship()
    {
        if (Status == OrderStatus.Pending)
        {
            // State-specific logic in context
        }
    }
}

// GOOD - Logic in state classes
public class PendingState : IOrderState
{
    public void Ship(Order order)
    {
        // State-specific logic here
    }
}
```

## Self-Check Questions

1. **What advantages does State pattern provide over if/else chains?**
   - Eliminates complex conditionals
   - Each state is self-contained and testable
   - Easy to add new states without modifying existing code
   - Makes state transitions explicit and traceable

2. **How does State pattern relate to finite state machines?**
   - State pattern implements FSM programmatically
   - Each state class represents FSM state
   - Transitions are method calls that change state
   - Can enforce valid transitions

3. **When should you use State pattern vs Strategy pattern?**
   - State: Object behavior depends on internal state that changes
   - Strategy: Select algorithm/behavior externally, usually doesn't change
   - State transitions are internal, Strategy selection is external

4. **How can you persist state in a database?**
   - Store current state enum/string
   - Reconstruct state object on load
   - Use factory pattern to create correct state
   - Consider storing transition history for audit

5. **What's the difference between State pattern and state machines?**
   - State pattern: Design pattern implementation
   - State machine: Abstract concept/model
   - State pattern is one way to implement state machines

## Key Takeaways

1. **State pattern** encapsulates state-specific behavior in separate classes
2. Eliminates **complex conditionals** and makes code more maintainable
3. **State transitions** become explicit and controllable
4. Each state is **independently testable** and modifiable
5. **Stateless library** provides robust state machine implementation for .NET
6. State pattern promotes **Open-Closed Principle**
7. Consider using **hierarchical states** for complex state machines
8. Always validate **state transitions** to prevent invalid states
