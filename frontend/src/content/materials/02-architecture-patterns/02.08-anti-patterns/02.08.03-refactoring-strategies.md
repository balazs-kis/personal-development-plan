## Introduction

Refactoring is the process of improving code structure without changing its external behavior. It's the primary technique for managing technical debt and maintaining code quality over time. Effective refactoring strategies help teams:
- Maintain velocity as codebases grow
- Reduce bug rates through clearer code structure
- Enable faster onboarding of new team members
- Make code more adaptable to changing requirements

**Refactoring vs Rewriting:**
- Refactoring: Small, incremental improvements with tests providing safety net
- Rewriting: Starting from scratch, high risk, often fails
- Principle: Prefer refactoring, reserve rewrites for truly broken systems

**The Refactoring Mindset:**
Refactoring should be continuous, not a special activity. It's like brushing your teeth—do it regularly in small amounts rather than waiting for a "dental sprint."

### Core Refactoring Techniques

**1. Extract Method**

```csharp
// Before - Long method doing too much
public void ProcessOrder(Order order)
{
    // Validate
    if (string.IsNullOrEmpty(order.CustomerEmail))
        throw new ValidationException("Email required");
    if (!IsValidEmail(order.CustomerEmail))
        throw new ValidationException("Invalid email");
    if (order.Items.Count == 0)
        throw new ValidationException("No items");
    
    // Calculate total
    decimal total = 0;
    foreach (var item in order.Items)
    {
        total += item.Price * item.Quantity;
        if (item.Quantity > 100)
            total *= 0.95m; // Bulk discount
    }
    order.Total = total;
    
    // Apply tax
    if (order.ShippingAddress.Country == "US")
        order.Tax = total * 0.07m;
    else
        order.Tax = total * 0.20m;
    
    // Save
    _context.Orders.Add(order);
    _context.SaveChanges();
}

// After - Extracted methods
public void ProcessOrder(Order order)
{
    ValidateOrder(order);
    CalculateOrderTotal(order);
    CalculateOrderTax(order);
    SaveOrder(order);
}

private void ValidateOrder(Order order)
{
    if (string.IsNullOrEmpty(order.CustomerEmail))
        throw new ValidationException("Email required");
    if (!IsValidEmail(order.CustomerEmail))
        throw new ValidationException("Invalid email");
    if (order.Items.Count == 0)
        throw new ValidationException("No items");
}

private void CalculateOrderTotal(Order order)
{
    order.Total = order.Items.Sum(item => 
    {
        var itemTotal = item.Price * item.Quantity;
        return item.Quantity > 100 ? itemTotal * 0.95m : itemTotal;
    });
}

private void CalculateOrderTax(Order order)
{
    var taxRate = order.ShippingAddress.Country == "US" ? 0.07m : 0.20m;
    order.Tax = order.Total * taxRate;
}

private void SaveOrder(Order order)
{
    _context.Orders.Add(order);
    _context.SaveChanges();
}
```

### Large-Scale Refactoring Strategies

**1. Strangler Fig Pattern**

```csharp
// Old monolithic service
public class LegacyOrderService
{
    public void ProcessOrder(Order order)
    {
        // 500 lines of legacy code
    }
}

// Step 1: Create new service
public class NewOrderService
{
    public async Task ProcessOrderAsync(Order order)
    {
        // New implementation
    }
}

// Step 2: Create facade that routes to old or new
public class OrderServiceFacade
{
    private readonly LegacyOrderService _legacy;
    private readonly NewOrderService _new;
    private readonly IFeatureToggle _features;
    
    public async Task ProcessOrder(Order order)
    {
        if (_features.IsEnabled("UseNewOrderService"))
        {
            await _new.ProcessOrderAsync(order);
        }
        else
        {
            _legacy.ProcessOrder(order);
        }
    }
}

// Step 3: Gradually migrate
// - Enable for 10% of users
// - Monitor metrics
// - Enable for 50%, then 100%
// - Delete legacy code
```

**2. Branch by Abstraction**

```csharp
// Step 1: Extract interface from existing implementation
public interface IPaymentProcessor
{
    Task<PaymentResult> ProcessAsync(Payment payment);
}

public class OldPaymentProcessor : IPaymentProcessor
{
    // Existing implementation
}

// Step 2: Create new implementation
public class NewPaymentProcessor : IPaymentProcessor
{
    // New implementation
}

// Step 3: Use dependency injection to switch
services.AddScoped<IPaymentProcessor>(sp =>
{
    var config = sp.GetRequiredService<IConfiguration>();
    return config["Payment:UseNewProcessor"] == "true"
        ? new NewPaymentProcessor()
        : new OldPaymentProcessor();
});

// Step 4: Test thoroughly, then remove old implementation
```

```csharp
// Original signature
```

```csharp
// Leave code better than you found it

// Scenario: Adding discount code validation feature
public class OrderService
{
    // NEW FEATURE: Validate and apply discount code
    public async Task ApplyDiscountCodeAsync(Order order, string code)
    {

        if (discount == null)
            throw new DomainException("Invalid discount code");
            
        order.ApplyDiscount(discount);
        
        // OPPORTUNISTIC REFACTORING while here
        // Found this method was doing too much, so extracted helper methods:
        await RecalculateOrderTotalAsync(order);  // ← Extracted while here
        await ApplyTaxesAsync(order);             // ← Extracted while here  
        await _repository.SaveAsync(order);       // ← Was inline, extracted
    }
    
    // Helper methods extracted during feature work
    private async Task RecalculateOrderTotalAsync(Order order)
    {
        order.Total = order.Items.Sum(i => i.Price * i.Quantity);
        
        if (order.Discount != null)
            order.Total -= order.Discount.Amount;
    }
    
    private async Task ApplyTaxesAsync(Order order)
    {
        var taxRate = await _taxService.GetTaxRateAsync(order.ShippingAddress);
        order.Tax = order.Total * taxRate;
    }
}

// Time cost: ~15 extra minutes
```

### Managing Refactoring Risks

**Safe Refactoring Checklist:**

```markdown
# Pre-Refactoring Checklist

## 1. Safety Net
- [ ] Comprehensive tests exist
- [ ] Tests passing before refactoring
- [ ] CI/CD pipeline green
- [ ] Can rollback quickly if needed

## 2. Planning
- [ ] Refactoring goal is clear
- [ ] Scope is defined (not "refactor everything")
- [ ] Technique chosen (Extract Method, Replace Conditional, etc.)
- [ ] Estimated time is reasonable

## 3. Communication
- [ ] Team aware of refactoring
- [ ] Stakeholders understand value
- [ ] Branch strategy decided

## 4. Incremental Approach
- [ ] Can be done in small steps
- [ ] Each step leaves code working
- [ ] Can commit frequently

## 5. Monitoring
- [ ] Performance baseline captured
- [ ] Error rates tracked
- [ ] User impact considered
```

**When Refactoring Goes Wrong:**

```csharp
// ANTI-PATTERN: Big Bang Refactoring
public class BigBangRefactoring
{
    // Don't do this:
    // 1. Create feature branch
    // 2. Refactor entire service (2000 lines)
    // 3. Don't commit for 2 weeks
    // 4. Tests break, unsure what caused it
    // 5. Merge conflicts everywhere
    // 6. Give up or force merge, break production
}

// BETTER: Incremental Refactoring
public class IncrementalRefactoring
{
    // Do this instead:
    // Day 1: Extract 1 method, test, commit, merge
    // Day 2: Extract another method, test, commit, merge
    // Day 3: Introduce interface, test, commit, merge
    // Day 4: Move to new class, test, commit, merge
    // Result: Always working code, easy to review, low risk
}
```

**Refactoring Steps:**

**Step 1: Identify Code Smells**
```markdown
1. Long Method (100+ lines in one method)
2. Magic Numbers (100, 0.9m, 0.95m, 587)
3. String concatenation for SQL (SQL injection risk)
4. Mixed concerns (validation, calculation, database, email, logging)
5. Poor error handling (swallowing exceptions)
6. Hardcoded values (connection string, SMTP settings, file path)
7. No dependency injection
8. Not async
9. No parameter object (too many primitive parameters)
10. No separation of data access logic
```

**Step 2: Apply Refactoring Techniques**

```csharp
// 1. Configuration & Constants
public class OrderProcessorConfiguration
{
    public string ConnectionString { get; set; }
    public string SmtpHost { get; set; }
    public int SmtpPort { get; set; }
}

public static class DiscountRules
{
    public const int BulkQuantityThreshold = 100;
    public const decimal BulkDiscountRate = 0.10m;
    public const decimal LoyaltyThreshold = 100m;
    public const decimal LoyaltyDiscountRate = 0.05m;
}

// 2. Parameter Objects
public record ProcessOrderRequest(
    int OrderId,
    string CustomerName,
    string CustomerEmail,
    string Items,
    string ShippingAddress
);

public record OrderItem(string Name, decimal Price, int Quantity);

// 3. Parsing Logic
public class OrderParser
{
    public IEnumerable<OrderItem> ParseItems(string itemsString)
    {
        return itemsString.Split(',')
            .Select(item =>
            {
                var parts = item.Split(':');
                return new OrderItem(parts[0], decimal.Parse(parts[1]), int.Parse(parts[2]));
            });
    }
}

// 4. Calculation Logic
public class OrderCalculator
{
    public decimal CalculateTotal(IEnumerable<OrderItem> items)
    {
        var subtotal = items.Sum(item => CalculateItemTotal(item));
        return ApplyLoyaltyDiscount(subtotal);
    }
    
    private decimal CalculateItemTotal(OrderItem item)
    {
        var itemTotal = item.Price * item.Quantity;
        if (item.Quantity > DiscountRules.BulkQuantityThreshold)
            itemTotal *= (1 - DiscountRules.BulkDiscountRate);
        return itemTotal;
    }
    
    private decimal ApplyLoyaltyDiscount(decimal subtotal)
    {
        return subtotal > DiscountRules.LoyaltyThreshold 
            ? subtotal * (1 - DiscountRules.LoyaltyDiscountRate)
            : subtotal;
    }
}

// 5. Repository Pattern
public interface IOrderRepository
{
    Task SaveOrderAsync(Order order);
}

public class SqlOrderRepository : IOrderRepository
{
    private readonly string _connectionString;
    
    public SqlOrderRepository(IConfiguration config)
    {
        _connectionString = config.GetConnectionString("Default");
    }
    
    public async Task SaveOrderAsync(Order order)
    {
        await using var connection = new SqlConnection(_connectionString);
        var sql = "INSERT INTO Orders (Id, Customer, Total, Address) VALUES (@Id, @Customer, @Total, @Address)";
        await connection.ExecuteAsync(sql, new { order.Id, order.Customer, order.Total, order.Address });
    }
}

// 6. Email Service
public interface IEmailService
{
    Task SendOrderConfirmationAsync(int orderId, string customerEmail, decimal total);
}

public class SmtpEmailService : IEmailService
{
    private readonly ILogger<SmtpEmailService> _logger;
    private readonly OrderProcessorConfiguration _config;
    
    public async Task SendOrderConfirmationAsync(int orderId, string customerEmail, decimal total)
    {
        try
        {
            using var client = new SmtpClient(_config.SmtpHost, _config.SmtpPort);
            var message = new MailMessage(
                _config.OrderEmailFrom,
                customerEmail,
                "Order Confirmation",
                $"Your order #{orderId} total is ${total:F2}"
            );
            await client.SendMailAsync(message);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Failed to send email for order {OrderId}", orderId);
            throw;
        }
    }
}

// 7. Validation
public class OrderValidator
{
    public void Validate(ProcessOrderRequest request)
    {
        if (string.IsNullOrWhiteSpace(request.CustomerName))
            throw new ValidationException("Customer name is required");
        if (string.IsNullOrWhiteSpace(request.CustomerEmail))
            throw new ValidationException("Customer email is required");
        if (string.IsNullOrWhiteSpace(request.Items))
            throw new ValidationException("Order must contain items");
    }
}

// 8. Final Orchestrator
public class OrderProcessor
{
    private readonly OrderValidator _validator;
    private readonly OrderParser _parser;
    private readonly OrderCalculator _calculator;
    private readonly IOrderRepository _repository;
    private readonly IEmailService _emailService;
    private readonly ILogger<OrderProcessor> _logger;
    
    public async Task ProcessAsync(ProcessOrderRequest request)
    {
        _validator.Validate(request);
        var items = _parser.ParseItems(request.Items);
        var total = _calculator.CalculateTotal(items);
        var order = new Order(request.OrderId, request.CustomerName, total, request.ShippingAddress);
        
        await _repository.SaveOrderAsync(order);
        await _emailService.SendOrderConfirmationAsync(request.OrderId, request.CustomerEmail, total);
        
        _logger.LogInformation("Order {OrderId} processed. Total: {Total:C}", request.OrderId, total);
    }
}
```

## Self-Check Questions

1. **What's the difference between refactoring and rewriting?**
   - Refactoring: Incremental improvements, behavior unchanged, tests ensure safety
   - Rewriting: Start from scratch, high risk, often over-budget and delayed
   - Rule: Prefer refactoring, rewrite only when fundamentally broken

2. **When should you refactor, and when should you leave code as-is?**
   - Refactor when: About to add feature, fixing bug nearby, code is hard to understand
   - Leave when: Works well, no changes needed, rewrite cheaper than refactor
   - Boy Scout Rule: Always make small improvements when touching code

3. **How do you refactor safely without breaking things?**
   - Tests first: Comprehensive test suite before refactoring
   - Small steps: One refactoring at a time, tests pass after each
   - Version control: Commit frequently, can rollback easily
   - Continuous Integration: Automated tests catch regressions immediately

4. **What's the Strangler Fig pattern, and when is it useful?**
   - Pattern: Gradually replace legacy system by "strangling" it with new implementation
   - How: New code handles new features, gradually migrate old features
   - When: Legacy system too risky to replace at once, need to maintain operation
   - Alternative to: Big Bang rewrite (which usually fails)

5. **How do you prioritize which code to refactor first?**
   - Impact/Effort matrix: High impact, low effort first
   - Pain points: Where bugs cluster, where velocity slows
   - Change frequency: Refactor code that changes often
   - Business value: Refactor code supporting critical features

6. **What role do tests play in refactoring?**
   - Safety net: Confirm behavior unchanged
   - Confidence: Refactor fearlessly with passing tests
   - Documentation: Tests describe expected behavior
   - Design feedback: Hard to test? Probably needs refactoring

---

## Key Takeaways

- **Refactoring is continuous:** Not a special activity, part of every day
- **Small steps are safer:** Many small refactorings beat one big rewrite
- **Tests are essential:** Can't refactor safely without them
- **Balance is key:** 80% features, 20% refactoring is sustainable
- **Patterns help:** Strangler Fig, Branch by Abstraction for large changes
- **Tools assist:** Roslyn analyzers, SonarQube, EditorConfig enforce quality
- **Team practices matter:** Pairing, code reviews, shared standards
- **Measure progress:** Track metrics, show improvement over time

**The Golden Rule:** Make it work, make it right, make it fast—in that order.
