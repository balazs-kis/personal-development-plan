# Lesson 1: Factory Method and Abstract Factory

## Learning Objectives
- Implement Factory Method and Abstract Factory patterns
- Use factories for object creation flexibility
- Apply factory patterns in .NET with DI
- Choose between different factory patterns

## Introduction

Factory patterns encapsulate object creation logic, providing flexibility and loose coupling between client code and the concrete classes it uses. This lesson covers Factory Method and Abstract Factory patterns with modern .NET implementations.

## Key Concepts Summary

### Why Use Factories?

**Problem:**
```csharp
// Tight coupling - client knows about all concrete types
public class OrderProcessor
{
    public void ProcessOrder(Order order, string paymentType)
    {
        IPaymentProcessor processor;
        
        if (paymentType == "creditcard")
            processor = new CreditCardProcessor();
        else if (paymentType == "paypal")
            processor = new PayPalProcessor();
        else if (paymentType == "crypto")
            processor = new CryptoProcessor();
        else
            throw new ArgumentException("Unknown payment type");
        
        processor.Process(order);
    }
}
```

### Factory Method Pattern

**Definition:** Define an interface for creating an object, but let subclasses decide which class to instantiate.

```csharp
// Product interface
public interface IPaymentProcessor
{
    PaymentResult Process(PaymentRequest request);
}

// Concrete products
public class CreditCardProcessor : IPaymentProcessor
{
    public PaymentResult Process(PaymentRequest request)
    {
        // Credit card processing logic
        return new PaymentResult { Success = true };
    }
}

public class PayPalProcessor : IPaymentProcessor
{
    public PaymentResult Process(PaymentRequest request)
    {
        // PayPal processing logic
        return new PaymentResult { Success = true };
    }
}

// Creator (Factory)
public abstract class PaymentProcessorFactory
{
    // Factory method
    public abstract IPaymentProcessor CreateProcessor();
    
    // Template method that uses the factory method
    public PaymentResult ProcessPayment(PaymentRequest request)
    {
        var processor = CreateProcessor();
        return processor.Process(request);
    }
}

// Concrete creators
public class CreditCardProcessorFactory : PaymentProcessorFactory
{
    public override IPaymentProcessor CreateProcessor()
    {
        return new CreditCardProcessor();
    }
}

public class PayPalProcessorFactory : PaymentProcessorFactory
{
    public override IPaymentProcessor CreateProcessor()
    {
        return new PayPalProcessor();
    }
}

// Usage
var factory = new CreditCardProcessorFactory();
var result = factory.ProcessPayment(request);
```

### Simple Factory (Static Factory)

```csharp
// Simpler alternative when inheritance isn't needed
public static class PaymentProcessorFactory
{
    public static IPaymentProcessor Create(PaymentMethod method)
    {
        return method switch
        {
            PaymentMethod.CreditCard => new CreditCardProcessor(),
            PaymentMethod.PayPal => new PayPalProcessor(),
            PaymentMethod.Crypto => new CryptoProcessor(),
            _ => throw new ArgumentException($"Unknown payment method: {method}")
        };
    }
}

// Usage
var processor = PaymentProcessorFactory.Create(PaymentMethod.CreditCard);
var result = processor.Process(request);
```

### Factory with Dependency Injection

```csharp
// Modern approach: Use DI container as factory
public interface IPaymentProcessorFactory
{
    IPaymentProcessor Create(PaymentMethod method);
}

public class PaymentProcessorFactory : IPaymentProcessorFactory
{
    private readonly IServiceProvider _serviceProvider;
    
    public PaymentProcessorFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }
    
    public IPaymentProcessor Create(PaymentMethod method)
    {
        return method switch
        {
            PaymentMethod.CreditCard => _serviceProvider.GetRequiredService<CreditCardProcessor>(),
            PaymentMethod.PayPal => _serviceProvider.GetRequiredService<PayPalProcessor>(),
            PaymentMethod.Crypto => _serviceProvider.GetRequiredService<CryptoProcessor>(),
            _ => throw new ArgumentException($"Unknown payment method: {method}")
        };
    }
}

// Registration
services.AddTransient<CreditCardProcessor>();
services.AddTransient<PayPalProcessor>();
services.AddTransient<CryptoProcessor>();
services.AddSingleton<IPaymentProcessorFactory, PaymentProcessorFactory>();
```

### Abstract Factory Pattern

**Definition:** Provide an interface for creating families of related or dependent objects without specifying their concrete classes.

```csharp
// Abstract products
public interface IButton
{
    void Render();
}

public interface ICheckbox
{
    void Render();
}

// Concrete products - Windows family
public class WindowsButton : IButton
{
    public void Render() => Console.WriteLine("Rendering Windows button");
}

public class WindowsCheckbox : ICheckbox
{
    public void Render() => Console.WriteLine("Rendering Windows checkbox");
}

// Concrete products - Mac family
public class MacButton : IButton
{
    public void Render() => Console.WriteLine("Rendering Mac button");
}

public class MacCheckbox : ICheckbox
{
    public void Render() => Console.WriteLine("Rendering Mac checkbox");
}

// Abstract factory
public interface IUIFactory
{
    IButton CreateButton();
    ICheckbox CreateCheckbox();
}

// Concrete factories
public class WindowsUIFactory : IUIFactory
{
    public IButton CreateButton() => new WindowsButton();
    public ICheckbox CreateCheckbox() => new WindowsCheckbox();
}

public class MacUIFactory : IUIFactory
{
    public IButton CreateButton() => new MacButton();
    public ICheckbox CreateCheckbox() => new MacCheckbox();
}

// Client code
public class Application
{
    private readonly IUIFactory _factory;
    
    public Application(IUIFactory factory)
    {
        _factory = factory;
    }
    
    public void RenderUI()
    {
        var button = _factory.CreateButton();
        var checkbox = _factory.CreateCheckbox();
        
        button.Render();
        checkbox.Render();
    }
}

// Usage
IUIFactory factory = OperatingSystem.IsWindows() 
    ? new WindowsUIFactory() 
    : new MacUIFactory();

var app = new Application(factory);
app.RenderUI();
```

### Real-World Example: Report Generation

```csharp
// Abstract factory for report generation
public interface IReportFactory
{
    IReportGenerator CreateGenerator();
    IReportFormatter CreateFormatter();
    IReportExporter CreateExporter();
}

// PDF Report family
public class PdfReportFactory : IReportFactory
{
    public IReportGenerator CreateGenerator() => new PdfReportGenerator();
    public IReportFormatter CreateFormatter() => new PdfFormatter();
    public IReportExporter CreateExporter() => new PdfExporter();
}

// Excel Report family
public class ExcelReportFactory : IReportFactory
{
    public IReportGenerator CreateGenerator() => new ExcelReportGenerator();
    public IReportFormatter CreateFormatter() => new ExcelFormatter();
    public IReportExporter CreateExporter() => new ExcelExporter();
}

// Report service
public class ReportService
{
    public async Task<byte[]> GenerateReport(ReportData data, ReportType type)
    {
        IReportFactory factory = type switch
        {
            ReportType.Pdf => new PdfReportFactory(),
            ReportType.Excel => new ExcelReportFactory(),
            ReportType.Html => new HtmlReportFactory(),
            _ => throw new ArgumentException("Unknown report type")
        };
        
        var generator = factory.CreateGenerator();
        var formatter = factory.CreateFormatter();
        var exporter = factory.CreateExporter();
        
        var report = await generator.Generate(data);
        var formatted = formatter.Format(report);
        return exporter.Export(formatted);
    }
}
```

### Functional Factory Pattern (Modern C#)

```csharp
// Using delegates/functions as factories
public delegate IPaymentProcessor PaymentProcessorFactory();

// Registration
var factories = new Dictionary<PaymentMethod, PaymentProcessorFactory>

    [PaymentMethod.PayPal] = () => new PayPalProcessor(),
    [PaymentMethod.Crypto] = () => new CryptoProcessor()

// Usage

var processor = factory();
```

### Factory with Configuration

```csharp
// Factory that uses configuration to determine which implementation to create
public interface IDatabaseConnectionFactory
{
    IDbConnection CreateConnection();
}

public class ConfigurableDatabaseFactory : IDatabaseConnectionFactory
{
    private readonly DatabaseConfiguration _config;
    
    public ConfigurableDatabaseFactory(IOptions<DatabaseConfiguration> config)
    {
        _config = config.Value;
    }
    
    public IDbConnection CreateConnection()
    {
        return _config.Provider switch
        {
            "SqlServer" => new SqlConnection(_config.ConnectionString),
            "PostgreSQL" => new NpgsqlConnection(_config.ConnectionString),
            "MySQL" => new MySqlConnection(_config.ConnectionString),
            "SQLite" => new SQLiteConnection(_config.ConnectionString),
            _ => throw new NotSupportedException($"Database provider '{_config.Provider}' is not supported")
        };
    }
}

// appsettings.json
{
  "Database": {
    "Provider": "PostgreSQL",
    "ConnectionString": "Host=localhost;Database=mydb;..."
  }
}

// Registration
services.Configure<DatabaseConfiguration>(configuration.GetSection("Database"));
services.AddSingleton<IDatabaseConnectionFactory, ConfigurableDatabaseFactory>();

// Usage in services
public class UserRepository
{
    private readonly IDatabaseConnectionFactory _connectionFactory;
    
    public UserRepository(IDatabaseConnectionFactory connectionFactory)
    {
        _connectionFactory = connectionFactory;
    }
    
    public async Task<User> GetUserById(int id)
    {
        using var connection = _connectionFactory.CreateConnection();
        await connection.OpenAsync();
        // Query execution...
    }
}
```

### Factory with Lazy Initialization

```csharp
// Factory that creates instances lazily only when needed
public interface IDocumentProcessorFactory
{
    IDocumentProcessor GetProcessor(string fileType);
}

public class LazyDocumentProcessorFactory : IDocumentProcessorFactory
{
    private readonly IServiceProvider _serviceProvider;
    private readonly Dictionary<string, Lazy<IDocumentProcessor>> _processors;
    
    public LazyDocumentProcessorFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
        _processors = new Dictionary<string, Lazy<IDocumentProcessor>>
        {
            [".pdf"] = new Lazy<IDocumentProcessor>(() => 
                serviceProvider.GetRequiredService<PdfProcessor>()),
            [".docx"] = new Lazy<IDocumentProcessor>(() => 
                serviceProvider.GetRequiredService<WordProcessor>()),
            [".xlsx"] = new Lazy<IDocumentProcessor>(() => 
                serviceProvider.GetRequiredService<ExcelProcessor>())
        };
    }
    
    public IDocumentProcessor GetProcessor(string fileType)
    {
        if (_processors.TryGetValue(fileType.ToLower(), out var lazyProcessor))
            return lazyProcessor.Value;
        
        throw new NotSupportedException($"File type '{fileType}' is not supported");
    }
}
```

### Named Factory Pattern with Keyed Services (.NET 8+)

```csharp
// Register multiple implementations with keys
services.AddKeyedTransient<IPaymentProcessor, CreditCardProcessor>("CreditCard");
services.AddKeyedTransient<IPaymentProcessor, PayPalProcessor>("PayPal");
services.AddKeyedTransient<IPaymentProcessor, CryptoProcessor>("Crypto");

// Factory that uses keyed services
public class PaymentProcessorFactory : IPaymentProcessorFactory
{
    private readonly IServiceProvider _serviceProvider;
    
    public PaymentProcessorFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }
    
    public IPaymentProcessor Create(PaymentMethod method)
    {
        var key = method.ToString();
        return _serviceProvider.GetRequiredKeyedService<IPaymentProcessor>(key);
    }
}

// Or inject directly
public class OrderService
{
    private readonly IPaymentProcessor _creditCardProcessor;
    private readonly IPaymentProcessor _paypalProcessor;
    
    public OrderService(
        [FromKeyedServices("CreditCard")] IPaymentProcessor creditCardProcessor,
        [FromKeyedServices("PayPal")] IPaymentProcessor paypalProcessor)
    {
        _creditCardProcessor = creditCardProcessor;
        _paypalProcessor = paypalProcessor;
    }
}
```

### Testing Factories

```csharp
// Factory for testing - makes it easy to inject test doubles
public interface IHttpClientFactory
{
    HttpClient CreateClient(string name = "default");
}

// Real implementation
public class DefaultHttpClientFactory : IHttpClientFactory
{
    private readonly IHttpClientFactory _innerFactory;
    
    public DefaultHttpClientFactory(IHttpClientFactory innerFactory)
    {
        _innerFactory = innerFactory;
    }
    
    public HttpClient CreateClient(string name = "default")
    {
        return _innerFactory.CreateClient(name);
    }
}

// Test implementation
public class TestHttpClientFactory : IHttpClientFactory
{
    private readonly HttpMessageHandler _handler;
    
    public TestHttpClientFactory(HttpMessageHandler handler)
    {
        _handler = handler;
    }
    
    public HttpClient CreateClient(string name = "default")
    {

// Usage in tests
[Fact]
public async Task GetUser_ReturnsDeserializedUser()
```

### Anti-Pattern: Anemic Factory

```csharp
// BAD - Factory that doesn't add value
public class UserFactory
{
    public User CreateUser(string name, string email)
    {
        return new User { Name = name, Email = email };
    }
}

// GOOD - Just use constructor or object initializer
var user = new User { Name = "John", Email = "john@example.com" };

// Factories are only valuable when:
// 1. Complex creation logic
// 2. Need to abstract concrete types
// 3. Runtime selection of implementations
// 4. Managing dependencies/resources
```

### Performance Considerations

```csharp
// For hot paths, cache factory instances
public class CachedPaymentProcessorFactory : IPaymentProcessorFactory
{
    private readonly IServiceProvider _serviceProvider;
    private readonly ConcurrentDictionary<PaymentMethod, IPaymentProcessor> _cache = new();
    
    public CachedPaymentProcessorFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }
    
    public IPaymentProcessor Create(PaymentMethod method)
    {
        return _cache.GetOrAdd(method, CreateProcessor);
    }
    
    private IPaymentProcessor CreateProcessor(PaymentMethod method)
    {
        return method switch
        {
            PaymentMethod.CreditCard => _serviceProvider.GetRequiredService<CreditCardProcessor>(),
            PaymentMethod.PayPal => _serviceProvider.GetRequiredService<PayPalProcessor>(),
            _ => throw new ArgumentException($"Unknown payment method: {method}")
        };
    }
}

// Note: Only cache if processors are stateless and thread-safe!
```

### When to Use Which Pattern

| Pattern | Use When | Example |
|---------|----------|---------|
| **Simple Factory** | Single product hierarchy, simple creation logic | Creating loggers based on environment |
| **Factory Method** | Subclasses need to specify which class to instantiate | Template method with customizable object creation |
| **Abstract Factory** | Need to create families of related objects | UI components for different platforms |
| **DI Container** | Modern applications with dependency injection | Most .NET applications |
| **Keyed Services** | Multiple implementations of same interface (.NET 8+) | Named HttpClient instances |
| **Functional Factory** | Simple, stateless object creation | Mapping enums to implementations |

### Common Mistakes to Avoid

1. **Over-engineering:** Don't use factories for simple object creation
2. **Service Locator Anti-Pattern:** Don't inject `IServiceProvider` everywhere
3. **Stateful Factories:** Keep factories stateless and thread-safe
4. **Factory in Factory:** Avoid nested factory patterns unless truly necessary
5. **No Validation:** Always validate inputs and configurations in factories

**Scenario:** Document processing system

Create a factory system that can create different document processors:

1. **Product Interface:**
   - `IDocumentProcessor` with methods: `Parse()`, `Validate()`, `Save()`

2. **Concrete Products:**
   - `PdfDocumentProcessor`

**Example Solution Structure:**

```csharp
// 1. Product interface
public interface IDocumentProcessor
{
    Task<DocumentData> Parse(Stream stream);
    ValidationResult Validate(DocumentData data);
    Task Save(DocumentData data, Stream outputStream);
}

// 2. Concrete products
public class PdfDocumentProcessor : IDocumentProcessor
{
    public async Task<DocumentData> Parse(Stream stream) 
    { 
        // PDF parsing logic
        return new DocumentData();
    }
    
    public ValidationResult Validate(DocumentData data) 
    { 
        return ValidationResult.Success;
    }
    
    public async Task Save(DocumentData data, Stream outputStream) 
    { 
        // PDF saving logic
    }
}

// 3. Factory
public interface IDocumentProcessorFactory
{
    IDocumentProcessor CreateProcessor(string fileExtension);
    bool SupportsExtension(string extension);
}

public class DocumentProcessorFactory : IDocumentProcessorFactory
{
    private readonly IServiceProvider _serviceProvider;
    private readonly Dictionary<string, Type> _processors;
    
    public DocumentProcessorFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
        _processors = new Dictionary<string, Type>
        {
            [".pdf"] = typeof(PdfDocumentProcessor),
            [".docx"] = typeof(WordDocumentProcessor),
            [".xlsx"] = typeof(ExcelDocumentProcessor)
        };
    }
    
    public IDocumentProcessor CreateProcessor(string fileExtension)
    {
        var ext = fileExtension.ToLower();
        if (!_processors.TryGetValue(ext, out var processorType))
        {
            throw new NotSupportedException($"File extension '{fileExtension}' is not supported");
        }
        
        return (IDocumentProcessor)_serviceProvider.GetRequiredService(processorType);
    }
    
    public bool SupportsExtension(string extension)
    {
        return _processors.ContainsKey(extension.ToLower());
    }
}

// Registration
services.AddTransient<PdfDocumentProcessor>();
services.AddTransient<WordDocumentProcessor>();
services.AddTransient<ExcelDocumentProcessor>();
services.AddSingleton<IDocumentProcessorFactory, DocumentProcessorFactory>();
```

## Real-World Scenario

**E-commerce Payment Processing System**

Consider building a payment processing system that must support multiple payment providers:

**Requirements:**
- Support credit cards (Stripe), PayPal, and cryptocurrency (Coinbase)
- Each provider has different APIs and requirements
- Need to add new providers without changing existing code
- Must work with dependency injection
- Support transaction logging and retry logic

**Solution Approach:**

```csharp
// 1. Define common payment abstraction
public interface IPaymentProcessor
{
    Task<PaymentResult> ProcessPayment(PaymentRequest request);
    Task<RefundResult> RefundPayment(string transactionId, decimal amount);
    Task<PaymentStatus> GetPaymentStatus(string transactionId);
}

// 2. Implement provider-specific processors
public class StripePaymentProcessor : IPaymentProcessor
{
    private readonly StripeClient _client;
    private readonly ILogger<StripePaymentProcessor> _logger;
    
    public StripePaymentProcessor(
        IOptions<StripeSettings> settings,
        ILogger<StripePaymentProcessor> logger)
    {
        _client = new StripeClient(settings.Value.ApiKey);
        _logger = logger;
    }
    
    public async Task<PaymentResult> ProcessPayment(PaymentRequest request)
    {
        try
        {
            var charge = await _client.Charges.CreateAsync(new ChargeCreateOptions
            {
                Amount = (long)(request.Amount * 100),
                Currency = request.Currency,
                Source = request.PaymentMethodToken
            });
            
            return new PaymentResult 
            { 
                Success = true, 
                TransactionId = charge.Id 
            };
        }
        catch (StripeException ex)
        {
            _logger.LogError(ex, "Stripe payment failed");
            return new PaymentResult 
            { 
                Success = false, 
                ErrorMessage = ex.Message 
            };
        }
    }
    
    // Other methods...
}

// 3. Factory with strategy selection
public interface IPaymentProcessorFactory
{
    IPaymentProcessor GetProcessor(PaymentProvider provider);
}

public class PaymentProcessorFactory : IPaymentProcessorFactory
{
    private readonly IServiceProvider _serviceProvider;
    
    public PaymentProcessorFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }
    
    public IPaymentProcessor GetProcessor(PaymentProvider provider)
    {
        return provider switch
        {
            PaymentProvider.Stripe => _serviceProvider.GetRequiredService<StripePaymentProcessor>(),
            PaymentProvider.PayPal => _serviceProvider.GetRequiredService<PayPalPaymentProcessor>(),
            PaymentProvider.Coinbase => _serviceProvider.GetRequiredService<CoinbasePaymentProcessor>(),
            _ => throw new ArgumentException($"Unknown payment provider: {provider}")
        };
    }
}

// 4. Service that uses the factory
public class PaymentService
{
    private readonly IPaymentProcessorFactory _processorFactory;
    private readonly ILogger<PaymentService> _logger;
    
    public PaymentService(
        IPaymentProcessorFactory processorFactory,
        ILogger<PaymentService> logger)
    {
        _processorFactory = processorFactory;
        _logger = logger;
    }
    
    public async Task<PaymentResult> ProcessPayment(Order order)
    {
        var processor = _processorFactory.GetProcessor(order.PaymentProvider);
        
        var request = new PaymentRequest
        {
            Amount = order.Total,
            Currency = order.Currency,
            PaymentMethodToken = order.PaymentToken
        };
        
        var result = await processor.ProcessPayment(request);
        
        if (result.Success)
        {
            _logger.LogInformation(
                "Payment processed successfully: {TransactionId}", 
                result.TransactionId);
        }
        
        return result;
    }
}
```

**Key Benefits:**
- **Open/Closed Principle:** Add new payment providers without modifying existing code
- **Testability:** Easy to mock factories and inject test implementations
- **Flexibility:** Switch payment providers at runtime based on business rules
- **Maintainability:** Each processor is isolated and focused on one provider

## Self-Check Questions

1. **What's the difference between Factory Method and Abstract Factory?**
   - Factory Method: Single product, subclasses decide implementation
   - Abstract Factory: Families of related products

2. **When would you use a Simple Factory vs Factory Method?**
   - Simple Factory: When you don't need inheritance/polymorphism in the factory itself
   - Factory Method: When the creation process needs to be overridden by subclasses

3. **How do modern DI containers act as factories?**
   - They manage object creation, lifecycle, and dependency resolution
   - Replace manual factory code with configuration-based registration

4. **What problem do factory patterns solve?**
   - Decouple object creation from usage
   - Enable runtime selection of implementations
   - Centralize complex creation logic
   - Support dependency injection

5. **When should you NOT use a factory?**
   - Simple object creation with no logic
   - No variation in implementation
   - Objects with no dependencies
   - When direct instantiation is clearer

6. **How do you test code that uses factories?**
   - Mock the factory interface
   - Inject test implementations through the factory
   - Verify factory calls in tests
