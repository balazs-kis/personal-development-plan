## Introduction

Token validation is critical for application security. Many OAuth 2.0 and OIDC vulnerabilities arise from improper token handling: accepting unsigned tokens, skipping audience validation, or trusting unverified data. This lesson covers the essential security checklist for working with tokens safely.

**Core principle:** Never trust a token until you've validated every critical claim.

## Key Concepts Summary

### The Token Validation Checklist

Every token must pass these validation steps before you trust it:

```
┌─────────────────────────────────────────────────────┐
│ CRITICAL VALIDATIONS (Must pass ALL)               │
├─────────────────────────────────────────────────────┤
│ ✓ 1. Signature is valid                            │
│ ✓ 2. Issuer (iss) is expected                      │
│ ✓ 3. Audience (aud) matches your app/API           │
│ ✓ 4. Expiration (exp) has not passed               │
│ ✓ 5. Not before (nbf) time has passed (if present) │
│ ✓ 6. Nonce matches (for ID tokens with nonce)      │
│ ✓ 7. Algorithm (alg) is expected and secure        │
└─────────────────────────────────────────────────────┘

Skip ANY of these → Security vulnerability
```

## 1. Signature Validation

### Why It Matters

The signature ensures the token hasn't been tampered with and was issued by a trusted authority.

```
Token = Header.Payload.Signature
        ───────────────  ↑
             │           │
             └───────────┴──── Signature cryptographically
                               proves these haven't changed
```

### How to Validate

**Step 1: Get the signing keys from JWKS (JSON Web Key Set)**

```csharp
// JWKS endpoint from discovery document
var jwksUri = "https://auth.example.com/.well-known/jwks.json";

public async Task<IList<SecurityKey>> GetSigningKeysAsync()
{
    var httpClient = new HttpClient();
    var response = await httpClient.GetStringAsync(jwksUri);
    var jwks = JsonConvert.DeserializeObject<JsonWebKeySet>(response);
    return jwks.GetSigningKeys();
}
```

**Example JWKS response:**
```json
{
  "keys": [
    {
      "kty": "RSA",
      "use": "sig",
      "kid": "abc123",
      "n": "0vx7agoebGcQ...",
      "e": "AQAB"
    }
  ]
}
```

**Step 2: Validate using the public key**

```csharp
var tokenHandler = new JwtSecurityTokenHandler();
var validationParameters = new TokenValidationParameters
{
    ValidateIssuerSigningKey = true,
    IssuerSigningKeys = await GetSigningKeysAsync(),
    
    // Other validations...
};

try
{
    var principal = tokenHandler.ValidateToken(token, validationParameters, 
        out SecurityToken validatedToken);
    // Token signature is valid
}
catch (SecurityTokenInvalidSignatureException)
{
    // Token has been tampered with
    throw;
}
```

### Common Signature Attacks

#### Attack: "None" Algorithm

```json
// Attacker modifies header
{
  "alg": "none",  // ← Claims no signature needed
  "typ": "JWT"
}
```

**Defense:**
```csharp
// Explicitly require algorithms
tokenValidationParameters.ValidAlgorithms = new[] { "RS256", "RS384", "RS512" };

// NEVER accept "none"
if (token.Header.Alg == "none")
    throw new SecurityTokenInvalidAlgorithmException("Algorithm 'none' not allowed");
```

#### Attack: Algorithm Confusion (HS256 vs RS256)

Attacker changes algorithm from RS256 (asymmetric) to HS256 (symmetric) and signs with the public key.

**Defense:**
```csharp
// Whitelist expected algorithms only
ValidAlgorithms = new[] { "RS256" }  // Don't accept HS256 if you expect RS256
```

## 2. Issuer Validation

### Why It Matters

Ensures the token was issued by your trusted authorization server, not a malicious impersonator.

```csharp
var validationParameters = new TokenValidationParameters
{
    ValidateIssuer = true,
    ValidIssuer = "https://auth.example.com",  // Exact match required
    
    // Or multiple issuers
    ValidIssuers = new[]
    {
        "https://auth.example.com",
        "https://auth.example.org"
    }
};
```

### Common Mistakes

```csharp
// ❌ WRONG: Not validating issuer
ValidateIssuer = false

// ❌ WRONG: Accepting any issuer
ValidIssuer = null

// ✅ CORRECT: Explicit expected issuer
ValidIssuer = "https://auth.example.com"
```

## 3. Audience Validation

### Why It Matters

The most commonly skipped validation. Ensures the token was intended for **your** application or API.

### For ID Tokens (Client Application)

```csharp
// ID Token audience should be your client ID
var validationParameters = new TokenValidationParameters
{
    ValidateAudience = true,
    ValidAudience = "your-client-id",  // Your OAuth client ID
};
```

### For Access Tokens (API)

```csharp
// Access Token audience should be your API identifier
var validationParameters = new TokenValidationParameters
{
    ValidateAudience = true,
    ValidAudience = "https://api.example.com",  // Your API URL or identifier
};
```

### Attack Scenario: Missing Audience Validation

```
1. Attacker gets valid token for "api.attacker.com"
2. Attacker sends token to "api.victim.com"
3. If api.victim.com doesn't validate audience...
4. Token is accepted (wrong!)
```

**Defense:**
```csharp
// Always validate audience
ValidateAudience = true,
ValidAudience = "https://api.victim.com"

// Token with "aud": "api.attacker.com" will be rejected ✓
```

## 4. Expiration Validation

### Why It Matters

Tokens should be short-lived. Expired tokens must be rejected.

```csharp
var validationParameters = new TokenValidationParameters
{
    ValidateLifetime = true,
    ClockSkew = TimeSpan.FromMinutes(5),  // Allow 5 min clock skew
};
```

### Clock Skew

Different servers may have slightly different clocks. Clock skew allows a small time buffer:

```
Token expires at: 12:00:00
Current time:     12:02:00
Clock skew:       5 minutes

Result: Token accepted (within skew tolerance)

But at 12:06:00 → Rejected (beyond skew)
```

**Recommendation:** Keep clock skew small (5 minutes maximum).

## 5. Not Before (nbf) Validation

### Why It Matters

Prevents accepting tokens that aren't valid yet.

```json
{
  "iat": 1641234000,  // Issued at: Jan 3, 2022 12:00:00
  "nbf": 1641234060,  // Not before: Jan 3, 2022 12:01:00 (60 sec later)
  "exp": 1641237600   // Expires: Jan 3, 2022 13:00:00
}
```

```csharp
var validationParameters = new TokenValidationParameters
{
    ValidateLifetime = true,  // Also validates nbf
    ClockSkew = TimeSpan.FromMinutes(5)
};
```

## 6. Nonce Validation (ID Tokens)

### Why It Matters

Prevents replay attacks. The nonce ties the ID token to the specific authentication request.

```csharp
// Step 1: Generate nonce before authorization request
string nonce = GenerateNonce();
HttpContext.Session.SetString("auth_nonce", nonce);

// Step 2: Include in authorization request
var authUrl = $"{authEndpoint}?...&nonce={nonce}";

// Step 3: After receiving ID token, validate nonce
var idToken = new JwtSecurityTokenHandler().ReadJwtToken(idTokenString);
var receivedNonce = idToken.Claims.FirstOrDefault(c => c.Type == "nonce")?.Value;

if (receivedNonce != HttpContext.Session.GetString("auth_nonce"))
{
    throw new SecurityException("Nonce mismatch - possible replay attack");
}

// Step 4: Clear nonce (single use)
HttpContext.Session.Remove("auth_nonce");
```

## 7. Algorithm Validation

### Why It Matters

Ensures only secure algorithms are accepted.

```csharp
var validationParameters = new TokenValidationParameters
{
    // Whitelist algorithms
    ValidAlgorithms = new[] { "RS256", "RS384", "RS512" },
    
    ValidateIssuerSigningKey = true,
    IssuerSigningKeys = await GetSigningKeysAsync()
};
```

### Recommended Algorithms

```
✅ SECURE:
   RS256, RS384, RS512 (RSA with SHA-256/384/512)
   ES256, ES384, ES512 (ECDSA)

⚠️ USE WITH CAUTION:
   HS256, HS384, HS512 (HMAC - symmetric key)
   - Only if you control both token issuer and validator
   - Key must remain secret

❌ NEVER ACCEPT:
   none (no signature)
```

## Complete Validation Example

### Client-Side (ID Token Validation)

```csharp
public class TokenValidator
{
    private readonly string _issuer = "https://auth.example.com";
    private readonly string _audience = "your-client-id";
    private readonly IHttpClientFactory _httpClientFactory;
    
    public async Task<ClaimsPrincipal> ValidateIdToken(string idToken, string expectedNonce)
    {
        var tokenHandler = new JwtSecurityTokenHandler();
        
        // Get signing keys from JWKS
        var signingKeys = await GetSigningKeysAsync();
        
        var validationParameters = new TokenValidationParameters
        {
            // Signature validation
            ValidateIssuerSigningKey = true,
            IssuerSigningKeys = signingKeys,
            
            // Issuer validation
            ValidateIssuer = true,
            ValidIssuer = _issuer,
            
            // Audience validation
            ValidateAudience = true,
            ValidAudience = _audience,
            
            // Lifetime validation
            ValidateLifetime = true,
            ClockSkew = TimeSpan.FromMinutes(5),
            
            // Algorithm validation
            ValidAlgorithms = new[] { "RS256" }
        };
        
        try
        {
            var principal = tokenHandler.ValidateToken(idToken, validationParameters, 
                out SecurityToken validatedToken);
            
            // Additional nonce validation
            var nonce = principal.FindFirst("nonce")?.Value;
            if (nonce != expectedNonce)
            {
                throw new SecurityTokenValidationException("Nonce mismatch");
            }
            
            return principal;
        }
        catch (SecurityTokenException ex)
        {
            // Log the validation failure
            Console.WriteLine($"Token validation failed: {ex.Message}");
            throw;
        }
    }
    
    private async Task<IList<SecurityKey>> GetSigningKeysAsync()
    {
        var httpClient = _httpClientFactory.CreateClient();
        var jwksUri = $"{_issuer}/.well-known/jwks.json";
        var response = await httpClient.GetStringAsync(jwksUri);
        var jwks = new JsonWebKeySet(response);
        return jwks.GetSigningKeys();
    }
}
```

### API-Side (Access Token Validation)

```csharp
// Startup.cs / Program.cs
services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.Authority = "https://auth.example.com";
        options.Audience = "https://api.example.com";
        
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidAlgorithms = new[] { "RS256" },
            ClockSkew = TimeSpan.FromMinutes(5)
        };
        
        options.Events = new JwtBearerEvents
        {
            OnAuthenticationFailed = context =>
            {
                Console.WriteLine($"Token validation failed: {context.Exception.Message}");
                return Task.CompletedTask;
            },
            
            OnTokenValidated = context =>
            {
                var userId = context.Principal?.FindFirst("sub")?.Value;
                Console.WriteLine($"Token validated for user: {userId}");
                return Task.CompletedTask;
            }
        };
    });
```

## Common OAuth 2.0 Security Vulnerabilities

### 1. Redirect URI Validation Failures

**Attack:**
```
Attacker registers: https://attacker.com/callback
Your app uses: https://yourapp.com/callback

If authorization server doesn't validate redirect URI strictly,
attacker can intercept authorization code
```

**Defense:**
```csharp
// Register exact redirect URIs (no wildcards)
options.RedirectUris = new[]
{
    "https://yourapp.com/callback",  // Exact match
    "https://yourapp.com/oauth/callback"
};

// NEVER use wildcard or pattern matching for redirect URIs
```

### 2. Missing State Parameter

**Attack:** Cross-Site Request Forgery (CSRF)

**Defense:**
```csharp
// Generate random state before authorization request
string state = GenerateCryptographicRandomString(32);
HttpContext.Session.SetString("oauth_state", state);

// Include in authorization URL
var authUrl = $"{authEndpoint}?...&state={state}";

// After redirect, validate state matches
var receivedState = Request.Query["state"];
if (receivedState != HttpContext.Session.GetString("oauth_state"))
{
    throw new SecurityException("State mismatch - possible CSRF attack");
}
```

### 3. Token Leakage

**Vulnerable locations:**
- Browser history (if tokens in URL fragments)
- Logs (if tokens logged)
- Referer headers (if tokens in URL)
- Local storage (vulnerable to XSS)

**Defense:**
```csharp
// Store tokens securely
✅ Server-side session (encrypted at rest)
✅ HttpOnly, Secure cookies
✅ In-memory (for SPAs, cleared on reload)

❌ localStorage
❌ sessionStorage (better, but still XSS-vulnerable)
❌ URL parameters
❌ Logs
```

### 4. Insufficient Scope Validation

**Attack:** Token granted for `read:profile` used to access `write:posts`

**Defense:**
```csharp
[Authorize]
[RequiredScope("write:posts")]
public IActionResult CreatePost([FromBody] Post post)
{
    // Verify scope in access token
    var scopes = User.FindFirst("scope")?.Value.Split(' ') ?? Array.Empty<string>();
    
    if (!scopes.Contains("write:posts"))
    {
        return Forbid();  // 403 Forbidden
    }
    
    // Process request
    return Ok();
}
```

## Security Best Practices Checklist

### Token Issuance
- ✓ Use Authorization Code Flow with PKCE for all clients
- ✓ Issue short-lived access tokens (5-60 minutes)
- ✓ Issue longer-lived refresh tokens (with rotation)
- ✓ Use HTTPS for all token endpoints
- ✓ Implement proper redirect URI validation

### Token Validation
- ✓ Validate signature using JWKS
- ✓ Validate issuer matches expected
- ✓ Validate audience matches your app/API
- ✓ Validate token hasn't expired
- ✓ Validate nonce (for ID tokens)
- ✓ Whitelist allowed algorithms

### Token Storage
- ✓ Store tokens server-side when possible
- ✓ Use HttpOnly, Secure cookies
- ✓ Never store tokens in localStorage
- ✓ Use in-memory storage for SPAs
- ✓ Encrypt tokens at rest

### Token Transmission
- ✓ Always use HTTPS/TLS
- ✓ Use Authorization header (not URL parameters)
- ✓ Implement proper CORS policies
- ✓ Don't log tokens

### Token Refresh
- ✓ Rotate refresh tokens on use
- ✓ Implement refresh token revocation
- ✓ Bind refresh tokens to clients
- ✓ Monitor for suspicious refresh patterns
