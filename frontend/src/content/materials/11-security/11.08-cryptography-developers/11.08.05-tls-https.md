## Introduction

TLS (Transport Layer Security) is the protocol that secures communication over networks, providing encryption, authentication, and integrity for data in transit. HTTPS is simply HTTP over TLS. As a developer, you need to understand how TLS works, how to configure it properly, and what best practices to follow to ensure your applications communicate securely.

**Key principle:** Always use HTTPS in production. Let the OS handle TLS version and cipher suite negotiation. Validate certificates properly.

## Key Concepts Summary

### How TLS/HTTPS Works

```
1. TCP Connection Established
   Client → [TCP Handshake] → Server

2. TLS Handshake Begins
   Client → ClientHello (supported versions, cipher suites)
   Server → ServerHello (selected version, cipher suite)
   Server → Certificate (server's X.509 certificate)
   Server → ServerHelloDone

3. Client Validates Certificate
   - Check certificate is not expired
   - Verify domain name matches
   - Validate certificate chain back to trusted root CA
   - Check certificate revocation status (optional)

4. Key Exchange
   Client → ClientKeyExchange (encrypted with server's public key)
   Both sides derive symmetric session keys

5. Secure Communication Begins
   All subsequent messages encrypted with session keys (symmetric encryption)

Key Insight: TLS uses ASYMMETRIC crypto for handshake/key exchange,
then SYMMETRIC crypto for actual data transfer (much faster).
```

### Enforcing HTTPS in ASP.NET Core

```csharp
// Program.cs
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllersWithViews();

// Add HTTPS redirection
builder.Services.AddHttpsRedirection(options =>
{
    options.RedirectStatusCode = StatusCodes.Status307TemporaryRedirect;
    options.HttpsPort = 443; // Default HTTPS port
});

var app = builder.Build();

// Configure middleware pipeline
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    
    // ✅ IMPORTANT: Add HSTS (HTTP Strict Transport Security)
    app.UseHsts();
}

// ✅ IMPORTANT: Redirect HTTP to HTTPS
app.UseHttpsRedirection();

app.UseStaticFiles();
app.UseRouting();
app.UseAuthorization();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

app.Run();
```

### HSTS (HTTP Strict Transport Security)

```csharp
// Configure HSTS
builder.Services.AddHsts(options =>
{
    options.MaxAge = TimeSpan.FromDays(365); // How long browsers remember
    options.IncludeSubDomains = true; // Apply to all subdomains
    options.Preload = true; // Allow HSTS preload list submission
});

// HSTS tells browsers: "Only connect to this site via HTTPS for X days"
// Once set, browsers will:
// 1. Automatically upgrade HTTP to HTTPS
// 2. Refuse to connect if certificate is invalid (no bypass option)

// ⚠️ IMPORTANT: Do NOT use HSTS for APIs!
// Non-browser clients (mobile apps, desktop apps) don't obey HSTS headers
```

### Loading Certificates from Various Sources

```csharp
public class CertificateLoader
{
    // From file (PFX)
    public static X509Certificate2 LoadFromPfx(string path, string password)
    {
        return new X509Certificate2(path, password);
    }
    
    // From PEM files (common with Let's Encrypt)
    public static X509Certificate2 LoadFromPem(string certPath, string keyPath)
    {
        return X509Certificate2.CreateFromPemFile(certPath, keyPath);
    }
    
    // From Windows Certificate Store
    public static X509Certificate2 LoadFromStore(string thumbprint)
    {
        using var store = new X509Store(StoreName.My, StoreLocation.LocalMachine);
        store.Open(OpenFlags.ReadOnly);
        
        var certs = store.Certificates.Find(
            X509FindType.FindByThumbprint,
            thumbprint,
            validOnly: true);
        
        if (certs.Count == 0)
            throw new InvalidOperationException("Certificate not found");
        
        return certs[0];
    }
    
    // From Azure Key Vault
    public static async Task<X509Certificate2> LoadFromKeyVault(
        string keyVaultUrl, 
        string certificateName)
    {
        var client = new CertificateClient(
            new Uri(keyVaultUrl), 
            new DefaultAzureCredential());
        
        var certificate = await client.DownloadCertificateAsync(certificateName);
        return certificate.Value;
    }
}

// Use in Kestrel configuration
builder.WebHost.ConfigureKestrel(options =>
{
    options.Listen(IPAddress.Any, 443, listenOptions =>
    {
        listenOptions.UseHttps(httpsOptions =>
        {
            // Load from environment-specific source
            if (builder.Environment.IsProduction())
            {
                httpsOptions.ServerCertificate = 
                    CertificateLoader.LoadFromStore(
                        builder.Configuration["CertificateThumbprint"]);
            }
            else
            {
                httpsOptions.ServerCertificate = 
                    CertificateLoader.LoadFromPfx(
                        "localhost.pfx", 
                        "dev-password");
            }
        });
    });
});
```

### TLS Version Configuration

```csharp
using System.Security.Authentication;

builder.WebHost.ConfigureKestrel(options =>
{
    options.Listen(IPAddress.Any, 443, listenOptions =>
    {
        listenOptions.UseHttps(httpsOptions =>
        {
            httpsOptions.ServerCertificate = LoadCertificate();
            
            // ✅ RECOMMENDED: Let OS choose TLS version (default)
            httpsOptions.SslProtocols = SslProtocols.None;
            
            // This allows the OS to:
            // - Use the most secure TLS version available
            // - Automatically adopt new versions when OS is updated
            // - Disable vulnerable versions when OS patches them
            
            // ⚠️ Only specify versions if you have a specific requirement:
            // httpsOptions.SslProtocols = SslProtocols.Tls12 | SslProtocols.Tls13;
        });
    });
});
```

### Client Certificate Authentication

```csharp
// Require client certificates (mutual TLS)
builder.Services.AddAuthentication(
    CertificateAuthenticationDefaults.AuthenticationScheme)
    .AddCertificate(options =>
    {
        // Validate client certificate
        options.AllowedCertificateTypes = CertificateTypes.All;
        options.RevocationMode = X509RevocationMode.Online;
        
        options.Events = new CertificateAuthenticationEvents
        {
            OnCertificateValidated = context =>
            {
                var claims = new[]
                {
                    new Claim(
                        ClaimTypes.NameIdentifier,
                        context.ClientCertificate.Subject,
                        ClaimValueTypes.String,
                        context.Options.ClaimsIssuer),
                    new Claim(
                        ClaimTypes.Name,
                        context.ClientCertificate.Subject,
                        ClaimValueTypes.String,
                        context.Options.ClaimsIssuer)
                };
                
                context.Principal = new ClaimsPrincipal(
                    new ClaimsIdentity(claims, context.Scheme.Name));
                context.Success();
                
                return Task.CompletedTask;
            },
            OnAuthenticationFailed = context =>
            {
                context.Fail("Invalid client certificate");
                return Task.CompletedTask;
            }
        };
    });

// Configure Kestrel to require client certificates
builder.WebHost.ConfigureKestrel(options =>
{
    options.Listen(IPAddress.Any, 443, listenOptions =>
    {
        listenOptions.UseHttps(httpsOptions =>
        {
            httpsOptions.ServerCertificate = LoadCertificate();
            httpsOptions.ClientCertificateMode = ClientCertificateMode.RequireCertificate;
            httpsOptions.AllowAnyClientCertificate(); // Or implement validation
        });
    });
});
```

### Making HTTPS Requests as a Client

```csharp
public class SecureHttpClient
{
    private readonly HttpClient _client;
    
    public SecureHttpClient()
    {
        var handler = new HttpClientHandler();
        
        // ✅ DEFAULT: Validate server certificates (recommended)
        handler.ServerCertificateCustomValidationCallback = null;
        
        // ⚠️ DEVELOPMENT ONLY: Accept self-signed certificates
        if (IsDevelopment())
        {
            handler.ServerCertificateCustomValidationCallback = 
                HttpClientHandler.DangerousAcceptAnyServerCertificateValidator;
        }
        
        // ✅ Custom certificate validation
        handler.ServerCertificateCustomValidationCallback = 
            (message, cert, chain, errors) =>
            {
                // Validate certificate
                if (errors == SslPolicyErrors.None)
                    return true;
                
                // Log errors
                Console.WriteLine($"Certificate errors: {errors}");
                
                // Implement custom validation logic
                return false;
            };
        
        _client = new HttpClient(handler);
    }
    
    // Add client certificate
    public void AddClientCertificate(X509Certificate2 certificate)
    {
        var handler = new HttpClientHandler();
        handler.ClientCertificates.Add(certificate);
        _client = new HttpClient(handler);
    }
}
```

### Common Pitfalls and Solutions

```csharp
// ❌ BAD: Accepting any certificate in production
var handler = new HttpClientHandler();
handler.ServerCertificateCustomValidationCallback = 
    HttpClientHandler.DangerousAcceptAnyServerCertificateValidator;

// ✅ GOOD: Only bypass validation in development
if (environment.IsDevelopment())
{
    handler.ServerCertificateCustomValidationCallback = 
        HttpClientHandler.DangerousAcceptAnyServerCertificateValidator;
}

// ❌ BAD: Hardcoding certificate password in code
var cert = new X509Certificate2("cert.pfx", "hardcoded-password");

// ✅ GOOD: Load password from configuration/Key Vault
var password = configuration["Certificate:Password"];
var cert = new X509Certificate2("cert.pfx", password);

// ❌ BAD: Using HSTS on APIs
app.UseHsts(); // Mobile apps won't understand this!

// ✅ GOOD: Only use HSTS for browser-facing apps
if (app.Services.GetService<IHostEnvironment>()?.EnvironmentName != "API")
{
    app.UseHsts();
}

// ❌ BAD: Specifying TLS 1.0 or 1.1
httpsOptions.SslProtocols = SslProtocols.Tls | SslProtocols.Tls11;

// ✅ GOOD: Use TLS 1.2+ or let OS decide
httpsOptions.SslProtocols = SslProtocols.None; // OS decides
// Or: SslProtocols.Tls12 | SslProtocols.Tls13
```

### Best Practices Checklist

```
✅ Always use HTTPS in production
✅ Use HSTS for browser-facing applications
✅ Let the OS handle TLS version negotiation (SslProtocols.None)
✅ Use strong certificates (2048-bit RSA minimum)
✅ Store certificates securely (Key Vault, not in source control)
✅ Implement proper certificate validation in HTTP clients
✅ Use separate certificates for different environments
✅ Monitor certificate expiration and automate renewal
✅ Test HTTPS configuration in CI/CD pipeline
✅ Use HTTP/2 or HTTP/3 when possible
✅ Configure proper CORS for HTTPS endpoints
✅ Implement certificate pinning for sensitive mobile/desktop apps

❌ Don't accept invalid certificates in production
❌ Don't commit certificates to source control
❌ Don't use HSTS on APIs consumed by non-browser clients
❌ Don't hardcode certificate passwords
❌ Don't manually specify cipher suites (let OS handle it)
❌ Don't use TLS 1.0 or 1.1 (deprecated)
❌ Don't ignore certificate validation errors
```
