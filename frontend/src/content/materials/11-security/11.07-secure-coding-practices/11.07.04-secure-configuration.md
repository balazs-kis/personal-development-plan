# Lesson 4: Secure Configuration Management

## Learning Objectives

By the end of this lesson, you will be able to:
- Manage application secrets securely without committing them to source control
- Use User Secrets for local development
- Implement environment-based configuration properly
- Integrate Azure Key Vault for production secrets
- Understand configuration hierarchy and overrides in .NET

---

## Introduction

Configuration management is critical for security. Hard-coded secrets in source code or configuration files are a leading cause of security breaches. This lesson teaches you how to externalize configuration, use secret management tools, and follow best practices for handling sensitive data across different environments.

**Key principle:** Never commit secrets to source control. Use different secret management strategies for development, staging, and production environments.

## Key Concepts Summary

### What NOT to Do (Secrets in appsettings.json)

```json
// appsettings.json - NEVER commit secrets here!
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=prod.db.com;Database=MyApp;User=admin;Password=P@ssw0rd123"
  },
  "ApiKeys": {
    "SendGrid": "SG.actual-api-key-here",
    "Stripe": "sk_live_actual_stripe_key"
  }
}
```

### Proper Configuration Structure

```json
// appsettings.json - Safe structure, no secrets
{
  "ConnectionStrings": {
    "DefaultConnection": ""  // Will be overridden by environment-specific config
  },
  "ApiKeys": {
    "SendGrid": "",
    "Stripe": ""
  },
  "Features": {
    "EnableCaching": true,
    "MaxUploadSize": 10485760
  }
}

// appsettings.Development.json - Still no secrets!
{
  "Logging": {
    "LogLevel": {
      "Default": "Debug"
    }
  }
  // Secrets come from User Secrets, not here
}
```

### Using User Secrets (Development)

```bash
# Initialize User Secrets for your project
dotnet user-secrets init

# Add secrets (stored outside project directory)
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=localhost;Database=MyAppDev;Trusted_Connection=true"
dotnet user-secrets set "ApiKeys:SendGrid" "SG.dev-key-here"
dotnet user-secrets set "ApiKeys:Stripe" "sk_test_dev_key"

# List all secrets
dotnet user-secrets list

# Remove a secret
dotnet user-secrets remove "ApiKeys:SendGrid"

# Clear all secrets
dotnet user-secrets clear
```

### Accessing Configuration in Code

```csharp
// Startup.cs or Program.cs
public class Program
{
    public static void Main(string[] args)
    {
        var builder = WebApplication.CreateBuilder(args);
        
        // Configuration is automatically loaded from:
        // 1. appsettings.json
        // 2. appsettings.{Environment}.json
        // 3. User Secrets (in Development)
        // 4. Environment variables
        // 5. Command-line arguments
        
        var app = builder.Build();
        app.Run();
    }
}

// Using configuration in a service
public class EmailService
{
    private readonly string _sendGridApiKey;
    
    public EmailService(IConfiguration configuration)
    {
        // Reads from User Secrets in dev, environment variables in production
        _sendGridApiKey = configuration["ApiKeys:SendGrid"];
        
        // Or use strongly-typed configuration
        var apiKeys = configuration.GetSection("ApiKeys").Get<ApiKeySettings>();
    }
}
```

### Strongly-Typed Configuration

```csharp
// Configuration class
public class ApiKeySettings
{
    public string SendGrid { get; set; }
    public string Stripe { get; set; }
}

public class ConnectionStringSettings
{
    public string DefaultConnection { get; set; }
}

// Register in Program.cs
builder.Services.Configure<ApiKeySettings>(
    builder.Configuration.GetSection("ApiKeys"));
builder.Services.Configure<ConnectionStringSettings>(
    builder.Configuration.GetSection("ConnectionStrings"));

// Use with IOptions
public class EmailService
{
    private readonly ApiKeySettings _apiKeys;
    
    public EmailService(IOptions<ApiKeySettings> apiKeys)
    {
        _apiKeys = apiKeys.Value;
        
        if (string.IsNullOrEmpty(_apiKeys.SendGrid))
        {
            throw new InvalidOperationException("SendGrid API key not configured");
        }
    }
}
```

### Environment Variables (Production)

```bash
# Linux/macOS
export ConnectionStrings__DefaultConnection="Server=prod;Database=MyApp;..."
export ApiKeys__SendGrid="SG.prod-key"

# Windows PowerShell
$env:ConnectionStrings__DefaultConnection="Server=prod;Database=MyApp;..."
$env:ApiKeys__SendGrid="SG.prod-key"

# Docker
docker run -e ConnectionStrings__DefaultConnection="..." myapp

# Azure App Service - set in Configuration blade
# Automatically available as environment variables
```

### Azure Key Vault Integration

```csharp
// Install package: Azure.Extensions.AspNetCore.Configuration.Secrets
using Azure.Identity;
using Azure.Security.KeyVault.Secrets;

public class Program
{
    public static void Main(string[] args)
    {
        var builder = WebApplication.CreateBuilder(args);
        
        // Add Azure Key Vault as configuration source
        if (!builder.Environment.IsDevelopment())
        {
            var keyVaultUrl = builder.Configuration["KeyVaultUrl"];
            
            builder.Configuration.AddAzureKeyVault(
                new Uri(keyVaultUrl),
                new DefaultAzureCredential());
        }
        
        var app = builder.Build();
        app.Run();
    }
}
```

### Validating Configuration at Startup

```csharp
public class ApiKeySettings
{
    public string SendGrid { get; set; }
    public string Stripe { get; set; }
    
    public void Validate()
    {
        if (string.IsNullOrWhiteSpace(SendGrid))
            throw new InvalidOperationException("SendGrid API key is required");
            
        if (string.IsNullOrWhiteSpace(Stripe))
            throw new InvalidOperationException("Stripe API key is required");
    }
}

// In Program.cs
builder.Services.AddOptions<ApiKeySettings>()
    .Bind(builder.Configuration.GetSection("ApiKeys"))
    .ValidateDataAnnotations()
    .ValidateOnStart();

// Or use IValidateOptions
public class ApiKeySettingsValidator : IValidateOptions<ApiKeySettings>
{
    public ValidateOptionsResult Validate(string name, ApiKeySettings options)
    {
        if (string.IsNullOrWhiteSpace(options.SendGrid))
            return ValidateOptionsResult.Fail("SendGrid API key is required");
            
        if (!options.Stripe.StartsWith("sk_"))
            return ValidateOptionsResult.Fail("Invalid Stripe API key format");
            
        return ValidateOptionsResult.Success;
    }
}

// Register validator
builder.Services.AddSingleton<IValidateOptions<ApiKeySettings>, ApiKeySettingsValidator>();
```

### Configuration Hierarchy and Overrides

```csharp
// Configuration sources are loaded in order (later sources override earlier ones):
// 1. appsettings.json
// 2. appsettings.{Environment}.json
// 3. User Secrets (Development only)
// 4. Environment variables
// 5. Command-line arguments

var builder = WebApplication.CreateBuilder(args);

// You can add custom sources
builder.Configuration
    .AddJsonFile("custom-config.json", optional: true)
    .AddJsonFile($"custom-config.{builder.Environment.EnvironmentName}.json", optional: true)
    .AddEnvironmentVariables(prefix: "MYAPP_")
    .AddCommandLine(args);
```

### Protecting Connection Strings in Development

```xml
<!-- Old ASP.NET approach - externalize secrets -->
<!-- Web.config -->
<connectionStrings configSource="ConnectionStrings.config" />

<!-- ConnectionStrings.config (add to .gitignore) -->
<connectionStrings>
  <add name="DefaultConnection" 
       connectionString="Server=...;Database=...;User=...;Password=..." />
</connectionStrings>
```

### Best Practices Checklist

```csharp
// ✅ DO: Use User Secrets for local development
// ✅ DO: Use environment variables or Key Vault for production
// ✅ DO: Validate configuration at startup
// ✅ DO: Use different credentials for each environment
// ✅ DO: Rotate secrets regularly
// ✅ DO: Use managed identities when possible (Azure)

// ❌ DON'T: Commit secrets to source control
// ❌ DON'T: Hard-code secrets in code
// ❌ DON'T: Log sensitive configuration values
// ❌ DON'T: Use production secrets in development
// ❌ DON'T: Store secrets in plain text files
// ❌ DON'T: Share secrets via email or chat
```
