## Introduction

The **Transactional Outbox pattern** solves one of the hardest problems in distributed systems: ensuring atomicity between database operations and message publishing. Without this pattern, you risk inconsistency—database changes succeed but messages fail, or vice versa.

This pattern ensures that database writes and message publishes happen atomically by treating the outbox table as part of the same database transaction, then publishing messages in a separate process. It's essential for maintaining consistency in event-driven systems.

## Key Concepts Summary

### The Problem: Dual Writes

```csharp
// ❌ PROBLEM: Two separate writes (not atomic)
public async Task CreateOrder(Order order)
{
    // Write 1: Database
    await _db.Orders.AddAsync(order);
    await _db.SaveChangesAsync();
    
    // Write 2: Message broker
    await _producer.ProduceAsync("orders", order);
    
    // What if Kafka fails? Order exists but no event!
    // What if DB fails after Kafka succeeds? Event exists but no order!
}
```

### The Solution: Transactional Outbox

```csharp
// ✅ SOLUTION: Single atomic write
public async Task CreateOrder(Order order)
{
    using var transaction = await _db.Database.BeginTransactionAsync();
    
    try
    {
        // Write order
        _db.Orders.Add(order);
        
        // Write event to outbox (same transaction)
        _db.OutboxMessages.Add(new OutboxMessage
        {
            AggregateId = order.Id,
            EventType = "OrderCreated",
            Payload = JsonSerializer.Serialize(order),
            CreatedAt = DateTime.UtcNow
        });
        
        await _db.SaveChangesAsync();
        await transaction.CommitAsync();
        
        // Both writes succeed together or both fail together ✓
    }
    catch
    {
        await transaction.RollbackAsync();
        throw;
    }
}
```

```csharp
public class OrderService
{
    private readonly AppDbContext _db;
    
    public async Task<string> CreateOrder(CreateOrderCommand cmd)
    {
        var orderId = Guid.NewGuid().ToString();
        
        using var transaction = await _db.Database.BeginTransactionAsync();
        
        try
        {
            var order = new Order
            {
                Id = orderId,
                CustomerId = cmd.CustomerId,
                TotalAmount = cmd.TotalAmount,
                Status = OrderStatus.Created
            };
            
            _db.Orders.Add(order);

            {
                OrderId = orderId,
                CustomerId = cmd.CustomerId,
                TotalAmount = cmd.TotalAmount

            {
                Id = Guid.NewGuid(),
                AggregateId = orderId,
                EventType = nameof(OrderCreatedEvent),
                Payload = JsonSerializer.Serialize(evt),
                CreatedAt = DateTime.UtcNow
            });
            
            await _db.SaveChangesAsync();
            await transaction.CommitAsync();
            
            return orderId;
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}
```

**Outbox Publisher (Polling):**

```csharp
public class OutboxPublisher : BackgroundService
{
    private readonly IServiceProvider _serviceProvider;
    private readonly ILogger<OutboxPublisher> _logger;
    
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await PublishPendingMessages(stoppingToken);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error publishing outbox messages");
            }
            
            await Task.Delay(TimeSpan.FromSeconds(1), stoppingToken);
        }
    }
    
    private async Task PublishPendingMessages(CancellationToken ct)
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        var producer = scope.ServiceProvider.GetRequiredService<IProducer<string, string>>();
        
        var messages = await db.OutboxMessages
            .Where(m => m.ProcessedAt == null)
            .OrderBy(m => m.CreatedAt)
            .Take(100)
            .ToListAsync(ct);
        
        foreach (var msg in messages)
        {
            try
            {
                await producer.ProduceAsync(
                    GetTopicName(msg.EventType),
                    new Message<string, string>
                    {
                        Key = msg.AggregateId,
                        Value = msg.Payload,
                        Headers = new Headers
                        {
                            { "event-type", Encoding.UTF8.GetBytes(msg.EventType) },
                            { "outbox-id", Encoding.UTF8.GetBytes(msg.Id.ToString()) }
                        }
                    },
                    ct
                );
                
                msg.ProcessedAt = DateTime.UtcNow;
                await db.SaveChangesAsync(ct);
                
                _logger.LogInformation("Published outbox message {Id}", msg.Id);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Failed to publish outbox message {Id}", msg.Id);
                // Continue to next message
            }
        }
    }
    
    private string GetTopicName(string eventType) => 
        eventType.ToLowerInvariant().Replace("event", "-events");
}
```

### Change Data Capture (CDC) Approach

Instead of polling, use database CDC to detect new outbox rows:

```
Database Outbox Table
        ↓ (CDC captures changes)
    Debezium / SQL Server CDC
        ↓
    Kafka Connect
        ↓
    Kafka Topic (events)
```

**Benefits:**
- Near real-time (no polling delay)
- Lower database load
- Scalable

**Trade-offs:**
- External dependency (CDC tool)
- More complex setup
- Requires CDC-capable database

### Cleanup Strategy

```csharp
public class OutboxCleanupService : BackgroundService
{
    private readonly IServiceProvider _serviceProvider;
    private readonly ILogger<OutboxCleanupService> _logger;
    private readonly OutboxCleanupOptions _options;
    
    public OutboxCleanupService(
        IServiceProvider serviceProvider,
        IOptions<OutboxCleanupOptions> options,
        ILogger<OutboxCleanupService> logger)
    {
        _serviceProvider = serviceProvider;
        _options = options.Value;
        _logger = logger;
    }
    
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            try
            {
                await Task.Delay(_options.CleanupInterval, ct);
                await CleanupOldMessages(ct);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error during outbox cleanup");
            }
        }
    }
    
    private async Task CleanupOldMessages(CancellationToken ct)
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        
        var cutoffDate = DateTime.UtcNow - _options.RetentionPeriod;
        
        var deletedCount = await db.OutboxMessages
            .Where(m => m.ProcessedAt != null && m.ProcessedAt < cutoffDate)
            .ExecuteDeleteAsync(ct);
        
        if (deletedCount > 0)
        {
            _logger.LogInformation(
                "Cleaned up {Count} outbox messages older than {Cutoff}",
                deletedCount, cutoffDate);
        }
        
        // Also cleanup very old unprocessed messages (stuck messages)
        var stuckCutoff = DateTime.UtcNow.AddDays(-30);
        var stuckCount = await db.OutboxMessages
            .Where(m => m.ProcessedAt == null && m.CreatedAt < stuckCutoff)
            .ExecuteDeleteAsync(ct);
        
        if (stuckCount > 0)
        {
            _logger.LogWarning(
                "Deleted {Count} stuck unprocessed messages older than 30 days",
                stuckCount);
        }
    }
}

public class OutboxCleanupOptions
{
    public TimeSpan CleanupInterval { get; set; } = TimeSpan.FromHours(1);
    public TimeSpan RetentionPeriod { get; set; } = TimeSpan.FromDays(7);
}
```

### Monitoring and Alerting

```csharp
public class OutboxMonitoring
{
    private readonly Counter _published;
    private readonly Counter _failed;
    private readonly Gauge _pending;
    private readonly Gauge _oldestUnprocessed;
    private readonly Histogram _publishLatency;
    
    public OutboxMonitoring(IMeterFactory meterFactory)
    {
        var meter = meterFactory.Create("Outbox");
        
        _published = meter.CreateCounter<long>("outbox_published_total");
        _failed = meter.CreateCounter<long>("outbox_failed_total");
        _pending = meter.CreateGauge<long>("outbox_pending_messages");
        _oldestUnprocessed = meter.CreateGauge<double>("outbox_oldest_unprocessed_seconds");
        _publishLatency = meter.CreateHistogram<double>("outbox_publish_duration_seconds");
    }
    
    public void RecordPublished(string eventType, TimeSpan duration)
    {
        _published.Add(1, new("event_type", eventType));
        _publishLatency.Record(duration.TotalSeconds, new("event_type", eventType));
    }
    
    public void RecordFailed(string eventType)
    {
        _failed.Add(1, new("event_type", eventType));
    }
    
    public async Task UpdatePendingMetrics(AppDbContext db)
    {
        var pendingCount = await db.OutboxMessages
            .CountAsync(m => m.ProcessedAt == null);
        
        _pending.Record(pendingCount);
        
        var oldestUnprocessed = await db.OutboxMessages
            .Where(m => m.ProcessedAt == null)
            .OrderBy(m => m.CreatedAt)
            .Select(m => m.CreatedAt)
            .FirstOrDefaultAsync();
        
        if (oldestUnprocessed != default)
        {
            var age = (DateTime.UtcNow - oldestUnprocessed).TotalSeconds;
            _oldestUnprocessed.Record(age);
            
            // Alert if messages are too old
            if (age > 300) // 5 minutes
            {
                Console.WriteLine($"⚠️ WARNING: Oldest unprocessed message is {age:F0} seconds old");
            }
        }
    }
}
```

### Alternative Implementation: Polling with Distributed Lock

For multi-instance deployments, use distributed locking:

```csharp
public class DistributedOutboxPublisher : BackgroundService
{
    private readonly IServiceProvider _serviceProvider;
    private readonly IDistributedLock _distributedLock;
    private readonly ILogger<DistributedOutboxPublisher> _logger;
    
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            try
            {
                // Try to acquire distributed lock
                await using var lockHandle = await _distributedLock.TryAcquireAsync(
                    "outbox-publisher",
                    TimeSpan.FromSeconds(30),
                    ct);
                
                if (lockHandle != null)
                {
                    // This instance has the lock
                    await PublishPendingMessages(ct);
                }
                
                await Task.Delay(TimeSpan.FromSeconds(1), ct);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error in outbox publisher");
            }
        }
    }
    
    private async Task PublishPendingMessages(CancellationToken ct)
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        var producer = scope.ServiceProvider.GetRequiredService<IMessageProducer>();
        
        // Process batch
        var messages = await db.OutboxMessages
            .Where(m => m.ProcessedAt == null)
            .OrderBy(m => m.CreatedAt)
            .Take(100)
            .ToListAsync(ct);
        
        foreach (var msg in messages)
        {
            try
            {
                await producer.PublishAsync(msg.EventType, msg.Payload, ct);
                msg.ProcessedAt = DateTime.UtcNow;
                await db.SaveChangesAsync(ct);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Failed to publish outbox message {Id}", msg.Id);
            }
        }
    }
}
```

### Optimistic Concurrency for Outbox

Prevent duplicate publishing in race conditions:

```csharp
public class OutboxMessage
{
    public Guid Id { get; set; }
    public string AggregateId { get; set; }
    public string EventType { get; set; }
    public string Payload { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? ProcessedAt { get; set; }
    
    // Optimistic concurrency token
    [Timestamp]
    public byte[] RowVersion { get; set; }
}

public class ConcurrentOutboxPublisher : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            var messages = await GetPendingMessages(ct);
            
            foreach (var msg in messages)
            {
                try
                {
                    await PublishMessage(msg, ct);
                    await MarkAsProcessed(msg, ct);
                }
                catch (DbUpdateConcurrencyException)
                {
                    // Another instance already processed this message
                    _logger.LogInformation(
                        "Message {Id} already processed by another instance",
                        msg.Id);
                }
                catch (Exception ex)
                {
                    _logger.LogError(ex, "Failed to publish message {Id}", msg.Id);
                }
            }
            
            await Task.Delay(TimeSpan.FromSeconds(1), ct);
        }
    }
    
    private async Task MarkAsProcessed(OutboxMessage msg, CancellationToken ct)
    {
        msg.ProcessedAt = DateTime.UtcNow;
        
        // SaveChanges will throw DbUpdateConcurrencyException
        // if RowVersion changed (another instance processed it)
        await _db.SaveChangesAsync(ct);
    }
}
```

### Outbox with Inbox Pattern (Exactly-Once Processing)

Combine outbox with inbox for end-to-end exactly-once:

```csharp
// Consuming service inbox
public class InboxMessage
{
    public Guid Id { get; set; }  // Message ID from producer
    public string EventType { get; set; }
    public string Payload { get; set; }
    public DateTime ReceivedAt { get; set; }
    public DateTime? ProcessedAt { get; set; }
}

public class OrderEventConsumer
{
    private readonly AppDbContext _db;
    
    public async Task Handle(OrderCreatedEvent evt, string messageId)
    {
        using var transaction = await _db.Database.BeginTransactionAsync();
        
        try
        {
            // Check inbox for duplicate
            var existing = await _db.InboxMessages
                .FirstOrDefaultAsync(m => m.Id == Guid.Parse(messageId));
            
            if (existing?.ProcessedAt != null)
            {
                _logger.LogInformation("Duplicate message {Id}, skipping", messageId);
                return; // Already processed
            }
            
            // Process event (business logic)
            await ProcessOrderCreated(evt);
            
            // Record in inbox
            if (existing == null)
            {
                _db.InboxMessages.Add(new InboxMessage
                {
                    Id = Guid.Parse(messageId),
                    EventType = nameof(OrderCreatedEvent),
                    Payload = JsonSerializer.Serialize(evt),
                    ReceivedAt = DateTime.UtcNow
                });
            }
            
            existing.ProcessedAt = DateTime.UtcNow;
            
            await _db.SaveChangesAsync();
            await transaction.CommitAsync();
            
            _logger.LogInformation("Processed order created event: {OrderId}", evt.OrderId);
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}
```

```csharp
    }
    
    [Fact]
    public async Task Publisher_Handles_Message_Broker_Failure()
    {
        // Arrange
        var db = CreateTestDatabase();
        var failingProducer = new Mock<IProducer<string, string>>();
        failingProducer.Setup(p => p.ProduceAsync(It.IsAny<string>(), It.IsAny<Message<string, string>>(), It.IsAny<CancellationToken>()))
            .ThrowsAsync(new KafkaException(ErrorCode.Unknown));
        
        var publisher = new OutboxPublisher(db, failingProducer.Object);
        
        // Add message to outbox
        db.OutboxMessages.Add(new OutboxMessage
        {
            Id = Guid.NewGuid(),
            EventType = "TestEvent",
            Payload = "{}",
            CreatedAt = DateTime.UtcNow
        });
        await db.SaveChangesAsync();
        
        // Act: Try to publish (will fail)
        await publisher.PublishPendingMessages();
        
        // Assert: Message remains unprocessed
        var msg = await db.OutboxMessages.FirstAsync();
        Assert.Null(msg.ProcessedAt);
        
        // Fix broker and retry
        failingProducer.Setup(p => p.ProduceAsync(It.IsAny<string>(), It.IsAny<Message<string, string>>(), It.IsAny<CancellationToken>()))
            .ReturnsAsync(new DeliveryResult<string, string>());
        
        await publisher.PublishPendingMessages();
        
        // Assert: Now processed
        await db.Entry(msg).ReloadAsync();
        Assert.NotNull(msg.ProcessedAt);
    }
```

### Production Checklist

Before deploying outbox pattern to production:

**1. Database:**
- [ ] Index on `ProcessedAt` column for query performance
- [ ] Index on `CreatedAt` for cleanup queries
- [ ] Partition table if expecting high volume (>10M records)
- [ ] Set up database backups

**2. Publisher:**
- [ ] Configure batch size appropriately (50-1000)
- [ ] Set polling interval based on latency requirements
- [ ] Implement distributed locking for multi-instance deployments
- [ ] Add circuit breaker for broker failures
- [ ] Configure retry policy with exponential backoff

**3. Monitoring:**
- [ ] Alert on pending message count > threshold
- [ ] Alert on oldest unprocessed message age > 5 minutes
- [ ] Track publish success/failure rates
- [ ] Monitor publisher lag
- [ ] Dashboard showing outbox health metrics

**4. Cleanup:**
- [ ] Configure retention period (default 7 days)
- [ ] Schedule cleanup job (hourly or daily)
- [ ] Monitor cleanup performance
- [ ] Handle stuck messages (never processed)

**5. Testing:**
- [ ] Test database transaction rollback
- [ ] Test publisher failure recovery
- [ ] Test duplicate message handling
- [ ] Load test with high volume
- [ ] Test multi-instance coordination
