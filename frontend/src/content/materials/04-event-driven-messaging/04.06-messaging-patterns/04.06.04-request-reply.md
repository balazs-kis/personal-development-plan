# Lesson 4: Request-Reply Over Messaging

## Learning Objectives

By the end of this lesson, you will be able to:
- Implement synchronous-style request/response over asynchronous messaging
- Use correlation IDs to match requests with replies
- Design temporary and permanent reply queues
- Handle timeouts and failures in request-reply scenarios
- Choose when request-reply is appropriate vs direct HTTP calls

---

## Introduction

The **Request-Reply pattern** enables synchronous-style communication over asynchronous messaging infrastructure. The requestor sends a message and waits for a response, similar to HTTP request/response, but gains the benefits of messaging: decoupling, load balancing, and reliability.

This pattern is useful when you need a response from a remote service but want messaging benefits like durability, retry logic, and load distribution. It's commonly used for distributed RPC-style calls, query operations, and command validation.

## Key Concepts Summary

### Request-Reply Flow

```
Client → [Request Queue] → Server
Client ← [Reply Queue]   ← Server
```

**Steps:**
1. Client sends request with correlation ID and reply-to address
2. Server receives request, processes it
3. Server sends response to reply queue with same correlation ID
4. Client matches response using correlation ID

### RabbitMQ Request-Reply

```csharp
// Client: Sends request and waits for reply
public class OrderQueryClient
{
    private readonly IModel _channel;
    private readonly string _replyQueueName;
    private readonly ConcurrentDictionary<string, TaskCompletionSource<string>> _pendingRequests;
    
    public OrderQueryClient(IConnection connection)
    {
        _channel = connection.CreateModel();
        _pendingRequests = new ConcurrentDictionary<string, TaskCompletionSource<string>>();
        
        // Create temporary reply queue (exclusive, auto-delete)
        _replyQueueName = _channel.QueueDeclare(
            queue: "",  // Let server generate name
            durable: false,
            exclusive: true,  // Only this connection
            autoDelete: true  // Delete when connection closes
        ).QueueName;
        
        // Start listening for replies
        var consumer = new EventingBasicConsumer(_channel);
        consumer.Received += (model, ea) =>
        {
            var correlationId = ea.BasicProperties.CorrelationId;
            var response = Encoding.UTF8.GetString(ea.Body.ToArray());
            
            if (_pendingRequests.TryRemove(correlationId, out var tcs))
            {
                tcs.SetResult(response);
            }
        };
        
        _channel.BasicConsume(_replyQueueName, autoAck: true, consumer: consumer);
    }
    
    public async Task<Order> GetOrderAsync(string orderId, TimeSpan timeout)
    {
        var correlationId = Guid.NewGuid().ToString();
        var tcs = new TaskCompletionSource<string>();
        _pendingRequests[correlationId] = tcs;
        
        var properties = _channel.CreateBasicProperties();
        properties.CorrelationId = correlationId;
        properties.ReplyTo = _replyQueueName;
        
        var request = new { OrderId = orderId };
        var body = Encoding.UTF8.GetBytes(JsonSerializer.Serialize(request));
        
        _channel.BasicPublish(
            exchange: "",
            routingKey: "order-query",
            basicProperties: properties,
            body: body
        );
        
        // Wait for reply with timeout
        var timeoutTask = Task.Delay(timeout);
        var completedTask = await Task.WhenAny(tcs.Task, timeoutTask);
        
        if (completedTask == timeoutTask)
        {
            _pendingRequests.TryRemove(correlationId, out _);
            throw new TimeoutException($"Request {correlationId} timed out");
        }
        
        var response = await tcs.Task;
        return JsonSerializer.Deserialize<Order>(response);
    }
}

// Server: Processes requests and sends replies
public class OrderQueryServer
{
    private readonly IModel _channel;
    
    public OrderQueryServer(IConnection connection)
    {
        _channel = connection.CreateModel();
        
        _channel.QueueDeclare(
            queue: "order-query",
            durable: true,
            exclusive: false,
            autoDelete: false
        );
        
        _channel.BasicQos(0, 1, false);
    }
    
    public void Start()
    {
        var consumer = new EventingBasicConsumer(_channel);
        
        consumer.Received += (model, ea) =>
        {
            var body = ea.Body.ToArray();
            var request = JsonSerializer.Deserialize<dynamic>(Encoding.UTF8.GetString(body));
            
            string orderId = request.OrderId;
            Console.WriteLine($"[Server] Received query for order {orderId}");
            
            // Process request
            var order = GetOrder(orderId);
            var response = JsonSerializer.Serialize(order);
            
            // Send reply
            var replyProperties = _channel.CreateBasicProperties();
            replyProperties.CorrelationId = ea.BasicProperties.CorrelationId;
            
            _channel.BasicPublish(
                exchange: "",
                routingKey: ea.BasicProperties.ReplyTo,  // Use reply-to address
                basicProperties: replyProperties,
                body: Encoding.UTF8.GetBytes(response)
            );
            
            _channel.BasicAck(ea.DeliveryTag, false);
            Console.WriteLine($"[Server] Sent reply for order {orderId}");
        };
        
        _channel.BasicConsume("order-query", autoAck: false, consumer: consumer);
        Console.WriteLine("[Server] Waiting for requests...");
    }
    
    private Order GetOrder(string orderId)
    {
        // Simulate database lookup
        Thread.Sleep(100);
        return new Order { Id = orderId, Status = "Shipped" };
    }
}

// Usage
using var connection = new ConnectionFactory { HostName = "localhost" }.CreateConnection();

// Start server
var server = new OrderQueryServer(connection);
Task.Run(() => server.Start());

// Make requests from client
var client = new OrderQueryClient(connection);
var order = await client.GetOrderAsync("order-123", TimeSpan.FromSeconds(5));
Console.WriteLine($"Received order: {order.Id}, Status: {order.Status}");
```

### Kafka Request-Reply (More Complex)

Kafka requires more manual work for request-reply:

```csharp
// Client: Sends request and polls for reply
public class KafkaRpcClient
{
    private readonly IProducer<string, string> _producer;
    private readonly IConsumer<string, string> _consumer;
    private readonly string _replyTopic;
    
    public KafkaRpcClient(string bootstrapServers)
    {
        var producerConfig = new ProducerConfig { BootstrapServers = bootstrapServers };
        _producer = new ProducerBuilder<string, string>(producerConfig).Build();
        
        var consumerConfig = new ConsumerConfig
        {
            BootstrapServers = bootstrapServers,
            GroupId = $"rpc-client-{Guid.NewGuid()}",
            AutoOffsetReset = AutoOffsetReset.Latest
        };
        _consumer = new ConsumerBuilder<string, string>(consumerConfig).Build();
        
        // Create or use reply topic
        _replyTopic = $"rpc-replies-{Guid.NewGuid()}";
        _consumer.Subscribe(_replyTopic);
    }
    
    public async Task<string> CallAsync(string requestTopic, string request, TimeSpan timeout)
    {
        var correlationId = Guid.NewGuid().ToString();
        
        var headers = new Headers
        {
            { "correlation-id", Encoding.UTF8.GetBytes(correlationId) },
            { "reply-to", Encoding.UTF8.GetBytes(_replyTopic) }
        };
        
        await _producer.ProduceAsync(requestTopic, new Message<string, string>
        {
            Key = correlationId,
            Value = request,
            Headers = headers
        });
        
        // Poll for reply
        var deadline = DateTime.UtcNow + timeout;
        while (DateTime.UtcNow < deadline)
        {
            var result = _consumer.Consume(TimeSpan.FromMilliseconds(100));
            
            if (result != null &&
                result.Message.Headers.TryGetLastBytes("correlation-id", out var corrIdBytes))
            {
                var responseCorrelationId = Encoding.UTF8.GetString(corrIdBytes);
                
                if (responseCorrelationId == correlationId)
                {
                    _consumer.Commit(result);
                    return result.Message.Value;
                }
            }
        }
        
        throw new TimeoutException($"Request {correlationId} timed out");
    }
}

// Server: Processes requests from request topic, sends replies to reply topics
public class KafkaRpcServer
{
    private readonly IConsumer<string, string> _consumer;
    private readonly IProducer<string, string> _producer;
    
    public KafkaRpcServer(string bootstrapServers, string requestTopic)
    {
        var consumerConfig = new ConsumerConfig
        {
            BootstrapServers = bootstrapServers,
            GroupId = "rpc-server",
            AutoOffsetReset = AutoOffsetReset.Earliest
        };
        _consumer = new ConsumerBuilder<string, string>(consumerConfig).Build();
        _consumer.Subscribe(requestTopic);
        
        var producerConfig = new ProducerConfig { BootstrapServers = bootstrapServers };
        _producer = new ProducerBuilder<string, string>(producerConfig).Build();
    }
    
    public void Start(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            var result = _consumer.Consume(ct);
            
            if (result.Message.Headers.TryGetLastBytes("correlation-id", out var corrIdBytes) &&
                result.Message.Headers.TryGetLastBytes("reply-to", out var replyToBytes))
            {
                var correlationId = Encoding.UTF8.GetString(corrIdBytes);
                var replyTopic = Encoding.UTF8.GetString(replyToBytes);
                
                Console.WriteLine($"[Server] Processing request {correlationId}");
                
                // Process request
                var response = ProcessRequest(result.Message.Value);
                
                // Send reply
                var replyHeaders = new Headers
                {
                    { "correlation-id", corrIdBytes }
                };
                
                _producer.Produce(replyTopic, new Message<string, string>
                {
                    Key = correlationId,
                    Value = response,
                    Headers = replyHeaders
                });
                
                _consumer.Commit(result);
                Console.WriteLine($"[Server] Sent reply to {replyTopic}");
            }
        }
    }
    
    private string ProcessRequest(string request)
    {
        // Business logic
        return $"Processed: {request}";
    }
}
```

### Design Considerations

**Reply Queue Strategies:**

1. **Temporary queue per client** (RabbitMQ example above)
   - **Pros:** Simple, automatic cleanup, no name collisions
   - **Cons:** More queues, connection-specific, overhead per client
   - **Use when:** Clients are short-lived, low client count

2. **Shared reply queue with correlation IDs**
   - **Pros:** Fewer queues, efficient resource usage
   - **Cons:** Need filtering by correlation ID, potential hot spot
   - **Use when:** Many concurrent clients, long-lived connections

```csharp
// Shared reply queue implementation
public class SharedReplyQueueClient
{
    private readonly IModel _channel;
    private readonly string _sharedReplyQueue = "rpc-replies";
    private readonly ConcurrentDictionary<string, TaskCompletionSource<string>> _pendingRequests;
    
    public SharedReplyQueueClient(IConnection connection)
    {
        _channel = connection.CreateModel();
        _pendingRequests = new ConcurrentDictionary<string, TaskCompletionSource<string>>();
        
        // Declare shared reply queue
        _channel.QueueDeclare(_sharedReplyQueue, durable: true, exclusive: false, autoDelete: false);
        
        var consumer = new EventingBasicConsumer(_channel);
        consumer.Received += (model, ea) =>
        {
            var correlationId = ea.BasicProperties.CorrelationId;
            var response = Encoding.UTF8.GetString(ea.Body.ToArray());
            
            if (_pendingRequests.TryRemove(correlationId, out var tcs))
            {
                tcs.SetResult(response);
            }
        };
        
        _channel.BasicConsume(_sharedReplyQueue, autoAck: true, consumer: consumer);
    }
    
    public async Task<string> CallAsync(string requestQueue, string request, TimeSpan timeout)
    {
        var correlationId = Guid.NewGuid().ToString();
        var tcs = new TaskCompletionSource<string>();
        _pendingRequests[correlationId] = tcs;
        
        var properties = _channel.CreateBasicProperties();
        properties.CorrelationId = correlationId;
        properties.ReplyTo = _sharedReplyQueue;
        
        _channel.BasicPublish("", requestQueue, properties, Encoding.UTF8.GetBytes(request));
        
        using var cts = new CancellationTokenSource(timeout);
        cts.Token.Register(() => 
        {
            _pendingRequests.TryRemove(correlationId, out _);
            tcs.TrySetException(new TimeoutException());
        });
        
        return await tcs.Task;
    }
}
```

3. **Reply topic per service** (Kafka)
   - **Pros:** Scalable, isolated per service
   - **Cons:** More topics, manual cleanup, higher complexity
   - **Use when:** Kafka-based architecture, need durability

**Timeout Handling Strategies:**

```csharp
public class ResilientRpcClient
{
    private readonly OrderQueryClient _client;
    
    // Strategy 1: Simple timeout with retry
    public async Task<Order> CallWithRetry(string orderId, int maxRetries = 3)
    {
        for (int attempt = 1; attempt <= maxRetries; attempt++)
        {
            try
            {
                return await _client.GetOrderAsync(orderId, TimeSpan.FromSeconds(5));
            }
            catch (TimeoutException) when (attempt < maxRetries)
            {
                Console.WriteLine($"Attempt {attempt} timed out, retrying...");
                await Task.Delay(TimeSpan.FromSeconds(Math.Pow(2, attempt))); // Exponential backoff
            }
        }
        
        throw new TimeoutException($"All {maxRetries} attempts failed for order {orderId}");
    }
    
    // Strategy 2: Circuit breaker pattern
    private int _failureCount = 0;
    private DateTime _circuitOpenedAt = DateTime.MinValue;
    private const int FailureThreshold = 5;
    private TimeSpan CircuitResetTimeout = TimeSpan.FromMinutes(1);
    
    public async Task<Order> CallWithCircuitBreaker(string orderId)
    {
        // Check circuit state
        if (_failureCount >= FailureThreshold)
        {
            if (DateTime.UtcNow - _circuitOpenedAt < CircuitResetTimeout)
            {
                throw new CircuitBreakerOpenException("Circuit breaker is open");
            }
            
            // Try to close circuit (half-open state)
            _failureCount = 0;
        }
        
        try
        {
            var result = await _client.GetOrderAsync(orderId, TimeSpan.FromSeconds(5));
            _failureCount = 0; // Reset on success
            return result;
        }
        catch (TimeoutException)
        {
            _failureCount++;
            if (_failureCount >= FailureThreshold)
            {
                _circuitOpenedAt = DateTime.UtcNow;
                Console.WriteLine($"⚠️ Circuit breaker opened after {_failureCount} failures");
            }
            throw;
        }
    }
    
    // Strategy 3: Fallback with cached response
    private readonly IMemoryCache _cache;
    
    public async Task<Order> CallWithFallback(string orderId)
    {
        try
        {
            var order = await _client.GetOrderAsync(orderId, TimeSpan.FromSeconds(3));
            
            // Cache successful response
            _cache.Set($"order:{orderId}", order, TimeSpan.FromMinutes(5));
            
            return order;
        }
        catch (TimeoutException)
        {
            // Try cache
            if (_cache.TryGetValue($"order:{orderId}", out Order cachedOrder))
            {
                Console.WriteLine($"⚠️ Using cached response for order {orderId}");
                return cachedOrder;
            }
            
            throw;
        }
    }
}
```

### Load Balancing Requests

**Multiple RPC servers with competing consumers:**

```csharp
// Run multiple server instances for load balancing and fault tolerance
public class ScalableRpcServer
{
    private readonly IModel _channel;
    private readonly int _serverId;
    
    public ScalableRpcServer(IConnection connection, int serverId)
    {
        _channel = connection.CreateModel();
        _serverId = serverId;
        
        _channel.QueueDeclare("order-query", durable: true, exclusive: false, autoDelete: false);
        
        // Fair dispatch
        _channel.BasicQos(prefetchSize: 0, prefetchCount: 1, global: false);
        
        Console.WriteLine($"[Server {_serverId}] Started and ready");
    }
    
    public void Start()
    {
        var consumer = new EventingBasicConsumer(_channel);
        
        consumer.Received += (model, ea) =>
        {
            var requestId = ea.BasicProperties.CorrelationId;
            Console.WriteLine($"[Server {_serverId}] Processing request {requestId}");
            
            try
            {
                var request = JsonSerializer.Deserialize<GetOrderRequest>(
                    Encoding.UTF8.GetString(ea.Body.ToArray()));
                
                // Simulate processing time
                Thread.Sleep(100);
                
                var order = GetOrder(request.OrderId);
                var response = JsonSerializer.Serialize(order);
                
                var replyProps = _channel.CreateBasicProperties();
                replyProps.CorrelationId = requestId;
                
                _channel.BasicPublish("", ea.BasicProperties.ReplyTo, replyProps,
                    Encoding.UTF8.GetBytes(response));
                
                _channel.BasicAck(ea.DeliveryTag, false);
                
                Console.WriteLine($"[Server {_serverId}] Completed request {requestId}");
            }
            catch (Exception ex)
            {
                Console.WriteLine($"[Server {_serverId}] Error: {ex.Message}");
                _channel.BasicNack(ea.DeliveryTag, false, true); // Requeue
            }
        };
        
        _channel.BasicConsume("order-query", autoAck: false, consumer: consumer);
    }
}

// Usage: Run multiple servers
class Program
{
    static void Main()
    {
        var factory = new ConnectionFactory { HostName = "localhost" };
        using var connection = factory.CreateConnection();
        
        // Start 3 competing servers
        for (int i = 1; i <= 3; i++)
        {
            var server = new ScalableRpcServer(connection, i);
            Task.Run(() => server.Start());
        }
        
        Console.WriteLine("RPC server farm started. Press Enter to exit.");
        Console.ReadLine();
    }
}
```

### Monitoring and Observability

```csharp
public class RpcMetrics
{
    private readonly Histogram _requestDuration;
    private readonly Counter _requestsTotal;
    private readonly Counter _requestsTimedOut;
    private readonly Gauge _pendingRequests;
    
    public RpcMetrics(IMeterFactory meterFactory)
    {
        var meter = meterFactory.Create("RpcClient");
        
        _requestDuration = meter.CreateHistogram<double>("rpc_request_duration_seconds");
        _requestsTotal = meter.CreateCounter<long>("rpc_requests_total");
        _requestsTimedOut = meter.CreateCounter<long>("rpc_requests_timeout_total");
        _pendingRequests = meter.CreateGauge<long>("rpc_pending_requests");
    }
    
    public async Task<T> MeasureRequest<T>(
        string operation, 
        Func<Task<T>> request)
    {
        var sw = Stopwatch.StartNew();
        _requestsTotal.Add(1, new("operation", operation));
        _pendingRequests.Add(1, new("operation", operation));
        
        try
        {
            var result = await request();
            
            _requestDuration.Record(sw.Elapsed.TotalSeconds, 
                new("operation", operation), 
                new("status", "success"));
            
            return result;
        }
        catch (TimeoutException)
        {
            _requestsTimedOut.Add(1, new("operation", operation));
            _requestDuration.Record(sw.Elapsed.TotalSeconds, 
                new("operation", operation), 
                new("status", "timeout"));
            throw;
        }
        catch
        {
            _requestDuration.Record(sw.Elapsed.TotalSeconds, 
                new("operation", operation), 
                new("status", "error"));
            throw;
        }
        finally
        {
            _pendingRequests.Add(-1, new("operation", operation));
        }
    }
}

// Usage
var result = await _metrics.MeasureRequest("GetOrder", async () =>
    await _rpcClient.GetOrderAsync(orderId, TimeSpan.FromSeconds(5)));
```

### Advanced Pattern: Streaming RPC

For long-running operations, stream progress updates:

```csharp
// Server: Send progress updates
public class StreamingRpcServer
{
    public void ProcessLongRunningTask(BasicDeliverEventArgs ea)
    {
        var correlationId = ea.BasicProperties.CorrelationId;
        var replyTo = ea.BasicProperties.ReplyTo;
        
        // Send progress updates
        for (int progress = 0; progress <= 100; progress += 10)
        {
            var update = new { Progress = progress, Status = "Processing" };
            SendReply(replyTo, correlationId, update, isComplete: false);
            Thread.Sleep(500);
        }
        
        // Send final result
        var result = new { Progress = 100, Status = "Complete", Data = "Result data" };
        SendReply(replyTo, correlationId, result, isComplete: true);
    }
    
    private void SendReply(string replyTo, string correlationId, object payload, bool isComplete)
    {
        var props = _channel.CreateBasicProperties();
        props.CorrelationId = correlationId;
        props.Headers = new Dictionary<string, object>
        {
            { "is-complete", isComplete }
        };
        
        _channel.BasicPublish("", replyTo, props, 
            Encoding.UTF8.GetBytes(JsonSerializer.Serialize(payload)));
    }
}

// Client: Receive progress updates
public async Task<TResult> CallWithProgress<TResult>(
    string request,
    Action<int> onProgress)
{
    var correlationId = Guid.NewGuid().ToString();
    var tcs = new TaskCompletionSource<TResult>();
    
    _consumer.Received += (model, ea) =>
    {
        if (ea.BasicProperties.CorrelationId != correlationId)
            return;
        
        var isComplete = ea.BasicProperties.Headers.TryGetValue("is-complete", out var completeObj) &&
                        (bool)completeObj;
        
        var response = JsonSerializer.Deserialize<ProgressResponse>(
            Encoding.UTF8.GetString(ea.Body.ToArray()));
        
        if (isComplete)
        {
            tcs.SetResult((TResult)response.Data);
        }
        else
        {
            onProgress(response.Progress);
        }
    };
    
    // Send request
    SendRequest(correlationId, request);
    
    return await tcs.Task;
}
```

**When to Use Request-Reply:**

✅ **Good use cases:**
- Need response from remote service
- Want messaging benefits (durability, retries, load balancing)
- Can tolerate slightly higher latency than HTTP (typically +5-50ms)
- Need to decouple caller from service location
- Service registry not available or preferred
- Want built-in load balancing across multiple servers
- Need persistent request queue for reliability

❌ **Poor use cases:**
- Need very low latency (<5ms) - use HTTP/gRPC
- Request-response is truly synchronous (blocking user interface)
- Simple point-to-point communication suffices
- Real-time requirements (use WebSocket)
- Large payload transfers (use HTTP with streaming)

**Comparison with alternatives:**

| Aspect | Request-Reply | HTTP/REST | gRPC |
|--------|---------------|-----------|------|
| Latency | Medium | Low | Very Low |
| Reliability | High (broker) | Medium | Medium |
| Load balancing | Built-in | Needs LB | Needs LB |
| Coupling | Loose | Tight | Medium |
| Tooling | Limited | Excellent | Good |
