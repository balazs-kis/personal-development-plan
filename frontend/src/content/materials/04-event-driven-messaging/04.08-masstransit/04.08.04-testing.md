# Lesson 4: Testing with MassTransit

## Learning Objectives

By the end of this lesson, you will be able to:
- Test message consumers in isolation
- Use test harnesses to verify message flow
- Test sagas and state machines
- Mock external dependencies
- Implement integration tests with real brokers

---

## Introduction

Testing messaging systems can be challenging—messages are asynchronous, involve external brokers, and span multiple services. MassTransit provides excellent testing support through **test harnesses** that allow you to verify message behavior without real message brokers, making tests fast, reliable, and isolated.

### Testing Consumers

```csharp
[Test]
public async Task OrderSubmittedConsumer_ProcessesMessage()
{
    // Arrange
    var orderId = Guid.NewGuid();
    var customerId = "customer-123";
    
    // Act: Publish message
    await _harness.Bus.Publish<OrderSubmitted>(new
    {
        OrderId = orderId,
        CustomerId = customerId,
        TotalAmount = 100m,
        SubmittedAt = DateTime.UtcNow
    });
    
    // Assert: Message was consumed
    Assert.That(await _harness.Consumed.Any<OrderSubmitted>(), Is.True);
    
    // Assert: Consumer processed it
    var consumerHarness = _harness.Consumer<OrderSubmittedConsumer>();
    Assert.That(await consumerHarness.Consumed.Any<OrderSubmitted>(), Is.True);
    
    // Assert: No faults
    Assert.That(await _harness.Published.Any<Fault<OrderSubmitted>>(), Is.False);
}
```

### Testing Sagas

```csharp
[TestFixture]
public class OrderStateMachineTests
{
    private ITestHarness _harness;
    private ISagaStateMachineTestHarness<OrderStateMachine, OrderState> _sagaHarness;
    
    [OneTimeSetUp]
    public async Task Setup()
    {
        _harness = new InMemoryTestHarness();
        
        _sagaHarness = _harness.StateMachineSaga<OrderState, OrderStateMachine>(
            new InMemorySagaRepository<OrderState>());
        
        await _harness.Start();
    }
    
    [Test]
    public async Task OrderStateMachine_HappyPath()
    {
        // Arrange
        var orderId = Guid.NewGuid();
        
        // Act: Submit order
        await _harness.Bus.Publish<OrderSubmitted>(new
        {
            OrderId = orderId,
            CustomerId = "customer-123",
            TotalAmount = 100m
        });
        
        // Assert: Saga created
        Assert.That(await _sagaHarness.Created.Any(x => x.CorrelationId == orderId), Is.True);
        
        // Assert: In AwaitingPayment state
        var saga = _sagaHarness.Created.ContainsInState(orderId, _sagaHarness.StateMachine.AwaitingPayment);
        Assert.That(saga, Is.Not.Null);
        
        // Act: Process payment
        await _harness.Bus.Publish<PaymentProcessed>(new
        {
            OrderId = orderId,
            Amount = 100m
        });
        
        // Assert: Transitioned to Paid
        saga = _sagaHarness.Created.ContainsInState(orderId, _sagaHarness.StateMachine.Paid);
        Assert.That(saga, Is.Not.Null);
        
        // Assert: Published ShipOrder command
        Assert.That(await _harness.Published.Any<ShipOrder>(), Is.True);
        
        // Act: Ship order
        await _harness.Bus.Publish<OrderShipped>(new
        {
            OrderId = orderId
        });
        
        // Assert: Saga completed
        Assert.That(await _sagaHarness.Consumed.Any<OrderShipped>(), Is.True);
        
        var sagaInstance = _sagaHarness.Sagas.Contains(orderId);
        Assert.That(sagaInstance, Is.Null);  // Finalized and removed
    }
    
    [Test]
    public async Task OrderStateMachine_PaymentFailed_CancelsOrder()
    {
        // Arrange
        var orderId = Guid.NewGuid();
        
        // Act
        await _harness.Bus.Publish<OrderSubmitted>(new { OrderId = orderId });
        
        await _harness.Bus.Publish<PaymentFailed>(new
        {
            OrderId = orderId,
            Reason = "Insufficient funds"
        });
        
        // Assert: Transitioned to Cancelled
        var saga = _sagaHarness.Created.ContainsInState(
            orderId,
            _sagaHarness.StateMachine.Cancelled);
        
        Assert.That(saga, Is.Not.Null);
        Assert.That(saga.FailureReason, Is.EqualTo("Insufficient funds"));
        
        // Assert: Published OrderCancelled
        Assert.That(await _harness.Published.Any<OrderCancelled>(), Is.True);
    }
}
```

```csharp
[Category("Integration")]
public class OrderIntegrationTests : IAsyncLifetime
{
    private WebApplicationFactory<Program> _factory;
    private IBusControl _bus;
    
    public async Task InitializeAsync()
    {
        _factory = new WebApplicationFactory<Program>()
            .WithWebHostBuilder(builder =>
            {
                builder.ConfigureServices(services =>
                {
                    // Use test database
                    services.RemoveAll<DbContextOptions<OrderDbContext>>();
                    services.AddDbContext<OrderDbContext>(options =>
                        options.UseInMemoryDatabase("TestDb"));
                });
            });
        
        // Create separate bus for testing

        {
            cfg.Host("localhost", "/", h =>
            {
                h.Username("guest");
                h.Password("guest");
            });
        });
        
        await _bus.StartAsync();
    }
    
    [Test]
    public async Task PlaceOrder_ProcessedSuccessfully()
    {
        // Arrange
        var client = _factory.CreateClient();
        var orderId = Guid.NewGuid();
        
        var taskCompletion = new TaskCompletionSource<OrderValidated>();
        
        // Subscribe to OrderValidated event
        var handle = _bus.ConnectReceiveEndpoint("test-queue", e =>
        {
            e.Handler<OrderValidated>(context =>
            {
                taskCompletion.SetResult(context.Message);
                return Task.CompletedTask;
            });
        });
        
        await handle.Ready;
        
        // Act: Submit order via API
        var response = await client.PostAsJsonAsync("/api/orders", new

            CustomerId = "customer-123",
            Items = new[] { new { ProductId = "prod-1", Quantity = 2 } }
        });
        
        // Assert: API returns success
        Assert.That(response.IsSuccessStatusCode, Is.True);
        
        // Wait for OrderValidated event
        var validated = await taskCompletion.Task.WaitAsync(TimeSpan.FromSeconds(10));
        
        Assert.That(validated, Is.Not.Null);
        Assert.That(validated.OrderId, Is.Not.Empty);
    }
    
    public async Task DisposeAsync()
    {
        await _bus.StopAsync();

    }
}
```

### Testing Retry Logic

```csharp
[Test]
public async Task FailingConsumer_RetriesBeforeFaulting()
{
    // Arrange
    var attemptCount = 0;
    
    var services = new ServiceCollection();
    services.AddScoped<FailingService>(_ => new FailingService(() => attemptCount++));
    
    services.AddMassTransitTestHarness(cfg =>
    {
        cfg.AddConsumer<FailingConsumer>();
        
        cfg.UsingInMemory((context, config) =>
        {
            config.UseMessageRetry(r => r.Immediate(3));
            config.ConfigureEndpoints(context);
        });
    });
    
    var provider = services.BuildServiceProvider();
    var harness = provider.GetRequiredService<ITestHarness>();
    
    await harness.Start();
    
    try
    {
        // Act
        await harness.Bus.Publish<TestMessage>(new { Value = "test" });
        
        // Wait for processing
        await Task.Delay(TimeSpan.FromSeconds(2));
        
        // Assert: Retried 3 times (4 total attempts)
        Assert.That(attemptCount, Is.EqualTo(4));
        
        // Assert: Faulted after retries
        Assert.That(await harness.Published.Any<Fault<TestMessage>>(), Is.True);
    }
    finally
    {
        await harness.Stop();
    }
}

public class FailingConsumer : IConsumer<TestMessage>
{
    private readonly FailingService _service;
    
    public FailingConsumer(FailingService service)
    {
        _service = service;
    }
    
    public async Task Consume(ConsumeContext<TestMessage> context)
    {
        _service.IncrementAttempts();
        throw new InvalidOperationException("Simulated failure");
    }
}

public class FailingService
{
    private readonly Action _onAttempt;
    
    public FailingService(Action onAttempt)
    {
        _onAttempt = onAttempt;
    }
    
    public void IncrementAttempts() => _onAttempt();
}
```

### Performance Testing

```csharp
[Test]
[Category("Performance")]
public async Task Consumer_ProcessesHighVolume()
{
    // Arrange
    const int messageCount = 10000;
    var harness = new InMemoryTestHarness();
    harness.Consumer<OrderSubmittedConsumer>(cfg =>
    {
        cfg.UseConcurrentMessageLimit(100);
    });
    
    await harness.Start();
    
    try
    {
        var sw = Stopwatch.StartNew();
        
        // Act: Publish 10k messages
        var tasks = Enumerable.Range(0, messageCount)
            .Select(i => harness.Bus.Publish<OrderSubmitted>(new
            {
                OrderId = Guid.NewGuid(),
                CustomerId = $"customer-{i}"
            }));
        
        await Task.WhenAll(tasks);
        
        // Wait for all to be consumed
        await harness.Consumed.Any<OrderSubmitted>(
            context => context.Count() == messageCount,
            timeout: TimeSpan.FromMinutes(2));
        
        sw.Stop();
        
        // Assert: Performance metrics
        var messagesPerSecond = messageCount / sw.Elapsed.TotalSeconds;
        
        Console.WriteLine($"Processed {messageCount} messages in {sw.Elapsed.TotalSeconds:F2}s");
        Console.WriteLine($"Throughput: {messagesPerSecond:F2} messages/second");
        
        Assert.That(messagesPerSecond, Is.GreaterThan(1000), 
            "Should process at least 1000 messages per second");
    }
    finally
    {
        await harness.Stop();
    }
}
```

## Self-Check Questions

1. What's the difference between test harness and real broker tests?
   - **Answer:** Test harness uses in-memory transport (fast, isolated, no dependencies). Real broker tests use actual infrastructure (slower, realistic, catch transport-specific issues).

2. How do you verify a message was consumed?
   - **Answer:** Use `harness.Consumed.Any<TMessage>()` to check if any consumer received the message. Access `harness.Consumed.Select<TMessage>()` for specific message details.

3. How do you test saga state transitions?
   - **Answer:** Use `ISagaStateMachineTestHarness` to publish events and verify state changes with `sagaHarness.Created.ContainsInState()`. Check published commands/events with `harness.Published.Any<T>()`.

4. What's the purpose of `TaskCompletionSource` in tests?
   - **Answer:** Allows async tests to wait for specific events. Set result when the expected message arrives, then await the task with timeout to synchronize test execution.

5. When should you use integration tests vs unit tests?
   - **Answer:** Unit tests for consumer logic, validation, transforms (fast feedback). Integration tests for end-to-end flows, transport behavior, persistence (realistic scenarios).

6. How do you test timeout scenarios in sagas?
   - **Answer:** Use scheduled message support in test harness or manually advance time. Publish the timeout event directly to verify saga behavior.

7. How do you test filter behavior?
   - **Answer:** Use `OnConfigureReceiveEndpoint` to add filters before consumer. Publish message and verify filter side effects (logging, metrics, modified headers).

8. What's the best way to test error handling?
   - **Answer:** Create consumers that throw exceptions. Verify retry attempts, fault message publication, and final state. Mock dependencies to control failure scenarios.

## Key Takeaways

- **Test harness** provides in-memory transport for fast, isolated unit tests without external dependencies
- **Consumer harness** tracks messages consumed by specific consumer types
- **Saga harness** verifies state transitions, correlation, and saga lifecycle
- **Publish/Send tracking** allows assertions on messages published or sent during consumer execution
- **Request/response** can be tested using `IRequestClient` from the test harness
- **Integration tests** with real brokers catch transport-specific issues and verify end-to-end behavior
- **Docker Compose** provides consistent integration test environments
- **Performance tests** measure throughput and verify concurrency limits
- **Fault testing** verifies retry logic, error handling, and compensation behavior
- **TaskCompletionSource** synchronizes async test execution with message arrivals
- **Test categories** organize tests by speed/scope (Unit, Integration, Performance)
- **Mocking** dependencies in consumers enables isolated testing of business logic
