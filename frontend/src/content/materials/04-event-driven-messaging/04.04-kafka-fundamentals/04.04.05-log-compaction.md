## Introduction

Kafka typically retains messages based on time or size limits, after which they're deleted. However, for certain use cases—like maintaining the latest state of entities or implementing changelog streams—you need to keep the most recent value for each key indefinitely while discarding older values.

**Log compaction** is Kafka's solution to this problem. Instead of deleting old messages based on time, compaction keeps the latest value for each message key and removes older values. This enables Kafka topics to serve as long-term state stores, change data capture (CDC) logs, and event-sourced aggregate stores.

## Key Concepts Summary

### What is Log Compaction?

**Standard retention (time/size-based):**
```
Topic messages over time:
T0: Key=A, Value=1
T1: Key=B, Value=2
T2: Key=A, Value=3  (updates Key A)
T3: Key=C, Value=4
T4: (retention expires)
T5: All messages deleted ✗
```

**Log compaction (key-based):**
```
Topic messages over time:
T0: Key=A, Value=1
T1: Key=B, Value=2
T2: Key=A, Value=3  (updates Key A)
T3: Key=C, Value=4
T4: (compaction runs)
T5: Compacted result:
    Key=A, Value=3  ✓ (latest for Key A)
    Key=B, Value=2  ✓ (latest for Key B)
    Key=C, Value=4  ✓ (latest for Key C)
```

**Key characteristics:**
- Keeps the **latest value** for each message key
- Removes older values for the same key
- Messages with `null` values act as **tombstones** (deletion markers)
- Compaction is a background process (doesn't happen immediately)
- Guarantees: every key's latest value is retained indefinitely

### How Log Compaction Works

Kafka divides the log into two sections:

```
Partition Log Structure:
|<------- Clean (compacted) ------->|<----- Dirty (uncompacted) ----->|
[latest K1] [latest K2] [latest K3] [K1=v1][K2=v1][K1=v2][K3=v1][K2=v2]
                                     ↑
                                Clean Point
```

**1. Clean Section:**
- Already compacted
- Contains only the latest value for each key
- Immutable until next compaction

**2. Dirty Section:**
- New messages not yet compacted
- May contain duplicate keys
- Compacted when it reaches a threshold

**Compaction process:**
1. Background thread scans the dirty section
2. Builds an in-memory map: `key → latest offset`
3. Copies only the latest value for each key to a new segment
4. Deletes old segments
5. Moves clean point forward

**Guarantees during compaction:**
- Consumers can still read while compaction runs
- No message is deleted if it's the latest value for its key
- Ordering within a partition is preserved

### Configuration: Enabling Log Compaction

```bash
# Create a compacted topic
kafka-topics --create \
  --topic user-profiles \
  --partitions 3 \
  --replication-factor 3 \
  --config cleanup.policy=compact \
  --config min.cleanable.dirty.ratio=0.5 \
  --config segment.ms=100 \
  --bootstrap-server localhost:9092
```

```csharp
// Using AdminClient in .NET to create compacted topic
using var adminClient = new AdminClientBuilder(config).Build();

await adminClient.CreateTopicsAsync(new[]
{
    new TopicSpecification
    {
        Name = "user-profiles",
        NumPartitions = 3,
        ReplicationFactor = 3,
        Configs = new Dictionary<string, string>
        {
            ["cleanup.policy"] = "compact",
            ["min.cleanable.dirty.ratio"] = "0.5",
            ["segment.ms"] = "100",
            ["delete.retention.ms"] = "86400000"  // 24 hours
        }
    }
});
```

**Key configuration parameters:**

### 1. `cleanup.policy`

- **`delete`** (default): Time/size-based retention
- **`compact`**: Log compaction enabled
- **`compact,delete`**: Both compaction and time-based retention

```
Example with "compact,delete":
- Compact to keep latest values
- Delete compacted messages older than retention.ms
```

### 2. `min.cleanable.dirty.ratio`

Minimum ratio of dirty section to total log before compaction triggers:

```
Example: min.cleanable.dirty.ratio=0.5 (50%)

Log size: 100 MB
Clean section: 60 MB
Dirty section: 40 MB
Ratio: 40/100 = 0.4 → No compaction yet

After more messages:
Clean section: 60 MB
Dirty section: 60 MB
Ratio: 60/120 = 0.5 → Compaction triggers ✓
```

**Lower values** = more frequent compaction, less disk usage
**Higher values** = less frequent compaction, more disk usage

### 3. `segment.ms` and `segment.bytes`

Control when a new segment is created:

- **`segment.ms`**: Max time before creating new segment (default: 7 days)
- **`segment.bytes`**: Max size before creating new segment (default: 1 GB)

**Why this matters:** Only closed segments can be compacted

```
Active segment (still being written) → Cannot compact
Closed segment → Eligible for compaction
```

**For faster compaction in development:**
```csharp
Configs = new Dictionary<string, string>
{
    ["segment.ms"] = "60000"  // 1 minute (default: 604800000 = 7 days)
}
```

### 4. `delete.retention.ms`

How long tombstones (null values) are retained before deletion:

```csharp
// Publish delete event (tombstone)
await producer.ProduceAsync("user-profiles", new Message<string, UserProfile>
{
    Key = "user-123",
    Value = null  // Tombstone: marks user-123 for deletion
});
```

**Tombstone lifecycle:**
1. `T0`: Tombstone published (`Key=user-123, Value=null`)
2. `T0 to T0+delete.retention.ms`: Tombstone visible to consumers
3. `T0+delete.retention.ms`: Tombstone deleted during compaction

**Why retain tombstones?**
- Ensures all consumers see the deletion
- Consumers that were offline can catch up
- After retention, key is completely removed from log

**Default:** 24 hours (86400000 ms)

### Use Cases for Log Compaction

#### 1. Change Data Capture (CDC)

Capture database changes as Kafka events:

```csharp
// Database update triggers event
public async Task UpdateUser(User user)
{
    await _database.UpdateUser(user);
    
    // Publish change event to compacted topic
    await _producer.ProduceAsync("users-changelog", new Message<string, User>
    {
        Key = user.Id,
        Value = user  // Latest state
    });
}

// Downstream consumers always see latest user state
// Rebuilding consumer can replay topic to get current state of all users
```

**Benefits:**
- Complete audit trail of all changes
- Point-in-time state reconstruction
- Reliable cache invalidation

#### 2. Event Sourcing with Snapshots

Store aggregate snapshots in compacted topic:

```csharp
// Event-sourced Order aggregate
public class Order
{
    public string Id { get; set; }
    public List<OrderEvent> Events { get; set; }
    
    // Snapshot for performance
    public OrderSnapshot ToSnapshot() => new OrderSnapshot
    {
        Id = Id,
        Status = CurrentStatus,
        TotalAmount = CalculateTotal(),
        LastEventSequence = Events.Count
    };
}

// Publish snapshot to compacted topic
await _producer.ProduceAsync("order-snapshots", new Message<string, OrderSnapshot>
{
    Key = order.Id,
    Value = order.ToSnapshot()  // Latest snapshot
});

// Rebuild: Read snapshot + events since snapshot
var snapshot = await ReadLatestSnapshot(orderId);
var events = await ReadEventsSince(orderId, snapshot.LastEventSequence);
var order = snapshot.RehydrateWithEvents(events);
```

#### 3. Configuration Management

Distribute configuration updates:

```csharp
// Topic: "feature-flags" (compacted)
// Key: feature flag name
// Value: enabled/disabled state

await _producer.ProduceAsync("feature-flags", new Message<string, bool>
{
    Key = "dark-mode-enabled",
    Value = true
});

// All services consume compacted topic
// On startup: Read entire topic to get current state of all flags
// At runtime: Listen for updates
```

#### 4. Reference Data / Lookup Tables

Maintain reference data in Kafka:

```csharp
// Topic: "product-catalog" (compacted)
// Key: product SKU
// Value: product details

// Producer updates catalog
await _producer.ProduceAsync("product-catalog", new Message<string, Product>
{
    Key = "SKU-12345",
    Value = new Product { Name = "Widget", Price = 29.99m }
});

// Consumer builds in-memory cache from compacted topic
var productCache = new Dictionary<string, Product>();

consumer.Subscribe("product-catalog");
while (true)
{
    var result = consumer.Consume();
    
    if (result.Message.Value == null)
    {
        // Tombstone: remove from cache
        productCache.Remove(result.Message.Key);
    }
    else
    {
        // Update cache
        productCache[result.Message.Key] = result.Message.Value;
    }
}
```

### Tombstones: Deleting Keys

To remove a key from a compacted topic, publish a message with `null` value:

```csharp
// Delete user profile
await producer.ProduceAsync("user-profiles", new Message<string, UserProfile>
{
    Key = "user-123",
    Value = null  // Tombstone
});
```

**Tombstone behavior:**
1. Tombstone is retained for `delete.retention.ms`
2. Consumers see the tombstone and can react (e.g., remove from cache)
3. After retention period, both tombstone and all previous values for the key are deleted
4. Key no longer exists in the topic

**Important:** Never send `null` values unless you intend to delete the key!

### Compaction Performance Considerations

**Benefits:**
- Bounded storage growth (one value per key)
- Enables infinite retention of latest state
- Faster consumer bootstrap (fewer messages to read)

**Trade-offs:**
- CPU overhead for compaction process
- Memory overhead for compaction buffer
- Temporary disk usage during compaction
- Consumers may see duplicate keys before compaction

**Monitoring compaction:**

```csharp
// Monitor compaction metrics (via JMX/Prometheus)
// Key metrics:
// - kafka.log:type=LogCleanerManager,name=max-dirty-percent
// - kafka.log:type=LogCleaner,name=cleaner-recopy-percent
// - kafka.log:type=Log,name=LogEndOffset
// - kafka.log:type=Log,name=LogStartOffset
```

**Tuning for faster compaction:**
- Decrease `min.cleanable.dirty.ratio` (more frequent)
- Decrease `segment.ms` (close segments sooner)
- Increase cleaner threads (`log.cleaner.threads`)
- Increase cleaner buffer (`log.cleaner.dedupe.buffer.size`)

### Advanced Compaction Configurations

**Server-level settings:**

```bash
# server.properties

# Cleaner threads (more = faster compaction)
log.cleaner.threads=2

# Dedupe buffer (larger = handle more unique keys per pass)
log.cleaner.dedupe.buffer.size=134217728  # 128MB

# I/O buffer size
log.cleaner.io.buffer.size=524288  # 512KB

# Backoff between runs
log.cleaner.backoff.ms=15000  # 15 seconds

# Min compaction lag (prevent compacting too-recent messages)
log.cleaner.min.compaction.lag.ms=0

# Max compaction lag (force compaction if dirty section too old)
log.cleaner.max.compaction.lag.ms=9223372036854775807  # Max long
```

**Topic-level settings:**

```csharp

                {

                    // Keep tombstones for 24 hours

                    // Force compaction if dirty section > 1 day old
                    ["max.compaction.lag.ms"] = "86400000",
                    
                    // Use high compression for compacted logs
                    ["compression.type"] = "zstd"
                }
            }
        });
    }
}
```

### Compaction with Retention

**Hybrid approach: compact + delete:**

```bash
# Compact to remove duplicates, then delete old messages
kafka-topics --alter \
  --topic user-sessions \
  --config cleanup.policy=compact,delete \
  --config retention.ms=604800000 \  # 7 days
  --config min.cleanable.dirty.ratio=0.5 \
  --bootstrap-server localhost:9092
```

**Behavior:**
1. Compaction removes older values for same key
2. After 7 days, compacted messages are deleted
3. Result: Latest state for active users, old users purged

**Use cases:**
- User sessions (keep recent active users)
- Device telemetry (keep recent devices)
- Cache entries (expire old entries)

### Building State Stores from Compacted Topics

**Pattern: Local cache from compacted topic:**

```csharp
public class CompactedTopicCache<TKey, TValue>
{
    private readonly Dictionary<TKey, TValue> _cache = new();
    private readonly IConsumer<TKey, TValue> _consumer;
    
    public async Task BuildCacheAsync()
    {
        _consumer.Subscribe("user-profiles");
        
        // Bootstrap: Read entire topic
        _consumer.Assign(_consumer.Assignment
            .Select(tp => new TopicPartitionOffset(tp, Offset.Beginning)));
        
        while (true)
        {
            var result = _consumer.Consume(TimeSpan.FromMilliseconds(100));
            
            if (result == null)
            {
                // Caught up to end of topic
                break;
            }
            
            if (result.Message.Value == null)
            {
                // Tombstone: remove from cache
                _cache.Remove(result.Message.Key);
            }
            else
            {
                // Update cache
                _cache[result.Message.Key] = result.Message.Value;
            }
        }
        
        _logger.LogInformation($"Cache built: {_cache.Count} entries");
        
        // Continue consuming for updates
        _ = Task.Run(() => ConsumeContinuously());
    }
    
    private async Task ConsumeContinuously()
    {
        while (true)
        {
            var result = _consumer.Consume();
            
            if (result.Message.Value == null)
            {
                _cache.Remove(result.Message.Key);
            }
            else
            {
                _cache[result.Message.Key] = result.Message.Value;
            }
        }
    }
    
    public TValue? Get(TKey key)
    {
        return _cache.TryGetValue(key, out var value) ? value : default;
    }
    
    public IReadOnlyDictionary<TKey, TValue> GetAll()
    {
        return _cache;
    }
}
```

### Compaction for Event Sourcing

**Snapshot pattern:**

```csharp
public class EventSourcedAggregate
{
    public string AggregateId { get; set; }
    public int Version { get; set; }
    public List<DomainEvent> Events { get; set; } = new();
    
    public AggregateSnapshot ToSnapshot()
    {
        return new AggregateSnapshot
        {
            AggregateId = AggregateId,
            Version = Version,
            State = ComputeState(Events),
            SnapshotTime = DateTime.UtcNow
        };
    }
}

public class SnapshotStore
{
    private readonly IProducer<string, AggregateSnapshot> _producer;
    
    public async Task SaveSnapshotAsync(AggregateSnapshot snapshot)
    {
        // Save to compacted topic
        await _producer.ProduceAsync("aggregate-snapshots",
            new Message<string, AggregateSnapshot>
            {
                Key = snapshot.AggregateId,
                Value = snapshot  // Latest snapshot
            });
    }
    
    public async Task<AggregateSnapshot?> LoadSnapshotAsync(string aggregateId)
    {
        // Read latest snapshot from compacted topic
        var consumer = new ConsumerBuilder<string, AggregateSnapshot>(config).Build();
        
        consumer.Assign(new TopicPartitionOffset(
            new TopicPartition("aggregate-snapshots", 0), 
            Offset.Beginning));
        
        AggregateSnapshot? latestSnapshot = null;
        
        while (true)
        {
            var result = consumer.Consume(TimeSpan.FromMilliseconds(100));
            
            if (result == null)
                break;
            
            if (result.Message.Key == aggregateId && result.Message.Value != null)
            {
                latestSnapshot = result.Message.Value;
            }
        }
        
        return latestSnapshot;
    }
}
```

```csharp
public class CompactionTests

    [Fact]
    public async Task TestCompaction()
    {
        // Create compacted topic
        await CreateCompactedTopic("test-compaction", 1, 
            minCleanableDirtyRatio: 0.01,  // Compact aggressively
            segmentMs: 1000);  // Close segments every second
        
        var producer = new ProducerBuilder<string, string>(producerConfig).Build();
        
        // Publish multiple versions of same keys
        await producer.ProduceAsync("test-compaction",
            new Message<string, string> { Key = "k1", Value = "v1" });
        await producer.ProduceAsync("test-compaction",
            new Message<string, string> { Key = "k2", Value = "v2" });
        await producer.ProduceAsync("test-compaction",
            new Message<string, string> { Key = "k1", Value = "v1-updated" });
        await producer.ProduceAsync("test-compaction",
            new Message<string, string> { Key = "k2", Value = "v2-updated" });
        await producer.ProduceAsync("test-compaction",
            new Message<string, string> { Key = "k1", Value = "v1-final" });
        
        // Wait for compaction
        await Task.Delay(TimeSpan.FromSeconds(15));
        
        // Read all messages
        var consumer = new ConsumerBuilder<string, string>(consumerConfig).Build();
        consumer.Assign(new TopicPartitionOffset("test-compaction", 0, Offset.Beginning));
        
        var messages = new Dictionary<string, string>();
        
        while (true)
        {
            var result = consumer.Consume(TimeSpan.FromMilliseconds(100));
            if (result == null)
                break;
            
            messages[result.Message.Key] = result.Message.Value;
        }
        
        // Verify only latest values remain
        Assert.Equal("v1-final", messages["k1"]);
        Assert.Equal("v2-updated", messages["k2"]);
        Assert.Equal(2, messages.Count);
    }
}
```

### Troubleshooting Compaction Issues

**Issue 1: Compaction not running:**

```csharp
public class CompactionDiagnostics
{
    public async Task CheckCompactionStatus()
    {
        var adminClient = new AdminClientBuilder(config).Build();
        var configs = await adminClient.DescribeConfigsAsync(new[]
        {
            new ConfigResource { Type = ResourceType.Topic, Name = "user-profiles" }
        });
        
        foreach (var config in configs)
        {
            var cleanupPolicy = config.Entries
                .FirstOrDefault(e => e.Name == "cleanup.policy")?.Value;
            
            if (cleanupPolicy != "compact" && cleanupPolicy != "compact,delete")
            {
                _logger.LogError($"Compaction not enabled! cleanup.policy={cleanupPolicy}");
            }
            
            var dirtyRatio = config.Entries
                .FirstOrDefault(e => e.Name == "min.cleanable.dirty.ratio")?.Value;
            
            _logger.LogInformation($"min.cleanable.dirty.ratio={dirtyRatio}");
        }
    }
}
```

**Issue 2: Slow compaction:**

```
Symptoms:
- High dirty ratio
- Growing disk usage
- Slow consumer bootstrap

Solutions:
- Lower min.cleanable.dirty.ratio
- Lower segment.ms
- Increase log.cleaner.threads
- Increase log.cleaner.dedupe.buffer.size
```

**Issue 3: Tombstones not deleted:**

```
Check delete.retention.ms setting:
- Too high = tombstones kept too long
- Too low = consumers may miss deletions
```
