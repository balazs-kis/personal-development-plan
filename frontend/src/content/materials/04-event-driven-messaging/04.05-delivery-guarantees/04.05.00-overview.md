# Chapter 4.5: Message Delivery Guarantees

## Overview
This chapter explores the critical concept of delivery guarantees in messaging systems. You'll understand the trade-offs between at-most-once, at-least-once, and exactly-once semantics, and learn how to implement each with RabbitMQ and Kafka. We'll cover idempotent consumers, transactional messaging, and practical patterns for ensuring correctness in distributed systems.

## Key Concepts
- **At-Most-Once Delivery:** messages may be lost but never duplicated—fastest, lowest reliability.
- **At-Least-Once Delivery:** messages never lost but may be duplicated—common default, requires idempotence.
- **Exactly-Once Semantics:** messages delivered once and only once—strongest guarantee, highest complexity.
- **Idempotent Consumers:** designing consumers that handle duplicate messages safely.
- **Transactional Messaging:** atomic operations across message production, consumption, and database updates.
