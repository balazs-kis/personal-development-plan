## Introduction

PostgreSQL's full-text search is a powerful built-in feature that eliminates the need for external search engines in many applications. Unlike LIKE operators or regular expressions, full-text search provides linguistic support, stemming, stop word removal, and relevance ranking. At its core are two specialized data types: `tsvector` (representing documents) and `tsquery` (representing search queries).

## Key Concepts Summary

### The tsvector Data Type

`tsvector` represents a document in a form optimized for text search. It contains a sorted list of distinct lexemes (normalized words) with positional information.

**Creating a tsvector:**
```sql
-- Basic conversion
SELECT to_tsvector('english', 'The quick brown fox jumps over the lazy dog');
-- Result: 'brown':3 'dog':9 'fox':4 'jump':5 'lazi':8 'quick':2

-- Note: Stop words ('the', 'over') are removed
-- Words are stemmed ('jumps' → 'jump', 'lazy' → 'lazi')
-- Numbers indicate word positions
```

**What happens during conversion:**
1. Text is parsed into tokens
2. Stop words (common words like 'the', 'a', 'an') are removed
3. Words are converted to lexemes (normalized forms) through stemming
4. Positional information is preserved
5. Results are sorted and deduplicated

**Example with detailed output:**
```sql
SELECT to_tsvector('english', 'PostgreSQL databases are powerful databases');
-- Result: 'databas':2,6 'postgresql':1 'power':4

-- 'databases' appears at positions 2 and 6 (stemmed to 'databas')
-- 'are' is removed as a stop word
-- 'powerful' is stemmed to 'power'
```

### The tsquery Data Type

`tsquery` represents a search query with logical operators for combining search terms.

**Creating queries with different functions:**

```sql
-- to_tsquery: Requires explicit operators
SELECT to_tsquery('english', 'postgresql & database');
-- Matches documents containing both 'postgresql' AND 'database'

SELECT to_tsquery('english', 'postgresql | mysql');
-- Matches documents containing 'postgresql' OR 'mysql'

SELECT to_tsquery('english', 'postgresql & !mysql');
-- Matches documents with 'postgresql' but NOT 'mysql'

-- plainto_tsquery: Converts plain text to query (implicitly ANDs terms)
SELECT plainto_tsquery('english', 'postgresql database');
-- Equivalent to: 'postgresql' & 'database'
-- More user-friendly for simple searches

-- phraseto_tsquery: Searches for exact phrases
SELECT phraseto_tsquery('english', 'full text search');
-- Matches only when words appear in exact order

-- websearch_to_tsquery: Google-like syntax (PostgreSQL 11+)
SELECT websearch_to_tsquery('english', '"full text" -search');
-- Supports quoted phrases and minus for exclusion
```

**Query operators:**
- `&` (AND): Both terms must be present
- `|` (OR): Either term must be present
- `!` (NOT): Term must not be present
- `<->` (FOLLOWED BY): Terms must be adjacent in that order
- `<N>` (DISTANCE): Terms within N words of each other

### The @@ Match Operator

The `@@` operator checks if a `tsvector` matches a `tsquery`:

```sql
-- Basic matching
SELECT 'quick brown fox'::tsvector @@ 'fox'::tsquery;
-- Returns: true

-- Using conversion functions
SELECT to_tsvector('english', 'PostgreSQL is a powerful database') 
       @@ to_tsquery('english', 'postgresql & database');
-- Returns: true (both terms present)

-- Practical table search
SELECT title, body
FROM articles
WHERE to_tsvector('english', title || ' ' || body) 
      @@ plainto_tsquery('english', 'full text search');
```

### Stop Words and Language Configuration

Stop words are common words filtered out during text processing:

```sql
-- English stop words: 'the', 'a', 'an', 'and', 'or', 'but', 'in', 'on', etc.
SELECT to_tsvector('english', 'the cat and the dog');
-- Result: 'cat':2 'dog':5
-- 'the' and 'and' are removed

-- Different languages have different stop words and stemming rules
SELECT to_tsvector('spanish', 'el gato y el perro');
-- Uses Spanish stop words and stemming

-- Simple configuration (no stop words, no stemming)
SELECT to_tsvector('simple', 'the running cats');
-- Result: 'cats':3 'running':2 'the':1
-- All words preserved, no stemming
```

### Lexeme Normalization (Stemming)

Stemming reduces words to their root form:

```sql
SELECT to_tsvector('english', 'running runs ran runner');
-- Result: 'ran':3 'run':1,2,4
-- 'running', 'runs', and 'runner' all stem to 'run'
-- 'ran' is irregular, so it stays as 'ran'

-- This allows searches to match related forms
SELECT to_tsvector('english', 'The database is running') 
       @@ to_tsquery('english', 'run');
-- Returns: true (matches 'running')
```

## Practical Examples

### Example 1: Basic Article Search

```sql
-- Create a sample table
CREATE TABLE articles (
    id SERIAL PRIMARY KEY,
    title TEXT,
    body TEXT
);

INSERT INTO articles (title, body) VALUES
    ('Introduction to PostgreSQL', 'PostgreSQL is a powerful open-source database'),
    ('MySQL vs PostgreSQL', 'Both MySQL and PostgreSQL are popular databases'),
    ('NoSQL Databases', 'MongoDB and Redis are NoSQL databases');

-- Search for articles about PostgreSQL
SELECT id, title
FROM articles
WHERE to_tsvector('english', title || ' ' || body) 
      @@ plainto_tsquery('english', 'postgresql');
-- Returns: rows 1 and 2

-- Search with AND operator
SELECT id, title
FROM articles
WHERE to_tsvector('english', title || ' ' || body) 
      @@ to_tsquery('english', 'postgresql & powerful');
-- Returns: row 1 only
```

### Example 2: Understanding Operator Differences

```sql
-- OR operator: matches either term
SELECT to_tsvector('english', 'PostgreSQL database') 
       @@ to_tsquery('english', 'postgresql | mysql');
-- Returns: true (postgresql is present)

-- AND operator: requires both terms
SELECT to_tsvector('english', 'PostgreSQL database') 
       @@ to_tsquery('english', 'postgresql & mysql');
-- Returns: false (mysql is not present)

-- NOT operator: excludes term
SELECT to_tsvector('english', 'PostgreSQL database') 
       @@ to_tsquery('english', 'database & !mysql');
-- Returns: true (has database, doesn't have mysql)
```

### Example 3: Function Comparison

```sql
-- Sample text
WITH doc AS (
    SELECT 'PostgreSQL full text search is powerful' AS content
)

-- to_tsquery: Strict syntax
SELECT content, 
       to_tsvector('english', content) @@ to_tsquery('english', 'full & text')
FROM doc;
-- Works: explicit operators

-- plainto_tsquery: User-friendly
SELECT content, 
       to_tsvector('english', content) @@ plainto_tsquery('english', 'full text')
FROM doc;
-- Works: automatically adds & operator

-- phraseto_tsquery: Exact phrase
SELECT content, 
       to_tsvector('english', content) @@ phraseto_tsquery('english', 'full text search')
FROM doc;
-- Works: matches exact phrase

-- websearch_to_tsquery: Google-like
SELECT content, 
       to_tsvector('english', content) @@ websearch_to_tsquery('english', '"full text" search')
FROM doc;
-- Works: supports quoted phrases
```

## Common Patterns and Best Practices

### 1. Concatenating Multiple Columns

```sql
-- Search across title and body
SELECT * FROM articles
WHERE to_tsvector('english', 
                  COALESCE(title, '') || ' ' || COALESCE(body, '')) 
      @@ plainto_tsquery('english', 'search terms');
```

### 2. Handling NULL Values

```sql
-- Use COALESCE to handle NULLs
SELECT to_tsvector('english', COALESCE(column_name, ''));
```

### 3. Choosing the Right Query Function

- **to_tsquery()**: When you need full control with explicit operators
- **plainto_tsquery()**: For simple user searches (most common)
- **phraseto_tsquery()**: For exact phrase matching
- **websearch_to_tsquery()**: For Google-like search UX

### 4. Performance Consideration

```sql
-- This is slow on large tables (converts on every search)
SELECT * FROM articles
WHERE to_tsvector('english', body) @@ plainto_tsquery('english', 'search');

-- Better: Use a generated column (covered in next lessons)
ALTER TABLE articles ADD COLUMN search_vector tsvector 
    GENERATED ALWAYS AS (to_tsvector('english', title || ' ' || body)) STORED;
```

## Key Takeaways

- `tsvector` represents searchable documents with normalized lexemes
- `tsquery` represents search queries with logical operators
- The `@@` operator performs the matching
- Stop words are automatically removed based on language configuration
- Stemming normalizes word variations to their root forms
- Different query functions offer different levels of control and user-friendliness
- Full-text search is more powerful than LIKE or regex for natural language searching
