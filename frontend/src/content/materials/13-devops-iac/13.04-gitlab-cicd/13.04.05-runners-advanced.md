## Key Concepts Summary

### GitLab Runner Architecture

```yaml
# GitLab.com provides shared runners automatically
# Self-managed GitLab requires runner installation

# Runners pick up jobs based on:
# 1. Tags matching
# 2. Runner type (shared, group, specific)
# 3. Runner availability

build:
  tags:
    - docker       # Requires runner with 'docker' tag
    - linux        # Requires runner with 'linux' tag
  script:
    - make build
```

### Docker Executor

```yaml
# Most common executor - runs jobs in Docker containers

# Default image for all jobs
default:
  image: node:20

stages:
  - build
  - test

build:
  # Uses default image
  script:
    - npm ci
    - npm run build

test:
  # Override with different image
  image: node:18
  script:
    - npm test
```

### Docker-in-Docker (DinD)

```yaml
# Build Docker images inside pipeline
build:docker:
  image: docker:latest
  services:
    - docker:dind
  variables:
    DOCKER_DRIVER: overlay2
    DOCKER_TLS_CERTDIR: "/certs"
  before_script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
  script:
    - docker build -t $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA .
    - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
```

### Using Services

```yaml
# Run service containers alongside job
test:integration:
  image: node:20
  services:
    - name: postgres:15
      alias: db
    - redis:7-alpine
  variables:
    POSTGRES_DB: testdb
    POSTGRES_USER: test
    POSTGRES_PASSWORD: test
    POSTGRES_HOST_AUTH_METHOD: trust
    # Connect to services by alias/name
    DATABASE_URL: "postgresql://test:test@db:5432/testdb"
    REDIS_URL: "redis://redis:6379"
  script:
    - npm run test:integration
```

## GitLab Auto DevOps

### Enabling Auto DevOps

```yaml
# Auto DevOps works without .gitlab-ci.yml
# Automatically detects language and framework
# Provides build, test, security, and deploy stages

# To customize Auto DevOps, create .gitlab-ci.yml:
include:
  - template: Auto-DevOps.gitlab-ci.yml

# Override specific jobs
test:
  extends: .test
  script:
    - echo "Custom test script"

# Disable specific stages
variables:
  SAST_DISABLED: "true"
  DAST_DISABLED: "true"
```

### Auto DevOps Stages

```yaml
# Auto DevOps includes these stages:
# - build: Dockerfile or buildpacks
# - test: Language-specific tests
# - code_quality: Code quality analysis
# - sast: Static application security testing
# - dependency_scanning: Check for vulnerabilities
# - container_scanning: Scan Docker images
# - dast: Dynamic application security testing
# - review: Deploy review apps
# - staging: Deploy to staging
# - production: Deploy to production
# - performance: Performance testing
# - cleanup: Remove review apps
```

### Customizing Auto DevOps

```yaml
# Include Auto DevOps template
include:
  - template: Auto-DevOps.gitlab-ci.yml

# Customize variables
variables:
  POSTGRES_ENABLED: "true"
  POSTGRES_VERSION: "15"
  POSTGRES_DB: "myapp"
  POSTGRES_USER: "myapp"
  POSTGRES_PASSWORD: "secret"
  
  # Kubernetes settings
  KUBE_NAMESPACE: "myapp-production"
  PRODUCTION_REPLICAS: 3

# Add custom jobs
before_deploy:
  stage: .pre
  script:
    - echo "Running before deployment"

# Override existing jobs
production:
  extends: .production
  before_script:
    - echo "Custom production setup"
```

## Advanced Pipeline Patterns

### Parent-Child Pipelines

```yaml
# Parent pipeline triggers child pipelines
trigger:downstream:
  trigger:
    include: .gitlab-ci-downstream.yml
    strategy: depend  # Wait for child to complete

# .gitlab-ci-downstream.yml
stages:
  - test

test:child:
  script:
    - npm test
```

### Multi-Project Pipelines

```yaml
# Trigger pipeline in another project
trigger:api:
  trigger:
    project: group/api-project
    branch: main
    strategy: depend

# With variable passing
trigger:service:
  trigger:
    project: group/service-project
    branch: main
  variables:
    DEPLOY_ENV: staging
```

### Merge Request Pipelines

```yaml
workflow:
  rules:
    # Create pipeline for merge requests
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    # And for main branch
    - if: $CI_COMMIT_BRANCH == "main"

test:
  script:
    - npm test
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == "main"

# Only run in merge request pipelines
test:mr-only:
  script:
    - npm run lint
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
```

### Scheduled Pipelines

```yaml
# Nightly builds (configured in UI: CI/CD → Schedules)
nightly:build:
  script:
    - make full-build
  only:
    - schedules

# Different behavior for scheduled runs
test:
  script:
    - |
      if [ "$CI_PIPELINE_SOURCE" == "schedule" ]; then
        npm run test:full
      else
        npm run test:quick
      fi
```

## Pipeline Optimization Techniques

### Parallel Jobs

```yaml
# Split tests across multiple jobs
test:
  parallel: 5
  script:
    - npm run test -- --shard=$CI_NODE_INDEX/$CI_NODE_TOTAL

# Parallel matrix
test:matrix:
  parallel:
    matrix:
      - BROWSER: [chrome, firefox, safari]
        OS: [linux, windows]
  script:
    - npm run test -- --browser=$BROWSER --os=$OS
```

### Interruptible Jobs

```yaml
# Cancel old pipeline jobs when new commit is pushed
build:
  interruptible: true
  script:
    - make build

# Don't interrupt deployment
deploy:
  interruptible: false
  script:
    - make deploy
```

### Resource Groups

```yaml
# Ensure only one deployment at a time
deploy:production:
  resource_group: production
  script:
    - ./deploy.sh production
  environment:
    name: production
```

### Conditional Job Execution

```yaml
# Run only when specific files change
test:frontend:
  script:
    - cd frontend && npm test
  rules:
    - changes:
        - "frontend/**/*"

test:backend:
  script:
    - cd backend && dotnet test
  rules:
    - changes:
        - "backend/**/*"

# Skip pipelines for documentation-only changes
workflow:
  rules:
    - if: $CI_COMMIT_MESSAGE =~ /\[skip ci\]/
      when: never
    - changes:
        - "*.md"
        - "docs/**/*"
      when: never
    - when: always
```

## Complete Advanced Example

```yaml
# .gitlab-ci.yml
image: mcr.microsoft.com/dotnet/sdk:8.0

variables:
  DOCKER_DRIVER: overlay2
  DOCKER_TLS_CERTDIR: "/certs"

# Global cache
default:
  cache:
    key:
      files:
        - "**/*.csproj"
    paths:
      - .nuget/
    policy: pull

stages:
  - restore
  - build
  - test
  - security
  - package
  - deploy

# Only run pipeline for MRs and main branch
workflow:
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == "main"
    - if: $CI_PIPELINE_SOURCE == "schedule"

restore:
  stage: restore
  cache:
    key:
      files:
        - "**/*.csproj"
    paths:
      - .nuget/
    policy: pull-push
  script:
    - dotnet restore --packages .nuget/
  artifacts:
    paths:
      - .nuget/
    expire_in: 1 hour

build:
  stage: build
  needs: [restore]
  tags:
    - docker
    - linux
  script:
    - dotnet build --no-restore -c Release
  artifacts:
    paths:
      - "**/bin/Release/"
    expire_in: 1 day
  interruptible: true

# Parallel test execution
test:unit:
  stage: test
  needs: [build]
  parallel: 3
  script:
    - dotnet test --no-build -c Release --filter Category=Unit
  interruptible: true

test:integration:
  stage: test
  needs: [build]
  services:
    - postgres:15
    - redis:7
  variables:
    POSTGRES_DB: testdb
    POSTGRES_USER: test
    POSTGRES_PASSWORD: test
  script:
    - dotnet test --no-build -c Release --filter Category=Integration
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"

# Security scanning
sast:
  stage: security
  include:
    - template: Security/SAST.gitlab-ci.yml
  needs: [build]

dependency_scanning:
  stage: security
  include:
    - template: Security/Dependency-Scanning.gitlab-ci.yml
  needs: [build]

# Build Docker image
package:docker:
  stage: package
  image: docker:latest
  services:
    - docker:dind
  needs:
    - build
    - test:unit
    - test:integration
  before_script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
  script:
    - docker build -t $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA .
    - docker tag $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA $CI_REGISTRY_IMAGE:latest
    - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
    - docker push $CI_REGISTRY_IMAGE:latest
  rules:
    - if: $CI_COMMIT_BRANCH == "main"

# Deploy to staging
deploy:staging:
  stage: deploy
  needs: [package:docker]
  tags:
    - kubernetes
  script:
    - kubectl set image deployment/myapp myapp=$CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
  environment:
    name: staging
    url: https://staging.example.com
    on_stop: stop:staging
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
  resource_group: staging

stop:staging:
  stage: deploy
  tags:
    - kubernetes
  script:
    - kubectl delete deployment myapp
  environment:
    name: staging
    action: stop
  when: manual
  rules:
    - if: $CI_COMMIT_BRANCH == "main"

# Deploy to production
deploy:production:
  stage: deploy
  needs: [deploy:staging]
  tags:
    - kubernetes
  script:
    - kubectl set image deployment/myapp myapp=$CI_REGISTRY_IMAGE:$CI_COMMIT_SHA --namespace=production
  environment:
    name: production
    url: https://example.com
  when: manual
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
  resource_group: production
```

## Runner Configuration Best Practices

### Tagging Strategies

```yaml
# Use descriptive tags
build:linux:
  tags:
    - docker
    - linux
    - x64
  script:
    - make build

build:windows:
  tags:
    - shell
    - windows
    - x64
  script:
    - .\build.ps1

# Environment-specific runners
deploy:production:
  tags:
    - production
    - kubernetes
  script:
    - kubectl apply -f deployment.yml
```

### Image Selection

```yaml
# Use specific image versions
build:
  image: node:20.10.0  # Pin exact version
  script:
    - npm ci

# Use minimal images for speed
test:
  image: node:20-alpine  # Smaller, faster to pull
  script:
    - npm test
```

## When to Use What

| Scenario | Solution |
|----------|----------|
| Standard web app | Auto DevOps |
| Custom build process | Manual `.gitlab-ci.yml` |
| Docker image builds | Docker executor + DinD |
| Integration tests | Services (postgres, redis, etc.) |
| Long-running tests | Parallel jobs |
| Multi-project coordination | Trigger pipelines |
| Production deployments | Manual gates + resource groups |
| MR-specific checks | Merge request pipelines |
| Nightly builds | Scheduled pipelines |
