## Introduction

HCL (HashiCorp Configuration Language) is the declarative language used by Terraform to describe infrastructure. Understanding HCL syntax is the foundation for writing effective Terraform configurations. HCL is designed to be both human-readable and machine-friendly, making it easy to define complex infrastructure in a clear, maintainable way.

## Key Concepts Summary

### HCL Basic Structure

Terraform configurations are built using two key constructs:

**1. Arguments** assign values to names:
```hcl
image_id = "ami-abc123"
availability_zone = "us-west-2a"
```

**2. Blocks** are containers for configuration:
```hcl
resource "aws_instance" "example" {
  ami           = "ami-abc123"
  instance_type = "t2.micro"
}
```

### Block Anatomy

```hcl
<BLOCK_TYPE> "<BLOCK_LABEL>" "<BLOCK_LABEL>" {
  # Block body
  <IDENTIFIER> = <EXPRESSION>  # Argument
}
```

Example:
```hcl
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
  
  tags = {
    Name = "main-vpc"
  }
}
```

Components:
- `resource` = Block type
- `"aws_vpc"` = First label (resource type)
- `"main"` = Second label (resource name)
- `cidr_block = "10.0.0.0/16"` = Argument
- `tags = { ... }` = Nested block/map

## Terraform Data Types

### Primitive Types

```hcl
# String
name = "web-server"
description = "Main application server"

# Number
instance_count = 3
port = 8080

# Bool
enable_monitoring = true
publicly_accessible = false
```

### Collection Types

```hcl
# List (ordered collection)
availability_zones = ["us-west-2a", "us-west-2b", "us-west-2c"]

# Set (unordered collection, no duplicates)
security_groups = toset(["sg-123", "sg-456"])

# Map (key-value pairs)
tags = {
  Environment = "production"
  Team        = "platform"
  Owner       = "devops@example.com"
}
```

### Complex Types

```hcl
# Object (specific structure)
vpc_config = {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true
}

# Tuple (fixed-length list with specific types)
network_config = ["10.0.0.0/16", 2, true]
```

### The Null Value

```hcl
# Represents absence of a value
user_data = null  # Don't set user data
```

## File Organization

### Standard File Structure

```
my-terraform-project/
├── main.tf           # Primary resources
├── variables.tf      # Input variable declarations
├── outputs.tf        # Output value declarations
├── versions.tf       # Provider version constraints
├── terraform.tfvars  # Variable values (gitignore this!)
└── README.md         # Documentation
```

### main.tf Example

```hcl
# Configure the AWS provider
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
  required_version = ">= 1.6"
}

provider "aws" {
  region = var.aws_region
}

# Create a VPC
resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  enable_dns_support   = true
  
  tags = {
    Name        = "${var.project_name}-vpc"
    Environment = var.environment
  }
}
```

### variables.tf Example

```hcl
variable "aws_region" {
  description = "AWS region for resources"
  type        = string
  default     = "us-west-2"
}

variable "vpc_cidr" {
  description = "CIDR block for VPC"
  type        = string
  default     = "10.0.0.0/16"
  
  validation {
    condition     = can(cidrhost(var.vpc_cidr, 0))
    error_message = "Must be a valid IPv4 CIDR block."
  }
}

variable "environment" {
  description = "Environment name"
  type        = string
  
  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}
```

### outputs.tf Example

```hcl
output "vpc_id" {
  description = "ID of the VPC"
  value       = aws_vpc.main.id
}

output "vpc_cidr_block" {
  description = "CIDR block of the VPC"
  value       = aws_vpc.main.cidr_block
}
```

## String Interpolation

```hcl
# Basic interpolation
name = "web-${var.environment}"

# Multiple interpolations
description = "Web server for ${var.project_name} in ${var.environment}"

# Expressions in interpolation
cidr_block = "10.${var.subnet_index}.0.0/24"

# Template strings
user_data = <<-EOF
  #!/bin/bash
  echo "Environment: ${var.environment}"
  echo "Region: ${var.aws_region}"
EOF
```

### Heredoc Strings

```hcl
# Standard heredoc (preserves indentation)
user_data = <<EOF
#!/bin/bash
apt-get update
apt-get install -y nginx
EOF

# Indented heredoc (strips leading whitespace)
user_data = <<-EOF
  #!/bin/bash
  apt-get update
  apt-get install -y nginx
EOF
```

## Expressions and Operators

### Arithmetic Operators

```hcl
count = var.instance_count + 2
size  = var.base_size * 1024
ratio = var.numerator / var.denominator
remainder = var.number % 10
```

### Comparison Operators

```hcl
# Equality
is_production = var.environment == "prod"
is_not_dev    = var.environment != "dev"

# Numeric comparison
is_large = var.size > 100
is_small = var.size <= 10
```

### Logical Operators

```hcl
# AND
enable_feature = var.is_production && var.feature_enabled

# OR
allow_access = var.is_admin || var.is_owner

# NOT
is_disabled = !var.is_enabled
```

### Conditional Expressions

```hcl
# Ternary operator
instance_type = var.environment == "prod" ? "t3.large" : "t3.micro"

# With complex expressions
monitoring_enabled = var.environment == "prod" ? true : false

# Nested conditionals
tier = var.environment == "prod" ? "premium" : (
  var.environment == "staging" ? "standard" : "basic"
)
```

## Style and Formatting Best Practices

### Indentation

```hcl
# Use 2 spaces for indentation
resource "aws_instance" "example" {
  ami           = "ami-abc123"
  instance_type = "t2.micro"
  
  tags = {
    Name = "example"
  }
}
```

### Alignment

```hcl
# Align equals signs for readability
resource "aws_instance" "example" {
  ami               = "ami-abc123"
  instance_type     = "t2.micro"
  availability_zone = "us-west-2a"
}
```

### Naming Conventions

```hcl
# Use snake_case for everything
resource "aws_security_group" "web_server_sg" {
  name        = "web-server-sg"
  description = "Security group for web servers"
}

# Use descriptive names
variable "vpc_cidr_block" {
  # Better than just "cidr"
}

# Module names should be descriptive
module "web_server_cluster" {
  # Better than just "cluster"
}
```

### Terraform Fmt Command

```bash
# Format all .tf files in current directory
terraform fmt

# Format recursively
terraform fmt -recursive

# Check if files are formatted (CI/CD)
terraform fmt -check

# Show diff of formatting changes
terraform fmt -diff
```

## References and Interpolation

### Resource References

```hcl
# Reference another resource's attribute
resource "aws_subnet" "main" {
  vpc_id     = aws_vpc.main.id  # Reference VPC ID
  cidr_block = "10.0.1.0/24"
}

# Self-reference
resource "aws_security_group" "example" {
  name = "example-sg"
  
  ingress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    self        = true  # Allow traffic from same security group
  }
}
```

### Variable References

```hcl
resource "aws_instance" "web" {
  ami           = var.ami_id
  instance_type = var.instance_type
  
  tags = {
    Environment = var.environment
  }
}
```

### Local Values

```hcl
locals {
  common_tags = {
    Environment = var.environment
    Project     = var.project_name
    ManagedBy   = "Terraform"
  }
  
  name_prefix = "${var.project_name}-${var.environment}"
}

resource "aws_vpc" "main" {
  cidr_block = var.vpc_cidr
  tags       = local.common_tags
}

resource "aws_subnet" "public" {
  vpc_id = aws_vpc.main.id
  
  tags = merge(
    local.common_tags,
    {
      Name = "${local.name_prefix}-public-subnet"
      Type = "public"
    }
  )
}
```

## Functions

Terraform includes many built-in functions:

```hcl
# String functions
upper_name    = upper("hello")          # "HELLO"
lower_name    = lower("WORLD")          # "world"
title_name    = title("hello world")    # "Hello World"
trimmed       = trim("  hello  ")       # "hello"

# Collection functions
list_length   = length(["a", "b", "c"]) # 3
list_element  = element(["a", "b", "c"], 1) # "b"
list_concat   = concat(["a"], ["b"])    # ["a", "b"]

# Numeric functions
min_value     = min(1, 2, 3)           # 1
max_value     = max(1, 2, 3)           # 3
absolute      = abs(-5)                # 5

# Type conversion
to_string     = tostring(123)          # "123"
to_number     = tonumber("456")        # 456
to_bool       = tobool("true")         # true

# Date/time functions
timestamp     = timestamp()            # "2024-01-15T10:30:00Z"

# File functions
file_content  = file("${path.module}/config.txt")
template_file = templatefile("${path.module}/template.tpl", {
  name = "example"
})

# Encoding functions
base64_encode = base64encode("hello")
json_encode   = jsonencode({key = "value"})
```

## Common Mistakes to Avoid

| Mistake | Problem | Solution |
|---------|---------|----------|
| Using wrong quotes | `name = 'value'` | Use double quotes: `name = "value"` |
| Missing equals sign | `name value` | Use: `name = value` |
| Incorrect indentation | Hard to read | Use `terraform fmt` |
| Not using terraform fmt | Inconsistent style | Run before committing |
| Mixing underscores and hyphens | Inconsistent naming | Use underscores in HCL |
| Hardcoding values | Not reusable | Use variables |
| No descriptions | Hard to understand | Add descriptions to all variables |
