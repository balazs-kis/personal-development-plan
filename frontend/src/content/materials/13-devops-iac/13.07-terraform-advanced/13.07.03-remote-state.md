# Lesson 3: Remote State Management

## Learning Objectives

By the end of this lesson, you will be able to:
- Configure remote backends for state storage
- Understand different backend options and their trade-offs
- Implement secure state storage practices
- Migrate state between backends

---

## Introduction

Terraform state files are critical for tracking your infrastructure. By default, Terraform stores state locally, which is problematic for teams. Remote state storage enables collaboration, provides backup and versioning, and enables advanced features like state locking. This lesson covers remote backend configuration, best practices, and common patterns.

## Key Concepts Summary

### Why Remote State?

**Problems with Local State:**
- ❌ Can't collaborate with teams
- ❌ No backup or versioning
- ❌ Risk of committing secrets to Git
- ❌ No locking (concurrent modification risk)

**Benefits of Remote State:**
- ✅ Team collaboration
- ✅ Automatic backup
- ✅ State locking
- ✅ Secrets stored remotely
- ✅ State versioning

## Backend Types

### S3 Backend (AWS)

**Basic Configuration:**

```hcl
# backend.tf
terraform {
  backend "s3" {
    bucket         = "my-terraform-state"
    key            = "prod/terraform.tfstate"
    region         = "us-east-1"
    encrypt        = true
    
    # State locking
    use_lockfile   = true
  }
}
```

**Complete Setup with S3 + State Locking:**

```hcl
terraform {
  backend "s3" {
    bucket         = "mycompany-terraform-state"
    key            = "app/prod/terraform.tfstate"
    region         = "us-east-1"
    encrypt        = true
    use_lockfile   = true
    
    # Optional: Custom S3 endpoint
    # endpoint = "https://s3.amazonaws.com"
    
    # Optional: KMS encryption
    # kms_key_id = "arn:aws:kms:us-east-1:123456789012:key/12345678-1234-1234-1234-123456789012"
  }
}
```

**S3 Bucket Setup Script:**

```bash
#!/bin/bash
BUCKET_NAME="mycompany-terraform-state"
REGION="us-east-1"

# Create S3 bucket
aws s3api create-bucket \
  --bucket $BUCKET_NAME \
  --region $REGION \
  --create-bucket-configuration LocationConstraint=$REGION

# Enable versioning
aws s3api put-bucket-versioning \
  --bucket $BUCKET_NAME \
  --versioning-configuration Status=Enabled

# Enable encryption
aws s3api put-bucket-encryption \
  --bucket $BUCKET_NAME \
  --server-side-encryption-configuration '{
    "Rules": [{
      "ApplyServerSideEncryptionByDefault": {
        "SSEAlgorithm": "AES256"
      },
      "BucketKeyEnabled": true
    }]
  }'

# Block public access
aws s3api put-public-access-block \
  --bucket $BUCKET_NAME \
  --public-access-block-configuration \
    "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"
```

### Azure Storage Backend

```hcl
terraform {
  backend "azurerm" {
    resource_group_name  = "terraform-state-rg"
    storage_account_name = "tfstateaccount"
    container_name       = "tfstate"

  }
}
```

### GCS Backend (Google Cloud)

```hcl
terraform {
  backend "gcs" {
    bucket = "my-terraform-state"
    prefix = "terraform/state"
  }
}
```

```hcl

  cloud {
    organization = "my-organization"
    
    workspaces {
      name = "my-app-prod"
    }
  }
}
```

## Backend Configuration Patterns

### Partial Configuration

**Don't hardcode credentials:**

```hcl
# backend.tf - Partial configuration
terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "prod/terraform.tfstate"
    region = "us-east-1"
    # No credentials here!
  }
}
```

**Supply at init time:**

```bash
# Using CLI flags
terraform init \
  -backend-config="bucket=my-terraform-state" \
  -backend-config="key=prod/terraform.tfstate" \
  -backend-config="region=us-east-1"

# Using a backend config file
terraform init -backend-config=backend-config.hcl
```

```hcl
# backend-config.hcl
bucket = "my-terraform-state"
key    = "prod/terraform.tfstate"
region = "us-east-1"
```

### Environment-Specific Backends

**Directory structure:**

```
terraform/
├── modules/
│   └── ...
├── environments/
│   ├── dev/
│   │   ├── backend.tf
│   │   ├── main.tf
│   │   └── terraform.tfvars
│   ├── staging/
│   │   ├── backend.tf
│   │   ├── main.tf
│   │   └── terraform.tfvars
│   └── prod/
│       ├── backend.tf
│       ├── main.tf
│       └── terraform.tfvars
```

**Dev backend:**

```hcl
# environments/dev/backend.tf
```

## State Migration

### Migrating from Local to Remote

**Step 1: Add backend configuration**

```hcl
terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "app/terraform.tfstate"
    region = "us-east-1"
  }
}
```

**Step 2: Reinitialize**

```bash
# Terraform will detect backend change
terraform init

# Answer 'yes' when prompted to migrate state
```

**Step 3: Verify**

```bash
# Confirm state is accessible
terraform state list

# Verify local state was migrated
ls terraform.tfstate*  # Should be backup only
```

### Migrating Between Backends

**Example: S3 to Terraform Cloud**

**Old configuration:**

```hcl
terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "app/terraform.tfstate"
    region = "us-east-1"
  }
}
```

**New configuration:**

```hcl
terraform {
  cloud {
    organization = "my-organization"
    
    workspaces {
      name = "my-app-prod"
    }
  }
}
```

**Migration process:**

```bash
# Step 1: Authenticate to Terraform Cloud
terraform login

# Step 2: Update backend configuration in your code

# Step 3: Reinitialize
terraform init -migrate-state

# Step 4: Verify
terraform state list
```

### Manual State Operations

**Pull state from remote:**

```bash
terraform state pull > terraform.tfstate.backup
```

**Push state to remote:**

```bash
terraform state push terraform.tfstate
```

**Replace provider in state (after provider migration):**

```bash
terraform state replace-provider \
  registry.terraform.io/hashicorp/aws \
  registry.terraform.io/custom/aws
```

## Backend Security Best Practices

### 1. Enable Encryption

**S3 Backend:**

```hcl
terraform {
  backend "s3" {
    bucket  = "my-terraform-state"
    key     = "prod/terraform.tfstate"
    region  = "us-east-1"
    encrypt = true
    
    # Optional: Use KMS for encryption
    kms_key_id = "arn:aws:kms:us-east-1:123456789012:key/12345678-1234-1234-1234-123456789012"
  }
}
```

### 2. Enable Versioning

```bash
# S3 versioning
aws s3api put-bucket-versioning \
  --bucket my-terraform-state \
  --versioning-configuration Status=Enabled
```

Benefits:
- Recover from accidental deletion
- Roll back to previous state
- Audit trail

### 3. Restrict Access with IAM

**Least-privilege IAM policy:**

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::my-terraform-state"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": "arn:aws:s3:::my-terraform-state/*"
    }
  ]
}
```

### 4. Separate State by Environment

```
✅ Good:
  - my-terraform-state-dev
  - my-terraform-state-staging
  - my-terraform-state-prod

Or:
  - my-terraform-state/dev/
  - my-terraform-state/staging/
  - my-terraform-state/prod/
```

### 5. Block Public Access

```bash
aws s3api put-public-access-block \
  --bucket my-terraform-state \
  --public-access-block-configuration \
    "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"
```

### 6. Enable Logging

```bash
# S3 access logging
aws s3api put-bucket-logging \
  --bucket my-terraform-state \
  --bucket-logging-status '{
    "LoggingEnabled": {
      "TargetBucket": "my-logs-bucket",
      "TargetPrefix": "terraform-state-logs/"
    }
  }'
```

## State Storage Comparison

| Backend | Locking | Encryption | Versioning | Cost | Best For |
|---------|---------|------------|------------|------|----------|
| **S3** | ✅ (built-in) | ✅ | ✅ | Low | AWS projects |
| **Azure Storage** | ✅ | ✅ | ✅ | Low | Azure projects |
| **GCS** | ✅ | ✅ | ✅ | Low | GCP projects |
| **Terraform Cloud** | ✅ | ✅ | ✅ | Free/Paid | Multi-cloud, teams |
| **Local** | ❌ | ❌ | ❌ | Free | Solo dev only |

## Common Patterns

### Multi-Region State

```hcl
# Use region-specific buckets
terraform {
  backend "s3" {
    bucket = "my-terraform-state-${var.region}"
    key    = "prod/terraform.tfstate"
    region = var.region
  }
}
```

### State Per Application/Service

```
my-terraform-state/
├── app1/
│   ├── dev/terraform.tfstate
│   ├── staging/terraform.tfstate
│   └── prod/terraform.tfstate
├── app2/
│   ├── dev/terraform.tfstate
│   └── prod/terraform.tfstate
└── shared/
    └── networking/terraform.tfstate
```
