## Introduction

State locking prevents concurrent operations that could corrupt your Terraform state. When multiple team members or CI/CD systems work with the same infrastructure, proper state locking and collaboration practices are essential. This lesson covers locking mechanisms, team workflows, and best practices for collaborative infrastructure management.

## Key Concepts Summary

### State Locking Fundamentals

**What is State Locking?**

State locking automatically prevents concurrent Terraform operations from modifying the same state file, protecting against:
- State corruption
- Lost updates
- Race conditions

**When Locking Occurs:**

Terraform automatically locks state for operations that could write to state:
- `terraform apply`
- `terraform destroy`
- `terraform import`
- `terraform state` (write operations)
- `terraform taint`

**Read-only operations don't require locks:**
- `terraform plan` (typically)
- `terraform state list`
- `terraform state show`

## Backend Locking Support

### Backends with Native Locking

| Backend | Locking Support | Configuration |
|---------|----------------|---------------|
| **S3** | ✅ Built-in | `use_lockfile = true` |
| **Azure Storage** | ✅ Native | Automatic |
| **GCS** | ✅ Native | Automatic |
| **Terraform Cloud** | ✅ Native | Automatic |
| **Consul** | ✅ Native | Automatic |
| **Local** | ❌ None | Single user only |

### S3 Backend with Locking

**Modern Configuration (Terraform 1.8+):**

```hcl
terraform {
  backend "s3" {
    bucket       = "my-terraform-state"
    key          = "prod/terraform.tfstate"
    region       = "us-east-1"
    encrypt      = true
    use_lockfile = true
  }
}
```

The state lock file is stored at: `{key}.tflock`

**Legacy Configuration (< 1.8 - deprecated):**

```hcl
terraform {
  backend "s3" {
    bucket         = "my-terraform-state"
    key            = "prod/terraform.tfstate"
    region         = "us-east-1"
    encrypt        = true
    
    # DynamoDB for locking (deprecated)
    dynamodb_table = "terraform-state-lock"
  }
}
```

### Azure Storage Backend

```hcl
terraform {
  backend "azurerm" {
    resource_group_name  = "terraform-state-rg"
    storage_account_name = "tfstateaccount"
    container_name       = "tfstate"
    key                  = "prod.terraform.tfstate"
    
    # Locking is automatic via blob leases
  }
}
```

### GCS Backend

```hcl
terraform {
  backend "gcs" {
    bucket = "my-terraform-state"
    prefix = "terraform/state"
    
    # Locking is automatic
  }
}
```

## Working with Locks

### Lock Behavior

**Automatic Locking:**

```bash
# Terraform automatically acquires lock
$ terraform apply

Acquiring state lock. This may take a few moments...

# If another operation holds the lock
Error: Error acquiring the state lock

Error message: ConditionalCheckFailedException: The conditional request failed
Lock Info:
  ID:        a1b2c3d4-5e6f-7g8h-9i0j-k1l2m3n4o5p6
  Path:      prod/terraform.tfstate
  Operation: OperationTypeApply
  Who:       john@workstation
  Version:   1.7.0
  Created:   2026-02-02 14:23:45.123456789 +0000 UTC
  Info:      
```

### Disabling Locks (Not Recommended)

```bash
# Disable locking for an operation (dangerous!)
terraform apply -lock=false

# Disable lock timeout (wait indefinitely)
terraform apply -lock-timeout=0s

# Increase lock timeout (default 0s)
terraform apply -lock-timeout=10m
```

⚠️ **Warning:** Only disable locking if you're absolutely certain no other operations are running.

### Force Unlock

**When to Force Unlock:**

- Lock was not released due to Terraform crash
- Process was killed unexpectedly
- You verified no other operations are running

**How to Force Unlock:**

```bash
# Get lock ID from error message
terraform force-unlock <LOCK_ID>

# Example
terraform force-unlock a1b2c3d4-5e6f-7g8h-9i0j-k1l2m3n4o5p6
```

⚠️ **Critical Warning:** Never force-unlock if:
- Another person/system might be running Terraform
- You're unsure if the operation is still running
- It's not your own lock

**Verifying Before Force Unlock:**

```bash
# Check if process is still running
ps aux | grep terraform

# Check CI/CD systems
# Check with team members
# Verify in Terraform Cloud UI (if applicable)
```

## Team Collaboration Patterns

### 1. Version Control Workflow

**Basic Git Workflow:**

```bash
# Feature branch workflow
git checkout -b feature/add-monitoring
# Make changes
terraform fmt
terraform validate
git add .
git commit -m "Add CloudWatch monitoring"
git push origin feature/add-monitoring
# Create PR for review
```

**Branch Protection:**

```yaml
# .github/workflows/terraform.yml
name: Terraform CI
on:
  pull_request:
    branches: [main]

jobs:
  terraform:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: hashicorp/setup-terraform@v2
      
      - name: Terraform Format
        run: terraform fmt -check
      
      - name: Terraform Init
        run: terraform init
      
      - name: Terraform Validate
        run: terraform validate
      
      - name: Terraform Plan
        run: terraform plan -out=tfplan
```

### 3. Prevent Manual Changes

**Drift Detection:**

```bash
# Regularly check for drift
terraform plan -detailed-exitcode

# Exit codes:
# 0 = No changes
# 1 = Error
# 2 = Changes detected (drift)
```

**Automated Drift Detection:**

```yaml
# .github/workflows/drift-detection.yml
name: Drift Detection
on:
  schedule:
    - cron: '0 9 * * 1-5'  # 9 AM weekdays

jobs:
  detect-drift:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: hashicorp/setup-terraform@v2
      
      - name: Terraform Init
        run: terraform init
      
      - name: Check for Drift
        run: |
          if ! terraform plan -detailed-exitcode; then
            echo "::error::Infrastructure drift detected!"
            exit 1
          fi
```

### 4. Environment Isolation

**Separate State Per Environment:**

```
terraform/
├── modules/
│   └── app/
├── environments/
│   ├── dev/
│   │   ├── backend.tf     # Separate backend
│   │   ├── main.tf
│   │   └── terraform.tfvars
│   ├── staging/
│   │   ├── backend.tf
│   │   ├── main.tf
│   │   └── terraform.tfvars
│   └── prod/
│       ├── backend.tf     # Isolated from dev/staging
│       ├── main.tf
│       └── terraform.tfvars
```

**Different IAM Roles:**

```hcl
# environments/prod/backend.tf
terraform {
  backend "s3" {
    bucket         = "company-terraform-prod"
    key            = "app/terraform.tfstate"
    region         = "us-east-1"
    role_arn       = "arn:aws:iam::123456789012:role/TerraformProdRole"
  }
}
```

## Troubleshooting Lock Issues

### Issue 1: Lock Timeout

**Problem:**
```
Error: Error acquiring the state lock
```

**Solution:**
```bash
# Increase timeout
terraform apply -lock-timeout=10m

# Or wait for current operation to complete
```

### Issue 2: Stale Lock

**Problem:**
Lock not released after process crash

**Solution:**
```bash
# 1. Verify no operations running
ps aux | grep terraform

# 2. Check with team
# 3. Force unlock with lock ID from error
terraform force-unlock <LOCK_ID>
```

### Issue 3: Permission Denied

**Problem:**
```
Error: Unable to acquire state lock
```

**Solution:**
Check IAM permissions for state file access

## Lock Monitoring

**Script to Check Lock Status:**

```bash
#!/bin/bash
# check-lock.sh

STATE_FILE="s3://my-terraform-state/prod/terraform.tfstate"
LOCK_FILE="${STATE_FILE}.tflock"

# Check if lock file exists
if aws s3 ls "$LOCK_FILE" 2>/dev/null; then
  echo "State is LOCKED"
  aws s3 cp "$LOCK_FILE" - | jq .
else
  echo "State is UNLOCKED"
fi
```
