# Lesson 5: Testing Infrastructure as Code

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand different types of infrastructure tests
- Implement static analysis and validation for IaC
- Write unit tests for infrastructure modules
- Perform integration testing with real resources
- Design end-to-end testing strategies
- Integrate IaC testing into CI/CD pipelines

---

## Introduction

Just like application code, Infrastructure as Code should be tested to ensure it works correctly, follows best practices, and doesn't introduce security vulnerabilities or break existing infrastructure. Testing IaC helps catch errors early, validates configurations across environments, and provides confidence when making infrastructure changes.

## Key Concepts Summary

### The Infrastructure Testing Pyramid

```
        ┌─────────────────┐
        │   E2E Tests     │  ← Slowest, most expensive
        │   (minutes)     │     Complete infrastructure
        ├─────────────────┤
        │ Integration     │  ← Moderate cost
        │ Tests (seconds) │     Real resources
        ├─────────────────┤
        │  Unit Tests     │  ← Fast, cheap
        │ (milliseconds)  │     Mocked dependencies
        ├─────────────────┤
        │ Static Analysis │  ← Fastest, cheapest
        │ (milliseconds)  │     No resources created
        └─────────────────┘
```

**Principle:** Use less expensive test methods first, progress to more complex/expensive tests for higher confidence.

## Testing Levels

### 1. Static Analysis (Fastest, No Cost)

**What:** Validate syntax, structure, and basic correctness without creating resources.

```bash
# Terraform validation
terraform fmt -check       # Check formatting
terraform validate         # Check syntax
terraform plan            # Check configuration validity

# Linting
tflint                    # Terraform linter
checkov -d .              # Security scanning
terrascan scan           # Policy and compliance
```

**Catches:**
- Syntax errors
- Invalid resource configurations
- Missing required arguments
- Security misconfigurations
- Style violations

**Example:**
```bash
$ terraform validate
Error: Unsupported argument

  on main.tf line 5, in resource "aws_instance" "web":
   5:   instance_tipe = "t2.micro"

An argument named "instance_tipe" is not expected here.
Did you mean "instance_type"?
```

### 2. Unit Tests (Fast, Minimal Cost)

**What:** Test individual modules in isolation with mocked or minimal dependencies.

```hcl
# tests/vpc_test.tftest.hcl
run "validate_vpc_cidr" {
  command = plan  # Don't create resources, just validate
  
  variables {
    vpc_cidr = "10.0.0.0/16"
  }
  
  assert {
    condition     = aws_vpc.main.cidr_block == "10.0.0.0/16"
    error_message = "VPC CIDR must be 10.0.0.0/16"
  }
}
```

**Terraform v1.7+ Provider Mocking:**
```hcl
# Mock AWS provider for unit testing
run "test_with_mocking" {
  command = plan
  
  override_resource {
    target = aws_instance.web
    values = {
      id  = "i-mock123"
      ami = "ami-mock123"
    }
  }
}
```

**Catches:**
- Logic errors in modules
- Invalid variable combinations
- Resource attribute validation
- Output correctness

### 3. Integration Tests (Moderate Cost)

**What:** Deploy actual infrastructure to test environment, verify it works, then destroy.

```hcl
# tests/integration_test.tftest.hcl
run "create_and_test_vpc" {
  command = apply  # Actually creates resources
  
  variables {
    vpc_cidr = "10.0.0.0/16"
    environment = "test"
  }
  
  assert {
    condition     = aws_vpc.main.state == "available"
    error_message = "VPC should be in available state"
  }
  
  assert {
    condition     = length(aws_subnet.public) == 2
    error_message = "Should create 2 public subnets"
  }
}
```

**Using Terratest (Go):**
```go
func TestVPCCreation(t *testing.T) {
    opts := &terraform.Options{
        TerraformDir: "../examples/vpc",
        Vars: map[string]interface{}{
            "vpc_cidr": "10.0.0.0/16",
        },
    }
    
    defer terraform.Destroy(t, opts)
    terraform.InitAndApply(t, opts)
    
    vpcID := terraform.Output(t, opts, "vpc_id")
    assert.NotEmpty(t, vpcID)
}
```

**Catches:**
- Resource creation failures
- Networking issues
- Permission problems
- Resource dependencies
- Cross-resource integration

### 4. End-to-End Tests (Slowest, Highest Cost)

**What:** Deploy complete infrastructure stack and test application functionality.

```bash
# Deploy entire stack
terraform apply -var-file=test.tfvars

# Test application endpoints
curl https://app.test.example.com/health
# Expected: HTTP 200

# Run application tests
pytest tests/e2e/

# Cleanup
terraform destroy -auto-approve
```

**Catches:**
- Full stack integration issues
- Application deployment problems
- Load balancer/DNS configuration
- Security group rules
- Complete user workflows

## Unit Testing with Terraform

### Native Terraform Tests (v1.6+)

```hcl
# tests/vpc.tftest.hcl

# Test 1: Validate CIDR
run "validate_vpc_cidr" {
  command = plan
  
  variables {
    vpc_cidr = "10.0.0.0/16"
  }
  
  assert {
    condition     = aws_vpc.main.cidr_block == var.vpc_cidr
    error_message = "VPC CIDR mismatch"
  }
}

# Test 2: Validate subnets
run "validate_subnets" {
  command = plan
  
  variables {
    vpc_cidr         = "10.0.0.0/16"
    availability_zones = ["us-east-1a", "us-east-1b"]
  }
  
  assert {
    condition     = length(aws_subnet.public) == 2
    error_message = "Should create 2 public subnets"
  }
  
  assert {
    condition = alltrue([
      for subnet in aws_subnet.public :
      subnet.map_public_ip_on_launch == true
    ])
    error_message = "Public subnets must auto-assign public IPs"
  }
}
```

```bash
# Run tests
terraform test

# Output:
# tests/vpc.tftest.hcl... in progress
#   run "validate_vpc_cidr"... pass
#   run "validate_subnets"... pass
# tests/vpc.tftest.hcl... tearing down
# tests/vpc.tftest.hcl... pass
```

### Testing with Provider Mocking (v1.7+)

```hcl
# tests/mock_test.tftest.hcl
mock_provider "aws" {
  mock_resource "aws_instance" {
    defaults = {
      id                = "i-mock123"
      ami               = "ami-mock123"
      instance_type     = "t2.micro"
      availability_zone = "us-east-1a"
    }
  }
}

run "test_instance_logic" {
  command = plan
  
  assert {
    condition     = aws_instance.web.instance_type == "t2.micro"
    error_message = "Instance type should be t2.micro"
  }
}
```

## Integration Testing

### Terratest (Go Framework)

```go
package test

import (
    "testing"
    "github.com/gruntwork-io/terratest/modules/terraform"
    "github.com/stretchr/testify/assert"
)

func TestWebServerModule(t *testing.T) {
    t.Parallel()
    
    // Define Terraform options
    opts := &terraform.Options{
        TerraformDir: "../modules/web-server",
        Vars: map[string]interface{}{
            "instance_type": "t2.micro",
            "environment":   "test",
        },
    }
    
    // Cleanup resources
    defer terraform.Destroy(t, opts)
    
    // Deploy infrastructure
    terraform.InitAndApply(t, opts)
    
    // Validate outputs
    publicIP := terraform.Output(t, opts, "public_ip")
    assert.NotEmpty(t, publicIP)
    
    instanceID := terraform.Output(t, opts, "instance_id")
    assert.Regexp(t, "^i-[a-z0-9]+$", instanceID)
}
```

# Run tests
go test -v -timeout 30m

## Testing Best Practices

### 1. Test Idempotency

```hcl
# Run apply twice, verify no changes on second run
run "test_idempotency" {
  command = apply
  
  variables {
    vpc_cidr = "10.0.0.0/16"
  }
}

run "test_second_apply" {
  command = apply
  
  # Should show no changes
  assert {
    condition     = terraform_plan_changes == 0
    error_message = "Second apply should not make changes"
  }
}
```

### 2. Test Across Environments

```bash
# Test dev configuration
terraform test -var-file=dev.tfvars

# Test staging configuration
terraform test -var-file=staging.tfvars

# Test prod configuration
terraform test -var-file=prod.tfvars
```

### 3. Test Failure Scenarios

```hcl
run "test_invalid_cidr" {
  command = plan
  
  variables {
    vpc_cidr = "invalid"
  }
  
  expect_failures = [
    aws_vpc.main
  ]
}
```

### 4. Test Outputs

```hcl
run "test_outputs" {
  command = apply
  
  assert {
    condition     = output.vpc_id != ""
    error_message = "VPC ID output should not be empty"
  }
  
  assert {
    condition     = can(regex("^vpc-", output.vpc_id))
    error_message = "VPC ID should start with 'vpc-'"
  }
}
```

### 5. Test Resource Tagging

```hcl
run "test_required_tags" {
  command = plan
  
  assert {
    condition = alltrue([
      for resource in [aws_vpc.main, aws_subnet.public] :
      lookup(resource.tags, "Environment", "") != "" &&
      lookup(resource.tags, "ManagedBy", "") == "Terraform"
    ])
    error_message = "All resources must have required tags"
  }
}
```

## CI/CD Integration

### GitHub Actions

```yaml
# .github/workflows/terraform-test.yml
name: Terraform Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v2
        with:
          terraform_version: 1.7.0
      
      - name: Terraform Format Check
        run: terraform fmt -check -recursive
      
      - name: Terraform Validate
        run: |
          terraform init
          terraform validate
      
      - name: Run TFLint
        uses: terraform-linters/setup-tflint@v3
      - run: tflint --init
      - run: tflint -f compact
      
      - name: Run Checkov
        uses: bridgecrewio/checkov-action@master
        with:
          directory: .
          framework: terraform
      
      - name: Terraform Tests
        run: terraform test
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
```

  default = false  # Disable expensive resources in tests
}
```

```

## Common Testing Mistakes

| Mistake | Problem | Solution |
|---------|---------|----------|
| Only testing in production | Catches errors too late | Test in dev/staging first |
| No automated testing | Manual testing inconsistent | Integrate into CI/CD |
| Testing only happy paths | Failures in production | Test failure scenarios |
| Leaving test resources running | Unnecessary costs | Always cleanup |
| Not testing idempotency | Drift and inconsistency | Run apply twice |
| Skipping security scans | Vulnerabilities deployed | Add Checkov/Terrascan |
