## Introduction

Artifacts are the packaged outputs of your build process—binaries, container images, libraries, and configuration files that you deploy across environments. Proper artifact management ensures you deploy exactly what you tested, enables rollbacks, and maintains an audit trail of what's running in production.

This lesson explores artifact creation, versioning strategies, storage solutions, and best practices that enable reliable, repeatable deployments.

## Key Concepts Summary

### What Are Artifacts?

**Definition:** Files created during the build process that are deployed to environments.

**Common artifact types:**
```
Source Code → Build Process → Artifacts
                                  ↓
                          ┌───────┴───────┐
                          │               │
                    Binaries        Container Images
                    .dll, .exe      Docker images
                    .jar, .war      
                          │               │
                    Libraries       Config Files
                    NuGet packages  appsettings.json
                    npm packages    environment configs
```

**Why artifacts matter:**

1. **Consistency:** Deploy the same artifact to all environments
2. **Traceability:** Know exactly what version is running
3. **Rollback capability:** Redeploy previous artifacts if needed
4. **Security:** Scan artifacts once, deploy everywhere
5. **Speed:** Build once, deploy many times

```csharp
// Example: Artifact creation in .NET
public class BuildArtifactCreator
{
    public async Task<Artifact> CreateAsync(string commitSha, string version)
    {
        // Build the application
        await RunCommand("dotnet", "publish -c Release -o ./publish");
        
        // Create artifact package
        var artifactPath = $"./artifacts/myapp-{version}.zip";
        await ZipDirectory("./publish", artifactPath);
        
        // Calculate checksum for integrity
        var checksum = await CalculateChecksumAsync(artifactPath);
        
        // Create artifact metadata
        var artifact = new Artifact
        {
            Name = $"myapp-{version}",
            Version = version,
            CommitSha = commitSha,
            FilePath = artifactPath,
            Checksum = checksum,
            CreatedAt = DateTime.UtcNow,
            Size = new FileInfo(artifactPath).Length
        };
        
        _logger.LogInformation(
            "Created artifact {Name} from commit {Commit}",
            artifact.Name,
            commitSha
        );
        
        return artifact;
    }
}
```

### Artifact Versioning Strategies

#### 1. Semantic Versioning (SemVer)

**Format:** `MAJOR.MINOR.PATCH` (e.g., `2.3.1`)

- **MAJOR:** Breaking changes
- **MINOR:** New features (backward compatible)
- **PATCH:** Bug fixes (backward compatible)

```csharp
// Example: Semantic versioning
public class SemanticVersionGenerator
{
    public string GenerateVersion(GitInfo gitInfo)
    {
        // Parse version from git tags
        var lastTag = gitInfo.LastTag; // e.g., "v2.3.0"
        var version = Version.Parse(lastTag.TrimStart('v'));
        
        // Increment based on commit messages
        var commits = gitInfo.CommitsSinceLastTag;
        var hasBreakingChanges = commits.Any(c => c.Message.Contains("BREAKING CHANGE"));
        var hasFeatures = commits.Any(c => c.Message.StartsWith("feat:"));
        var hasFixes = commits.Any(c => c.Message.StartsWith("fix:"));
        
        if (hasBreakingChanges)
        {
            return $"{version.Major + 1}.0.0";
        }
        else if (hasFeatures)
        {
            return $"{version.Major}.{version.Minor + 1}.0";
        }
        else if (hasFixes)
        {
            return $"{version.Major}.{version.Minor}.{version.Build + 1}";
        }
        
        return version.ToString();
    }
}
```

**When to use:** Libraries, APIs, public-facing releases

#### 2. Git SHA-Based Versioning

**Format:** `{short-sha}` or `{timestamp}-{short-sha}` (e.g., `20240202-a3f5b2c`)

```csharp
// Example: Git SHA versioning
public class GitShaVersionGenerator
{
    public string GenerateVersion(string commitSha, DateTime buildTime)
    {
        var shortSha = commitSha.Substring(0, 7);
        var timestamp = buildTime.ToString("yyyyMMdd-HHmmss");
        
        return $"{timestamp}-{shortSha}";
        // Result: 20240202-103045-a3f5b2c
    }
}
```

**When to use:** Internal deployments, microservices, continuous deployment

#### 3. Date-Based Versioning

**Format:** `YYYY.MM.DD.build` (e.g., `2024.02.02.1`)

```csharp
// Example: Date-based versioning with build number
public class DateVersionGenerator
{
    public string GenerateVersion(DateTime buildTime, int buildNumber)
    {
        return $"{buildTime:yyyy.MM.dd}.{buildNumber}";
        // Result: 2024.02.02.15
    }
}
```

**When to use:** Release trains, scheduled deployments

#### 4. Hybrid Versioning

**Format:** Combine approaches (e.g., `2.3.1+a3f5b2c`)

```yaml
# Example: Hybrid version in pipeline
version:
  script:
    - SEMVER=$(git describe --tags --abbrev=0)
    - SHA=$(git rev-parse --short HEAD)
    - BUILD_NUM=$CI_PIPELINE_IID
    - VERSION="${SEMVER}+${BUILD_NUM}.${SHA}"
    - echo "VERSION=$VERSION" >> build.env
  artifacts:
    reports:
      dotenv: build.env
```

**When to use:** Need both human-readable versions and commit traceability

### Implementing Artifact Management

#### Example 1: Creating and Publishing .NET Artifacts

```yaml
# .github/workflows/build-and-publish.yml
name: Build and Publish Artifacts

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0  # Full history for versioning
      
      - name: Generate version
        id: version
        run: |
          SHA_SHORT=$(git rev-parse --short HEAD)
          BUILD_NUM=${{ github.run_number }}
          VERSION="1.0.$BUILD_NUM+$SHA_SHORT"
          echo "version=$VERSION" >> $GITHUB_OUTPUT
      
      - name: Setup .NET
        uses: actions/setup-dotnet@v3
        with:
          dotnet-version: '8.0'
      
      - name: Build
        run: |
          dotnet build -c Release \
            /p:Version=${{ steps.version.outputs.version }}
      
      - name: Publish
        run: |
          dotnet publish -c Release \
            -o ./publish \
            /p:Version=${{ steps.version.outputs.version }}
      
      - name: Create artifact archive
        run: |
          cd publish
          tar -czf ../myapp-${{ steps.version.outputs.version }}.tar.gz .
      
      - name: Upload artifact to workflow
        uses: actions/upload-artifact@v3
        with:
          name: myapp-${{ steps.version.outputs.version }}
          path: myapp-${{ steps.version.outputs.version }}.tar.gz
          retention-days: 90
      
      - name: Publish to package registry
        run: |
          dotnet nuget push ./publish/*.nupkg \
            --source https://api.nuget.org/v3/index.json \
            --api-key ${{ secrets.NUGET_API_KEY }}
```

#### Example 2: Container Image Artifacts

```yaml
# Build and push Docker image
build-image:
  stage: build
  script:
    - VERSION=$(cat VERSION)
    - SHA_SHORT=$(git rev-parse --short HEAD)
    - IMAGE_TAG="$VERSION-$SHA_SHORT"

    - docker build -t myapp:$IMAGE_TAG .
    
    # Tag with multiple versions
    - docker tag myapp:$IMAGE_TAG myapp:$VERSION
    - docker tag myapp:$IMAGE_TAG myapp:latest
    
    # Push to registry
    - docker push myapp:$IMAGE_TAG
    - docker push myapp:$VERSION
    - docker push myapp:latest
    
    # Save metadata
    - echo "IMAGE=myapp:$IMAGE_TAG" >> build.env
  artifacts:
    reports:
      dotenv: build.env
```

#### Example 3: Artifact Promotion Pattern

```csharp
// Example: Artifact promotion service
public class ArtifactPromotionService
{
    public async Task PromoteToProductionAsync(string artifactId)
    {
        // Get artifact from staging
        var artifact = await _repository.GetArtifactAsync(artifactId);
        
        // Verify artifact passed all tests
        var testResults = await _testService.GetResultsAsync(artifact.Version);
        if (!testResults.AllPassed)
        {
            throw new InvalidOperationException(
                "Cannot promote artifact with failing tests"
            );
        }
        
        // Verify security scan passed
        var securityScan = await _securityService.GetScanAsync(artifact.Version);
        if (securityScan.HasCriticalVulnerabilities)
        {
            throw new InvalidOperationException(
                "Cannot promote artifact with critical vulnerabilities"
            );
        }
        
        // Tag artifact for production
        await _repository.TagArtifactAsync(
            artifactId,
            new[] { "production", "stable", $"release-{DateTime.UtcNow:yyyy-MM-dd}" }
        );
        
        // Update deployment manifest
        await _manifestService.UpdateAsync(
            environment: "production",
            service: artifact.ServiceName,
            version: artifact.Version
        );
        
        _logger.LogInformation(
            "Promoted artifact {Artifact} to production",
            artifact.Version
        );
    }
}
```

### Security Best Practices

#### 1. Immutable Artifacts

**Principle:** Once created, artifacts should never be modified

```csharp
// Bad: Modifying artifact after creation
await _repository.UpdateArtifactAsync(artifactId, newContent);

// Good: Create new artifact with new version
var newArtifact = await _builder.BuildAsync(newContent);
await _repository.StoreArtifactAsync(newArtifact);
```

#### 2. Access Control

```yaml
# Example: Artifact repository access control
artifact-repository:
  authentication:
    type: "token"
    required: true
  
  authorization:
    read:
      - "developers"
      - "ci-cd-agents"
    
    write:
      - "ci-cd-agents"  # Only automated builds can write
    
    delete:
      - "administrators"  # Manual cleanup only by admins
      - "automated-retention"  # Or automated retention policies
```

#### 3. Artifact Signing and Verification

```csharp
// Example: Signing artifacts
public class ArtifactSigner
{
    private readonly RSA _privateKey;
    
    public async Task<SignedArtifact> SignArtifactAsync(Artifact artifact)
    {
        // Calculate artifact hash
        var hash = await CalculateHashAsync(artifact.FilePath);
        
        // Sign hash with private key
        var signature = _privateKey.SignHash(
            hash,
            HashAlgorithmName.SHA256,
            RSASignaturePadding.Pkcs1
        );
        
        return new SignedArtifact
        {
            Artifact = artifact,
            Signature = Convert.ToBase64String(signature),
            SignedAt = DateTime.UtcNow,
            SignedBy = "CI/CD Pipeline"
        };
    }
}

// Example: Verifying artifacts before deployment
public class ArtifactVerifier
{
    private readonly RSA _publicKey;
    
    public async Task<bool> VerifyArtifactAsync(SignedArtifact signedArtifact)
    {
        // Calculate current hash
        var hash = await CalculateHashAsync(signedArtifact.Artifact.FilePath);
        
        // Verify signature
        var signature = Convert.FromBase64String(signedArtifact.Signature);
        var isValid = _publicKey.VerifyHash(
            hash,
            signature,
            HashAlgorithmName.SHA256,
            RSASignaturePadding.Pkcs1
        );
        
        if (!isValid)
        {
            _logger.LogError(
                "Artifact verification failed for {Artifact}",
                signedArtifact.Artifact.Version
            );
        }
        
        return isValid;
    }
}
```

### Artifact Lifecycle Management

#### Retention Policies

```csharp
// Example: Artifact retention policy
public class ArtifactRetentionPolicy
{
    public async Task ApplyRetentionAsync()
    {
        var policies = new[]
        {
            // Keep production artifacts forever
            new RetentionRule
            {
                Tag = "production",
                RetentionDays = null  // Never delete
            },
            
            // Keep staging artifacts for 90 days
            new RetentionRule
            {
                Tag = "staging",
                RetentionDays = 90
            },
            
            // Keep dev artifacts for 30 days
            new RetentionRule
            {
                Tag = "dev",
                RetentionDays = 30
            },
            
            // Keep all artifacts from main branch for 180 days
            new RetentionRule
            {
                Branch = "main",
                RetentionDays = 180
            },
            
            // Delete feature branch artifacts after 7 days
            new RetentionRule
            {
                Branch = "feature/*",
                RetentionDays = 7
            }
        };
        
        foreach (var policy in policies)
        {
            await ApplyPolicyAsync(policy);
        }
    }
    
    private async Task ApplyPolicyAsync(RetentionRule rule)
    {
        if (rule.RetentionDays == null) return;  // Keep forever
        
        var cutoffDate = DateTime.UtcNow.AddDays(-rule.RetentionDays.Value);
        var artifacts = await _repository.GetArtifactsAsync(
            tag: rule.Tag,
            branch: rule.Branch,
            createdBefore: cutoffDate
        );
        
        foreach (var artifact in artifacts)
        {
            _logger.LogInformation(
                "Deleting artifact {Artifact} (created {Created})",
                artifact.Version,
                artifact.CreatedAt
            );
            
            await _repository.DeleteArtifactAsync(artifact.Id);
        }
    }
}
```

## Key Takeaways

1. **Artifacts enable consistent deployments**—build once, deploy the same artifact everywhere to ensure what you test is what you run.

2. **Version artifacts clearly and consistently**—use semantic versioning for releases, git SHAs for traceability, or hybrid approaches.

3. **Store artifacts securely with access control**—use artifact repositories with authentication, enforce immutability, and scan for vulnerabilities.

4. **Sign and verify artifacts**—ensure integrity by signing artifacts during build and verifying signatures before deployment.

5. **Implement retention policies**—automatically clean up old artifacts while preserving production releases and important builds.
