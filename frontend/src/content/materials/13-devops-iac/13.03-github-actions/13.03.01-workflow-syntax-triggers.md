---

## Introduction

GitHub Actions workflows are defined using YAML files stored in the `.github/workflows` directory of your repository. Understanding workflow syntax and triggers is fundamental to automating your CI/CD processes. Workflows can be triggered by GitHub events, schedules, or external webhooks.

## Key Concepts Summary

### Basic Workflow Structure

```yaml
# .github/workflows/ci.yml
name: CI Pipeline                    # Workflow name (displayed in Actions tab)
run-name: Build ${{ github.ref }}    # Custom run name (supports expressions)

on: [push, pull_request]            # Trigger events

jobs:
  build:
    runs-on: ubuntu-latest          # Runner environment
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
      
      - name: Run build
        run: |
          echo "Building..."
          # Your build commands
```

### Common Trigger Events

```yaml
# Single event
on: push

# Multiple events
on: [push, pull_request, workflow_dispatch]

# Event with configuration
on:
  push:
    branches:
      - main
      - 'releases/**'           # Wildcard patterns
    paths:
      - 'src/**'                # Only trigger on specific paths
      - '!docs/**'              # Exclude paths
    tags:
      - 'v*'                    # Tag patterns

  pull_request:
    types: [opened, synchronize, reopened]
    branches:
      - main

  # Manual trigger with inputs
  workflow_dispatch:
    inputs:
      environment:
        description: 'Environment to deploy'
        required: true
        default: 'staging'
        type: choice
        options:
          - staging
          - production

  # Schedule (cron syntax)
  schedule:
    - cron: '0 2 * * *'         # Daily at 2 AM UTC
```

### Activity Types

```yaml
# Different activity types for different events
on:
  issues:
    types: [opened, edited, closed]
  
  pull_request:
    types: [opened, synchronize, reopened, closed]
  
  label:
    types: [created, edited, deleted]
  
  release:
    types: [published, created, edited]
```

### Workflow Naming and Metadata

```yaml
name: Production Deployment

# Dynamic run name with expressions
run-name: Deploy ${{ github.ref_name }} by @${{ github.actor }}

# Permissions (restrict GITHUB_TOKEN)
permissions:
  contents: read
  pull-requests: write

# Defaults for all run steps
defaults:
  run:
    shell: bash
    working-directory: ./src

# Environment variables for all jobs
env:
  NODE_VERSION: '18'
  BUILD_TYPE: 'Release'
```

### Context and Expressions

```yaml
# Access GitHub context information
on: push

jobs:
  debug:
    runs-on: ubuntu-latest
    steps:
      - name: Print context info
        run: |
          echo "Repository: ${{ github.repository }}"
          echo "Ref: ${{ github.ref }}"
          echo "SHA: ${{ github.sha }}"
          echo "Actor: ${{ github.actor }}"
          echo "Event: ${{ github.event_name }}"
      
      # Conditional step
      - name: Only on main branch
        if: github.ref == 'refs/heads/main'
        run: echo "This is the main branch"
      
      # Complex condition
      - name: Only for PRs to main
        if: |
          github.event_name == 'pull_request' &&
          github.base_ref == 'main'
        run: echo "PR targeting main"
```

### Path and Branch Filters

```yaml
on:
  push:
    # Run only when specific files change
    paths:
      - 'src/**/*.cs'           # C# source files
      - 'tests/**'              # Test files
      - 'Directory.Build.props' # Build configuration
      - '!**/*.md'              # Exclude markdown files

    # Run only on specific branches
    branches:
      - main
      - develop
      - 'feature/**'            # All feature branches
      - 'hotfix/*'              # All hotfix branches
    
    # Exclude branches
    branches-ignore:
      - 'experimental/**'

  pull_request:
    branches:
      - main                    # Only PRs targeting main
```

### Workflow Dispatch with Inputs

```yaml
on:
  workflow_dispatch:
    inputs:
      environment:
        description: 'Deployment environment'
        required: true
        type: choice
        options:
          - development
          - staging
          - production
      
      version:
        description: 'Version to deploy'
        required: false
        type: string
        default: 'latest'
      
      dry-run:
        description: 'Run in dry-run mode'
        required: false
        type: boolean
        default: false

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy
        run: |
          echo "Environment: ${{ inputs.environment }}"
          echo "Version: ${{ inputs.version }}"
          echo "Dry run: ${{ inputs.dry-run }}"
```

### Scheduled Workflows

```yaml
on:
  schedule:
    # Run at 00:00 UTC every day
    - cron: '0 0 * * *'
    
    # Run every Monday at 9:00 AM UTC
    - cron: '0 9 * * 1'
    
    # Run every 6 hours
    - cron: '0 */6 * * *'

# Note: Scheduled workflows run on the default branch only
```

### Repository Dispatch (External Triggers)

```yaml
on:
  repository_dispatch:
    types: [deploy, rebuild-cache]

jobs:
  handle-dispatch:
    runs-on: ubuntu-latest
    steps:
      - name: Handle custom event
        run: |
          echo "Event type: ${{ github.event.action }}"
          echo "Payload: ${{ toJSON(github.event.client_payload) }}"

# Trigger this workflow via API:
# curl -X POST \
#   -H "Accept: application/vnd.github.v3+json" \
#   -H "Authorization: token YOUR_TOKEN" \
#   https://api.github.com/repos/OWNER/REPO/dispatches \
#   -d '{"event_type":"deploy","client_payload":{"version":"1.2.3"}}'
```

## Common Patterns

### Multi-Event Workflow

```yaml
name: CI/CD Pipeline

on:
  # Run on all pushes
  push:
  
  # Run on PRs to main
  pull_request:
    branches: [main]
  
  # Allow manual trigger
  workflow_dispatch:

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build and test
        run: echo "Building..."
```

### Conditional Workflow

```yaml
name: Deploy to Production

on:
  push:
    branches: [main]
    tags:
      - 'v*.*.*'

jobs:
  deploy:
    # Only deploy if push is to main OR it's a version tag
    if: github.ref == 'refs/heads/main' || startsWith(github.ref, 'refs/tags/v')
    runs-on: ubuntu-latest
    steps:
      - name: Deploy
        run: echo "Deploying..."
```

## When to Use What Trigger

| Use Case | Trigger | Configuration |
|----------|---------|---------------|
| CI on every commit | `push` | All branches or specific branches |
| PR validation | `pull_request` | Types: `[opened, synchronize]` |
| Deploy on release | `push` or `release` | Tags or release types |
| Manual deployment | `workflow_dispatch` | With inputs for parameters |
| Nightly builds | `schedule` | Cron expression |
| External integration | `repository_dispatch` | Custom event types |
| Run after another workflow | `workflow_run` | Specify workflow to wait for |
