# Lesson 4: Matrix Builds and Advanced Workflows

## Learning Objectives

By the end of this lesson, you will be able to:
- Use matrix strategy to test across multiple configurations
- Implement parallel job execution with matrices
- Configure dynamic matrices based on workflow context
- Use include/exclude to customize matrix combinations
- Apply caching strategies to speed up workflows
- Optimize workflow performance with advanced techniques

---

## Introduction

Matrix builds allow you to test your code across multiple versions, operating systems, or configurations by automatically creating parallel jobs from a set of variables. This is essential for ensuring compatibility across different environments without manually duplicating job definitions.

## Key Concepts Summary

### Basic Matrix Strategy

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        # Test across multiple Node.js versions
        node-version: [16, 18, 20]
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup Node.js ${{ matrix.node-version }}
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      
      - run: npm ci
      - run: npm test

# This creates 3 parallel jobs:
# - test (node-version: 16)
# - test (node-version: 18)
# - test (node-version: 20)
```

### Multi-Dimensional Matrix

```yaml
jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        node-version: [18, 20]
        # Creates 6 jobs: 3 OS × 2 Node versions

    steps:
      - uses: actions/checkout@v4
      
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      
      - name: Display matrix info
        run: |
          echo "OS: ${{ matrix.os }}"
          echo "Node: ${{ matrix.node-version }}"
      
      - run: npm ci
      - run: npm test
```

### Matrix with Include

```yaml
jobs:
  build:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
        node-version: [18, 20]
        # Base combinations: ubuntu-18, ubuntu-20, windows-18, windows-20
        
        include:
          # Add specific combination with extra properties
          - os: macos-latest
            node-version: 20
            experimental: true
          
          # Add properties to existing combination
          - os: ubuntu-latest
            node-version: 20
            coverage: true
    
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      
      - run: npm ci
      - run: npm test
      
      # Conditional step based on matrix property
      - name: Upload coverage
        if: matrix.coverage
        uses: codecov/codecov-action@v3
```

### Matrix with Exclude

```yaml
jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        python-version: ['3.9', '3.10', '3.11', '3.12']
        # Base: 12 combinations (4 versions × 3 OS)
        
        exclude:
          # Don't test Python 3.9 on Windows
          - os: windows-latest
            python-version: '3.9'
          
          # Don't test Python 3.12 on macOS
          - os: macos-latest
            python-version: '3.12'
        
        # Final: 10 combinations (12 - 2 excluded)
    
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
      - run: pip install -r requirements.txt
      - run: pytest
```

### Matrix Failure Handling

```yaml
jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      # Don't cancel other jobs if one fails (default: true)
      fail-fast: false
      
      # Maximum number of concurrent jobs (default: max possible)
      max-parallel: 2
      
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        node-version: [18, 20]
        
        include:
          # Mark specific combinations as experimental
          - os: ubuntu-latest
            node-version: 21
            experimental: true
    
    # Allow experimental combinations to fail without failing workflow
    continue-on-error: ${{ matrix.experimental == true }}
    
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      - run: npm test
```

### Dynamic Matrix from JSON

```yaml
jobs:
  # Generate matrix dynamically
  generate-matrix:
    runs-on: ubuntu-latest
    outputs:
      matrix: ${{ steps.set-matrix.outputs.matrix }}
    steps:
      - uses: actions/checkout@v4
      
      - name: Generate matrix
        id: set-matrix
        run: |
          # Read from file or generate dynamically
          MATRIX=$(cat .github/test-matrix.json)
          echo "matrix=$MATRIX" >> $GITHUB_OUTPUT
  
  test:
    needs: generate-matrix
    runs-on: ${{ matrix.os }}
    strategy:
      matrix: ${{ fromJSON(needs.generate-matrix.outputs.matrix) }}
    
    steps:
      - name: Test
        run: echo "Testing on ${{ matrix.os }} with ${{ matrix.version }}"
```

### Dependency Caching

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [18, 20]
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          # Built-in caching
          cache: 'npm'
      
      # Or use cache action explicitly
      - name: Cache dependencies
        uses: actions/cache@v4
        with:
          path: ~/.npm
          key: ${{ runner.os }}-node-${{ matrix.node-version }}-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-${{ matrix.node-version }}-
            ${{ runner.os }}-node-
      
      - run: npm ci
      - run: npm test
```

### Advanced Caching Patterns

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      # Cache multiple paths
      - name: Cache build outputs
        uses: actions/cache@v4
        with:
          path: |
            ~/.nuget/packages
            **/obj
            **/bin
          key: ${{ runner.os }}-dotnet-${{ hashFiles('**/*.csproj') }}
          restore-keys: |
            ${{ runner.os }}-dotnet-
      
      # Separate cache for different purposes
      - name: Cache test data
        uses: actions/cache@v4
        with:
          path: ./test-data
          key: test-data-${{ hashFiles('test-data/**') }}
      
      - name: Build
        run: dotnet build
      
      - name: Test
        run: dotnet test
```

## Real-World Examples

### .NET Multi-Target Testing

```yaml
name: .NET CI

on: [push, pull_request]

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        dotnet-version: ['6.0', '7.0', '8.0']
        exclude:
          # Skip .NET 6.0 on macOS (example)
          - os: macos-latest
            dotnet-version: '6.0'
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup .NET ${{ matrix.dotnet-version }}
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: ${{ matrix.dotnet-version }}
      
      - name: Restore dependencies
        run: dotnet restore
      
      - name: Build
        run: dotnet build --no-restore -c Release
      
      - name: Test
        run: dotnet test --no-build -c Release --logger "trx;LogFileName=test-results.trx"
      
      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results-${{ matrix.os }}-${{ matrix.dotnet-version }}
          path: '**/test-results.trx'
```

### Docker Multi-Platform Builds

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        platform:
          - linux/amd64
          - linux/arm64
          - linux/arm/v7
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Set up QEMU
        uses: docker/setup-qemu-action@v3
      
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3
      
      - name: Login to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
      
      - name: Build and push
        uses: docker/build-push-action@v5
        with:
          context: .
          platforms: ${{ matrix.platform }}
          push: true
          tags: myapp:latest-${{ matrix.platform }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

### Database Integration Testing

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        database:
          - postgres:14
          - postgres:15
          - postgres:16
        include:
          - database: postgres:14
            port: 5432
          - database: postgres:15
            port: 5433
          - database: postgres:16
            port: 5434
    
    services:
      postgres:
        image: ${{ matrix.database }}
        env:
          POSTGRES_PASSWORD: postgres
        ports:
          - ${{ matrix.port }}:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Run integration tests
        env:
          DATABASE_URL: postgresql://postgres:postgres@localhost:${{ matrix.port }}/testdb
        run: npm run test:integration
```

## Performance Optimization

### Conditional Matrix Expansion

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        # Only test on all Node versions for main branch
        node-version: ${{ github.ref == 'refs/heads/main' && fromJSON('["16", "18", "20"]') || fromJSON('["20"]') }}
    
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      - run: npm test
```

### Parallel Job Limits

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      # Limit concurrent jobs to avoid rate limits or resource constraints
      max-parallel: 3
      matrix:
        node-version: [16, 18, 20, 21]
    
    steps:
      - run: npm test
```

### Smart Caching by Matrix

```yaml
jobs:
  build:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
        node-version: [18, 20]
    
    steps:
      - uses: actions/checkout@v4
      
      # Cache key includes OS and Node version
      - name: Cache dependencies
        uses: actions/cache@v4
        with:
          path: node_modules
          key: ${{ runner.os }}-node-${{ matrix.node-version }}-${{ hashFiles('package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-${{ matrix.node-version }}-
            ${{ runner.os }}-node-
      
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      
      - run: npm ci
      - run: npm test
```

## Best Practices

### Matrix Naming

```yaml
jobs:
  test:
    name: Test (OS:${{ matrix.os }}, Node:${{ matrix.node-version }})
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
        node-version: [18, 20]
    
    steps:
      - run: npm test
```

### Collecting Results from Matrix

```yaml
jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
    
    steps:
      - uses: actions/checkout@v4
      - run: npm test
      
      - name: Upload results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results-${{ matrix.os }}
          path: test-results/
  
  # Job that runs after all matrix jobs complete
  report:
    needs: test
    if: always()
    runs-on: ubuntu-latest
    steps:
      - name: Download all results
        uses: actions/download-artifact@v4
        with:
          pattern: test-results-*
          merge-multiple: true
      
      - name: Generate report
        run: node generate-report.js
```

## When to Use Matrix Builds

| Use Case | Matrix Configuration |
|----------|---------------------|
| Multi-version testing | `node-version: [16, 18, 20]` |
| Cross-platform builds | `os: [ubuntu, windows, macos]` |
| Database compatibility | `database: [postgres:14, postgres:15]` |
| Browser testing | `browser: [chrome, firefox, safari]` |
| Language versions | `python-version: ['3.9', '3.10', '3.11']` |
| Feature flag testing | `feature: [enabled, disabled]` |
