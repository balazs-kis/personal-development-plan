- Recognize when to use specialized index types

---

## Introduction

While single-field and compound indexes handle most scenarios, MongoDB provides specialized index types for specific use cases. Multikey indexes automatically handle array fields, enabling efficient queries on tags, categories, or any array data. Text indexes support full-text search with stemming and language support. Geospatial indexes power location-based queries. Understanding these specialized indexes expands your ability to optimize diverse query patterns and build feature-rich applications.

## Key Concepts Summary

### Multikey Indexes

Multikey indexes index array fields, creating an entry for each array element.

**Automatic Creation:**
```javascript
// Document with array
{
  _id: 1,
  title: "MongoDB Basics",
  tags: ["database", "nosql", "tutorial"]
}

// Create index (automatically becomes multikey)
db.articles.createIndex({ tags: 1 })

// Index entries created:
"database" → doc1
"nosql" → doc1
"tutorial" → doc1
```

**Querying:**
```javascript
// Find articles with "nosql" tag
db.articles.find({ tags: "nosql" })
// Uses multikey index efficiently

// Find articles with multiple tags
db.articles.find({ tags: { $all: ["nosql", "tutorial"] } })
// Uses multikey index

// Find articles with any of these tags
db.articles.find({ tags: { $in: ["nosql", "mongodb"] } })
// Uses multikey index
```

**Compound Multikey Indexes:**

Only **one** indexed field can be an array:

```javascript
// Document
{
  _id: 1,
  author: "John",
  tags: ["mongodb", "database"],      // Array
  categories: ["tech", "tutorial"]    // Array
}

// Valid: One array field
db.posts.createIndex({ tags: 1, author: 1 })  // ✅

// Invalid: Two array fields
db.posts.createIndex({ tags: 1, categories: 1 })  // ❌ Error
```

**Nested Arrays:**
```javascript
// Document with nested array
{
  _id: 1,
  items: [
    { name: "Laptop", price: 1000 },
    { name: "Mouse", price: 25 }
  ]
}

// Index on nested field
db.orders.createIndex({ "items.name": 1 })

// Query
db.orders.find({ "items.name": "Laptop" })
```

**Performance Considerations:**
- Each array element creates an index entry
- Large arrays create many index entries per document
- Increases index size and write overhead
- Limit array sizes when possible

### Text Indexes

Text indexes support full-text search with language-aware stemming and stop words.

**Creating Text Indexes:**

**Single field:**
```javascript
db.articles.createIndex({ content: "text" })
```

**Multiple fields:**
```javascript
db.articles.createIndex({
  title: "text",
  content: "text",
  tags: "text"
})
```

**With weights (prioritize fields):**
```javascript
db.articles.createIndex(
  {
    title: "text",
    content: "text"
  },
  {
    weights: {
      title: 10,    // Title matches score 10x higher
      content: 1
    }
  }
)
```

**Text Queries:**

**Basic search:**
```javascript
db.articles.find({ $text: { $search: "mongodb indexing" } })
// Finds documents containing "mongodb" OR "indexing"
```

**Phrase search:**
```javascript
db.articles.find({ $text: { $search: "\"exact phrase\"" } })
// Finds documents with exact phrase
```

**Exclude words:**
```javascript
db.articles.find({ $text: { $search: "mongodb -sql" } })
// Finds "mongodb" but NOT "sql"
```

**With score (relevance):**
```javascript
db.articles.find(
  { $text: { $search: "mongodb indexing" } },
  { score: { $meta: "textScore" } }
).sort({ score: { $meta: "textScore" } })
// Sorts by relevance score
```

**Language Support:**
```javascript
// Create index with language
db.articles.createIndex(
  { content: "text" },
  { default_language: "spanish" }
)

// Per-document language
{
  _id: 1,
  content: "Base de datos",
  language: "spanish"
}

db.articles.createIndex(
  { content: "text" },
  { language_override: "language" }
)
```

**Text Index Limitations:**
- Only one text index per collection
- Cannot use text index for sorting (use score instead)
- Case-insensitive by default
- Stemming depends on language

### Geospatial Indexes

Geospatial indexes support location-based queries.

**2dsphere Index (GeoJSON):**

```javascript
// Document with GeoJSON point
{
  _id: 1,
  name: "Starbucks",
  location: {
    type: "Point",
    coordinates: [-73.97, 40.77]  // [longitude, latitude]
  }
}

// Create 2dsphere index
db.places.createIndex({ location: "2dsphere" })
```

**Queries:**

**1. Find nearby places:**
```javascript
db.places.find({
  location: {
    $near: {
      $geometry: {
        type: "Point",
        coordinates: [-73.98, 40.76]
      },
      $maxDistance: 500  // meters
    }
  }
})
```

**2. Find within area:**
```javascript
db.places.find({
  location: {
    $geoWithin: {
      $geometry: {
        type: "Polygon",
        coordinates: [[
          [-73.99, 40.75],
          [-73.96, 40.75],
          [-73.96, 40.78],
          [-73.99, 40.78],
          [-73.99, 40.75]
        ]]
      }
    }
  }
})
```

**GeoJSON Types:**
- Point - Single location
- LineString - Path
- Polygon - Area
- MultiPoint, MultiLineString, MultiPolygon

### Unique Indexes

Unique indexes enforce uniqueness across field values.

**Creating Unique Indexes:**
```javascript
// Single field
db.users.createIndex({ email: 1 }, { unique: true })

// Compound unique
db.users.createIndex(
  { firstName: 1, lastName: 1 },
  { unique: true }
)
// Combination must be unique
```

**Null Handling:**
```javascript
// Problem: Only one document can have null
db.users.insertOne({ name: "Alice" })  // email is null
db.users.insertOne({ name: "Bob" })    // ❌ Duplicate null

// Solution: Sparse index
db.users.createIndex(
  { email: 1 },
  { unique: true, sparse: true }
)
// Only indexes documents with email field
```

### Sparse Indexes

Sparse indexes only index documents with the indexed field.

**Use Case: Optional Fields**
```javascript
// Not all users have phone numbers
db.users.createIndex({ phone: 1 }, { sparse: true })

// Only indexes documents where phone exists
// Saves space for documents without phone
```

**Important:** Sparse indexes may skip documents in queries:
```javascript
db.users.find().sort({ phone: 1 })
// May not include documents without phone field
```

### Partial Indexes

Partial indexes index only documents matching a filter expression.

**Creating Partial Indexes:**
```javascript
// Only index active users
db.users.createIndex(
  { email: 1 },
  {
    partialFilterExpression: {
      status: "active"
    }
  }
)

// Only indexes users where status = "active"
// Reduces index size
```

**Use Cases:**
- Index only recent documents
- Index only documents above threshold
- Index specific status or type

**Example: Recent orders only:**
```javascript
db.orders.createIndex(
  { customerId: 1, orderDate: -1 },
  {
    partialFilterExpression: {
      orderDate: { $gte: ISODate("2025-01-01") }
    }
  }
)
// Only indexes orders from 2025 onward
// Smaller index, faster writes
```

### Hashed Indexes

Hashed indexes support hash-based sharding and equality queries.

**Creating Hashed Indexes:**
```javascript
db.users.createIndex({ _id: "hashed" })
```

**Use Cases:**
- Sharding key distribution
- Equality queries on high-cardinality fields

**Limitations:**
- Only supports equality queries (not range)
- Cannot be unique
- Slower than regular indexes for most queries

### TTL Indexes

TTL (Time-To-Live) indexes automatically delete documents after a time period.

**Creating TTL Indexes:**
```javascript
// Delete sessions after 30 minutes
db.sessions.createIndex(
  { createdAt: 1 },
  { expireAfterSeconds: 1800 }
)

// MongoDB automatically deletes documents where:
// createdAt + 1800 seconds < now
```

**Use Cases:**
- Session management
- Log cleanup
- Temporary data expiration

**Important:**
- Field must be Date or array of Dates
- Background process runs every 60 seconds
- Deletion may lag by up to 60 seconds

## Practice Exercise

After completing the materials, try this exercise (do not spend more than 20 minutes):

Given a `movies` collection:
```javascript
{
  _id: 1,
  title: "The Matrix",
  genres: ["Action", "Sci-Fi"],
  description: "A computer hacker learns about the true nature of reality",
  releaseDate: ISODate("1999-03-31"),
  rating: 8.7,
  status: "released",
  location: {
    type: "Point",
    coordinates: [-118.24, 34.05]  // Filming location
  }
}
```

**Query patterns:**

1. **Find movies by genre:**
   ```javascript
   db.movies.find({ genres: "Sci-Fi" })
   ```

2. **Search movie descriptions:**
   ```javascript
   db.movies.find({ $text: { $search: "computer reality" } })
   ```

3. **Find movies filmed nearby:**
   ```javascript
   db.movies.find({
     location: {
       $near: {
         $geometry: { type: "Point", coordinates: [-118.25, 34.06] },
         $maxDistance: 10000
       }
     }
   })
   ```

4. **Ensure unique titles:**
   - No duplicate movie titles allowed

**Tasks:**
1. Create appropriate indexes for each query pattern
2. Identify which index type to use (multikey, text, geospatial, unique)
3. Can you combine any of these into compound indexes?
4. What are the limitations of each index type?
