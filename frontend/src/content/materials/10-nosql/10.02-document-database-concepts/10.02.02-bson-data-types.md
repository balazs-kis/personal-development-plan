## Introduction

While document databases present data in a JSON-like format, MongoDB and many other document databases internally use BSON (Binary JSON) for storage and transmission. BSON extends JSON with additional data types and provides binary encoding for efficiency. Understanding BSON is crucial for effective document database usage, especially when dealing with dates, binary data, and numeric precision.

## Key Concepts Summary

### What is BSON?

**BSON** (Binary JSON) is a binary-encoded serialization of JSON-like documents. It was designed to be:
- **Lightweight:** Minimizes space usage
- **Traversable:** Easy to navigate and parse
- **Efficient:** Fast encoding and decoding

```
JSON (Text)                    BSON (Binary)
{"name": "Alice", "age": 30} → [binary data: 27 bytes]
```

### JSON vs. BSON

| Aspect | JSON | BSON |
|--------|------|------|
| **Format** | Text-based | Binary |
| **Parsing speed** | Slower | Faster |
| **Size** | Variable | Slightly larger (includes metadata) |
| **Data types** | Limited (6 types) | Extensive (30+ types) |
| **Readability** | Human-readable | Machine-optimized |
| **Type information** | No | Yes (embedded) |
| **Date support** | No native type | Native Date type |
| **Binary data** | Must encode as string | Native binary type |

### Core BSON Data Types

**String (type 2):**
```javascript
{ "name": "Alice Johnson" }
// UTF-8 encoded strings
```

**Number Types:**
```javascript
{ 
  "score": 95.5,           // Double (type 1) - 64-bit floating point
  "count": 42,             // 32-bit integer (type 16)
  "bigCount": NumberLong("9223372036854775807"), // 64-bit integer (type 18)
  "price": NumberDecimal("19.99") // Decimal128 (type 19) - for precise decimals
}
```

**Boolean (type 8):**
```javascript
{ "active": true, "verified": false }
```

**Null (type 10):**
```javascript
{ "middleName": null }
```

**Object (type 3) and Array (type 4):**
```javascript
{
  "address": {              // Embedded object
    "city": "Springfield",
    "state": "IL"
  },
  "tags": ["mongodb", "database", "nosql"]  // Array
}
```

### Extended BSON Types (Not in JSON)

**ObjectId (type 7):**
```javascript
{
  "_id": ObjectId("507f1f77bcf86cd799439011")
}
// 12-byte identifier: timestamp + machine id + process id + counter
// Provides uniqueness without coordination
```

**Date (type 9):**
```javascript
{
  "createdAt": ISODate("2026-01-27T10:30:00Z"),
  "updatedAt": new Date("2026-01-27")
}
// Stored as 64-bit integer (milliseconds since Unix epoch)
// Not the same as JavaScript Date string
```

**Binary Data (type 5):**
```javascript
{
  "profilePicture": BinData(0, "base64encodeddata=="),
  "fileContent": BinData(0, "...")
}
// Subtypes: generic, function, UUID, MD5, encrypted, vector
```

**Regular Expression (type 11):**
```javascript
{
  "pattern": /^[a-z0-9]+$/i
}
// Store regex patterns for validation or searching
```

**Timestamp (type 17):**
```javascript
{
  "oplogTimestamp": Timestamp(1706371200, 1)
}
// Internal MongoDB type for replication
// Different from Date type
```

**Decimal128 (type 19):**
```javascript
{
  "price": NumberDecimal("99.99"),
  "taxRate": NumberDecimal("0.085")
}
// 128-bit decimal for financial calculations
// Avoids floating-point precision issues
// Essential for money calculations
```

**MinKey and MaxKey (types -1 and 127):**
```javascript
{
  "minValue": MinKey(),
  "maxValue": MaxKey()
}
// Special types for comparisons
// Always compare as lowest/highest values
```

### Why BSON Matters

**1. Type Safety:**
```javascript
// JSON: Everything is a string or number
{ "date": "2026-01-27" }  // String, not a date

// BSON: Proper types
{ "date": ISODate("2026-01-27T00:00:00Z") }  // Actual date object
```

**2. Efficient Storage:**
```javascript
// BSON includes length information for traversing
// Can skip fields without parsing them
// Better for large documents
```

**3. Financial Precision:**
```javascript
// JSON/JavaScript
0.1 + 0.2 === 0.3  // false! (floating point error)

// BSON Decimal128
NumberDecimal("0.1") + NumberDecimal("0.2") === NumberDecimal("0.3")  // true!
```

**4. Rich Data Types:**
```javascript
{
  "_id": ObjectId("..."),                    // Unique identifier
  "createdAt": ISODate("2026-01-27"),       // Real date
  "avatar": BinData(0, "..."),              // Binary image
  "price": NumberDecimal("19.99"),          // Exact decimal
  "pattern": /^[A-Z]/,                      // Regex
  "coordinates": [40.7128, -74.0060]        // Geospatial data
}
```

### Working with BSON Types

**In MongoDB Shell (mongosh):**
```javascript
// Create document with BSON types
db.products.insertOne({
  name: "Premium Widget",
  price: NumberDecimal("99.99"),
  releaseDate: new Date("2026-01-15"),
  tags: ["premium", "featured"],
  stock: NumberInt(100)
})

// Query by type
db.products.find({ price: { $type: "decimal" } })
db.products.find({ releaseDate: { $type: "date" } })
```

**Type Checking:**
```javascript
// Check field type
db.collection.find({ fieldName: { $type: "string" } })
db.collection.find({ fieldName: { $type: 2 } })  // Type by number

// Multiple types
db.collection.find({ fieldName: { $type: ["string", "null"] } })
```

### Extended JSON Representation

When exporting or transmitting BSON data as JSON, use Extended JSON:

```json
{
  "_id": { "$oid": "507f1f77bcf86cd799439011" },
  "createdAt": { "$date": "2026-01-27T10:30:00.000Z" },
  "price": { "$numberDecimal": "99.99" },
  "count": { "$numberLong": "1234567890" }
}
```

This preserves type information when BSON is converted to JSON.

### Best Practices

**1. Use appropriate numeric types:**
```javascript
// DON'T: Use doubles for money
{ "price": 19.99 }  // Floating point errors

// DO: Use Decimal128 for money
{ "price": NumberDecimal("19.99") }
```

**2. Use Date type for dates:**
```javascript
// DON'T: Store dates as strings
{ "createdAt": "2026-01-27" }  // Can't do date math

// DO: Use ISODate
{ "createdAt": ISODate("2026-01-27T10:30:00Z") }
```

**3. Let MongoDB generate ObjectIds:**
```javascript
// Usually let MongoDB handle _id
// Only use custom _id if you have a natural unique key
```

**4. Use Binary for large data:**
```javascript
// For files, images, use Binary type
// Not for large documents (>16MB) - use GridFS instead
```
