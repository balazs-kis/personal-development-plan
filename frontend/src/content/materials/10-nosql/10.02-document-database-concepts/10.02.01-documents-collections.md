## Introduction

Document databases organize data differently from relational databases. Instead of rows in tables, data is stored as documents grouped into collections. Each document is a self-contained unit of data, typically in JSON-like format, that can contain nested structures, arrays, and various data types. This lesson explores the foundational concepts of documents and collections.

## Key Concepts Summary

### What is a Document?

A **document** is a single record in a document database, analogous to a row in a relational database. However, documents are far more flexible and expressive:

```json
{
  "_id": ObjectId("507f1f77bcf86cd799439011"),
  "name": "Alice Johnson",
  "email": "alice@example.com",
  "age": 30,
  "address": {
    "street": "123 Main St",
    "city": "Springfield",
    "state": "IL",
    "zipCode": "62701"
  },
  "interests": ["hiking", "photography", "coding"],
  "joinedDate": ISODate("2024-01-15T10:30:00Z"),
  "active": true
}
```

**Key characteristics of documents:**
- Self-contained units with all related data in one place
- JSON-like format (stored as BSON in MongoDB)
- Can contain nested objects and arrays
- No predefined schema required (though optional validation is available)
- Each document has a unique identifier (`_id`)

### What is a Collection?

A **collection** is a grouping of documents, analogous to a table in a relational database. Collections:

```javascript
// Users collection might contain:
users: [
  { _id: 1, name: "Alice", role: "admin", email: "alice@example.com" },
  { _id: 2, name: "Bob", role: "user" }, // Note: no email field
  { _id: 3, name: "Charlie", role: "user", email: "charlie@example.com", phone: "555-0123" }
]
```

**Key characteristics of collections:**
- Group related documents together
- Do not enforce a schema (documents can have different fields)
- Can have indexes for improved query performance
- Can have validation rules (optional)
- Exist within a database

### Databases

A **database** is a container for collections, similar to a database in a relational system:

```
Database: ecommerce
  ├── Collection: users
  ├── Collection: products
  ├── Collection: orders
  └── Collection: reviews
```

### Document vs. Relational Comparison

| Concept | Relational | Document |
|---------|-----------|----------|
| **Data unit** | Row | Document |
| **Schema** | Fixed, predefined | Flexible, dynamic |
| **Structure** | Flat (single table) | Hierarchical (nested) |
| **Grouping** | Table | Collection |
| **Container** | Database | Database |
| **Relationships** | Foreign keys, joins | Embedding or references |
| **Normalization** | Highly normalized | Often denormalized |

### The `_id` Field

Every document must have an `_id` field that uniquely identifies it within a collection:

```json
{
  "_id": ObjectId("507f1f77bcf86cd799439011"),  // Auto-generated
  "title": "Introduction to MongoDB"
}

// Or with custom _id:
{
  "_id": "user_alice_2024",  // User-defined
  "name": "Alice Johnson"
}
```

**Properties of `_id`:**
- Automatically generated if not provided (using ObjectId type)
- Must be unique within the collection
- Immutable (cannot be changed after creation)
- Can be of any BSON type (commonly ObjectId or string)
- Automatically indexed for fast lookups

### Basic Document Operations

**Creating documents:**
```javascript
// Insert one document
db.users.insertOne({
  name: "Alice",
  email: "alice@example.com",
  age: 30
})

// Insert multiple documents
db.users.insertMany([
  { name: "Bob", email: "bob@example.com" },
  { name: "Charlie", email: "charlie@example.com" }
])
```

**Reading documents:**
```javascript
// Find all documents
db.users.find()

// Find with filter
db.users.find({ age: { $gte: 25 } })

// Find one document
db.users.findOne({ name: "Alice" })
```

**Updating documents:**
```javascript
// Update one document
db.users.updateOne(
  { name: "Alice" },
  { $set: { age: 31 } }
)

// Update multiple documents
db.users.updateMany(
  { active: false },
  { $set: { status: "inactive" } }
)
```

**Deleting documents:**
```javascript
// Delete one document
db.users.deleteOne({ name: "Bob" })

// Delete multiple documents
db.users.deleteMany({ active: false })
```

### Collections are Created Implicitly

In MongoDB, collections are created automatically when you first insert a document:

```javascript
// This creates the 'products' collection if it doesn't exist
db.products.insertOne({ name: "Laptop", price: 999 })
```

You can also explicitly create collections with options:

```javascript
// Create collection with validation rules
db.createCollection("users", {
  validator: {
    $jsonSchema: {
      required: ["name", "email"],
      properties: {
        name: { bsonType: "string" },
        email: { bsonType: "string" }
      }
    }
  }
})
```
