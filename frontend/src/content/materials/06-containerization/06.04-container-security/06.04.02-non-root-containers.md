- Configure file permissions for non-root users
- Use security contexts in Kubernetes
- Troubleshoot common permission issues

---

## Introduction

By default, containers run as root (UID 0), which presents a significant security risk. If an attacker compromises your container, they have root privileges and can potentially escape to the host system. Running containers as non-root users follows the principle of least privilege and dramatically reduces your attack surface.

## Key Concepts Summary

### The Root Problem

**Running as root (default):**
```dockerfile
FROM nginx:alpine
# Container runs as root (UID 0)
CMD ["nginx"]
```

**Risks:**
- Container escape leads to root access on host
- Can modify critical files
- Can install malware
- Can access other containers' data

**Impact of compromise:**
```
Attacker compromises app →
  Runs commands as root →
    Escapes container →
      Full host access! 💥
```

### Creating Non-Root Users

**Basic approach:**
```dockerfile
FROM node:18-alpine

# Create user
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001

# Set ownership
RUN chown -R nodejs:nodejs /app

# Switch to non-root user
USER nodejs

WORKDIR /app
COPY --chown=nodejs:nodejs . .

CMD ["node", "server.js"]
```

**For .NET:**
```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app/publish

FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
WORKDIR /app

# Create non-root user
RUN addgroup -g 1000 appgroup && \
    adduser -D -u 1000 -G appgroup appuser && \
    chown -R appuser:appgroup /app

USER appuser

COPY --from=build --chown=appuser:appgroup /app/publish .
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

**For Python:**
```dockerfile
FROM python:3.11-slim

# Create user
RUN useradd -m -u 1000 appuser && \
    mkdir -p /app && \
    chown -R appuser:appuser /app

USER appuser
WORKDIR /app

COPY --chown=appuser:appuser requirements.txt .
RUN pip install --user --no-cache-dir -r requirements.txt

COPY --chown=appuser:appuser . .

CMD ["python", "app.py"]
```

### File Permissions and Ownership

**Set ownership during COPY:**
```dockerfile
# Copy with specific ownership
COPY --chown=appuser:appgroup app.js /app/

# Copy entire directory
COPY --chown=appuser:appgroup . /app/
```

**Fix permissions after copy:**
```dockerfile
COPY . /app/
RUN chown -R appuser:appgroup /app
```

**Create writeable directories:**
```dockerfile
USER root
RUN mkdir -p /app/temp /app/logs && \
    chown -R appuser:appgroup /app/temp /app/logs && \
    chmod 755 /app/temp /app/logs

USER appuser
```

### USER Instruction

```dockerfile
# Switch to user by name
USER appuser

# Switch to user by UID
USER 1000

# Switch to user and group
USER appuser:appgroup

# Switch to user and group by ID
USER 1000:1000
```

**Best practice:** Use numeric UID for Kubernetes compatibility:
```dockerfile
USER 1000:1000
```

### Handling Root Requirements

Some operations require root privileges during build:

```dockerfile
FROM node:18-alpine

# Do root operations first
RUN apk add --no-cache python3 make g++

# Create user
RUN addgroup -g 1001 nodejs && \
    adduser -S nodejs -u 1001 && \
    chown -R nodejs:nodejs /app

# Switch to non-root
USER nodejs

# Now all following operations run as nodejs
WORKDIR /app
COPY --chown=nodejs:nodejs package*.json ./
RUN npm install
COPY --chown=nodejs:nodejs . .

CMD ["node", "server.js"]
```

### Docker Run Security Options

**Run as specific user:**
```bash
docker run --user 1000:1000 myapp
```

**Read-only root filesystem:**
```bash
docker run --read-only myapp
```

**Drop capabilities:**
```bash
docker run --cap-drop ALL --cap-add NET_BIND_SERVICE myapp
```

**No new privileges:**
```bash
docker run --security-opt=no-new-privileges myapp
```

### Kubernetes Security Context

**Pod security context:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 1000
    fsGroup: 1000
    seccompProfile:
      type: RuntimeDefault
  containers:
  - name: app
    image: myapp:latest
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop:
          - ALL
```

### Common Permission Issues and Solutions

**Issue 1: Can't write to filesystem**
```dockerfile
# Solution: Create writable directory
USER root
RUN mkdir -p /app/data && chown appuser:appuser /app/data
USER appuser
VOLUME /app/data
```

**Issue 2: Can't bind to port 80/443**
```dockerfile
# Solution: Use port > 1024
EXPOSE 8080
ENV ASPNETCORE_URLS=http://+:8080
```

Or use capability:
```bash
docker run --cap-add=NET_BIND_SERVICE --user 1000 myapp
```

**Issue 3: Can't install packages**
```dockerfile
# Solution: Install before switching user
FROM python:3.11-slim
RUN apt-get update && apt-get install -y gcc
RUN useradd -m appuser
USER appuser
RUN pip install --user -r requirements.txt
```

### Complete Secure Example

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app/publish

FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
WORKDIR /app

# Install dependencies as root
RUN apk add --no-cache icu-libs curl

# Create non-root user
RUN addgroup -g 1000 appgroup && \
    adduser -D -u 1000 -G appgroup appuser

# Create necessary directories with proper permissions
RUN mkdir -p /app/logs /app/temp && \
    chown -R appuser:appgroup /app

# Switch to non-root user
USER 1000:1000

# Copy app with correct ownership
COPY --from=build --chown=1000:1000 /app/publish .

# Environment variables
ENV ASPNETCORE_URLS=http://+:8080 \
    DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=false

EXPOSE 8080

HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget --no-verbose --tries=1 --spider http://localhost:8080/health || exit 1

ENTRYPOINT ["dotnet", "MyApp.dll"]
```

### Advanced User Management

**Using existing non-root user in base image:**
```dockerfile
# Many base images include non-root users
FROM node:18-alpine

# node user already exists (uid 1000)
USER node

WORKDIR /home/node/app
COPY --chown=node:node . .

CMD ["node", "server.js"]
```

**Common non-root users in base images:**
```
node:18-alpine → node (uid 1000)
nginx:alpine → nginx (uid 101)
postgres:15 → postgres (uid 999)
redis:7-alpine → redis (uid 999)
python:3.11-slim → No default non-root user (create one)
```

**Multiple users for different stages:**
```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build

# Build as root (need to install packages)
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app/publish

FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine

# Install packages as root
RUN apk add --no-cache icu-libs curl

# Create app user
RUN addgroup -g 1000 appgroup && \
    adduser -D -u 1000 -G appgroup appuser && \
    mkdir -p /app/logs /app/temp && \
    chown -R appuser:appgroup /app

# Create cache user for different workload
RUN adduser -D -u 1001 -G appgroup cacheuser && \
    mkdir -p /app/cache && \
    chown -R cacheuser:appgroup /app/cache

# Run as app user
USER appuser
COPY --from=build --chown=appuser:appgroup /app/publish /app/
WORKDIR /app

ENTRYPOINT ["dotnet", "MyApp.dll"]
```

### Security Implications Deep Dive

**Container escape scenarios:**
```
Root container + Kernel vulnerability = Host compromise
Non-root container + Kernel vulnerability = Limited damage
```

**Real-world example:**
```
CVE-2019-5736 (runc escape):
- Allowed container root to overwrite host runc binary
- Root containers: Complete host takeover
- Non-root containers: Attack failed (no write permissions)
```

**Defense in depth:**
```
Layer 1: Non-root user
Layer 2: Read-only filesystem
Layer 3: Dropped capabilities
Layer 4: AppArmor/SELinux
Layer 5: Network policies
Layer 6: Runtime security monitoring
```

### User Namespace Remapping (Advanced)

**What is it?**
```
Maps container users to different host users:
Container UID 0 (root) → Host UID 100000
Container UID 1000 → Host UID 101000

Even if container runs as root, host sees it as unprivileged user
```

**Enable in Docker daemon:**
```json
// /etc/docker/daemon.json
{
  "userns-remap": "default"
}
```

```bash
# Restart Docker
sudo systemctl restart docker

# Verify
docker info | grep "userns"
```

**Kubernetes user namespace (alpha in 1.25+):**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: userns-pod
spec:
  hostUsers: false  # Enable user namespace
  containers:
  - name: app
    image: nginx
    securityContext:
      runAsUser: 0  # Root in container
      # But mapped to non-root on host
```

### File System Permissions Best Practices

**Principle of least privilege:**
```dockerfile
# Create granular permissions
FROM node:18-alpine

RUN addgroup -g 1000 appgroup && \
    adduser -D -u 1000 -G appgroup appuser

# App code: read-only
RUN mkdir -p /app && \
    chown -R appuser:appgroup /app && \
    chmod 755 /app

# Temp directory: read-write
RUN mkdir -p /app/tmp && \
    chown appuser:appgroup /app/tmp && \
    chmod 700 /app/tmp  # Only user access

# Logs: write-only (for security)
RUN mkdir -p /app/logs && \
    chown appuser:appgroup /app/logs && \
    chmod 300 /app/logs  # Write and execute only

# Config: read-only, group-accessible
RUN mkdir -p /app/config && \
    chown root:appgroup /app/config && \
    chmod 750 /app/config

USER appuser
```

**Verify permissions:**
```bash
docker run --rm myapp ls -la /app
docker run --rm myapp ls -la /app/logs
docker run --rm myapp ls -la /app/tmp
```

### Handling Special Ports

**Problem: Ports < 1024 require root**
```dockerfile
# Won't work as non-root
USER 1000
EXPOSE 80
# bind: permission denied
```

**Solution 1: Use high ports**
```dockerfile
USER 1000
EXPOSE 8080
ENV ASPNETCORE_URLS=http://+:8080
```

**Solution 2: Grant NET_BIND_SERVICE capability**
```bash
docker run --cap-add=NET_BIND_SERVICE --user 1000 myapp
```

**Solution 3: Use reverse proxy**
```yaml
# docker-compose.yml
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    # nginx runs as root but isolated
    
  app:
    image: myapp:latest
    user: "1000:1000"
    expose:
      - "8080"
    # app runs as non-root
```

### Debugging Non-Root Container Issues

**Issue: "Permission denied" errors**
```bash
# Check current user
docker run --rm myapp whoami
docker run --rm myapp id

# Check file permissions
docker run --rm myapp ls -la /app

# Check what user owns files
docker run --rm myapp stat -c '%U %G' /app/file.txt

# Run as root temporarily for debugging
docker run --rm --user root myapp ls -la /app
```

**Issue: Can't write to volume**
```yaml
# Problem
volumes:
  - ./data:/app/data  # Host UID doesn't match container UID

# Solution 1: Fix permissions on host
chown -R 1000:1000 ./data

# Solution 2: Use named volume (better)
volumes:
  - app-data:/app/data
volumes:
  app-data:
```

**Issue: Can't install packages at runtime**
```dockerfile
# Wrong - trying to install as non-root
USER 1000
RUN apt-get install -y package  # Fails

# Right - install before switching user
RUN apt-get install -y package
USER 1000
```

### Production-Grade Examples

**ASP.NET Core API:**
```dockerfile

WORKDIR /src

RUN dotnet restore "MyApi/MyApi.csproj"

    dotnet publish -c Release -o /app/publish /p:UseAppHost=false

FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
WORKDIR /app

# Install runtime dependencies as root
RUN apk add --no-cache \
    icu-libs \
    tzdata \

RUN mkdir -p /app/logs /app/temp /app/data && \
    chown -R appuser:appgroup /app && \
    chmod 755 /app && \
    chmod 700 /app/temp && \
    chmod 755 /app/logs

# Switch to non-root user
USER 1654:1654

# Copy application
```

### Kubernetes Security Best Practices

**Enforce non-root at cluster level:**
```yaml
apiVersion: policy/v1beta1
kind: PodSecurityPolicy
metadata:
  name: restricted
spec:
  privileged: false
  allowPrivilegeEscalation: false
  requiredDropCapabilities:
    - ALL
  runAsUser:
    rule: MustRunAsNonRoot
  seLinux:
    rule: RunAsAny
  fsGroup:
    rule: RunAsAny
  supplementalGroups:
    rule: RunAsAny
  volumes:
    - 'configMap'
    - 'emptyDir'
    - 'projected'
    - 'secret'
    - 'downwardAPI'
    - 'persistentVolumeClaim'
```

**Use Pod Security Standards:**
```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: production
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/warn: restricted
```

### Compliance and Auditing

**Check for root containers:**
```bash
# Docker
docker ps --format 'table {{.Names}}\t{{.Image}}' | while read name image; do
  echo -n "$name: "
  docker inspect $name --format '{{.Config.User}}'
done

# Kubernetes
kubectl get pods -o json | \
  jq -r '.items[] | select(.spec.securityContext.runAsUser == 0 or .spec.securityContext.runAsNonRoot == false) | .metadata.name'
```

**Automated compliance checking:**
```yaml
# OPA policy
package kubernetes.admission

deny[msg] {
  input.request.kind.kind == "Pod"
  container := input.request.object.spec.containers[_]
  not container.securityContext.runAsNonRoot
  msg := sprintf("Container %v must run as non-root", [container.name])
}
```

## Practice Exercise

After completing the materials (20 minutes max):

1. **Create a vulnerable Dockerfile (running as root):**
```dockerfile
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/
CMD ["nginx", "-g", "daemon off;"]
```

2. **Make it secure (non-root):**
```dockerfile
FROM nginx:alpine

# Create non-root user
RUN addgroup -g 101 -S nginx && \
    adduser -S -D -H -u 101 -h /var/cache/nginx -s /sbin/nologin -G nginx -g nginx nginx

# Set permissions
RUN chown -R nginx:nginx /usr/share/nginx/html && \
    chown -R nginx:nginx /var/cache/nginx && \
    chown -R nginx:nginx /var/log/nginx && \
    chmod -R 755 /var/log/nginx && \
    touch /var/run/nginx.pid && \
    chown nginx:nginx /var/run/nginx.pid

USER nginx

COPY --chown=nginx:nginx index.html /usr/share/nginx/html/
CMD ["nginx", "-g", "daemon off;"]
```

3. **Test both:**
```bash
# Build and test root version
docker build -f Dockerfile.root -t test:root .
docker run -d --name root test:root
docker exec root whoami  # Should be root
docker exec root id      # uid=0(root)

# Build and test non-root version
docker build -f Dockerfile.nonroot -t test:nonroot .
docker run -d --name nonroot test:nonroot
docker exec nonroot whoami  # Should be nginx
docker exec nonroot id      # uid=101(nginx)
```

4. **Verify the difference:**
```bash
# Check configured user
docker inspect root --format='{{.Config.User}}'     # empty (root)
docker inspect nonroot --format='{{.Config.User}}'  # nginx

# Check running process user
docker top root
docker top nonroot
```

5. **Test with Kubernetes security context:**
```yaml
# secure-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: secure-app
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    fsGroup: 1000
  containers:
  - name: app
    image: myapp:latest
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop:
          - ALL
    volumeMounts:
    - name: tmp
      mountPath: /tmp
  volumes:
  - name: tmp
    emptyDir: {}
```

```bash
kubectl apply -f secure-pod.yaml
kubectl exec secure-app -- id
kubectl exec secure-app -- whoami
```

6. **Debug permission issues:**
```bash
# If your app fails with permission errors
docker run --rm myapp ls -la /app
docker run --rm myapp stat /app/data

# Fix permissions
docker run --rm --user root myapp chown -R 1000:1000 /app/data
```
