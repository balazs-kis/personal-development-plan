# Lesson 5: Secrets Management

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand why secrets shouldn't be in images or environment variables
- Use Docker Secrets in Swarm mode
- Configure Kubernetes Secrets
- Integrate with external secret stores (Azure Key Vault, AWS Secrets Manager)
- Implement secrets rotation strategies

---

## Introduction

Secrets (passwords, API keys, certificates, tokens) require special handling. Storing them in images, environment variables, or configuration files creates security vulnerabilities. This lesson covers secure secrets management using Docker, Kubernetes, and cloud-native solutions.

## Key Concepts Summary

### What NOT to Do

**❌ Never hardcode secrets:**
```dockerfile
# BAD - Secret in image
ENV DB_PASSWORD="SuperSecret123"
```

**❌ Don't commit secrets to Git:**
```csharp
// BAD - Secret in code
var connectionString = "Server=db;Password=MyPassword;";
```

**❌ Don't pass as build arguments:**
```dockerfile
# BAD - Secret in build history
ARG API_KEY=abc123
RUN echo $API_KEY > /config/key.txt
```

**❌ Don't expose in environment variables (less secure):**
```bash
# Less secure - visible in docker inspect
docker run -e DB_PASSWORD=secret myapp
```

### Docker Compose Secrets

**File-based secrets:**
```yaml
version: '3.8'

services:
  app:
    image: myapp:latest
    secrets:
      - db_password
      - api_key
    environment:
      DB_PASSWORD_FILE: /run/secrets/db_password
      API_KEY_FILE: /run/secrets/api_key

secrets:
  db_password:
    file: ./secrets/db_password.txt
  api_key:
    file: ./secrets/api_key.txt
```

**Secrets are mounted at `/run/secrets/<secret_name>`:**
```bash
# Inside container
cat /run/secrets/db_password
```

**Reading secrets in .NET:**
```csharp
public class SecretReader
{
    public static string ReadSecret(string secretName)
    {
        var secretPath = $"/run/secrets/{secretName}";
        if (File.Exists(secretPath))
        {
            return File.ReadAllText(secretPath).Trim();
        }
        
        // Fallback to environment variable
        return Environment.GetEnvironmentVariable(secretName) ?? "";
    }
}

// Usage
var dbPassword = SecretReader.ReadSecret("db_password");
var connectionString = $"Server=db;Password={dbPassword};";
```

### Docker Swarm Secrets

**Create secret:**
```bash
# From file
echo "MySecretPassword" | docker secret create db_password -

# From stdin
docker secret create api_key api_key.txt

# List secrets
docker secret ls

# Inspect (value is never shown)
docker secret inspect db_password
```

**Use in service:**
```bash
docker service create \
  --name myapp \
  --secret db_password \
  --secret api_key \
  myapp:latest
```

**Or in docker-compose.yml (Swarm mode):**
```yaml
version: '3.8'

services:
  app:
    image: myapp:latest
    secrets:
      - db_password
      - api_key
    deploy:
      replicas: 3

secrets:
  db_password:
    external: true
  api_key:
    external: true
```

### Kubernetes Secrets

**Create from literal:**
```bash
kubectl create secret generic db-credentials \
  --from-literal=username=admin \
  --from-literal=password=SuperSecret123
```

**Create from file:**
```bash
kubectl create secret generic api-keys \
  --from-file=api-key.txt \
  --from-file=oauth-token.txt
```

**Create from YAML:**
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-credentials
type: Opaque
data:
  username: YWRtaW4=        # base64 encoded
  password: U3VwZXJTZWNyZXQ= # base64 encoded
```

**Encode values:**
```bash
echo -n 'admin' | base64
echo -n 'SuperSecret123' | base64
```

**Types of secrets:**
- `Opaque` - Generic secrets (default)
- `kubernetes.io/dockerconfigjson` - Docker registry credentials
- `kubernetes.io/tls` - TLS certificates
- `kubernetes.io/service-account-token` - Service account tokens
- `kubernetes.io/basic-auth` - Basic authentication

### Using Secrets in Pods

**As environment variables:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  containers:
  - name: app
    image: myapp:latest
    env:
    - name: DB_USERNAME
      valueFrom:
        secretKeyRef:
          name: db-credentials
          key: username
    - name: DB_PASSWORD
      valueFrom:
        secretKeyRef:
          name: db-credentials
          key: password
```

**As volume mounts (more secure):**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  containers:
  - name: app
    image: myapp:latest
    volumeMounts:
    - name: secrets
      mountPath: "/etc/secrets"
      readOnly: true
  volumes:
  - name: secrets
    secret:
      secretName: db-credentials
```

**Files created:**
```
/etc/secrets/username
/etc/secrets/password
```

### Azure Key Vault Integration

**Using CSI Driver:**
```yaml
apiVersion: secrets-store.csi.x-k8s.io/v1
kind: SecretProviderClass
metadata:
  name: azure-keyvault
spec:
  provider: azure
  parameters:
    usePodIdentity: "false"
    useVMManagedIdentity: "true"
    userAssignedIdentityID: "client-id"
    keyvaultName: "mykeyvault"
    tenantId: "tenant-id"
    objects: |
      array:
        - |
          objectName: DbPassword
          objectType: secret
          objectVersion: ""
```

**Mount in pod:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  containers:
  - name: app
    image: myapp:latest
    volumeMounts:
    - name: secrets-store
      mountPath: "/mnt/secrets"
      readOnly: true
  volumes:
  - name: secrets-store
    csi:
      driver: secrets-store.csi.k8s.io
      readOnly: true
      volumeAttributes:
        secretProviderClass: "azure-keyvault"
```

**In .NET application:**
```csharp
// Program.cs
builder.Configuration.AddAzureKeyVault(
    new Uri($"https://{keyVaultName}.vault.azure.net/"),
    new DefaultAzureCredential());

// Access secrets
var dbPassword = builder.Configuration["DbPassword"];
```

### External Secrets Operator

**Install:**
```bash
helm repo add external-secrets https://charts.external-secrets.io
helm install external-secrets external-secrets/external-secrets
```

**Configure SecretStore:**
```yaml
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: azure-keyvault-store
spec:
  provider:
    azurekv:
      authType: ManagedIdentity
      vaultUrl: "https://mykeyvault.vault.azure.net"
      identityId: "managed-identity-client-id"
```

**Create ExternalSecret:**
```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: app-secrets
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: azure-keyvault-store
    kind: SecretStore
  target:
    name: app-secrets
    creationPolicy: Owner
  data:
  - secretKey: db-password
    remoteRef:
      key: DbPassword
  - secretKey: api-key
    remoteRef:
      key: ApiKey
```

**Automatically syncs to Kubernetes Secret:**
```bash
kubectl get secret app-secrets -o yaml
```

### Secrets Rotation

**Automatic rotation with External Secrets:**
```yaml
spec:
  refreshInterval: 15m  # Check every 15 minutes
```

**Manual rotation:**
```bash
# Update in Key Vault
az keyvault secret set --vault-name mykeyvault --name DbPassword --value NewPassword

# Restart pods to pick up new secret
kubectl rollout restart deployment myapp
```

**Using reload annotations:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  template:
    metadata:
      annotations:
        reloader.stakater.com/auto: "true"
```

### Best Practices

**1. Use external secret stores:**
```
Application → Kubernetes Secret → Azure Key Vault
              (synced)
```

**2. Encrypt at rest:**
```yaml
# Enable encryption in Kubernetes
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
    - secrets
    providers:
    - aescbc:
        keys:
        - name: key1
          secret: <base64 encoded secret>
```

**3. Limit access with RBAC:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: secret-reader
rules:
- apiGroups: [""]
  resources: ["secrets"]
  resourceNames: ["app-secrets"]
  verbs: ["get", "list"]
```

**4. Use short-lived secrets:**
- Rotate frequently
- Use managed identities when possible
- Generate temporary tokens

**5. Never log secrets:**
```csharp
// BAD
_logger.LogInformation($"Connecting with password: {password}");

// GOOD
_logger.LogInformation("Connecting to database");
```

**6. Audit secret access:**
```bash
# Enable audit logging for secret access
kubectl get events -A | grep secrets

# Check who accessed secrets
kubectl auth can-i get secrets --as=user@example.com
```

**7. Use separate secrets per environment:**
```bash
# Development
kubectl create secret generic app-secrets-dev --from-literal=key=dev-value -n development

# Production
kubectl create secret generic app-secrets-prod --from-literal=key=prod-value -n production
```

### Advanced Secrets Patterns

**Multi-tenant secrets:**
```yaml
# Separate secrets per tenant
apiVersion: v1
kind: Secret
metadata:
  name: tenant-a-secrets
  namespace: tenant-a
type: Opaque
data:
  db-password: <base64>
  api-key: <base64>
---
apiVersion: v1
kind: Secret
metadata:
  name: tenant-b-secrets
  namespace: tenant-b
type: Opaque
data:
  db-password: <base64>
  api-key: <base64>
```

**Dynamic secret generation (Vault):**
```yaml
# Vault sidecar injector
apiVersion: v1
kind: Pod
metadata:
  name: app
  annotations:
    vault.hashicorp.com/agent-inject: "true"
    vault.hashicorp.com/role: "myapp"
    vault.hashicorp.com/agent-inject-secret-database: "database/creds/myapp"
spec:
  containers:
  - name: app
    image: myapp:latest
    # Vault generates dynamic DB credentials
```

**Sealed Secrets (GitOps-friendly):**
```bash
# Install Sealed Secrets controller
kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.18.0/controller.yaml

# Create sealed secret
echo -n "supersecret" | kubectl create secret generic mysecret --dry-run=client --from-file=password=/dev/stdin -o yaml | \
  kubeseal -o yaml > sealed-secret.yaml

# Commit to Git (safe!)
git add sealed-secret.yaml
git commit -m "Add sealed secret"
```

**Immutable secrets:**
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: immutable-secret
type: Opaque
immutable: true  # Cannot be modified after creation
data:
  password: <base64>
```

### Secrets in CI/CD Pipelines

**GitHub Actions with Azure Key Vault:**
```yaml
name: Deploy
on: push

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Azure Login
        uses: azure/login@v1
        with:
          creds: ${{ secrets.AZURE_CREDENTIALS }}
      
      - name: Get secrets from Key Vault
        uses: azure/get-keyvault-secrets@v1
        with:
          keyvault: "mykeyvault"
          secrets: 'DbPassword, ApiKey'
        id: keyvault
      
      - name: Deploy with secrets
        run: |
          kubectl create secret generic app-secrets \
            --from-literal=db-password=${{ steps.keyvault.outputs.DbPassword }} \
            --from-literal=api-key=${{ steps.keyvault.outputs.ApiKey }} \
            --dry-run=client -o yaml | kubectl apply -f -
```

**Azure DevOps with Key Vault:**
```yaml
trigger:
  - main

pool:
  vmImage: 'ubuntu-latest'

steps:
- task: AzureKeyVault@2
  inputs:
    azureSubscription: 'MyServiceConnection'
    KeyVaultName: 'mykeyvault'
    SecretsFilter: 'DbPassword,ApiKey'
    RunAsPreJob: true

- task: Kubernetes@1
  inputs:
    command: 'apply'
    arguments: '-f deployment.yaml'
  env:
    DB_PASSWORD: $(DbPassword)
    API_KEY: $(ApiKey)
```

### Compliance and Security Standards

**Secret scanning in repositories:**
```yaml
# .github/workflows/secret-scan.yml
name: Secret Scan
on: [push, pull_request]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0
      
      - name: TruffleHog
        uses: trufflesecurity/trufflehog@main
        with:
          path: ./
          base: main
          head: HEAD
```

**Compliance requirements:**
```
SOC 2:
- Encrypt secrets at rest and in transit
- Audit all secret access
- Rotate secrets regularly
- Use MFA for secret access

PCI-DSS:
- Store payment credentials in compliant vault
- Encrypt with strong algorithms
- Restrict access based on least privilege
- Log and monitor secret access

HIPAA:
- Encrypt PHI-related secrets
- Implement access controls
- Maintain audit trails
- Regular security assessments
```

### Monitoring and Alerting

**Alert on secret access:**
```yaml
# Prometheus AlertRule
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: secret-alerts
spec:
  groups:
  - name: secrets
    rules:
    - alert: UnauthorizedSecretAccess
      expr: |
        sum(rate(apiserver_audit_event_total{objectRef_resource="secrets",verb="get"}[5m])) by (user) > 10
      annotations:
        summary: "Unusual secret access by {{ $labels.user }}"
    
    - alert: SecretModified
      expr: |
        sum(rate(apiserver_audit_event_total{objectRef_resource="secrets",verb=~"update|patch|delete"}[5m])) > 0
      annotations:
        summary: "Secret was modified in cluster"
```

**Audit logging:**
```yaml
# Kubernetes audit policy
apiVersion: audit.k8s.io/v1
kind: Policy
rules:
- level: RequestResponse
  resources:
  - group: ""
    resources: ["secrets"]
  verbs: ["get", "list", "create", "update", "patch", "delete"]
```

### Troubleshooting Common Issues

**Issue 1: Permission denied accessing secret**
```bash
# Check RBAC
kubectl auth can-i get secrets --as=system:serviceaccount:default:myapp

# Check service account
kubectl get serviceaccount myapp -o yaml

# Check role binding
kubectl get rolebinding -o yaml | grep -A 10 secret-reader
```

**Issue 2: Secret not mounting**
```bash
# Check pod events
kubectl describe pod myapp

# Check volume mount
kubectl exec myapp -- ls -la /etc/secrets

# Verify secret exists
kubectl get secret app-secrets
```

**Issue 3: External Secrets not syncing**
```bash
# Check ExternalSecret status
kubectl get externalsecrets
kubectl describe externalsecret app-secrets

# Check SecretStore connection
kubectl describe secretstore azure-keyvault-store

# Check operator logs
kubectl logs -n external-secrets-system deployment/external-secrets
```

### Complete Example

**docker-compose.yml:**
```yaml
version: '3.8'

services:
  api:
    build: .
    secrets:
      - db_password
      - api_key
    environment:
      ConnectionStrings__DefaultConnection: "Server=db;Database=mydb;User=admin;Password_File=/run/secrets/db_password"
      ApiKey_File: /run/secrets/api_key

  db:
    image: postgres:15
    secrets:
      - db_password
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password

secrets:
  db_password:
    file: ./secrets/db_password.txt
  api_key:
    file: ./secrets/api_key.txt
```

**.NET reading secrets:**
```csharp
public static class SecretExtensions
{
    public static IConfigurationBuilder AddDockerSecrets(
        this IConfigurationBuilder builder)
    {
        var secretsPath = "/run/secrets";
        if (Directory.Exists(secretsPath))
        {
            var secrets = Directory.GetFiles(secretsPath)
                .ToDictionary(
                    Path.GetFileName,
                    File.ReadAllText
                );
            
            builder.AddInMemoryCollection(secrets);
        }
        
        return builder;
    }
}

// Usage in Program.cs
builder.Configuration.AddDockerSecrets();
```
