# Lesson 3: The Kubernetes API

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand the Kubernetes API object model
- Work with different API groups and versions
- Use kubectl to interact with the API
- Understand resource types and their relationships
- Explore the API using kubectl and curl

---

## Introduction

The Kubernetes API is the foundation of the entire system. Everything in Kubernetes is represented as an API object (pods, services, deployments, etc.), and all components communicate through the API server. Understanding the API structure is essential for effectively working with Kubernetes.

## Key Concepts Summary

### Kubernetes API Structure

```
Kubernetes API
├── Core API Group (v1)
│   ├── pods
│   ├── services
│   ├── configmaps
│   ├── secrets
│   └── nodes
│
├── apps/v1
│   ├── deployments
│   ├── statefulsets
│   ├── daemonsets
│   └── replicasets
│
├── batch/v1
│   ├── jobs
│   └── cronjobs
│
├── networking.k8s.io/v1
│   ├── ingresses
│   └── networkpolicies
│
└── rbac.authorization.k8s.io/v1
    ├── roles
    ├── rolebindings
    ├── clusterroles
    └── clusterrolebindings
```

### API Object Model

**Every Kubernetes object has:**

**1. API Version:**
```yaml
apiVersion: apps/v1  # API group + version
```

**2. Kind:**
```yaml
kind: Deployment  # Resource type
```

**3. Metadata:**
```yaml
metadata:
  name: myapp
  namespace: default
  labels:
    app: web
    tier: frontend
  annotations:
    description: "My web application"
```

**4. Spec (desired state):**
```yaml
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
```

**5. Status (current state - read-only):**
```yaml
status:
  replicas: 3
  availableReplicas: 3
  readyReplicas: 3
  conditions:
  - type: Available
    status: "True"
```

### Complete Object Example

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
  namespace: default
  labels:
    app: nginx
  annotations:
    kubernetes.io/change-cause: "Update to nginx 1.21"
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
        ports:
        - containerPort: 80
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 500m
            memory: 512Mi
status:
  observedGeneration: 1
  replicas: 3
  updatedReplicas: 3
  readyReplicas: 3
  availableReplicas: 3
  conditions:
  - type: Progressing
    status: "True"
    reason: NewReplicaSetAvailable
  - type: Available
    status: "True"
```

### API Groups and Versions

**Core Group (legacy):**
```yaml
# No group specified - it's the core group
apiVersion: v1
kind: Pod
```

**Named Groups:**
```yaml
# Group: apps, Version: v1
apiVersion: apps/v1
kind: Deployment

# Group: batch, Version: v1
apiVersion: batch/v1
kind: Job

# Group: networking.k8s.io, Version: v1
apiVersion: networking.k8s.io/v1
kind: Ingress
```

**Versioning:**
- **Alpha** (v1alpha1): Experimental, may change
- **Beta** (v1beta1): Well-tested, but may still change
- **Stable** (v1): Production-ready, won't change

**List API groups:**
```bash
kubectl api-resources

# Output shows:
# NAME          SHORTNAMES   APIVERSION              NAMESPACED   KIND
# pods          po           v1                      true         Pod
# deployments   deploy       apps/v1                 true         Deployment
# services      svc          v1                      true         Service
# ingresses     ing          networking.k8s.io/v1    true         Ingress
```

### Working with the API

**Using kubectl:**
```bash
# Create resource
kubectl create -f deployment.yaml

# Apply (create or update)
kubectl apply -f deployment.yaml

# Get resources
kubectl get deployments
kubectl get pods
kubectl get all

# Describe (includes events)
kubectl describe deployment nginx

# Get full object as YAML
kubectl get deployment nginx -o yaml

# Get specific fields
kubectl get pods -o jsonpath='{.items[*].metadata.name}'

# Watch for changes
kubectl get pods -w

# Delete resource
kubectl delete deployment nginx
```

**Using kubectl proxy:**
```bash
# Start proxy to API server
kubectl proxy --port=8080

# Access API via HTTP
curl http://localhost:8080/api/v1/namespaces/default/pods
```

**Direct API access:**
```bash
# Get API server URL
kubectl cluster-info

# Get token
TOKEN=$(kubectl create token default)

# Get API server CA cert
kubectl config view --raw -o jsonpath='{.clusters[0].cluster.certificate-authority-data}' | base64 -d > ca.crt

# Make API request
curl --cacert ca.crt \
  -H "Authorization: Bearer $TOKEN" \
  https://kubernetes-api-server:6443/api/v1/namespaces/default/pods
```

### Resource Relationships

**Ownership and Garbage Collection:**
```
Deployment
    ↓ (owns)
ReplicaSet
    ↓ (owns)
Pods

# When Deployment is deleted:
# → ReplicaSet is deleted (garbage collected)
# → Pods are deleted (garbage collected)
```

**Owner References:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-abc123
  ownerReferences:
  - apiVersion: apps/v1
    kind: ReplicaSet
    name: nginx-789xyz
    uid: 12345-67890
    controller: true
    blockOwnerDeletion: true
```

### Labels and Selectors

**Labels (metadata):**
```yaml
metadata:
  labels:
    app: nginx
    tier: frontend
    environment: prod
    version: v1.21
```

**Equality-based selectors:**
```bash
# Single label
kubectl get pods -l app=nginx

# Multiple labels (AND)
kubectl get pods -l app=nginx,tier=frontend

# Not equal
kubectl get pods -l environment!=prod
```

**Set-based selectors:**
```bash
# In set
kubectl get pods -l 'environment in (prod,staging)'

# Not in set
kubectl get pods -l 'tier notin (cache,database)'

# Key exists
kubectl get pods -l version

# Key doesn't exist
kubectl get pods -l '!version'
```

**Selector in specs:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx
spec:
  selector:
    app: nginx  # Equality-based selector
  ports:
  - port: 80

---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
spec:
  selector:
    matchLabels:  # Equality-based
      app: nginx
    matchExpressions:  # Set-based
    - key: tier
      operator: In
      values:
      - frontend
```

### Annotations

**Non-identifying metadata:**
```yaml
metadata:
  annotations:
    kubernetes.io/change-cause: "Update to v1.21"
    description: "Production web server"
    contact: "devops@company.com"
    deployment.kubernetes.io/revision: "3"
    prometheus.io/scrape: "true"
    prometheus.io/port: "9090"
```

**Common use cases:**
- Build/release info
- Image provenance
- Tool configuration (Prometheus, Istio, etc.)
- Change tracking
- Contact information

### Field Selectors

**Query by status fields:**
```bash
# Running pods only
kubectl get pods --field-selector=status.phase=Running

# Pods on specific node
kubectl get pods --field-selector=spec.nodeName=worker-1

# Failed pods
kubectl get pods --field-selector=status.phase=Failed

# Combine multiple
kubectl get pods --field-selector=status.phase=Running,spec.nodeName=worker-1
```

### API Discovery

**Explore API resources:**
```bash
# List all resource types
kubectl api-resources

# Filter by API group
kubectl api-resources --api-group=apps

# Show verbs (actions)
kubectl api-resources -o wide

# List API versions
kubectl api-versions
```

**Explain resources:**
```bash
# Get resource documentation
kubectl explain pod
kubectl explain pod.spec
kubectl explain pod.spec.containers
kubectl explain deployment.spec.strategy

# Show all fields
kubectl explain pod --recursive
```

### Watching and Events

**Watch resources:**
```bash
# Watch pods
kubectl get pods -w

# Watch events
kubectl get events -w

# Watch specific resource
kubectl get deployment nginx -w

# Watch with output format
kubectl get pods -w -o wide
```

**Get events:**
```bash
# All events in namespace
kubectl get events

# Sort by timestamp
kubectl get events --sort-by='.lastTimestamp'

# Events for specific resource
kubectl describe pod nginx-abc123

# Filter by type
kubectl get events --field-selector type=Warning

# Watch events for debugging
kubectl get events -w --field-selector involvedObject.kind=Pod
```

**Event Structure:**
```yaml
apiVersion: v1
kind: Event
metadata:
  name: nginx-abc123.17a2b3c4d5e6f7g8
  namespace: default
involvedObject:
  apiVersion: v1
  kind: Pod
  name: nginx-abc123
  namespace: default
  uid: 12345-67890
reason: Started
message: Started container nginx
source:
  component: kubelet
  host: worker-1
type: Normal
firstTimestamp: 2024-01-15T10:30:00Z
lastTimestamp: 2024-01-15T10:30:00Z
count: 1
```

### Custom Resource Definitions (CRDs)

**Extending the API:**
```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: applications.example.com
spec:
  group: example.com
  names:
    kind: Application
    plural: applications
    singular: application
    shortNames:
    - app
  scope: Namespaced
  versions:
  - name: v1
    served: true
    storage: true
    schema:
      openAPIV3Schema:
        type: object
        properties:
          spec:
            type: object
            properties:
              replicas:
                type: integer
              image:
                type: string
          status:
            type: object
            properties:
              availableReplicas:
                type: integer
```

**Using Custom Resources:**
```yaml
apiVersion: example.com/v1
kind: Application
metadata:
  name: myapp
spec:
  replicas: 3
  image: myapp:latest
```

```bash
# List custom resources
kubectl get applications

# Describe custom resource
kubectl describe application myapp

# Edit custom resource
kubectl edit application myapp
```

### Server-Side Apply

**Three-way merge vs Server-side apply:**
```bash
# Traditional apply (client-side)
kubectl apply -f deployment.yaml

# Server-side apply
kubectl apply --server-side -f deployment.yaml

# Force ownership
kubectl apply --server-side --force-conflicts -f deployment.yaml
```

**Field Management:**
```yaml
# Each field tracks its manager
metadata:
  managedFields:
  - apiVersion: apps/v1
    fieldsType: FieldsV1
    fieldsV1:
      f:spec:
        f:replicas: {}
    manager: kubectl-client-side-apply
  - apiVersion: apps/v1
    fieldsType: FieldsV1
    fieldsV1:
      f:spec:
        f:template:
          f:spec:
            f:containers: {}
    manager: deployment-controller
```

### API Request Patterns

**List vs Watch:**
```bash
# List: One-time snapshot
kubectl get pods

# Watch: Continuous stream
kubectl get pods -w

# Internally uses different API calls:
# List: GET /api/v1/namespaces/default/pods
# Watch: GET /api/v1/namespaces/default/pods?watch=true
```

**Pagination:**
```bash
# Large lists are paginated
kubectl get pods --limit=500

# Get next page
kubectl get pods --limit=500 --continue=<token>

# API request:
# GET /api/v1/pods?limit=500&continue=<token>
```

**Resource Versions:**
```bash
# Every object has a resourceVersion
kubectl get pod nginx -o jsonpath='{.metadata.resourceVersion}'

# Used for optimistic concurrency
# Update fails if resourceVersion changed
```

### Advanced Querying

**JSONPath queries:**
```bash
# Get pod IPs
kubectl get pods -o jsonpath='{.items[*].status.podIP}'

# Get container images
kubectl get pods -o jsonpath='{.items[*].spec.containers[*].image}'

# Complex query with range
kubectl get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.phase}{"\n"}{end}'

# Conditional filtering
kubectl get pods -o jsonpath='{.items[?(@.status.phase=="Running")].metadata.name}'
```

**Custom columns:**
```bash
# Custom output format
kubectl get pods -o custom-columns=NAME:.metadata.name,STATUS:.status.phase,IP:.status.podIP

# With sorting
kubectl get pods --sort-by=.status.startTime

# Multiple resources
kubectl get pods,services -o wide
```

### API Versioning Strategy

**Deprecation Timeline:**
```
v1alpha1 → v1alpha2 → v1beta1 → v1beta2 → v1
   ↓          ↓          ↓         ↓       ↓
  Can be    Removed    9 months  9 months GA
  removed   anytime    minimum   minimum
  anytime
```

**Version Conversion:**
```yaml
# Old version
apiVersion: apps/v1beta1
kind: Deployment
# Automatically converted to:
apiVersion: apps/v1
kind: Deployment
```

**Checking Deprecated APIs:**
```bash
# Find deprecated API usage
kubectl get --raw /apis | jq .

# Check deprecations in your manifests
kubectl apply --dry-run=server -f deployment.yaml

# Use tools like pluto or kubectl-deprecations
kubectl deprecations --help
```

## Practice Exercise

After completing the materials (20 minutes max):

1. **Explore API resources:**
```bash
# List all resource types
kubectl api-resources

# Find shortnames
kubectl api-resources | grep deployment

# Check API groups
kubectl api-versions

# Show verbs for resources
kubectl api-resources -o wide | head -20
```

2. **Work with objects:**
```bash
# Create a deployment
kubectl create deployment nginx --image=nginx

# Get as YAML
kubectl get deployment nginx -o yaml

# Get as JSON
kubectl get deployment nginx -o json

# Get specific fields
kubectl get deployment nginx -o jsonpath='{.spec.replicas}'
kubectl get deployment nginx -o jsonpath='{.status.availableReplicas}'

# Explain the structure
kubectl explain deployment
kubectl explain deployment.spec
kubectl explain deployment.spec.template
```

3. **Use labels and selectors:**
```bash
# Add labels to pods
kubectl label pod nginx-xxx app=web tier=frontend env=prod

# Query by labels
kubectl get pods -l app=web
kubectl get pods -l 'tier in (frontend,backend)'
kubectl get pods -l app=web,env=prod

# Show labels
kubectl get pods --show-labels

# Label nodes
kubectl label nodes worker-1 disktype=ssd
kubectl get nodes -l disktype=ssd

# Remove label
kubectl label pod nginx-xxx env-
```

4. **Work with annotations:**
```bash
# Add annotation
kubectl annotate pod nginx-xxx description="Production web server"
kubectl annotate pod nginx-xxx contact="devops@company.com"

# View annotations
kubectl get pod nginx-xxx -o jsonpath='{.metadata.annotations}'

# Remove annotation
kubectl annotate pod nginx-xxx description-
```

5. **Access the API directly:**
```bash
# Start kubectl proxy
kubectl proxy --port=8080 &

# List pods via API
curl http://localhost:8080/api/v1/namespaces/default/pods | jq '.items[].metadata.name'

# Get specific pod
curl http://localhost:8080/api/v1/namespaces/default/pods/nginx-xxx

# List all API groups
curl http://localhost:8080/apis | jq '.groups[].name'

# Stop proxy when done
kill %1
```

6. **Explore Custom Resources (if available):**
```bash
# List CRDs
kubectl get crd

# Get details of a CRD
kubectl get crd <crd-name> -o yaml

# List custom resource instances
kubectl get <custom-resource-plural>

# Describe custom resource
kubectl describe <custom-resource-kind> <name>
```
