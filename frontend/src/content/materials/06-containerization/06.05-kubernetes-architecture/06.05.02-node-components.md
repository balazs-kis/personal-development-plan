---

## Introduction

Worker nodes are where your application containers actually run. Each node runs three essential components: kubelet (the node agent), kube-proxy (network proxy), and a container runtime (like containerd or Docker). These components work together with the control plane to execute and manage your workloads.

### 1. kubelet: The Node Agent

**Role:** The primary node agent that ensures containers are running in pods as specified.

**Key Responsibilities:**

**Pod Management:**
```
1. Watch for pod assignments from API server
2. Pull container images
3. Start containers via container runtime
4. Monitor container health
5. Report pod status back to API server
6. Restart failed containers
```

**Health Monitoring:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  containers:
  - name: app
    image: myapp:latest
    # Liveness probe - kubelet checks this
    livenessProbe:
      httpGet:
        path: /health
        port: 8080
      initialDelaySeconds: 30
      periodSeconds: 10
    # Readiness probe - kubelet checks this
    readinessProbe:
      httpGet:
        path: /ready
        port: 8080
      initialDelaySeconds: 5
      periodSeconds: 5
```

**Resource Monitoring:**
```bash
# Kubelet reports node resources
kubectl describe node worker-1

# Output includes:
# Capacity:
#   cpu:     4
#   memory:  16Gi
#   pods:    110
# Allocatable:
#   cpu:     3900m
#   memory:  15Gi
#   pods:    110
```

**Communication Flow:**
```
┌──────────────┐
│  API Server  │
└──────┬───────┘
       ↓ (Watch for pod assignments)
┌──────────────┐
│   kubelet    │
└──────┬───────┘
       ↓ (CRI - Container Runtime Interface)
┌──────────────┐
│ containerd   │
└──────┬───────┘
       ↓ (OCI Runtime)
┌──────────────┐
│     runc     │ (starts containers)
└──────────────┘
```

**Kubelet Configuration:**
```yaml
# /var/lib/kubelet/config.yaml
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
authentication:
  webhook:
    enabled: true
authorization:
  mode: Webhook
clusterDNS:
  - 10.96.0.10
clusterDomain: cluster.local
cgroupDriver: systemd
containerLogMaxSize: 50Mi
maxPods: 110
```

**Static Pods:**
```bash
# Kubelet can run pods from local manifests
# Place YAML files in: /etc/kubernetes/manifests/

# Example: control plane components as static pods
ls /etc/kubernetes/manifests/
# etcd.yaml
# kube-apiserver.yaml
# kube-controller-manager.yaml
# kube-scheduler.yaml
```

### 2. kube-proxy: Network Proxy

**Role:** Maintains network rules on nodes to allow network communication to Pods from inside and outside the cluster.

**Service Implementation:**
```
Service (ClusterIP: 10.96.10.20)
       ↓
kube-proxy creates rules
       ↓
┌─────────────────────────────┐
│  iptables / IPVS rules      │
│  - Forward to pod IPs       │
│  - Load balance requests    │
│  - NAT translations         │
└─────────────────────────────┘
       ↓
Pod IPs: 10.244.1.5, 10.244.2.8, 10.244.3.12
```

**Proxy Modes:**

**1. iptables Mode (default):**
```bash
# kube-proxy creates iptables rules
sudo iptables -t nat -L KUBE-SERVICES

# Example rules for a service
-A KUBE-SERVICES -d 10.96.10.20/32 -p tcp -m tcp --dport 80 \
   -j KUBE-SVC-ABCDEF123456

-A KUBE-SVC-ABCDEF123456 -m statistic --mode random --probability 0.33 \
   -j KUBE-SEP-POD1

-A KUBE-SVC-ABCDEF123456 -m statistic --mode random --probability 0.50 \
   -j KUBE-SEP-POD2

-A KUBE-SVC-ABCDEF123456 -j KUBE-SEP-POD3
```

**2. IPVS Mode (more efficient):**
```bash
# Enable IPVS mode
kube-proxy --proxy-mode=ipvs

# View IPVS rules
sudo ipvsadm -Ln

# IPVS provides better performance for large clusters
# Supports multiple load balancing algorithms:
# - Round Robin (rr)
# - Least Connection (lc)
# - Source Hashing (sh)
```

**Service Example:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: ClusterIP
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 8080

---
# kube-proxy watches this service
# Creates rules: Service IP → Pod IPs
# Handles load balancing across pods
```

**Network Flow:**
```
Client → Service IP (10.96.10.20:80)
         ↓ (kube-proxy iptables/IPVS)
         Load balance to one of:
         → Pod 1 (10.244.1.5:8080)
         → Pod 2 (10.244.2.8:8080)
         → Pod 3 (10.244.3.12:8080)
```

### 3. Container Runtime

**Role:** Software responsible for running containers on the node.

**Supported Runtimes:**
- **containerd** (most common, Docker's runtime)
- **CRI-O** (designed for Kubernetes)
- **Docker Engine** (deprecated in Kubernetes 1.24+)

**Container Runtime Interface (CRI):**
```
┌──────────────┐
│   kubelet    │
└──────┬───────┘
       ↓ (CRI API - gRPC)
┌──────────────┐
│ containerd   │  or  CRI-O
└──────┬───────┘
       ↓ (OCI spec)
┌──────────────┐
│  runc/crun   │
└──────────────┘
```

**Runtime Operations:**
```bash
# Using containerd (via crictl)
# List running containers
sudo crictl ps

# List images
sudo crictl images

# Pull image
sudo crictl pull nginx:alpine

# Inspect container
sudo crictl inspect <container-id>
```

### Node Registration and Lifecycle

**Self-Registration:**
```yaml
# Kubelet automatically registers node
# Registration includes:
apiVersion: v1
kind: Node
metadata:
  name: worker-1
  labels:
    kubernetes.io/hostname: worker-1
    kubernetes.io/os: linux
    kubernetes.io/arch: amd64
    node-role.kubernetes.io/worker: ""
status:
  capacity:
    cpu: "4"
    memory: 16Gi
  addresses:
  - type: InternalIP
    address: 192.168.1.10
  - type: Hostname
    address: worker-1
```

**Node Heartbeat:**
```
kubelet → API server (every 10 seconds)
   ↓
Updates node status
   ↓
Node Controller monitors
   ↓
If no heartbeat for 40 seconds:
   → Mark node as NotReady
If no heartbeat for 5 minutes:
   → Start pod eviction
```

**Node Conditions:**
```bash
kubectl describe node worker-1

# Conditions:
#   Type             Status  Reason
#   ----             ------  ------
#   MemoryPressure   False   KubeletHasSufficientMemory
#   DiskPressure     False   KubeletHasNoDiskPressure
#   PIDPressure      False   KubeletHasSufficientPID
#   Ready            True    KubeletReady
```

### Node Taints and Labels

**Taints (prevent pod scheduling):**
```bash
# Add taint
kubectl taint nodes worker-1 dedicated=gpu:NoSchedule

# Remove taint
kubectl taint nodes worker-1 dedicated=gpu:NoSchedule-

# View taints
kubectl describe node worker-1 | grep Taints
```

**Labels (for pod scheduling):**
```bash
# Add label
kubectl label nodes worker-1 disktype=ssd

# Remove label
kubectl label nodes worker-1 disktype-

# Select nodes with label
kubectl get nodes -l disktype=ssd
```

### Troubleshooting Node Issues

**Check node status:**
```bash
# List nodes
kubectl get nodes

# Detailed node info
kubectl describe node worker-1

# Node logs (if systemd)
journalctl -u kubelet -f

# Check kubelet config
cat /var/lib/kubelet/config.yaml
```

**Common Issues:**

**1. Node NotReady:**
```bash
# Check kubelet
systemctl status kubelet

# Check kubelet logs
journalctl -u kubelet --no-pager | tail -50

# Common causes:
# - Kubelet not running
# - Network connectivity issues
# - Certificate expiration
# - Disk pressure
# - CNI plugin failure

# Fix steps:
# 1. Restart kubelet
sudo systemctl restart kubelet

# 2. Check certificates
sudo ls -l /var/lib/kubelet/pki/

# 3. Check disk space
df -h

# 4. Check CNI
ls -l /etc/cni/net.d/
sudo systemctl status containerd
```

**2. Pods not starting:**
```bash
# Check events
kubectl get events --sort-by='.lastTimestamp'

# Check pod status
kubectl describe pod <pod-name>

# Check kubelet logs for specific pod
journalctl -u kubelet | grep <pod-name>

# Common causes:
# - Image pull errors (check registry access)
# - Insufficient resources (check node capacity)
# - Volume mount failures (check storage)
# - Scheduling constraints (check taints/tolerations)
```

**3. Network issues:**
```bash
# Check kube-proxy
kubectl get pods -n kube-system -l k8s-app=kube-proxy
kubectl logs -n kube-system -l k8s-app=kube-proxy

# Check CNI plugin
kubectl get pods -n kube-system -l k8s-app=calico-node
# or
kubectl get pods -n kube-system -l k8s-app=flannel

# Test pod networking
kubectl run test --image=busybox --rm -it -- sh
# Inside pod:
# ping <another-pod-ip>
# nslookup kubernetes.default

# Check iptables rules
sudo iptables-save | grep KUBE

# Check service endpoints
kubectl get endpoints
```

### Node Lifecycle Management

**Cordoning and Draining:**
```bash
# Cordon node (prevent new pod scheduling)
kubectl cordon worker-1
# Node marked as SchedulingDisabled

# Drain node (evict all pods)
kubectl drain worker-1 \
  --ignore-daemonsets \
  --delete-emptydir-data \
  --force

# Perform maintenance on node...

# Uncordon node (allow scheduling again)
kubectl uncordon worker-1
```

**Node Upgrade Process:**
```bash
# 1. Cordon and drain
kubectl drain worker-1 --ignore-daemonsets

# 2. SSH to node and upgrade
ssh worker-1
sudo apt-get update
sudo apt-get upgrade -y kubelet kubectl
sudo systemctl restart kubelet

# 3. Verify node is healthy
kubectl get nodes

# 4. Uncordon
kubectl uncordon worker-1
```

**Node Resource Management:**
```bash
# View resource allocation
kubectl describe node worker-1 | grep -A 10 "Allocated resources"

# Output shows:
#   CPU Requests:    2000m (50%)
#   CPU Limits:      4000m (100%)
#   Memory Requests: 4Gi (25%)
#   Memory Limits:   8Gi (50%)

# View actual resource usage
kubectl top node worker-1

# View pod resource usage on node
kubectl top pods --all-namespaces --field-selector spec.nodeName=worker-1
```

### Advanced Node Configuration

**Kubelet Flags:**
```bash
# View current kubelet configuration
sudo systemctl cat kubelet

# Common flags:
--kubeconfig=/etc/kubernetes/kubelet.conf
--config=/var/lib/kubelet/config.yaml
--container-runtime-endpoint=unix:///var/run/containerd/containerd.sock
--pod-manifest-path=/etc/kubernetes/manifests
--max-pods=110
--node-labels=disktype=ssd,nodepool=general
--register-with-taints=dedicated=gpu:NoSchedule
```

**Container Runtime Debugging:**
```bash
# Check containerd status
sudo systemctl status containerd

# View containerd config
sudo cat /etc/containerd/config.toml

# Check runtime classes
kubectl get runtimeclass

# Debug container issues
sudo crictl ps -a | grep <pod-name>
sudo crictl logs <container-id>
sudo crictl inspect <container-id>
```

**Node Problem Detector:**
```yaml
# Detects node-level issues
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-problem-detector
spec:
  selector:
    matchLabels:
      app: node-problem-detector
  template:
    metadata:
      labels:
        app: node-problem-detector
    spec:
      hostNetwork: true
      containers:
      - name: node-problem-detector
        image: k8s.gcr.io/node-problem-detector:v0.8.10
        securityContext:
          privileged: true
        volumeMounts:
        - name: log
          mountPath: /var/log
      volumes:
      - name: log
        hostPath:
          path: /var/log/
```
