# Lesson 2: Multi-Stage Builds for .NET

## Learning Objectives

By the end of this lesson, you will be able to:
- Implement efficient multi-stage builds for .NET applications

- Configure build arguments and outputs
- Implement build optimization techniques (trimming, ReadyToRun)
- Create production-ready .NET container images

---

## Introduction

Multi-stage builds are essential for .NET containerization. They allow you to use the full SDK for building while keeping only the minimal runtime in the final image. This lesson focuses on .NET-specific patterns and optimizations that result in smaller, faster, and more secure containers.

## Key Concepts Summary

### Basic Multi-Stage Pattern for .NET

```dockerfile
# Stage 1: Build
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app/publish

# Stage 2: Runtime
FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

**Benefits:**
- Final image: ~200MB (vs ~700MB with SDK)
- 70% size reduction
- No build tools in production
- Faster deployment and startup

### Optimized Multi-Stage Build

```dockerfile
# Stage 1: Restore dependencies
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS restore
WORKDIR /src
COPY ["MyApp/MyApp.csproj", "MyApp/"]
COPY ["MyApp.Core/MyApp.Core.csproj", "MyApp.Core/"]
RUN dotnet restore "MyApp/MyApp.csproj"

# Stage 2: Build
FROM restore AS build
COPY . .
WORKDIR "/src/MyApp"
RUN dotnet build "MyApp.csproj" -c Release -o /app/build --no-restore

# Stage 3: Publish
FROM build AS publish
RUN dotnet publish "MyApp.csproj" \
    -c Release \
    -o /app/publish \
    --no-restore \
    --no-build \
    /p:UseAppHost=false

# Stage 4: Runtime
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS final
WORKDIR /app

# Security: Run as non-root
RUN adduser --disabled-password --gecos '' appuser && \
    chown -R appuser /app
USER appuser

EXPOSE 8080
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

### Why Separate Restore Stage?

**Layer caching optimization:**

```dockerfile
# Copy only .csproj files first
COPY ["MyApp/MyApp.csproj", "MyApp/"]
RUN dotnet restore "MyApp/MyApp.csproj"

# Then copy source code
COPY . .
RUN dotnet build ...
```

**Benefits:**
- `dotnet restore` runs only when .csproj changes
- Source code changes don't invalidate restore cache
- Much faster incremental builds

**Without optimization:**
```dockerfile
COPY . .                    # ← All source changes invalidate this
RUN dotnet restore          # ← Restore runs every time
RUN dotnet build
```

**With optimization:**
```dockerfile
COPY ["*.csproj", "./"]     # ← Only .csproj changes invalidate
RUN dotnet restore          # ← Cached when dependencies unchanged
COPY . .                    # ← Source changes happen after restore
RUN dotnet build --no-restore
```

### Multi-Project Solution Example

```dockerfile
# For solutions with multiple projects
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Copy solution file
COPY ["MyApp.sln", "./"]

# Copy all project files
COPY ["src/MyApp.Api/MyApp.Api.csproj", "src/MyApp.Api/"]
COPY ["src/MyApp.Core/MyApp.Core.csproj", "src/MyApp.Core/"]
COPY ["src/MyApp.Infrastructure/MyApp.Infrastructure.csproj", "src/MyApp.Infrastructure/"]
COPY ["tests/MyApp.Tests/MyApp.Tests.csproj", "tests/MyApp.Tests/"]

# Restore for the solution
RUN dotnet restore "MyApp.sln"

# Copy everything else
COPY . .

# Build
WORKDIR "/src/src/MyApp.Api"
RUN dotnet build "MyApp.Api.csproj" -c Release -o /app/build --no-restore

# Publish
FROM build AS publish
RUN dotnet publish "MyApp.Api.csproj" \
    -c Release \
    -o /app/publish \
    --no-restore \
    --no-build

# Runtime
FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "MyApp.Api.dll"]
```

### Build Configuration Options

**Basic publish:**
```dockerfile
RUN dotnet publish -c Release -o /app/publish
```

**Optimized publish:**
```dockerfile
RUN dotnet publish "MyApp.csproj" \
    -c Release \
    -o /app/publish \
    --no-restore \
    --no-build \
    /p:UseAppHost=false \
    /p:PublishTrimmed=false \
    /p:PublishSingleFile=false
```

**Aggressive optimization:**
```dockerfile
RUN dotnet publish "MyApp.csproj" \
    -c Release \
    -o /app/publish \
    --no-restore \
    /p:UseAppHost=false \
    /p:PublishTrimmed=true \
    /p:PublishSingleFile=true \
    /p:PublishReadyToRun=true \
    /p:TrimMode=link
```

### Understanding Publish Options

| Option | Effect | Size Impact | Performance | Risk |
|--------|--------|-------------|-------------|------|
| `UseAppHost=false` | No native executable | -10MB | Standard | Low |
| `PublishTrimmed=true` | Remove unused code | -50% | Slightly slower startup | Medium |
| `PublishSingleFile=true` | Bundle into one file | Similar | Faster startup | Low |
| `PublishReadyToRun=true` | AOT compilation | +20MB | Faster startup | Low |
| `TrimMode=link` | Aggressive trimming | -60% | Standard | High |

**Conservative (recommended):**
```dockerfile
RUN dotnet publish \
    -c Release \
    -o /app/publish \
    /p:UseAppHost=false
```

**Balanced:**
```dockerfile
RUN dotnet publish \
    -c Release \
    -o /app/publish \
    /p:UseAppHost=false \
    /p:PublishReadyToRun=true
```

**Aggressive (test thoroughly):**
```dockerfile
RUN dotnet publish \
    -c Release \
    -o /app/publish \
    /p:UseAppHost=false \
    /p:PublishTrimmed=true \
    /p:TrimMode=link
```

### ASP.NET Core Specific Optimizations

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Copy and restore
COPY ["MyWebApi/MyWebApi.csproj", "MyWebApi/"]
RUN dotnet restore "MyWebApi/MyWebApi.csproj"

# Copy source
COPY . .
WORKDIR "/src/MyWebApi"

# Build with optimizations
RUN dotnet build "MyWebApi.csproj" \
    -c Release \
    -o /app/build \
    --no-restore

# Publish
FROM build AS publish
RUN dotnet publish "MyWebApi.csproj" \
    -c Release \
    -o /app/publish \
    --no-restore \
    --no-build \
    /p:UseAppHost=false \
    /p:PublishReadyToRun=true

# Runtime stage
FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine AS final
WORKDIR /app

# Install required packages for Alpine
RUN apk add --no-cache icu-libs

# Environment variables
ENV DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=false \
    ASPNETCORE_URLS=http://+:8080 \
    DOTNET_EnableDiagnostics=0

# Security: non-root user
RUN adduser -D -g '' appuser && chown -R appuser /app
USER appuser

EXPOSE 8080

# Copy published app
COPY --from=publish /app/publish .

# Health check
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s \
    CMD wget --no-verbose --tries=1 --spider http://localhost:8080/health || exit 1

ENTRYPOINT ["dotnet", "MyWebApi.dll"]
```

### Blazor WebAssembly Optimization

```dockerfile
# Build stage
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

COPY ["BlazorApp/BlazorApp.csproj", "BlazorApp/"]
RUN dotnet restore "BlazorApp/BlazorApp.csproj"

COPY . .
WORKDIR "/src/BlazorApp"
RUN dotnet build "BlazorApp.csproj" -c Release -o /app/build

# Publish Blazor WASM
FROM build AS publish
RUN dotnet publish "BlazorApp.csproj" \
    -c Release \
    -o /app/publish

# Serve with nginx (smallest runtime)
FROM nginx:alpine AS final
COPY --from=publish /app/publish/wwwroot /usr/share/nginx/html
COPY nginx.conf /etc/nginx/nginx.conf
EXPOSE 80
```

**Result:** ~20MB image for Blazor WASM!

### Worker Service Example

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

COPY ["WorkerService/WorkerService.csproj", "WorkerService/"]
RUN dotnet restore "WorkerService/WorkerService.csproj"

COPY . .

FROM build AS publish
RUN dotnet publish "WorkerService.csproj" \
    -c Release \
    -o /app/publish \
    --no-restore \
    --no-build

# Use runtime (not aspnet) for worker services

# Set environment

    TZ=UTC

COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "WorkerService.dll"]
```

### Build Arguments and Customization

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build

# Build arguments
ARG BUILD_CONFIGURATION=Release
ARG VERSION=1.0.0
ARG BUILD_NUMBER=0

WORKDIR /src
COPY ["MyApp/MyApp.csproj", "MyApp/"]
RUN dotnet restore "MyApp/MyApp.csproj"

COPY . .
WORKDIR "/src/MyApp"

# Use build arguments
RUN dotnet build "MyApp.csproj" \
    -c ${BUILD_CONFIGURATION} \
    -o /app/build \
    /p:Version=${VERSION}.${BUILD_NUMBER}

FROM build AS publish
RUN dotnet publish "MyApp.csproj" \
    -c ${BUILD_CONFIGURATION} \
    -o /app/publish \
    --no-build

FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app

# Label with version info
LABEL version="${VERSION}.${BUILD_NUMBER}"
LABEL build.configuration="${BUILD_CONFIGURATION}"

COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

**Build with arguments:**
```bash
docker build \
    --build-arg VERSION=2.1.0 \
    --build-arg BUILD_NUMBER=42 \
    -t myapp:2.1.0.42 \
    .
```

### Testing Stage (Optional)

```dockerfile
# Build stage
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet build -c Release

# Test stage (optional, can be targeted separately)
FROM build AS test
RUN dotnet test --no-build -c Release --logger "trx;LogFileName=test_results.xml"

# Publish stage
FROM build AS publish
RUN dotnet publish "MyApp/MyApp.csproj" \
    -c Release \
    -o /app/publish \
    --no-build

# Runtime stage
FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

**Run tests during build:**
```bash
# Build up to test stage
docker build --target test -t myapp:test .

# Build full image (skips test stage)
docker build -t myapp:latest .
```

### Complete Production-Ready Example

```dockerfile
# syntax=docker/dockerfile:1

# Build stage
FROM mcr.microsoft.com/dotnet/sdk:8.0-bookworm-slim AS build
ARG BUILD_CONFIGURATION=Release
WORKDIR /src

# Copy project files
COPY ["src/MyApp.Api/MyApp.Api.csproj", "src/MyApp.Api/"]
COPY ["src/MyApp.Core/MyApp.Core.csproj", "src/MyApp.Core/"]
COPY ["src/MyApp.Infrastructure/MyApp.Infrastructure.csproj", "src/MyApp.Infrastructure/"]

# Restore dependencies
RUN dotnet restore "src/MyApp.Api/MyApp.Api.csproj"

# Copy source code
COPY . .
WORKDIR "/src/src/MyApp.Api"

# Build
RUN dotnet build "MyApp.Api.csproj" \
    -c ${BUILD_CONFIGURATION} \
    -o /app/build \
    --no-restore

# Publish stage
FROM build AS publish
RUN dotnet publish "MyApp.Api.csproj" \
    -c ${BUILD_CONFIGURATION} \
    -o /app/publish \
    --no-restore \
    --no-build \
    /p:UseAppHost=false \
    /p:PublishReadyToRun=true

# Runtime stage
FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine AS final
WORKDIR /app

# Install required packages
RUN apk add --no-cache \
    icu-libs \
    tzdata \
    curl

# Environment configuration
ENV DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=false \
    ASPNETCORE_URLS=http://+:8080 \
    DOTNET_EnableDiagnostics=0 \
    DOTNET_USE_POLLING_FILE_WATCHER=true \
    TZ=UTC

# Create non-root user
RUN addgroup -g 1000 appgroup && \
    adduser -D -u 1000 -G appgroup appuser && \
    chown -R appuser:appgroup /app

USER appuser

EXPOSE 8080

# Copy published application
COPY --from=publish --chown=appuser:appgroup /app/publish .

# Health check
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD wget --no-verbose --tries=1 --spider http://localhost:8080/health || exit 1

ENTRYPOINT ["dotnet", "MyApp.Api.dll"]
```
