## Introduction

Deployments are the standard way to run stateless applications in Kubernetes. They provide declarative updates for Pods and ReplicaSets, handling rolling updates, rollbacks, and scaling automatically. Understanding Deployments is essential for managing production applications.

## Key Concepts Summary

### What is a Deployment?

```
Deployment
    ↓ (creates and manages)
ReplicaSet
    ↓ (creates and manages)
Pods
```

**Purpose:**
- Ensures desired number of Pods are running
- Handles rolling updates with zero downtime
- Allows easy rollback to previous versions
- Scales applications up or down

### Basic Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
        ports:
        - containerPort: 80
        resources:
          requests:
            memory: "64Mi"
            cpu: "100m"
          limits:
            memory: "128Mi"
            cpu: "200m"
```

**Key fields:**
- `replicas`: Desired number of pods
- `selector`: How to find pods to manage
- `template`: Pod specification

### Creating and Managing Deployments

```bash
# Create deployment
kubectl apply -f deployment.yaml

# Get deployments
kubectl get deployments

# Detailed status
kubectl describe deployment nginx-deployment

# Get ReplicaSets
kubectl get replicasets

# Get Pods
kubectl get pods -l app=nginx

# Watch rollout status
kubectl rollout status deployment/nginx-deployment
```

### Scaling

**Declarative (recommended):**
```yaml
# Update deployment.yaml
spec:
  replicas: 5
```

```bash
kubectl apply -f deployment.yaml
```

**Imperative:**
```bash
# Scale up
kubectl scale deployment nginx-deployment --replicas=5

# Scale down
kubectl scale deployment nginx-deployment --replicas=2

# Autoscale
kubectl autoscale deployment nginx-deployment --min=2 --max=10 --cpu-percent=80
```

**Watch scaling:**
```bash
kubectl get pods -w
kubectl get deployment nginx-deployment -w
```

### Rolling Updates

**Update image (declarative):**
```yaml
# deployment.yaml
spec:
  template:
    spec:
      containers:
      - name: nginx
        image: nginx:1.22  # Updated version
```

```bash
kubectl apply -f deployment.yaml
```

**Update image (imperative):**
```bash
kubectl set image deployment/nginx-deployment nginx=nginx:1.22
```

**Rolling update strategy:**
```yaml
spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1        # Max extra pods during update
      maxUnavailable: 0  # Min available pods during update
```

**Example:**
```
Before:  [v1] [v1] [v1]
Step 1:  [v1] [v1] [v1] [v2]  (maxSurge: 1)
Step 2:  [v1] [v1] [v2] [v2]  (v1 deleted)
Step 3:  [v1] [v2] [v2] [v2]
Step 4:  [v2] [v2] [v2]
```

**Monitor rollout:**
```bash
# Watch rollout
kubectl rollout status deployment/nginx-deployment

# View rollout history
kubectl rollout history deployment/nginx-deployment

# View specific revision
kubectl rollout history deployment/nginx-deployment --revision=2
```

### Rollback

**Undo last deployment:**
```bash
kubectl rollout undo deployment/nginx-deployment
```

**Rollback to specific revision:**
```bash
kubectl rollout undo deployment/nginx-deployment --to-revision=1
```

**Pause/Resume rollout:**
```bash
# Pause
kubectl rollout pause deployment/nginx-deployment

# Make changes
kubectl set image deployment/nginx-deployment nginx=nginx:1.22
kubectl set resources deployment/nginx-deployment -c=nginx --limits=cpu=300m

# Resume
kubectl rollout resume deployment/nginx-deployment
```

### Update Strategies

**RollingUpdate (default):**
```yaml
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 25%
    maxUnavailable: 25%
```

**Pros:** Zero downtime, gradual rollout  
**Cons:** Both versions run simultaneously

**Recreate:**
```yaml
strategy:
  type: Recreate
```

**Pros:** Simple, only one version at a time  
**Cons:** Downtime during update

### ReplicaSets

**Automatically created by Deployments:**
```bash
kubectl get replicasets

# Output:
# NAME                      DESIRED   CURRENT   READY
# nginx-deployment-abc123   3         3         3
# nginx-deployment-def456   0         0         0  (old version)
```

**ReplicaSet manifest (usually created by Deployment):**
```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: nginx-rs
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
```

**Note:** Use Deployments, not ReplicaSets directly!

### Advanced Deployment Configuration

**Revision history:**
```yaml
spec:
  revisionHistoryLimit: 10  # Keep last 10 ReplicaSets
```

**Progress deadline:**
```yaml
spec:
  progressDeadlineSeconds: 600  # Fail if not ready in 10 min
```

**Min ready seconds:**
```yaml
spec:
  minReadySeconds: 10  # Wait 10s before considering pod ready
```

### Complete Production Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
  labels:
    app: api
    tier: backend
spec:
  replicas: 3
  revisionHistoryLimit: 10
  progressDeadlineSeconds: 600
  minReadySeconds: 10
  
  selector:
    matchLabels:
      app: api
  
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
      - name: api
        image: myapi:1.2.0
        ports:
        - containerPort: 8080
          name: http
        
        env:
        - name: ENVIRONMENT
          value: "production"
        
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
          limits:
            memory: "512Mi"
            cpu: "500m"
        
        livenessProbe:
          httpGet:
            path: /health
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
        
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 5
      
      # Graceful shutdown
      terminationGracePeriodSeconds: 30
```

### Best Practices

**1. Always use Deployments, not bare Pods:**
```yaml
# Good
kind: Deployment

# Bad (for production)
kind: Pod
```

**2. Set resource requests and limits:**
```yaml
resources:
  requests:
    memory: "256Mi"
    cpu: "250m"
  limits:
    memory: "512Mi"
    cpu: "500m"
```

**3. Configure probes:**
```yaml
livenessProbe:
  httpGet:
    path: /health
    port: 8080
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
```

**4. Use specific image tags:**
```yaml
# Good
image: nginx:1.21.6

# Bad
image: nginx:latest
```

**5. Set maxUnavailable to 0 for zero downtime:**
```yaml
rollingUpdate:
  maxSurge: 1
  maxUnavailable: 0
```

### Advanced Deployment Patterns

**Blue-Green Deployment:**
```yaml
# Blue deployment (current)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-blue
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
      version: blue
  template:
    metadata:
      labels:
        app: myapp
        version: blue
    spec:
      containers:
      - name: app
        image: myapp:1.0

---
# Green deployment (new)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-green
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
      version: green
  template:
    metadata:
      labels:
        app: myapp
        version: green
    spec:
      containers:
      - name: app
        image: myapp:2.0

---
# Service switches between versions
apiVersion: v1
kind: Service
metadata:
  name: myapp
spec:
  selector:
    app: myapp
    version: blue  # Switch to green when ready
  ports:
  - port: 80
```

**Canary Deployment:**
```yaml
# Main deployment (90% of traffic)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-stable
spec:
  replicas: 9
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
        version: stable
    spec:
      containers:
      - name: app
        image: myapp:1.0

---
# Canary deployment (10% of traffic)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-canary
spec:
  replicas: 1
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
        version: canary
    spec:
      containers:
      - name: app
        image: myapp:2.0

---
# Service load balances across both
apiVersion: v1
kind: Service
metadata:
  name: myapp
spec:
  selector:
    app: myapp  # Selects both stable and canary
  ports:
  - port: 80
```

### Deployment Status Conditions

**Understanding conditions:**
```bash
kubectl describe deployment myapp

# Conditions:
#   Type           Status  Reason
#   ----           ------  ------
#   Available      True    MinimumReplicasAvailable
#   Progressing    True    NewReplicaSetAvailable
```

**Available:** Deployment has minimum replicas available
**Progressing:** Deployment is actively rolling out

**Check status programmatically:**
```bash
kubectl get deployment myapp -o jsonpath='{.status.conditions[?(@.type=="Available")].status}'
```

### Horizontal Pod Autoscaler (HPA)

**Auto-scale based on metrics:**
```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: myapp-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: myapp
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 80
```

**Manage HPA:**
```bash
# Create HPA
kubectl autoscale deployment myapp --min=2 --max=10 --cpu-percent=70

# Get HPA status
kubectl get hpa

# Describe HPA
kubectl describe hpa myapp-hpa
```

### Deployment Labels and Annotations

**Best practices for labels:**
```yaml
metadata:
  labels:
    app.kubernetes.io/name: myapp
    app.kubernetes.io/version: "1.2.0"
    app.kubernetes.io/component: backend
    app.kubernetes.io/part-of: ecommerce
    app.kubernetes.io/managed-by: kubectl
    environment: production
    tier: backend
```

**Useful annotations:**
```yaml
metadata:
  annotations:
    kubernetes.io/change-cause: "Update to v1.2.0 with performance improvements"
    deployment.kubernetes.io/revision: "5"
    description: "Main API backend service"
    contact: "backend-team@company.com"
```

### Troubleshooting

**Deployment not progressing:**
```bash
kubectl describe deployment <name>
kubectl get events --sort-by='.lastTimestamp'
```

**Check rollout status:**
```bash
kubectl rollout status deployment/<name>
```

**Failed rollout:**
```bash
# View history
kubectl rollout history deployment/<name>

# Rollback
kubectl rollout undo deployment/<name>
```

**Pods not starting:**
```bash
kubectl get pods
kubectl describe pod <pod-name>
kubectl logs <pod-name>
```
