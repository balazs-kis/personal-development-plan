# Lesson 1: ConfigMaps for Configuration

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand what ConfigMaps are and why they're needed
- Create ConfigMaps from literals, files, and YAML manifests
- Consume ConfigMaps as environment variables and volume mounts
- Update ConfigMaps and propagate changes to pods
- Apply ConfigMap best practices

---

## Introduction

ConfigMaps decouple configuration from container images, making applications more portable across environments. They store non-sensitive configuration data as key-value pairs that can be consumed by pods as environment variables, command-line arguments, or mounted files. This separation enables the same image to run in development, staging, and production with different configurations.

## Key Concepts Summary

### What is a ConfigMap?

```
Problem:
- Hard-coded config in images
- Need to rebuild for each environment
- No separation of concerns

Solution:
ConfigMap stores config data
  ↓
Pods consume at runtime
  ↓
Same image, different configs
```

**Use ConfigMaps for:**
- Application settings
- Environment-specific configuration
- Command-line arguments
- Configuration files

**Don't use ConfigMaps for:**
- Sensitive data (use Secrets)
- Large data (> 1 MiB limit)

### Creating ConfigMaps

**From literal values:**
```bash
kubectl create configmap app-config \
  --from-literal=APP_ENV=production \
  --from-literal=LOG_LEVEL=info \
  --from-literal=MAX_CONNECTIONS=100
```

**From files:**
```bash
# Single file
kubectl create configmap app-config \
  --from-file=config.json

# Multiple files
kubectl create configmap app-config \
  --from-file=app.properties \
  --from-file=database.properties

# Entire directory
kubectl create configmap app-config \
  --from-file=./config-dir/
```

**From YAML manifest:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: default
data:
  # Simple key-value pairs
  APP_ENV: "production"
  LOG_LEVEL: "info"
  MAX_CONNECTIONS: "100"
  
  # Multi-line data
  app.properties: |
    server.port=8080
    server.host=0.0.0.0
    database.url=postgresql://db:5432/myapp
    cache.ttl=3600
  
  # JSON configuration
  config.json: |
    {
      "server": {
        "port": 8080,
        "host": "0.0.0.0"
      },
      "features": {
        "caching": true,
        "logging": true
      }
    }
```

### Consuming as Environment Variables

**Single key:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: myapp:latest
    env:
    - name: APP_ENV
      valueFrom:
        configMapKeyRef:
          name: app-config
          key: APP_ENV
    - name: LOG_LEVEL
      valueFrom:
        configMapKeyRef:
          name: app-config
          key: LOG_LEVEL
```

**All keys at once:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: myapp:latest
    envFrom:
    - configMapRef:
        name: app-config
```

**Result:**
```bash
# Inside container
echo $APP_ENV        # production
echo $LOG_LEVEL      # info
echo $MAX_CONNECTIONS # 100
```

### Consuming as Volume Mounts

**Mount entire ConfigMap:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: myapp:latest
    volumeMounts:
    - name: config-volume
      mountPath: /etc/config
      readOnly: true
  volumes:
  - name: config-volume
    configMap:
      name: app-config
```

**Result:**
```bash
# Inside container at /etc/config/
/etc/config/APP_ENV           # "production"
/etc/config/LOG_LEVEL         # "info"
/etc/config/app.properties    # file contents
/etc/config/config.json       # file contents
```

**Mount specific keys:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: myapp:latest
    volumeMounts:
    - name: config-volume
      mountPath: /etc/config
  volumes:
  - name: config-volume
    configMap:
      name: app-config
      items:
      - key: app.properties
        path: application.properties
      - key: config.json
        path: config.json
```

**Result:**
```bash
/etc/config/application.properties  # renamed from app.properties
/etc/config/config.json
```

### Deployment with ConfigMap

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: web-config
data:
  ENVIRONMENT: "production"
  API_URL: "https://api.example.com"
  CACHE_TTL: "3600"

---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: web
        image: nginx:alpine
        envFrom:
        - configMapRef:
            name: web-config
        volumeMounts:
        - name: nginx-config
          mountPath: /etc/nginx/conf.d
      volumes:
      - name: nginx-config
        configMap:
          name: nginx-config
```

### Updating ConfigMaps

**Edit existing ConfigMap:**
```bash
kubectl edit configmap app-config
```

**Replace from file:**
```bash
kubectl create configmap app-config \
  --from-file=config.json \
  --dry-run=client -o yaml | kubectl apply -f -
```

**Update via patch:**
```bash
kubectl patch configmap app-config \
  -p '{"data":{"LOG_LEVEL":"debug"}}'
```

**Important:** ConfigMap updates propagate differently:

**Environment variables:** ❌ NOT updated until pod restart
```bash
# Need to restart pods
kubectl rollout restart deployment web
```

**Volume mounts:** ✅ Updated automatically (eventually consistent)
```bash
# Files update after ~1 minute (kubelet sync period)
# Pods see changes without restart
```

### Immutable ConfigMaps

**Prevent accidental changes:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  APP_ENV: "production"
immutable: true
```

**Benefits:**
- Prevents accidental updates
- Improves cluster performance (no watches)
- Forces explicit version changes

**To update:** Delete and recreate with new name
```bash
kubectl delete configmap app-config
kubectl apply -f app-config-v2.yaml
```

### ConfigMap Per Environment

```yaml
# configmap-dev.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: development
data:
  API_URL: "http://api.dev.example.com"
  LOG_LEVEL: "debug"

---
# configmap-prod.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: production
data:
  API_URL: "https://api.example.com"
  LOG_LEVEL: "warn"
```

**Deploy to different namespaces:**
```bash
kubectl apply -f configmap-dev.yaml -n development
kubectl apply -f configmap-prod.yaml -n production
```

### Complete Example: Web Application

```yaml
# nginx-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config
data:
  nginx.conf: |
    server {
      listen 80;
      server_name _;
      
      location / {
        root /usr/share/nginx/html;
        index index.html;
      }
      
      location /api {
        proxy_pass http://api-service:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
      }
    }

---
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  DATABASE_URL: "postgresql://db:5432/myapp"
  REDIS_URL: "redis://cache:6379"
  LOG_LEVEL: "info"
  MAX_WORKERS: "4"

---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:alpine
        ports:
        - containerPort: 80
        volumeMounts:
        - name: nginx-config
          mountPath: /etc/nginx/conf.d
          readOnly: true
      - name: app
        image: myapp:latest
        envFrom:
        - configMapRef:
            name: app-config
        env:
        - name: POD_NAME
          valueFrom:
            fieldRef:
              fieldPath: metadata.name
      volumes:
      - name: nginx-config
        configMap:
          name: nginx-config
```

### Checking ConfigMaps

```bash
# List ConfigMaps
kubectl get configmaps

# Describe ConfigMap
kubectl describe configmap app-config

# View ConfigMap data
kubectl get configmap app-config -o yaml

# Check which pods use ConfigMap
kubectl get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.volumes[*].configMap.name}{"\n"}{end}'
```

### Advanced Patterns

**Subpath mounting (preserve existing files):**
```yaml
volumeMounts:
- name: config
  mountPath: /etc/nginx/nginx.conf
  subPath: nginx.conf  # Mount single file
  readOnly: true
```

**ConfigMap with binary data:**
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: binary-config
binaryData:
  logo.png: <base64-encoded-binary>
data:
  text-file.txt: "text content"
```

**Multiple ConfigMaps in one pod:**
```yaml
spec:
  containers:
  - name: app
    envFrom:
    - configMapRef:
        name: app-config
    - configMapRef:
        name: feature-flags
    volumeMounts:
    - name: nginx-config
      mountPath: /etc/nginx
    - name: app-settings
      mountPath: /app/config
  volumes:
  - name: nginx-config
    configMap:
      name: nginx-config
  - name: app-settings
    configMap:
      name: app-settings
```

**Optional ConfigMap (won't fail if missing):**
```yaml
envFrom:
- configMapRef:
    name: optional-config
    optional: true

volumes:
- name: optional-volume
  configMap:
    name: optional-config
    optional: true
```

**Default values with ConfigMap:**
```yaml
env:
- name: LOG_LEVEL
  valueFrom:
    configMapKeyRef:
      name: app-config
      key: LOG_LEVEL
      optional: true
- name: LOG_LEVEL
  value: "info"  # Default if not in ConfigMap
```

### ConfigMap Size Limits

**Limits:**
```
Maximum size: 1 MiB (1,048,576 bytes)
Etcd limit: 1.5 MiB per object
Practical limit: Keep under 1 MiB
```

**Check size:**
```bash
kubectl get configmap app-config -o yaml | wc -c
```

**For large configs:**
```
Option 1: Split into multiple ConfigMaps
Option 2: Use external config server
Option 3: Mount from external storage
```

### ConfigMap Generators (Kustomize)

**kustomization.yaml:**
```yaml
configMapGenerator:
- name: app-config
  literals:
  - APP_ENV=production
  - LOG_LEVEL=info
  files:
  - config.json
  - database.properties
```

**Generate:**
```bash
kustomize build . | kubectl apply -f -
```

**Benefits:**
- Automatic hash suffix (triggers pod restart)
- Easier to manage multiple environments

### Reloading Applications

**Strategy 1: Rolling restart:**
```bash
kubectl patch configmap app-config -p '{"data":{"LOG_LEVEL":"debug"}}'
kubectl rollout restart deployment api
```

**Strategy 2: Watch files (application-level):**
```go
// Application watches /etc/config/app.conf
watcher.Watch("/etc/config")
// Reload on change
```

**Strategy 3: Reloader controller:**
```bash
# Install Reloader
kubectl apply -f https://raw.githubusercontent.com/stakater/Reloader/master/deployments/kubernetes/reloader.yaml

# Annotate deployment
annotations:
  reloader.stakater.com/auto: "true"
```

**Strategy 4: Versioned ConfigMaps:**
```yaml
# app-config-v1, app-config-v2, etc.
configMapRef:
  name: app-config-v2
```

### Best Practices

**1. Use meaningful names:**
```yaml
metadata:
  name: api-config-v1  # Good
  # Not: config1
```

**2. Add labels and annotations:**
```yaml
metadata:
  labels:
    app: web
    version: v1.0
    environment: production
  annotations:
    description: "Web application configuration"
    owner: "platform-team"
```

**3. One ConfigMap per component:**
```bash
# Good
kubectl create configmap web-config ...
kubectl create configmap api-config ...

# Not one giant ConfigMap for everything
```

**4. Use namespaces for environments:**
```bash
kubectl apply -f config.yaml -n production
kubectl apply -f config.yaml -n staging
```

**5. Version your ConfigMaps:**
```yaml
metadata:
  name: app-config-v2  # Include version
```

Update deployment to use new version:
```yaml
configMapRef:
  name: app-config-v2
```

**6. Validate before applying:**
```bash
kubectl apply -f config.yaml --dry-run=client
kubectl diff -f config.yaml
```

**7. Use volume mounts for files:**
```yaml
# Good for config files
volumeMounts:
- name: config
  mountPath: /etc/app/

# Use env vars for simple values
env:
- name: LOG_LEVEL
  value: info
```

**8. Keep size under 1 MiB:**
```bash
# Split large configs
kubectl create configmap part1 --from-file=part1/
kubectl create configmap part2 --from-file=part2/
```

**9. Use immutable for production:**
```yaml
immutable: true
```

**10. Document changes:**
```yaml
annotations:
  change-cause: "Updated API endpoint for production"
  changed-by: "john@example.com"
  changed-at: "2026-02-10T10:00:00Z"
```

### Troubleshooting

**ConfigMap not found:**
```bash
# Check ConfigMap exists
kubectl get configmap app-config

# Check namespace
kubectl get configmap app-config -n production

# Check pod events
kubectl describe pod <pod-name>
```

**Changes not reflected:**
```bash
# For env vars, restart pods
kubectl rollout restart deployment web

# For volumes, wait ~1 minute or force pod restart
kubectl delete pod <pod-name>
```

**Pod fails to start:**
```bash
# Check required key exists
kubectl get configmap app-config -o yaml

# Check optional keys
env:
- name: OPTIONAL_VAR
  valueFrom:
    configMapKeyRef:
      name: app-config
      key: OPTIONAL_KEY
      optional: true  # Won't fail if missing
```
