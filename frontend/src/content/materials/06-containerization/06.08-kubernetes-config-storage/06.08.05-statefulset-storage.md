---

## Introduction

StatefulSets manage stateful applications that require stable network identities and persistent storage. Unlike Deployments where pods are interchangeable, StatefulSet pods have unique identities that persist across rescheduling. The volumeClaimTemplates feature automatically creates a dedicated PersistentVolumeClaim for each pod, ensuring data persists independently for each instance.

## Key Concepts Summary

### StatefulSet vs Deployment

**Deployment:**
```
Pod names: random (web-7f4d6-abc12)
Networking: service load balances
Storage: shared PVC (if any)
Use: Stateless apps (web servers)
```

**StatefulSet:**
```
Pod names: ordered (web-0, web-1, web-2)
Networking: stable DNS per pod
Storage: unique PVC per pod
Use: Stateful apps (databases)
```

### StatefulSet Guarantees

**Stable network identity:**
```
web-0.web.default.svc.cluster.local
web-1.web.default.svc.cluster.local
web-2.web.default.svc.cluster.local
```

**Stable storage:**
```
web-0 → pvc-web-0 (persists even if pod deleted)
web-1 → pvc-web-1
web-2 → pvc-web-2
```

**Ordered operations:**
```
Creation: 0 → 1 → 2 (sequential)
Deletion: 2 → 1 → 0 (reverse)
Updates: 2 → 1 → 0 (reverse)
```

### Basic StatefulSet with volumeClaimTemplates

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx
  labels:
    app: nginx
spec:
  clusterIP: None  # Headless service!
  selector:
    app: nginx
  ports:
  - port: 80
    name: web

---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: web
spec:
  serviceName: nginx  # Must match headless service
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:alpine
        ports:
        - containerPort: 80
          name: web
        volumeMounts:
        - name: www
          mountPath: /usr/share/nginx/html
  volumeClaimTemplates:
  - metadata:
      name: www
    spec:
      accessModes:
      - ReadWriteOnce
      storageClassName: fast
      resources:
        requests:
          storage: 1Gi
```

**Result:**
```bash
kubectl apply -f statefulset.yaml

# Pods created in order
kubectl get pods
# NAME    READY   STATUS
# web-0   1/1     Running
# web-1   1/1     Running
# web-2   1/1     Running

# PVCs created automatically!
kubectl get pvc
# NAME        STATUS   VOLUME
# www-web-0   Bound    pvc-abc123...
# www-web-1   Bound    pvc-def456...
# www-web-2   Bound    pvc-ghi789...
```

### Headless Service

**Required for StatefulSet:**
```yaml
apiVersion: v1
kind: Service

  name: mysql
```

**DNS entries:**

```bash
mysql-0.mysql.default.svc.cluster.local
```

### Complete MySQL Example

```yaml
# mysql-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: mysql-config
data:
  my.cnf: |
    [mysqld]
    default_authentication_plugin=mysql_native_password
    bind-address=0.0.0.0
    max_connections=1000

---
# mysql-secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: mysql-secret
type: Opaque
stringData:
  root-password: MySecureRootPassword123!
  user-password: MySecureUserPassword123!

---
# mysql-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: mysql
  labels:
    app: mysql
spec:
  clusterIP: None
  selector:
    app: mysql
  ports:
  - name: mysql
    port: 3306
    targetPort: 3306

---
# mysql-statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
      - name: mysql
        image: mysql:8.0
        ports:
        - containerPort: 3306
          name: mysql
        env:
        - name: MYSQL_ROOT_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-secret
              key: root-password
        - name: MYSQL_DATABASE
          value: myapp
        - name: MYSQL_USER
          value: appuser
        - name: MYSQL_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-secret
              key: user-password
        volumeMounts:
        - name: data
          mountPath: /var/lib/mysql
        - name: config
          mountPath: /etc/mysql/conf.d
      volumes:
      - name: config
        configMap:
          name: mysql-config
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes:
      - ReadWriteOnce
      storageClassName: fast
      resources:
        requests:
          storage: 10Gi
```

**Deploy:**
```bash
kubectl apply -f mysql-configmap.yaml
kubectl apply -f mysql-secret.yaml
kubectl apply -f mysql-service.yaml
kubectl apply -f mysql-statefulset.yaml

# Watch pods start in order
kubectl get pods -w

# Check PVCs
kubectl get pvc
```

**Connect:**
```bash
# From another pod
kubectl run mysql-client --rm -it --image=mysql:8.0 -- bash
mysql -h mysql-0.mysql -u appuser -p

# Or connect to service (load balances)
mysql -h mysql -u appuser -p
```

### Scaling StatefulSets

**Scale up:**
```bash
kubectl scale statefulset mysql --replicas=5

# Pods created in order
# mysql-3, then mysql-4
```

**Scale down:**
```bash
kubectl scale statefulset mysql --replicas=2

# Pods deleted in reverse
# mysql-4, then mysql-3
```

**⚠️ PVCs are NOT deleted:**
```bash
kubectl get pvc
# PVCs for mysql-3 and mysql-4 still exist!

# Scale back up
kubectl scale statefulset mysql --replicas=5
# mysql-3 and mysql-4 reattach to existing PVCs
```

### Updating StatefulSets

**Update strategy:**
```yaml
spec:
  updateStrategy:
    type: RollingUpdate  # Default
    rollingUpdate:
      partition: 0  # Update all pods
```

**Rolling update (reverse order):**
```bash
kubectl set image statefulset/mysql mysql=mysql:8.1

# Updates in reverse
# mysql-2 → mysql-1 → mysql-0
```

**Partitioned update:**
```yaml
spec:
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      partition: 2  # Only update pods >= 2
```

```bash
# Only mysql-2 updated
# mysql-0 and mysql-1 remain on old version
```

**OnDelete strategy:**
```yaml
spec:
  updateStrategy:
    type: OnDelete
```

Manual control:
```bash
kubectl delete pod mysql-0  # Gets new version
kubectl delete pod mysql-1  # Gets new version
# etc.
```

### Pod Management Policies

**OrderedReady (default):**
```yaml
spec:
  podManagementPolicy: OrderedReady
```
- Sequential startup/shutdown
- Wait for each pod to be ready

**Parallel:**
```yaml
spec:
  podManagementPolicy: Parallel
```
- Start all pods simultaneously
- Faster startup
- Use for stateless apps in StatefulSet

### Deleting StatefulSets

**Delete StatefulSet but keep pods:**
```bash
kubectl delete statefulset mysql --cascade=orphan
```

**Delete StatefulSet and pods:**
```bash
kubectl delete statefulset mysql
```

**⚠️ PVCs are never automatically deleted:**
```bash
# Must delete manually
kubectl delete pvc -l app=mysql
```

### PostgreSQL Example

```yaml
apiVersion: v1
kind: Service
metadata:
  name: postgres
spec:
  clusterIP: None
  selector:
    app: postgres
  ports:
  - port: 5432

---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres
spec:
  serviceName: postgres
  replicas: 1
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres
    spec:
      containers:
      - name: postgres
        image: postgres:15-alpine
        ports:
        - containerPort: 5432
        env:
        - name: POSTGRES_DB
          value: myapp
        - name: POSTGRES_USER
          value: appuser
        - name: POSTGRES_PASSWORD
          valueFrom:
            secretKeyRef:
              name: postgres-secret
              key: password
        - name: PGDATA
          value: /var/lib/postgresql/data/pgdata
        volumeMounts:
        - name: data
          mountPath: /var/lib/postgresql/data
        livenessProbe:
          exec:
            command:
            - pg_isready
            - -U
            - appuser
          initialDelaySeconds: 30
          periodSeconds: 10
        readinessProbe:
          exec:
            command:
            - pg_isready
            - -U
            - appuser
          initialDelaySeconds: 5
          periodSeconds: 5
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes:
      - ReadWriteOnce
      storageClassName: fast
      resources:
        requests:
          storage: 20Gi
```

### Troubleshooting

**Pod stuck in Pending:**
```bash
kubectl describe pod mysql-0

# Common issues:
# - PVC not bound (no StorageClass/PV)
# - Node has no space
# - Pod affinity issues
```

**PVC not created:**
```bash
kubectl describe statefulset mysql

# Check:
# - StorageClass exists
# - volumeClaimTemplates syntax
```

**Data not persisting:**
```bash
# Verify PVC bound
kubectl get pvc

# Check volume mount
kubectl describe pod mysql-0

# Verify data path
kubectl exec mysql-0 -- ls -la /var/lib/mysql
```

**Can't connect to pod:**
```bash
# Verify headless service
kubectl get svc mysql

# Test DNS
kubectl run test --rm -it --image=busybox -- nslookup mysql-0.mysql

# Check pod readiness
kubectl get pods
```

### Best Practices

**1. Always use headless service:**
```yaml
spec:
  clusterIP: None
```

**2. Set appropriate storage:**
```yaml
resources:
  requests:
    storage: 20Gi  # Based on needs
```

**3. Use fast StorageClass:**
```yaml
storageClassName: fast-ssd
```

**4. Add health checks:**
```yaml
livenessProbe:
  exec:
    command: [...]
readinessProbe:
  exec:
    command: [...]
```

**5. Configure resource limits:**
```yaml
resources:
  requests:
    memory: "1Gi"
    cpu: "500m"
  limits:
    memory: "2Gi"
    cpu: "1000m"
```

**6. Use Init Containers for setup:**
```yaml
initContainers:
- name: init-db
  image: busybox
  command: ["sh", "-c", "chown -R 999:999 /data"]
  volumeMounts:
  - name: data
    mountPath: /data
```

**7. Plan for backups:**
```bash
kubectl exec mysql-0 -- mysqldump ... > backup.sql
```

**8. Monitor storage usage:**
```bash
kubectl exec mysql-0 -- df -h /var/lib/mysql
```
