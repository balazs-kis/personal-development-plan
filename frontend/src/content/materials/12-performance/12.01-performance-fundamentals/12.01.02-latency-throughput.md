## Introduction

Latency and throughput are the two fundamental performance metrics, but they measure different things and sometimes conflict with each other. Understanding when each matters and how to optimize for the right metric is crucial for effective performance engineering.

## Key Concepts Summary

### Latency: How Long

**Definition:** Latency is the time it takes to complete a single operation, measured from start to finish.

**Units:** Milliseconds (ms), microseconds (μs), or seconds (s)

**User impact:** Directly affects perceived responsiveness. High latency = slow, frustrating experience.

**Examples:**
```csharp
// Measuring latency
var stopwatch = Stopwatch.StartNew();
var result = await ProcessRequestAsync(request);
stopwatch.Stop();

var latencyMs = stopwatch.ElapsedMilliseconds;
// Latency: 127ms
```

**Real-world latencies:**
```
Reading from L1 cache: 0.5ns
Reading from RAM: 100ns
SSD read: 150μs
Network round-trip (same datacenter): 0.5ms
Database query: 1-50ms
API call to external service: 50-500ms
```

### Throughput: How Many

**Definition:** Throughput is the number of operations completed per unit of time.

**Units:** Requests per second (RPS), transactions per second (TPS), megabits per second (Mbps)

**System impact:** Determines capacity and scalability. Low throughput = can't handle load.

**Examples:**
```csharp
// Measuring throughput
var requestCount = 0;
var stopwatch = Stopwatch.StartNew();

for (int i = 0; i < 10000; i++)
{
    await ProcessRequestAsync(requests[i]);
    requestCount++;
}

stopwatch.Stop();
var throughput = requestCount / stopwatch.Elapsed.TotalSeconds;
// Throughput: 847 requests/second
```

### The Relationship

**They're related but different:**
```
Latency = Time per operation
Throughput = Operations per time

Ideal scenario:
- Low latency (fast individual operations)
- High throughput (many operations per second)

Reality:
- Often trade-offs between the two
```

**Example:**
```csharp
// Low latency, low throughput (synchronous processing)
public async Task<Result> ProcessSync(Request request)
{
    // Each request: 10ms latency
    // Throughput: 100 requests/second (1 request at a time)
    return await ProcessSingleRequest(request);
}

// Higher latency, high throughput (batch processing)
public async Task<List<Result>> ProcessBatch(List<Request> requests)
{
    // Batch of 100 requests: 200ms latency
    // But throughput: 500 requests/second (100 requests / 0.2s)
    return await ProcessRequestsBatch(requests);
}
```

## When to Optimize for Each

### Optimize for Latency When:

**1. User-Facing Operations**
```csharp
// Web API endpoints
[HttpGet("products/{id}")]
public async Task<ActionResult<Product>> GetProduct(int id)
{
    // Users notice every millisecond
    // Target: p95 < 200ms
    var product = await _cache.GetOrCreateAsync(
        $"product:{id}",
        async entry =>
        {
            entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
            return await _db.Products.FindAsync(id);
        });
    
    return Ok(product);
}
```

**2. Real-Time Systems**
```csharp
// Trading platform
public async Task<OrderResult> PlaceOrder(Order order)
{
    // Every millisecond of latency costs money
    // Target: p99 < 5ms
    return await _orderBook.ExecuteOrder(order);
}
```

**3. Interactive Features**
```csharp
// Auto-complete search
public async Task<List<string>> SearchSuggestions(string query)
{
    // Users type and expect immediate results
    // Target: p95 < 50ms
    return await _searchIndex.FindMatches(query, limit: 10);
}
```

### Optimize for Throughput When:

**1. Batch Processing**
```csharp
// Email notification system
public async Task SendDailyDigests()
{
    // Individual email latency doesn't matter
    // Total throughput determines completion time
    // Target: 10,000 emails/minute
    
    var users = await _db.Users.Where(u => u.ReceivesDigests).ToListAsync();
    
    await Parallel.ForEachAsync(
        users.Chunk(100),
        new ParallelOptions { MaxDegreeOfParallelism = 10 },
        async (batch, ct) =>
        {
            await _emailService.SendBatchAsync(batch, ct);
        });
}
```

**2. Data Processing Pipelines**
```csharp
// Log processing
public async Task ProcessLogs(Stream logStream)
{
    // Process millions of records efficiently
    // Target: 100,000 records/second
    
    await foreach (var batch in ReadBatches(logStream, batchSize: 1000))
    {
        await _processor.ProcessBatchAsync(batch);
    }
}
```

**3. High-Volume APIs**
```csharp
// Webhook endpoint
[HttpPost("webhooks/events")]
public async Task<IActionResult> ReceiveEvent(Event eventData)
{
    // Receive thousands of events per second
    // Individual latency less critical than overall capacity
    // Target: 5,000 events/second
    
    await _queue.EnqueueAsync(eventData);
    return Accepted();  // Fast response, process async
}
```

## Measuring Latency in .NET

### Application Insights / OpenTelemetry

```csharp
using var activity = ActivitySource.StartActivity("ProcessOrder");
activity?.SetTag("order.id", orderId);

var stopwatch = Stopwatch.StartNew();
try
{
    var result = await _orderService.ProcessAsync(orderId);
    
    stopwatch.Stop();
    activity?.SetTag("latency.ms", stopwatch.ElapsedMilliseconds);
    activity?.SetTag("status", "success");
    
    return result;
}
catch (Exception ex)
{
    stopwatch.Stop();
    activity?.SetTag("latency.ms", stopwatch.ElapsedMilliseconds);
    activity?.SetTag("status", "error");
    activity?.SetTag("error.message", ex.Message);
    throw;
}
```

### Custom Middleware for Request Latency

```csharp
public class LatencyMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<LatencyMiddleware> _logger;

    public LatencyMiddleware(RequestDelegate next, ILogger<LatencyMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        var stopwatch = Stopwatch.StartNew();
        
        try
        {
            await _next(context);
        }
        finally
        {
            stopwatch.Stop();
            
            _logger.LogInformation(
                "Request {Method} {Path} completed in {LatencyMs}ms with status {StatusCode}",
                context.Request.Method,
                context.Request.Path,
                stopwatch.ElapsedMilliseconds,
                context.Response.StatusCode);
        }
    }
}
```

### Histogram Metrics

```csharp
using System.Diagnostics.Metrics;

public class PerformanceMetrics
{
    private readonly Meter _meter;
    private readonly Histogram<double> _requestLatency;

    public PerformanceMetrics(IMeterFactory meterFactory)
    {
        _meter = meterFactory.Create("MyApp.Performance");
        
        _requestLatency = _meter.CreateHistogram<double>(
            "request.latency",
            unit: "ms",
            description: "Request latency in milliseconds");
    }

    public void RecordLatency(double latencyMs, string endpoint, string method)
    {
        _requestLatency.Record(
            latencyMs,
            new KeyValuePair<string, object?>("endpoint", endpoint),
            new KeyValuePair<string, object?>("method", method));
    }
}
```

## Measuring Throughput in .NET

### Basic Throughput Counter

```csharp
public class ThroughputMonitor
{
    private readonly Counter<long> _requestCounter;
    private long _totalRequests;
    private readonly Stopwatch _stopwatch = Stopwatch.StartNew();

    public ThroughputMonitor(IMeterFactory meterFactory)
    {
        var meter = meterFactory.Create("MyApp.Performance");
        _requestCounter = meter.CreateCounter<long>(
            "requests.processed",
            unit: "requests",
            description: "Total requests processed");
    }

    public void RecordRequest()
    {
        Interlocked.Increment(ref _totalRequests);
        _requestCounter.Add(1);
    }

    public double GetThroughput()
    {
        return _totalRequests / _stopwatch.Elapsed.TotalSeconds;
    }
}
```

## The Trade-offs

### Batching: Higher Throughput, Higher Latency

```csharp
// Low latency, low throughput (individual processing)
public async Task<Result> ProcessIndividual(Item item)
{
    // Latency: 10ms per item
    // Throughput: 100 items/second
    await _database.SaveAsync(item);
    return Result.Success;
}

// Higher latency, higher throughput (batch processing)
public async Task<List<Result>> ProcessBatch(List<Item> items)
{
    // Latency: 100ms for 50 items (50ms per item on average)
    // But throughput: 500 items/second
    await _database.SaveManyAsync(items);
    return items.Select(_ => Result.Success).ToList();
}
```

**When to use batching:**
- Background jobs
- Data imports
- Bulk operations
- Offline processing

**When to avoid batching:**
- User-facing operations
- Real-time systems
- When individual latency matters

### Concurrency: Higher Throughput, Resource Costs

```csharp
// Sequential: Low throughput, predictable latency
public async Task<List<Result>> ProcessSequential(List<Request> requests)
{
    var results = new List<Result>();
    foreach (var request in requests)
    {
        results.Add(await ProcessAsync(request));
    }
    return results;
    // Total time: 100 requests × 50ms = 5 seconds
    // Throughput: 20 requests/second
}

// Parallel: High throughput, higher resource usage
public async Task<List<Result>> ProcessParallel(List<Request> requests)
{
    var tasks = requests.Select(ProcessAsync);
    return (await Task.WhenAll(tasks)).ToList();
    // Total time: ~50ms (all at once)
    // Throughput: 2000 requests/second
    // But: Higher CPU, memory, and connection usage
}
```

### Caching: Lower Latency, Stale Data Risk

```csharp
// Without cache: Higher latency, always fresh
public async Task<Product> GetProduct(int id)
{
    return await _db.Products.FindAsync(id);
    // Latency: 15ms
}

// With cache: Lower latency, potentially stale
public async Task<Product> GetProductCached(int id)
{
    return await _cache.GetOrCreateAsync(
        $"product:{id}",
        async entry =>
        {
            entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
            return await _db.Products.FindAsync(id);
        });
    // Latency: 0.5ms (cache hit)
    // But: Data could be up to 5 minutes stale
}
```

## Common Patterns

### Pattern 1: Optimize Critical Path Latency

```csharp
public class CheckoutService
{
    // Identify hot path
    public async Task<CheckoutResult> ProcessCheckout(Cart cart)
    {
        // Critical: Must be fast
        var validation = await ValidateCart(cart);  // 5ms
        var payment = await ProcessPayment(cart);   // 100ms
        var order = await CreateOrder(cart);        // 20ms
        
        // Non-critical: Can be async
        _ = Task.Run(async () =>
        {
            await SendConfirmationEmail(order);     // 500ms - don't wait
            await UpdateAnalytics(order);           // 200ms - don't wait
            await NotifyInventory(order);           // 100ms - don't wait
        });
        
        return new CheckoutResult { OrderId = order.Id };
        // User sees result in ~125ms instead of ~925ms
    }
}
```

### Pattern 2: Maximize Throughput with Queues

```csharp
public class EventProcessor
{
    private readonly Channel<Event> _channel = Channel.CreateUnbounded<Event>();

    // Fast ingestion (high throughput)
    public async Task<bool> EnqueueEvent(Event evt)
    {
        await _channel.Writer.WriteAsync(evt);
        return true;  // Latency: <1ms
        // Throughput: 50,000+ events/second
    }

    // Process asynchronously
    public async Task ProcessEvents(CancellationToken ct)
    {
        await foreach (var evt in _channel.Reader.ReadAllAsync(ct))
        {
            await ProcessSingleEvent(evt);  // Can be slower
        }
    }
}
```

### Pattern 3: Balance with Connection Pooling

```csharp
// Connection pool manages throughput vs resource usage
public class DatabaseConfig
{
    public void ConfigureDbContext(DbContextOptionsBuilder options)
    {
        options.UseSqlServer(connectionString, sqlOptions =>
        {
            // Balance throughput with connection limits
            sqlOptions.MaxBatchSize(100);  // Higher throughput per batch
            
            // Pool size affects max concurrent operations
            // Too small: Limits throughput
            // Too large: Resource exhaustion
        });
    }
}
```

## Practical Guidelines

### For Latency-Sensitive Applications:

1. **Measure p95 and p99**, not averages
2. **Optimize hot paths** (code executed frequently)
3. **Cache aggressively** for read-heavy workloads
4. **Use async/await** properly (don't block)
5. **Reduce allocations** in hot paths
6. **Connection pooling** for external resources

### For Throughput-Sensitive Applications:

1. **Batch operations** when possible
2. **Parallel processing** with appropriate limits
3. **Queue-based architectures** for decoupling
4. **Optimize for sustained load**, not peak latency
5. **Monitor resource utilization** (CPU, memory, connections)
6. **Horizontal scaling** for more capacity

## Summary

Latency measures how fast individual operations complete (important for user experience), while throughput measures how many operations you can handle (important for capacity). They often trade off against each other—optimizing one can hurt the other. Choose your optimization target based on your specific use case: latency for user-facing features, throughput for background processing and high-volume systems.
