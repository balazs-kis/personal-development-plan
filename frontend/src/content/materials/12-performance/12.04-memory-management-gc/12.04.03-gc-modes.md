# Lesson 3: GC Modes (Workstation vs Server)

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand the differences between Workstation and Server GC
- Choose the appropriate GC mode for your application
- Configure GC mode via runtime configuration
- Understand background vs non-concurrent GC
- Optimize GC settings for your workload

---

## Introduction

.NET provides two GC modes optimized for different scenarios: Workstation GC for client apps with short GC pauses, and Server GC for server apps prioritizing throughput. Choosing the right mode significantly impacts application performance.

## Key Concepts Summary

### Workstation vs Server GC

**Workstation GC:**
```csharp
// Optimized for:
// - Client applications (desktop, mobile)
// - Low latency (short GC pauses)
// - Single-threaded or few threads
// - Interactive applications

// Characteristics:
// - Runs on user thread that triggered GC
// - Normal thread priority
// - Competes with other threads for CPU
// - More frequent but shorter pauses
// - Lower memory consumption
```

**Server GC:**
```csharp
// Optimized for:
// - Server applications (web servers, APIs)
// - High throughput
// - Multi-threaded applications
// - Background processing

// Characteristics:
// - Dedicated GC threads (one per logical CPU)
// - Highest thread priority
// - Multiple heaps (one per CPU)
// - Longer pauses but higher throughput
// - Higher memory consumption
```

### Performance Comparison

```
┌─────────────────┬──────────────────┬──────────────────┐
│   Metric        │  Workstation GC  │    Server GC     │
├─────────────────┼──────────────────┼──────────────────┤
│ Pause Time      │ Shorter (~10ms)  │ Longer (~50ms)   │
│ Throughput      │ Lower            │ Higher           │
│ Memory Usage    │ Lower            │ Higher           │
│ CPU Usage       │ Lower            │ Higher (dedicated│
│                 │                  │ GC threads)      │
│ Heaps           │ Single           │ One per CPU      │
│ Thread Priority │ Normal           │ Highest          │
│ Best For        │ Client apps      │ Server apps      │
└─────────────────┴──────────────────┴──────────────────┘
```

### Configuring GC Mode

**Project File Configuration:**

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <!-- Use Server GC -->
    <ServerGarbageCollection>true</ServerGarbageCollection>
    
    <!-- Enable concurrent (background) GC -->
    <ConcurrentGarbageCollection>true</ConcurrentGarbageCollection>
    
    <!-- Optional: Retain VM -->
    <RetainVMGarbageCollection>true</RetainVMGarbageCollection>
  </PropertyGroup>
</Project>
```

**Runtime Configuration (runtimeconfig.json):**

```json
{
  "runtimeOptions": {
    "configProperties": {
      "System.GC.Server": true,
      "System.GC.Concurrent": true,
      "System.GC.RetainVM": true
    }
  }
}
```

**Environment Variables:**

```bash
# Windows
set COMPLUS_gcServer=1
set COMPLUS_gcConcurrent=1

# Linux/Mac
export COMPLUS_gcServer=1
export COMPLUS_gcConcurrent=1
```

### Background (Concurrent) GC

**Background GC (.NET 4+):**

```csharp
// Allows managed threads to continue during GC
// Replaces "Concurrent GC" from earlier versions

public void UnderstandBackgroundGC()
{
    // Without background GC:
    // Thread 1: [Working] → [Paused for GC] → [Working]
    // Thread 2: [Working] → [Paused for GC] → [Working]
    
    // With background GC:
    // Thread 1: [Working continuously........................]
    // Thread 2: [Working continuously........................]
    // GC Thread: [---------- Collection happens in background]
    
    // Benefits:
    // - Lower pause times
    // - Better responsiveness
    // - Slight overhead from coordination
}

// Configure in project file
// <ConcurrentGarbageCollection>true</ConcurrentGarbageCollection>
```

**When GC Must Pause All Threads:**

```csharp
public void ForegroundGCScenarios()
{
    // Even with background GC, some operations require pausing:
    
    // 1. Gen 0/Gen 1 collections (ephemeral GCs)
    //    - Always foreground (fast, so acceptable)
    
    // 2. Foreground Gen 2 GC
    //    - When Gen 0 allocation fills up during background GC
    //    - When background GC can't keep up
    
    // 3. LOH allocations during background Gen 2 GC
    //    - May trigger foreground GC
}
```

### GC Latency Modes

```csharp
public class LatencyModes
{
    public void DemonstrateLatencyModes()
    {
        // Default: Interactive (balance latency and throughput)
        Console.WriteLine($"Default: {GCSettings.LatencyMode}");
        
        // LowLatency: Suppress Gen 2 GCs temporarily
        GCSettings.LatencyMode = GCLatencyMode.LowLatency;
        DoShortCriticalWork();  // No Gen 2 GCs during this
        GCSettings.LatencyMode = GCLatencyMode.Interactive;  // Restore
        
        // SustainedLowLatency: Longer low-latency period
        GCSettings.LatencyMode = GCLatencyMode.SustainedLowLatency;
        DoLongCriticalWork();  // Background Gen 2 only
        GCSettings.LatencyMode = GCLatencyMode.Interactive;
        
        // Batch: Disable concurrent GC for max throughput
        GCSettings.LatencyMode = GCLatencyMode.Batch;
        ProcessLargeBatch();  // Maximize throughput
        GCSettings.LatencyMode = GCLatencyMode.Interactive;
    }
    
    private void DoShortCriticalWork() { /* ... */ }
    private void DoLongCriticalWork() { /* ... */ }
    private void ProcessLargeBatch() { /* ... */ }
}
```

### Workstation GC in Detail

```csharp
public class WorkstationGCBehavior
{
    // Single heap for all threads
    // Collection triggered by user thread
    
    public void SimulateWorkstationGC()
    {
        // Thread allocates objects
        var obj1 = new MyObject();  // User thread
        var obj2 = new MyObject();  // User thread
        
        // Gen 0 full → User thread performs GC
        // [User thread paused for GC]
        // Other threads wait for GC to complete
        
        // GC completes, user thread resumes
        var obj3 = new MyObject();
    }
    
    // Best for:
    // - Desktop applications
    // - Applications with few threads
    // - When pause time matters more than throughput
    // - Lower memory budget
}
```

### Server GC in Detail

```csharp
public class ServerGCBehavior
{
    // Multiple heaps (one per logical CPU)
    // Dedicated GC threads at highest priority
    
    public void SimulateServerGC()
    {
        // 4 CPUs → 4 heaps → 4 GC threads
        
        // Thread 1 allocates on Heap 1
        // Thread 2 allocates on Heap 2
        // Thread 3 allocates on Heap 3
        // Thread 4 allocates on Heap 4
        
        // GC triggered:
        // [All user threads pause]
        // GC Thread 1 collects Heap 1 (parallel)
        // GC Thread 2 collects Heap 2 (parallel)
        // GC Thread 3 collects Heap 3 (parallel)
        // GC Thread 4 collects Heap 4 (parallel)
        // [All user threads resume]
        
        // Faster collection, but longer pause
    }
    
    // Best for:
    // - Web servers (ASP.NET Core)
    // - API services
    // - Background processing services
    // - Multi-threaded server applications
}
```

### Choosing the Right GC Mode

```csharp
public class GCModeSelector
{
    public void DecideGCMode()
    {
        // Use Workstation GC when:
        // ✅ Desktop/client application
        // ✅ Interactive UI
        // ✅ Pause time critical (<10ms pauses needed)
        // ✅ Single-threaded or few threads
        // ✅ Limited memory available
        
        // Use Server GC when:
        // ✅ Server application (web, API)
        // ✅ High throughput needed
        // ✅ Multi-threaded workload
        // ✅ Plenty of memory available
        // ✅ Multiple CPUs available
        // ✅ Can tolerate longer pauses (50-100ms)
    }
}
```

### Measuring GC Impact

```csharp
public class GCPerformanceMeasurement
{
    public void CompareGCModes()
    {
        // Measure with Workstation GC
        MeasureWorkload("Workstation");
        
        // Switch to Server GC (requires app restart)
        // Configure in project file and rebuild
        
        // Measure with Server GC
        MeasureWorkload("Server");
    }
    
    private void MeasureWorkload(string mode)
    {
        var sw = Stopwatch.StartNew();
        int gen0Before = GC.CollectionCount(0);
        int gen1Before = GC.CollectionCount(1);
        int gen2Before = GC.CollectionCount(2);
        
        // Run workload
        ExecuteWorkload();
        
        sw.Stop();
        
        Console.WriteLine($"Mode: {mode}");
        Console.WriteLine($"Time: {sw.ElapsedMilliseconds}ms");
        Console.WriteLine($"Gen 0 GCs: {GC.CollectionCount(0) - gen0Before}");
        Console.WriteLine($"Gen 1 GCs: {GC.CollectionCount(1) - gen1Before}");
        Console.WriteLine($"Gen 2 GCs: {GC.CollectionCount(2) - gen2Before}");
        Console.WriteLine($"Total memory: {GC.GetTotalMemory(false):N0}");
        Console.WriteLine();
    }
    
    private void ExecuteWorkload()
    {
        // Simulate workload
        var data = new List<byte[]>();
        for (int i = 0; i < 10000; i++)
        {
            data.Add(new byte[1024]);
        }
    }
}
```

### Advanced Configuration

**Heap Count (Server GC):**

```xml
<!-- Limit number of heaps in Server GC -->
<PropertyGroup>
  <ServerGarbageCollection>true</ServerGarbageCollection>
  <!-- Limit to 4 heaps even on 8+ CPU system -->
  <GCHeapCount>4</GCHeapCount>
</PropertyGroup>
```

**Heap Affinitization:**

```xml
<!-- Pin GC threads to specific CPUs -->
<PropertyGroup>
  <ServerGarbageCollection>true</ServerGarbageCollection>
  <!-- Heaps 0xC (binary 1100, CPUs 2 and 3) -->
  <GCHeapAffinitizeMask>0xC</GCHeapAffinitizeMask>
</PropertyGroup>
```

**DATAS (Dynamic Adaptation, .NET 8+):**

```xml
<!-- Enable dynamic heap size adaptation -->
<PropertyGroup>
  <ServerGarbageCollection>true</ServerGarbageCollection>
  <!-- Server GC by default doesn't adapt heap size -->
  <!-- DATAS makes Server GC adapt like Workstation GC -->
  <!-- Default in .NET 9+ -->
</PropertyGroup>
```

## Practice Exercise

1. **Compare GC modes in a test application**:

```csharp
public class GCModeComparison
{
    public static void Main()
    {
        Console.WriteLine($"Server GC: {GCSettings.IsServerGC}");
        Console.WriteLine($"CPU Count: {Environment.ProcessorCount}");
        Console.WriteLine();
        
        // Run benchmark
        BenchmarkAllocation();
        BenchmarkThroughput();
    }
    
    private static void BenchmarkAllocation()
    {
        Console.WriteLine("=== Allocation Benchmark ===");
        var sw = Stopwatch.StartNew();
        
        for (int i = 0; i < 1_000_000; i++)
        {
            var obj = new object();
        }
        
        sw.Stop();
        Console.WriteLine($"Time: {sw.ElapsedMilliseconds}ms");
        Console.WriteLine($"Gen 0 collections: {GC.CollectionCount(0)}");
    }
    
    private static void BenchmarkThroughput()
    {
        Console.WriteLine("\n=== Throughput Benchmark ===");
        int cpuCount = Environment.ProcessorCount;
        var tasks = new Task[cpuCount];
        var sw = Stopwatch.StartNew();
        
        for (int i = 0; i < cpuCount; i++)
        {
            tasks[i] = Task.Run(() =>
            {
                for (int j = 0; j < 100_000; j++)
                {
                    var obj = new byte[1024];
                }
            });
        }
        
        Task.WaitAll(tasks);
        sw.Stop();
        
        Console.WriteLine($"Time: {sw.ElapsedMilliseconds}ms");
        Console.WriteLine($"Gen 0 collections: {GC.CollectionCount(0)}");
    }
}

// Test with different configurations:
// 1. <ServerGarbageCollection>false</ServerGarbageCollection>
// 2. <ServerGarbageCollection>true</ServerGarbageCollection>
// Compare results
```

```csharp
public class LatencyModeTest
{
    public void TestLatencyModes()
    {
        TestMode(GCLatencyMode.Interactive, "Interactive");
        TestMode(GCLatencyMode.LowLatency, "LowLatency");

    }
```

## Summary

Workstation GC optimizes for low latency with short pauses, while Server GC optimizes for high throughput with dedicated GC threads and multiple heaps. Configure GC mode via project properties or runtime configuration. Background GC allows managed threads to continue during Gen 2 collections. Use latency modes to fine-tune GC behavior for specific scenarios. Choose Workstation GC for client apps and Server GC for server applications with multiple CPUs.
