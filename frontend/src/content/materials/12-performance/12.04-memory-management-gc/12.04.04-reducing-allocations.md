## Learning Objectives

By the end of this lesson, you will be able to:
- Identify common sources of unnecessary allocations

## Introduction

Every allocation creates work for the garbage collector. Reducing allocations improves performance by minimizing GC pressure, reducing pause times, and improving cache locality. Modern .NET provides powerful tools like Span<T> and Memory<T> for zero-allocation scenarios.

## Key Concepts Summary

### Span<T>: Stack-Based Memory Access

**What is Span<T>?**

```csharp
// Span<T> is a ref struct that provides type-safe access
// to contiguous memory without allocating

public void UnderstandSpan()
{
    // Can wrap:
    // 1. Array
    int[] array = { 1, 2, 3, 4, 5 };
    Span<int> span1 = array;
    
    // 2. Stackalloc
    Span<int> span2 = stackalloc int[5];
    
    // 3. Pointer (unsafe)
    unsafe
    {
        int* ptr = stackalloc int[5];
        Span<int> span3 = new Span<int>(ptr, 5);
    }
    
    // No heap allocation for Span itself!
}
```

**Key Characteristics:**

```csharp
// Span<T> is a ref struct
public ref struct Span<T>
{
    // Cannot be:
    // - Stored in fields of non-ref-struct types
    // - Used in async methods
    // - Boxed
    // - Used as generic type argument
    
    // Can be:
    // - Passed as method parameters
    // - Returned from methods
    // - Stored in local variables
    // - Stored in other ref structs
}
```

### Span<T> vs Array

```csharp
// ❌ Traditional approach: allocates array
public int SumArray(int[] numbers)
{
    int sum = 0;
    for (int i = 0; i < numbers.Length; i++)
    {
        sum += numbers[i];
    }
    return sum;  // Array allocated on heap
}

// ✅ Span approach: no allocation
public int SumSpan(ReadOnlySpan<int> numbers)
{
    int sum = 0;
    foreach (var num in numbers)  // No allocation
    {
        sum += num;
    }
    return sum;
}

// Usage
int[] array = { 1, 2, 3, 4, 5 };
int result1 = SumArray(array);           // Heap allocation
int result2 = SumSpan(array);            // No allocation (wraps existing array)
int result3 = SumSpan(stackalloc int[5]); // No allocation (stack)
```

### Slicing Without Allocation

```csharp
// ❌ Traditional: creates new array
public int[] GetMiddleElements(int[] array)
{
    int start = array.Length / 4;
    int length = array.Length / 2;
    
    var middle = new int[length];  // ❌ Allocation!
    Array.Copy(array, start, middle, 0, length);
    return middle;
}

// ✅ Span: creates view without allocation
public ReadOnlySpan<int> GetMiddleElements(ReadOnlySpan<int> span)
{
    int start = span.Length / 4;
    int length = span.Length / 2;
    
    return span.Slice(start, length);  // ✅ No allocation!
}

// Usage
int[] data = new int[100];
var middle1 = GetMiddleElements(data);      // Allocates new array
var middle2 = GetMiddleElements(data);      // No allocation, just a view
```

### Memory<T>: Heap-Friendly Alternative

```csharp
// Memory<T> can be stored on heap (unlike Span<T>)
public class BufferManager
{
    private Memory<byte> _buffer;  // ✅ Can store as field
    
    public BufferManager(int size)
    {
        _buffer = new byte[size];  // Wraps array
    }
    
    // ✅ Can use in async methods
    public async Task<int> ProcessAsync(Stream stream)
    {
        return await stream.ReadAsync(_buffer);
        // Memory<T> works with async, Span<T> doesn't
    }
    
    // Convert to Span when needed
    public void Process()
    {
        Span<byte> span = _buffer.Span;
        // Work with Span for zero-allocation operations
    }
}
```

### String Optimization with Span

**Parsing Without Allocation:**

```csharp
// ❌ Traditional: allocates substrings
public (string, string) ParseName(string fullName)
{
    int spaceIndex = fullName.IndexOf(' ');
    string firstName = fullName.Substring(0, spaceIndex);  // ❌ Allocation
    string lastName = fullName.Substring(spaceIndex + 1);  // ❌ Allocation
    return (firstName, lastName);
}

// ✅ Span: no allocations
public (ReadOnlySpan<char>, ReadOnlySpan<char>) ParseName(ReadOnlySpan<char> fullName)
{
    int spaceIndex = fullName.IndexOf(' ');
    var firstName = fullName.Slice(0, spaceIndex);         // ✅ No allocation
    var lastName = fullName.Slice(spaceIndex + 1);         // ✅ No allocation
    return (firstName, lastName);
}

// Usage
string name = "John Doe";
var (first1, last1) = ParseName(name);              // 2 allocations
var (first2, last2) = ParseName(name.AsSpan());     // 0 allocations
```

**String Building:**

```csharp
// ❌ Bad: multiple allocations
public string FormatValue(int value)
{
    return "Value: " + value.ToString();  // Multiple allocations
}

// ✅ Better: use Span
public string FormatValue(int value)
{
    Span<char> buffer = stackalloc char[32];
    value.TryFormat(buffer, out int written);
    
    // Or use string interpolation with spans (.NET 6+)
    return $"Value: {value}";  // Optimized by compiler
}

// ✅ Best: write directly to destination
public void FormatValue(int value, Span<char> destination)
{
    "Value: ".AsSpan().CopyTo(destination);
    value.TryFormat(destination[7..], out int written);
}
```

### Struct Optimization

**Value Type Benefits:**

```csharp
// Structs don't allocate on heap (when used as locals)
public struct Point  // Value type
{
    public int X { get; set; }
    public int Y { get; set; }
    
    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }
}

public void UsePoint()
{
    Point p = new Point(10, 20);  // ✅ Stack allocation
    // No GC pressure
}

// Compare to class
public class PointClass  // Reference type
{
    public int X { get; set; }
    public int Y { get; set; }
}

public void UsePointClass()
{
    PointClass p = new PointClass { X = 10, Y = 20 };  // ❌ Heap allocation
    // Creates GC pressure
}
```

**When to Use Structs:**

```csharp
// ✅ Good candidates for structs:
// - Small (≤16 bytes recommended)
// - Immutable
// - Short-lived
// - Logically represent single value

public readonly struct Money  // ✅ Good struct
{
    public decimal Amount { get; }
    public string Currency { get; }  // ⚠️ Reference, but struct is still small
    
    public Money(decimal amount, string currency)
    {
        Amount = amount;
        Currency = currency;
    }
}

// ❌ Bad candidates for structs:
// - Large (>16 bytes)
// - Mutable
// - Long-lived
// - Contain large reference types

public struct BadStruct  // ❌ Too large
{
    public double Value1;
    public double Value2;
    public double Value3;
    public double Value4;
    public double Value5;  // 40 bytes!
}
```

### Avoiding Boxing

```csharp
// ❌ Boxing allocates
public void PrintValue(object value)  // object parameter boxes value types
{
    Console.WriteLine(value);
}

int number = 42;
PrintValue(number);  // ❌ Boxes int → allocates

// ✅ Avoid boxing with generics
public void PrintValue<T>(T value)
{
    Console.WriteLine(value);
}

PrintValue(number);  // ✅ No boxing

// ❌ Boxing in collections
ArrayList list = new ArrayList();  // Legacy, don't use
list.Add(42);  // ❌ Boxes

// ✅ Generic collections
List<int> list2 = new List<int>();
list2.Add(42);  // ✅ No boxing
```

### LINQ Optimization

**Avoiding Allocations:**

```csharp
// ❌ LINQ allocates enumerators
public int SumEven(int[] numbers)
{
    return numbers.Where(x => x % 2 == 0).Sum();  // 2 allocations
}

// ✅ For loop: no allocations
public int SumEven(int[] numbers)
{
    int sum = 0;
    for (int i = 0; i < numbers.Length; i++)
    {
        if (numbers[i] % 2 == 0)
            sum += numbers[i];
    }
    return sum;  // ✅ No allocations
}

// ✅ Span with foreach: no allocations
public int SumEven(ReadOnlySpan<int> numbers)
{
    int sum = 0;
    foreach (var num in numbers)  // ✅ No allocations
    {
        if (num % 2 == 0)
            sum += num;
    }
    return sum;
}
```

**When LINQ is OK:**

```csharp
// LINQ is fine for:
// - Cold paths (infrequent operations)
// - Readability-critical code
// - Prototyping

public void ProcessOrders(Order[] orders)
{
    // OK: runs once per request, readability matters
    var highValue = orders
        .Where(o => o.Total > 1000)
        .OrderByDescending(o => o.Total)
        .Take(10)
        .ToList();
}

// Not OK: hot path
public decimal CalculateTotal(int[] prices)
{
    // Bad: called millions of times
    return prices.Where(p => p > 0).Sum();
}
```

### Reducing Closure Allocations

```csharp
// ❌ Lambda captures local variable → allocates
public void ProcessItems(List<Item> items, int threshold)
{
    items.RemoveAll(item => item.Value < threshold);  // ❌ Allocates closure
}

// ✅ Avoid capture with for loop
public void ProcessItems(List<Item> items, int threshold)
{
    for (int i = items.Count - 1; i >= 0; i--)
    {
        if (items[i].Value < threshold)
            items.RemoveAt(i);
    }
}

// ✅ Or pass threshold as parameter (no capture)
public void ProcessItems(List<Item> items, int threshold)
{
    items.RemoveAll(CreatePredicate(threshold));
}

private static Predicate<Item> CreatePredicate(int threshold)
{
    return item => item.Value < threshold;  // Allocates once
}
```

### Stack Allocation with stackalloc

```csharp
// ✅ Small temporary buffers on stack
public void ProcessSmallBuffer()
{
    Span<byte> buffer = stackalloc byte[256];  // ✅ Stack, no GC
    
    // Use buffer...
    
    // Automatically cleaned up when method returns
}

// ⚠️ Don't stackalloc large buffers
public void DangerousLargeStack()
{
    Span<byte> huge = stackalloc byte[1_000_000];  // ❌ Stack overflow!
}

// ✅ For large buffers, rent from pool
public void ProcessLargeBuffer()
{
    var buffer = ArrayPool<byte>.Shared.Rent(1_000_000);
    try
    {
        var span = buffer.AsSpan(0, 1_000_000);
        // Use span...
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer);
    }
}
```

### String Interning

```csharp
// String interning for frequently used strings
public class ConfigManager
{
    // ❌ New string allocation each time
    public string GetEnvironment()
    {
        return "Production";  // New string? Maybe not (literal interned by compiler)
    }
    
    // ✅ Explicit interning for runtime strings
    public string NormalizeEnvironment(string env)
    {
        // Intern frequently compared strings
        return string.Intern(env.ToUpperInvariant());
        // Future comparisons use reference equality
    }
}

// Use with caution: interned strings never GC'd
```

public class SpanPractice
{
    public void ParseCsv(string csvLine)
    {
        ReadOnlySpan<char> span = csvLine.AsSpan();
        
        while (span.Length > 0)
        {
            int comma = span.IndexOf(',');
            if (comma == -1)
            {
                ProcessField(span);
                break;
            }
            
            ProcessField(span[..comma]);
            span = span[(comma + 1)..];
        }
    }

## Summary

Reducing allocations minimizes GC pressure and improves performance. Use Span<T> for stack-based zero-allocation operations and Memory<T> for heap-storable scenarios. Prefer structs for small, immutable value types. Avoid boxing, minimize LINQ in hot paths, and reduce closure allocations. Use stackalloc for small temporary buffers and ArrayPool for larger ones. Modern .NET provides powerful tools for writing high-performance, low-allocation code.
