## Introduction

While cache-aside is the most common pattern, write-through and write-behind patterns offer different trade-offs for write-heavy workloads. Write-through ensures cache and database are always synchronized by writing to both simultaneously. Write-behind (write-back) improves write performance by queuing database updates asynchronously. Understanding these patterns helps you choose the right caching strategy for your application's read/write characteristics.

## Key Concepts Summary

### Cache-Aside vs Write-Through vs Write-Behind

| Aspect | Cache-Aside | Write-Through | Write-Behind |
|--------|-------------|---------------|--------------|
| Read behavior | Check cache, load on miss | Check cache, load on miss | Check cache, load on miss |
| Write behavior | Write to DB, invalidate cache | Write to cache & DB together | Write to cache, queue DB update |
| Consistency | Eventually consistent | Always consistent | Eventually consistent |
| Write latency | Low (DB only) | High (cache + DB sync) | Very low (cache only) |
| Complexity | Low | Medium | High |
| Data loss risk | None | None | Possible if cache fails |

### Write-Through Pattern

**Characteristics:**
- Application writes to cache
- Cache synchronously writes to database
- Read request always gets consistent data
- Higher write latency due to dual writes

**Implementation:**
```csharp
public class WriteThroughCacheService
{
    private readonly IDistributedCache _cache;
    private readonly ApplicationDbContext _dbContext;
    
    public async Task<Product> CreateProductAsync(Product product)
    {
        // 1. Write to database first
        _dbContext.Products.Add(product);
        await _dbContext.SaveChangesAsync();
        
        // 2. Write to cache (synchronously)
        var cacheKey = $"product:{product.Id}";
        var serialized = JsonSerializer.Serialize(product);
        
        var options = new DistributedCacheEntryOptions
        {
            AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(30)
        };
        
        await _cache.SetStringAsync(cacheKey, serialized, options);
        
        return product;
    }
    
    public async Task<Product> UpdateProductAsync(Product product)
    {
        // 1. Update database
        _dbContext.Products.Update(product);
        await _dbContext.SaveChangesAsync();
        
        // 2. Update cache immediately
        var cacheKey = $"product:{product.Id}";
        var serialized = JsonSerializer.Serialize(product);
        await _cache.SetStringAsync(cacheKey, serialized);
        
        return product;
    }
    
    public async Task<Product?> GetProductAsync(int id)
    {
        var cacheKey = $"product:{id}";
        
        // Try cache first
        var cached = await _cache.GetStringAsync(cacheKey);
        if (cached != null)
        {
            return JsonSerializer.Deserialize<Product>(cached);
        }
        
        // Load from database
        var product = await _dbContext.Products.FindAsync(id);
        
        if (product != null)
        {
            // Populate cache
            var serialized = JsonSerializer.Serialize(product);
            await _cache.SetStringAsync(cacheKey, serialized);
        }
        
        return product;
    }
}
```

### Write-Behind (Write-Back) Pattern

**Characteristics:**
- Application writes to cache only
- Cache asynchronously syncs to database
- Lowest write latency
- Risk of data loss if cache crashes
- Can batch multiple writes

**Implementation with Background Service:**
```csharp
public class WriteBehindCacheService
{
    private readonly IDistributedCache _cache;
    private readonly IConnectionMultiplexer _redis;
    
    public async Task UpdateProductAsync(Product product)
    {
        var cacheKey = $"product:{product.Id}";
        
        // 1. Write to cache immediately
        var serialized = JsonSerializer.Serialize(product);
        await _cache.SetStringAsync(cacheKey, serialized);
        
        // 2. Queue for background sync to database
        var queue = _redis.GetDatabase();
        await queue.ListLeftPushAsync("write-queue", $"{cacheKey}:{serialized}");
        
        // Return immediately - database write happens in background
    }

    {

        var cached = await _cache.GetStringAsync(cacheKey);
        
        if (cached != null)
        {
            return JsonSerializer.Deserialize<Product>(cached);
        }
        
        // If not in cache, load from database

public class WriteBehindProcessor : BackgroundService
{
    private readonly IConnectionMultiplexer _redis;
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly ILogger<WriteBehindProcessor> _logger;
    
    public WriteBehindProcessor(
        IConnectionMultiplexer redis,
        IServiceScopeFactory scopeFactory,
        ILogger<WriteBehindProcessor> logger)
    {
        _redis = redis;
        _scopeFactory = scopeFactory;
        _logger = logger;
    }
    
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var db = _redis.GetDatabase();
        
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                // Dequeue items from write queue
                var item = await db.ListRightPopAsync("write-queue");
                
                if (!item.IsNullOrEmpty)
                {
                    await ProcessWriteAsync(item);
                }
                else
                {
                    // No items, wait before checking again
                    await Task.Delay(TimeSpan.FromMilliseconds(100), stoppingToken);
                }
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error processing write queue");
                await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
            }
        }
    }
    
    private async Task ProcessWriteAsync(string queueItem)
    {
        using var scope = _scopeFactory.CreateScope();
        var dbContext = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>();
        
        // Parse queue item and write to database
        var parts = queueItem.Split(':', 2);
        var cacheKey = parts[0];
        var serialized = parts[1];
        
        var product = JsonSerializer.Deserialize<Product>(serialized);
        
        if (product != null)
        {
            dbContext.Products.Update(product);
            await dbContext.SaveChangesAsync();
        }
    }
}
```

### Write-Behind with Batching

```csharp
public class BatchedWriteBehindProcessor : BackgroundService
{
    private readonly IConnectionMultiplexer _redis;
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly int _batchSize = 100;
    private readonly TimeSpan _batchInterval = TimeSpan.FromSeconds(5);
    
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var db = _redis.GetDatabase();
        
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                var batch = new List<Product>();
                
                // Collect up to batchSize items or wait for interval
                for (int i = 0; i < _batchSize; i++)
                {
                    var item = await db.ListRightPopAsync("write-queue");
                    
                    if (item.IsNullOrEmpty)
                        break;
                    
                    var product = DeserializeQueueItem(item);
                    if (product != null)
                        batch.Add(product);
                }
                
                if (batch.Any())
                {
                    await WriteBatchToDatabaseAsync(batch);
                }
                else
                {
                    await Task.Delay(_batchInterval, stoppingToken);
                }
            }
            catch (Exception ex)
            {
                // Error handling
            }
        }
    }
    
    private async Task WriteBatchToDatabaseAsync(List<Product> products)
    {
        using var scope = _scopeFactory.CreateScope();
        var dbContext = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>();
        
        dbContext.Products.UpdateRange(products);
        await dbContext.SaveChangesAsync();
    }
}
```

### Use Cases Comparison

**Write-Through Best For:**
- ✅ Financial transactions (consistency critical)
- ✅ User account updates
- ✅ Inventory management
- ✅ Applications that can't tolerate data loss
- ✅ When write latency is acceptable

**Write-Behind Best For:**
- ✅ Activity logs and analytics
- ✅ User view/watch timestamps
- ✅ Non-critical metrics
- ✅ High-volume writes that can be batched
- ✅ When write performance is critical

**Cache-Aside Best For:**
- ✅ Read-heavy workloads
- ✅ Data that changes infrequently
- ✅ Simple caching needs
- ✅ Most general-purpose scenarios

### Handling Failures

```csharp
public class ResilientWriteThroughService
{
    public async Task<Product> UpdateProductAsync(Product product)
    {
        // Always update database first
        _dbContext.Products.Update(product);
        await _dbContext.SaveChangesAsync();
        
        // Try to update cache, but don't fail if cache is down
        try
        {
            await UpdateCacheAsync(product);
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Failed to update cache for product {ProductId}", product.Id);
            // Cache will be populated on next read (fallback to cache-aside)
        }
        
        return product;
    }
}
```
