## Introduction

In distributed systems with database-per-service, maintaining data consistency is challenging. You can't use traditional ACID transactions across services. This lesson explores strategies for managing consistency, from strong consistency within services to eventual consistency across services, and practical patterns like the Outbox pattern.

## Key Concepts

### Consistency Spectrum

```
Strong Consistency                      Eventual Consistency
        │                                       │
        │                                       │
   ┌────▼────┐                            ┌────▼────┐
   │  ACID   │                            │  BASE   │
   │         │                            │         │
   │ All or  │                            │ Basic   │
   │ Nothing │                            │ Avail   │
   │         │                            │ Soft    │
   │ Single  │                            │ Event   │
   │ Service │                            │         │
   └─────────┘                            └─────────┘
```

**ACID (Strong)**:
- Atomicity: All or nothing
- Consistency: Valid state transitions
- Isolation: Concurrent transactions don't interfere
- Durability: Committed data persists

**BASE (Eventual)**:
- Basically Available: System appears to work
- Soft state: State may change without input
- Eventually consistent: System becomes consistent over time

## Within-Service Consistency (Strong)

Use traditional database transactions:

```csharp
// Strong consistency within Order Service
public async Task PlaceOrderAsync(PlaceOrderCommand cmd)
{
    using var transaction = await _dbContext.Database.BeginTransactionAsync();
    try
    {
        // Create order
        var order = new Order(cmd);
        await _dbContext.Orders.AddAsync(order);

        // Create order lines
        foreach (var item in cmd.Items)
        {
            await _dbContext.OrderLines.AddAsync(new OrderLine
            {
                OrderId = order.Id,
                ProductId = item.ProductId,
                Quantity = item.Quantity,
                Price = item.Price
            });
        }

        // Update aggregate totals
        var customer = await _dbContext.Customers.FindAsync(cmd.CustomerId);
        customer.TotalOrders++;
        customer.LifetimeValue += order.Total;

        // All or nothing
        await _dbContext.SaveChangesAsync();
        await transaction.CommitAsync();
    }
    catch
    {
        await transaction.RollbackAsync();
        throw;
    }
}
```

## Advanced Consistency Patterns

### Pattern: Compensating Reads (Read-After-Write)

When a user creates data, ensure they can read it immediately:

```csharp
[HttpPost("orders")]
public async Task<ActionResult<OrderDto>> CreateOrder(CreateOrderCommand cmd)
{
    // Write to command side
    var order = await _commandService.CreateOrderAsync(cmd);
    
    // Return authoritative write model immediately
    // (Don't wait for read model to update)
    return CreatedAtAction(
        nameof(GetOrder), 
        new { id = order.Id, version = order.Version }, 
        MapToDto(order));
}

[HttpGet("orders/{id}")]
public async Task<ActionResult<OrderDto>> GetOrder(
    int id, 
    [FromQuery] int? expectedVersion = null)
{
    // Try read model first
    var order = await _queryService.GetOrderAsync(id);
    
    if (order == null)
    {
        // Read model not ready, fall back to write model
        return Ok(await _commandService.GetOrderAsync(id));
    }

    // Check if read model is stale
    if (expectedVersion.HasValue && order.Version < expectedVersion.Value)
    {
        // Exponential backoff polling
        for (int i = 0; i < 5; i++)
        {
            await Task.Delay(TimeSpan.FromMilliseconds(50 * Math.Pow(2, i)));
            order = await _queryService.GetOrderAsync(id);
            
            if (order != null && order.Version >= expectedVersion.Value)
                break;
        }

        // If still stale, fall back to write model
        if (order == null || order.Version < expectedVersion.Value)
        {
            return Ok(await _commandService.GetOrderAsync(id));
        }
    }

    return Ok(order);
}
```

### Pattern: Versioned Events with Ordering

```csharp
public class VersionedEventHandler<T> : IEventHandler<T> where T : DomainEvent
{
    private readonly SemaphoreSlim _lock = new(1, 1);

    public async Task HandleAsync(T @event)
    {
        await _lock.WaitAsync();
        
        try
        {
            var aggregate = await _readDb.FindAsync(@event.AggregateId);
            
            // Ensure events are applied in order
            if (@event.Version <= aggregate.Version)
            {
                _logger.LogWarning(
                    "Skipping event {EventId} version {EventVersion}, already applied {CurrentVersion}",
                    @event.Id, @event.Version, aggregate.Version);
                return;
            }

            if (@event.Version > aggregate.Version + 1)
            {
                // Missing events, enqueue for retry
                _logger.LogWarning(
                    "Event {EventId} version {EventVersion} arrived out of order, expected {ExpectedVersion}",
                    @event.Id, @event.Version, aggregate.Version + 1);
                
                await _retryQueue.EnqueueAsync(@event, delay: TimeSpan.FromSeconds(5));
                return;
            }

            // Apply event
            await ApplyEventAsync(aggregate, @event);
            aggregate.Version = @event.Version;
            await _readDb.SaveChangesAsync();
        }
        finally
        {
            _lock.Release();
        }
    }
}
```

## The Outbox Pattern

**Problem**: Publishing events atomically with database changes

```csharp
❌ PROBLEM: Not atomic!
await _dbContext.SaveChangesAsync();  // ← Database updated
await _eventBus.PublishAsync(@event); // ← What if this fails?
// Event lost! Read model out of sync!
```

**Solution**: Outbox table

```csharp
// Add Outbox table
public class OutboxMessage
{
    public Guid Id { get; set; }
    public string EventType { get; set; }
    public string EventData { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? ProcessedAt { get; set; }
}

// Write to Outbox in same transaction
public async Task PlaceOrderAsync(PlaceOrderCommand cmd)
{
    using var transaction = await _dbContext.Database.BeginTransactionAsync();

    var order = new Order(cmd);
    await _dbContext.Orders.AddAsync(order);

    // Write event to outbox (same transaction)
    var outboxMessage = new OutboxMessage
    {
        EventType = nameof(OrderPlacedEvent),
        EventData = JsonSerializer.Serialize(new OrderPlacedEvent
        {
            OrderId = order.Id,
            CustomerId = order.CustomerId,
            Total = order.Total
        }),
        CreatedAt = DateTime.UtcNow
    };
    await _dbContext.OutboxMessages.AddAsync(outboxMessage);

    // Atomic: both or neither
    await _dbContext.SaveChangesAsync();
    await transaction.CommitAsync();
}

// Background worker publishes from outbox
public class OutboxProcessor : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            var messages = await _dbContext.OutboxMessages
                .Where(m => m.ProcessedAt == null)
                .OrderBy(m => m.CreatedAt)
                .Take(100)
                .ToListAsync(stoppingToken);

            foreach (var message in messages)
            {
                try
                {
                    var @event = DeserializeEvent(message);
                    await _eventBus.PublishAsync(@event, stoppingToken);

                    message.ProcessedAt = DateTime.UtcNow;
                    await _dbContext.SaveChangesAsync(stoppingToken);
                }
                catch (Exception ex)
                {
                    _logger.LogError(ex, "Failed to process outbox message {Id}", 
                        message.Id);
                }
            }

            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }
}
```

**Benefits**:
- ✅ Guaranteed event delivery (at-least-once)
- ✅ Atomic with database changes
- ✅ Can retry on failures
- ✅ Audit trail of published events

### Outbox Pattern with EF Core

```csharp
// Outbox table in same DbContext
public class ApplicationDbContext : DbContext
{
    public DbSet<Order> Orders { get; set; }
    public DbSet<OutboxMessage> OutboxMessages { get; set; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<OutboxMessage>(entity =>
        {
            entity.HasKey(e => e.Id);
            entity.HasIndex(e => e.ProcessedAt);
            entity.Property(e => e.EventType).HasMaxLength(255);
        });
    }
}

// Interceptor to automatically create outbox messages
public class OutboxInterceptor : SaveChangesInterceptor
{
    public override ValueTask<InterceptionResult<int>> SavingChangesAsync(
        DbContextEventData eventData,
        InterceptionResult<int> result,
        CancellationToken cancellationToken = default)
    {
        var context = eventData.Context;
        if (context == null) return ValueTask.FromResult(result);

        // Find entities with domain events
        var entities = context.ChangeTracker
            .Entries<IAggregateRoot>()
            .Where(e => e.Entity.DomainEvents.Any())
            .ToList();

        foreach (var entity in entities)
        {
            foreach (var domainEvent in entity.Entity.DomainEvents)
            {
                // Add to outbox instead of publishing
                context.Set<OutboxMessage>().Add(new OutboxMessage
                {
                    EventType = domainEvent.GetType().Name,
                    EventData = JsonSerializer.Serialize(domainEvent),
                    CreatedAt = DateTime.UtcNow
                });
            }

            entity.Entity.ClearDomainEvents();
        }

        return ValueTask.FromResult(result);
    }
}

// Background processor with batching
public class OutboxProcessor : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await ProcessBatchAsync(stoppingToken);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error processing outbox messages");
            }

            await Task.Delay(TimeSpan.FromSeconds(1), stoppingToken);
        }
    }

    private async Task ProcessBatchAsync(CancellationToken ct)
    {
        using var scope = _serviceScopeFactory.CreateScope();
        var dbContext = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>();
        var eventBus = scope.ServiceProvider.GetRequiredService<IEventBus>();

        // Fetch batch with lock (prevent multiple processors from picking same messages)
        var messages = await dbContext.OutboxMessages
            .Where(m => m.ProcessedAt == null)
            .OrderBy(m => m.CreatedAt)
            .Take(100)
            .ToListAsync(ct);

        if (!messages.Any())
            return;

        foreach (var message in messages)
        {
            try
            {
                var @event = DeserializeEvent(message);
                await eventBus.PublishAsync(@event, ct);

                message.ProcessedAt = DateTime.UtcNow;
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Failed to process outbox message {Id}", message.Id);
                
                message.RetryCount++;
                message.LastError = ex.Message;

                // Dead letter after too many retries
                if (message.RetryCount >= 10)
                {
                    message.ProcessedAt = DateTime.UtcNow; // Mark as processed to skip
                    await _deadLetterQueue.EnqueueAsync(message);
                }
            }
        }

        await dbContext.SaveChangesAsync(ct);
    }
}
```

### Inbox Pattern (Idempotent Consumers)

Prevent duplicate message processing:

```csharp
public class InboxMessage
{
    public Guid MessageId { get; set; }
    public string EventType { get; set; }
    public DateTime ReceivedAt { get; set; }
    public DateTime ProcessedAt { get; set; }
}

public class IdempotentEventHandler<T> : IEventHandler<T> where T : DomainEvent
{
    public async Task HandleAsync(T @event)
    {
        // Check if already processed
        var existing = await _dbContext.InboxMessages
            .FirstOrDefaultAsync(m => m.MessageId == @event.Id);

        if (existing != null)
        {
            _logger.LogInformation(
                "Event {EventId} already processed, skipping", @event.Id);
            return;
        }

        using var transaction = await _dbContext.Database.BeginTransactionAsync();
        
        try
        {
            // Record receipt
            await _dbContext.InboxMessages.AddAsync(new InboxMessage
            {
                MessageId = @event.Id,
                EventType = @event.GetType().Name,
                ReceivedAt = DateTime.UtcNow,
                ProcessedAt = DateTime.UtcNow
            });

            // Process event
            await ProcessEventAsync(@event);

            await _dbContext.SaveChangesAsync();
            await transaction.CommitAsync();
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}
```

## Read Your Own Writes

**Problem**: User creates order, redirects to order details, but read model not yet updated!

```csharp
// User creates order
POST /api/orders
→ Order created, event published
→ Redirect to GET /api/orders/123

// But read model not updated yet!
GET /api/orders/123
→ 404 Not Found ❌
```

**Solutions**:

**1. Return write model immediately**:
```csharp
[HttpPost("orders")]
public async Task<ActionResult<OrderDto>> CreateOrder(CreateOrderCommand cmd)
{
    var order = await _commandService.CreateOrderAsync(cmd);
    
    // Return from write model (authoritative)
    return CreatedAtAction(nameof(GetOrder), new { id = order.Id }, 
        MapToDto(order));
}
```

**2. Version-based polling**:
```csharp
[HttpGet("orders/{id}")]
public async Task<ActionResult<OrderDto>> GetOrder(int id, [FromQuery] int? expectedVersion)
{
    var order = await _queryService.GetOrderAsync(id);
    
    if (order == null)
        return NotFound();

    // If read model is behind, wait and retry
    if (expectedVersion.HasValue && order.Version < expectedVersion.Value)
    {
        await Task.Delay(100);  // Brief wait
        order = await _queryService.GetOrderAsync(id);
    }

    return Ok(order);
}
```

**3. Sync-on-demand**:
```csharp
[HttpGet("orders/{id}")]
public async Task<ActionResult<OrderDto>> GetOrder(int id, [FromQuery] bool forceSync = false)
{
    if (forceSync)
    {
        // Query write model directly for fresh data
        return Ok(await _writeModel.GetOrderAsync(id));
    }

    // Use eventual read model
    return Ok(await _readModel.GetOrderAsync(id));
}
```

**4. Client-side retry**:
```typescript
// Frontend code
async function createAndFetchOrder(orderData) {
  // Create order
  const response = await fetch('/api/orders', {
    method: 'POST',
    body: JSON.stringify(orderData)
  });
  
  const { orderId, version } = await response.json();
  
  // Retry fetch until read model is ready
  for (let i = 0; i < 10; i++) {
    const order = await fetch(`/api/orders/${orderId}?expectedVersion=${version}`);
    
    if (order.status === 200) {
      return await order.json();
    }
    
    // Exponential backoff
    await delay(50 * Math.pow(2, i));
  }
  
  throw new Error('Order not available in read model');
}
```

## Consistency Monitoring

### Measuring Lag Between Write and Read Models

```csharp
public class ConsistencyMonitor : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await MeasureConsistencyLagAsync();
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error measuring consistency lag");
            }

            await Task.Delay(TimeSpan.FromSeconds(10), stoppingToken);
        }
    }

    private async Task MeasureConsistencyLagAsync()
    {
        // Get latest event in outbox
        var latestEvent = await _writeDb.OutboxMessages
            .OrderByDescending(m => m.CreatedAt)
            .FirstOrDefaultAsync();

        if (latestEvent == null || latestEvent.ProcessedAt == null)
            return;

        // Measure lag
        var lag = DateTime.UtcNow - latestEvent.ProcessedAt.Value;

        // Record metric
        _metrics.RecordConsistencyLag(lag.TotalMilliseconds);

        // Alert if lag is too high
        if (lag > TimeSpan.FromSeconds(10))
        {
            _logger.LogWarning("Consistency lag is {Lag}ms, threshold exceeded", 
                lag.TotalMilliseconds);
        }
    }
}

// Prometheus metrics
public class ConsistencyMetrics
{
    private readonly Histogram _lagHistogram;
    private readonly Counter _inconsistencyCounter;

    public ConsistencyMetrics()
    {
        _lagHistogram = Metrics.CreateHistogram(
            "consistency_lag_milliseconds",
            "Time between write and read model update",
            new HistogramConfiguration
            {
                Buckets = Histogram.ExponentialBuckets(10, 2, 10) // 10ms to 5s
            });

        _inconsistencyCounter = Metrics.CreateCounter(
            "consistency_violations_total",
            "Number of detected consistency violations");
    }

    public void RecordConsistencyLag(double milliseconds)
    {
        _lagHistogram.Observe(milliseconds);
    }

    public void RecordInconsistency()
    {
        _inconsistencyCounter.Inc();
    }
}
```

## Consistency Decision Matrix

| Scenario | Consistency Level | Pattern |
|----------|-------------------|---------|
| Order placement (within service) | Strong (ACID) | Database transaction |
| Inventory reservation (across services) | Eventual | Saga pattern |
| Event publishing | At-least-once | Outbox pattern |
| Read after write | Read-your-writes | Version checks, sync-on-demand |
| Analytics queries | Eventual | CQRS read models |
| Financial transactions | Strong within, Saga across | Saga with compensations |
| User profile updates | Eventual | Event-driven cache invalidation |
| Shopping cart | Session consistency | Redis with TTL |
| Product catalog search | Eventual | Elasticsearch projection |
| Audit logs | Strong | Direct write, no read model |

## Testing Consistency Guarantees

### Testing Eventual Consistency

```csharp
public class EventualConsistencyTests
{
    [Fact]
    public async Task ReadModel_EventuallyConsistent_WithWriteModel()
    {
        // Arrange
        var orderId = Guid.NewGuid();

        // Act: Write to command side
        await _commandService.CreateOrderAsync(new CreateOrderCommand
        {
            OrderId = orderId,
            CustomerId = Guid.NewGuid(),
            Total = 100m
        });

        // Wait for eventual consistency (with timeout)
        var order = await PollUntilAsync(
            async () => await _queryService.GetOrderAsync(orderId),
            order => order != null,
            timeout: TimeSpan.FromSeconds(5));

        // Assert
        Assert.NotNull(order);
        Assert.Equal(100m, order.Total);
    }

    private async Task<T> PollUntilAsync<T>(
        Func<Task<T>> poll,
        Func<T, bool> condition,
        TimeSpan timeout)
    {
        var sw = Stopwatch.StartNew();
        
        while (sw.Elapsed < timeout)
        {
            var result = await poll();
            if (condition(result))
                return result;

            await Task.Delay(100);
        }

        throw new TimeoutException("Condition not met within timeout");
    }
}
```

## Common Anti-Patterns to Avoid

### Anti-Pattern 1: Distributed Transactions

```csharp
❌ WRONG: 2PC across services
using var transaction = new DistributedTransaction();
await _hotelService.BookHotel(request);
await _flightService.BookFlight(request);
await transaction.CommitAsync(); // Doesn't exist!

✅ CORRECT: Saga pattern
var saga = new BookingSaga(request);
await _sagaOrchestrator.ExecuteAsync(saga);
```

### Anti-Pattern 2: Synchronous Read-Your-Writes

```csharp
❌ WRONG: Blocking until read model updated
await _writeService.CreateOrderAsync(order);
// Block until read model updated (could be forever!)
while (await _readService.GetOrderAsync(order.Id) == null)
{
    await Task.Delay(100);
}

✅ CORRECT: Return write model or accept eventual consistency
var order = await _writeService.CreateOrderAsync(order);
return order; // Return from write model
```

### Anti-Pattern 3: Eventual Consistency Everywhere

```csharp
❌ WRONG: User creates order, immediately charges payment (eventual)
await _orderService.CreateOrderAsync(order);
// Order might not be committed yet!
await _paymentService.ChargeAsync(order.Id);

✅ CORRECT: Strong consistency for related operations
using var transaction = await _db.BeginTransactionAsync();
await _orderService.CreateOrderAsync(order);
await _paymentService.ChargeAsync(order.Id);
await transaction.CommitAsync();
```

## Self-Check Questions

1. **What's the difference between strong and eventual consistency?**
   - Strong: immediate, ACID; Eventual: eventually consistent, BASE

2. **Why use the Outbox pattern?**
   - Atomic event publishing with database changes, guaranteed delivery

3. **What is "read your own writes" consistency?**
   - User sees their own changes immediately, even with eventual consistency

4. **Can you have ACID transactions across microservices?**
   - No, use Saga pattern for coordinated distributed transactions

## Key Takeaways

✅ **Strong consistency** within services, **eventual consistency** across services

✅ **Outbox pattern** ensures atomic event publishing

✅ **Saga pattern** for distributed transactions with compensations

✅ **Read-your-writes** strategies for better UX

✅ **Choose consistency** based on business requirements, not defaults

✅ **CAP theorem**: Can't have all three (Consistency, Availability, Partition tolerance)
