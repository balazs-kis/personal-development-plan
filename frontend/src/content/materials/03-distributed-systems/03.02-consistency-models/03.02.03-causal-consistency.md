## Learning Objectives

By the end of this lesson, you will be able to:
- Understand causal consistency and the happens-before relationship
- Implement causal ordering in distributed systems
- Use causal consistency for better user experience than eventual consistency
- Apply version vectors and vector clocks for causality tracking
- Recognize when causal consistency is the right choice

---

## Introduction

Causal consistency sits between strong consistency and eventual consistency, providing a middle ground that's often "good enough" for many applications. It guarantees that causally related operations are seen in the same order by all nodes, while allowing concurrent operations to be seen in any order. This provides better guarantees than eventual consistency without the performance penalty of strong consistency.

## What is Causal Consistency?

### The Guarantee

**Causal Consistency Promise:**
> If operation A causally precedes operation B, then all nodes observe A before B. Operations that are not causally related (concurrent) may be observed in any order.

### Causal Relationships

Two operations are causally related if:
1. They're in the same process/session (program order)
2. One reads what the other wrote
3. Transitivity: if A → B and B → C, then A → C

```csharp
// Example of causal relationships

// Thread 1:
Write(x = 1)        // Event A
Write(y = 2)        // Event B (A → B, same thread)

// Thread 2:
value = Read(y)     // Event C (reads B's write, so B → C)
Write(z = value)    // Event D (C → D, same thread)

// Causal order: A → B → C → D
// All nodes must see these in this order

// Thread 3:
Write(w = 5)        // Event E (concurrent with all above!)

// E has no causal relationship with A, B, C, or D
// Different nodes may observe E at different points in the sequence
```

## Implementing Causal Consistency

### 1. Using Version Vectors

```csharp
public class CausallyConsistentStore
{
    private readonly string _nodeId;
    private readonly Dictionary<string, (string Value, VectorClock Clock)> _data = new();
    private VectorClock _nodeClock;
    
    public CausallyConsistentStore(string nodeId, List<string> allNodeIds)
    {
        _nodeId = nodeId;
        _nodeClock = new VectorClock(allNodeIds);
    }
    
    public async Task WriteAsync(string key, string value, VectorClock? causalContext = null)
    {
        // Increment local clock
        _nodeClock.Increment(_nodeId);
        
        // Merge with causal context if provided
        if (causalContext != null)
        {
            _nodeClock.Merge(causalContext);
        }
        
        // Store value with its causal context
        _data[key] = (value, _nodeClock.Clone());
        
        _logger.LogInformation(
            "Written {Key}={Value} with clock {Clock}",
            key, value, _nodeClock);
    }
    
    public async Task<(string Value, VectorClock Context)> ReadAsync(string key)
    {
        if (!_data.TryGetValue(key, out var entry))
        {
            throw new KeyNotFoundException(key);
        }
        
        // Return value AND its causal context
        // Client must provide this context for future writes
        return (entry.Value, entry.Clock);
    }
    
    public async Task ReplicateAsync(
        string key, 
        string value, 
        VectorClock clock,
        string sourceNode)
    {
        // Only apply if causally after current version
        if (_data.TryGetValue(key, out var current))
        {
            var relation = VectorClock.Compare(clock, current.Clock);
            
            if (relation == ClockRelation.Before)
            {
                // Incoming write is older - ignore
                _logger.LogDebug("Ignored older write for {Key}", key);
                return;
            }
            else if (relation == ClockRelation.Concurrent)
            {
                // Conflict! Must resolve
                var resolved = ResolveConflict(
                    (value, clock), 
                    (current.Value, current.Clock));
                
                _data[key] = resolved;
                return;
            }
        }
        
        // Incoming write is causally after (or no current version)
        _data[key] = (value, clock);
        
        // Update local clock to reflect this knowledge
        _nodeClock.Merge(clock);
    }
}

public class VectorClock
{
    private readonly Dictionary<string, long> _clock;
    
    public VectorClock(List<string> nodeIds)
    {
        _clock = nodeIds.ToDictionary(id => id, id => 0L);
    }
    
    public void Increment(string nodeId)
    {
        _clock[nodeId]++;
    }
    
    public void Merge(VectorClock other)
    {
        foreach (var (nodeId, timestamp) in other._clock)
        {
            _clock[nodeId] = Math.Max(_clock[nodeId], timestamp);
        }
    }
    
    public VectorClock Clone()
    {
        var clone = new VectorClock(new List<string>());
        clone._clock.Clear();
        foreach (var kvp in _clock)
        {
            clone._clock[kvp.Key] = kvp.Value;
        }
        return clone;
    }
    
    public static ClockRelation Compare(VectorClock a, VectorClock b)
    {
        bool aLessOrEqual = true;
        bool bLessOrEqual = true;
        
        foreach (var nodeId in a._clock.Keys.Union(b._clock.Keys))
        {
            var aValue = a._clock.GetValueOrDefault(nodeId);
            var bValue = b._clock.GetValueOrDefault(nodeId);
            
            if (aValue > bValue) bLessOrEqual = false;
            if (bValue > aValue) aLessOrEqual = false;
        }
        
        if (aLessOrEqual && bLessOrEqual)
            return ClockRelation.Equal;
        if (aLessOrEqual)
            return ClockRelation.Before;
        if (bLessOrEqual)
            return ClockRelation.After;
        
        return ClockRelation.Concurrent;
    }
}

public enum ClockRelation
{
    Before,      // a happened before b
    After,       // a happened after b
    Equal,       // Same event
    Concurrent   // No causal relationship
}
```

### 2. Session-Based Causal Consistency

```csharp
public class SessionCausalStore
{
    private readonly IDataStore _store;
    private readonly Dictionary<string, VectorClock> _sessionContexts = new();
    
    public async Task<string> ReadInSessionAsync(
        string sessionId, 
        string key)
    {
        var (value, clock) = await _store.ReadWithClockAsync(key);
        
        // Update session's causal context
        if (!_sessionContexts.ContainsKey(sessionId))
        {
            _sessionContexts[sessionId] = clock;
        }
        else
        {
            _sessionContexts[sessionId].Merge(clock);
        }
        
        return value;
    }
    
    public async Task WriteInSessionAsync(
        string sessionId,
        string key,
        string value)
    {
        // Get session's causal context
        var context = _sessionContexts.GetValueOrDefault(sessionId);
        
        // Write with causal dependencies
        await _store.WriteWithClockAsync(key, value, context);
        
        // Update session context with new write
        var newClock = await _store.GetClockAsync(key);
        _sessionContexts[sessionId] = newClock;
    }
    
    public void EndSession(string sessionId)
    {
        _sessionContexts.Remove(sessionId);
    }
}
```

## Real-World Examples

### 1. Social Media Comments

```csharp
public class CausalCommentSystem
{
    private readonly ICausalStore _store;
    
    public async Task<Comment> PostCommentAsync(
        string postId,
        string content,
        string? parentCommentId,
        VectorClock? causalContext)
    {
        var comment = new Comment
        {
            Id = Guid.NewGuid().ToString(),
            PostId = postId,
            Content = content,
            ParentCommentId = parentCommentId,
            Timestamp = DateTime.UtcNow
        };
        
        // If replying to a comment, include its context
        VectorClock context = causalContext;
        if (parentCommentId != null)
        {
            var (parent, parentClock) = await _store.ReadAsync(parentCommentId);
            context = context?.Merge(parentClock) ?? parentClock;
        }
        
        // Write with causal dependencies
        await _store.WriteAsync(comment.Id, comment, context);
        
        return comment;
    }
    
    public async Task<List<Comment>> GetCommentsAsync(string postId)
    {
        var comments = await _store.QueryAsync<Comment>(
            c => c.PostId == postId);
        
        // Causal consistency guarantees:
        // - If you see a reply, you'll see the original comment
        // - Comments appear in causal order (replies after parents)
        
        return comments
            .OrderBy(c => c.CausalTimestamp)
            .ToList();
    }
}
```

### 2. Collaborative Editing

```csharp
public class CausalCollaborativeEditor
{
    private readonly ICausalStore _store;
    
    public async Task ApplyEditAsync(
        string documentId,
        Edit edit,
        VectorClock clientContext)
    {
        // Read current document state
        var (document, serverClock) = await _store.ReadAsync(documentId);
        
        // Check if client's view is causally consistent
        var relation = VectorClock.Compare(clientContext, serverClock);
        
        if (relation == ClockRelation.Before)
        {
            // Client is behind - must refresh and retry
            throw new StaleContextException(
                "Your edits are based on an old version. Please refresh.");
        }
        
        if (relation == ClockRelation.Concurrent)
        {
            // Concurrent edits! Transform the operation
            edit = TransformEdit(edit, document.RecentEdits);
        }
        
        // Apply edit with causal context
        document.ApplyEdit(edit);
        await _store.WriteAsync(documentId, document, clientContext);
    }
    
    private Edit TransformEdit(Edit edit, List<Edit> recentEdits)
    {
        // Operational Transformation (OT) or CRDTs
        // Ensures concurrent edits converge correctly
        foreach (var recentEdit in recentEdits)
        {
            edit = OperationalTransform(edit, recentEdit);
        }
        return edit;
    }
}
```

## Azure Cosmos DB Causal Consistency

```csharp
public class CosmosDbCausalExample
{
    private readonly Container _container;
    
    public CosmosDbCausalExample()
    {
        // Cosmos DB offers multiple consistency levels
        // including causal consistency variants
        var clientOptions = new CosmosClientOptions
        {
            // Consistent Prefix = causal consistency within a partition
            ConsistencyLevel = ConsistencyLevel.ConsistentPrefix
        };
        
        var client = new CosmosClient(connectionString, clientOptions);
        _container = client.GetContainer("database", "container");
    }
    
    public async Task DemonstrateCausalityAsync()
    {
        // Within a session, writes have causal ordering
        var sessionOptions = new ItemRequestOptions
        {
            SessionToken = null // Will be set after first operation
        };
        
        // Write 1
        var response1 = await _container.CreateItemAsync(
            new { id = "1", value = "A" },
            new PartitionKey("user123"),
            sessionOptions);
        
        // Capture session token (causal context)
        var sessionToken = response1.Headers.Session;
        
        // Write 2 (causally after Write 1)
        sessionOptions.SessionToken = sessionToken;
        var response2 = await _container.CreateItemAsync(
            new { id = "2", value = "B" },
            new PartitionKey("user123"),
            sessionOptions);
        
        // Any read with this session token will see both writes
        // in the correct causal order
        sessionOptions.SessionToken = response2.Headers.Session;
        
        var item1 = await _container.ReadItemAsync<dynamic>(
            "1",
            new PartitionKey("user123"),
            sessionOptions);
        
        // Guaranteed to see both items now
    }
}
```

## Benefits Over Eventual Consistency

Causal consistency provides stronger guarantees that prevent confusing user experiences.

### Prevents Causality Violations

```csharp
// Scenario: User posts a comment, then deletes it

// WITHOUT Causal Consistency:
Node1: See: Post comment    ✓
Node2: See: Delete comment  ✓ (arrives first!)
Node2: See: Post comment    ✓ (arrives late)
// Result: Deleted comment appears! (Anomaly!)

// WITH Causal Consistency:
Node1: See: Post comment (clock: [1,0])    ✓
Node2: Must buffer: Delete comment (clock: [2,0]) - waits
Node2: See: Post comment (clock: [1,0])    ✓
Node2: Now apply: Delete comment (clock: [2,0]) ✓
// Result: Comment correctly deleted (No anomaly!)
```

### Improved User Experience

**Example 1: Social Media Thread**

```csharp
public class ThreadAnomalyPrevention
{
    // Without causal consistency:
    // User A: Posts "What's the answer?"
    // User B: Replies "It's 42"
    // User C sees reply before question! (confusing)
    
    // With causal consistency:
    // System ensures question visible before reply
    
    public async Task PostReplyAsync(string threadId, string replyTo, string content)

        // Get causal context of parent post
        var (parentPost, parentClock) = await _store.ReadAsync(replyTo);
        
        var reply = new Post
        {
            Id = Guid.NewGuid().ToString(),
            ThreadId = threadId,
            ReplyTo = replyTo,
            Content = content
        };
        
        // Reply causally depends on parent
        await _store.WriteAsync(reply.Id, reply, parentClock);
    }
}
```

**Example 2: Collaborative Document Editing**
```csharp
public class DocumentEditCausality
{
    // Without causal consistency:
    // User A: Types "Hello"
    // User A: Types " World"
    // User B sees " World" then "Hello" (reversed!)
    
    // With causal consistency:
    // User B sees edits in correct order
    
    public async Task ApplySequentialEditsAsync(
        string documentId,
        List<Edit> edits,
        VectorClock clientClock)
    {
        foreach (var edit in edits)
        {
            // Each edit causally depends on previous
            var (doc, serverClock) = await _store.ReadAsync(documentId);
            
            // Ensure client is up to date
            clientClock.Merge(serverClock);
            clientClock.Increment(_clientId);
            
            doc.ApplyEdit(edit);
            await _store.WriteAsync(documentId, doc, clientClock);
        }
    }
}
```

## Trade-offs and Limitations

### Performance Characteristics

| Aspect | Strong | Causal | Eventual |
|--------|--------|--------|----------|
| **Read Latency** | High | Medium | Low |
| **Write Latency** | High | Medium-Low | Low |
| **Throughput** | Limited | Good | Excellent |
| **Scalability** | Poor | Good | Excellent |
| **Complexity** | Low | Medium | High |

### Storage Overhead

```csharp
public class CausalityOverhead
{
    // Each value must store its vector clock
    public class CausalValue<T>
    {
        public T Value { get; set; }
        public VectorClock Clock { get; set; } // Overhead: O(N) where N = nodes
        public DateTime Timestamp { get; set; }
    }
    
    // For 100 nodes, vector clock = ~800 bytes
    // Small values: high overhead percentage
    // Large values: negligible overhead
    
    public void AnalyzeOverhead()
    {
        var smallValue = "x";  // 1 byte + 800 bytes clock = 80,000% overhead!
        var largeValue = new byte[1_000_000]; // 1MB + 800 bytes = 0.08% overhead
        
        _logger.LogInformation(
            "Causal consistency adds vector clock overhead. " +
            "More significant for small values.");
    }
}
```

### Limitations

**1. Doesn't Prevent All Anomalies**
```csharp
// Causal consistency still allows:
// - Lost updates (concurrent writes)
// - Write skew
// - Phantom reads

public class CausalLimitations
{
    public async Task DemonstrateLostUpdateAsync()
    {
        // Two concurrent increments
        var (account1, clock1) = await _store.ReadAsync("account");
        var (account2, clock2) = await _store.ReadAsync("account");
        
        // Both read balance = 100
        
        // Concurrent writes (no causal relationship)
        await _store.WriteAsync("account", 
            new Account { Balance = account1.Balance + 10 }, clock1);
        
        await _store.WriteAsync("account", 
            new Account { Balance = account2.Balance + 20 }, clock2);
        
        // Result: balance = 120 (lost one increment!)
        // Causal consistency doesn't prevent this!
    }
}
```

**2. Requires Causal Context Tracking**
```csharp
public class ContextManagement
{
    // Clients must track and pass causal context
    // This adds complexity to client code
    
    private VectorClock _clientContext = new VectorClock();
    
    public async Task<T> ReadAsync<T>(string key)
    {
        var (value, clock) = await _store.ReadWithClockAsync(key);
        
        // Must merge clock into client context
        _clientContext.Merge(clock);
        
        return value;
    }
    
    public async Task WriteAsync<T>(string key, T value)
    {
        // Must pass client context with write
        await _store.WriteAsync(key, value, _clientContext);
        
        // Update context after write
        var newClock = await _store.GetClockAsync(key);
        _clientContext = newClock;
    }
}
```

**3. Doesn't Scale Well with Many Nodes**
```csharp
public class ScalabilityAnalysis
{
    // Vector clock size = O(N) where N = number of nodes
    // 10 nodes: 80 bytes
    // 100 nodes: 800 bytes
    // 1,000 nodes: 8 KB per value!
    
    // Solutions:
    // 1. Use bounded vector clocks (approximate)
    // 2. Prune old entries
    // 3. Use dotted version vectors (more compact)
    
    public class BoundedVectorClock
    {
        private readonly SortedDictionary<string, long> _clock;
        private readonly int _maxSize;
        
        public BoundedVectorClock(int maxSize)
        {
            _clock = new SortedDictionary<string, long>();
            _maxSize = maxSize;
        }
        
        public void Increment(string nodeId)
        {
            _clock[nodeId] = _clock.GetValueOrDefault(nodeId) + 1;
            
            // Prune if too large
            if (_clock.Count > _maxSize)
            {
                // Remove oldest entry
                var oldest = _clock.OrderBy(kvp => kvp.Value).First();
                _clock.Remove(oldest.Key);
            }
        }
    }
}
```

## When to Use Causal Consistency

### ✅ Use Causal Consistency When:

**1. Social Media / Messaging**
- Comments/replies must appear after parent
- Conversation threads need logical ordering
- User experience matters more than absolute consistency

**2. Collaborative Applications**
- Document editing
- Real-time collaboration
- Shared whiteboards

**3. Distributed Caching**
- Cache invalidation must respect update ordering
- Stale reads acceptable, but causality violations not

**4. User Profile Updates**
- Users must see their own changes immediately
- Other users can see updates with slight delay

### ❌ Don't Use Causal Consistency When:

**1. Financial Transactions**
- Need strong consistency
- Causal consistency not sufficient for atomicity

**2. Inventory Management**
- Can't tolerate lost updates
- Need serializable transactions

**3. Single-User Applications**
- Causality guarantees unnecessary
- Eventual consistency simpler

**4. Systems with Few Concurrent Operations**
- Overhead not worth it
- Strong consistency feasible

## Key Takeaways

- Causal consistency preserves cause-and-effect relationships
- Operations that are causally related are observed in order across all nodes
- Concurrent operations (no causal relationship) can be seen in any order
- Implemented using version vectors or vector clocks
- Provides better user experience than eventual consistency
- Lower latency and higher availability than strong consistency
- Ideal for: social media, collaborative apps, messaging systems
- Azure Cosmos DB's "Consistent Prefix" is a form of causal consistency
- Session tokens can provide per-session causal consistency
