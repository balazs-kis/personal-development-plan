## Introduction

Interoperability (interop) is essential when your .NET application needs to call native code—whether it's Windows APIs, C/C++ libraries, or platform-specific functionality. Modern .NET has evolved from runtime-based P/Invoke marshalling to compile-time source generation, offering better performance and Native AOT compatibility. Understanding these mechanisms helps you integrate with existing native code efficiently.

## Key Concepts Summary

### What is Platform Invoke (P/Invoke)?

P/Invoke is a technology that allows managed .NET code to call unmanaged functions exported from native libraries (DLLs on Windows, shared libraries on Linux/macOS).

```
Managed .NET Code
     ↓
P/Invoke Layer (marshalling)
     ↓
Unmanaged Native Code (C/C++ DLL)
     ↓
Operating System APIs
```

**Why P/Invoke Matters:**
- Access operating system APIs not available in .NET
- Integrate with existing C/C++ libraries
- Call platform-specific functionality
- Reuse legacy native code

### Basic P/Invoke Example

**Native C Function:**
```c
// In some native DLL (e.g., user32.dll)
int MessageBoxW(
    HWND hWnd,
    LPCWSTR lpText,
    LPCWSTR lpCaption,
    UINT uType
);
```

**Traditional DllImport Approach (.NET Framework - .NET 7):**
```csharp
using System.Runtime.InteropServices;

class Program
{
    // Import the native function
    [DllImport("user32.dll", CharSet = CharSet.Unicode)]
    private static extern int MessageBoxW(
        IntPtr hWnd,
        string lpText,
        string lpCaption,
        uint uType
    );

    static void Main()
    {
        // Call it like a managed method
        MessageBoxW(IntPtr.Zero, "Hello from C#!", "P/Invoke Demo", 0);
    }
}
```

**How It Works:**
1. `DllImport` tells the runtime which DLL contains the function
2. The `extern` keyword indicates the implementation is external
3. At runtime, the CLR locates the DLL and function
4. Marshalling layer converts managed types to native types
5. Function executes in native code
6. Result is marshalled back to managed code

### DllImport vs LibraryImport

**DllImport (Traditional - Runtime Generation):**
```csharp
[DllImport("kernel32.dll", SetLastError = true)]
private static extern IntPtr CreateFileW(
    string lpFileName,
    uint dwDesiredAccess,
    uint dwShareMode,
    IntPtr lpSecurityAttributes,
    uint dwCreationDisposition,
    uint dwFlagsAndAttributes,
    IntPtr hTemplateFile
);
```

**Characteristics:**
- Marshalling code generated at **runtime** via IL stubs
- Works with JIT compilation
- **NOT compatible** with Native AOT
- Reflection-based metadata access
- Slightly slower first call (stub generation)

**LibraryImport (Modern - Compile-Time Generation):**
```csharp
[LibraryImport("kernel32.dll", SetLastError = true, StringMarshalling = StringMarshalling.Utf16)]
private static partial IntPtr CreateFileW(
    string lpFileName,
    uint dwDesiredAccess,
    uint dwShareMode,
    IntPtr lpSecurityAttributes,
    uint dwCreationDisposition,
    uint dwFlagsAndAttributes,
    IntPtr hTemplateFile
);
```

**Characteristics:**
- Marshalling code generated at **compile time** via source generators
- **Compatible** with Native AOT and trimming
- Must be `partial` method (generator fills in implementation)
- Explicit `StringMarshalling` parameter required
- Better startup performance (no runtime codegen)

### Comparison Table

| Feature | DllImport | LibraryImport |
|---------|-----------|---------------|
| **Generation Time** | Runtime (IL stub) | Compile-time (source generator) |
| **AOT Compatible** | ❌ No | ✅ Yes |
| **Trimming Compatible** | ❌ Limited | ✅ Yes |
| **Method Modifier** | `extern` | `partial` |
| **String Marshalling** | Implicit (CharSet) | Explicit (StringMarshalling) |
| **Performance** | Slight runtime overhead | Optimized |
| **Available Since** | .NET Framework 1.0 | .NET 7+ |

**Migration Strategy:**
```csharp
// Old
[DllImport("mylib.dll", CharSet = CharSet.Unicode)]
static extern int MyFunction(string text);

// New
[LibraryImport("mylib.dll", StringMarshalling = StringMarshalling.Utf16)]
static partial int MyFunction(string text);
```

### Type Marshalling

Marshalling is the process of converting types between managed and unmanaged representations.

**Common Type Mappings:**

| C/C++ Type | .NET Type | Notes |
|------------|-----------|-------|
| `int` | `int` | Direct mapping |
| `unsigned int` | `uint` | Direct mapping |
| `long` (C) | `int` or `long` | Platform-dependent! |
| `void*` | `IntPtr` | Generic pointer |
| `char*` (ANSI) | `string` | Marshal as ANSI |
| `wchar_t*` (Unicode) | `string` | Marshal as Unicode |
| `struct` | `struct` with `[StructLayout]` | Explicit layout |
| `bool` | `[MarshalAs(UnmanagedType.Bool)] bool` | Size varies |
| `HANDLE` | `IntPtr` or `SafeHandle` | Use SafeHandle for safety |

**String Marshalling Options:**

```csharp
// ANSI strings (char*, LPStr)
[LibraryImport("mylib.dll", StringMarshalling = StringMarshalling.Custom, 
    StringMarshallingCustomType = typeof(AnsiStringMarshaller))]
static partial void FunctionA(string text);

// UTF-8 strings (common in cross-platform code)
[LibraryImport("mylib.dll", StringMarshalling = StringMarshalling.Utf8)]
static partial void FunctionB(string text);

// UTF-16 strings (wchar_t*, LPWStr, Windows default)
[LibraryImport("mylib.dll", StringMarshalling = StringMarshalling.Utf16)]
static partial void FunctionC(string text);
```

**Why String Marshalling Matters:**
- .NET strings are UTF-16 encoded
- C strings vary: ANSI, UTF-8, UTF-16 (Windows Unicode)
- Wrong encoding = corrupted text or crashes
- LibraryImport requires explicit choice

### Struct Marshalling

When passing structs to native code, you must specify their memory layout:

**C Struct:**
```c
typedef struct {
    int x;
    int y;
    wchar_t* name;
} Point;
```

**C# Equivalent:**
```csharp
[StructLayout(LayoutKind.Sequential, CharSet = CharSet.Unicode)]
public struct Point
{
    public int x;
    public int y;
    
    [MarshalAs(UnmanagedType.LPWStr)]
    public string name;
}

[LibraryImport("mylib.dll")]
static partial void ProcessPoint(Point pt);
```

**StructLayout Options:**

```csharp
// Sequential: Fields laid out in order (C default)
[StructLayout(LayoutKind.Sequential)]
struct MyStruct { }

// Explicit: Manually specify field offsets
[StructLayout(LayoutKind.Explicit)]
struct Union
{
    [FieldOffset(0)]
    public int intValue;
    
    [FieldOffset(0)]
    public float floatValue;
}

// Auto: .NET optimizes layout (NOT for interop!)
[StructLayout(LayoutKind.Auto)]  // ❌ Don't use for P/Invoke
struct BadForInterop { }
```

### Calling Conventions

Calling conventions define how arguments are passed and who cleans up the stack.

**Common Conventions:**

| Convention | Used By | Description |
|------------|---------|-------------|
| **Cdecl** | Unix, Linux, standard C | Caller cleans stack; variable args |
| **Stdcall** | Windows API (Win32) | Callee cleans stack; faster |
| **Fastcall** | Performance-critical | Some args in registers |
| **Thiscall** | C++ methods | Implicit `this` pointer |

**Platform Defaults:**
- **Windows x86:** `Stdcall` (Win32 API)
- **Linux x86:** `Cdecl`
- **x64 (all platforms):** Unified calling convention (both behave the same)

**Specifying Calling Convention:**

```csharp
// DllImport approach
[DllImport("mylib.dll", CallingConvention = CallingConvention.Cdecl)]
static extern int MyFunction(int x);

// LibraryImport approach (uses UnmanagedCallConv attribute)
[LibraryImport("mylib.dll")]
[UnmanagedCallConv(CallConvs = new[] { typeof(CallConvCdecl) })]
static partial int MyFunction(int x);
```

**Why It Matters:**
- Wrong calling convention = stack corruption and crashes
- Most Windows APIs use `Stdcall`
- Most Unix/Linux libraries use `Cdecl`
- x64 code usually doesn't need explicit specification

### Error Handling

**Getting Last Error (Windows):**

```csharp
[LibraryImport("kernel32.dll", SetLastError = true)]
private static partial IntPtr CreateFileW(/* parameters */);

static void OpenFile()
{
    IntPtr handle = CreateFileW(/* arguments */);
    
    if (handle == IntPtr.Zero || handle == new IntPtr(-1))
    {
        int errorCode = Marshal.GetLastWin32Error();
        throw new System.ComponentModel.Win32Exception(errorCode);
    }
}
```

**SetLastError Behavior:**
- Preserves the native error code
- Use `Marshal.GetLastWin32Error()` to retrieve it
- Essential for diagnosing native failures

### SafeHandle for Resource Management

**Problem with Raw IntPtr:**
```csharp
IntPtr handle = NativeOpen();
// If exception thrown here, resource leaks!
DoSomething();
NativeClose(handle);
```

**Solution: SafeHandle**
```csharp
public class MyResourceHandle : SafeHandleZeroOrMinusOneIsInvalid
{
    private MyResourceHandle() : base(ownsHandle: true) { }

    protected override bool ReleaseHandle()
    {
        // Called by finalizer - always runs
        return NativeClose(handle);
    }
    
    [LibraryImport("mylib.dll")]
    private static partial bool NativeClose(IntPtr handle);
}

// Usage
using (MyResourceHandle handle = NativeOpen())
{
    // Even if exception occurs, handle will be released
    DoSomething(handle);
}
```

**Benefits:**
- Automatic resource cleanup
- Exception-safe
- Works with finalizer (last resort)
- Critical for security (prevents resource leaks)

### Function Pointers and Callbacks

**Calling Native Code with Callbacks:**

**Native Function:**
```c
typedef void (*Callback)(int value);
void IterateWithCallback(Callback callback);
```

**C# Implementation:**
```csharp
// Define delegate matching native signature
[UnmanagedFunctionPointer(CallingConvention.Cdecl)]
delegate void CallbackDelegate(int value);

[LibraryImport("mylib.dll")]
[UnmanagedCallConv(CallConvs = new[] { typeof(CallConvCdecl) })]
static partial void IterateWithCallback(CallbackDelegate callback);

static void MyCallback(int value)
{
    Console.WriteLine($"Callback received: {value}");
}

static void Main()
{
    // CRITICAL: Keep delegate alive!
    CallbackDelegate callback = MyCallback;
    IterateWithCallback(callback);
    // callback must not be garbage collected during native execution
    GC.KeepAlive(callback);
}
```

**Important:** Delegates passed to native code must not be garbage collected while the native code might call them!

**Modern Function Pointers (C# 9+):**
```csharp
// Using unsafe function pointers
[LibraryImport("mylib.dll")]
static partial void IterateWithCallback(
    delegate* unmanaged[Cdecl]<int, void> callback
);

[UnmanagedCallersOnly(CallConvs = new[] { typeof(CallConvCdecl) })]
static void MyCallback(int value)
{
    Console.WriteLine($"Callback: {value}");
}

unsafe static void Main()
{
    // Get function pointer directly
    delegate* unmanaged[Cdecl]<int, void> ptr = &MyCallback;
    IterateWithCallback(ptr);
}
```

**Benefits of Function Pointers:**
- No delegate allocation
- No GC pressure
- Faster
- More explicit about calling convention

### Best Practices

**1. Prefer LibraryImport for New Code**
```csharp
✅ Modern (AOT-compatible)
[LibraryImport("mylib.dll", StringMarshalling = StringMarshalling.Utf8)]
static partial void MyFunction(string text);

❌ Legacy (avoid in new code)
[DllImport("mylib.dll", CharSet = CharSet.Unicode)]
static extern void MyFunction(string text);
```

**2. Use SafeHandle for Resources**
```csharp
✅ Safe (automatic cleanup)
class FileHandle : SafeHandleZeroOrMinusOneIsInvalid { /* ... */ }

❌ Unsafe (manual cleanup, leak-prone)
IntPtr handle = OpenFile();
// Must remember to close!
```

**3. Keep Delegates Alive**
```csharp
✅ Prevents GC
CallbackDelegate callback = MyMethod;
NativeFunction(callback);
GC.KeepAlive(callback);

❌ Delegate might be collected
NativeFunction(MyMethod);  // Inline delegate can be GC'd!
```

**4. Match Calling Conventions**
```csharp
✅ Explicit and correct
[UnmanagedCallConv(CallConvs = new[] { typeof(CallConvCdecl) })]
static partial void UnixFunction();

❌ Wrong convention = crash
[LibraryImport("unixlib.so")]  // Assumes default (might be wrong)
```

**5. Handle Errors Properly**
```csharp
✅ Check return values and get error codes
[LibraryImport("api.dll", SetLastError = true)]
static partial bool DoSomething();

if (!DoSomething())
{
    int error = Marshal.GetLastWin32Error();
    throw new Win32Exception(error);
}

❌ Ignore errors (silent failures)
DoSomething();  // Did it work? Who knows!
```

### Source Generation in Action

When you use LibraryImport, the source generator creates marshalling code:

**Your Code:**
```csharp
[LibraryImport("mylib.dll", StringMarshalling = StringMarshalling.Utf8)]
static partial int ProcessString(string input);
```

**Generated Code (conceptual):**
```csharp
static partial int ProcessString(string input)
{
    byte[] utf8Bytes = Encoding.UTF8.GetBytes(input + '\0');
    
    fixed (byte* ptr = utf8Bytes)
    {
        return __PInvoke(ptr);
    }
    
    [DllImport("mylib.dll", EntryPoint = "ProcessString")]
    static extern int __PInvoke(byte* input);
}
```

**Benefits:**
- Visible in IntelliSense (you can see generated code)
- Optimized at compile time
- No runtime overhead
- AOT-compatible

### Practical Example: File Operations

**Complete example using modern P/Invoke patterns:**

```csharp
using System;
using System.Runtime.InteropServices;
using Microsoft.Win32.SafeHandles;

// SafeHandle for file handles
public class SafeFileHandle : SafeHandleZeroOrMinusOneIsInvalid
{
    private SafeFileHandle() : base(ownsHandle: true) { }
    
    protected override bool ReleaseHandle()
    {
        return CloseHandle(handle);
    }
    
    [LibraryImport("kernel32.dll", SetLastError = true)]
    [return: MarshalAs(UnmanagedType.Bool)]
    private static partial bool CloseHandle(IntPtr handle);
}

public static class NativeFile
{
    const uint GENERIC_READ = 0x80000000;
    const uint OPEN_EXISTING = 3;
    
    [LibraryImport("kernel32.dll", SetLastError = true, 
        StringMarshalling = StringMarshalling.Utf16)]
    private static partial SafeFileHandle CreateFileW(
        string lpFileName,
        uint dwDesiredAccess,
        uint dwShareMode,
        IntPtr lpSecurityAttributes,
        uint dwCreationDisposition,
        uint dwFlagsAndAttributes,
        IntPtr hTemplateFile
    );
    
    public static SafeFileHandle OpenFile(string path)
    {
        SafeFileHandle handle = CreateFileW(
            path,
            GENERIC_READ,
            0,
            IntPtr.Zero,
            OPEN_EXISTING,
            0,
            IntPtr.Zero
        );
        
        if (handle.IsInvalid)
        {
            int error = Marshal.GetLastWin32Error();
            throw new System.ComponentModel.Win32Exception(error);
        }
        
        return handle;
    }
}

// Usage
using (SafeFileHandle handle = NativeFile.OpenFile(@"C:\test.txt"))
{
    // Use handle
    // Automatically closed when disposed
}
```
