# Lesson 3: Middleware and Request Pipeline

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand the ASP.NET Core request pipeline and how middleware components work
- Explain the order of execution in the middleware pipeline
- Create custom inline middleware using `Use`, `Map`, and `Run` methods
- Build reusable class-based middleware components
- Inject services into middleware using dependency injection
- Apply middleware conditionally based on environment or configuration
- Understand middleware short-circuiting and branching patterns
- Debug and troubleshoot common middleware issues

---

## Introduction

The middleware pipeline is the heart of ASP.NET Core applications. Every request that comes into your application flows through a series of middleware components, each performing specific tasks like authentication, routing, logging, or error handling. Understanding how to build and configure this pipeline is essential for creating robust, maintainable applications. This lesson covers everything from the fundamentals of middleware to advanced patterns for building custom components.

## Key Concepts Summary

### What is Middleware?

Middleware is software assembled into an application pipeline to handle requests and responses:

```
Request → [Middleware 1] → [Middleware 2] → [Middleware 3] → Endpoint
              ↓                ↓                ↓                ↓
Response ← [Middleware 1] ← [Middleware 2] ← [Middleware 3] ← Return
```

**Key Characteristics:**
- Each component can process the request before passing it to the next component
- Each component can process the response after the next component returns
- A component can choose to short-circuit (not call the next component)
- Order matters—middleware runs in the order it's added to the pipeline

### The Request Pipeline

**Typical Pipeline Structure:**

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// Middleware pipeline
app.UseExceptionHandler("/error");      // 1. Error handling
app.UseHttpsRedirection();              // 2. HTTPS redirection
app.UseStaticFiles();                   // 3. Static file serving
app.UseRouting();                       // 4. Routing
app.UseAuthentication();                // 5. Authentication
app.UseAuthorization();                 // 6. Authorization
app.MapControllers();                   // 7. Endpoint routing

app.Run();
```

**Request Flow:**
```
1. Request arrives → Exception Handler
2. → HTTPS Redirect (if HTTP)
3. → Static Files (if static file request, short-circuits here)
4. → Routing (matches endpoint)
5. → Authentication (who are you?)
6. → Authorization (what can you do?)
7. → Endpoint execution
8. ← Response flows back through all middleware
```

### Middleware Order Matters

**Correct Order (Authentication before Authorization):**
```csharp
✅ Correct:
app.UseAuthentication();  // First: Identify the user
app.UseAuthorization();   // Then: Check permissions

// Request flow:
// 1. User authenticated → Identity established
// 2. Authorization checks identity → Allow/Deny
```

**Incorrect Order (Authorization before Authentication):**
```csharp
❌ Wrong:
app.UseAuthorization();   // Authorization runs first
app.UseAuthentication();  // Identity set too late

// Request flow:
// 1. Authorization checks → No identity yet → Denied
// 2. Authentication runs → Identity set but too late
```

### Three Ways to Add Middleware

#### 1. Use - Chain to Next Middleware

```csharp
app.Use(async (context, next) =>
{
    // Code before next middleware
    Console.WriteLine("Before next");
    
    await next(context);  // Call next middleware
    
    // Code after next middleware (on response)
    Console.WriteLine("After next");
});
```

**When to Use:**
- Need to execute code before AND after the next middleware
- Want to modify request or response
- Don't want to terminate the pipeline

#### 2. Run - Terminal Middleware

```csharp
app.Run(async context =>
{
    // This terminates the pipeline
    await context.Response.WriteAsync("End of pipeline");
    // next() is NOT called
});
```

**When to Use:**
- At the end of the pipeline
- Want to terminate without calling further middleware
- Fallback/404 handlers

#### 3. Map - Branch the Pipeline

```csharp
// Branch for requests starting with /api
app.Map("/api", apiApp =>
{
    apiApp.UseAuthentication();
    apiApp.UseAuthorization();
    apiApp.MapControllers();
});

// Different branch for /admin
app.Map("/admin", adminApp =>
{
    adminApp.UseAuthentication();
    adminApp.UseAuthorization();
    // Admin-specific middleware
    adminApp.MapRazorPages();
});
```

**When to Use:**
- Different pipeline for different routes
- Conditional middleware based on path
- Organizing large applications

### Creating Inline Middleware

**Basic Inline Middleware:**

```csharp
app.Use(async (context, next) =>
{
    // Access request
    var path = context.Request.Path;
    var method = context.Request.Method;
    
    Console.WriteLine($"{method} {path}");
    
    // Call next
    await next(context);
    
    // Access response
    var statusCode = context.Response.StatusCode;
    Console.WriteLine($"Response: {statusCode}");
});
```

**Request Timing Middleware:**

```csharp
app.Use(async (context, next) =>
{
    var sw = System.Diagnostics.Stopwatch.StartNew();
    
    await next(context);
    
    sw.Stop();
    var elapsed = sw.ElapsedMilliseconds;
    
    context.Response.Headers.Add("X-Response-Time", $"{elapsed}ms");
});
```

**Custom Header Middleware:**

```csharp
app.Use(async (context, next) =>
{
    // Add custom header to all responses
    context.Response.OnStarting(() =>
    {
        context.Response.Headers.Add("X-Custom-Header", "MyValue");
        return Task.CompletedTask;
    });
    
    await next(context);
});
```

### Creating Class-Based Middleware

**Convention-Based Middleware:**

```csharp
public class RequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestLoggingMiddleware> _logger;

    // Constructor: RequestDelegate is required
    // Other parameters are injected from DI
    public RequestLoggingMiddleware(
        RequestDelegate next,
        ILogger<RequestLoggingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    // InvokeAsync or Invoke method is required
    // HttpContext is required, other parameters injected per-request
    public async Task InvokeAsync(HttpContext context)
    {
        _logger.LogInformation(
            "Request: {Method} {Path}",
            context.Request.Method,
            context.Request.Path);

        await _next(context);

        _logger.LogInformation(
            "Response: {StatusCode}",
            context.Response.StatusCode);
    }
}
```

**Extension Method for Registration:**

```csharp
public static class RequestLoggingMiddlewareExtensions
{
    public static IApplicationBuilder UseRequestLogging(
        this IApplicationBuilder builder)
    {
        return builder.UseMiddleware<RequestLoggingMiddleware>();
    }
}

// Usage:
app.UseRequestLogging();
```

### Factory-Based Middleware

For more control over lifetime and dependencies:

```csharp
public class MyFactoryMiddleware : IMiddleware
{
    private readonly ILogger<MyFactoryMiddleware> _logger;

    public MyFactoryMiddleware(ILogger<MyFactoryMiddleware> logger)
    {
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context, RequestDelegate next)
    {
        _logger.LogInformation("Factory middleware executing");
        await next(context);
    }
}

// Registration (must register in DI):
builder.Services.AddTransient<MyFactoryMiddleware>();

// Usage:
app.UseMiddleware<MyFactoryMiddleware>();
```

**Difference from Convention-Based:**
- Must implement `IMiddleware` interface
- Must be registered in DI container
- Instance is created per-request (if registered as transient)
- Easier to test
- Better for complex dependencies

### Dependency Injection in Middleware

#### Constructor Injection (Singleton Services Only)

```csharp
public class MyMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger _logger;          // ✅ Singleton
    private readonly IConfiguration _config;   // ✅ Singleton

    public MyMiddleware(
        RequestDelegate next,
        ILogger<MyMiddleware> logger,
        IConfiguration config)
    {
        _next = next;
        _logger = logger;
        _config = config;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // Use _logger and _config
        await _next(context);
    }
}
```

**Warning:** Middleware constructors are called once at startup. Only inject singleton services in constructors!

#### Method Injection (Scoped Services)

```csharp
public class MyMiddleware
{
    private readonly RequestDelegate _next;

    public MyMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    // Scoped services injected per-request
    public async Task InvokeAsync(
        HttpContext context,
        IMyService service,           // ✅ Scoped service
        IRepository repository)        // ✅ Scoped service
    {
        // Use service and repository (per-request instances)
        var data = await repository.GetDataAsync();
        await service.ProcessAsync(data);
        
        await _next(context);
    }
}
```

### Common Middleware Patterns

#### 1. Request/Response Logging

```csharp
public class RequestResponseLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger _logger;

    public RequestResponseLoggingMiddleware(
        RequestDelegate next,
        ILogger<RequestResponseLoggingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // Log request
        _logger.LogInformation(
            "HTTP {Method} {Path} started",
            context.Request.Method,
            context.Request.Path);

        var sw = Stopwatch.StartNew();

        try
        {
            await _next(context);
        }
        finally
        {
            sw.Stop();
            
            // Log response
            _logger.LogInformation(
                "HTTP {Method} {Path} responded {StatusCode} in {Elapsed}ms",
                context.Request.Method,
                context.Request.Path,
                context.Response.StatusCode,
                sw.ElapsedMilliseconds);
        }
    }
}
```

#### 2. API Key Validation

```csharp
public class ApiKeyMiddleware
{
    private readonly RequestDelegate _next;
    private const string ApiKeyHeader = "X-Api-Key";

    public ApiKeyMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(HttpContext context, IConfiguration config)
    {
        // Skip validation for certain paths
        if (context.Request.Path.StartsWithSegments("/health"))
        {
            await _next(context);
            return;
        }

        if (!context.Request.Headers.TryGetValue(ApiKeyHeader, out var extractedApiKey))
        {
            context.Response.StatusCode = 401;
            await context.Response.WriteAsync("API Key missing");
            return;
        }

        var apiKey = config.GetValue<string>("ApiKey");
        
        if (!apiKey.Equals(extractedApiKey))
        {
            context.Response.StatusCode = 401;
            await context.Response.WriteAsync("Invalid API Key");
            return;
        }

        await _next(context);
    }
}
```

#### 3. Correlation ID

```csharp
public class CorrelationIdMiddleware
{
    private readonly RequestDelegate _next;
    private const string CorrelationIdHeader = "X-Correlation-ID";

    public CorrelationIdMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // Get or generate correlation ID
        var correlationId = context.Request.Headers[CorrelationIdHeader].FirstOrDefault()
            ?? Guid.NewGuid().ToString();

        // Add to response headers
        context.Response.Headers.Add(CorrelationIdHeader, correlationId);

        // Store in context for logging
        context.Items["CorrelationId"] = correlationId;

        await _next(context);
    }
}
```

#### 4. Exception Handling

```csharp
public class GlobalExceptionMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger _logger;

    public GlobalExceptionMiddleware(
        RequestDelegate next,
        ILogger<GlobalExceptionMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Unhandled exception occurred");
            await HandleExceptionAsync(context, ex);
        }
    }

    private static Task HandleExceptionAsync(HttpContext context, Exception exception)
    {
        var statusCode = exception switch
        {
            ArgumentException => StatusCodes.Status400BadRequest,
            UnauthorizedAccessException => StatusCodes.Status401Unauthorized,
            KeyNotFoundException => StatusCodes.Status404NotFound,
            _ => StatusCodes.Status500InternalServerError
        };

        context.Response.StatusCode = statusCode;
        context.Response.ContentType = "application/json";

        var response = new
        {
            error = exception.Message,
            statusCode = statusCode
        };

        return context.Response.WriteAsJsonAsync(response);
    }
}
```

### Conditional Middleware

#### Environment-Based

```csharp
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
    app.UseSwagger();
    app.UseSwaggerUI();
}
else
{
    app.UseExceptionHandler("/error");
    app.UseHsts();
}
```

#### Configuration-Based

```csharp
if (builder.Configuration.GetValue<bool>("EnableRequestLogging"))
{
    app.UseRequestLogging();
}
```

#### Path-Based (Branching)

```csharp
// Only apply to /api routes
app.UseWhen(
    context => context.Request.Path.StartsWithSegments("/api"),
    appBuilder =>
    {
        appBuilder.UseApiKeyValidation();
        appBuilder.UseRateLimiting();
    });
```

### Short-Circuiting the Pipeline

**Example: Static Files Short-Circuit**

```csharp
app.UseStaticFiles();  // If request is for static file, short-circuits here

// These middleware never run for static files:
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
```

**Custom Short-Circuit:**

```csharp
app.Use(async (context, next) =>
{
    // Health check endpoint - short circuit
    if (context.Request.Path == "/health")
    {
        context.Response.StatusCode = 200;
        await context.Response.WriteAsync("Healthy");
        return;  // Don't call next()
    }

    await next(context);
});
```

### Reading Request Body

**Important:** Request body can only be read once by default!

```csharp
public async Task InvokeAsync(HttpContext context)
{
    // Enable buffering to allow multiple reads
    context.Request.EnableBuffering();

    // Read body
    using var reader = new StreamReader(
        context.Request.Body,
        leaveOpen: true);  // Don't dispose the stream
    
    var body = await reader.ReadToEndAsync();
    
    // Reset position for next middleware
    context.Request.Body.Position = 0;

    // Process body
    Console.WriteLine($"Request body: {body}");

    await _next(context);
}
```

### Modifying Response Body

```csharp
public async Task InvokeAsync(HttpContext context)
{
    // Capture original response body stream
    var originalBodyStream = context.Response.Body;

    // Create new memory stream
    using var responseBody = new MemoryStream();
    context.Response.Body = responseBody;

    // Execute next middleware
    await _next(context);

    // Read response
    responseBody.Seek(0, SeekOrigin.Begin);
    var responseText = await new StreamReader(responseBody).ReadToEndAsync();

    // Modify response
    var modifiedResponse = $"{{\"wrapped\": {responseText}}}";

    // Write modified response to original stream
    responseBody.Seek(0, SeekOrigin.Begin);
    await responseBody.CopyToAsync(originalBodyStream);
}
```

### Middleware Best Practices

**1. Order Matters**
```csharp
✅ Correct order:
app.UseExceptionHandler();    // 1. Catch exceptions
app.UseHttpsRedirection();    // 2. Redirect to HTTPS
app.UseStaticFiles();         // 3. Serve static files (can short-circuit)
app.UseRouting();             // 4. Route matching
app.UseAuthentication();      // 5. Who are you?
app.UseAuthorization();       // 6. What can you do?
app.MapControllers();         // 7. Execute endpoint
```

**2. Use Extension Methods**
```csharp
✅ Good: Clean, discoverable
public static class MyMiddlewareExtensions
{
    public static IApplicationBuilder UseMyMiddleware(this IApplicationBuilder app)
    {
        return app.UseMiddleware<MyMiddleware>();
    }
}
```

**3. Inject Scoped Services via InvokeAsync**
```csharp
✅ Correct:
public async Task InvokeAsync(
    HttpContext context,
    DbContext db)  // Scoped service
{
    // Use db
}

❌ Wrong:
public MyMiddleware(
    RequestDelegate next,
    DbContext db)  // DbContext is scoped, not singleton!
{
    // This will fail!
}
```

**4. Handle Exceptions**
```csharp
✅ Good: Always handle exceptions
public async Task InvokeAsync(HttpContext context)
{
    try
    {
        await _next(context);
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Error in middleware");
        throw;  // Or handle gracefully
    }
}
```

**5. Use OnStarting for Headers**
```csharp
✅ Correct: Headers added before response starts
context.Response.OnStarting(() =>
{
    context.Response.Headers.Add("X-Custom", "Value");
    return Task.CompletedTask;
});
```
