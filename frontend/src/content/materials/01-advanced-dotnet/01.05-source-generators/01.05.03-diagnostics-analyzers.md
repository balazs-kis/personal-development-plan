# Lesson 3: Emitting Diagnostics and Working with Analyzers

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand how to emit diagnostics (warnings, errors, info) from source generators
- Create and configure DiagnosticDescriptor instances
- Differentiate between source generators and Roslyn analyzers
- Combine source generators with analyzers for comprehensive tooling
- Report diagnostics at appropriate locations in source code
- Apply severity levels and diagnostic categories correctly
- Understand diagnostic IDs and suppression mechanisms

---

## Introduction

Source generators don't just generate code—they can also communicate with developers through diagnostics. Whether it's warning about incorrect attribute usage, reporting errors in configuration, or providing informational messages, diagnostics make your generators more helpful and user-friendly. Understanding how to emit proper diagnostics, and when to combine generators with analyzers, is crucial for building production-quality tooling.

## Key Concepts Summary

### Source Generators vs Analyzers

**Source Generators:**
```
Purpose:     Generate additional source code
When:        During compilation
Output:      .cs files added to compilation
Can:         Read code, generate code, emit diagnostics
Cannot:      Modify existing code
```

**Analyzers:**
```
Purpose:     Analyze code for issues and violations
When:        During compilation AND in IDE (live)
Output:      Diagnostics (warnings, errors, info)
Can:         Analyze code, emit diagnostics, suggest code fixes
Cannot:      Generate new files or modify code directly
```

**Code Fixes (companion to Analyzers):**
```
Purpose:     Automatically fix issues found by analyzers
When:        User invokes (light bulb, Ctrl+.)
Output:      Modified code
Can:         Modify existing code, add/remove code
Cannot:      Generate new files
```

**When to Use Each:**

| Scenario | Tool |
|----------|------|
| Generate boilerplate code | Source Generator |
| Report style violations | Analyzer |
| Report incorrect attribute usage | Generator (diagnostics) OR Analyzer |
| Auto-fix code issues | Analyzer + Code Fix |
| Add missing using directives | Analyzer + Code Fix |
| Generate serialization code | Source Generator |
| Enforce naming conventions | Analyzer |

### Emitting Diagnostics from Generators

#### Creating a DiagnosticDescriptor

```csharp
using Microsoft.CodeAnalysis;

public class MyGenerator : IIncrementalGenerator
{
    // Define diagnostic descriptors as static fields
    private static readonly DiagnosticDescriptor MissingPartialModifier = new(
        id: "MYGEN001",
        title: "Class must be partial",
        messageFormat: "Class '{0}' must be marked as partial to use [AutoNotify]",
        category: "MyGenerator.Usage",
        defaultSeverity: DiagnosticSeverity.Error,
        isEnabledByDefault: true,
        description: "The AutoNotify attribute requires classes to be partial so the generator can add members."
    );
    
    private static readonly DiagnosticDescriptor NoPropertiesFound = new(
        id: "MYGEN002",
        title: "No properties to generate",
        messageFormat: "Class '{0}' has [AutoNotify] but no private fields were found",
        category: "MyGenerator.Usage",
        defaultSeverity: DiagnosticSeverity.Warning,
        isEnabledByDefault: true
    );
}
```

**DiagnosticDescriptor Properties:**

| Property | Description | Example |
|----------|-------------|---------|
| **id** | Unique diagnostic code | "MYGEN001", "SYSLIB1001" |
| **title** | Short summary | "Class must be partial" |
| **messageFormat** | Template with placeholders | "Class '{0}' must be marked as partial" |
| **category** | Grouping category | "MyGenerator.Usage" |
| **defaultSeverity** | Error, Warning, Info, Hidden | DiagnosticSeverity.Error |
| **isEnabledByDefault** | Enabled out of the box | true |
| **description** | Detailed explanation | "The AutoNotify attribute requires..." |
| **helpLinkUri** | Link to docs | "https://docs.example.com/MYGEN001" |

#### Reporting Diagnostics

```csharp
public void Initialize(IncrementalGeneratorInitializationContext context)
{
    var classDeclarations = context.SyntaxProvider
        .ForAttributeWithMetadataName(
            "MyNamespace.AutoNotifyAttribute",
            predicate: (node, _) => node is ClassDeclarationSyntax,
            transform: GetClassInfo
        );

    context.RegisterSourceOutput(classDeclarations,
        (spc, classInfo) => Generate(classInfo, spc));
}

static void Generate(ClassInfo classInfo, SourceProductionContext context)
{
    // Check if class is partial
    if (!classInfo.IsPartial)
    {
        // Report error at the class location
        var diagnostic = Diagnostic.Create(
            MissingPartialModifier,
            classInfo.Location,
            classInfo.Name
        );
        
        context.ReportDiagnostic(diagnostic);
        return; // Don't generate code
    }
    
    // Check if there are properties to generate
    if (classInfo.Fields.Length == 0)
    {
        // Report warning
        var diagnostic = Diagnostic.Create(
            NoPropertiesFound,
            classInfo.Location,
            classInfo.Name
        );
        
        context.ReportDiagnostic(diagnostic);
        return;
    }
    
    // Generate code...
    context.AddSource($"{classInfo.Name}.g.cs", GenerateCode(classInfo));
}
```

### Diagnostic Severity Levels

```csharp
// Error: Prevents compilation
DiagnosticSeverity.Error
// Show: Red squiggly, stops build

// Warning: Compilation succeeds but issue reported
DiagnosticSeverity.Warning
// Show: Yellow/orange squiggly, shows in error list

// Info: Informational message
DiagnosticSeverity.Info
// Show: Blue squiggly, shows in error list

// Hidden: Not visible by default (used for code fixes)
DiagnosticSeverity.Hidden
// Show: Only visible in IDE under certain conditions
```

**When to Use Each:**

```csharp
// ERROR: Code won't work without fixing this
// - Missing required attribute properties
// - Class not marked partial when required
// - Invalid configuration that prevents generation

// WARNING: Code might work but is suspicious
// - Unused attributes
// - Deprecated patterns
// - Performance concerns

// INFO: Helpful information
// - Successfully generated code
// - Alternative approaches available
// - Optimization opportunities

// HIDDEN: For refactorings/code fixes only
// - Not shown as diagnostics
// - Only surfaces with code fix actions
```

### Diagnostic Location and Span

#### Report at Class Declaration

```csharp
// Highlight the entire class
var diagnostic = Diagnostic.Create(
    descriptor,
    classDeclaration.GetLocation(),
    className
);
```

#### Report at Attribute

```csharp
// Highlight just the attribute
var attributeLocation = classDeclaration.AttributeLists
    .SelectMany(al => al.Attributes)
    .First(a => a.Name.ToString().Contains("AutoNotify"))
    .GetLocation();

var diagnostic = Diagnostic.Create(
    descriptor,
    attributeLocation,
    className
);
```

#### Report at Specific Token

```csharp
// Highlight just the class name
var identifierLocation = classDeclaration.Identifier.GetLocation();

var diagnostic = Diagnostic.Create(
    descriptor,
    identifierLocation,
    className
);
```

#### Report at Custom Location (from Semantic Model)

```csharp
static ClassInfo GetClassInfo(GeneratorAttributeSyntaxContext context)
{
    var classSymbol = (INamedTypeSymbol)context.TargetSymbol;
    
    // Get location of the symbol (works across partial classes)
    var location = classSymbol.Locations.FirstOrDefault();
    
    return new ClassInfo
    {
        Name = classSymbol.Name,
        Location = location,
        // ...
    };
}
```

### Standard Diagnostic ID Conventions

**Official .NET Diagnostics:**
```
Compiler errors:       CS0001 - CS9999
Compiler warnings:     CS0001 - CS9999
Analyzer diagnostics:  CAxxxx (Code Analysis)
SYSLIB diagnostics:    SYSLIB1001 - SYSLIB1999
```

**Your Generator Diagnostics:**
```
Format:  [PREFIX][NUMBER]

Examples:
- MYGEN001, MYGEN002, ...    (MyGenerator)
- AUTMAP100, AUTMAP101, ...  (AutoMapper)
- RGEN001, RGEN002, ...      (RegexGenerator)

Best Practices:
- Use 3-4 digits for readability
- Reserve ranges for categories:
  - 001-099: Usage errors
  - 100-199: Configuration errors
  - 200-299: Performance warnings
  - 300-399: Informational
```

### Combining Generators with Analyzers

**Architecture Pattern:**

```
Generator Package (NuGet)
├─ Generator DLL
│  └─ Generates code + basic diagnostics
└─ Analyzer DLL
   └─ Validates usage + provides code fixes
```

**Example: JSON Serializer Generator + Analyzer**

```csharp
// Generator: Creates serialization code
[Generator]
public class JsonGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // Generate serialization methods
        // Report errors if types can't be serialized
    }
}

// Analyzer: Validates attribute usage
[DiagnosticAnalyzer(LanguageNames.CSharp)]
public class JsonAnalyzer : DiagnosticAnalyzer
{
    public override void Initialize(AnalysisContext context)
    {
        // Check for common mistakes
        // Warn about performance issues
        // Suggest optimizations
    }
}

// Code Fix: Automatically fixes issues
[ExportCodeFixProvider(LanguageNames.CSharp)]
public class JsonCodeFixProvider : CodeFixProvider
{
    public override Task RegisterCodeFixesAsync(CodeFixContext context)
    {
        // Offer to add missing [JsonSerializable] attributes
        // Offer to make classes partial
        // Offer to add required properties
    }
}
```

### Creating an Analyzer (Quick Overview)

```csharp
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.Diagnostics;

[DiagnosticAnalyzer(LanguageNames.CSharp)]
public class AutoNotifyAnalyzer : DiagnosticAnalyzer
{
    private static readonly DiagnosticDescriptor Rule = new(
        "MYGEN001",
        "Class must be partial",
        "Class '{0}' with [AutoNotify] must be partial",
        "Usage",
        DiagnosticSeverity.Error,
        true
    );

    public override ImmutableArray<DiagnosticDescriptor> SupportedDiagnostics =>
        ImmutableArray.Create(Rule);

    public override void Initialize(AnalysisContext context)
    {
        context.ConfigureGeneratedCodeAnalysis(
            GeneratedCodeAnalysisFlags.None);
        context.EnableConcurrentExecution();

        // Register syntax node action
        context.RegisterSyntaxNodeAction(AnalyzeClass, SyntaxKind.ClassDeclaration);
    }

    private void AnalyzeClass(SyntaxNodeAnalysisContext context)
    {
        var classDecl = (ClassDeclarationSyntax)context.Node;
        
        // Check if has AutoNotify attribute
        bool hasAttribute = classDecl.AttributeLists
            .SelectMany(al => al.Attributes)
            .Any(a => a.Name.ToString().Contains("AutoNotify"));
        
        if (!hasAttribute)
            return;
        
        // Check if partial
        bool isPartial = classDecl.Modifiers.Any(m => m.IsKind(SyntaxKind.PartialKeyword));
        
        if (!isPartial)
        {
            var diagnostic = Diagnostic.Create(
                Rule,
                classDecl.Identifier.GetLocation(),
                classDecl.Identifier.Text
            );
            
            context.ReportDiagnostic(diagnostic);
        }
    }
}
```

### Suppressing Diagnostics

**Users can suppress diagnostics multiple ways:**

**1. Using #pragma**
```csharp
#pragma warning disable MYGEN001
[AutoNotify]
public class MyClass { }
#pragma warning restore MYGEN001
```

**2. Using [SuppressMessage]**
```csharp
[SuppressMessage("MyGenerator.Usage", "MYGEN001", Justification = "Legacy code")]
[AutoNotify]
public class MyClass { }
```

**3. Using .editorconfig**
```ini
# Suppress specific diagnostic
dotnet_diagnostic.MYGEN001.severity = none

# Change severity
dotnet_diagnostic.MYGEN002.severity = suggestion
```

**4. Using project-level NoWarn**
```xml
<PropertyGroup>
  <NoWarn>$(NoWarn);MYGEN001;MYGEN002</NoWarn>
</PropertyGroup>
```

### Best Practices for Diagnostics

#### 1. Clear, Actionable Messages

```csharp
❌ Bad:
"Invalid usage"

✅ Good:
"Class '{0}' must be marked as partial to use [AutoNotify]. Add the 'partial' keyword to the class declaration."
```

#### 2. Provide Help Links

```csharp
private static readonly DiagnosticDescriptor Rule = new(
    id: "MYGEN001",
    title: "Class must be partial",
    messageFormat: "Class '{0}' must be partial",
    category: "Usage",
    defaultSeverity: DiagnosticSeverity.Error,
    isEnabledByDefault: true,
    description: "Detailed explanation here",
    helpLinkUri: "https://github.com/me/mygenerator/docs/MYGEN001.md"
);
```

#### 3. Use Appropriate Severity

```csharp
// Will code fail at runtime? → Error
// Will code work but is problematic? → Warning
// Helpful suggestion? → Info
```

#### 4. Report at the Right Location

```csharp
❌ Bad: Report at arbitrary location
var diagnostic = Diagnostic.Create(descriptor, Location.None);

✅ Good: Report at exact problem location
var diagnostic = Diagnostic.Create(descriptor, classDecl.Identifier.GetLocation());
```

#### 5. Include Context in Message

```csharp
// Use placeholders for dynamic information
messageFormat: "Property '{0}' of type '{1}' cannot be auto-implemented"

// Provide context
context.ReportDiagnostic(
    Diagnostic.Create(descriptor, location, propertyName, propertyType)
);
```

### Diagnostic Categories

Organize diagnostics into logical categories:

```csharp
// Usage errors (incorrect API usage)
category: "MyGenerator.Usage"
// MYGEN001: Missing partial modifier
// MYGEN002: Invalid attribute target

// Design issues (code quality)
category: "MyGenerator.Design"
// MYGEN100: Inefficient pattern detected
// MYGEN101: Consider using alternative approach

// Performance warnings
category: "MyGenerator.Performance"
// MYGEN200: Large collection may cause GC pressure
// MYGEN201: Avoid reflection in hot path

// Compatibility issues
category: "MyGenerator.Compatibility"
// MYGEN300: Not compatible with Native AOT
// MYGEN301: Requires .NET 6+
```

### Testing Diagnostics

```csharp
[Fact]
public void Generator_ReportsError_WhenClassNotPartial()
{
    var source = """
        [AutoNotify]
        public class Person  // Missing 'partial'
        {
            private string _name;
        }
        """;

    var (diagnostics, _) = RunGenerator(source);

    // Assert error was reported
    Assert.Single(diagnostics);
    var diagnostic = diagnostics[0];
    Assert.Equal("MYGEN001", diagnostic.Id);
    Assert.Equal(DiagnosticSeverity.Error, diagnostic.Severity);
    Assert.Contains("partial", diagnostic.GetMessage());
}

[Fact]
public void Generator_ReportsWarning_WhenNoFieldsFound()
{
    var source = """
        [AutoNotify]
        public partial class Person
        {
            // No fields!
        }

    var (diagnostics, _) = RunGenerator(source);

    Assert.Single(diagnostics);
    var diagnostic = diagnostics[0];
    Assert.Equal("MYGEN002", diagnostic.Id);
    Assert.Equal(DiagnosticSeverity.Warning, diagnostic.Severity);
}
```

### Real-World Example: Complete Diagnostic Flow

```csharp
[Generator]
public class AutoNotifyGenerator : IIncrementalGenerator
{
    // Diagnostic descriptors
    private static readonly DiagnosticDescriptor MissingPartial = new(
        "AN001",
        "Class must be partial",
        "Class '{0}' must be marked as partial",
        "Usage",
        DiagnosticSeverity.Error,
        true,
        "Classes using [AutoNotify] must be partial so the generator can add properties.",
        "https://github.com/example/docs/AN001"
    );

    private static readonly DiagnosticDescriptor NoFields = new(
        "AN002",
        "No fields to process",
        "Class '{0}' has no private fields to generate properties for",
        "Usage",
        DiagnosticSeverity.Warning,
        true
    );

    private static readonly DiagnosticDescriptor FieldNamingConvention = new(
        "AN100",
        "Field naming convention",
        "Field '{0}' should start with underscore for property generation",
        "Design",
        DiagnosticSeverity.Info,
        true
    );

    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        var classes = context.SyntaxProvider
            .ForAttributeWithMetadataName(
                "AutoNotify.AutoNotifyAttribute",
                (node, _) => node is ClassDeclarationSyntax,
                GetClassInfo
            )
            .Where(c => c != null);

        context.RegisterSourceOutput(classes, Execute);
    }

    static void Execute(SourceProductionContext context, ClassInfo classInfo)
    {
        // Validation 1: Must be partial
        if (!classInfo.IsPartial)
        {
            context.ReportDiagnostic(Diagnostic.Create(
                MissingPartial,
                classInfo.Location,
                classInfo.Name
            ));
            return;
        }

        // Validation 2: Must have fields
        if (classInfo.Fields.Length == 0)
        {
            context.ReportDiagnostic(Diagnostic.Create(
                NoFields,
                classInfo.Location,
                classInfo.Name
            ));
            return;
        }

        // Informational: Check naming conventions
        foreach (var field in classInfo.Fields)
        {
            if (!field.Name.StartsWith("_"))
            {
                context.ReportDiagnostic(Diagnostic.Create(
                    FieldNamingConvention,
                    field.Location,
                    field.Name
                ));
            }
        }

        // All good, generate code
        var source = GenerateCode(classInfo);
        context.AddSource($"{classInfo.Name}.g.cs", source);
    }
}
```
