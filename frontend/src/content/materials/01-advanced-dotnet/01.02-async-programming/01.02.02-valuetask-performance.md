## Introduction

While `Task<T>` is the standard return type for async methods, it always allocates on the heap. In high-throughput scenarios where async operations often complete synchronously (like cache hits or pooled objects), these allocations add up. `ValueTask<T>` is a struct that can wrap either a completed result or a Task, eliminating allocations when operations complete synchronously. This lesson explores when and how to use ValueTask for optimal performance.

## Key Concepts Summary

### Task vs ValueTask: The Core Difference

| Aspect | Task<T> | ValueTask<T> |
|--------|---------|--------------|
| **Type** | Reference type (class) | Value type (struct) |
| **Allocation** | Always allocates on heap | Zero allocations if completed synchronously |
| **Caching** | Built-in for completed tasks | No caching (creates new struct each time) |
| **Multiple awaits** | ✅ Safe | ⚠️ Only await once |
| **Storing in fields** | ✅ Safe | ❌ Not recommended |
| **WhenAll/WhenAny** | ✅ Supported | ✅ Supported (via AsTask()) |
| **Primary use case** | General async operations | Hot paths with frequent sync completion |

### When to Use ValueTask

**✅ Use ValueTask when:**
- Operations frequently complete synchronously (cache hits, pooled objects)
- You're in a hot path with thousands/millions of calls
- You've profiled and confirmed allocations are a problem
- The operation will only be awaited once

**❌ Use Task when:**
- Writing typical application code
- Operations rarely complete synchronously
- Simplicity and clarity are more important than micro-optimizations
- You need to await the result multiple times

### How ValueTask Works

ValueTask is a discriminated union that can hold either a result or a Task:

```csharp
public readonly struct ValueTask<T>
{
    private readonly object? _obj; // Could be Task<T> or IValueTaskSource<T>
    private readonly T _result;    // Direct result if completed synchronously
    private readonly bool _continueOnCapturedContext;
    private readonly short _token; // For IValueTaskSource validation
    
    // Simplified implementation
}
```

**Synchronous Completion (no allocation):**
```csharp
public ValueTask<int> GetCachedValueAsync(string key)
{
    if (_cache.TryGetValue(key, out int value))
    {
        // Completes synchronously - wraps value directly
        return new ValueTask<int>(value);
    }
    
    // Completes asynchronously - wraps Task
    return new ValueTask<int>(FetchFromDatabaseAsync(key));
}
```

### Real-World Example: Caching

```csharp
public class UserService
{
    private readonly ConcurrentDictionary<int, User> _cache = new();
    private readonly IUserRepository _repository;
    
    // ❌ Task - always allocates even for cache hits
    public async Task<User> GetUserTaskAsync(int id)
    {
        if (_cache.TryGetValue(id, out var user))
            return user; // Still allocates Task<User>
            
        user = await _repository.GetUserAsync(id);
        _cache.TryAdd(id, user);
        return user;
    }
    
    // ✅ ValueTask - zero allocations for cache hits
    public ValueTask<User> GetUserValueTaskAsync(int id)
    {
        if (_cache.TryGetValue(id, out var user))
            return new ValueTask<User>(user); // No allocation!
            
        return new ValueTask<User>(FetchAndCacheAsync(id));
    }
    
    private async Task<User> FetchAndCacheAsync(int id)
    {
        var user = await _repository.GetUserAsync(id);
        _cache.TryAdd(id, user);
        return user;
    }
}
```

**Performance Impact:**
- Task version: Allocates Task<User> on every call (24-32 bytes + GC pressure)
- ValueTask version: Zero allocations for cache hits (just stack allocation of the struct)

### ValueTask Restrictions

**⚠️ Critical Rules:**

1. **Await only once**
   ```csharp
   ValueTask<int> vt = GetValueAsync();
   int result1 = await vt; // ✅ First await
   int result2 = await vt; // ❌ UNDEFINED BEHAVIOR!
   ```

2. **Don't store in fields or collections**
   ```csharp
   // ❌ DON'T DO THIS
   private ValueTask<int> _pendingOperation;
   
   // ✅ Store the Task instead if needed
   private Task<int> _pendingOperation;
   ```

3. **Don't use .Result or .GetAwaiter().GetResult() multiple times**
   ```csharp
   ValueTask<int> vt = GetValueAsync();
   int result = vt.Result; // ⚠️ Risky
   // later...
   result = vt.Result; // ❌ UNDEFINED BEHAVIOR!
   ```

4. **Convert to Task if needed for multiple awaits**
   ```csharp
   ValueTask<int> vt = GetValueAsync();
   Task<int> task = vt.AsTask(); // Now safe for multiple awaits
   
   int result1 = await task;
   int result2 = await task; // ✅ Safe now
   ```

### IValueTaskSource: Advanced Optimization

For ultimate performance, implement `IValueTaskSource<T>` with object pooling:

```csharp
public class PooledValueTaskSource<T> : IValueTaskSource<T>
{
    private static readonly ObjectPool<PooledValueTaskSource<T>> Pool = 
        new DefaultObjectPool<PooledValueTaskSource<T>>(
            new DefaultPooledObjectPolicy<PooledValueTaskSource<T>>());
    
    private ManualResetValueTaskSourceCore<T> _core;
    
    public static PooledValueTaskSource<T> Rent()
    {
        var source = Pool.Get();
        return source;
    }
    
    public void SetResult(T result)
    {
        _core.SetResult(result);
    }
    
    public void SetException(Exception error)
    {
        _core.SetException(error);
    }
    
    public T GetResult(short token)
    {
        try
        {
            return _core.GetResult(token);
        }
        finally
        {
            _core.Reset();
            Pool.Return(this);
        }
    }
    
    public ValueTaskSourceStatus GetStatus(short token) => 
        _core.GetStatus(token);
    
    public void OnCompleted(Action<object?> continuation, object? state, 
        short token, ValueTaskSourceOnCompletedFlags flags) => 
        _core.OnCompleted(continuation, state, token, flags);
}
```

```csharp
[MemoryDiagnoser]
public class TaskVsValueTaskBenchmark
{
    private readonly Dictionary<int, string> _cache = new()
    {
        [1] = "Cached Value"
    };
    
    [Benchmark(Baseline = true)]
    public async Task<string> Task_CacheHit()

    }

        return await GetWithValueTaskAsync(1);
    }
    
    private async Task<string> GetWithTaskAsync(int id)
    {

            return value;

    private ValueTask<string> GetWithValueTaskAsync(int id)
```

### Common Patterns

#### 1. Caching Layer
```csharp
public class CachedDataService
{
    private readonly IMemoryCache _cache;
    private readonly IDataRepository _repository;
    
    public ValueTask<Data> GetDataAsync(string key)
    {
        if (_cache.TryGetValue(key, out Data data))
        {
            return new ValueTask<Data>(data);
        }
        
        return new ValueTask<Data>(FetchAndCacheAsync(key));
    }
    
    private async Task<Data> FetchAndCacheAsync(string key)
    {
        var data = await _repository.GetAsync(key);
        _cache.Set(key, data, TimeSpan.FromMinutes(5));
        return data;
    }
}
```

#### 2. Object Pool Pattern
```csharp
public class PooledResourceService
{
    private readonly ObjectPool<Resource> _pool;
    
    public ValueTask<Resource> GetResourceAsync()
    {
        var resource = _pool.Get();
        if (resource.IsReady)
        {
            return new ValueTask<Resource>(resource);
        }
        
        return new ValueTask<Resource>(InitializeResourceAsync(resource));
    }
    
    private async Task<Resource> InitializeResourceAsync(Resource resource)
    {
        await resource.InitializeAsync();
        return resource;
    }
}
```

#### 3. Fast Path Optimization
```csharp
public class ValidationService
{
    public ValueTask<ValidationResult> ValidateAsync(Request request)
    {
        // Fast path: synchronous validation
        if (request == null)
        {
            return new ValueTask<ValidationResult>(
                ValidationResult.Failed("Request is null"));
        }
        
        if (string.IsNullOrEmpty(request.Id))
        {
            return new ValueTask<ValidationResult>(
                ValidationResult.Failed("Id is required"));
        }
        
        // Slow path: async validation
        return new ValueTask<ValidationResult>(ValidateWithDatabaseAsync(request));
    }
    
    private async Task<ValidationResult> ValidateWithDatabaseAsync(Request request)
    {
        var exists = await _repository.ExistsAsync(request.Id);
        return exists 
            ? ValidationResult.Success() 
            : ValidationResult.Failed("Id not found");
    }
}
```

### Best Practices

1. **Only optimize hot paths**
   - Profile first, optimize second
   - Don't use ValueTask everywhere "just in case"

2. **Document ValueTask usage**
   ```csharp
   /// <summary>
   /// Gets user data. Returns synchronously from cache if available.
   /// </summary>
   /// <remarks>
   /// Returns ValueTask for performance - this method is called
   /// millions of times per day and 95% are cache hits.
   /// </remarks>
   public ValueTask<User> GetUserAsync(int id) { }
   ```

3. **Consider converting to Task for complex operations**
   ```csharp
   public async Task ProcessMultipleAsync()
   {
       ValueTask<int> vt1 = GetValueAsync(1);
       ValueTask<int> vt2 = GetValueAsync(2);
       
       // Need WhenAll - convert to Task
       await Task.WhenAll(vt1.AsTask(), vt2.AsTask());
   }
   ```

4. **Use the right tool for the job**
   ```csharp
   // ✅ Library method called millions of times
   public ValueTask<byte[]> ReadAsync(int count);
   
   // ✅ Application code, typical usage
   public Task<User> GetUserAsync(int id);
   ```
