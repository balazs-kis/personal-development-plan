## Introduction

The principle of least privilege is foundational to Linux security: users and processes should have only the minimum permissions needed to perform their tasks. Proper user management prevents unauthorized access, limits damage from compromised accounts, and ensures compliance with security standards.

This lesson covers how to implement least privilege through user management, permissions, and access control.

## Key Concepts Summary

### Principle of Least Privilege

**Definition:**
- Grant minimum permissions necessary for tasks
- Users and processes operate with lowest possible privileges
- Reduces attack surface and potential damage
- Fundamental security principle

**Why it matters:**
```
Compromised account with limited privileges:
- Attacker can only access user's files
- Cannot modify system files
- Cannot install malware system-wide
- Easier to contain and remediate

Compromised root account:
- Attacker has complete system control
- Can modify/delete any file
- Can install persistent malware
- Difficult to detect and remove
```

**Benefits:**
- Reduces security risks
- Limits blast radius of breaches
- Prevents accidental system damage
- Aids compliance (PCI-DSS, HIPAA, GDPR)
- Simplifies auditing

### User Account Types

**Root (superuser):**
```
UID: 0
Username: root
Access: Unrestricted system access
Purpose: System administration
```

**System users:**
```
UID: 1-999 (or 1-499)
Purpose: Run services and daemons
Examples: www-data, mysql, nginx
No login shell typically
```

**Regular users:**
```
UID: 1000+ 
Purpose: Human users
Access: Limited to home directory and granted permissions
Can use sudo for admin tasks
```

**Service accounts:**
```
Purpose: Application-specific access
Minimal permissions
No interactive login
```

### User Management Commands

**Create user:**
```bash
# Basic user creation
sudo useradd username

# Create with home directory and shell
sudo useradd -m -s /bin/bash username

# Create with specific UID
sudo useradd -u 1500 username

# Create with comment (full name)
sudo useradd -c "Alice Smith" alice

# Create with specific group
sudo useradd -g developers alice
```

**Set password:**
```bash
sudo passwd username

# Force password change on next login
sudo passwd -e username

# Lock account
sudo passwd -l username

# Unlock account
sudo passwd -u username
```

**Modify user:**
```bash
# Change username
sudo usermod -l newname oldname

# Change home directory
sudo usermod -d /new/home -m username

# Change shell
sudo usermod -s /bin/zsh username

# Add to supplementary group
sudo usermod -aG groupname username

# Set expiry date
sudo usermod -e 2026-12-31 username

# Lock account
sudo usermod -L username
```

**Delete user:**
```bash
# Delete user (keep home directory)
sudo userdel username

# Delete user and home directory
sudo userdel -r username

# Delete user and force removal
sudo userdel -f username
```

**View user info:**
```bash
# User details
id username
finger username
getent passwd username

# Current user
whoami
id

# Logged in users
who
w
users

# Last logins
last
last username
```

### Group Management

**Create group:**
```bash
sudo groupadd groupname
sudo groupadd -g 5000 groupname  # Specific GID
```

**Delete group:**
```bash
sudo groupdel groupname
```

**Add user to group:**
```bash
# Add to supplementary group
sudo usermod -aG groupname username
sudo gpasswd -a username groupname

# Set as primary group
sudo usermod -g groupname username
```

**Remove user from group:**
```bash
sudo gpasswd -d username groupname
```

**View groups:**
```bash
# User's groups
groups username
id username

# All groups
cat /etc/group
getent group
```

### File Permissions

**Permission types:**
```
r (4) - Read
w (2) - Write
x (1) - Execute

Applied to:
- Owner (user)
- Group
- Others
```

**View permissions:**
```bash
ls -l file.txt
# -rw-r--r-- 1 alice developers 1234 Jan 26 10:00 file.txt
# Owner: rw- (6)
# Group: r-- (4)
# Others: r-- (4)
```

**Change permissions:**
```bash
# Symbolic mode
chmod u+x file.sh          # Add execute for owner
chmod g-w file.txt         # Remove write for group
chmod o= file.txt          # Remove all for others
chmod a+r file.txt         # Add read for all

# Numeric mode
chmod 644 file.txt         # rw-r--r--
chmod 755 script.sh        # rwxr-xr-x
chmod 600 private.key      # rw-------
chmod 700 private_dir/     # rwx------
```

**Change ownership:**
```bash
# Change owner
sudo chown alice file.txt

# Change owner and group
sudo chown alice:developers file.txt

# Recursive
sudo chown -R alice:developers directory/

# Change group only
sudo chgrp developers file.txt
```

### Special Permissions

**Setuid (SUID):**
```bash
# Execute as owner
chmod u+s /usr/bin/program
chmod 4755 /usr/bin/program

# Example: passwd command
ls -l /usr/bin/passwd
# -rwsr-xr-x (s instead of x)
```

**Setgid (SGID):**
```bash
# Execute as group / inherit group
chmod g+s directory/
chmod 2755 directory/

# Files created in directory inherit group
```

**Sticky bit:**
```bash
# Only owner can delete files
chmod +t directory/
chmod 1777 directory/

# Example: /tmp
ls -ld /tmp
# drwxrwxrwt (t at end)
```

### Password Security

**Password policies:**
```bash
# Install password quality library
sudo apt install libpam-pwquality  # Ubuntu/Debian
sudo dnf install libpwquality      # Red Hat/Fedora

# Configure in /etc/security/pwquality.conf
minlen = 12          # Minimum length
dcredit = -1         # Require digit
ucredit = -1         # Require uppercase
lcredit = -1         # Require lowercase
ocredit = -1         # Require special char
maxrepeat = 3        # Max repeated chars
```

**Password aging:**
```bash
# Set password expiry
sudo chage -M 90 username      # Max 90 days
sudo chage -m 7 username       # Min 7 days between changes
sudo chage -W 14 username      # Warn 14 days before expiry
sudo chage -I 30 username      # Lock 30 days after expiry

# View password info
sudo chage -l username

# Force password change
sudo chage -d 0 username
```

**Account expiration:**
```bash
# Set account expiry date
sudo usermod -e 2026-12-31 username

# View expiry
sudo chage -l username
```

### Implementing Least Privilege

**Strategy 1: Dedicated accounts**
```bash
# Create service account
sudo useradd -r -s /usr/sbin/nologin -d /opt/myapp myapp

# Set ownership
sudo chown -R myapp:myapp /opt/myapp

# Run service as user
sudo -u myapp /opt/myapp/start.sh
```

**Strategy 2: Group-based access**
```bash
# Create groups for roles
sudo groupadd developers
sudo groupadd operators
sudo groupadd auditors

# Add users to groups
sudo usermod -aG developers alice
sudo usermod -aG operators bob

# Set directory permissions
sudo chgrp developers /var/www/app
sudo chmod 775 /var/www/app
```

**Strategy 3: Sudo for specific tasks**
```bash
# Allow user to restart specific service (covered in next lesson)
# /etc/sudoers.d/app-restart
alice ALL=(ALL) NOPASSWD: /bin/systemctl restart myapp.service
```

**Strategy 4: Remove unnecessary privileges**
```bash
# Disable direct root login
sudo passwd -l root

# Remove from sudo group
sudo deluser username sudo

# Audit user permissions regularly
sudo find /home -type f -perm /o+w
```

### Security Auditing

**Review user accounts:**
```bash
# List all users
cut -d: -f1 /etc/passwd

# Find users with UID 0 (root privileges)
awk -F: '$3 == 0 {print $1}' /etc/passwd

# Find users with no password
sudo awk -F: '$2 == "" {print $1}' /etc/shadow

# Find users with shell access
grep -v '/nologin\|/false' /etc/passwd
```

**Review sudo access:**
```bash
# List sudo group members
getent group sudo
getent group wheel  # Red Hat/CentOS

# Check sudoers configuration
sudo visudo -c
```

**Review file permissions:**
```bash
# Find world-writable files
sudo find / -type f -perm -o+w 2>/dev/null

# Find SUID files
sudo find / -type f -perm -4000 2>/dev/null

# Find SGID files
sudo find / -type f -perm -2000 2>/dev/null

# Find files with no owner
sudo find / -nouser -o -nogroup 2>/dev/null
```

**Check last logins:**
```bash
# Recent logins
last | head -20

# Failed login attempts
sudo lastb | head -20

# Login history for user
last username
```

### Best Practices

**User account management:**
- Create individual accounts (no shared accounts)
- Use descriptive usernames
- Implement strong password policies
- Enable password aging
- Set account expiration dates
- Remove or disable unused accounts
- Use service accounts for applications
- Never run services as root

**Permission management:**
- Apply least privilege principle
- Use groups for role-based access
- Regular permission audits
- Avoid world-writable permissions
- Secure sensitive files (600 or 400)
- Use sticky bit on shared directories
- Minimize SUID/SGID binaries

**Authentication:**
- Enforce strong passwords
- Implement two-factor authentication
- Use SSH keys over passwords
- Disable root login
- Log and monitor authentication attempts
- Regular password rotation
- Account lockout policies
