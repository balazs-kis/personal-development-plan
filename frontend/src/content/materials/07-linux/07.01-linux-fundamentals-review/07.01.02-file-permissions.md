## Introduction

Linux is a multi-user system where file permissions are fundamental to security. Every file and directory has permissions that control who can read, write, or execute it. Understanding permissions is essential for system administration, troubleshooting access issues, and securing your applications.

Permissions issues are among the most common problems in Linux administration—mastering this topic will save you countless hours of debugging.

## Key Concepts Summary

### Permission Types

Each file has three types of permissions:
- **Read (r)** - View file contents or list directory contents
- **Write (w)** - Modify file or create/delete files in directory
- **Execute (x)** - Run file as program or access directory

### Permission Classes

Permissions apply to three user classes:
- **User (u)** - The file owner
- **Group (g)** - Members of the file's group
- **Others (o)** - Everyone else

### Reading Permission Strings

The `ls -l` command shows permissions:

```bash
-rw-r--r--  1 alice developers  1234 Jan 26 10:00 report.txt
drwxr-xr-x  2 alice developers  4096 Jan 26 09:30 scripts/
```

Breaking down `-rw-r--r--`:
- **First character:** File type (- = regular file, d = directory, l = symbolic link)
- **Next 3 characters (rw-):** Owner permissions (read + write, no execute)
- **Next 3 characters (r--):** Group permissions (read only)
- **Last 3 characters (r--):** Other permissions (read only)

### Numeric (Octal) Notation

Each permission has a numeric value:
- **Read (r)** = 4
- **Write (w)** = 2  
- **Execute (x)** = 1
- **No permission (-)** = 0

Add values for each class:
- **7** (rwx) = 4 + 2 + 1 = read + write + execute
- **6** (rw-) = 4 + 2 = read + write
- **5** (r-x) = 4 + 1 = read + execute
- **4** (r--) = 4 = read only
- **0** (---) = no permissions

Examples:
```bash
chmod 755 script.sh    # rwxr-xr-x (owner: all, group/others: read+execute)
chmod 644 config.txt   # rw-r--r-- (owner: read+write, group/others: read)
chmod 600 secret.key   # rw------- (owner: read+write, no access for others)
chmod 777 shared.txt   # rwxrwxrwx (all permissions for everyone - dangerous!)
```

### Changing Permissions with chmod

**Symbolic notation:**
```bash
chmod u+x script.sh        # Add execute for user
chmod g-w file.txt         # Remove write for group
chmod o+r document.pdf     # Add read for others
chmod a+x program          # Add execute for all (user, group, others)
chmod u=rw,g=r,o= private  # Set exact permissions
```

**Numeric notation:**
```bash
chmod 755 app.sh          # rwxr-xr-x
chmod 644 data.json       # rw-r--r--
chmod 700 ~/.ssh          # rwx------ (secure directory)
chmod 600 ~/.ssh/id_rsa   # rw------- (secure key file)
```

### Common Permission Patterns

- **755** (rwxr-xr-x) - Executable files, scripts, directories
- **644** (rw-r--r--) - Regular files (documents, configs)
- **600** (rw-------) - Private files (SSH keys, credentials)
- **700** (rwx------) - Private directories
- **777** (rwxrwxrwx) - Full access (avoid! security risk)

### Special Permissions (Brief Overview)

- **Setuid (4000)** - Run executable as file owner
- **Setgid (2000)** - Run executable as file group, or inherit group on new files
- **Sticky bit (1000)** - Only owner can delete files in directory (used on /tmp)

```bash
chmod 4755 executable  # setuid + rwxr-xr-x
chmod 2755 directory   # setgid + rwxr-xr-x  
chmod 1777 /tmp        # sticky + rwxrwxrwx
```

## Practice Exercise

After completing the materials, try these exercises (spend 10 minutes):

```bash
# Create test files
touch testfile.txt
mkdir testdir

# Practice symbolic notation
chmod u+rwx,g+rx,o+r testfile.txt
ls -l testfile.txt

# Practice numeric notation
chmod 755 testdir
chmod 644 testfile.txt
ls -l

# Try setting restrictive permissions
chmod 600 testfile.txt
ls -l testfile.txt

# Check your home directory permissions
ls -ld ~
ls -l ~/.ssh/
```
