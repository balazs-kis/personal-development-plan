## Introduction

Resource limits are essential for multi-tenant container environments. Without limits, a single container can monopolize CPU, memory, or I/O, affecting other containers and the host. Understanding how to configure and monitor resource limits ensures fair resource allocation, prevents system instability, and improves overall reliability.

## Key Concepts Summary

### Why Resource Limits Matter

**Without limits:**
```
Problems:
- Noisy neighbor effect
- Resource starvation
- System instability
- Unpredictable performance
- Security vulnerabilities
- OOM killer on host
```

**With limits:**
```
Benefits:
- Fair resource sharing
- Predictable performance
- Isolation between containers
- Capacity planning
- Cost optimization
- Security hardening
```

### Types of Resource Limits

**CPU limits:**
```
--cpus           - Maximum CPU usage
--cpu-shares     - CPU weight/priority
--cpuset-cpus    - Pin to specific CPUs
--cpu-period     - CPU CFS period
--cpu-quota      - CPU CFS quota
```

**Memory limits:**
```
--memory (-m)    - Maximum memory
--memory-swap    - Memory + swap limit
--memory-reservation - Soft memory limit
--oom-kill-disable - Disable OOM killer
--kernel-memory  - Kernel memory limit
```

**I/O limits:**
```
--blkio-weight           - I/O priority
--device-read-bps        - Read bandwidth limit
--device-write-bps       - Write bandwidth limit
--device-read-iops       - Read IOPS limit
--device-write-iops      - Write IOPS limit
```

**Other limits:**
```
--pids-limit     - Maximum processes
--ulimit         - Ulimits (files, processes, etc.)
```

### CPU Limits

**Basic CPU limit:**
```bash
# Limit to 1.5 CPUs
docker run --cpus="1.5" nginx

# Limit to 50% of one CPU
docker run --cpus="0.5" nginx

# No limit (default)
docker run nginx
```

**How --cpus works:**
```
Sets cpu.cfs_quota_us and cpu.cfs_period_us
Default period: 100ms (100000 microseconds)

--cpus="1.0"
→ quota=100000, period=100000
→ 100% of one CPU

--cpus="0.5"
→ quota=50000, period=100000
→ 50% of one CPU

--cpus="2.0"
→ quota=200000, period=100000
→ 200% (two full CPUs)
```

**CPU shares (relative weight):**
```bash
# CPU shares (default: 1024)
docker run --cpu-shares=512 nginx
docker run --cpu-shares=1024 nginx
docker run --cpu-shares=2048 nginx

# Higher shares = more CPU when contention
# Only matters when CPU is busy
# 2048 shares gets 2x more CPU than 1024
```

**CPU affinity:**
```bash
# Pin to specific CPUs
docker run --cpuset-cpus="0,1" nginx     # CPUs 0 and 1
docker run --cpuset-cpus="0-3" nginx     # CPUs 0 through 3
docker run --cpuset-cpus="1" nginx       # CPU 1 only

# Useful for:
# - NUMA optimization
# - Isolating workloads
# - Cache optimization
```

**Advanced CPU control:**
```bash
# Set period and quota directly
docker run \
  --cpu-period=100000 \
  --cpu-quota=50000 \
  nginx
# 50000/100000 = 50% of one CPU

# Real-time scheduling (requires host config)
docker run --cpu-rt-runtime=950000 --cpu-rt-period=1000000 nginx
```

### Memory Limits

**Basic memory limit:**
```bash
# Limit to 512MB
docker run -m 512m nginx

# Limit to 2GB
docker run -m 2g nginx

# Units: b, k, m, g (bytes, KB, MB, GB)
docker run -m 256m nginx
```

**Memory + swap:**
```bash
# Memory: 512MB, Swap: 512MB (total 1GB)
docker run -m 512m --memory-swap 1g nginx

# Memory: 512MB, Swap: unlimited
docker run -m 512m --memory-swap -1 nginx

# Memory: 512MB, No swap
docker run -m 512m --memory-swap 512m nginx

# Default: memory-swap = 2x memory
docker run -m 512m nginx  # 512MB memory + 512MB swap
```

**Soft memory limit:**
```bash
# Reservation (soft limit)
docker run -m 1g --memory-reservation 512m nginx

# System tries to keep usage below 512MB
# But allows up to 1GB if needed
# Useful for flexible allocation
```

**OOM behavior:**
```bash
# Default: OOM killer kills container
docker run -m 256m nginx
# If exceeds 256MB → container killed

# Disable OOM killer (risky!)
docker run -m 256m --oom-kill-disable nginx
# If exceeds → container frozen, host at risk

# Set OOM score adjustment
docker run --oom-score-adj 500 nginx
# Higher score = more likely to be killed
# Range: -1000 to 1000
```

**Kernel memory:**
```bash
# Limit kernel memory (advanced)
docker run --kernel-memory 50m nginx

# Prevents kernel memory exhaustion
# Includes: socket buffers, slab, page tables
# Rarely needed in practice
```

### I/O Limits

**Block I/O weight:**
```bash
# I/O priority (default: 500)
docker run --blkio-weight 300 nginx    # Lower priority
docker run --blkio-weight 700 nginx    # Higher priority

# Range: 10-1000
# Only matters during I/O contention
# Like CPU shares for disk
```

**Bandwidth limits:**
```bash
# Limit read bandwidth to 10 MB/s
docker run \
  --device-read-bps /dev/sda:10mb \
  nginx

# Limit write bandwidth to 5 MB/s
docker run \
  --device-write-bps /dev/sda:5mb \
  nginx

# Combine limits
docker run \
  --device-read-bps /dev/sda:100mb \
  --device-write-bps /dev/sda:50mb \
  nginx
```

**IOPS limits:**
```bash
# Limit read IOPS to 1000
docker run \
  --device-read-iops /dev/sda:1000 \
  nginx

# Limit write IOPS to 500
docker run \
  --device-write-iops /dev/sda:500 \
  nginx

# Useful for rate-limiting disk access
```

**Device access:**
```bash
# Read-only device access
docker run --device /dev/sda:/dev/sda:r nginx

# Read-write device access
docker run --device /dev/sda:/dev/sda:rw nginx

# Multiple devices
docker run \
  --device /dev/sda:/dev/sda:r \
  --device /dev/sdb:/dev/sdb:rw \
  nginx
```

### Process Limits

**PID limit:**
```bash
# Limit to 100 processes
docker run --pids-limit 100 nginx

# Prevent fork bombs
# Limit container process count
# Good security practice

# Unlimited (default, risky)
docker run --pids-limit -1 nginx
```

### Ulimits

**File descriptor limits:**
```bash
# Set nofile (max open files)
docker run --ulimit nofile=1024:2048 nginx
# Soft limit: 1024
# Hard limit: 2048

# Common ulimits:
# nofile  - Max open files
# nproc   - Max processes
# core    - Core dump size
# memlock - Max locked memory
```

**Multiple ulimits:**
```bash
docker run \
  --ulimit nofile=1024:2048 \
  --ulimit nproc=512:1024 \
  --ulimit core=0:0 \
  nginx
```

### Monitoring Resource Usage

**docker stats:**
```bash
# Real-time stats
docker stats

# Output:
CONTAINER ID   NAME      CPU %     MEM USAGE / LIMIT     MEM %
abc123         web       0.50%     128MiB / 512MiB      25.00%

# Specific container
docker stats container_name

# Single snapshot
docker stats --no-stream

# Format output
docker stats --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}"
```

**Container resource usage:**
```bash
# View cgroup values
docker exec container cat /sys/fs/cgroup/memory.max
docker exec container cat /sys/fs/cgroup/memory.current
docker exec container cat /sys/fs/cgroup/cpu.max

# Or from host
CONTAINER_ID=$(docker inspect -f '{{.Id}}' container_name)
cat /sys/fs/cgroup/system.slice/docker-$CONTAINER_ID.scope/memory.max
```

**Detailed inspection:**
```bash
# View all resource limits
docker inspect container_name | jq '.[0].HostConfig'

# Specific limits
docker inspect -f '{{.HostConfig.Memory}}' container_name
docker inspect -f '{{.HostConfig.CpuQuota}}' container_name
docker inspect -f '{{.HostConfig.PidsLimit}}' container_name
```

### Practical Examples

**Example 1: Web server with limits**
```bash
docker run -d --name web \
  --cpus="1.0" \
  -m 512m \
  --memory-swap 1g \
  --pids-limit 50 \
  nginx

# Monitor
docker stats web
```

**Example 2: Database with I/O limits**
```bash
docker run -d --name db \
  --cpus="2.0" \
  -m 2g \
  --device-read-bps /dev/sda:200mb \
  --device-write-bps /dev/sda:100mb \
  postgres

# Check limits
docker inspect db | jq '.[0].HostConfig'
```

**Example 3: Resource reservation**
```bash
docker run -d --name app \
  --cpus="2.0" \
  -m 1g \
  --memory-reservation 512m \
  --cpu-shares=1024 \
  myapp

# Guaranteed: 512MB, 1024 CPU shares
# Max: 2 CPUs, 1GB memory
```

### Troubleshooting

**Issue: Container killed by OOM**
```bash
# Check if OOM killed
docker inspect container | grep OOMKilled

# View logs
docker logs container
dmesg | grep -i "oom"

# Solutions:
# 1. Increase memory limit
docker run -m 1g container

# 2. Add swap
docker run -m 512m --memory-swap 1g container

# 3. Fix memory leak in application
```

**Issue: CPU throttling**
```bash
# Check CPU usage
docker stats container

# If consistently at limit, increase:
docker run --cpus="2.0" container

# Or use CPU shares for fairness
docker run --cpu-shares=2048 container
```

**Issue: I/O slowness**
```bash
# Check I/O limits
docker inspect container | grep -i blkio

# Increase limits
docker run \
  --device-read-bps /dev/sda:500mb \
  --device-write-bps /dev/sda:250mb \
  container

# Or use volumes for better performance
docker run -v /data:/data container
```

### Best Practices

**Always set limits:**
```bash
# Production template
docker run -d \
  --name myapp \
  --cpus="1.0" \
  -m 512m \
  --memory-swap 1g \
  --pids-limit 100 \
  --restart unless-stopped \
  myapp:latest
```

**Resource planning:**
```
1. Measure actual usage
   - Run without limits
   - Monitor with docker stats
   - Analyze resource patterns

2. Set limits with headroom
   - Add 20-50% above average
   - Account for spikes
   - Test under load

3. Monitor and adjust
   - Track OOM kills
   - Watch for throttling
   - Tune based on metrics
```

**Security:**
```
- Always set --pids-limit
- Use --memory-swap carefully
- Never use --oom-kill-disable in production
- Set appropriate --ulimit values
- Consider --cpu-shares for multi-tenant
```
