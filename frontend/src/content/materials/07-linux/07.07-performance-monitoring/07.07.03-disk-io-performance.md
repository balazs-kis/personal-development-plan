- Understand the impact of I/O wait on system performance

---

## Introduction

Disk I/O is often the slowest component in a system, and disk bottlenecks can severely impact application performance. Unlike CPU or memory issues, disk problems are harder to diagnose because symptoms may appear across the entire system. This lesson teaches you to identify and troubleshoot disk I/O bottlenecks effectively.

## Key Concepts Summary

### Disk I/O Metrics

**Key performance indicators:**
```
IOPS (I/O Operations Per Second)
- Read operations/sec
- Write operations/sec
- Total operations/sec

Throughput
- Read MB/s
- Write MB/s
- Total MB/s

Latency
- Average response time
- Queue time
- Service time

Utilization
- Percentage of time disk is busy
- Queue depth
```

**Performance targets:**
```
HDD (7200 RPM):
- IOPS: 75-100
- Throughput: 80-160 MB/s
- Latency: 10-20ms

SSD (SATA):
- IOPS: 10,000-90,000
- Throughput: 200-550 MB/s
- Latency: <1ms

NVMe SSD:
- IOPS: 100,000-1,000,000+
- Throughput: 2000-7000 MB/s
- Latency: <0.1ms
```

### Understanding I/O Wait

**What is I/O wait?**
- CPU time waiting for I/O to complete
- Shows as %wa in top/mpstat
- High I/O wait = disk bottleneck

**Checking I/O wait:**
```bash
# With top
top
# Look at: %wa (I/O wait)

# With mpstat
mpstat 1

# With vmstat
vmstat 1
# Look at: wa column
```

**I/O wait guidelines:**
```
< 10%   - Good
10-20%  - Monitor
20-40%  - Potential bottleneck
> 40%   - Serious bottleneck
```

### iostat Command

**Installation:**
```bash
sudo apt install sysstat  # Ubuntu/Debian
sudo dnf install sysstat  # Red Hat/Fedora
```

**Basic usage:**
```bash
# Current stats
iostat

# Extended statistics
iostat -x

# Monitor every 2 seconds
iostat -x 2

# Human-readable
iostat -xh 2

# Specific device
iostat -x sda 2
```

**Key columns:**
```
r/s    - Reads per second
w/s    - Writes per second
rkB/s  - KB read per second
wkB/s  - KB written per second
%util  - Device utilization (0-100%)
await  - Average wait time (ms)
svctm  - Average service time (ms) [deprecated]
avgqu-sz - Average queue size
```

**Example output:**
```bash
$ iostat -x 1
Device    r/s   w/s  rkB/s  wkB/s  await  %util
sda      50.0  30.0  2048   1024    5.2    85.0
```

**Warning signs:**
```
%util > 80%         - Disk saturated
await > 10-20ms     - High latency
avgqu-sz > 1        - Queue building up
r/s or w/s very high - High IOPS
```

### iotop Command

**Installation:**
```bash
sudo apt install iotop  # Ubuntu/Debian
sudo dnf install iotop  # Red Hat/Fedora
```

**Basic usage:**
```bash
# Requires root
sudo iotop

# Only show processes doing I/O
sudo iotop -o

# Non-interactive (for logging)
sudo iotop -b -n 3

# Show specific processes
sudo iotop -p PID
```

**Key columns:**
```
TID     - Thread ID
PRIO    - Priority
USER    - Username
DISK READ - Read speed
DISK WRITE - Write speed
SWAPIN  - Swap in percentage
IO      - I/O wait percentage
COMMAND - Process name
```

**Interactive keys:**
```
o - Only show processes with I/O
p - Show processes (default is threads)
a - Accumulated I/O
r - Reverse sort
q - Quit
```

### Other I/O Monitoring Tools

**blktrace:**

```bash
# Detailed block I/O tracing

```

**ioping:**
```bash
# Disk latency monitoring
sudo apt install ioping

```

**atop:**
```bash
# Comprehensive monitoring
sudo apt install atop
atop
# Press 'd' for disk stats
```

### Finding I/O-Heavy Processes

**Using iotop:**
```bash
sudo iotop -o
# Shows only active I/O processes
```

**Using pidstat:**
```bash
# I/O stats by process
pidstat -d 1
```

**Using ps:**
```bash
# Sort by I/O wait
ps -eo pid,state,wchan,comm | grep "^D"
# D state = uninterruptible sleep (usually I/O)
```

**Check process I/O:**
```bash
# Total I/O for process
cat /proc/PID/io

# Example:
cat /proc/1234/io
rchar: 1048576      # Bytes read
wchar: 524288       # Bytes written
read_bytes: 1048576 # Actual disk reads
write_bytes: 524288 # Actual disk writes
```

### Troubleshooting Disk I/O

**Symptom: High I/O wait**
```bash
# 1. Confirm high I/O wait
top  # Check %wa
mpstat 1

# 2. Identify busy disks
iostat -x 1

# 3. Find processes causing I/O
sudo iotop -o

# 4. Check specific process
cat /proc/PID/io
```

**Symptom: Slow disk performance**
```bash
# 1. Check utilization
iostat -x 1

# 2. Look for:
# - %util near 100%
# - High await times
# - Large queue sizes

# 3. Test disk speed
sudo hdparm -Tt /dev/sda

# 4. Check for errors
sudo smartctl -a /dev/sda
dmesg | grep -i error
```

**Symptom: Random high latency**
```bash
# Check for:
# 1. Other processes doing I/O
sudo iotop -o

# 2. Disk errors
dmesg | grep -i "error\|fail"

# 3. RAID rebuild/scrub
cat /proc/mdstat

# 4. VM host overcommitment (if VM)
# Check steal time
mpstat 1
```

### Optimization Strategies

**Read optimization:**
```
- Increase read-ahead
- Use larger block sizes
- Add more RAM for cache
- Use faster storage (SSD)
- Optimize application queries
```

**Write optimization:**
```
- Batch writes
- Use write-back cache
- Optimize fsync() usage
- Use appropriate filesystem
- Consider write buffer tuning
```

**Filesystem tuning:**
```bash
# Check mount options
mount | grep sda

# Common optimizations:
# - noatime (don't update access time)
# - discard (SSD TRIM support)
# - commit interval (ext4)
```

### Disk Performance Testing

**Read speed:**
```bash
# Cached read
sudo hdparm -t /dev/sda

# Direct read (bypasses cache)
sudo hdparm -T /dev/sda
```

**Write speed:**
```bash
# Test write speed
dd if=/dev/zero of=/tmp/test bs=1M count=1024
rm /tmp/test
```

**IOPS testing:**
```bash
# Random read IOPS
fio --name=random-read --ioengine=libaio --iodepth=16 --rw=randread --bs=4k --direct=1 --size=1G --numjobs=1 --runtime=60
```

### Practical Examples

**Monitor disk I/O:**
```bash
#!/bin/bash
# Continuous disk monitoring

while true; do
    echo "=== $(date) ==="
    iostat -x 1 1 | grep -A 10 "Device"
    echo ""
    sleep 5
done
```

**Alert on high I/O wait:**
```bash
#!/bin/bash
# Alert if I/O wait > 20%

IOWAIT=$(mpstat 1 1 | awk '/Average/ {print $6}' | cut -d'.' -f1)

if [ "$IOWAIT" -gt 20 ]; then
    echo "WARNING: High I/O wait: ${IOWAIT}%"
    iostat -x
    sudo iotop -b -n 1 -o
fi
```

**Log I/O-heavy processes:**
```bash
#!/bin/bash
# Log processes with high I/O

sudo iotop -b -n 1 -o | tee -a /var/log/io_monitor.log
```
