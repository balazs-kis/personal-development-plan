# Lesson 5: Network Troubleshooting Tools

## Learning Objectives

By the end of this lesson, you will be able to:
- Use netstat and ss to view network connections and listening ports
- Capture and analyze packets with tcpdump
- Test HTTP/HTTPS connections with curl and wget
- Trace network routes with traceroute and mtr
- Scan networks and ports with nmap
- Troubleshoot network connectivity systematically
- Diagnose common network issues efficiently

## Introduction

Network troubleshooting requires the right tools and a systematic approach. Linux provides powerful command-line utilities for diagnosing connectivity issues, analyzing traffic, and understanding network behavior. Mastering these tools is essential for backend engineers working with distributed systems and network services.

This lesson covers the essential network troubleshooting toolkit every Linux administrator should know.

## Key Concepts Summary

### netstat (Network Statistics)

**What is netstat?**
- Displays network connections, routing tables, interface statistics
- Legacy tool (being replaced by ss)
- Still widely used and available
- Part of net-tools package

**View all connections:**
```bash
netstat -a          # All sockets
netstat -at         # TCP connections
netstat -au         # UDP connections
```

**View listening ports:**
```bash
netstat -l          # Listening sockets
netstat -lt         # Listening TCP
netstat -lu         # Listening UDP
netstat -ltn        # Listening TCP, numeric
```

**Common options:**
```bash
-a      # Show all sockets
-t      # TCP connections
-u      # UDP connections
-l      # Listening sockets
-n      # Numeric (no DNS resolution)
-p      # Show process/PID
-r      # Routing table
-i      # Interface statistics
-s      # Protocol statistics
```

**Useful combinations:**
```bash
# TCP listening ports with programs
netstat -tlnp

# All TCP connections with programs
netstat -tanp

# Routing table
netstat -rn

# Interface statistics
netstat -i

# Protocol statistics
netstat -s
```

**Example output:**
```bash
$ netstat -tlnp
Proto Recv-Q Send-Q Local Address    Foreign Address   State       PID/Program
tcp        0      0 0.0.0.0:22       0.0.0.0:*         LISTEN      1234/sshd
tcp        0      0 0.0.0.0:80       0.0.0.0:*         LISTEN      5678/nginx
```

### ss (Socket Statistics)

**What is ss?**
- Modern replacement for netstat
- Faster and more efficient
- Part of iproute2 package
- Preferred tool on modern systems

**Basic usage:**
```bash
ss                  # Show all connections
ss -t               # TCP connections
ss -u               # UDP connections
ss -l               # Listening sockets
ss -a               # All sockets
```

**Common options:**
```bash
-a      # All sockets
-t      # TCP
-u      # UDP
-l      # Listening
-n      # Numeric
-p      # Show processes
-r      # Resolve names
-s      # Summary statistics
-m      # Memory info
-i      # Internal TCP info
```

**Useful combinations:**
```bash
# TCP listening ports with processes
sudo ss -tlnp

# All TCP connections
ss -tan

# UDP listening
sudo ss -ulnp

# Summary statistics
ss -s

# Show all established connections
ss -tan state established
```

**Filter by state:**
```bash
ss -tan state listening
ss -tan state established
ss -tan state time-wait
ss -tan state syn-sent
```

**Filter by port:**
```bash
ss -tan '( dport = :80 or sport = :80 )'
ss -tan '( dport = :443 )'
ss -ltn sport = :22
```

**Example output:**
```bash
$ sudo ss -tlnp
State   Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
LISTEN  0      128    0.0.0.0:22           0.0.0.0:*     users:(("sshd",pid=1234,fd=3))
LISTEN  0      511    0.0.0.0:80           0.0.0.0:*     users:(("nginx",pid=5678,fd=6))
```

### tcpdump (Packet Capture)

**What is tcpdump?**
- Command-line packet analyzer
- Captures network traffic
- Supports filtering expressions
- Can save to pcap files for Wireshark

**Basic capture:**
```bash
# Capture on default interface
sudo tcpdump

# Capture on specific interface
sudo tcpdump -i enp3s0

# Capture limited packets
sudo tcpdump -c 10

# Verbose output
sudo tcpdump -v
sudo tcpdump -vv   # More verbose
```

**Save to file:**
```bash
# Save capture
sudo tcpdump -w capture.pcap

# Read from file
sudo tcpdump -r capture.pcap
```

**Common filters:**
```bash
# Filter by host
sudo tcpdump host 192.168.1.100
sudo tcpdump src 192.168.1.100
sudo tcpdump dst 192.168.1.100

# Filter by port
sudo tcpdump port 80
sudo tcpdump port 443
sudo tcpdump portrange 80-443

# Filter by protocol
sudo tcpdump tcp
sudo tcpdump udp
sudo tcpdump icmp

# Filter by network
sudo tcpdump net 192.168.1.0/24
```

**Complex filters:**
```bash
# HTTP traffic to/from specific host
sudo tcpdump -i enp3s0 'tcp port 80 and host 192.168.1.100'

# SSH traffic
sudo tcpdump -i enp3s0 'tcp port 22'

# DNS queries
sudo tcpdump -i enp3s0 'udp port 53'

# SYN packets (new connections)
sudo tcpdump 'tcp[tcpflags] & tcp-syn != 0'

# Not from my IP
sudo tcpdump 'not src 192.168.1.100'
```

**Display options:**
```bash
# Show ASCII content
sudo tcpdump -A

# Show hex and ASCII
sudo tcpdump -XX

# Don't resolve hostnames (faster)
sudo tcpdump -n

# Don't resolve ports
sudo tcpdump -nn

# Show absolute sequence numbers
sudo tcpdump -S
```

**Practical examples:**
```bash
# Capture HTTP requests
sudo tcpdump -i enp3s0 -A 'tcp port 80'

# Capture packets to/from specific server
sudo tcpdump -i enp3s0 -nn host 93.184.216.34

# Capture and save for later analysis
sudo tcpdump -i enp3s0 -w debug.pcap port 443

# Read and filter saved capture
sudo tcpdump -r debug.pcap port 443
```

### curl (HTTP Client)

**What is curl?**
- Command-line HTTP client
- Supports HTTP, HTTPS, FTP, and more
- Test web services and APIs
- Download files

**Basic requests:**
```bash
# GET request
curl http://example.com

# View headers
curl -I http://example.com

# Follow redirects
curl -L http://example.com

# Save output to file
curl -o output.html http://example.com
curl -O http://example.com/file.zip  # Use remote filename
```

**HTTP methods:**
```bash
# GET (default)
curl http://api.example.com/users

# POST
curl -X POST http://api.example.com/users

# PUT
curl -X PUT http://api.example.com/users/1

# DELETE
curl -X DELETE http://api.example.com/users/1
```

**Headers and data:**
```bash
# Custom header
curl -H "Authorization: Bearer token123" http://api.example.com

# Multiple headers
curl -H "Content-Type: application/json" \
     -H "Authorization: Bearer token123" \
     http://api.example.com

# POST JSON data
curl -X POST \
     -H "Content-Type: application/json" \
     -d '{"name":"Alice","email":"alice@example.com"}' \
     http://api.example.com/users

# POST form data
curl -X POST \
     -d "name=Alice" \
     -d "email=alice@example.com" \
     http://example.com/form
```

**Authentication:**
```bash
# Basic auth
curl -u username:password http://example.com

# Bearer token
curl -H "Authorization: Bearer token123" http://api.example.com
```

**Debugging:**
```bash
# Verbose output
curl -v http://example.com

# Trace request/response
curl --trace-ascii trace.txt http://example.com

# Show timing
curl -w "@curl-format.txt" http://example.com

# Ignore SSL certificate errors
curl -k https://example.com

# Specify SSL/TLS version
curl --tlsv1.2 https://example.com
```

**Testing endpoints:**
```bash
# Test if service is up
curl -I http://localhost:8080

# Test with timeout
curl --connect-timeout 5 http://example.com

# Test API endpoint
curl -X GET http://localhost:3000/api/health

# Test with specific IP (override DNS)
curl --resolve example.com:80:93.184.216.34 http://example.com
```

### wget

**Download files:**
```bash
# Download file
wget http://example.com/file.zip

# Download with custom name
wget -O myfile.zip http://example.com/file.zip

# Continue interrupted download
wget -c http://example.com/largefile.iso

# Download recursively
wget -r http://example.com
```

**Background download:**
```bash
wget -b http://example.com/file.zip
tail -f wget-log
```

### ping

**Test connectivity:**
```bash
# Ping host
ping example.com
ping 8.8.8.8

# Limited count
ping -c 4 example.com

# Set interval
ping -i 2 example.com  # Every 2 seconds

# Set packet size
ping -s 1000 example.com

# Flood ping (root only)
sudo ping -f example.com
```

### traceroute / tracepath

**Trace route to host:**
```bash
# Trace route
traceroute example.com
traceroute 8.8.8.8

# Don't resolve hostnames
traceroute -n example.com

# Use TCP instead of UDP
traceroute -T example.com

# Specify port
traceroute -p 80 example.com
```

**tracepath (no root required):**
```bash
tracepath example.com
tracepath 8.8.8.8
```

### mtr (My Traceroute)

**Combined ping and traceroute:**
```bash
# Interactive mode
mtr example.com

# Report mode
mtr --report example.com

# Limited count
mtr -c 10 example.com

# No DNS resolution
mtr -n example.com
```

### nc (netcat)

**Network utility:**
```bash
# Test if port is open
nc -zv example.com 80
nc -zv 192.168.1.100 22

# Scan port range
nc -zv example.com 20-30

# Listen on port
nc -l 8080

# Send data
echo "GET / HTTP/1.0\r\n\r\n" | nc example.com 80

# Chat between machines
# On server:
nc -l 9999
# On client:
nc server_ip 9999
```

### nmap (Network Mapper)

**Port scanning:**
```bash
# Scan common ports
nmap example.com

# Scan all ports
nmap -p- example.com

# Scan specific ports
nmap -p 80,443,3306 example.com

# Scan port range
nmap -p 1-1000 example.com

# TCP SYN scan (faster, requires root)
sudo nmap -sS example.com

# Service version detection
nmap -sV example.com

# OS detection
sudo nmap -O example.com

# Aggressive scan
sudo nmap -A example.com
```

**Scan network:**
```bash
# Scan subnet
nmap 192.168.1.0/24

# Scan range
nmap 192.168.1.1-100

# Ping scan (find live hosts)
nmap -sn 192.168.1.0/24
```

### Troubleshooting Workflow

**Step 1: Test basic connectivity**
```bash
# Can you reach the host?
ping -c 4 example.com

# Is DNS working?
dig example.com
nslookup example.com
```

**Step 2: Check local network**
```bash
# Check interface
ip addr show

# Check routing
ip route show

# Check default gateway
ip route | grep default
ping <gateway_ip>
```

**Step 3: Check listening services**
```bash
# What's listening?
sudo ss -tlnp
sudo netstat -tlnp

# Is my service running?
sudo ss -tlnp | grep 8080
```

**Step 4: Check connectivity to service**
```bash
# Can you reach the port?
nc -zv example.com 80
telnet example.com 80

# Test HTTP
curl -v http://example.com
```

**Step 5: Check firewall**
```bash
# Are there blocking rules?
sudo iptables -L -n
sudo firewall-cmd --list-all
sudo ufw status
```

**Step 6: Capture and analyze traffic**
```bash
# Capture traffic
sudo tcpdump -i enp3s0 -n port 80

# Is traffic reaching the server?
# Are responses being sent?
```

**Step 7: Check application logs**
```bash
# Application logs
sudo journalctl -u myapp.service

# System logs
sudo tail -f /var/log/syslog
```
