## Introduction

DNS (Domain Name System) translates human-readable domain names into IP addresses. Proper DNS configuration is essential for applications to resolve hostnames and connect to services. DNS issues are among the most common network problems, making troubleshooting skills crucial for backend engineers.

This lesson covers DNS configuration methods, troubleshooting techniques, and the tools you need to diagnose and fix DNS problems.

## Key Concepts Summary

### DNS Basics

**What is DNS?**
- Domain Name System
- Translates hostnames to IP addresses
- Hierarchical, distributed database
- Uses UDP port 53 (TCP for large responses)

**DNS resolution process:**
```
1. Application requests: www.example.com
2. Resolver checks /etc/hosts
3. Resolver checks /etc/resolv.conf for nameservers
4. Query sent to DNS server
5. DNS server returns IP: 93.184.216.34
6. Application connects to IP
```

**Record types:**
```
A       - IPv4 address
AAAA    - IPv6 address
CNAME   - Canonical name (alias)
MX      - Mail exchange
NS      - Name server
PTR     - Pointer (reverse DNS)
TXT     - Text record
SOA     - Start of authority
```

### Linux DNS Resolution Components

**Key files and services:**
```
/etc/hosts              - Static hostname to IP mapping
/etc/resolv.conf        - DNS server configuration
/etc/nsswitch.conf      - Name service switch order
systemd-resolved        - systemd DNS resolver
NetworkManager          - Network management daemon
```

**Resolution order (nsswitch):**
```bash
# /etc/nsswitch.conf
hosts: files dns myhostname

# Means: check files (/etc/hosts), then DNS, then hostname
```

### /etc/hosts File

**Purpose:**
- Static hostname to IP mapping
- Checked before DNS
- Local overrides for DNS

**Format:**
```bash
# /etc/hosts
127.0.0.1       localhost
127.0.1.1       myhostname
192.168.1.100   server.local server
192.168.1.101   db.local db

# IPv6
::1             localhost ip6-localhost ip6-loopback
```

**Test:**
```bash
getent hosts server.local
ping server.local
```

### /etc/resolv.conf

**Purpose:**
- Configure DNS nameservers
- Set search domains
- DNS resolution options

**Basic format:**
```bash
# /etc/resolv.conf
nameserver 8.8.8.8
nameserver 1.1.1.1
search example.com local
options timeout:2 attempts:3
```

**Directives:**
```
nameserver      - DNS server IP (max 3)
search          - Search domain list (max 6)
domain          - Local domain name
options         - Resolution options
```

**Common options:**
```
timeout:n       - Query timeout (default 5s)
attempts:n      - Number of retries (default 2)
rotate          - Rotate through nameservers
ndots:n         - Dots needed for absolute name
```

**Example:**
```bash
nameserver 8.8.8.8
nameserver 8.8.4.4
nameserver 1.1.1.1
search example.com internal.example.com
options timeout:2 attempts:3 rotate
```

**View current DNS:**
```bash
cat /etc/resolv.conf
```

### systemd-resolved

**What is systemd-resolved?**
- systemd's DNS resolver service
- Provides local DNS caching
- Integrates with NetworkManager
- Used on modern systemd-based distros

**Check status:**
```bash
systemctl status systemd-resolved
resolvectl status
```

**View DNS settings:**
```bash
resolvectl status
resolvectl status enp3s0  # Specific interface
```

**Query DNS:**
```bash
resolvectl query example.com
resolvectl query --type=MX example.com
```

**Set DNS for interface:**
```bash
sudo resolvectl dns enp3s0 8.8.8.8 1.1.1.1
```

**Flush DNS cache:**
```bash
sudo resolvectl flush-caches
```

**Configuration:**
```bash
# /etc/systemd/resolved.conf
[Resolve]
DNS=8.8.8.8 1.1.1.1
FallbackDNS=8.8.4.4
Domains=example.com
```

**Restart service:**
```bash
sudo systemctl restart systemd-resolved
```

### NetworkManager DNS

**View connections:**
```bash
nmcli connection show
```

**View DNS for connection:**
```bash
nmcli connection show enp3s0 | grep dns
```

**Set DNS servers:**
```bash
sudo nmcli con mod enp3s0 ipv4.dns "8.8.8.8 1.1.1.1"
sudo nmcli con mod enp3s0 ipv4.ignore-auto-dns yes
sudo nmcli con up enp3s0
```

**Add additional DNS:**
```bash
sudo nmcli con mod enp3s0 +ipv4.dns 8.8.4.4
```

**Remove DNS:**
```bash
sudo nmcli con mod enp3s0 -ipv4.dns 8.8.8.8
```

### DNS Query Tools

**dig (Domain Information Groper):**
```bash
# Basic query
dig example.com

# Query specific type
dig example.com A
dig example.com AAAA
dig example.com MX
dig example.com NS

# Short answer only
dig +short example.com

# Query specific server
dig @8.8.8.8 example.com

# Reverse lookup
dig -x 93.184.216.34

# Trace query path
dig +trace example.com
```

**nslookup:**
```bash
# Basic query
nslookup example.com

# Query specific server
nslookup example.com 8.8.8.8

# Reverse lookup
nslookup 93.184.216.34

# Interactive mode
nslookup
> set type=MX
> example.com
> exit
```

**host:**
```bash
# Basic query
host example.com

# Query specific type
host -t A example.com
host -t MX example.com

# Reverse lookup
host 93.184.216.34

# Query specific server
host example.com 8.8.8.8
```

**getent:**
```bash
# Query using system resolver (honors /etc/hosts)
getent hosts example.com
getent hosts 93.184.216.34
```

### DNS Troubleshooting Steps

**Step 1: Check basic connectivity**
```bash
# Can you reach DNS server?
ping 8.8.8.8

# Can you reach any IP?
ping 1.1.1.1
```

**Step 2: Check DNS configuration**
```bash
# What DNS servers are configured?
cat /etc/resolv.conf

# With systemd-resolved
resolvectl status

# With NetworkManager
nmcli dev show | grep DNS
```

**Step 3: Test DNS resolution**
```bash
# Can you resolve hostnames?
dig example.com
nslookup example.com
host example.com

# Try specific DNS server
dig @8.8.8.8 example.com
```

**Step 4: Check /etc/hosts**
```bash
cat /etc/hosts
getent hosts problematic-hostname
```

**Step 5: Check nsswitch order**
```bash
cat /etc/nsswitch.conf | grep hosts
```

**Step 6: Check firewall**
```bash
# Is DNS port 53 open?
sudo iptables -L -n | grep 53
sudo ss -tunlp | grep 53
```

**Step 7: Flush DNS cache**
```bash
# systemd-resolved
sudo resolvectl flush-caches

# nscd (if installed)
sudo systemctl restart nscd

# dnsmasq (if installed)
sudo systemctl restart dnsmasq
```

### Common DNS Problems

**Problem: "Could not resolve hostname"**
```bash
# Check DNS servers
cat /etc/resolv.conf

# Test with known good DNS
dig @8.8.8.8 example.com

# Fix: Update DNS servers
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf
```

**Problem: Slow DNS resolution**
```bash
# Test query time
time dig example.com

# Try different DNS server
time dig @1.1.1.1 example.com

# Check for IPv6 timeout issues
dig example.com AAAA
```

**Problem: resolv.conf keeps getting overwritten**
```bash
# Make immutable (not recommended)
sudo chattr +i /etc/resolv.conf

# Better: configure through NetworkManager
sudo nmcli con mod enp3s0 ipv4.dns "8.8.8.8"
sudo nmcli con mod enp3s0 ipv4.ignore-auto-dns yes

# Or use systemd-resolved
sudo nano /etc/systemd/resolved.conf
```

**Problem: Some domains don't resolve**
```bash
# Check if DNS server has the record
dig @8.8.8.8 problematic-domain.com

# Try authoritative nameserver
dig +trace problematic-domain.com

# Check DNSSEC
dig +dnssec problematic-domain.com
```

**Problem: Reverse DNS not working**
```bash
# Test reverse lookup
dig -x 93.184.216.34
host 93.184.216.34

# May be normal if PTR record doesn't exist
```

### DNS Configuration by Distribution

**Ubuntu (with systemd-resolved):**
```bash
# View status
resolvectl status

# Edit config
sudo nano /etc/systemd/resolved.conf

# Restart
sudo systemctl restart systemd-resolved
```

**Ubuntu (with netplan):**
```yaml
# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  ethernets:
    enp3s0:
      dhcp4: false
      addresses: [192.168.1.100/24]
      gateway4: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]
        search: [example.com]
```

```bash
sudo netplan apply
```

**Red Hat/CentOS (NetworkManager):**
```bash
sudo nmcli con mod enp3s0 ipv4.dns "8.8.8.8 1.1.1.1"
sudo nmcli con mod enp3s0 ipv4.dns-search "example.com"
sudo nmcli con up enp3s0
```

**Debian (legacy):**
```bash
# /etc/network/interfaces
iface enp3s0 inet static
    dns-nameservers 8.8.8.8 1.1.1.1
    dns-search example.com
```
