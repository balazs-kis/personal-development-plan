## Introduction

SSH (Secure Shell) is the standard protocol for secure remote access to Linux systems. Properly configuring and hardening SSH is critical for security, especially on internet-facing servers. A misconfigured SSH server can be a major vulnerability, while a well-secured one provides reliable, safe remote access.

This lesson covers essential SSH security practices that every backend engineer should know.

## Key Concepts Summary

### SSH Basics

**What is SSH?**
- Secure Shell protocol
- Encrypted remote access
- Default port: 22
- Uses public key cryptography
- Replaces insecure telnet, rlogin, rsh

**SSH components:**
```
Client: ssh, scp, sftp
Server: sshd (SSH daemon)
Config: /etc/ssh/sshd_config (server)
        ~/.ssh/config (client)
Keys:   ~/.ssh/id_rsa (private key)
        ~/.ssh/id_rsa.pub (public key)
        ~/.ssh/authorized_keys (allowed keys)
```

**How SSH works:**
```
1. Client connects to server port 22
2. Server sends public key
3. Client verifies server identity
4. Encrypted session established
5. Client authenticates (password or key)
6. Secure shell session active
```

### Basic SSH Usage

**Connect to remote host:**
```bash
ssh username@hostname
ssh username@192.168.1.100
ssh user@example.com

# Specify port
ssh -p 2222 user@hostname

# Run command without shell
ssh user@hostname 'ls -la'

# Enable verbose mode (debugging)
ssh -v user@hostname
ssh -vv user@hostname  # More verbose
```

**Copy files with scp:**
```bash
# Copy to remote
scp file.txt user@hostname:/path/to/destination/

# Copy from remote
scp user@hostname:/path/to/file.txt ./

# Copy directory
scp -r directory/ user@hostname:/path/

# Specify port
scp -P 2222 file.txt user@hostname:/path/
```

**SFTP (Secure FTP):**
```bash
sftp user@hostname

# SFTP commands:
ls          # List remote files
lls         # List local files
cd          # Change remote directory
lcd         # Change local directory
put file    # Upload file
get file    # Download file
quit        # Exit
```

### SSH Key-Based Authentication

**Why use keys?**
- More secure than passwords
- Can't be brute-forced
- Can be passwordless or passphrase-protected
- One key can access many servers

**Generate SSH key pair:**
```bash
# Generate RSA key (2048-bit minimum, 4096-bit recommended)
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

# Generate Ed25519 key (modern, recommended)
ssh-keygen -t ed25519 -C "your_email@example.com"

# Specify filename
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_work

# Enter passphrase (recommended for security)
```

**Key files created:**
```
~/.ssh/id_ed25519       # Private key (keep secret!)
~/.ssh/id_ed25519.pub   # Public key (share with servers)
```

**Copy public key to server:**
```bash
# Easy way (if password auth still enabled)
ssh-copy-id user@hostname
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@hostname

# Manual way
cat ~/.ssh/id_ed25519.pub | ssh user@hostname 'cat >> ~/.ssh/authorized_keys'

# Or copy-paste manually
cat ~/.ssh/id_ed25519.pub
# Copy output, then on server:
mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "paste_public_key_here" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

**Connect using key:**
```bash
ssh user@hostname
# Should connect without password

# Specify key file
ssh -i ~/.ssh/id_ed25519_work user@hostname
```

**Multiple keys:**
```bash
# Create ~/.ssh/config
Host workserver
    HostName work.example.com
    User username
    IdentityFile ~/.ssh/id_ed25519_work
    Port 22

Host homeserver
    HostName home.example.com
    User admin
    IdentityFile ~/.ssh/id_ed25519_home
    Port 2222

# Connect using alias
ssh workserver
ssh homeserver
```

### SSH Server Configuration

**Configuration file: /etc/ssh/sshd_config**

**View current config:**
```bash
sudo cat /etc/ssh/sshd_config
```

**Always backup before editing:**
```bash
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.backup
```

**Edit configuration:**
```bash
sudo nano /etc/ssh/sshd_config
```

**Test configuration:**
```bash
sudo sshd -t
```

**Apply changes:**
```bash
sudo systemctl restart sshd
# or
sudo systemctl reload sshd
```

### Essential Security Settings

**Disable root login:**
```bash
PermitRootLogin no
```

**Disable password authentication (after setting up keys!):**
```bash
PasswordAuthentication no
PubkeyAuthentication yes
```

**Change default port:**
```bash
Port 2222  # Use port 1024-65535
```

**Limit users:**
```bash
AllowUsers alice bob
# or
AllowGroups sshusers
```

**Disable empty passwords:**
```bash
PermitEmptyPasswords no
```

**Use Protocol 2 only:**
```bash
Protocol 2
```

**Set login grace time:**
```bash
LoginGraceTime 60
```

**Limit authentication attempts:**
```bash
MaxAuthTries 3
MaxSessions 2
```

**Disable X11 forwarding (if not needed):**
```bash
X11Forwarding no
```

**Disable port forwarding (if not needed):**
```bash
AllowTcpForwarding no
AllowStreamLocalForwarding no
GatewayPorts no
```

### Complete Hardened Configuration

**Secure /etc/ssh/sshd_config:**
```bash
# Network
Port 2222
AddressFamily inet
ListenAddress 0.0.0.0

# Protocol
Protocol 2

# Host keys
HostKey /etc/ssh/ssh_host_ed25519_key
HostKey /etc/ssh/ssh_host_rsa_key

# Ciphers and keying
Ciphers chacha20-poly1305@openssh.com,aes256-gcm@openssh.com
MACs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com
KexAlgorithms curve25519-sha256,curve25519-sha256@libssh.org,diffie-hellman-group16-sha512

# Authentication
PermitRootLogin no
PasswordAuthentication no
PermitEmptyPasswords no
ChallengeResponseAuthentication no
PubkeyAuthentication yes
AuthenticationMethods publickey

# Access control
AllowUsers alice bob
MaxAuthTries 3
MaxSessions 2
LoginGraceTime 60

# Forwarding
X11Forwarding no
AllowTcpForwarding no
AllowAgentForwarding no
AllowStreamLocalForwarding no
GatewayPorts no
PermitTunnel no

# Logging
SyslogFacility AUTH
LogLevel VERBOSE

# Other
PrintMotd no
PrintLastLog yes
TCPKeepAlive yes
UsePAM yes
ClientAliveInterval 300
ClientAliveCountMax 2
```

**Test and apply:**
```bash
sudo sshd -t
sudo systemctl restart sshd
```

### SSH Hardening Checklist

**Before disabling password auth:**
- ✅ Generate SSH keys
- ✅ Copy public keys to server
- ✅ Test key-based login
- ✅ Keep backup session open

**Security measures:**
- ✅ Disable root login
- ✅ Disable password authentication
- ✅ Change default port
- ✅ Limit allowed users
- ✅ Set max auth tries
- ✅ Use strong ciphers
- ✅ Enable verbose logging
- ✅ Set login grace time
- ✅ Disable unnecessary features

**Additional hardening:**
- ✅ Use Fail2Ban to block brute force
- ✅ Use firewall to restrict SSH access by IP
- ✅ Use SSH certificates (advanced)
- ✅ Monitor SSH logs regularly
- ✅ Keep OpenSSH updated

### Fail2Ban Integration

**Install Fail2Ban:**
```bash
sudo apt install fail2ban  # Ubuntu/Debian
sudo dnf install fail2ban  # Red Hat/Fedora
```

**Configure SSH jail:**
```bash
# /etc/fail2ban/jail.local
[sshd]
enabled = true
port = 2222
logpath = /var/log/auth.log
maxretry = 3
bantime = 3600
findtime = 600
```

**Start Fail2Ban:**
```bash
sudo systemctl enable fail2ban
sudo systemctl start fail2ban
```

**Check banned IPs:**
```bash
sudo fail2ban-client status sshd
```

### SSH Advanced Features

**Port forwarding (local):**
```bash
# Forward local port 8080 to remote server's port 80
ssh -L 8080:localhost:80 user@hostname

# Access remote web server on local http://localhost:8080
```

**Port forwarding (remote):**
```bash
# Forward remote port 8080 to local port 80
ssh -R 8080:localhost:80 user@hostname
```

**Dynamic port forwarding (SOCKS proxy):**
```bash
ssh -D 8080 user@hostname

# Configure browser to use SOCKS5 proxy localhost:8080
```

**SSH tunneling:**
```bash
# Access database through bastion host
ssh -L 5432:db-server:5432 user@bastion-host

# Connect to localhost:5432 to reach db-server
```

**SSH agent forwarding:**
```bash
ssh -A user@hostname

# In ~/.ssh/config:
Host hostname
    ForwardAgent yes
```

**ProxyJump (bastion host):**
```bash
# Connect through jump host
ssh -J user@bastion user@internal-server

# In ~/.ssh/config:
Host internal-server
    ProxyJump user@bastion
    HostName 10.0.1.100
```

### Troubleshooting

**Connection refused:**
```bash
# Check SSH service is running
sudo systemctl status sshd

# Check port
sudo ss -tlnp | grep sshd

# Check firewall
sudo iptables -L -n | grep 22
sudo firewall-cmd --list-all
```

**Permission denied:**
```bash
# Check key permissions (must be 600)
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub

# Check authorized_keys
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

# Verify public key is in authorized_keys
cat ~/.ssh/authorized_keys
```

**Too many authentication failures:**
```bash
# Limit identity files tried
ssh -o IdentitiesOnly=yes -i ~/.ssh/specific_key user@host
```

**Debug connection:**
```bash
ssh -vvv user@hostname

# On server, check logs
sudo tail -f /var/log/auth.log
sudo journalctl -u sshd -f
```

**Check SSH server config:**
```bash
sudo sshd -t  # Test configuration
sudo sshd -T  # Dump effective configuration
```

### Monitoring SSH Access

**View SSH logs:**
```bash
# Ubuntu/Debian
sudo tail -f /var/log/auth.log

# Red Hat/CentOS
sudo tail -f /var/log/secure

# systemd
sudo journalctl -u sshd -f
```

**Failed login attempts:**
```bash
sudo grep "Failed password" /var/log/auth.log
sudo grep "Invalid user" /var/log/auth.log
```

**Successful logins:**
```bash
sudo grep "Accepted" /var/log/auth.log
```

**Active SSH sessions:**
```bash
who
w
last
```
