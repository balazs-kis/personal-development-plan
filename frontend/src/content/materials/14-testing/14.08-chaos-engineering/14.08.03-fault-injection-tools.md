## Key Concepts Summary

### Fault Injection Categories

#### 1. Infrastructure Faults
- **Instance/Pod failures:** Terminate containers or VMs
- **Network issues:** Packet loss, latency, partitions
- **Resource exhaustion:** CPU, memory, disk stress
- **DNS failures:** Lookup failures or delays

#### 2. Application Faults
- **Exceptions:** Thrown errors and failures
- **Latency:** Artificial delays in processing
- **Result substitution:** Return error responses
- **Behavior modification:** Custom fault behaviors

#### 3. Dependency Faults
- **Service unavailability:** External services down
- **Database issues:** Connection failures, slow queries
- **API failures:** HTTP errors, timeouts
- **Message broker problems:** Queue unavailability

### Simmy: Chaos Engineering for .NET

**Simmy** is a chaos-engineering library for .NET that integrates with Polly (the resilience and transient-fault-handling library).

**Key Features:**
- Integrates seamlessly with existing Polly policies
- Chaos policies can be toggled on/off at runtime
- Supports fault, latency, and behavior injection
- Works with dependency injection
- Production-safe with configurable injection rates

### Fault Injection with Simmy

#### Basic Fault Policy

**Inject exceptions:**

```csharp
using Polly;
using Polly.Contrib.Simmy;
using Polly.Contrib.Simmy.Outcomes;

// Create a chaos policy that injects exceptions
var chaosPolicy = MonkeyPolicy.InjectException(with =>
    with.Fault(new InvalidOperationException("Chaos monkey exception!"))
        .InjectionRate(0.1)  // 10% of requests
        .Enabled()
);

// Use the policy
var result = await chaosPolicy.ExecuteAsync(async () =>
{
    return await httpClient.GetStringAsync("https://api.example.com/users");
});
```

**Inject specific HTTP errors:**

```csharp
var chaosPolicy = MonkeyPolicy.InjectResult<HttpResponseMessage>(with =>
    with.Result(new HttpResponseMessage(HttpStatusCode.InternalServerError))
        .InjectionRate(0.05)  // 5% of requests
        .Enabled()
);

var response = await chaosPolicy.ExecuteAsync(async () =>
{
    return await httpClient.GetAsync("https://api.example.com/users");
});
```

#### Conditional Fault Injection

**Only inject faults when enabled:**

```csharp
public class ChaosSettings
{
    public bool ChaosEnabled { get; set; }
    public double InjectionRate { get; set; } = 0.1;
}

var settings = new ChaosSettings { ChaosEnabled = true };

var chaosPolicy = MonkeyPolicy.InjectException(with =>
    with.Fault(new TimeoutException("Simulated timeout"))
        .InjectionRate(settings.InjectionRate)
        .EnabledWhen((context) => settings.ChaosEnabled)
);
```

**Inject faults based on context:**

```csharp
var chaosPolicy = MonkeyPolicy.InjectException(with =>
    with.Fault(new HttpRequestException("Service unavailable"))
        .InjectionRate(0.1)
        .EnabledWhen((context) => 
        {
            // Only inject chaos for specific endpoints
            return context.ContainsKey("endpoint") && 
                   context["endpoint"].ToString().Contains("/orders");
        })
);

// Use with context
var context = new Context { ["endpoint"] = "/api/orders" };
await chaosPolicy.ExecuteAsync((ctx) => CallOrdersApi(), context);
```

### Latency Injection with Simmy

**Add artificial delays:**

```csharp
using Polly.Contrib.Simmy.Latency;

var latencyPolicy = MonkeyPolicy.InjectLatency(with =>
    with.Latency(TimeSpan.FromSeconds(5))  // 5 second delay
        .InjectionRate(0.1)  // 10% of requests
        .Enabled()
);

var result = await latencyPolicy.ExecuteAsync(async () =>
{
    return await httpClient.GetStringAsync("https://api.example.com/users");
});
```

**Variable latency:**

```csharp
var random = new Random();

var latencyPolicy = MonkeyPolicy.InjectLatency(with =>
    with.Latency(() => TimeSpan.FromMilliseconds(random.Next(100, 5000)))
        .InjectionRate(0.2)
        .Enabled()
);
```

**Latency with distribution:**

```csharp
// Simulate realistic network latency distribution
var latencyPolicy = MonkeyPolicy.InjectLatency(with =>
    with.Latency(() =>
    {
        // 80% fast (100-200ms), 15% medium (500-1000ms), 5% slow (2-5s)
        var rand = random.NextDouble();
        if (rand < 0.80)
            return TimeSpan.FromMilliseconds(random.Next(100, 200));
        else if (rand < 0.95)
            return TimeSpan.FromMilliseconds(random.Next(500, 1000));
        else
            return TimeSpan.FromSeconds(random.Next(2, 5));
    })
    .InjectionRate(0.3)
    .Enabled()
);
```

### Behavior Injection with Simmy

**Execute custom behavior:**

```csharp
using Polly.Contrib.Simmy.Behavior;

var behaviorPolicy = MonkeyPolicy.InjectBehavior(with =>
    with.Behavior(() => 
    {
        // Custom chaos behavior
        Console.WriteLine("Chaos monkey is causing trouble!");
        
        // Could do anything here:
        // - Log to special chaos log
        // - Increment chaos metric counter
        // - Trigger alert
        // - Modify request/response
    })
    .InjectionRate(0.1)
    .Enabled()
);
```

**Modify application state:**

```csharp
var behaviorPolicy = MonkeyPolicy.InjectBehavior(with =>
    with.Behavior(() =>
    {
        // Simulate memory pressure
        var list = new List<byte[]>();
        for (int i = 0; i < 100; i++)
        {
            list.Add(new byte[1024 * 1024]); // Allocate 1MB
        }
        Thread.Sleep(1000);
    })
    .InjectionRate(0.05)
    .Enabled()
);
```

### Combining Simmy with Polly Resilience Policies

**The power of Simmy:** Test your resilience policies!

```csharp
using Polly;
using Polly.Contrib.Simmy;
using Polly.Contrib.Simmy.Outcomes;
using Polly.Timeout;
using Polly.CircuitBreaker;

// 1. Define resilience policies
var retryPolicy = Policy
    .Handle<HttpRequestException>()
    .WaitAndRetryAsync(3, retryAttempt => 
        TimeSpan.FromSeconds(Math.Pow(2, retryAttempt)));

var circuitBreakerPolicy = Policy
    .Handle<HttpRequestException>()
    .CircuitBreakerAsync(
        handledEventsAllowedBeforeBreaking: 5,
        durationOfBreak: TimeSpan.FromSeconds(30)
    );

var timeoutPolicy = Policy
    .TimeoutAsync(TimeSpan.FromSeconds(10), TimeoutStrategy.Pessimistic);

// 2. Define chaos policy
var chaosPolicy = MonkeyPolicy.InjectException(with =>
    with.Fault(new HttpRequestException("Chaos-injected failure"))
        .InjectionRate(0.1)
        .Enabled()
);

// 3. Wrap policies together (order matters!)
var policyWrap = Policy.WrapAsync(
    retryPolicy,           // Outermost: Retry if failures occur
    circuitBreakerPolicy,  // Middle: Break circuit if too many failures
    timeoutPolicy,         // Prevent indefinite waits
    chaosPolicy            // Innermost: Inject chaos
);

// 4. Execute with all policies
var result = await policyWrap.ExecuteAsync(async () =>
{
    return await httpClient.GetStringAsync("https://api.example.com/users");
});
```

**What this tests:**
- Does retry policy handle the injected failures?
- Does circuit breaker open after enough failures?
- Does timeout policy prevent hanging?
- Does the application handle all these gracefully?

### ASP.NET Core Integration

#### Startup Configuration

```csharp
// Program.cs or Startup.cs
public class ChaosSettings
{
    public bool Enabled { get; set; }
    public double ExceptionInjectionRate { get; set; }
    public double LatencyInjectionRate { get; set; }
    public int LatencyMs { get; set; }
}

// appsettings.json
{
  "Chaos": {
    "Enabled": true,
    "ExceptionInjectionRate": 0.05,
    "LatencyInjectionRate": 0.1,
    "LatencyMs": 1000
  }
}

// Configure services
builder.Services.Configure<ChaosSettings>(
    builder.Configuration.GetSection("Chaos"));

// Add HttpClient with chaos policies
builder.Services.AddHttpClient("ChaosClient")
    .AddTransientHttpErrorPolicy(policyBuilder =>
        policyBuilder.WaitAndRetryAsync(3, retryAttempt =>
            TimeSpan.FromSeconds(Math.Pow(2, retryAttempt))))
    .AddPolicyHandler((services, request) =>
    {
        var chaosSettings = services.GetRequiredService<IOptions<ChaosSettings>>().Value;
        
        return MonkeyPolicy.InjectException(with =>
            with.Fault(new HttpRequestException("Chaos fault"))
                .InjectionRate(chaosSettings.ExceptionInjectionRate)
                .EnabledWhen(_ => chaosSettings.Enabled)
        );
    })
    .AddPolicyHandler((services, request) =>
    {
        var chaosSettings = services.GetRequiredService<IOptions<ChaosSettings>>().Value;
        
        return MonkeyPolicy.InjectLatency(with =>
            with.Latency(TimeSpan.FromMilliseconds(chaosSettings.LatencyMs))
                .InjectionRate(chaosSettings.LatencyInjectionRate)
                .EnabledWhen(_ => chaosSettings.Enabled)
        );
    });
```

#### Using in Controllers

```csharp
[ApiController]
[Route("api/[controller]")]
public class UsersController : ControllerBase
{
    private readonly IHttpClientFactory _httpClientFactory;
    private readonly ILogger<UsersController> _logger;

    public UsersController(
        IHttpClientFactory httpClientFactory,
        ILogger<UsersController> logger)
    {
        _httpClientFactory = httpClientFactory;
        _logger = logger;
    }

    [HttpGet]
    public async Task<IActionResult> GetUsers()
    {
        try
        {
            var client = _httpClientFactory.CreateClient("ChaosClient");
            var response = await client.GetStringAsync("https://external-api.com/users");
            return Ok(response);
        }
        catch (HttpRequestException ex)
        {
            _logger.LogError(ex, "Failed to fetch users");
            return StatusCode(503, "Service temporarily unavailable");
        }
        catch (TimeoutException ex)
        {
            _logger.LogError(ex, "Request timed out");
            return StatusCode(504, "Gateway timeout");
        }
    }
}
```

### Chaos Middleware

**Create middleware for endpoint-level chaos:**

```csharp
public class ChaosMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ChaosSettings _settings;
    private readonly Random _random;

    public ChaosMiddleware(
        RequestDelegate next, 
        IOptions<ChaosSettings> settings)
    {
        _next = next;
        _settings = settings.Value;
        _random = new Random();
    }

    public async Task InvokeAsync(HttpContext context)
    {
        if (_settings.Enabled && ShouldInjectChaos())
        {
            // Inject latency
            if (_random.NextDouble() < _settings.LatencyInjectionRate)
            {
                await Task.Delay(_settings.LatencyMs);
            }

            // Inject errors
            if (_random.NextDouble() < _settings.ExceptionInjectionRate)
            {
                context.Response.StatusCode = 503;
                await context.Response.WriteAsync("Chaos-injected failure");
                return;
            }
        }

        await _next(context);
    }

    private bool ShouldInjectChaos()
    {
        // Don't inject chaos for health checks
        return !_context.Request.Path.StartsWithSegments("/health");
    }
}

// Register middleware
app.UseMiddleware<ChaosMiddleware>();
```

### Testing Resilience Patterns

#### Test Circuit Breaker

```csharp
// Setup: Circuit breaker + chaos
var circuitBreaker = Policy
    .Handle<HttpRequestException>()
    .CircuitBreakerAsync(
        handledEventsAllowedBeforeBreaking: 3,
        durationOfBreak: TimeSpan.FromSeconds(30),
        onBreak: (ex, duration) => 
            Console.WriteLine($"Circuit opened for {duration}"),
        onReset: () => 
            Console.WriteLine("Circuit reset"),
        onHalfOpen: () => 
            Console.WriteLine("Circuit half-open")
    );

var chaos = MonkeyPolicy.InjectException(with =>
    with.Fault(new HttpRequestException("Chaos fault"))
        .InjectionRate(0.5)  // 50% failure rate
        .Enabled()
);

var policy = Policy.WrapAsync(circuitBreaker, chaos);

// Test: Should open circuit after 3 failures
for (int i = 0; i < 10; i++)
{
    try
    {
        await policy.ExecuteAsync(() => CallExternalApi());
        Console.WriteLine($"Request {i}: Success");
    }
    catch (BrokenCircuitException)
    {
        Console.WriteLine($"Request {i}: Circuit open!");
    }
    catch (HttpRequestException)
    {
        Console.WriteLine($"Request {i}: Failed");
    }
    
    await Task.Delay(1000);
}
```

#### Test Retry with Exponential Backoff

```csharp
var retry = Policy
    .Handle<HttpRequestException>()
    .WaitAndRetryAsync(
        retryCount: 5,
        sleepDurationProvider: retryAttempt => 
            TimeSpan.FromSeconds(Math.Pow(2, retryAttempt)),
        onRetry: (exception, timeSpan, retryCount, context) =>
        {
            Console.WriteLine($"Retry {retryCount} after {timeSpan.TotalSeconds}s");
        }
    );

var chaos = MonkeyPolicy.InjectException(with =>
    with.Fault(new HttpRequestException("Transient failure"))
        .InjectionRate(0.8)  // 80% failure rate initially
        .Enabled()
);

var policy = Policy.WrapAsync(retry, chaos);

// Should eventually succeed due to retries
var result = await policy.ExecuteAsync(() => CallExternalApi());
```

#### Test Fallback

```csharp
var fallback = Policy<string>
    .Handle<HttpRequestException>()
    .FallbackAsync(
        fallbackValue: "[]",  // Empty array as fallback
        onFallbackAsync: async (result, context) =>
        {
            Console.WriteLine("Using fallback response");
            await Task.CompletedTask;
        }
    );

var chaos = MonkeyPolicy.InjectException(with =>
    with.Fault(new HttpRequestException("Service down"))
        .InjectionRate(1.0)  // 100% failure
        .Enabled()
);

var policy = Policy.WrapAsync(fallback, chaos);

// Should return fallback value instead of failing
var result = await policy.ExecuteAsync(() => GetUsersFromApi());
Console.WriteLine($"Result: {result}"); // Output: "[]"
```

## Best Practices

### ✅ Do's

1. **Start in development/staging** before production
2. **Use feature flags** to enable/disable chaos easily
3. **Make injection rates configurable** via settings
4. **Log chaos events** for observability
5. **Test resilience patterns** with realistic failures
6. **Gradually increase chaos** as confidence grows
7. **Combine chaos with monitoring** to observe effects

### ❌ Don'ts

1. **Don't enable chaos in production** without testing first
2. **Don't use high injection rates** (start with 1-5%)
3. **Don't inject chaos without monitoring** what happens
4. **Don't forget rollback mechanisms**
5. **Don't inject chaos on health checks** or critical paths initially
6. **Don't leave chaos always enabled** in production
7. **Don't inject chaos without team awareness**
