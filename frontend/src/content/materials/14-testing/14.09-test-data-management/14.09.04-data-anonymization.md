- Distinguish between anonymization and pseudonymization

- Use tools and libraries to anonymize production data for testing
- Design test data strategies that maintain compliance

---

## Introduction

Using production data for testing is tempting—it's realistic and catches edge cases—but it's also dangerous. Privacy regulations like GDPR, HIPAA, and CCPA impose strict requirements on personal data handling. This lesson teaches you how to protect sensitive data while maintaining test data realism through anonymization and masking techniques.

**Key principle:** Under GDPR, once data is truly anonymized (irreversibly), it's no longer personal data and regulations no longer apply. But pseudonymization (reversible) still counts as personal data.

## Key Concepts Summary

### Legal Context: GDPR and Personal Data

```
Personal Data (GDPR Article 4):
"Any information relating to an identified or identifiable natural person"

Key Point: Both direct identifiers (name, email) and indirect identifiers 
(combination of age, zip code, gender) count as personal data.

GDPR Requirements for Test Data:
1. Lawful Basis: Need legal basis to process personal data (even for testing)
2. Purpose Limitation: Can't use production data for unrelated purposes
3. Data Minimization: Use minimum data necessary
4. Storage Limitation: Don't keep longer than necessary
5. Integrity & Confidentiality: Protect from unauthorized access

Penalties: Up to €20 million or 4% of global annual revenue (whichever is higher)
```

### Anonymization vs Pseudonymization

```
┌─────────────────────────────────────────────────────────────┐
│ ANONYMIZATION (Irreversible)                                │
├─────────────────────────────────────────────────────────────┤
│ Definition: Data cannot be linked back to individual        │
│ GDPR Status: NOT personal data (regulations don't apply)    │
│ Reversible: NO - identity cannot be recovered               │
│ Example: Name → "Person 1", Email → removed entirely        │
│ Use Case: Public datasets, long-term analytics, testing     │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ PSEUDONYMIZATION (Reversible)                               │
├─────────────────────────────────────────────────────────────┤
│ Definition: Identifiers replaced with tokens/codes          │
│ GDPR Status: STILL personal data (full regulations apply)   │
│ Reversible: YES - with additional information (keys)        │
│ Example: Name → "ID-12345", reversible via lookup table     │
│ Use Case: Internal processing, production systems           │
└─────────────────────────────────────────────────────────────┘

Common Mistake: Thinking pseudonymization = anonymization
Reality: Pseudonymized data is still personal data under GDPR!
```

### Anonymization Techniques

```csharp
// 1. DATA MASKING - Replace sensitive values with realistic alternatives
public class DataMasking
{
    public static string MaskEmail(string email)
    {
        // Original: john.doe@example.com
        // Masked: xxxx.xxx@example.com
        var parts = email.Split('@');
        return $"xxxx.xxx@{parts[1]}";
    }
    
    public static string MaskCreditCard(string cardNumber)
    {
        // Original: 1234-5678-9012-3456
        // Masked: ****-****-****-3456
        return $"****-****-****-{cardNumber[^4..]}";
    }
    
    public static string MaskPhoneNumber(string phone)
    {
        // Original: (555) 123-4567
        // Masked: (XXX) XXX-4567
        return $"(XXX) XXX-{phone[^4..]}";
    }
}

// 2. GENERALIZATION - Reduce precision to prevent identification
public class Generalization
{
    public static string GeneralizeAge(int age)
    {
        // Original: 27
        // Generalized: "25-30"
        return age switch
        {
            < 18 => "Under 18",
            >= 18 and < 25 => "18-24",
            >= 25 and < 35 => "25-34",
            >= 35 and < 45 => "35-44",
            >= 45 and < 55 => "45-54",
            >= 55 and < 65 => "55-64",
            _ => "65+"
        };
    }
    
    public static string GeneralizeZipCode(string zipCode)
    {
        // Original: 62701
        // Generalized: 627XX (keep first 3 digits)
        return zipCode.Length >= 3 ? $"{zipCode[..3]}XX" : zipCode;
    }
    
    public static string GeneralizeIncome(decimal income)
    {
        // Original: $47,523
        // Generalized: "$40,000-$50,000"
        var bracket = Math.Floor(income / 10000) * 10000;
        return $"${bracket:N0}-${bracket + 10000:N0}";
    }
}

// 3. NOISE ADDITION - Add random variation to numeric data
public class NoiseAddition
{
    private static readonly Random _random = new Random();
    
    public static decimal AddNoise(decimal value, double percentVariation = 0.1)
    {
        // Add ±10% random noise
        var noise = value * (decimal)(_random.NextDouble() * percentVariation * 2 - percentVariation);
        return value + noise;
    }
    
    public static DateTime AddNoise(DateTime date, int maxDayVariation = 7)
    {
        // Add random days ±7 days
        var days = _random.Next(-maxDayVariation, maxDayVariation + 1);
        return date.AddDays(days);
    }
}

// 4. DATA SWAPPING - Exchange values between records
public class DataSwapping
{
    public static void SwapAddresses(List<Customer> customers)
    {
        // Shuffle addresses among customers
        var addresses = customers.Select(c => c.Address).ToList();
        addresses = addresses.OrderBy(_ => Guid.NewGuid()).ToList();
        
        for (int i = 0; i < customers.Count; i++)
        {
            customers[i].Address = addresses[i];
        }
    }
}

// 5. AGGREGATION - Combine data to hide individuals
public class Aggregation
{
    public static IEnumerable<AggregateData> AggregateByRegion(
        IEnumerable<Customer> customers)
    {
        // Original: Individual customer records
        // Aggregated: Summary statistics per region
        return customers
            .GroupBy(c => c.Region)
            .Select(g => new AggregateData
            {
                Region = g.Key,
                CustomerCount = g.Count(),
                AveragePurchaseAmount = g.Average(c => c.TotalPurchases),
                MedianAge = CalculateMedian(g.Select(c => c.Age))
            });
    }
}
```

### Practical Anonymization Implementation

```csharp
// Complete anonymization utility using Bogus
using Bogus;

public class CustomerAnonymizer
{
    private readonly Faker _faker;
    private readonly Dictionary<string, string> _emailMapping;
    
    public CustomerAnonymizer()
    {
        _faker = new Faker();
        _emailMapping = new Dictionary<string, string>();
    }
    
    public Customer Anonymize(Customer customer)
    {
        return new Customer
        {
            Id = customer.Id, // Keep ID for referential integrity
            
            // Replace with fake data
            FirstName = _faker.Name.FirstName(),
            LastName = _faker.Name.LastName(),
            Email = GenerateConsistentEmail(customer.Email),
            Phone = _faker.Phone.PhoneNumber(),
            
            // Generalize sensitive data
            DateOfBirth = GeneralizeDateOfBirth(customer.DateOfBirth),
            
            // Keep non-sensitive data
            Country = customer.Country,
            AccountCreatedAt = customer.AccountCreatedAt,
            
            // Anonymize nested objects
            Address = AnonymizeAddress(customer.Address),
            
            // Preserve relationships
            Orders = customer.Orders // IDs maintained for FK relationships
        };
    }
    
    private string GenerateConsistentEmail(string originalEmail)
    {
        // Same original email always maps to same fake email
        if (_emailMapping.TryGetValue(originalEmail, out var fakeEmail))
        {
            return fakeEmail;
        }
        
        fakeEmail = _faker.Internet.Email();
        _emailMapping[originalEmail] = fakeEmail;
        return fakeEmail;
    }
    
    private DateTime GeneralizeDateOfBirth(DateTime dob)
    {
        // Keep only year, set to Jan 1
        return new DateTime(dob.Year, 1, 1);
    }
    
    private Address AnonymizeAddress(Address address)
    {
        return new Address
        {
            Id = address.Id,
            Street = _faker.Address.StreetAddress(),
            City = address.City, // Keep city for testing location-based logic
            State = address.State,
            // Generalize zip code
            ZipCode = address.ZipCode.Length >= 3 
                ? $"{address.ZipCode[..3]}XX" 
                : address.ZipCode,
            Country = address.Country
        };
    }
}

// Usage
public async Task AnonymizeDatabase()
{
    var anonymizer = new CustomerAnonymizer();
    var customers = await _context.Customers
        .Include(c => c.Address)
        .Include(c => c.Orders)
        .ToListAsync();
    
    foreach (var customer in customers)
    {
        var anonymized = anonymizer.Anonymize(customer);
        _context.Entry(customer).CurrentValues.SetValues(anonymized);
    }
    
    await _context.SaveChangesAsync();
}
```

### Preserving Referential Integrity

```csharp
// Challenge: Anonymizing data while keeping foreign keys intact
public class DatabaseAnonymizer
{
    private readonly ApplicationDbContext _context;
    private readonly Dictionary<string, string> _emailMappings = new();
    private readonly Faker _faker = new();
    
    public async Task AnonymizeFullDatabaseAsync()
    {
        // Order matters! Anonymize in correct sequence
        
        // 1. Anonymize customers (referenced by orders)
        await AnonymizeCustomersAsync();
        
        // 2. Anonymize orders (references customers via FK)
        await AnonymizeOrdersAsync();
        
        // 3. Anonymize payments (references orders via FK)
        await AnonymizePaymentsAsync();
        
        await _context.SaveChangesAsync();
    }
    
    private async Task AnonymizeCustomersAsync()
    {
        var customers = await _context.Customers.ToListAsync();
        
        foreach (var customer in customers)
        {
            // Keep ID - it's the foreign key!
            // Replace PII
            customer.FirstName = _faker.Name.FirstName();
            customer.LastName = _faker.Name.LastName();
            customer.Email = GetConsistentEmail(customer.Email);
            customer.Phone = _faker.Phone.PhoneNumber();
        }
    }
    
    private async Task AnonymizeOrdersAsync()
    {
        var orders = await _context.Orders.ToListAsync();
        
        foreach (var order in orders)
        {
            // Keep CustomerId - FK to Customer!
            // Keep OrderId - FK from OrderLineItems!
            
            // Anonymize payment info
            if (!string.IsNullOrEmpty(order.CreditCardLast4))
            {
                order.CreditCardLast4 = _faker.Finance.CreditCardNumber()[^4..];
            }
            
            // Add noise to amounts (±10%)
            order.Total = AddNoise(order.Total, 0.1m);
        }
    }
    
    private async Task AnonymizePaymentsAsync()
    {
        var payments = await _context.Payments.ToListAsync();
        
        foreach (var payment in payments)
        {
            // Keep OrderId - FK to Order!
            
            // Mask transaction IDs
            payment.TransactionId = Guid.NewGuid().ToString();
            
            // Anonymize payment method details
            payment.PaymentMethodDetails = "ANONYMIZED";
        }
    }
    
    private string GetConsistentEmail(string original)
    {
        if (_emailMappings.TryGetValue(original, out var fake))
            return fake;
        
        fake = _faker.Internet.Email();
        _emailMappings[original] = fake;
        return fake;
    }
    
    private decimal AddNoise(decimal value, decimal percentVariation)
    {
        var noise = value * (decimal)(_faker.Random.Double() * 2 - 1) * percentVariation;
        return value + noise;
    }
}
```

### The "Motivated Intruder" Test

```
The UK ICO's "Motivated Intruder" Test:

Could a reasonably competent person, with access to:
- The anonymized dataset
- Publicly available information
- Reasonable resources and determination

...re-identify individuals?

Example Scenarios:

❌ FAIL: Anonymizing a small dataset
Problem: Dataset of 50 people in a small town
Even with names removed, combination of age, job, education uniquely identifies people

❌ FAIL: Removing direct identifiers but keeping rare attributes
Problem: "Male, age 102, NYC" - likely only one person fits this
Solution: Generalize rare values or remove outliers

✅ PASS: Proper generalization and aggregation
Solution: "Male, age 100+, New York State" with k≥5 similar records

Key Consideration: What information is publicly available?
- Social media profiles
- Public records
- News articles
- Directory listings
```

### Test Data Compliance Checklist

```csharp
// Automated compliance check for test data
public class TestDataComplianceChecker
{
    public async Task<ComplianceReport> CheckComplianceAsync(
        ApplicationDbContext context)
    {
        var report = new ComplianceReport();
        
        // Check for direct identifiers
        var customersWithRealEmails = await context.Customers
            .Where(c => c.Email.Contains("gmail.com") || 
                       c.Email.Contains("yahoo.com") ||
                       c.Email.Contains("outlook.com"))
            .CountAsync();
        
        if (customersWithRealEmails > 0)
        {
            report.Issues.Add($"Found {customersWithRealEmails} customers with real email domains");
        }
        
        // Check for real credit card patterns
        var ordersWithPotentialRealCards = await context.Orders
            .Where(o => o.CreditCardLast4 != null && 
                       !o.CreditCardLast4.StartsWith("0000"))
            .CountAsync();
        
        if (ordersWithPotentialRealCards > 0)
        {
            report.Warnings.Add($"Found {ordersWithPotentialRealCards} orders with potential real CC info");
        }
        
        // Check for realistic phone numbers (could be real)
        var customersWithRealisticPhones = await context.Customers
            .Where(c => Regex.IsMatch(c.Phone ?? "", @"^\+?1?\d{10,}$"))
            .CountAsync();
        
        if (customersWithRealisticPhones > 0)
        {
            report.Warnings.Add($"Found {customersWithRealisticPhones} customers with realistic phone numbers");
        }
        
        // Check for PII in comments/notes fields
        var ordersWithPotentialPII = await context.Orders
            .Where(o => o.Notes != null && 
                       (o.Notes.Contains("@") || 
                        Regex.IsMatch(o.Notes, @"\b\d{3}-\d{2}-\d{4}\b"))) // SSN pattern
            .CountAsync();
        
        if (ordersWithPotentialPII > 0)
        {
            report.Issues.Add($"Found {ordersWithPotentialPII} orders with potential PII in notes");
        }
        
        report.IsCompliant = !report.Issues.Any();
        return report;
    }
}

public class ComplianceReport
{
    public bool IsCompliant { get; set; }
    public List<string> Issues { get; set; } = new();
    public List<string> Warnings { get; set; } = new();
}
```

```csharp
// Using Bogus for comprehensive anonymization
public class BogusAnonymizer
{
    private readonly Faker _faker = new();
    
    // Create anonymization rules once, reuse for consistency
    private readonly Dictionary<string, Func<Faker, object>> _rules = new()
    {
        ["Name"] = f => f.Name.FullName(),
        ["FirstName"] = f => f.Name.FirstName(),
        ["LastName"] = f => f.Name.LastName(),
        ["Email"] = f => f.Internet.Email(),
        ["Phone"] = f => f.Phone.PhoneNumber(),
        ["Address"] = f => f.Address.FullAddress(),
        ["City"] = f => f.Address.City(),
        ["ZipCode"] = f => f.Address.ZipCode(),
        ["CreditCard"] = f => f.Finance.CreditCardNumber(),
        ["SSN"] = f => f.Random.Replace("###-##-####"),
        ["IPAddress"] = f => f.Internet.Ip(),
        ["UserAgent"] = f => f.Internet.UserAgent(),
        ["CompanyName"] = f => f.Company.CompanyName(),
        ["JobTitle"] = f => f.Name.JobTitle()
    };
    
    public string Anonymize(string fieldName, string originalValue)
    {
        if (_rules.TryGetValue(fieldName, out var rule))
        {
            return rule(_faker).ToString() ?? "";
        }
        
        // Default: return anonymized placeholder
        return $"ANONYMIZED_{fieldName}";
    }
}
```

### Synthetic Data as Alternative

```csharp
// Instead of anonymizing production data, generate synthetic data
public class SyntheticDataGenerator
{
    public async Task GenerateSyntheticDatabaseAsync(
        ApplicationDbContext context, 
        int customerCount = 1000)
    {
        var customerFaker = new Faker<Customer>()
            .RuleFor(c => c.FirstName, f => f.Name.FirstName())
            .RuleFor(c => c.LastName, f => f.Name.LastName())
            .RuleFor(c => c.Email, (f, c) => f.Internet.Email(c.FirstName, c.LastName))
            .RuleFor(c => c.Phone, f => f.Phone.PhoneNumber())
            .RuleFor(c => c.DateOfBirth, f => f.Date.Past(50, DateTime.Now.AddYears(-18)))
            .RuleFor(c => c.Address, f => new Address
            {
                Street = f.Address.StreetAddress(),
                City = f.Address.City(),
                State = f.Address.State(),
                ZipCode = f.Address.ZipCode()
            });
        
        var customers = customerFaker.Generate(customerCount);
        await context.Customers.AddRangeAsync(customers);
        await context.SaveChangesAsync();
        
        // No compliance issues - it's all fake from the start!
    }
}

// Benefits of synthetic data:
// ✅ Zero compliance risk (no real PII)
// ✅ Unlimited volume
// ✅ Controlled characteristics
// ✅ No anonymization overhead
// ❌ May not capture real-world edge cases
// ❌ Requires effort to make realistic
```
