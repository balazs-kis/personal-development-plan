## Introduction

Integration testing often requires external dependencies like databases, message brokers, or caching systems. Testcontainers eliminates the pain of managing these dependencies by spinning up real Docker containers during your tests. This approach provides higher confidence than mocking while maintaining test isolation and reproducibility.

## Key Concepts Summary

### What is Testcontainers?

Testcontainers is a library that provides lightweight, throwaway instances of databases, message brokers, web browsers, or anything that can run in a Docker container. It enables integration testing with real dependencies instead of mocks or in-memory alternatives.

**Key Benefits:**
- **Real Environment Testing:** Test against actual services, catching issues that mocks can't detect
- **Isolation:** Each test can have its own fresh container instance
- **CI/CD Friendly:** Works seamlessly in Docker-enabled environments
- **Reduced Setup:** No need to maintain shared test databases or complex infrastructure

### Basic Setup

Install Testcontainers via NuGet:
```bash
dotnet add package Testcontainers
```

For xUnit integration (recommended):
```bash
dotnet add package Testcontainers.Xunit
```

### Container Lifecycle Management

```csharp
using Testcontainers.PostgreSql;

public class DatabaseTests : IAsyncLifetime
{
    private readonly PostgreSqlContainer _postgres = new PostgreSqlBuilder()
        .WithImage("postgres:16-alpine")
        .WithDatabase("testdb")
        .WithUsername("testuser")
        .WithPassword("testpass")
        .Build();

    public async Task InitializeAsync()
    {
        // Start the container before tests
        await _postgres.StartAsync();
    }

    public async Task DisposeAsync()
    {
        // Stop and remove the container after tests
        await _postgres.DisposeAsync();
    }

    [Fact]
    public async Task CanConnectToDatabase()
    {
        // Get the connection string
        var connectionString = _postgres.GetConnectionString();
        
        // Use the database in your test
        // ...
    }
}
```

### Core Concepts

**Builder Pattern:**
Testcontainers uses a fluent builder API to configure containers:
```csharp
var container = new ContainerBuilder()
    .WithImage("redis:7-alpine")
    .WithPortBinding(6379, true) // Random host port
    .WithWaitStrategy(Wait.ForUnixContainer().UntilPortIsAvailable(6379))
    .Build();
```

**Wait Strategies:**
Ensure containers are fully initialized before tests run:
- `UntilPortIsAvailable()` - Wait for port to be accessible
- `UntilHttpRequestIsSucceeded()` - Wait for HTTP endpoint
- `UntilCommandIsCompleted()` - Wait for command to complete

**Resource Management:**
Testcontainers automatically cleans up containers, networks, and volumes after tests complete through the Resource Reaper (Moby Ryuk).
