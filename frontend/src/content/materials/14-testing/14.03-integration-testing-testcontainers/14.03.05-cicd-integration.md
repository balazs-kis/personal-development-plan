## Introduction

Running Testcontainers in CI/CD pipelines ensures that integration tests run automatically with every code change. Modern CI/CD platforms like GitHub Actions and Azure DevOps provide Docker support out-of-the-box, making Testcontainers integration straightforward. However, you need to understand platform-specific considerations and optimization techniques to get the best results.

## Key Concepts Summary

### CI/CD Requirements

Testcontainers requires:
1. **Docker installed** on the CI agent (locally or remotely)
2. **Docker daemon running** during test execution
3. **Network access** for pulling container images
4. **Sufficient resources** (CPU, memory, disk space)

Most modern CI platforms include Docker by default on their hosted runners.

### GitHub Actions Configuration

GitHub-hosted runners come with Docker pre-installed, so Testcontainers works immediately without additional setup.

**Basic Workflow Example:**

```yaml
name: Integration Tests

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  integration-tests:
    runs-on: ubuntu-latest
    
    steps:
    - name: Checkout code
      uses: actions/checkout@v4
    
    - name: Setup .NET
      uses: actions/setup-dotnet@v4
      with:
        dotnet-version: '8.0.x'
    
    - name: Restore dependencies
      run: dotnet restore
    
    - name: Build
      run: dotnet build --no-restore --configuration Release
    
    - name: Run integration tests
      run: dotnet test --no-build --configuration Release --filter Category=Integration
      env:
        # Testcontainers automatically detects Docker
        DOTNET_ENVIRONMENT: Testing
```

**With Test Result Reporting:**

```yaml
    - name: Run integration tests
      run: dotnet test --no-build --configuration Release --filter Category=Integration --logger "trx;LogFileName=test-results.trx"
    
    - name: Publish test results
      uses: EnricoMi/publish-unit-test-result-action@v2
      if: always()
      with:
        files: '**/test-results.trx'
```

### Azure Pipelines Configuration

Microsoft-hosted agents include Docker, but Windows agents use the Docker Windows engine and cannot run Linux containers.

**azure-pipelines.yml Example:**

```yaml
trigger:
  branches:
    include:
    - main
    - develop

pool:
  vmImage: 'ubuntu-latest'  # Use Linux for Linux containers

variables:
  buildConfiguration: 'Release'

steps:
- task: UseDotNet@2
  displayName: 'Install .NET SDK'
  inputs:
    version: '8.x'

- task: DotNetCoreCLI@2
  displayName: 'Restore dependencies'
  inputs:
    command: 'restore'

- task: DotNetCoreCLI@2
  displayName: 'Build solution'
  inputs:
    command: 'build'
    arguments: '--configuration $(buildConfiguration) --no-restore'

- task: DotNetCoreCLI@2
  displayName: 'Run integration tests'
  inputs:
    command: 'test'
    arguments: '--configuration $(buildConfiguration) --no-build --filter Category=Integration --logger trx'
    publishTestResults: true

- task: PublishTestResults@2
  displayName: 'Publish test results'
  condition: always()
  inputs:
    testResultsFormat: 'VSTest'
    testResultsFiles: '**/*.trx'
```

**Windows Agent Considerations:**

If you must use Windows agents, specify Windows container images:

```csharp
var container = new ContainerBuilder()
    .WithImage("mcr.microsoft.com/windows/servercore:ltsc2022")
    .Build();
```

### Optimization Strategies

**1. Parallelize Tests**

xUnit runs tests in parallel by default. Configure parallelism:

```csharp
// xunit.runner.json
{
  "parallelizeTestCollections": true,
  "maxParallelThreads": 4
}
```

**2. Use Test Categorization**

Run fast unit tests first, then integration tests:

```yaml
- name: Run unit tests
  run: dotnet test --filter Category=Unit

- name: Run integration tests
  run: dotnet test --filter Category=Integration
```

**3. Cache Docker Images**

Use Docker layer caching where available:

```yaml
# GitHub Actions example
- name: Set up Docker Buildx
  uses: docker/setup-buildx-action@v3

- name: Cache Docker layers
  uses: actions/cache@v4
  with:
    path: /tmp/.buildx-cache
    key: ${{ runner.os }}-buildx-${{ github.sha }}
    restore-keys: |
      ${{ runner.os }}-buildx-
```

**4. Pull Images Before Tests**

Pre-pull images to avoid timeouts:

```yaml
- name: Pre-pull Docker images
  run: |
    docker pull postgres:16-alpine
    docker pull redis:7-alpine
    docker pull rabbitmq:3.13-management-alpine
```

**5. Use Smaller Images**

Alpine variants are faster to pull and start:

```csharp
.WithImage("postgres:16-alpine")  // ~80MB
// Instead of:
.WithImage("postgres:16")         // ~350MB
```

### Testcontainers Cloud

Testcontainers Cloud offloads container execution to a remote environment via SSH tunnel.

**Benefits:**
- Faster test execution (no image pulls on CI runner)
- No Docker daemon required on CI runner
- Consistent performance across environments
- Reduced CI agent resource usage

**GitHub Actions Setup:**

```yaml
jobs:
  integration-tests:
    runs-on: ubuntu-latest
    
    steps:
    - name: Setup Testcontainers Cloud
      uses: atomicjar/testcontainers-cloud-setup-action@v1
      with:
        token: ${{ secrets.TC_CLOUD_TOKEN }}
    
    - name: Run tests
      run: dotnet test --filter Category=Integration
```

**Azure Pipelines Setup:**

```yaml
- script: |
    curl -fsSL https://app.testcontainers.cloud/download/testcontainers-cloud-agent_linux_x86-64 -o ~/testcontainers-cloud-agent
    chmod +x ~/testcontainers-cloud-agent
    ~/testcontainers-cloud-agent &
  displayName: 'Start Testcontainers Cloud Agent'
  env:
    TC_CLOUD_TOKEN: $(TC_CLOUD_TOKEN)
```

### Troubleshooting Common Issues

**Issue 1: "Cannot connect to Docker daemon"**

Solution: Ensure Docker service is running on the agent:

```yaml
- name: Verify Docker
  run: docker ps
```

**Issue 2: Port conflicts**

Solution: Always use random port bindings:

```csharp
.WithPortBinding(5432, true)  // Not WithPortBinding(5432, 5432)
```

**Issue 3: Test timeouts**

Solution: Increase wait strategy timeouts or pre-pull images:

```csharp
.WithWaitStrategy(Wait.ForUnixContainer()
    .UntilPortIsAvailable(5432)
    .WithTimeout(TimeSpan.FromMinutes(2)))
```

**Issue 4: Out of disk space**

Solution: Clean up unused images and containers:

```yaml
- name: Clean Docker
  run: docker system prune -af
```

**Issue 5: Windows agent cannot run Linux containers**

Solution: Use Linux agents or Windows container images.

### Test Result Reporting

**JUnit XML Format (for GitHub/Azure compatibility):**

```bash
dotnet test --logger "junit;LogFilePath=test-results.xml"
```

**Azure DevOps Integration:**

```yaml
- task: PublishTestResults@2
  condition: always()
  inputs:
    testResultsFormat: 'JUnit'
    testResultsFiles: '**/test-results.xml'
    mergeTestResults: true
    failTaskOnFailedTests: true
```

### Performance Benchmarks

Typical integration test suite timings on CI:

- **10 tests, container per test:** ~5-8 minutes
- **10 tests, shared container:** ~2-4 minutes
- **10 tests, shared container + Respawn:** ~1-2 minutes
- **10 tests, Testcontainers Cloud:** ~1-3 minutes
