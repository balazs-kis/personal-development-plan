## Key Concepts Summary

### What are Message Queues?

Message queues enable asynchronous communication between services:

```
Producer → [Message Queue] → Consumer

Instead of:
Service A → (HTTP) → Service B (synchronous, coupled)

Use:
Service A → Message Queue → Service B (asynchronous, decoupled)
```

**Benefits:**
- **Decoupling:** Services don't need to know about each other
- **Scalability:** Add more consumers to handle load
- **Resilience:** Queue buffers during consumer downtime
- **Asynchronous Processing:** Producer doesn't wait for consumer

## Message Queue Patterns

### 1. Message Queuing (Point-to-Point)

```
Producer → Queue → Consumer
                → Consumer (round-robin)
                → Consumer
```

**Characteristics:**
- Each message consumed by exactly one consumer
- Message removed from queue after consumption
- Work distribution pattern

**Example:**
```csharp
// Order processing queue
public class OrderProducer
{
    public async Task CreateOrder(Order order)
    {
        // Add to queue
        await queue.SendAsync("order-queue", order);
        
        // Producer continues immediately
    }
}

public class OrderConsumer
{
    public async Task ProcessOrders()
    {
        while (true)
        {
            var order = await queue.ReceiveAsync("order-queue");
            await ProcessOrder(order);
            await queue.AcknowledgeAsync(order); // Mark as processed
        }
    }
}
```

**Use cases:**
- Task distribution (image processing, email sending)
- Load leveling (buffer traffic spikes)
- Background jobs

### 2. Publish/Subscribe (Pub/Sub)

```
Publisher → Topic → Subscriber 1
                  → Subscriber 2
                  → Subscriber 3
```

**Characteristics:**
- Each message delivered to all subscribers
- Multiple consumers receive same message
- Broadcast pattern

**Example:**
```csharp
// User registration event
public class UserService
{
    public async Task RegisterUser(User user)
    {
        await database.SaveAsync(user);
        
        // Publish event to topic
        await messageQueue.PublishAsync("user-registered", new UserRegisteredEvent
        {
            UserId = user.Id,
            Email = user.Email,
            Timestamp = DateTime.UtcNow
        });
    }
}

// Multiple subscribers
public class EmailService
{
    // Subscriber 1: Send welcome email
    public async Task OnUserRegistered(UserRegisteredEvent evt)
    {
        await SendWelcomeEmail(evt.Email);
    }
}

public class AnalyticsService
{
    // Subscriber 2: Track registration
    public async Task OnUserRegistered(UserRegisteredEvent evt)
    {
        await TrackRegistration(evt.UserId);
    }
}

public class NotificationService
{
    // Subscriber 3: Send notification to admins
    public async Task OnUserRegistered(UserRegisteredEvent evt)
    {
        await NotifyAdmins($"New user: {evt.Email}");
    }
}
```

**Use cases:**
- Event-driven architecture
- Fanout notifications
- Real-time updates

## Kafka vs RabbitMQ

### Apache Kafka

**Architecture:**
```
Producers → Kafka Brokers → Consumers
              ├─ Topic 1 (Partitions: [P0][P1][P2])
              ├─ Topic 2 (Partitions: [P0][P1])
              └─ Topic 3 (Partitions: [P0][P1][P2][P3])
```

**Key Features:**
- **Event streaming platform** (not just message queue)
- **Distributed commit log**
- **Unlimited retention** (configurable)
- **Replay capability** (re-read old messages)
- **High throughput** (10M+ msg/sec)
- **Latency:** 2-5ms

**When to use Kafka:**
- Event streaming and processing
- High throughput requirements
- Need to replay messages
- Real-time data pipelines
- Log aggregation
- Metrics and monitoring

**Example:**
```csharp
// Kafka producer
var config = new ProducerConfig 
{ 
    BootstrapServers = "localhost:9092" 
};

using var producer = new ProducerBuilder<string, string>(config).Build();

await producer.ProduceAsync("user-events", new Message<string, string>
{
    Key = user.Id.ToString(), // Partition by user ID
    Value = JsonSerializer.Serialize(userEvent)
});

// Kafka consumer
var config = new ConsumerConfig
{
    BootstrapServers = "localhost:9092",
    GroupId = "user-event-processor",
    AutoOffsetReset = AutoOffsetReset.Earliest
};

using var consumer = new ConsumerBuilder<string, string>(config).Build();
consumer.Subscribe("user-events");

while (true)
{
    var message = consumer.Consume(CancellationToken.None);
    
    ProcessEvent(message.Value);
    
    // Commit offset (mark as processed)
    consumer.Commit(message);
}
```

### RabbitMQ

**Architecture:**
```
Producers → Exchange → Queues → Consumers
              ├─ direct exchange
              ├─ fanout exchange
              ├─ topic exchange
              └─ headers exchange
```

**Key Features:**
- **Traditional message broker**
- **Rich routing capabilities** (exchanges)
- **Message acknowledgments**
- **TTL and dead letter queues**
- **Throughput:** 1M msg/sec
- **Latency:** 1-20ms

**When to use RabbitMQ:**
- Traditional message queuing
- Complex routing requirements
- Task distribution
- Request/reply patterns
- Simpler setup for basic needs

**Example:**
```csharp
// RabbitMQ producer
var factory = new ConnectionFactory { HostName = "localhost" };
using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

channel.QueueDeclare(
    queue: "task-queue",
    durable: true,
    exclusive: false,
    autoDelete: false
);

var message = JsonSerializer.Serialize(task);
var body = Encoding.UTF8.GetBytes(message);

channel.BasicPublish(
    exchange: "",
    routingKey: "task-queue",
    basicProperties: null,
    body: body
);

// RabbitMQ consumer
channel.BasicQos(prefetchSize: 0, prefetchCount: 1, global: false);

var consumer = new EventingBasicConsumer(channel);
consumer.Received += (model, ea) =>
{
    var body = ea.Body.ToArray();
    var message = Encoding.UTF8.GetString(body);
    
    ProcessTask(message);
    
    // Acknowledge message
    channel.BasicAck(deliveryTag: ea.DeliveryTag, multiple: false);
};

channel.BasicConsume(
    queue: "task-queue",
    autoAck: false,
    consumer: consumer
);
```

### Comparison Table

| Feature | Kafka | RabbitMQ |
|---------|-------|----------|
| **Type** | Event streaming | Message broker |
| **Throughput** | 10M+ msg/sec | 1M msg/sec |
| **Latency** | 2-5ms | 1-20ms |
| **Retention** | Unlimited (configurable) | Until consumed |
| **Replay** | Yes (offset-based) | No |
| **Ordering** | Per partition | Per queue |
| **Routing** | Topic-based | Rich exchange types |
| **Use Case** | Event streaming, logs | Task queues, RPC |
| **Complexity** | Higher | Lower (for basics) |

## Message Delivery Guarantees

### At-Most-Once (0-1)

```
Producer → Queue → Consumer
Fire and forget - may lose messages
```

**Behavior:**
- No retries
- Fast but unreliable
- Message may be lost

**Use when:** Speed > reliability (metrics, logs)

### At-Least-Once (1+)

```
Producer → Queue → Consumer
           ↓        ↓
         Retry   Acknowledge
```

**Behavior:**
- Retries on failure
- Duplicates possible
- Most common

**Use when:** Can tolerate duplicates (idempotent processing)

```csharp
public class IdempotentOrderProcessor
{
    private readonly HashSet<string> _processedIds = new();
    
    public async Task ProcessOrder(Order order)
    {
        // Check if already processed
        if (_processedIds.Contains(order.Id))
        {
            // Duplicate - skip
            return;
        }
        
        // Process order
        await ProcessOrderInternal(order);
        
        // Mark as processed
        _processedIds.Add(order.Id);
    }
}
```

### Exactly-Once (1)

```
Producer → Queue → Consumer
    ↓        ↓        ↓
Transactional guarantees
```

**Behavior:**
- Message processed exactly once
- Most expensive
- Requires transaction support

**Use when:** Correctness critical (payments, financial transactions)

**Kafka Example:**
```csharp
// Enable exactly-once semantics
var config = new ProducerConfig
{
    BootstrapServers = "localhost:9092",
    EnableIdempotence = true, // Exactly-once within Kafka
    TransactionalId = "my-transactional-id"
};
```

## Common Patterns

### 1. Load Leveling

```
Traffic Spike → Queue (buffer) → Steady processing rate
```

**Problem:** Backend can't handle traffic spikes
**Solution:** Queue buffers requests, consumers process at steady rate

### 2. Priority Queue

```csharp
// High priority messages processed first
await queue.SendAsync("orders", order, priority: Priority.High);
```

### 3. Dead Letter Queue (DLQ)

```
Message fails 3 times → Move to DLQ → Manual investigation
```

```csharp
public async Task ProcessMessage(Message msg)
{
    try
    {
        await Process(msg);
    }
    catch (Exception ex)
    {
        msg.RetryCount++;
        
        if (msg.RetryCount >= 3)
        {
            // Move to DLQ
            await queue.SendAsync("dead-letter-queue", msg);
        }
        else
        {
            // Retry
            await queue.SendAsync("main-queue", msg);
        }
    }
}
```

### 4. Request-Reply Pattern

```csharp
// Synchronous-style communication over async queue
public async Task<Response> RequestReply(Request request)
{
    var correlationId = Guid.NewGuid().ToString();
    var replyQueue = $"reply-{correlationId}";
    
    // Send request with reply queue
    await queue.SendAsync("request-queue", new Message
    {
        CorrelationId = correlationId,
        ReplyTo = replyQueue,
        Body = request
    });
    
    // Wait for reply
    return await queue.ReceiveAsync<Response>(replyQueue, timeout: TimeSpan.FromSeconds(30));
}
```

### 5. Saga Pattern (Distributed Transactions)

```csharp
// Order saga: Reserve inventory → Charge payment → Ship order
public class OrderSaga
{
    public async Task CreateOrder(Order order)
    {
        // Step 1: Reserve inventory
        await PublishAsync(new ReserveInventoryCommand(order));
    }
    
    // On inventory reserved
    public async Task OnInventoryReserved(InventoryReservedEvent evt)
    {
        // Step 2: Charge payment
        await PublishAsync(new ChargePaymentCommand(evt.OrderId));
    }
    
    // On payment charged
    public async Task OnPaymentCharged(PaymentChargedEvent evt)
    {
        // Step 3: Ship order
        await PublishAsync(new ShipOrderCommand(evt.OrderId));
    }
    
    // On any failure - compensate
    public async Task OnInventoryReserveFailed(InventoryReserveFailedEvent evt)
    {
        // Cancel order
        await PublishAsync(new CancelOrderCommand(evt.OrderId));
    }
}
```
