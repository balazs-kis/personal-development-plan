# Lesson 5: Tooling and Repository Management

## Learning Objectives

By the end of this lesson, you will be able to:
- Set up an ADR repository structure

## Introduction

While ADRs can be managed with plain text files and Git, specialized tooling can streamline creation, management, and discovery. This lesson covers the ecosystem of ADR tools, repository organization patterns, and best practices for making ADRs easily accessible to your team.

## Key Concepts Summary

### ADR Repository Organization

```
project-root/
├── docs/
│   └── adr/
│       ├── README.md          (ADR index)
│       ├── template.md        (ADR template)
│       ├── 0001-use-adrs.md
│       ├── 0002-choose-database.md
│       ├── 0003-api-design.md
│       └── ...
├── src/
└── README.md
```

**Key principles:**
- Store with code (version controlled)
- Dedicated `docs/adr/` directory
- Sequential numbering with leading zeros
- Include README index
- Keep template for consistency

## Repository Structures

### Option 1: Single ADR Directory (Recommended for Most Projects)

```
docs/adr/
├── README.md
├── template.md
├── 0001-record-architecture-decisions.md
├── 0002-use-postgresql.md
├── 0003-adopt-microservices.md
└── 0004-implement-cqrs.md
```

**Pros:**
- Simple
- Easy to browse
- Works for most projects (<100 ADRs)

**Cons:**
- Can become crowded with many ADRs

### Option 2: Categorized by Status

```
docs/adr/
├── accepted/
│   ├── 0001-record-architecture-decisions.md
│   └── 0002-use-postgresql.md
├── proposed/
│   ├── 0005-add-graphql-api.md
│   └── 0006-migrate-to-kubernetes.md
├── superseded/
│   ├── 0003-use-mongodb.md
│   └── 0004-deploy-to-heroku.md
└── README.md
```

**Pros:**
- Clear status at glance
- Easy to find active decisions

**Cons:**
- Files move between directories (git history tracking)
- More complex structure

### Option 3: Categorized by Domain

```
docs/adr/
├── infrastructure/
│   ├── 0001-kubernetes-deployment.md
│   └── 0005-cloudflare-cdn.md
├── backend/
│   ├── 0002-use-postgresql.md
│   └── 0004-grpc-communication.md
├── frontend/
│   ├── 0003-react-framework.md
│   └── 0006-redux-state-management.md
└── README.md
```

**Pros:**
- Easy to find domain-specific decisions
- Good for large teams with specializations

**Cons:**
- Cross-cutting concerns hard to categorize
- Numbering may be per-category or global

### Option 4: Archive Old ADRs

```
docs/adr/
├── active/
│   ├── 0010-current-database-strategy.md
│   └── 0011-api-versioning.md
├── archive/
│   ├── 2023/
│   │   ├── 0001-initial-architecture.md
│   │   └── 0002-first-deployment.md
│   └── 2024/
│       ├── 0005-microservices-migration.md
│       └── 0008-api-redesign.md
└── README.md
```

**Pros:**
- Keeps main directory clean
- Historical context preserved

**Cons:**
- When to archive? (arbitrary)
- Superseded ADRs still reference archived ones

**Recommendation:** Start with Option 1. Move to categories only if needed at scale (50+ ADRs).

## ADR Command-Line Tools

### 1. adr-tools (Original Bash Tools)

**Installation:**
```bash
# macOS
brew install adr-tools

# Linux
curl -L https://raw.githubusercontent.com/npryce/adr-tools/master/install.sh | sh

# Windows (via WSL or Git Bash)
```

**Usage:**
```bash
# Initialize ADR directory
adr init docs/adr

# Create new ADR
adr new "Use PostgreSQL for primary database"
# Creates: docs/adr/0001-use-postgresql-for-primary-database.md

# Create ADR that supersedes another
adr new -s 0001 "Migrate to PostgreSQL with replication"
# Creates: 0002-migrate-to-postgresql-with-replication.md
# Updates: 0001 status to "Superseded by ADR-0002"

# Generate table of contents
adr generate toc > docs/adr/README.md

# List all ADRs
adr list
```

**Template Example:**
```markdown
# 1. Use PostgreSQL for primary database

Date: 2024-01-15

## Status

Accepted

## Context

[You fill this in]

## Decision

[You fill this in]

## Consequences

[You fill this in]
```

### 2. dotnet-adr (.NET Global Tool)

**Installation:**
```bash
dotnet tool install -g adr
```

**Usage:**
```bash
# Initialize
adr init

# Create new ADR
adr new "Use Redis for caching"

# List ADRs
adr list

# Open ADR in editor
adr edit 0001

# Support for MADR template
adr new --template madr "Use Kafka for events"
```

**Features:**
- Cross-platform (.NET Core)
- Multiple template support
- Integrated with .NET projects

### 3. ADG (Architectural Decision Guidance) - Go

**Installation:**
```bash
# macOS
brew install adg

# Go
go install github.com/npryce/adr-tools@latest
```

**Usage:**
```bash
# Supports multiple templates
adg init --template nygard
adg init --template madr
adg init --template qoc

# Create ADR
adg new "Adopt microservices architecture"

# Link ADRs
adg link 0001 supersedes 0002
```

**Features:**
- Multiple template formats
- Cross-platform
- Fast (written in Go)

### 4. log4brains (Node.js)

**Installation:**
```bash
npm install -g log4brains
```

**Usage:**
```bash
# Initialize with preview site
log4brains init

# Create ADR
log4brains adr new

# Start preview server
log4brains preview

# Build static site
log4brains build
```

**Features:**
- Interactive web UI
- Automatic documentation site generation
- Search functionality
- Timeline view
- Markdown-based

**Preview:**
```
http://localhost:4004

- Timeline of all ADRs
- Search by title, content, status
- Filter by status, date
- View superseded chains
```

## Generating ADR Indexes

### Manual README.md

```markdown
# Architecture Decision Records

## Current ADRs

- [ADR-0001](0001-record-architecture-decisions.md) - Record architecture decisions
- [ADR-0002](0002-use-postgresql.md) - Use PostgreSQL for primary database
- [ADR-0003](0003-adopt-microservices.md) - Adopt microservices architecture

## Superseded ADRs

- [ADR-0004](0004-use-mongodb.md) - Use MongoDB (superseded by ADR-0002)

## Rejected ADRs

- [ADR-0005](0005-use-nosql.md) - Use NoSQL database
```

### Automated Index with adr-tools

```bash
# Generate table of contents
adr generate toc > docs/adr/README.md

# Output:
# * [ADR-0001](0001-record-architecture-decisions.md) - Record architecture decisions
# * [ADR-0002](0002-use-postgresql.md) - Use PostgreSQL for primary database
```

### Automated Index with Script

```bash
#!/bin/bash
# generate-adr-index.sh

echo "# Architecture Decision Records" > docs/adr/README.md
echo "" >> docs/adr/README.md

for file in docs/adr/[0-9]*.md; do
  number=$(basename "$file" | cut -d'-' -f1)
  title=$(grep "^# " "$file" | head -1 | sed 's/^# //')
  echo "- [ADR-$number]($file) - $title" >> docs/adr/README.md
done
```

### Automated Index in CI

```yaml
# .github/workflows/adr-index.yml
name: Generate ADR Index

on:
  push:
    paths:
      - 'docs/adr/*.md'

jobs:
  generate-index:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      
      - name: Install adr-tools
        run: |
          curl -L https://raw.githubusercontent.com/npryce/adr-tools/master/install.sh | sh
      
      - name: Generate index
        run: adr generate toc > docs/adr/README.md
      
      - name: Commit changes
        uses: stefanzweifel/git-auto-commit-action@v4
        with:
          commit_message: "Update ADR index"
          file_pattern: docs/adr/README.md
```

## ADR Documentation Sites

### Static Site Generation

#### Option 1: log4brains

```bash
# Install
npm install -g log4brains

# Build static site
log4brains build

# Output: .log4brains/out/
# Deploy to: GitHub Pages, Netlify, Vercel
```

**Features:**
- Beautiful UI
- Search functionality
- Timeline view
- Status filters
- Automatic cross-references

#### Option 2: adr-viewer

```bash
# Install
npm install -g adr-viewer

# Generate site
adr-viewer --input docs/adr --output adr-site

# Serve locally
cd adr-site && python -m http.server 8000
```

#### Option 3: Custom with MkDocs

```yaml
# mkdocs.yml
site_name: Our ADRs
nav:
  - Home: index.md
  - ADRs: adr/

# Build
mkdocs build

# Serve
mkdocs serve
```

### GitHub Pages Deployment

```yaml
# .github/workflows/deploy-adrs.yml
name: Deploy ADR Site

on:
  push:
    branches: [main]
    paths:
      - 'docs/adr/**'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      
      - name: Install log4brains
        run: npm install -g log4brains
      
      - name: Build site
        run: log4brains build
      
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: .log4brains/out
```

**Result:** https://yourorg.github.io/yourproject/

## Search and Discovery

### Full-Text Search

#### Option 1: GitHub Search

```
repo:yourorg/yourproject path:docs/adr/ "Redis"
repo:yourorg/yourproject path:docs/adr/ status:accepted
```

#### Option 2: grep/ripgrep

```bash
# Search ADR content
grep -r "Redis" docs/adr/

# Search with context
grep -r -B 2 -A 2 "Redis" docs/adr/

# Ripgrep (faster)
rg "Redis" docs/adr/

# Case-insensitive
rg -i "redis" docs/adr/
```

#### Option 3: log4brains Search

```
http://localhost:4004/?search=Redis

- Full-text search
- Filters by status, date
- Highlights matches
```

### ADR Metadata for Search

```yaml
---
title: Use Redis for Session Storage
status: accepted
created: 2024-01-15
tags: [caching, sessions, redis, performance]
team: backend
category: infrastructure
---
```

**Enables:**
- Filtering by tags
- Team-specific ADRs
- Category browsing

## Integration with Development Workflow

### Pull Request Template

```markdown
## Changes
[Description of changes]

## ADR Reference
Does this PR implement or relate to any ADR?
- [ ] No ADR involved
- [ ] Implements [ADR-XXXX](link)
- [ ] Requires new ADR (attached)

## Architectural Impact
- [ ] No architectural impact
- [ ] Minor change (within existing ADR)
- [ ] Significant change (new ADR needed)
```

### Git Hooks

```bash
# .git/hooks/pre-commit
#!/bin/bash

# Check if ADR is referenced in commit message
if ! grep -q "ADR-[0-9]\+" "$1"; then
  echo "Warning: No ADR referenced in commit message"
  echo "If this introduces architectural changes, please reference an ADR"
  echo "Format: ADR-XXXX"
  # Warning only, don't block
fi
```

### Code Comments Reference ADRs

```csharp
// Session storage implementation
// See ADR-0015: Use Redis for Session Storage
public class RedisSessionStore : ISessionStore
{
    // Implementation follows ADR-0015 decision
}
```

## ADR Repository Best Practices

### 1. Keep ADRs in Same Repo as Code

```
✅ Good:
myproject/
├── docs/adr/
├── src/
└── tests/

❌ Bad (separate repo):
myproject/
myproject-docs/
└── adr/
```

**Why together:**
- ADRs version with code
- Easy to reference in PRs
- Single source of truth

### 2. Automate What You Can

```yaml
# Automated checks
- ADR numbering sequential
- ADR has status field
- Superseded ADRs link to replacement
- Index is up to date
- No broken links
```

### 3. Make ADRs Discoverable

```
- Link from README.md
- Include in documentation site
- Reference in onboarding docs
- Discuss in architecture reviews
- Tag in Slack/Teams
```

### 4. Regular Maintenance

```
Weekly:
- Review new ADRs
- Update statuses

Monthly:
- Regenerate index
- Check for broken links

Quarterly:
- Review stagnant ADRs
- Archive old superseded ADRs
```

## Tool Selection Guide

| Need | Recommended Tool |
|------|------------------|
| Just starting | adr-tools (bash) or dotnet-adr |
| .NET project | dotnet-adr |
| Need web UI | log4brains |
| VS Code users | VS Code ADR Manager extension |
| Multiple templates | ADG (Go) |
| Static site | log4brains or adr-viewer |
| Enterprise | Consider custom tooling |

**Start simple:** Plain markdown + adr-tools is enough for most teams.
