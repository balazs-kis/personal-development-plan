## Introduction

LogQL (Log Query Language) is Loki's query language, designed to be familiar to users of Prometheus's PromQL. LogQL allows you to select log streams, filter log lines, parse structured data, and even convert logs into metrics for visualization. Understanding LogQL is essential for effective log analysis, troubleshooting, and creating dashboards and alerts.

## Key Concepts Summary

### LogQL Query Structure

A LogQL query consists of two parts:

```
{stream selector} | filter expression | parser | filter | ...
└─────────────┘   └───────────────────────────────────────┘
   Log Stream              Pipeline (optional)
   Selector
```

**Example:**
```logql
{app="nginx", environment="production"} 
  |= "error" 
  | json 
  | level="error" 
  | line_format "{{.method}} {{.path}}"
```

### Query Types

**1. Log Queries**
Return actual log lines as streams:

```logql
{app="nginx"} |= "error"
```

Returns log lines that match the selector and filter.

**2. Metric Queries**
Convert logs into time-series metrics:

```logql
rate({app="nginx"} |= "error" [5m])
```

Returns the rate of error logs over 5-minute windows.

### Log Stream Selectors

Stream selectors use labels to filter log streams:

**Operators:**
- `=` : Exact match
- `!=` : Not equal
- `=~` : Regex match
- `!~` : Regex not match

**Examples:**

```logql
# Exact match
{app="nginx"}

# Multiple labels (AND logic)
{app="nginx", environment="production"}

# Regex match
{app=~"nginx|apache"}

# Not equal
{environment!="dev"}

# Regex not match
{pod!~"test-.*"}
```

### Filter Expressions

Filter expressions operate on log line content:

**Line Filter Operators:**
- `|=` : Contains (case-sensitive)
- `!=` : Does not contain
- `|~` : Regex match
- `!~` : Regex not match

**Examples:**

```logql
# Contains "error"
{app="nginx"} |= "error"

# Does not contain "debug"
{app="nginx"} != "debug"

# Regex: contains "error" or "warning"
{app="nginx"} |~ "error|warning"

# Chaining filters
{app="nginx"} |= "error" != "timeout"

# Case-insensitive (using regex)
{app="nginx"} |~ "(?i)error"
```

### Parser Expressions

Parsers extract data from log lines:

**1. JSON Parser**

```logql
{app="api"} | json
```

Automatically extracts all JSON fields:

```json
{"level":"error", "message":"Database connection failed", "user_id":123}
```

Extracted: `level`, `message`, `user_id`

**Using extracted fields:**

```logql
{app="api"} | json | level="error"
```

**Extracting specific fields:**

```logql
{app="api"} | json level="lvl", msg="message"
```

**2. Logfmt Parser**

```logql
{app="api"} | logfmt
```

Parses logfmt-style logs:

```
level=error msg="connection failed" user_id=123
```

**3. Regex Parser**

```logql
{app="nginx"} 
  | regexp '(?P<ip>\S+) .* "(?P<method>\S+) (?P<path>\S+) (?P<protocol>\S+)" (?P<status>\d+)'
```

Extracts named groups from regex patterns.

**4. Pattern Parser**

```logql
{app="nginx"} 
  | pattern '<ip> - - <_> "<method> <path> <_>" <status> <_>'
```

Simpler alternative to regex for structured logs.

### Label Filter Expressions

Filter on extracted labels after parsing:

```logql
{app="api"} 
  | json 
  | level="error"           # Only error-level logs
  | status_code >= 500      # HTTP 500+ errors
  | duration > 1s           # Requests taking > 1 second
```

**Comparison Operators:**
- `=` and `!=`
- `>`, `>=`, `<`, `<=`
- `=~` and `!~` (regex)

### Line Format Expressions

Transform log output:

```logql
{app="nginx"} 
  | json 
  | line_format "{{.method}} {{.path}} - {{.status}}"
```

Output: `GET /api/users - 200`

**Template Functions:**

```logql
{app="api"} 
  | json 
  | line_format "{{.level | ToUpper}} - {{.message}}"
```

Output: `ERROR - Connection failed`

**Available functions:**
- `ToUpper`, `ToLower`
- `Replace`
- `Trim`, `TrimSpace`
- `printf` style formatting

### Metric Queries and Aggregations

Convert logs to metrics for visualization:

**Range Vector Aggregations:**

```logql
# Count logs over time
count_over_time({app="nginx"} [5m])

# Rate of logs per second
rate({app="nginx"} [5m])

# Bytes processed
bytes_over_time({app="nginx"} [5m])

# Rate of bytes per second
bytes_rate({app="nginx"} [5m])
```

**Aggregation Operators:**

```logql
# Sum logs across all pods
sum(rate({app="nginx"} [5m]))

# Count by status code
sum by (status) (rate({app="nginx"} | json [5m]))

# Average duration
avg(rate({app="api"} | json | unwrap duration [5m]))

# Top 5 error-producing services
topk(5, sum by (app) (rate({level="error"} [5m])))
```

**Unwrap:**

Extract numeric values for aggregation:

```logql
# Average request duration
avg_over_time(
  {app="api"} 
    | json 
    | unwrap duration [5m]
)

# Sum of bytes sent
sum_over_time(
  {app="nginx"} 
    | json 
    | unwrap bytes_sent [5m]
)
```

### Common Query Patterns

**1. Error Rate by Service**

```logql
sum by (app) (
  rate({environment="production"} |= "error" [5m])
)
```

**2. HTTP 500 Errors**

```logql
{app="nginx"} 
  | json 
  | status >= 500
```

**3. Slow Requests (p95)**

```logql
quantile_over_time(0.95,
  {app="api"} 
    | json 
    | unwrap duration [5m]
)
```

**4. Failed Login Attempts**

```logql
{app="auth"} 
  |= "login" 
  |= "failed" 
  | json 
  | line_format "Failed login for user: {{.username}} from {{.ip}}"
```

**5. Kubernetes Pod Logs**

```logql
{namespace="production", pod=~"api-.*"} 
  | json 
  | level="error"
```

**6. Logs NOT Matching Pattern**

```logql
{app="nginx"} !~ "health|metrics"
```

**7. Count Unique Values**

```logql
count by (user_id) (
  {app="api"} 
    | json 
    | user_id != ""
)
```

### Advanced Features

**1. Label Formatting**

```logql
{app="api"} 
  | json 
  | label_format level="{{.lvl}}", user="user_{{.user_id}}"
```

**2. Drop Labels**

```logql
{app="api"} 
  | json 
  | drop pod, namespace  # Remove high-cardinality labels from query
```

**3. Keep Labels**

```logql
{app="api"} 
  | json 
  | keep level, message  # Keep only specific labels
```

**4. Decolorize**

```logql
{app="api"} | decolorize  # Remove ANSI color codes
```
