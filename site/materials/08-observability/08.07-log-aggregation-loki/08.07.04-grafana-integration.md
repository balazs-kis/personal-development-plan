## Learning Objectives

By the end of this lesson, you will be able to:
- Configure Loki as a data source in Grafana

- Use template variables to create dynamic log dashboards

---

## Introduction

Grafana's integration with Loki provides a powerful interface for exploring, searching, and visualizing logs. The tight integration between Grafana, Loki, and Prometheus enables unified observability where you can correlate logs with metrics and traces in a single pane of glass. This lesson covers how to leverage Grafana's features to create effective log dashboards and troubleshooting workflows.

## Key Concepts Summary

### Configuring Loki Data Source

**Steps to Add Loki:**

1. Navigate to **Configuration → Data Sources**
2. Click **Add data source**
3. Select **Loki**
4. Configure:
   - **Name:** `Loki` (or descriptive name)
   - **URL:** `http://loki:3100` (or your Loki endpoint)
   - **Access:** Server (default) or Browser
5. Click **Save & Test**

**Configuration Options:**

```yaml
# Basic configuration
URL: http://loki:3100

# Authentication (if needed)
Basic Auth: enabled
User: admin
Password: ***

# Advanced settings
Timeout: 60s
Max lines: 1000

# Derived fields (link to traces)
Regex: traceID=(\w+)
URL: ${__value.raw}
Internal link: Tempo data source
```

### Explore Interface

**Two Query Builder Modes:**

**1. Builder Mode (Beginner-Friendly)**
- Select labels from dropdowns
- Visual filter building
- No LogQL knowledge required

**2. Code Mode (Advanced)**
- Write LogQL directly
- Full language features
- Syntax highlighting and autocomplete

**Interface Features:**

```
┌─────────────────────────────────────────────────┐
│ Data Source: [Loki ▼]    Time: [Last 1 hour ▼] │
├─────────────────────────────────────────────────┤
│ Query Editor:                                    │
│ {app="nginx"} |= "error"                        │
├─────────────────────────────────────────────────┤
│ Log Panel:                                       │
│ [Show context] [Wrap lines] [Dedup]             │
│                                                  │
│ [2024-01-27 10:15:23] ERROR: Connection failed  │
│ [2024-01-27 10:15:25] ERROR: Retry attempt 1    │
│ [2024-01-27 10:15:27] ERROR: Retry attempt 2    │
│                                                  │
├─────────────────────────────────────────────────┤
│ Statistics: [Total: 1.2k] [Rate: 4 logs/s]     │
└─────────────────────────────────────────────────┘
```

**Explore Features:**

- **Show context:** Expand to see logs before/after
- **Live tail:** Stream logs in real-time
- **Wrap lines:** Toggle line wrapping
- **Deduplication:** Remove duplicate log lines
- **Log level detection:** Automatic color coding
- **Copy to clipboard:** Quick log sharing

### Dashboard Panels

**1. Logs Panel**

The primary visualization for log data:

```json
{
  "type": "logs",
  "title": "Application Logs",
  "targets": [
    {
      "expr": "{app=\"nginx\"} |= \"error\"",
      "refId": "A"
    }
  ],
  "options": {
    "showTime": true,
    "showLabels": false,
    "showCommonLabels": false,
    "wrapLogMessage": false,
    "prettifyLogMessage": false,
    "enableLogDetails": true,
    "dedupStrategy": "none",
    "sortOrder": "Descending"
  }
}
```

**Panel Options:**
- Show/hide timestamps
- Show/hide labels
- Enable log details expansion
- Deduplication strategy
- Sort order (ascending/descending)

**2. Time Series Panel (Metric Queries)**

Visualize log metrics:

```logql
# Error rate over time
rate({app="nginx"} |= "error" [5m])

# Log volume by level
sum by (level) (rate({app="api"} | json [5m]))
```

**3. Stat Panel**

Show aggregate metrics:

```logql
# Total error count in time range
sum(count_over_time({app="nginx"} |= "error" [1h]))

# Current error rate
sum(rate({level="error"} [5m]))
```

**4. Table Panel**

Display structured log data:

```logql
{app="nginx"} 
  | json 
  | line_format "{{.method}}\t{{.path}}\t{{.status}}\t{{.duration}}"
```

### Template Variables for Dynamic Dashboards

**Common Variable Patterns:**

**1. Label Values Variable**

Query: `label_values(app)`

Allows selection of application:

```logql
{app="$app"}
```

**2. Namespace Variable (Kubernetes)**

Query: `label_values(namespace)`

```logql
{namespace="$namespace"}
```

**3. Log Level Variable**

Custom variable:
- Name: `level`
- Type: Custom
- Values: `debug,info,warning,error`
- Multi-value: enabled

```logql
{app="$app"} | json | level="$level"
```

**4. Text Search Variable**

- Name: `search`
- Type: Text box
- Default: `error`

```logql
{app="$app"} |= "$search"
```

**5. Time Range Variable**

Use `$__range` for queries based on dashboard time range:

```logql
rate({app="$app"} [$__range])
```

### Example Dashboard Configuration

**Variables:**

```yaml
# Namespace selector
- name: namespace
  type: query
  datasource: Loki
  query: label_values(namespace)
  
# Pod selector (depends on namespace)
- name: pod
  type: query
  datasource: Loki
  query: label_values({namespace="$namespace"}, pod)
  multi: true
  includeAll: true
  
# Search box
- name: search
  type: textbox
  default: ""
```

**Panels:**

```yaml
# Panel 1: Log volume graph
query: sum by (level) (rate({namespace="$namespace", pod=~"$pod"} [5m]))
type: timeseries

# Panel 2: Logs table
query: {namespace="$namespace", pod=~"$pod"} |= "$search"
type: logs
maxDataPoints: 1000

# Panel 3: Error count stat
query: sum(count_over_time({namespace="$namespace", pod=~"$pod"} |= "error" [$__range]))
type: stat
```

### Correlating Logs with Metrics

**Using the Same Variables:**

```yaml
# Prometheus panel
CPU Usage: rate(container_cpu_usage_seconds_total{namespace="$namespace", pod=~"$pod"}[5m])

# Loki panel
Logs: {namespace="$namespace", pod=~"$pod"}
```

Both panels update when variables change, showing correlated data.

**Derived Fields for Trace Correlation:**

Link from logs to traces:

```yaml
# In Loki data source config
Derived Fields:
  - Name: traceID
    Regex: trace_id=(\w+)
    URL: ${__value.raw}
    Internal Link: Tempo
```

Clicking a trace ID in logs opens the trace in Tempo.

### Advanced Dashboard Patterns

**1. Log Search Interface**

Create an intuitive search dashboard:

- Namespace dropdown (from Prometheus)
- Pod dropdown (from Prometheus)
- Text search box
- Logs panel with query: `{namespace="$namespace", pod=~"$pod"} |= "$search"`

**2. Service Health Dashboard**

Combine metrics and logs:

```
┌─────────────────┬─────────────────┐
│   Request Rate  │   Error Rate    │
│   (Prometheus)  │   (Prometheus)  │
├─────────────────┴─────────────────┤
│        Recent Error Logs          │
│            (Loki)                 │
└───────────────────────────────────┘
```

**3. Log Level Distribution**

```logql
sum by (level) (count_over_time({app="$app"} | json [5m]))
```

Visualize as pie chart or bar chart.

**4. Top Error Messages**

```logql
topk(10, 
  sum by (message) (
    count_over_time(
      {app="$app"} 
        | json 
        | level="error" [1h]
    )
  )
)
```
