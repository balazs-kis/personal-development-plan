---

## Introduction

Getting logs into Loki requires a collector that discovers log sources, reads log files, and ships them to Loki. Promtail is the traditional agent designed specifically for Loki, while Grafana Alloy is the newer, more versatile collector that supports multiple protocols. Understanding different ingestion patterns and how to configure collectors properly ensures your logs reach Loki efficiently with appropriate metadata.

## Key Concepts Summary

### Log Collectors Overview

**Promtail (Traditional)**
- Purpose-built agent for shipping logs to Loki
- Lightweight and efficient
- Excellent Kubernetes integration via service discovery
- Supports log parsing and label extraction

**Grafana Alloy (Modern)**
- Next-generation collector (successor to Grafana Agent)
- Supports multiple protocols: Loki, Prometheus, Tempo, Pyroscope
- More flexible configuration
- Better observability of the collector itself

**Other Options:**
- Fluentd / Fluent Bit (with Loki output plugin)
- Logstash (with Loki output plugin)
- OpenTelemetry Collector (with Loki exporter)
- Docker logging driver
- Lambda Promtail (for AWS CloudWatch)

### Promtail Configuration

**Basic Configuration Structure:**

```yaml
server:
  http_listen_port: 9080
  grpc_listen_port: 0

positions:
  filename: /tmp/positions.yaml

clients:
  - url: http://loki:3100/loki/api/v1/push

scrape_configs:
  - job_name: system
    static_configs:
      - targets:
          - localhost
        labels:
          job: varlogs
          __path__: /var/log/*log
```

**Key Sections:**

1. **server:** Promtail's own HTTP server for metrics and health checks
2. **positions:** Tracks file read positions to avoid duplicate sends after restart
3. **clients:** Loki endpoints to push logs to
4. **scrape_configs:** Defines what logs to collect and how to label them

### Service Discovery

**Static Configuration:**

```yaml
scrape_configs:
  - job_name: my-app
    static_configs:
      - targets:
          - localhost
        labels:
          app: myapp
          environment: production
          __path__: /var/log/myapp/*.log
```

**Kubernetes Service Discovery:**

```yaml
scrape_configs:
  - job_name: kubernetes-pods
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      # Only scrape pods with specific annotations
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
      
      # Extract namespace
      - source_labels: [__meta_kubernetes_namespace]
        target_label: namespace
      
      # Extract pod name
      - source_labels: [__meta_kubernetes_pod_name]
        target_label: pod
      
      # Extract container name
      - source_labels: [__meta_kubernetes_pod_container_name]
        target_label: container
      
      # Set log path
      - source_labels: [__meta_kubernetes_pod_uid, __meta_kubernetes_pod_container_name]
        target_label: __path__
        replacement: /var/log/pods/*$1*/*/*.log
```

**Docker Service Discovery:**

```yaml
scrape_configs:
  - job_name: docker
    docker_sd_configs:
      - host: unix:///var/run/docker.sock
    relabel_configs:
      - source_labels: [__meta_docker_container_name]
        target_label: container
      - source_labels: [__meta_docker_container_log_stream]
        target_label: stream
```

### Pipeline Stages

Promtail pipelines transform log lines before sending to Loki:

**Common Pipeline Stages:**

```yaml
pipeline_stages:
  # 1. Parse JSON logs
  - json:
      expressions:
        level: level
        message: msg
        timestamp: ts
  
  # 2. Extract labels
  - labels:
      level:
  
  # 3. Parse timestamps
  - timestamp:
      source: timestamp
      format: RFC3339
  
  # 4. Add static labels
  - static_labels:
      environment: production
  
  # 5. Use regex to extract fields
  - regex:
      expression: '^(?P<ip>\S+) .* "(?P<method>\S+) (?P<path>\S+)'
  
  # 6. Filter out logs
  - match:
      selector: '{job="varlogs"} |= "debug"'
      action: drop
```

**Example: Parsing Nginx Access Logs:**

```yaml
pipeline_stages:
  - regex:
      expression: '^(?P<remote_addr>\S+) - (?P<remote_user>\S+) \[(?P<time_local>[^\]]+)\] "(?P<method>\S+) (?P<request>\S+) (?P<protocol>\S+)" (?P<status>\d+) (?P<body_bytes_sent>\d+)'
  
  - labels:
      method:
      status:
  
  - template:
      source: message
      template: '{{ .method }} {{ .request }} -> {{ .status }}'
  
  - output:
      source: message
```

### Grafana Alloy Configuration

**Basic Alloy Configuration:**

```alloy
// Discover log files
local.file_match "logs" {
  path_targets = [{
    __path__  = "/var/log/*.log",
    job       = "varlogs",
    host      = env("HOSTNAME"),
  }]
}

// Configure Loki write endpoint
loki.write "local" {
  endpoint {
    url = "http://loki:3100/loki/api/v1/push"
  }
}

// Scrape discovered logs
loki.source.file "logs" {
  targets    = local.file_match.logs.targets
  forward_to = [loki.process.filter.receiver]
}

// Process and filter logs
loki.process "filter" {
  forward_to = [loki.write.local.receiver]

  // Parse JSON logs
  stage.json {
    expressions = {
      level = "level",
      msg   = "message",
    }
  }

  // Extract level as a label
  stage.labels {
    values = {
      level = "",
    }
  }
}
```

### Dynamic Label Addition

**Using Regex to Extract Labels:**

```yaml
# Promtail example
pipeline_stages:
  - regex:
      expression: 'user_id=(?P<user_id>\d+)'
  
  # DON'T add high-cardinality as label!
  # Instead, keep it in the log line
  
  - regex:
      expression: 'severity=(?P<severity>\w+)'
  
  # DO add low-cardinality extracted fields
  - labels:
      severity:
```

**Using Template to Modify Log Line:**

```yaml
pipeline_stages:
  - template:
      source: output
      template: '{{ .level | ToUpper }} - {{ .message }}'
```

### Best Practices for Log Ingestion

**1. Position Files**
Always configure position tracking to avoid re-sending logs:

```yaml
positions:
  filename: /var/lib/promtail/positions.yaml
```

**2. Batch Configuration**
Tune batching for efficiency:

```yaml
clients:
  - url: http://loki:3100/loki/api/v1/push
    batchwait: 1s      # Max wait before sending batch
    batchsize: 1048576 # Max batch size in bytes (1MB)
```

**3. Resource Limits**
Set appropriate limits:

```yaml
limits_config:
  readline_rate: 10000        # Lines per second
  readline_burst: 20000       # Burst limit
  max_streams: 1000           # Max streams per file
```

**4. Multiline Logs**
Handle multiline logs (e.g., stack traces):

```yaml
pipeline_stages:
  - multiline:
      firstline: '^\d{4}-\d{2}-\d{2}'
      max_wait_time: 3s
```

**5. Health Checks**
Monitor Promtail itself:

```yaml
server:
  http_listen_port: 9080

# Metrics available at http://promtail:9080/metrics
# Health check at http://promtail:9080/ready
```
