## Introduction

OpenTelemetry is the modern standard for distributed tracing, and Jaeger v2 is built on the OpenTelemetry Collector framework. All new applications should use OpenTelemetry SDKs to instrument code and send traces to Jaeger. This lesson covers how to integrate OpenTelemetry with Jaeger, configure exporters, and ensure your traces flow correctly from applications to the Jaeger backend.

## Key Concepts Summary

### OpenTelemetry and Jaeger Integration

**The Modern Stack:**

```
Application Code
      ↓
OpenTelemetry SDK
      ↓
OTLP Exporter (gRPC or HTTP)
      ↓
Jaeger Collector (OTLP Receiver)
      ↓
Storage Backend
      ↓
Jaeger UI
```

**Key Points:**
- **No Jaeger SDKs needed** - Use OpenTelemetry SDKs only
- **OTLP protocol** - Standard OpenTelemetry Protocol
- **Vendor neutral** - Can switch from Jaeger to other backends easily

### Setting Up Jaeger with OTLP Support

**Docker Quick Start:**

```bash
docker run --rm --name jaeger \
  -p 16686:16686 \
  -p 4317:4317 \
  -p 4318:4318 \
  jaegertracing/jaeger:latest \
  --set receivers.otlp.protocols.http.endpoint=0.0.0.0:4318 \
  --set receivers.otlp.protocols.grpc.endpoint=0.0.0.0:4317
```

**Ports:**
- `16686`: Jaeger UI (HTTP)
- `4317`: OTLP gRPC receiver
- `4318`: OTLP HTTP receiver

**Docker Compose:**

```yaml
version: '3'
services:
  jaeger:
    image: jaegertracing/jaeger:latest
    ports:
      - "16686:16686"  # Jaeger UI
      - "4317:4317"    # OTLP gRPC
      - "4318:4318"    # OTLP HTTP
    environment:
      - COLLECTOR_OTLP_ENABLED=true
    command:
      - --set=receivers.otlp.protocols.grpc.endpoint=0.0.0.0:4317
      - --set=receivers.otlp.protocols.http.endpoint=0.0.0.0:4318
```

### Instrumenting .NET Applications

**1. Install Required Packages:**

```bash
dotnet add package OpenTelemetry
dotnet add package OpenTelemetry.Exporter.OpenTelemetryProtocol
dotnet add package OpenTelemetry.Instrumentation.AspNetCore
dotnet add package OpenTelemetry.Instrumentation.Http
dotnet add package OpenTelemetry.Extensions.Hosting
```

**2. Configure TracerProvider in Program.cs:**

```csharp
using OpenTelemetry;
using OpenTelemetry.Resources;
using OpenTelemetry.Trace;

var builder = WebApplication.CreateBuilder(args);

// Configure OpenTelemetry
builder.Services.AddOpenTelemetry()
    .WithTracing(tracerProviderBuilder =>
    {
        tracerProviderBuilder
            .SetResourceBuilder(ResourceBuilder
                .CreateDefault()
                .AddService(
                    serviceName: "MyService",
                    serviceVersion: "1.0.0"))
            .AddAspNetCoreInstrumentation()
            .AddHttpClientInstrumentation()
            .AddSource("MyService")
            .AddOtlpExporter(options =>
            {
                // Jaeger OTLP endpoint
                options.Endpoint = new Uri("http://localhost:4317");
                options.Protocol = OtlpExportProtocol.Grpc;
            });
    });

var app = builder.Build();
app.Run();
```

**3. Create Custom Spans:**

```csharp
using System.Diagnostics;
using OpenTelemetry.Trace;

public class OrderService
{
    private static readonly ActivitySource ActivitySource = 
        new ActivitySource("MyService");

    public async Task<Order> ProcessOrder(int orderId)
    {
        // Create a custom span
        using var activity = ActivitySource.StartActivity("ProcessOrder");
        
        // Add tags/attributes
        activity?.SetTag("order.id", orderId);
        activity?.SetTag("order.status", "processing");
        
        try
        {
            var order = await GetOrder(orderId);
            await ValidateOrder(order);
            await ChargePayment(order);
            await UpdateInventory(order);
            
            activity?.SetTag("order.status", "completed");
            return order;
        }
        catch (Exception ex)
        {
            // Record exception
            activity?.SetStatus(ActivityStatusCode.Error, ex.Message);
            activity?.RecordException(ex);
            throw;
        }
    }

    private async Task<Order> GetOrder(int orderId)
    {
        // Automatic HTTP instrumentation creates span
        using var httpClient = new HttpClient();
        var response = await httpClient.GetAsync($"/api/orders/{orderId}");
        // ...
    }
}
```

### OTLP Exporter Configuration

**gRPC vs HTTP:**

```csharp
// Option 1: gRPC (Default, recommended)
.AddOtlpExporter(options =>
{
    options.Endpoint = new Uri("http://localhost:4317");
    options.Protocol = OtlpExportProtocol.Grpc;
});

// Option 2: HTTP/Protobuf
.AddOtlpExporter(options =>
{
    options.Endpoint = new Uri("http://localhost:4318/v1/traces");
    options.Protocol = OtlpExportProtocol.HttpProtobuf;
});
```

**gRPC Advantages:**
- Better performance (binary protocol)
- Bidirectional streaming
- Widely supported

**HTTP Advantages:**
- Works through HTTP proxies
- Easier firewall configuration
- Simpler debugging

**Configuration via Environment Variables:**

```bash
# OTLP endpoint
export OTEL_EXPORTER_OTLP_ENDPOINT=http://jaeger:4317

# Or specify traces endpoint specifically
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://jaeger:4317

# Protocol (grpc or http/protobuf)
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc

# Headers (if authentication needed)
export OTEL_EXPORTER_OTLP_HEADERS="api-key=secret"
```

### Resource Configuration

**Service Identification:**

```csharp
.SetResourceBuilder(ResourceBuilder.CreateDefault()
    .AddService(
        serviceName: "order-service",
        serviceVersion: "1.2.3",
        serviceInstanceId: Environment.MachineName)
    .AddAttributes(new Dictionary<string, object>
    {
        ["deployment.environment"] = "production",
        ["service.namespace"] = "ecommerce",
        ["host.name"] = Environment.MachineName,
        ["k8s.pod.name"] = Environment.GetEnvironmentVariable("POD_NAME"),
        ["k8s.namespace.name"] = Environment.GetEnvironmentVariable("NAMESPACE")
    }))
```

**Why Resources Matter:**
- Identify which service/instance created the trace
- Filter traces by environment, version, etc.
- Group services in Jaeger UI
- Essential for multi-tenant scenarios

### Automatic Instrumentation

**ASP.NET Core:**

```csharp
.AddAspNetCoreInstrumentation(options =>
{
    // Enrich spans with additional data
    options.Enrich = (activity, eventName, rawObject) =>
    {
        if (eventName == "OnStartActivity")
        {
            if (rawObject is HttpRequest request)
            {
                activity.SetTag("http.client_ip", 
                    request.HttpContext.Connection.RemoteIpAddress);
                activity.SetTag("http.user_agent", 
                    request.Headers["User-Agent"].ToString());
            }
        }
    };
    
    // Filter requests
    options.Filter = (httpContext) =>
    {
        // Don't trace health check endpoints
        return !httpContext.Request.Path.StartsWithSegments("/health");
    };
});
```

**HttpClient:**

```csharp
.AddHttpClientInstrumentation(options =>
{
    // Enrich outgoing HTTP requests
    options.EnrichWithHttpRequestMessage = (activity, request) =>
    {
        activity.SetTag("http.request.method", request.Method.Method);
    };
    
    options.EnrichWithHttpResponseMessage = (activity, response) =>
    {
        activity.SetTag("http.response.status_code", (int)response.StatusCode);
    };
});
```

**Entity Framework Core:**

```bash
dotnet add package OpenTelemetry.Instrumentation.EntityFrameworkCore
```

### Sampling Configuration

**Sampling Strategies:**

```csharp
// 1. Always sample (development)
.SetSampler(new AlwaysOnSampler())

// 2. Never sample (disabled)
.SetSampler(new AlwaysOffSampler())

// 3. Probabilistic (10% of traces)
.SetSampler(new TraceIdRatioBasedSampler(0.1))

// 4. Parent-based (follow parent decision)
.SetSampler(new ParentBasedSampler(
    new TraceIdRatioBasedSampler(0.1)))
```

**Practical Sampling Strategy:**

```csharp
.SetSampler(new ParentBasedSampler(
    // Root sampler (for requests starting at this service)
    rootSampler: new TraceIdRatioBasedSampler(0.01), // 1%
    
    // Remote parent sampled: follow parent decision
    remoteParentSampled: new AlwaysOnSampler(),
    
    // Remote parent not sampled: follow parent decision
    remoteParentNotSampled: new AlwaysOffSampler()
))
```

**Environment-Based Sampling:**

```csharp
var environment = builder.Environment;
var samplingRate = environment.IsProduction() ? 0.01 : 1.0;

.SetSampler(new TraceIdRatioBasedSampler(samplingRate))
```

### Troubleshooting

**Common Issues:**

**1. No Traces Appearing in Jaeger**

Check:
```bash
# Is Jaeger running?
curl http://localhost:16686

# Is OTLP receiver enabled?
curl http://localhost:4317
curl http://localhost:4318

# Check application logs for errors
```

Solution:
- Verify Jaeger is running with OTLP receivers enabled
- Check firewall rules
- Verify endpoint URL in application configuration

**2. Connection Refused**

```
Error: Connection refused to localhost:4317
```

Solution:
- Use correct hostname (not `localhost` in Docker)
- Use service name in Docker Compose: `jaeger:4317`
- Check network connectivity

**3. Traces Missing Spans**

Causes:
- Auto-instrumentation not configured
- Custom ActivitySource not registered
- Spans not started correctly

Solution:
```csharp
// Register your ActivitySource
.AddSource("MyService")

// Create spans correctly
using var activity = ActivitySource.StartActivity("OperationName");
```

**4. High Memory Usage**

Causes:
- Sampling rate too high
- Batch size too large
- Too many spans per trace

Solution:
```csharp
.AddOtlpExporter(options =>
{
    options.BatchExportProcessorOptions = new()
    {
        MaxQueueSize = 2048,
        ScheduledDelayMilliseconds = 5000,
        MaxExportBatchSize = 512
    };
});
```

### Complete Example

**Minimal Working Application:**

```csharp
using OpenTelemetry;
using OpenTelemetry.Resources;
using OpenTelemetry.Trace;

var builder = WebApplication.CreateBuilder(args);

// Configure OpenTelemetry
builder.Services.AddOpenTelemetry()
    .WithTracing(tracing =>
    {
        tracing
            .SetResourceBuilder(ResourceBuilder
                .CreateDefault()
                .AddService("demo-service"))
            .AddAspNetCoreInstrumentation()
            .AddHttpClientInstrumentation()
            .AddOtlpExporter(options =>
            {
                options.Endpoint = new Uri("http://localhost:4317");
            });
    });

var app = builder.Build();

app.MapGet("/", () => "Hello World!");

app.MapGet("/external", async () =>
{
    using var client = new HttpClient();
    var response = await client.GetStringAsync("https://api.github.com");
    return "OK";
});

app.Run();
```

**Run Jaeger:**

```bash
docker run --rm --name jaeger \
  -p 16686:16686 \
  -p 4317:4317 \
  jaegertracing/jaeger:latest
```

**Test:**

```bash
curl http://localhost:5000/
curl http://localhost:5000/external

# View traces
open http://localhost:16686
```

## Key Takeaways

- **Use OpenTelemetry SDKs** for all new instrumentation (not legacy Jaeger SDKs)
- **OTLP is the standard** protocol for sending traces to Jaeger
- **Automatic instrumentation** covers most common scenarios (HTTP, DB)
- **Custom spans** provide business-level observability
- **Sampling is essential** for production (typically 1-5%)
- **Resources identify** your service in a multi-service environment
- **Jaeger v2** fully embraces OpenTelemetry
