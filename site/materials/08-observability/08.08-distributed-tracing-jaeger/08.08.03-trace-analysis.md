# Lesson 3: Trace Analysis with Jaeger UI

## Learning Objectives

By the end of this lesson, you will be able to:
- Navigate the Jaeger UI effectively
- Search for traces using various criteria
- Analyze individual traces and identify bottlenecks
- Use different visualization modes (timeline, graph, flame graph)
- Compare multiple traces to find performance differences
- Export and share trace data

---

## Introduction

The Jaeger UI is a powerful interface for exploring and analyzing distributed traces. It provides multiple visualization modes, search capabilities, and analytical tools that help you understand system behavior, identify performance bottlenecks, and troubleshoot issues across microservices. Mastering the Jaeger UI is essential for effective trace analysis and system observability.

## Key Concepts Summary

### Accessing Jaeger UI

**Default Ports:**
- UI: `http://localhost:16686`
- API: `http://localhost:16686/api`

**Quick Start with Docker:**

```bash
docker run --rm --name jaeger \
  -p 16686:16686 \
  -p 4317:4317 \
  -p 4318:4318 \
  jaegertracing/jaeger:latest
```

### Main UI Sections

```
┌─────────────────────────────────────────────┐
│  [Jaeger Logo]  Search  System Architecture │
├─────────────────────────────────────────────┤
│                                             │
│  Service: [dropdown]  Operation: [dropdown]│
│  Tags: [input]  Lookback: [dropdown]       │
│  Min/Max Duration: [inputs]                │
│  Limit Results: [input]  [Find Traces]     │
│                                             │
├─────────────────────────────────────────────┤
│  Results: Scatter Plot / Timeline View     │

└─────────────────────────────────────────────┘
```

### Trace Search

**Search Criteria:**

**1. Service**
- Select the service you want to investigate
- Required field

**2. Operation**
- Specific operation within the service
- Optional (leave empty to search all operations)
- Examples: `GET /api/users`, `ProcessOrder`, `SaveToDatabase`

**3. Tags**
- Key-value pairs to filter traces
- Format: `key=value`
- Multiple tags use AND logic

**Common Tag Filters:**

```
# HTTP status codes
http.status_code=500
http.status_code=404

# Error traces
error=true

# Specific user or tenant
user.id=12345
tenant=acme-corp

# Response time
http.response_time>1000

# Environment
environment=production
```

**4. Lookback Period**
- Last hour, 2 hours, 3 hours, etc.
- Custom time range

**5. Duration**
- Min Duration: Show only traces longer than X
- Max Duration: Show only traces shorter than X
- Example: Find traces between 500ms and 2s

**6. Limit Results**
- Number of traces to return (default: 20)
- Max usually 100-500

### Search Results Visualization

**Scatter Plot View:**

```
Duration (ms)
    ↑
2000│          ●
    │        ●  ●
1500│    ●  ●    ●
    │  ● ●  ●  ●  ●
1000│ ●● ●● ●● ●● ●●
    │●●●●●●●●●●●●●●●
    └─────────────────→ Time
```

**Features:**
- Each dot represents a trace
- X-axis: Time
- Y-axis: Duration
- Color: Number of spans (darker = more spans)
- **Click any dot** to view the trace details

**Benefits:**
- Quickly identify outliers (unusually slow traces)
- Spot patterns (e.g., periodic slow requests)
- Find the "interesting" traces to investigate

**Table View:**

| Trace ID | Services | Duration | Spans | Start Time |
|----------|----------|----------|-------|------------|
| abc123... | 5 | 1.2s | 23 | 10:15:23 |
| def456... | 4 | 850ms | 18 | 10:15:24 |
| ghi789... | 6 | 2.1s | 31 | 10:15:25 |

**Features:**
- Sortable by any column
- Click row to view trace details
- Select multiple traces for comparison

### Within-Trace Search

**Search Box:**
Filter spans within a trace:

```
Search: "GET"
→ Shows only spans with "GET" in operation name or tags
→ Automatically expands matching spans
```

**Use Cases:**
- Find all database queries: `db.statement`
- Find errors: `error`
- Find slow operations: Look at duration

### Alternative Visualization Modes

**1. Graph View**

```
┌─────────┐
│ Gateway │
└────┬────┘
     │
     ├──→ ┌──────┐
     │    │ Auth │
     │    └──────┘
     │
     └──→ ┌───────┐
          │ Order │
          └───┬───┘
              │
              ├──→ ┌──────────┐
              │    │ Database │
              │    └──────────┘
              │
              └──→ ┌─────────┐
                   │ Payment │
                   └─────────┘
```

**Features:**
- **Node view** of service calls
- **Color by service** or highlight critical path
- **Show self-time** (time spent in span excluding children)
- Useful for understanding service dependencies

**2. Flame Graph**

```
                Gateway (200ms)
    ┌──────────────┬──────────────────┐
    │              │                  │
   Auth         Order              Other
  (50ms)      (100ms)            (50ms)
            ┌────┴────┐
            │         │
        Database   Payment
         (30ms)    (50ms)
                     │
                 Ext API
                  (40ms)
```

**Features:**
- **Width** represents duration
- **Height** represents call stack depth
- Quick identification of bottlenecks
- Common in performance profiling

**3. Spans Table**

| Operation | Service | Duration | Start Offset |
|-----------|---------|----------|--------------|
| GET /orders | gateway | 200ms | 0ms |
| CheckAuth | auth | 50ms | 5ms |
| ProcessOrder | order | 100ms | 60ms |
| SELECT * | db | 30ms | 70ms |
| ChargeCard | payment | 50ms | 110ms |

**Features:**
- Tabular view of all spans
- Sortable columns
- Good for detailed analysis

### Trace Comparison

**Steps:**
1. Search for traces
2. Select 2+ traces in table view
3. Click "Compare" button
4. View side-by-side comparison

**Comparison View:**

```
Trace A                    Trace B
Gateway (200ms)           Gateway (1500ms)
├─ Auth (50ms)            ├─ Auth (50ms)
├─ Order (100ms)          ├─ Order (1200ms) ⚠️
│  ├─ DB (30ms)           │  ├─ DB (800ms) ⚠️
│  └─ Payment (50ms)      │  └─ Payment (300ms) ⚠️
```

**Highlighted Differences:**
- **Red**: Operations present in one trace but not the other
- **Orange**: Significant duration differences
- Helps identify where performance degrades

**Use Cases:**
- Compare fast vs. slow requests
- Before/after code changes
- Different user paths
- Error vs. success traces

### Advanced Features

**JSON View:**
View raw trace data:

```json
{
  "traceID": "abc123",
  "spans": [
    {
      "spanID": "span1",
      "operationName": "GET /api/orders",
      "startTime": 1706357723123000,
      "duration": 200000,
      "tags": [
        {"key": "http.method", "value": "GET"},
        {"key": "http.status_code", "value": 200}
      ]
    }
  ]
}
```

**Export Options:**
- JSON export for programmatic analysis
- Share via URL (includes search params)
- Embed in documentation

**Keyboard Shortcuts:**
- `[` / `]`: Navigate between spans
- `g`: Go to span (by ID)
- `/`: Focus search box
- `u`: Expand/collapse all

3. In Jaeger UI:
   - Search for traces from the "frontend" service
   - Find the slowest trace
   - Identify which span is the bottleneck
