---

## Introduction

Grafana provides a wide variety of visualization types (called "panels") to represent different kinds of data. Choosing the right visualization type is crucial for effective data communication. A gauge works well for showing a single metric's current value within a range, while time series graphs excel at showing trends over time. Understanding when to use each panel type will help you create dashboards that communicate insights clearly and quickly.

## Key Concepts Summary

### Panel Types Overview

**Time Series**
- **Best for:** Showing trends over time, comparing multiple metrics
- **Use cases:** CPU usage, request rates, latency trends
- **Key features:** Multiple series, legend, thresholds, annotations

**Gauge**
- **Best for:** Showing a single metric's current value within a min/max range
- **Use cases:** CPU percentage, disk usage, error rate
- **Key features:** Visual representation of thresholds, at-a-glance status

**Stat**
- **Best for:** Displaying a single large number with optional sparkline
- **Use cases:** Total request count, current active users, success rate
- **Key features:** Color thresholds, value reduction (last, min, max, avg)

**Table**
- **Best for:** Displaying multiple series with multiple fields
- **Use cases:** Service status lists, resource inventories, log summaries
- **Key features:** Sorting, filtering, cell coloring

**Logs**
- **Best for:** Displaying log lines from Loki or other log sources
- **Use cases:** Application logs, error investigation, audit trails
- **Key features:** Log line highlighting, filtering, context expansion

**Bar Chart**
- **Best for:** Comparing discrete values or categories
- **Use cases:** Request counts by endpoint, errors by service
- **Key features:** Horizontal or vertical orientation, stacking

### Using the Panel Editor

The panel editor has several key sections:

1. **Query tab:** Define data source queries
2. **Transform tab:** Manipulate query results (filter, join, calculate)
3. **Alert tab:** Configure alerts for the panel
4. **Panel options:** Set title, description, repeat options
5. **Visualization:** Choose panel type and configure display options
6. **Field options:** Configure units, thresholds, value mappings

### The RED Method Visualization Pattern

For microservices monitoring, use these visualization patterns:

- **Rate:** Time series graph showing requests per second
- **Errors:** Time series graph showing error rate or percentage
- **Duration:** Time series graph showing latency percentiles (p50, p95, p99)

Group these three metrics together in a dashboard row for each service.

### Best Practices

**Choose the Right Visualization**
- Use time series for trends and comparisons
- Use gauges for current state within a range
- Use stat panels for key numbers that need to stand out
- Use tables when you need to show multiple dimensions

**Configure Appropriately**
- Set meaningful units (bytes, seconds, requests/sec)
- Apply color thresholds that match your SLOs
- Use consistent colors across dashboards (red = bad, green = good)
- Add helpful descriptions and tooltips

**Performance Tips**
- Limit time series to essential data points
- Use dashboard variables instead of many similar panels
- Choose appropriate query intervals
- Consider using recording rules in Prometheus for expensive queries
