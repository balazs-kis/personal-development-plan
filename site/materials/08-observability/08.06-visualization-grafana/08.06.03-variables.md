---

## Introduction

Variables make Grafana dashboards dynamic and reusable. Instead of creating separate dashboards for each server, environment, or service, you can create one dashboard with variables that allow users to select what they want to view. Variables can be populated from queries, defined as custom lists, or pulled from data sources. They enable interactive exploration and reduce dashboard maintenance overhead significantly.

## Key Concepts Summary

### Variable Types

**Query Variable**
- Populated by running a query against a data source
- Example: List of servers from Prometheus `label_values(up, instance)`
- Updates dynamically as data changes

**Custom Variable**
- Manually defined list of values
- Example: Environments (dev, staging, production)
- Useful for known, static options

**Data Source Variable**
- Allows selection between multiple data source instances
- Example: Choose between different Prometheus databases
- Enables environment switching without dashboard duplication

**Interval Variable**
- Defines time ranges or intervals
- Example: `1m`, `5m`, `1h` for aggregation intervals
- Useful for adjusting query granularity

**Text Box Variable**
- Free-form text input
- Example: Search term, custom threshold
- Provides maximum flexibility

**Constant Variable**
- Hidden variable with a fixed value
- Useful for dashboard configuration without UI clutter

### Using Variables in Queries

Variables are referenced using `$variable_name` or `${variable_name}` syntax:

```promql
# Single value
rate(http_requests_total{instance="$server"}[5m])

# Multi-select with regex
rate(http_requests_total{instance=~"$server"}[5m])

# Variable in aggregation
sum by (job) (rate(http_requests_total{instance=~"$server"}[5m]))
```

### Multi-Select Variables

Enable multiple selections:
- Set **Multi-value** option in variable settings
- Use **Include All option** to add an "All" choice
- In queries, use regex operator `=~` instead of `=`
- Values are joined with `|` automatically: `server1|server2|server3`

### Data Links and Drill-Downs

Create navigation between dashboards:

1. Configure a data link in panel settings
2. Pass variables in the URL: `d/dashboard-uid?var-server=$server`
3. Preserve time range: `&from=$__from&to=$__to`
4. Enable drill-down from summary to detailed views
5. Maintain context across navigation

### Variable Chaining

Create dependent variables where one variable filters another:

```promql
# First variable: Select region
label_values(region)

# Second variable: Servers in selected region
label_values(up{region="$region"}, instance)
```

### Library Panels

Create reusable panels:
- Create a panel, then **Share → Library panel**
- Reuse across multiple dashboards
- Changes propagate to all instances
- Perfect for standardized metrics
