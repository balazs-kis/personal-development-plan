---

## Introduction

Managing dashboards through the UI works well for initial development, but it becomes challenging at scale. Dashboard as Code treats your dashboards like application code—versioned, reviewed, tested, and deployed automatically. This approach enables consistency across environments, easier rollbacks, team collaboration through pull requests, and reproducible dashboard infrastructure. Whether using simple provisioning files, Terraform, or the Grafana Foundation SDK, Dashboard as Code is essential for mature observability practices.

## Key Concepts Summary

### Dashboard Provisioning

**File-Based Provisioning**

Grafana can automatically load dashboards from files on startup:

```yaml
# provisioning/dashboards/dashboards.yml
apiVersion: 1

providers:
  - name: 'default'
    orgId: 1
    folder: ''
    type: file
    disableDeletion: false
    updateIntervalSeconds: 10
    allowUiUpdates: true
    options:
      path: /var/lib/grafana/dashboards
```

Place dashboard JSON files in the configured path, and Grafana loads them automatically.

**Benefits:**
- Version control your dashboards
- Easy deployment with configuration management tools
- Consistent across environments
- No manual clicking in the UI

**Limitations:**
- Dashboards are read-only by default (unless `allowUiUpdates: true`)
- Changes in UI don't persist unless `allowUiUpdates` is enabled
- Requires file system access

### Dashboard JSON Model

Every Grafana dashboard is stored as JSON:

```json
{
  "dashboard": {
    "title": "My Dashboard",
    "uid": "my-dashboard-uid",
    "panels": [
      {
        "id": 1,
        "type": "timeseries",
        "title": "CPU Usage",
        "targets": [
          {
            "expr": "rate(cpu_usage[5m])",
            "datasource": "Prometheus"
          }
        ]
      }
    ],
    "templating": {
      "list": []
    },
    "time": {
      "from": "now-6h",
      "to": "now"
    }
  }
}
```

**Key sections:**
- **Metadata:** Title, UID, tags, version
- **Panels:** Array of visualization configurations
- **Templating:** Variables definition
- **Time:** Default time range
- **Annotations:** Event markers configuration

You can view any dashboard's JSON: **Dashboard settings → JSON Model**

### Terraform Management

The Grafana Terraform provider manages dashboards as infrastructure:

```hcl
terraform {
  required_providers {
    grafana = {
      source  = "grafana/grafana"
      version = "~> 2.0"
    }
  }
}

provider "grafana" {
  url  = "http://localhost:3000"
  auth = var.grafana_auth
}

resource "grafana_dashboard" "metrics" {
  folder = grafana_folder.monitoring.id
  
  config_json = jsonencode({
    title = "Service Metrics"
    uid   = "service-metrics"
    panels = [
      {
        id    = 1
        type  = "timeseries"
        title = "Request Rate"
        targets = [{
          expr       = "rate(http_requests_total[5m])"
          datasource = "Prometheus"
        }]
      }
    ]
  })
}
```

**Benefits:**
- Complete infrastructure as code
- Manage dashboards alongside other resources
- Plan and preview changes before applying
- State management and drift detection

**Best Practices:**
- Use Terraform modules for reusable dashboard patterns
- Store Terraform code in version control
- Use separate workspaces for different environments
- Automate with CI/CD pipelines

### Grafana Foundation SDK

The Foundation SDK enables programmatic dashboard creation:

**Use cases:**
- Generate dashboards dynamically
- Create dashboards from templates
- Build custom dashboard generation tools
- Automate dashboard creation in code

**Languages supported:**
- Go
- TypeScript
- Python
- Java

Example conceptual usage:
```typescript
import { Dashboard, Panel } from '@grafana/foundation-sdk';

const dashboard = new Dashboard('My Dashboard')
  .addPanel(
    new Panel('timeseries')
      .setTitle('Request Rate')
      .addTarget({ expr: 'rate(http_requests_total[5m])' })
  );

const json = dashboard.toJSON();
```

### CI/CD Integration

Automate dashboard deployment:

```yaml
# GitHub Actions example
name: Deploy Dashboards

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v2
        
      - name: Terraform Init
        run: terraform init
        
      - name: Terraform Plan
        run: terraform plan
        
      - name: Terraform Apply
        run: terraform apply -auto-approve
        env:
          GRAFANA_AUTH: ${{ secrets.GRAFANA_AUTH }}
```

**Benefits:**
- Automated testing of dashboard changes
- Pull request reviews for dashboard modifications
- Consistent deployment process
- Rollback capability
- Audit trail of changes

### Best Practices

**Version Control**
- Store all dashboard definitions in Git
- Use meaningful commit messages
- Implement code review for dashboard changes
- Tag releases for easy rollback

**Environment Management**
- Use variables for environment-specific values
- Separate Terraform workspaces for dev/staging/prod
- Test dashboard changes in lower environments first

**Dashboard Structure**
- Use consistent naming conventions
- Organize dashboards in folders
- Include metadata (tags, descriptions)
- Document dashboard purpose and usage

**Automation**
- Validate JSON syntax in CI pipeline
- Test dashboard rendering
- Automate deployment on merge to main
- Monitor deployment success
