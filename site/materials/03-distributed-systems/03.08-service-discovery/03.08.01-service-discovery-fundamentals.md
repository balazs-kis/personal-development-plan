## Introduction

In a monolithic application, components call each other through in-process method calls or localhost connections. But in a microservices architecture with dozens or hundreds of services, how does Service A find Service B? 

In traditional infrastructure, you might hardcode IP addresses or hostnames in configuration files. But in modern containerized environments (Kubernetes, Docker Swarm, ECS), services are ephemeral—they scale up and down, get deployed to different nodes, and fail and restart constantly. **Service discovery** solves this by providing a dynamic, always-current directory of available service instances.

Think of service discovery like a phone book that updates itself in real-time. When a new service instance starts, it registers itself. When it stops, it's automatically removed. Other services query this directory to find healthy instances they can call.

## Key Concepts Summary

### The Problem: Static Configuration Doesn't Scale

**Traditional Approach (Doesn't Work for Microservices):**
```json
{
  "OrderService": {
    "host": "10.0.1.5",
    "port": 8080
  },
  "InventoryService": {
    "host": "10.0.1.12",
    "port": 8081
  }
}
```

**Problems:**
- ❌ IP addresses change when instances restart
- ❌ New instances added by auto-scaling aren't known
- ❌ Failed instances remain in configuration
- ❌ Configuration must be updated and deployed for every change
- ❌ Doesn't work with container orchestrators
- ❌ No health checking or automatic failover
- ❌ Manual intervention required for scaling operations

### Service Discovery Solution

```
┌──────────────┐
│  Service A   │
└──────┬───────┘
       │ 1. Query: "Where is Service B?"
       ▼
┌──────────────────┐
│ Service Registry │ ← 2. Returns: [10.0.1.5:8080, 10.0.1.7:8080]
└──────────────────┘
       ▲
       │ 3. Register/Heartbeat
       │
┌──────┴───────┬──────────┐
│ Service B    │Service B │
│ Instance 1   │Instance 2│
└──────────────┴──────────┘
```

### Core Components

**1. Service Registry**
- Centralized database of service instances
- Tracks: service name, IP address, port, health status, metadata
- Examples: Consul, Eureka, etcd, Zookeeper, Kubernetes API Server

**2. Service Registration**
- Process of adding a service instance to the registry
- **Self-Registration:** Service registers itself on startup
- **Third-Party Registration:** Sidecar or orchestrator registers the service

**3. Service Query/Lookup**
- How clients find service instances
- Returns: list of healthy instances with their addresses
- May include load balancing hints, metadata, priorities

## Registration Patterns

### Self-Registration Pattern

```csharp
public class ServiceRegistration : IHostedService
{
    private readonly IServiceRegistry _registry;
    private readonly IConfiguration _config;
    private readonly ILogger<ServiceRegistration> _logger;
    private Timer _heartbeatTimer;
    private string _instanceId;
    
    public async Task StartAsync(CancellationToken cancellationToken)
    {
        _instanceId = Guid.NewGuid().ToString();
        
        var registration = new ServiceRegistration
        {
            ServiceName = "order-service",
            InstanceId = _instanceId,
            Host = GetLocalIPAddress(),
            Port = _config.GetValue<int>("Port"),
            HealthCheckUrl = $"http://localhost:{_config.GetValue<int>("Port")}/health",
            Tags = new[] { "v1.2.0", "prod", "us-west-2" },
            Metadata = new Dictionary<string, string>
            {
                ["version"] = "1.2.0",
                ["environment"] = "production",
                ["datacenter"] = "us-west-2"
            }
        };
        
        try
        {
            await _registry.RegisterAsync(registration);
            _logger.LogInformation("Service registered with ID: {InstanceId}", _instanceId);
            
            // Start heartbeat timer
            _heartbeatTimer = new Timer(
                SendHeartbeat,
                null,
                TimeSpan.FromSeconds(10),
                TimeSpan.FromSeconds(10));
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Failed to register service");
            throw;
        }
    }
    
    private async void SendHeartbeat(object state)
    {
        try
        {
            await _registry.SendHeartbeatAsync(_instanceId);
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Failed to send heartbeat");
        }
    }
    
    public async Task StopAsync(CancellationToken cancellationToken)
    {
        _heartbeatTimer?.Dispose();
        
        try
        {
            await _registry.DeregisterAsync(_instanceId);
            _logger.LogInformation("Service deregistered: {InstanceId}", _instanceId);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Failed to deregister service");
        }
    }
    
    private string GetLocalIPAddress()
    {
        var host = Dns.GetHostEntry(Dns.GetHostName());
        foreach (var ip in host.AddressList)
        {
            if (ip.AddressFamily == AddressFamily.InterNetwork)
            {
                return ip.ToString();
            }
        }
        throw new Exception("No network adapters with an IPv4 address found");
    }
}
```

## Service Discovery Implementations

### Using Consul

```csharp
public class ConsulServiceDiscovery : IServiceDiscovery
{
    private readonly IConsulClient _consul;
    private readonly IMemoryCache _cache;
    private readonly ILogger<ConsulServiceDiscovery> _logger;
    
    public ConsulServiceDiscovery(
        IConsulClient consul,
        IMemoryCache cache,
        ILogger<ConsulServiceDiscovery> logger)
    {
        _consul = consul;
        _cache = cache;
        _logger = logger;
    }
    
    public async Task<List<ServiceInstance>> DiscoverServiceAsync(
        string serviceName,
        string tag = null)
    {
        var cacheKey = $"service:{serviceName}:{tag}";
        
        // Check cache first
        if (_cache.TryGetValue(cacheKey, out List<ServiceInstance> cached))
        {
            _logger.LogDebug("Cache hit for service {ServiceName}", serviceName);
            return cached;
        }
        
        try
        {
            // Query Consul for healthy instances
            var queryResult = await _consul.Health.Service(
                serviceName,
                tag,
                passingOnly: true);
            
            var instances = queryResult.Response.Select(entry => new ServiceInstance
            {
                Id = entry.Service.ID,
                ServiceName = entry.Service.Service,
                Host = string.IsNullOrEmpty(entry.Service.Address)
                    ? entry.Node.Address
                    : entry.Service.Address,
                Port = entry.Service.Port,
                Tags = entry.Service.Tags,
                Metadata = entry.Service.Meta,
                HealthStatus = entry.Checks.All(c => c.Status == HealthStatus.Passing)
                    ? InstanceHealthStatus.Healthy
                    : InstanceHealthStatus.Unhealthy
            }).ToList();
            
            // Cache for 30 seconds
            _cache.Set(cacheKey, instances, TimeSpan.FromSeconds(30));
            
            _logger.LogInformation(
                "Discovered {Count} instances of {ServiceName}",
                instances.Count,
                serviceName);
            
            return instances;
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Failed to discover service {ServiceName}", serviceName);
            
            // Return cached data even if expired
            if (_cache.TryGetValue(cacheKey, out cached))
            {
                _logger.LogWarning("Returning stale cache data for {ServiceName}", serviceName);
                return cached;
            }
            
            throw;
        }
    }
    
    public async Task RegisterServiceAsync(ServiceRegistration registration)
    {
        var consulRegistration = new AgentServiceRegistration
        {
            ID = registration.InstanceId,
            Name = registration.ServiceName,
            Address = registration.Host,
            Port = registration.Port,
            Tags = registration.Tags,
            Meta = registration.Metadata,
            Check = new AgentServiceCheck
            {
                HTTP = registration.HealthCheckUrl,
                Interval = TimeSpan.FromSeconds(10),
                Timeout = TimeSpan.FromSeconds(5),
                DeregisterCriticalServiceAfter = TimeSpan.FromMinutes(1)
            }
        };
        
        await _consul.Agent.ServiceRegister(consulRegistration);
    }
}

// Usage
public class OrderController : ControllerBase
{
    private readonly IServiceDiscovery _discovery;
    private readonly IHttpClientFactory _httpClientFactory;
    
    [HttpPost]
    public async Task<IActionResult> CreateOrder(Order order)
    {
        // Discover inventory service instances
        var instances = await _discovery.DiscoverServiceAsync("inventory-service");
        
        if (!instances.Any())
        {
            return ServiceUnavailable("Inventory service not available");
        }
        
        // Choose an instance (load balancing)
        var instance = instances[Random.Shared.Next(instances.Count)];
        
        // Make request
        var client = _httpClientFactory.CreateClient();
        var response = await client.PostAsJsonAsync(
            $"http://{instance.Host}:{instance.Port}/api/inventory/reserve",
            order.Items);
        
        // Handle response...
    }
}
```

### Using Kubernetes DNS

```csharp
// Kubernetes provides built-in DNS-based discovery
public class KubernetesServiceDiscovery : IServiceDiscovery
{
    private readonly IHttpClientFactory _httpClientFactory;
    private readonly ILogger<KubernetesServiceDiscovery> _logger;
    
    public async Task<T> CallServiceAsync<T>(
        string serviceName,
        string path,
        HttpMethod method,
        object body = null)
    {
        // Kubernetes DNS resolves service name to ClusterIP
        // ClusterIP load-balances across pods automatically
        var baseUrl = $"http://{serviceName}";
        
        var client = _httpClientFactory.CreateClient();
        var request = new HttpRequestMessage(method, $"{baseUrl}{path}");
        
        if (body != null)
        {
            request.Content = JsonContent.Create(body);
        }
        
        try
        {
            var response = await client.SendAsync(request);
            response.EnsureSuccessStatusCode();
            
            return await response.Content.ReadFromJsonAsync<T>();
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Failed to call {ServiceName}{Path}", serviceName, path);
            throw;
        }
    }
}

// Usage - simple and elegant
var inventory = await _k8sDiscovery.CallServiceAsync<InventoryResponse>(
    serviceName: "inventory-service",
    path: "/api/stock/check",
    method: HttpMethod.Post,
    body: new { productIds = order.Items.Select(i => i.ProductId) }
);
```

## Service Registry Solutions Comparison

### Consul

**Architecture:**
```
┌─────────────────────────────────────────┐
│           Consul Cluster                │
│  ┌──────────┐  ┌──────────┐  ┌────────┐│
│  │ Server 1 │◄─┤ Server 2 │◄─┤Server 3││
│  │ (Leader) │  │(Follower)│  │(Follow)││
│  └──────────┘  └──────────┘  └────────┘│
└────────────────┬────────────────────────┘
                 │
     ┌───────────┼────────────┐
     │           │            │
┌────▼────┐ ┌───▼─────┐ ┌───▼─────┐
│ Agent 1 │ │ Agent 2 │ │ Agent 3 │
│ + App A │ │ + App B │ │ + App C │
└─────────┘ └─────────┘ └─────────┘
```

**Pros:**
- ✅ Rich feature set (KV store, health checks, UI, multi-DC)
- ✅ Strong consistency (CP in CAP theorem)
- ✅ Built-in health checking
- ✅ Service mesh capabilities (Consul Connect)

**Cons:**
- ❌ Requires separate deployment and maintenance
- ❌ More complex setup than Kubernetes-native solutions

**Configuration Example:**
```json
{
  "service": {
    "name": "order-service",
    "id": "order-service-1",
    "port": 8080,
    "tags": ["v1", "prod"],
    "meta": {
      "version": "1.0.0",
      "region": "us-west-2"
    },
    "check": {
      "http": "http://localhost:8080/health",
      "interval": "10s",
      "timeout": "5s",
      "deregister_critical_service_after": "1m"
    }
  }
}
```

### Kubernetes Services

**Pros:**
- ✅ Built-in, no extra components
- ✅ DNS-based discovery (transparent)
- ✅ Automatic load balancing
- ✅ Simple for Kubernetes users

**Cons:**
- ❌ Kubernetes-only (no VMs, bare metal)
- ❌ Limited to Kubernetes features
- ❌ Less flexible than dedicated registries

**How it Works:**
```
1. Service definition creates ClusterIP
2. CoreDNS creates DNS record: service-name.namespace.svc.cluster.local
3. kube-proxy updates iptables rules for load balancing
4. Clients just use DNS name, Kubernetes handles everything
```

## Advanced Patterns

### Service Discovery with Caching and Fallback

```csharp
public class ResilientServiceDiscovery : IServiceDiscovery
{
    private readonly IServiceDiscovery _primary;
    private readonly IDistributedCache _cache;
    private readonly ICircuitBreaker _circuitBreaker;
    
    public async Task<List<ServiceInstance>> DiscoverServiceAsync(string serviceName)
    {
        var cacheKey = $"service:{serviceName}";
        
        try
        {
            // Try primary discovery through circuit breaker
            var instances = await _circuitBreaker.ExecuteAsync(async () =>
            {
                var discovered = await _primary.DiscoverServiceAsync(serviceName);
                
                // Update cache on success
                await _cache.SetStringAsync(
                    cacheKey,
                    JsonSerializer.Serialize(discovered),
                    new DistributedCacheEntryOptions
                    {
                        AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5)
                    });
                
                return discovered;
            });
            
            return instances;
        }
        catch (CircuitBreakerOpenException)
        {
            _logger.LogWarning("Circuit breaker open, using cached service data");
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Service discovery failed, attempting cache fallback");
        }
        
        // Fallback to cache
        var cached = await _cache.GetStringAsync(cacheKey);
        if (cached != null)
        {
            return JsonSerializer.Deserialize<List<ServiceInstance>>(cached);
        }
        
        throw new ServiceDiscoveryException($"Could not discover service {serviceName}");
    }
}
```

### Multi-Region Service Discovery

```csharp
public class MultiRegionServiceDiscovery : IServiceDiscovery
{
    private readonly Dictionary<string, IServiceDiscovery> _regionalDiscoveries;
    private readonly string _currentRegion;
    
    public async Task<List<ServiceInstance>> DiscoverServiceAsync(
        string serviceName,
        bool includeRemoteRegions = false)
    {
        var instances = new List<ServiceInstance>();
        
        // Always include local region
        var localInstances = await _regionalDiscoveries[_currentRegion]
            .DiscoverServiceAsync(serviceName);
        instances.AddRange(localInstances);
        
        if (includeRemoteRegions && localInstances.Count < 2)
        {
            // Only query remote regions if local region has few instances
            foreach (var (region, discovery) in _regionalDiscoveries)
            {
                if (region == _currentRegion) continue;
                
                try
                {
                    var remoteInstances = await discovery.DiscoverServiceAsync(serviceName);
                    // Mark as remote for preference scoring
                    remoteInstances.ForEach(i => i.Region = region);
                    instances.AddRange(remoteInstances);
                }
                catch (Exception ex)
                {
                    _logger.LogWarning(ex, "Failed to discover from region {Region}", region);
                }
            }
        }
        
        return instances;
    }
}
```

## Monitoring and Observability

### Service Registry Metrics

```csharp
public class ObservableServiceRegistry : IServiceRegistry
{
    private readonly IServiceRegistry _inner;
    private readonly Counter<long> _registrationCounter;
    private readonly Counter<long> _discoveryCounter;
    private readonly Histogram<double> _discoveryLatency;
    
    public ObservableServiceRegistry(IServiceRegistry inner, IMeterFactory meterFactory)
    {
        _inner = inner;
        var meter = meterFactory.Create("ServiceRegistry");
        
        _registrationCounter = meter.CreateCounter<long>(
            "service.registrations",
            description: "Number of service registrations");
        
        _discoveryCounter = meter.CreateCounter<long>(
            "service.discoveries",
            description: "Number of service discovery operations");
        
        _discoveryLatency = meter.CreateHistogram<double>(
            "service.discovery.latency_ms",
            unit: "ms",
            description: "Service discovery latency");
    }
    
    public async Task RegisterAsync(ServiceRegistration registration)
    {
        await _inner.RegisterAsync(registration);
        
        _registrationCounter.Add(1,
            new KeyValuePair<string, object>("service", registration.ServiceName),
            new KeyValuePair<string, object>("action", "register"));
    }
    
    public async Task<List<ServiceInstance>> DiscoverAsync(string serviceName)
    {
        var sw = Stopwatch.StartNew();
        try
        {
            var instances = await _inner.DiscoverAsync(serviceName);
            
            _discoveryCounter.Add(1,
                new KeyValuePair<string, object>("service", serviceName),
                new KeyValuePair<string, object>("status", "success"));
            
            _discoveryLatency.Record(sw.Elapsed.TotalMilliseconds,
                new KeyValuePair<string, object>("service", serviceName));
            
            return instances;
        }
        catch (Exception)
        {
            _discoveryCounter.Add(1,
                new KeyValuePair<string, object>("service", serviceName),
                new KeyValuePair<string, object>("status", "failure"));
            throw;
        }
    }
}
```

## Testing Service Discovery

```csharp
public class ServiceDiscoveryTests
{
    [Fact]
    public async Task ServiceRegistration_Succeeds()
    {
        // Arrange
        var registry = new InMemoryServiceRegistry();
        var registration = new ServiceRegistration
        {
            ServiceName = "test-service",
            InstanceId = "test-1",
            Host = "127.0.0.1",
            Port = 8080
        };
        
        // Act
        await registry.RegisterAsync(registration);
        var instances = await registry.DiscoverAsync("test-service");
        
        // Assert
        Assert.Single(instances);
        Assert.Equal("test-1", instances[0].Id);
    }
    
    [Fact]
    public async Task ServiceDiscovery_ReturnsHealthyInstancesOnly()
    {
        // Arrange
        var registry = new InMemoryServiceRegistry();
        await registry.RegisterAsync(new ServiceRegistration
        {
            ServiceName = "test-service",
            InstanceId = "healthy-1",
            Host = "127.0.0.1",
            Port = 8080
        });
        await registry.RegisterAsync(new ServiceRegistration
        {
            ServiceName = "test-service",
            InstanceId = "unhealthy-1",
            Host = "127.0.0.2",
            Port = 8080
        });
        
        // Mark one unhealthy
        await registry.MarkUnhealthyAsync("unhealthy-1");
        
        // Act
        var instances = await registry.DiscoverAsync("test-service", healthyOnly: true);
        
        // Assert
        Assert.Single(instances);
        Assert.Equal("healthy-1", instances[0].Id);
    }
}
```

## Key Takeaways

✅ Service discovery provides dynamic, real-time service location information

✅ Self-registration gives services control; third-party registration reduces complexity

✅ Service registries must be highly available (clustered)

✅ Caching service locations reduces registry load and improves resilience

✅ Health checking ensures only healthy instances receive traffic

✅ Choose registry based on infrastructure (Kubernetes→K8s Services, Multi-platform→Consul)

✅ Monitor service discovery performance and availability
