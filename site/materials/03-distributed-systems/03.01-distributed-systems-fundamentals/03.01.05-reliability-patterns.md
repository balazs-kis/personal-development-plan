One of the most pervasive myths in distributed systems is "exactly-once delivery." Marketers claim it, developers desire it, but it's fundamentally impossible to guarantee. ## Why Exactly-Once is Impossible

### The Two-Phase Problem

To achieve "exactly-once," you need to atomically:
1. Receive/acknowledge a message
2. Process the message
3. Produce any outputs

If any step fails, you must retry, but retries can cause duplicates.

### The FLP Impossibility Result

In an asynchronous system with even one faulty process, you cannot reliably determine if an operation succeeded:
- Request sent → timeout → did it complete or not?
- If you retry → might execute twice
- If you don't retry → might execute zero times

**Fundamental Truth:** You can't distinguish between a slow process and a dead process.

```csharp
// The uncertainty problem
public async Task<Result> ProcessPaymentAsync(Payment payment)
{
    try
    {
        // Send request to payment processor
        var response = await _paymentGateway.ChargeAsync(payment);
        return Result.Success();
    }
    catch (TimeoutException)
    {
        // Did the charge go through or not?
        // - If we retry → might charge twice
        // - If we don't retry → might not charge at all
        // - We can't know for certain!
        
        throw new UncertaintyException(
            "Payment status unknown - requires manual verification");
    }
}
```

## Delivery Semantics

### 1. At-Most-Once Delivery

**Guarantee:** Message delivered zero or one times (never duplicated)

**Implementation:** Send message, don't retry on failure

**Use Cases:**
- Metrics/monitoring (loss acceptable, duplicates problematic)
- Telemetry data
- Non-critical notifications

```csharp
public class AtMostOncePublisher
{
    private readonly IMessageBroker _broker;
    
    public async Task PublishAsync(Event evt)
    {
        try
        {
            // Send once, no retries
            await _broker.SendAsync(evt, 
                retryPolicy: RetryPolicy.NoRetry);
        }
        catch (Exception ex)
        {
            // Log and move on - accept message loss
            _logger.LogWarning(ex, 
                "Failed to publish event {EventId}, not retrying", 
                evt.Id);
        }
    }
}
```

### 2. At-Least-Once Delivery

**Guarantee:** Message delivered one or more times (might duplicate)

**Implementation:** Retry until acknowledged

**Use Cases:**
- Most reliable message delivery
- Paired with idempotent processing

```csharp
public class AtLeastOncePublisher
{
    private readonly IMessageBroker _broker;
    private readonly IAsyncPolicy _retryPolicy;
    
    public AtLeastOncePublisher(IMessageBroker broker)
    {
        _broker = broker;
        _retryPolicy = Policy
            .Handle<Exception>()
            .WaitAndRetryForeverAsync(
                retryAttempt => TimeSpan.FromSeconds(Math.Min(
                    Math.Pow(2, retryAttempt), 
                    60)));
    }
    
    public async Task PublishAsync(Event evt)
    {
        await _retryPolicy.ExecuteAsync(async () =>
        {
            await _broker.SendAsync(evt);
            _logger.LogInformation(
                "Successfully published event {EventId}", 
                evt.Id);
        });
    }
}
```

### 3. "Exactly-Once" (Really: Effectively-Once)

**Reality:** At-least-once delivery + idempotent processing = effectively-once

**Guarantee:** Even if message is delivered multiple times, effect happens once

```csharp
public class EffectivelyOnceProcessor
{
    private readonly IDeduplicationStore _dedup;
    
    public async Task ProcessAsync(Event evt)
    {
        // Check if already processed
        if (await _dedup.HasBeenProcessedAsync(evt.IdempotencyKey))
        {
            _logger.LogInformation(
                "Event {Key} already processed, skipping", 
                evt.IdempotencyKey);
            return;
        }
        
        // Process idempotently
        await ProcessEventIdempotentlyAsync(evt);
        
        // Mark as processed
        await _dedup.MarkAsProcessedAsync(evt.IdempotencyKey);
    }
}
```

## Idempotency: The Key to Reliability

### What is Idempotency?

An operation is idempotent if performing it multiple times has the same effect as performing it once.

**Examples:**
- ✅ Idempotent: SET x = 5 (repeating doesn't change result)
- ✅ Idempotent: DELETE user WHERE id = 123
- ❌ Not idempotent: INCREMENT x (result changes each time)
- ❌ Not idempotent: ADD $100 to account

### Making Operations Idempotent

#### 1. Natural Idempotency

Some operations are naturally idempotent:

```csharp
// Naturally idempotent: set operations
public async Task UpdateUserEmailAsync(string userId, string newEmail)
{
    var user = await _dbContext.Users.FindAsync(userId);
    user.Email = newEmail; // Setting - repeatable
    await _dbContext.SaveChangesAsync();
}
```

#### 2. Idempotency Keys

For non-idempotent operations, use unique identifiers:

```csharp
public class Payment
{
    public string IdempotencyKey { get; set; } // Client-provided unique ID
    public string AccountId { get; set; }
    public decimal Amount { get; set; }
}

public class PaymentProcessor
{
    private readonly IPaymentStore _store;
    
    public async Task<PaymentResult> ProcessPaymentAsync(Payment payment)
    {
        // Check if payment with this idempotency key already processed
        var existing = await _store.GetByIdempotencyKeyAsync(
            payment.IdempotencyKey);
        
        if (existing != null)
        {
            // Already processed - return previous result
            return new PaymentResult
            {
                PaymentId = existing.Id,
                Status = existing.Status,
                Message = "Payment already processed",
                IsIdempotentRetry = true
            };
        }
        
        // Process payment in transaction
        using var transaction = await _dbContext.Database
            .BeginTransactionAsync(IsolationLevel.Serializable);
        
        try
        {
            // Charge account
            var account = await _dbContext.Accounts
                .FindAsync(payment.AccountId);
            
            if (account.Balance < payment.Amount)
            {
                throw new InsufficientFundsException();
            }
            
            account.Balance -= payment.Amount;
            
            // Store payment record with idempotency key
            var paymentRecord = new PaymentRecord
            {
                Id = Guid.NewGuid().ToString(),
                IdempotencyKey = payment.IdempotencyKey,
                AccountId = payment.AccountId,
                Amount = payment.Amount,
                Status = PaymentStatus.Completed,
                ProcessedAt = DateTime.UtcNow
            };
            
            await _store.AddAsync(paymentRecord);
            await _dbContext.SaveChangesAsync();
            await transaction.CommitAsync();
            
            return new PaymentResult
            {
                PaymentId = paymentRecord.Id,
                Status = paymentRecord.Status,
                Message = "Payment processed successfully"
            };
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}
```

public class ConditionalUpdater
{
    public async Task<bool> UpdateInventoryAsync(
        string productId, 
        int expectedVersion,
        int quantityChange)
    {
        // Only update if version matches (optimistic locking)
        var rowsAffected = await _dbContext.Database
            .ExecuteSqlInterpolatedAsync($@"
                UPDATE Products 
                SET Quantity = Quantity + {quantityChange},
                    Version = Version + 1
                WHERE ProductId = {productId} 
                AND Version = {expectedVersion}
            ");
        
        if (rowsAffected == 0)
        {
            // Version mismatch - someone else updated it
            return false;
        }
        
        return true;
    }
}

## Deduplication Strategies

Deduplication prevents duplicate processing of messages that are delivered multiple times. This is critical when implementing at-least-once delivery.

### 1. In-Memory Deduplication (Recent Window)

Suitable for high-throughput scenarios where recent history is sufficient.

**Pros:**
- Fast lookups (O(1))
- Low latency
- No external dependencies

**Cons:**
- Limited to recent window
- Lost on restart
- Memory constrained

```csharp
public class RecentMessageDeduplicator
{
    private readonly ConcurrentDictionary<string, DateTime> _processedMessages;
    private readonly TimeSpan _retentionPeriod = TimeSpan.FromMinutes(10);
    private readonly ILogger _logger;
    
    public RecentMessageDeduplicator(ILogger<RecentMessageDeduplicator> logger)
    {
        _processedMessages = new ConcurrentDictionary<string, DateTime>();
        _logger = logger;
        
        // Periodically clean up old entries
        Task.Run(async () => await CleanupOldEntriesAsync());
    }
    
    public bool IsMessageProcessed(string messageId)
    {
        return _processedMessages.ContainsKey(messageId);
    }
    
    public bool TryMarkAsProcessed(string messageId)
    {
        var added = _processedMessages.TryAdd(messageId, DateTime.UtcNow);
        
        if (!added)
        {
            _logger.LogInformation(
                "Message {MessageId} already processed (duplicate detected)",
                messageId);
        }
        
        return added;
    }
    
    private async Task CleanupOldEntriesAsync()
    {
        while (true)
        {
            await Task.Delay(TimeSpan.FromMinutes(1));
            
            var cutoff = DateTime.UtcNow - _retentionPeriod;
            var oldKeys = _processedMessages
                .Where(kvp => kvp.Value < cutoff)
                .Select(kvp => kvp.Key)
                .ToList();
            
            foreach (var key in oldKeys)
            {
                _processedMessages.TryRemove(key, out _);
            }
            
            if (oldKeys.Any())
            {
                _logger.LogDebug(
                    "Cleaned up {Count} old deduplication entries",
                    oldKeys.Count);
            }
        }
    }
    
    public int GetTrackedMessageCount() => _processedMessages.Count;
}

// Usage in message processor
public class MessageProcessor
{
    private readonly RecentMessageDeduplicator _deduplicator;
    
    public async Task ProcessMessageAsync(Message message)
    {
        // Check and mark as processed atomically
        if (!_deduplicator.TryMarkAsProcessed(message.Id))
        {
            _logger.LogInformation(
                "Skipping duplicate message {MessageId}",
                message.Id);
            return;
        }
        
        // Process message
        await ProcessMessageInternalAsync(message);
    }
}
```

### 2. Persistent Deduplication Store

For longer retention periods or when restart durability is required.

**Pros:**
- Survives restarts
- Longer retention windows
- Can store processing results for immediate return

**Cons:**
- Higher latency (database access)
- Additional infrastructure dependency
- Requires database maintenance

```csharp
public class PersistentDeduplicationStore
{
    private readonly DbContext _dbContext;
    private readonly IDistributedCache _cache;
    private readonly ILogger _logger;
    
    public async Task<bool> HasBeenProcessedAsync(string idempotencyKey)
    {
        // Check cache first (fast path)
        var cached = await _cache.GetStringAsync($"dedup:{idempotencyKey}");
        if (cached != null)
        {
            _logger.LogDebug(
                "Deduplication cache hit for {Key}",
                idempotencyKey);
            return true;
        }
        
        // Check database (slower path)
        var exists = await _dbContext.ProcessedMessages
            .AnyAsync(m => m.IdempotencyKey == idempotencyKey);
        
        if (exists)
        {
            // Cache for fast lookup next time
            await _cache.SetStringAsync(
                $"dedup:{idempotencyKey}", 
                "processed",
                new DistributedCacheEntryOptions
                {
                    AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(24)
                });
            
            _logger.LogDebug(
                "Deduplication database hit for {Key}, cached for future",
                idempotencyKey);
        }
        
        return exists;
    }
    
    public async Task<T> GetResultAsync<T>(string idempotencyKey)
    {
        // Try cache first
        var cachedResult = await _cache.GetStringAsync($"result:{idempotencyKey}");
        if (cachedResult != null)
        {
            return JsonSerializer.Deserialize<T>(cachedResult);
        }
        
        // Fall back to database
        var record = await _dbContext.ProcessedMessages
            .FirstOrDefaultAsync(m => m.IdempotencyKey == idempotencyKey);
        
        if (record?.Result != null)
        {
            var result = JsonSerializer.Deserialize<T>(record.Result);
            
            // Cache it
            await _cache.SetStringAsync(
                $"result:{idempotencyKey}",
                record.Result,
                new DistributedCacheEntryOptions
                {
                    AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(24)
                });
            
            return result;
        }
        
        return default;
    }
    
    public async Task MarkAsProcessedAsync(
        string idempotencyKey, 
        object result = null,
        Dictionary<string, string> metadata = null)
    {
        var record = new ProcessedMessage
        {
            IdempotencyKey = idempotencyKey,
            ProcessedAt = DateTime.UtcNow,
            Result = result != null ? JsonSerializer.Serialize(result) : null,
            Metadata = metadata != null ? JsonSerializer.Serialize(metadata) : null
        };
        
        try
        {
            await _dbContext.ProcessedMessages.AddAsync(record);
            await _dbContext.SaveChangesAsync();
            
            // Cache both the dedup flag and result
            await _cache.SetStringAsync(
                $"dedup:{idempotencyKey}", 
                "processed",
                new DistributedCacheEntryOptions
                {
                    AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(24)
                });
            
            if (result != null)
            {
                await _cache.SetStringAsync(
                    $"result:{idempotencyKey}",
                    JsonSerializer.Serialize(result),
                    new DistributedCacheEntryOptions
                    {
                        AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(24)
                    });
            }
            
            _logger.LogInformation(
                "Marked {Key} as processed",
                idempotencyKey);
        }
        catch (DbUpdateException ex) when (IsDuplicateKeyException(ex))
        {
            // Another process already marked it—this is fine
            _logger.LogDebug(
                "Idempotency key {Key} already exists (concurrent processing)",
                idempotencyKey);
        }
    }
    
    private bool IsDuplicateKeyException(DbUpdateException ex)
    {
        // Check for unique constraint violation
        return ex.InnerException?.Message.Contains("duplicate key") ?? false;
    }
}

// Database model
public class ProcessedMessage
{
    [Key]
    public string IdempotencyKey { get; set; }
    
    public DateTime ProcessedAt { get; set; }
    
    public string Result { get; set; }
    
    public string Metadata { get; set; }
    
    // Index for cleanup
    [Index]
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
}
```

### 3. Bloom Filter for Space-Efficient Deduplication

When you need to track millions of messages but can tolerate rare false positives.

**Pros:**
- Extremely space-efficient
- Fast lookups
- No false negatives

**Cons:**
- Allows false positives (configurable rate)
- Cannot remove items
- Requires backup mechanism for confirmed duplicates

```csharp
public class BloomFilterDeduplicator
{
    private readonly BloomFilter<string> _bloomFilter;
    private readonly PersistentDeduplicationStore _persistentStore;
    private readonly ILogger _logger;
    
    public BloomFilterDeduplicator(
        int expectedItemCount,
        double falsePositiveRate,
        PersistentDeduplicationStore persistentStore,
        ILogger<BloomFilterDeduplicator> logger)
    {
        _bloomFilter = new BloomFilter<string>(expectedItemCount, falsePositiveRate);
        _persistentStore = persistentStore;
        _logger = logger;
    }
    
    public async Task<bool> IsMessageProcessedAsync(string messageId)
    {
        // Quick check with Bloom filter
        if (!_bloomFilter.Contains(messageId))
        {
            // Definitely not processed (no false negatives)
            return false;
        }
        
        // Possible match—verify with persistent store
        _logger.LogDebug(
            "Bloom filter possible match for {MessageId}, verifying",
            messageId);
        
        return await _persistentStore.HasBeenProcessedAsync(messageId);
    }
    
    public async Task MarkAsProcessedAsync(string messageId, object result = null)
    {
        // Add to Bloom filter
        _bloomFilter.Add(messageId);
        
        // Store persistently
        await _persistentStore.MarkAsProcessedAsync(messageId, result);
    }
}

// Simple Bloom filter implementation
public class BloomFilter<T>
{
    private readonly BitArray _bits;
    private readonly int _hashFunctionCount;
    
    public BloomFilter(int expectedItemCount, double falsePositiveRate)
    {
        // Calculate optimal bit array size
        var m = Math.Ceiling(
            -expectedItemCount * Math.Log(falsePositiveRate) / Math.Pow(Math.Log(2), 2));
        
        // Calculate optimal hash function count
        _hashFunctionCount = (int)Math.Ceiling(m / expectedItemCount * Math.Log(2));
        
        _bits = new BitArray((int)m);
    }
    
    public void Add(T item)
    {
        foreach (var hash in GetHashes(item))
        {
            _bits[hash] = true;
        }
    }
    
    public bool Contains(T item)
    {
        return GetHashes(item).All(hash => _bits[hash]);
    }
    
    private IEnumerable<int> GetHashes(T item)
    {
        var hash1 = item.GetHashCode();
        var hash2 = hash1.GetHashCode();
        
        for (int i = 0; i < _hashFunctionCount; i++)
        {
            var combinedHash = hash1 + i * hash2;
            var index = Math.Abs(combinedHash % _bits.Length);
            yield return index;
        }
    }
}
```

### 4. Time-Window Deduplication with Sliding Window

Track recent messages with automatic expiration.

```csharp
public class SlidingWindowDeduplicator
{
    private readonly SortedSet<MessageEntry> _messageWindow = new();
    private readonly HashSet<string> _messageIds = new();
    private readonly TimeSpan _windowSize;
    private readonly object _lock = new object();
    private readonly ILogger _logger;
    
    public SlidingWindowDeduplicator(TimeSpan windowSize, ILogger<SlidingWindowDeduplicator> logger)
    {
        _windowSize = windowSize;
        _logger = logger;
        
        // Periodically clean up expired entries
        Task.Run(async () => await CleanupExpiredEntriesAsync());
    }
    
    public bool TryMarkAsProcessed(string messageId)
    {
        lock (_lock)
        {
            if (_messageIds.Contains(messageId))
            {
                _logger.LogInformation(
                    "Duplicate message detected: {MessageId}",
                    messageId);
                return false;
            }
            
            var entry = new MessageEntry
            {
                MessageId = messageId,
                Timestamp = DateTime.UtcNow
            };
            
            _messageWindow.Add(entry);
            _messageIds.Add(messageId);
            
            return true;
        }
    }
    
    private async Task CleanupExpiredEntriesAsync()
    {
        while (true)
        {
            await Task.Delay(TimeSpan.FromSeconds(10));
            
            lock (_lock)
            {
                var cutoff = DateTime.UtcNow - _windowSize;
                var expiredEntries = _messageWindow
                    .Where(e => e.Timestamp < cutoff)
                    .ToList();
                
                foreach (var entry in expiredEntries)
                {
                    _messageWindow.Remove(entry);
                    _messageIds.Remove(entry.MessageId);
                }
                
                if (expiredEntries.Any())
                {
                    _logger.LogDebug(
                        "Removed {Count} expired entries from deduplication window",
                        expiredEntries.Count);
                }
            }
        }
    }
    
    private class MessageEntry : IComparable<MessageEntry>
    {
        public string MessageId { get; init; }
        public DateTime Timestamp { get; init; }
        
        public int CompareTo(MessageEntry other)
        {
            var timeComparison = Timestamp.CompareTo(other.Timestamp);
            if (timeComparison != 0)
                return timeComparison;
            
            // Break ties with message ID
            return string.Compare(MessageId, other.MessageId, StringComparison.Ordinal);
        }
    }
}
```

## Practical Implementation: Idempotent API

```csharp
[ApiController]
[Route("api/[controller]")]
public class OrdersController : ControllerBase
{
    private readonly IOrderService _orderService;
    private readonly IDeduplicationStore _dedup;
    
    [HttpPost]
    public async Task<ActionResult<OrderResult>> CreateOrder(
        [FromBody] CreateOrderRequest request,
        [FromHeader(Name = "Idempotency-Key")] string idempotencyKey)
    {
        if (string.IsNullOrEmpty(idempotencyKey))
        {
            return BadRequest("Idempotency-Key header required");
        }
        
        // Check if already processed
        if (await _dedup.HasBeenProcessedAsync(idempotencyKey))
        {
            var cachedResult = await _dedup
                .GetResultAsync<OrderResult>(idempotencyKey);
            
            return Ok(cachedResult); // Return cached result
        }
        
        // Process order
        var result = await _orderService.CreateOrderAsync(request);
        
        // Store result with idempotency key
        await _dedup.MarkAsProcessedAsync(idempotencyKey, result);
        
        return Ok(result);
    }
}
```

## Key Takeaways

- Exactly-once delivery is impossible in distributed systems; it's always at-least-once or at-most-once
- "Exactly-once" in practice means at-least-once delivery + idempotent processing
- Idempotency allows operations to be safely retried
- Idempotency keys are essential for making non-idempotent operations idempotent
- Deduplication can be implemented with caching or persistent stores
- Designing for retries from the start leads to more robust systems
- Most production systems use at-least-once delivery with idempotent consumers
