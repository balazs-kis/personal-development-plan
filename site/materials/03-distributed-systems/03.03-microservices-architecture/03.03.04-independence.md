# Lesson 4: Independent Deployability and Polyglot Persistence

## Learning Objectives

By the end of this lesson, you will be able to:
- Implement truly independent deployability for services
- Choose appropriate databases for different service needs (polyglot persistence)
- Handle database schema evolution in microservices
- Implement database-per-service pattern correctly
- Avoid common pitfalls in data management

---

## Introduction

Two of the key benefits of microservices are independent deployability (teams can deploy without coordinating) and polyglot persistence (using the right database for each job). This lesson explores how to achieve these benefits while managing the complexity they introduce.

## Independent Deployability

### The Goal

Deploy a service without requiring other services to deploy simultaneously.

```csharp
// ✅ GOOD: Independent deployment
public class OrderServiceV2
{
    // New version deployed independently
    // Other services unaffected
    [HttpPost("orders")]
    public async Task<IActionResult> CreateOrder(CreateOrderRequest request)
    {
        // New functionality added
        var order = await _orderProcessor.ProcessOrderAsync(request);
        
        // Backward compatible with v1 clients
        return Ok(order);
    }
}

// ❌ BAD: Coordinated deployment required
public class TightlyCoupled
{
    // OrderService and InventoryService must deploy together
    // because they share a database table structure
    // Breaks independent deployability!
}
```

### Principles for Independent Deployment

#### 1. Backward Compatibility

```csharp
// API versions must be backward compatible

// V1: Original API
public class OrderV1
{
    public string Id { get; set; }
    public string Status { get; set; }
}

// V2: Add field (backward compatible)
public class OrderV2
{
    public string Id { get; set; }
    public string Status { get; set; }
    public DateTime? EstimatedDelivery { get; set; } // Optional new field
}

// V1 clients still work with V2 API!

// ❌ BAD: Breaking change
public class OrderV2Breaking
{
    public string OrderId { get; set; } // Renamed from "Id"
    public OrderStatus Status { get; set; } // Changed from string to enum
    // V1 clients break!
}
```

#### 3. Blue-Green Deployments

```csharp
// Deploy new version alongside old

public class BlueGreenDeployment
{
    public async Task DeployAsync()
    {
        // Green (new version) deployed
        await DeployNewVersionAsync("green");
        
        // Blue (old version) still running
        // Route 10% traffic to green
        await UpdateLoadBalancer(blueWeight: 90, greenWeight: 10);
        
        // Monitor for errors
        await Task.Delay(TimeSpan.FromMinutes(10));
        
        if (await IsHealthy("green"))
        {
            // Gradually shift traffic
            await UpdateLoadBalancer(blueWeight: 50, greenWeight: 50);
            await Task.Delay(TimeSpan.FromMinutes(5));
            
            await UpdateLoadBalancer(blueWeight: 0, greenWeight: 100);
            
            // Old version can be removed
            await RemoveOldVersionAsync("blue");
        }
        else
        {
            // Rollback instantly
            await UpdateLoadBalancer(blueWeight: 100, greenWeight: 0);
            await RemoveOldVersionAsync("green");
        }
    }
}
```

## Polyglot Persistence

### Choosing the Right Database

```csharp
// Different services, different database needs

// Product Catalog Service - MongoDB
public class ProductCatalogService
{
    private readonly IMongoCollection<Product> _products;
    
    // Why MongoDB?
    // - Flexible schema (products have varying attributes)
    // - Fast reads for catalog browsing
    // - Full-text search built-in
    
    public async Task<List<Product>> SearchAsync(string query)
    {
        return await _products
            .Find(p => p.Name.Contains(query))
            .ToListAsync();
    }
}

// Order Service - SQL Server
public class OrderService
{
    private readonly SqlConnection _connection;
    
    // Why SQL Server?
    // - ACID transactions for order processing
    // - Strong consistency required
    // - Complex joins for order history
    
    public async Task CreateOrderAsync(Order order)
    {
        using var transaction = await _connection.BeginTransactionAsync();
        
        await SaveOrderAsync(order, transaction);
        await SaveOrderLinesAsync(order.Lines, transaction);
        await transaction.CommitAsync();
    }
}

// Recommendation Service - Redis + Python/TensorFlow
public class RecommendationService
{
    private readonly IConnectionMultiplexer _redis;
    
    // Why Redis?
    // - Fast in-memory cache for recommendations
    // - ML model results cached here
    
    public async Task<List<Product>> GetRecommendationsAsync(string userId)
    {
        var cached = await _redis.GetDatabase()
            .StringGetAsync($"recommendations:{userId}");
        
        if (cached.HasValue)
        {
            return JsonSerializer.Deserialize<List<Product>>(cached);
        }
        
        // Generate recommendations with ML model
        var recommendations = await GenerateWithMLAsync(userId);
        
        // Cache for 1 hour
        await _redis.GetDatabase().StringSetAsync(
            $"recommendations:{userId}",
            JsonSerializer.Serialize(recommendations),
            TimeSpan.FromHours(1));
        
        return recommendations;
    }
}

// Analytics Service - Azure Data Lake / Parquet
public class AnalyticsService
{
    // Why Data Lake?
    // - Store massive amounts of events
    // - Column-oriented for analytics queries
    // - Cost-effective for historical data
    
    public async Task StoreEventAsync(AnalyticsEvent evt)
    {
        await _dataLakeClient.AppendAsync(
            $"/events/{evt.Date:yyyy/MM/dd}/events.parquet",
            SerializeToParquet(evt));
    }
}
```

### Database Per Service Pattern

```csharp
// Each service owns its database

// ✅ GOOD: Database per service
public class OrderService
{
    // OrderService Database:
    // - Orders table
    // - OrderLines table
    // - OrderStatus table
    // No other service accesses these tables!
    
    private readonly OrderDbContext _db;
    
    public async Task<Order> GetOrderAsync(string id)
    {
        return await _db.Orders
            .Include(o => o.Lines)
            .FirstOrDefaultAsync(o => o.Id == id);
    }
}

public class ShippingService
{
    // ShippingService Database:
    // - Shipments table
    // - TrackingEvents table
    // Separate database!
    
    private readonly ShippingDbContext _db;
    
    // Gets order info via API, not database
    public async Task CreateShipmentAsync(string orderId)
    {
        // Call OrderService API
        var order = await _orderClient.GetOrderAsync(orderId);
        
        // Create shipment in own database
        var shipment = new Shipment
        {
            OrderId = orderId,
            Address = order.ShippingAddress
        };
        
        await _db.Shipments.AddAsync(shipment);
        await _db.SaveChangesAsync();
    }
}

// ❌ BAD: Shared database
public class SharedDatabase
{
    // OrderService reads/writes Orders table
    // ShippingService reads Orders table directly
    // Tight coupling through database!
}
```

## Managing Data Across Services

### 1. Data Duplication / Denormalization

```csharp
// Duplicate data to avoid cross-service queries

public class OrderService
{
    public class Order
    {
        public string Id { get; set; }
        
        // Denormalized customer data
        public string CustomerId { get; set; }
        public string CustomerName { get; set; } // Snapshot from CustomerService
        public string CustomerEmail { get; set; } // Snapshot from CustomerService
        
        // Denormalized product data
        public List<OrderLine> Lines { get; set; }
    }
    
    public class OrderLine
    {
        public string ProductId { get; set; }
        public string ProductName { get; set; } // Snapshot from ProductService
        public decimal PriceAtOrderTime { get; set; } // Price at time of order
        public int Quantity { get; set; }
    }
    
    // Keep denormalized data updated via events
    public async Task HandleCustomerNameChangedAsync(CustomerNameChangedEvent evt)
    {
        await _db.Orders
            .Where(o => o.CustomerId == evt.CustomerId)
            .ForEachAsync(o => o.CustomerName = evt.NewName);
        
        await _db.SaveChangesAsync();
    }
}
```

### 2. Event-Driven Synchronization

```csharp
// Keep data in sync via domain events

// ProductService publishes events
public class ProductService
{
    public async Task UpdateProductNameAsync(string productId, string newName)
    {
        var product = await _db.Products.FindAsync(productId);
        product.Name = newName;
        
        await _db.SaveChangesAsync();
        
        // Publish event
        await _eventBus.PublishAsync(new ProductNameChangedEvent
        {
            ProductId = productId,
            NewName = newName
        });
    }
}

// OrderService subscribes to events
public class OrderService
{
    public async Task HandleProductNameChangedAsync(ProductNameChangedEvent evt)
    {
        // Update denormalized product names in historical orders
        var orders = await _db.Orders
            .Where(o => o.Lines.Any(l => l.ProductId == evt.ProductId))
            .ToListAsync();
        
        foreach (var order in orders)
        {
            foreach (var line in order.Lines.Where(l => l.ProductId == evt.ProductId))
            {
                line.ProductName = evt.NewName;
            }
        }
        
        await _db.SaveChangesAsync();
    }
}
```

### 3. API Composition

```csharp
// Compose data from multiple services at read time

public class OrderDetailsService
{
    public async Task<OrderDetailsView> GetOrderDetailsAsync(string orderId)
```

## Schema Evolution

### Expand-Contract Pattern

```csharp
// Safe database schema changes

// Phase 1: EXPAND - Add new column
public class Phase1Migration : Migration
{
    protected override void Up(MigrationBuilder builder)
    {
        // Add new column (nullable)
        builder.AddColumn<string>(
            name: "ShippingAddressJson",
            table: "Orders",
            nullable: true);
        
        // Start writing to both old and new columns
    }
}

// Phase 2: MIGRATE - Copy data
public class Phase2DataMigration
{
    public async Task MigrateDataAsync()
    {
        // Copy data from old columns to new
        var orders = await _db.Orders
            .Where(o => o.ShippingAddressJson == null)
            .ToListAsync();
        
        foreach (var order in orders)
        {
            order.ShippingAddressJson = JsonSerializer.Serialize(new
            {
                order.ShippingStreet,
                order.ShippingCity,
                order.ShippingZip
            });
        }
        
        await _db.SaveChangesAsync();
    }
}

// Phase 3: CONTRACT - Remove old columns
public class Phase3Migration : Migration
{
    protected override void Up(MigrationBuilder builder)
    {
        // Remove old columns (after all services updated)
        builder.DropColumn(name: "ShippingStreet", table: "Orders");
        builder.DropColumn(name: "ShippingCity", table: "Orders");
        builder.DropColumn(name: "ShippingZip", table: "Orders");
    }
}

// Deploy across 3 releases:
// Release 1: Add new column, write to both
// Release 2: Migrate data, read from new column
// Release 3: Remove old columns
```

## Advanced Deployment Strategies

### Canary Deployments

```csharp
// Gradually roll out to subset of users

public class CanaryDeployment
{
    public async Task DeployNewVersionAsync()
    {
        // Deploy canary (v2) alongside stable (v1)
        await DeployCanaryAsync("order-service-v2", replicas: 1);
        await Task.Delay(TimeSpan.FromMinutes(5)); // Warm up
        
        // Route 5% of traffic to canary
        await UpdateRoutingRulesAsync(new RoutingRule
        {
            Canary = new CanaryConfig
            {
                ServiceName = "order-service-v2",
                Weight = 5 // 5% traffic
            },
            Stable = new StableConfig
            {
                ServiceName = "order-service-v1",
                Weight = 95 // 95% traffic
            }
        });
        
        // Monitor canary metrics
        var canaryMetrics = await MonitorCanaryAsync(TimeSpan.FromMinutes(15));
        
        if (canaryMetrics.ErrorRate < 0.01 && canaryMetrics.Latency < 200)
        {
            // Canary healthy, increase traffic gradually
            await UpdateWeight(canary: 25, stable: 75);
            await Task.Delay(TimeSpan.FromMinutes(15));
            
            await UpdateWeight(canary: 50, stable: 50);
            await Task.Delay(TimeSpan.FromMinutes(15));
            
            await UpdateWeight(canary: 100, stable: 0);
            
            // Remove old version
            await RemoveServiceAsync("order-service-v1");
        }
        else
        {
            // Canary unhealthy, rollback immediately
            await UpdateWeight(canary: 0, stable: 100);
            await RemoveServiceAsync("order-service-v2");
            await AlertTeamAsync("Canary deployment failed");
        }
    }
}
```

### Feature Flags for Deployment

```csharp
// Decouple deployment from release

public class FeatureFlagDeployment
{
    // Deploy new code behind feature flag
    [HttpPost("orders")]
    public async Task<IActionResult> CreateOrder(CreateOrderRequest request)
    {
        // New code deployed but not active
        if (await _featureFlags.IsEnabledAsync("use_new_order_validation"))
        {
            // New validation logic (v2)
            return await CreateOrderWithNewValidationAsync(request);
        }
        else
        {
            // Old validation logic (v1)
            return await CreateOrderWithOldValidationAsync(request);
        }
    }
    
    // Rollout process:
    // 1. Deploy code with flag OFF
    // 2. Turn on for internal users (5%)
    // 3. Turn on for beta users (10%)
    // 4. Turn on for region A (25%)
    // 5. Turn on for all users (100%)
    // 6. Remove flag and old code
    
    // Can rollback instantly by toggling flag!
}

// Advanced: User-targeted flags
public class TargetedFeatureFlags
{
    public async Task<bool> IsNewOrderFlowEnabledAsync(string userId)
    {
        // Enable for specific users
        if (await _featureFlags.IsUserInGroupAsync(userId, "early_adopters"))
            return true;
        
        // Enable based on percentage
        if (await _featureFlags.IsUserInPercentileAsync(userId, 10))
            return true;
        
        // Enable based on attributes
        var user = await _userService.GetUserAsync(userId);
        if (user.IsEmployee || user.Region == "US-West")
            return true;
        
        return false;
    }
}
```

### Zero-Downtime Deployment Checklist

```csharp
public class ZeroDowntimeChecklist
{
    // ✅ Application-level requirements
    public class ApplicationRequirements
    {
        // - Health checks implemented
        // - Graceful shutdown (drain connections)
        // - Readiness probe (don't route until ready)
        // - Liveness probe (restart if unhealthy)
        
        [HttpGet("/health/ready")]
        public async Task<IActionResult> Ready()
        {
            // Check dependencies
            var dbHealthy = await _db.CanConnectAsync();
            var queueHealthy = await _queue.CanConnectAsync();
            
            if (dbHealthy && queueHealthy)
                return Ok("Ready");
            else
                return StatusCode(503, "Not Ready");
            // Load balancer won't route until 200 OK
        }
    }
    
    // ✅ Database-level requirements
    public class DatabaseRequirements
    {
        // - All migrations are backward compatible
        // - New columns are nullable initially
        // - Expand-contract for breaking changes
        // - No dropping columns in same release as code
    }
    
    // ✅ API-level requirements
    public class APIRequirements
    {
        // - API changes are backward compatible
        // - Old endpoints supported for 2+ releases
        // - API versioning in place
        // - Consumer-driven contracts tested
    }
    
    // ✅ Infrastructure-level requirements
    public class InfrastructureRequirements
    {
        // - Rolling updates configured
        // - Multiple replicas running
        // - Load balancer health checks configured
        // - Automated rollback on failure
    }
}
```

## Polyglot Persistence Deep Dive

### Database Selection Matrix

```csharp
// Comprehensive guide to choosing databases

public class DatabaseSelectionMatrix
{
    // Use Case 1: Transactional data (Orders, Payments)
    public class TransactionalData
    {
        // Requirements:
        // - ACID transactions
        // - Strong consistency
        // - Complex queries
        // - Relations between entities
        
        // Best choice: Relational database
        // - PostgreSQL
        // - SQL Server
        // - MySQL
        
        public class OrderService
        {
            private readonly DbContext _db;
            
            public async Task CreateOrderAsync(Order order)
            {
                using var transaction = await _db.Database.BeginTransactionAsync();
                
                await _db.Orders.AddAsync(order);
                await _db.OrderLines.AddRangeAsync(order.Lines);
                await UpdateInventoryAsync(order.Lines);
                
                await _db.SaveChangesAsync();
                await transaction.CommitAsync(); // Atomic!
            }
        }
    }
    
    // Use Case 2: Flexible schema (Product catalog)
    public class FlexibleSchemaData
    {
        // Requirements:
        // - Varying attributes per product
        // - Fast reads
        // - Schema evolution without migrations
        // - Full-text search
        
        // Best choice: Document database
        // - MongoDB
        // - Azure Cosmos DB
        // - CouchDB
        
        public class ProductCatalogService
        {
            private readonly IMongoCollection<BsonDocument> _products;
            
            public async Task<Product> GetProductAsync(string id)
            {
                // Each product can have different fields
                var doc = await _products.Find(p => p["_id"] == id).FirstAsync();
                
                return new Product
                {
                    Id = doc["_id"].AsString,
                    Name = doc["name"].AsString,
                    // Product A has "size", Product B has "duration"
                    Attributes = doc["attributes"].AsBsonDocument
                };
            }
        }
    }
    
    // Use Case 3: Caching (Session data, API responses)
    public class CachingData
    {
        // Requirements:
        // - Extremely fast reads/writes
        // - TTL (time to live)
        // - Simple key-value
        // - Ephemeral data OK
        
        // Best choice: In-memory store
        // - Redis
        // - Memcached
        
        public class SessionService
        {
            private readonly IConnectionMultiplexer _redis;
            
            public async Task StoreSessionAsync(string sessionId, UserSession session)
            {
                var db = _redis.GetDatabase();
                await db.StringSetAsync(
                    key: $"session:{sessionId}",
                    value: JsonSerializer.Serialize(session),
                    expiry: TimeSpan.FromHours(2)); // Auto-expire
            }
        }
    }
    
    // Use Case 4: Time-series data (Metrics, logs)
    public class TimeSeriesData
    {
        // Requirements:
        // - High write throughput
        // - Time-based queries
        // - Retention policies
        // - Aggregations over time
        
        // Best choice: Time-series database
        // - InfluxDB
        // - TimescaleDB
        // - Prometheus
        
        public class MetricsService
        {
            private readonly InfluxDBClient _influx;
            
            public async Task RecordMetricAsync(string metric, double value)
            {
                var point = PointData
                    .Measurement("api_latency")
                    .Tag("service", "order-service")
                    .Field("duration", value)
                    .Timestamp(DateTime.UtcNow, WritePrecision.Ms);
                
                await _influx.GetWriteApiAsync().WritePointAsync(point);
            }
        }
    }
    
    // Use Case 5: Graph relationships (Social network, recommendations)
    public class GraphData
    {
        // Requirements:
        // - Complex relationships
        // - Traversal queries
        // - "friends of friends"
        // - Recommendation algorithms
        
        // Best choice: Graph database
        // - Neo4j
        // - Amazon Neptune
        // - Azure Cosmos DB (Gremlin API)
        
        public class SocialGraphService
        {
            private readonly IDriver _neo4j;
            
            public async Task<List<User>> GetFriendsOfFriendsAsync(string userId)
            {
                var session = _neo4j.AsyncSession();
                
                // Cypher query
                var result = await session.RunAsync(@"
                    MATCH (user:User {id: $userId})-[:FRIEND]->(friend)-[:FRIEND]->(fof)
                    WHERE NOT (user)-[:FRIEND]->(fof)
                    RETURN DISTINCT fof
                    LIMIT 10
                ", new { userId });
                
                // Graph traversal is native
                return await result.ToListAsync(r => MapToUser(r["fof"]));
            }
        }
    }
    
    // Use Case 6: Full-text search
    public class SearchData
    {
        // Requirements:
        // - Fuzzy matching
        // - Relevance ranking
        // - Faceted search
        // - Autocomplete
        
        // Best choice: Search engine
        // - Elasticsearch
        // - Azure Cognitive Search
        // - Algolia
        
        public class ProductSearchService
        {
            private readonly ElasticClient _elastic;
            
            public async Task<SearchResults> SearchAsync(string query)
            {
                var response = await _elastic.SearchAsync<Product>(s => s
                    .Query(q => q
                        .MultiMatch(m => m
                            .Query(query)
                            .Fields(f => f
                                .Field(p => p.Name, boost: 2.0)
                                .Field(p => p.Description)
                                .Field(p => p.Tags))
                            .Fuzziness(Fuzziness.Auto)))
                    .Aggregations(a => a
                        .Terms("categories", t => t.Field(p => p.Category))));
                
                // Relevance-ranked results with facets
                return MapToSearchResults(response);
            }
        }
    }
}
```

### Managing Data Consistency

```csharp
// Strategies for consistency across polyglot persistence

public class CrossDatabaseConsistency
{
    // Strategy 1: Eventual consistency via events
    public class EventualConsistency
    {
        // OrderService writes to SQL Server
        public async Task CreateOrderAsync(Order order)
        {
            await _orderDb.Orders.AddAsync(order);
            await _orderDb.SaveChangesAsync();
            
            // Publish event
            await _eventBus.PublishAsync(new OrderCreatedEvent
            {
                OrderId = order.Id,
                CustomerId = order.CustomerId,
                // ... order details
            });
        }
        
        // SearchService updates Elasticsearch
        public async Task HandleOrderCreatedAsync(OrderCreatedEvent evt)
        {
            await _elasticClient.IndexDocumentAsync(new OrderSearchDocument
            {
                OrderId = evt.OrderId,
                CustomerId = evt.CustomerId,
                SearchableContent = $"{evt.OrderId} {evt.CustomerName}"
            });
            
            // Eventually consistent!
            // Small delay between SQL and Elasticsearch
        }
    }
    
    // Strategy 2: Saga for multi-database transactions
    public class SagaPattern
    {
        // Transfer money across services with different databases
        public async Task TransferMoneyAsync(string fromAccount, string toAccount, decimal amount)
        {
            var saga = new MoneyTransferSaga
            {
                FromAccount = fromAccount,
                ToAccount = toAccount,
                Amount = amount
            };
            
            try
            {
                // Step 1: Debit from account (PostgreSQL)
                await _accountService.DebitAsync(fromAccount, amount);
                saga.MarkDebitComplete();
                
                // Step 2: Credit to account (MongoDB in different service)
                await _ledgerService.CreditAsync(toAccount, amount);
                saga.MarkComplete();
            }
            catch
            {
                // Compensating transaction
                if (saga.DebitComplete)
                {
                    await _accountService.CreditAsync(fromAccount, amount);
                }
                throw;
            }
        }
    }
}
```

1. What makes a deployment truly "independent"?
2. Why is polyglot persistence beneficial?
3. How do you handle data consistency across services?
4. What is the expand-contract pattern for schema migration?

---

## Key Takeaways

- Independent deployability requires backward compatibility and versioning
- Polyglot persistence: use the right database for each service's needs
- Database-per-service pattern prevents coupling through schema
- Duplicate/denormalize data to avoid cross-service joins
- Use events to keep denormalized data in sync
- Schema evolution requires careful coordination (expand-contract)
- API composition for read-time data aggregation
- Blue-green deployments enable zero-downtime releases
- Consumer-driven contracts ensure compatibility
- Choose databases based on access patterns, not familiarity
