## Introduction

In a distributed system, a single failing service can bring down your entire application through cascading failures. When Service A calls Service B, and B is slow or failing, Service A's threads get blocked waiting for responses. As requests pile up, Service A exhausts its resources and starts failing too. The circuit breaker pattern prevents this by "breaking the circuit" when failures reach a threshold—failing fast instead of waiting for doomed requests.

The pattern works like an electrical circuit breaker in your home: when too much current flows (too many failures), the breaker trips (opens), protecting the system. After a timeout, it allows a test request through (half-open state) to see if the service has recovered.

This pattern is essential in microservices architectures where services call each other in complex dependency chains. A single slow service at the bottom of the chain can cascade upward, exhausting resources in every calling service. Circuit breakers provide a critical safety mechanism to prevent these cascading failures.

## Key Concepts Summary

### Three States of a Circuit Breaker

```csharp
public enum CircuitState
{
    Closed,    // Normal operation - requests flow through
    Open,      // Failure threshold exceeded - requests fail fast
    HalfOpen   // Testing if service has recovered
}
```

### State Transitions

**Closed → Open:**
- Occurs when failure threshold is exceeded (e.g., 5 failures in 10 seconds)
- All requests now fail immediately without calling the downstream service
- Prevents resource exhaustion and cascading failures

**Open → Half-Open:**
- After a timeout period (e.g., 30 seconds)
- Allows a limited number of test requests through
- Used to detect if the downstream service has recovered

**Half-Open → Closed:**
- If test requests succeed
- Circuit returns to normal operation

**Half-Open → Open:**
- If test requests fail
- Circuit remains open and timeout resets

### Visual State Diagram

```
         Success (within threshold)
                    ↓
            ┌──────CLOSED──────┐
            │  Normal Operation│
            │  Track failures  │
            └──────────────────┘
                    ↓ Failure threshold exceeded
            ┌──────OPEN────────┐
            │   Fail Fast      │
            │  Wait timeout    │
            └──────────────────┘
                    ↓ Timeout expires
            ┌────HALF-OPEN─────┐
            │  Test recovery   │
            │  Limited requests│
            └──────────────────┘
                ↓           ↓
            Success      Failure
                ↓           ↓
            CLOSED       OPEN
```

## Basic Implementation Concept

### Simple Circuit Breaker

```csharp
public class CircuitBreaker
{
    private CircuitState _state = CircuitState.Closed;
    private int _failureCount = 0;
    private DateTime _lastFailureTime;
    private readonly object _lock = new object();
    
    private const int FailureThreshold = 5;
    private const int TimeoutSeconds = 30;
    
    public async Task<T> ExecuteAsync<T>(Func<Task<T>> operation)
    {
        lock (_lock)
        {
            if (_state == CircuitState.Open)
            {
                // Check if timeout has elapsed
                if (DateTime.UtcNow - _lastFailureTime > TimeSpan.FromSeconds(TimeoutSeconds))
                {
                    _state = CircuitState.HalfOpen;
                }
                else
                {
                    throw new CircuitBreakerOpenException("Circuit breaker is OPEN");
                }
            }
        }
        
        try
        {
            T result = await operation();
            
            // Success - reset if we were testing
            lock (_lock)
            {
                if (_state == CircuitState.HalfOpen)
                {
                    _state = CircuitState.Closed;
                    _failureCount = 0;
                }
            }
            
            return result;
        }
        catch (Exception ex)
        {
            lock (_lock)
            {
                _lastFailureTime = DateTime.UtcNow;
                _failureCount++;
                
                if (_failureCount >= FailureThreshold)
                {
                    _state = CircuitState.Open;
                }
                
                if (_state == CircuitState.HalfOpen)
                {
                    // Test failed, reopen circuit
                    _state = CircuitState.Open;
                }
            }
            
            throw;
        }
    }
}
```

### Advanced: Sliding Window Circuit Breaker

The simple implementation counts consecutive failures. A more robust approach uses a **sliding window** to track failure rate over time:

```csharp
public class SlidingWindowCircuitBreaker
{
    private CircuitState _state = CircuitState.Closed;
    private readonly Queue<CallResult> _callHistory = new Queue<CallResult>();
    private DateTime _openedAt;
    private readonly object _lock = new object();
    
    private const int WindowSize = 10;  // Track last 10 calls
    private const double FailureThreshold = 0.5;  // 50% failure rate
    private const int MinimumThroughput = 5;  // Need at least 5 calls
    private const int TimeoutSeconds = 30;
    
    public async Task<T> ExecuteAsync<T>(Func<Task<T>> operation)
    {
        lock (_lock)
        {
            if (_state == CircuitState.Open)
            {
                if (DateTime.UtcNow - _openedAt > TimeSpan.FromSeconds(TimeoutSeconds))
                {
                    _state = CircuitState.HalfOpen;
                }
                else
                {
                    throw new CircuitBreakerOpenException(
                        $"Circuit breaker is OPEN. Will retry in {TimeoutSeconds - (DateTime.UtcNow - _openedAt).TotalSeconds:F0}s");
                }
            }
        }
        
        try
        {
            T result = await operation();
            RecordSuccess();
            return result;
        }
        catch (Exception ex)
        {
            RecordFailure();
            throw;
        }
    }
    
    private void RecordSuccess()
    {
        lock (_lock)
        {
            _callHistory.Enqueue(new CallResult { Success = true, Timestamp = DateTime.UtcNow });
            
            if (_callHistory.Count > WindowSize)
                _callHistory.Dequeue();
            
            if (_state == CircuitState.HalfOpen)
            {
                _state = CircuitState.Closed;
                _callHistory.Clear();  // Reset on recovery
            }
        }
    }
    
    private void RecordFailure()
    {
        lock (_lock)
        {
            _callHistory.Enqueue(new CallResult { Success = false, Timestamp = DateTime.UtcNow });
            
            if (_callHistory.Count > WindowSize)
                _callHistory.Dequeue();
            
            // Check if we should open the circuit
            if (_callHistory.Count >= MinimumThroughput)
            {
                var failureRate = _callHistory.Count(c => !c.Success) / (double)_callHistory.Count;
                
                if (failureRate >= FailureThreshold)
                {
                    _state = CircuitState.Open;
                    _openedAt = DateTime.UtcNow;
                }
            }
            
            if (_state == CircuitState.HalfOpen)
            {
                _state = CircuitState.Open;
                _openedAt = DateTime.UtcNow;
            }
        }
    }
    
    private class CallResult
    {
        public bool Success { get; set; }
        public DateTime Timestamp { get; set; }
    }
}
```

## Configuration Considerations

### Failure Threshold

**Simple Threshold (Consecutive Failures):**
- Too low: Circuit trips on transient errors
- Too high: Cascading failures before protection kicks in
- **Recommendation:** Start with 5-10 consecutive failures

**Percentage Threshold (Failure Rate):**
- Too low: Too sensitive to noise
- Too high: Slow to react to real issues
- **Recommendation:** 25-50% failure rate over a sliding window

**Example Configuration by Service Type:**

| Service Type | Threshold | Rationale |
|--------------|-----------|-----------|
| Critical Payment API | 3 consecutive or 25% in window | Fast fail to protect revenue |
| Internal Recommendation | 10 consecutive or 50% in window | More tolerance for non-critical |
| External Analytics | 5 consecutive or 40% in window | Balance between availability and reliability |

### Timeout Duration

**Factors to Consider:**
- Average recovery time for the dependency
- Impact of downtime on user experience
- Rate of retry attempts (avoid thundering herd)

**Too short (< 10s):**
- Constant retrying prevents service recovery
- Adds load during recovery period

**Too long (> 5min):**
- Extended outages before detecting recovery
- Poor user experience

**Recommendation:**
- Start with 30-60 seconds
- Adjust based on monitoring data
- Use exponential backoff for successive openings

```csharp
public class AdaptiveCircuitBreaker : CircuitBreaker
{
    private int _consecutiveOpens = 0;
    
    protected override TimeSpan CalculateTimeout()
    {
        // Exponential backoff: 30s, 60s, 120s, max 300s
        var timeout = TimeSpan.FromSeconds(30 * Math.Pow(2, _consecutiveOpens));
        return timeout > TimeSpan.FromSeconds(300) 
            ? TimeSpan.FromSeconds(300) 
            : timeout;
    }
    
    protected override void OnCircuitOpened()
    {
        _consecutiveOpens++;
    }
    
    protected override void OnCircuitClosed()
    {
        _consecutiveOpens = 0;  // Reset on successful recovery
    }
}
```

### What Constitutes a Failure

Define precisely which exceptions should trip the circuit:

```csharp
public class ConfigurableCircuitBreaker
{
    private readonly Func<Exception, bool> _shouldHandleException;
    
    public ConfigurableCircuitBreaker(Func<Exception, bool> shouldHandleException)
    {
        _shouldHandleException = shouldHandleException;
    }
    
    public async Task<T> ExecuteAsync<T>(Func<Task<T>> operation)
    {
        try
        {
            return await operation();
        }
        catch (Exception ex) when (_shouldHandleException(ex))
        {
            RecordFailure();
            throw;
        }
    }
}

// Usage for HTTP calls
var breaker = new ConfigurableCircuitBreaker(ex =>
{
    if (ex is HttpRequestException httpEx)
    {
        // Only trip on server errors and timeouts
        return httpEx.StatusCode >= HttpStatusCode.InternalServerError ||
               httpEx.StatusCode == HttpStatusCode.RequestTimeout;
    }
    
    if (ex is TimeoutException)
        return true;
    
    // Don't trip on validation errors, auth failures, etc.
    return false;
});
```

**Common Patterns:**

✅ **Should trip circuit:**
- HTTP 503 Service Unavailable
- HTTP 429 Too Many Requests
- TimeoutException
- Connection refused errors

❌ **Should NOT trip circuit:**
- HTTP 400 Bad Request (client error)
- HTTP 401 Unauthorized (auth issue)
- HTTP 404 Not Found (resource doesn't exist)
- Validation exceptions (business logic)

### Metrics and Alerting

public class ObservableCircuitBreaker : CircuitBreaker
{
    private readonly IMeter _meter;
    private readonly Counter<long> _stateTransitions;
    private readonly ObservableGauge<int> _failureCount;
    
    public ObservableCircuitBreaker(IMeterFactory meterFactory, string name)
    {
        _meter = meterFactory.Create("CircuitBreaker");
        
        _stateTransitions = _meter.CreateCounter<long>(
            "circuit_breaker.state_transitions",
            description: "Number of state transitions");
        
        _failureCount = _meter.CreateObservableGauge(
            "circuit_breaker.failure_count",
            () => new Measurement<int>(_failureCount, new KeyValuePair<string, object>("name", name)));
    }
    
    protected override void OnStateChange(CircuitState oldState, CircuitState newState)
    {
        _stateTransitions.Add(1, new KeyValuePair<string, object>("from", oldState),
                                 new KeyValuePair<string, object>("to", newState));
        
        if (newState == CircuitState.Open)
        {
            _logger.LogWarning("Circuit breaker {Name} opened after {FailureCount} failures",
                _name, _failureCount);
        }
    }
}

## Combining with Other Patterns

### Circuit Breaker + Retry

```csharp
// Retry wraps circuit breaker
var retryPolicy = Policy
    .Handle<HttpRequestException>()
    .WaitAndRetryAsync(3, attempt => TimeSpan.FromSeconds(Math.Pow(2, attempt)));

var circuitBreakerPolicy = Policy
    .Handle<HttpRequestException>()
    .CircuitBreakerAsync(5, TimeSpan.FromSeconds(30));

var combinedPolicy = Policy.WrapAsync(retryPolicy, circuitBreakerPolicy);

// If circuit is open, retry won't even attempt
// If closed, retry logic handles transient failures
```

### Circuit Breaker + Fallback

```csharp
public class ResilientService
{
    private readonly CircuitBreaker _breaker;
    private readonly ICache _cache;
    
    public async Task<WeatherData> GetWeatherAsync(string city)
    {
        try
        {
            return await _breaker.ExecuteAsync(async () =>
            {
                return await _weatherApiClient.GetAsync(city);
            });
        }
        catch (CircuitBreakerOpenException)
        {
            // Fallback to cached data
            var cached = await _cache.GetAsync<WeatherData>($"weather:{city}");
            
            if (cached != null)
            {
                cached.IsStale = true;
                return cached;
            }
            
            throw;
        }
    }
}
```

### Circuit Breaker + Bulkhead

```csharp
// Combine circuit breaker with bulkhead for maximum resilience
public class ResilientHttpClient
{
    private readonly CircuitBreaker _breaker;
    private readonly SemaphoreSlim _bulkhead;
    
    public ResilientHttpClient(int maxConcurrency)
    {
        _breaker = new CircuitBreaker(failureThreshold: 5, timeout: TimeSpan.FromSeconds(30));
        _bulkhead = new SemaphoreSlim(maxConcurrency);
    }
    
    public async Task<HttpResponseMessage> GetAsync(string url)
    {
        // Bulkhead limits concurrent requests
        await _bulkhead.WaitAsync();
        
        try
        {
            // Circuit breaker protects from cascading failures
            return await _breaker.ExecuteAsync(async () =>
            {
                return await _httpClient.GetAsync(url);
            });
        }
        finally
        {
            _bulkhead.Release();
        }
    }
}
```

## Real-World Scenarios

### Scenario 1: E-Commerce Payment Processing

```csharp
public class PaymentService
{
    private readonly CircuitBreaker _paymentGatewayBreaker;
    private readonly CircuitBreaker _fraudCheckBreaker;
    
    public PaymentService()
    {
        // Payment gateway: strict threshold
        _paymentGatewayBreaker = new CircuitBreaker(
            failureThreshold: 3,
            timeout: TimeSpan.FromSeconds(60));
        
        // Fraud check: more lenient (can skip if down)
        _fraudCheckBreaker = new CircuitBreaker(
            failureThreshold: 5,
            timeout: TimeSpan.FromSeconds(30));
    }
    
    public async Task<PaymentResult> ProcessPaymentAsync(PaymentRequest request)
    {
        // Critical: payment gateway must work
        var paymentResult = await _paymentGatewayBreaker.ExecuteAsync(async () =>
        {
            return await _paymentGateway.ChargeAsync(request);
        });
        
        // Non-critical: fraud check with fallback
        try
        {
            await _fraudCheckBreaker.ExecuteAsync(async () =>
            {
                await _fraudService.CheckAsync(request);
            });
        }
        catch (CircuitBreakerOpenException)
        {
            // Fraud service down - allow payment but flag for manual review
            await _auditLog.LogAsync($"Payment {paymentResult.Id} processed without fraud check");
        }
        
        return paymentResult;
    }
}
```

## Testing Circuit Breakers

### Unit Testing

```csharp
[Fact]
public async Task CircuitBreaker_Opens_After_ThresholdExceeded()
{
    // Arrange
    var breaker = new CircuitBreaker(failureThreshold: 3, timeout: TimeSpan.FromSeconds(30));
    var failingOperation = new Func<Task<string>>(() => throw new Exception("Simulated failure"));
    
    // Act - cause 3 failures
    await Assert.ThrowsAsync<Exception>(() => breaker.ExecuteAsync(failingOperation));
    await Assert.ThrowsAsync<Exception>(() => breaker.ExecuteAsync(failingOperation));
    await Assert.ThrowsAsync<Exception>(() => breaker.ExecuteAsync(failingOperation));
    
    // Assert - 4th call should fail fast
    var ex = await Assert.ThrowsAsync<CircuitBreakerOpenException>(
        () => breaker.ExecuteAsync(failingOperation));
    
    Assert.Equal(CircuitState.Open, breaker.State);
}

[Fact]
public async Task CircuitBreaker_TransitionsToHalfOpen_AfterTimeout()
{
    // Arrange
    var breaker = new CircuitBreaker(failureThreshold: 1, timeout: TimeSpan.FromSeconds(1));
    await Assert.ThrowsAsync<Exception>(() => 
        breaker.ExecuteAsync<string>(() => throw new Exception()));
    
    Assert.Equal(CircuitState.Open, breaker.State);
    
    // Act - wait for timeout
    await Task.Delay(TimeSpan.FromSeconds(1.5));
    
    // Next call should transition to half-open
    var successOperation = new Func<Task<string>>(() => Task.FromResult("success"));
    var result = await breaker.ExecuteAsync(successOperation);
    
    // Assert
    Assert.Equal("success", result);
    Assert.Equal(CircuitState.Closed, breaker.State);
}
```

## Common Pitfalls

### Pitfall 1: Shared Circuit Breaker Instance

❌ **Wrong:**
```csharp
// Single breaker for all tenants
private static readonly CircuitBreaker _breaker = new CircuitBreaker();

public async Task<Data> GetDataAsync(int tenantId)
{
    return await _breaker.ExecuteAsync(() => _api.GetAsync(tenantId));
}
// One tenant's failures affect all tenants!
```

✅ **Correct:**
```csharp
// Circuit breaker per tenant
private readonly ConcurrentDictionary<int, CircuitBreaker> _breakers = new();

public async Task<Data> GetDataAsync(int tenantId)
{
    var breaker = _breakers.GetOrAdd(tenantId, _ => new CircuitBreaker());
    return await breaker.ExecuteAsync(() => _api.GetAsync(tenantId));
}
```

### Pitfall 2: No Half-Open State

❌ **Wrong:**
```csharp
// Circuit stays open forever or closes immediately
if (_failureCount > threshold)
    _state = CircuitState.Open;
else
    _state = CircuitState.Closed;
```

✅ **Correct:**
```csharp
// Gradual recovery through half-open state
if (_state == CircuitState.Open && TimeoutExpired())
{
    _state = CircuitState.HalfOpen;  // Test recovery
}
```

### Pitfall 3: Inconsistent Failure Definition

```csharp
// Be consistent about what constitutes a failure
private bool IsFailure(HttpResponseMessage response)
{
    // Consistent rules
    return (int)response.StatusCode >= 500 ||
           response.StatusCode == HttpStatusCode.RequestTimeout ||
           response.StatusCode == HttpStatusCode.TooManyRequests;
}
```

## Key Takeaways

✅ Circuit breakers prevent cascading failures by failing fast

✅ Three states: Closed (normal), Open (failing fast), Half-Open (testing recovery)

✅ Use sliding windows for more accurate failure rate detection

✅ Configure thresholds based on service criticality and typical recovery times

✅ Combine with retry, fallback, and bulkhead patterns for maximum resilience

✅ Monitor state transitions and expose health endpoints

✅ Test circuit breaker behavior in integration tests
