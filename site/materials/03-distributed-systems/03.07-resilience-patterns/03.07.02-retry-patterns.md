## Introduction

Transient failures are temporary glitches in distributed systems—network blips, brief database locks, momentary resource exhaustion. Unlike permanent failures (like 404 Not Found), transient failures often resolve themselves within seconds. Retrying the operation after a brief delay can turn a failure into a success.

However, naive retry logic can make things worse. If a service is overloaded and you immediately retry failed requests, you're adding to the load that caused the problem. **Exponential backoff** solves this by progressively increasing the delay between retries. **Jitter** adds randomness to prevent thundering herds—when thousands of clients retry simultaneously after a timeout, they can overwhelm a recovering service.

Understanding when and how to retry is critical. A well-designed retry strategy improves reliability without degrading performance or user experience. A poorly designed one creates more problems than it solves.

## Key Concepts Summary

### Types of Failures

**Transient (Retry):**
- Network timeouts
- HTTP 503 Service Unavailable
- HTTP 429 Too Many Requests
- Temporary database deadlocks
- Brief resource exhaustion

**Permanent (Don't Retry):**
- HTTP 404 Not Found
- HTTP 401 Unauthorized
- HTTP 400 Bad Request
- Invalid input validation errors
- Business logic failures

### Exponential Backoff

Delay between retries grows exponentially:

```csharp
// Simple exponential backoff
int CalculateDelay(int retryAttempt, int baseDelayMs = 100)
{
    return baseDelayMs * (int)Math.Pow(2, retryAttempt);
}

// Example progression:
// Attempt 1: 100ms delay
// Attempt 2: 200ms delay
// Attempt 3: 400ms delay
// Attempt 4: 800ms delay
// Attempt 5: 1600ms delay
```

### Adding Jitter

Randomization prevents synchronized retries:

```csharp
// Exponential backoff with full jitter
int CalculateDelayWithJitter(int retryAttempt, int baseDelayMs = 100)
{
    int exponentialDelay = baseDelayMs * (int)Math.Pow(2, retryAttempt);
    Random random = new Random();
    return random.Next(0, exponentialDelay);
}

// With jitter, attempt 3 could be anywhere from 0-400ms
// This spreads out retry attempts across time
```

### Comprehensive Retry Implementation

```csharp
public class RetryPolicy
{
    private readonly int _maxRetries;
    private readonly int _baseDelayMs;
    private readonly int _maxDelayMs;
    
    public RetryPolicy(int maxRetries = 3, int baseDelayMs = 100, int maxDelayMs = 30000)
    {
        _maxRetries = maxRetries;
        _baseDelayMs = baseDelayMs;
        _maxDelayMs = maxDelayMs;
    }
    
    public async Task<T> ExecuteAsync<T>(
        Func<Task<T>> operation,
        Func<Exception, bool> shouldRetry)
    {
        int attempt = 0;
        
        while (true)
        {
            try
            {
                return await operation();
            }
            catch (Exception ex) when (shouldRetry(ex) && attempt < _maxRetries)
            {
                attempt++;
                int delay = CalculateDelay(attempt);
                
                Console.WriteLine($"Attempt {attempt} failed. Retrying after {delay}ms...");
                await Task.Delay(delay);
            }
        }
    }
    
    private int CalculateDelay(int attempt)
    {
        // Exponential backoff: baseDelay * 2^(attempt-1)
        int exponentialDelay = _baseDelayMs * (int)Math.Pow(2, attempt - 1);
        
        // Cap at max delay
        exponentialDelay = Math.Min(exponentialDelay, _maxDelayMs);
        
        // Add jitter (0-100% of calculated delay)
        Random random = new Random();
        int jitter = random.Next(0, exponentialDelay);
        
        return jitter;
    }
}

// Usage
var retryPolicy = new RetryPolicy(maxRetries: 3, baseDelayMs: 100, maxDelayMs: 5000);

var result = await retryPolicy.ExecuteAsync(
    operation: async () => await httpClient.GetAsync("https://api.example.com/data"),
    shouldRetry: ex => ex is HttpRequestException || ex is TaskCanceledException
);
```

### Configuration Guidelines

**Max Retries:**
- **Fast operations (< 100ms):** 3-5 retries
- **Slow operations (> 1s):** 2-3 retries
- **User-facing requests:** Fewer retries (don't make users wait too long)
- **Background jobs:** More retries acceptable

**Base Delay:**
- **High-frequency operations:** 50-100ms
- **Standard operations:** 100-500ms
- **Heavy operations:** 500-1000ms

**Max Delay:**
- Should be less than your total timeout budget
- Typically 5-30 seconds
- Consider user experience for user-facing calls

### Common Antipatterns

❌ **Immediate Retry (No Delay)**
```csharp
// Bad: Hammers the failing service
for (int i = 0; i < 3; i++)
{
    try { return await operation(); }
    catch { /* retry immediately */ }
}
```

❌ **Fixed Delay Without Jitter**
```csharp
// Bad: Thundering herd problem
await Task.Delay(1000); // All clients retry at same time
```

❌ **Retrying Non-Transient Errors**
```csharp
// Bad: Retrying a 400 Bad Request will never succeed
catch (HttpRequestException ex)
{
    // Should check status code!
    retry();
}
```

❌ **Infinite Retries**
```csharp
// Bad: Can loop forever
while (true)
{
    try { return await operation(); }
    catch { /* retry forever */ }
}
```

## Idempotency: The Foundation of Safe Retries

### Why Idempotency Matters

Retrying an operation means it might execute multiple times. If an operation is **idempotent**, executing it multiple times has the same effect as executing it once. This is critical for safe retries.

**Idempotent Operations:**
- ✅ GET requests (reading data)
- ✅ PUT requests with full replacement
- ✅ DELETE requests (deleting already deleted is safe)
- ✅ Database updates with explicit values: `UPDATE users SET status = 'active' WHERE id = 123`

**Non-Idempotent Operations:**
- ❌ POST requests that create resources
- ❌ Incrementing counters: `UPDATE users SET login_count = login_count + 1`
- ❌ Appending to lists without deduplication
- ❌ Processing payments without deduplication

### Making Non-Idempotent Operations Idempotent

#### Pattern 1: Idempotency Keys

```csharp
public class PaymentService
{
    public async Task<PaymentResult> ProcessPaymentAsync(PaymentRequest request)
    {
        // Generate idempotency key from request data
        var idempotencyKey = $"{request.OrderId}:{request.Amount}:{request.Timestamp}";
        
        // Check if we've already processed this payment
        var existingResult = await _cache.GetAsync<PaymentResult>(idempotencyKey);
        if (existingResult != null)
        {
            _logger.LogInformation("Payment already processed for key {Key}", idempotencyKey);
            return existingResult;
        }
        
        // Process payment
        var result = await _paymentGateway.ChargeAsync(request);
        
        // Store result for future duplicate checks (24 hour TTL)
        await _cache.SetAsync(idempotencyKey, result, TimeSpan.FromHours(24));
        
        return result;
    }
}
```

#### Pattern 2: Natural Keys

```csharp
public class OrderService
{
    public async Task CreateOrderAsync(CreateOrderCommand command)

        var order = new Order

        }
```

#### Pattern 3: Version Numbers

```csharp
public class InventoryService
{
    public async Task ReserveStockAsync(int productId, int quantity)
    {
        var maxRetries = 3;
        
        for (int attempt = 0; attempt < maxRetries; attempt++)
        {
            var product = await _db.Products.FindAsync(productId);
            
            if (product.StockQuantity < quantity)
                throw new InsufficientStockException();
            
            // Optimistic concurrency check
            var updatedRows = await _db.Database.ExecuteSqlInterpolatedAsync($@"
                UPDATE Products 
                SET StockQuantity = {product.StockQuantity - quantity},
                    Version = {product.Version + 1}
                WHERE ProductId = {productId} 
                  AND Version = {product.Version}
            ");
            
            if (updatedRows > 0)
            {
                return;  // Success
            }
            
            // Version mismatch - someone else updated, retry
            await Task.Delay(TimeSpan.FromMilliseconds(50 * (attempt + 1)));
        }
        
        throw new ConcurrencyException("Failed to reserve stock after retries");
    }
}
```

## Advanced Backoff Strategies

### Full Jitter vs Decorrelated Jitter

```csharp
public enum JitterType
{
    None,
    Full,
    Equal,
    Decorrelated
}

public class JitterCalculator
{
    private readonly Random _random = new Random();
    
    public TimeSpan CalculateDelay(int attempt, int baseDelayMs, JitterType jitter)
    {
        var exponentialDelay = baseDelayMs * Math.Pow(2, attempt);
        
        return jitter switch
        {
            JitterType.None => TimeSpan.FromMilliseconds(exponentialDelay),
            
            JitterType.Full => 
                // Random between 0 and exponentialDelay
                TimeSpan.FromMilliseconds(_random.Next(0, (int)exponentialDelay)),
            
            JitterType.Equal =>
                // Half constant, half random
                TimeSpan.FromMilliseconds(exponentialDelay / 2 + _random.Next(0, (int)(exponentialDelay / 2))),
            
            JitterType.Decorrelated =>
                // Based on previous delay (requires state)
                CalculateDecorrelatedJitter(exponentialDelay),
            
            _ => TimeSpan.FromMilliseconds(exponentialDelay)
        };
    }
    
    private int _previousDelay = 0;
    
    private TimeSpan CalculateDecorrelatedJitter(double baseDelay)
    {
        var delay = Math.Min(baseDelay, _random.Next(0, _previousDelay * 3));
        _previousDelay = (int)delay;
        return TimeSpan.FromMilliseconds(delay);
    }
}
```

### Comparison of Jitter Strategies

```
No Jitter:
Attempt 1: 100ms
Attempt 2: 200ms
Attempt 3: 400ms
Attempt 4: 800ms
Problem: All clients retry at same time

Full Jitter:
Attempt 1: 0-100ms (random)
Attempt 2: 0-200ms (random)
Attempt 3: 0-400ms (random)
Attempt 4: 0-800ms (random)
Benefit: Maximum distribution

Equal Jitter:
Attempt 1: 50ms + 0-50ms
Attempt 2: 100ms + 0-100ms
Attempt 3: 200ms + 0-200ms
Benefit: Guaranteed minimum wait

Decorrelated Jitter:
Attempt 1: 0-300ms (based on previous)
Attempt 2: 0-900ms (based on previous)
Benefit: Smooth distribution over time
```

## Production-Grade Retry Implementation

```csharp
public class RetryPolicyBuilder
{
    private int _maxRetries = 3;
    private int _baseDelayMs = 100;
    private int _maxDelayMs = 30000;
    private JitterType _jitter = JitterType.Full;
    private Func<Exception, bool> _shouldRetry = _ => true;
    private Func<Exception, int, Task> _onRetry = (_, __) => Task.CompletedTask;
    
    public RetryPolicyBuilder WithMaxRetries(int maxRetries)
    {
        _maxRetries = maxRetries;
        return this;
    }
    
    public RetryPolicyBuilder WithBaseDelay(TimeSpan delay)
    {
        _baseDelayMs = (int)delay.TotalMilliseconds;
        return this;
    }
    
    public RetryPolicyBuilder WithMaxDelay(TimeSpan delay)
    {
        _maxDelayMs = (int)delay.TotalMilliseconds;
        return this;
    }
    
    public RetryPolicyBuilder WithJitter(JitterType jitter)
    {
        _jitter = jitter;
        return this;
    }
    
    public RetryPolicyBuilder ShouldRetryOn<TException>(Func<TException, bool> predicate = null) 
        where TException : Exception
    {
        _shouldRetry = ex => ex is TException typedEx && (predicate?.Invoke(typedEx) ?? true);
        return this;
    }
    
    public RetryPolicyBuilder OnRetry(Func<Exception, int, Task> callback)
    {
        _onRetry = callback;
        return this;
    }
    
    public RetryPolicy Build()
    {
        return new RetryPolicy(
            _maxRetries, 
            _baseDelayMs, 
            _maxDelayMs, 
            _jitter,
            _shouldRetry, 
            _onRetry);
    }
}

// Usage
var retryPolicy = new RetryPolicyBuilder()
    .WithMaxRetries(5)
    .WithBaseDelay(TimeSpan.FromMilliseconds(100))
    .WithMaxDelay(TimeSpan.FromSeconds(10))
    .WithJitter(JitterType.Full)
    .ShouldRetryOn<HttpRequestException>(ex => 
        ex.StatusCode == HttpStatusCode.ServiceUnavailable ||
        ex.StatusCode == HttpStatusCode.TooManyRequests)
    .OnRetry(async (ex, attempt) =>
    {
        _logger.LogWarning(ex, "Retry attempt {Attempt}", attempt);
        await _metrics.IncrementCounterAsync("retries", new { attempt });
    })
    .Build();

var result = await retryPolicy.ExecuteAsync(async () =>
{
    return await _httpClient.GetAsync("https://api.example.com/data");
});
```

## Retry Budget Pattern

Limit the percentage of requests that can be retried to prevent overwhelming services:

```csharp
public class RetryBudget
{
    private readonly double _retryRatio;  // e.g., 0.1 = 10% of requests can retry
    private readonly int _windowSize;
    private readonly Queue<bool> _recentRequests = new Queue<bool>();
    private int _retryCount = 0;
    
    public RetryBudget(double retryRatio = 0.1, int windowSize = 100)
    {
        _retryRatio = retryRatio;
        _windowSize = windowSize;
    }
    
    public bool CanRetry()
    {
        lock (_recentRequests)
        {
            if (_recentRequests.Count < _windowSize)
                return true;  // Haven't reached window size yet
            
            var currentRetryRatio = _retryCount / (double)_recentRequests.Count;
            return currentRetryRatio < _retryRatio;
        }
    }
    
    public void RecordRequest(bool wasRetry)
    {
        lock (_recentRequests)
        {
            _recentRequests.Enqueue(wasRetry);
            
            if (wasRetry)
                _retryCount++;
            
            // Maintain sliding window
            if (_recentRequests.Count > _windowSize)
            {
                var removed = _recentRequests.Dequeue();
                if (removed)
                    _retryCount--;
            }
        }
    }
}

// Usage
public class RateLimitedRetryPolicy
{
    private readonly RetryBudget _budget = new RetryBudget(retryRatio: 0.1);
    
    public async Task<T> ExecuteAsync<T>(Func<Task<T>> operation)
    {
        var attempt = 0;
        
        while (true)
        {
            try
            {
                var result = await operation();
                _budget.RecordRequest(wasRetry: attempt > 0);
                return result;
            }
            catch (Exception ex) when (ShouldRetry(ex))
            {
                if (!_budget.CanRetry())
                {
                    _logger.LogWarning("Retry budget exhausted, failing immediately");
                    throw new RetryBudgetExhaustedException("Retry budget exceeded", ex);
                }
                
                attempt++;
                await Task.Delay(CalculateDelay(attempt));
            }
        }
    }
}
```

## Metrics and Monitoring

### Essential Retry Metrics

```csharp
public class ObservableRetryPolicy : RetryPolicy
{
    private readonly Counter<long> _retryCounter;
    private readonly Histogram<double> _retryDelayHistogram;
    private readonly Gauge<int> _activeRetries;
    
    public ObservableRetryPolicy(IMeterFactory meterFactory)
    {
        var meter = meterFactory.Create("RetryPolicy");
        
        _retryCounter = meter.CreateCounter<long>(
            "retry.attempts",
            description: "Number of retry attempts by outcome");
        
        _retryDelayHistogram = meter.CreateHistogram<double>(
            "retry.delay_ms",
            unit: "ms",
            description: "Distribution of retry delays");
        
        _activeRetries = meter.CreateGauge<int>(
            "retry.active",
            description: "Current number of active retries");
    }
    
    protected override async Task<T> ExecuteWithRetryAsync<T>(
        Func<Task<T>> operation,
        int attempt)
    {
        _activeRetries.Record(1);
        
        try
        {
            var delay = CalculateDelay(attempt);
            _retryDelayHistogram.Record(delay.TotalMilliseconds, 
                new KeyValuePair<string, object>("attempt", attempt));
            
            await Task.Delay(delay);
            
            var result = await operation();
            
            _retryCounter.Add(1, 
                new KeyValuePair<string, object>("outcome", "success"),
                new KeyValuePair<string, object>("attempt", attempt));
            
            return result;
        }
        catch (Exception ex)
        {
            _retryCounter.Add(1,
                new KeyValuePair<string, object>("outcome", "failure"),
                new KeyValuePair<string, object>("attempt", attempt),
                new KeyValuePair<string, object>("exception", ex.GetType().Name));
            throw;
        }
        finally
        {
            _activeRetries.Record(-1);
        }
    }
}
```

## Real-World Scenario: Order Processing

```csharp
public class OrderProcessingService
{
    private readonly RetryPolicy _paymentRetryPolicy;
    private readonly RetryPolicy _inventoryRetryPolicy;
    private readonly RetryPolicy _notificationRetryPolicy;
    
    public OrderProcessingService()
    {
        // Payment: critical, aggressive retries
        _paymentRetryPolicy = new RetryPolicyBuilder()
            .WithMaxRetries(5)
            .WithBaseDelay(TimeSpan.FromMilliseconds(200))
            .WithMaxDelay(TimeSpan.FromSeconds(10))
            .WithJitter(JitterType.Full)
            .ShouldRetryOn<HttpRequestException>(ex =>
                ex.StatusCode == HttpStatusCode.ServiceUnavailable ||
                ex.StatusCode == HttpStatusCode.RequestTimeout)
            .Build();
        
        // Inventory: moderate retries with shorter delays
        _inventoryRetryPolicy = new RetryPolicyBuilder()
            .WithMaxRetries(3)
            .WithBaseDelay(TimeSpan.FromMilliseconds(100))
            .WithMaxDelay(TimeSpan.FromSeconds(5))
            .Build();
        
        // Notifications: best effort, don't block order
        _notificationRetryPolicy = new RetryPolicyBuilder()
            .WithMaxRetries(2)
            .WithBaseDelay(TimeSpan.FromMilliseconds(500))
            .Build();
    }
    
    public async Task<OrderResult> ProcessOrderAsync(Order order)
    {
        // Critical: Payment must succeed
        var paymentResult = await _paymentRetryPolicy.ExecuteAsync(async () =>
        {
            return await _paymentService.ChargeAsync(order.Payment);
        });
        
        if (!paymentResult.Success)
            throw new PaymentFailedException();
        
        // Important: Reserve inventory
        try
        {
            await _inventoryRetryPolicy.ExecuteAsync(async () =>
            {
                await _inventoryService.ReserveAsync(order.Items);
            });
        }
        catch (Exception ex)
        {
            // Compensate: refund payment
            await _paymentService.RefundAsync(paymentResult.TransactionId);
            throw new InventoryReservationFailedException(ex);
        }
        
        // Nice to have: Send notification (don't block order)
        _ = Task.Run(async () =>
        {
            try
            {
                await _notificationRetryPolicy.ExecuteAsync(async () =>
                {
                    await _notificationService.SendAsync(order.CustomerId, "Order confirmed");
                });
            }
            catch (Exception ex)
            {
                _logger.LogWarning(ex, "Failed to send notification for order {OrderId}", order.Id);
                // Don't fail order - notification can be sent later
            }
        });
        
        return new OrderResult { OrderId = order.Id, Status = "Confirmed" };
    }
}
```
