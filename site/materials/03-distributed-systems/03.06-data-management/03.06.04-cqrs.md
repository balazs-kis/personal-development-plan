## Learning Objectives

By the end of this lesson, you will be able to:

- Implement CQRS with eventual consistency
- Choose when CQRS adds value vs unnecessary complexity

---

## Introduction

**CQRS (Command Query Responsibility Segregation)** is a pattern that separates read and write operations into different models. This enables optimization of each side independently: the write side focuses on consistency and business rules, while the read side optimizes for queries and performance.

## Key Concepts

### Traditional Approach

```csharp
// Single model for reads and writes
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public int StockQuantity { get; set; }
    public Guid CategoryId { get; set; }
}

// Write
await _repository.UpdateAsync(product);

// Read (same model)
var product = await _repository.GetByIdAsync(id);
```

Problems:
- ❌ Write model optimized for normalization
- ❌ Read model needs denormalization for performance
- ❌ Queries require multiple joins
- ❌ Different scaling needs (reads >> writes)

### CQRS Approach

**Separate Models:**

```csharp
// WRITE MODEL (Commands)
public class Product  // Normalized
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public int CategoryId { get; set; }
}

public class UpdateProductPriceCommand
{
    public int ProductId { get; set; }
    public decimal NewPrice { get; set; }
}

public class ProductCommandHandler
{
    public async Task HandleAsync(UpdateProductPriceCommand cmd)
    {
        var product = await _writeRepository.GetAsync(cmd.ProductId);
        product.Price = cmd.NewPrice;
        await _writeRepository.SaveAsync(product);

        // Publish event
        await _eventBus.PublishAsync(new ProductPriceChangedEvent
        {
            ProductId = product.Id,
            NewPrice = product.Price
        });
    }
}

// READ MODEL (Queries) - Denormalized
public class ProductDetailsReadModel
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public string CategoryName { get; set; }  // Denormalized!
    public int TotalReviews { get; set; }  // Precomputed!
    public decimal AverageRating { get; set; }  // Precomputed!
}

public class ProductQueryHandler
{
    public async Task<ProductDetailsReadModel> HandleAsync(int productId)
    {
        // Single query, no joins
        return await _readRepository.GetProductDetailsAsync(productId);
    }
}
```

**Architecture:**

```
Commands (Writes)              Queries (Reads)
      │                              │
      ▼                              ▼
┌──────────────┐            ┌──────────────┐
│ Command Side │            │  Query Side  │
│ (Normalized) │            │(Denormalized)│
└──────┬───────┘            └──────▲───────┘
       │                            │
       │ Events                     │
       └────────────▶ Event Bus ────┘
                        │
                  Read Model Builder
```

## Implementation with MediatR

// Command
public class UpdateProductPriceCommand : IRequest
{
    public int ProductId { get; set; }
    public decimal NewPrice { get; set; }
}

// Command Handler
public class UpdateProductPriceHandler : IRequestHandler<UpdateProductPriceCommand>
{
    public async Task Handle(UpdateProductPriceCommand cmd, CancellationToken ct)

        product.Price = cmd.NewPrice;

        await _writeDb.SaveChangesAsync(ct);

            ProductId = product.Id,

public class GetProductDetailsQuery : IRequest<ProductDetailsReadModel>

    }

## Advanced CQRS Patterns

### Pattern: Multiple Read Models from Single Write Model

```csharp
// Write side (single source of truth)
public class ProductCommandHandler
{
    public async Task HandleAsync(UpdateProductCommand cmd)
    {
        var product = await _writeDb.Products.FindAsync(cmd.ProductId);
        product.Name = cmd.Name;
        product.Price = cmd.Price;
        product.StockQuantity = cmd.StockQuantity;
        
        await _writeDb.SaveChangesAsync();

        // Publish event to update multiple read models
        await _eventBus.PublishAsync(new ProductUpdatedEvent
        {
            ProductId = product.Id,
            Name = product.Name,
            Price = product.Price,
            StockQuantity = product.StockQuantity,
            CategoryId = product.CategoryId,
            UpdatedAt = DateTime.UtcNow
        });
    }
}

// Read Model 1: Product listing (for browsing)
public class ProductListingReadModel
{
    public int ProductId { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public string CategoryName { get; set; }
    public string ThumbnailUrl { get; set; }
    public bool InStock { get; set; }
}

public class ProductListingProjection : IEventHandler<ProductUpdatedEvent>
{
    public async Task HandleAsync(ProductUpdatedEvent evt)
    {
        var listing = await _readDb.ProductListings.FindAsync(evt.ProductId);
        if (listing == null)
        {
            listing = new ProductListingReadModel { ProductId = evt.ProductId };
            await _readDb.ProductListings.AddAsync(listing);
        }

        listing.Name = evt.Name;
        listing.Price = evt.Price;
        listing.InStock = evt.StockQuantity > 0;
        
        await _readDb.SaveChangesAsync();
    }
}

// Read Model 2: Product search (for full-text search)
public class ProductSearchDocument
{
    public int ProductId { get; set; }
    public string Name { get; set; }
    public string Description { get; set; }
    public string[] Tags { get; set; }
    public decimal Price { get; set; }
    public string CategoryName { get; set; }
}

public class ProductSearchProjection : IEventHandler<ProductUpdatedEvent>
{
    private readonly IElasticClient _elastic;

    public async Task HandleAsync(ProductUpdatedEvent evt)
    {
        var document = new ProductSearchDocument
        {
            ProductId = evt.ProductId,
            Name = evt.Name,
            Price = evt.Price,
            // ... additional fields
        };

        await _elastic.IndexDocumentAsync(document);
    }
}

// Read Model 3: Product analytics (for reports)
public class ProductAnalyticsReadModel
{
    public int ProductId { get; set; }
    public int ViewCount { get; set; }
    public int PurchaseCount { get; set; }
    public decimal TotalRevenue { get; set; }
    public DateTime LastUpdated { get; set; }
}

public class ProductAnalyticsProjection : IEventHandler<ProductUpdatedEvent>,
                                          IEventHandler<ProductViewedEvent>,
                                          IEventHandler<ProductPurchasedEvent>
{
    public async Task HandleAsync(ProductUpdatedEvent evt)
    {
        var analytics = await _analyticsDb.ProductAnalytics.FindAsync(evt.ProductId);
        analytics.LastUpdated = evt.UpdatedAt;
        await _analyticsDb.SaveChangesAsync();
    }

    public async Task HandleAsync(ProductViewedEvent evt)
    {
        var analytics = await _analyticsDb.ProductAnalytics.FindAsync(evt.ProductId);
        analytics.ViewCount++;
        await _analyticsDb.SaveChangesAsync();
    }

    public async Task HandleAsync(ProductPurchasedEvent evt)
    {
        var analytics = await _analyticsDb.ProductAnalytics.FindAsync(evt.ProductId);
        analytics.PurchaseCount++;
        analytics.TotalRevenue += evt.Price * evt.Quantity;
        await _analyticsDb.SaveChangesAsync();
    }
}
```

### Pattern: Read Model Materialized Views

```csharp
// Complex aggregation in read model
public class OrderStatisticsReadModel
{
    public int CustomerId { get; set; }
    public int TotalOrders { get; set; }
    public decimal TotalSpent { get; set; }
    public decimal AverageOrderValue { get; set; }
    public DateTime FirstOrderDate { get; set; }
    public DateTime LastOrderDate { get; set; }
    public string[] FavoriteCategories { get; set; }
}

public class OrderStatisticsProjection : IEventHandler<OrderPlacedEvent>
{
    public async Task HandleAsync(OrderPlacedEvent evt)
    {
        var stats = await _readDb.OrderStatistics.FindAsync(evt.CustomerId);
        
        if (stats == null)
        {
            stats = new OrderStatisticsReadModel
            {
                CustomerId = evt.CustomerId,
                TotalOrders = 0,
                TotalSpent = 0,
                FirstOrderDate = evt.OrderDate
            };
            await _readDb.OrderStatistics.AddAsync(stats);
        }

        stats.TotalOrders++;
        stats.TotalSpent += evt.TotalAmount;
        stats.AverageOrderValue = stats.TotalSpent / stats.TotalOrders;
        stats.LastOrderDate = evt.OrderDate;
        
        await _readDb.SaveChangesAsync();
    }
}

// Query is now super fast
[HttpGet("customers/{customerId}/statistics")]
public async Task<OrderStatisticsReadModel> GetCustomerStatistics(int customerId)
{
    // Single query, all data precomputed
    return await _readDb.OrderStatistics.FindAsync(customerId);
}
```

## Read Model Synchronization

```csharp
// Listen to events and update read model
public class ProductReadModelUpdater : IEventHandler<ProductPriceChangedEvent>
{
    public async Task HandleAsync(ProductPriceChangedEvent evt)
    {
        var readModel = await _readDb.ProductDetails.FindAsync(evt.ProductId);
        if (readModel == null)
        {
            _logger.LogWarning("Read model not found for product {ProductId}", evt.ProductId);
            return;
        }

        readModel.Price = evt.NewPrice;
        readModel.LastUpdated = DateTime.UtcNow;
        await _readDb.SaveChangesAsync();
    }
}

// Handle out-of-order events
public class OrderedEventHandler<T> : IEventHandler<T> where T : DomainEvent
{
    public async Task HandleAsync(T evt)
    {
        var readModel = await _readDb.FindAsync(evt.AggregateId);
        
        // Check version to prevent out-of-order updates
        if (evt.Version <= readModel.Version)
        {
            _logger.LogWarning(
                "Ignoring out-of-order event version {EventVersion}, current {CurrentVersion}",
                evt.Version, readModel.Version);
            return;
        }

        // Apply update
        await ApplyEventToReadModel(readModel, evt);
        readModel.Version = evt.Version;
        await _readDb.SaveChangesAsync();
    }
}
```

**Eventual Consistency**: Read model updates asynchronously, slight delay possible (typically milliseconds to seconds).

### Handling Read Model Failures

```csharp
public class ResilientReadModelUpdater : IEventHandler<ProductUpdatedEvent>
{
    public async Task HandleAsync(ProductUpdatedEvent evt)
    {
        var retryPolicy = Policy
            .Handle<DbUpdateException>()
            .Or<TimeoutException>()
            .WaitAndRetryAsync(
                retryCount: 3,
                sleepDurationProvider: attempt => TimeSpan.FromSeconds(Math.Pow(2, attempt)),
                onRetry: (exception, timeSpan, retryCount, context) =>
                {
                    _logger.LogWarning(
                        "Retry {RetryCount} updating read model for product {ProductId}",
                        retryCount, evt.ProductId);
                });

        await retryPolicy.ExecuteAsync(async () =>
        {
            var readModel = await _readDb.ProductDetails.FindAsync(evt.ProductId);
            readModel.Price = evt.NewPrice;
            await _readDb.SaveChangesAsync();
        });
    }
}

// Dead letter queue for failed updates
public class ReadModelUpdateFailureHandler
{
    public async Task HandleAsync(ProductUpdatedEvent evt, Exception exception)
    {
        await _deadLetterQueue.EnqueueAsync(new FailedEvent
        {
            EventId = evt.Id,
            EventType = nameof(ProductUpdatedEvent),
            EventData = JsonSerializer.Serialize(evt),
            FailureReason = exception.Message,
            FailedAt = DateTime.UtcNow,
            RetryCount = 0
        });
        
        _logger.LogError(exception, 
            "Failed to update read model for product {ProductId}, sent to DLQ",
            evt.ProductId);
    }
}
```

### Rebuilding Read Models

```csharp
public class ReadModelRebuilder
{
    // Rebuild from events
    public async Task RebuildProductDetailsAsync()
    {
        _logger.LogInformation("Starting read model rebuild...");

        // Mark read model as rebuilding
        await _readDb.Database.ExecuteSqlRawAsync(
            "UPDATE ReadModelStatus SET Status = 'Rebuilding' WHERE Name = 'ProductDetails'");

        // Clear existing data
        await _readDb.Database.ExecuteSqlRawAsync("TRUNCATE TABLE ProductDetails");

        // Get all product events
        var productIds = await _eventStore.GetAllAggregateIdsAsync("Product");

        foreach (var productId in productIds)
        {
            var events = await _eventStore.GetEventsAsync(productId);
            
            foreach (var @event in events)
            {
                await _projectionHandler.HandleAsync(@event);
            }
        }

        // Mark as ready
        await _readDb.Database.ExecuteSqlRawAsync(
            "UPDATE ReadModelStatus SET Status = 'Ready', LastRebuilt = GETUTCDATE() WHERE Name = 'ProductDetails'");

        _logger.LogInformation("Read model rebuild complete");
    }

    // Rebuild from write model (if not using event sourcing)
    public async Task RebuildFromWriteModelAsync()
    {
        await _readDb.Database.ExecuteSqlRawAsync("TRUNCATE TABLE ProductDetails");

        var products = await _writeDb.Products
            .Include(p => p.Category)
            .Include(p => p.Reviews)
            .ToListAsync();

        foreach (var product in products)
        {
            var readModel = new ProductDetailsReadModel
            {
                ProductId = product.Id,
                Name = product.Name,
                Price = product.Price,
                CategoryName = product.Category.Name,
                TotalReviews = product.Reviews.Count,
                AverageRating = product.Reviews.Any() 
                    ? product.Reviews.Average(r => r.Rating) 
                    : 0
            };

            await _readDb.ProductDetails.AddAsync(readModel);
        }

        await _readDb.SaveChangesAsync();
    }
}
```

## Scaling CQRS Read and Write Sides Independently

### Scaling Writes

```csharp
// Write side: focused on consistency
services.AddDbContext<WriteDbContext>(options =>
{
    options.UseNpgsql(writeConnectionString);
    // Strong consistency, ACID transactions
});

// Separate connection pool for writes
services.Configure<NpgsqlConnectionStringBuilder>(options =>
{
    options.MaxPoolSize = 20; // Moderate pool for writes
    options.CommandTimeout = 30;
});
```

### Scaling Reads

```csharp
// Read side: optimized for performance
services.AddDbContext<ReadDbContext>(options =>
{
    // Use read replicas
    options.UseNpgsql(readReplicaConnectionString);
    
    // Enable query splitting for better performance
    options.UseSplitQuery();
    
    // Read-only optimization
    options.UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking);
});

// Large connection pool for reads
services.Configure<NpgsqlConnectionStringBuilder>(options =>
{
    options.MaxPoolSize = 100; // Large pool for many concurrent reads
    options.CommandTimeout = 5; // Short timeout for reads
});

// Add caching
services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = redisConnectionString;
});

// Multiple read replicas with load balancing
services.AddDbContext<ReadDbContext>(options =>
{
    var replica = _replicaSelector.GetNextReplica(); // Round-robin or least-loaded
    options.UseNpgsql(replica.ConnectionString);
});
```

## When to Use CQRS

### Use CQRS When:

✅ **Read and write patterns differ significantly**
```
Example: Product catalog
- Writes: ~10/minute (updates from sellers)
- Reads: ~10,000/minute (customer browsing)
```

✅ **Complex business logic on writes**
```
Example: Order processing with validations, rules, constraints
```

✅ **Simple queries on reads**
```
Example: List orders, search products (no complex business logic)
```

✅ **Different scaling needs**
```
Example: 1 write instance, 10 read replicas
```

✅ **Different consistency requirements**
```
Example: Writes need strong consistency, reads can be eventually consistent
```

### Don't Use CQRS When:

❌ **Simple CRUD applications**: Overhead not justified  
❌ **Read/write patterns are similar**: No benefit from separation  
❌ **Small team**: Complexity burden is high  
❌ **Starting new project**: Wait until you have CQRS needs

## Practice Exercise

**Scenario**: E-commerce product reviews system

**Requirements:**
- Users submit reviews (writes are infrequent)
- Product pages show reviews (reads are very frequent)
- Need to show: average rating, review count, recent reviews
- Need to search reviews by rating, date, keywords

**Tasks** (25 minutes):

1. **Design Write Model**: What does the write model look like?
   - Tables: Reviews (Id, ProductId, UserId, Rating, Comment, CreatedDate)
   - Commands: SubmitReview, UpdateReview, DeleteReview

2. **Design Read Models**: Design 2-3 read models for:
   - Product page (reviews + aggregate rating)
     - ProductReviewSummary: ProductId, AverageRating, TotalReviews, RecentReviews[]
   - Search (keyword-searchable reviews)
     - ReviewSearchDocument: ReviewId, ProductId, Comment (indexed), Rating, Date
   - Analytics (ratings over time)
     - RatingAnalytics: ProductId, Date, RatingDistribution{1:count, 2:count, ...}

3. **Event Design**: What events are published on writes?
   - ReviewSubmittedEvent, ReviewUpdatedEvent, ReviewDeletedEvent

4. **Sync Strategy**: How do read models stay updated?
   - Event handlers listen to review events
   - Update all relevant read models

5. **Trade-offs**: What are the benefits and costs of CQRS here?
   - Benefits: Fast reads (precomputed aggregates), scale reads independently
   - Costs: Eventual consistency (review might not show immediately), complexity

6. **Consistency Concerns**: What if a user submits a review then immediately refreshes?
   - They might not see their review yet (eventual consistency)
   - Solutions: Return write model, version-based polling, or accept UX tradeoff

## CQRS Implementation Checklist

Planning to implement CQRS? Follow this checklist:

**Design Phase:**
- [ ] Identify commands (writes) and queries (reads)
- [ ] Design command models (write side)
- [ ] Design query models (read side) - may have multiple
- [ ] Define events to synchronize read models
- [ ] Choose databases for read and write sides
- [ ] Decide on consistency level (immediate vs eventual)

**Implementation Phase:**
- [ ] Implement command handlers (write side)
- [ ] Implement query handlers (read side)
- [ ] Implement event publishing from write side
- [ ] Implement projections/read model updaters
- [ ] Add read model versioning (handle out-of-order events)
- [ ] Implement read model rebuilding capability

**Operations Phase:**
- [ ] Monitor event processing lag
- [ ] Set up alerts for read model sync failures
- [ ] Plan for read model rebuilds (downtime strategy)
- [ ] Document consistency guarantees for stakeholders
- [ ] Test disaster recovery (rebuild read models)

1. **What does CQRS stand for and what does it mean?**
   - Command Query Responsibility Segregation
   - Separate models for reads (queries) and writes (commands)

2. **Is CQRS always used with event sourcing?**
   - No! Can use CQRS without event sourcing
   - But they work well together

3. **What's the main benefit of CQRS?**
   - Optimize reads and writes independently
   - Different scaling, different databases, different models

4. **What's the main cost of CRS?**
   - Complexity, eventual consistency, more code to maintain

---

## Key Takeaways

✅ **CQRS separates** read and write models

✅ **Optimize independently**: Different databases, scaling, models

✅ **Eventual consistency** between write and read sides

✅ **Works great with event sourcing** but can be used independently

✅ **Only use when justified** - adds complexity
