# Lesson 4: Projections, Sort, Skip, and Limit

## Learning Objectives

By the end of this lesson, you will be able to:
- Use projections to select specific fields from query results
- Sort query results in ascending or descending order
- Implement pagination using skip() and limit()
- Combine these operations for efficient data retrieval

---

## Introduction

When querying large datasets, you often don't need all fields from every document, and you want results in a specific order with controlled pagination. MongoDB provides powerful operations to shape and control query results: projections select fields, sort orders results, and skip/limit enable pagination.

## Key Concepts Summary

### Projections

**Include Specific Fields:**

```javascript
// Include only name and email (_id included by default)
db.users.find(
  {},
  { name: 1, email: 1 }
)

// Result:
{
  _id: ObjectId("..."),
  name: "Alice Johnson",
  email: "alice@example.com"
}
```

**Exclude Specific Fields:**

```javascript
// Exclude password field
db.users.find(
  {},
  { password: 0 }
)

// Exclude multiple fields
db.users.find(
  {},
  { password: 0, internal_notes: 0 }
)
```

**Exclude _id:**

```javascript
// Get name and email without _id
db.users.find(
  {},
  { _id: 0, name: 1, email: 1 }
)

// Result:
{
  name: "Alice Johnson",
  email: "alice@example.com"
}
```

**Important Rules:**
- Cannot mix inclusion and exclusion (except for _id)
- _id is included by default unless explicitly excluded

```javascript
// VALID: Include specific fields
db.users.find({}, { name: 1, email: 1 })

// VALID: Exclude specific fields
db.users.find({}, { password: 0, notes: 0 })

// VALID: Exclude _id with inclusions
db.users.find({}, { _id: 0, name: 1, email: 1 })

// INVALID: Mix inclusion and exclusion
db.users.find({}, { name: 1, password: 0 })  // Error!
```

**Nested Field Projections:**

```javascript
// Include nested fields
db.users.find(
  {},
  { "address.city": 1, "address.state": 1 }
)

// Exclude nested fields
db.users.find(
  {},
  { "profile.private_notes": 0 }
)
```

**Array Element Projections:**

```javascript
// $ operator - first matching array element
db.posts.find(
  { "comments.user": "alice" },
  { "comments.$": 1 }
)

// $slice - limit array elements
db.posts.find(
  {},
  { comments: { $slice: 5 } }  // First 5 comments
)

// $slice with skip
db.posts.find(
  {},
  { comments: { $slice: [10, 5] } }  // Skip 10, return 5
)

// Last N elements
db.posts.find(
  {},
  { comments: { $slice: -3 } }  // Last 3 comments
)
```

**$elemMatch in Projection:**

```javascript
// Project only matching array elements
db.students.find(
  {},
  { 
    scores: { 
      $elemMatch: { 
        subject: "math", 
        score: { $gt: 80 } 
      } 
    } 
  }
)
```

### Sorting

**Basic Sorting:**

```javascript
// Sort ascending (1)
db.users.find().sort({ age: 1 })

// Sort descending (-1)
db.users.find().sort({ age: -1 })

// Multiple fields
db.users.find().sort({ 
  status: 1,  // First by status (ascending)
  age: -1     // Then by age (descending)
})
```

**Sorting with Queries:**

```javascript
// Query with sort
db.products.find({ 
  category: "electronics" 
}).sort({ price: -1 })

// With projection
db.products.find(
  { category: "electronics" },
  { name: 1, price: 1 }
).sort({ price: -1 })
```

**Sorting on Nested Fields:**

```javascript
// Sort by nested field
db.users.find().sort({ "address.city": 1 })

// Multiple nested fields
db.orders.find().sort({ 
  "customer.lastname": 1,
  "customer.firstname": 1 
})
```

**Natural Order:**

```javascript
// Sort by insertion order
db.collection.find().sort({ $natural: 1 })

// Reverse insertion order
db.collection.find().sort({ $natural: -1 })
```

**Sort Performance:**
- Sorting uses indexes when available
- Without index, limited to 32MB of data
- Use indexes on frequently sorted fields

```javascript
// Create index for sorting
db.users.createIndex({ age: 1 })
db.products.createIndex({ category: 1, price: -1 })
```

### Limiting Results

**limit() - Maximum Number of Documents:**

```javascript
// Return first 10 documents
db.users.find().limit(10)

// With query
db.products.find({ 
  category: "electronics" 
}).limit(20)

// With sort
db.products.find()
  .sort({ price: -1 })
  .limit(5)  // Top 5 most expensive
```

**Zero and Negative Limits:**

```javascript
// limit(0) means no limit
db.users.find().limit(0)  // Returns all

// Negative values not allowed in modern MongoDB
```

### Skipping Documents

**skip() - Skip N Documents:**

```javascript
// Skip first 10 documents
db.users.find().skip(10)

// Pagination: Page 2 (skip 10, limit 10)
db.users.find()
  .skip(10)
  .limit(10)
```

**Skip Performance Warning:**
- skip() is slow for large offsets
- Database must scan and discard skipped documents
- Alternative: use range queries on indexed fields

### Combining Operations

**Order of Operations:**

```javascript
// Operations applied in this order regardless of syntax:
// 1. Filter (find)
// 2. Sort
// 3. Skip
// 4. Limit
// 5. Projection

// These are equivalent:
db.users.find({}, { name: 1 })
  .sort({ age: -1 })
  .skip(20)
  .limit(10)

db.users.find({}, { name: 1 })
  .limit(10)
  .skip(20)
  .sort({ age: -1 })
// MongoDB reorders internally for efficiency
```

**Complete Example:**

```javascript
// Get page 3 of active users, newest first
db.users.find(
  { status: "active" },           // Filter
  { name: 1, email: 1, joinDate: 1 }  // Projection
)
.sort({ joinDate: -1 })           // Newest first
.skip(20)                          // Skip pages 1-2
.limit(10)                         // Page size 10
```

### Pagination Patterns

**Offset-Based Pagination:**

```javascript
// Page 1
db.products.find()
  .sort({ _id: 1 })
  .limit(20)

// Page 2
db.products.find()
  .sort({ _id: 1 })
  .skip(20)
  .limit(20)

// Page N
const page = 3
const pageSize = 20
db.products.find()
  .sort({ _id: 1 })
  .skip((page - 1) * pageSize)
  .limit(pageSize)
```

**Cursor-Based (Keyset) Pagination:**

```javascript
// More efficient for large datasets

// Page 1
db.products.find()
  .sort({ _id: 1 })
  .limit(20)

// Get last _id from previous page
const lastId = ... // ObjectId from last result

// Page 2
db.products.find({ 
  _id: { $gt: lastId } 
})
.sort({ _id: 1 })
.limit(20)

// For descending sort
db.products.find({ 
  _id: { $lt: lastId } 
})
.sort({ _id: -1 })
.limit(20)
```

**Benefits of Cursor-Based:**
- Constant time performance regardless of page number
- No need to skip documents
- Requires indexed field for cursor

### Practical Examples

**Example 1: Recent Posts Feed**

```javascript
// Latest 20 posts with author info
db.posts.find(
  { published: true },
  { 
    title: 1, 
    excerpt: 1, 
    author: 1, 
    publishedDate: 1,
    _id: 1 
  }
)
.sort({ publishedDate: -1 })
.limit(20)
```

**Example 2: Product Listing with Pagination**

```javascript
// Products page with filters
const page = 2
const pageSize = 24

db.products.find(
  { 
    category: "electronics",
    price: { $lte: 500 },
    inStock: true
  },
  { 
    name: 1, 
    price: 1, 
    thumbnail: 1,
    rating: 1
  }
)
.sort({ rating: -1, price: 1 })
.skip((page - 1) * pageSize)
.limit(pageSize)
```

**Example 3: Leaderboard Top 10**

```javascript
// Top 10 users by score
db.users.find(
  { active: true },
  { 
    username: 1, 
    score: 1, 
    avatar: 1 
  }
)
.sort({ score: -1 })
.limit(10)
```

**Example 4: Infinite Scroll**

```javascript
// Initial load
const initialBatch = db.posts.find()
  .sort({ _id: -1 })
  .limit(20)
  .toArray()

const lastId = initialBatch[initialBatch.length - 1]._id

// Load more (next batch)
const nextBatch = db.posts.find({ 
  _id: { $lt: lastId } 
})
.sort({ _id: -1 })
.limit(20)
.toArray()
```

### Best Practices

**1. Always Use Projections:**
```javascript
// GOOD: Return only needed fields
db.users.find({}, { name: 1, email: 1 })

// AVOID: Returning entire large documents
db.users.find()  // Returns all fields
```

**2. Create Indexes for Sort:**
```javascript
// Create compound index for sort order
db.products.createIndex({ category: 1, price: -1 })

// Now this query uses index
db.products.find({ category: "electronics" })
  .sort({ price: -1 })
```

**3. Use Cursor-Based Pagination for Large Datasets:**
```javascript
// GOOD: For deep pagination
db.products.find({ _id: { $gt: lastId } }).limit(20)

// AVOID: skip() for large offsets
db.products.find().skip(10000).limit(20)  // Slow!
```

**4. Limit Result Sets:**
```javascript
// Always use limit for UI displays
db.posts.find().sort({ date: -1 }).limit(50)

// Avoid unbounded queries
```

**5. Count with Limits:**
```javascript
// For pagination metadata
const total = await db.products.countDocuments({ category: "electronics" })
const pages = Math.ceil(total / pageSize)
```
