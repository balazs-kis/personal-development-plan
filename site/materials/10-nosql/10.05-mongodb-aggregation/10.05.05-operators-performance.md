# Lesson 5: Aggregation Operators and Performance

## Learning Objectives

By the end of this lesson, you will be able to:
- Use arithmetic, string, date, and conditional operators in pipelines
- Apply array operators to manipulate and analyze arrays
- Optimize aggregation pipelines for performance
- Use explain plans to diagnose performance issues
- Understand memory limits and disk usage options

---

## Introduction

MongoDB's aggregation framework includes a rich library of operators for manipulating data: arithmetic calculations, string transformations, date extractions, conditional logic, and array operations. Mastering these operators enables sophisticated data transformations without application code. However, powerful pipelines can be resource-intensive. This lesson covers essential operators and teaches you to optimize pipelines using indexes, stage ordering, and explain plans to ensure your aggregations run efficiently even on large datasets.

## Key Concepts Summary

### Arithmetic Operators

**Common arithmetic operators:**

```javascript
// $add - Addition
{
  $project: {
    total: { $add: ["$price", "$tax", "$shipping"] }
  }
}

// $subtract - Subtraction
{
  $project: {
    profit: { $subtract: ["$revenue", "$cost"] }
  }
}

// $multiply - Multiplication
{
  $project: {
    lineTotal: { $multiply: ["$price", "$quantity"] }
  }
}

// $divide - Division
{
  $project: {
    unitPrice: { $divide: ["$total", "$quantity"] }
  }
}

// $mod - Modulo
{
  $project: {
    isEven: { $eq: [{ $mod: ["$value", 2] }, 0] }
  }
}

// $round, $ceil, $floor
{
  $project: {
    rounded: { $round: ["$price", 2] },      // Round to 2 decimals
    ceiling: { $ceil: "$price" },             // Round up
    floored: { $floor: "$price" }             // Round down
  }
}
```

### String Operators

**Common string operations:**

```javascript
{
  $project: {
    // Concatenation
    fullName: { $concat: ["$firstName", " ", "$lastName"] },
    
    // Case conversion
    upperName: { $toUpper: "$name" },
    lowerEmail: { $toLower: "$email" },
    
    // Substring
    firstInitial: { $substr: ["$firstName", 0, 1] },
    
    // String length
    nameLength: { $strLenCP: "$name" },
    
    // Trim whitespace
    cleaned: { $trim: { input: "$description" } },
    
    // Split string
    words: { $split: ["$sentence", " "] },
    
    // Replace
    sanitized: {
      $replaceAll: {
        input: "$text",
        find: "bad_word",
        replacement: "***"
      }
    }
  }
}
```

### Date Operators

**Extract date components:**

```javascript
{
  $project: {
    // Extract components
    year: { $year: "$createdAt" },
    month: { $month: "$createdAt" },
    day: { $dayOfMonth: "$createdAt" },
    hour: { $hour: "$createdAt" },
    dayOfWeek: { $dayOfWeek: "$createdAt" },  // 1=Sunday, 7=Saturday
    
    // Format date as string
    formattedDate: {
      $dateToString: {
        format: "%Y-%m-%d %H:%M:%S",
        date: "$createdAt"
      }
    },
    
    // Date arithmetic
    expirationDate: {
      $dateAdd: {
        startDate: "$createdAt",
        unit: "day",
        amount: 30
      }
    },
    
    // Date difference
    daysOld: {
      $dateDiff: {
        startDate: "$createdAt",
        endDate: "$$NOW",
        unit: "day"
      }
    }
  }
}
```

### Conditional Operators

**$cond - If/Then/Else:**

```javascript
{
  $project: {
    status: {
      $cond: {
        if: { $gte: ["$score", 60] },
        then: "Pass",
        else: "Fail"
      }
    }
  }
}

// Shorthand syntax
{
  $project: {
    status: {
      $cond: [{ $gte: ["$score", 60] }, "Pass", "Fail"]
    }
  }
}
```

**$switch - Multiple Conditions:**

```javascript
{
  $project: {
    grade: {
      $switch: {
        branches: [
          { case: { $gte: ["$score", 90] }, then: "A" },
          { case: { $gte: ["$score", 80] }, then: "B" },
          { case: { $gte: ["$score", 70] }, then: "C" },
          { case: { $gte: ["$score", 60] }, then: "D" }
        ],
        default: "F"
      }
    }
  }
}
```

**$ifNull - Handle Null Values:**

```javascript
{
  $project: {
    displayName: { $ifNull: ["$nickname", "$fullName", "Anonymous"] }
  }
}
```

### Array Operators

**Array operations:**

```javascript
{
  $project: {
    // Array size
    itemCount: { $size: "$items" },
    
    // Get element at index
    firstItem: { $arrayElemAt: ["$items", 0] },
    lastItem: { $arrayElemAt: ["$items", -1] },
    
    // Slice array
    topThree: { $slice: ["$items", 3] },
    
    // Check if array contains element
    hasTag: { $in: ["mongodb", "$tags"] },
    
    // Filter array
    activeItems: {
      $filter: {
        input: "$items",
        as: "item",
        cond: { $eq: ["$$item.status", "active"] }
      }
    },
    
    // Map array (transform elements)
    itemNames: {
      $map: {
        input: "$items",
        as: "item",
        in: "$$item.name"
      }
    },
    
    // Reduce array (aggregate)
    totalPrice: {
      $reduce: {
        input: "$items",
        initialValue: 0,
        in: { $add: ["$$value", "$$this.price"] }
      }
    },
    
    // Concatenate arrays
    allTags: { $concatArrays: ["$tags", "$categories"] }
  }
}
```

### Accumulator Operators (in $group)

**Summary of key accumulators:**

```javascript
{
  $group: {
    _id: "$category",
    
    // Count
    count: { $sum: 1 },
    
    // Sum values
    totalSales: { $sum: "$amount" },
    
    // Average
    avgPrice: { $avg: "$price" },
    
    // Min/Max
    minPrice: { $min: "$price" },
    maxPrice: { $max: "$price" },
    
    // First/Last (depends on sort order)
    firstOrder: { $first: "$orderDate" },
    lastOrder: { $last: "$orderDate" },
    
    // Collect into array
    allProducts: { $push: "$productName" },
    
    // Collect unique values
    uniqueCategories: { $addToSet: "$category" },
    
    // Standard deviation
    priceStdDev: { $stdDevPop: "$price" }
  }
}
```

## Performance Optimization

### 1. Index Usage

**Use indexes for early $match stages:**

```javascript
// Create index
db.orders.createIndex({ status: 1, orderDate: -1 });

// This pipeline uses the index
db.orders.aggregate([
  {
    $match: {
      status: "completed",
      orderDate: { $gte: ISODate("2026-01-01") }
    }
  },
  // ... other stages
]);
```

**Important:** 
- Only the first `$match` and `$sort` can use indexes
- Indexes are not used after stages like `$project`, `$unwind`, or `$lookup`

### 2. Stage Ordering

**Place filtering stages early:**

```javascript
// GOOD: Filter first (reduces data for later stages)
[
  { $match: { status: "active" } },       // Processes all docs
  { $unwind: "$items" },                   // Processes filtered docs
  { $group: { _id: "$category", ... } }    // Processes unwound docs
]

// BAD: Unwind everything first
[
  { $unwind: "$items" },                   // Processes all docs (expensive)
  { $match: { status: "active" } },       // Filters after expansion
  { $group: { _id: "$category", ... } }
]
```

**Projection optimization:**
- MongoDB automatically optimizes projections
- No need to manually place `$project` early for performance
- Use `$project` at the end for output shaping

### 3. Memory Limits

**Default limits:**
- Each stage limited to 100 MB RAM
- Entire pipeline limited to 100 MB per stage
- Exceeding limit throws error

**Solutions:**

**Option 1: Use allowDiskUse**
```javascript
db.collection.aggregate(
  [
    // ... pipeline stages
  ],
  { allowDiskUse: true }
);
```
- Allows stages to write temporary files to disk
- Slower but handles large datasets
- Use for sorting/grouping large amounts of data

**Option 2: Optimize the pipeline**
- Filter more aggressively early
- Use `$limit` when possible
- Break into smaller operations

### 4. Automatic Optimizations

MongoDB automatically optimizes pipelines:

**$match optimization:**
```javascript
// You write
[
  { $project: { name: 1, price: 1, category: 1 } },
  { $match: { category: "Electronics" } }
]

// MongoDB optimizes to
[
  { $match: { category: "Electronics" } },
  { $project: { name: 1, price: 1, category: 1 } }
]
```

**$sort + $limit optimization:**
```javascript
// Optimized to use a limited sort (only keeps top N in memory)
[
  { $sort: { price: -1 } },
  { $limit: 10 }
]
```

### 5. Using Explain

**Analyze pipeline performance:**

```javascript
db.collection.aggregate(
  [
    // ... pipeline stages
  ],
  { explain: true }
);
```

**Key metrics to check:**
- `executionTimeMillis` - Total execution time
- `totalDocsExamined` - Documents scanned
- `nReturned` - Documents returned
- `indexesUsed` - Which indexes were used
- `stage` details - Time spent in each stage

**Example explain output analysis:**

```javascript
{
  stages: [
    {
      $cursor: {
        queryPlanner: {
          winningPlan: {
            stage: "IXSCAN",  // Index scan (good!)
            indexName: "status_1_date_-1"
          }
        },
        executionStats: {
          totalDocsExamined: 1000,  // Scanned docs
          nReturned: 1000            // Returned docs
        }
      }
    },
    {
      $group: {
        // ... grouping details
      }
    }
  ],
  executionTimeMillis: 45
}
```

**Look for:**
- `IXSCAN` vs `COLLSCAN` (index scan vs collection scan)
- Ratio of examined to returned docs (lower is better)
- Stages using disk vs memory

### 6. Blocking vs Streaming Stages

**Streaming stages** (pass documents immediately):
- `$match`
- `$project`
- `$addFields`
- `$limit`
- `$skip`
- `$lookup`
- `$unwind`

**Blocking stages** (must accumulate all data):
- `$sort` (unless with `$limit`)
- `$group`
- `$bucket`
- `$facet`
- `$sortByCount`

**Strategy:** Minimize data before blocking stages.

## Complete Example: E-commerce Analytics

```javascript
// Optimized pipeline for product performance report
db.orders.aggregate([
  // Stage 1: Index-friendly filter
  {
    $match: {
      status: "completed",
      orderDate: {
        $gte: ISODate("2026-01-01"),
        $lt: ISODate("2026-02-01")
      }
    }
  },
  
  // Stage 2: Unwind items
  {
    $unwind: "$items"
  },
  
  // Stage 3: Filter to specific categories (after unwind)
  {
    $match: {
      "items.category": { $in: ["Electronics", "Computers"] }
    }
  },
  
  // Stage 4: Compute line totals
  {
    $addFields: {
      lineRevenue: {
        $multiply: ["$items.price", "$items.quantity"]
      },
      discountAmount: {
        $multiply: [
          "$items.price",
          "$items.quantity",
          { $divide: ["$items.discountPercent", 100] }
        ]
      }
    }
  },
  
  // Stage 5: Group by product
  {
    $group: {
      _id: "$items.productId",
      productName: { $first: "$items.productName" },
      category: { $first: "$items.category" },
      totalRevenue: { $sum: "$lineRevenue" },
      totalDiscount: { $sum: "$discountAmount" },
      unitsSold: { $sum: "$items.quantity" },
      orderCount: { $sum: 1 },
      avgPrice: { $avg: "$items.price" }
    }
  },
  
  // Stage 6: Calculate metrics
  {
    $addFields: {
      netRevenue: { $subtract: ["$totalRevenue", "$totalDiscount"] },
      avgOrderSize: { $divide: ["$unitsSold", "$orderCount"] }
    }
  },
  
  // Stage 7: Sort by net revenue
  {
    $sort: { netRevenue: -1 }
  },
  
  // Stage 8: Top 50 products
  {
    $limit: 50
  },
  
  // Stage 9: Shape output
  {
    $project: {
      _id: 0,
      productId: "$_id",
      productName: 1,
      category: 1,
      totalRevenue: { $round: ["$totalRevenue", 2] },
      netRevenue: { $round: ["$netRevenue", 2] },
      unitsSold: 1,
      orderCount: 1,
      avgPrice: { $round: ["$avgPrice", 2] },
      avgOrderSize: { $round: ["$avgOrderSize", 1] }
    }
  }
], {
  allowDiskUse: true  // For large datasets
});
```

## Practice Exercise

After completing the materials, try this exercise (do not spend more than 25 minutes):

Given an `events` collection tracking user activity:

```javascript
{
  _id: 1,
  userId: "user123",
  eventType: "page_view",
  pagePath: "/products/laptop",
  duration: 45,  // seconds
  timestamp: ISODate("2026-01-27T10:30:00Z"),
  metadata: {
    device: "mobile",
    country: "USA"
  }
}
```

Write optimized aggregation pipelines to:

1. **User engagement metrics**
   - Group by userId
   - Calculate: total events, total duration, avg session length
   - Find most common event type per user
   - Only include users with > 10 events
   - Sort by total duration descending

2. **Hourly activity pattern**
   - Extract hour of day from timestamp
   - Count events per hour
   - Calculate avg duration per hour
   - Show which event types are most common each hour

3. **Geographic analysis with computed score**
   - Group by country
   - Count unique users per country
   - Calculate "engagement score": (total_events × avg_duration) / user_count
   - Filter to countries with > 100 events
   - Add a tier: "High" if score > 500, "Medium" if > 200, else "Low"

4. **Performance optimization challenge**
   - Write explain plan for geographic analysis
   - Identify which indexes would help
   - Estimate memory usage for the grouping stage
   - Consider if allowDiskUse is needed
