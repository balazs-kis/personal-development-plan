## Learning Objectives

By the end of this lesson, you will be able to:

## Introduction

How you query your data significantly influences database choice. OLTP (transactional) and OLAP (analytical) workloads have fundamentally different characteristics and performance requirements. Understanding your query patterns—simple lookups vs complex joins vs aggregations—helps you select the right database technology.

## Key Concepts Summary

### OLTP vs OLAP

#### OLTP (Online Transaction Processing)

**Purpose:** Support day-to-day business operations with fast, short transactions.

**Characteristics:**
- ⚡ Low latency (milliseconds)
- 📝 Simple queries (CRUD operations)
- 🔄 High concurrency (many users)
- 💾 Small data volumes per query
- ✅ ACID compliance required
- 📊 Normalized data model

**Typical Operations:**
```sql
-- Insert order
INSERT INTO orders (customer_id, order_date, total)
VALUES (123, GETDATE(), 99.99);

-- Retrieve order
SELECT * FROM orders WHERE order_id = 12345;

-- Update inventory
UPDATE products SET stock = stock - 1 WHERE product_id = 67;

-- Delete cart item
DELETE FROM cart_items WHERE cart_id = 789 AND item_id = 456;
```

**Use Cases:**
- E-commerce transactions
- Banking operations
- Reservation systems
- Point-of-sale (POS)
- Order management
- Inventory tracking

**Best Databases:**
- PostgreSQL
- SQL Server
- MySQL
- Oracle
- MongoDB (for document-based transactions)

---

#### OLAP (Online Analytical Processing)

**Purpose:** Support complex analytics and business intelligence on large datasets.

**Characteristics:**
- 📊 Complex queries (aggregations, joins)
- 🐌 Higher latency (seconds to minutes)
- 👥 Few concurrent users
- 💿 Large data volumes processed
- 📈 Read-heavy workload
- 🗂️ Denormalized data model (star/snowflake schema)

**Typical Operations:**
```sql
-- Sales by region and quarter
SELECT 
    r.region_name,
    DATE_TRUNC('quarter', o.order_date) as quarter,
    SUM(o.total_amount) as total_sales,
    COUNT(DISTINCT o.customer_id) as unique_customers,
    AVG(o.total_amount) as avg_order_value
FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
JOIN regions r ON c.region_id = r.region_id
WHERE o.order_date >= '2023-01-01'
GROUP BY r.region_name, DATE_TRUNC('quarter', o.order_date)
ORDER BY total_sales DESC;

-- Year-over-year growth
WITH yearly_sales AS (
    SELECT 
        EXTRACT(YEAR FROM order_date) as year,
        SUM(total_amount) as sales
    FROM orders
    GROUP BY EXTRACT(YEAR FROM order_date)
)
SELECT 
    year,
    sales,
    sales - LAG(sales) OVER (ORDER BY year) as growth,
    ((sales - LAG(sales) OVER (ORDER BY year)) / LAG(sales) OVER (ORDER BY year)) * 100 as growth_pct
FROM yearly_sales;
```

**Use Cases:**
- Business intelligence dashboards
- Trend analysis
- Forecasting
- Customer segmentation
- Financial reporting
- Data mining

**Best Databases:**
- Data Warehouses (Snowflake, Redshift, BigQuery)
- OLAP Cubes (SQL Server Analysis Services)
- Column stores (ClickHouse, Druid)
- Analytical engines (Apache Spark)

---

### Comparison Table

| Aspect | OLTP | OLAP |
|--------|------|------|
| **Purpose** | Daily operations | Analytics & reporting |
| **Users** | Thousands | Tens |
| **Query Type** | Simple, predefined | Complex, ad-hoc |
| **Response Time** | Milliseconds | Seconds to minutes |
| **Data Volume** | KB per transaction | GB-TB per query |
| **Data Age** | Current | Historical |
| **Normalization** | Normalized (3NF) | Denormalized (star) |
| **Updates** | Frequent | Rare (batch loads) |
| **Index Strategy** | B-tree indexes | Columnar, bitmap |
| **Example Query** | Get order #12345 | Total sales by region |

## Query Pattern Types

### 1. Key Lookups (Simple Reads)

**Pattern:** Retrieve single record by primary key.

```csharp
// SQL
var order = await _db.QueryFirstOrDefaultAsync<Order>(
    "SELECT * FROM orders WHERE order_id = @Id",
    new { Id = 12345 }
);

// NoSQL (MongoDB)
var order = await _orders
    .Find(o => o.Id == "12345")
    .FirstOrDefaultAsync();

// NoSQL (Redis)
var order = await _redis.StringGetAsync("order:12345");
```

**Best For:**
- ✅ Key-Value stores (Redis, DynamoDB)
- ✅ Document databases (MongoDB)
- ✅ SQL with proper indexing

**Performance:**
- SQL: 1-10ms (with index)
- NoSQL: <1ms (key lookup)

---

### 2. Simple Filters (WHERE clauses)

**Pattern:** Filter by non-key columns.

```csharp
// Get orders for specific customer
var orders = await _db.QueryAsync<Order>(
    "SELECT * FROM orders WHERE customer_id = @CustomerId",
    new { CustomerId = 123 }
);

// MongoDB equivalent
var orders = await _orders
    .Find(o => o.CustomerId == 123)
    .ToListAsync();
```

**Best For:**
- ✅ SQL with indexes on filter columns
- ✅ Document databases (MongoDB)
- ⚠️ Key-Value stores (requires secondary indexes)

**Performance:**
- Depends on indexing
- SQL with index: 1-50ms
- MongoDB with index: 1-20ms
- Without index: Full scan (slow)

---

### 3. Complex Joins

**Pattern:** Combine data from multiple tables/collections.

```csharp
// SQL - Natural fit
var result = await _db.QueryAsync<OrderDetails>(@"
    SELECT 
        o.order_id,
        c.customer_name,
        p.product_name,
        oi.quantity,
        oi.price
    FROM orders o
    JOIN customers c ON o.customer_id = c.customer_id
    JOIN order_items oi ON o.order_id = oi.order_id
    JOIN products p ON oi.product_id = p.product_id
    WHERE o.order_date >= @StartDate
", new { StartDate = DateTime.Now.AddDays(-30) });

// MongoDB - Less natural, requires $lookup or denormalization
var pipeline = new[]
{
    new BsonDocument("$match", new BsonDocument("orderDate", 
        new BsonDocument("$gte", DateTime.Now.AddDays(-30)))),
    new BsonDocument("$lookup", new BsonDocument
    {
        { "from", "customers" },
        { "localField", "customerId" },
        { "foreignField", "_id" },
        { "as", "customer" }
    }),
    new BsonDocument("$unwind", "$customer"),
    new BsonDocument("$lookup", new BsonDocument
    {
        { "from", "products" },
        { "localField", "items.productId" },
        { "foreignField", "_id" },
        { "as", "products" }
    })
};

var results = await _orders.Aggregate<OrderDetails>(pipeline).ToListAsync();
```

**Best For:**
- ✅ SQL databases (designed for joins)
- ⚠️ Document databases (denormalize or use $lookup)
- ❌ Key-Value stores (not suitable)

**When to Denormalize (NoSQL):**
```javascript
// Instead of joining, embed related data
{
  "_id": "order_123",
  "customer": {
    "id": 456,
    "name": "John Doe",
    "email": "john@example.com"
  },
  "items": [
    {
      "product_id": "prod_789",
      "product_name": "Laptop",
      "quantity": 1,
      "price": 999.99
    }
  ]
}
```

---

### 4. Aggregations

**Pattern:** Summarize data (SUM, COUNT, AVG, etc.).

```csharp
// SQL - Optimized for aggregations
var summary = await _db.QueryFirstAsync<SalesSummary>(@"
    SELECT 
        COUNT(*) as total_orders,
        SUM(total_amount) as total_sales,
        AVG(total_amount) as avg_order_value,
        MAX(total_amount) as largest_order
    FROM orders
    WHERE order_date >= @StartDate
", new { StartDate = DateTime.Now.AddMonths(-1) });

// MongoDB - Aggregation pipeline
var pipeline = new[]
{
    new BsonDocument("$match", new BsonDocument("orderDate", 
        new BsonDocument("$gte", DateTime.Now.AddMonths(-1)))),
    new BsonDocument("$group", new BsonDocument
    {
        { "_id", BsonNull.Value },
        { "totalOrders", new BsonDocument("$sum", 1) },
        { "totalSales", new BsonDocument("$sum", "$totalAmount") },
        { "avgOrderValue", new BsonDocument("$avg", "$totalAmount") },
        { "largestOrder", new BsonDocument("$max", "$totalAmount") }
    })
};

var summary = await _orders.Aggregate<SalesSummary>(pipeline).FirstOrDefaultAsync();
```

**Best For:**
- ✅ Column-store databases (ClickHouse, Redshift)
- ✅ SQL databases
- ✅ Document databases (aggregation framework)
- ⚠️ Key-Value stores (requires client-side aggregation)

---

### 5. Full-Text Search

**Pattern:** Search text content.

```csharp
// SQL (limited capabilities)
var products = await _db.QueryAsync<Product>(@"
    SELECT * FROM products
    WHERE CONTAINS(description, @SearchTerm)
    OR name LIKE @Pattern
", new { SearchTerm = "laptop", Pattern = "%laptop%" });

// Elasticsearch (purpose-built)
var searchResponse = await _elastic.SearchAsync<Product>(s => s
    .Query(q => q
        .MultiMatch(m => m
            .Query("gaming laptop")
            .Fields(f => f
                .Field(p => p.Name, boost: 2.0)
                .Field(p => p.Description)
            )
        )
    )
    .Highlight(h => h
        .Fields(f => f.Field(p => p.Description))
    )
);
```

**Best For:**
- ✅ Search engines (Elasticsearch, Solr)
- ⚠️ SQL (basic capabilities)
- ⚠️ MongoDB (text indexes)
- ❌ Key-Value stores

## Access Pattern Analysis

### Single-Entity Access

**Pattern:** Access one entity at a time.

```csharp
// Example: User profile page
var user = await GetUserAsync(userId);
var preferences = await GetUserPreferencesAsync(userId);
```

**Best Database:**
- Document database (MongoDB) - embed related data
- Key-Value store (DynamoDB) - if truly key-based

**Why:**
- No joins needed
- Single document/record fetch
- Low latency

---

### Multi-Entity Relationships

**Pattern:** Frequently need data from multiple entities.

```csharp
// Example: Order details with customer, products, shipping
var orderDetails = await GetOrderWithDetailsAsync(orderId);
// Needs: order, customer, products, shipping info
```

**Best Database:**
- SQL database - natural joins
- Document database - denormalize if read-heavy

**Why:**
- Relationships are core to the data model
- Normalization reduces redundancy
- Referential integrity important

---

### Time-Series Data

**Pattern:** Time-stamped events, append-only.

```csharp
// Example: Sensor readings
public class SensorReading
{
    public string SensorId { get; set; }
    public DateTime Timestamp { get; set; }
    public double Temperature { get; set; }
    public double Humidity { get; set; }
}

// Query: Recent readings for sensor
var readings = await _db.QueryAsync<SensorReading>(@"
    SELECT * FROM sensor_readings
    WHERE sensor_id = @SensorId
    AND timestamp >= @StartTime
    ORDER BY timestamp DESC
    LIMIT 100
", new { SensorId = "sensor_1", StartTime = DateTime.UtcNow.AddHours(-1) });
```

**Best Database:**
- Time-series (InfluxDB, TimescaleDB)
- Column store (ClickHouse)
- Wide-column (Cassandra)

**Why:**
- Optimized for time-range queries
- High write throughput
- Efficient compression
- Downsampling and retention policies

## Decision Framework

### Use SQL When:

✅ **Query patterns include:**
- Complex joins across multiple tables
- ACID transactions required
- Frequent updates to existing records
- Ad-hoc queries (unknown at design time)
- Strong referential integrity

```csharp
// Example: Financial system
public async Task TransferFundsAsync(int fromAccount, int toAccount, decimal amount)
{
    using var transaction = _db.BeginTransaction();
    
    await _db.ExecuteAsync(
        "UPDATE accounts SET balance = balance - @Amount WHERE account_id = @From",
        new { Amount = amount, From = fromAccount }
    );
    
    await _db.ExecuteAsync(
        "UPDATE accounts SET balance = balance + @Amount WHERE account_id = @To",
        new { Amount = amount, To = toAccount }
    );
    
    await _db.ExecuteAsync(
        "INSERT INTO transactions (from_account, to_account, amount) VALUES (@From, @To, @Amount)",
        new { From = fromAccount, To = toAccount, Amount = amount }
    );
    
    transaction.Commit();
}
```

---

### Use NoSQL When:

✅ **Query patterns include:**
- Key-based lookups (get by ID)
- Denormalized/embedded data
- Flexible schema needed
- High write throughput
- Eventual consistency acceptable

```csharp
// Example: Product catalog
public class Product
{
    public string Id { get; set; }
    public string Name { get; set; }
    public string Description { get; set; }
    public List<string> Images { get; set; }
    public Dictionary<string, object> Specifications { get; set; } // Flexible
    public List<Review> Reviews { get; set; } // Embedded
}

public async Task<Product> GetProductAsync(string productId)
{
    // Single document fetch, all data embedded
    return await _products.Find(p => p.Id == productId).FirstOrDefaultAsync();
}
```

## Best Practices

1. **Profile Your Queries:**
   - Identify most frequent operations
   - Measure query performance
   - Understand data access patterns

2. **Design for Access Patterns:**
   - NoSQL: Model based on queries
   - SQL: Model based on relationships

3. **Consider Hybrid:**
   - SQL for transactions
   - NoSQL for catalog
   - Search engine for full-text
   - Cache for hot data

4. **Monitor Query Performance:**
   - Slow query logs
   - Query profiling
   - Index usage analysis

5. **Test with Realistic Data:**
   - Representative volume
   - Actual query patterns
   - Concurrent load
