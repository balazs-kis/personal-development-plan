## Introduction

Most real-world queries filter on multiple fields, sort results, or combine both. While you could create separate indexes for each field, a well-designed compound index can support multiple query patterns efficiently. The key to effective compound indexes is field ordering, governed by the ESR (Equality, Sort, Range) rule. This principle ensures your index supports equality matches first, then sorts, and finally range conditions—maximizing selectivity and minimizing documents examined. Mastering compound indexes is essential for optimizing complex queries.

## Key Concepts Summary

### What Are Compound Indexes?

Compound indexes reference multiple fields in a specific order:

```javascript
// Compound index on two fields
db.orders.createIndex({ customerId: 1, orderDate: -1 })

// Index stores entries like:
(customerId: "cust123", orderDate: 2026-01-20) → doc1
(customerId: "cust123", orderDate: 2026-01-15) → doc2
(customerId: "cust456", orderDate: 2026-01-25) → doc3
```

**Key characteristic:** Fields are ordered hierarchically—like a phone book sorted by last name, then first name.

### Creating Compound Indexes

**Syntax:**
```javascript
db.collection.createIndex({
  <field1>: <1 or -1>,
  <field2>: <1 or -1>,
  <field3>: <1 or -1>,
  // ... up to 32 fields
})
```

**Example:**
```javascript
// E-commerce orders
db.orders.createIndex({
  status: 1,        // Equality field
  orderDate: -1,    // Sort field
  total: 1          // Range field
})
```

### Index Prefixes

A compound index supports queries on any **prefix** of its fields:

```javascript
// Index
db.orders.createIndex({ a: 1, b: 1, c: 1 })

// Supports queries on:
// ✅ {a}
// ✅ {a, b}
// ✅ {a, b, c}

// Does NOT support:
// ❌ {b}
// ❌ {c}
// ❌ {b, c}
```

**Example:**
```javascript
// Create compound index
db.products.createIndex({ category: 1, price: 1, name: 1 })

// These queries use the index:
db.products.find({ category: "Electronics" })
db.products.find({ category: "Electronics", price: { $gt: 100 } })
db.products.find({ category: "Electronics", price: { $gt: 100 }, name: /^Samsung/ })

// These DO NOT use the index:
db.products.find({ price: { $gt: 100 } })  // Missing prefix field
db.products.find({ name: "Laptop" })        // Missing prefix field
```

### The ESR Rule: Equality, Sort, Range

The ESR rule optimizes compound index field ordering:

**E - Equality fields first**
- Fields with exact matches (`=`, `$in`)
- Most selective filters
- Reduce the result set immediately

**S - Sort fields second**
- Fields used in `sort()`
- Placed after equality, before range
- Avoids in-memory sorts

**R - Range fields last**
- Fields with range queries (`$gt`, `$lt`, `$gte`, `$lte`, `$ne`)
- Least selective
- Placed at the end

### ESR Rule Examples

**Example 1: E-commerce Query**

```javascript
// Query: Find active orders from last month, sorted by date
db.orders.find({
  status: "active",           // Equality
  orderDate: { $gte: lastMonth }  // Range
}).sort({ orderDate: -1 })    // Sort

// ESR order: Equality (status), Sort (orderDate), Range (orderDate)
// But orderDate is used for both sort and range!

// Correct index:
db.orders.createIndex({ status: 1, orderDate: -1 })
// - status (Equality) comes first
// - orderDate handles both Sort and Range
```

**Example 2: User Search**

```javascript
// Query: Find users in a country, age range, sorted by name
db.users.find({
  country: "USA",                // Equality
  age: { $gte: 25, $lte: 35 }   // Range
}).sort({ lastName: 1 })         // Sort

// ESR order: Equality, Sort, Range
db.users.createIndex({ country: 1, lastName: 1, age: 1 })
```

**Example 3: Multiple Equality Fields**

```javascript
// Query: Find products by category and brand
db.products.find({
  category: "Electronics",  // Equality
  brand: "Samsung",        // Equality
  price: { $lt: 1000 }     // Range
}).sort({ name: 1 })       // Sort

// ESR order
db.products.createIndex({
  category: 1,   // Equality
  brand: 1,      // Equality
  name: 1,       // Sort
  price: 1       // Range
})
```

### Index Direction in Compound Indexes

For compound indexes, field direction **matters** when sorting:

**Rule:** Reverse the entire index if you reverse the sort order.

```javascript
// Index
db.orders.createIndex({ status: 1, orderDate: -1 })

// Supports these sort patterns efficiently:
db.orders.find({ status: "active" }).sort({ orderDate: -1 })  // ✅ Matches index
db.orders.find({ status: "active" }).sort({ orderDate: 1 })   // ✅ Reverse also works

// Supports these sort patterns efficiently:
db.orders.find({ status: "active" }).sort({ status: 1, orderDate: -1 })  // ✅ Matches
db.orders.find({ status: "active" }).sort({ status: -1, orderDate: 1 })  // ✅ Full reverse
```

**Mixed sort directions:**
```javascript
// Index
db.events.createIndex({ type: 1, date: -1, priority: 1 })

// Supports:
sort({ type: 1, date: -1, priority: 1 })   // ✅ Matches exactly
sort({ type: -1, date: 1, priority: -1 })  // ✅ Full reverse

// Does NOT efficiently support:
sort({ type: 1, date: 1, priority: 1 })    // ❌ Mixed directions
sort({ type: -1, date: -1, priority: 1 })  // ❌ Mixed directions
```

### Compound vs Multiple Single Indexes

**Scenario:** Query filters on two fields

**Option 1: Two single-field indexes (❌ Suboptimal)**
```javascript
db.products.createIndex({ category: 1 })
db.products.createIndex({ price: 1 })

db.products.find({ category: "Electronics", price: { $gt: 100 } })
// MongoDB might use index intersection, but it's inefficient
```

**Option 2: One compound index (✅ Optimal)**
```javascript
db.products.createIndex({ category: 1, price: 1 })

db.products.find({ category: "Electronics", price: { $gt: 100 } })
// Efficiently uses one index lookup
```

**Why compound is better:**
- Predictable performance
- Fewer index keys examined
- No overhead of merging results from multiple indexes
- Supports index-only (covered) queries

### Covered Queries with Compound Indexes

A **covered query** returns results entirely from the index without accessing documents:

```javascript
// Create compound index
db.users.createIndex({ country: 1, age: 1, email: 1 })

// Covered query (all fields in index)
db.users.find(
  { country: "USA", age: { $gte: 25 } },
  { _id: 0, email: 1 }  // Project only indexed field
)

// Returns email directly from index
// No document access needed
// Verify with explain(): totalDocsExamined = 0
```

### Real-World Example: Blog Platform

```javascript
// Use case: Blog posts with these queries:
// 1. Recent posts by author
// 2. Published posts sorted by date
// 3. Posts by category in date range

// Single compound index can support all:
db.posts.createIndex({
  status: 1,          // Equality: "published"
  category: 1,        // Equality: specific category
  publishDate: -1,    // Sort: newest first (and range)
  authorId: 1         // Equality: specific author
})

// Query 1: Recent posts by author
db.posts.find({
  status: "published",
  authorId: "author123"
}).sort({ publishDate: -1 })
// Uses: status, authorId (reordered internally), publishDate

// Query 2: Published posts sorted by date
db.posts.find({
  status: "published"
}).sort({ publishDate: -1 })
// Uses: status, publishDate

// Query 3: Posts by category in date range
db.posts.find({
  status: "published",
  category: "Technology",
  publishDate: { $gte: ISODate("2026-01-01") }
}).sort({ publishDate: -1 })
// Uses: status, category, publishDate
```

### Compound Index Limitations

**1. Maximum 32 fields:**
```javascript
// Valid
db.collection.createIndex({ f1: 1, f2: 1, ..., f32: 1 })

// Invalid
db.collection.createIndex({ f1: 1, f2: 1, ..., f33: 1 })  // ❌ Too many
```

**2. At most one array field per compound index:**
```javascript
// Document
{
  tags: ["mongodb", "database"],
  categories: ["tech", "tutorial"]
}

// Invalid: Two array fields
db.posts.createIndex({ tags: 1, categories: 1 })  // ❌ Error

// Valid: One array field
db.posts.createIndex({ tags: 1, author: 1 })  // ✅ OK
```

**3. Text index with other fields:**
```javascript
// Only one text field allowed in compound index
db.articles.createIndex({
  category: 1,
  content: "text"  // Only one text field
})
```
