# Lesson 1: Input Validation Strategies

## Learning Objectives

By the end of this lesson, you will be able to:
- Implement server-side input validation using multiple strategies
- Apply allowlisting principles to accept only known good input
- Use data annotations and model validation in ASP.NET Core
- Understand syntactic vs. semantic validation
- Validate data from all untrusted sources

---

## Introduction

Input validation is the first line of defense in secure coding. Most vulnerabilities stem from accepting untrusted input without proper validation. This lesson covers validation strategies that ensure only properly formed data enters your system, preventing malformed data from corrupting databases and triggering vulnerabilities in downstream components.

**Key principle:** Never trust user input. Validate everything on the server side, as client-side validation can be bypassed.

## Key Concepts Summary

### Server-Side Validation is Mandatory

```csharp
// Client-side validation is for UX only - NEVER trust it for security
[ApiController]
[Route("api/[controller]")]
public class UsersController : ControllerBase
{
    [HttpPost]
    public IActionResult CreateUser([FromBody] CreateUserRequest request)
    {
        // Always validate server-side
        if (!ModelState.IsValid)
        {
            return BadRequest(ModelState);
        }
        
        // Process validated data
        return Ok();
    }
}
```

### Allowlisting vs Denylisting

```csharp
// BAD: Denylisting - trying to block bad patterns (easily bypassed)
public bool IsValidUsername_Bad(string username)
{
    return !username.Contains("<") && 
           !username.Contains(">") && 
           !username.Contains("script");
}

// GOOD: Allowlisting - accepting only known good patterns
[RegularExpression(@"^[a-zA-Z0-9_]{3,20}$", 
    ErrorMessage = "Username must be 3-20 alphanumeric characters or underscores")]
public string Username { get; set; }
```

### Data Annotations for Validation

```csharp
public class CreateUserRequest
{
    [Required(ErrorMessage = "Username is required")]
    [StringLength(20, MinimumLength = 3, 
        ErrorMessage = "Username must be between 3 and 20 characters")]
    [RegularExpression(@"^[a-zA-Z0-9_]+$", 
        ErrorMessage = "Username can only contain letters, numbers, and underscores")]
    public string Username { get; set; }
    
    [Required]
    [EmailAddress(ErrorMessage = "Invalid email format")]
    public string Email { get; set; }
    
    [Required]
    [Range(18, 120, ErrorMessage = "Age must be between 18 and 120")]
    public int Age { get; set; }
    
    [Url(ErrorMessage = "Invalid URL format")]
    public string Website { get; set; }
}
```

### Syntactic vs Semantic Validation

```csharp
public class BookingRequest
{
    // Syntactic: Correct format/type
    [Required]
    [DataType(DataType.Date)]
    public DateTime CheckInDate { get; set; }
    
    [Required]
    [DataType(DataType.Date)]
    public DateTime CheckOutDate { get; set; }
    
    // Semantic: Business logic validation
    public IEnumerable<ValidationResult> Validate(ValidationContext validationContext)
    {
        if (CheckOutDate <= CheckInDate)
        {
            yield return new ValidationResult(
                "Check-out date must be after check-in date",
                new[] { nameof(CheckOutDate) });
        }
        
        if (CheckInDate < DateTime.Today)
        {
            yield return new ValidationResult(
                "Check-in date cannot be in the past",
                new[] { nameof(CheckInDate) });
        }
    }
}
```

### Custom Validation Attributes

```csharp
public class FutureDateAttribute : ValidationAttribute
{
    protected override ValidationResult IsValid(object value, ValidationContext validationContext)
    {
        if (value is DateTime dateValue)
        {
            if (dateValue > DateTime.Now)
            {
                return ValidationResult.Success;
            }
            return new ValidationResult("Date must be in the future");
        }
        return new ValidationResult("Invalid date format");
    }
}

// Usage
public class Event
{
    [FutureDate]
    public DateTime EventDate { get; set; }
}
```

### Validating Collections

```csharp
public class OrderRequest
{
    [Required]
    [MinLength(1, ErrorMessage = "At least one item is required")]
    [MaxLength(100, ErrorMessage = "Maximum 100 items allowed")]
    public List<OrderItem> Items { get; set; }
}

public class OrderItem
{
    [Required]
    [Range(1, int.MaxValue)]
    public int ProductId { get; set; }
    
    [Required]
    [Range(1, 999, ErrorMessage = "Quantity must be between 1 and 999")]
    public int Quantity { get; set; }
}
```

## Practice Exercise

After completing the materials, try this exercise (do not spend more than 10 minutes):

Create a `ProductRequest` model with the following validation requirements:
- `Name`: Required, 3-100 characters, alphanumeric with spaces allowed
- `Price`: Required, between 0.01 and 999999.99
- `Category`: Required, must be one of: "Electronics", "Clothing", "Food", "Books"
- `StockQuantity`: Required, between 0 and 10000
- `ReleaseDate`: Optional, but if provided must be a valid date not in the future

Implement both data annotations and a custom semantic validation method.
