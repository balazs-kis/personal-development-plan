## Introduction

The Principle of Least Privilege (PoLP) is a fundamental security concept: users, applications, and systems should have only the minimum access rights necessary to perform their specific functions. This principle limits the potential damage from accidents, errors, or malicious actions by restricting what any single entity can do.

## Key Concepts Summary

### Core Principles

```csharp
// Bad: Service has unnecessary admin access
public class OrderService
{
    private readonly IDbConnection _connection; // Uses admin connection string
    
    public async Task<Order> GetOrder(int orderId)
    {
        // This service can read/write/delete anything in the database
        return await _connection.QuerySingleAsync<Order>(
            "SELECT * FROM Orders WHERE Id = @Id", 
            new { Id = orderId });
    }
}

// Good: Service has read-only access to specific tables
public class OrderService
{
    private readonly IDbConnection _connection; // Uses read-only role
    
    public async Task<Order> GetOrder(int orderId)
    {
        // Database user can only SELECT from Orders table
        return await _connection.QuerySingleAsync<Order>(
            "SELECT * FROM Orders WHERE Id = @Id", 
            new { Id = orderId });
    }
}
```

### Role-Based Access Control (RBAC)

```csharp
// Define roles with minimal permissions
public static class Roles
{
    public const string OrderViewer = "order-viewer";    // Can only read orders
    public const string OrderManager = "order-manager";  // Can read and update orders
    public const string OrderAdmin = "order-admin";      // Full order management
}

[Authorize(Roles = Roles.OrderViewer)]
public async Task<IActionResult> GetOrder(int id)
{
    // Only users with order-viewer role or higher can access
    return Ok(await _orderService.GetOrderAsync(id));
}

[Authorize(Roles = Roles.OrderManager)]
public async Task<IActionResult> UpdateOrder(int id, UpdateOrderRequest request)
{
    // Requires higher privilege level
    return Ok(await _orderService.UpdateOrderAsync(id, request));
}
```

### Attribute-Based Access Control (ABAC)

```csharp
// Policy-based authorization with fine-grained attributes
public class ResourceBasedAuthorizationHandler : 
    AuthorizationHandler<OperationAuthorizationRequirement, Order>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        OperationAuthorizationRequirement requirement,
        Order resource)
    {
        var userId = context.User.GetUserId();
        
        // Users can only access their own orders
        if (resource.CustomerId == userId)
        {
            context.Succeed(requirement);
        }
        // Managers can access orders in their department
        else if (context.User.IsInRole("Manager") && 
                 resource.Department == context.User.GetDepartment())
        {
            context.Succeed(requirement);
        }
        
        return Task.CompletedTask;
    }
}
```

### Just-In-Time (JIT) Access

```csharp
// Temporary elevated permissions that expire
public class TemporaryAccessService
{
    public async Task<TemporaryAccessToken> GrantTemporaryAccess(
        string userId, 
        string resource, 
        TimeSpan duration)
    {
        var token = new TemporaryAccessToken
        {
            UserId = userId,
            Resource = resource,
            ExpiresAt = DateTime.UtcNow.Add(duration),
            Token = GenerateSecureToken()
        };
        
        await _tokenStore.SaveAsync(token);
        
        // Schedule automatic revocation
        _scheduler.Schedule(() => RevokeAccess(token.Token), duration);
        
        return token;
    }
}
```

### Preventing Privilege Creep

**Regular Access Reviews:**
- Audit permissions quarterly
- Remove access that's no longer needed
- Review role assignments

**Least Privilege by Default:**
- New accounts start with minimal access
- Require justification for privilege grants
- Time-limit elevated permissions
