## Introduction

Threat modeling is a structured process for identifying, understanding, and prioritizing potential security threats to a system. Rather than discovering vulnerabilities after deployment, threat modeling helps you find and fix design issues early in development. It's about asking "What could go wrong?" before it does.

## Key Concepts Summary

### The Four Question Framework

```
1. What are we working on?
   └─> Create architecture/data flow diagrams

2. What can go wrong?
   └─> Apply STRIDE or other frameworks

3. What are we going to do about it?
   └─> Define mitigations and controls

4. Did we do a good job?
   └─> Review and validate
```

### STRIDE Methodology

```csharp
// STRIDE: Six threat categories

// S - Spoofing Identity
// Attacker pretends to be someone else
public class SpoofingExample
{
    // Threat: Attacker uses stolen JWT token
    // Mitigation: Short-lived tokens, strong signature validation
    [Authorize]
    public IActionResult GetUserData()
    {
        // Verify token signature (prevents spoofing)
        // Check token expiration
        // Validate issuer and audience
        return Ok(_userService.GetData(User.GetUserId()));
    }
}

// T - Tampering with Data
// Unauthorized modification of data
public class TamperingExample
{
    // Threat: Attacker modifies data in transit or at rest
    // Mitigation: HTTPS, message signing, integrity checks
    public async Task<Order> GetOrderAsync(int orderId)
    {
        var encryptedData = await _repository.GetAsync(orderId);
        
        // Verify HMAC to detect tampering
        if (!_crypto.VerifyHmac(encryptedData))
            throw new SecurityException("Data integrity check failed");
        
        return _crypto.Decrypt(encryptedData);
    }
}

// R - Repudiation
// User denies performing an action
public class RepudiationExample
{
    // Threat: User claims they didn't make a transaction
    // Mitigation: Comprehensive audit logging
    public async Task<IActionResult> TransferFunds(TransferRequest request)
    {
        // Log with non-repudiable evidence
        await _auditLog.LogAsync(new AuditEntry
        {
            UserId = User.GetUserId(),
            Action = "TransferFunds",
            Details = JsonSerializer.Serialize(request),
            Timestamp = DateTime.UtcNow,
            IpAddress = HttpContext.Connection.RemoteIpAddress?.ToString(),
            UserAgent = HttpContext.Request.Headers["User-Agent"],
            // Could also include: digital signature, MFA verification
        });
        
        await _paymentService.TransferAsync(request);
        return Ok();
    }
}

// I - Information Disclosure
// Exposure of sensitive information
public class InformationDisclosureExample
{
    // Threat: Attacker gains access to sensitive data
    // Mitigation: Encryption, access controls, data masking
    public IActionResult GetCustomer(int customerId)
    {
        var customer = _customerService.GetById(customerId);
        
        // Don't expose sensitive data in responses
        return Ok(new CustomerDto
        {
            Id = customer.Id,
            Name = customer.Name,
            Email = MaskEmail(customer.Email),
            // Never include: SSN, passwords, credit cards
        });
    }
    
    private string MaskEmail(string email)
    {
        var parts = email.Split('@');
        if (parts.Length != 2) return email;
        
        var masked = parts[0].Length > 2 
            ? $"{parts[0][0]}***{parts[0][^1]}@{parts[1]}"
            : $"***@{parts[1]}";
        
        return masked;
    }
}

// D - Denial of Service
// System becomes unavailable
public class DenialOfServiceExample
{
    // Threat: Attacker overwhelms system with requests
    // Mitigation: Rate limiting, resource quotas, input validation
    [RateLimit(100, TimeSpan.FromMinutes(1))]
    [MaxRequestSize(1024 * 1024)] // 1 MB max
    public async Task<IActionResult> ProcessData([FromBody] DataRequest request)
    {
        // Validate input size to prevent resource exhaustion
        if (request.Items?.Count > 1000)
            return BadRequest("Too many items");
        
        // Set operation timeout
        using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(30));
        
        var result = await _processor.ProcessAsync(request, cts.Token);
        return Ok(result);
    }
}

// E - Elevation of Privilege
// Attacker gains unauthorized permissions
public class ElevationOfPrivilegeExample
{
    // Threat: User bypasses authorization checks
    // Mitigation: Robust authorization, input validation
    [Authorize]
    public async Task<IActionResult> DeleteUser(int userId)
    {
        // Verify user has permission to delete (not just authenticated)
        var currentUserId = User.GetUserId();
        
        // Check authorization at multiple levels
        if (!await _authService.CanDeleteUser(currentUserId, userId))
            return Forbid();
        
        // Verify not deleting admin users unless caller is admin
        var targetUser = await _userService.GetByIdAsync(userId);
        if (targetUser.IsAdmin && !User.IsInRole("Admin"))
            return Forbid();
        
        await _userService.DeleteAsync(userId);
        return NoContent();
    }
}
```

### Simple Threat Modeling Process

```
Step 1: Diagram the System
┌─────────────┐      ┌─────────────┐      ┌─────────────┐
│   Browser   │─────▶│   Web API   │─────▶│  Database   │
└─────────────┘      └─────────────┘      └─────────────┘
      (1)                  (2)                  (3)

Step 2: Identify Threats Using STRIDE
(1) Browser → API
    - S: Attacker spoofs user identity with stolen token
    - T: Attacker modifies request in transit
    - I: Attacker intercepts sensitive data

(2) API → Database  
    - I: SQL injection exposes data
    - T: Attacker modifies queries
    - E: Attacker escalates to admin privileges

Step 3: Mitigations
(1) Browser → API
    - S: Use short-lived JWTs, validate signature
    - T: Use HTTPS with TLS 1.3
    - I: Encrypt sensitive data in payload

(2) API → Database
    - I: Use parameterized queries, least privilege DB user
    - T: Use prepared statements, validate input
    - E: Implement authorization checks, use database roles

Step 4: Validate
- Code review authorization implementation
- Penetration test authentication
- Security scan for SQL injection
- Verify HTTPS configuration
```

### When to Threat Model

```
Continuous Threat Modeling:

┌─ Design Phase ────────────────────────────────┐
│ • Initial threat model                        │
│ • Identify major threats                      │
│ • Design security controls                    │
└───────────────────────────────────────────────┘
                    ↓
┌─ Development Phase ───────────────────────────┐
│ • Update model as design changes              │
│ • Validate controls during code review        │
└───────────────────────────────────────────────┘
                    ↓
┌─ Testing Phase ───────────────────────────────┐
│ • Test identified threats                     │
│ • Verify mitigations are effective            │
└───────────────────────────────────────────────┘
                    ↓
┌─ Production ──────────────────────────────────┐
│ • Monitor for new threats                     │
│ • Update after security incidents             │
│ • Revisit after major changes                 │
└───────────────────────────────────────────────┘
```

## Practice Exercise

After completing the materials, try this exercise (do not spend more than 15 minutes):

Create a simple threat model for an API endpoint that allows users to upload profile pictures:

1. **Draw the data flow:** User → API → Storage
2. **Apply STRIDE to each component:**
   - What could go wrong at each step?
3. **Identify 3 threats** (one from any STRIDE category)
4. **Define mitigations** for each threat

Example format:
- **Threat:** (S) Attacker uploads malicious file pretending to be an image
- **Mitigation:** Validate file type, scan for malware, enforce size limits
