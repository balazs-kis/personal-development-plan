## Introduction

OpenID Connect (OIDC) is an authentication layer built on top of OAuth 2.0. While OAuth 2.0 answers "what can this application access?" (authorization), OpenID Connect answers "who is this user?" (authentication).

OIDC adds standardized authentication features to OAuth 2.0, making it the de facto standard for modern web and mobile authentication, including "Login with Google," "Login with Microsoft," and similar single sign-on flows.

## Key Concepts Summary

### OAuth 2.0 vs OpenID Connect

```
┌─────────────────────────────────────────────────────────┐
│ OAuth 2.0                                               │
│ • Authorization framework                               │
│ • "What can the app access?"                            │
│ • Access tokens (opaque or JWT)                         │
│ • Scopes define permissions                             │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ OpenID Connect (Built on OAuth 2.0)                     │
│ • Authentication protocol                               │
│ • "Who is the user?"                                    │
│ • ID tokens (always JWT)                                │
│ • Standard claims for user identity                     │
└─────────────────────────────────────────────────────────┘
```

### Key Addition: The `openid` Scope

The magic that turns OAuth 2.0 into OIDC:

```
OAuth 2.0 Request:
  scope=profile email

OpenID Connect Request:
  scope=openid profile email
         ↑
         Adding "openid" makes it an OIDC request
```

When you include the `openid` scope, the authorization server returns an **ID token** in addition to the access token.

## OpenID Connect Flow

### Standard OIDC Authorization Code Flow

```
┌────────┐                                      ┌──────────────┐
│ Client │                                      │ OIDC Provider│
└───┬────┘                                      └───────┬──────┘
    │                                                   │
    │ 1. Authorization Request                         │
    │    + scope=openid profile email                  │
    │    + response_type=code                          │
    │    + code_challenge (PKCE)                       │
    ├──────────────────────────────────────────────────>│
    │                                                   │
    │                           2. User authenticates   │
    │                              and grants consent   │
    │                                                   │
    │ 3. Authorization Code                            │
    │<──────────────────────────────────────────────────┤
    │                                                   │
    │ 4. Token Request                                 │
    │    + authorization_code                          │
    │    + code_verifier (PKCE)                        │
    ├──────────────────────────────────────────────────>│
    │                                                   │
    │ 5. Token Response                                │
    │    + access_token                                │
    │    + id_token      ← NEW: User identity         │
    │    + refresh_token (optional)                    │
    │<──────────────────────────────────────────────────┤
    │                                                   │
    │ 6. Validate ID token                             │
    │    → Extract user claims                         │
    │                                                   │
    │ 7. (Optional) Call UserInfo endpoint             │
    │    with access_token                             │
    ├──────────────────────────────────────────────────>│
    │                                                   │
    │ 8. Additional user claims                        │
    │<──────────────────────────────────────────────────┤
    │                                                   │
```

## ID Tokens

### What is an ID Token?

An **ID token** is a JSON Web Token (JWT) that contains verified information about the authenticated user.

**Structure:**
```
Header.Payload.Signature

eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

**Decoded payload:**
```json
{
  "iss": "https://accounts.example.com",  // Issuer
  "sub": "248289761001",                   // Subject (user ID)
  "aud": "your-client-id",                 // Audience (your app)
  "exp": 1516239022,                       // Expiration time
  "iat": 1516239000,                       // Issued at
  "nonce": "n-0S6_WzA2Mj",                // CSRF protection
  "name": "John Doe",                      // User's name
  "email": "john.doe@example.com",         // User's email
  "email_verified": true,                  // Email verification status
  "picture": "https://example.com/photo"   // Profile picture URL
}
```

### ID Token vs Access Token

| ID Token | Access Token |
|----------|--------------|
| **Purpose:** Authentication | **Purpose:** Authorization |
| **Audience:** Client application | **Audience:** Resource server (API) |
| **Format:** Always JWT | **Format:** Opaque or JWT |
| **Contains:** User identity claims | **Contains:** Scopes/permissions |
| **Used for:** Login, display user info | **Used for:** API requests |
| **Validated by:** Client application | **Validated by:** Resource server |
| **Lifetime:** Short (minutes to hours) | **Lifetime:** Short (minutes to hours) |

```csharp
// ID Token: "Who is the user?"
var idToken = tokenResponse.IdToken;
var userClaims = ParseIdToken(idToken);
Console.WriteLine($"Hello, {userClaims.Name}!");

// Access Token: "What can the user access?"
var accessToken = tokenResponse.AccessToken;
var response = await httpClient.GetAsync("/api/profile", 
    headers: new { Authorization = $"Bearer {accessToken}" });
```

## OIDC Scopes and Claims

### Standard OIDC Scopes

| Scope | Claims Included |
|-------|----------------|
| `openid` | **Required.** Makes it an OIDC request. Returns `sub` (subject/user ID) |
| `profile` | Name, family name, given name, nickname, picture, website, gender, birthdate, locale, updated_at |
| `email` | Email address, email_verified |
| `address` | Formatted address, street, locality, region, postal code, country |
| `phone` | Phone number, phone_number_verified |

### Example Scope Request

```
GET /authorize?
  response_type=code&
  client_id=your-client-id&
  redirect_uri=https://your-app.com/callback&
  scope=openid profile email&
  state=abc123&
  nonce=xyz789
```

**Result:** ID token will contain:
- `sub` (from `openid`)
- `name`, `picture`, `locale`, etc. (from `profile`)
- `email`, `email_verified` (from `email`)

## Standard Claims

### Always Present in ID Token

```json
{
  "iss": "https://auth.example.com",   // Issuer (who issued the token)
  "sub": "248289761001",                // Subject (unique user ID)
  "aud": "your-client-id",              // Audience (your application)
  "exp": 1516239022,                    // Expiration (Unix timestamp)
  "iat": 1516239000                     // Issued at (Unix timestamp)
}
```

### Conditional Claims (based on scopes)

```json
{
  // profile scope
  "name": "John Doe",
  "given_name": "John",
  "family_name": "Doe",
  "nickname": "johnny",
  "picture": "https://example.com/john.jpg",
  "updated_at": 1516239000,
  
  // email scope
  "email": "john.doe@example.com",
  "email_verified": true,
  
  // phone scope
  "phone_number": "+1 (555) 123-4567",
  "phone_number_verified": false
}
```

## UserInfo Endpoint

The **UserInfo endpoint** provides additional claims about the authenticated user using the access token.

**When to use:**
- ID token is too large (ID tokens go in URLs, have size limits)
- You need claims not included in the ID token
- You need fresh user data (ID tokens are static once issued)

```csharp
// After getting access token from token response
var userInfoRequest = new HttpRequestMessage(HttpMethod.Get, 
    "https://auth.example.com/userinfo");
userInfoRequest.Headers.Authorization = 
    new AuthenticationHeaderValue("Bearer", accessToken);

var response = await httpClient.SendAsync(userInfoRequest);
var userInfo = await response.Content.ReadFromJsonAsync<UserInfo>();

Console.WriteLine($"Name: {userInfo.Name}");
Console.WriteLine($"Email: {userInfo.Email}");
```

**UserInfo response:**
```json
{
  "sub": "248289761001",
  "name": "John Doe",
  "email": "john.doe@example.com",
  "email_verified": true,
  "picture": "https://example.com/john.jpg"
}
```

**Important:** The `sub` claim in UserInfo response **must** match the `sub` claim in the ID token.

## Implementation Example

### ASP.NET Core OIDC Configuration

```csharp
// Program.cs
builder.Services.AddAuthentication(options =>
{
    options.DefaultScheme = CookieAuthenticationDefaults.AuthenticationScheme;
    options.DefaultChallengeScheme = OpenIdConnectDefaults.AuthenticationScheme;
})
.AddCookie()
.AddOpenIdConnect(options =>
{
    // OIDC Provider settings
    options.Authority = "https://login.microsoftonline.com/{tenant-id}/v2.0";
    options.ClientId = "your-client-id";
    options.ClientSecret = "your-client-secret";
    
    // OIDC-specific settings
    options.ResponseType = OpenIdConnectResponseType.Code;  // Authorization Code Flow
    options.UsePkce = true;  // Enable PKCE
    
    // Scopes
    options.Scope.Clear();
    options.Scope.Add("openid");     // Required for OIDC
    options.Scope.Add("profile");
    options.Scope.Add("email");
    
    // Save tokens for later use
    options.SaveTokens = true;
    
    // Map claims
    options.TokenValidationParameters = new TokenValidationParameters
    {
        NameClaimType = "name",
        RoleClaimType = "roles"
    };
    
    // Events
    options.Events = new OpenIdConnectEvents
    {
        OnTokenValidated = context =>
        {
            // Access ID token claims
            var idToken = context.SecurityToken as JwtSecurityToken;
            var name = idToken?.Claims.FirstOrDefault(c => c.Type == "name")?.Value;
            Console.WriteLine($"User {name} authenticated");
            return Task.CompletedTask;
        }
    };
});

// Enable authentication
app.UseAuthentication();
app.UseAuthorization();
```

### Accessing User Claims in Controllers

```csharp
[Authorize]
public class ProfileController : Controller
{
    public IActionResult Index()
    {
        // User claims from ID token
        var userId = User.FindFirst("sub")?.Value;
        var name = User.Identity?.Name;
        var email = User.FindFirst("email")?.Value;
        
        // Access stored tokens
        var accessToken = await HttpContext.GetTokenAsync("access_token");
        var idToken = await HttpContext.GetTokenAsync("id_token");
        var refreshToken = await HttpContext.GetTokenAsync("refresh_token");
        
        return View(new ProfileViewModel
        {
            UserId = userId,
            Name = name,
            Email = email
        });
    }
}
```

## Discovery Document

OIDC providers publish a **discovery document** at a well-known URL that describes their configuration.

**Discovery URL format:**
```
https://{authority}/.well-known/openid-configuration
```

**Example:**
```
https://login.microsoftonline.com/common/v2.0/.well-known/openid-configuration
```

**Discovery document content:**
```json
{
  "issuer": "https://login.microsoftonline.com/{tenant}/v2.0",
  "authorization_endpoint": "https://login.microsoftonline.com/{tenant}/oauth2/v2.0/authorize",
  "token_endpoint": "https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token",
  "userinfo_endpoint": "https://graph.microsoft.com/oidc/userinfo",
  "jwks_uri": "https://login.microsoftonline.com/common/discovery/v2.0/keys",
  "response_types_supported": ["code", "id_token", "code id_token"],
  "scopes_supported": ["openid", "profile", "email", "offline_access"],
  "claims_supported": ["sub", "name", "email", "picture", ...],
  "grant_types_supported": ["authorization_code", "refresh_token", "client_credentials"]
}
```

Most OIDC libraries automatically fetch and use the discovery document.

## Security Considerations

### Always Validate ID Tokens

```csharp
// Validation checklist
✅ Signature is valid (using JWKS from discovery document)
✅ Issuer (iss) matches expected provider
✅ Audience (aud) matches your client ID
✅ Expiration (exp) has not passed
✅ Nonce matches the one you sent (CSRF protection)
```

### Nonce Parameter

The **nonce** parameter prevents replay attacks:

```csharp
// 1. Generate random nonce before authorization request
string nonce = GenerateRandomString();
HttpContext.Session.SetString("nonce", nonce);

// 2. Include in authorization request
var authUrl = $"{authorizationEndpoint}?...&nonce={nonce}";

// 3. Validate nonce in ID token matches
var idToken = ParseIdToken(tokenResponse.IdToken);
var receivedNonce = idToken.Claims.First(c => c.Type == "nonce").Value;

if (receivedNonce != HttpContext.Session.GetString("nonce"))
{
    throw new SecurityException("Nonce mismatch");
}
```

## Common Patterns

### Login Flow

```
1. User clicks "Login"
2. App redirects to OIDC provider
3. User authenticates
4. Provider redirects back with code
5. App exchanges code for tokens
6. App validates ID token
7. App extracts claims and creates session
8. User is logged in
```

### Logout Flow

```
1. User clicks "Logout"
2. App clears local session
3. App redirects to OIDC provider's logout endpoint
4. Provider clears SSO session
5. Provider redirects back to app
6. User is fully logged out
```
