# Lesson 5: Account Enumeration Prevention

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand how account enumeration attacks work
- Implement consistent error messages across authentication flows
- Prevent timing attacks through constant-time operations
- Secure registration, login, and password reset flows
- Apply defense-in-depth strategies for account enumeration prevention

---

## Introduction

Account enumeration allows attackers to determine which usernames or email addresses exist in a system. Attackers use this information to build targeted attack lists, conduct credential stuffing, or plan social engineering attacks. Preventing enumeration requires careful attention to error messages, response timing, and behavior consistency across all authentication flows.

## Key Concepts Summary

### How Account Enumeration Works

```csharp
// VULNERABLE: Different error messages reveal account existence

[HttpPost]
public async Task<IActionResult> Login(LoginViewModel model)
{
    var user = await _userManager.FindByEmailAsync(model.Email);
    
    if (user == null)
    {
        // BAD: Reveals that email doesn't exist
        ModelState.AddModelError("", "No account found with that email");
        return View(model);
    }
    
    var result = await _signInManager.CheckPasswordSignInAsync(
        user,
        model.Password,
        lockoutOnFailure: false);
    
    if (!result.Succeeded)
    {
        // BAD: Reveals that email exists but password is wrong
        ModelState.AddModelError("", "Incorrect password");
        return View(model);
    }
    
    await _signInManager.SignInAsync(user, false);
    return RedirectToAction("Index", "Home");
}

// Attacker can enumerate accounts:
// 1. Try login with test@example.com + any password
//    Response: "No account found" = Account doesn't exist
// 2. Try login with admin@example.com + any password
//    Response: "Incorrect password" = Account exists!
```

### Consistent Error Messages

```csharp
// SECURE: Generic error message for all login failures

[HttpPost]
public async Task<IActionResult> Login(LoginViewModel model)
{
    if (!ModelState.IsValid)
        return View(model);
    
    // Try to sign in
    var result = await _signInManager.PasswordSignInAsync(
        model.Email,
        model.Password,
        model.RememberMe,
        lockoutOnFailure: true);
    
    if (result.Succeeded)
    {
        return RedirectToAction("Index", "Home");
    }
    
    if (result.IsLockedOut)
    {
        return View("Lockout");
    }
    
    if (result.RequiresTwoFactor)
    {
        return RedirectToAction("LoginWith2fa", new
        {
            ReturnUrl = model.ReturnUrl,
            RememberMe = model.RememberMe
        });
    }
    
    // GOOD: Same generic message regardless of whether
    // the account exists or the password is wrong
    ModelState.AddModelError("", "Invalid email or password");
    return View(model);
}

// Attacker cannot determine if account exists:
// test@example.com + any password → "Invalid email or password"
// admin@example.com + any password → "Invalid email or password"
// Both responses are identical
```

### Timing Attack Prevention

```csharp
// Timing attacks: Measure response time differences
// - Account exists → password hash verification takes time
// - Account doesn't exist → immediate response

// VULNERABLE: Timing reveals account existence
public async Task<bool> ValidateLoginAsync(string email, string password)
{
    var user = await _userManager.FindByEmailAsync(email);
    
    if (user == null)
    {
        return false; // Fast response (~1ms)
    }
    
    // Slow response (~250ms due to bcrypt)
    return await _userManager.CheckPasswordAsync(user, password);
}

// SECURE: Constant-time operation
public async Task<bool> ValidateLoginSecureAsync(string email, string password)
{
    var user = await _userManager.FindByEmailAsync(email);
    
    if (user == null)
    {
        // Perform dummy hash operation to match timing
        var dummyHasher = new PasswordHasher<string>();
        dummyHasher.VerifyHashedPassword(null, 
            "$2a$12$dummyHashToMatchTiming", 
            password);
        
        return false; // Now takes ~250ms like real verification
    }
    
    return await _userManager.CheckPasswordAsync(user, password);
}

// Both paths take approximately the same time
// Attacker cannot use timing to determine account existence
```

### Registration Enumeration Prevention

```csharp
// VULNERABLE: Registration reveals existing accounts

[HttpPost]
public async Task<IActionResult> Register(RegisterViewModel model)
{
    var existingUser = await _userManager.FindByEmailAsync(model.Email);
    
    if (existingUser != null)
    {
        // BAD: Reveals email is already registered
        ModelState.AddModelError("", "Email already in use");
        return View(model);
    }
    
    // Create user...
}

// SECURE: Don't reveal if email exists

[HttpPost]
public async Task<IActionResult> Register(RegisterViewModel model)
{
    if (!ModelState.IsValid)
        return View(model);
    
    var existingUser = await _userManager.FindByEmailAsync(model.Email);
    
    if (existingUser != null)
    {
        // GOOD: Send email to existing account instead of showing error
        await _emailService.SendEmailAsync(
            model.Email,
            "Registration Attempt",
            $"Someone tried to register with your email. " +
            $"If this wasn't you, please secure your account.");
        
        // Show success message even though registration didn't happen
        TempData["Message"] = 
            "Please check your email to confirm your account";
        return RedirectToAction("RegisterConfirmation");
    }
    
    // Proceed with actual registration
    var user = new ApplicationUser
    {
        UserName = model.Email,
        Email = model.Email
    };
    
    var result = await _userManager.CreateAsync(user, model.Password);
    
    if (result.Succeeded)
    {
        // Send confirmation email
        var token = await _userManager.GenerateEmailConfirmationTokenAsync(user);
        var callbackUrl = Url.Action("ConfirmEmail", "Account",
            new { userId = user.Id, token }, Request.Scheme);
        
        await _emailService.SendEmailAsync(
            model.Email,
            "Confirm your email",
            $"Please confirm your account by clicking this link: {callbackUrl}");
        
        TempData["Message"] = 
            "Please check your email to confirm your account";
        return RedirectToAction("RegisterConfirmation");
    }
    
    // Show generic error
    ModelState.AddModelError("", "Registration failed. Please try again");
    return View(model);
}
```

### Password Reset Enumeration Prevention

```csharp
// VULNERABLE: Password reset reveals account existence

[HttpPost]
public async Task<IActionResult> ForgotPassword(ForgotPasswordViewModel model)
{
    var user = await _userManager.FindByEmailAsync(model.Email);
    
    if (user == null)
    {
        // BAD: Reveals account doesn't exist
        ModelState.AddModelError("", "No account found with that email");
        return View(model);
    }
    
    if (!await _userManager.IsEmailConfirmedAsync(user))
    {
        // BAD: Reveals account exists but email not confirmed
        ModelState.AddModelError("", "Email not confirmed");
        return View(model);
    }
    
    // Send reset email...
}

// SECURE: Always show success message

[HttpPost]
public async Task<IActionResult> ForgotPassword(ForgotPasswordViewModel model)
{
    if (!ModelState.IsValid)
        return View(model);
    
    var user = await _userManager.FindByEmailAsync(model.Email);
    
    if (user != null && await _userManager.IsEmailConfirmedAsync(user))
    {
        // Account exists and is confirmed - send reset email
        var token = await _userManager.GeneratePasswordResetTokenAsync(user);
        var callbackUrl = Url.Action("ResetPassword", "Account",
            new { token }, Request.Scheme);
        
        await _emailService.SendEmailAsync(
            model.Email,
            "Reset Password",
            $"Please reset your password by clicking: {callbackUrl}");
        
        _logger.LogInformation($"Password reset email sent to {model.Email}");
    }
    else
    {
        // Account doesn't exist or email not confirmed
        // Log but don't reveal to user
        _logger.LogInformation(
            $"Password reset attempted for non-existent/unconfirmed email: {model.Email}");
    }
    
    // GOOD: Always show same success message
    TempData["Message"] = 
        "If an account exists with that email, " +
        "you will receive a password reset link.";
    
    return RedirectToAction("ForgotPasswordConfirmation");
}

// Attacker cannot determine if account exists:
// test@example.com → "If an account exists..."
// admin@example.com → "If an account exists..."
```

### Response Length Consistency

```csharp
// Ensure HTTP response lengths are consistent

public class ResponsePaddingMiddleware
{
    private readonly RequestDelegate _next;
    
    public async Task InvokeAsync(HttpContext context)
    {
        var originalBodyStream = context.Response.Body;
        
        using var memoryStream = new MemoryStream();
        context.Response.Body = memoryStream;
        
        await _next(context);
        
        memoryStream.Seek(0, SeekOrigin.Begin);
        var responseBody = await new StreamReader(memoryStream).ReadToEndAsync();
        
        // Add padding to normalize response length (for JSON responses)
        if (context.Response.ContentType?.Contains("application/json") ?? false)
        {
            const int targetLength = 1024; // Target response length
            
            if (responseBody.Length < targetLength)
            {
                var padding = new string(' ', targetLength - responseBody.Length);
                responseBody = responseBody.TrimEnd('}') + 
                    $",\"_padding\":\"{padding}\"}}";
            }
        }
        
        var bytes = Encoding.UTF8.GetBytes(responseBody);
        context.Response.ContentLength = bytes.Length;
        
        await originalBodyStream.WriteAsync(bytes);
    }
}

// Note: This adds complexity and may not be necessary for most applications
// Use only when facing sophisticated attackers analyzing response lengths
```

### Username Policy

```csharp
// Avoid predictable usernames that enable enumeration

// BAD: Predictable username pattern
// john.smith → j.smith → jsmith → jsmith1, jsmith2...
// Attacker can easily guess variations

// GOOD: Use email addresses or random usernames
public class UserService
{
    public async Task<IdentityResult> CreateUserAsync(string email, string password)
    {
        var user = new ApplicationUser
        {
            // Use email as username (unique and user-provided)
            UserName = email,
            Email = email,
            
            // Or generate random username
            // UserName = GenerateRandomUsername(),
            
            EmailConfirmed = false
        };
        
        return await _userManager.CreateAsync(user, password);
    }
    
    private string GenerateRandomUsername()
    {
        // Generate cryptographically random username
        var bytes = new byte[16];
        using var rng = RandomNumberGenerator.Create();
        rng.GetBytes(bytes);
        
        return $"user_{Convert.ToBase64String(bytes)
            .Replace("+", "")
            .Replace("/", "")
            .Replace("=", "")
            .Substring(0, 16)}";
    }
}
```

### Rate Limiting for Enumeration

```csharp
// Apply rate limiting to prevent automated enumeration

public class EnumerationRateLimiter
{
    public async Task<bool> CheckRateLimitAsync(
        HttpContext context,
        string operation)
    {
        var ipAddress = context.Connection.RemoteIpAddress?.ToString();
        var key = $"ratelimit:{operation}:{ipAddress}";
        
        var attempts = await _cache.GetStringAsync(key);
        var count = int.Parse(attempts ?? "0");
        
        if (count >= 10) // 10 attempts per hour
        {
            _logger.LogWarning(
                $"Rate limit exceeded for {operation} from {ipAddress}");
            return false;
        }
        
        await _cache.SetStringAsync(
            key,
            (count + 1).ToString(),
            new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(1)
            });
        
        return true;
    }
}

// Apply to registration endpoint
[HttpPost]
public async Task<IActionResult> Register(RegisterViewModel model)
{
    if (!await _rateLimiter.CheckRateLimitAsync(HttpContext, "register"))
    {
        return StatusCode(429, "Too many registration attempts");
    }
    
    // Proceed with registration...
}
```
