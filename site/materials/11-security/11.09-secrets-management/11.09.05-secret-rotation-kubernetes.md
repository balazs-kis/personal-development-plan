## Introduction

Secret rotation—the practice of regularly changing credentials—is a critical security control that limits the impact of compromised secrets. This lesson covers rotation strategies, automation approaches, and how to manage secrets in Kubernetes environments. You'll learn about blue/green rotation, Kubernetes Secrets, and external secret operators that integrate with secret stores.

**Key principle:** Automate secret rotation wherever possible. Manual rotation is error-prone and often neglected.

## Key Concepts Summary

### Why Rotate Secrets?

```
Reasons to Rotate:
✅ Limit blast radius if secret is compromised
✅ Reduce time window for exploitation
✅ Comply with security policies and regulations
✅ Protect against former employee access
✅ Detect and respond to security incidents

Rotation Frequency Guidelines:
- Highly sensitive (production DB): 30-90 days
- Moderately sensitive (API keys): 90-180 days
- Less sensitive (read-only): 180-365 days
- After any security incident: Immediately
- After employee departure: Within 24 hours
```

### Blue/Green Secret Rotation Strategy

```
Phase 1: Create Green Version
┌─────────┐         ┌─────────┐
│  Blue   │         │  Green  │
│ (Active)│         │  (New)  │
└─────────┘         └─────────┘
    ↓                    
All services use Blue

Phase 2: Transition Period
┌─────────┐         ┌─────────┐
│  Blue   │    →    │  Green  │
│         │         │         │
└─────────┘         └─────────┘
    ↓                    ↓
50% use Blue      50% use Green

Phase 3: Complete Migration
┌─────────┐         ┌─────────┐
│  Blue   │         │  Green  │
│(Retired)│         │ (Active)│
└─────────┘         └─────────┘
                         ↓
                 All services use Green

Phase 4: Cleanup
                        ┌─────────┐
                        │  Green  │
                        │ (Active)│
                        └─────────┘
                             ↓
Blue is deleted     All services use Green
```

### Implementing Blue/Green Rotation

```csharp
public class BlueGreenRotationService
{
    private readonly SecretClient _secretClient;
    
    // Phase 1: Create new version
    public async Task<string> CreateGreenVersionAsync(string secretName, string newValue)
    {
        // Store with version marker
        await _secretClient.SetSecretAsync($"{secretName}-green", newValue);
        
        // Mark as active in metadata
        var properties = (await _secretClient.GetSecretAsync($"{secretName}-green"))
            .Value.Properties;
        properties.Tags["status"] = "transitioning";
        await _secretClient.UpdateSecretPropertiesAsync(properties);
        
        return "green";
    }
    
    // Phase 2: Gradual rollout
    public async Task<string> GetSecretForService(string secretName, string serviceId)
    {
        // Use hash-based routing for gradual migration
        var hash = serviceId.GetHashCode();
        var useGreen = Math.Abs(hash % 100) < 50; // 50% traffic to green
        
        var versionToUse = useGreen ? $"{secretName}-green" : $"{secretName}-blue";
        
        var secret = await _secretClient.GetSecretAsync(versionToUse);
        return secret.Value.Value;
    }
    
    // Phase 3: Complete migration
    public async Task CompleteRotationAsync(string secretName)
    {
        // Get green version
        var greenSecret = await _secretClient.GetSecretAsync($"{secretName}-green");
        
        // Set as primary
        await _secretClient.SetSecretAsync(secretName, greenSecret.Value.Value);
        
        // Mark blue for deletion
        var blueProperties = (await _secretClient.GetSecretAsync($"{secretName}-blue"))
            .Value.Properties;
        blueProperties.Tags["status"] = "deprecated";
        await _secretClient.UpdateSecretPropertiesAsync(blueProperties);
    }
    
    // Phase 4: Cleanup
    public async Task CleanupOldVersionAsync(string secretName)
    {
        // Delete blue version after grace period
        await _secretClient.StartDeleteSecretAsync($"{secretName}-blue");
    }
}
```

### Automated Rotation with Azure Functions

```csharp
public class SecretRotationFunction
{
    private readonly SecretClient _keyVaultClient;
    private readonly SqlConnection _dbConnection;
    
    [FunctionName("RotateDatabasePassword")]
    public async Task Run(
        [TimerTrigger("0 0 2 * * 0")] TimerInfo timer, // Weekly at 2 AM Sunday
        ILogger log)
    {
        log.LogInformation("Starting database password rotation");
        
        try
        {
            // 1. Generate new password
            var newPassword = GenerateSecurePassword();
            
            // 2. Update password in database
            await UpdateDatabasePasswordAsync(newPassword);
            
            // 3. Store new password in Key Vault
            await _keyVaultClient.SetSecretAsync("DatabasePassword", newPassword);
            
            // 4. Verify new password works
            if (!await VerifyDatabaseConnectionAsync(newPassword))
            {
                log.LogError("Rotation failed - new password doesn't work");
                await RollbackAsync();
                return;
            }
            
            // 5. Trigger application restart/reload
            await NotifyApplicationsOfRotationAsync();
            
            log.LogInformation("Database password rotated successfully");
        }
        catch (Exception ex)
        {
            log.LogError(ex, "Failed to rotate database password");
            await SendAlertAsync("Password rotation failed", ex.Message);
        }
    }
    
    private string GenerateSecurePassword()
    {
        const string chars = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789!@#$%^&*";
        var random = RandomNumberGenerator.Create();
        var password = new char[32];
        
        for (int i = 0; i < password.Length; i++)
        {
            var randomByte = new byte[1];
            random.GetBytes(randomByte);
            password[i] = chars[randomByte[0] % chars.Length];
        }
        
        return new string(password);
    }
    
    private async Task UpdateDatabasePasswordAsync(string newPassword)
    {
        using var connection = new SqlConnection(_currentConnectionString);
        await connection.OpenAsync();
        
        using var command = new SqlCommand(
            "ALTER LOGIN [myapp_user] WITH PASSWORD = @password",
            connection);
        command.Parameters.AddWithValue("@password", newPassword);
        
        await command.ExecuteNonQueryAsync();
    }
}
```

### Kubernetes Secrets Basics

```yaml
# Creating a Kubernetes Secret
apiVersion: v1
kind: Secret
metadata:
  name: myapp-secrets
type: Opaque
data:
  # Base64 encoded values
  database-password: cGFzc3dvcmQxMjM=  # password123
  api-key: YWJjMTIzNDU2Nzg5MA==      # abc1234567890

---
# Using Secret in a Pod
apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  containers:
  - name: myapp
    image: myapp:latest
    env:
    # Load as environment variables
    - name: DATABASE_PASSWORD
      valueFrom:
        secretKeyRef:
          name: myapp-secrets
          key: database-password
    - name: API_KEY
      valueFrom:
        secretKeyRef:
          name: myapp-secrets
          key: api-key
    # Or mount as files
    volumeMounts:
    - name: secret-volume
      mountPath: /etc/secrets
      readOnly: true
  volumes:
  - name: secret-volume
    secret:
      secretName: myapp-secrets
```

### Creating Kubernetes Secrets Securely

```bash
# From literal values (NOT recommended for sensitive data)
kubectl create secret generic myapp-secrets \
  --from-literal=password=password123 \
  --from-literal=api-key=abc123

# From file (better, but file must be secured)
echo -n 'password123' > password.txt
kubectl create secret generic myapp-secrets \
  --from-file=password=password.txt
rm password.txt

# From environment variable (best for CI/CD)
kubectl create secret generic myapp-secrets \
  --from-literal=password=$DATABASE_PASSWORD

# Encrypt secrets at rest (enable in cluster)
# Edit kube-apiserver manifest:
# --encryption-provider-config=/etc/kubernetes/encryption-config.yaml
```

### External Secrets Operator

```yaml
# Install External Secrets Operator
# https://external-secrets.io

# SecretStore - connects to Azure Key Vault
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: azure-keyvault
  namespace: default
spec:
  provider:
    azurekv:
      tenantId: "your-tenant-id"
      vaultUrl: "https://myvault.vault.azure.net"
      authSecretRef:
        clientId:
          name: azure-sp-credentials
          key: client-id
        clientSecret:
          name: azure-sp-credentials
          key: client-secret

---
# ExternalSecret - syncs from Key Vault to K8s Secret
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: myapp-external-secret
  namespace: default
spec:
  refreshInterval: 1h  # Sync every hour
  secretStoreRef:
    name: azure-keyvault
    kind: SecretStore
  target:
    name: myapp-secrets  # Name of K8s Secret to create
    creationPolicy: Owner
  data:
  - secretKey: database-password
    remoteRef:
      key: DatabasePassword  # Name in Key Vault
  - secretKey: api-key
    remoteRef:
      key: ApiKeys--Stripe
```

### Sealed Secrets (GitOps Approach)

```bash
# Install Sealed Secrets controller
kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.24.0/controller.yaml

# Install kubeseal CLI
brew install kubeseal  # macOS
# Or download from GitHub releases

# Create a secret (doesn't create in cluster yet)
kubectl create secret generic myapp-secrets \
  --from-literal=password=secret123 \
  --dry-run=client -o yaml > secret.yaml

# Seal the secret (encrypted with cluster-specific key)
kubeseal -f secret.yaml -w sealed-secret.yaml

# Now sealed-secret.yaml can be committed to Git!
# Only the cluster with the private key can decrypt it
git add sealed-secret.yaml
git commit -m "Add sealed secret"

# Apply to cluster
kubectl apply -f sealed-secret.yaml

# Controller automatically creates the actual Secret
```

### Monitoring Secret Access

```csharp
public class SecretAccessAuditor
{
    private readonly ILogger _logger;
    private readonly IMemoryCache _cache;
    
    public async Task<string> GetSecretWithAuditAsync(
        string secretName, 
        string userId,
        string purpose)
    {
        // Check if user has accessed this secret recently
        var cacheKey = $"secret-access:{userId}:{secretName}";
        if (_cache.TryGetValue(cacheKey, out DateTime lastAccess))
        {
            var timeSinceAccess = DateTime.UtcNow - lastAccess;
            if (timeSinceAccess < TimeSpan.FromMinutes(1))
            {
                _logger.LogWarning(
                    "Unusual: User {UserId} accessed secret {SecretName} multiple times in {Seconds} seconds",
                    userId, secretName, timeSinceAccess.TotalSeconds);
            }
        }
        
        // Log access
        _logger.LogInformation(
            "Secret accessed: {SecretName} by {UserId} for {Purpose}",
            secretName, userId, purpose);
        
        // Update cache
        _cache.Set(cacheKey, DateTime.UtcNow, TimeSpan.FromMinutes(5));
        
        // Retrieve secret
        var secret = await RetrieveSecretAsync(secretName);
        
        // Log to security audit system
        await AuditSecretAccessAsync(secretName, userId, purpose);
        
        return secret;
    }
}
```

### Secret Rotation Notifications

```csharp
public class RotationNotificationService
{
    private readonly IEmailService _emailService;
    private readonly ISlackService _slackService;
    
    public async Task NotifyRotationScheduledAsync(
        string secretName, 
        DateTime scheduledTime)
    {
        var message = $"Secret '{secretName}' is scheduled for rotation at {scheduledTime:yyyy-MM-dd HH:mm} UTC";
        
        await _emailService.SendToSecurityTeamAsync(
            "Secret Rotation Scheduled",
            message);
    }
    
    public async Task NotifyRotationCompletedAsync(
        string secretName, 
        bool success,
        string details)
    {
        var emoji = success ? "✅" : "❌";
        var status = success ? "successful" : "failed";
        
        var message = $"{emoji} Secret rotation {status}: {secretName}\nDetails: {details}";
        
        await _slackService.PostToChannelAsync("#security-alerts", message);
        
        if (!success)
        {
            await _emailService.SendToSecurityTeamAsync(
                $"ALERT: Secret Rotation Failed - {secretName}",
                message);
        }
    }
}
```

### Best Practices Checklist

```
Secret Rotation:
□ Automate rotation where possible
□ Use blue/green strategy for zero-downtime rotation
□ Test rotation process in non-production first
□ Monitor rotation success/failure
□ Alert on rotation failures
□ Document rotation procedures
□ Maintain rotation schedule
□ Rotate immediately after security incidents

Kubernetes Secrets:
□ Enable encryption at rest
□ Use RBAC to restrict access
□ Avoid environment variables for very sensitive secrets
□ Use External Secrets Operator or Sealed Secrets
□ Never commit raw secrets to Git
□ Audit secret access regularly
□ Use separate namespaces for isolation
□ Implement least privilege access

General:
□ Rotate secrets regularly based on sensitivity
□ Use different secrets per environment
□ Implement secret versioning
□ Log all secret access
□ Test secret rotation in staging
□ Have rollback procedures
□ Notify applications of rotations
□ Retire old versions after grace period
```

### Common Rotation Pitfalls

```csharp
// ❌ BAD: Not handling rotation in application
public class Service
{
    private readonly string _apiKey;
    
    public Service(IConfiguration config)
    {
        // Loaded once at startup - won't see rotated value!
        _apiKey = config["ApiKey"];
    }
}

// ✅ GOOD: Reload configuration on changes
public class Service
{
    private readonly IOptionsMonitor<ApiSettings> _options;
    
    public Service(IOptionsMonitor<ApiSettings> options)
    {
        _options = options;
        
        // Subscribe to changes
        options.OnChange(newSettings =>
        {
            // Handle rotation
            ReinitializeClient(newSettings.ApiKey);
        });
    }
    
    public void DoWork()
    {
        // Always get current value
        var apiKey = _options.CurrentValue.ApiKey;
    }
}

// ❌ BAD: Rotating without grace period
// Old services still using old secret will break immediately

// ✅ GOOD: Maintain both versions during transition
// Blue/green rotation with overlap period

// ❌ BAD: No monitoring or alerts
// Rotation failures go unnoticed

// ✅ GOOD: Monitor and alert
await NotifyRotationCompletedAsync(secretName, success, details);
```
