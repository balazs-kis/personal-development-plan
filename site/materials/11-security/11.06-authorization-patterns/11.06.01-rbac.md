## Introduction

Role-Based Access Control (RBAC) is the most widely used authorization model. It assigns permissions to roles, and users are assigned to roles. While conceptually simple, proper RBAC implementation requires careful design to avoid common pitfalls like role explosion, privilege creep, and inflexible permission structures.

**Key principle:** Roles should represent job functions, not individual users. Permissions should be atomic, and roles should be composable.

## Key Concepts Summary

### What is RBAC?

RBAC controls access based on a user's role within an organization.

```
┌────────────────────────────────────────────────┐
│ RBAC Model                                     │
├────────────────────────────────────────────────┤
│                                                │
│  Users  →  Roles  →  Permissions  →  Resources│
│                                                │
│  Alice  →  Editor →  Write       →  Documents │
│  Bob    →  Viewer →  Read        →  Documents │
│  Carol  →  Admin  →  All         →  All       │
└────────────────────────────────────────────────┘
```

**Three core components:**
1. **Users:** People or services that need access
2. **Roles:** Collections of permissions (e.g., Editor, Viewer, Admin)
3. **Permissions:** Specific rights to perform actions on resources

## RBAC Fundamentals

### Roles

**What is a Role?**
A role is a named collection of permissions that represents a job function or responsibility.

```csharp
public class Role
{
    public string Name { get; set; }           // "Editor", "Viewer", "Admin"
    public string Description { get; set; }
    public List<Permission> Permissions { get; set; }
}
```

**Examples:**
- **Editor:** Can create, read, update documents
- **Viewer:** Can only read documents
- **Admin:** Can do everything including manage users
- **Moderator:** Can review and approve content
- **Contributor:** Can create drafts but not publish

### Permissions

**What is a Permission?**
A permission is a specific right to perform an action on a resource type.

```csharp
public class Permission
{
    public string Resource { get; set; }    // "Document", "User", "Comment"
    public string Action { get; set; }      // "Read", "Write", "Delete", "Approve"
}

// Examples
{ Resource: "Document", Action: "Read" }
{ Resource: "Document", Action: "Write" }
{ Resource: "User", Action: "Delete" }
{ Resource: "Comment", Action: "Approve" }
```

### User-Role Assignment

```csharp
public class UserRole
{
    public string UserId { get; set; }
    public string RoleId { get; set; }
    public DateTime AssignedAt { get; set; }
    public DateTime? ExpiresAt { get; set; }  // Optional expiration
}
```

## RBAC Best Practices

### 1. Principle of Least Privilege

Grant users only the minimum permissions necessary for their tasks.

```csharp
// ❌ BAD: Overly permissive
var role = new Role
{
    Name = "ContentCreator",
    Permissions = new[]
    {
        new Permission("Document", "Read"),
        new Permission("Document", "Write"),
        new Permission("Document", "Delete"),      // Probably too much
        new Permission("User", "Read"),            // Probably unnecessary
        new Permission("Settings", "Update")       // Definitely too much
    }
};

// ✅ GOOD: Minimal necessary permissions
var role = new Role
{
    Name = "ContentCreator",
    Permissions = new[]
    {
        new Permission("Document", "Read"),
        new Permission("Document", "Write")
    }
};
```

### 2. Separate Users, Roles, and Permissions

Treat permissions as atomic units. Roles bundle permissions, but don't lock users into single roles.

```csharp
// ✅ GOOD: Atomic permissions
public static class Permissions
{
    public const string DocumentRead = "document:read";
    public const string DocumentWrite = "document:write";
    public const string DocumentDelete = "document:delete";
    public const string DocumentPublish = "document:publish";
    public const string UserRead = "user:read";
    public const string UserWrite = "user:write";
}

// ✅ GOOD: Composable roles
public static class Roles
{
    public static Role Viewer => new Role
    {
        Name = "Viewer",
        Permissions = new[]
        {
            Permissions.DocumentRead
        }
    };
    
    public static Role Editor => new Role
    {
        Name = "Editor",
        Permissions = new[]
        {
            Permissions.DocumentRead,
            Permissions.DocumentWrite
        }
    };
    
    public static Role Publisher => new Role
    {
        Name = "Publisher",
        Permissions = new[]
        {
            Permissions.DocumentRead,
            Permissions.DocumentWrite,
            Permissions.DocumentPublish
        }
    };
}
```

### 3. Design Roles Around Business Functions

Align roles with actual job functions and organizational structure.

```
// ✅ GOOD: Business-aligned roles
- Content Writer
- Content Editor
- Content Publisher
- Content Reviewer
- Marketing Manager
- Sales Representative

// ❌ BAD: Technical or vague roles
- User
- Power User
- Super User
- Advanced
- Basic
```

### 4. Avoid Role Explosion

**The Problem:**
Starting with 15 clean roles but expanding to hundreds as business needs change.

**Why it happens:**
- Creating new roles is faster than refactoring existing ones
- Temporary access becomes permanent
- Exception roles for individual users

**Prevention:**

```csharp
// ❌ BAD: Role explosion
public static class Roles
{
    public const string Editor = "editor";
    public const string EditorWithApproval = "editor_with_approval";
    public const string EditorNoDelete = "editor_no_delete";
    public const string EditorLimited = "editor_limited";
    public const string EditorForJohn = "editor_for_john";  // VERY BAD!
    // ... 50 more editor variants
}

// ✅ GOOD: Composable permissions
public static class Roles
{
    public const string Editor = "editor";
    public const string Approver = "approver";
}

// Users can have multiple roles
user.Roles = new[] { Roles.Editor, Roles.Approver };
```

### 5. Use Scoped Roles

Roles should have specific scope and duration limits, not global permissions.

```csharp
public class ScopedRole
{
    public string UserId { get; set; }
    public string RoleName { get; set; }
    public string Scope { get; set; }         // "Organization:123", "Project:456"
    public DateTime? ExpiresAt { get; set; }  // Time-limited access
}

// Example: Project-scoped roles
var assignment = new ScopedRole
{
    UserId = "user123",
    RoleName = "ProjectManager",
    Scope = "Project:ProjectA",
    ExpiresAt = DateTime.UtcNow.AddMonths(6)
};

// User is ProjectManager ONLY for ProjectA, expires in 6 months
```

## ASP.NET Core RBAC Implementation

### Simple Role-Based Authorization

```csharp
// Startup / Program.cs
services.AddAuthorization(options =>
{
    options.AddPolicy("RequireEditor", policy =>
        policy.RequireRole("Editor"));
    
    options.AddPolicy("RequireAdminOrEditor", policy =>
        policy.RequireRole("Admin", "Editor"));  // OR condition
});

// Controller
[Authorize(Roles = "Editor")]
public class DocumentController : Controller
{
    [HttpPost]
    public IActionResult Create([FromBody] Document doc)
    {
        // Only users with "Editor" role can access
        return Ok();
    }
    
    [Authorize(Roles = "Admin,Publisher")]  // Multiple roles (OR)
    [HttpPost("publish")]
    public IActionResult Publish(int id)
    {
        // Only Admin OR Publisher can access
        return Ok();
    }
}
```

### Adding Roles to Users

```csharp
// Using ASP.NET Core Identity
public class AccountService
{
    private readonly UserManager<ApplicationUser> _userManager;
    
    public async Task AssignRole(string userId, string roleName)
    {
        var user = await _userManager.FindByIdAsync(userId);
        if (user == null)
            throw new NotFoundException("User not found");
        
        // Ensure role exists
        if (!await _roleManager.RoleExistsAsync(roleName))
        {
            await _roleManager.CreateAsync(new IdentityRole(roleName));
        }
        
        // Assign role
        await _userManager.AddToRoleAsync(user, roleName);
    }
    
    public async Task<List<string>> GetUserRoles(string userId)
    {
        var user = await _userManager.FindByIdAsync(userId);
        if (user == null)
            return new List<string>();
        
        var roles = await _userManager.GetRolesAsync(user);
        return roles.ToList();
    }
}
```

### Custom RBAC Implementation

```csharp
// Without ASP.NET Core Identity
public class RbacService
{
    private readonly IUserRepository _userRepo;
    private readonly IRoleRepository _roleRepo;
    
    public async Task<bool> UserHasPermission(string userId, string permission)
    {
        // Get user's roles
        var userRoles = await _userRepo.GetUserRoles(userId);
        
        // Get permissions for all roles
        foreach (var roleName in userRoles)
        {
            var role = await _roleRepo.GetRoleByName(roleName);
            if (role.Permissions.Contains(permission))
            {
                return true;
            }
        }
        
        return false;
    }
    
    public async Task<bool> UserHasRole(string userId, string roleName)
    {
        var userRoles = await _userRepo.GetUserRoles(userId);
        return userRoles.Contains(roleName);
    }
}

// Usage in controller
[ApiController]
[Route("api/[controller]")]
public class DocumentController : ControllerBase
{
    private readonly RbacService _rbac;
    
    [HttpDelete("{id}")]
    public async Task<IActionResult> Delete(int id)
    {
        var userId = User.FindFirst("sub")?.Value;
        
        if (!await _rbac.UserHasPermission(userId, "document:delete"))
        {
            return Forbid();
        }
        
        // Process deletion
        return Ok();
    }
}
```

## RBAC Database Schema

### Recommended Schema

```sql
-- Users table (from Identity or custom)
CREATE TABLE Users (
    UserId VARCHAR(255) PRIMARY KEY,
    Email VARCHAR(255),
    Name VARCHAR(255)
);

-- Roles table
CREATE TABLE Roles (
    RoleId VARCHAR(255) PRIMARY KEY,
    Name VARCHAR(100) NOT NULL UNIQUE,
    Description VARCHAR(500)
);

-- Permissions table
CREATE TABLE Permissions (
    PermissionId VARCHAR(255) PRIMARY KEY,
    Name VARCHAR(100) NOT NULL UNIQUE,  -- "document:read"
    Description VARCHAR(500)
);

-- Role-Permission mapping
CREATE TABLE RolePermissions (
    RoleId VARCHAR(255) REFERENCES Roles(RoleId),
    PermissionId VARCHAR(255) REFERENCES Permissions(PermissionId),
    PRIMARY KEY (RoleId, PermissionId)
);

-- User-Role assignment
CREATE TABLE UserRoles (
    UserId VARCHAR(255) REFERENCES Users(UserId),
    RoleId VARCHAR(255) REFERENCES Roles(RoleId),
    AssignedAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    ExpiresAt DATETIME NULL,
    Scope VARCHAR(255) NULL,  -- Optional: "Project:123"
    PRIMARY KEY (UserId, RoleId, Scope)
);

-- Indexes
CREATE INDEX IX_UserRoles_UserId ON UserRoles(UserId);
CREATE INDEX IX_UserRoles_RoleId ON UserRoles(RoleId);
CREATE INDEX IX_RolePermissions_RoleId ON RolePermissions(RoleId);
```

## Common RBAC Pitfalls

### Pitfall 1: Role Explosion

```
// ❌ BAD: Creating a new role for every edge case
- Editor
- EditorWithDelete
- EditorNoDelete
- EditorForDrafts
- EditorForPublished
- ... (100+ roles)

// ✅ GOOD: Combine roles or use ABAC for edge cases
- Editor (base role)
- DeletePermission (additional permission)
- User can have multiple roles: Editor + DeletePermission
```

### Pitfall 2: User-Specific Roles

```csharp
// ❌ BAD: Creating roles for specific users
public static class Roles
{
    public const string AdminForJohn = "admin_john";
    public const string EditorForMary = "editor_mary";
}

// ✅ GOOD: Use generic roles, scope if needed
public static class Roles
{
    public const string Admin = "admin";
    public const string Editor = "editor";
}
```

### Pitfall 3: Hardcoded Roles in Code

```csharp
// ❌ BAD: Hardcoding role names everywhere
if (user.Roles.Contains("Admin") || user.Roles.Contains("SuperAdmin") || 
    user.Roles.Contains("GlobalAdmin"))
{
    // Allow access
}

// ✅ GOOD: Use constants and permissions
if (await _rbac.UserHasPermission(userId, Permissions.UserManagement))
{
    // Allow access
}
```

### Pitfall 4: No Role Auditing

```csharp
// ✅ GOOD: Track role changes
public class RoleAudit
{
    public int AuditId { get; set; }
    public string UserId { get; set; }
    public string RoleName { get; set; }
    public string Action { get; set; }      // "Assigned", "Removed"
    public string PerformedBy { get; set; }
    public DateTime Timestamp { get; set; }
    public string Reason { get; set; }
}

public async Task AssignRoleWithAudit(
    string userId, string roleName, string performedBy, string reason)
{
    await _rbac.AssignRole(userId, roleName);
    
    await _auditRepo.LogRoleChange(new RoleAudit
    {
        UserId = userId,
        RoleName = roleName,
        Action = "Assigned",
        PerformedBy = performedBy,
        Timestamp = DateTime.UtcNow,
        Reason = reason
    });
}
```

## RBAC Maintenance

### Regular Audits

```csharp
public class RbacAuditService
{
    public async Task<RbacAuditReport> AuditRoles()
    {
        var report = new RbacAuditReport();
        
        // Find users with multiple high-privilege roles
        report.OverPrivilegedUsers = await FindUsersWithRoles(
            new[] { "Admin", "SuperAdmin", "GlobalAdmin" }, count: 2);
        
        // Find unused roles
        report.UnusedRoles = await _roleRepo.GetRolesWithNoUsers();
        
        // Find roles with too many permissions
        report.OverloadedRoles = await _roleRepo.GetRolesWithPermissionCount(
            threshold: 20);
        
        // Find expired role assignments still active
        report.ExpiredAssignments = await _userRoleRepo
            .GetExpiredAssignments();
        
        return report;
    }
}
```

### Cleanup Strategies

```csharp
// Remove expired role assignments
public async Task CleanupExpiredRoles()
{
    var expired = await _userRoleRepo.GetExpiredAssignments();
    
    foreach (var assignment in expired)
    {
        await _rbac.RemoveRole(assignment.UserId, assignment.RoleId);
        
        await _auditRepo.LogRoleChange(new RoleAudit
        {
            UserId = assignment.UserId,
            RoleName = assignment.RoleId,
            Action = "AutoRemoved",
            PerformedBy = "System",
            Reason = "Expired",
            Timestamp = DateTime.UtcNow
        });
    }
}
```

### Unit Tests

```csharp
[Fact]
public async Task UserWithEditorRole_CanAccessEditEndpoint()
{
    // Arrange
    var user = CreateUser("user1");
    await _rbac.AssignRole(user.Id, "Editor");
    
    // Act
    var result = await _controller.Edit(documentId: 1);
    
    // Assert
    Assert.IsType<OkResult>(result);
}

[Fact]
public async Task UserWithoutEditorRole_CannotAccessEditEndpoint()
{
    // Arrange
    var user = CreateUser("user1");
    // No role assigned
    
    // Act
    var result = await _controller.Edit(documentId: 1);
    
    // Assert
    Assert.IsType<ForbidResult>(result);
}

[Fact]
public async Task RoleExpiration_RevokeAccess()
{
    // Arrange
    var user = CreateUser("user1");
    await _rbac.AssignRoleWithExpiration(
        user.Id, "Editor", expiresAt: DateTime.UtcNow.AddSeconds(1));
    
    // Wait for expiration
    await Task.Delay(1100);
    
    // Act
    await _rbac.CleanupExpiredRoles();
    var hasRole = await _rbac.UserHasRole(user.Id, "Editor");
    
    // Assert
    Assert.False(hasRole);
}
```
