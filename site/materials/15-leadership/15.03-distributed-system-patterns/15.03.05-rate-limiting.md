## Key Concepts Summary

### What is Rate Limiting?

Rate limiting controls the rate of requests a client can make to prevent:
- System overload
- Abuse and DDoS attacks
- Resource exhaustion
- Unfair usage (one client consuming all resources)

```
Without Rate Limiting:
Client → 10,000 req/sec → Server → Crash

With Rate Limiting:
Client → 10,000 req/sec → Rate Limiter (allows 100 req/sec) → Server → Stable
                            ↓ (reject 9,900)
                         429 Too Many Requests
```

**Benefits:**
- **Availability:** Prevent resource exhaustion
- **Cost Control:** Limit infrastructure costs
- **Fair Access:** Prevent noisy neighbor problems
- **Security:** DDoS protection
- **Revenue:** Tiered pricing based on limits

## Rate Limiting Algorithms

### 1. Token Bucket

**How it works:**
- Bucket holds tokens (max capacity)
- Tokens added at constant rate (refill rate)
- Each request consumes a token
- If no tokens available, request rejected

```
Bucket: [🪙 🪙 🪙 🪙 🪙] (capacity = 5)
Refill rate: 2 tokens/second

Request 1 → ✅ (4 tokens left)
Request 2 → ✅ (3 tokens left)
Request 3 → ✅ (2 tokens left)
Request 4 → ✅ (1 token left)
Request 5 → ✅ (0 tokens left)
Request 6 → ❌ (no tokens)
... 1 second passes → 2 tokens added ...
Request 7 → ✅ (1 token left)
```

**Implementation:**
```csharp
public class TokenBucket
{
    private readonly int _capacity;
    private readonly double _refillRate; // tokens per second
    private double _tokens;
    private DateTime _lastRefill;
    
    public TokenBucket(int capacity, double refillRate)
    {
        _capacity = capacity;
        _refillRate = refillRate;
        _tokens = capacity;
        _lastRefill = DateTime.UtcNow;
    }
    
    public bool TryConsume(int tokensNeeded = 1)
    {
        Refill();
        
        if (_tokens >= tokensNeeded)
        {
            _tokens -= tokensNeeded;
            return true; // Allow request
        }
        
        return false; // Reject request
    }
    
    private void Refill()
    {
        var now = DateTime.UtcNow;
        var timePassed = (now - _lastRefill).TotalSeconds;
        
        // Add tokens based on time passed
        _tokens = Math.Min(_capacity, _tokens + timePassed * _refillRate);
        _lastRefill = now;
    }
}

// Usage
var limiter = new TokenBucket(capacity: 100, refillRate: 10); // 10 req/sec

if (limiter.TryConsume())
{
    // Process request
}
else
{
    // Return 429 Too Many Requests
}
```

**Pros:**
- Handles burst traffic (up to bucket capacity)
- Smooth long-term rate
- Memory efficient

**Cons:**
- Can allow large bursts if bucket is full
- More complex than fixed window

**Use when:** Need to allow bursts but control long-term rate (most common choice)

### 2. Leaky Bucket

**How it works:**
- Requests added to queue (bucket)
- Processed at constant rate (leak rate)
- If queue full, reject new requests

```
Requests → [Queue: ▓▓▓▓▓▓__] → Process at constant rate
           Max size = 8
           Process rate = 2/sec

Request arrives → Add to queue (if space)
Every 0.5s → Process one request
```

**Implementation:**
```csharp
public class LeakyBucket
{
    private readonly Queue<DateTime> _queue;
    private readonly int _capacity;
    private readonly double _leakRate; // requests per second
    private DateTime _lastLeak;
    
    public LeakyBucket(int capacity, double leakRate)
    {
        _queue = new Queue<DateTime>();
        _capacity = capacity;
        _leakRate = leakRate;
        _lastLeak = DateTime.UtcNow;
    }
    
    public bool TryAdd()
    {
        Leak();
        
        if (_queue.Count < _capacity)
        {
            _queue.Enqueue(DateTime.UtcNow);
            return true;
        }
        
        return false; // Queue full
    }
    
    private void Leak()
    {
        var now = DateTime.UtcNow;
        var timePassed = (now - _lastLeak).TotalSeconds;
        var requestsToProcess = (int)(timePassed * _leakRate);
        
        for (int i = 0; i < requestsToProcess && _queue.Count > 0; i++)
        {
            _queue.Dequeue();
        }
        
        _lastLeak = now;
    }
}
```

**Pros:**
- Smooth output rate (no bursts)
- Predictable behavior

**Cons:**
- Doesn't handle burst well
- Queue can fill during temporary spike

**Use when:** Need strict constant rate (video streaming, network traffic shaping)

### 3. Fixed Window Counter

**How it works:**
- Time divided into fixed windows (e.g., 1 minute)
- Counter for each window
- Reset counter at window boundary

```
Window 1 (0:00-0:59): 100 requests (limit: 100) ✅
Window 2 (1:00-1:59): 150 requests (limit: 100) ❌ (50 rejected)
Window 3 (2:00-2:59): 80 requests ✅
```

**Implementation:**
```csharp
public class FixedWindowCounter
{
    private readonly int _limit;
    private readonly TimeSpan _window;
    private int _counter;
    private DateTime _windowStart;
    
    public FixedWindowCounter(int limit, TimeSpan window)
    {
        _limit = limit;
        _window = window;
        _counter = 0;
        _windowStart = DateTime.UtcNow;
    }
    
    public bool TryIncrement()
    {
        var now = DateTime.UtcNow;
        
        // Check if window expired
        if (now - _windowStart >= _window)
        {
            _counter = 0;
            _windowStart = now;
        }
        
        if (_counter < _limit)
        {
            _counter++;
            return true;
        }
        
        return false;
    }
}

// Distributed version with Redis
public class DistributedFixedWindow
{
    private readonly IDatabase _redis;
    
    public async Task<bool> TryIncrementAsync(string key, int limit, TimeSpan window)
    {
        var windowKey = $"{key}:{DateTime.UtcNow.Ticks / window.Ticks}";
        
        var count = await _redis.StringIncrementAsync(windowKey);
        
        if (count == 1)
        {
            // Set expiry on first request in window
            await _redis.KeyExpireAsync(windowKey, window);
        }
        
        return count <= limit;
    }
}
```

**Pros:**
- Simple to implement
- Memory efficient
- Easy to understand

**Cons:**
- **Boundary problem:** Can allow 2x limit at window edges
  ```
  0:59 → 100 requests ✅
  1:00 → 100 requests ✅
  = 200 requests in 1 second!
  ```

**Use when:** Simplicity more important than precision

### 4. Sliding Window Log

**How it works:**
- Store timestamp of each request
- Count requests in last N seconds
- Remove old timestamps

```
Current time: 10:05:30
Window: 1 minute
Timestamps: [10:04:35, 10:04:50, 10:05:10, 10:05:25, 10:05:29]
           ^ expired → remove
Valid requests in last minute: 4
```

**Implementation:**
```csharp
public class SlidingWindowLog
{
    private readonly Queue<DateTime> _timestamps;
    private readonly int _limit;
    private readonly TimeSpan _window;
    
    public SlidingWindowLog(int limit, TimeSpan window)
    {
        _timestamps = new Queue<DateTime>();
        _limit = limit;
        _window = window;
    }
    
    public bool TryAdd()
    {
        var now = DateTime.UtcNow;
        var cutoff = now - _window;
        
        // Remove expired timestamps
        while (_timestamps.Count > 0 && _timestamps.Peek() < cutoff)
        {
            _timestamps.Dequeue();
        }
        
        if (_timestamps.Count < _limit)
        {
            _timestamps.Enqueue(now);
            return true;
        }
        
        return false;
    }
}
```

**Pros:**
- Most accurate
- No boundary problem

**Cons:**
- High memory usage (stores all timestamps)
- Expensive to track

**Use when:** Accuracy critical, limited number of users

### 5. Sliding Window Counter (Hybrid)

**How it works:**
- Combines fixed window and sliding window
- Uses weighted count from previous and current window

```
Previous window: 80 requests
Current window: 40 requests
Current time: 30% into current window

Estimated requests in last minute:
= (70% × 80) + (100% × 40)
= 56 + 40
= 96 requests
```

**Implementation:**
```csharp
public class SlidingWindowCounter
{
    private int _previousCount;
    private int _currentCount;
    private DateTime _currentWindowStart;
    private readonly int _limit;
    private readonly TimeSpan _window;
    
    public bool TryIncrement()
    {
        var now = DateTime.UtcNow;
        var elapsed = now - _currentWindowStart;
        
        if (elapsed >= _window)
        {
            // Move to next window
            _previousCount = _currentCount;
            _currentCount = 0;
            _currentWindowStart = now;
        }
        
        // Calculate weighted count
        var percentOfWindow = elapsed.TotalSeconds / _window.TotalSeconds;
        var previousWindowWeight = 1 - percentOfWindow;
        var estimatedCount = (_previousCount * previousWindowWeight) + _currentCount;
        
        if (estimatedCount < _limit)
        {
            _currentCount++;
            return true;
        }
        
        return false;
    }
}
```

**Pros:**
- Good accuracy
- Memory efficient (only 2 counters)
- Smooth rate

**Cons:**
- Approximation (not exact)
- More complex

**Use when:** Balance between accuracy and efficiency

## Algorithm Comparison

| Algorithm | Memory | Accuracy | Burst Handling | Complexity |
|-----------|--------|----------|----------------|------------|
| Token Bucket | Low | Good | Good (controlled) | Medium |
| Leaky Bucket | Medium | Excellent | Poor | Medium |
| Fixed Window | Very Low | Poor (boundary) | Poor | Low |
| Sliding Log | High | Excellent | Good | High |
| Sliding Counter | Low | Good | Good | Medium |

**Recommendation:** Token Bucket for most use cases, Sliding Window Counter for better accuracy.

## Distributed Rate Limiting

### Using Redis

```csharp
public class RedisRateLimiter
{
    private readonly IDatabase _redis;
    
    // Token bucket with Redis
    public async Task<bool> TryConsumeAsync(string userId, int capacity, double refillRate)
    {
        var key = $"ratelimit:{userId}";
        var now = DateTime.UtcNow.Ticks;
        
        // Lua script ensures atomicity
        var script = @"
            local key = KEYS[1]
            local capacity = tonumber(ARGV[1])
            local refill_rate = tonumber(ARGV[2])
            local now = tonumber(ARGV[3])
            
            local bucket = redis.call('HMGET', key, 'tokens', 'last_refill')
            local tokens = tonumber(bucket[1]) or capacity
            local last_refill = tonumber(bucket[2]) or now
            
            -- Refill tokens
            local elapsed = (now - last_refill) / 10000000.0
            tokens = math.min(capacity, tokens + elapsed * refill_rate)
            
            if tokens >= 1 then
                tokens = tokens - 1
                redis.call('HMSET', key, 'tokens', tokens, 'last_refill', now)
                redis.call('EXPIRE', key, 3600)
                return 1
            else
                return 0
            end
        ";
        
        var result = await _redis.ScriptEvaluateAsync(
            script,
            new RedisKey[] { key },
            new RedisValue[] { capacity, refillRate, now }
        );
        
        return (int)result == 1;
    }
}
```

### Rate Limiter Placement

```
Option 1: Client-side (soft limit, guidance)
Client → Self-limit → Server

Option 2: API Gateway (common)
Client → API Gateway (rate limit) → Services

Option 3: Application layer (granular control)
Client → Load Balancer → App (rate limit) → Services

Option 4: Multi-tier (defense in depth)
Client → CDN → API Gateway → App → Database
          ↓        ↓           ↓        ↓
      Rate limit at each layer
```

## Communicating Rate Limits

### HTTP Headers

```http
HTTP/1.1 200 OK
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 45
X-RateLimit-Reset: 1640000000

HTTP/1.1 429 Too Many Requests
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1640000060
Retry-After: 60
```

```csharp
public class RateLimitMiddleware
{
    public async Task InvokeAsync(HttpContext context)
    {
        var limiter = context.RequestServices.GetRequiredService<IRateLimiter>();
        var userId = context.User.Identity.Name;
        
        var result = await limiter.TryConsumeAsync(userId);
        
        // Add rate limit headers
        context.Response.Headers["X-RateLimit-Limit"] = result.Limit.ToString();
        context.Response.Headers["X-RateLimit-Remaining"] = result.Remaining.ToString();
        context.Response.Headers["X-RateLimit-Reset"] = result.ResetTime.ToString();
        
        if (!result.Allowed)
        {
            context.Response.StatusCode = 429;
            context.Response.Headers["Retry-After"] = result.RetryAfterSeconds.ToString();
            await context.Response.WriteAsync("Rate limit exceeded");
            return;
        }
        
        await _next(context);
    }
}
```

## Multi-Tier Rate Limiting

```csharp
public class TieredRateLimiter
{
    public async Task<bool> CheckLimits(string userId, string endpoint)
    {
        // 1. Global rate limit (protect entire system)
        if (!await CheckGlobalLimit())
            return false;
        
        // 2. Per-user rate limit (fair usage)
        if (!await CheckUserLimit(userId))
            return false;
        
        // 3. Per-endpoint rate limit (protect expensive operations)
        if (!await CheckEndpointLimit(endpoint))
            return false;
        
        // 4. Per-user-per-endpoint (fine-grained)
        if (!await CheckUserEndpointLimit(userId, endpoint))
            return false;
        
        return true;
    }
}

// Example limits:
// - Global: 100,000 req/sec
// - Per user: 100 req/sec
// - Per endpoint (/search): 10,000 req/sec
// - Per user per endpoint: 10 req/sec
```

### By Pricing Tier

```csharp
public class TierBasedLimiter
{
    private readonly Dictionary<string, RateLimit> _tiers = new()
    {
        ["free"] = new RateLimit(100, TimeSpan.FromHours(1)),
        ["basic"] = new RateLimit(1000, TimeSpan.FromHours(1)),
        ["premium"] = new RateLimit(10000, TimeSpan.FromHours(1)),
        ["enterprise"] = new RateLimit(100000, TimeSpan.FromHours(1))
    };
    
    public async Task<bool> TryConsumeAsync(string userId)
    {
        var tier = await GetUserTier(userId);
        var limit = _tiers[tier];
        return await CheckLimit(userId, limit);
    }
```
