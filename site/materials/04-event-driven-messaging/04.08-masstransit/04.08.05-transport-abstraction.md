## Learning Objectives

By the end of this lesson, you will be able to:
- Understand MassTransit's transport abstraction

- Switch between RabbitMQ, Azure Service Bus, and Amazon SQS
- Understand transport-specific features and limitations
- Migrate between transports with minimal code changes

---

## Introduction

One of MassTransit's most powerful features is **transport abstraction**—the ability to write messaging code once and run it on different message brokers (RabbitMQ, Azure Service Bus, Amazon SQS, Kafka, etc.) with minimal changes. This flexibility allows you to start with one broker and migrate to another as requirements change, or use different brokers in different environments (RabbitMQ locally, Azure Service Bus in production).

```csharp
// appsettings.json

// Program.cs
var transportType = builder.Configuration["Transport:Type"];

builder.Services.AddMassTransit(x =>
{
    x.AddConsumer<OrderSubmittedConsumer>();
    
    switch (transportType)
    {
        case "RabbitMQ":
            x.UsingRabbitMq((context, cfg) =>
            {
                var host = builder.Configuration["Transport:RabbitMQ:Host"];
                var username = builder.Configuration["Transport:RabbitMQ:Username"];
                var password = builder.Configuration["Transport:RabbitMQ:Password"];
                
                cfg.Host(host, "/", h =>
                {
                    h.Username(username);
                    h.Password(password);
                });
                
                cfg.ConfigureEndpoints(context);
            });
            break;
        
        case "AzureServiceBus":
            x.UsingAzureServiceBus((context, cfg) =>
            {
                var connectionString = builder.Configuration["Transport:AzureServiceBus:ConnectionString"];
                cfg.Host(connectionString);
                cfg.ConfigureEndpoints(context);
            });
            break;
        
        case "AmazonSqs":
            x.UsingAmazonSqs((context, cfg) =>
            {
                var region = builder.Configuration["Transport:AmazonSqs:Region"];
                cfg.Host(region, h =>
                {
                    var accessKey = builder.Configuration["Transport:AmazonSqs:AccessKey"];
                    var secretKey = builder.Configuration["Transport:AmazonSqs:SecretKey"];
                    h.AccessKey(accessKey);
                    h.SecretKey(secretKey);
                });
                cfg.ConfigureEndpoints(context);
            });
            break;
    }
});
```

```csharp
public static class TransportConfiguration
{
    public static void AddMassTransitWithTransport(
        this IServiceCollection services,
        IConfiguration configuration)
    {
        var transportType = configuration["Transport:Type"];
        
        services.AddMassTransit(x =>
        {

                    ConfigureAzureServiceBus(x, configuration);
                    break;
                
                case "AmazonSqs":
                    ConfigureAmazonSqs(x, configuration);
                    break;
                
                default:
                    throw new InvalidOperationException($"Unsupported transport: {transportType}");
            }
        });
    }
    
    private static void ConfigureRabbitMq(
        IBusRegistrationConfigurator x,
        IConfiguration configuration)
    {
        x.UsingRabbitMq((context, cfg) =>
        {
            var host = configuration["Transport:RabbitMQ:Host"];
            var username = configuration["Transport:RabbitMQ:Username"];
            var password = configuration["Transport:RabbitMQ:Password"];
            
            cfg.Host(host, "/", h =>
            {
                h.Username(username);
                h.Password(password);
            });
            
            cfg.ConfigureEndpoints(context);
        });
    }
    
    private static void ConfigureAzureServiceBus(
        IBusRegistrationConfigurator x,
        IConfiguration configuration)
    {
        x.UsingAzureServiceBus((context, cfg) =>

            // Use managed identity in production
```

### Transport Monitoring and Diagnostics

```csharp
// Transport-specific health checks
public class TransportHealthCheck : IHealthCheck
{
    private readonly IBusControl _bus;
    private readonly string _transportType;
    
    public async Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken cancellationToken = default)
    {
        try
        {
            // Check bus connectivity
            var busHealth = await _bus.GetProbeResult();
            
            if (busHealth.Results.Any(r => r.Exception != null))
            {
                return HealthCheckResult.Unhealthy(
                    $"{_transportType} transport unhealthy",
                    data: new Dictionary<string, object>
                    {
                        ["transport"] = _transportType,
                        ["errors"] = busHealth.Results
                            .Where(r => r.Exception != null)
                            .Select(r => r.Exception.Message)
                    });
            }
            
            return HealthCheckResult.Healthy(
                $"{_transportType} transport healthy",
                data: new Dictionary<string, object>
                {
                    ["transport"] = _transportType
                });
        }
        catch (Exception ex)
        {
            return HealthCheckResult.Unhealthy(
                $"{_transportType} transport check failed",
                ex,
                data: new Dictionary<string, object>
                {
                    ["transport"] = _transportType
                });
        }
    }
}
```

### Graceful Degradation

```csharp
// Fallback to alternative transport on failure
public class ResilientMessagingService
{
    private readonly IBus _primaryBus;
    private readonly IBus _fallbackBus;
    private readonly ILogger<ResilientMessagingService> _logger;
    
    public async Task PublishAsync<T>(T message) where T : class
    {
        try
        {
            await _primaryBus.Publish(message);
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Primary transport failed, using fallback");
            
            try
            {
                await _fallbackBus.Publish(message);
            }
            catch (Exception fallbackEx)
            {
                _logger.LogError(fallbackEx, "Both transports failed");
                throw;
            }
        }
    }
}
```

```csharp
{

    private readonly IBus _azureServiceBus; // Higher cost, managed

        }
    }
```

### Migration Strategies

```csharp
// Phase 1: Dual-write during migration
public class MigrationPublisher
{
    private readonly IBus _oldTransport;
    private readonly IBus _newTransport;
    
    public async Task PublishAsync<T>(T message) where T : class
    {
        // Publish to both transports
        await Task.WhenAll(
            _oldTransport.Publish(message),
            _newTransport.Publish(message)
        );
    }
}

// Phase 2: Feature flag for gradual rollout
public class FeatureFlaggedPublisher
{
    private readonly IBus _oldTransport;
    private readonly IBus _newTransport;
    private readonly IFeatureManager _featureManager;
    
    public async Task PublishAsync<T>(T message) where T : class
    {
        if (await _featureManager.IsEnabledAsync("UseNewTransport"))
        {
            await _newTransport.Publish(message);
        }
        else
        {
            await _oldTransport.Publish(message);
        }
    }
}

// Phase 3: Percentage-based rollout
public class PercentageBasedPublisher
{
    private readonly IBus _oldTransport;
    private readonly IBus _newTransport;
    private readonly int _newTransportPercentage = 10; // 10% traffic
    
    public async Task PublishAsync<T>(T message) where T : class
    {
        var useNew = Random.Shared.Next(100) < _newTransportPercentage;
        
        if (useNew)
        {
            await _newTransport.Publish(message);
        }
        else
        {
            await _oldTransport.Publish(message);
        }
    }
}
```

## Self-Check Questions

1. What makes MassTransit's transport abstraction powerful?
   - **Answer:** Write once, run anywhere—consumer code works unchanged across RabbitMQ, Azure Service Bus, Amazon SQS, Kafka. Only configuration changes, enabling easy migration and environment-specific transports.

2. Which transports support message scheduling?
   - **Answer:** RabbitMQ (via delayed exchange plugin), Azure Service Bus (native), Kafka (no). Amazon SQS supports delays but not scheduling at specific times.

3. How do you configure environment-specific transports?
   - **Answer:** Use configuration files (appsettings.json) with transport type and settings. Switch transports via configuration without code changes using conditional registration based on transport type.

4. What are the key differences between RabbitMQ and Azure Service Bus?
   - **Answer:** RabbitMQ: self-hosted, flexible routing, priority queues, lower cost. Azure Service Bus: managed, built-in sessions, simpler operations, higher cost, better Azure integration.

5. When would you use multiple transports in one application?
   - **Answer:** Internal services (RabbitMQ) + external partners (Azure Service Bus), migration phases (dual-write), cost optimization (bulk on RabbitMQ, critical on managed service).

6. How does Kafka integration differ from queue-based transports?
   - **Answer:** Kafka uses Rider (separate add-on), focuses on streaming not queuing, no request/response, messages retained for replay, partition-based parallelism instead of competing consumers.

7. What's the purpose of in-memory transport?
   - **Answer:** Fast, isolated testing without external dependencies. Perfect for unit tests, CI pipelines, and development without infrastructure setup.

8. How do you handle transport-specific features gracefully?
   - **Answer:** Use feature detection, provide fallbacks, or abstract capabilities behind interfaces. Document which features require specific transports.

## Key Takeaways

- **Transport abstraction** allows code to work unchanged across RabbitMQ, Azure Service Bus, Amazon SQS, and Kafka
- **Configuration-driven** transport selection enables environment-specific choices without code changes
- **Feature parity** varies—understand each transport's capabilities (sessions, priority, scheduling, transactions)
- **RabbitMQ** is flexible, self-hosted, and cost-effective for internal messaging
- **Azure Service Bus** is managed, reliable, and integrates well with Azure ecosystem
- **Amazon SQS** is simple, serverless, and good for AWS-native applications
- **Kafka** excels at event streaming, retention, and replay but requires different patterns (Rider)
- **In-memory transport** perfect for testing without external dependencies
- **Multiple transports** can coexist for internal vs external, migration, or cost optimization
- **Migration strategies** include dual-write, feature flags, and percentage-based rollout
- **Monitoring** should be transport-aware to surface transport-specific health and metrics
- **Cost optimization** can route messages to appropriate transports based on priority/volume
