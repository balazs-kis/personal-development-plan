# Lesson 3: Middleware and Filters

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand MassTransit's middleware pipeline
- Implement custom filters for cross-cutting concerns
- Configure retry and error handling policies
- Add circuit breakers and rate limiting
- Implement logging, tracing, and monitoring

---

## Introduction

**Middleware** in MassTransit provides a composable pipeline for processing messages. Filters can add cross-cutting concerns like retry logic, circuit breakers, logging, authentication, and validation without cluttering business logic. Understanding middleware is key to building production-ready messaging systems.

## Key Concepts Summary

### Retry Policy

```csharp
builder.Services.AddMassTransit(x =>
{
    x.AddConsumer<OrderSubmittedConsumer>();
    
    x.UsingRabbitMq((context, cfg) =>
    {
        cfg.Host("localhost");
        
        // Global retry policy
        cfg.UseMessageRetry(r =>
        {
            r.Exponential(5,
                TimeSpan.FromSeconds(1),
                TimeSpan.FromMinutes(1),
                TimeSpan.FromSeconds(5));
            
            // Only retry on specific exceptions
            r.Handle<TimeoutException>();
            r.Handle<HttpRequestException>();
            
            // Don't retry on validation errors
            r.Ignore<ValidationException>();
        });
        
        cfg.ConfigureEndpoints(context);
    });
});

// Per-consumer retry
public class OrderSubmittedConsumer : IConsumer<OrderSubmitted>
{
    public async Task Consume(ConsumeContext<OrderSubmitted> context)
    {
        // Will use retry policy
        await ProcessOrderAsync(context.Message);
    }
}
```

### Circuit Breaker

```csharp
cfg.UseCircuitBreaker(cb =>
{
    cb.TrackingPeriod = TimeSpan.FromMinutes(1);
    cb.TripThreshold = 15;  // 15% failure rate
    cb.ActiveThreshold = 10;  // At least 10 calls before tripping
    cb.ResetInterval = TimeSpan.FromMinutes(5);
});

// Sequence:
// 1. 10+ calls in 1 minute
// 2. 15% fail → Circuit opens
// 3. New calls immediately fail
// 4. After 5 minutes, circuit half-opens
// 5. Test call succeeds → Circuit closes
```

### Custom Filter

```csharp
public class LoggingFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    private readonly ILogger<LoggingFilter<T>> _logger;
    
    public LoggingFilter(ILogger<LoggingFilter<T>> logger)
    {
        _logger = logger;
    }
    
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        var messageType = typeof(T).Name;
        var messageId = context.MessageId;
        
        _logger.LogInformation(
            "Consuming {MessageType} {MessageId}",
            messageType, messageId);
        
        var sw = Stopwatch.StartNew();
        
        try
        {
            await next.Send(context);
            
            _logger.LogInformation(
                "Consumed {MessageType} {MessageId} in {Duration}ms",
                messageType, messageId, sw.ElapsedMilliseconds);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex,
                "Error consuming {MessageType} {MessageId}",
                messageType, messageId);
            
            throw;
        }
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("logging");
    }
}

// Register globally
cfg.UseConsumeFilter(typeof(LoggingFilter<>), context);

// Or per-consumer
cfg.ReceiveEndpoint("order-queue", e =>
{
    e.UseConsumeFilter(typeof(LoggingFilter<>), context);
    e.ConfigureConsumer<OrderSubmittedConsumer>(context);
});
```

### Validation Filter

```csharp
public class ValidationFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    private readonly IValidator<T> _validator;
    
    public ValidationFilter(IValidator<T> validator)
    {
        _validator = validator;
    }
    
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        var result = await _validator.ValidateAsync(context.Message);
        
        if (!result.IsValid)
        {
            throw new ValidationException(result.Errors);
        }
        
        await next.Send(context);
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("validation");
    }
}

// FluentValidation validator
public class OrderSubmittedValidator : AbstractValidator<OrderSubmitted>
{
    public OrderSubmittedValidator()
    {
        RuleFor(x => x.OrderId).NotEmpty();
        RuleFor(x => x.CustomerId).NotEmpty();
        RuleFor(x => x.TotalAmount).GreaterThan(0);
    }
}

// Register
builder.Services.AddValidatorsFromAssemblyContaining<OrderSubmittedValidator>();
cfg.UseConsumeFilter(typeof(ValidationFilter<>), context);
```

### Scoped Filters

```csharp
// Scoped filter for tenant isolation
public class TenantFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    private readonly ITenantContext _tenantContext;
    
    public TenantFilter(ITenantContext tenantContext)
    {
        _tenantContext = tenantContext;
    }
    
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        // Extract tenant ID from headers
        if (context.Headers.TryGetHeader("TenantId", out var tenantId))
        {
            _tenantContext.SetTenant(tenantId.ToString());
        }
        else
        {
            throw new InvalidOperationException("TenantId header is required");
        }
        
        try
        {
            await next.Send(context);
        }
        finally
        {
            _tenantContext.Clear();
        }
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("tenant");
    }
}

// Scoped filter registration
cfg.UseConsumeFilter(typeof(TenantFilter<>), context);
```

### Exception Filters

```csharp
// Classify exceptions for different handling
public class ExceptionClassificationFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        try
        {
            await next.Send(context);
        }
        catch (ValidationException ex)
        {
            // Validation errors - don't retry, move to error queue
            context.Headers.Set("ExceptionType", "Validation");
            throw new ConsumerCancelledException($"Validation failed: {ex.Message}");
        }
        catch (TimeoutException ex)
        {
            // Timeout - should retry
            context.Headers.Set("ExceptionType", "Timeout");
            throw;
        }
        catch (HttpRequestException ex)
        {
            // HTTP errors - should retry
            context.Headers.Set("ExceptionType", "HttpRequest");
            throw;
        }
        catch (DbException ex)
        {
            // Database errors - should retry
            context.Headers.Set("ExceptionType", "Database");
            throw;
        }
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("exception-classification");
    }
}
```

```csharp
// Dynamic throttling based on system load
public class DynamicThrottleFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    private readonly ISystemMonitor _monitor;
    
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        // Check system resources
        var cpuUsage = await _monitor.GetCpuUsageAsync();
        
        if (cpuUsage > 80)
        {
            // Slow down processing
            await Task.Delay(TimeSpan.FromSeconds(1));
        }
        
        await next.Send(context);
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("dynamic-throttle");
    }
}
```

### Message Deduplication

```csharp
// In-memory deduplication filter
public class DeduplicationFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    private readonly IMemoryCache _cache;
    private readonly TimeSpan _deduplicationWindow = TimeSpan.FromMinutes(10);
    
    public DeduplicationFilter(IMemoryCache cache)
    {
        _cache = cache;
    }
    
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        var messageId = context.MessageId.ToString();
        var cacheKey = $"msg-{messageId}";
        
        if (_cache.TryGetValue(cacheKey, out _))
        {
            // Duplicate message - skip processing
            return;
        }
        
        // Mark message as seen
        _cache.Set(cacheKey, true, _deduplicationWindow);
        
        await next.Send(context);
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("deduplication");
    }
}

cfg.UseConsumeFilter(typeof(DeduplicationFilter<>), context);
```

### Transaction Filters

```csharp
// Wrap consumer in database transaction
public class TransactionFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    private readonly DbContext _dbContext;
    
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        var strategy = _dbContext.Database.CreateExecutionStrategy();
        
        await strategy.ExecuteAsync(async () =>
        {
            await using var transaction = await _dbContext.Database.BeginTransactionAsync();
            
            try
            {
                await next.Send(context);
                await transaction.CommitAsync();
            }
            catch
            {
                await transaction.RollbackAsync();
                throw;
            }
        });
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("transaction");
    }
}

// Apply to specific consumer
cfg.ReceiveEndpoint("order-queue", e =>
{
    e.UseConsumeFilter(typeof(TransactionFilter<>), context);
    e.ConfigureConsumer<OrderSubmittedConsumer>(context);
});
```

### Performance Monitoring

```csharp
public class PerformanceMonitoringFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    private readonly IMetrics _metrics;
    
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        var messageType = typeof(T).Name;
        var sw = Stopwatch.StartNew();
        
        try
        {
            await next.Send(context);
            
            sw.Stop();
            
            // Record metrics
            _metrics.RecordConsumeSuccess(messageType, sw.ElapsedMilliseconds);
            _metrics.IncrementCounter($"messages.{messageType}.success");
        }
        catch (Exception ex)
        {
            sw.Stop();
            
            _metrics.RecordConsumeFailure(messageType, sw.ElapsedMilliseconds);
            _metrics.IncrementCounter($"messages.{messageType}.failure");
            _metrics.IncrementCounter($"messages.{messageType}.exception.{ex.GetType().Name}");
            
            throw;
        }
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("performance-monitoring");
    }
}
```

### Killswitch Filter

```csharp
// Circuit breaker that stops consuming on high error rate
public class KillswitchFilter<T> : IFilter<ConsumeContext<T>>
    where T : class
{
    private int _consecutiveFailures;
    private bool _killswitchActive;
    private readonly int _threshold = 10;
    
    public async Task Send(ConsumeContext<T> context, IPipe<ConsumeContext<T>> next)
    {
        if (_killswitchActive)
        {
            throw new InvalidOperationException(
                "Killswitch active due to high error rate");
        }
        
        try
        {
            await next.Send(context);
            _consecutiveFailures = 0;
        }
        catch
        {
            _consecutiveFailures++;
            
            if (_consecutiveFailures >= _threshold)
            {
                _killswitchActive = true;
                // Alert operations team
                await NotifyOpsTeamAsync();
            }
            
            throw;
        }
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateFilterScope("killswitch");
    }
}
```

## Self-Check Questions

1. What's the difference between retry and redelivery?
   - **Answer:** Retry happens immediately in the same consumer instance before acknowledgment. Redelivery returns the message to the queue with a delay, allowing another consumer instance to process it.

2. When should a circuit breaker be used?
   - **Answer:** When calling external services that might fail. The circuit breaker prevents cascading failures by stopping calls to failing services and giving them time to recover.

3. How do you create a custom filter?
   - **Answer:** Implement `IFilter<ConsumeContext<T>>` with a `Send` method that calls `next.Send(context)` to continue the pipeline. Register with `UseConsumeFilter()`.

4. What happens to messages when retries are exhausted?
   - **Answer:** MassTransit publishes a `Fault<T>` message and moves the original message to the error queue (if configured). Fault consumers can handle these permanently failed messages.

5. How does OpenTelemetry integration work?
   - **Answer:** MassTransit automatically creates spans for message publish/send/consume operations. Add MassTransit's trace source to your OpenTelemetry configuration to collect these spans.

6. What information is available in health checks?
   - **Answer:** Bus connection status, receive endpoint states (Ready/Stopped/Faulted), and transport-specific health information. Useful for Kubernetes readiness/liveness probes.

7. How do scoped filters differ from singleton filters?
   - **Answer:** Scoped filters are created per message using DI, allowing access to scoped services like DbContext. Singleton filters are created once and shared across all messages.

8. What's the purpose of partition filters?
   - **Answer:** Limit concurrent processing based on a partition key (e.g., customer ID), ensuring messages for the same partition are processed sequentially while allowing parallelism across partitions.

## Key Takeaways

- **Middleware pipeline** processes messages through a chain of filters before reaching the consumer
- **Retry policies** handle transient failures with configurable intervals (immediate, interval, exponential)
- **Circuit breakers** prevent cascading failures by opening after a threshold of failures
- **Rate limiting** controls message throughput per endpoint or globally
- **Custom filters** implement cross-cutting concerns (logging, validation, tenant isolation, transactions)
- **Error handling** includes retries, redelivery, fault messages, and dead letter queues
- **OpenTelemetry** integration provides distributed tracing and metrics out-of-the-box
- **Health checks** expose bus and endpoint status for monitoring and orchestration
- **Validation filters** reject invalid messages early before business logic executes
- **Deduplication** prevents processing the same message multiple times
- **Performance monitoring** tracks consume duration and success/failure rates
- **Filter order matters**: Applied in sequence (retry → circuit breaker → rate limit → custom → consumer)
