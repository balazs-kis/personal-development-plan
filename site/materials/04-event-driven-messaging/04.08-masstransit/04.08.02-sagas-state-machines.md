## Introduction

**Sagas** (also called process managers) coordinate long-running business processes that span multiple services. Instead of locking resources with distributed transactions, sagas orchestrate a series of local transactions, with compensation logic to handle failures. MassTransit provides powerful state machine capabilities through integration with Automatonymous.

Understanding sagas is essential for building reliable distributed systems that maintain consistency without distributed locks.

## Key Concepts Summary

### What is a Saga?

```
Traditional Transaction:
BEGIN TRANSACTION
  - Reserve inventory
  - Charge payment
  - Create shipment
COMMIT/ROLLBACK

Saga (Distributed):
1. Reserve inventory ✓
2. Charge payment ✓
3. Create shipment ✗ FAILED
→ Compensate: Refund payment
→ Compensate: Release inventory
```

### State Machine Definition

```csharp
public class OrderStateMachine : MassTransitStateMachine<OrderState>
{
    public OrderStateMachine()
    {
        // Define events
        Event(() => OrderSubmitted, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => PaymentProcessed, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => PaymentFailed, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => OrderShipped, x => x.CorrelateById(m => m.Message.OrderId));
        
        // Define initial state
        InstanceState(x => x.CurrentState);
        
        // Define transitions
        Initially(
            When(OrderSubmitted)
                .Then(context =>
                {
                    context.Saga.OrderId = context.Message.OrderId;
                    context.Saga.CustomerId = context.Message.CustomerId;
                    context.Saga.TotalAmount = context.Message.TotalAmount;
                    context.Saga.SubmittedAt = DateTime.UtcNow;
                })
                .TransitionTo(AwaitingPayment)
                .Publish(context => new ProcessPayment
                {
                    OrderId = context.Saga.OrderId,
                    Amount = context.Saga.TotalAmount
                }));
        
        During(AwaitingPayment,
            When(PaymentProcessed)
                .TransitionTo(Paid)
                .Publish(context => new ShipOrder
                {
                    OrderId = context.Saga.OrderId,
                    CustomerId = context.Saga.CustomerId
                }),
            
            When(PaymentFailed)
                .Then(context =>
                {
                    context.Saga.FailureReason = context.Message.Reason;
                })
                .TransitionTo(Cancelled)
                .Publish(context => new OrderCancelled
                {
                    OrderId = context.Saga.OrderId,
                    Reason = context.Saga.FailureReason
                }));
        
        During(Paid,
            When(OrderShipped)
                .TransitionTo(Shipped)
                .Finalize());
        
        SetCompletedWhenFinalized();
    }
    
    public State AwaitingPayment { get; private set; }
    public State Paid { get; private set; }
    public State Shipped { get; private set; }
    public State Cancelled { get; private set; }
    
    public Event<OrderSubmitted> OrderSubmitted { get; private set; }
    public Event<PaymentProcessed> PaymentProcessed { get; private set; }
    public Event<PaymentFailed> PaymentFailed { get; private set; }
    public Event<OrderShipped> OrderShipped { get; private set; }
}
```

### Compensation Pattern

```csharp
public class PaymentStateMachine : MassTransitStateMachine<PaymentState>
{
    public PaymentStateMachine()
    {
        Event(() => ProcessPayment, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => RefundPayment, x => x.CorrelateById(m => m.Message.OrderId));
        
        Initially(
            When(ProcessPayment)
                .Then(context =>
                {
                    // Charge payment
                    context.Saga.Amount = context.Message.Amount;
                    context.Saga.ChargedAt = DateTime.UtcNow;
                })
                .TransitionTo(Charged)
                .PublishAsync(context => context.Init<PaymentProcessed>(new
                {
                    OrderId = context.Saga.CorrelationId,
                    Amount = context.Saga.Amount
                })));
        
        During(Charged,
            When(RefundPayment)
                .Then(context =>
                {
                    // Compensate: refund the payment
                    context.Saga.RefundedAt = DateTime.UtcNow;
                })
                .TransitionTo(Refunded)
                .Publish(context => new PaymentRefunded
                {
                    OrderId = context.Saga.CorrelationId,
                    Amount = context.Saga.Amount
                })
                .Finalize());
        
        SetCompletedWhenFinalized();
    }
    
    public State Charged { get; private set; }
    public State Refunded { get; private set; }
    
    public Event<ProcessPayment> ProcessPayment { get; private set; }
    public Event<RefundPayment> RefundPayment { get; private set; }
}
```

### Scheduling and Timeouts

```csharp
public class OrderStateMachine : MassTransitStateMachine<OrderState>
{
    public OrderStateMachine()
    {
        Event(() => OrderSubmitted, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => PaymentProcessed, x => x.CorrelateById(m => m.Message.OrderId));
        
        // Timeout event
        Schedule(() => PaymentTimeout, x => x.PaymentTimeoutTokenId, s =>
        {
            s.Delay = TimeSpan.FromMinutes(15);
            s.Received = r => r.CorrelateById(context => context.Message.OrderId);
        });
        
        Initially(
            When(OrderSubmitted)
                .Then(context =>
                {
                    context.Saga.OrderId = context.Message.OrderId;
                })
                .TransitionTo(AwaitingPayment)
                .Schedule(PaymentTimeout, context => context.Init<PaymentTimeoutExpired>(new
                {
                    OrderId = context.Saga.OrderId
                }))
                .Publish(context => new ProcessPayment
                {
                    OrderId = context.Saga.OrderId
                }));
        
        During(AwaitingPayment,
            When(PaymentProcessed)
                .Unschedule(PaymentTimeout)  // Cancel timeout
                .TransitionTo(Paid),
            
            When(PaymentTimeout.Received)
                .Then(context =>
                {
                    context.Saga.FailureReason = "Payment timeout";
                })
                .TransitionTo(Cancelled)
                .Publish(context => new OrderCancelled
                {
                    OrderId = context.Saga.OrderId,
                    Reason = "Payment timeout"
                }));
    }
    
    public State AwaitingPayment { get; private set; }
    public State Paid { get; private set; }
    public State Cancelled { get; private set; }
    
    public Event<OrderSubmitted> OrderSubmitted { get; private set; }
    public Event<PaymentProcessed> PaymentProcessed { get; private set; }
    
    public Schedule<OrderState, PaymentTimeoutExpired> PaymentTimeout { get; private set; }
}
```

### Querying Saga State

```csharp
public class OrderStatusController : ControllerBase
{
    private readonly ISagaRepository<OrderState> _repository;
    
    public OrderStatusController(ISagaRepository<OrderState> repository)
    {
        _repository = repository;
    }
    
    [HttpGet("orders/{orderId}/status")]
    public async Task<IActionResult> GetStatus(Guid orderId)
    {
        // Query saga by correlation ID
        var saga = await _repository.Where(x => x.OrderId == orderId).FirstOrDefaultAsync();
        
        if (saga == null)
            return NotFound();
        
        return Ok(new
        {
            OrderId = saga.OrderId,
            State = saga.CurrentState,
            CustomerId = saga.CustomerId,
            TotalAmount = saga.TotalAmount,
            SubmittedAt = saga.SubmittedAt
        });
    }
}
```

### Advanced State Machine Features

```csharp
public class OrderStateMachine : MassTransitStateMachine<OrderState>
{
    public OrderStateMachine()
    {
        InstanceState(x => x.CurrentState);
        
        Event(() => OrderSubmitted, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => PaymentProcessed, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => PaymentFailed, x => x.CorrelateById(m => m.Message.OrderId));
        
        // Composite events: wait for multiple events
        CompositeEvent(() => OrderReadyToShip,
            x => x.OrderReadyFlags,
            PaymentProcessed, InventoryReserved);
        
        Initially(
            When(OrderSubmitted)
                .Then(context =>
                {
                    context.Saga.OrderId = context.Message.OrderId;
                    context.Saga.CustomerId = context.Message.CustomerId;
                })
                .TransitionTo(Processing)
                .Publish(context => new ProcessPayment
                {
                    OrderId = context.Saga.OrderId
                })
                .Publish(context => new ReserveInventory
                {
                    OrderId = context.Saga.OrderId
                }));
        
        During(Processing,
            // When both events received, trigger composite event
            When(OrderReadyToShip)
                .Then(context =>
                {
                    _logger.LogInformation("Order {OrderId} ready to ship", context.Saga.OrderId);
                })
                .TransitionTo(ReadyToShip)
                .Publish(context => new ShipOrder
                {
                    OrderId = context.Saga.OrderId
                }));
    }
    
    public State Processing { get; private set; }
    public State ReadyToShip { get; private set; }
    
    public Event<OrderSubmitted> OrderSubmitted { get; private set; }
    public Event<PaymentProcessed> PaymentProcessed { get; private set; }
    public Event<InventoryReserved> InventoryReserved { get; private set; }
    
    public Event OrderReadyToShip { get; private set; }
}
```

### Activities for Reusable Logic

```csharp
// Reusable activity
public class SendEmailActivity : IStateMachineActivity<OrderState, OrderSubmitted>
{
    private readonly IEmailService _emailService;
    
    public SendEmailActivity(IEmailService emailService)
    {
        _emailService = emailService;
    }
    
    public async Task Execute(
        BehaviorContext<OrderState, OrderSubmitted> context,
        IBehavior<OrderState, OrderSubmitted> next)
    {
        await _emailService.SendOrderConfirmationAsync(
            context.Saga.CustomerId,
            context.Saga.OrderId);
        
        await next.Execute(context);
    }
    
    public Task Faulted<TException>(
        BehaviorExceptionContext<OrderState, OrderSubmitted, TException> context,
        IBehavior<OrderState, OrderSubmitted> next)
        where TException : Exception
    {
        // Handle activity failure
        return next.Faulted(context);
    }
    
    public void Accept(StateMachineVisitor visitor)
    {
        visitor.Visit(this);
    }
    
    public void Probe(ProbeContext context)
    {
        context.CreateScope("send-email");
    }
}

// Use activity in state machine
Initially(
    When(OrderSubmitted)
        .Activity(x => x.OfType<SendEmailActivity>())
        .TransitionTo(Submitted));
```

### Error Handling in Sagas

```csharp
public class OrderStateMachine : MassTransitStateMachine<OrderState>
{
    public OrderStateMachine()
    {
        Event(() => OrderSubmitted, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => PaymentProcessed, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => PaymentFailed, x => x.CorrelateById(m => m.Message.OrderId));
        
        // Handle faults
        Event(() => OrderSubmittedFault, x =>
            x.CorrelateById(m => m.Message.Message.OrderId));
        
        Initially(
            When(OrderSubmitted)
                .Then(context =>
                {
                    context.Saga.OrderId = context.Message.OrderId;
                    context.Saga.RetryCount = 0;
                })
                .TransitionTo(Processing)
                .Publish(context => new ProcessPayment
                {
                    OrderId = context.Saga.OrderId
                }));
        
        During(Processing,
            When(PaymentProcessed)
                .TransitionTo(Paid)
                .Publish(context => new ShipOrder
                {
                    OrderId = context.Saga.OrderId
                }),
            
            When(PaymentFailed)
                .Then(context =>
                {
                    context.Saga.RetryCount++;
                })
                .If(context => context.Saga.RetryCount < 3,
                    binder => binder
                        .Publish(context => new ProcessPayment
                        {
                            OrderId = context.Saga.OrderId
                        }))
                .Else(binder => binder
                    .TransitionTo(Failed)
                    .Publish(context => new OrderFailed
                    {
                        OrderId = context.Saga.OrderId,
                        Reason = "Payment failed after 3 attempts"
                    })));
        
        // Handle unhandled exceptions
        DuringAny(
            When(OrderSubmittedFault)
                .Then(context =>
                {
                    var fault = context.Message;
                    _logger.LogError(
                        "Saga fault: {ExceptionType} - {Message}",
                        fault.Exceptions.First().ExceptionType,
                        fault.Exceptions.First().Message);
                })
                .TransitionTo(Faulted));
    }
    
    public State Processing { get; private set; }
    public State Paid { get; private set; }
    public State Failed { get; private set; }
    public State Faulted { get; private set; }
    
    public Event<OrderSubmitted> OrderSubmitted { get; private set; }
    public Event<PaymentProcessed> PaymentProcessed { get; private set; }
    public Event<PaymentFailed> PaymentFailed { get; private set; }
    public Event<Fault<OrderSubmitted>> OrderSubmittedFault { get; private set; }
}

public class OrderState : SagaStateMachineInstance
{
    public Guid CorrelationId { get; set; }
    public string CurrentState { get; set; }
    public Guid OrderId { get; set; }
    public string CustomerId { get; set; }
    public int RetryCount { get; set; }
}
```

```csharp
[TestFixture]
public class OrderStateMachineTests

    [OneTimeSetUp]

        await _harness.Stop();
    }

    public async Task OrderStateMachine_WithTimeout_CancelsOrder()
    {
        // Arrange
        var orderId = Guid.NewGuid();
        
        // Act: Submit order
        await _harness.Bus.Publish<OrderSubmitted>(new
        {
            OrderId = orderId,
            CustomerId = "customer-123"
        });

        var saga = _sagaHarness.Created.ContainsInState(
            orderId,
            _sagaHarness.StateMachine.Cancelled);
        
        Assert.That(saga, Is.Not.Null);
        Assert.That(saga.FailureReason, Is.EqualTo("Payment timeout"));
    }
```

## Self-Check Questions

1. What's the difference between a saga and a distributed transaction?
   - **Answer:** Distributed transactions use 2PC to lock resources across services, blocking until completion. Sagas coordinate through local transactions and events, using compensation for failures—no locks, better availability.

2. How does MassTransit correlate messages to saga instances?
   - **Answer:** Using `CorrelationId`. Events specify correlation through `CorrelateById()` in the state machine definition, mapping message properties to the saga's `CorrelationId`.

3. What is compensation logic and when is it needed?
   - **Answer:** Compensation undoes completed steps when a saga fails. Needed when you can't rollback distributed transactions—e.g., refund payment if shipping fails.

4. How do you implement timeouts in sagas?
   - **Answer:** Use `Schedule()` to define timeout events with delays. The state machine transitions to a timeout state if the expected event doesn't arrive within the specified time.

5. Where should saga state be persisted?
   - **Answer:** In a database accessible to the saga handler (Entity Framework, MongoDB, etc.). State must survive restarts and support queries for saga status.

6. What happens if a saga receives an event in the wrong state?
   - **Answer:** The event is ignored by default. You can use `Ignore()` explicitly or handle it with `DuringAny()`. MassTransit logs unhandled events for debugging.

7. How do composite events work?
   - **Answer:** Composite events trigger when multiple specified events have been received. MassTransit tracks which events arrived and fires the composite event when all conditions are met.

8. What's the difference between `Finalize()` and marking a saga complete?
   - **Answer:** `Finalize()` marks the saga as complete and moves it to the `Final` state. `SetCompletedWhenFinalized()` tells MassTransit to remove the saga from the repository once finalized.

## Key Takeaways

- **Sagas coordinate** long-running business processes across multiple services without distributed locks
- **State machines** define saga behavior through states, events, and transitions in a declarative way
- **Compensation logic** handles failures by undoing completed steps (e.g., refund, release inventory)
- **Persistence** is required—saga state must survive restarts and be queryable
- **Correlation** links messages to saga instances via `CorrelationId` configured in event definitions
- **Timeouts** handle scenarios where expected events never arrive, enabling automatic cleanup or retries
- **Composite events** wait for multiple events before triggering the next step
- **Activities** provide reusable saga logic that can be shared across state machines
- **Error handling** includes retry logic, failure states, and fault event handling
- **Concurrency** is managed through optimistic locking or pessimistic locks in the repository
- **Testing** is supported through `ISagaStateMachineTestHarness` for verifying state transitions
