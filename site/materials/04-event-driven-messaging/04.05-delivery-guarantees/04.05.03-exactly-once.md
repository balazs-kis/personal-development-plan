## Introduction

**Exactly-once semantics** (EOS) is the strongest delivery guarantee: each message is delivered exactly one time—never lost, never duplicated. This is the holy grail of distributed messaging, but it comes with significant complexity and performance costs.

In reality, true exactly-once delivery across all failure scenarios is theoretically impossible in distributed systems (see: Two Generals Problem). What Kafka calls "exactly-once" is more accurately "effectively once"—within the Kafka ecosystem, using specific APIs and configurations, you can achieve exactly-once processing semantics.

## Key Concepts Summary

### What is Exactly-Once Semantics?

**Definition:** A message will be delivered **exactly one time**—never lost, never duplicated.

```
Producer → Message → [Network/Broker/Consumer] → Delivered ONCE ✓
                                                  - Not lost ✓
                                                  - Not duplicated ✓
```

**Important clarification:**
- Exactly-once applies to the **messaging system**, not end-to-end application logic
- External side effects (database writes, API calls) require additional patterns
- Performance cost: 2-3x slower than at-least-once

### The Three Components of Kafka Exactly-Once

Kafka achieves exactly-once through three mechanisms:

#### 1. Idempotent Producer

Prevents duplicate messages on the producer side:

```csharp
var config = new ProducerConfig
{
    BootstrapServers = "localhost:9092",
    EnableIdempotence = true,        // Enable idempotence
    Acks = Acks.All,                 // Required for idempotence
    MaxInFlight = 5,                 // Can be > 1 with idempotence
    Retries = int.MaxValue           // Retry safely without duplicates
};

using var producer = new ProducerBuilder<string, Order>(config).Build();

// Producer automatically assigns:
// - Producer ID (PID): unique identifier for this producer instance
// - Sequence number: monotonically increasing per partition

await producer.ProduceAsync("orders", new Message<string, Order>
{
    Key = order.OrderId,
    Value = order
});

// If retry occurs, broker detects duplicate via PID + sequence number
// Duplicate is acknowledged but not stored again
```

**How it works:**
1. Producer is assigned a unique Producer ID (PID)
2. Each message gets a sequence number (per partition)
3. Broker tracks last sequence number from each PID
4. On retry, broker detects duplicate and returns success without storing

**Limitations:**
- Only prevents duplicates from same producer session
- PID changes if producer restarts
- Only guarantees idempotence within Kafka (not to external systems)

#### 2. Transactional Producer

Atomic writes across multiple partitions/topics:

```csharp
var config = new ProducerConfig
{
    BootstrapServers = "localhost:9092",
    EnableIdempotence = true,
    TransactionalId = "order-processor-1",  // Unique ID for this transactional producer
    TransactionTimeoutMs = 60000            // 60 second transaction timeout
};

using var producer = new ProducerBuilder<string, Order>(config).Build();

// Initialize transactions
producer.InitTransactions(TimeSpan.FromSeconds(10));

try
{
    // Begin transaction
    producer.BeginTransaction();
    
    // Produce multiple messages atomically
    await producer.ProduceAsync("orders", new Message<string, Order>
    {
        Key = order.OrderId,
        Value = order
    });
    
    await producer.ProduceAsync("order-events", new Message<string, OrderEvent>
    {
        Key = order.OrderId,
        Value = new OrderEvent { OrderId = order.OrderId, Type = "Created" }
    });
    
    await producer.ProduceAsync("inventory", new Message<string, InventoryUpdate>
    {
        Key = order.ProductId,
        Value = new InventoryUpdate { ProductId = order.ProductId, Quantity = -order.Quantity }
    });
    
    // Commit transaction - all messages written atomically
    producer.CommitTransaction();
}
catch (Exception ex)
{
    logger.LogError(ex, "Transaction failed, aborting");
    producer.AbortTransaction();
    throw;
}
```

**Guarantees:**
- All messages in transaction are written atomically
- Either all succeed or none appear
- Survives producer crashes/restarts (via TransactionalId)

#### 3. Transactional Consumer

Read-process-write exactly-once pattern:

```csharp
var consumerConfig = new ConsumerConfig
{
    GroupId = "order-processor",
    BootstrapServers = "localhost:9092",
    EnableAutoCommit = false,
    IsolationLevel = IsolationLevel.ReadCommitted,  // Only read committed transactions
    AutoOffsetReset = AutoOffsetReset.Earliest
};

var producerConfig = new ProducerConfig
{
    BootstrapServers = "localhost:9092",
    EnableIdempotence = true,
    TransactionalId = $"order-processor-{Guid.NewGuid()}"
};

using var consumer = new ConsumerBuilder<string, Order>(consumerConfig).Build();
using var producer = new ProducerBuilder<string, ProcessedOrder>(producerConfig).Build();

consumer.Subscribe("orders");
producer.InitTransactions(TimeSpan.FromSeconds(10));

while (true)
{
    var consumeResult = consumer.Consume(cancellationToken);
    
    try
    {
        producer.BeginTransaction();
        
        // Process message
        var processedOrder = await ProcessOrder(consumeResult.Message.Value);
        
        // Write result
        await producer.ProduceAsync("processed-orders", new Message<string, ProcessedOrder>
        {
            Key = processedOrder.OrderId,
            Value = processedOrder
        });
        
        // Commit consumer offset within transaction
        producer.SendOffsetsToTransaction(
            new[] {
                new TopicPartitionOffset(
                    consumeResult.TopicPartition,
                    consumeResult.Offset + 1
                )
            },
            consumer.ConsumerGroupMetadata,
            TimeSpan.FromSeconds(10)
        );
        
        // Commit transaction atomically
        producer.CommitTransaction();
    }
    catch (Exception ex)
    {
        logger.LogError(ex, "Processing failed, aborting transaction");
        producer.AbortTransaction();
        // Message will be reprocessed, but transaction ensures no duplicates
    }
}
```

**Key points:**
- `IsolationLevel.ReadCommitted` ensures consumer only sees committed data
- `SendOffsetsToTransaction` commits offsets atomically with produced messages
- If transaction aborts, neither output messages nor offset are committed
- Message will be reprocessed, but previous attempt's output is not visible

### Exactly-Once with External Systems

Kafka's exactly-once only covers Kafka operations. For external systems (databases, APIs), use additional patterns:

#### Pattern 1: Idempotent Database Operations

```csharp
public class OrderService
{
    private readonly DbContext _db;
    
    public async Task ProcessOrder(Order order, long kafkaOffset)
    {
        // Use Kafka offset as idempotency key
        var existing = await _db.ProcessedOrders
            .FirstOrDefaultAsync(o => o.OrderId == order.OrderId && o.KafkaOffset == kafkaOffset);
        
        if (existing != null)
        {
            // Already processed - idempotent
            return;
        }
        
        using var transaction = await _db.Database.BeginTransactionAsync();
        
        try
        {
            // Process order
            _db.Orders.Add(order);
            
            // Record processing with idempotency key
            _db.ProcessedOrders.Add(new ProcessedOrder
            {
                OrderId = order.OrderId,
                KafkaOffset = kafkaOffset,
                ProcessedAt = DateTime.UtcNow
            });
            
            await _db.SaveChangesAsync();
            await transaction.CommitAsync();
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}
```

#### Pattern 2: Transactional Outbox

Combine database transaction with Kafka transaction:

```csharp
public class OrderService
{
    private readonly DbContext _db;
    private readonly IProducer<string, OrderEvent> _producer;
    
    public async Task CreateOrder(Order order)
    {
        using var dbTransaction = await _db.Database.BeginTransactionAsync();
        
        try
        {
            // Write to database
            _db.Orders.Add(order);
            
            // Write to outbox table (same database transaction)
            _db.OutboxMessages.Add(new OutboxMessage
            {
                AggregateId = order.OrderId,
                EventType = "OrderCreated",
                Payload = JsonSerializer.Serialize(order),
                CreatedAt = DateTime.UtcNow
            });
            
            await _db.SaveChangesAsync();
            await dbTransaction.CommitAsync();
            
            // Separate process reads outbox and publishes to Kafka
            // See Lesson 5: Transactional Messaging for details
        }
        catch
        {
            await dbTransaction.RollbackAsync();
            throw;
        }
    }
}
```

### Performance Impact

**Throughput comparison (approximate):**

```
At-most-once:  100,000 msg/sec
At-least-once:  50,000 msg/sec
Exactly-once:   20,000 msg/sec (with transactions)
```

**Latency comparison:**

```
At-most-once:    1-2 ms per message
At-least-once:   3-5 ms per message
Exactly-once:   10-15 ms per message
```

**Why exactly-once is slower:**
- Additional broker coordination
- Transaction log writes
- Increased disk I/O
- More network round trips

### When to Use Exactly-Once

**Use exactly-once when:**
- ✅ Financial transactions (payments, transfers)
- ✅ Inventory management (stock levels must be precise)
- ✅ Billing systems (no duplicate charges)
- ✅ Compliance/audit requirements (exact counts matter)
- ✅ State aggregation (count, sum where duplicates would corrupt results)

**Don't use exactly-once when:**
- ❌ High throughput is critical
- ❌ Occasional duplicates are acceptable (use idempotent consumers instead)
- ❌ Simple logging/metrics
- ❌ Read-only operations
- ❌ Idempotent natural operations (e.g., "set status to X")

### Exactly-Once Limitations

1. **Not end-to-end:** Only within Kafka ecosystem
2. **Performance cost:** 2-3x slower than at-least-once
3. **Complexity:** More configuration and error handling
4. **External systems:** Requires additional patterns (outbox, idempotency)
5. **Kafka Streams/Connect:** Best support; raw consumer/producer requires careful implementation

```csharp
// Example: Kafka Streams has built-in exactly-once
var config = new StreamsConfig
{
    ApplicationId = "order-processor",
    BootstrapServers = "localhost:9092",
    ProcessingGuarantee = ProcessingGuarantee.ExactlyOnce  // Built-in support
};

// Streams API handles transactions automatically
// Much simpler than manual consumer/producer transactions
```

### Advanced Transactional Patterns

**Pattern 1: Multi-Topic Atomic Writes:**

```csharp
public class MultiTopicTransactionalProducer
{
    private readonly IProducer<string, string> _producer;
    
    public async Task PublishOrderCreated(Order order)
    {
        try
        {
            _producer.BeginTransaction();
            
            // Write to multiple topics atomically
            await _producer.ProduceAsync("orders", new Message<string, string>
            {
                Key = order.Id,
                Value = JsonSerializer.Serialize(order)
            });
            
            await _producer.ProduceAsync("order-events", new Message<string, string>
            {
                Key = order.Id,
                Value = JsonSerializer.Serialize(new OrderCreatedEvent(order))
            });
            
            await _producer.ProduceAsync("inventory-updates", new Message<string, string>
            {
                Key = order.ProductId,
                Value = JsonSerializer.Serialize(new InventoryReserved(order))
            });
            
            await _producer.ProduceAsync("analytics", new Message<string, string>
            {
                Key = order.CustomerId,
                Value = JsonSerializer.Serialize(new OrderMetrics(order))
            });
            
            // All messages written atomically
            _producer.CommitTransaction();
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Transaction failed, aborting");
            _producer.AbortTransaction();
            throw;
        }
    }
```

**Pattern 2: Consume-Transform-Produce Exactly-Once:**

```csharp
public class TransformationPipeline
{
    private readonly IConsumer<string, RawOrder> _consumer;
    private readonly IProducer<string, EnrichedOrder> _producer;
    
    public async Task ProcessPipeline()
    {
        var consumerConfig = new ConsumerConfig
        {
            GroupId = "order-enricher",
            BootstrapServers = "localhost:9092",
            EnableAutoCommit = false,
            IsolationLevel = IsolationLevel.ReadCommitted
        };
        
        var producerConfig = new ProducerConfig
        {
            BootstrapServers = "localhost:9092",
            EnableIdempotence = true,
            TransactionalId = $"order-enricher-{Environment.MachineName}"
        };
        
        _consumer = new ConsumerBuilder<string, RawOrder>(consumerConfig).Build();
        _producer = new ProducerBuilder<string, EnrichedOrder>(producerConfig).Build();
        
        _consumer.Subscribe("raw-orders");
        _producer.InitTransactions(TimeSpan.FromSeconds(10));
        
        while (true)
        {
            var result = _consumer.Consume();
            
            try
            {
                _producer.BeginTransaction();
                
                // Transform message
                var enrichedOrder = await EnrichOrder(result.Message.Value);
                
                // Produce result
                await _producer.ProduceAsync("enriched-orders",
                    new Message<string, EnrichedOrder>
                    {
                        Key = enrichedOrder.OrderId,
                        Value = enrichedOrder
                    });
                
                // Commit offset within transaction
                _producer.SendOffsetsToTransaction(
                    new[] { new TopicPartitionOffset(result.TopicPartition, result.Offset + 1) },
                    _consumer.ConsumerGroupMetadata,
                    TimeSpan.FromSeconds(10));
                
                _producer.CommitTransaction();
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Pipeline processing failed");
                _producer.AbortTransaction();
                // Will reprocess from last committed offset
            }
        }
    }
}
```

**Pattern 3: Transactional Read-Write:**

```csharp
public class StatefulProcessor
{
    private readonly Dictionary<string, CustomerState> _stateStore = new();
    
    public async Task ProcessWithState()
    {
        var consumer = new ConsumerBuilder<string, OrderEvent>(consumerConfig).Build();
        var producer = new ProducerBuilder<string, CustomerStats>(producerConfig).Build();
        
        consumer.Subscribe("order-events");
        producer.InitTransactions(TimeSpan.FromSeconds(10));
        
        while (true)
        {
            var result = consumer.Consume();
            
            try
            {
                producer.BeginTransaction();
                
                // Read from local state store
                var customerId = result.Message.Value.CustomerId;
                if (!_stateStore.TryGetValue(customerId, out var state))
                {
                    state = new CustomerState { CustomerId = customerId };
                    _stateStore[customerId] = state;
                }
                
                // Update state
                state.TotalOrders++;
                state.TotalSpent += result.Message.Value.Amount;
                
                // Write updated stats
                await producer.ProduceAsync("customer-stats",
                    new Message<string, CustomerStats>
                    {
                        Key = customerId,
                        Value = new CustomerStats
                        {
                            CustomerId = customerId,
                            TotalOrders = state.TotalOrders,
                            TotalSpent = state.TotalSpent
                        }
                    });
                
                // Commit transaction
                producer.SendOffsetsToTransaction(
                    new[] { new TopicPartitionOffset(result.TopicPartition, result.Offset + 1) },
                    consumer.ConsumerGroupMetadata,
                    TimeSpan.FromSeconds(10));
                
                producer.CommitTransaction();
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Processing failed");
                producer.AbortTransaction();
            }
        }
    }
}
```

### Transaction Coordinator and Logs

**Understanding transaction internals:**

```
Kafka Transaction Flow:

1. Producer: InitTransactions()
   → Finds transaction coordinator
   → Gets Producer ID (PID)

2. Producer: BeginTransaction()
   → Local transaction state

3. Producer: ProduceAsync(topic, message)
   → Writes to partition with PID + sequence number
   → Marks as part of transaction

4. Producer: SendOffsetsToTransaction(offsets)
   → Writes offsets to __consumer_offsets (transactionally)

5. Producer: CommitTransaction()
   → Transaction Coordinator writes commit marker
   → Messages become visible to ReadCommitted consumers
```

**Transaction logs:**

- `__transaction_state`: Stores transaction metadata
- Transaction markers in each partition: `COMMIT` or `ABORT`
- Consumers with `IsolationLevel.ReadCommitted` only see committed messages

### Monitoring Transactions

```csharp
public class TransactionMonitoring
{
    public void MonitorTransactionMetrics()
    {
        // Key metrics to track:
        
        // 1. Transaction rate
        _metrics.RecordCounter("kafka.transactions.started");
        _metrics.RecordCounter("kafka.transactions.committed");
        _metrics.RecordCounter("kafka.transactions.aborted");
        
        // 2. Transaction duration
        var sw = Stopwatch.StartNew();
        // ... transaction code ...
        _metrics.RecordHistogram("kafka.transaction.duration_ms", sw.ElapsedMilliseconds);
        
        // 3. Transaction size (messages per transaction)
        _metrics.RecordHistogram("kafka.transaction.message_count", messageCount);
        
        // 4. Abort rate
        var abortRate = _metrics.GetCounter("kafka.transactions.aborted").Value /
                       _metrics.GetCounter("kafka.transactions.started").Value;
        
        if (abortRate > 0.1)
        {
            _logger.LogWarning("High transaction abort rate: {Rate}%", abortRate * 100);
        }
    }
}
```

### Error Handling in Transactions

```csharp
public class RobustTransactionalProcessor
{
    public async Task ProcessWithRetry(ConsumeResult<string, Order> result)
    {
        var maxRetries = 3;
        
        for (int attempt = 1; attempt <= maxRetries; attempt++)
        {
            try
            {
                _producer.BeginTransaction();
                
                // Process message
                var processed = await ProcessOrder(result.Message.Value);
                
                // Produce result
                await _producer.ProduceAsync("processed-orders",
                    new Message<string, ProcessedOrder>
                    {
                        Key = processed.OrderId,
                        Value = processed
                    });
                
                // Commit offset
                _producer.SendOffsetsToTransaction(
                    new[] { new TopicPartitionOffset(result.TopicPartition, result.Offset + 1) },
                    _consumer.ConsumerGroupMetadata,
                    TimeSpan.FromSeconds(10));
                
                _producer.CommitTransaction();
                
                return;  // Success
            }
            catch (KafkaException ex) when (ex.Error.IsRetriable && attempt < maxRetries)
            {
                _logger.LogWarning(
                    "Transaction attempt {Attempt}/{Max} failed: {Error}",
                    attempt, maxRetries, ex.Error.Reason);
                
                try
                {
                    _producer.AbortTransaction();
                }
                catch
                {
                    // Abort may fail if transaction already aborted
                }
                
                await Task.Delay(TimeSpan.FromSeconds(Math.Pow(2, attempt)));
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Transaction failed permanently");
                
                try
                {
                    _producer.AbortTransaction();
                }
                catch { }
                
                throw;
            }
        }
        
        throw new Exception($"Transaction failed after {maxRetries} attempts");
    }
}
```
