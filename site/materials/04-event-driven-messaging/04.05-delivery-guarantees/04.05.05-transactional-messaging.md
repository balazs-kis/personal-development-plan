---

## Introduction

One of the hardest problems in distributed systems is ensuring atomicity between database changes and message publishing. Consider this scenario: You save an order to the database and then publish an "OrderCreated" event—but what if the publish fails? Or what if the publish succeeds but the database commit fails?

**Transactional messaging** patterns solve this problem by treating message publishing as part of the database transaction. The most common pattern is the **Transactional Outbox**, which ensures that database updates and message publishes are atomic, preventing lost messages or inconsistent state.

## Key Concepts Summary

### The Problem: Dual Writes

**Scenario:** Create order and publish event

```csharp
// ❌ PROBLEMATIC: Two separate writes (not atomic)
public class OrderService
{
    public async Task CreateOrder(Order order)
    {
        // Write 1: Database
        await _db.Orders.AddAsync(order);
        await _db.SaveChangesAsync();
        
        // Write 2: Message broker
        await _producer.ProduceAsync("orders", new Message<string, Order>
        {
            Key = order.Id,
            Value = order
        });
    }
}
```

**What can go wrong:**

1. **Database succeeds, message fails:**
   ```
   Order saved ✓
   Message publish fails ✗
   Result: Order exists but no event → downstream systems unaware
   ```

2. **Message succeeds, database fails:**
   ```
   Message published ✓
   Database save fails (constraint violation) ✗
   Result: Event exists but no order → inconsistent state
   ```

3. **Partial success with retries:**
   ```
   Database save succeeds
   Message publish times out (unclear if succeeded)
   Retry attempt → duplicate message?
   ```

### Solution 1: Transactional Outbox Pattern

**Core idea:** Write messages to a database table within the same transaction, then publish them separately.

#### Schema Design

```sql
CREATE TABLE OutboxMessages (
    Id UNIQUEIDENTIFIER PRIMARY KEY,
    AggregateId NVARCHAR(255) NOT NULL,
    AggregateType NVARCHAR(255) NOT NULL,
    EventType NVARCHAR(255) NOT NULL,
    Payload NVARCHAR(MAX) NOT NULL,
    CreatedAt DATETIME2 NOT NULL,
    ProcessedAt DATETIME2 NULL,
    INDEX IX_OutboxMessages_ProcessedAt (ProcessedAt) WHERE ProcessedAt IS NULL
);
```

```csharp
public class OutboxMessage
{
    public Guid Id { get; set; }
    public string AggregateId { get; set; }
    public string AggregateType { get; set; }
    public string EventType { get; set; }
    public string Payload { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? ProcessedAt { get; set; }
}
```

#### Writing to Outbox

```csharp
public class OrderService
{
    private readonly DbContext _db;
    
    public async Task CreateOrder(Order order)
    {
        using var transaction = await _db.Database.BeginTransactionAsync();
        
        try
        {
            // Write 1: Save order to database
            _db.Orders.Add(order);
            
            // Write 2: Save event to outbox (same transaction)
            _db.OutboxMessages.Add(new OutboxMessage
            {
                Id = Guid.NewGuid(),
                AggregateId = order.Id,
                AggregateType = nameof(Order),
                EventType = "OrderCreated",
                Payload = JsonSerializer.Serialize(new OrderCreatedEvent
                {
                    OrderId = order.Id,
                    CustomerId = order.CustomerId,
                    TotalAmount = order.TotalAmount,
                    Items = order.Items
                }),
                CreatedAt = DateTime.UtcNow
            });
            
            await _db.SaveChangesAsync();
            await transaction.CommitAsync();
            
            // Both writes are atomic ✓
            // If commit fails, neither order nor outbox message exist
            // If commit succeeds, both exist together
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}
```

**Key benefit:** Atomicity guaranteed by database transaction

#### Publishing from Outbox: Polling Approach

**Background service polls the outbox and publishes messages:**

```csharp
public class OutboxPublisher : BackgroundService
{
    private readonly IServiceProvider _serviceProvider;
    private readonly ILogger<OutboxPublisher> _logger;
    
    public OutboxPublisher(IServiceProvider serviceProvider, ILogger<OutboxPublisher> logger)
    {
        _serviceProvider = serviceProvider;
        _logger = logger;
    }
    
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await ProcessOutboxMessages(stoppingToken);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error processing outbox messages");
            }
            
            await Task.Delay(TimeSpan.FromSeconds(1), stoppingToken);
        }
    }
    
    private async Task ProcessOutboxMessages(CancellationToken cancellationToken)
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<DbContext>();
        var producer = scope.ServiceProvider.GetRequiredService<IProducer<string, string>>();
        
        // Fetch unprocessed messages
        var messages = await db.OutboxMessages
            .Where(m => m.ProcessedAt == null)
            .OrderBy(m => m.CreatedAt)
            .Take(100)
            .ToListAsync(cancellationToken);
        
        foreach (var message in messages)
        {
            try
            {
                // Publish to Kafka
                await producer.ProduceAsync(
                    GetTopicName(message.AggregateType),
                    new Message<string, string>
                    {
                        Key = message.AggregateId,
                        Value = message.Payload,
                        Headers = new Headers
                        {
                            { "event-type", Encoding.UTF8.GetBytes(message.EventType) },
                            { "aggregate-id", Encoding.UTF8.GetBytes(message.AggregateId) }
                        }
                    },
                    cancellationToken
                );
                
                // Mark as processed
                message.ProcessedAt = DateTime.UtcNow;
                await db.SaveChangesAsync(cancellationToken);
                
                _logger.LogInformation(
                    "Published outbox message {MessageId} of type {EventType}",
                    message.Id,
                    message.EventType
                );
            }
            catch (Exception ex)
            {
                _logger.LogError(
                    ex,
                    "Failed to publish outbox message {MessageId}",
                    message.Id
                );
                // Continue to next message, will retry on next poll
            }
        }
    }
    
    private string GetTopicName(string aggregateType) => aggregateType.ToLowerInvariant() + "-events";
}
```

**Characteristics:**
- **Pros:** Simple to implement, no external dependencies
- **Cons:** Polling introduces latency, database load

**Optimizations:**
- Batch publishing (multiple messages per poll)
- Exponential backoff on failures
- Multiple publisher instances for scalability
- Cleanup of old processed messages

### Solution 2: Event Sourcing with Outbox

Combine event sourcing with outbox for ultimate reliability:

```csharp
public class OrderAggregate
{
    private readonly List<IDomainEvent> _uncommittedEvents = new();
    
    public string Id { get; private set; }
    public string CustomerId { get; private set; }
    public decimal TotalAmount { get; private set; }
    public OrderStatus Status { get; private set; }
    
    public void Create(string customerId, decimal totalAmount)
    {
        var evt = new OrderCreatedEvent
        {
            OrderId = Guid.NewGuid().ToString(),
            CustomerId = customerId,
            TotalAmount = totalAmount
        };
        
        Apply(evt);
        _uncommittedEvents.Add(evt);
    }
    
    private void Apply(OrderCreatedEvent evt)
    {
        Id = evt.OrderId;
        CustomerId = evt.CustomerId;
        TotalAmount = evt.TotalAmount;
        Status = OrderStatus.Created;
    }
    
    public IReadOnlyList<IDomainEvent> GetUncommittedEvents() => _uncommittedEvents.AsReadOnly();
}

public class EventSourcingRepository
{
    private readonly DbContext _db;
    
    public async Task Save(OrderAggregate aggregate)
    {
        using var transaction = await _db.Database.BeginTransactionAsync();
        
        try
        {
            foreach (var evt in aggregate.GetUncommittedEvents())
            {
                // Persist event to event store
                _db.Events.Add(new EventRecord
                {
                    AggregateId = aggregate.Id,
                    EventType = evt.GetType().Name,
                    Payload = JsonSerializer.Serialize(evt),
                    CreatedAt = DateTime.UtcNow
                });
                
                // Also write to outbox for external publishing
                _db.OutboxMessages.Add(new OutboxMessage
                {
                    Id = Guid.NewGuid(),
                    AggregateId = aggregate.Id,
                    AggregateType = nameof(Order),
                    EventType = evt.GetType().Name,
                    Payload = JsonSerializer.Serialize(evt),
                    CreatedAt = DateTime.UtcNow
                });
            }
            
            await _db.SaveChangesAsync();
            await transaction.CommitAsync();
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}
```

### Handling Failures

**Scenario 1: Message publish fails**

```
1. Order and outbox message committed ✓
2. Publisher attempts to send to Kafka
3. Kafka publish fails (network error)
4. Message remains in outbox (ProcessedAt = NULL)
5. Next polling cycle retries
6. Eventually succeeds (at-least-once delivery)
```

**Consumer must be idempotent to handle retries**

**Scenario 2: Marking processed fails**

```
1. Message successfully published to Kafka ✓
2. Database update (ProcessedAt) fails
3. Message remains unprocessed in outbox
4. Next poll republishes (duplicate in Kafka)
5. Consumer deduplicates using message ID
```

**Solution: Include outbox message ID in Kafka message headers**

```csharp
await producer.ProduceAsync(topic, new Message<string, string>
{
    Key = message.AggregateId,
    Value = message.Payload,
    Headers = new Headers
    {
        { "outbox-message-id", Encoding.UTF8.GetBytes(message.Id.ToString()) }
    }
});

// Consumer checks outbox-message-id for deduplication
```

### Complete Example: Order Service with Outbox

```csharp
// Domain Event
public record OrderCreatedEvent(string OrderId, string CustomerId, decimal TotalAmount);

// Outbox Message Entity
public class OutboxMessage
{
    public Guid Id { get; set; }
    public string AggregateId { get; set; }
    public string EventType { get; set; }
    public string Payload { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? ProcessedAt { get; set; }
}

// Service with Outbox Write
public class OrderService
{
    private readonly ApplicationDbContext _db;
    
    public async Task<string> CreateOrder(string customerId, decimal totalAmount)
    {
        var orderId = Guid.NewGuid().ToString();
        
        using var transaction = await _db.Database.BeginTransactionAsync();
        
        try
        {
            // Write order
            var order = new Order
            {
                Id = orderId,
                CustomerId = customerId,
                TotalAmount = totalAmount,
                Status = OrderStatus.Created
            };
            _db.Orders.Add(order);
            
            // Write event to outbox
            var evt = new OrderCreatedEvent(orderId, customerId, totalAmount);
            _db.OutboxMessages.Add(new OutboxMessage
            {
                Id = Guid.NewGuid(),
                AggregateId = orderId,
                EventType = nameof(OrderCreatedEvent),
                Payload = JsonSerializer.Serialize(evt),
                CreatedAt = DateTime.UtcNow
            });
            
            await _db.SaveChangesAsync();
            await transaction.CommitAsync();
            
            return orderId;
        }
        catch
        {
            await transaction.RollbackAsync();
            throw;
        }
    }
}

// Background Publisher
public class OutboxPublisher : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            await ProcessOutbox(stoppingToken);
            await Task.Delay(TimeSpan.FromMilliseconds(500), stoppingToken);
        }
    }
    
    private async Task ProcessOutbox(CancellationToken ct)
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>();
        var producer = scope.ServiceProvider.GetRequiredService<IProducer<string, string>>();
        
        var messages = await db.OutboxMessages
            .Where(m => m.ProcessedAt == null)
            .OrderBy(m => m.CreatedAt)
            .Take(50)
            .ToListAsync(ct);
        
        foreach (var msg in messages)
        {
            try
            {
                await producer.ProduceAsync("orders", new Message<string, string>
                {
                    Key = msg.AggregateId,
                    Value = msg.Payload
                }, ct);
                
                msg.ProcessedAt = DateTime.UtcNow;
                await db.SaveChangesAsync(ct);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Failed to publish message {Id}", msg.Id);
            }
        }
    }
}
```

### Outbox Maintenance and Optimization

**Cleanup of processed messages:**

```csharp
public class OutboxCleanupService : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await CleanupOldMessages();
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error cleaning up outbox");
            }
            
            // Run cleanup every hour
            await Task.Delay(TimeSpan.FromHours(1), stoppingToken);
        }
    }
    
    private async Task CleanupOldMessages()
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>();
        
        // Delete messages processed more than 7 days ago
        var cutoff = DateTime.UtcNow.AddDays(-7);
        
        var deleted = await db.OutboxMessages
            .Where(m => m.ProcessedAt != null && m.ProcessedAt < cutoff)
            .ExecuteDeleteAsync();
        
        _logger.LogInformation("Cleaned up {Count} old outbox messages", deleted);
    }
}
```

**Horizontal scaling with distributed locks:**

```csharp
public class DistributedOutboxPublisher : BackgroundService
{
    private readonly IDistributedLockProvider _lockProvider;
    
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            // Acquire distributed lock to prevent multiple instances processing same messages
            await using (var @lock = await _lockProvider.AcquireLockAsync(
                "outbox-publisher", 
                TimeSpan.FromSeconds(30), 
                stoppingToken))
            {
                if (@lock != null)
                {
                    await ProcessOutbox(stoppingToken);
                }
                else
                {
                    // Another instance holds the lock
                    await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
                }
            }
            
            await Task.Delay(TimeSpan.FromMilliseconds(100), stoppingToken);
        }
    }
}
```
