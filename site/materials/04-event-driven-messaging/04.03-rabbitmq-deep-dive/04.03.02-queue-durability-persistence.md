## Introduction

Message persistence and queue durability are essential for building reliable systems with RabbitMQ. While RabbitMQ is primarily an in-memory broker for performance, it provides durability options to ensure messages survive broker crashes and restarts. Understanding these options helps you balance reliability with performance.

## Key Concepts Summary

### Three Levels of Durability

**1. Queue Durability**
```csharp
// Durable queue survives broker restart
channel.QueueDeclare(
    queue: "orders",
    durable: true,      // Queue definition survives restart
    exclusive: false,
    autoDelete: false
);

// Non-durable queue (deleted on restart)
channel.QueueDeclare(
    queue: "temp_queue",
    durable: false,     // Queue deleted on restart
    exclusive: false,
    autoDelete: false
);
```

**2. Message Persistence**
```csharp
// Persistent messages written to disk
var properties = channel.CreateBasicProperties();
properties.Persistent = true;  // Message survives restart

channel.BasicPublish(
    exchange: "",
    routingKey: "orders",
    basicProperties: properties,
    body: message
);

// Non-persistent (faster but lost on crash)
properties.Persistent = false;
channel.BasicPublish("", "orders", properties, message);
```

**3. Exchange Durability**
```csharp
// Durable exchange
channel.ExchangeDeclare(
    exchange: "orders_exchange",
    type: ExchangeType.Topic,
    durable: true       // Exchange survives restart
);
```

### Durability Matrix

| Queue Durable | Message Persistent | Survives Restart? |
|---------------|-------------------|-------------------|
| No | No | ❌ Nothing survives |
| Yes | No | Queue survives, messages lost |
| No | Yes | ❌ Everything lost |
| Yes | Yes | ✅ Everything survives |

### Lazy Queues

**For durability-critical scenarios:**
```csharp
// Lazy queue: messages immediately written to disk
var args = new Dictionary<string, object>
{
    { "x-queue-mode", "lazy" }
};

channel.QueueDeclare(
    queue: "critical_orders",
    durable: true,
    exclusive: false,
    autoDelete: false,
    arguments: args
);

// Benefits: Better durability, handles millions of messages
// Trade-off: Higher latency (disk I/O)
```

**When to Use Lazy Queues:**

1. **Large message backlogs** - Messages go to disk immediately
2. **Predictable memory usage** - Doesn't spike with message volume
3. **Long-term message storage** - Can hold millions of messages
4. **Lower memory requirements** - Frees up RAM for other operations

**Performance Comparison:**

```csharp
public class LazyQueuePerformance
{
    public async Task CompareLazyVsNormal()
    {
        // Normal queue: Fast initially, slows under load
        var normalQueue = SetupNormalQueue();
        await PublishMessages(normalQueue, 100_000);
        // Memory: 2GB, Throughput: 50k msg/sec
        
        // Lazy queue: Consistent performance
        var lazyQueue = SetupLazyQueue();
        await PublishMessages(lazyQueue, 100_000);
        // Memory: 200MB, Throughput: 20k msg/sec
        
        // Lazy queue wins: high volume, limited memory
        // Normal queue wins: low latency, plenty of memory
    }
    
    private string SetupLazyQueue()
    {
        var args = new Dictionary<string, object>
        {
            { "x-queue-mode", "lazy" }
        };
        
        _channel.QueueDeclare("lazy_orders", durable: true, arguments: args);
        return "lazy_orders";
    }
    
    private string SetupNormalQueue()
    {
        _channel.QueueDeclare("normal_orders", durable: true);
        return "normal_orders";
    }
}
```

### Quorum Queues (RabbitMQ 3.8+)

**For high availability:**
```csharp
var args = new Dictionary<string, object>
{
    { "x-queue-type", "quorum" }
};

channel.QueueDeclare(
    queue: "ha_orders",
    durable: true,
    exclusive: false,
    autoDelete: false,
    arguments: args
);

// Replicated across cluster
// Strong consistency
// Automatic failover
```

**Quorum Queue Features:**

```csharp
public class QuorumQueueFeatures
{
    public void DemonstrateQuorumFeatures()
    {
        // 1. Replicated by default (majority of nodes)
        var args = new Dictionary<string, object>
        {
            { "x-queue-type", "quorum" }
        };
        
        _channel.QueueDeclare("orders", durable: true, arguments: args);
        
        // 2. Automatic leader election
        // If leader node fails, new leader elected automatically
        
        // 3. Strong consistency (no message loss)
        // Message written to majority before publisher confirm
        
        // 4. Poison message handling
        var quorumArgs = new Dictionary<string, object>
        {
            { "x-queue-type", "quorum" },
            { "x-delivery-limit", 3 }  // Auto-DLX after 3 redeliveries
        };
        
        _channel.QueueDeclare("safe_orders", durable: true, arguments: quorumArgs);
    }
}
```

**Quorum vs Classic Queues:**

| Feature | Classic Queue | Quorum Queue |
|---------|--------------|--------------|
| **Replication** | Optional (mirroring) | Built-in (Raft) |
| **Consistency** | Eventually consistent | Strongly consistent |
| **Performance** | Higher throughput | Lower throughput |
| **Memory** | In-memory by default | Disk-backed |
| **Ordering** | Per-consumer | Total order |
| **Poison message handling** | Manual | Automatic |
| **Recommended for** | High throughput | Critical data |

### Persistence Configuration in Practice

**Mission-Critical System:**

```csharp
public class MissionCriticalSetup
{
    public void SetupFinancialTransactionQueue()
    {
        using var channel = _connection.CreateModel();
        
        // 1. Durable exchange
        channel.ExchangeDeclare(
            exchange: "financial_transactions",
            type: ExchangeType.Topic,
            durable: true,
            autoDelete: false
        );
        
        // 2. Quorum queue for high availability
        var args = new Dictionary<string, object>
        {
            { "x-queue-type", "quorum" },
            { "x-delivery-limit", 5 },  // Auto-DLX after 5 retries
            { "x-dead-letter-exchange", "failed_transactions" }
        };
        
        channel.QueueDeclare(
            queue: "transactions",
            durable: true,
            exclusive: false,
            autoDelete: false,
            arguments: args
        );
        
        // 3. Bind queue
        channel.QueueBind("transactions", "financial_transactions", "#");
        
        // 4. Configure dead letter exchange
        channel.ExchangeDeclare("failed_transactions", ExchangeType.Fanout, durable: true);
        channel.QueueDeclare("failed_transactions_queue", durable: true);
        channel.QueueBind("failed_transactions_queue", "failed_transactions", "");
    }
    
    public void PublishTransaction(Transaction tx)
    {
        using var channel = _connection.CreateModel();
        
        // Enable publisher confirms
        channel.ConfirmSelect();
        
        // Create persistent message
        var props = channel.CreateBasicProperties();
        props.Persistent = true;
        props.MessageId = tx.Id.ToString();
        props.Timestamp = new AmqpTimestamp(DateTimeOffset.UtcNow.ToUnixTimeSeconds());
        
        var body = Encoding.UTF8.GetBytes(JsonSerializer.Serialize(tx));
        
        channel.BasicPublish(
            exchange: "financial_transactions",
            routingKey: $"{tx.Type}.{tx.Currency}",
            basicProperties: props,
            body: body
        );
        
        // Wait for broker confirmation
        if (!channel.WaitForConfirms(TimeSpan.FromSeconds(5)))
        {
            throw new Exception("Transaction not confirmed by broker");
        }
    }
}
```

**High-Throughput System:**

```csharp
public class HighThroughputSetup
{
    public void SetupAnalyticsQueue()
    {
        using var channel = _connection.CreateModel();
        
        // Non-durable for speed (acceptable data loss)
        channel.ExchangeDeclare(
            exchange: "analytics_events",
            type: ExchangeType.Fanout,
            durable: false,  // Faster
            autoDelete: false
        );
        
        // Non-durable queue
        channel.QueueDeclare(
            queue: "analytics",
            durable: false,  // In-memory only
            exclusive: false,
            autoDelete: false
        );
        
        channel.QueueBind("analytics", "analytics_events", "");
    }
    
    public void PublishEvent(AnalyticsEvent evt)
    {
        using var channel = _connection.CreateModel();
        
        // Non-persistent message
        var props = channel.CreateBasicProperties();
        props.Persistent = false;  // Faster
        
        var body = Encoding.UTF8.GetBytes(JsonSerializer.Serialize(evt));
        
        // No confirms for maximum throughput
        channel.BasicPublish(
            exchange: "analytics_events",
            routingKey: "",
            basicProperties: props,
            body: body
        );
    }
}
```

### Monitoring Persistence and Performance

```csharp
public class PersistenceMonitoring
{
    public void MonitorQueueMetrics()
    {
        // Use RabbitMQ Management API
        var client = new HttpClient();
        client.DefaultRequestHeaders.Authorization = 
            new AuthenticationHeaderValue("Basic", 
                Convert.ToBase64String(Encoding.ASCII.GetBytes("guest:guest")));
        
        var response = await client.GetAsync("http://localhost:15672/api/queues/%2F/orders");
        var json = await response.Content.ReadAsStringAsync();
        var queue = JsonSerializer.Deserialize<QueueInfo>(json);
        
        // Key metrics
        _logger.LogInformation($"Messages: {queue.Messages}");
        _logger.LogInformation($"Messages Ready: {queue.MessagesReady}");
        _logger.LogInformation($"Messages Unacked: {queue.MessagesUnacknowledged}");
        _logger.LogInformation($"Message Bytes: {queue.MessageBytes}");
        _logger.LogInformation($"Memory: {queue.Memory}");
        _logger.LogInformation($"Consumers: {queue.Consumers}");
        
        // Disk writes (for durable/persistent)
        _logger.LogInformation($"Disk Writes: {queue.DiskWrites}");
        _logger.LogInformation($"Disk Reads: {queue.DiskReads}");
        
        // Alert if backlog growing
        if (queue.Messages > 10000)
        {
            _alertService.Alert("Queue backlog exceeds threshold");
        }
    }
}
```

### Best Practices Summary

**1. Match durability to requirements:**
```csharp
// Financial transactions - maximum durability
var financialArgs = new Dictionary<string, object>
{
    { "x-queue-type", "quorum" }
};

// Analytics - speed over durability
var analyticsArgs = new Dictionary<string, object>
{
    { "x-queue-mode", "lazy" }  // If large backlog expected
};

// Real-time notifications - no persistence needed
var notificationArgs = new Dictionary<string, object>();  // Default
```

**2. Test failure scenarios:**
```csharp
[Fact]
public async Task TestBrokerRestart()
{
    // Publish messages
    await PublishDurableMessages(100);
    
    // Simulate broker restart
    await RestartBroker();
    
    // Verify messages survived
    var count = GetQueueMessageCount("orders");
    Assert.Equal(100, count);
}
```

**3. Monitor disk space:**
```csharp
// Configure disk space alerts

```

**4. Use appropriate queue type:**
- **Classic** - Default, good balance
- **Quorum** - Critical data, HA required
- **Lazy** - Large backlogs, limited memory
- **Stream** - Event streaming, replay needed

**Answers:**

## Key Takeaways

- **Durable queues** survive broker restarts (queue definition only)
- **Persistent messages** written to disk before acknowledgment (message content)
- **Both required** for true durability (durable queue + persistent message)
- **Performance cost:** 5-10x slower with full persistence
- **Lazy queues** for large backlogs and limited memory
- **Quorum queues** for maximum reliability and high availability
- **Choose wisely:** Match durability to business requirements
- **Monitor:** Track queue depth, disk usage, and memory consumption
