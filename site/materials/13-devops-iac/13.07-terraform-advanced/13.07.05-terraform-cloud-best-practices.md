## Best Practices

### 1. State Management

**✅ DO:**
- Use remote state storage
- Enable state locking
- Back up state files (versioning)
- Use one state per environment
- Manipulate state only through Terraform commands

**❌ DON'T:**
- Store state in Git
- Edit state files manually
- Share state files between environments
- Use local state for team projects

**Example:**

```hcl
# ✅ Good: Remote state with locking
terraform {
  backend "s3" {
    bucket       = "my-terraform-state"
    key          = "prod/app/terraform.tfstate"
    region       = "us-east-1"
    encrypt      = true
    use_lockfile = true
  }
}
```

### 3. Naming Conventions

**Resources:**

```hcl
# ✅ Good: Descriptive, noun-based
resource "aws_instance" "web_server" { }
resource "aws_security_group" "application" { }

# ❌ Bad: Includes resource type, unclear
resource "aws_instance" "aws_instance_web" { }
resource "aws_security_group" "sg1" { }
```

**Variables:**

```hcl
# ✅ Good: Clear, descriptive
variable "instance_type" {
  description = "EC2 instance type for application servers"
  type        = string
  default     = "t3.micro"
}

# ❌ Bad: Vague, no description
variable "type" {
  default = "t3.micro"
}
```

**Modules:**

```
✅ Good:
  - networking/vpc
  - compute/ec2-instance
  - data/postgresql

❌ Bad:
  - module1
  - infrastructure
  - stuff
```

### 5. Variable Management

**✅ Best Practices:**

```hcl
# Always include type and description
variable "environment" {
  description = "Environment name (dev, staging, prod)"
  type        = string
  
  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}

# Use complex types for structured data
variable "vpc_config" {
  description = "VPC configuration"
  type = object({
    cidr_block           = string
    enable_dns_hostnames = bool
    enable_dns_support   = bool
  })
  
  default = {
    cidr_block           = "10.0.0.0/16"
    enable_dns_hostnames = true
    enable_dns_support   = true
  }
}

# Sensitive variables
variable "database_password" {
  description = "Database master password"
  type        = string
  sensitive   = true
}
```

**Variable Files:**

```hcl
# terraform.tfvars (default values)
environment   = "dev"
instance_type = "t3.micro"

# prod.tfvars (production overrides)
environment   = "prod"
instance_type = "t3.large"
instance_count = 3
```

### 7. Secrets Management

**✅ DO:**

```hcl
# Use sensitive variables
variable "api_key" {
  type      = string
  sensitive = true
}

# Reference from secret management services
data "aws_secretsmanager_secret_version" "db_password" {
  secret_id = "prod/database/password"
}

resource "aws_db_instance" "main" {
  password = data.aws_secretsmanager_secret_version.db_password.secret_string
}

# Use environment variables
# export TF_VAR_api_key="secret-value"
```

**❌ DON'T:**

```hcl
# ❌ Hardcoded secrets
resource "aws_db_instance" "main" {
  password = "MyPassword123!"  # NEVER DO THIS
}

# ❌ Secrets in tfvars committed to Git
# database_password = "secret123"
```

# Terraform files

# Sensitive files

*.pem

### 8. CI/CD Integration

**GitHub Actions Example:**

```yaml
name: Terraform
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  terraform:
    runs-on: ubuntu-latest
    
    permissions:
      contents: read
      pull-requests: write
    
    steps:
      - uses: actions/checkout@v4
      
      - uses: hashicorp/setup-terraform@v3
        with:
          terraform_version: 1.7.0
      
      - name: Terraform Format Check
        run: terraform fmt -check -recursive
      
      - name: Terraform Init
        run: terraform init
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
      
      - name: Terraform Validate
        run: terraform validate
      
      - name: Terraform Plan
        id: plan
        run: terraform plan -no-color -out=tfplan
        continue-on-error: true
      
      - name: Comment PR
        uses: actions/github-script@v7
        if: github.event_name == 'pull_request'
        with:
          script: |
            const output = `#### Terraform Format and Style 🖌\`${{ steps.fmt.outcome }}\`
            #### Terraform Plan 📖\`${{ steps.plan.outcome }}\`
            
            <details><summary>Show Plan</summary>
            
            \`\`\`
            ${{ steps.plan.outputs.stdout }}
            \`\`\`
            
            </details>`;
            
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: output
            });
      
      - name: Terraform Apply
        if: github.ref == 'refs/heads/main' && github.event_name == 'push'
        run: terraform apply -auto-approve tfplan
```

### 9. Documentation

**Module Documentation:**

```markdown
# VPC Module

Creates a VPC with public and private subnets across multiple availability zones.

## Usage

```hcl
module "vpc" {
  source = "./modules/vpc"
  
  name               = "my-vpc"
  cidr_block         = "10.0.0.0/16"
  availability_zones = ["us-east-1a", "us-east-1b"]
  
  tags = {
    Environment = "prod"
  }
}
```

## Requirements

| Name | Version |
|------|---------|
| terraform | >= 1.7.0 |
| aws | ~> 5.0 |

## Inputs

| Name | Description | Type | Default | Required |
|------|-------------|------|---------|:--------:|
| name | VPC name | `string` | n/a | yes |
| cidr_block | VPC CIDR block | `string` | `"10.0.0.0/16"` | no |

## Outputs

| Name | Description |
|------|-------------|
| vpc_id | ID of the VPC |
| public_subnet_ids | IDs of public subnets |
```

**Inline Documentation:**

```hcl
# Create VPC with DNS support enabled
resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  enable_dns_support   = true
  
  tags = merge(
    var.tags,
    {
      Name = "${var.name}-vpc"
    }
  )
}

# Public subnets for internet-facing resources
resource "aws_subnet" "public" {
  count = length(var.public_subnet_cidrs)
  
  vpc_id                  = aws_vpc.main.id
  cidr_block              = var.public_subnet_cidrs[count.index]
  availability_zone       = var.availability_zones[count.index]
  map_public_ip_on_launch = true
  
  tags = {
    Name = "${var.name}-public-${count.index + 1}"
    Type = "public"
  }
}
```

## Terraform Cloud Workflow

### 1. VCS-Driven Workflow

```
Developer pushes code → GitHub
  ↓
Webhook triggers → Terraform Cloud
  ↓
Terraform Cloud runs plan
  ↓
Plan posted to PR as comment
  ↓
Code review + approval
  ↓
Merge to main
  ↓
Terraform Cloud applies changes (with approval gate)
```

### 2. Approval Workflow

```hcl
# Workspace settings in Terraform Cloud
# - Auto-apply: Disabled
# - Require approval for applies
# - Designated approvers: team-leads
```

### 3. Policy as Code (Sentinel)

```hcl
# policy/require-tags.sentinel
import "tfplan/v2" as tfplan

mandatory_tags = ["Environment", "Owner", "CostCenter"]

main = rule {
  all tfplan.resource_changes as _, rc {
    rc.change.after.tags contains mandatory_tags
  }
}
```

## Performance Optimization

### 1. Reduce Resource Count

```hcl
# ✅ Use for_each instead of count when possible
resource "aws_s3_bucket" "data" {
  for_each = toset(var.bucket_names)
  
  bucket = each.value
}

# Easier to manage than count-based approach
```

### 2. Target Specific Resources

```bash
# Apply only specific resources
terraform apply -target=module.networking.aws_vpc.main

# Useful for large infrastructures
```

### 3. Parallel Execution

```bash
# Increase parallelism (default 10)
terraform apply -parallelism=20
```

## Common Anti-Patterns to Avoid

**❌ Massive State Files:**
```
# Don't put 1000+ resources in one state
# Split by environment, application, layer
```

**❌ Hardcoded Values:**
```hcl
# ❌ Bad
resource "aws_instance" "app" {
  instance_type = "t3.large"
  ami           = "ami-12345678"
}

# ✅ Good
resource "aws_instance" "app" {
  instance_type = var.instance_type
  ami           = data.aws_ami.ubuntu.id
}
```

**❌ No Resource Lifecycles:**
```hcl
# ✅ Good: Prevent accidental deletion
resource "aws_db_instance" "main" {
  # Configuration...
  
  lifecycle {
    prevent_destroy = true
  }
}
```
