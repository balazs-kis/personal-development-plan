## Introduction

Idempotency is a core principle of Ansible—running the same playbook multiple times should produce the same result without unintended side effects. Combined with best practices for security, performance, and maintainability, idempotent automation enables safe, reliable infrastructure management. This lesson covers idempotency concepts, production best practices, and testing strategies.

## Key Concepts Summary

### What Is Idempotency?

**Definition:** An operation is idempotent if applying it multiple times produces the same result as applying it once.

**In Ansible context:**
```bash
# First run: Makes changes
$ ansible-playbook playbook.yml
changed: [host1]

# Second run: No changes (idempotent)
$ ansible-playbook playbook.yml
ok: [host1]

# Third run: Still no changes
$ ansible-playbook playbook.yml
ok: [host1]
```

**Benefits:**
- **Safe to retry:** Can rerun after failures
- **Predictable:** Same result every time
- **Fast:** Skips unnecessary work
- **Auditable:** Clear what changed

## Idempotency in Practice

### Built-in Idempotency

**Most Ansible modules are idempotent by default:**

```yaml
# ✅ Idempotent: Ensures package is present
- name: Install nginx
  apt:
    name: nginx
    state: present

# ✅ Idempotent: Ensures service is started
- name: Ensure nginx is running
  service:
    name: nginx
    state: started
    enabled: yes

# ✅ Idempotent: Ensures file exists with content
- name: Deploy configuration
  copy:
    src: nginx.conf
    dest: /etc/nginx/nginx.conf
    mode: '0644'
```

### Non-Idempotent Patterns

**Command/Shell modules are often not idempotent:**

```yaml
# ❌ Not idempotent: Creates duplicate entries
- name: Add line to file
  shell: echo "export PATH=$PATH:/opt/bin" >> ~/.bashrc

# ✅ Idempotent alternative
- name: Add line to file
  lineinfile:
    path: ~/.bashrc
    line: "export PATH=$PATH:/opt/bin"
    state: present
```

### Making Commands Idempotent

**Use creates/removes:**

```yaml
# ✅ Idempotent: Only runs if file doesn't exist
- name: Download file
  command: wget https://example.com/file.tar.gz
  args:
    creates: /tmp/file.tar.gz

# ✅ Idempotent: Only runs if directory exists
- name: Clean directory
  command: rm -rf /tmp/old_data
  args:
    removes: /tmp/old_data
```

**Use changed_when:**

```yaml
# ✅ Idempotent: Controls when task reports changes
- name: Check if service is configured
  command: /usr/local/bin/check-config.sh
  register: config_check
  changed_when: config_check.rc != 0
  failed_when: config_check.rc > 1
```

**Check before acting:**

```yaml
- name: Check if database exists
  command: psql -lqt
  register: db_list
  changed_when: false

- name: Create database if missing
  command: createdb myapp
  when: "'myapp' not in db_list.stdout"
```

## The Ansible Way: Core Principles

### 1. Complexity Kills Productivity

**Start simple, add complexity only when needed:**

```yaml
# ✅ Good: Simple and clear
- name: Install web server
  apt:
    name: nginx
    state: present

# ❌ Bad: Unnecessarily complex
- name: Install web server
  shell: |
    if ! dpkg -l | grep -q nginx; then
      apt-get update && apt-get install -y nginx
    fi
```

**Do one thing and do it well:**

```yaml
# ✅ Good: Each task has single responsibility
- name: Install nginx
  apt:
    name: nginx
    state: present

- name: Start nginx
  service:
    name: nginx
    state: started

# ❌ Bad: Task does too much
- name: Setup nginx
  shell: |
    apt-get install -y nginx
    systemctl start nginx
    systemctl enable nginx
```

### 2. Optimize for Readability

**Your automation should serve as documentation:**

```yaml
# ✅ Good: Clear names, comments where needed
- name: Install application dependencies
  apt:
    name:
      - python3
      - python3-pip
      - python3-venv
    state: present

- name: Create application user
  user:
    name: appuser
    comment: "Application service account"
    system: yes
    create_home: yes

# ❌ Bad: Cryptic, no context
- apt:
    name: "{{ pkgs }}"
    state: present

- user:
    name: au
    system: yes
```

### 3. Think Declaratively

**Describe desired state, not steps:**

```yaml
# ✅ Good: Declarative (what should exist)
- name: Ensure nginx configuration is correct
  template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    mode: '0644'
  notify: Reload nginx

- name: Ensure nginx is running
  service:
    name: nginx
    state: started
    enabled: yes

# ❌ Bad: Imperative (sequence of commands)
- name: Stop nginx
  service:
    name: nginx
    state: stopped

- name: Update config
  copy:
    src: nginx.conf
    dest: /etc/nginx/nginx.conf

- name: Start nginx
  service:
    name: nginx
    state: started
```

## Security Best Practices

### 1. Use Ansible Vault for Secrets

**Encrypt sensitive data:**

```bash
# Create encrypted file
ansible-vault create group_vars/all/vault.yml

# Edit encrypted file
ansible-vault edit group_vars/all/vault.yml

# Encrypt existing file
ansible-vault encrypt vars/secrets.yml
```

**vault.yml (encrypted):**

```yaml
---
vault_db_password: SecretPassword123
vault_api_key: abc123xyz789
vault_ssl_key_content: |
  -----BEGIN PRIVATE KEY-----
  ...
  -----END PRIVATE KEY-----
```

**Using vaulted variables:**

```yaml
# group_vars/all/vars.yml (not encrypted)
---
db_user: myapp
db_host: localhost

# Reference vaulted variables
db_password: "{{ vault_db_password }}"
api_key: "{{ vault_api_key }}"
```

**Run with vault password:**

```bash
# Prompt for password
ansible-playbook site.yml --ask-vault-pass

# Use password file
ansible-playbook site.yml --vault-password-file ~/.vault_pass

# Environment variable
export ANSIBLE_VAULT_PASSWORD_FILE=~/.vault_pass
ansible-playbook site.yml
```

### 2. Principle of Least Privilege

```yaml
# ✅ Good: Use become only when needed
- name: Install package (requires sudo)
  apt:
    name: nginx
    state: present
  become: yes

- name: Copy user file (doesn't need sudo)
  copy:
    src: .bashrc
    dest: ~/.bashrc

# ❌ Bad: Always using root
- hosts: webservers
  become: yes
  user: root  # Too permissive
```

### 3. Validate Before Acting

```yaml
- name: Validate nginx configuration
  command: nginx -t
  changed_when: false
  check_mode: no

- name: Reload nginx if config is valid
  service:
    name: nginx
    state: reloaded
```

### 4. Don't Log Sensitive Data

```yaml
- name: Set database password
  shell: psql -c "ALTER USER myuser PASSWORD '{{ db_password }}'"
  no_log: true  # Don't log output

- name: Deploy SSL certificate
  copy:
    content: "{{ ssl_cert }}"
    dest: /etc/ssl/certs/app.crt
  no_log: true
```

## Performance Optimization

### 1. Minimize Facts Gathering

```yaml
# Disable facts if not needed
- hosts: webservers
  gather_facts: no
  tasks:
    - name: Simple task
      ping:

# Gather only subset of facts
- hosts: webservers
  gather_facts: yes
  gather_subset:
    - '!all'
    - '!min'
    - network
```

### 2. Use Async for Long-Running Tasks

```yaml
- name: Run long-running task asynchronously
  command: /usr/local/bin/long-running-script.sh
  async: 3600  # Maximum runtime
  poll: 0      # Fire and forget
  register: long_task

- name: Do other work
  apt:
    name: some-package
    state: present

- name: Wait for long-running task
  async_status:
    jid: "{{ long_task.ansible_job_id }}"
  register: job_result
  until: job_result.finished
  retries: 60
  delay: 10
```

### 3. Parallelize with Serial

```yaml
- name: Rolling update
  hosts: webservers
  serial: 2  # Update 2 servers at a time
  
  tasks:
    - name: Take server out of load balancer
      command: remove_from_lb.sh
      delegate_to: localhost
    
    - name: Update application
      apt:
        name: myapp
        state: latest
    
    - name: Add server back to load balancer
      command: add_to_lb.sh
      delegate_to: localhost
```

### 4. Use Package Module Instead of apt/yum

```yaml
# ✅ Good: Package module is cross-platform
- name: Install packages
  package:
    name:
      - git
      - curl
    state: present

# ❌ Less flexible: OS-specific
- name: Install packages
  apt:
    name:
      - git
      - curl
    state: present
  when: ansible_os_family == "Debian"
```

## Testing Strategies

### 1. Check Mode (Dry Run)

```bash
# Test without making changes
ansible-playbook playbook.yml --check

# Show what would change
ansible-playbook playbook.yml --check --diff

# Limit to specific hosts
ansible-playbook playbook.yml --check --limit webserver1
```

**Make tasks work in check mode:**

```yaml
- name: Check if service exists
  command: systemctl status myapp
  register: service_status
  check_mode: no  # Always run, even in check mode
  failed_when: false
  changed_when: false
```

### 2. Syntax Validation

```bash
# Check playbook syntax
ansible-playbook playbook.yml --syntax-check

# Validate all playbooks
find . -name "*.yml" -exec ansible-playbook {} --syntax-check \;
```

### 3. Lint Your Code

```bash
# Install ansible-lint
pip install ansible-lint

# Run linter
ansible-lint playbook.yml

# Lint all playbooks
ansible-lint playbooks/
```

**Fix common issues:**

```yaml
# ✅ Good: Specific state
- name: Ensure nginx is latest
  apt:
    name: nginx
    state: latest  # Explicit state

# ❌ Lint warning: No state specified
- name: Install nginx
  apt:
    name: nginx
```

### 4. Molecule Testing

**Install Molecule:**

```bash
pip install molecule molecule-docker
```

**Create test scenario:**

```bash
cd roles/myapp
molecule init scenario
```

**Test role:**

```bash
# Run full test sequence
molecule test

# Individual steps
molecule create    # Create test environment
molecule converge  # Run playbook
molecule verify    # Run tests
molecule destroy   # Clean up
```

## Code Organization Best Practices

### 1. Directory Structure

```
ansible/
├── ansible.cfg
├── inventories/
│   ├── production/
│   │   ├── hosts
│   │   └── group_vars/
│   └── staging/
│       ├── hosts
│       └── group_vars/
├── roles/
│   ├── common/
│   ├── webserver/
│   └── database/
├── playbooks/
│   ├── site.yml
│   ├── deploy.yml
│   └── rollback.yml
├── group_vars/
│   └── all/
│       ├── vars.yml
│       └── vault.yml
├── requirements.yml
└── README.md
```

### 2. Variable Precedence

**Understand the order (highest to lowest):**

1. Extra vars (`-e` command line)
2. Task vars
3. Block vars
4. Role and include vars
5. Play vars_files
6. Play vars_prompt
7. Play vars
8. Host facts
9. Playbook host_vars
10. Playbook group_vars
11. Inventory host_vars
12. Inventory group_vars
13. Inventory vars
14. Role defaults

### 3. Naming Conventions

```yaml
# ✅ Good: Consistent, descriptive names
# Roles: lowercase with underscores
roles/
  web_server/
  database_setup/
  security_hardening/

# Variables: lowercase with underscores
nginx_port: 80
app_version: "1.0.0"
enable_ssl: true

# Tasks: Descriptive action + object
- name: Install nginx package
- name: Deploy application configuration
- name: Restart web server service
```

## Common Patterns

### 1. Conditional Includes

```yaml
- name: Include OS-specific tasks
  include_tasks: "{{ ansible_os_family }}.yml"

- name: Include environment-specific vars
  include_vars: "{{ environment }}.yml"
```

### 2. Error Handling

```yaml
- name: Attempt to start service
  service:
    name: myapp
    state: started
  register: start_result
  ignore_errors: yes

- name: Fall back to alternative
  service:
    name: myapp-alternative
    state: started
  when: start_result is failed

- name: Fail with custom message
  fail:
    msg: "Unable to start any application service"
  when:
    - start_result is failed
    - alternative_result is failed
```

### 3. Retries and Delays

```yaml
- name: Wait for service to be ready
  uri:
    url: http://localhost:8080/health
    status_code: 200
  register: health_check
  until: health_check.status == 200
  retries: 10
  delay: 5
```

### 4. Delegation

```yaml
- name: Deploy to web servers
  hosts: webservers
  
  tasks:
    - name: Remove from load balancer
      command: /usr/local/bin/remove-from-lb {{ inventory_hostname }}
      delegate_to: localhost
    
    - name: Update application
      apt:
        name: myapp
        state: latest
    
    - name: Add back to load balancer
      command: /usr/local/bin/add-to-lb {{ inventory_hostname }}
      delegate_to: localhost
```

## Production Checklist

**Before deploying to production:**

- [ ] All tasks have descriptive names
- [ ] Playbooks pass `--syntax-check`
- [ ] Playbooks pass ansible-lint
- [ ] Tested with `--check` mode
- [ ] Secrets encrypted with Ansible Vault
- [ ] No hardcoded passwords or keys
- [ ] Role dependencies documented
- [ ] Backup/rollback procedures tested
- [ ] Monitoring and alerting configured
- [ ] Documentation up to date

## Practice Exercise

1. **Review and improve** an existing playbook:
   - Check for idempotency issues
   - Replace shell/command with native modules
   - Add appropriate `changed_when` conditions
   - Test with `--check` and `--diff`

2. **Implement security:**
   - Move secrets to Ansible Vault
   - Add `no_log` to sensitive tasks
   - Use least privilege (become only when needed)

3. **Add testing:**
   - Validate syntax
   - Run ansible-lint
   - Test in check mode
   - Verify idempotency (run twice, check for changes)

4. **Optimize performance:**
   - Minimize fact gathering
   - Use package module for cross-platform support
   - Implement serial updates for rolling deployments

5. **Document everything:**
   - Add README with usage instructions
   - Document all variables
   - Include examples
   - Add troubleshooting section
