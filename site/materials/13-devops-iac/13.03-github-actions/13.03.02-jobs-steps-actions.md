# Lesson 2: Jobs, Steps, and Actions

## Learning Objectives

By the end of this lesson, you will be able to:
- Organize workflows into jobs and steps
- Use pre-built actions from the GitHub Marketplace
- Configure job dependencies and parallelization
- Understand runner environments and their capabilities
- Share data between jobs using artifacts
- Create custom run commands and use shell scripts

---

## Introduction

Jobs and steps are the building blocks that execute your workflow logic. Jobs run in parallel by default but can be configured to run sequentially with dependencies. Each job contains multiple steps that execute commands or use pre-built actions from the marketplace.

## Key Concepts Summary

### Basic Job Structure

```yaml
name: CI Pipeline

on: push

jobs:
  # Job 1: Build
  build:
    name: Build Application              # Display name
    runs-on: ubuntu-latest               # Runner OS
    timeout-minutes: 30                  # Job timeout
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4        # Using an action
      
      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0'          # Action inputs
      
      - name: Build
        run: dotnet build                # Run command
      
      - name: Run tests
        run: dotnet test --no-build

  # Job 2: Lint
  lint:
    name: Code Quality
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run linter
        run: dotnet format --verify-no-changes
```

### Using Actions from Marketplace

```yaml
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      # Action from marketplace with version pinning
      - name: Checkout code
        uses: actions/checkout@v4         # Major version (recommended)
        # uses: actions/checkout@v4.1.2   # Exact version
        # uses: actions/checkout@main     # Branch (not recommended)
      
      # Action with inputs
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      
      # Docker container action
      - name: Run custom container
        uses: docker://alpine:3.18
        with:
          args: /bin/sh -c "echo Hello"
      
      # Local action from same repository
      - name: Run local action
        uses: ./.github/actions/custom-action
```

### Runner Environments

```yaml
jobs:
  # GitHub-hosted runners
  ubuntu-job:
    runs-on: ubuntu-latest              # Ubuntu 22.04
    # runs-on: ubuntu-22.04
    # runs-on: ubuntu-20.04
  
  windows-job:
    runs-on: windows-latest             # Windows Server 2022
    # runs-on: windows-2022
    # runs-on: windows-2019
  
  macos-job:
    runs-on: macos-latest               # macOS 14
    # runs-on: macos-14
    # runs-on: macos-13
  
  # Self-hosted runner
  self-hosted-job:
    runs-on: [self-hosted, linux, x64]

  # Matrix of runners (covered in Lesson 4)
  multi-os:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
```

### Step Configuration

```yaml
jobs:
  example:
    runs-on: ubuntu-latest
    steps:
      # Basic step with action
      - uses: actions/checkout@v4
      
      # Step with name
      - name: Print message
        run: echo "Hello, World!"
      
      # Multi-line command
      - name: Multi-line script
        run: |
          echo "Line 1"
          echo "Line 2"
          echo "Line 3"
      
      # Working directory
      - name: Build in subdirectory
        run: dotnet build
        working-directory: ./src
      
      # Environment variables for step
      - name: Use env vars
        env:
          API_KEY: ${{ secrets.API_KEY }}
          NODE_ENV: production
        run: npm run deploy
      
      # Conditional step
      - name: Only on main branch
        if: github.ref == 'refs/heads/main'
        run: echo "Main branch"
      
      # Continue on error
      - name: Optional linting
        continue-on-error: true
        run: npm run lint
      
      # Timeout for specific step
      - name: Long-running task
        timeout-minutes: 10
        run: npm run integration-tests
```

### Shell Selection

```yaml
jobs:
  shell-examples:
    runs-on: ubuntu-latest
    steps:
      # Default shell (bash on Linux/macOS, pwsh on Windows)
      - name: Default shell
        run: echo "Hello"
      
      # Explicit bash
      - name: Bash script
        shell: bash
        run: |
          #!/bin/bash
          set -e
          echo "Using bash"
      
      # PowerShell
      - name: PowerShell script
        shell: pwsh
        run: Write-Host "Using PowerShell"
      
      # Python
      - name: Python script
        shell: python
        run: |
          import platform
          print(f"Python on {platform.system()}")
      
      # Custom shell
      - name: Custom shell
        shell: bash --noprofile --norc -eo pipefail {0}
        run: echo "Custom bash configuration"
```

### Job Dependencies

```yaml
jobs:
  # Jobs run in parallel by default
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm run build
  
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm test
  
  # This job waits for build and test to complete
  deploy:
    needs: [build, test]                # Job dependencies
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploying..."
  
  # Diamond dependency pattern
  verify:
    needs: deploy                       # Runs after deploy
    runs-on: ubuntu-latest
    steps:
      - run: echo "Verification complete"
```

### Conditional Jobs

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Always runs"
  
  # Only run on main branch
  deploy-staging:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploy to staging"
  
  # Only run on tags
  deploy-production:
    needs: build
    if: startsWith(github.ref, 'refs/tags/v')
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploy to production"
  
  # Only run on PRs
  preview:
    needs: build
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploy preview"
```

### Sharing Data with Artifacts

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Build
        run: dotnet build -c Release -o ./output
      
      # Upload artifact
      - name: Upload build artifacts
        uses: actions/upload-artifact@v4
        with:
          name: build-output
          path: ./output/
          retention-days: 7              # Keep for 7 days
  
  test:
    needs: build
    runs-on: ubuntu-latest
    steps:
      # Download artifact from previous job
      - name: Download build artifacts
        uses: actions/download-artifact@v4
        with:
          name: build-output
          path: ./output/
      
      - name: Run tests
        run: dotnet test ./output/MyApp.dll
  
  publish:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: build-output
          path: ./output/
      
      - name: Publish
        run: echo "Publishing artifacts..."
```

### Job Outputs

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      version: ${{ steps.version.outputs.value }}
      build-time: ${{ steps.time.outputs.value }}
    steps:
      - uses: actions/checkout@v4
      
      - name: Get version
        id: version
        run: echo "value=1.2.3" >> $GITHUB_OUTPUT
      
      - name: Get build time
        id: time
        run: echo "value=$(date -u +'%Y-%m-%dT%H:%M:%SZ')" >> $GITHUB_OUTPUT
  
  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - name: Use outputs from build job
        run: |
          echo "Version: ${{ needs.build.outputs.version }}"
          echo "Build time: ${{ needs.build.outputs.build-time }}"
```

### Concurrency Control

```yaml
# Prevent multiple deployments to same environment
jobs:
  deploy:
    runs-on: ubuntu-latest
    concurrency:
      group: production-deploy           # Concurrency group name
      cancel-in-progress: false         # Wait for previous to finish
    steps:
      - run: echo "Deploying..."

# Cancel old runs when new push occurs
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Building..."
```

## Common Actions from Marketplace

### Essential Actions

```yaml
jobs:
  example:
    runs-on: ubuntu-latest
    steps:
      # Checkout code
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0                 # Full git history
      
      # Setup programming languages
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0'
      
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      
      # Caching dependencies
      - uses: actions/cache@v4
        with:
          path: ~/.npm
          key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-
      
      # Upload/download artifacts
      - uses: actions/upload-artifact@v4
        with:
          name: my-artifact
          path: ./dist/
      
      - uses: actions/download-artifact@v4
        with:
          name: my-artifact
      
      # Docker build and push
      - uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
      
      - uses: docker/build-push-action@v5
        with:
          push: true
          tags: myapp:latest
```

## Best Practices

### Job Organization

```yaml
jobs:
  # Fast checks first (fail fast)
  lint:
    name: Code Quality
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm run lint
  
  # Parallel test jobs
  test-unit:
    runs-on: ubuntu-latest
    steps:
      - run: npm run test:unit
  
  test-integration:
    runs-on: ubuntu-latest
    steps:
      - run: npm run test:integration
  
  # Build after checks pass
  build:
    needs: [lint, test-unit, test-integration]
    runs-on: ubuntu-latest
    steps:
      - run: npm run build
  
  # Deploy only after everything passes
  deploy:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - run: npm run deploy
```

## When to Use What

| Use Case | Solution |
|----------|----------|
| Run commands | `run:` with shell scripts |
| Reusable logic | Use actions from marketplace |
| Need specific tool version | `actions/setup-*` actions |
| Share build outputs | Use `actions/upload-artifact` and `actions/download-artifact` |
| Speed up builds | Use `actions/cache` for dependencies |
| Sequential execution | Use `needs` for job dependencies |
| Parallel execution | Define multiple jobs without `needs` |
| Prevent concurrent runs | Use `concurrency` configuration |
