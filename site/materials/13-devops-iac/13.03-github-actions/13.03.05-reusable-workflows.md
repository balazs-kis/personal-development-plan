# Lesson 5: Reusable Workflows and Best Practices

## Learning Objectives

By the end of this lesson, you will be able to:
- Create reusable workflows that can be called from other workflows
- Understand the difference between reusable workflows and composite actions
- Implement workflow best practices for maintainability and performance
- Use composite actions to encapsulate repeated steps
- Design workflow templates for team-wide consistency
- Apply security and optimization best practices

---

## Introduction

Reusable workflows and composite actions eliminate duplication by allowing you to define workflow logic once and reuse it across multiple workflows and repositories. This promotes consistency, reduces maintenance burden, and enables teams to share best practices through centralized workflow templates.

## Key Concepts Summary

### Creating a Reusable Workflow

```yaml
# .github/workflows/reusable-build.yml
name: Reusable Build Workflow

on:
  workflow_call:
    inputs:
      dotnet-version:
        description: '.NET version to use'
        required: false
        type: string
        default: '8.0'
      configuration:
        description: 'Build configuration'
        required: false
        type: string
        default: 'Release'
    outputs:
      artifact-name:
        description: 'Name of the build artifact'
        value: ${{ jobs.build.outputs.artifact-name }}
    secrets:
      NUGET_API_KEY:
        description: 'NuGet API key for package restore'
        required: false

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      artifact-name: ${{ steps.upload.outputs.artifact-name }}
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: ${{ inputs.dotnet-version }}
      
      - name: Restore dependencies
        env:
          NUGET_API_KEY: ${{ secrets.NUGET_API_KEY }}
        run: dotnet restore
      
      - name: Build
        run: dotnet build -c ${{ inputs.configuration }} --no-restore
      
      - name: Test
        run: dotnet test -c ${{ inputs.configuration }} --no-build
      
      - name: Upload artifact
        id: upload
        uses: actions/upload-artifact@v4
        with:
          name: build-${{ inputs.configuration }}
          path: ./bin/${{ inputs.configuration }}/
```

### Calling a Reusable Workflow

```yaml
# .github/workflows/ci.yml
name: CI Pipeline

on: [push, pull_request]

jobs:
  # Call the reusable workflow
  build-debug:
    uses: ./.github/workflows/reusable-build.yml
    with:
      dotnet-version: '8.0'
      configuration: 'Debug'
    secrets:
      NUGET_API_KEY: ${{ secrets.NUGET_API_KEY }}
  
  build-release:
    uses: ./.github/workflows/reusable-build.yml
    with:
      dotnet-version: '8.0'
      configuration: 'Release'
    secrets:
      NUGET_API_KEY: ${{ secrets.NUGET_API_KEY }}
  
  # Use outputs from reusable workflow
  deploy:
    needs: build-release
    runs-on: ubuntu-latest
    steps:
      - name: Download artifact
        uses: actions/download-artifact@v4
        with:
          name: ${{ needs.build-release.outputs.artifact-name }}
      
      - name: Deploy
        run: echo "Deploying..."
```

### Calling External Reusable Workflows

```yaml
jobs:
  # Call workflow from another repository
  shared-build:
    uses: my-org/shared-workflows/.github/workflows/dotnet-build.yml@v1
    with:
      dotnet-version: '8.0'
    secrets: inherit  # Pass all secrets to called workflow
  
  # Call workflow with specific ref
  versioned-workflow:
    uses: my-org/shared-workflows/.github/workflows/deploy.yml@main
    with:
      environment: production
    secrets:
      DEPLOY_KEY: ${{ secrets.PROD_DEPLOY_KEY }}
```

### Composite Actions

```yaml
# .github/actions/setup-dotnet-with-cache/action.yml
name: 'Setup .NET with Caching'
description: 'Setup .NET SDK with NuGet package caching'

inputs:
  dotnet-version:
    description: '.NET SDK version'
    required: true
    default: '8.0'
  working-directory:
    description: 'Working directory'
    required: false
    default: '.'

outputs:
  cache-hit:
    description: 'Whether cache was hit'
    value: ${{ steps.cache.outputs.cache-hit }}

runs:
  using: 'composite'
  steps:
    - name: Setup .NET
      uses: actions/setup-dotnet@v4
      with:
        dotnet-version: ${{ inputs.dotnet-version }}
    
    - name: Cache NuGet packages
      id: cache
      uses: actions/cache@v4
      with:
        path: ~/.nuget/packages
        key: ${{ runner.os }}-nuget-${{ hashFiles('**/packages.lock.json') }}
        restore-keys: |
          ${{ runner.os }}-nuget-
    
    - name: Restore dependencies
      if: steps.cache.outputs.cache-hit != 'true'
      working-directory: ${{ inputs.working-directory }}
      shell: bash
      run: dotnet restore
```

### Using Composite Actions

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      # Use local composite action
      - name: Setup .NET with caching
        uses: ./.github/actions/setup-dotnet-with-cache
        with:
          dotnet-version: '8.0'
      
      - name: Build
        run: dotnet build
```

## Reusable Workflow vs Composite Action

### When to Use Reusable Workflows

```yaml
# Use for complete CI/CD pipelines with multiple jobs
# .github/workflows/reusable-ci-cd.yml
on:
  workflow_call:
    inputs:
      environment:
        required: true
        type: string

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Building..."
  
  test:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - run: echo "Testing..."
  
  deploy:
    needs: test
    runs-on: ubuntu-latest
    environment: ${{ inputs.environment }}
    steps:
      - run: echo "Deploying to ${{ inputs.environment }}"
```

### When to Use Composite Actions

```yaml
# Use for repeated steps within jobs
# .github/actions/setup-and-test/action.yml
name: 'Setup and Test'
description: 'Setup environment and run tests'

runs:
  using: 'composite'
  steps:
    - uses: actions/checkout@v4
    
    - uses: actions/setup-node@v4
      with:
        node-version: '20'
    
    - shell: bash
      run: npm ci
    
    - shell: bash
      run: npm test
```

### Key Differences

| Feature | Reusable Workflow | Composite Action |
|---------|-------------------|------------------|
| Can contain multiple jobs | ✅ Yes | ❌ No |
| Can specify runner | ✅ Yes | ❌ No (uses caller's runner) |
| Can use secrets | ✅ Yes | ✅ Yes (passed from caller) |
| Can use if conditionals | ✅ Yes | ✅ Yes |
| Separate logs per step | ✅ Yes | ❌ No (grouped under action) |
| Can call other workflows | ✅ Yes | ❌ No |
| Can use services | ✅ Yes | ❌ No |

## Best Practices

### Workflow Organization

```yaml
# Project structure for reusable workflows
.github/
  workflows/
    # Callable workflows
    ci.yml                          # Main CI workflow
    cd.yml                          # Main CD workflow
    
    # Reusable workflows
    _reusable-build.yml            # Prefix with _ for reusable
    _reusable-test.yml
    _reusable-deploy.yml
  
  actions/
    # Composite actions
    setup-environment/
      action.yml
    run-tests/
      action.yml
    deploy-app/
      action.yml
```

### Parameterization

```yaml
# Make workflows flexible with inputs
on:
  workflow_call:
    inputs:
      # Use sensible defaults
      node-version:
        type: string
        default: '20'
      
      # Make optional what can be optional
      run-lint:
        type: boolean
        default: true
      
      # Use choice for limited options
      environment:
        type: choice
        options:
          - development
          - staging
          - production
        default: development
      
      # Document inputs clearly
      custom-script:
        description: 'Custom script to run after build'
        type: string
        required: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ inputs.node-version }}
      
      - run: npm run lint
        if: ${{ inputs.run-lint }}
      
      - run: ${{ inputs.custom-script }}
        if: ${{ inputs.custom-script != '' }}
```

### Documentation

```yaml
# .github/workflows/reusable-deploy.yml
name: Reusable Deployment Workflow

# Document the workflow purpose and usage
# 
# This workflow deploys the application to the specified environment.
# 
# Usage:
#   jobs:
#     deploy:
#       uses: ./.github/workflows/reusable-deploy.yml
#       with:
#         environment: production
#         version: v1.2.3
#       secrets:
#         DEPLOY_TOKEN: ${{ secrets.PROD_DEPLOY_TOKEN }}

on:
  workflow_call:
    inputs:
      environment:
        description: 'Target environment (dev, staging, production)'
        required: true
        type: string
      
      version:
        description: 'Version to deploy (e.g., v1.2.3 or commit SHA)'
        required: true
        type: string
      
      dry-run:
        description: 'Run in dry-run mode without actual deployment'
        required: false
        type: boolean
        default: false
    
    secrets:
      DEPLOY_TOKEN:
        description: 'Deployment token for target environment'
        required: true
```

### Security Best Practices

```yaml
# Restrict permissions in reusable workflows
on:
  workflow_call:

# Set minimal permissions
permissions:
  contents: read
  deployments: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    # Further restrict at job level if needed
    permissions:
      contents: read
    
    steps:
      # Use actions from trusted sources
      - uses: actions/checkout@v4  # Official GitHub action
      
      # Pin actions to specific SHA for security
      - uses: docker/build-push-action@4a13e500e55cf31b7a5d59a38ab2040ab0f42f56  # v5.1.0
      
      # Validate inputs
      - name: Validate environment
        run: |
          if [[ ! "${{ inputs.environment }}" =~ ^(dev|staging|production)$ ]]; then
            echo "Invalid environment: ${{ inputs.environment }}"
            exit 1
          fi
```

### Error Handling

```yaml
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Deploy with retry logic
        uses: nick-fields/retry@v2
        with:
          timeout_minutes: 10
          max_attempts: 3
          retry_on: error
          command: ./deploy.sh
      
      - name: Rollback on failure
        if: failure()
        run: ./rollback.sh
      
      - name: Notify team
        if: always()
        uses: 8398a7/action-slack@v3
        with:
          status: ${{ job.status }}
          webhook_url: ${{ secrets.SLACK_WEBHOOK }}
```

## Real-World Examples

### Complete .NET CI/CD Pipeline

```yaml
# .github/workflows/dotnet-cicd.yml
name: .NET CI/CD

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  DOTNET_VERSION: '8.0'

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # Full history for versioning
      
      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: ${{ env.DOTNET_VERSION }}
      
      - name: Restore dependencies
        run: dotnet restore
      
      - name: Build
        run: dotnet build --no-restore -c Release
      
      - name: Run unit tests
        run: dotnet test --no-build -c Release --logger "trx;LogFileName=test-results.trx"
      
      - name: Publish test results
        if: always()
        uses: dorny/test-reporter@v1
        with:
          name: .NET Tests
          path: '**/test-results.trx'
          reporter: dotnet-trx
      
      - name: Publish
        run: dotnet publish -c Release -o ./publish
      
      - name: Upload artifact
        uses: actions/upload-artifact@v4
        with:
          name: dotnet-app
          path: ./publish/
  
  deploy-staging:
    needs: build-and-test
    if: github.ref == 'refs/heads/develop'
    uses: ./.github/workflows/_reusable-deploy.yml
    with:
      environment: staging
      artifact-name: dotnet-app
    secrets:
      DEPLOY_TOKEN: ${{ secrets.STAGING_DEPLOY_TOKEN }}
  
  deploy-production:
    needs: build-and-test
    if: github.ref == 'refs/heads/main'
    uses: ./.github/workflows/_reusable-deploy.yml
    with:
      environment: production
      artifact-name: dotnet-app
    secrets:
      DEPLOY_TOKEN: ${{ secrets.PROD_DEPLOY_TOKEN }}
```

### Shared Workflow Repository Pattern

```yaml
# Organization: my-org
# Repository: shared-workflows
# File: .github/workflows/dotnet-build.yml

name: Reusable .NET Build

on:
  workflow_call:
    inputs:
      dotnet-version:
        type: string
        default: '8.0'
      solution-path:
        type: string
        default: '.'
      configuration:
        type: string
        default: 'Release'
    outputs:
      version:
        value: ${{ jobs.build.outputs.version }}

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      version: ${{ steps.version.outputs.version }}
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: ${{ inputs.dotnet-version }}
      
      - name: Get version
        id: version
        run: |
          VERSION=$(grep -oP '<Version>\K[^<]+' Directory.Build.props)
          echo "version=$VERSION" >> $GITHUB_OUTPUT
      
      - name: Build
        working-directory: ${{ inputs.solution-path }}
        run: dotnet build -c ${{ inputs.configuration }}

# Usage in other repositories:
# jobs:
#   build:
#     uses: my-org/shared-workflows/.github/workflows/dotnet-build.yml@v1
#     with:
#       dotnet-version: '8.0'
```

### Monorepo with Selective Workflows

```yaml
name: Monorepo CI

on:
  push:
    paths:
      - 'services/**'
      - '.github/workflows/**'

jobs:
  # Detect changed services
  detect-changes:
    runs-on: ubuntu-latest
    outputs:
      services: ${{ steps.filter.outputs.changes }}
    steps:
      - uses: actions/checkout@v4
      
      - uses: dorny/paths-filter@v2
        id: filter
        with:
          filters: |
            service-a:
              - 'services/service-a/**'
            service-b:
              - 'services/service-b/**'
            service-c:
              - 'services/service-c/**'
  
  # Build only changed services
  build:
    needs: detect-changes
    if: ${{ needs.detect-changes.outputs.services != '[]' }}
    strategy:
      matrix:
        service: ${{ fromJSON(needs.detect-changes.outputs.services) }}
    uses: ./.github/workflows/_reusable-build-service.yml
    with:
      service-name: ${{ matrix.service }}
```

## Performance Optimization

### Caching in Reusable Workflows

```yaml
on:
  workflow_call:
    inputs:
      cache-version:
        type: string
        default: 'v1'

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      # Cache with versioning for cache busting
      - name: Cache dependencies
        uses: actions/cache@v4
        with:
          path: |
            ~/.nuget/packages
            **/obj
          key: ${{ runner.os }}-nuget-${{ inputs.cache-version }}-${{ hashFiles('**/*.csproj') }}
          restore-keys: |
            ${{ runner.os }}-nuget-${{ inputs.cache-version }}-
            ${{ runner.os }}-nuget-
```

### Parallel Job Execution

```yaml
on:
  workflow_call:

jobs:
  # These jobs run in parallel
  lint:
    runs-on: ubuntu-latest
    steps:
      - run: npm run lint
  
  unit-tests:
    runs-on: ubuntu-latest
    steps:
      - run: npm run test:unit
  
  integration-tests:
    runs-on: ubuntu-latest
    steps:
      - run: npm run test:integration
  
  # This job waits for all parallel jobs
  report:
    needs: [lint, unit-tests, integration-tests]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - run: echo "All checks completed"
```

## Workflow Best Practices Checklist

- ✅ Use reusable workflows for complete CI/CD pipelines
- ✅ Use composite actions for repeated step sequences
- ✅ Organize reusable workflows in a dedicated repository for organization-wide sharing
- ✅ Version reusable workflows using tags or branches
- ✅ Document inputs, outputs, and secrets clearly
- ✅ Provide sensible defaults for inputs
- ✅ Validate inputs at the start of workflows
- ✅ Use minimal required permissions
- ✅ Pin third-party actions to specific SHAs
- ✅ Implement proper error handling and rollback
- ✅ Cache dependencies appropriately
- ✅ Run fast checks first (fail fast)
- ✅ Use matrix builds for multi-platform testing
- ✅ Set up proper notification on failures
- ✅ Test reusable workflows before deploying to production
