---

## Introduction

Artifacts and caching are essential for efficient CI/CD pipelines. Artifacts are build outputs passed between jobs in the same pipeline, while caching stores dependencies to speed up subsequent pipeline runs. Understanding when to use each and how to configure them properly can dramatically improve pipeline performance.

## Key Concepts Summary

### Artifacts vs Caching

```yaml
# Key Differences:

# ARTIFACTS
# - Build outputs (binaries, test results, reports)
# - Passed between jobs in the SAME pipeline
# - Stored in GitLab (downloadable from UI)
# - Have expiration dates
# - Always fresh for each pipeline

build:
  stage: build
  script:
    - dotnet build -o ./output
  artifacts:
    paths:
      - output/
    expire_in: 1 week

# CACHE
# - Dependencies downloaded from internet (npm packages, NuGet, etc.)
# - Shared across pipelines and branches
# - Stored on runner or S3
# - No expiration (cleared by runner when full)
# - May be stale

build:
  stage: build
  cache:
    key: $CI_COMMIT_REF_SLUG
    paths:
      - .npm/
  script:
    - npm ci --cache .npm
```

### Basic Artifacts Configuration

```yaml
build:
  stage: build
  script:
    - dotnet build -c Release -o ./bin
    - dotnet test --logger "trx"
  artifacts:
    paths:
      - bin/           # Directory
      - "*.trx"        # Glob pattern
    expire_in: 30 days # Default if not specified
```

### Artifact Reports

```yaml
test:
  stage: test
  script:
    - dotnet test --logger "trx"
  artifacts:
    when: always  # Upload even on failure
    reports:
      junit:
        - "**/*TestResults.trx"
    paths:
      - test-results/

coverage:
  stage: test
  script:
    - dotnet test /p:CollectCoverage=true
  coverage: '/Total\s+\|\s+(\d+\.?\d*)%/'
  artifacts:
    reports:
      coverage_report:
        coverage_format: cobertura
        path: coverage/cobertura-coverage.xml
```

### Artifact Dependencies

```yaml
build:
  stage: build
  script:
    - make build
  artifacts:
    paths:
      - dist/

# Automatically downloads artifacts from build job
test:
  stage: test
  dependencies:
    - build
  script:
    - make test

# Downloads from ALL previous stage jobs (default)
deploy:
  stage: deploy
  script:
    - make deploy

# Downloads no artifacts
lint:
  stage: test
  dependencies: []
  script:
    - make lint
```

### Advanced Artifact Control

```yaml
build:
  stage: build
  script:
    - make build
  artifacts:
    # Upload artifacts only when job succeeds
    when: on_success  # on_success | on_failure | always
    
    # Artifact naming
    name: "build-$CI_COMMIT_REF_SLUG-$CI_COMMIT_SHORT_SHA"
    
    # Untracked files
    untracked: false
    
    # Exclude paths
    exclude:
      - "**/*.log"
      - "tmp/**/*"
    
    # Expose URLs for external access
    expose_as: "Build Artifacts"
    
    paths:
      - dist/
```

## Caching Strategies

### Per-Branch Caching

```yaml
# Default: Cache per branch
default:
  cache:
    key: $CI_COMMIT_REF_SLUG
    paths:
      - .npm/
      - node_modules/

build:
  script:
    - npm ci
```

### File-Based Cache Keys

```yaml
# Regenerate cache when lock file changes
default:
  cache:
    key:
      files:
        - package-lock.json
        - yarn.lock
    paths:
      - node_modules/

build:
  script:
    - npm ci
```

### Multiple Caches

```yaml
build:
  script:
    - npm ci
    - dotnet restore
  cache:
    # Multiple caches with different keys
    - key:
        files:
          - package-lock.json
      paths:
        - node_modules/
    
    - key:
        files:
          - packages.lock.json
      paths:
        - ~/.nuget/packages/
```

### Cache Policies

```yaml
# Job that populates cache
build:
  stage: build
  cache:
    key: build-cache
    paths:
      - node_modules/
    policy: pull-push  # Default: download and upload
  script:
    - npm ci
    - npm run build

# Jobs that only read cache
test:unit:
  stage: test
  cache:
    key: build-cache
    paths:
      - node_modules/
    policy: pull  # Only download, don't upload
  script:
    - npm test

test:integration:
  stage: test
  cache:
    key: build-cache
    paths:
      - node_modules/
    policy: pull
  script:
    - npm run test:integration
```

### Fallback Cache Keys

```yaml
build:
  cache:
    key: "$CI_COMMIT_REF_SLUG"
    paths:
      - .npm/
    # Fallback to main branch cache if current branch has none
    fallback_keys:
      - main
      - develop
  script:
    - npm ci --cache .npm
```

## Language-Specific Examples

### Node.js / npm

```yaml
# Configure npm to use project directory
default:
  cache:
    key:
      files:
        - package-lock.json
    paths:
      - .npm/
  before_script:
    - npm ci --cache .npm --prefer-offline

build:
  script:
    - npm run build
```

### .NET / NuGet

```yaml
variables:
  NUGET_PACKAGES_DIRECTORY: '.nuget'

default:
  cache:
    key:
      files:
        - "**/*.csproj"
    paths:
      - .nuget/
  before_script:
    - dotnet restore --packages $NUGET_PACKAGES_DIRECTORY

build:
  script:
    - dotnet build --no-restore
```

### Python / pip

```yaml
variables:
  PIP_CACHE_DIR: "$CI_PROJECT_DIR/.cache/pip"

default:
  cache:
    key:
      files:
        - requirements.txt
    paths:
      - .cache/pip/
      - venv/
  before_script:
    - python -m venv venv
    - source venv/bin/activate
    - pip install -r requirements.txt

test:
  script:
    - pytest
```

### Go

```yaml
variables:
  GOPATH: $CI_PROJECT_DIR/.go

default:
  cache:
    key:
      files:
        - go.sum
    paths:
      - .go/pkg/mod/

build:
  script:
    - go build
```

### Docker Layer Caching

```yaml
build:
  image: docker:latest
  services:
    - docker:dind
  variables:
    DOCKER_DRIVER: overlay2
  cache:
    key: docker-cache
    paths:
      - docker-cache/
  before_script:
    - docker load -i docker-cache/image.tar || true
  script:
    - docker build -t myapp .
  after_script:
    - mkdir -p docker-cache
    - docker save myapp -o docker-cache/image.tar
```

## Complete Example: Optimized .NET Pipeline

```yaml
image: mcr.microsoft.com/dotnet/sdk:8.0

variables:
  NUGET_PACKAGES_DIRECTORY: '.nuget'
  SOLUTION: 'MySolution.sln'

# Global cache configuration
default:
  cache:
    key:
      files:
        - "**/*.csproj"
    paths:
      - .nuget/
      - "**/obj/"
    policy: pull

stages:
  - restore
  - build
  - test
  - package

# This job populates the cache
restore:
  stage: restore
  cache:
    key:
      files:
        - "**/*.csproj"
    paths:
      - .nuget/
      - "**/obj/"
    policy: pull-push  # Download and upload
  script:
    - dotnet restore $SOLUTION --packages $NUGET_PACKAGES_DIRECTORY

build:
  stage: build
  needs: [restore]
  script:
    - dotnet build $SOLUTION --no-restore -c Release
  artifacts:
    paths:
      - "**/bin/Release/"
    expire_in: 1 day

test:unit:
  stage: test
  needs:
    - restore
    - build
  dependencies:
    - build  # Download build artifacts
  script:
    - dotnet test $SOLUTION --no-build -c Release --logger "trx"
  artifacts:
    when: always
    reports:
      junit:
        - "**/*TestResults.trx"
    expire_in: 7 days

test:integration:
  stage: test
  needs:
    - restore
    - build
  dependencies:
    - build
  services:
    - postgres:15
  variables:
    POSTGRES_DB: testdb
    POSTGRES_USER: test
    POSTGRES_PASSWORD: test
  script:
    - dotnet test $SOLUTION --no-build -c Release --filter "Category=Integration"

package:
  stage: package
  needs:
    - test:unit
    - test:integration
  dependencies:
    - build
  script:
    - dotnet publish $SOLUTION -c Release -o ./publish --no-build
  artifacts:
    name: "app-$CI_COMMIT_SHORT_SHA"
    paths:
      - publish/
    expire_in: 1 week
```

## Best Practices

### Artifacts Best Practices

```yaml
# ✅ GOOD: Specific paths
artifacts:
  paths:
    - dist/
    - bin/Release/

# ❌ BAD: Too broad
artifacts:
  paths:
    - "**/*"  # Everything! Slow and wasteful

# ✅ GOOD: Appropriate expiration
artifacts:
  paths:
    - reports/
  expire_in: 1 week  # or: 30 mins, 3 hours, 2 days, 1 month

# ❌ BAD: Never expires
artifacts:
  paths:
    - reports/
  expire_in: never  # Wastes storage

# ✅ GOOD: Use when: always for test results
test:
  script:
    - npm test
  artifacts:
    when: always  # Upload even on failure
    reports:
      junit: test-results.xml
```

### Caching Best Practices

```yaml
# ✅ GOOD: Cache dependencies, not build outputs
cache:
  paths:
    - node_modules/
    - .npm/

# ❌ BAD: Caching build outputs (use artifacts instead)
cache:
  paths:
    - dist/
    - bin/

# ✅ GOOD: Use file-based keys for lock files
cache:
  key:
    files:
      - package-lock.json
  paths:
    - node_modules/

# ✅ GOOD: Per-branch caching
cache:
  key: $CI_COMMIT_REF_SLUG
  paths:
    - .npm/

# ✅ GOOD: Read-only cache for most jobs
test:
  cache:
    key: deps-cache
    paths:
      - node_modules/
    policy: pull  # Don't waste time uploading
```

### Combining Artifacts and Cache

```yaml
# Cache for dependencies (persists across pipelines)
cache:
  key:
    files:
      - package-lock.json
  paths:
    - node_modules/

# Artifacts for build outputs (current pipeline only)
build:
  script:
    - npm ci
    - npm run build
  artifacts:
    paths:
      - dist/
    expire_in: 1 hour
```

## Troubleshooting

### Cache Not Working

```yaml
# Check cache configuration
test:
  # Ensure cache key is consistent
  cache:
    key: my-cache-key  # Same across jobs?
    paths:
      - node_modules/  # Path exists?
  script:
    # Verify files are created
    - ls -la node_modules/ || echo "No node_modules"
    - npm ci
```

### Artifacts Not Passing

```yaml
build:
  script:
    - make build
    # Verify artifacts exist before job ends
    - ls -la dist/
  artifacts:
    paths:
      - dist/  # Does this path exist?

test:
  # Check dependencies
  dependencies:
    - build
  script:
    - ls -la dist/  # Are artifacts downloaded?
```

## Performance Optimization Checklist

- ✅ Use cache for dependencies (node_modules, NuGet packages)
- ✅ Use artifacts for build outputs
- ✅ Set cache policy to `pull` for jobs that don't modify cache
- ✅ Use file-based cache keys (package-lock.json, *.csproj)
- ✅ Set appropriate artifact expiration times
- ✅ Exclude unnecessary files from artifacts
- ✅ Use `dependencies: []` when artifacts aren't needed
- ✅ Consider distributed caching (S3) for multiple runners
- ✅ Use specific artifact paths, not broad globs
- ✅ Tag runners for consistent cache access

## When to Use What

| Scenario | Solution |
|----------|----------|
| Pass compiled binaries between jobs | Artifacts |
| Store npm/NuGet packages | Cache |
| Test results and reports | Artifacts with reports |
| Build outputs for deployment | Artifacts |
| Downloaded dependencies | Cache |
| Temporary files not needed later | Neither |
| Docker images | Registry, not cache/artifacts |
| Large datasets for testing | Cache with long expiration |
