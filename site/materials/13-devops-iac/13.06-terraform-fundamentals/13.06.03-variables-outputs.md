# Lesson 3: Variables and Outputs

## Learning Objectives

By the end of this lesson, you will be able to:
- Define and use input variables effectively
- Implement variable validation and sensitive data handling
- Create output values to expose resource information
- Pass data between modules using outputs
- Use variable files and environment-specific configurations
- Apply best practices for variable organization

---

## Introduction

Variables and outputs are fundamental to creating reusable, flexible Terraform configurations. Input variables allow you to parameterize your configurations without changing the code, while output values expose information about your infrastructure for use in other configurations or for display to users.

## Key Concepts Summary

### Input Variables

**Input variables** serve as parameters for Terraform modules, allowing customization without altering the source code.

```hcl
# Declare a variable
variable "instance_type" {
  description = "EC2 instance type"
  type        = string
  default     = "t2.micro"
}

# Use the variable
resource "aws_instance" "example" {
  instance_type = var.instance_type
}
```

---

## Variable Declaration

### Basic Variable Syntax

```hcl
variable "NAME" {
  description = "Description of the variable"
  type        = TYPE
  default     = DEFAULT_VALUE
  sensitive   = BOOLEAN
  nullable    = BOOLEAN
  validation {
    condition     = CONDITION
    error_message = ERROR_MESSAGE
  }
}
```

### Variable Types

```hcl
# String
variable "region" {
  type    = string
  default = "us-west-2"
}

# Number
variable "instance_count" {
  type    = number
  default = 3
}

# Bool
variable "enable_monitoring" {
  type    = bool
  default = true
}

# List
variable "availability_zones" {
  type    = list(string)
  default = ["us-west-2a", "us-west-2b", "us-west-2c"]
}

# Set
variable "allowed_ports" {
  type    = set(number)
  default = [80, 443, 8080]
}

# Map
variable "tags" {
  type = map(string)
  default = {
    Environment = "dev"
    Team        = "platform"
  }
}

# Object (structured)
variable "vpc_config" {
  type = object({
    cidr_block           = string
    enable_dns_hostnames = bool
    enable_dns_support   = bool
  })
  
  default = {
    cidr_block           = "10.0.0.0/16"
    enable_dns_hostnames = true
    enable_dns_support   = true
  }
}

# Tuple
variable "network_config" {
  type    = tuple([string, number, bool])
  default = ["10.0.0.0/16", 2, true]
}

# Any (use sparingly)
variable "dynamic_value" {
  type    = any
  default = null
}
```

## Variable Validation

```hcl
variable "environment" {
  description = "Environment name"
  type        = string
  
  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}

variable "vpc_cidr" {
  description = "CIDR block for VPC"
  type        = string
  
  validation {
    condition     = can(cidrhost(var.vpc_cidr, 0))
    error_message = "Must be a valid IPv4 CIDR block."
  }
}

variable "instance_count" {
  description = "Number of instances"
  type        = number
  
  validation {
    condition     = var.instance_count > 0 && var.instance_count <= 10
    error_message = "Instance count must be between 1 and 10."
  }
}

variable "instance_type" {
  description = "EC2 instance type"
  type        = string
  
  validation {
    condition     = can(regex("^t[23]\\.(micro|small|medium)$", var.instance_type))
    error_message = "Instance type must be t2 or t3 and micro, small, or medium."
  }
}
```

## Sensitive Variables

```hcl
variable "database_password" {
  description = "Database password"
  type        = string
  sensitive   = true  # Masks value in output
}

# Terraform will not display the value in plan/apply output
resource "aws_db_instance" "example" {
  password = var.database_password
  # ... other config
}
```

When running `terraform plan`:
```
# aws_db_instance.example will be created
+ resource "aws_db_instance" "example" {
    + password = (sensitive value)
  }
```

## Setting Variable Values

### Method 1: Default Values

```hcl
variable "region" {
  type    = string
  default = "us-west-2"  # Used if not overridden
}
```

### Method 2: Command Line

```bash
# Using -var flag
terraform apply -var="region=us-east-1" -var="instance_count=5"

# Multiple variables
terraform apply \
  -var="region=us-east-1" \
  -var="environment=prod"
```

### Method 3: Variable Files

```hcl
# terraform.tfvars (automatically loaded)
region           = "us-west-2"
instance_count   = 3
enable_monitoring = true

tags = {
  Environment = "production"
  Team        = "platform"
}
```

```bash
# Using specific .tfvars file
terraform apply -var-file="production.tfvars"
```

**Environment-specific files:**
```
config/
├── dev.tfvars
├── staging.tfvars
└── prod.tfvars
```

```bash
terraform apply -var-file="config/prod.tfvars"
```

### Method 4: Environment Variables

```bash
# Format: TF_VAR_<variable_name>
export TF_VAR_region="us-west-2"
export TF_VAR_instance_count="3"

terraform apply  # Uses environment variables
```

### Variable Precedence (Lowest to Highest)

1. Default value in variable declaration
2. Environment variables (`TF_VAR_*`)
3. `terraform.tfvars` file
4. `*.auto.tfvars` files (alphabetical order)
5. `-var-file` flag
6. `-var` flag

## Complex Variable Examples

### List of Objects

```hcl
variable "subnets" {
  description = "List of subnet configurations"
  type = list(object({
    name              = string
    cidr_block        = string
    availability_zone = string
    public            = bool
  }))
  
  default = [
    {
      name              = "public-1"
      cidr_block        = "10.0.1.0/24"
      availability_zone = "us-west-2a"
      public            = true
    },
    {
      name              = "public-2"
      cidr_block        = "10.0.2.0/24"
      availability_zone = "us-west-2b"
      public            = true
    },
    {
      name              = "private-1"
      cidr_block        = "10.0.11.0/24"
      availability_zone = "us-west-2a"
      public            = false
    }
  ]
}

# Use in configuration
resource "aws_subnet" "subnets" {
  for_each = { for subnet in var.subnets : subnet.name => subnet }
  
  vpc_id                  = aws_vpc.main.id
  cidr_block              = each.value.cidr_block
  availability_zone       = each.value.availability_zone
  map_public_ip_on_launch = each.value.public
  
  tags = {
    Name = each.value.name
  }
}
```

## Output Values

**Output values** expose information about your infrastructure.

### Basic Output Syntax

```hcl
output "NAME" {
  description = "Description of output"
  value       = VALUE
  sensitive   = BOOLEAN
}
```

### Output Examples

```hcl
# Simple value
output "vpc_id" {
  description = "ID of the VPC"
  value       = aws_vpc.main.id
}

# Computed value
output "instance_public_ips" {
  description = "Public IP addresses of instances"
  value       = aws_instance.web[*].public_ip
}

# Object
output "vpc_info" {
  description = "VPC information"
  value = {
    id         = aws_vpc.main.id
    cidr_block = aws_vpc.main.cidr_block
    arn        = aws_vpc.main.arn
  }
}

# Sensitive output
output "database_password" {
  description = "Database password"
  value       = aws_db_instance.main.password
  sensitive   = true
}

# Conditional output
output "load_balancer_dns" {
  description = "DNS name of load balancer (if created)"
  value       = var.create_load_balancer ? aws_lb.main[0].dns_name : null
}
```

## Using Outputs

### Display After Apply

```bash
terraform apply

# Outputs:
#
# Outputs:
#
# instance_public_ips = [
#   "54.123.45.67",
#   "54.123.45.68",
# ]
# vpc_id = "vpc-0123456789abcdef"
```

### Query Outputs

```bash
# Show all outputs
terraform output

# Show specific output
terraform output vpc_id

# Output as JSON
terraform output -json

# Output raw value (no quotes)
terraform output -raw vpc_id

# Use in scripts
VPC_ID=$(terraform output -raw vpc_id)
echo "VPC ID is: $VPC_ID"
```

### Module Outputs

```hcl
# In module: modules/networking/outputs.tf
output "vpc_id" {
  value = aws_vpc.main.id
}

output "public_subnet_ids" {
  value = aws_subnet.public[*].id
}

# In root module: main.tf
module "networking" {
  source = "./modules/networking"
  # ...
}

# Reference module outputs
resource "aws_instance" "web" {
  subnet_id = module.networking.public_subnet_ids[0]
  # ...
}

# Expose module outputs
output "vpc_id" {
  description = "VPC ID from networking module"
  value       = module.networking.vpc_id
}
```

## Local Values

**Local values** assign names to expressions for reuse within a module.

```hcl
locals {
  # Common tags
  common_tags = {
    Environment = var.environment
    Project     = var.project_name
    ManagedBy   = "Terraform"
  }
  
  # Computed name prefix
  name_prefix = "${var.project_name}-${var.environment}"
  
  # Conditional value
  instance_count = var.environment == "prod" ? 5 : 2
  
  # Complex computation
  subnet_cidrs = [
    for i in range(var.subnet_count) :
    cidrsubnet(var.vpc_cidr, 8, i)
  ]
}

# Use locals
resource "aws_vpc" "main" {
  cidr_block = var.vpc_cidr
  tags       = local.common_tags
}

resource "aws_subnet" "public" {
  count      = length(local.subnet_cidrs)
  vpc_id     = aws_vpc.main.id
  cidr_block = local.subnet_cidrs[count.index]
  
  tags = merge(
    local.common_tags,
    {
      Name = "${local.name_prefix}-subnet-${count.index}"
    }
  )
}
```

**When to use locals vs variables:**
- **Variables:** External input, can be set by users
- **Locals:** Internal computation, derived from variables

## Variable Organization Best Practices

### File Structure

```
terraform/
├── main.tf              # Resources
├── variables.tf         # Variable declarations
├── outputs.tf          # Output declarations
├── terraform.tfvars    # Variable values (gitignore!)
├── dev.tfvars          # Dev environment values
├── staging.tfvars      # Staging environment values
├── prod.tfvars         # Production environment values
└── locals.tf           # Local values
```

### variables.tf Example

```hcl
# variables.tf - Organized by category

# =============================================================================
# GENERAL
# =============================================================================

variable "project_name" {
  description = "Name of the project"
  type        = string
}

variable "environment" {
  description = "Environment name (dev, staging, prod)"
  type        = string
  
  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}

# =============================================================================
# NETWORKING
# =============================================================================

variable "vpc_cidr" {
  description = "CIDR block for VPC"
  type        = string
  default     = "10.0.0.0/16"
}

variable "availability_zones" {
  description = "List of availability zones"
  type        = list(string)
}

# =============================================================================
# COMPUTE
# =============================================================================

variable "instance_type" {
  description = "EC2 instance type"
  type        = string
  default     = "t2.micro"
}

variable "instance_count" {
  description = "Number of instances to create"
  type        = number
  default     = 1
  
  validation {
    condition     = var.instance_count > 0 && var.instance_count <= 10
    error_message = "Instance count must be between 1 and 10."
  }
}

# =============================================================================
# TAGS
# =============================================================================

variable "tags" {
  description = "Additional tags to apply to resources"
  type        = map(string)
  default     = {}
}
```

### terraform.tfvars Example

```hcl
# terraform.tfvars - Default/shared values

project_name = "my-app"
environment  = "dev"

availability_zones = [
  "us-west-2a",
  "us-west-2b",
  "us-west-2c"
]

tags = {
  Team  = "platform"
  Owner = "devops@example.com"
}
```

### prod.tfvars Example

```hcl
# prod.tfvars - Production-specific overrides

environment    = "prod"
instance_type  = "t3.large"
instance_count = 5

tags = {
  Team        = "platform"
  Owner       = "devops@example.com"
  Environment = "production"
  CostCenter  = "engineering"
}
```

## Remote State Data Source

Access outputs from another Terraform configuration:

```hcl
# Configuration A: networking/outputs.tf
output "vpc_id" {
  value = aws_vpc.main.id
}

output "subnet_ids" {
  value = aws_subnet.private[*].id
}

# Configuration B: application/main.tf
data "terraform_remote_state" "networking" {
  backend = "s3"
  
  config = {
    bucket = "my-terraform-state"
    key    = "networking/terraform.tfstate"
    region = "us-west-2"
  }
}

# Use outputs from remote state
resource "aws_instance" "app" {
  subnet_id = data.terraform_remote_state.networking.outputs.subnet_ids[0]
  # ...
}
```

## Common Mistakes to Avoid

| Mistake | Problem | Solution |
|---------|---------|----------|
| No descriptions | Hard to understand | Add descriptions to all variables |
| No type constraints | Type errors | Always specify types |
| No validation | Invalid values | Add validation rules |
| Committing tfvars with secrets | Security breach | Gitignore variable files with secrets |
| Using default for required vars | Missing values | Omit default for required inputs |
| Overly complex variables | Hard to use | Break into simpler variables |
| Not using sensitive flag | Secrets exposed | Mark sensitive variables |
