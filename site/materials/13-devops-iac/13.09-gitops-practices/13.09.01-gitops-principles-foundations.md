## Learning Objectives

By the end of this lesson, you will be able to:

- Recognize the key pillars of GitOps methodology

---

## Introduction

GitOps represents a paradigm shift in how we manage infrastructure and applications. By treating Git repositories as the source of truth for declarative infrastructure and applications, GitOps enables teams to leverage the power of version control for operations—bringing the same practices that revolutionized software development to infrastructure management.

## Key Concepts Summary

### The Four Core GitOps Principles

**1. Declarative Configuration**
The entire system (infrastructure and applications) must be described declaratively. Rather than imperative scripts that execute commands, GitOps uses declarative configurations (YAML, JSON, HCL) that define the desired end state.

```yaml
# Declarative approach
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  template:
    spec:
      containers:
      - name: app
        image: myapp:v1.2.3
```

**2. Versioned and Immutable**
All configuration must be stored in Git (or another version control system), providing:
- Complete audit trail of who changed what and when
- Ability to rollback to any previous state
- Immutable history that cannot be altered

**3. Automatically Applied**
Once changes are committed to Git, they should be automatically applied to the target system without manual intervention. This is typically achieved through GitOps operators or controllers.

**4. Continuously Reconciled**
Software agents continuously monitor both the desired state (in Git) and actual state (in production), automatically correcting any drift.

### GitOps vs Traditional CI/CD

| Aspect | Traditional CI/CD | GitOps |
|--------|------------------|---------|
| Deployment Trigger | Push from CI pipeline | Pull by GitOps operator |
| Source of Truth | CI/CD configuration | Git repository |
| Credentials | Stored in CI/CD tool | Remain in cluster |
| Drift Detection | Manual checks | Automatic reconciliation |
| Rollback | Pipeline reversal | Git revert |

### Benefits of GitOps

- **Single Source of Truth:** Git becomes the authoritative source for desired system state
- **Enhanced Security:** Credentials don't leave the cluster; no need for external access
- **Auditability:** Every change is tracked with Git history
- **Easy Rollbacks:** Revert to previous states with `git revert`
- **Self-Healing:** Automatic drift correction prevents configuration drift
- **Developer Experience:** Developers use familiar Git workflows

## Practice Exercise

After completing the materials, try this exercise (do not spend more than 10 minutes):

Consider your current deployment process:
1. List 3 manual steps in your current deployment workflow
2. For each step, identify how GitOps could automate or improve it
3. Identify one area where drift between configuration and actual state has caused issues

Write down your thoughts—this will help you think critically about GitOps applicability to your environment.
