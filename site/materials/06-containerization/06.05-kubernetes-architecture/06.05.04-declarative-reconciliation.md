---

## Introduction

Kubernetes uses a declarative approach: you declare what you want (desired state), and Kubernetes figures out how to make it happen through continuous reconciliation. This is fundamentally different from imperative systems where you specify exact steps. Understanding this pattern is key to mastering Kubernetes.

## Key Concepts Summary

### Declarative vs Imperative

**Imperative (commands):**
```bash
# Tell Kubernetes exactly what to do
kubectl create deployment nginx --image=nginx
kubectl scale deployment nginx --replicas=3
kubectl set image deployment/nginx nginx=nginx:1.21
kubectl expose deployment nginx --port=80
```

**Pros:** Quick for one-off tasks  
**Cons:** Not repeatable, no version control, hard to track changes

**Declarative (configuration files):**
```yaml
# deployment.yaml - Declare what you want
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
        ports:
        - containerPort: 80
```

```bash
# Apply the desired state
kubectl apply -f deployment.yaml

# Modify the file, apply again
kubectl apply -f deployment.yaml
```

**Pros:** Repeatable, version controlled, self-documenting, GitOps-friendly  
**Cons:** Slightly more verbose

### The Reconciliation Loop

**Core Pattern:**
```
1. Observe current state
   ↓
2. Compare with desired state
   ↓
3. Take action if different
   ↓
4. Wait and repeat
```

**Detailed Flow:**
```
┌─────────────────────────────────────────┐
│  Controller watches API server          │
│  (using Watch API for efficiency)       │
└────────────┬────────────────────────────┘
             ↓
┌─────────────────────────────────────────┐
│  Event: Deployment changed               │
│  Desired: 5 replicas                     │
└────────────┬────────────────────────────┘
             ↓
┌─────────────────────────────────────────┐
│  Query current state                     │
│  Actual: 3 replicas                      │
└────────────┬────────────────────────────┘
             ↓
┌─────────────────────────────────────────┐
│  Calculate diff: Need 2 more pods        │
└────────────┬────────────────────────────┘
             ↓
┌─────────────────────────────────────────┐
│  Take action: Create 2 new pods          │
└────────────┬────────────────────────────┘
             ↓
┌─────────────────────────────────────────┐
│  Update status in API server             │
└────────────┬────────────────────────────┘
             ↓
         [Loop repeats]
```

### Deployment Controller Example

**Desired State:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
spec:
  replicas: 3  # Desired: 3 replicas
  selector:
    matchLabels:
      app: nginx
  template:
    # Pod template...
```

**Controller Actions:**

**Scenario 1: Scale Up**
```
Current: 2 pods running
Desired: 3 pods

Action: Create 1 new pod
```

**Scenario 2: Scale Down**
```
Current: 5 pods running
Desired: 3 pods

Action: Delete 2 pods (oldest first)
```

**Scenario 3: Pod Crash**
```
Current: 2 healthy pods, 1 crashed
Desired: 3 healthy pods

Action: Create 1 new pod to replace crashed one
```

**Scenario 4: Image Update**
```
Current: 3 pods with image nginx:1.20
Desired: 3 pods with image nginx:1.21

Action: Rolling update
1. Create 1 pod with new image
2. Wait for it to be ready
3. Delete 1 old pod
4. Repeat until all updated
```

### Using kubectl apply

**Basic apply:**
```bash
# Apply single file
kubectl apply -f deployment.yaml

# Apply directory
kubectl apply -f manifests/

# Apply with recursive
kubectl apply -f manifests/ --recursive

# Apply from URL
kubectl apply -f https://example.com/manifest.yaml
```

**Tracking changes:**
```yaml
# deployment.yaml v1
spec:
  replicas: 3
```

```bash
kubectl apply -f deployment.yaml
# Created deployment with 3 replicas
```

```yaml
# deployment.yaml v2 (changed)
spec:
  replicas: 5
```

```bash
kubectl apply -f deployment.yaml
# Updated deployment to 5 replicas
```

**Last-applied annotation:**
```bash
# kubectl stores last-applied configuration
kubectl get deployment nginx -o yaml

# Shows:
# metadata:
#   annotations:
#     kubectl.kubernetes.io/last-applied-configuration: |
#       {"apiVersion":"apps/v1","kind":"Deployment",...}
```

**Three-way merge:**
```
┌─────────────────────────────────────────┐
│  Current local file (new desired state) │
└────────────┬────────────────────────────┘
             ↓
        [Compare with]
             ↓
┌─────────────────────────────────────────┐
│  Last applied configuration (previous)   │
└────────────┬────────────────────────────┘
             ↓
        [And with]
             ↓
┌─────────────────────────────────────────┐
│  Current cluster state (actual)          │
└────────────┬────────────────────────────┘
             ↓
        [Results in]
             ↓
┌─────────────────────────────────────────┐
│  Calculated patch to apply               │
└─────────────────────────────────────────┘
```

### Controller Pattern in Detail

**Generic Controller Structure:**
```go
// Simplified controller pseudocode
type Controller struct {
    client    kubernetes.Interface
    workqueue workqueue.RateLimitingInterface
}

func (c *Controller) Run() {
    // Watch for changes
    informer.AddEventHandler(cache.ResourceEventHandlerFuncs{
        AddFunc:    c.handleAdd,
        UpdateFunc: c.handleUpdate,
        DeleteFunc: c.handleDelete,
    })
    
    // Process work queue
    for {
        item := c.workqueue.Get()
        c.reconcile(item)
    }
}

func (c *Controller) reconcile(key string) {
    // Get desired state
    desired := c.client.Get(key)
    
    // Get current state
    actual := getCurrentState()
    
    // Compare and act
    if !reflect.DeepEqual(desired, actual) {
        makeItSo(desired, actual)
    }
}
```

**Built-in Controllers:**

**Deployment Controller:**
- Manages ReplicaSets
- Handles rolling updates
- Rollback support

**ReplicaSet Controller:**
- Ensures correct number of pods
- Creates/deletes pods as needed

**Node Controller:**
- Monitors node health
- Evicts pods from failed nodes

**Service Controller:**
- Creates cloud load balancers
- Updates endpoints

**Job Controller:**
- Runs pods to completion
- Tracks success/failure

### Level-Triggered vs Edge-Triggered

**Level-Triggered (Kubernetes approach):**
```
Controller continuously checks state
Not dependent on catching every event
Eventually consistent
Resilient to missed events or downtime
```

**Example:**
```
Desired: 3 replicas
Events:
  - Pod 1 created ✓
  - Pod 2 created ✓
  - [Controller restarts - misses event]
  - Pod 3 creation event missed ✗

Level-triggered behavior:
  Controller wakes up
  Checks: How many pods? (2)
  Desired: 3
  Action: Create 1 more pod
  Result: Converges to desired state ✓
```

### Practical Examples

**Example 1: Self-Healing**
```bash
# Create deployment
kubectl apply -f deployment.yaml
# 3 pods created

# Delete a pod manually
kubectl delete pod nginx-abc123

# Controller detects: 2 pods (desired: 3)
# Automatically creates new pod
# System self-heals!
```

**Example 2: Configuration Drift**
```bash
# Apply initial config
kubectl apply -f deployment.yaml
# replicas: 3

# Someone manually scales
kubectl scale deployment nginx --replicas=5
# Now: 5 pods running

# Re-apply original config
kubectl apply -f deployment.yaml
# System converges back to 3 replicas
```

**Example 3: Rolling Update**
```yaml
# v1 - deployment.yaml
spec:
  replicas: 3
  template:
    spec:
      containers:
      - name: nginx
        image: nginx:1.20
```

```bash
kubectl apply -f deployment.yaml
# 3 pods with nginx:1.20
```

```yaml
# v2 - deployment.yaml (changed image)
spec:
  replicas: 3
  template:
    spec:
      containers:
      - name: nginx
        image: nginx:1.21  # Changed!
```

```bash
kubectl apply -f deployment.yaml

# Controller orchestrates rolling update:
# 1. Create new pod with 1.21
# 2. Wait for ready
# 3. Delete old pod
# 4. Repeat
```

### GitOps Workflow

**Store configuration in Git:**
```
1. Modify deployment.yaml
   ↓
2. Commit and push to Git
   ↓
3. CI/CD pipeline applies to cluster
   ↓
4. kubectl apply -f deployment.yaml
   ↓
5. Controllers reconcile to new state
```

**Benefits:**
- Version control for infrastructure
- Audit trail of changes
- Easy rollback (git revert)
- Pull request workflow
- Automated deployments

**GitOps Tools:**
```
- ArgoCD: Declarative GitOps CD for Kubernetes
- Flux: GitOps operator for Kubernetes
- Jenkins X: CI/CD solution for cloud native apps
```

### Operator Pattern

**Custom Controllers:**
```
Operator = Custom Resource + Custom Controller

Example: MySQL Operator
1. Define MySQL CRD
2. Implement controller that:
   - Watches MySQL custom resources
   - Creates Deployments, Services, PVCs
   - Manages backups, upgrades
   - Handles failover
```

**MySQL Operator Example:**
```yaml
apiVersion: mysql.oracle.com/v1
kind: MySQLCluster
metadata:
  name: my-database
spec:
  instances: 3
  version: "8.0"
  backup:
    enabled: true
    schedule: "0 2 * * *"
  resources:
    requests:
      memory: 2Gi
      cpu: 1
```

**Operator Reconciliation:**
```
MySQL Operator watches MySQLCluster resources:

1. User creates MySQLCluster "my-database"
2. Operator detects new resource
3. Operator creates:
   - StatefulSet (3 replicas)
   - Service (ClusterIP)
   - Service (Headless for replication)
   - PersistentVolumeClaims (3)
   - ConfigMap (MySQL configuration)
   - Secret (root password)
4. Operator monitors cluster health
5. If pod fails, StatefulSet recreates it
6. Operator ensures replication is healthy
```

### Advanced Reconciliation Patterns

**Status Conditions:**
```yaml
status:
  conditions:
  - type: Available
    status: "True"
    lastTransitionTime: "2024-01-15T10:30:00Z"
    reason: MinimumReplicasAvailable
    message: Deployment has minimum availability
  - type: Progressing
    status: "True"
    lastTransitionTime: "2024-01-15T10:29:45Z"
    reason: NewReplicaSetAvailable
    message: ReplicaSet "nginx-abc123" has successfully progressed
```

**Finalizers:**
```yaml
# Prevent deletion until cleanup is done
metadata:
  finalizers:
  - cleanup.example.com/database

# Controller process:
# 1. User deletes resource
# 2. Resource marked for deletion (deletionTimestamp set)
# 3. Controller performs cleanup (delete external resources)
# 4. Controller removes finalizer
# 5. Kubernetes deletes the object
```

**Owner References and Cascading Deletion:**
```yaml
# Child object references parent
metadata:
  ownerReferences:
  - apiVersion: apps/v1
    kind: Deployment
    name: nginx
    uid: 12345-67890
    controller: true
    blockOwnerDeletion: true

# When Deployment is deleted:
# → All owned ReplicaSets deleted
# → All owned Pods deleted (cascade)
```

**Garbage Collection Policies:**
```bash
# Foreground: Delete owner after dependents
kubectl delete deployment nginx --cascade=foreground

# Background: Delete owner immediately, dependents later (default)
kubectl delete deployment nginx --cascade=background

# Orphan: Delete owner, leave dependents
kubectl delete deployment nginx --cascade=orphan
```

### Declarative Management Best Practices

**Directory Structure:**
```
k8s/
├── base/
│   ├── deployment.yaml
│   ├── service.yaml
│   └── configmap.yaml
├── overlays/
│   ├── dev/
│   │   └── kustomization.yaml
│   ├── staging/
│   │   └── kustomization.yaml
│   └── prod/
│       └── kustomization.yaml
└── kustomization.yaml
```

**Kustomize Example:**
```yaml
# base/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
- deployment.yaml
- service.yaml
- configmap.yaml

---
# overlays/prod/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
bases:
- ../../base
replicas:
- name: nginx
  count: 5
images:
- name: nginx
  newTag: "1.21"
```

```bash
# Apply with kustomize
kubectl apply -k overlays/prod/
```

## Practice Exercise

After completing the materials (25 minutes max):

1. **Create declarative configuration:**
```yaml
# nginx-app.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
  labels:
    app: nginx
spec:
  replicas: 2
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.20
        ports:
        - containerPort: 80
        resources:
          requests:
            memory: "64Mi"
            cpu: "100m"
          limits:
            memory: "128Mi"
            cpu: "200m"
---
apiVersion: v1
kind: Service
metadata:
  name: nginx
spec:
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```

2. **Apply and observe:**
```bash
# Apply
kubectl apply -f nginx-app.yaml

# Check status
kubectl get deployments,pods,services

# Watch the reconciliation
kubectl get pods -w

# Check events
kubectl get events --sort-by='.lastTimestamp' | tail -10
```

3. **Test reconciliation (self-healing):**
```bash
# Delete a pod
POD=$(kubectl get pods -l app=nginx -o jsonpath='{.items[0].metadata.name}')
kubectl delete pod $POD

# Watch it recreate
kubectl get pods -w

# Verify count is maintained
kubectl get pods -l app=nginx
```

4. **Update configuration (scaling):**
```yaml
# Change replicas to 4 in nginx-app.yaml
spec:
  replicas: 4
```

```bash
# Apply changes
kubectl apply -f nginx-app.yaml

# Watch scale up
kubectl get pods -w

# View diff
kubectl diff -f nginx-app.yaml
```

5. **Observe rolling update:**
```yaml
# Change image in nginx-app.yaml
image: nginx:1.21
```

```bash
# Apply update
kubectl apply -f nginx-app.yaml

# Watch rollout
kubectl rollout status deployment nginx

# View rollout history
kubectl rollout history deployment nginx

# Check ReplicaSets
kubectl get rs

# See old and new ReplicaSets
```

6. **Test drift correction:**
```bash
# Manually scale deployment
kubectl scale deployment nginx --replicas=6

# Verify scale
kubectl get pods -l app=nginx

# Re-apply manifest
kubectl apply -f nginx-app.yaml

# Watch it converge back to 4 replicas
kubectl get pods -w
```

7. **Rollback:**
```bash
# View revision history
kubectl rollout history deployment nginx

# Rollback to previous version
kubectl rollout undo deployment nginx

# Rollback to specific revision
kubectl rollout undo deployment nginx --to-revision=1

# Check rollout status
kubectl rollout status deployment nginx
```

8. **Clean up:**
```bash
# Delete resources
kubectl delete -f nginx-app.yaml

# Verify deletion
kubectl get all -l app=nginx
```
