# Lesson 1: .NET Base Images and Selection

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand the different .NET container image types (SDK, ASP.NET runtime, runtime)
- Choose between Debian and Alpine-based images
- Select the appropriate base image for your use case
- Understand image tagging and versioning strategies
- Optimize image size for .NET applications

---

## Introduction

Microsoft provides official .NET container images optimized for different scenarios. Choosing the right base image affects your container's size, security, performance, and compatibility. This lesson covers the .NET image ecosystem and helps you make informed decisions about which images to use.

## Key Concepts Summary

### .NET Container Image Types

Microsoft provides several image variants for different purposes:

```
┌─────────────────────────────────────────────┐
│         .NET Image Hierarchy                 │
├─────────────────────────────────────────────┤
│  mcr.microsoft.com/dotnet/sdk:8.0           │
│  ↓ (Build stage)                            │
│  - Full .NET SDK                             │
│  - Build tools (MSBuild, NuGet)             │
│  - Development tools                         │
│  - Size: ~700MB                              │
├─────────────────────────────────────────────┤
│  mcr.microsoft.com/dotnet/aspnet:8.0        │
│  ↓ (Runtime for ASP.NET Core)              │
│  - ASP.NET Core runtime                      │
│  - .NET runtime                              │
│  - No SDK or build tools                    │
│  - Size: ~200MB                              │
├─────────────────────────────────────────────┤
│  mcr.microsoft.com/dotnet/runtime:8.0       │
│  ↓ (Runtime for console apps)              │
│  - .NET runtime only                         │
│  - No ASP.NET Core                           │
│  - No SDK                                    │
│  - Size: ~190MB                              │
└─────────────────────────────────────────────┘
```

### 1. SDK Images (`dotnet/sdk`)

**Used for:** Building .NET applications

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0
```

**Contains:**
- Full .NET SDK
- MSBuild, NuGet, dotnet CLI
- Development tools
- Runtime

**Size:** ~700MB (Debian), ~400MB (Alpine)

**Use case:** Build stage in multi-stage Dockerfiles

**Example:**
```dockerfile
# Build stage only
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app/publish
```

### 2. ASP.NET Core Runtime Images (`dotnet/aspnet`)

**Used for:** Running ASP.NET Core applications (web apps, APIs)

```dockerfile
FROM mcr.microsoft.com/dotnet/aspnet:8.0
```

**Contains:**
- ASP.NET Core runtime
- .NET runtime
- Kestrel web server

**Size:** ~200MB (Debian), ~110MB (Alpine)

**Use case:** Production runtime for web applications

**Example:**
```dockerfile
# Runtime stage
FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "MyWebApp.dll"]
```

### 3. .NET Runtime Images (`dotnet/runtime`)

**Used for:** Running console applications, workers, background services

```dockerfile
FROM mcr.microsoft.com/dotnet/runtime:8.0
```

**Contains:**
- .NET runtime only
- No ASP.NET Core

**Size:** ~190MB (Debian), ~100MB (Alpine)

**Use case:** Non-web .NET applications

**Example:**
```dockerfile
FROM mcr.microsoft.com/dotnet/runtime:8.0
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "MyConsoleApp.dll"]
```

### Debian vs Alpine Variants

Each image type comes in Debian and Alpine variants:

| Aspect | Debian | Alpine |
|--------|--------|--------|
| **Size** | Larger (~200MB) | Smaller (~110MB) |
| **C Library** | glibc | musl libc |
| **Compatibility** | Broader | Some native dependencies may not work |
| **Security** | Fewer vulnerabilities (larger surface) | Minimal attack surface |
| **Performance** | Standard | Slightly slower in some scenarios |
| **Recommendation** | **Default choice** | Use for size optimization |

**Debian examples:**
```dockerfile
FROM mcr.microsoft.com/dotnet/aspnet:8.0
FROM mcr.microsoft.com/dotnet/aspnet:8.0-bookworm-slim
```

**Alpine examples:**
```dockerfile
FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine3.18
```

### Image Tagging Strategy

**Specify explicit versions:**
```dockerfile
# ❌ Bad: unpredictable
FROM mcr.microsoft.com/dotnet/aspnet:latest

# ✅ Good: major version
FROM mcr.microsoft.com/dotnet/aspnet:8.0

# ✅ Better: specific patch version
FROM mcr.microsoft.com/dotnet/aspnet:8.0.1

# ✅ Best: include OS variant
FROM mcr.microsoft.com/dotnet/aspnet:8.0.1-bookworm-slim
```

**Tag format:**
```
mcr.microsoft.com/dotnet/{image-type}:{dotnet-version}-{os-version}

Examples:
- dotnet/sdk:8.0-alpine
- dotnet/aspnet:8.0-bookworm-slim
- dotnet/runtime:8.0.1-jammy
```

### Common Scenarios and Image Selection

**Scenario 1: ASP.NET Core Web API**
```dockerfile
# Build stage: Use SDK
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build

# Runtime stage: Use ASP.NET runtime
FROM mcr.microsoft.com/dotnet/aspnet:8.0
```

**Scenario 2: Console Application**
```dockerfile
# Build stage: Use SDK
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build

# Runtime stage: Use .NET runtime (smaller)
FROM mcr.microsoft.com/dotnet/runtime:8.0
```

**Scenario 3: Blazor WebAssembly (Static)**
```dockerfile
# Build stage: Use SDK
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build

# Runtime stage: Use nginx (smallest)
FROM nginx:alpine
COPY --from=build /app/publish/wwwroot /usr/share/nginx/html
```

**Scenario 4: Worker Service**
```dockerfile
# Build stage: Use SDK
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build

# Runtime stage: Use .NET runtime
FROM mcr.microsoft.com/dotnet/runtime:8.0
```

### Complete Multi-Stage Example

```dockerfile
# Build stage
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Copy and restore
COPY ["MyApp/MyApp.csproj", "MyApp/"]
RUN dotnet restore "MyApp/MyApp.csproj"

# Copy source and build
COPY . .
WORKDIR "/src/MyApp"
RUN dotnet build "MyApp.csproj" -c Release -o /app/build

# Publish stage
FROM build AS publish
RUN dotnet publish "MyApp.csproj" \
    -c Release \
    -o /app/publish \
    /p:UseAppHost=false

# Runtime stage
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS final
WORKDIR /app

# Create non-root user
RUN adduser --disabled-password --gecos '' appuser && \
    chown -R appuser /app
USER appuser

EXPOSE 8080

COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

### Size Comparison

Real-world size comparison for an ASP.NET Core API:

| Image Configuration | Size |
|---------------------|------|
| SDK only (no multi-stage) | ~700MB |
| SDK + ASP.NET Runtime (multi-stage, Debian) | ~200MB |
| SDK + ASP.NET Runtime (multi-stage, Alpine) | ~110MB |
| SDK + ASP.NET Runtime (Alpine + optimized) | ~85MB |

**Optimization techniques:**
- Use Alpine images: -45% size
- Enable trimming: -20% size
- Enable ReadyToRun: same size, faster startup

### .NET 8+ Enhancements

**.NET 8 introduces smaller images:**
```dockerfile
# .NET 8 with Ubuntu Chiseled (ultra-minimal)
FROM mcr.microsoft.com/dotnet/aspnet:8.0-jammy-chiseled

# Benefits:
# - No package manager
# - No shell
# - Smaller size
# - Fewer vulnerabilities
```

### Architecture-Specific Images

Support for multiple architectures:

```dockerfile
# Multi-arch support (AMD64, ARM64, ARM32)
FROM mcr.microsoft.com/dotnet/aspnet:8.0

# Specific architecture
FROM --platform=linux/amd64 mcr.microsoft.com/dotnet/aspnet:8.0
FROM --platform=linux/arm64 mcr.microsoft.com/dotnet/aspnet:8.0
```

### Best Practices

**1. Use specific version tags:**
```dockerfile
# ✅ Good
FROM mcr.microsoft.com/dotnet/aspnet:8.0.1-bookworm-slim

# ❌ Bad
FROM mcr.microsoft.com/dotnet/aspnet:latest
```

**2. Choose minimal runtime:**
```dockerfile
# ASP.NET Core app
FROM mcr.microsoft.com/dotnet/aspnet:8.0

# Console app (use smaller runtime)
FROM mcr.microsoft.com/dotnet/runtime:8.0
```

**3. Consider Alpine for size:**
```dockerfile
FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
```

**4. Use multi-stage builds:**
```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
# ... build steps ...

FROM mcr.microsoft.com/dotnet/aspnet:8.0
# ... runtime setup ...
```

**5. Keep images updated:**
```bash
# Pull latest patches
docker pull mcr.microsoft.com/dotnet/aspnet:8.0
```

### Troubleshooting Common Issues

**Issue 1: Alpine compatibility problems**
```
Error: Unable to load shared library 'libXYZ.so'
```
**Solution:** Switch to Debian-based image or install Alpine dependencies

**Issue 2: Time zone issues**
```dockerfile
# Set timezone in Alpine
RUN apk add --no-cache tzdata
ENV TZ=America/New_York
```

**Issue 3: Globalization issues**
```dockerfile
# Enable globalization in Alpine
ENV DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=false
RUN apk add --no-cache icu-libs
```

## Practice Exercise

After completing the materials (20 minutes max):

1. **Create a simple ASP.NET Core app:**
```bash
dotnet new webapi -n MyApi
cd MyApi
```

2. **Create a Dockerfile with different base images:**

**Dockerfile.debian:**
```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app

FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app
COPY --from=build /app .
ENTRYPOINT ["dotnet", "MyApi.dll"]
```

**Dockerfile.alpine:**
```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0-alpine AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app

FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
WORKDIR /app
COPY --from=build /app .
ENTRYPOINT ["dotnet", "MyApi.dll"]
```

3. **Build and compare:**
```bash
docker build -f Dockerfile.debian -t myapi:debian .
docker build -f Dockerfile.alpine -t myapi:alpine .

docker images | grep myapi
```

4. **Test both:**
```bash
docker run -p 5000:8080 myapi:debian
docker run -p 5000:8080 myapi:alpine
```
