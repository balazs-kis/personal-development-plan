# Lesson 5: Debugging Containerized .NET Apps

## Learning Objectives

By the end of this lesson, you will be able to:
- Debug .NET applications running in Docker containers
- Use Visual Studio and VS Code for container debugging
- Access logs from containerized applications
- Attach debuggers to running containers
- Troubleshoot common containerization issues
- Use diagnostic tools in production containers

---

## Introduction

Debugging containerized applications presents unique challenges. Your code runs in an isolated environment with different networking, file systems, and dependencies. This lesson covers techniques and tools for effectively debugging .NET applications in containers during development and troubleshooting issues in production.

### Visual Studio Container Debugging

**Visual Studio automatically:**
1. Builds a debug version of your image
2. Mounts source code as volumes
3. Enables hot reload
4. Attaches the debugger
5. Provides full debugging experience

**Setup:**
```xml
<!-- Add Docker support to existing project -->
Right-click project → Add → Docker Support
```

**Generated Dockerfile:**
```dockerfile
# Visual Studio generates multi-stage Dockerfile
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS base
WORKDIR /app
EXPOSE 80

FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY ["MyApp/MyApp.csproj", "MyApp/"]
RUN dotnet restore
COPY . .
WORKDIR "/src/MyApp"
RUN dotnet build -c Release -o /app/build

FROM build AS publish
RUN dotnet publish -c Release -o /app/publish

FROM base AS final
WORKDIR /app
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

**Debug:**
- Press F5 or click "Docker" in the debug dropdown
- Set breakpoints as normal
- Full IntelliSense and debugging features

### VS Code Container Debugging

**Install extensions:**
- Docker
- C# Dev Kit
- Remote - Containers

**launch.json:**
```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Docker .NET Launch",
      "type": "docker",
      "request": "launch",
      "preLaunchTask": "docker-run: debug",
      "netCore": {
        "appProject": "${workspaceFolder}/MyApp/MyApp.csproj"
      }
    }
  ]
}
```

**tasks.json:**
```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "type": "docker-build",
      "label": "docker-build: debug",
      "dependsOn": ["build"],
      "dockerBuild": {
        "tag": "myapp:dev",
        "target": "base",
        "dockerfile": "${workspaceFolder}/Dockerfile",
        "context": "${workspaceFolder}",
        "pull": true
      },
      "netCore": {
        "appProject": "${workspaceFolder}/MyApp/MyApp.csproj"
      }
    },
    {
      "type": "docker-run",
      "label": "docker-run: debug",
      "dependsOn": ["docker-build: debug"],
      "dockerRun": {
        "env": {
          "ASPNETCORE_ENVIRONMENT": "Development"
        },
        "ports": [
          {
            "containerPort": 80,
            "hostPort": 5000
          }
        ],
        "volumes": [
          {
            "localPath": "${workspaceFolder}",
            "containerPath": "/src",
            "permissions": "rw"
          }
        ]
      },
      "netCore": {
        "appProject": "${workspaceFolder}/MyApp/MyApp.csproj",
        "enableDebugging": true
      }
    }
  ]
}
```

### Container Logs

**View logs:**
```bash
# Follow logs (real-time)
docker logs -f mycontainer

# Last 100 lines
docker logs --tail 100 mycontainer

# Logs since 1 hour ago
docker logs --since 1h mycontainer

# Logs with timestamps
docker logs -t mycontainer
```

**Docker Compose logs:**
```bash
# All services
docker-compose logs -f

# Specific service
docker-compose logs -f api

# Last 50 lines from all services
docker-compose logs --tail=50
```

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Debug",
      "Microsoft.AspNetCore": "Information",
      "Microsoft.EntityFrameworkCore": "Information"
    }
  }
}
```

**appsettings.Production.json:**
```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning",
      "Microsoft.EntityFrameworkCore": "Warning"
    }
  }
}
```

**Program.cs:**
```csharp
var builder = WebApplication.CreateBuilder(args);

// Configure logging
builder.Logging.ClearProviders();
builder.Logging.AddConsole();
builder.Logging.AddDebug();

// In production, add structured logging
if (builder.Environment.IsProduction())
{
    builder.Logging.AddJsonConsole();
}
```

**Get shell access:**
```bash

# Windows containers (PowerShell)
```

### Inspect Container Configuration

**View container details:**
```bash
# Full inspection
docker inspect mycontainer

# Get specific value
docker inspect -f '{{.State.Status}}' mycontainer
docker inspect -f '{{range.NetworkSettings.Networks}}{{.IPAddress}}{{end}}' mycontainer

# Environment variables
docker inspect -f '{{range.Config.Env}}{{println .}}{{end}}' mycontainer
```

### Development Dockerfile with Debugging

```dockerfile
# Development stage with debugger
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS development
WORKDIR /src

# Install debugger (vsdbg)
RUN apt-get update && apt-get install -y --no-install-recommends \
    unzip \
    && rm -rf /var/lib/apt/lists/*

# Install Visual Studio Remote Debugger
RUN curl -sSL https://aka.ms/getvsdbgsh | bash /dev/stdin -v latest -l /vsdbg

# Copy project files
COPY ["MyApp/MyApp.csproj", "MyApp/"]
RUN dotnet restore "MyApp/MyApp.csproj"

# Copy source
COPY . .
WORKDIR "/src/MyApp"

# Build in Debug mode
RUN dotnet build "MyApp.csproj" -c Debug -o /app/build

# Enable debugging
ENV ASPNETCORE_ENVIRONMENT=Development
ENV DOTNET_USE_POLLING_FILE_WATCHER=true

EXPOSE 80
EXPOSE 443

CMD ["dotnet", "run", "--no-build", "--no-launch-profile"]
```

**Use in docker-compose.override.yml:**
```yaml
version: '3.8'

services:
  api:
    build:
      context: .
      target: development
    volumes:
      - ./src:/src
    environment:
      - ASPNETCORE_ENVIRONMENT=Development
      - ASPNETCORE_URLS=http://+:80
    ports:
      - "5000:80"
      - "5001:443"
```

### Remote Debugging

**Attach debugger to running container:**
```bash
# Copy vsdbg to container
docker cp ~/.vs-debugger mycontainer:/vsdbg

# Get container ID
docker ps

# In VS Code, attach to process
# F1 → ".NET: Attach to Process" → Select container → Select process
```

**VS Code launch.json for remote debugging:**
```json
{
  "name": ".NET Core Docker Attach",
  "type": "coreclr",
  "request": "attach",
  "processId": "${command:pickRemoteProcess}",
  "pipeTransport": {
    "pipeProgram": "docker",
    "pipeArgs": ["exec", "-i", "mycontainer"],
    "debuggerPath": "/vsdbg/vsdbg",
    "pipeCwd": "${workspaceRoot}",
    "quoteArgs": false
  },
  "sourceFileMap": {
    "/src": "${workspaceFolder}"
  }
}
```

### Diagnostic Endpoints

**Enable diagnostic endpoints in Program.cs:**
```csharp
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
}

// Diagnostic endpoints (be careful in production!)
if (app.Environment.IsDevelopment())
{
    // Environment info
    app.MapGet("/debug/env", (IConfiguration config) => 
        config.AsEnumerable().ToDictionary(k => k.Key, v => v.Value));
    
    // Process info
    app.MapGet("/debug/process", () => new
    {
        ProcessId = Environment.ProcessId,
        WorkingSet = Environment.WorkingSet,
        ProcessorCount = Environment.ProcessorCount,
        OSVersion = Environment.OSVersion.ToString(),
        Is64BitProcess = Environment.Is64BitProcess
    });
}
```

### Collecting Diagnostic Data

**Generate dump file:**
```bash
# Install dotnet-dump
docker exec mycontainer dotnet tool install -g dotnet-dump

# Collect dump
docker exec mycontainer /root/.dotnet/tools/dotnet-dump collect -p 1

# Copy dump out
docker cp mycontainer:/app/core_20240122_123456 ./dump.dmp
```

**Analyze dump:**
```bash
# Install dotnet-dump locally
dotnet tool install -g dotnet-dump

# Analyze
dotnet-dump analyze dump.dmp
```

**Collect trace:**
```bash
# Install dotnet-trace
docker exec mycontainer dotnet tool install -g dotnet-trace

# Collect trace
docker exec mycontainer /root/.dotnet/tools/dotnet-trace collect -p 1 --duration 00:00:30

# Copy trace out
docker cp mycontainer:/app/trace.nettrace ./
```

### Common Issues and Solutions

**Issue 1: Can't connect to database**
```bash
# Check if database container is running
docker ps | grep db

# Test connectivity from app container
docker exec myapp ping db

# Check connection string
docker exec myapp printenv | grep ConnectionStrings
```

**Issue 2: Port already in use**
```bash
# Check what's using the port
netstat -ano | findstr :5000  # Windows
lsof -i :5000                  # Linux/Mac

# Use different port
docker run -p 5001:80 myapp
```

**Issue 3: App crashes immediately**
```bash
# Check logs
docker logs mycontainer

# Run interactively to see output
docker run -it --rm myapp

# Check if DLL exists
docker run -it --rm myapp ls -la /app
```

**Issue 4: Environment variables not loaded**
```bash
# Verify environment variables
docker inspect mycontainer | grep -A 20 Env

# Check inside container
docker exec mycontainer env
```

### Production Debugging (Cautiously!)

**Add debug symbols to production:**
```dockerfile
# Publish with debug symbols
RUN dotnet publish "MyApp.csproj" \
    -c Release \
    -o /app/publish \
    /p:DebugType=portable
```

**⚠️ Warning:** Only enable debugging in production for troubleshooting, then remove it.

**Enable diagnostic ports:**
```dockerfile
ENV DOTNET_DiagnosticPorts=/diag/port.sock
VOLUME /diag
```

### Docker Compose Debugging Example

**docker-compose.yml:**
```yaml
version: '3.8'

services:
  api:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "5000:8080"
    environment:
      - ASPNETCORE_ENVIRONMENT=Development
      - ConnectionStrings__DefaultConnection=Server=db;Database=MyDb;User Id=sa;Password=YourPassword;
    volumes:
      # Mount source for hot reload
      - ./src:/app/src:ro
    depends_on:
      - db

  db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    environment:
      - ACCEPT_EULA=Y
      - SA_PASSWORD=YourPassword
    ports:
      - "1433:1433"
```

**Debug workflow:**
```bash
# Start services
docker-compose up -d

# View all logs
docker-compose logs -f

# View specific service logs
docker-compose logs -f api

# Exec into container
docker-compose exec api /bin/sh

# Restart service
docker-compose restart api

# Stop and remove
docker-compose down
```

### Best Practices

**1. Use layered logging:**
```csharp
_logger.LogDebug("Detailed debug info");
_logger.LogInformation("Important info");
_logger.LogWarning("Something unexpected");
_logger.LogError(ex, "Error occurred");
```

**2. Include correlation IDs:**
```csharp
using var scope = _logger.BeginScope(new Dictionary<string, object>
{
    ["CorrelationId"] = correlationId
});
```

**3. Structure logs for containers:**
```csharp
builder.Logging.AddJsonConsole(options =>
{
    options.IncludeScopes = true;
    options.TimestampFormat = "yyyy-MM-dd HH:mm:ss.fff";
    options.JsonWriterOptions = new JsonWriterOptions
    {
        Indented = false
    };
});
```

**4. Don't log sensitive data:**
```csharp
// ❌ Bad
_logger.LogInformation($"Password: {password}");

// ✅ Good
_logger.LogInformation("User authenticated successfully");
```

**5. Use health checks for debugging:**
```csharp
app.MapGet("/debug/status", () => new
{
    Environment = app.Environment.EnvironmentName,
    MachineName = Environment.MachineName,
    ProcessId = Environment.ProcessId,
    Uptime = DateTime.UtcNow - Process.GetCurrentProcess().StartTime.ToUniversalTime()
});
```
