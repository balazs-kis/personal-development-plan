---

## Introduction

In Kubernetes, Pods are ephemeral—they can be created and destroyed at any time. Services provide a stable network endpoint to access a group of pods, abstracting away the constantly changing pod IPs. Services use label selectors to determine which pods receive traffic and provide load balancing across them.

## Key Concepts Summary

### Why Services?

```
Problem without Services:
Pod 1 (10.244.1.5) ←┐
Pod 2 (10.244.2.8) ←┼─ Clients need to track all pod IPs
Pod 3 (10.244.3.12)←┘   IPs change when pods restart!

Solution with Services:
Service (10.96.10.20) → Load balances to all pods
   ↓
Pods can restart, IPs can change
Service endpoint stays stable
```

**Services provide:**
- Stable IP address and DNS name
- Load balancing across pods
- Service discovery
- Abstraction over pod lifecycle

### ClusterIP (Default)

**Internal-only access:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: backend
spec:
  type: ClusterIP  # Default, can be omitted
  selector:
    app: backend
  ports:
  - port: 80        # Service port
    targetPort: 8080  # Pod port
```

**Access:**
```bash
# From within cluster
curl http://backend
curl http://backend.default.svc.cluster.local
```

**Use cases:**
- Internal microservices
- Databases
- Internal APIs

### NodePort

**External access via node IP:port:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: NodePort
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 8080
    nodePort: 30080  # 30000-32767, optional
```

**Access:**
```bash
# From outside cluster
curl http://<any-node-ip>:30080
```

**How it works:**
```
External Client
    ↓
NodeIP:30080
    ↓
Service (10.96.10.20:80)
    ↓
Pods (targetPort 8080)
```

**Use cases:**
- Development/testing
- On-premises without load balancer
- Direct node access needed

### LoadBalancer

**Cloud provider load balancer:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: LoadBalancer
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 8080
```

**Result:**
```bash
kubectl get svc web

# NAME   TYPE           EXTERNAL-IP      PORT(S)
# web    LoadBalancer   52.14.123.45     80:31234/TCP
```

**How it works:**
```
External Client
    ↓
Cloud Load Balancer (52.14.123.45:80)
    ↓
NodePort (automatically created)
    ↓
Service (ClusterIP)
    ↓
Pods
```

**Cloud provider annotations:**
```yaml
# AWS
metadata:
  annotations:
    service.beta.kubernetes.io/aws-load-balancer-type: "nlb"
    service.beta.kubernetes.io/aws-load-balancer-scheme: "internet-facing"

# Azure
metadata:
  annotations:
    service.beta.kubernetes.io/azure-load-balancer-internal: "false"

# GCP
metadata:
  annotations:
    cloud.google.com/load-balancer-type: "External"
```

**Use cases:**
- Production web applications
- Public-facing APIs
- Cloud-native deployments

### ExternalName

**CNAME to external service:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: external-db
spec:
  type: ExternalName
  externalName: db.example.com
```

**Access:**
```bash
# Inside cluster
curl http://external-db
# Resolves to db.example.com
```

**Use cases:**
- Migrate external services to cluster
- Access cloud services by name
- Abstraction over external endpoints

### Service Selectors

**Label-based routing:**
```yaml
# Service
spec:
  selector:
    app: web
    tier: frontend
  ports:
  - port: 80

---
# Pods with matching labels
apiVersion: v1
kind: Pod
metadata:
  labels:
    app: web
    tier: frontend
spec:
  # ...
```

**Without selector (manual endpoints):**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: external-service
spec:
  ports:
  - port: 80

---
apiVersion: v1
kind: Endpoints
metadata:
  name: external-service
subsets:
- addresses:
  - ip: 192.168.1.10
  - ip: 192.168.1.11
  ports:
  - port: 80
```

### Multi-Port Services

```yaml
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  selector:
    app: web
  ports:
  - name: http
    port: 80
    targetPort: 8080
  - name: https
    port: 443
    targetPort: 8443
  - name: metrics
    port: 9090
    targetPort: 9090
```

### Session Affinity

**Sticky sessions:**
```yaml
spec:
  sessionAffinity: ClientIP
  sessionAffinityConfig:
    clientIP:
      timeoutSeconds: 10800  # 3 hours
```

**Default (None):**
- Round-robin load balancing
- New request → random pod

**ClientIP:**
- Same client → same pod
- Based on source IP
- Useful for stateful apps

### Service Discovery

**DNS-based:**
```bash
# Same namespace
curl http://backend

# Different namespace
curl http://backend.production

# Fully qualified
curl http://backend.production.svc.cluster.local
```

**Environment variables:**
```bash
# Kubernetes creates env vars for services
echo $BACKEND_SERVICE_HOST
echo $BACKEND_SERVICE_PORT
```

### Endpoints

**View service endpoints:**
```bash
kubectl get endpoints backend

# NAME      ENDPOINTS
# backend   10.244.1.5:8080,10.244.2.8:8080,10.244.3.12:8080
```

**EndpointSlices (Kubernetes 1.21+):**
```bash
kubectl get endpointslices -l kubernetes.io/service-name=backend
```

More scalable for large services (1000+ endpoints).

### Headless Services

**No cluster IP, direct pod IPs:**
```yaml
apiVersion: v1
kind: Service
metadata:
  name: database
spec:
  clusterIP: None  # Headless!
  selector:
    app: database
  ports:
  - port: 3306
```

**DNS returns pod IPs:**
```bash
nslookup database.default.svc.cluster.local

# Returns:
# database-0.database.default.svc.cluster.local  10.244.1.5
# database-1.database.default.svc.cluster.local  10.244.2.8
# database-2.database.default.svc.cluster.local  10.244.3.12
```

**Use cases:**
- StatefulSets
- Direct pod addressing
- Custom load balancing

### Complete Example

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:alpine
        ports:
        - containerPort: 80

---
apiVersion: v1
kind: Service
metadata:
  name: web
  labels:
    app: web
spec:
  type: LoadBalancer
  selector:
    app: web
  ports:
  - name: http
    port: 80
    targetPort: 80
  sessionAffinity: ClientIP
```

### Troubleshooting Services

**Service not working:**
```bash
# 1. Check service exists
kubectl get svc web

# 2. Check endpoints
kubectl get endpoints web
# Should show pod IPs

# 3. Check pod labels match selector
kubectl get pods --show-labels
kubectl describe svc web

# 4. Test from inside cluster
kubectl run test --rm -it --image=busybox -- sh
wget -O- http://web

# 5. Check pod port
kubectl get pods -o wide
kubectl describe pod <pod-name>
```

**No endpoints:**
```bash
# Check selector
kubectl describe svc web | grep Selector

# Check pod labels
kubectl get pods --show-labels

# Must match!
```

**LoadBalancer pending:**
```bash
kubectl describe svc web

# Check:
# - Cloud provider support
# - Service controller running
# - Cloud credentials configured
```

### Best Practices

**1. Use meaningful names:**
```yaml
metadata:
  name: api-service  # Good
  # Not: svc1
```

**2. Add labels for organization:**
```yaml
metadata:
  labels:
    app: web
    tier: frontend
    environment: production
```

**3. Use named ports:**
```yaml
ports:
- name: http
  port: 80
- name: https
  port: 443
```

**4. Set appropriate type:**
- ClusterIP for internal
- LoadBalancer for external
- Don't expose everything!

**5. Use health checks:**
```yaml
# In pod spec
readinessProbe:
  httpGet:
    path: /health
    port: 8080
```

Only ready pods receive traffic.

## Practice Exercise

After completing the materials (20 minutes max):

1. **Create deployment and ClusterIP service:**
```yaml
# web-app.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:alpine
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  selector:
    app: web
  ports:
  - port: 80
```

```bash
kubectl apply -f web-app.yaml
kubectl get svc web
kubectl get endpoints web
```

2. **Test from inside cluster:**
```bash
kubectl run test --rm -it --image=busybox -- sh
wget -O- http://web
```

3. **Change to NodePort:**
```bash
kubectl patch svc web -p '{"spec":{"type":"NodePort"}}'
kubectl get svc web
# Access from outside: http://<node-ip>:<node-port>
```

4. **Check service routing:**
```bash
kubectl scale deployment web --replicas=3
kubectl get endpoints web
# Should show 3 pod IPs
```
