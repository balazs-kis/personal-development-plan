## Introduction

While Services expose applications at Layer 4 (TCP/UDP), Ingress operates at Layer 7 (HTTP/HTTPS), providing advanced routing capabilities. Ingress controllers act as reverse proxies, consolidating multiple services behind a single entry point with path-based routing, host-based routing, TLS termination, and more.

## Key Concepts Summary

### Ingress vs Services

```
Without Ingress (multiple LoadBalancers):
LoadBalancer 1 → Service A
LoadBalancer 2 → Service B  $$$ Expensive!
LoadBalancer 3 → Service C

With Ingress (single entry point):
LoadBalancer → Ingress Controller
                  ├─→ Service A (path /api)
                  ├─→ Service B (path /web)
                  └─→ Service C (host app.example.com)
```

### Ingress Components

**Ingress Resource** (rules):
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
spec:
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web
            port:
              number: 80
```

**Ingress Controller** (implementation):
- NGINX Ingress Controller
- Traefik
- HAProxy
- AWS Load Balancer Controller
- Google Cloud Load Balancer

### Installing NGINX Ingress Controller

**Using Helm:**
```bash
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo update

helm install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx \
  --create-namespace \
  --set controller.service.type=LoadBalancer
```

**Using kubectl:**
```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.8.1/deploy/static/provider/cloud/deploy.yaml
```

**Check installation:**
```bash
kubectl get pods -n ingress-nginx
kubectl get svc -n ingress-nginx
```

### Path-Based Routing

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: path-routing
spec:
  ingressClassName: nginx
  rules:
  - http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api-service
            port:
              number: 8080
      - path: /web
        pathType: Prefix
        backend:
          service:
            name: web-service
            port:
              number: 80
      - path: /admin
        pathType: Prefix
        backend:
          service:
            name: admin-service
            port:
              number: 3000
```

**PathType options:**
- `Prefix`: Matches /path and /path/*
- `Exact`: Only /path (no trailing parts)
- `ImplementationSpecific`: Controller-specific

### TLS Termination

**Create TLS secret:**
```bash
kubectl create secret tls my-tls-secret \
  --cert=path/to/cert.crt \
  --key=path/to/key.key
```

**Or with Let's Encrypt (cert-manager):**
```bash
# Install cert-manager first
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.13.0/cert-manager.yaml
```

**Ingress with TLS:**
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: tls-ingress
  annotations:
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - app.example.com
    secretName: app-tls-secret
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web
            port:
              number: 80
```

### Ingress Annotations

**NGINX-specific:**
```yaml
metadata:
  annotations:
    # Rewrite paths
    nginx.ingress.kubernetes.io/rewrite-target: /$2
    
    # SSL redirect
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    
    # Rate limiting
    nginx.ingress.kubernetes.io/limit-rps: "10"
    
    # CORS
    nginx.ingress.kubernetes.io/enable-cors: "true"
    
    # Timeouts
    nginx.ingress.kubernetes.io/proxy-connect-timeout: "600"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "600"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "600"
    
    # Custom headers
    nginx.ingress.kubernetes.io/configuration-snippet: |
      more_set_headers "X-Frame-Options: DENY";
```

### URL Rewriting

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: rewrite-example
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /$2
spec:
  rules:
  - http:
      paths:
      - path: /app(/|$)(.*)
        pathType: Prefix
        backend:
          service:
            name: app-service
            port:
              number: 80
```

**Result:**
```
/app/users    → /users
/app/products → /products
/app          → /
```

### Default Backend

```yaml
apiVersion: v1
kind: Service
metadata:
  name: default-backend
spec:
  selector:
    app: default-backend
  ports:
  - port: 80
    targetPort: 8080

---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: main-ingress
spec:
  defaultBackend:
    service:
      name: default-backend
      port:
        number: 80
  rules:
  # ... other rules
```

Catches unmatched requests (404 handler).

### Complete Production Example

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: production-app
  annotations:
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/rate-limit: "100"
    nginx.ingress.kubernetes.io/proxy-body-size: "10m"
    nginx.ingress.kubernetes.io/enable-cors: "true"
    nginx.ingress.kubernetes.io/cors-allow-origin: "https://app.example.com"
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - app.example.com
    - api.example.com
    secretName: app-tls
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: frontend
            port:
              number: 80
  - host: api.example.com
    http:
      paths:
      - path: /v1
        pathType: Prefix
        backend:
          service:
            name: api-v1
            port:
              number: 8080
      - path: /v2
        pathType: Prefix
        backend:
          service:
            name: api-v2
            port:
              number: 8080
```

### Troubleshooting Ingress

**Check controller pods:**
```bash
kubectl get pods -n ingress-nginx
kubectl logs -n ingress-nginx <controller-pod>
```

**Check Ingress resource:**
```bash
kubectl get ingress
kubectl describe ingress <name>
```

**Check service backends:**
```bash
kubectl get svc
kubectl get endpoints <service-name>
```

**Test DNS:**
```bash
nslookup app.example.com
dig app.example.com
```

**Check controller config:**
```bash
kubectl exec -n ingress-nginx <controller-pod> -- cat /etc/nginx/nginx.conf
```

**Common issues:**
- Ingress has no address → Controller not running
- 404 errors → Path/host mismatch
- 502/503 errors → Backend service down
- TLS not working → Secret missing/wrong format

### Best Practices

**1. Use TLS everywhere:**
```yaml
tls:
- hosts:
  - app.example.com
  secretName: app-tls
```

**2. Implement rate limiting:**
```yaml
annotations:
  nginx.ingress.kubernetes.io/limit-rps: "100"
```

**3. Set appropriate timeouts:**
```yaml
annotations:
  nginx.ingress.kubernetes.io/proxy-read-timeout: "600"
```

**4. Use meaningful names:**
```yaml
metadata:
  name: production-api-ingress
```

**5. Organize by namespace:**
```bash
# Separate ingress per namespace
kubectl apply -f ingress.yaml -n production
```
