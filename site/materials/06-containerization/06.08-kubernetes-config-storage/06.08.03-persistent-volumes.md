## Introduction

Pods are ephemeral—when they're deleted, their data is lost. PersistentVolumes provide durable storage that exists independently of pod lifecycle. The PersistentVolume (PV) represents actual storage, while PersistentVolumeClaim (PVC) is a user's request for that storage. This abstraction separates storage provisioning from consumption, enabling portable applications across different environments.

## Key Concepts Summary

### Storage Architecture

```
Physical Storage (Cloud disk, NFS, etc.)
    ↓
PersistentVolume (PV)
    ↓ (binding)
PersistentVolumeClaim (PVC)
    ↓
Pod
```

**Separation of concerns:**
- **Admin:** Provisions PVs
- **User:** Creates PVCs
- **Pod:** Consumes PVCs

### Access Modes

**ReadWriteOnce (RWO):**
- Mounted read-write by single node
- Most common for block storage
- Example: AWS EBS, Azure Disk

**ReadOnlyMany (ROX):**
- Mounted read-only by many nodes
- Example: Static content

**ReadWriteMany (RWX):**
- Mounted read-write by many nodes
- Requires network storage
- Example: NFS, Azure Files, AWS EFS

**ReadWriteOncePod (RWOP):**
- Single pod on single node (Kubernetes 1.22+)
- Stronger isolation than RWO

### Reclaim Policies

**Retain:**
```yaml
persistentVolumeReclaimPolicy: Retain
```
- Data preserved after PVC deletion
- Manual cleanup required
- Use for production data

**Delete:**
```yaml
persistentVolumeReclaimPolicy: Delete
```
- Volume deleted when PVC deleted
- Default for dynamic provisioning
- Use for temporary data

**Recycle (Deprecated):**
- Basic scrub (`rm -rf /volume/*`)
- Don't use

### Creating PersistentVolume

**Local hostPath (dev/testing only):**
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-local
spec:
  capacity:
    storage: 10Gi
  accessModes:
  - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  storageClassName: manual
  hostPath:
    path: /mnt/data
```

**NFS:**
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-nfs
spec:
  capacity:
    storage: 100Gi
  accessModes:
  - ReadWriteMany
  persistentVolumeReclaimPolicy: Retain
  storageClassName: nfs
  nfs:
    server: nfs-server.example.com
    path: /exported/path
```

**AWS EBS:**
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-aws-ebs
spec:
  capacity:
    storage: 50Gi
  accessModes:
  - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  storageClassName: aws-ebs
  awsElasticBlockStore:
    volumeID: vol-0123456789abcdef0
    fsType: ext4
```

**Azure Disk:**
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-azure-disk
spec:
  capacity:
    storage: 50Gi
  accessModes:
  - ReadWriteOnce
  persistentVolumeReclaimPolicy: Delete
  storageClassName: azure-disk
  azureDisk:
    diskName: myDisk
    diskURI: /subscriptions/.../resourceGroups/.../providers/Microsoft.Compute/disks/myDisk
```

### Creating PersistentVolumeClaim

**Basic PVC:**
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  storageClassName: manual
```

**Matching:** PVC binds to PV with:
- Same storageClassName
- Sufficient capacity
- Compatible accessModes

**PVC with selector:**
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  storageClassName: ssd
  selector:
    matchLabels:
      environment: production
      tier: high-performance
```

### Using PVC in Pod

**Single container:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod-with-pvc
spec:
  containers:
  - name: app
    image: nginx:alpine
    volumeMounts:
    - name: data
      mountPath: /usr/share/nginx/html
  volumes:
  - name: data
    persistentVolumeClaim:
      claimName: my-pvc
```

**Multiple containers sharing volume:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: shared-volume
spec:
  containers:
  - name: writer
    image: busybox
    command: ["sh", "-c", "while true; do date >> /data/log.txt; sleep 5; done"]
    volumeMounts:
    - name: shared-data
      mountPath: /data
  - name: reader
    image: busybox
    command: ["sh", "-c", "tail -f /data/log.txt"]
    volumeMounts:
    - name: shared-data
      mountPath: /data
  volumes:
  - name: shared-data
    persistentVolumeClaim:
      claimName: my-pvc
```

### Using PVC in Deployment

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: web-pvc
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi

---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 1  # Only 1 for RWO volumes!
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:alpine
        ports:
        - containerPort: 80
        volumeMounts:
        - name: web-storage
          mountPath: /usr/share/nginx/html
      volumes:
      - name: web-storage
        persistentVolumeClaim:
          claimName: web-pvc
```

**⚠️ Important:** With ReadWriteOnce, only 1 replica can use the volume!

### Volume Lifecycle

**1. Provisioning:**
```
Static: Admin creates PV manually
Dynamic: PV created automatically from StorageClass
```

**2. Binding:**
```
PVC created → Matches PV → Bound
Status: Bound
```

**3. Using:**
```
Pod references PVC → Volume mounted
```

**4. Releasing:**
```
PVC deleted → PV status: Released
```

**5. Reclaiming:**
```
Retain: Manual cleanup needed
Delete: PV automatically deleted
```

**Check status:**
```bash
kubectl get pv
# NAME      CAPACITY   STATUS      CLAIM
# pv-local  10Gi       Bound       default/my-pvc

kubectl get pvc
# NAME     STATUS   VOLUME    CAPACITY
# my-pvc   Bound    pv-local  10Gi
```

### Volume Expansion

**Enable in StorageClass:**
```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: expandable
provisioner: kubernetes.io/aws-ebs
allowVolumeExpansion: true
```

**Expand PVC:**
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 20Gi  # Increased from 10Gi
```

**Apply:**
```bash
kubectl apply -f pvc.yaml
kubectl get pvc my-pvc
# STATUS may show FileSystemResizePending

# May need to restart pod
kubectl delete pod <pod-name>
```

### Complete Database Example

```yaml
# pv.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: postgres-pv
  labels:
    type: local
spec:
  capacity:
    storage: 20Gi
  accessModes:
  - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  storageClassName: manual
  hostPath:
    path: /mnt/postgres-data

---
# pvc.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-pvc
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 20Gi
  storageClassName: manual

---
# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: postgres
spec:
  replicas: 1
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres
    spec:
      containers:
      - name: postgres
        image: postgres:15-alpine
        ports:
        - containerPort: 5432
        env:
        - name: POSTGRES_PASSWORD
          valueFrom:
            secretKeyRef:
              name: postgres-secret
              key: password
        - name: PGDATA
          value: /var/lib/postgresql/data/pgdata
        volumeMounts:
        - name: postgres-storage
          mountPath: /var/lib/postgresql/data
      volumes:
      - name: postgres-storage
        persistentVolumeClaim:
          claimName: postgres-pvc

---
# service.yaml
apiVersion: v1
kind: Service
metadata:
  name: postgres
spec:
  selector:
    app: postgres
  ports:
  - port: 5432
    targetPort: 5432
```

### Volume Modes

**Filesystem (default):**
```yaml
spec:
  volumeMode: Filesystem
```
Volume mounted as directory with filesystem.

**Block:**
```yaml
spec:
  volumeMode: Block
```
Raw block device (no filesystem).

**Use block for:**
- Databases with custom storage layers
- Performance-critical apps

### Troubleshooting

**PVC stuck in Pending:**
```bash
kubectl describe pvc my-pvc

# Common issues:
# 1. No matching PV
kubectl get pv

# 2. StorageClass doesn't exist
kubectl get storageclass

# 3. Insufficient capacity
# 4. Access mode mismatch
```

**Pod stuck in ContainerCreating:**
```bash
kubectl describe pod <pod-name>

# Common issues:
# - PVC doesn't exist
# - PVC not bound
# - Volume already mounted elsewhere (RWO)
```

**Data lost after pod restart:**
```bash
# Check volume is actually persistent
kubectl get pvc
kubectl get pv

# Check volume mount path
kubectl describe pod <pod-name>
```

**Volume not expanding:**
```bash
# Check allowVolumeExpansion
kubectl get storageclass <name> -o yaml

# Check PVC conditions
kubectl describe pvc my-pvc

# May need pod restart
kubectl delete pod <pod-name>
```

### Volume Snapshots

**Create VolumeSnapshotClass:**
```yaml
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshotClass
metadata:
  name: aws-ebs-snapshot
driver: ebs.csi.aws.com
deletionPolicy: Delete
```

**Create snapshot:**
```yaml
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshot
metadata:
  name: postgres-snapshot
spec:
  volumeSnapshotClassName: aws-ebs-snapshot
  source:
    persistentVolumeClaimName: postgres-pvc
```

**Restore from snapshot:**
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-restored
spec:
  accessModes:
  - ReadWriteOnce
  storageClassName: fast
  dataSource:
    name: postgres-snapshot
    kind: VolumeSnapshot
    apiGroup: snapshot.storage.k8s.io
  resources:
    requests:
      storage: 20Gi
```

**Check snapshot:**
```bash
kubectl get volumesnapshot
kubectl describe volumesnapshot postgres-snapshot
```

### Volume Cloning

**Clone existing PVC:**
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-clone
spec:
  accessModes:
  - ReadWriteOnce
  storageClassName: fast
  dataSource:
    name: postgres-pvc
    kind: PersistentVolumeClaim
  resources:
    requests:
      storage: 20Gi
```

**Use cases:**
- Testing with production data copy
- Blue-green deployments
- Development environments

### Local Persistent Volumes

**Create local PVs:**
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: local-pv-1
spec:
  capacity:
    storage: 100Gi
  accessModes:
  - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  storageClassName: local-storage
  local:
    path: /mnt/disks/ssd1
  nodeAffinity:
    required:
      nodeSelectorTerms:
      - matchExpressions:
        - key: kubernetes.io/hostname
          operator: In
          values:
          - node-1
```

**StorageClass for local:**
```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-storage
provisioner: kubernetes.io/no-provisioner
volumeBindingMode: WaitForFirstConsumer
```

**Benefits:**
- High performance (local SSD)
- Lower cost
- No network overhead

**Limitations:**
- Node-specific (not portable)
- Manual provisioning
- No HA (data lost if node fails)

### ReadWriteMany (RWX) Storage

**NFS example:**
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: nfs-pv
spec:
  capacity:
    storage: 100Gi
  accessModes:
  - ReadWriteMany
  nfs:
    server: nfs-server.example.com
    path: /exports/data
```

**Use in deployment with multiple replicas:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3  # Multiple pods sharing storage
  template:
    spec:
      containers:
      - name: nginx
        image: nginx
        volumeMounts:
        - name: shared-data
          mountPath: /usr/share/nginx/html
      volumes:
      - name: shared-data
        persistentVolumeClaim:
          claimName: nfs-pvc
```

**RWX options:**
- NFS
- Azure Files
- AWS EFS
- GlusterFS
- CephFS

### Best Practices

**1. Use StorageClasses (dynamic provisioning):**
```yaml
# Let Kubernetes create PVs
spec:
  storageClassName: fast-ssd
```

**2. Set appropriate reclaim policy:**
```yaml
# Production
persistentVolumeReclaimPolicy: Retain

# Dev/Test
persistentVolumeReclaimPolicy: Delete
```

**3. Request appropriate size:**
```yaml
resources:
  requests:
    storage: 10Gi  # Not too large
```

**4. Use correct access mode:**
```yaml
# Single node
accessModes:
- ReadWriteOnce

# Multiple nodes need ReadWriteMany
accessModes:
- ReadWriteMany
```

**5. Add labels for organization:**
```yaml
metadata:
  labels:
    app: database
    environment: production
    tier: high-performance
```

**6. Backup important data:**
```bash
kubectl exec <pod> -- pg_dump ... > backup.sql

# Or use snapshots
kubectl create volumesnapshot ...
```

**7. Monitor storage usage:**
```bash
kubectl exec <pod> -- df -h /data

# Set up alerts
kubectl top pv
```

**8. Use node affinity for local volumes:**
```yaml
nodeAffinity:
  required:
    nodeSelectorTerms:
    - matchExpressions:
      - key: kubernetes.io/hostname
        operator: In
        values:
        - specific-node
```

**9. Enable volume expansion:**
```yaml
allowVolumeExpansion: true
```

**10. Document volume requirements:**
```yaml
annotations:
  description: "PostgreSQL data volume"
  backup-policy: "daily"
  retention: "30 days"
```
