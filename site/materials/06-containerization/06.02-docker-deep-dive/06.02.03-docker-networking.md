## Key Concepts Summary

### Docker Network Architecture

```
┌─────────────────────────────────────────────┐
│            Host Machine                      │
│                                              │
│  ┌────────────────────────────────────────┐ │
│  │      Docker Network Drivers             │ │
│  │  ┌──────┐ ┌──────┐ ┌────────┐ ┌──────┐│ │
│  │  │Bridge│ │ Host │ │ Overlay│ │ None ││ │
│  │  └──────┘ └──────┘ └────────┘ └──────┘│ │
│  └────────────────────────────────────────┘ │
│         ▲           ▲         ▲              │
│         │           │         │              │
│  ┌──────┴───┐ ┌────┴───┐ ┌──┴─────┐        │
│  │Container│  │Container│ │Container│        │
│  │   App1  │  │  App2  │ │  App3   │        │
│  └─────────┘  └────────┘ └─────────┘        │
└─────────────────────────────────────────────┘
```

### Network Drivers Overview

| Driver | Use Case | Isolation | Performance |
|--------|----------|-----------|-------------|
| **bridge** | Single host, default | Container-to-container | Good |
| **host** | Remove network isolation | None (uses host's network) | Best |
| **overlay** | Multi-host (Swarm, Kubernetes) | Cross-host containers | Good |
| **macvlan** | Legacy apps needing MAC addresses | Physical network integration | Good |
| **none** | Disable networking | Complete | N/A |

### 1. Bridge Network (Default)

The default network driver. Each container gets an IP on a private network.

**Create a custom bridge network:**
```bash
docker network create my-network
```

**Run containers on the network:**
```bash
docker run -d --name web --network my-network nginx
docker run -d --name api --network my-network node:18
```

**Containers can communicate by name:**
```bash
# Inside 'web' container
curl http://api:3000
```

**Key Features:**
- DNS resolution by container name
- Isolation from other networks
- Port mapping to host

**Example Docker Network Setup:**
```bash
# Create network
docker network create --driver bridge app-network

# Run database
docker run -d \
  --name postgres \
  --network app-network \
  -e POSTGRES_PASSWORD=secret \
  postgres:15

# Run application (can access postgres by name)
docker run -d \
  --name myapp \
  --network app-network \
  -p 8080:8080 \
  -e DATABASE_URL=postgres://postgres:secret@postgres:5432/mydb \
  myapp:latest
```

### 2. Host Network

Container shares the host's network stack. No network isolation.

```bash
docker run --network host nginx
```

**Use cases:**
- Performance-critical applications
- When you need access to host network interfaces
- Testing/debugging

**Limitations:**
- No port mapping (uses host ports directly)
- Less isolation
- Not available on Docker Desktop (Mac/Windows)

**Example:**
```bash
# Container listens on host's port 80 directly
docker run --network host --name nginx nginx

# Access directly on host
curl http://localhost:80
```

### 3. Overlay Network

For container communication across multiple Docker hosts (Swarm, Kubernetes).

```bash
# Initialize Swarm
docker swarm init

# Create overlay network
docker network create --driver overlay my-overlay

# Deploy service
docker service create \
  --name web \
  --network my-overlay \
  --replicas 3 \
  nginx
```

**Features:**
- Multi-host networking
- Service discovery
- Load balancing
- Encrypted by default (can be disabled)

### 4. None Network

Disables networking completely.

```bash
docker run --network none alpine
```

**Use cases:**
- Maximum isolation
- Batch jobs that don't need network
- Security-sensitive workloads

### Network Commands

```bash
# List networks
docker network ls

# Inspect network
docker network inspect bridge

# Create network
docker network create my-network

# Connect container to network
docker network connect my-network my-container

# Disconnect container from network
docker network disconnect my-network my-container

# Remove network
docker network rm my-network

# Prune unused networks
docker network prune
```

### DNS Resolution

Containers on custom bridge networks get automatic DNS resolution:

```bash
# Create network
docker network create mynet

# Run containers
docker run -d --name db --network mynet postgres:15
docker run -d --name app --network mynet myapp

# Inside 'app' container:
ping db           # ✅ Works! Resolves to db container IP
curl http://db:5432  # ✅ Works!
```

**Default bridge network:**
- No automatic DNS
- Must use `--link` (deprecated) or IP addresses

**Custom bridge networks:**
- Automatic DNS by container name
- Recommended for production

### Port Mapping

Expose container ports to the host:

```bash
# Publish port
docker run -p 8080:80 nginx
# Host:8080 → Container:80

# Publish to specific interface
docker run -p 127.0.0.1:8080:80 nginx

# Publish all exposed ports to random ports
docker run -P nginx

# Multiple ports
docker run -p 8080:80 -p 8443:443 nginx
```

**Port mapping syntax:**
```
-p <host-port>:<container-port>
-p <host-ip>:<host-port>:<container-port>
-p <host-port>:<container-port>/<protocol>
```

### Network Configuration Options

```bash
# Create network with custom subnet
docker network create \
  --driver bridge \
  --subnet 172.20.0.0/16 \
  --gateway 172.20.0.1 \
  my-network

# Assign static IP to container
docker run --network my-network \
  --ip 172.20.0.10 \
  nginx

# Set DNS servers
docker run --dns 8.8.8.8 --dns 8.8.4.4 nginx

# Add DNS search domains
docker run --dns-search example.com nginx

# Set hostname
docker run --hostname myapp nginx

# Add to /etc/hosts
docker run --add-host db:192.168.1.100 nginx
```

### Multi-Container Application Example

**Setup:**
```bash
# Create network
docker network create todo-network

# Run PostgreSQL
docker run -d \
  --name postgres \
  --network todo-network \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=tododb \
  postgres:15

# Run Redis
docker run -d \
  --name redis \
  --network todo-network \
  redis:7-alpine

# Run API
docker run -d \
  --name api \
  --network todo-network \
  -e DATABASE_URL=postgres://postgres:secret@postgres:5432/tododb \
  -e REDIS_URL=redis://redis:6379 \
  -p 3000:3000 \
  todo-api:latest

# Run Frontend
docker run -d \
  --name frontend \
  --network todo-network \
  -e API_URL=http://api:3000 \
  -p 8080:80 \
  todo-frontend:latest
```

### Network Inspection and Troubleshooting

```bash
# Inspect network
docker network inspect bridge

# See which containers are connected
docker network inspect my-network --format='{{range .Containers}}{{.Name}} {{end}}'

# Check container's network settings
docker inspect my-container --format='{{range $k, $v := .NetworkSettings.Networks}}{{$k}}{{end}}'

# Get container IP
docker inspect -f '{{range.NetworkSettings.Networks}}{{.IPAddress}}{{end}}' my-container

# Test connectivity
docker exec my-container ping other-container
docker exec my-container curl http://other-container:8080

# View network traffic
docker run --rm --net container:my-container nicolaka/netshoot tcpdump
```

### Common Networking Patterns

**1. Frontend → Backend → Database:**
```
Frontend (port 80) → Backend (internal) → Database (internal)
      ↓ bridge network ↓
```

**2. Microservices with Service Mesh:**
```
All services on same overlay network
DNS-based service discovery
```

**3. Development with Docker Compose:**
```yaml
version: '3.8'
services:
  db:
    image: postgres:15
    networks:
      - backend
  
  api:
    build: ./api
    networks:
      - backend
      - frontend
    depends_on:
      - db
  
  web:
    build: ./web
    ports:
      - "8080:80"
    networks:
      - frontend
    depends_on:
      - api

networks:
  frontend:
  backend:
```

### Security Considerations

**1. Use Custom Networks:**
```bash
# ✅ Good: isolated network
docker network create --internal secure-network
docker run --network secure-network myapp
```

**2. Internal Networks (no external access):**
```bash
docker network create --internal db-network
docker run --network db-network postgres
```

**3. Limit Port Exposure:**
```bash
# ❌ Bad: exposed to all interfaces
docker run -p 5432:5432 postgres

# ✅ Good: only localhost
docker run -p 127.0.0.1:5432:5432 postgres
```

**4. Network Policies:**
```bash
# Use firewall rules
iptables -A DOCKER-USER -i ext_if ! -s 192.168.1.0/24 -j DROP
```

## Key Takeaways

✅ **Bridge networks enable container communication**
- Custom bridge networks provide DNS resolution
- Containers can communicate by name
- Isolated from other networks

✅ **Choose the right network driver for your use case**
- Bridge: Single host, default choice
- Host: Performance-critical, no isolation
- Overlay: Multi-host orchestration
- Macvlan: Physical network integration

✅ **Port mapping exposes services**
- `-p 8080:80` maps container port 80 to host 8080
- `-P` publishes all exposed ports
- `127.0.0.1:8080:80` binds to localhost only

✅ **Network security and isolation**
- Default bridge: no DNS, less secure
- Custom bridge: DNS, better isolation
- Network policies control traffic

✅ **Troubleshooting with network commands**
- `docker network ls` - List networks
- `docker network inspect` - Detailed info
- `docker exec` - Test connectivity
- `tcpdump` - Packet analysis
