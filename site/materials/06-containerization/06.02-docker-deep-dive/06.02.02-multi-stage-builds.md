# Lesson 2: Multi-Stage Builds

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand the purpose and benefits of multi-stage builds
- Create Dockerfiles with multiple stages
- Copy artifacts between build stages
- Optimize images by separating build and runtime dependencies
- Dramatically reduce final image sizes

---

## Introduction

Multi-stage builds are one of Docker's most powerful features. They allow you to use one set of dependencies to build your application and a completely different, minimal set to run it. This results in smaller, more secure production images without the complexity of maintaining multiple Dockerfiles.

## Key Concepts Summary

### The Problem: Bloated Images

**Single-Stage Build (Bad):**
```dockerfile
FROM node:18
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build
EXPOSE 3000
CMD ["npm", "start"]
```

**Result:**
- Final image: ~1GB
- Includes: npm, node_modules (dev dependencies), build tools, source code
- Everything needed to BUILD, not just RUN

### The Solution: Multi-Stage Builds

Separate build dependencies from runtime dependencies:

```dockerfile
# Stage 1: Build
FROM node:18 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Stage 2: Runtime
FROM node:18-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/package*.json ./
RUN npm install --production
EXPOSE 3000
CMD ["node", "dist/server.js"]
```

**Result:**
- Final image: ~150MB
- Only production dependencies and built artifacts
- 85% size reduction!

### Multi-Stage Build Anatomy

```dockerfile
# Stage 1 (name it with AS)
FROM <base-image> AS <stage-name>
<build commands>

# Stage 2
FROM <different-base> AS <another-stage>
COPY --from=<stage-name> <source> <destination>
<runtime commands>

# Final stage (last FROM)
FROM <minimal-base>
COPY --from=<earlier-stage> <artifacts> <destination>
CMD [...]
```

### .NET Multi-Stage Build Example

```dockerfile
# Stage 1: Build
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Restore dependencies
COPY ["MyApp/MyApp.csproj", "MyApp/"]
RUN dotnet restore "MyApp/MyApp.csproj"

# Build
COPY . .
WORKDIR "/src/MyApp"
RUN dotnet build "MyApp.csproj" -c Release -o /app/build

# Stage 2: Publish
FROM build AS publish
RUN dotnet publish "MyApp.csproj" \
    -c Release \
    -o /app/publish \
    /p:UseAppHost=false

# Stage 3: Runtime
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS final
WORKDIR /app
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "MyApp.dll"]
```

**Image Size Comparison:**
- SDK image: ~700MB
- ASP.NET runtime image: ~200MB
- **Savings: 70%**

### React/Frontend Build Example

```dockerfile
# Stage 1: Build
FROM node:18 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Production with Nginx
FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
COPY nginx.conf /etc/nginx/nginx.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**Benefits:**
- No Node.js in final image
- Just static files + nginx
- Image size: ~25MB (vs ~1GB with Node)

### Go Application Example

```dockerfile
# Stage 1: Build
FROM golang:1.21 AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo -o main .

# Stage 2: Minimal runtime
FROM alpine:latest
RUN apk --no-cache add ca-certificates
WORKDIR /root/
COPY --from=builder /app/main .
CMD ["./main"]
```

**Result:**
- golang:1.21 image: ~800MB
- alpine + binary: ~10MB
- **Savings: 98%!**

### Using Distroless Images

Google's distroless images contain only your application and runtime dependencies:

```dockerfile
# Build stage
FROM golang:1.21 AS builder
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 go build -o app .

# Runtime stage with distroless
FROM gcr.io/distroless/static-debian11
COPY --from=builder /app/app /
CMD ["/app"]
```

**Benefits:**
- No shell, package manager, or utilities
- Minimal attack surface
- Still runs dynamically linked binaries

### Advanced: Named Stages and Multiple Copies

```dockerfile
# Stage 1: Dependencies
FROM node:18 AS dependencies
WORKDIR /app
COPY package*.json ./
RUN npm ci --production
RUN cp -R node_modules /prod_node_modules
RUN npm ci

# Stage 2: Build
FROM node:18 AS builder
WORKDIR /app
COPY --from=dependencies /app/node_modules ./node_modules
COPY . .
RUN npm run build
RUN npm run test

# Stage 3: Test (optional, can be run separately)
FROM node:18 AS test
WORKDIR /app
COPY --from=dependencies /app/node_modules ./node_modules
COPY . .
RUN npm test

# Stage 4: Production
FROM node:18-alpine
WORKDIR /app
COPY --from=dependencies /app/prod_node_modules ./node_modules
COPY --from=builder /app/dist ./dist
COPY package.json ./
USER node
CMD ["node", "dist/server.js"]
```

### Targeting Specific Stages

Build and run different stages for different purposes:

```bash
# Build only test stage (CI/CD)
docker build --target test -t myapp:test .
docker run myapp:test  # Runs tests

# Build only builder stage (debugging)
docker build --target builder -t myapp:builder .
docker run --rm -it myapp:builder sh

# Build full production image
docker build -t myapp:prod .

# Build with specific stage output
docker build --target dependencies -t myapp:deps .
```

### Python Application with Virtual Environment

```dockerfile
# Stage 1: Build with dependencies
FROM python:3.11 AS builder
WORKDIR /app

# Create virtual environment
RUN python -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

# Install dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application
COPY . .

# Stage 2: Runtime
FROM python:3.11-slim
WORKDIR /app

# Copy virtual environment from builder
COPY --from=builder /opt/venv /opt/venv
COPY --from=builder /app .

# Activate virtual environment
ENV PATH="/opt/venv/bin:$PATH"

# Non-root user
RUN useradd --create-home appuser && \
    chown -R appuser:appuser /app
USER appuser

CMD ["python", "app.py"]
```

**Result:**
- Build image: ~1GB (includes build tools)
- Runtime image: ~150MB (slim Python + app)

### Java/Maven Multi-Stage Build

```dockerfile
# Stage 1: Build
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app

# Copy pom.xml and download dependencies (cached)
COPY pom.xml .
RUN mvn dependency:go-offline

# Copy source and build
COPY src ./src
RUN mvn clean package -DskipTests

# Stage 2: Runtime
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app

# Copy JAR from build stage
COPY --from=build /app/target/*.jar app.jar

# Non-root user
RUN addgroup -g 1000 appgroup && \
    adduser -D -u 1000 -G appgroup appuser && \
    chown -R appuser:appgroup /app
USER appuser

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

**Savings:**
- Maven + JDK: ~700MB
- JRE only: ~170MB
- **80% reduction**

### Rust Application Example

```dockerfile
# Stage 1: Build
FROM rust:1.75 AS builder
WORKDIR /app

# Copy manifests
COPY Cargo.toml Cargo.lock ./

# Create dummy source to cache dependencies
RUN mkdir src && \
    echo "fn main() {}" > src/main.rs && \
    cargo build --release && \
    rm -rf src

# Copy real source and build
COPY src ./src
RUN touch src/main.rs && \
    cargo build --release

# Stage 2: Runtime
FROM debian:bookworm-slim
WORKDIR /app

# Install runtime dependencies
RUN apt-get update && \
    apt-get install -y ca-certificates && \
    rm -rf /var/lib/apt/lists/*

# Copy binary from builder
COPY --from=builder /app/target/release/myapp .

# Non-root user
RUN useradd -m -u 1000 appuser && \
    chown -R appuser:appuser /app
USER appuser

CMD ["./myapp"]
```

**Result:**
- Rust build environment: ~2GB
- Final image: ~80MB

### Copying from External Images

You can copy from any image, not just previous stages:

```dockerfile
FROM alpine

# Copy from official nginx image
COPY --from=nginx:latest /etc/nginx/nginx.conf /nginx.conf

# Copy from your registry
COPY --from=myregistry.io/shared:latest /app/lib /usr/local/lib

# Copy from specific platform
COPY --from=--platform=linux/amd64 golang:1.21 /usr/local/go /usr/local/go
```

**Use Cases:**
- Reuse configuration from official images
- Share libraries across teams
- Copy binaries from trusted sources

### Multi-Platform Builds with Multi-Stage

```dockerfile
FROM --platform=$BUILDPLATFORM golang:1.21 AS builder
ARG TARGETPLATFORM
ARG BUILDPLATFORM
ARG TARGETOS
ARG TARGETARCH

WORKDIR /app
COPY . .

# Build for target platform
RUN GOOS=$TARGETOS GOARCH=$TARGETARCH go build -o app .

FROM alpine
COPY --from=builder /app/app /
CMD ["/app"]
```

```bash
# Build for multiple platforms
docker buildx build \
  --platform linux/amd64,linux/arm64,linux/arm/v7 \
  -t myapp:latest \
  --push .
```

### Build Arguments and Stage Selection

```dockerfile
ARG BASE_IMAGE=node:18
FROM ${BASE_IMAGE} AS base
WORKDIR /app

FROM base AS development
COPY package*.json ./
RUN npm install
COPY . .
CMD ["npm", "run", "dev"]

FROM base AS production
COPY package*.json ./
RUN npm ci --only=production
COPY . .
CMD ["node", "server.js"]
```

```bash
# Build development
docker build --target development -t myapp:dev .

# Build production
docker build --target production -t myapp:prod .

# Use different base
docker build --build-arg BASE_IMAGE=node:20 -t myapp:node20 .
```

### Best Practices for Multi-Stage Builds

**1. Name Your Stages Clearly**

```dockerfile
# Bad: Unnamed stages
FROM node:18
# ...

FROM node:18-alpine
# ...

# Good: Clear names
FROM node:18 AS dependencies
# ...

FROM node:18 AS builder
# ...

FROM node:18-alpine AS production
# ...
```

**2. Use Minimal Runtime Images**

```
Size Comparison:
├─ node:18           ~900MB
├─ node:18-alpine    ~170MB  ← Use this
├─ node:18-slim      ~240MB
└─ distroless/nodejs ~50MB   ← Or this
```

**3. Copy Only Required Artifacts**

```dockerfile
# Bad: Copying everything
COPY --from=builder /app .

# Good: Specific artifacts
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./
```

**4. Leverage Build Cache Effectively**

```dockerfile
# Copy dependency manifests first
COPY package*.json ./
RUN npm install  # Cached unless package.json changes

# Copy source last
COPY src ./src
RUN npm run build  # Only re-runs if source changes
```

**5. Use BuildKit Cache Mounts**

```dockerfile
# syntax=docker/dockerfile:1

FROM node:18 AS build
WORKDIR /app

# Cache npm dependencies
RUN --mount=type=cache,target=/root/.npm \
    npm install

COPY . .
RUN npm run build
```

**6. Separate Test and Production Stages**

```dockerfile
FROM builder AS test
RUN npm test
RUN npm run lint

FROM builder AS production
# No test dependencies
```

### Security Benefits

**Principle: Minimal Attack Surface**

```dockerfile
# Build stage includes:
# - Compilers
# - Build tools
# - Development dependencies
# - Source code
FROM golang:1.21 AS build
# ... large attack surface

# Runtime stage includes only:
# - Compiled binary
# - Runtime dependencies
FROM scratch
COPY --from=build /app /app
# ... minimal attack surface
```

**No Build Tools in Production:**

```
Build Stage Contains:
├─ gcc, make, git
├─ Development headers
├─ Package managers
└─ Source code

Production Stage Contains:
├─ Compiled binary
└─ Runtime libraries only

Result: 90%+ reduction in vulnerabilities
```

### Troubleshooting Multi-Stage Builds

**Issue: Large final image despite multi-stage**

```dockerfile
# Problem: Copying unnecessary files
COPY --from=build /app .  # Includes build artifacts!

# Solution: Be specific
COPY --from=build /app/dist ./dist
COPY --from=build /app/package.json ./
```

**Issue: Build cache not working**

```dockerfile
# Problem: Files change frequently
COPY . .
RUN npm install

# Solution: Copy manifests first
COPY package*.json ./
RUN npm install
COPY . .
```

**Issue: Slow build times**

```bash
# Enable BuildKit (parallel stages)
export DOCKER_BUILDKIT=1
docker build .

# Use cache mounts
# syntax=docker/dockerfile:1
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install -r requirements.txt
```

## Key Takeaways

✅ **Multi-stage builds dramatically reduce image size**
- Separate build and runtime dependencies
- 50-98% size reduction typical
- Include only what's needed to run

✅ **Name stages for clarity and reusability**
- `AS builder`, `AS test`, `AS production`
- Target specific stages: `--target test`
- Better documentation and maintenance

✅ **Use minimal base images for runtime**
- Alpine: ~5-10MB
- Distroless: ~10-20MB
- Scratch: 0MB (static binaries)

✅ **Security through minimization**
- No build tools in production
- Fewer packages = fewer vulnerabilities
- Smaller attack surface

✅ **Build cache optimization**
- Copy manifests before source
- Layer stages appropriately
- Use BuildKit cache mounts

✅ **Flexibility for different environments**
- Development stage with hot reload
- Test stage for CI/CD
- Production stage optimized
