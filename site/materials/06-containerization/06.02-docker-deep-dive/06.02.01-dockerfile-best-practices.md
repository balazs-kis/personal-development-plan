# Lesson 1: Dockerfile Best Practices

## Learning Objectives

By the end of this lesson, you will be able to:
- Write efficient and maintainable Dockerfiles
- Optimize image build times using layer caching strategies
- Reduce image size using proven optimization techniques
- Implement security best practices in Docker images
- Order Dockerfile instructions for maximum efficiency
- Apply Docker build optimization patterns
- Debug and troubleshoot Dockerfile issues

## Introduction

Writing a Dockerfile is easy, but writing a **good** Dockerfile requires understanding how Docker builds images, how caching works, and how to optimize for size, speed, and security. A well-crafted Dockerfile can mean the difference between 2-second and 2-minute builds, between 50MB and 500MB images, and between secure and vulnerable deployments.

This lesson covers industry best practices that will make your Docker images production-ready, efficient, and secure. We'll explore real-world patterns used by leading organizations and common pitfalls to avoid.

## Key Concepts Summary

### 1. Order Instructions from Least to Most Frequently Changing

**Why:** Docker caches each layer. If a layer changes, all subsequent layers are rebuilt.

**Bad Example:**
```dockerfile
FROM node:18
COPY . /app
RUN npm install
```
Every code change invalidates `npm install` cache!

**Good Example:**
```dockerfile
FROM node:18
WORKDIR /app
# Copy dependency files first
COPY package*.json ./
RUN npm install
# Copy source code last
COPY . .
```

### 2. Use Specific Base Image Tags

**Bad:**
```dockerfile
FROM node:latest
FROM python:latest
```
- `latest` changes over time
- Breaks reproducibility
- Can introduce breaking changes

**Good:**
```dockerfile
FROM node:18.19.0-alpine
FROM python:3.11-slim
```
- Specific, predictable versions
- Use Alpine or slim variants for smaller size

### 3. Minimize the Number of Layers

Each `RUN`, `COPY`, and `ADD` creates a new layer.

**Bad:**
```dockerfile
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y git
RUN apt-get clean
```

**Good:**
```dockerfile
RUN apt-get update && \
    apt-get install -y \
        curl \
        git \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*
```

### 4. Use .dockerignore

Just like `.gitignore`, exclude unnecessary files from the build context:

**.dockerignore:**
```
node_modules
npm-debug.log
.git
.gitignore
README.md
.vscode
.idea
*.swp
*.bak
test/
docs/
```

**Benefits:**
- Faster builds (smaller context)
- Smaller images
- Avoids copying sensitive files

### 5. Don't Run as Root

**Bad:**
```dockerfile
FROM node:18
WORKDIR /app
COPY . .
RUN npm install
CMD ["node", "app.js"]
```
Runs as root (uid 0) - security risk!

**Good:**
```dockerfile
FROM node:18
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .

# Create non-root user
RUN addgroup --system --gid 1001 nodejs && \
    adduser --system --uid 1001 appuser
USER appuser

CMD ["node", "app.js"]
```

### 6. Use COPY Instead of ADD

**`COPY`** is more transparent and preferred for local files.

**`ADD`** has extra features (tar extraction, URL support) but is less explicit.

**Prefer:**
```dockerfile
COPY package.json /app/
COPY src/ /app/src/
```

**Only use ADD when needed:**
```dockerfile
ADD https://example.com/file.tar.gz /tmp/
ADD archive.tar.gz /app/
```

### 7. Leverage Build Cache with --mount

Use BuildKit's advanced caching:

```dockerfile
# syntax=docker/dockerfile:1
FROM node:18

WORKDIR /app

# Cache npm dependencies
RUN --mount=type=cache,target=/root/.npm \
    npm install

COPY . .
```

### 8. Set Appropriate WORKDIR

**Bad:**
```dockerfile
RUN cd /app
COPY . /app
RUN cd /app && npm install
```

**Good:**
```dockerfile
WORKDIR /app
COPY . .
RUN npm install
```

### 9. Label Your Images

Add metadata for documentation and automation:

```dockerfile
LABEL maintainer="yourname@example.com"
LABEL version="1.0"
LABEL description="My application"
LABEL org.opencontainers.image.source="https://github.com/user/repo"
```

### 10. Use HEALTHCHECK

Define how to test if your container is working:

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD curl -f http://localhost:8080/health || exit 1
```

### Complete Example: .NET Application

```dockerfile
# Build stage
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Copy project file and restore dependencies
COPY ["MyApp/MyApp.csproj", "MyApp/"]
RUN dotnet restore "MyApp/MyApp.csproj"

# Copy everything else and build
COPY . .
WORKDIR "/src/MyApp"
RUN dotnet build "MyApp.csproj" -c Release -o /app/build

# Publish stage
FROM build AS publish
RUN dotnet publish "MyApp.csproj" -c Release -o /app/publish /p:UseAppHost=false

# Runtime stage
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS final
WORKDIR /app

# Create non-root user
RUN adduser --disabled-password --gecos '' appuser && \
    chown -R appuser /app
USER appuser

EXPOSE 8080

# Copy published app
COPY --from=publish /app/publish .

# Health check
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s \
  CMD curl -f http://localhost:8080/health || exit 1

ENTRYPOINT ["dotnet", "MyApp.dll"]
```

### Complete Example: Node.js Application

```dockerfile
FROM node:18.19.0-alpine

# Set working directory
WORKDIR /app

# Copy package files
COPY package*.json ./

# Install dependencies
RUN npm ci --only=production && \
    npm cache clean --force

# Copy application code
COPY . .

# Create non-root user
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001 && \
    chown -R nodejs:nodejs /app
USER nodejs

# Expose port
EXPOSE 3000

# Health check
HEALTHCHECK --interval=30s --timeout=3s \
  CMD node healthcheck.js

# Start application
CMD ["node", "server.js"]
```

### Advanced: Layer Optimization Techniques

**Understanding Layer Size:**

Each instruction adds to the image. Understanding what creates size helps optimize:

```dockerfile
# Bad: Creates multiple layers with temp files
FROM ubuntu:22.04
RUN apt-get update                          # ~50MB layer
RUN apt-get install -y python3              # ~100MB layer
RUN apt-get install -y python3-pip          # ~80MB layer
RUN wget https://example.com/large.tar.gz   # ~200MB layer
RUN tar -xzf large.tar.gz                   # ~300MB layer
RUN rm large.tar.gz                         # ~0MB (doesn't remove previous layer!)
# Total: ~730MB

# Good: Single layer, cleanup in same step
FROM ubuntu:22.04
RUN apt-get update && \
    apt-get install -y \
        python3 \
        python3-pip \
        wget && \
    wget https://example.com/large.tar.gz && \
    tar -xzf large.tar.gz && \
    rm large.tar.gz && \
    apt-get clean && \
    rm -rf /var/lib/apt/lists/*
# Total: ~280MB
```

**BuildKit Mount Caching:**

```dockerfile
# syntax=docker/dockerfile:1

FROM node:18 AS build
WORKDIR /app

# Mount npm cache for faster rebuilds
RUN --mount=type=cache,target=/root/.npm \
    --mount=type=bind,source=package.json,target=package.json \
    --mount=type=bind,source=package-lock.json,target=package-lock.json \
    npm ci

COPY . .
RUN npm run build
```

**Conditional Logic with ARG:**

```dockerfile
ARG BUILD_ENV=production

FROM node:18
WORKDIR /app
COPY package*.json ./

# Install different deps based on environment
RUN if [ "$BUILD_ENV" = "development" ] ; then \
        npm install ; \
    else \
        npm ci --only=production ; \
    fi

COPY . .
```

### Security Hardening Techniques

**1. Use Minimal Base Images:**

```dockerfile
# Size comparison
FROM ubuntu:22.04        # ~78MB
FROM debian:bookworm     # ~124MB
FROM alpine:3.18         # ~7MB ✅
FROM scratch             # ~0MB (for static binaries)

# Distroless (Google)
FROM gcr.io/distroless/static-debian11  # ~2MB ✅
```

**2. Scan for Vulnerabilities:**

```bash
# Using Docker Scout
docker scout cves myimage:latest

# Using Trivy
trivy image myimage:latest

# Using Snyk
snyk container test myimage:latest
```

**3. Multi-Stage with Distroless:**

```dockerfile
# Build
FROM golang:1.21 AS build
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 go build -o app

# Runtime - no shell, no package manager
FROM gcr.io/distroless/static-debian11
COPY --from=build /app/app /
USER nonroot:nonroot
CMD ["/app"]
```

**4. Drop Capabilities:**

```dockerfile
FROM alpine:3.18
RUN apk add --no-cache curl

# Drop all capabilities except NET_BIND_SERVICE
USER 1000:1000
# Set in docker run or kubernetes:
# --cap-drop=ALL --cap-add=NET_BIND_SERVICE
```

**5. Read-Only Root Filesystem:**

```dockerfile
FROM node:18-alpine
WORKDIR /app

# App code (read-only)
COPY --chown=node:node . .
RUN npm ci --only=production

# Writable directories
RUN mkdir -p /tmp/uploads /tmp/cache && \
    chown -R node:node /tmp/uploads /tmp/cache

USER node

# In docker run: --read-only --tmpfs /tmp
CMD ["node", "server.js"]
```

### Performance Optimization Patterns

**Parallel Dependency Installation:**

```dockerfile
FROM node:18
WORKDIR /app

# Copy all package.json files first
COPY frontend/package*.json ./frontend/
COPY backend/package*.json ./backend/
COPY shared/package*.json ./shared/

# Install in parallel (BuildKit)
RUN cd frontend && npm ci &\
    cd backend && npm ci & \
    cd shared && npm ci & \
    wait

COPY . .
```

**Leverage Build Arguments:**

```dockerfile
ARG NODE_VERSION=18
FROM node:${NODE_VERSION}-alpine

ARG NPM_REGISTRY=https://registry.npmjs.org/
RUN npm config set registry ${NPM_REGISTRY}

WORKDIR /app
COPY package*.json ./
RUN npm ci
```

**Build:**
```bash
docker build \
  --build-arg NODE_VERSION=20 \
  --build-arg NPM_REGISTRY=https://custom-registry.com/ \
  -t myapp:latest .
```

### Debugging Dockerfiles

**Inspect Build Process:**

```bash
# Build with progress output
docker build --progress=plain -t myapp .

# Build specific stage
docker build --target build -t myapp:build .

# Run intermediate stage
docker run --rm -it myapp:build sh
```

**Common Issues and Solutions:**

**Issue: Cache not working**
```dockerfile
# Bad: COPY invalidates cache
COPY . .
RUN npm install

# Good: Copy deps first
COPY package*.json ./
RUN npm install
COPY . .
```

**Issue: Large image size**
```bash
# Analyze layers
docker history myapp:latest

# Find large layers
docker history myapp:latest --human --format "{{.Size}}\t{{.CreatedBy}}"
```

**Issue: Slow builds**
```dockerfile
# Enable BuildKit
export DOCKER_BUILDKIT=1

# Use cache mounts
# syntax=docker/dockerfile:1
RUN --mount=type=cache,target=/root/.npm npm install
```

### Security Best Practices Checklist

- ✅ Use specific, minimal base images (Alpine, distroless)
- ✅ Run as non-root user
- ✅ Don't include secrets in images (use BuildKit secrets)
- ✅ Scan images for vulnerabilities regularly
- ✅ Keep base images updated with automated pipelines
- ✅ Minimize installed packages
- ✅ Use read-only root filesystem when possible
- ✅ Drop unnecessary Linux capabilities
- ✅ Use multi-stage builds to exclude build tools
- ✅ Implement health checks
- ✅ Sign images for supply chain security

### Build Optimization Checklist

- ✅ Order layers from least to most frequently changing
- ✅ Use `.dockerignore` to exclude unnecessary files
- ✅ Combine RUN commands to minimize layers
- ✅ Use specific base image tags (not `latest`)
- ✅ Leverage build cache with proper ordering
- ✅ Use multi-stage builds (next lesson!)
- ✅ Clean up in the same layer (apt-get clean, rm cache)
- ✅ Use BuildKit for advanced caching
- ✅ Parallel builds where possible
- ✅ Cache package manager downloads

## Key Takeaways

✅ **Layer ordering is critical for cache efficiency**
- Copy dependency files first, source code last
- Least frequently changing → most frequently changing
- Each cache miss rebuilds all subsequent layers

✅ **Minimize image size for better performance**
- Use Alpine or distroless base images
- Combine RUN commands to reduce layers
- Clean up in the same layer where files are created
- Use multi-stage builds (next lesson)

✅ **Security must be built in, not bolted on**
- Run as non-root user (create dedicated user)
- Use specific image tags, not `latest`
- Scan regularly for vulnerabilities
- Minimize attack surface (fewer packages)

✅ **Use .dockerignore like .gitignore**
- Exclude node_modules, .git, test files
- Faster builds, smaller context
- Prevents sensitive files in images

✅ **BuildKit enables advanced patterns**
- Cache mounts for package managers
- Secrets that don't persist in layers
- Parallel stage execution
- Better build performance

✅ **Health checks enable container orchestration**
- Define how to verify container is working
- Used by Docker, Kubernetes for health monitoring
- Enables zero-downtime deployments
