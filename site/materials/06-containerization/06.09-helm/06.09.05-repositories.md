## Introduction

Helm repositories enable chart sharing and distribution within organizations and publicly. Whether using public repositories like Artifact Hub, hosting private repositories with ChartMuseum or Harbor, or leveraging OCI registries, understanding repository management is essential for production Helm workflows.

### Repository Structure

**index.yaml:**
```yaml
apiVersion: v1
entries:
  nginx:
  - name: nginx
    version: 13.2.0
    appVersion: 1.23.3
    description: NGINX Open Source
    urls:
    - https://example.com/charts/nginx-13.2.0.tgz
    created: 2026-01-26T10:00:00Z
    digest: sha256:abc123...
  - name: nginx
    version: 13.1.0
    appVersion: 1.23.2
    urls:
    - https://example.com/charts/nginx-13.1.0.tgz
    created: 2026-01-20T10:00:00Z
```

**Directory layout:**
```
my-repo/
├── index.yaml
├── nginx-13.2.0.tgz
├── nginx-13.1.0.tgz
├── postgres-12.1.0.tgz
└── redis-17.3.0.tgz
```

### Creating a Chart Repository

**1. Package charts:**
```bash
helm package mychart/
# Successfully packaged chart and saved it to: mychart-0.1.0.tgz
```

**2. Create repository directory:**
```bash
mkdir my-repo
mv mychart-0.1.0.tgz my-repo/
cd my-repo/
```

**3. Generate index.yaml:**
```bash
helm repo index . --url https://example.com/charts
```

**4. Host files:**
```bash
# Simple HTTP server for testing
python3 -m http.server 8080

# Production: Use nginx, S3, GCS, etc.
```

**5. Add repository:**
```bash
helm repo add myrepo http://localhost:8080
helm repo update
helm search repo myrepo/
```

### ChartMuseum

**Run ChartMuseum (Docker):**
```bash
docker run -d \
  --name chartmuseum \
  -p 8080:8080 \
  -e DEBUG=1 \
  -e STORAGE=local \
  -e STORAGE_LOCAL_ROOTDIR=/charts \
  -v $(pwd)/charts:/charts \
  chartmuseum/chartmuseum:latest
```

**Upload chart:**
```bash
# Install push plugin
helm plugin install https://github.com/chartmuseum/helm-push

# Package chart
helm package mychart/

# Push to ChartMuseum
helm cm-push mychart-0.1.0.tgz myrepo

# Or use curl
curl --data-binary "@mychart-0.1.0.tgz" http://localhost:8080/api/charts
```

**Add repository:**
```bash
helm repo add myrepo http://localhost:8080
helm repo update
helm search repo myrepo/
```

**Kubernetes deployment:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: chartmuseum
spec:
  replicas: 1
  selector:
    matchLabels:
      app: chartmuseum
  template:
    metadata:
      labels:
        app: chartmuseum
    spec:
      containers:
      - name: chartmuseum
        image: chartmuseum/chartmuseum:latest
        args:
        - --storage=local
        - --storage-local-rootdir=/charts
        ports:
        - containerPort: 8080
        volumeMounts:
        - name: storage
          mountPath: /charts
      volumes:
      - name: storage
        persistentVolumeClaim:
          claimName: chartmuseum-pvc

---
apiVersion: v1
kind: Service
metadata:
  name: chartmuseum
spec:
  selector:
    app: chartmuseum
  ports:
  - port: 8080
    targetPort: 8080
```

**ChartMuseum with authentication:**
```bash
docker run -d \
  --name chartmuseum \
  -p 8080:8080 \
  -e BASIC_AUTH_USER=admin \
```

### OCI Registries

**Helm 3.8+ supports OCI:**
```bash
# Enable OCI support (default in Helm 3.8+)
export HELM_EXPERIMENTAL_OCI=1
```

**Login to registry:**
```bash
# Docker Hub
helm registry login registry-1.docker.io -u username

# AWS ECR
aws ecr get-login-password | helm registry login \
  --username AWS \
  --password-stdin 123456789.dkr.ecr.us-west-2.amazonaws.com

# Azure ACR
helm registry login myregistry.azurecr.io -u username
```

**Push chart as OCI:**
```bash
# Package chart
helm package mychart/

# Push to OCI registry
helm push mychart-0.1.0.tgz oci://registry-1.docker.io/username

# Or
helm push mychart-0.1.0.tgz oci://123456789.dkr.ecr.us-west-2.amazonaws.com/charts
```

**Pull chart from OCI:**
```bash
# Install directly
helm install myapp oci://registry-1.docker.io/username/mychart --version 0.1.0

# Or pull first
helm pull oci://registry-1.docker.io/username/mychart --version 0.1.0
helm install myapp mychart-0.1.0.tgz
```

**Show OCI chart info:**
```bash
helm show chart oci://registry-1.docker.io/username/mychart --version 0.1.0
```

### Chart Versioning Strategy

**Semantic Versioning:**
```
MAJOR.MINOR.PATCH

1.0.0 → 1.0.1  (patch: bug fixes)
1.0.1 → 1.1.0  (minor: new features, backwards compatible)
1.1.0 → 2.0.0  (major: breaking changes)
```

**Chart version vs App version:**
```yaml
# Chart.yaml
version: 1.2.3      # Chart structure/templates version
appVersion: "2.0.1" # Application version
```

**Update versions:**
```bash
# Update chart version
yq -i '.version = "1.2.4"' Chart.yaml

# Update app version
yq -i '.appVersion = "2.0.2"' Chart.yaml
```

### Publishing Workflow

**Complete workflow:**
```bash
# 1. Make changes to chart
vim mychart/templates/deployment.yaml

# 2. Update version
vim mychart/Chart.yaml
# version: 0.2.0

# 3. Lint chart
helm lint mychart/

# 4. Package chart
helm package mychart/

# 5. Update repo index
helm repo index . --url https://example.com/charts --merge index.yaml

# 6. Push to repository
helm cm-push mychart-0.2.0.tgz myrepo

# 7. Test
helm repo update
helm search repo myrepo/mychart
helm install test-app myrepo/mychart --version 0.2.0
```

### CI/CD Pipeline Example

**GitHub Actions:**
```yaml
# .github/workflows/release-chart.yaml
name: Release Chart

on:
  push:
    branches:
      - main
    paths:
      - 'charts/**'

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
    - name: Checkout
      uses: actions/checkout@v3
      with:
        fetch-depth: 0

    - name: Configure Git
      run: |
        git config user.name "$GITHUB_ACTOR"
        git config user.email "$GITHUB_ACTOR@users.noreply.github.com"

    - name: Install Helm
      uses: azure/setup-helm@v3

    - name: Package chart
      run: |
        helm package charts/mychart/

    - name: Upload to ChartMuseum
      run: |
        curl --data-binary "@mychart-*.tgz" \
          -u ${{ secrets.CHARTMUSEUM_USER }}:${{ secrets.CHARTMUSEUM_PASS }} \
          https://chartmuseum.example.com/api/charts
```

### Chart Signing and Verification

**Generate GPG key:**
```bash
# Generate key
gpg --full-generate-key
# Select: RSA and RSA, 4096 bits, no expiration

# List keys
gpg --list-keys

# Export public key
gpg --export --armor your@email.com > publickey.asc

# Import public key (for verification)
gpg --import publickey.asc
```

**Sign chart:**
```bash
# Package and sign
helm package mychart/ \
  --sign \
  --key 'Your Name' \
  --keyring ~/.gnupg/secring.gpg

# Creates:
# - mychart-0.1.0.tgz
# - mychart-0.1.0.tgz.prov (provenance file)
```

**Verify signed chart:**
```bash
# Verify with provenance
helm verify mychart-0.1.0.tgz

# Install with verification
helm install myapp myrepo/mychart --verify
```

### Repository Mirroring

**Mirror public repository:**
```bash
#!/bin/bash
# Download and mirror charts

SOURCE_REPO="https://charts.bitnami.com/bitnami"
CHARTS=("nginx" "redis" "postgresql")
DEST_DIR="./mirror"

for chart in "${CHARTS[@]}"; do
  helm pull $SOURCE_REPO/$chart -d $DEST_DIR
done

helm repo index $DEST_DIR --url https://mymirror.example.com
```

### Chart Versioning Automation

**Semantic version bumping:**
```bash
#!/bin/bash
# Bump chart version

CHART_FILE="Chart.yaml"
BUMP_TYPE=${1:-patch}
CURRENT=$(yq eval '.version' $CHART_FILE)

# Parse and bump version
IFS='.' read -ra VERSION <<< "$CURRENT"
MAJOR=${VERSION[0]}
MINOR=${VERSION[1]}
PATCH=${VERSION[2]}

case $BUMP_TYPE in
  major) MAJOR=$((MAJOR + 1)); MINOR=0; PATCH=0 ;;
  minor) MINOR=$((MINOR + 1)); PATCH=0 ;;
  patch) PATCH=$((PATCH + 1)) ;;
esac

NEW_VERSION="$MAJOR.$MINOR.$PATCH"
yq eval -i ".version = \"$NEW_VERSION\"" $CHART_FILE
echo "Version bumped: $CURRENT → $NEW_VERSION"
```
