- Manage releases (install, upgrade, rollback, uninstall)
- Use basic Helm commands effectively

---

## Introduction

Helm is the package manager for Kubernetes, similar to apt for Ubuntu or npm for Node.js. It packages Kubernetes applications into charts—collections of files that describe a related set of Kubernetes resources. Helm makes it easy to deploy complex applications, manage configuration, and maintain consistency across environments.

## Key Concepts Summary

### What is Helm?

```
Without Helm:
- Manage dozens of YAML files
- Copy/paste for each environment
- Manual parameter updates
- No version history
❌ Complex and error-prone

With Helm:
- Single chart package
- Parameterized templates
- Easy upgrades/rollbacks
- Version-controlled releases
✅ Simple and maintainable
```

### Core Concepts

**Chart:**
```
Package containing:
- Kubernetes resource definitions
- Configuration defaults
- Documentation
```

**Release:**
```
Chart + Configuration → Deployed Instance
Same chart → Multiple releases
```

**Repository:**
```
Collection of charts
- Public (Artifact Hub)
- Private (ChartMuseum, Harbor)
```

### Three Big Concepts

**1. Chart:** A Helm package
```bash
# Chart contains:
Chart.yaml          # Metadata
values.yaml         # Default config
templates/          # Kubernetes manifests
```

**2. Repository:** Where charts live
```bash
# Add repository
helm repo add bitnami https://charts.bitnami.com/bitnami

# Search charts
helm search repo nginx
```

**3. Release:** Deployed chart instance
```bash
# Install creates release
helm install my-nginx bitnami/nginx

# Multiple releases from same chart
helm install nginx-1 bitnami/nginx
helm install nginx-2 bitnami/nginx
```

### Searching for Charts

**Search Artifact Hub (public charts):**
```bash
helm search hub wordpress
# Searches https://artifacthub.io/

# NAME                        CHART VERSION   APP VERSION     DESCRIPTION
# artifact-hub/wordpress      15.2.0          6.1.1           Web publishing platform for...
```

**Search added repositories:**
```bash
# Add Bitnami repository
helm repo add bitnami https://charts.bitnami.com/bitnami

# Update repository index
helm repo update

# Search in added repos
helm search repo nginx
# NAME                    CHART VERSION   APP VERSION     DESCRIPTION
# bitnami/nginx           13.2.0          1.23.3          NGINX Open Source is a web server...
```

**Show chart information:**
```bash
helm show chart bitnami/nginx
helm show values bitnami/nginx
helm show all bitnami/nginx
```

### Installing Charts

**Basic install:**
```bash
helm install my-release bitnami/nginx
```

**Install with custom name:**
```bash
helm install my-nginx bitnami/nginx
```

**Install with generated name:**
```bash
helm install bitnami/nginx --generate-name
# Release name: nginx-1674567890
```

**Install with custom values:**
```bash
# Override single value
helm install my-nginx bitnami/nginx \
  --set service.type=LoadBalancer

# Override multiple values
helm install my-nginx bitnami/nginx \
  --set service.type=LoadBalancer \
  --set replicaCount=3

# Use custom values file
helm install my-nginx bitnami/nginx -f custom-values.yaml
```

**Install in specific namespace:**
```bash
helm install my-nginx bitnami/nginx -n production --create-namespace
```

**Dry run (preview):**
```bash
helm install my-nginx bitnami/nginx --dry-run --debug
```

### Managing Releases

**List releases:**
```bash
# Current namespace
helm list

# All namespaces
helm list --all-namespaces

# Specific namespace
helm list -n production
```

**Get release status:**
```bash
helm status my-nginx

# NAME: my-nginx
# NAMESPACE: default
# STATUS: deployed
# REVISION: 1
```

**Get release values:**
```bash
# User-supplied values
helm get values my-nginx

# All values (including defaults)
helm get values my-nginx --all
```

**Get release manifest:**
```bash
helm get manifest my-nginx
```

### Upgrading Releases

**Upgrade to new version:**
```bash
helm upgrade my-nginx bitnami/nginx --version 14.0.0
```

**Upgrade with new values:**
```bash
helm upgrade my-nginx bitnami/nginx \
  --set replicaCount=5
```

**Upgrade or install (idempotent):**
```bash
helm upgrade --install my-nginx bitnami/nginx
```

**Upgrade with custom values file:**
```bash
helm upgrade my-nginx bitnami/nginx -f new-values.yaml
```

**Reuse previous values:**
```bash
helm upgrade my-nginx bitnami/nginx --reuse-values
```

### Rollback Releases

**View release history:**
```bash
helm history my-nginx

# REVISION  UPDATED                   STATUS      CHART           DESCRIPTION
# 1         Mon Jan 22 10:00:00 2026  superseded  nginx-13.2.0    Install complete
# 2         Mon Jan 22 11:00:00 2026  superseded  nginx-13.2.1    Upgrade complete
# 3         Mon Jan 22 12:00:00 2026  deployed    nginx-14.0.0    Upgrade complete
```

**Rollback to previous revision:**
```bash
helm rollback my-nginx
# Rolls back to revision 2
```

**Rollback to specific revision:**
```bash
helm rollback my-nginx 1
```

**Rollback dry run:**
```bash
helm rollback my-nginx 1 --dry-run
```

### Uninstalling Releases

**Uninstall release:**
```bash
helm uninstall my-nginx
```

**Uninstall with history kept:**
```bash
helm uninstall my-nginx --keep-history
```

**List uninstalled releases:**
```bash
helm list --uninstalled
```

### Complete Example Workflow

```bash
# 1. Add repository
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update

# 2. Search for chart
helm search repo wordpress

# 3. View chart info
helm show values bitnami/wordpress | less

# 4. Create custom values
cat > my-values.yaml <<EOF
wordpressUsername: admin
wordpressEmail: admin@example.com
service:
  type: LoadBalancer
persistence:
  size: 10Gi
EOF

# 5. Install chart
helm install my-wordpress bitnami/wordpress \
  -f my-values.yaml \
  -n production \
  --create-namespace

# 6. Check status
helm status my-wordpress -n production
kubectl get pods -n production

# 7. Get WordPress password
kubectl get secret my-wordpress \
  -n production \
  -o jsonpath="{.data.wordpress-password}" | base64 -d

# 8. Upgrade with more replicas
helm upgrade my-wordpress bitnami/wordpress \
  -n production \
  --set replicaCount=3 \
  --reuse-values

# 9. Check history
helm history my-wordpress -n production

# 10. Rollback if needed
helm rollback my-wordpress -n production

# 11. Uninstall when done
helm uninstall my-wordpress -n production
```

### Best Practices

**1. Always use namespaces:**
```bash
helm install my-app bitnami/app -n production --create-namespace
```

**2. Use meaningful release names:**
```bash
helm install wordpress-prod bitnami/wordpress  # Good
helm install my-release bitnami/wordpress      # Not descriptive
```

**3. Use custom values files:**
```bash
# production-values.yaml
replicaCount: 3
resources:
  requests:
    memory: "1Gi"
    cpu: "500m"

helm install my-app bitnami/app -f production-values.yaml
```

**4. Test before deploying:**
```bash
helm install my-app bitnami/app --dry-run --debug
```

**5. Keep release history manageable:**
```bash
# Limit history (default 10)
helm upgrade my-app bitnami/app --history-max 5
```

**6. Document your values:**
```yaml
# my-values.yaml
# Number of replicas for high availability
replicaCount: 3

# Resource limits based on load testing
resources:
  requests:
    memory: "1Gi"
```

### Troubleshooting

**Release stuck:**
```bash
# Check status
helm status my-nginx
kubectl get pods

# Check events
kubectl get events --sort-by='.lastTimestamp'

# Uninstall and reinstall
helm uninstall my-nginx
helm install my-nginx bitnami/nginx
```

**Can't find chart:**
```bash
# Update repo index
helm repo update

# Search again
helm search repo nginx

# Check repo is added
helm repo list
```

**Values not applied:**
```bash
# Check what values are set
helm get values my-nginx

# Verify in manifest
helm get manifest my-nginx | grep -A 10 "kind: Service"
```

### Helm Hooks

**Lifecycle hooks:**
```yaml
# Pre-install hook
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migration
  annotations:
    "helm.sh/hook": pre-install
    "helm.sh/hook-weight": "0"
    "helm.sh/hook-delete-policy": hook-succeeded
spec:
  template:
    spec:
      containers:
      - name: migrate
        image: my-app:1.0.0
        command: ["./migrate.sh"]
      restartPolicy: Never
```

**Available hooks:**
```
pre-install      → Before install
post-install     → After install
pre-upgrade      → Before upgrade
post-upgrade     → After upgrade
pre-rollback     → Before rollback
post-rollback    → After rollback
pre-delete       → Before delete
post-delete      → After delete
test             → Test hook (helm test)
```

**Hook weights:**
```yaml
# Control execution order (lower runs first)
annotations:
  "helm.sh/hook-weight": "-5"  # Runs first
  "helm.sh/hook-weight": "0"   # Runs second
  "helm.sh/hook-weight": "5"   # Runs last
```

**Hook deletion policies:**
```yaml
# When to delete hook resources
"helm.sh/hook-delete-policy": before-hook-creation  # Before next hook
"helm.sh/hook-delete-policy": hook-succeeded        # On success
"helm.sh/hook-delete-policy": hook-failed           # On failure
```

### Common Use Cases

**WordPress deployment:**
```bash
# Install WordPress with MySQL
helm install my-wordpress bitnami/wordpress \
  --set wordpressUsername=admin \
  --set wordpressPassword=password \
  --set mariadb.auth.rootPassword=rootpassword \
  --set service.type=LoadBalancer

# Get WordPress URL
kubectl get svc my-wordpress -o jsonpath='{.status.loadBalancer.ingress[0].ip}'

# Get WordPress credentials
echo Username: admin
echo Password: $(kubectl get secret my-wordpress -o jsonpath="{.data.wordpress-password}" | base64 -d)
```

**Redis cluster:**
```bash
# Install Redis with replicas
helm install my-redis bitnami/redis \
  --set architecture=replication \
  --set auth.enabled=true \
  --set auth.password=myredispass \
  --set master.persistence.size=8Gi \
  --set replica.replicaCount=3 \
  --set replica.persistence.size=8Gi

# Get Redis password
export REDIS_PASSWORD=$(kubectl get secret my-redis -o jsonpath="{.data.redis-password}" | base64 -d)

# Connect to Redis
kubectl run redis-client --rm -it --image bitnami/redis:latest -- redis-cli -h my-redis-master -a $REDIS_PASSWORD
```

**Monitoring stack:**
```bash
# Add Prometheus repo
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts

# Install Prometheus + Grafana
helm install monitoring prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --create-namespace \
  --set prometheus.service.type=LoadBalancer \
  --set grafana.service.type=LoadBalancer \
  --set grafana.adminPassword=admin123

# Access Grafana
kubectl get svc -n monitoring monitoring-grafana
```

### Multi-Environment Management

**Development environment:**
```yaml
# dev-values.yaml
replicaCount: 1

resources:
  limits:
    cpu: 100m
    memory: 128Mi
  requests:
    cpu: 50m
    memory: 64Mi

ingress:
  enabled: false

autoscaling:
  enabled: false
```

**Production environment:**
```yaml
# prod-values.yaml
replicaCount: 5

resources:
  limits:
    cpu: 1000m
    memory: 2Gi
  requests:
    cpu: 500m
    memory: 1Gi

ingress:
  enabled: true
  className: nginx
  hosts:
    - host: app.example.com
      paths:
        - path: /
          pathType: Prefix

autoscaling:
  enabled: true
  minReplicas: 5
  maxReplicas: 20
  targetCPUUtilizationPercentage: 70
```

**Deploy to environments:**
```bash
# Development
helm install myapp ./mychart -f dev-values.yaml -n development --create-namespace

# Staging
helm install myapp ./mychart -f staging-values.yaml -n staging --create-namespace

# Production
helm install myapp ./mychart -f prod-values.yaml -n production --create-namespace
```

### Security Best Practices

**1. Don't commit secrets:**
```bash
# Use --set for sensitive values
helm install myapp ./mychart \
  --set database.password=secretpassword \
  --set api.key=apikey123
```

**2. Use external secrets:**
```yaml
# Reference Kubernetes secrets
env:
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef:
        name: db-credentials
        key: password
```

**3. Verify chart signatures:**
```bash
# Install with verification
helm install myapp myrepo/mychart --verify

# Requires chart to be signed with GPG key
```

**4. Use RBAC:**
```bash
# Install with service account
helm install myapp ./mychart --create-namespace -n production \
  --set serviceAccount.create=true \
  --set serviceAccount.name=myapp-sa
```

**5. Scan charts for vulnerabilities:**
```bash
# Use tools like Checkov, Trivy
trivy config ./mychart
```
