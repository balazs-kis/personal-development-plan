# Lesson 4: Chart Dependencies and Release Management

## Learning Objectives

By the end of this lesson, you will be able to:
- Manage chart dependencies
- Use version ranges for dependencies
- Configure optional dependencies with conditions and tags
- Upgrade and rollback releases effectively
- Understand release lifecycle and revisions
- Implement release strategies for production

---

## Introduction

Complex applications often require multiple components—databases, caches, message queues. Helm dependencies allow charts to include other charts, creating a complete application stack. Release management provides version control for deployed applications, enabling safe upgrades, rollbacks, and testing strategies.

## Key Concepts Summary

### Chart Dependencies

**Define in Chart.yaml:**
```yaml
apiVersion: v2
name: myapp
version: 1.0.0
dependencies:
  - name: postgresql
    version: 12.1.0
    repository: https://charts.bitnami.com/bitnami
  - name: redis
    version: 17.3.0
    repository: https://charts.bitnami.com/bitnami
```

**Dependency fields:**
```yaml
dependencies:
  - name: postgresql              # Chart name (required)
    version: ~12.1.0               # Version range (required)
    repository: https://...        # Chart repo URL (required)
    alias: db                      # Override name in templates
    condition: postgresql.enabled  # Enable/disable condition
    tags:                          # Group dependencies
      - database
    import-values:                 # Import parent values
      - child: key
        parent: key
```

### Managing Dependencies

**Download dependencies:**
```bash
helm dependency update myapp/

# Downloads to charts/ subdirectory:
# charts/postgresql-12.1.0.tgz
# charts/redis-17.3.0.tgz
```

**List dependencies:**
```bash
helm dependency list myapp/

# NAME          VERSION   REPOSITORY                              STATUS
# postgresql    12.1.0    https://charts.bitnami.com/bitnami      ok
# redis         17.3.0    https://charts.bitnami.com/bitnami      ok
```

**Build dependencies:**
```bash
# Package dependency charts
helm dependency build myapp/
```

### Version Ranges

**Exact version:**
```yaml
version: 12.1.0  # Only 12.1.0
```

**Patch-level matching (recommended):**
```yaml
version: ~12.1.0
# Equivalent to: >= 12.1.0, < 12.2.0
# Allows: 12.1.0, 12.1.1, 12.1.2
# Blocks: 12.2.0
```

**Minor-level matching:**
```yaml
version: ^12.1.0
# Equivalent to: >= 12.1.0, < 13.0.0
# Allows: 12.1.x, 12.2.x
# Blocks: 13.0.0
```

**Range operators:**
```yaml
version: ">= 12.1.0, < 13.0.0"
version: "> 12.0.0"
version: "!= 12.1.5"  # Exclude specific version
```

### Optional Dependencies

**Using conditions:**
```yaml
# Chart.yaml
dependencies:
  - name: postgresql
    version: 12.1.0
    repository: https://charts.bitnami.com/bitnami
    condition: postgresql.enabled
  - name: redis
    version: 17.3.0
    repository: https://charts.bitnami.com/bitnami
    condition: redis.enabled
```

**Control in values.yaml:**
```yaml
# values.yaml
postgresql:
  enabled: true
  auth:
    password: mypassword

redis:
  enabled: false  # Won't be installed
```

**Install with override:**
```bash
helm install myapp ./myapp --set postgresql.enabled=false
```

### Using Tags

**Group related dependencies:**
```yaml
# Chart.yaml
dependencies:
  - name: postgresql
    version: 12.1.0
    repository: https://charts.bitnami.com/bitnami
    tags:
      - database
      - backend
  - name: redis
    version: 17.3.0
    repository: https://charts.bitnami.com/bitnami
    tags:
      - cache
      - backend
  - name: mongodb
    version: 13.6.0
    repository: https://charts.bitnami.com/bitnami
    tags:
      - database
      - backend
```

**Enable/disable by tag:**
```yaml
# values.yaml
tags:
  database: true  # Enable all database dependencies
  cache: false    # Disable cache dependencies
  backend: true   # Enable all backend dependencies
```

**Install with tags:**
```bash
helm install myapp ./myapp --set tags.database=false
```

### Alias Dependencies

**Override subchart name:**
```yaml
# Chart.yaml
dependencies:
  - name: postgresql
    version: 12.1.0
    repository: https://charts.bitnami.com/bitnami
    alias: primary-db
  - name: postgresql
    version: 12.1.0
    repository: https://charts.bitnami.com/bitnami
    alias: replica-db
```

**Configure separately:**
```yaml
# values.yaml
primary-db:
  enabled: true
  primary:
    persistence:
      size: 50Gi

replica-db:
  enabled: true
  readReplicas:
    replicaCount: 2
```

### Complete Dependency Example

**Chart.yaml:**
```yaml
apiVersion: v2
name: webapp
version: 1.0.0
appVersion: "1.0.0"
description: Full-stack web application

dependencies:
  - name: postgresql
    version: ~12.1.0
    repository: https://charts.bitnami.com/bitnami
    condition: postgresql.enabled
    tags:
      - database
  
  - name: redis
    version: ~17.3.0
    repository: https://charts.bitnami.com/bitnami
    condition: redis.enabled
    tags:
      - cache
  
  - name: nginx-ingress-controller
    version: ~9.3.0
    repository: https://charts.bitnami.com/bitnami
    condition: ingress.enabled
```

**values.yaml:**
```yaml
postgresql:
  enabled: true
  auth:
    username: webapp
    password: ""  # Set via --set
    database: webapp
  primary:
    persistence:
      size: 20Gi

redis:
  enabled: true
  auth:
    enabled: false
  master:
    persistence:
      size: 8Gi

ingress:
  enabled: true
```

### Release Management

**Install release:**
```bash
helm install myapp ./myapp -n production --create-namespace
```

**List releases:**
```bash
helm list -n production

# NAME    NAMESPACE   REVISION  UPDATED                   STATUS    CHART
# myapp   production  1         2026-01-26 10:00:00 UTC   deployed  myapp-1.0.0
```

**Get release status:**
```bash
helm status myapp -n production
```

**Get release values:**
```bash
# User-supplied values
helm get values myapp -n production

# All values (including defaults)
helm get values myapp -n production --all
```

**Get release manifest:**
```bash
helm get manifest myapp -n production
```

### Upgrading Releases

**Basic upgrade:**
```bash
helm upgrade myapp ./myapp -n production
```

**Upgrade with new values:**
```bash
helm upgrade myapp ./myapp \
  -n production \
  --set replicaCount=5
```

**Upgrade with values file:**
```bash
helm upgrade myapp ./myapp \
  -n production \
  -f production-values.yaml
```

**Reuse previous values:**
```bash
helm upgrade myapp ./myapp \
  -n production \
  --reuse-values
```

**Reset values:**
```bash
helm upgrade myapp ./myapp \
  -n production \
  --reset-values
```

**Atomic upgrade (rollback on failure):**
```bash
helm upgrade myapp ./myapp \
  -n production \
  --atomic \
  --timeout 5m
```

**Wait for resources:**
```bash
helm upgrade myapp ./myapp \
  -n production \
  --wait \
  --timeout 10m
```

### Release History

**View history:**
```bash
helm history myapp -n production

# REVISION  UPDATED                   STATUS      CHART       APP VERSION DESCRIPTION
# 1         Mon Jan 26 10:00:00 2026  superseded  myapp-1.0.0 1.0.0       Install complete
# 2         Mon Jan 26 11:00:00 2026  superseded  myapp-1.0.1 1.0.1       Upgrade complete
# 3         Mon Jan 26 12:00:00 2026  deployed    myapp-1.1.0 1.1.0       Upgrade complete
```

**Limit history:**
```bash
# Keep only last 5 revisions
helm upgrade myapp ./myapp \
  -n production \
  --history-max 5
```

### Rollback

**Rollback to previous:**
```bash
helm rollback myapp -n production
# Rolls back to revision 2
```

**Rollback to specific revision:**
```bash
helm rollback myapp 1 -n production
```

**Rollback dry-run:**
```bash
helm rollback myapp 1 -n production --dry-run
```

**Rollback with cleanup:**
```bash
helm rollback myapp 1 -n production --cleanup-on-fail
```

**Wait for rollback:**
```bash
helm rollback myapp 1 -n production --wait --timeout 5m
```

### Release Strategies

**Blue-Green Deployment:**
```bash
# Install blue
helm install myapp-blue ./myapp -n production

# Test blue
kubectl get svc myapp-blue -n production

# Install green
helm install myapp-green ./myapp -n production

# Switch traffic (update ingress/service)
# ...

# Remove blue when stable
helm uninstall myapp-blue -n production
```

**Canary Deployment:**
```bash
# Stable version
helm install myapp-stable ./myapp -n production --set replicaCount=9

# Canary version (10% traffic)
helm install myapp-canary ./myapp -n production --set replicaCount=1

# Monitor canary
# ...

# Promote canary
helm upgrade myapp-stable ./myapp -n production
helm uninstall myapp-canary -n production
```

**Progressive Rollout:**
```bash
# Start with 1 replica
helm install myapp ./myapp -n production --set replicaCount=1

# Increase gradually
helm upgrade myapp ./myapp -n production --set replicaCount=3
helm upgrade myapp ./myapp -n production --set replicaCount=5
helm upgrade myapp ./myapp -n production --set replicaCount=10
```

### Testing Releases

**Helm test:**
```yaml
# templates/tests/test-connection.yaml
apiVersion: v1
kind: Pod
metadata:
  name: "{{ include "myapp.fullname" . }}-test-connection"
  annotations:
    "helm.sh/hook": test
spec:
  containers:
  - name: wget
    image: busybox
    command: ['wget']
    args: ['{{ include "myapp.fullname" . }}:{{ .Values.service.port }}']
  restartPolicy: Never
```

**Run test:**
```bash
helm test myapp -n production

# NAME: myapp
# LAST DEPLOYED: Mon Jan 26 10:00:00 2026
# NAMESPACE: production
# STATUS: deployed
# TEST SUITE:     myapp-test-connection
# Last Started:   Mon Jan 26 10:05:00 2026
# Last Completed: Mon Jan 26 10:05:05 2026
# Phase:          Succeeded
```

### Best Practices

**1. Use version ranges:**
```yaml
version: ~12.1.0  # Patch updates only
```

**2. Enable optional dependencies with conditions:**
```yaml
condition: postgresql.enabled
```

**3. Group dependencies with tags:**
```yaml
tags:
  - database
  - backend
```

**4. Test before upgrading production:**
```bash
helm upgrade myapp ./myapp --dry-run --debug
```

**5. Use atomic upgrades:**
```bash
helm upgrade myapp ./myapp --atomic --timeout 5m
```

**6. Keep release history limited:**
```bash
helm upgrade myapp ./myapp --history-max 10
```

**7. Document upgrade procedures:**
```markdown
# Upgrade Steps
1. Backup database
2. Run helm upgrade with --dry-run
3. Upgrade with --atomic
4. Run helm test
5. Monitor for 30 minutes
```

### Managing Multiple Releases

**Release naming strategy:**
```bash
# Environment-based
helm install myapp-dev ./mychart -n development
helm install myapp-staging ./mychart -n staging
helm install myapp-prod ./mychart -n production

# Version-based
helm install myapp-v1 ./mychart -n default
helm install myapp-v2 ./mychart -n default

# Feature-based
helm install myapp-feature-auth ./mychart -n feature-testing
helm install myapp-feature-api ./mychart -n feature-testing
```

**List all releases:**
```bash
# All namespaces
helm list -A

# Specific namespace
helm list -n production

# All statuses (including uninstalled)
helm list -A --all

# Filter by status
helm list -A --deployed
helm list -A --failed
helm list -A --pending
```

**Compare releases:**
```bash
# Compare values between releases
helm get values myapp-dev -n development > dev-values.yaml
helm get values myapp-prod -n production > prod-values.yaml
diff dev-values.yaml prod-values.yaml
```

### Advanced Upgrade Strategies

**Zero-downtime upgrade:**
```bash
# 1. Ensure PodDisruptionBudget
helm upgrade myapp ./mychart \
  --set podDisruptionBudget.enabled=true \
  --set podDisruptionBudget.minAvailable=1

# 2. Upgrade with wait
helm upgrade myapp ./mychart \
  --wait \
  --timeout 10m \
  --atomic
```

**Staged rollout:**
```bash
# Stage 1: Canary (10%)
helm upgrade myapp ./mychart --set replicaCount=1

# Monitor metrics, then expand
helm upgrade myapp ./mychart --set replicaCount=10
```

**Diff before upgrade:**
```bash
# Install helm-diff plugin
helm plugin install https://github.com/databus23/helm-diff

# Preview changes
helm diff upgrade myapp ./mychart -f new-values.yaml

# Shows:
# + Added resources
# - Removed resources
# ~ Modified resources
```

### Rollback Strategies

**Conditional rollback:**
```bash
# Upgrade with health check (automatic rollback on failure)
helm upgrade myapp ./mychart --atomic --timeout 5m
```

**Emergency rollback:**
```bash
# Quick rollback to previous

# Rollback with wait (safer)

```

### Dependency Updates and Locking

**Chart.lock file:**
```yaml
# Generated by helm dependency update
dependencies:
- name: postgresql
  repository: https://charts.bitnami.com/bitnami
  version: 12.1.5
  digest: sha256:abc123...
- name: redis
  repository: https://charts.bitnami.com/bitnami
  version: 17.3.7
  digest: sha256:def456...
```

**Lock dependencies:**
```bash
# Update dependencies and create Chart.lock
helm dependency update ./mychart

# Build from existing Chart.lock
helm dependency build ./mychart
```

**Verify dependency integrity:**
```bash
# Check if dependencies match Chart.lock
helm dependency list ./mychart

# STATUS column shows:
# - ok: matches Chart.lock
# - missing: not downloaded
# - unpacked: extracted but no .tgz
```

**Update specific dependency:**
```bash
# Update Chart.yaml version, then:
helm dependency update ./mychart
```
