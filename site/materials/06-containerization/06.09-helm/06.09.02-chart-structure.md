## Learning Objectives

By the end of this lesson, you will be able to:

## Introduction

Helm charts are structured packages that contain all the information needed to deploy an application to Kubernetes. Understanding chart structure is essential for creating maintainable, reusable packages. This lesson covers the anatomy of a chart, required files, naming conventions, and best practices for chart development.

## Key Concepts Summary

### Chart Directory Structure

```
mychart/
├── Chart.yaml          # Chart metadata (REQUIRED)
├── values.yaml         # Default configuration values
├── charts/             # Dependent charts (subcharts)
├── templates/          # Template files
│   ├── NOTES.txt       # Usage notes (optional)
│   ├── _helpers.tpl    # Template helpers (underscore = not rendered)
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   └── tests/          # Test files
│       └── test-connection.yaml
├── .helmignore         # Files to ignore (like .gitignore)
└── README.md           # Chart documentation (optional)
```

### Creating a New Chart

**Generate chart scaffold:**
```bash
helm create mychart

# Creates directory with:
# - Chart.yaml
# - values.yaml
# - templates/ with examples
```

**Result:**
```
mychart/
├── Chart.yaml
├── values.yaml
├── charts/
└── templates/
    ├── NOTES.txt
    ├── _helpers.tpl
    ├── deployment.yaml
    ├── hpa.yaml
    ├── ingress.yaml
    ├── service.yaml
    ├── serviceaccount.yaml
    └── tests/
        └── test-connection.yaml
```

### Chart.yaml Structure

**Required fields:**
```yaml
apiVersion: v2              # Chart API version (v2 for Helm 3)
name: mychart               # Chart name
version: 0.1.0              # Chart version (SemVer 2)
```

**Common optional fields:**
```yaml
apiVersion: v2
name: mychart
version: 0.1.0
kubeVersion: ">=1.24.0"     # Compatible Kubernetes versions
description: A Helm chart for my application
type: application           # application or library
keywords:
  - web
  - nginx
home: https://example.com
sources:
  - https://github.com/example/mychart
maintainers:
  - name: John Doe
    email: john@example.com
    url: https://github.com/johndoe
icon: https://example.com/icon.png
appVersion: "1.0.0"         # Version of the app (not chart version)
deprecated: false           # Mark as deprecated
annotations:
  example.com/category: "web"
```

**Version types:**
```yaml
# Chart version: Version of the chart itself
version: 1.2.3

# App version: Version of the app being deployed
appVersion: "2.0.1"
```

### Chart Types

**Application (default):**
```yaml
type: application
```
- Fully functional applications
- Can be deployed directly
- Most common type

**Library:**
```yaml
type: library
```
- Shared templates/functions
- Cannot be deployed
- Used as dependencies

### values.yaml

**Default configuration:**
```yaml
# values.yaml
replicaCount: 1

image:
  repository: nginx
  pullPolicy: IfNotPresent
  tag: ""  # Defaults to appVersion

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: false
  className: nginx
  annotations: {}
  hosts:
    - host: chart-example.local
      paths:
        - path: /
          pathType: ImplementationSpecific
  tls: []

resources:
  limits:
    cpu: 100m
    memory: 128Mi
  requests:
    cpu: 100m
    memory: 128Mi

autoscaling:
  enabled: false
  minReplicas: 1
  maxReplicas: 100
  targetCPUUtilizationPercentage: 80

nodeSelector: {}
tolerations: []
affinity: {}
```

### Templates Directory

**Template files:**
```yaml
# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "mychart.fullname" . }}
  labels:
    {{- include "mychart.labels" . | nindent 4 }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      {{- include "mychart.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "mychart.selectorLabels" . | nindent 8 }}
    spec:
      containers:
      - name: {{ .Chart.Name }}
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
        ports:
        - containerPort: 80
```

**Helper templates (_helpers.tpl):**
```yaml
{{/*
Expand the name of the chart.
*/}}
{{- define "mychart.name" -}}
{{- default .Chart.Name .Values.nameOverride | trunc 63 | trimSuffix "-" }}
{{- end }}

{{/*
Create a default fully qualified app name.
*/}}
{{- define "mychart.fullname" -}}
{{- if .Values.fullnameOverride }}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- $name := default .Chart.Name .Values.nameOverride }}
{{- printf "%s-%s" .Release.Name $name | trunc 63 | trimSuffix "-" }}
{{- end }}
{{- end }}

{{/*
Common labels
*/}}
{{- define "mychart.labels" -}}
helm.sh/chart: {{ include "mychart.chart" . }}
{{ include "mychart.selectorLabels" . }}
{{- if .Chart.AppVersion }}
app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
{{- end }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}
```

### NOTES.txt

**Post-install instructions:**
```
# templates/NOTES.txt
1. Get the application URL by running these commands:
{{- if .Values.ingress.enabled }}
{{- range $host := .Values.ingress.hosts }}
  http{{ if $.Values.ingress.tls }}s{{ end }}://{{ $host.host }}{{ .path }}
{{- end }}
{{- else if contains "NodePort" .Values.service.type }}
  export NODE_PORT=$(kubectl get --namespace {{ .Release.Namespace }} -o jsonpath="{.spec.ports[0].nodePort}" services {{ include "mychart.fullname" . }})
  export NODE_IP=$(kubectl get nodes --namespace {{ .Release.Namespace }} -o jsonpath="{.items[0].status.addresses[0].address}")
  echo http://$NODE_IP:$NODE_PORT
{{- else if contains "LoadBalancer" .Values.service.type }}
     NOTE: It may take a few minutes for the LoadBalancer IP to be available.
           You can watch the status by running 'kubectl get --namespace {{ .Release.Namespace }} svc -w {{ include "mychart.fullname" . }}'
  export SERVICE_IP=$(kubectl get svc --namespace {{ .Release.Namespace }} {{ include "mychart.fullname" . }} --template "{{"{{ range (index .status.loadBalancer.ingress 0) }}{{.}}{{ end }}"}}")
  echo http://$SERVICE_IP:{{ .Values.service.port }}
{{- else if contains "ClusterIP" .Values.service.type }}
  export POD_NAME=$(kubectl get pods --namespace {{ .Release.Namespace }} -l "app.kubernetes.io/name={{ include "mychart.name" . }},app.kubernetes.io/instance={{ .Release.Name }}" -o jsonpath="{.items[0].metadata.name}")
  echo "Visit http://127.0.0.1:8080 to use your application"
  kubectl --namespace {{ .Release.Namespace }} port-forward $POD_NAME 8080:80
{{- end }}
```

### Chart Naming Conventions

**Chart names:**
```bash
# Lowercase letters and numbers
mychart         ✓
my-chart        ✓
myChart         ✗ (no uppercase)
my_chart        ✗ (no underscores)
my.chart        ✗ (no dots)
```

**File names:**
```bash
# Lowercase with dashes
deployment.yaml         ✓
service-account.yaml    ✓
Deployment.yaml         ✗
deployment_file.yaml    ✗
```

**Template names:**
```bash
# Helpers start with underscore
_helpers.tpl            ✓ (not rendered)
deployment.yaml         ✓ (rendered)
```

### Complete Example Chart

```bash
# Create chart
helm create webapp

# Chart.yaml
cat > webapp/Chart.yaml <<EOF
apiVersion: v2
name: webapp
description: A simple web application
type: application
version: 0.1.0
appVersion: "1.0.0"
maintainers:
  - name: DevOps Team
    email: devops@example.com
EOF

# values.yaml
cat > webapp/values.yaml <<EOF
replicaCount: 2

image:
  repository: nginx
  pullPolicy: IfNotPresent
  tag: "1.25-alpine"

service:
  type: ClusterIP
  port: 80

resources:
  limits:
    cpu: 200m
    memory: 256Mi
  requests:
    cpu: 100m
    memory: 128Mi
EOF

# templates/deployment.yaml (simplified)
cat > webapp/templates/deployment.yaml <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "webapp.fullname" . }}
  labels:
    {{- include "webapp.labels" . | nindent 4 }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      {{- include "webapp.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "webapp.selectorLabels" . | nindent 8 }}
    spec:
      containers:
      - name: {{ .Chart.Name }}
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
        imagePullPolicy: {{ .Values.image.pullPolicy }}
        ports:
        - name: http
          containerPort: 80
          protocol: TCP
        resources:
          {{- toYaml .Values.resources | nindent 10 }}
EOF
```

### Best Practices

**1. Use SemVer 2 for versions:**
```yaml
version: 1.2.3       # MAJOR.MINOR.PATCH
version: 1.2.3-rc.1  # Pre-release
```

**2. Keep templates simple:**
```yaml
# Good: Simple, readable
replicas: {{ .Values.replicaCount }}

# Avoid: Complex logic in templates
replicas: {{ if .Values.production }}5{{ else }}1{{ end }}
```

**3. Document values:**
```yaml
# values.yaml
# Number of pod replicas
# Default: 1
# Production: 3+
replicaCount: 1
```

**4. Use YAML formatting:**
```yaml
# 2 spaces for indentation (no tabs)
spec:
  replicas: 2
  template:
    spec:
      containers:
      - name: app
```

**5. Version app separately:**
```yaml
# Chart version (chart changes)
version: 0.2.0

# App version (application changes)
appVersion: "1.5.2"
```

### Chart Metadata Best Practices

**Comprehensive Chart.yaml:**
```yaml
apiVersion: v2
name: myapp
version: 1.2.3
kubeVersion: ">=1.24.0"
description: >
  A production-ready web application with Redis cache,
  PostgreSQL database, and comprehensive monitoring.
type: application

keywords:
  - web
  - api
  - microservices
  - production

home: https://github.com/myorg/myapp
sources:
  - https://github.com/myorg/myapp
  - https://github.com/myorg/myapp-charts

maintainers:
  - name: DevOps Team
    email: devops@example.com
    url: https://github.com/myorg
  - name: John Doe
    email: john@example.com

icon: https://example.com/assets/myapp-icon.png

appVersion: "2.1.0"

dependencies:
  - name: redis
    version: ~17.3.0
    repository: https://charts.bitnami.com/bitnami
    condition: redis.enabled
  - name: postgresql
    version: ~12.1.0
    repository: https://charts.bitnami.com/bitnami
    condition: postgresql.enabled

annotations:
  category: Applications
  licenses: Apache-2.0
  artifacthub.io/changes: |
    - kind: added
      description: Added Redis cache support
    - kind: fixed
      description: Fixed ingress TLS configuration
  artifacthub.io/links: |
    - name: Documentation
      url: https://docs.example.com/myapp
    - name: Support
      url: https://support.example.com
```

**Artifact Hub annotations:**
```yaml
annotations:
  # Change log
  artifacthub.io/changes: |
    - kind: added
      description: New feature X
    - kind: fixed
      description: Bug fix in component A
  
  # Links
  artifacthub.io/links: |
    - name: Documentation
      url: https://docs.example.com
```

### Chart Documentation

**README.md structure:**
```markdown
# MyApp Helm Chart

## Introduction
Brief description of what this chart deploys.

## Prerequisites
- Kubernetes 1.24+
- Helm 3.8+
- PV provisioner support (for persistence)

## Installation

### Add repository
\`\`\`bash
helm repo add myrepo https://charts.example.com
helm repo update
\`\`\`

### Install chart
\`\`\`bash
helm install myapp myrepo/myapp
\`\`\`

## Configuration

### Common parameters
| Parameter | Description | Default |
|-----------|-------------|---------|
| `replicaCount` | Number of replicas | `1` |
| `image.repository` | Image repository | `myapp` |
| `image.tag` | Image tag | `1.0.0` |
| `service.type` | Service type | `ClusterIP` |

### Redis parameters
| Parameter | Description | Default |
|-----------|-------------|---------|
| `redis.enabled` | Enable Redis | `false` |
| `redis.auth.password` | Redis password | `""` |

## Examples

### Production deployment
\`\`\`bash
helm install myapp myrepo/myapp -f prod-values.yaml
\`\`\`

### With custom values
\`\`\`bash
helm install myapp myrepo/myapp \
  --set replicaCount=3 \
  --set redis.enabled=true
\`\`\`

## Upgrading
\`\`\`bash
helm upgrade myapp myrepo/myapp
\`\`\`

## Uninstallation
\`\`\`bash
helm uninstall myapp
\`\`\`

## Troubleshooting
Common issues and solutions.
```

**values.yaml with comments:**
```yaml
## @section Global parameters
## @descriptionStart
## Global values are used to override values across all subcharts.
## @descriptionEnd

## @param global.imageRegistry Global Docker image registry
global:
  imageRegistry: ""

## @section Common parameters

## @param replicaCount Number of application replicas
## @default 1
replicaCount: 1

## @param nameOverride String to partially override fullname
nameOverride: ""

## @param fullnameOverride String to fully override fullname
fullnameOverride: ""

## @section Image parameters

image:
  ## @param image.repository Application image repository
  repository: nginx
  
  ## @param image.pullPolicy Image pull policy
  ## @default IfNotPresent
  pullPolicy: IfNotPresent
  
  ## @param image.tag Overrides the image tag (defaults to chart appVersion)
  tag: ""

## @section Service parameters

service:
  ## @param service.type Kubernetes Service type
  ## @default ClusterIP
  type: ClusterIP
  
  ## @param service.port Service HTTP port
  port: 80
```

### Chart Testing

**Test suite structure:**
```
templates/tests/
├── test-connection.yaml       # Basic connectivity test
└── test-api-response.yaml     # API endpoint test
```

**API response test:**
```yaml
# templates/tests/test-api-response.yaml
apiVersion: v1
kind: Pod
metadata:
  name: "{{ include "mychart.fullname" . }}-test-api"
  annotations:
    "helm.sh/hook": test
spec:
  containers:
  - name: api-test
    image: curlimages/curl:latest
    command: ['curl', '-f', 'http://{{ include "mychart.fullname" . }}:{{ .Values.service.port }}/health']
  restartPolicy: Never
```


### Chart Development Workflow

**1. Create chart skeleton:**
```bash
helm create mychart
cd mychart
```

**2. Customize templates:**
```bash
# Remove unused templates
rm templates/hpa.yaml templates/serviceaccount.yaml

# Edit remaining templates
vim templates/deployment.yaml
```

**3. Update values:**
```bash
vim values.yaml
```

**4. Validate:**
```bash
# Lint
helm lint .

# Dry run
helm install test . --dry-run --debug

# Template
helm template test .
```

**5. Package:**
```bash
helm package .
```

**6. Test installation:**
```bash
helm install test ./mychart-0.1.0.tgz
helm test test
helm uninstall test
```
