---

## Introduction

DaemonSets ensure that all (or some) nodes run a copy of a specific Pod. As nodes are added to the cluster, Pods are automatically added. As nodes are removed, those Pods are garbage collected. DaemonSets are ideal for cluster-wide services like log collection, monitoring agents, and storage daemons.

## Key Concepts Summary

### What is a DaemonSet?

```
Cluster
├── Node 1 → DaemonSet Pod
├── Node 2 → DaemonSet Pod
├── Node 3 → DaemonSet Pod
└── Node 4 → DaemonSet Pod

(One pod per node automatically)
```

**Typical use cases:**
- **Log collectors:** Fluent Bit, Fluentd, Logstash
- **Monitoring agents:** Prometheus Node Exporter, Datadog agent
- **Storage daemons:** Ceph, GlusterFS
- **Network plugins:** Calico, Weave Net
- **Security agents:** Falco, Sysdig

### Basic DaemonSet

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: fluentd
  labels:
    app: fluentd
spec:
  selector:
    matchLabels:
      app: fluentd
  template:
    metadata:
      labels:
        app: fluentd
    spec:
      containers:
      - name: fluentd
        image: fluent/fluentd:v1.14
        resources:
          limits:
            memory: 200Mi
          requests:
            cpu: 100m
            memory: 200Mi
        volumeMounts:
        - name: varlog
          mountPath: /var/log
        - name: varlibdockercontainers
          mountPath: /var/lib/docker/containers
          readOnly: true
      
      terminationGracePeriodSeconds: 30
      
      volumes:
      - name: varlog
        hostPath:
          path: /var/log
      - name: varlibdockercontainers
        hostPath:
          path: /var/lib/docker/containers
```

**Key features:**
- Automatically runs on all nodes
- New nodes automatically get the pod
- Removed nodes cleanup pods automatically
- Often uses hostPath volumes

### Managing DaemonSets

```bash
# Create DaemonSet
kubectl apply -f daemonset.yaml

# Get DaemonSets
kubectl get daemonsets

# Detailed status
kubectl describe daemonset fluentd

# Get pods
kubectl get pods -l app=fluentd -o wide

# Check which nodes have the pod
kubectl get pods -l app=fluentd -o wide | awk '{print $7}'
```

### Node Selection

**Run on all nodes (default):**
```yaml
spec:
  template:
    spec:
      containers:
      - name: app
        image: myapp:1.0
```

**Run on specific nodes with nodeSelector:**
```yaml
spec:
  template:
    spec:
      nodeSelector:
        disktype: ssd  # Only nodes with this label
      containers:
      - name: app
        image: myapp:1.0
```

**Run on nodes with node affinity:**
```yaml
spec:
  template:
    spec:
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: kubernetes.io/os
                operator: In
                values:
                - linux
      containers:
      - name: app
        image: myapp:1.0
```

**Exclude nodes with taints:**
```bash
# Taint node (prevents DaemonSet pods)
kubectl taint nodes node1 dedicated=special-user:NoSchedule

# DaemonSet with toleration
```

```yaml
spec:
  template:
    spec:
      tolerations:
      - key: dedicated
        operator: Equal
        value: special-user
        effect: NoSchedule
      containers:
      - name: app
        image: myapp:1.0
```

### Tolerations for Control Plane

**Run on master/control plane nodes:**
```yaml
spec:
  template:
    spec:
      tolerations:
      - key: node-role.kubernetes.io/control-plane
        effect: NoSchedule
      - key: node-role.kubernetes.io/master
        effect: NoSchedule
      containers:
      - name: monitoring-agent
        image: prometheus/node-exporter:latest
```

### Update Strategies

**RollingUpdate (default):**
```yaml
spec:
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1  # Update one node at a time
```

**Process:**
```
1. Delete pod on Node 1
2. Create new pod on Node 1
3. Wait for Ready
4. Delete pod on Node 2
5. Create new pod on Node 2
... (continues)
```

**OnDelete (manual):**
```yaml
spec:
  updateStrategy:
    type: OnDelete
```

Pods only updated when manually deleted.

### Performing Updates

**Update image:**
```bash
kubectl set image daemonset/fluentd fluentd=fluent/fluentd:v1.15
```

**Or update YAML:**
```yaml
spec:
  template:
    spec:
      containers:
      - name: fluentd
        image: fluent/fluentd:v1.15  # Updated
```

```bash
kubectl apply -f daemonset.yaml
```

**Monitor rollout:**
```bash
kubectl rollout status daemonset/fluentd
```

### Best Practices

**1. Set resource limits:**
```yaml
resources:
  limits:
    memory: 200Mi
    cpu: 200m
  requests:
    memory: 100Mi
    cpu: 100m
```

**2. Use tolerations appropriately:**
```yaml
tolerations:
- operator: Exists  # Run on all nodes including control plane
```

**3. Configure graceful termination:**
```yaml
terminationGracePeriodSeconds: 30
```

**4. Use hostNetwork when needed:**
```yaml
hostNetwork: true  # For network plugins, monitoring
```

**5. Implement update strategy:**
```yaml
updateStrategy:
  rollingUpdate:
    maxUnavailable: 1
```

### DaemonSet Use Cases in Detail

**1. Log Collection Architecture:**
```
┌─────────────────────────────────────┐
│ Application Pods                     │
│ Write logs to /var/log/containers   │
└──────────────┬──────────────────────┘

┌─────────────────────────────────────┐
```

### DaemonSet Scheduling Deep Dive

**Node Affinity for Specific Hardware:**
```yaml
spec:
  template:
    spec:
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: feature.node.kubernetes.io/gpu
                operator: Exists
              - key: nvidia.com/gpu.present
                operator: In
                values:
                - "true"
```

**Multiple Node Selectors:**
```yaml
spec:
  template:
    spec:
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: kubernetes.io/os
                operator: In
                values:
                - linux
              - key: node.kubernetes.io/instance-type
                operator: In
                values:
                - m5.xlarge
                - m5.2xlarge
```

### Testing DaemonSets

**Verify deployment:**
```bash
# Count nodes
NODE_COUNT=$(kubectl get nodes --no-headers | wc -l)

# Count DaemonSet pods
POD_COUNT=$(kubectl get pods -l app=myapp --no-headers | wc -l)

# Should match
if [ "$NODE_COUNT" -eq "$POD_COUNT" ]; then
  echo "DaemonSet deployed correctly"
else
  echo "Missing pods on some nodes"
fi
```

**Check distribution:**
```bash
# Show which node each pod is on
kubectl get pods -l app=myapp -o custom-columns=NAME:.metadata.name,NODE:.spec.nodeName --sort-by=.spec.nodeName
```

### Troubleshooting

**Pods not scheduled on all nodes:**
```bash
kubectl get daemonset fluentd
kubectl describe daemonset fluentd

# Check:
# - Node taints
# - Node selectors
# - Resource constraints
```

**Check node taints:**
```bash
kubectl describe nodes | grep Taints
```

**Pods failing to start:**
```bash
kubectl get pods -l app=fluentd
kubectl describe pod <pod-name>
kubectl logs <pod-name>

# Common issues:
# - hostPath permissions
# - Resource limits
# - Image pull errors
```

**Update stuck:**
```bash
kubectl rollout status daemonset/fluentd
kubectl get pods -l app=fluentd -o wide

# Check pod status on each node
```
