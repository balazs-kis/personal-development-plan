By the end of this lesson, you will be able to:
- Understand Jobs and when to use them

- Configure parallel and sequential job execution
- Use CronJobs for scheduled tasks
- Handle job failures and retries
- Clean up completed jobs automatically

---

## Introduction

Jobs and CronJobs are designed for batch processing and scheduled tasks. Unlike Deployments that run continuously, Jobs run to completion and track success or failure. CronJobs create Jobs on a schedule, similar to cron but with Kubernetes reliability guarantees. They're perfect for database migrations, backups, reports, and cleanup tasks.

## Key Concepts Summary

### What is a Job?

**Job:** Runs a container to completion, ensuring it finishes successfully.

```
Regular Deployment:     Job:
Run forever            Run once → Success/Failure
Restart if crashes     Retry if fails (up to limit)
Always running         Terminates when done
```

**Use cases:**
- Database migrations
- Data imports/exports
- Batch processing
- One-time setup tasks
- Report generation

### Basic Job

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: pi-calculation
spec:
  template:
    spec:
      containers:
      - name: pi
        image: perl:5.34
        command: ["perl", "-Mbignum=bpi", "-wle", "print bpi(2000)"]
      restartPolicy: Never  # or OnFailure
  backoffLimit: 4  # Retry 4 times on failure
```

**Key fields:**
- `restartPolicy`: Never or OnFailure (not Always!)
- `backoffLimit`: Max retries before marking as failed
- `completions`: How many successful completions needed
- `parallelism`: How many pods to run in parallel

### Managing Jobs

```bash
# Create job
kubectl apply -f job.yaml

# Get jobs
kubectl get jobs

# Detailed status
kubectl describe job pi-calculation

# Get pods
kubectl get pods -l job-name=pi-calculation

# View logs
kubectl logs job/pi-calculation

# Delete job (and its pods)
kubectl delete job pi-calculation
```

**Job status:**
```bash
kubectl get jobs

# Output:
# NAME             COMPLETIONS   DURATION   AGE
# pi-calculation   1/1           5s         1m
```

### Job Completion Modes

**Single completion (default):**
```yaml
spec:
  completions: 1  # Run once successfully
  template:
    # Pod spec...
```

**Multiple completions (sequential):**
```yaml
spec:
  completions: 5  # Need 5 successful runs
  parallelism: 1  # Run one at a time
  template:
    # Pod spec...
```

**Parallel execution:**
```yaml
spec:
  completions: 10  # Need 10 successes
  parallelism: 3   # Run 3 at once
  template:
    # Pod spec...
```

**Work queue pattern:**
```yaml
spec:
  parallelism: 5   # 5 workers
  # No completions = run until queue empty
  template:
    # Pod spec that processes queue items
```

### Retry and Failure Handling

**Configure retries:**
```yaml
spec:
  backoffLimit: 4  # Retry up to 4 times
  template:
    spec:
      restartPolicy: OnFailure  # Restart container on failure
```

**Or never restart:**
```yaml
spec:
  backoffLimit: 4
  template:
    spec:
      restartPolicy: Never  # Create new pod on failure
```

**Backoff behavior:**
```
Failure 1: Wait 10s
Failure 2: Wait 20s
Failure 3: Wait 40s
Failure 4: Wait 80s
Max wait: 6 minutes
```

### Automatic Cleanup

**TTL after finished:**
```yaml
spec:
  ttlSecondsAfterFinished: 300  # Delete 5 minutes after completion
```

**Without TTL, manually clean up:**
```bash
# Delete completed jobs
kubectl delete job --field-selector=status.successful=1

# Delete failed jobs
kubectl delete job --field-selector=status.failed=1
```

### Practical Job Examples

**Database Migration:**
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migration
spec:
  backoffLimit: 3
  ttlSecondsAfterFinished: 600
  template:
    spec:
      containers:
      - name: migrate
        image: myapp:1.2.0
        command: ["npm", "run", "migrate"]
        env:
        - name: DATABASE_URL
          valueFrom:
            secretKeyRef:
              name: db-secret
              key: url
      restartPolicy: OnFailure
```

**Data Import:**
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: data-import
spec:
  completions: 1
  backoffLimit: 2
  template:
    spec:
      containers:
      - name: importer
        image: data-import:1.0
        args: ["--file", "/data/import.csv"]
        volumeMounts:
        - name: data
          mountPath: /data
      volumes:
      - name: data
        persistentVolumeClaim:
          claimName: import-data-pvc
      restartPolicy: Never
```

### CronJobs

**CronJob:** Creates Jobs on a recurring schedule.

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup
spec:
  schedule: "0 2 * * *"  # 2 AM daily
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: backup
            image: backup-tool:1.0
            command: ["backup.sh"]
            env:
            - name: BACKUP_LOCATION
              value: "s3://backups/db"
          restartPolicy: OnFailure
```

**Schedule format (cron syntax):**
```
┌─────── minute (0 - 59)
│ ┌─────── hour (0 - 23)
│ │ ┌─────── day of month (1 - 31)
│ │ │ ┌─────── month (1 - 12)
│ │ │ │ ┌─────── day of week (0 - 6) (Sunday=0)
│ │ │ │ │
* * * * *
```

**Examples:**
```yaml
# Every minute
schedule: "* * * * *"

# Every hour
schedule: "0 * * * *"

# Daily at 2 AM
schedule: "0 2 * * *"

# Every Sunday at 3 AM
schedule: "0 3 * * 0"

# 1st of every month at midnight
schedule: "0 0 1 * *"

# Every 15 minutes
schedule: "*/15 * * * *"

# Weekdays at 9 AM
schedule: "0 9 * * 1-5"
```

**Predefined schedules:**
```yaml
schedule: "@hourly"   # 0 * * * *
schedule: "@daily"    # 0 0 * * *
schedule: "@weekly"   # 0 0 * * 0
schedule: "@monthly"  # 0 0 1 * *
schedule: "@yearly"   # 0 0 1 1 *
```

### CronJob Configuration

**Concurrency policy:**
```yaml
spec:
  concurrencyPolicy: Allow  # Allow concurrent jobs (default)
  # Or:
  # Replace  - Kill old job, start new one
  # Forbid   - Skip new job if old still running
```

**History limits:**
```yaml
spec:
  successfulJobsHistoryLimit: 3  # Keep last 3 successful
  failedJobsHistoryLimit: 1      # Keep last failed
```

**Starting deadline:**
```yaml
spec:
  startingDeadlineSeconds: 200  # Must start within 200s of scheduled time
```

**Suspend:**
```yaml
spec:
  suspend: true  # Temporarily disable CronJob
```

### Complete CronJob Example

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: database-backup
  namespace: production
spec:
  schedule: "0 2 * * *"  # 2 AM daily
  successfulJobsHistoryLimit: 7  # Keep 1 week
  failedJobsHistoryLimit: 3
  concurrencyPolicy: Forbid
  startingDeadlineSeconds: 300
  
  jobTemplate:
    spec:
      backoffLimit: 2
      ttlSecondsAfterFinished: 86400  # Clean up after 24h
      
      template:
        metadata:
          labels:
            app: backup
        spec:
          containers:
          - name: backup
            image: postgres:15
            command:
            - /bin/bash
            - -c
            - |
              pg_dump -h $DB_HOST -U $DB_USER $DB_NAME | \
              gzip > /backup/db-$(date +%Y%m%d-%H%M%S).sql.gz
            env:
            - name: DB_HOST
              value: "postgres-service"
            - name: DB_USER
              valueFrom:
                secretKeyRef:
                  name: db-credentials
                  key: username
            - name: PGPASSWORD
              valueFrom:
                secretKeyRef:
                  name: db-credentials
                  key: password
            - name: DB_NAME
              value: "production"
            volumeMounts:
            - name: backup-storage
              mountPath: /backup
          
          volumes:
          - name: backup-storage
            persistentVolumeClaim:
              claimName: backup-pvc
          
          restartPolicy: OnFailure
```

### Managing CronJobs

```bash
# Create CronJob
kubectl apply -f cronjob.yaml

# Get CronJobs
kubectl get cronjobs

# Detailed info
kubectl describe cronjob backup

# Get jobs created by CronJob
kubectl get jobs -l cronjob=backup

# Manually trigger CronJob
kubectl create job --from=cronjob/backup backup-manual

# Suspend CronJob
kubectl patch cronjob backup -p '{"spec":{"suspend":true}}'

# Resume CronJob
kubectl patch cronjob backup -p '{"spec":{"suspend":false}}'

# Delete CronJob
kubectl delete cronjob backup
```

### Practical CronJob Examples

**Cleanup old data:**
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: cleanup-old-logs
spec:
  schedule: "0 0 * * *"  # Daily at midnight
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: cleanup
            image: busybox
            command:
            - /bin/sh
            - -c
            - find /logs -type f -mtime +30 -delete
            volumeMounts:
            - name: logs
              mountPath: /logs
          volumes:
          - name: logs
            hostPath:
              path: /var/log/app
          restartPolicy: OnFailure
```

**Generate reports:**
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: daily-report
spec:
  schedule: "0 6 * * *"  # 6 AM daily
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: report
            image: report-generator:1.0
            args: ["--type", "daily", "--date", "$(date -d 'yesterday' +%Y-%m-%d)"]
            env:
            - name: SMTP_HOST
              value: "smtp.company.com"
          restartPolicy: OnFailure
```

### Best Practices

**1. Set TTL for cleanup:**
```yaml
ttlSecondsAfterFinished: 3600  # 1 hour
```

**2. Configure retry limits:**
```yaml
backoffLimit: 3  # Reasonable retries
```

**3. Use proper restart policy:**
```yaml
restartPolicy: OnFailure  # Usually best for jobs
```

**4. Set history limits:**
```yaml
successfulJobsHistoryLimit: 3
failedJobsHistoryLimit: 1
```

**5. Handle concurrency:**
```yaml
concurrencyPolicy: Forbid  # For critical tasks
```

**6. Use resource limits:**
```yaml
resources:
  limits:
    memory: "512Mi"
    cpu: "500m"
```

### Advanced Job Patterns

**Indexed Job (Kubernetes 1.24+):**
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: indexed-job
spec:
  completions: 5
  parallelism: 2
  completionMode: Indexed
  template:
    spec:
      containers:
      - name: worker
        image: myworker:1.0
        env:
        - name: JOB_COMPLETION_INDEX
          valueFrom:
            fieldRef:
              fieldPath: metadata.annotations['batch.kubernetes.io/job-completion-index']
        command: ["process-index", "$(JOB_COMPLETION_INDEX)"]
      restartPolicy: Never
```

**Job with Init Container:**
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: job-with-init
spec:
  template:
    spec:
      initContainers:
      - name: setup
        image: busybox
        command: ['sh', '-c', 'echo Setting up... && sleep 5']
      containers:
      - name: main
        image: busybox
        command: ['sh', '-c', 'echo Processing... && sleep 10']
      restartPolicy: Never
```

**Job with Sidecar Pattern:**
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: job-with-sidecar
spec:
  template:
    spec:
      containers:
      - name: main
        image: myapp:1.0
        command: ["process-data"]
      - name: log-shipper
        image: fluent-bit:1.9
        volumeMounts:
        - name: logs
          mountPath: /logs
      volumes:
      - name: logs
        emptyDir: {}
      restartPolicy: Never
```

### CronJob Advanced Patterns

**Time Zone Support (Kubernetes 1.27+):**
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup-with-timezone
spec:
  schedule: "0 2 * * *"
  timeZone: "America/New_York"  # Specific timezone
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: backup
            image: backup:1.0
          restartPolicy: OnFailure
```

**Chained CronJobs:**
```yaml
# Job 1: Extract
apiVersion: batch/v1
kind: CronJob
metadata:
  name: etl-extract
spec:
  schedule: "0 1 * * *"
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: extract
            image: etl:1.0
            command: ["extract.sh"]
          restartPolicy: OnFailure

---
# Job 2: Transform (runs after extract)
apiVersion: batch/v1
kind: CronJob
metadata:
  name: etl-transform
spec:
  schedule: "0 2 * * *"  # 1 hour later
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: transform
            image: etl:1.0
            command: ["transform.sh"]
          restartPolicy: OnFailure
```

### Monitoring Jobs and CronJobs

**Job metrics:**
```bash
# Check job completion rate
kubectl get jobs -o json | jq '.items | length as $total | 
  [.[] | select(.status.succeeded == 1)] | length as $successful | 
  ($successful / $total * 100)'

# Failed jobs
kubectl get jobs --field-selector status.successful!=1
```

**CronJob monitoring:**
```bash
# Last schedule time
kubectl get cronjob backup -o jsonpath='{.status.lastScheduleTime}'

# Active jobs
kubectl get cronjob backup -o jsonpath='{.status.active}'

# Last successful time
kubectl get cronjob backup -o jsonpath='{.status.lastSuccessfulTime}'
```

**Prometheus alerts:**
```yaml
# Alert on failed CronJob
- alert: CronJobFailed
  expr: kube_job_status_failed{job=~".*cronjob.*"} > 0
  for: 5m
  annotations:
    summary: "CronJob {{ $labels.job }} failed"

# Alert on missed CronJob
- alert: CronJobMissed
  expr: time() - kube_cronjob_status_last_schedule_time > 3600
  for: 15m
  annotations:
    summary: "CronJob {{ $labels.cronjob }} hasn't run in 1 hour"
```

### Troubleshooting

**Job not completing:**
```bash
kubectl describe job <job-name>
kubectl get pods -l job-name=<job-name>
kubectl logs <pod-name>
```

**CronJob not running:**
```bash
kubectl describe cronjob <name>
# Check:
# - Schedule syntax
# - Suspended status
# - Starting deadline
```

**Too many jobs accumulating:**
```bash
# Set history limits
successfulJobsHistoryLimit: 3
failedJobsHistoryLimit: 1

# Or set TTL
ttlSecondsAfterFinished: 600
```

**Job failing repeatedly:**
```bash
kubectl logs <pod-name>
kubectl describe pod <pod-name>

# Check:
# - Backoff limit
# - Resource constraints
# - Application errors
```

```yaml

      template:
```

```yaml
            - /bin/sh
```

```bash
kubectl apply -f hello-cronjob.yaml

kubectl get jobs --watch
```

```bash

```

4. **Clean up:**
```bash
kubectl delete cronjob hello-cron
kubectl delete job hello
```
