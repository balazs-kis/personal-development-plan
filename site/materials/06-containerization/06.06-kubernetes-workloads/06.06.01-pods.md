## Introduction

Pods are the smallest and simplest unit in the Kubernetes object model. A Pod represents a single instance of a running process in your cluster and can contain one or more containers that share storage, network, and specifications for how to run. Understanding Pods is fundamental to working with Kubernetes.

## Key Concepts Summary

### What is a Pod?

```
┌────────────────────────────────────────┐
│              POD                        │
│                                         │
│  ┌──────────────┐  ┌──────────────┐   │
│  │ Container 1  │  │ Container 2  │   │
│  │   (nginx)    │  │   (sidecar)  │   │
│  └──────────────┘  └──────────────┘   │
│                                         │
│  Shared:                                │
│  • Network namespace (IP address)       │
│  • IPC namespace                        │
│  • Volumes                              │
│  • Hostname                             │
└────────────────────────────────────────┘
```

**Key characteristics:**
- Pods are the atomic unit of scheduling
- Containers in a pod share network and storage
- Each pod gets a unique IP address
- Containers in a pod can communicate via localhost
- Pods are ephemeral (not durable)

### Single-Container Pod

Most common pattern - one container per pod:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
    tier: frontend
spec:
  containers:
  - name: nginx
    image: nginx:1.21
    ports:
    - containerPort: 80
    resources:
      requests:
        memory: "64Mi"
        cpu: "250m"
      limits:
        memory: "128Mi"
        cpu: "500m"
```

**Create and manage:**
```bash
# Create pod
kubectl apply -f nginx-pod.yaml

# Get pods
kubectl get pods

# Describe pod (detailed info)
kubectl describe pod nginx-pod

# Get pod logs
kubectl logs nginx-pod

# Execute command in pod
kubectl exec nginx-pod -- nginx -v

# Interactive shell
kubectl exec -it nginx-pod -- /bin/bash

# Delete pod
kubectl delete pod nginx-pod
```

### Multi-Container Pods

Multiple containers that need to work closely together:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-app
spec:
  containers:
  # Main application
  - name: app
    image: myapp:1.0
    ports:
    - containerPort: 8080
    volumeMounts:
    - name: shared-data
      mountPath: /app/data
  
  # Sidecar: log collector
  - name: log-collector
    image: fluent/fluent-bit:latest
    volumeMounts:
    - name: shared-data
      mountPath: /logs
      readOnly: true
  
  volumes:
  - name: shared-data
    emptyDir: {}
```

**When to use:**
- Sidecar pattern (logging, monitoring)
- Ambassador pattern (proxy requests)
- Adapter pattern (standardize output)

### Common Sidecar Patterns

**1. Logging Sidecar:**
```yaml
spec:
  containers:
  - name: app
    image: myapp:1.0
    volumeMounts:
    - name: logs
      mountPath: /var/log/app
  
  - name: log-shipper
    image: fluent-bit:latest
    volumeMounts:
    - name: logs
      mountPath: /var/log/app
      readOnly: true
  
  volumes:
  - name: logs
    emptyDir: {}
```

**2. Proxy Sidecar:**
```yaml
spec:
  containers:
  - name: app
    image: myapp:1.0
    env:
    - name: HTTP_PROXY
      value: "http://localhost:8080"
  
  - name: proxy
    image: envoyproxy/envoy:v1.20
    ports:
    - containerPort: 8080
```

### Init Containers

Run before main containers, must complete successfully:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  initContainers:
  # Run database migrations
  - name: init-db
    image: myapp:1.0
    command: ['sh', '-c', 'npm run migrate']
    env:
    - name: DATABASE_URL
      valueFrom:
        secretKeyRef:
          name: db-secret
          key: url
  
  # Wait for service to be available
  - name: wait-for-service
    image: busybox:1.28
    command: ['sh', '-c', 
      'until nslookup database-service; do echo waiting; sleep 2; done']
  
  containers:
  - name: app
    image: myapp:1.0
    ports:
    - containerPort: 8080
```

**Init container use cases:**
- Database migrations
- Waiting for dependencies
- Downloading configurations
- Setting up volumes

### Pod Lifecycle

**Pod Phases:**
```
Pending → Running → Succeeded/Failed
```

**Phase descriptions:**
- **Pending:** Accepted but not yet running (downloading images, scheduling)
- **Running:** At least one container is running
- **Succeeded:** All containers terminated successfully
- **Failed:** All containers terminated, at least one failed
- **Unknown:** State cannot be obtained

**Container States:**
- **Waiting:** Initial state, pulling image or waiting for conditions
- **Running:** Container is executing
- **Terminated:** Container finished or was stopped

**Check pod status:**
```bash
kubectl get pods

# Output:
# NAME         READY   STATUS    RESTARTS   AGE
# nginx-pod    1/1     Running   0          5m
# init-pod     0/1     Init:0/2  0          10s
# failed-pod   0/1     Error     3          2m
```

### Container Probes

**Liveness Probe** - Is container alive?
```yaml
livenessProbe:
  httpGet:
    path: /health
    port: 8080
  initialDelaySeconds: 15
  periodSeconds: 10
  timeoutSeconds: 3
  failureThreshold: 3
```

**Readiness Probe** - Is container ready to serve traffic?
```yaml
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5
  timeoutSeconds: 2
```

**Startup Probe** - Has container started?
```yaml
startupProbe:
  httpGet:
    path: /startup
    port: 8080
  initialDelaySeconds: 0
  periodSeconds: 10
  failureThreshold: 30  # 5 minutes
```

**Probe types:**
- `httpGet` - HTTP GET request
- `tcpSocket` - TCP connection
- `exec` - Execute command

### Resource Management

**Resource requests (scheduling):**
```yaml
resources:
  requests:
    memory: "256Mi"
    cpu: "250m"       # 0.25 CPU cores
  limits:
    memory: "512Mi"
    cpu: "500m"       # 0.5 CPU cores
```

**What happens:**
- **Requests:** Guaranteed resources, used for scheduling
- **Limits:** Maximum resources, container throttled/killed if exceeded

### Volumes in Pods

**EmptyDir (temporary):**
```yaml
volumes:
- name: cache
  emptyDir: {}

containers:
- name: app
  volumeMounts:
  - name: cache
    mountPath: /cache
```

**ConfigMap volume:**
```yaml
volumes:
- name: config
  configMap:
    name: app-config

containers:
- name: app
  volumeMounts:
  - name: config
    mountPath: /etc/config
```

**PersistentVolumeClaim:**
```yaml
volumes:
- name: data
  persistentVolumeClaim:
    claimName: app-pvc

containers:
- name: app
  volumeMounts:
  - name: data
    mountPath: /data
```

### Pod Security

**Security Context (pod-level):**
```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  fsGroup: 2000
  seccompProfile:
    type: RuntimeDefault
```

**Security Context (container-level):**
```yaml
containers:
- name: app
  securityContext:
    allowPrivilegeEscalation: false
    readOnlyRootFilesystem: true
    runAsNonRoot: true
    runAsUser: 1000
    capabilities:
      drop:
      - ALL
```

**Complete secure pod:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secure-app
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    fsGroup: 2000
    seccompProfile:
      type: RuntimeDefault
  
  containers:
  - name: app
    image: myapp:1.0
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop:
        - ALL
    volumeMounts:
    - name: tmp
      mountPath: /tmp
    - name: cache
      mountPath: /cache
  
  volumes:
  - name: tmp
    emptyDir: {}
  - name: cache
    emptyDir: {}
```

### Pod Networking

**Pod IP Address:**
```bash
# Get pod IP
kubectl get pod nginx -o jsonpath='{.status.podIP}'

# Pods can communicate directly via IP
# From pod A:
curl http://10.244.1.5:8080
```

**DNS Resolution:**
```bash
# Service DNS: <service-name>.<namespace>.svc.cluster.local
curl http://api-service.default.svc.cluster.local

# Pod DNS: <pod-ip-with-dashes>.<namespace>.pod.cluster.local
curl http://10-244-1-5.default.pod.cluster.local
```

**Port Mapping:**
```yaml
spec:
  containers:
  - name: app
    image: myapp:1.0
    ports:
    - name: http
      containerPort: 8080
      protocol: TCP
    - name: metrics
      containerPort: 9090
      protocol: TCP
```

### Pod Quality of Service (QoS)

**Guaranteed (highest priority):**
```yaml
resources:
  requests:
    memory: "256Mi"
    cpu: "500m"
  limits:
    memory: "256Mi"  # Same as requests
    cpu: "500m"      # Same as requests
```

**Burstable (medium priority):**
```yaml
resources:
  requests:
    memory: "128Mi"
    cpu: "250m"
  limits:
    memory: "512Mi"  # Higher than requests
    cpu: "1000m"
```

**BestEffort (lowest priority):**
```yaml
# No resources specified
# First to be evicted under pressure
```

**Check QoS class:**
```bash
kubectl get pod nginx -o jsonpath='{.status.qosClass}'
```

### Pod Disruption Budgets

**Protect pods during voluntary disruptions:**
```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: myapp-pdb
spec:
  minAvailable: 2  # Always keep at least 2 running
  selector:
    matchLabels:
      app: myapp
```

**Or use maxUnavailable:**
```yaml
spec:
  maxUnavailable: 1  # Allow max 1 unavailable
  selector:
    matchLabels:
      app: myapp
```

### Pod Affinity and Anti-Affinity

**Schedule pods together:**
```yaml
affinity:
  podAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
    - labelSelector:
        matchExpressions:
        - key: app
          operator: In
          values:
          - cache
      topologyKey: kubernetes.io/hostname
```

**Schedule pods apart:**
```yaml
affinity:
  podAntiAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
    - weight: 100
      podAffinityTerm:
        labelSelector:
          matchExpressions:
          - key: app
            operator: In
            values:
            - web
        topologyKey: kubernetes.io/hostname
```

### Pod Termination

**Graceful shutdown:**
```yaml
spec:
  terminationGracePeriodSeconds: 30  # Default
  
  containers:
  - name: app
    image: myapp:1.0
    lifecycle:
      preStop:
        exec:
          command: ["/bin/sh", "-c", "sleep 15"]
```

**Termination process:**
```
1. Pod marked for deletion
2. PreStop hook executed (if defined)
3. SIGTERM sent to containers
4. Grace period timer starts (30s default)
5. Containers continue running
6. If still running after grace period → SIGKILL
7. Pod removed from API server
```

### Troubleshooting Pods

**Common issues:**

**1. ImagePullBackOff:**
```bash
kubectl describe pod <pod-name>
# Check: image name, registry access, imagePullSecrets
```

**2. CrashLoopBackOff:**
```bash
kubectl logs <pod-name>
kubectl logs <pod-name> --previous  # Previous instance
# Check: application errors, liveness probe failures
```

**3. Pending:**
```bash
kubectl describe pod <pod-name>
# Check: insufficient resources, node selectors, taints
```

**4. Container not starting:**
```bash
kubectl logs <pod-name> -c <container-name>
kubectl describe pod <pod-name>
# Check: init containers, resource limits, dependencies
```

1. **Create a simple pod:**
```yaml
# nginx-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
  labels:
    app: nginx
spec:
  containers:
  - name: nginx
    image: nginx:alpine
    ports:
    - containerPort: 80
```

```bash
kubectl apply -f nginx-pod.yaml
kubectl get pods
kubectl describe pod nginx
```

2. **Create multi-container pod:**
```yaml
# multi-container.yaml
apiVersion: v1
kind: Pod
metadata:
  name: multi-container
spec:
  containers:
  - name: nginx
    image: nginx:alpine
    volumeMounts:
    - name: html
      mountPath: /usr/share/nginx/html
  
  - name: content-creator
    image: busybox
    command: ['sh', '-c', 
      'while true; do echo $(date) > /html/index.html; sleep 10; done']
    volumeMounts:
    - name: html
      mountPath: /html
  
  volumes:
  - name: html
    emptyDir: {}
```

3. **Test the pod:**
```bash
kubectl apply -f multi-container.yaml
kubectl get pods
kubectl port-forward multi-container 8080:80
# Visit http://localhost:8080
```

4. **Check logs:**
```bash
kubectl logs multi-container -c nginx
kubectl logs multi-container -c content-creator
```
