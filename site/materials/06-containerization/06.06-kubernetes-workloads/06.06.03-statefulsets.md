## Introduction

StatefulSets are designed for applications that require stable network identities, persistent storage, and ordered deployment/scaling. Unlike Deployments where Pods are interchangeable, StatefulSets maintain a sticky identity for each Pod, making them ideal for databases, message queues, and other stateful workloads.

## Key Concepts Summary

### StatefulSet vs Deployment

| Aspect | Deployment | StatefulSet |
|--------|-----------|-------------|
| **Pod Identity** | Random names | Stable, ordered names |
| **Network** | Random IPs | Stable hostnames |
| **Storage** | Shared or random | Dedicated per pod |
| **Scaling** | Random order | Ordered (0,1,2...) |
| **Updates** | Parallel | Sequential |
| **Use Case** | Stateless apps | Databases, clusters |

### StatefulSet Guarantees

1. **Stable Network Identity**
   - Each Pod gets a persistent hostname
   - Format: `<statefulset-name>-<ordinal>`
   - Example: `mysql-0`, `mysql-1`, `mysql-2`

2. **Stable Storage**
   - Each Pod gets its own PersistentVolumeClaim
   - Storage persists across pod rescheduling
   - Not deleted when StatefulSet scales down

3. **Ordered Deployment and Scaling**
   - Pods created sequentially: 0, then 1, then 2...
   - Next pod waits for previous to be Running and Ready
   - Scaling down happens in reverse: 2, then 1, then 0...

4. **Ordered Updates**
   - Rolling updates happen in reverse order
   - Each pod updated only after next one is Running and Ready

### Basic StatefulSet

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx
  labels:
    app: nginx
spec:
  ports:
  - port: 80
    name: web
  clusterIP: None  # Headless service!
  selector:
    app: nginx
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: web
spec:
  serviceName: "nginx"  # Must match headless service
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
        ports:
        - containerPort: 80
          name: web
        volumeMounts:
        - name: www
          mountPath: /usr/share/nginx/html
  volumeClaimTemplates:
  - metadata:
      name: www
    spec:
      accessModes: [ "ReadWriteOnce" ]
      resources:
        requests:
          storage: 1Gi
```

**Key components:**
- **Headless Service** (`clusterIP: None`): Enables direct pod addressing
- **serviceName**: Links StatefulSet to headless service
- **volumeClaimTemplates**: Creates PVC for each pod

### Headless Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mysql
spec:
  clusterIP: None  # Headless!
  selector:
    app: mysql
  ports:
  - port: 3306
    name: mysql
```

**Purpose:**
- Provides stable DNS entries for each pod
- DNS format: `<pod-name>.<service-name>.<namespace>.svc.cluster.local`
- Example: `mysql-0.mysql.default.svc.cluster.local`

**Without headless service:**
```
Service → Load balances to random pod
```

**With headless service:**
```
mysql-0.mysql.default.svc.cluster.local → Directly to mysql-0
mysql-1.mysql.default.svc.cluster.local → Directly to mysql-1
mysql-2.mysql.default.svc.cluster.local → Directly to mysql-2
```

### Persistent Storage

**volumeClaimTemplates** creates a PVC for each pod:

```yaml
volumeClaimTemplates:
- metadata:
    name: data
  spec:
    accessModes: [ "ReadWriteOnce" ]
    storageClassName: "fast-ssd"
    resources:
      requests:
        storage: 10Gi
```

**Result:**
```
web-0 → data-web-0 (10Gi PVC)
web-1 → data-web-1 (10Gi PVC)
web-2 → data-web-2 (10Gi PVC)
```

**Important:** PVCs are NOT deleted when StatefulSet is deleted!

```bash
# Delete StatefulSet
kubectl delete statefulset web

# PVCs still exist!
kubectl get pvc
# data-web-0   Bound    10Gi
# data-web-1   Bound    10Gi
# data-web-2   Bound    10Gi

# Manual cleanup required
kubectl delete pvc data-web-0 data-web-1 data-web-2
```

### Ordered Deployment Example

```bash
# Create StatefulSet with 3 replicas
kubectl apply -f statefulset.yaml

# Watch pods come up
kubectl get pods -w

# Order:
# 1. web-0 created
# 2. Wait for web-0 to be Running and Ready
# 3. web-1 created
# 4. Wait for web-1 to be Running and Ready
# 5. web-2 created
```

### Scaling

**Scale up:**
```bash
kubectl scale statefulset web --replicas=5

# Order: web-3, then web-4
```

**Scale down:**
```bash
kubectl scale statefulset web --replicas=2

# Order: web-4 deleted, then web-3
```

**Update replicas declaratively:**
```yaml

  replicas: 5
```

```bash
kubectl apply -f statefulset.yaml
```

### Update Strategies

**RollingUpdate (default):**
```yaml
spec:
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      partition: 0  # Update all pods
```

**Process:**
```
Update web-2 → Wait for Ready → Update web-1 → Wait → Update web-0
(Reverse ordinal order)
```

**Partitioned rollout:**
```yaml
updateStrategy:
  rollingUpdate:
    partition: 2  # Only update pods >= ordinal 2
```

**OnDelete:**
```yaml
updateStrategy:
  type: OnDelete  # Manual updates only
```

### StatefulSet for MySQL Cluster

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mysql
spec:
  clusterIP: None
  selector:
    app: mysql
  ports:
  - port: 3306
    name: mysql
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      initContainers:
      - name: init-mysql
        image: mysql:8.0
        command:
        - bash
        - "-c"
        - |
          set -ex
          # Generate server-id from pod ordinal
          [[ $(hostname) =~ -([0-9]+)$ ]] || exit 1
          ordinal=${BASH_REMATCH[1]}
          echo [mysqld] > /mnt/conf.d/server-id.cnf
          echo server-id=$((100 + $ordinal)) >> /mnt/conf.d/server-id.cnf
        volumeMounts:
        - name: conf
          mountPath: /mnt/conf.d
      
      containers:
      - name: mysql
        image: mysql:8.0
        env:
        - name: MYSQL_ROOT_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-secret
              key: password
        ports:
        - containerPort: 3306
          name: mysql
        volumeMounts:
        - name: data
          mountPath: /var/lib/mysql
        - name: conf
          mountPath: /etc/mysql/conf.d
        
        livenessProbe:
          exec:
            command: ["mysqladmin", "ping"]
          initialDelaySeconds: 30
          periodSeconds: 10
        
        readinessProbe:
          exec:
            command:
            - bash
            - "-c"
            - mysql -h 127.0.0.1 -e 'SELECT 1'
          initialDelaySeconds: 5
          periodSeconds: 2
      
      volumes:
      - name: conf
        emptyDir: {}
  
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 10Gi
```

### Best Practices

**1. Always use headless service:**
```yaml
spec:
  clusterIP: None
```

**2. Set pod management policy for faster scaling:**
```yaml
spec:
  podManagementPolicy: Parallel  # Instead of OrderedReady
```

**3. Configure readiness probes:**
```yaml
readinessProbe:
  exec:
    command: ["check-health.sh"]
  initialDelaySeconds: 10
```

**4. Use init containers for setup:**
```yaml
initContainers:
- name: setup
  image: busybox
  command: ["sh", "-c", "setup-script.sh"]
```

**5. Backup PVCs regularly:**
```bash
# Create snapshots or backup to cloud storage
```

### StatefulSet Patterns

**Leader Election Pattern:**
```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: leader-election
spec:
  serviceName: election
  replicas: 3
  selector:
    matchLabels:
      app: election
  template:
    spec:
      containers:
      - name: app
        image: myapp:1.0
        env:
        - name: POD_NAME
          valueFrom:
            fieldRef:
              fieldPath: metadata.name
        - name: IS_LEADER
          value: "$([ $POD_NAME = 'leader-election-0' ] && echo 'true' || echo 'false')"
```

**Primary-Replica Pattern (MySQL):**
```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      initContainers:
      - name: init-mysql
        image: mysql:8.0
        command:
        - bash
        - "-c"
        - |
          set -ex
          # Determine if this is primary (ordinal 0) or replica
          [[ $(hostname) =~ -([0-9]+)$ ]] || exit 1
          ordinal=${BASH_REMATCH[1]}
          
          if [[ $ordinal -eq 0 ]]; then
            # Primary configuration
            cat > /mnt/conf.d/server.cnf <<EOF
          [mysqld]
          server-id=1
          log-bin=mysql-bin
          binlog-format=ROW
          EOF
          else
            # Replica configuration
            cat > /mnt/conf.d/server.cnf <<EOF
          [mysqld]
          server-id=$((100 + $ordinal))
          relay-log=mysql-relay-bin
          EOF
          fi
        volumeMounts:
        - name: conf
          mountPath: /mnt/conf.d
      
      containers:
      - name: mysql
        image: mysql:8.0
        ports:
        - containerPort: 3306
        volumeMounts:
        - name: data
          mountPath: /var/lib/mysql
        - name: conf
          mountPath: /etc/mysql/conf.d
      
      volumes:
      - name: conf
        emptyDir: {}
  
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 10Gi
```

**Shard Pattern (MongoDB):**
```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mongodb-shard
spec:
  serviceName: mongodb
  replicas: 3
  selector:
    matchLabels:
      app: mongodb
      role: shard
  template:
    spec:
      containers:
      - name: mongodb
        image: mongo:6.0
        command:
        - mongod
        - "--replSet"
        - "rs0"
        - "--bind_ip_all"
        ports:
        - containerPort: 27017
        volumeMounts:
        - name: data
          mountPath: /data/db
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 20Gi
```

### StatefulSet vs Deployment Decision Tree

```
Need persistent storage per pod?
├─ Yes → StatefulSet
└─ No
   │
   Need stable network identity?
   ├─ Yes → StatefulSet
   └─ No
      │
      Need ordered startup/shutdown?
      ├─ Yes → StatefulSet
      └─ No → Deployment
```

**StatefulSet use cases:**
- Databases (MySQL, PostgreSQL, MongoDB)
- Message queues (Kafka, RabbitMQ)
- Distributed systems (Elasticsearch, Cassandra)
- Leader election scenarios
- Any stateful clustered application

**Deployment use cases:**
- Web servers
- API backends
- Microservices
- Worker pools
- Any stateless application

### Advanced StatefulSet Configuration

**Partition updates:**
```yaml
spec:
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      partition: 2
# Only pods with ordinal >= 2 will be updated
# Allows testing new version on subset
```

**Persistent Volume Reclaim Policy:**
```yaml
apiVersion: v1
kind: StorageClass
metadata:
  name: stateful-storage
provisioner: kubernetes.io/aws-ebs
reclaimPolicy: Retain  # Keep PV after PVC deletion
volumeBindingMode: WaitForFirstConsumer
```

### Monitoring StatefulSets

**Key metrics to track:**
```bash
# Current replicas vs desired
kubectl get statefulset myapp -o jsonpath='{.status.currentReplicas}/{.spec.replicas}'

# Ready replicas
kubectl get statefulset myapp -o jsonpath='{.status.readyReplicas}'

# Update revision
kubectl get statefulset myapp -o jsonpath='{.status.updateRevision}'
```

**Set up alerts:**
```yaml
# Prometheus alert example
- alert: StatefulSetReplicasMismatch
  expr: |
    kube_statefulset_status_replicas_ready != kube_statefulset_status_replicas
  for: 15m
  annotations:
    summary: "StatefulSet replicas mismatch"
```

### Troubleshooting

**Pod stuck in Pending:**
```bash
kubectl describe pod mysql-0
# Check: PVC binding, storage class, resources
```

**Pod won't start in order:**
```bash
kubectl describe pod mysql-1
# Previous pod must be Running and Ready
kubectl get pods
```

**PVC not binding:**
```bash
kubectl get pvc
kubectl describe pvc data-mysql-0
# Check: StorageClass, PV availability
```

**Deleting StatefulSet stuck:**
```bash
# Force delete pod
kubectl delete pod mysql-0 --grace-period=0 --force

# Delete StatefulSet
kubectl delete statefulset mysql --cascade=orphan
```
