# Lesson 3: Read-Only Filesystems and Security Contexts

## Learning Objectives

By the end of this lesson, you will be able to:
- Configure containers with read-only root filesystems
- Create volume mounts for writable directories
- Use security contexts to enhance container security
- Drop unnecessary Linux capabilities
- Prevent privilege escalation in containers

---

## Introduction

A read-only root filesystem prevents attackers from modifying binaries, installing malware, or tampering with application files if they compromise your container. Combined with dropped capabilities and proper security contexts, this creates multiple layers of defense against attacks.

## Key Concepts Summary

### Read-Only Root Filesystem

**Enable read-only filesystem:**
```bash
docker run --read-only myapp
```

**Problem:**
Many applications need to write temporary files:
```
Error: Cannot write to /tmp
Error: Cannot write to /var/log
```

**Solution:** Mount specific directories as writable:
```bash
docker run --read-only \
  --tmpfs /tmp \
  --tmpfs /var/run \
  -v app-logs:/var/log \
  myapp
```

### Dockerfile for Read-Only Containers

```dockerfile
FROM node:18-alpine

# Create user
RUN addgroup -g 1001 nodejs && \
    adduser -S nodejs -u 1001

# Create writable directories
RUN mkdir -p /app/temp /app/logs && \
    chown -R nodejs:nodejs /app

USER nodejs
WORKDIR /app

COPY --chown=nodejs:nodejs package*.json ./
RUN npm ci --production

COPY --chown=nodejs:nodejs . .

# Declare volumes for writable paths
VOLUME /app/temp
VOLUME /app/logs

CMD ["node", "server.js"]
```

**Run with read-only:**
```bash
docker run -d \
  --read-only \
  --tmpfs /app/temp \
  -v logs:/app/logs \
  myapp
```

### .NET with Read-Only Filesystem

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app/publish

FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
WORKDIR /app

# Install dependencies
RUN apk add --no-cache icu-libs

# Create user and directories
RUN addgroup -g 1000 appgroup && \
    adduser -D -u 1000 -G appgroup appuser && \
    mkdir -p /app/temp /app/logs && \
    chown -R appuser:appgroup /app

USER 1000:1000

# Copy application
COPY --from=build --chown=1000:1000 /app/publish .

# Configure for read-only filesystem
ENV ASPNETCORE_URLS=http://+:8080 \
    DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=false \
    TMPDIR=/app/temp

# Declare writable volumes
VOLUME /app/temp
VOLUME /app/logs

EXPOSE 8080

ENTRYPOINT ["dotnet", "MyApp.dll"]
```

**Run:**
```bash
docker run -d \
  --read-only \
  --tmpfs /app/temp:uid=1000,gid=1000 \
  -v app-logs:/app/logs \
  myapp
```

### Linux Capabilities

Linux divides root privileges into **capabilities**. Drop unnecessary ones:

**Common capabilities:**
- `CHOWN` - Change file ownership
- `NET_BIND_SERVICE` - Bind to ports < 1024
- `SETUID/SETGID` - Change user/group IDs
- `SYS_ADMIN` - Administrative operations
- `NET_ADMIN` - Network configuration

**Drop all capabilities:**
```bash
docker run --cap-drop ALL myapp
```

**Add specific capabilities back:**
```bash
docker run \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  myapp
```

**Example: Web server needing port 80:**
```bash
docker run \
  --user 1000 \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  -p 80:80 \
  nginx
```

### Security Options

**No new privileges:**
```bash
docker run --security-opt=no-new-privileges myapp
```

Prevents processes from gaining additional privileges via setuid binaries.

**AppArmor profile:**
```bash
docker run --security-opt apparmor=docker-default myapp
```

**SELinux label:**
```bash
docker run --security-opt label=level:s0:c100,c200 myapp
```

**Seccomp profile:**
```bash
docker run --security-opt seccomp=profile.json myapp
```

### Kubernetes Security Context

**Pod-level security:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 1000
    fsGroup: 1000
    seccompProfile:
      type: RuntimeDefault
  
  containers:
  - name: app
    image: myapp:latest
    securityContext:
      # Container-level settings
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop:
          - ALL
        add:
          - NET_BIND_SERVICE
    
    volumeMounts:
    - name: temp
      mountPath: /app/temp
    - name: logs
      mountPath: /app/logs
  
  volumes:
  - name: temp
    emptyDir: {}
  - name: logs
    emptyDir: {}
```

### Pod Security Standards

Kubernetes defines three security levels:

**Privileged (default):**
- No restrictions
- Not recommended

**Baseline:**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: baseline-pod
spec:
  securityContext:
    runAsNonRoot: true
  containers:
  - name: app
    image: myapp
    securityContext:
      allowPrivilegeEscalation: false
```

**Restricted (most secure):**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: restricted-pod
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    fsGroup: 1000
    seccompProfile:
      type: RuntimeDefault
  containers:
  - name: app
    image: myapp
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      capabilities:
        drop:
          - ALL
```

### Docker Compose Security

```yaml
version: '3.8'

services:

      - logs:/app/logs

  logs:
```

### Testing Security Configuration

**Verify non-root:**
```bash
docker exec mycontainer whoami
docker exec mycontainer id
```

**Try escalation (should fail):**
```bash
docker exec mycontainer sudo su -
# Should fail with "command not found" or "permission denied"
```

**Test filesystem:**
```bash
docker exec mycontainer touch /test.txt
# Should fail on read-only filesystem

# Should succeed
docker exec mycontainer touch /tmp/test.txt
```

**Check capabilities:**
```bash
docker exec mycontainer cat /proc/1/status | grep Cap
```

### Troubleshooting Read-Only Filesystems

**Common issues and solutions:**

**Issue 1: Application writes to unexpected locations**
```bash
# Find what files app tries to write
docker run --rm --read-only myapp 2>&1 | grep "Read-only file system"

# Or use strace
docker run --rm --cap-add SYS_PTRACE myapp strace -e open,openat node server.js 2>&1 | grep EROFS
```

**Issue 2: Cache directories**
```dockerfile
# Many frameworks write cache files
# .NET
ENV DOTNET_EnableDiagnostics=0
ENV DOTNET_CLI_TELEMETRY_OPTOUT=1

# Node.js
ENV NPM_CONFIG_CACHE=/tmp/.npm
ENV NODE_OPTIONS="--max-old-space-size=460"

# Python
ENV PYTHONDONTWRITEBYTECODE=1
```

**Issue 3: TLS/SSL certificate stores**
```dockerfile
# Some apps need to write to cert stores
RUN mkdir -p /app/.dotnet/corefx/cryptography/x509stores && \
    chown -R appuser:appgroup /app/.dotnet

# Mount as volume
VOLUME /app/.dotnet
```

**Issue 4: Package managers**
```dockerfile
# Install dependencies before switching to read-only
# Don't allow runtime package installation
RUN npm ci --production && \
    npm cache clean --force && \
    rm -rf /root/.npm /tmp/*
```

### Automated Security Testing

**Verify filesystem is read-only:**
```bash
# Try to write to root filesystem
docker run --rm --read-only myapp sh -c "echo test > /test.txt"
# Should fail: sh: can't create /test.txt: Read-only file system

# Verify writable volumes work
docker run --rm --read-only --tmpfs /tmp myapp sh -c "echo test > /tmp/test.txt && cat /tmp/test.txt"
# Should succeed
```

**Automated test script:**
```bash
#!/bin/bash
# test-readonly.sh

IMAGE="myapp:latest"

echo "Testing read-only filesystem..."

# Test 1: Root filesystem should be read-only
docker run --rm --read-only $IMAGE sh -c "echo test > /test.txt" 2>&1 | grep -q "Read-only"
if [ $? -eq 0 ]; then
    echo "✓ Root filesystem is read-only"
else
    echo "✗ Root filesystem is writable!"
    exit 1
fi

# Test 2: Temp directory should be writable
docker run --rm --read-only --tmpfs /tmp $IMAGE sh -c "echo test > /tmp/test.txt && cat /tmp/test.txt" | grep -q "test"
if [ $? -eq 0 ]; then
    echo "✓ Temp directory is writable"
else
    echo "✗ Temp directory is not writable!"
    exit 1
fi

# Test 3: Application should start successfully
docker run --rm --read-only --tmpfs /tmp -d --name test-readonly $IMAGE
sleep 5
docker logs test-readonly | grep -q "Started"
if [ $? -eq 0 ]; then
    echo "✓ Application starts with read-only filesystem"
    docker stop test-readonly
else
    echo "✗ Application fails with read-only filesystem!"
    docker logs test-readonly
    docker stop test-readonly
    exit 1
fi

echo "All tests passed!"
```

### Performance and Compliance

**Read-only filesystem performance:**
```
Benefits:
✓ Slightly faster reads (no write tracking)
✓ Better caching (immutable content)
✓ Reduced I/O contention

Overhead:
- Minimal to negligible
- tmpfs volumes are memory-backed (fast)
```

**CIS Docker Benchmark requirements:**
```
5.12: Ensure the container's root filesystem is mounted as read-only
5.25: Ensure that the container is restricted from acquiring additional privileges
5.3:  Verify that containers are running only a single main process
```

**Implementation:**
```bash
docker run \
  --read-only \
  --security-opt=no-new-privileges \
  --init \
  myapp
```

2. **Run with maximum security:**
```bash
docker run -d \
  --name secure-app \
  --read-only \
  --tmpfs /app/temp:uid=1000,gid=1000 \
  --cap-drop ALL \
  --security-opt=no-new-privileges \
  -p 8080:8080 \
  myapp
```

3. **Verify security:**
```bash
# Check user
docker exec secure-app id

# Try to write (should fail)
docker exec secure-app touch /test.txt

# Check process capabilities
docker exec secure-app grep Cap /proc/1/status
```

4. **Deploy to Kubernetes with full security:**
```yaml
# secure-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: secure-api
spec:
  replicas: 2
  selector:
    matchLabels:
      app: secure-api
  template:
    metadata:
      labels:
        app: secure-api
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
        fsGroup: 1000
        seccompProfile:
          type: RuntimeDefault
      
      containers:
      - name: api
        image: myapp:latest
        
        securityContext:
          allowPrivilegeEscalation: false
          readOnlyRootFilesystem: true
          capabilities:
            drop:
              - ALL
        
        resources:
          requests:
            memory: "256Mi"
            cpu: "250m"
          limits:
            memory: "512Mi"
            cpu: "500m"
        
        volumeMounts:
        - name: tmp
          mountPath: /tmp
        - name: app-temp
          mountPath: /app/temp
        
        ports:
        - containerPort: 8080
        
        livenessProbe:
          httpGet:
            path: /health
            port: 8080
          initialDelaySeconds: 10
          periodSeconds: 10
        
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 5
      
      volumes:
      - name: tmp
        emptyDir: {}
      - name: app-temp
        emptyDir: {}
```

```bash
kubectl apply -f secure-deployment.yaml
kubectl get pods
kubectl exec secure-api-xxx -- id
kubectl exec secure-api-xxx -- touch /test.txt  # Should fail
```

5. **Test with different security levels:**
