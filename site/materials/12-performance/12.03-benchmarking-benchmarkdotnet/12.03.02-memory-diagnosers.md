# Lesson 2: Memory Diagnosers and Allocation Tracking

## Learning Objectives

By the end of this lesson, you will be able to:
- Use MemoryDiagnoser to track allocations
- Understand GC generation metrics
- Identify memory allocation hotspots
- Compare memory efficiency of different implementations
- Interpret memory diagnoser output correctly

---

## Introduction

Memory allocations impact performance through garbage collection overhead. MemoryDiagnoser tracks allocations, GC pressure, and memory efficiency, helping you identify code that allocates unnecessarily and optimize memory usage.

## Key Concepts Summary

### Enabling Memory Diagnoser

**Class-Level Attribute (All Methods)**
```csharp
[MemoryDiagnoser]
public class AllocationBenchmarks
{
    [Benchmark]
    public string StringConcat() { /* ... */ }
    
    [Benchmark]
    public string StringBuilder() { /* ... */ }
}
```

**Assembly-Level Configuration**
```csharp
[assembly: MemoryDiagnoser]

namespace MyBenchmarks
{
    public class MyBenchmarks
    {
        // All benchmarks in assembly track memory
    }
}
```

### Understanding Memory Output

```
|          Method |     Mean | Allocated |
|---------------- |---------:|----------:|
|    StringConcat | 10.5 us  |   50.1 KB |
|   StringBuilder |  1.2 us  |    0.5 KB |
```

**Key Metrics:**
- **Allocated:** Total memory allocated during benchmark execution
- **Gen0, Gen1, Gen2:** Number of GC collections per 1000 operations
- **Allocated Native:** Native memory allocations (if applicable)

### GC Generation Metrics

```
| Method |     Mean |  Gen0 |  Gen1 | Allocated |
|------- |---------:|------:|------:|----------:|
| Method1 | 100.0 us | 0.50 | 0.25 |    10 KB |
| Method2 | 150.0 us | 2.00 | 1.00 |    50 KB |
```

**Interpretation:**
- **Gen0:** Short-lived objects (collected frequently)
- **Gen1:** Medium-lived objects (collected less frequently)
- **Gen2:** Long-lived objects (collected rarely, most expensive)
- **Higher Gen0/Gen1 counts:** More GC pressure, potential performance impact

### Example: Comparing String Operations

```csharp
[MemoryDiagnoser]
public class StringAllocationBenchmarks
{
    private const int Iterations = 1000;
    
    [Benchmark(Baseline = true)]
    public string StringConcatenation()
    {
        string result = "";
        for (int i = 0; i < Iterations; i++)
        {
            result += i.ToString();  // Creates new string each time!
        }
        return result;
    }
    
    [Benchmark]
    public string StringBuilder()
    {
        var sb = new StringBuilder(Iterations * 10);  // Pre-size
        for (int i = 0; i < Iterations; i++)
        {
            sb.Append(i);
        }
        return sb.ToString();
    }
    
    [Benchmark]
    public string StringCreate()
    {
        return string.Create(
            Iterations * 10,
            Iterations,
            (span, state) =>
            {
                int pos = 0;
                for (int i = 0; i < state; i++)
                {
                    i.TryFormat(span[pos..], out int written);
                    pos += written;
                }
            });
    }
}

// Expected Output:
// |              Method |     Mean | Allocated |
// |-------------------- |---------:|----------:|
// | StringConcatenation | 125.3 us |   50.1 KB |  ← Worst
// |      StringBuilder  |   8.2 us |    2.1 KB |  ← Better
// |        StringCreate |   5.1 us |    0.5 KB |  ← Best
```

### Tracking Collections

```csharp
[MemoryDiagnoser]
public class CollectionBenchmarks
{
    private const int Count = 10000;
    
    [Benchmark]
    public List<int> ListWithCapacity()
    {
        var list = new List<int>(Count);  // Pre-allocate capacity
        for (int i = 0; i < Count; i++)
            list.Add(i);
        return list;
    }
    
    [Benchmark]
    public List<int> ListWithoutCapacity()
    {
        var list = new List<int>();  // Grows dynamically
        for (int i = 0; i < Count; i++)
            list.Add(i);  // May trigger multiple reallocations
        return list;
    }
}

// Output shows:
// |              Method |     Mean |  Gen0 | Allocated |
// |-------------------- |---------:|------:|----------:|
// |   ListWithCapacity  |  45.2 us | 0.10 |    40 KB |
// | ListWithoutCapacity |  52.8 us | 0.25 |    80 KB |  ← More allocations
```

### ArrayPool for Zero-Allocation

```csharp
[MemoryDiagnoser]
public class ArrayPoolBenchmarks
{
    private const int Size = 1000;
    
    [Benchmark(Baseline = true)]
    public int[] RegularArray()
    {
        var array = new int[Size];  // Allocates
        for (int i = 0; i < Size; i++)
            array[i] = i * 2;
        return array;
    }
    
    [Benchmark]
    public int[] ArrayPooled()
    {
        var pool = ArrayPool<int>.Shared;
        var array = pool.Rent(Size);  // Reuses buffer
        try
        {
            for (int i = 0; i < Size; i++)
                array[i] = i * 2;
            return array[..Size].ToArray();  // Copy for return
        }
        finally
        {
            pool.Return(array);
        }
    }
}

// ArrayPool reduces allocations but adds complexity
// Use when allocations are in hot paths
```

### Memory-Efficient LINQ Alternatives

```csharp
[MemoryDiagnoser]
public class LinqAllocationBenchmarks
{
    private readonly int[] _data = Enumerable.Range(0, 10000).ToArray();
    
    [Benchmark(Baseline = true)]
    public int LinqWhereSelect()
    {
        return _data
            .Where(x => x % 2 == 0)      // Allocates enumerator
            .Select(x => x * 2)          // Allocates enumerator
            .Sum();                       // Allocates enumerator
    }
    
    [Benchmark]
    public int ForLoop()
    {
        int sum = 0;
        for (int i = 0; i < _data.Length; i++)
        {
            if (_data[i] % 2 == 0)
                sum += _data[i] * 2;
        }
        return sum;
    }
    
    [Benchmark]
    public int SpanBased()
    {
        var span = _data.AsSpan();
        int sum = 0;
        foreach (var item in span)
        {
            if (item % 2 == 0)
                sum += item * 2;
        }
        return sum;
    }
}

// ForLoop and SpanBased show zero allocations
// LinqWhereSelect shows allocations for enumerators
```

### Interpreting Memory Results

**Good Signs:**
- Low or zero allocations
- Low Gen0/Gen1 counts
- Consistent allocation patterns

**Warning Signs:**
- High allocations relative to work done
- Increasing Gen0/Gen1 counts
- Unexpected allocations in hot paths

**Example Analysis:**
```
| Method | Mean | Allocated | Gen0 |
|--------|------|-----------|------|
| Fast   | 10us | 0 B       | 0.00 |  ← Excellent
| Medium | 50us | 1 KB      | 0.10 |  ← Acceptable
| Slow   | 100us| 50 KB     | 2.00 |  ← Problem!
```

## Common Memory Benchmarking Mistakes

### Mistake 1: Not Accounting for Setup Allocations
```csharp
// ❌ Setup allocations counted in benchmark
[GlobalSetup]
public void Setup()
{
    _data = new int[10000];  // Allocated once, not per benchmark
}

[Benchmark]
public int Process()
{
    return _data.Sum();  // Only this allocation is measured
}
```

### Mistake 2: Ignoring GC Pressure
```csharp
// ❌ Focus only on execution time
[Benchmark]
public string FastButAllocates()
{
    return new string('x', 10000);  // Fast but allocates
}

// ✅ Consider both time and allocations
[MemoryDiagnoser]
[Benchmark]
public string FastButAllocates()
{
    return new string('x', 10000);  // Shows allocation cost
}
```

### Mistake 3: Not Pre-sizing Collections
```csharp
// ❌ Multiple reallocations
var list = new List<int>();
for (int i = 0; i < 10000; i++)
    list.Add(i);  // May reallocate multiple times

// ✅ Pre-size to avoid reallocations
var list = new List<int>(10000);
for (int i = 0; i < 10000; i++)
    list.Add(i);  // Single allocation
```

## Summary

MemoryDiagnoser tracks allocations and GC pressure, revealing memory efficiency differences between implementations. Use `[MemoryDiagnoser]` at the class or assembly level, interpret Allocated bytes and Gen0/Gen1/Gen2 counts, and optimize by reducing allocations in hot paths. Memory diagnostics complement execution time measurements, providing a complete picture of performance characteristics.
