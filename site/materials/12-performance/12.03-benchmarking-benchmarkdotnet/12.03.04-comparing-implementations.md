## Key Concepts Summary

### Setting a Baseline

**Marking a Baseline:**
```csharp
[MemoryDiagnoser]
public class ComparisonBenchmarks
{
    private readonly int[] _data = Enumerable.Range(0, 1000).ToArray();
    
    [Benchmark(Baseline = true)]  // ← Baseline method
    public int ForLoop()
    {
        int sum = 0;
        for (int i = 0; i < _data.Length; i++)
            sum += _data[i];
        return sum;
    }
    
    [Benchmark]
    public int Foreach()
    {
        int sum = 0;
        foreach (var item in _data)
            sum += item;
        return sum;
    }
    
    [Benchmark]
    public int LinqSum() => _data.Sum();
}

// Output:
// |  Method |     Mean | Ratio | Allocated |
// |-------- |---------:|------:|----------:|
// | ForLoop | 1.234 us |  1.00 |        - |  ← Baseline (1.00)
// | Foreach | 1.245 us |  1.01 |        - |  ← 1% slower
// | LinqSum | 1.567 us |  1.27 |     40 B |  ← 27% slower, allocates
```

**Key Points:**
- Only **one method per class** can be marked as baseline
- Baseline always shows ratio of **1.00**
- Other methods show ratio relative to baseline

### Understanding Ratio Column

**Ratio Interpretation:**
```
Ratio < 1.00  → Faster than baseline (e.g., 0.50 = 2x faster)
Ratio = 1.00  → Same speed as baseline
Ratio > 1.00  → Slower than baseline (e.g., 2.00 = 2x slower)
```

**Example Output:**
```
|  Method |     Mean | Ratio |
|-------- |---------:|------:|
| Baseline| 100.0 us |  1.00 |
| Fast    |  50.0 us |  0.50 |  ← 2x faster
| Medium  | 100.0 us |  1.00 |  ← Same speed
| Slow    | 200.0 us |  2.00 |  ← 2x slower
```

### Ratio Calculation Details

**Important:** Ratio represents the **mean of the ratio distribution**, not a simple division of means.

```csharp
// BenchmarkDotNet calculates:
// For each measurement pair:
//   ratio[i] = test_measurement[i] / baseline_measurement[i]
// Then averages all ratios

// This is different from:
//   mean_ratio = mean(test) / mean(baseline)  ← Not used!
```

**Why This Matters:**
- More statistically sound
- Accounts for variance in measurements
- RatioSD column shows standard deviation of ratios

### RatioSD Column

**When RatioSD Appears:**
```
|  Method |     Mean | Ratio | RatioSD |
|-------- |---------:|------:|--------:|
| Baseline| 100.0 us |  1.00 |      -  |
| Variable| 105.0 us |  1.05 |   0.15  |  ← High variance
```

**Interpretation:**
- **Low RatioSD (< 0.10):** Stable comparison
- **High RatioSD (> 0.20):** Unreliable comparison, high variance
- **Very High RatioSD (> 0.50):** Results may not be meaningful

### Statistical Significance

**Understanding Error and StdDev:**
```
|  Method |     Mean |    Error |   StdDev | Ratio |
|-------- |---------:|---------:|---------:|------:|
| Baseline| 100.0 us |   1.0 us |   0.9 us |  1.00 |
| Test    | 101.0 us |   1.0 us |   0.9 us |  1.01 |
```

**When Differences Matter:**
- **Error bars overlap:** Difference may not be significant
- **Error bars don't overlap:** Difference is likely significant
- **Large StdDev:** High variance, less reliable

**Example:**
```
| Method | Mean | Error | StdDev | Ratio |
|--------|------|-------|--------|-------|
| Base   | 100  | ±1    | 0.9    | 1.00  |
| Test1  | 101  | ±1    | 0.9    | 1.01  |  ← Probably not significant
| Test2  | 120  | ±2    | 1.8    | 1.20  |  ← Likely significant
```

### Comparing Multiple Implementations

```csharp
[MemoryDiagnoser]
public class AlgorithmComparisonBenchmarks
{
    private readonly int[] _data = Enumerable.Range(0, 10000).ToArray();
    
    [Benchmark(Baseline = true)]
    public int[] BubbleSort()
    {
        var copy = (int[])_data.Clone();
        // Bubble sort implementation
        return copy;
    }
    
    [Benchmark]
    public int[] QuickSort()
    {
        var copy = (int[])_data.Clone();
        Array.Sort(copy);
        return copy;
    }
    
    [Benchmark]
    public int[] LinqOrderBy()
    {
        return _data.OrderBy(x => x).ToArray();
    }
}

// Output shows clear performance differences:
// |     Method |      Mean | Ratio | Allocated |
// |----------- |----------:|------:|----------:|
// | BubbleSort | 125.3 ms  |  1.00 |    40 KB  |
// |  QuickSort |   2.1 ms  |  0.02 |    40 KB  |  ← 50x faster!
// | LinqOrderBy|   5.3 ms  |  0.04 |    80 KB  |  ← 4x faster, but allocates more
```

### Real-World Comparison Example

```csharp
[MemoryDiagnoser]
public class StringBuildingComparisonBenchmarks
{
    private const int Iterations = 10000;
    
    [Benchmark(Baseline = true)]
    public string StringConcatenation()
    {
        string result = "";
        for (int i = 0; i < Iterations; i++)
            result += i.ToString();
        return result;
    }
    
    [Benchmark]
    public string StringBuilder()
    {
        var sb = new StringBuilder();
        for (int i = 0; i < Iterations; i++)
            sb.Append(i);
        return sb.ToString();
    }
    
    [Benchmark]
    public string StringCreate()
    {
        return string.Create(
            Iterations * 10,
            Iterations,
            (span, state) =>
            {
                int pos = 0;
                for (int i = 0; i < state; i++)
                {
                    i.TryFormat(span[pos..], out int written);
                    pos += written;
                }
            });
    }
}

// Output:
// |            Method |     Mean | Ratio | Allocated |
// |------------------ |---------:|------:|----------:|
// | StringConcatenation| 125.3 us |  1.00 |   50.1 KB |  ← Baseline
// |      StringBuilder |   8.2 us |  0.07 |    2.1 KB |  ← 14x faster, 24x less memory
// |        StringCreate |   5.1 us |  0.04 |    0.5 KB |  ← 25x faster, 100x less memory
```

### Interpreting Combined Metrics

**Time vs Memory Trade-offs:**
```
| Method | Mean | Ratio | Allocated | Gen0 |
|--------|------|-------|-----------|------|
| Fast   | 10us | 0.50  | 100 KB    | 2.0  |  ← Fast but allocates
| Slow   | 20us | 1.00  |   5 KB    | 0.1  |  ← Slower but memory-efficient
```

**Decision Factors:**
- **Hot path:** Prefer faster, even if more allocations
- **Cold path:** Prefer memory-efficient
- **GC pressure:** High Gen0/Gen1 may cause pauses
- **Scalability:** Consider behavior under load

### Common Interpretation Mistakes

**Mistake 1: Ignoring Statistical Significance**
```csharp
// ❌ Wrong: "Method2 is faster!"
// | Method | Mean | Ratio |
// |--------|------|-------|
// | Method1| 100us|  1.00 |
// | Method2|  99us|  0.99 |  ← Error bars overlap, not significant

// ✅ Correct: "No significant difference"
```

**Mistake 2: Focusing Only on Mean**
```csharp
// ❌ Wrong: "Method2 is better (lower mean)"
// | Method | Mean | StdDev | Ratio |
// |--------|------|--------|-------|
// | Method1| 100us|   5us   |  1.00 |
// | Method2|  95us|  50us   |  0.95 |  ← High variance!

// ✅ Correct: Consider StdDev - Method1 is more consistent
```

**Mistake 3: Ignoring Memory Allocations**
```csharp
// ❌ Wrong: "Method2 is faster, use it!"
// | Method | Mean | Ratio | Allocated |
// |--------|------|-------|-----------|
// | Method1| 100us|  1.00 |     1 KB  |
// | Method2|  80us|  0.80 |   100 KB  |  ← 100x more allocations!

// ✅ Correct: Consider both time and memory
```

**Mistake 4: Extrapolating Results**
```csharp
// ❌ Wrong: "Method2 is faster on Windows, so it's faster everywhere"
// ✅ Correct: Results are specific to:
//   - Runtime (.NET 8.0)
//   - Platform (Windows x64)
//   - Hardware (specific CPU)
//   - Configuration (Release mode)
```

### Best Practices for Comparison

**1. Use Realistic Data**
```csharp
// ✅ Good: Production-like data
[GlobalSetup]
public void Setup()
{
    _data = LoadProductionSample(count: 10000);
}

// ❌ Bad: Artificial data
[GlobalSetup]
public void Setup()
{
    _data = new int[10000];  // All zeros, not realistic
}
```

**2. Run Multiple Times**
```csharp
// BenchmarkDotNet automatically runs multiple iterations
// But verify consistency across runs:
// Run 1: Method2 is 1.2x faster
// Run 2: Method2 is 1.25x faster
// Run 3: Method2 is 1.18x faster
// → Consistent improvement, reliable result
```

**3. Consider Context**
```csharp
// Fast method with high allocations might be fine for:
// - One-time operations
// - Low-frequency calls
// - When memory is abundant

// But problematic for:
// - Hot paths called millions of times
// - Memory-constrained environments
// - High-frequency operations
```

**4. Test at Scale**
```csharp
[Params(100, 1000, 10000, 100000)]
public int Size { get; set; }

// Method1 might be faster at Size=100
// Method2 might be faster at Size=100000
// → Choose based on actual usage patterns
```

## Practice Exercise

1. **Create comparison benchmarks for different search algorithms**:
   ```csharp
   [MemoryDiagnoser]
   public class SearchComparisonBenchmarks
   {
       [Params(100, 1000, 10000)]
       public int Size { get; set; }
       
       private int[] _sortedData;
       private HashSet<int> _hashSet;
       private int _target;
       
       [GlobalSetup]
       public void Setup()
       {
           _sortedData = Enumerable.Range(0, Size).ToArray();
           _hashSet = new HashSet<int>(_sortedData);
           _target = Size - 1;
       }
       
       [Benchmark(Baseline = true)]
       public bool LinearSearch()
       {
           return Array.IndexOf(_sortedData, _target) >= 0;
       }
       
       [Benchmark]
       public bool BinarySearch()
       {
           return Array.BinarySearch(_sortedData, _target) >= 0;
       }
       
       [Benchmark]
       public bool HashSetContains()
       {
           return _hashSet.Contains(_target);
       }
   }
   ```

2. **Analyze the results**:
   - Which method is fastest at each size?
   - How do ratios change with size?
   - What's the memory allocation difference?
   - Which method would you choose and why?

## Summary

Baseline benchmarks enable direct comparison using ratio metrics. A ratio of 1.00 is the baseline; values < 1.00 are faster, values > 1.00 are slower. Consider statistical significance (Error, StdDev, RatioSD), memory allocations, and context when interpreting results. Avoid extrapolating results to different environments, focus on realistic data, and test at multiple scales. BenchmarkDotNet's statistical analysis provides reliable comparisons when used correctly.
