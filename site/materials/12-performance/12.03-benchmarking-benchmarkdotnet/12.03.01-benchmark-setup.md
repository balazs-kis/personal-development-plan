# Lesson 1: Benchmark Setup and Configuration

## Learning Objectives

By the end of this lesson, you will be able to:
- Set up BenchmarkDotNet in a .NET project
- Create benchmark classes with proper configuration
- Configure benchmark jobs and run settings
- Run benchmarks correctly in Release mode
- Understand basic benchmark output and results

---

## Introduction

BenchmarkDotNet is the gold standard for micro-benchmarking in .NET. It handles JIT warmup, statistical analysis, and result presentation automatically, ensuring your measurements are accurate and meaningful. Proper setup and configuration are essential for reliable benchmark results.

## Key Concepts Summary

### Basic Setup

**Step 1: Create a Console Project**
```bash
dotnet new console -n MyBenchmarks
cd MyBenchmarks
```

**Step 2: Install BenchmarkDotNet**
```bash
dotnet add package BenchmarkDotNet
```

**Step 3: Create a Benchmark Class**
```csharp
using BenchmarkDotNet.Attributes;
using BenchmarkDotNet.Running;

namespace MyBenchmarks
{
    public class Md5VsSha256
    {
        private const int N = 10000;
        private readonly byte[] data;
        private readonly SHA256 sha256 = SHA256.Create();
        private readonly MD5 md5 = MD5.Create();

        public Md5VsSha256()
        {
            data = new byte[N];
            new Random(42).NextBytes(data);
        }

        [Benchmark]
        public byte[] Sha256() => sha256.ComputeHash(data);

        [Benchmark]
        public byte[] Md5() => md5.ComputeHash(data);
    }

    public class Program
    {
        public static void Main(string[] args)
        {
            var summary = BenchmarkRunner.Run<Md5VsSha256>();
        }
    }
}
```

**Step 4: Run in Release Mode**
```bash
dotnet run -c Release
```

### Benchmark Attributes

**`[Benchmark]`** - Marks a method to be benchmarked:
```csharp
[Benchmark]
public int SumArray()
{
    int sum = 0;
    for (int i = 0; i < _data.Length; i++)
        sum += _data[i];
    return sum;
}
```

**`[GlobalSetup]`** - Runs once before all benchmarks:
```csharp
private int[] _data;

[GlobalSetup]
public void Setup()
{
    _data = Enumerable.Range(0, 1000).ToArray();
}
```

**`[GlobalCleanup]`** - Runs once after all benchmarks:
```csharp
[GlobalCleanup]
public void Cleanup()
{
    _data = null;
    GC.Collect();
}
```

**`[IterationSetup]`** - Runs before each benchmark iteration:
```csharp
[IterationSetup]
public void IterationSetup()
{
    // Reset state for each iteration
}
```

**`[IterationCleanup]`** - Runs after each benchmark iteration:
```csharp
[IterationCleanup]
public void IterationCleanup()
{
    // Clean up after each iteration
}
```

### Job Configuration

**Simple Job (Default)**
```csharp
[SimpleJob(RuntimeMoniker.Net80)]
public class MyBenchmarks
{
    // Runs with .NET 8.0
}
```

**Multiple Runtimes**
```csharp
[SimpleJob(RuntimeMoniker.Net60)]
[SimpleJob(RuntimeMoniker.Net80)]
public class MyBenchmarks
{
    // Compares .NET 6.0 vs .NET 8.0
}
```

**Custom Job Configuration**
```csharp
[SimpleJob(
    RuntimeMoniker.Net80,
    warmupCount: 5,
    iterationCount: 10,
    invocationCount: 1,
    launchCount: 1)]
public class MyBenchmarks
{
    // Custom iteration and warmup counts
}
```

**Short Run (for quick testing)**
```csharp
[ShortRunJob]
public class MyBenchmarks
{
    // Faster execution, less accurate
}
```

### Running Benchmarks

**Method 1: BenchmarkRunner (Single Type)**
```csharp
public class Program
{
    public static void Main(string[] args)
    {
        BenchmarkRunner.Run<MyBenchmarks>();
    }
}
```

**Method 2: BenchmarkSwitcher (Multiple Types)**
```csharp
public class Program
{
    public static void Main(string[] args)
    {
        BenchmarkSwitcher.FromAssembly(typeof(Program).Assembly).Run(args);
    }
}

// Run specific benchmark:
// dotnet run -c Release -- --filter "*MyBenchmarks*"
```

**Key Metrics:**
- **Mean:** Average execution time
- **Error:** Half of 99.9% confidence interval
- **StdDev:** Standard deviation (measure of variance)

### Critical Configuration Rules

**1. Always Use Release Mode**
```bash
# ✅ Correct
dotnet run -c Release

# ❌ Wrong - Debug mode is 10-100x slower
dotnet run -c Debug
```

**2. Never Attach Debugger**
```
❌ Don't run benchmarks with Visual Studio debugger attached
✅ Run from command line: dotnet run -c Release
```

**3. Optimize Must Be Enabled**
```xml
<!-- In .csproj file -->
<PropertyGroup>
  <Optimize>true</Optimize>
</PropertyGroup>
```

**4. Close Unnecessary Applications**
- Close Visual Studio, browsers, and other apps
- Use maximum performance mode on laptops
- Keep laptop plugged in

## Common Setup Mistakes

### Mistake 1: Running in Debug Mode
```
❌ Problem: Results are 10-100x slower than production
✅ Solution: Always use Release configuration
```

### Mistake 2: Attached Debugger
```
❌ Problem: Debugger overhead affects measurements
✅ Solution: Run from command line without debugger
```

### Mistake 3: Wrong Project Type
```
❌ Problem: Trying to benchmark in library projects
✅ Solution: Use console application project
```

### Mistake 4: Not Returning Values
```csharp
// ❌ JIT may eliminate dead code
[Benchmark]
public void BadBenchmark()
{
    Math.Exp(1);  // Result not used!
}

// ✅ Return the result
[Benchmark]
public double GoodBenchmark()
{
    return Math.Exp(1);
}
```

## Practice Exercise

1. **Create a new console project** and install BenchmarkDotNet:
   ```bash
   dotnet new console -n StringBenchmarks
   cd StringBenchmarks
   dotnet add package BenchmarkDotNet
   ```

2. **Create benchmarks comparing string concatenation methods**:
   ```csharp
   public class StringConcatenationBenchmarks
   {
       private const int Iterations = 1000;
       
       [Benchmark(Baseline = true)]
       public string StringConcat()
       {
           string result = "";
           for (int i = 0; i < Iterations; i++)
               result += i.ToString();
           return result;
       }
       
       [Benchmark]
       public string StringBuilder()
       {
           var sb = new StringBuilder();
           for (int i = 0; i < Iterations; i++)
               sb.Append(i);
           return sb.ToString();
       }
       
       [Benchmark]
       public string StringInterpolation()
       {
           var parts = new List<string>();
           for (int i = 0; i < Iterations; i++)
               parts.Add($"{i}");
           return string.Join("", parts);
       }
   }
   ```

3. **Run the benchmarks**:
   ```bash
   dotnet run -c Release
   ```

4. **Analyze the results**:
   - Which method is fastest?
   - Which method allocates the most memory?
   - What's the performance difference?

## Summary

BenchmarkDotNet setup requires a console application, the BenchmarkDotNet NuGet package, and benchmark classes marked with `[Benchmark]` attributes. Always run benchmarks in Release mode without a debugger attached. Use `[GlobalSetup]` for initialization, configure jobs for different runtimes, and understand that Mean, Error, and StdDev metrics help interpret results. Proper setup ensures accurate, reproducible performance measurements.
