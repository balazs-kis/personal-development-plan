## Introduction

Memory leaks in .NET applications cause memory to grow unbounded over time, eventually leading to OutOfMemoryExceptions or degraded performance due to excessive garbage collection. Memory profilers help identify which objects are consuming memory and why they haven't been collected, enabling you to fix leaks and optimize memory usage.

## Key Concepts Summary

### What is Memory Profiling?

Memory profiling tracks:
- **Memory usage** (how much memory is allocated)
- **Object instances** (what types are using memory)
- **Object retention** (why objects aren't being collected)
- **GC behavior** (garbage collection frequency and impact)

### Memory Leak vs Memory Pressure

**Memory Leak:**
```csharp
// Objects unintentionally kept alive
public class EventManager
{
    private static List<EventHandler> _handlers = new();
    
    public void Subscribe(EventHandler handler)
    {
        _handlers.Add(handler);  // Never removed - leak!
    }
}
```

**Memory Pressure (Not a Leak):**
```csharp
// Intentional memory use, but needs optimization
public class CacheService
{
    private Dictionary<string, byte[]> _cache = new();
    
    public void CacheFile(string key, byte[] data)
    {
        _cache[key] = data;  // Intentional, but may need limits
    }
}
```

## Visual Studio Memory Profiler

### Memory Usage Tool

**Starting a memory profiling session:**
```
1. Open your project in Visual Studio
2. Set to Release configuration
3. Debug → Performance Profiler (Alt+F2)
4. Check "Memory Usage"
5. Click "Start"
6. Exercise the application
7. Click "Take Snapshot" at different points
8. Click "Stop Collection"
```

### Taking and Comparing Snapshots

**Workflow:**
```
1. Take Snapshot #1 (baseline)
2. Perform operation suspected of leaking
3. Take Snapshot #2
4. Repeat operation
5. Take Snapshot #3
6. Compare snapshots to find growing objects
```

**Example scenario:**
```csharp
public class MemoryLeakExample
{
    // Snapshot 1: Start app, 50 MB
    
    public void LoadDashboard()
    {
        // Load data
        var data = LoadLargeDataset();
        
        // Snapshot 2: After first load, 150 MB
        
        // Navigate away and return
        ClearDashboard();
        LoadDashboard();
        
        // Snapshot 3: After second load, 250 MB
        // ⚠️ Memory increased by 100 MB again!
        // Expected: Should return to ~150 MB
        // Indicates: Objects from first load not collected
    }
}
```

## dotMemory: Advanced Memory Profiling

### Why Use dotMemory?

**Advantages:**
- Detailed memory traffic analysis
- Visual timeline of memory usage
- Automatic snapshot comparison
- Object allocation tracking
- Cross-platform support (Windows, Linux, macOS)

### Memory Traffic Analysis

**What is Memory Traffic?**
- Shows allocations between snapshots
- Reveals short-lived objects causing GC pressure
- Identifies unexpected allocations

**Example:**
```csharp
// dotMemory shows high memory traffic here
public string ProcessRequests(List<Request> requests)
{
    string result = "";
    
    foreach (var request in requests)
    {
        // dotMemory reveals: 100,000 string allocations per second!
        result += request.ToString() + "\n";
    }
    
    return result;
}
```

### Automatic Issue Detection

dotMemory automatically identifies:
- **Similar Retained Sizes** - Objects with similar retention patterns
- **Sparse Arrays** - Arrays with mostly empty slots
- **Redundant References** - Multiple paths keeping objects alive
- **Event Handler Leaks** - Subscribers not unsubscribed

## Common Memory Leak Patterns

### Pattern 1: Event Handler Leaks

```csharp
// ❌ Leak: Event handler keeps Form alive
public class DataService
{
    public event EventHandler DataChanged;
    
    private static DataService _instance = new DataService();
}

public class CustomerForm : Form
{
    public CustomerForm()
    {
        DataService._instance.DataChanged += OnDataChanged;
        // ⚠️ Form closed but handler not removed
        // Form can't be GC'd because event holds reference
    }
    
    private void OnDataChanged(object sender, EventArgs e)
    {
        RefreshData();
    }
}

// ✅ Fixed: Unsubscribe when done
public class CustomerForm : Form
{
    public CustomerForm()
    {
        DataService._instance.DataChanged += OnDataChanged;
    }
    
    protected override void Dispose(bool disposing)
    {
        if (disposing)
        {
            DataService._instance.DataChanged -= OnDataChanged;
        }
        base.Dispose(disposing);
    }
    
    private void OnDataChanged(object sender, EventArgs e)
    {
        RefreshData();
    }
}
```

### Pattern 2: Static Collection Leaks

```csharp
// ❌ Leak: Static cache grows unbounded
public class UserCache
{
    private static Dictionary<int, User> _cache = new();
    
    public static void AddUser(User user)
    {
        _cache[user.Id] = user;  // Never removed!
    }
    
    public static User GetUser(int id)
    {
        return _cache.TryGetValue(id, out var user) ? user : null;
    }
}

// ✅ Fixed: Bounded cache with eviction
public class UserCache
{
    private static LruCache<int, User> _cache = new(maxSize: 1000);
    
    public static void AddUser(User user)
    {
        _cache.Add(user.Id, user);  // Evicts oldest when full
    }
    
    public static User GetUser(int id)
    {
        return _cache.TryGet(id, out var user) ? user : null;
    }
}
```

### Pattern 3: Captured Variables in Closures

```csharp
// ❌ Leak: Timer captures large object
public class DataProcessor
{
    private byte[] _largeBuffer = new byte[10_000_000]; // 10 MB
    
    public void StartProcessing()
    {
        var timer = new Timer(_ =>
        {
            // Lambda captures 'this', keeping _largeBuffer alive
            ProcessData();
        }, null, 0, 1000);
    }
    
    private void ProcessData()
    {
        // Processing logic (doesn't use _largeBuffer)
    }
}

// ✅ Fixed: Don't capture unnecessary variables
public class DataProcessor
{
    private byte[] _largeBuffer = new byte[10_000_000];
    
    public void StartProcessing()
    {
        // Use static method or separate class to avoid capturing 'this'
        var processor = new BackgroundProcessor();
        var timer = new Timer(_ =>
        {
            processor.ProcessData();  // Doesn't capture _largeBuffer
        }, null, 0, 1000);
    }
}
```

### Pattern 4: Finalizer Resurrection

```csharp
// ❌ Problem: Finalizer keeps object alive longer
public class ResourceHolder : IDisposable
{
    private IntPtr _handle;
    
    ~ResourceHolder()
    {
        // Finalizer runs on finalizer thread
        // Object promoted to Gen2, increasing GC pressure
        Cleanup();
    }
    
    public void Dispose()
    {
        Cleanup();
    }
    
    private void Cleanup()
    {
        if (_handle != IntPtr.Zero)
        {
            ReleaseHandle(_handle);
            _handle = IntPtr.Zero;
        }
    }
}

// ✅ Fixed: Suppress finalization when disposed
public class ResourceHolder : IDisposable
{
    private IntPtr _handle;
    
    ~ResourceHolder()
    {
        Cleanup();
    }
    
    public void Dispose()
    {
        Cleanup();
        GC.SuppressFinalize(this);  // Don't run finalizer
    }
    
    private void Cleanup()
    {
        if (_handle != IntPtr.Zero)
        {
            ReleaseHandle(_handle);
            _handle = IntPtr.Zero;
        }
    }
}
```

## Memory Profiling Workflow

### Step 1: Identify Symptoms

```csharp
// Monitor for memory leak symptoms
public class MemoryMonitor
{
    public void CheckForLeaks()
    {
        var initialMemory = GC.GetTotalMemory(forceFullCollection: true);
        
        // Perform operations
        for (int i = 0; i < 100; i++)
        {
            PerformOperation();
        }
        
        var finalMemory = GC.GetTotalMemory(forceFullCollection: true);
        var growth = finalMemory - initialMemory;
        
        if (growth > 10_000_000) // > 10 MB growth
        {
            Console.WriteLine($"⚠️ Potential leak: Memory grew by {growth / 1024 / 1024} MB");
        }
    }
}
```

### Step 2: Reproduce in Controlled Environment

```csharp
[Fact]
public void DetectMemoryLeak()
{
    var baseline = GC.GetTotalMemory(true);
    
    // Repeat operation multiple times
    for (int i = 0; i < 1000; i++)
    {
        var service = new LeakyService();
        service.ProcessData();
        // Service goes out of scope, should be collected
    }
    
    GC.Collect();
    GC.WaitForPendingFinalizers();
    GC.Collect();
    
    var afterGC = GC.GetTotalMemory(false);
    var growth = afterGC - baseline;
    
    // If memory grew significantly, there's a leak
    Assert.That(growth, Is.LessThan(1_000_000), 
        $"Memory leak detected: {growth / 1024} KB not collected");
}
```

### Step 3: Take Snapshots

```
Visual Studio:
1. Start profiling
2. Take Snapshot 1 (baseline)
3. Perform operation 10 times
4. Force GC: GC.Collect(); GC.WaitForPendingFinalizers(); GC.Collect();
5. Take Snapshot 2
6. Repeat step 3
7. Force GC
8. Take Snapshot 3
9. Compare: Snapshot 3 vs Snapshot 1
```

### Step 4: Analyze Root Causes

```
1. Sort by size delta (largest growth first)
2. Identify unexpected types growing
3. View "Paths to Root" for those types
4. Trace back to static fields or event handlers
5. Fix the leak
6. Re-profile to verify
```

## Best Practices

### 1. Use Weak References for Caches

```csharp
// Allows GC to collect cached objects under memory pressure
public class ImageCache
{
    private Dictionary<string, WeakReference<Image>> _cache = new();
    
    public Image GetImage(string key)
    {
        if (_cache.TryGetValue(key, out var weakRef) && 
            weakRef.TryGetTarget(out var image))
        {
            return image;  // Cache hit
        }
        
        // Cache miss or collected - reload
        image = LoadImage(key);
        _cache[key] = new WeakReference<Image>(image);
        return image;
    }
}
```

### 2. Implement Proper Disposal

```csharp
public class DatabaseConnection : IDisposable
{
    private SqlConnection _connection;
    private bool _disposed;
    
    public void Dispose()
    {
        Dispose(true);
        GC.SuppressFinalize(this);
    }
    
    protected virtual void Dispose(bool disposing)
    {
        if (_disposed) return;
        
        if (disposing)
        {
            // Dispose managed resources
            _connection?.Dispose();
        }
        
        // Clean up unmanaged resources here
        
        _disposed = true;
    }
}
```

### 3. Limit Collection Sizes

```csharp
public class BoundedCache<TKey, TValue>
{
    private readonly LinkedList<CacheItem> _lruList = new();
    private readonly Dictionary<TKey, LinkedListNode<CacheItem>> _cache;
    private readonly int _maxSize;
    
    public BoundedCache(int maxSize)
    {
        _maxSize = maxSize;
        _cache = new Dictionary<TKey, LinkedListNode<CacheItem>>(maxSize);
    }
    
    public void Add(TKey key, TValue value)
    {
        if (_cache.Count >= _maxSize)
        {
            // Evict oldest
            var oldest = _lruList.Last;
            _cache.Remove(oldest.Value.Key);
            _lruList.RemoveLast();
        }
        
        var item = new CacheItem { Key = key, Value = value };
        var node = _lruList.AddFirst(item);
        _cache[key] = node;
    }
}
```

### 4. Monitor Production Memory

```csharp
public class MemoryHealthCheck : IHealthCheck
{
    private const long WarningThresholdBytes = 500_000_000; // 500 MB
    private const long CriticalThresholdBytes = 1_000_000_000; // 1 GB
    
    public Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken ct = default)
    {
        var memoryUsed = GC.GetTotalMemory(forceFullCollection: false);
        
        if (memoryUsed > CriticalThresholdBytes)
        {
            return Task.FromResult(HealthCheckResult.Unhealthy(
                $"Memory usage critical: {memoryUsed / 1024 / 1024} MB"));
        }
        
        if (memoryUsed > WarningThresholdBytes)
        {
            return Task.FromResult(HealthCheckResult.Degraded(
                $"Memory usage high: {memoryUsed / 1024 / 1024} MB"));
        }
        
        return Task.FromResult(HealthCheckResult.Healthy(
            $"Memory usage normal: {memoryUsed / 1024 / 1024} MB"));
    }
}
```

## Summary

Memory profiling identifies objects consuming memory and why they aren't being collected. Use Visual Studio's Memory Usage tool for basic profiling, dotMemory for advanced analysis, and .NET diagnostic tools (dotnet-gcdump, dotnet-dump) for production scenarios. Common leak patterns include event handler leaks, static collection growth, and captured variables in closures. Always take multiple snapshots, compare them, and trace objects back to their roots to find the cause of leaks.
