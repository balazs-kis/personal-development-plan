## Introduction

Even without memory leaks, excessive allocations cause performance problems through GC pressure. Every object allocated eventually needs collection, consuming CPU time and causing latency spikes. Allocation tracking reveals where objects are created, enabling you to reduce allocations in hot paths and minimize GC impact.

## Key Concepts Summary

### What is Allocation Tracking?

Allocation tracking shows:
- **Where objects are allocated** (method, call stack)
- **How many instances** of each type
- **Total size** of allocations
- **Allocation frequency** (allocations per second)

### Why Allocations Matter

**GC Pressure:**
```
More allocations → More GC collections → Higher CPU usage → Latency spikes

Example:
Application allocates 1 GB/second
Gen0 collection every 100ms
Gen1 collection every 1 second
Gen2 collection every 10 seconds
Result: Significant CPU time spent on GC instead of actual work
```

**Performance Impact:**
- Gen0 collection: ~1ms pause
- Gen1 collection: ~10ms pause  
- Gen2 collection (full GC): ~100ms+ pause

**Goal:** Reduce allocations in hot paths to minimize GC frequency.

## Common Allocation Patterns and Fixes

### Pattern 1: String Concatenation in Loops

```csharp
// ❌ Allocates many strings
public string BuildReport(List<Order> orders)
{
    string report = "Orders:\n";
    
    foreach (var order in orders)
    {
        // Each += creates a new string
        report += $"Order {order.Id}: ${order.Total}\n";
    }
    
    return report;
}

// Allocation tracking shows:
// System.String: 10,000 allocations, 5 MB
// System.Char[]: 10,000 allocations, 4 MB

// ✅ Use StringBuilder
public string BuildReport(List<Order> orders)
{
    var sb = new StringBuilder(orders.Count * 50);
    sb.AppendLine("Orders:");
    
    foreach (var order in orders)
    {
        sb.AppendLine($"Order {order.Id}: ${order.Total}");
    }
    
    return sb.ToString();
}

// Allocation tracking shows:
// System.String: 1 allocation, 50 KB (result only)
// System.Char[]: 1-2 allocations (StringBuilder internal buffer)
```

### Pattern 2: LINQ in Hot Paths

```csharp
// ❌ Creates many intermediate objects
public List<CustomerDto> GetActiveCustomers()
{
    return _customers
        .Where(c => c.IsActive)           // Allocates enumerator
        .Select(c => new CustomerDto      // Allocates DTOs
        {
            Name = c.Name,
            Email = c.Email
        })
        .OrderBy(c => c.Name)             // Allocates for sorting
        .ToList();                         // Allocates list
}

// ✅ Optimize allocation-heavy path
public List<CustomerDto> GetActiveCustomers()
{
    var activeCount = _customers.Count(c => c.IsActive);
    var result = new List<CustomerDto>(activeCount);  // Pre-size
    
    foreach (var customer in _customers)
    {
        if (customer.IsActive)
        {
            result.Add(new CustomerDto
            {
                Name = customer.Name,
                Email = customer.Email
            });
        }
    }
    
    result.Sort((a, b) => string.Compare(a.Name, b.Name));
    return result;
}
```

### Pattern 3: Boxing Value Types

```csharp
// ❌ Boxing allocates on heap
public void LogValues(List<int> numbers)
{
    foreach (var num in numbers)
    {
        // int boxed to object - allocation!
        _logger.LogInformation("Value: {Value}", num);
    }
}

// Allocation tracking shows:
// System.Int32 (boxed): 10,000 allocations

// ✅ Avoid boxing with generic constraints
public void LogValues<T>(List<T> values)
{
    foreach (var value in values)
    {
        // No boxing with generic
        _logger.LogInformation("Value: {Value}", value);
    }
}

// Or use string interpolation wisely
public void LogValues(List<int> numbers)
{
    foreach (var num in numbers)
    {
        // Convert to string explicitly, no boxing
        _logger.LogInformation($"Value: {num}");
    }
}
```

### Pattern 4: Unnecessary Array Allocations

```csharp
// ❌ Allocates array every time
public byte[] ProcessData(byte[] input)
{
    var temp = new byte[input.Length];  // Allocation!
    
    for (int i = 0; i < input.Length; i++)
    {
        temp[i] = (byte)(input[i] ^ 0xFF);
    }
    
    return temp;
}

// ✅ Use ArrayPool
public byte[] ProcessData(byte[] input)
{
    var temp = ArrayPool<byte>.Shared.Rent(input.Length);
    
    try
    {
        for (int i = 0; i < input.Length; i++)
        {
            temp[i] = (byte)(input[i] ^ 0xFF);
        }
        
        var result = new byte[input.Length];
        Array.Copy(temp, result, input.Length);
        return result;
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(temp);
    }
}

// ✅ Or use Span<T> (zero allocation)
public void ProcessData(Span<byte> input, Span<byte> output)
{
    for (int i = 0; i < input.Length; i++)
    {
        output[i] = (byte)(input[i] ^ 0xFF);
    }
}
```

### Interpreting GC Behavior

**Good GC behavior:**
```
Gen 0 GC: Every few seconds
Gen 1 GC: Every 10-30 seconds
Gen 2 GC: Rarely (minutes to hours)
% Time in GC: < 5%
```

**Problem indicators:**
```
⚠️ Gen 0 GC: Multiple per second → Too many allocations
⚠️ Gen 2 GC: Every few seconds → Long-lived objects or memory leak
⚠️ % Time in GC: > 10% → Excessive GC pressure
⚠️ High Allocation Rate: > 100 MB/sec → Reduce allocations
```

### Reducing GC Pressure

**Strategy 1: Reduce Allocation Rate**
```csharp
// Before: 100 MB/sec allocation rate
public List<string> ProcessItems(List<Item> items)
{
    var results = new List<string>();
    
    foreach (var item in items)
    {
        results.Add($"Item: {item.Name} - {item.Value}");
    }
    
    return results;
}

// After: 20 MB/sec allocation rate
public List<string> ProcessItems(List<Item> items)
{
    var results = new List<string>(items.Count);  // Pre-size
    var sb = new StringBuilder(50);
    
    foreach (var item in items)
    {
        sb.Clear();
        sb.Append("Item: ").Append(item.Name)
          .Append(" - ").Append(item.Value);
        results.Add(sb.ToString());
    }
    
    return results;
}
```

**Strategy 2: Object Pooling**
```csharp
public class ObjectPoolExample
{
    private static ObjectPool<StringBuilder> _pool = 
        new DefaultObjectPoolProvider().CreateStringBuilderPool();
    
    public string FormatData(Data data)
    {
        var sb = _pool.Get();
        
        try
        {
            sb.Append("Data: ").Append(data.Value);
            return sb.ToString();
        }
        finally
        {
            _pool.Return(sb);  // Reuse instead of GC
        }
    }
}
```

**Strategy 3: Struct Instead of Class**
```csharp
// ❌ Class: Allocates on heap
public class Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

var points = new List<Point>();
for (int i = 0; i < 1000; i++)
{
    points.Add(new Point { X = i, Y = i * 2 });  // 1000 heap allocations
}

// ✅ Struct: Allocates on stack or inline
public struct Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

var points = new List<Point>();
for (int i = 0; i < 1000; i++)
{
    points.Add(new Point { X = i, Y = i * 2 });  // 1 allocation (list), points inline
}
```

### 3. Measure Allocation Impact

public class AllocationBenchmark
{

    {

            result += i.ToString();
        return result;
    }

    [Benchmark]

### 4. Monitor Production GC

```csharp
public class GcMonitoringService : BackgroundService
{
    private readonly ILogger<GcMonitoringService> _logger;
    
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            var gen0 = GC.CollectionCount(0);
            var gen1 = GC.CollectionCount(1);
            var gen2 = GC.CollectionCount(2);
            var memory = GC.GetTotalMemory(false) / 1024 / 1024;
            
            _logger.LogInformation(
                "GC Stats - Gen0: {Gen0}, Gen1: {Gen1}, Gen2: {Gen2}, Memory: {Memory}MB",
                gen0, gen1, gen2, memory);
            
            if (gen2 > _lastGen2Count + 5)  // 5+ Gen2 GCs in 1 minute
            {
                _logger.LogWarning("High Gen2 GC activity detected");
            }
            
            _lastGen2Count = gen2;
            await Task.Delay(TimeSpan.FromMinutes(1), ct);
        }
    }
    
    private int _lastGen2Count;
}
```

## Practical Optimization Example

**Before optimization:**
```csharp
public class OrderProcessor
{
    public List<OrderSummary> ProcessOrders(List<Order> orders)
    {
        var summaries = new List<OrderSummary>();
        
        foreach (var order in orders)
        {
            var items = order.Items
                .Where(i => i.IsActive)
                .Select(i => $"{i.Name}: ${i.Price}")
                .ToList();
            
            var summary = new OrderSummary
            {
                OrderId = order.Id,
                ItemCount = items.Count,
                ItemList = string.Join(", ", items)  // String allocations
            };
            
            summaries.Add(summary);
        }
        
        return summaries;
    }
}

// Allocation tracking shows:
// - 50,000 string allocations (5 MB)
// - 10,000 List<string> allocations (1 MB)
// - High Gen0 GC frequency
```

**After optimization:**
```csharp
public class OrderProcessor
{
    private static readonly ObjectPool<StringBuilder> _sbPool = 
        new DefaultObjectPoolProvider().CreateStringBuilderPool();
    
    public List<OrderSummary> ProcessOrders(List<Order> orders)
    {
        var summaries = new List<OrderSummary>(orders.Count);
        
        foreach (var order in orders)
        {
            var sb = _sbPool.Get();
            try
            {
                var itemCount = 0;
                var first = true;
                
                foreach (var item in order.Items)
                {
                    if (item.IsActive)
                    {
                        if (!first) sb.Append(", ");
                        sb.Append(item.Name).Append(": $").Append(item.Price);
                        itemCount++;
                        first = false;
                    }
                }
                
                var summary = new OrderSummary
                {
                    OrderId = order.Id,
                    ItemCount = itemCount,
                    ItemList = sb.ToString()
                };
                
                summaries.Add(summary);
            }
            finally
            {
                _sbPool.Return(sb);
            }
        }
        
        return summaries;
    }
}

// Allocation tracking shows:
// - 5,000 string allocations (500 KB) - 90% reduction
// - 0 List<string> allocations - 100% reduction
// - Reduced Gen0 GC frequency by 80%
```

## Summary

Allocation tracking reveals where objects are created, enabling targeted optimization to reduce GC pressure. Use the .NET Object Allocation Tracking tool to identify hot spots, then apply strategies like using StringBuilder, pre-sizing collections, struct instead of class, ArrayPool, and object pooling. Monitor GC metrics in production to ensure allocations stay under control. Reducing allocations in hot paths significantly improves performance by minimizing GC frequency and pause times.
