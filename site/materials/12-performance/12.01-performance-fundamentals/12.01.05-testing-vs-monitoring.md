# Lesson 5: Performance Testing vs Production Monitoring

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand the differences between performance testing and production monitoring
- Know when to use each approach
- Design effective performance test scenarios
- Implement production monitoring with minimal overhead
- Combine testing and monitoring for comprehensive performance insights

---

## Introduction

Performance testing and production monitoring serve different purposes and answer different questions. Testing validates performance before deployment in controlled environments, while monitoring observes real user behavior in production. Both are essential for a complete performance engineering strategy, and they complement each other.

## Key Concepts Summary

### Performance Testing

**Definition:** Controlled experiments to measure application behavior under specific conditions.

**Purpose:**
- Validate performance before deployment
- Identify capacity limits
- Find bottlenecks in controlled environment
- Prevent performance regressions
- Establish performance baselines

**Environment:** Pre-production (staging, test)

**Control:** High (you control load, data, environment)

**Cost of failure:** Low (caught before users affected)

### Production Monitoring

**Definition:** Continuous observation of application behavior with real users and traffic.

**Purpose:**
- Detect issues in real-time
- Understand actual user experience
- Track SLO compliance
- Identify degradation trends
- Guide optimization priorities

**Environment:** Production

**Control:** Low (real users, real data, real conditions)

**Cost of failure:** High (users affected, business impact)

## When to Use Each

### Use Performance Testing When:

**1. Before Deployment**
```csharp
// Validate new feature doesn't degrade performance
[Test]
public async Task CheckoutPerformanceTest()
{
    // Arrange: Load test scenario
    var scenario = ScenarioBuilder
        .CreateScenario("checkout", async context =>
        {
            var response = await _client.PostAsync("/api/checkout", testData);
            return response.IsSuccessStatusCode 
                ? Response.Ok() 
                : Response.Fail();
        })
        .WithLoadSimulations(
            Simulation.RampConstant(copies: 10, during: TimeSpan.FromSeconds(30)),
            Simulation.KeepConstant(copies: 100, during: TimeSpan.FromMinutes(5))
        );

    // Act: Run test
    var stats = NBomberRunner
        .RegisterScenarios(scenario)
        .Run();

    // Assert: Verify SLO
    Assert.That(stats.ScenarioStats[0].Ok.Latency.Percent95, 
        Is.LessThan(200)); // P95 < 200ms
}
```

**2. Capacity Planning**
```csharp
// Find breaking point
public void StressTest()
{
    var scenario = Scenario.Create("stress_test", async context =>
    {
        return await CallApi();
    })
    .WithLoadSimulations(
        // Gradually increase load until system breaks
        Simulation.RampConstant(copies: 10, during: TimeSpan.FromMinutes(1)),
        Simulation.RampConstant(copies: 50, during: TimeSpan.FromMinutes(2)),
        Simulation.RampConstant(copies: 100, during: TimeSpan.FromMinutes(2)),
        Simulation.RampConstant(copies: 200, during: TimeSpan.FromMinutes(2))
    );
    
    // Results show: System handles 150 RPS before degrading
}
```

**3. Regression Prevention**
```csharp
// CI/CD pipeline test
```

### Use Production Monitoring When:

**1. Detecting Real Issues**
```csharp
// Monitor actual user experience
public class ProductionMonitor
{
    private readonly ILogger _logger;
    private readonly IMetrics _metrics;

    public async Task<IActionResult> HandleRequest()
    {
        using var activity = Activity.StartActivity("ProcessRequest");
        var stopwatch = Stopwatch.StartNew();
        
        try
        {
            var result = await ProcessRequestAsync();
            
            stopwatch.Stop();
            _metrics.RecordLatency(stopwatch.ElapsedMilliseconds);
            
            // Alert if latency exceeds SLO
            if (stopwatch.ElapsedMilliseconds > 200)
            {
                _logger.LogWarning(
                    "Slow request detected: {Latency}ms",
                    stopwatch.ElapsedMilliseconds);
            }
            
            return result;
        }
        catch (Exception ex)
        {
            _metrics.RecordError();
            _logger.LogError(ex, "Request failed");
            throw;
        }
    }
}
```

**4. Continuous SLO Tracking**

## Performance Testing Types

### 1. Load Testing

**Purpose:** Validate performance under expected load.

```csharp
public void LoadTest()
{
    var scenario = Scenario.Create("load_test", async context =>
    {
        return await CallApi();
    })
    .WithLoadSimulations(
        // Simulate normal traffic: 50 concurrent users
        Simulation.KeepConstant(copies: 50, during: TimeSpan.FromMinutes(10))
    );
    
    var stats = NBomberRunner.RegisterScenarios(scenario).Run();
    
    // Verify:
    // - P95 latency < 200ms
    // - Error rate < 0.1%
    // - Resource utilization < 70%
}
```

### 2. Stress Testing

**Purpose:** Find breaking point.

```csharp
public void StressTest()
{
    var scenario = Scenario.Create("stress_test", async context =>
    {
        return await CallApi();
    })
    .WithLoadSimulations(
        // Gradually increase until failure
        Simulation.RampConstant(copies: 500, during: TimeSpan.FromMinutes(5))
    );
    
    // Observe when system starts failing
    // Results: Starts degrading at 350 concurrent users
    // CPU hits 95%, latency spikes, errors increase
}
```

### 3. Soak Testing

**Purpose:** Detect memory leaks and stability issues.

```csharp
public void SoakTest()
{
    var scenario = Scenario.Create("soak_test", async context =>
    {
        return await CallApi();
    })
    .WithLoadSimulations(
        // Sustained load for extended period
        Simulation.KeepConstant(copies: 30, during: TimeSpan.FromHours(8))
    );
    
    // Monitor:
    // - Memory usage over time (leaks?)
    // - GC frequency (increasing?)
    // - Connection pool exhaustion?
    // - File handle leaks?
}
```

### 4. Spike Testing

**Purpose:** Validate handling of traffic surges.

```csharp
public void SpikeTest()
{
    var scenario = Scenario.Create("spike_test", async context =>
    {
        return await CallApi();
    })
    .WithLoadSimulations(
        // Normal load
        Simulation.KeepConstant(copies: 30, during: TimeSpan.FromMinutes(2)),
        // Sudden spike
        Simulation.KeepConstant(copies: 300, during: TimeSpan.FromMinutes(1)),
        // Back to normal
        Simulation.KeepConstant(copies: 30, during: TimeSpan.FromMinutes(2))
    );
    
    // Verify:
    // - System recovers after spike
    // - No cascading failures
    // - Error rate stays low
}
```

## Production Monitoring Strategies

### 1. Application Instrumentation

```csharp
public class InstrumentedService
{
    private readonly Meter _meter;
    private readonly Counter<long> _requestsTotal;
    private readonly Histogram<double> _requestDuration;
    private readonly Counter<long> _errorsTotal;

    public InstrumentedService(IMeterFactory meterFactory)
    {
        _meter = meterFactory.Create("MyApp.Service");
        
        _requestsTotal = _meter.CreateCounter<long>(
            "requests.total",
            description: "Total requests");
        
        _requestDuration = _meter.CreateHistogram<double>(
            "request.duration",
            unit: "ms",
            description: "Request duration");
        
        _errorsTotal = _meter.CreateCounter<long>(
            "errors.total",
            description: "Total errors");
    }

    public async Task<Result> ProcessRequest(Request request)
    {
        var stopwatch = Stopwatch.StartNew();
        _requestsTotal.Add(1, 
            new KeyValuePair<string, object?>("endpoint", request.Endpoint));
        
        try
        {
            var result = await ProcessAsync(request);
            
            stopwatch.Stop();
            _requestDuration.Record(
                stopwatch.ElapsedMilliseconds,
                new KeyValuePair<string, object?>("endpoint", request.Endpoint),
                new KeyValuePair<string, object?>("status", "success"));
            
            return result;
        }
        catch (Exception ex)
        {
            stopwatch.Stop();
            _errorsTotal.Add(1,
                new KeyValuePair<string, object?>("endpoint", request.Endpoint),
                new KeyValuePair<string, object?>("error_type", ex.GetType().Name));
            
            _requestDuration.Record(
                stopwatch.ElapsedMilliseconds,
                new KeyValuePair<string, object?>("endpoint", request.Endpoint),
                new KeyValuePair<string, object?>("status", "error"));
            
            throw;
        }
    }
}
```

### 2. Distributed Tracing

```csharp
public class TracedService
{
    private static readonly ActivitySource ActivitySource = 
        new("MyApp", "1.0.0");

    public async Task<Order> ProcessOrder(int orderId)
    {
        using var activity = ActivitySource.StartActivity("ProcessOrder");
        activity?.SetTag("order.id", orderId);
        
        // Trace propagates across service boundaries
        var order = await FetchOrder(orderId);
        activity?.SetTag("order.total", order.Total);
        
        await ValidateOrder(order);
        await ProcessPayment(order);
        await NotifyCustomer(order);
        
        return order;
    }

    private async Task<Order> FetchOrder(int orderId)
    {
        using var activity = ActivitySource.StartActivity("FetchOrder");
        activity?.SetTag("order.id", orderId);
        
        // Database call - traced
        return await _db.Orders.FindAsync(orderId);
    }
}
```

### 4. Synthetic Monitoring

```csharp
// Periodically test production from outside
public class SyntheticMonitor
{
    public async Task RunSyntheticTests()
    {
        // Simulate user journey in production
        var results = await Task.WhenAll(
            TestLogin(),
            TestProductSearch(),
            TestCheckout()
        );
        
        foreach (var result in results)
        {
            if (!result.Success || result.Duration > result.SloTarget)
            {
                await SendAlert($"Synthetic test failed: {result.TestName}");
            }
        }
    }

    private async Task<SyntheticTestResult> TestCheckout()
    {
        var stopwatch = Stopwatch.StartNew();
        
        try
        {
            // Execute actual checkout in production
            var response = await _client.PostAsync(
                "/api/checkout",
                CreateTestPayload());
            
            stopwatch.Stop();
            
            return new SyntheticTestResult
            {
                TestName = "Checkout",
                Success = response.IsSuccessStatusCode,
                Duration = stopwatch.ElapsedMilliseconds,
                SloTarget = 200
            };
        }
        catch (Exception ex)
        {
            stopwatch.Stop();
            return new SyntheticTestResult
            {
                TestName = "Checkout",
                Success = false,
                Duration = stopwatch.ElapsedMilliseconds,
                SloTarget = 200,
                Error = ex.Message
            };
        }
    }
}
```

## Combining Testing and Monitoring

### 1. Use Test Results to Set Monitoring Baselines

```csharp
public class BaselineEstablisher
{
    public async Task EstablishBaselines()
    {
        // Run performance tests
        var testResults = await RunPerformanceTests();
        
        // Use test results to configure monitoring
        var monitoringConfig = new MonitoringConfig
        {
            LatencyWarningThreshold = testResults.P95Latency * 1.2,
            LatencyCriticalThreshold = testResults.P95Latency * 1.5,
            ThroughputWarningThreshold = testResults.MaxThroughput * 0.8,
            ErrorRateThreshold = 0.01 // 1%
        };
        
        await ApplyMonitoringConfig(monitoringConfig);
    }
}
```

## Best Practices

### Performance Testing

**1. Test in Production-Like Environment**
```
❌ Test on laptop
✅ Test on environment matching production specs
```

**2. Use Realistic Data**
```csharp
// Bad: Empty database
var testData = Array.Empty<Product>();

// Good: Production-scale data
var testData = GenerateRealisticProducts(count: 1_000_000);
```

**3. Warm Up First**
```csharp
var scenario = Scenario.Create("test", async context => await CallApi())
    .WithWarmUpDuration(TimeSpan.FromSeconds(30))  // Allow JIT compilation
    .WithLoadSimulations(/* ... */);
```

**4. Isolate Tests**
```
- One test type at a time
- Clear state between runs
- Monitor external dependencies
```

### Production Monitoring

**1. Instrument Everything**
```csharp
// Every service, every endpoint, every external call
_metrics.RecordRequest(endpoint, method, statusCode, duration);
```

**2. Focus on User Experience**
```
✅ Monitor: Request latency, error rate, success rate
❌ Don't obsess over: Internal metrics that don't affect users
```

**3. Set Meaningful Alerts**
```csharp
// Bad: Alert on every error
if (error) SendAlert();

// Good: Alert on error rate threshold
if (errorRate > 0.01) SendAlert();  // > 1% error rate

// Better: Alert on SLO breach
if (p95Latency > sloTarget || errorRate > errorBudget) SendAlert();
```

**4. Minimize Overhead**
```csharp
// Sampling for high-volume traces
var sampler = new TraceIdRatioBasedSampler(0.1);  // Sample 10%

// Histogram buckets (not full percentiles)
_histogram.Record(latency);  // Prometheus aggregates later
```

## Summary

Performance testing validates behavior in controlled environments before deployment, while production monitoring observes real user experiences. Testing answers "Can our system handle expected load?" while monitoring answers "How is our system actually performing?" Use load testing, stress testing, and soak testing to find limits and prevent regressions. Use production monitoring with metrics, traces, and health checks to detect issues and track SLOs. Combine both approaches: use test results to set monitoring baselines, and use production data to make tests more realistic.
