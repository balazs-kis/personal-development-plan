## Introduction

Averages lie about performance. A system with an average response time of 50ms might be delivering a terrible experience to 1% of users (thousands of requests in high-traffic systems). Percentiles tell the truth about what real users experience across the distribution of performance.

## Key Concepts Summary

### What Percentiles Mean

**P50 (Median):** Half of requests are faster, half are slower.
- Represents the **typical user experience**
- Good for detecting broad regressions
- Less affected by outliers

**P95:** 95% of requests are faster, 5% are slower.
- Early warning signal for **degraded performance**
- Affects a significant number of users in high-traffic systems
- Common SLO target

**P99:** 99% of requests are faster, 1% are slower.
- Represents the **worst experiences** users have
- In a system handling 10,000 requests/minute, that's **100 slow requests per minute**
- Often includes high-value transactions (checkouts, admin operations)

**P99.9:** 99.9% of requests are faster, 0.1% are slower.
- Extreme tail latency
- Critical for very high-scale systems
- Expensive to optimize

### Why Averages Are Misleading

Consider this latency distribution:

```
10,000 requests:
- 9,990 requests: 50ms each
- 10 requests: 8,000ms each (due to GC pause, network issue, etc.)

Average: (9,990 × 50 + 10 × 8,000) / 10,000 = 118ms
P50: 50ms
P95: 50ms
P99: 50ms
P99.9: 8,000ms

The average (118ms) suggests most users have a bad experience.
The median (50ms) shows most users are actually fine.
The P99.9 (8,000ms) reveals the outliers causing pain.
```

**Problem with averages:**
- They compress the distribution into a single number
- Outliers heavily influence them
- They hide the extremes that cause user frustration
- They don't tell you what percentage of users are affected

## Understanding Each Percentile

### P50 (Median) - The Typical Experience

```csharp
// Calculate P50 from a list of latencies
public static double CalculateP50(List<double> latencies)
{
    if (latencies.Count == 0) return 0;
    
    var sorted = latencies.OrderBy(x => x).ToList();
    var middleIndex = sorted.Count / 2;
    
    if (sorted.Count % 2 == 0)
    {
        // Even count: average of two middle values
        return (sorted[middleIndex - 1] + sorted[middleIndex]) / 2.0;
    }
    else
    {
        // Odd count: middle value
        return sorted[middleIndex];
    }
}

// Example
var latencies = new List<double> { 45, 50, 55, 48, 52, 51, 49, 53, 50, 47 };
var p50 = CalculateP50(latencies);
// P50 = 50ms - half the requests are faster, half are slower
```

**Use P50 for:**
- Understanding typical user experience
- Detecting broad performance regressions
- Initial performance baseline

**Don't use P50 for:**
- SLOs (doesn't protect against tail latency)
- Identifying outliers
- Understanding worst-case scenarios

### P95 - The Warning Signal

```csharp
public static double CalculatePercentile(List<double> latencies, double percentile)
{
    if (latencies.Count == 0) return 0;
    
    var sorted = latencies.OrderBy(x => x).ToList();
    var index = (int)Math.Ceiling(percentile / 100.0 * sorted.Count) - 1;
    index = Math.Max(0, Math.Min(sorted.Count - 1, index));
    
    return sorted[index];
}

// Calculate P95
var p95 = CalculatePercentile(latencies, 95);
// P95 = 55ms - 95% of requests complete faster than this
```

**Impact at scale:**
```
System: 10,000 requests/minute
P95: 200ms (95% under 200ms, 5% over)

Affected users: 500 requests/minute are slower than 200ms
That's: 8 slow requests every second
Per day: 720,000 slow requests

In high-traffic systems, 5% is a LOT of users!
```

**Use P95 for:**
- Setting realistic SLOs
- Performance tuning targets
- Identifying when system is degrading
- Alerting thresholds

### P99 - The Worst Experience

```csharp
var p99 = CalculatePercentile(latencies, 99);
```

**Why P99 matters:**

1. **High-value transactions often land in the tail:**
   - Checkout with large carts (more items to process)
   - Admin operations (complex queries)
   - First-time visitors (cold caches)
   - Mobile users on poor connections

2. **Outliers create support tickets:**
   ```
   P50: 50ms → "App is fast!"
   P99: 5,000ms → "Your app is broken!" (support ticket)
   ```

3. **Cumulative effect:**
   ```
   Single page load: 10 API calls
   If each call has P99 = 1% slow (due to independent issues):
   Probability entire page load is slow: 1 - (0.99)^10 = 9.6%
   
   Nearly 1 in 10 page loads will be slow!
   ```

**Use P99 for:**
- Exposing architectural bottlenecks
- Understanding tail latency issues
- Critical systems (payment, authentication)
- High-value user journeys

**Don't optimize for P100:** The single slowest request is usually noise (network glitch, hardware fault, one-off issue). Focus on P99 or P99.9.

## Implementing Percentile Tracking in .NET

### Using Histograms with System.Diagnostics.Metrics

```csharp
using System.Diagnostics.Metrics;

public class LatencyTracker
{
    private readonly Meter _meter;
    private readonly Histogram<double> _latencyHistogram;

    public LatencyTracker(IMeterFactory meterFactory)
    {
        _meter = meterFactory.Create("MyApp.Performance");
        
        // Create histogram for latency measurements
        _latencyHistogram = _meter.CreateHistogram<double>(
            name: "http.server.request.duration",
            unit: "ms",
            description: "HTTP request duration in milliseconds");
    }

    public void RecordLatency(double latencyMs, string endpoint)
    {
        _latencyHistogram.Record(
            latencyMs,
            new KeyValuePair<string, object?>("endpoint", endpoint));
    }
}

// Usage in middleware
public class PerformanceMiddleware
{
    private readonly RequestDelegate _next;
    private readonly LatencyTracker _tracker;

    public async Task InvokeAsync(HttpContext context)
    {
        var stopwatch = Stopwatch.StartNew();
        
        try
        {
            await _next(context);
        }
        finally
        {
            stopwatch.Stop();
            _tracker.RecordLatency(
                stopwatch.ElapsedMilliseconds,
                context.Request.Path);
        }
    }
}
```

### Custom Percentile Calculator

```csharp
public class PercentileCalculator
{
    private readonly ConcurrentBag<double> _latencies = new();
    private readonly int _maxSamples = 10000;

    public void Record(double latencyMs)
    {
        _latencies.Add(latencyMs);
        
        // Keep bounded size
        if (_latencies.Count > _maxSamples)
        {
            // Remove oldest half
            var toKeep = _latencies.Take(_maxSamples / 2).ToList();
            _latencies.Clear();
            foreach (var value in toKeep)
                _latencies.Add(value);
        }
    }

    public PercentileSnapshot GetSnapshot()
    {
        var sorted = _latencies.OrderBy(x => x).ToList();
        if (sorted.Count == 0)
            return new PercentileSnapshot();

        return new PercentileSnapshot
        {
            Count = sorted.Count,
            Min = sorted[0],
            Max = sorted[^1],
            P50 = GetPercentile(sorted, 50),
            P95 = GetPercentile(sorted, 95),
            P99 = GetPercentile(sorted, 99),
            P999 = GetPercentile(sorted, 99.9),
            Average = sorted.Average()
        };
    }

    private static double GetPercentile(List<double> sorted, double percentile)
    {
        var index = (int)Math.Ceiling(percentile / 100.0 * sorted.Count) - 1;
        index = Math.Max(0, Math.Min(sorted.Count - 1, index));
        return sorted[index];
    }
}

public record PercentileSnapshot
{
    public int Count { get; init; }
    public double Min { get; init; }
    public double Max { get; init; }
    public double P50 { get; init; }
    public double P95 { get; init; }
    public double P99 { get; init; }
    public double P999 { get; init; }
    public double Average { get; init; }
}
```

## Setting SLOs with Percentiles

### Choosing the Right Percentile

**P50 SLOs:**
```
❌ Too lenient: "P50 latency < 100ms"
Allows 50% of requests to exceed 100ms!
```

**P95 SLOs (Recommended):**
```
✅ Balanced: "P95 latency < 200ms"
Protects 95% of users
Realistic to achieve
Standard industry practice
```

**P99 SLOs:**
```
✅ Strict: "P99 latency < 500ms"
Protects 99% of users
More challenging to maintain
Good for critical systems
```

**P99.9 SLOs:**
```
⚠️ Very strict: "P99.9 latency < 1000ms"
Extremely challenging
Only for highest-tier services
Very expensive to achieve
```

### Example SLO Definitions

```csharp
public class LatencySlo
{
    public string Name { get; set; }
    public string Endpoint { get; set; }
    public double TargetPercentile { get; set; }  // e.g., 95 for P95
    public double TargetLatencyMs { get; set; }
    public TimeSpan MeasurementWindow { get; set; }
    
    public bool IsMet(PercentileSnapshot snapshot)
    {
        var actualLatency = TargetPercentile switch
        {
            50 => snapshot.P50,
            95 => snapshot.P95,
            99 => snapshot.P99,
            99.9 => snapshot.P999,
            _ => throw new ArgumentException($"Unsupported percentile: {TargetPercentile}")
        };
        
        return actualLatency <= TargetLatencyMs;
    }
}

// Example SLOs
var checkoutSlo = new LatencySlo
{
    Name = "Checkout Latency",
    Endpoint = "/api/checkout",
    TargetPercentile = 95,
    TargetLatencyMs = 200,
    MeasurementWindow = TimeSpan.FromDays(30)
};

var searchSlo = new LatencySlo
{
    Name = "Search Latency",
    Endpoint = "/api/search",
    TargetPercentile = 99,
    TargetLatencyMs = 500,
    MeasurementWindow = TimeSpan.FromDays(30)
};
```

## Analyzing Percentile Distributions

### Identifying Bimodal Distributions

```csharp
public class DistributionAnalyzer
{
    public DistributionAnalysis Analyze(List<double> latencies)
    {
        var sorted = latencies.OrderBy(x => x).ToList();
        
        return new DistributionAnalysis
        {
            P50 = GetPercentile(sorted, 50),
            P95 = GetPercentile(sorted, 95),
            P99 = GetPercentile(sorted, 99),
            IsBimodal = DetectBimodal(sorted)
        };
    }
    
    private bool DetectBimodal(List<double> sorted)
    {
        var p50 = GetPercentile(sorted, 50);
        var p99 = GetPercentile(sorted, 99);
        
        // Large gap suggests two different populations
        // (e.g., cache hits vs cache misses)
        return (p99 / p50) > 10;
    }
}

// Example: Cache hit/miss pattern
/*
Cache hits: 5ms (99% of requests)
Cache misses: 100ms (1% of requests)

P50: 5ms
P95: 5ms
P99: 100ms

Ratio: 100/5 = 20 (bimodal!)

This suggests two distinct populations.
Action: Improve cache hit rate or optimize cache miss path.
*/
```

### Detecting Performance Degradation

```csharp
public class PerformanceMonitor
{
    private PercentileSnapshot _baseline;
    
    public void SetBaseline(PercentileSnapshot baseline)
    {
        _baseline = baseline;
    }
    
    public PerformanceAlert CheckForDegradation(PercentileSnapshot current)
    {
        var alerts = new List<string>();
        
        // Check if P95 degraded by more than 20%
        if (current.P95 > _baseline.P95 * 1.2)
        {
            alerts.Add($"P95 degraded: {_baseline.P95}ms → {current.P95}ms");
        }
        
        // Check if P99 degraded by more than 30%
        if (current.P99 > _baseline.P99 * 1.3)
        {
            alerts.Add($"P99 degraded: {_baseline.P99}ms → {current.P99}ms");
        }
        
        // Check if tail latency is growing
        var tailRatio = current.P99 / current.P50;
        var baselineTailRatio = _baseline.P99 / _baseline.P50;
        
        if (tailRatio > baselineTailRatio * 1.5)
        {
            alerts.Add($"Tail latency growing: P99/P50 ratio increased from {baselineTailRatio:F1} to {tailRatio:F1}");
        }
        
        return new PerformanceAlert
        {
            HasIssues = alerts.Any(),
            Messages = alerts,
            Severity = DetermineSeverity(alerts.Count)
        };
    }
}
```

## Common Patterns and Anti-Patterns

### ✅ Good: Track Multiple Percentiles

```csharp
public class MetricsReporter
{
    public void Report(PercentileSnapshot snapshot)
    {
        Console.WriteLine($"""
            Latency Distribution:
            - Count: {snapshot.Count}
            - P50: {snapshot.P50}ms
            - P95: {snapshot.P95}ms
            - P99: {snapshot.P99}ms
            - Max: {snapshot.Max}ms
            """);
    }
}
```

### ❌ Bad: Only Track Averages

```csharp
public class BadMetricsReporter
{
    public void Report(List<double> latencies)
    {
        Console.WriteLine($"Average latency: {latencies.Average()}ms");
        // Missing the distribution! Could be hiding serious problems.
    }
}
```

### ✅ Good: Set Percentile-Based SLOs

```
✅ "P95 latency < 200ms over 30 days"
✅ "P99 latency < 500ms for checkout endpoint"
```

### ❌ Bad: Average-Based SLOs

```
❌ "Average latency < 100ms"
Allows terrible experiences for significant % of users
```

### ✅ Good: Alert on Percentile Degradation

```csharp
// Alert when P95 exceeds SLO
if (currentP95 > sloTarget)
{
    SendAlert($"P95 latency ({currentP95}ms) exceeds SLO ({sloTarget}ms)");
}
```

### ❌ Bad: Alert on Single Slow Request

```csharp
// Too noisy!
if (latency > threshold)
{
    SendAlert($"Slow request detected: {latency}ms");
}
```

## Summary

Percentiles tell the truth about performance by showing the distribution of latencies across all users. P50 shows typical experience, P95 is ideal for SLOs and alerts, P99 reveals tail latency problems that affect real users. Always track and optimize percentiles, not averages. In high-traffic systems, even 1% of slow requests represents thousands of frustrated users.
