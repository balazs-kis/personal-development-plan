- Understand when in-memory caching is appropriate vs distributed caching
- Set cache priorities and handle cache eviction

---

## Introduction

In-memory caching stores frequently accessed data directly in the application's memory, providing the fastest possible access times. The `IMemoryCache` interface in ASP.NET Core offers a simple yet powerful API for implementing cache logic. Understanding when and how to use in-memory caching is fundamental to application performance optimization.

## Key Concepts Summary

### Setting Up IMemoryCache

```csharp
// Register in Program.cs
builder.Services.AddMemoryCache();

// Inject into services/controllers
public class ProductService
{
    private readonly IMemoryCache _cache;
    
    public ProductService(IMemoryCache cache)
    {
        _cache = cache;
    }
}
```

### Basic Cache Operations

```csharp
// Get or Create pattern
public async Task<Product> GetProductAsync(int id)
{
    return await _cache.GetOrCreateAsync(
        $"product_{id}",
        async entry =>
        {
            entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
            entry.SlidingExpiration = TimeSpan.FromMinutes(2);
            entry.Priority = CacheItemPriority.Normal;
            
            return await _dbContext.Products.FindAsync(id);
        });
}

// Manual set
_cache.Set("key", value, TimeSpan.FromMinutes(10));

// Try get
if (_cache.TryGetValue("key", out Product product))
{
    return product;
}

// Remove
_cache.Remove("key");
```

### Expiration Policies

**Absolute Expiration**: Cache entry expires at a specific time
```csharp
entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10);
// Or specific date/time
entry.AbsoluteExpiration = DateTimeOffset.Now.AddHours(1);
```

**Sliding Expiration**: Entry expires if not accessed within the specified timespan
```csharp
entry.SlidingExpiration = TimeSpan.FromMinutes(5);
// Resets the 5-minute timer on each access
```

### Cache Priorities

Control which entries are evicted first when memory pressure occurs:
```csharp
entry.Priority = CacheItemPriority.High;      // Last to be evicted
entry.Priority = CacheItemPriority.Normal;    // Default
entry.Priority = CacheItemPriority.Low;       // First to be evicted
entry.Priority = CacheItemPriority.NeverRemove; // Never evicted due to pressure
```

### When to Use In-Memory Caching

**✅ Good scenarios:**
- Single-server applications
- Session-affinity (sticky sessions) scenarios
- Small to medium data sets
- Data that changes infrequently
- Fast, frequently accessed lookups

**❌ Avoid when:**
- Multiple servers without session affinity
- Large data sets that could cause memory issues
- Need to share cache across different applications
- Server restarts must not lose cache
