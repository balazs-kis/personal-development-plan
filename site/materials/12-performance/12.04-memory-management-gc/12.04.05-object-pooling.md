## Introduction

Object pooling reuses objects instead of creating and destroying them repeatedly, reducing GC pressure and allocation costs. ArrayPool<T> is .NET's built-in solution for pooling arrays, dramatically improving performance in scenarios with frequent large allocations.

## Key Concepts Summary

### What is Object Pooling?

```csharp
// Traditional approach: allocate and discard
public void ProcessData()
{
    var buffer = new byte[10000];  // Allocate
    // Use buffer...
    // Buffer becomes garbage → GC pressure
}

// Pooling approach: rent and return
public void ProcessDataPooled()
{
    var buffer = ArrayPool<byte>.Shared.Rent(10000);  // Rent from pool
    try
    {
        // Use buffer...
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer);  // Return to pool
    }
    // Buffer reused, no GC pressure
}
```

**Benefits:**
- Reduces allocations
- Minimizes GC pressure
- Improves performance in hot paths
- Especially effective for large objects (LOH)

### ArrayPool<T> Basics

**Shared Pool:**

```csharp
// Using the shared global pool
public void UseSharedPool()
{
    // Rent array of at least 1000 elements
    int[] array = ArrayPool<int>.Shared.Rent(1000);
    
    try
    {
        // Use array
        // ⚠️ Array might be larger than requested
        // ⚠️ Array might contain previous data
        
        for (int i = 0; i < 1000; i++)
        {
            array[i] = i * 2;
        }
        
        // Process...
    }
    finally
    {
        // Always return in finally block
        ArrayPool<int>.Shared.Return(array);
    }
}
```

**Key Characteristics:**

```csharp
public void UnderstandArrayPool()
{
    // 1. Rent returns array of AT LEAST requested size
    var array = ArrayPool<byte>.Shared.Rent(100);
    Console.WriteLine($"Requested: 100, Got: {array.Length}");
    // Output might be: "Requested: 100, Got: 128" (power of 2)
    
    // 2. Arrays are NOT zero-initialized
    array = ArrayPool<byte>.Shared.Rent(10);
    Console.WriteLine($"First byte: {array[0]}");  // Might not be 0!
    
    // 3. Always return arrays
    ArrayPool<byte>.Shared.Return(array);
    // ⚠️ Don't use array after returning!
}
```

### ArrayPool<T> Pattern

**Basic Pattern:**

```csharp
public class ArrayPoolPattern
{
    public void ProcessFile(string path)
    {
        var pool = ArrayPool<byte>.Shared;
        byte[] buffer = null;
        
        try
        {
            buffer = pool.Rent(4096);
            
            using var stream = File.OpenRead(path);
            int bytesRead;
            while ((bytesRead = stream.Read(buffer, 0, buffer.Length)) > 0)
            {
                // Process buffer[0..bytesRead]
                ProcessChunk(buffer.AsSpan(0, bytesRead));
            }
        }
        finally
        {
            if (buffer != null)
                pool.Return(buffer);
        }
    }
    
    private void ProcessChunk(Span<byte> chunk) { /* ... */ }
}
```

**With Clear Option:**

```csharp
public void SecureProcessing()
{
    var buffer = ArrayPool<byte>.Shared.Rent(1000);
    
    try
    {
        // Store sensitive data
        buffer[0] = 0x42;
    }
    finally
    {
        // Clear array before returning (for security)
        ArrayPool<byte>.Shared.Return(buffer, clearArray: true);
    }
}
```

### Practical Example: Processing Large Data

```csharp
public class DataProcessor
{
    // ❌ Without pooling: many allocations
    public async Task<byte[]> DownloadAndProcessBad(string url)
    {
        using var client = new HttpClient();
        var data = await client.GetByteArrayAsync(url);  // Allocates
        
        var processed = new byte[data.Length];  // Allocates
        for (int i = 0; i < data.Length; i++)
        {
            processed[i] = (byte)(data[i] ^ 0xFF);
        }
        
        return processed;  // 2 large allocations
    }
    
    // ✅ With pooling: reuses buffers
    public async Task<byte[]> DownloadAndProcessGood(string url)
    {
        using var client = new HttpClient();
        using var response = await client.GetAsync(url);
        
        var contentLength = (int)(response.Content.Headers.ContentLength ?? 1_000_000);
        var buffer = ArrayPool<byte>.Shared.Rent(contentLength);
        
        try
        {
            using var stream = await response.Content.ReadAsStreamAsync();
            int totalRead = 0;
            int bytesRead;
            
            while ((bytesRead = await stream.ReadAsync(
                buffer.AsMemory(totalRead, buffer.Length - totalRead))) > 0)
            {
                totalRead += bytesRead;
            }
            
            // Process in place
            for (int i = 0; i < totalRead; i++)
            {
                buffer[i] ^= 0xFF;
            }
            
            // Copy only the used portion
            var result = new byte[totalRead];
            Array.Copy(buffer, result, totalRead);
            return result;
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(buffer);
        }
    }
}
```

### Custom Object Pool

**Generic Object Pool:**

```csharp
public class ObjectPool<T> where T : class
{
    private readonly ConcurrentBag<T> _pool = new();
    private readonly Func<T> _factory;
    private readonly Action<T> _reset;
    
    public ObjectPool(Func<T> factory, Action<T> reset = null)
    {
        _factory = factory ?? throw new ArgumentNullException(nameof(factory));
        _reset = reset ?? (_ => { });
    }
    
    public T Rent()
    {
        return _pool.TryTake(out var item) ? item : _factory();
    }
    
    public void Return(T item)
    {
        _reset(item);
        _pool.Add(item);
    }
}

// Usage
public class Example
{
    private static readonly ObjectPool<StringBuilder> _stringBuilderPool =
        new ObjectPool<StringBuilder>(
            factory: () => new StringBuilder(256),
            reset: sb => sb.Clear()
        );
    
    public string FormatMessage(string name, int value)
    {
        var sb = _stringBuilderPool.Rent();
        try
        {
            sb.Append("Hello, ").Append(name);
            sb.Append(". Value: ").Append(value);
            return sb.ToString();
        }
        finally
        {
            _stringBuilderPool.Return(sb);
        }
    }
}
```

### Common Pitfalls

**Pitfall 1: Forgetting to Return**

```csharp
// ❌ Memory leak: never returns array
public void LeakMemory()
{
    var buffer = ArrayPool<byte>.Shared.Rent(1000);
    // Use buffer...
    // ❌ Forgot to return!
}

// ✅ Always use try-finally
public void ProperReturn()
{
    var buffer = ArrayPool<byte>.Shared.Rent(1000);
    try
    {
        // Use buffer...
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer);
    }
}
```

**Pitfall 2: Using After Return**

```csharp
// ❌ Use after return
public byte[] DangerousPattern()
{
    var buffer = ArrayPool<byte>.Shared.Rent(100);
    // ... use buffer ...
    ArrayPool<byte>.Shared.Return(buffer);
    
    return buffer;  // ❌ Returned buffer might be reused!
}

// ✅ Copy data before returning
public byte[] SafePattern()
{
    var buffer = ArrayPool<byte>.Shared.Rent(100);
    try
    {
        // ... use buffer ...
        
        var result = new byte[100];
        Array.Copy(buffer, result, 100);
        return result;
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer);
    }
}
```

**Pitfall 3: Assuming Zero-Initialization**

```csharp
// ❌ Assumes array is zeroed
public void AssumeZero()
{
    var buffer = ArrayPool<int>.Shared.Rent(10);
    
    // ❌ Might not be zero!
    for (int i = 0; i < 10; i++)
    {
        Console.WriteLine(buffer[i]);  // Might print non-zero values
    }
    
    ArrayPool<int>.Shared.Return(buffer);
}

// ✅ Initialize explicitly if needed
public void ExplicitZero()
{
    var buffer = ArrayPool<int>.Shared.Rent(10);
    Array.Clear(buffer, 0, 10);  // Explicitly zero
    
    // Now safe to assume zeros
    
    ArrayPool<int>.Shared.Return(buffer);
}
```

**Pitfall 4: Ignoring Actual Length**

```csharp
// ❌ Uses array.Length instead of requested size
public void WrongLength()
{
    var buffer = ArrayPool<byte>.Shared.Rent(100);
    
    // Buffer might be 128 or more!
    for (int i = 0; i < buffer.Length; i++)  // ❌ Processes extra elements
    {
        buffer[i] = 0xFF;
    }
    
    ArrayPool<byte>.Shared.Return(buffer);
}

// ✅ Track requested size separately
public void CorrectLength()
{
    int requestedSize = 100;
    var buffer = ArrayPool<byte>.Shared.Rent(requestedSize);
    
    for (int i = 0; i < requestedSize; i++)  // ✅ Uses requested size
    {
        buffer[i] = 0xFF;
    }
    
    ArrayPool<byte>.Shared.Return(buffer);
}
```

### When to Use Pooling

**✅ Good Candidates:**
```csharp
public class GoodPoolingScenarios
{
    // 1. High-frequency allocations
    public void ProcessManyRequests()
    {
        for (int i = 0; i < 1000000; i++)
        {
            var buffer = ArrayPool<byte>.Shared.Rent(1024);
            try
            {
                // Process
            }
            finally
            {
                ArrayPool<byte>.Shared.Return(buffer);
            }
        }
    }
    
    // 2. Large objects (especially > 85KB for LOH)
    public void ProcessLargeData()
    {
        var buffer = ArrayPool<byte>.Shared.Rent(500_000);  // Avoids LOH churn
        try { /* ... */ }
        finally { ArrayPool<byte>.Shared.Return(buffer); }
    }
    
    // 3. Short-lived, predictable lifetime
    public async Task ProcessStream(Stream stream)
    {
        var buffer = ArrayPool<byte>.Shared.Rent(4096);
        try
        {
            await stream.ReadAsync(buffer);
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(buffer);
        }
    }
}
```

**❌ Poor Candidates:**
```csharp
public class PoorPoolingScenarios
{
    // 1. Long-lived objects
    private byte[] _longLivedBuffer;  // Don't pool, just allocate once
    
    // 2. Unpredictable lifetimes
    public byte[] GetBuffer()
    {
        return ArrayPool<byte>.Shared.Rent(100);  // ❌ Can't control return
    }
    
    // 3. Small, infrequent allocations
    public void ProcessOnce()
    {
        var small = new byte[10];  // ❌ Pooling overhead not worth it
    }
}
```

        try
        {
            string line;
            while ((line = await reader.ReadLineAsync()) != null)

                int byteCount = Encoding.UTF8.GetByteCount(line);

        {

        }

// Implement a pool for HttpClient messages
public class HttpMessagePool
{
    private readonly ObjectPool<HttpRequestMessage> _pool;
    
    public HttpMessagePool()
    {
        _pool = new ObjectPool<HttpRequestMessage>(
            factory: () => new HttpRequestMessage(),
            reset: msg =>
            {
                msg.Method = HttpMethod.Get;
                msg.RequestUri = null;
                msg.Content = null;
                msg.Headers.Clear();
            }
        );
    }
    
    public async Task<string> GetAsync(string url)
    {
        var request = _pool.Rent();
        try
        {
            request.RequestUri = new Uri(url);
            
            using var client = new HttpClient();
            using var response = await client.SendAsync(request);
            return await response.Content.ReadAsStringAsync();
        }
        finally
        {
            _pool.Return(request);
        }
    }
}

## Summary

Object pooling reuses objects to reduce allocations and GC pressure. ArrayPool<T> provides built-in array pooling with `Rent()` and `Return()` methods. Always return pooled objects in `finally` blocks, track requested sizes separately from actual array length, and don't assume zero-initialization. Custom pools can be created for any object type. Use pooling for high-frequency or large allocations with predictable lifetimes. Monitor performance with BenchmarkDotNet to verify pooling benefits outweigh overhead.
