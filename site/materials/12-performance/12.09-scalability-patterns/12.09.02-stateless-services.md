## Learning Objectives

By the end of this lesson, you will be able to:
- Understand what stateless services are and why they matter for scalability
- Identify stateful vs stateless application components
- Design stateless APIs and microservices
- Externalize state using appropriate storage mechanisms
- Implement session management for horizontally scaled applications
- Apply the twelve-factor app principles for stateless design

---

## Introduction

Stateless service design is the foundation of horizontal scalability. When services don't maintain state between requests, any instance can handle any request, enabling you to add or remove servers dynamically without coordination. This lesson covers how to design truly stateless services and where to put the state instead.

## Key Concepts Summary

### What is a Stateless Service?

**Definition:** A stateless service does not maintain state within the service across requests. It processes each request independently, treating every request as if it's the first.

**Key characteristic:** Any instance of the service can handle any request at any time.

```
Stateless Service:
┌─────────────────┐
│   Request 1     │ ──► [Instance A] ──► Response
└─────────────────┘

┌─────────────────┐
│   Request 2     │ ──► [Instance B] ──► Response
└─────────────────┘

┌─────────────────┐
│   Request 3     │ ──► [Instance A] ──► Response
└─────────────────┘

Each request is independent. Instance A or B can handle any request.
```

### Stateful vs Stateless

#### Stateful Service (Anti-Pattern for Scalability)

```csharp
// ❌ BAD: Storing state in-memory
public class OrderController : ControllerBase
{
    // Instance field - state stored in this specific server
    private static Dictionary<string, Order> _activeOrders = new();
    
    [HttpPost("cart/add")]
    public IActionResult AddToCart(string userId, Product product)
    {
        if (!_activeOrders.ContainsKey(userId))
            _activeOrders[userId] = new Order();
            
        _activeOrders[userId].Items.Add(product);
        return Ok();
    }
    
    [HttpGet("cart")]
    public IActionResult GetCart(string userId)
    {
        // Only works if request routes to same server!
        return Ok(_activeOrders[userId]);
    }
}
```

**Problems:**
- Only works if all user requests go to same server (sticky sessions)
- Can't scale horizontally (each server has different data)
- Lost if server restarts
- Memory grows unbounded

#### Stateless Service (Correct Pattern)

```csharp
// ✅ GOOD: Stateless with external state storage
public class OrderController : ControllerBase
{
    private readonly ICartRepository _cartRepo;
    
    public OrderController(ICartRepository cartRepo)
    {
        _cartRepo = cartRepo;
    }
    
    [HttpPost("cart/add")]
    public async Task<IActionResult> AddToCart(string userId, Product product)
    {
        // Fetch state from external storage
        var cart = await _cartRepo.GetCartAsync(userId) ?? new Cart();
        cart.Items.Add(product);
        
        // Persist state to external storage
        await _cartRepo.SaveCartAsync(userId, cart);
        
        return Ok();
    }
    
    [HttpGet("cart")]
    public async Task<IActionResult> GetCart(string userId)
    {
        // Any server can handle this request
        var cart = await _cartRepo.GetCartAsync(userId);
        return Ok(cart);
    }
}
```

**Benefits:**
- Any server can handle any request
- Can scale horizontally without limits
- Survives server restarts
- Predictable memory usage

### Where Does the State Go?

State doesn't disappear—it moves to appropriate storage:

#### 1. Database (Persistent State)

```csharp
public class UserService
{
    private readonly ApplicationDbContext _db;
    
    public async Task<User> GetUserAsync(int id)
    {
        // State in database, not service memory
        return await _db.Users.FindAsync(id);
    }
    
    public async Task UpdateUserAsync(User user)
    {
        _db.Users.Update(user);
        await _db.SaveChangesAsync();
    }
}
```

**Use for:** Long-term, durable state (user profiles, orders, products)

#### 2. Distributed Cache (Short-term State)

```csharp
public class SessionService
{
    private readonly IDistributedCache _cache;
    
    public async Task<Session> GetSessionAsync(string sessionId)
    {
        var json = await _cache.GetStringAsync($"session:{sessionId}");
        return json != null ? JsonSerializer.Deserialize<Session>(json) : null;
    }
    
    public async Task SaveSessionAsync(string sessionId, Session session)
    {
        var json = JsonSerializer.Serialize(session);
        await _cache.SetStringAsync(
            $"session:{sessionId}",
            json,
            new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(1)
            });
    }
}
```

**Use for:** Temporary state (sessions, shopping carts, user preferences)

#### 3. Message Queue (Transient State)

```csharp
public class OrderProcessingService
{
    private readonly IMessageBus _bus;
    
    public async Task ProcessOrderAsync(Order order)
    {
        // Publish event, don't hold state
        await _bus.PublishAsync(new OrderPlacedEvent
        {
            OrderId = order.Id,
            UserId = order.UserId,
            Total = order.Total
        });
    }
}
```

**Use for:** Work items, background processing, event-driven workflows

#### 4. Client (User-Specific State)

```csharp
// JWT token contains user identity and claims
[Authorize]
[HttpGet("profile")]
public IActionResult GetProfile()
{
    // State comes from the request (JWT token)
    var userId = User.FindFirstValue(ClaimTypes.NameIdentifier);
    var email = User.FindFirstValue(ClaimTypes.Email);
    
    // Fetch additional data as needed
    var profile = _userService.GetProfile(userId);
    return Ok(profile);
}
```

**Use for:** Authentication state, user preferences, client-side caching

### Common Stateful Anti-Patterns

#### Anti-Pattern 1: In-Memory Session State

```csharp
// ❌ BAD: ASP.NET Core in-memory session
services.AddDistributedMemoryCache(); // Stored in server RAM
services.AddSession();
```

**Problem:** Session data stored in server memory. Horizontal scaling requires sticky sessions.

**Solution:** Use distributed session state
```csharp
// ✅ GOOD: Distributed session state
services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = Configuration["Redis:ConnectionString"];
});
services.AddSession();
```

#### Anti-Pattern 2: Static Variables

```csharp
// ❌ BAD: Static state
public class MetricsService
{
    private static int _requestCount = 0;
    
    public void RecordRequest()
    {
        _requestCount++; // Only increments on this server
    }
}
```

**Solution:** Use external metrics system
```csharp
// ✅ GOOD: External metrics
public class MetricsService
{
    private readonly IMetricsCollector _metrics;
    
    public void RecordRequest()
    {
        _metrics.Increment("requests.count");
    }
}
```

#### Anti-Pattern 3: File System Storage

```csharp
// ❌ BAD: Local file storage
public class FileService
{
    public void SaveFile(string filename, byte[] content)
    {
        File.WriteAllBytes($"./uploads/{filename}", content);
        // Only exists on this server!
    }
}
```

**Solution:** Use shared storage
```csharp
// ✅ GOOD: Shared blob storage
public class FileService
{
    private readonly BlobServiceClient _blobClient;
    
    public async Task SaveFileAsync(string filename, Stream content)
    {
        var container = _blobClient.GetBlobContainerClient("uploads");
        var blob = container.GetBlobClient(filename);
        await blob.UploadAsync(content);
    }
}
```

### Designing Stateless APIs

#### RESTful API Principles

**1. Each Request Contains All Context**

```csharp
// Request includes all necessary information
[HttpGet("orders/{orderId}")]
public async Task<IActionResult> GetOrder(int orderId)
{
    // Authorization context from token
    var userId = User.FindFirstValue(ClaimTypes.NameIdentifier);
    
    var order = await _orderService.GetOrderAsync(orderId);
    
    // Verify ownership
    if (order.UserId != userId)
        return Forbid();
    
    return Ok(order);
}
```

**2. No Server-Side Workflow State**

```csharp
// ❌ BAD: Multi-step workflow with server state
private static Dictionary<string, WizardState> _wizardState = new();

[HttpPost("wizard/step1")]
public IActionResult Step1(Step1Data data)
{
    var state = new WizardState { Step1 = data };
    var wizardId = Guid.NewGuid().ToString();
    _wizardState[wizardId] = state;
    return Ok(new { wizardId });
}

[HttpPost("wizard/step2")]
public IActionResult Step2(string wizardId, Step2Data data)
{
    _wizardState[wizardId].Step2 = data;
    return Ok();
}
```

```csharp
// ✅ GOOD: Client maintains workflow state
[HttpPost("wizard/complete")]
public async Task<IActionResult> CompleteWizard(WizardData data)
{
    // Client sends all data at once
    var result = await _wizardService.ProcessAsync(data);
    return Ok(result);
}

// OR store in database between steps
[HttpPost("wizard/step1")]
public async Task<IActionResult> Step1(Step1Data data)
{
    var wizardId = Guid.NewGuid();
    await _db.WizardState.AddAsync(new WizardState
    {
        Id = wizardId,
        Step1 = data
    });
    await _db.SaveChangesAsync();
    return Ok(new { wizardId });
}
```

**3. Idempotent Operations**

```csharp
[HttpPut("orders/{orderId}")]
public async Task<IActionResult> UpdateOrder(int orderId, Order order)
{
    // Can safely retry - same input produces same result
    var existing = await _db.Orders.FindAsync(orderId);
    if (existing == null)
        return NotFound();
    
    existing.Status = order.Status;
    existing.UpdatedAt = DateTime.UtcNow;
    
    await _db.SaveChangesAsync();
    return Ok(existing);
}
```

### Authentication in Stateless Services

#### Token-Based Authentication (Stateless)

```csharp
// Issue JWT token on login
[HttpPost("login")]
public IActionResult Login(LoginRequest request)
{
    var user = _userService.Authenticate(request.Username, request.Password);
    if (user == null)
        return Unauthorized();
    
    var claims = new[]
    {
        new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
        new Claim(ClaimTypes.Email, user.Email),
        new Claim(ClaimTypes.Role, user.Role)
    };
    
    var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_config["Jwt:Key"]));
    var credentials = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);
    
    var token = new JwtSecurityToken(
        issuer: _config["Jwt:Issuer"],
        audience: _config["Jwt:Audience"],
        claims: claims,
        expires: DateTime.UtcNow.AddHours(24),
        signingCredentials: credentials
    );
    
    return Ok(new
    {
        token = new JwtSecurityTokenHandler().WriteToken(token),
        expiration = token.ValidTo
    });
}

// All subsequent requests include token
[Authorize]
[HttpGet("profile")]
public IActionResult GetProfile()
{
    var userId = User.FindFirstValue(ClaimTypes.NameIdentifier);
    var profile = _userService.GetProfile(userId);
    return Ok(profile);
}
```

**Benefits:**
- No server-side session storage
- Token contains all auth context
- Any server can validate token
- Scales horizontally without coordination

#### Distributed Session (Semi-Stateless)

```csharp
// Configure Redis for session storage
services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = "localhost:6379";
});

services.AddSession(options =>
{
    options.Cookie.HttpOnly = true;
    options.Cookie.IsEssential = true;
    options.IdleTimeout = TimeSpan.FromMinutes(30);
});

// Use session for user state
[HttpPost("login")]
public IActionResult Login(LoginRequest request)
{
    var user = _userService.Authenticate(request.Username, request.Password);
    if (user == null)
        return Unauthorized();
    
    HttpContext.Session.SetString("UserId", user.Id.ToString());
    HttpContext.Session.SetString("Email", user.Email);
    
    return Ok();
}

[HttpGet("profile")]
public IActionResult GetProfile()
{
    var userId = HttpContext.Session.GetString("UserId");
    if (userId == null)
        return Unauthorized();
    
    var profile = _userService.GetProfile(int.Parse(userId));
    return Ok(profile);
}
```

**Note:** While Redis is external, this is still "session-based." Token-based auth is more truly stateless.

### Twelve-Factor App Principles (Relevant to Statelessness)

#### Factor VI: Processes

**Execute the app as one or more stateless processes.**

> Any data that needs to persist must be stored in a stateful backing service, typically a database.

✅ **Good:**
```csharp
public class OrderService
{
    private readonly IDatabase _db;
    
    public async Task<Order> GetOrderAsync(int id)
    {
        return await _db.Orders.FindAsync(id);
    }
}
```

#### Factor X: Dev/Prod Parity

**Keep development, staging, and production as similar as possible.**

Stateless services make this easier - any environment can run the same code:

```csharp
// Configuration from environment
public void ConfigureServices(IServiceCollection services)
{
    var redisConnection = Configuration["Redis:ConnectionString"];
    services.AddStackExchangeRedisCache(opt => opt.Configuration = redisConnection);
}
```

#### Factor XI: Logs

**Treat logs as event streams.**

Don't write to local files—send to centralized logging:

```csharp
// ❌ BAD: Local file logging
services.AddLogging(builder =>
{
    builder.AddFile("logs/app.log");
});

// ✅ GOOD: Structured logging to external service
services.AddLogging(builder =>
{
    builder.AddApplicationInsights();
    builder.AddSeq("http://seq-server:5341");
});
```

### Practical Patterns

#### Pattern 1: Repository with Caching

```csharp
public class CachedUserRepository : IUserRepository
{
    private readonly IDistributedCache _cache;
    private readonly IUserRepository _dbRepo;
    
    public async Task<User> GetByIdAsync(int id)
    {
        var cacheKey = $"user:{id}";
        var cached = await _cache.GetStringAsync(cacheKey);
        
        if (cached != null)
            return JsonSerializer.Deserialize<User>(cached);
        
        var user = await _dbRepo.GetByIdAsync(id);
        if (user != null)
        {
            await _cache.SetStringAsync(
                cacheKey,
                JsonSerializer.Serialize(user),
                new DistributedCacheEntryOptions
                {
                    AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
                });
        }
        
        return user;
    }
}
```

#### Pattern 2: Background Jobs with Queues

```csharp
public class OrderController : ControllerBase
{
    private readonly IBackgroundJobClient _jobClient;
    
    [HttpPost("orders")]
    public async Task<IActionResult> CreateOrder(CreateOrderRequest request)
    {
        var order = await _orderService.CreateAsync(request);
        
        // Don't process synchronously - queue for background processing
        _jobClient.Enqueue<IOrderProcessor>(x => x.ProcessOrderAsync(order.Id));
        
        return Ok(new { orderId = order.Id });
    }
}
```

#### Pattern 3: Saga Pattern for Distributed Transactions

```csharp
public class OrderSaga
{
    public async Task ExecuteAsync(CreateOrderCommand command)
    {
        var orderId = await _orderService.CreateOrderAsync(command);
        
        try
        {
            await _inventoryService.ReserveItemsAsync(orderId, command.Items);
            await _paymentService.ChargeAsync(orderId, command.PaymentInfo);
            await _shippingService.CreateShipmentAsync(orderId, command.Address);
            
            await _orderService.CompleteOrderAsync(orderId);
        }
        catch (Exception ex)
        {
            // Compensating actions
            await _inventoryService.ReleaseItemsAsync(orderId);
            await _paymentService.RefundAsync(orderId);
            await _orderService.CancelOrderAsync(orderId);
            
            throw;
        }
    }
}
```

## Common Mistakes

| Mistake | Problem | Solution |
|---------|---------|----------|
| **In-memory caching** | Each server has different cache | Use distributed cache (Redis) |
| **Static fields** | State not shared across instances | Use external storage |
| **Sticky sessions** | Load balancer ties user to server | Design stateless, use distributed session |
| **Local file storage** | Files only on one server | Use blob storage (S3, Azure Blob) |
| **Background threads** | Work lost if server restarts | Use job queues (Hangfire, RabbitMQ) |

## Benefits of Stateless Design

✅ **Unlimited horizontal scaling** - Add/remove instances freely

✅ **High availability** - Instance failures don't lose state

✅ **Zero-downtime deployments** - Rolling updates without coordination

✅ **Auto-scaling** - Instances can be added/removed automatically

✅ **Simplified operations** - No special handling for individual servers

✅ **Geographic distribution** - Deploy instances globally

---

## Key Takeaways

- **Stateless services can handle any request on any instance** - enabling horizontal scaling
- **State doesn't disappear** - it moves to databases, caches, or client
- **Use tokens instead of sessions** for truly stateless authentication
- **Avoid static variables and in-memory storage** - they prevent scaling
- **Design APIs to include all context in each request** - no server-side workflow state
- **External storage enables stateless design** - Redis, databases, blob storage
