## Introduction

The Richardson Maturity Model describes four levels of REST API maturity, from simple HTTP endpoints (Level 0) to fully hypermedia-driven APIs (Level 3). HATEOAS, the highest level, means clients navigate your API by following links, making the API self-documenting and discoverable. While not all APIs need Level 3 maturity, understanding these concepts helps you make informed design decisions.

## Key Concepts Summary

### Richardson Maturity Model

```
Level 0: The Swamp of POX (Plain Old XML)
    - Single endpoint, single HTTP method (usually POST)
    - All operations sent to same URI
    - Like RPC over HTTP

Level 1: Resources
    - Multiple resource URIs
    - Still using single HTTP method (usually POST)
    - Beginning of resource-oriented thinking

Level 2: HTTP Verbs
    - Multiple resources with proper URIs
    - HTTP methods used correctly (GET, POST, PUT, DELETE)
    - HTTP status codes used appropriately
    - Most REST APIs stop here

Level 3: Hypermedia Controls (HATEOAS)
    - Everything from Level 2
    - Responses include links to related resources
    - Responses include links to available actions
    - API is discoverable and self-documenting
    - True REST according to Roy Fielding
```

### Level 0: The Swamp of POX

```csharp
// Level 0: Single endpoint, POST for everything
[ApiController]
[Route("api/service")]
public class Level0Controller : ControllerBase
{
    [HttpPost]
    public ActionResult ProcessRequest([FromBody] Request request)
    {
        // POST /api/service
        // Body: { "action": "getProduct", "id": 123 }
        // Body: { "action": "createOrder", "data": {...} }
        // Body: { "action": "deleteUser", "id": 456 }
        
        return request.Action switch
        {
            "getProduct" => GetProduct(request.Id),
            "createOrder" => CreateOrder(request.Data),
            "deleteUser" => DeleteUser(request.Id),
            _ => BadRequest("Unknown action")
        };
    }
}

// Issues:
// - Can't cache (everything is POST)
// - Can't use HTTP semantics
// - No standard tooling support
// - Not discoverable
// - This is basically RPC over HTTP, not REST
```

### Level 2: HTTP Verbs

```csharp
// Level 2: Resources + HTTP methods + status codes
[ApiController]
[Route("api/products")]
public class Level2Controller : ControllerBase
{
    [HttpGet]
    public ActionResult<List<ProductDto>> GetProducts()
    {
        // GET /api/products
        var products = _repository.GetAll();
        return Ok(products); // 200 OK
    }
    
    [HttpGet("{id}")]
    public ActionResult<ProductDto> GetProduct(int id)
    {
        // GET /api/products/123
        var product = _repository.GetById(id);
        
        if (product == null)
            return NotFound(); // 404 Not Found
        
        return Ok(product); // 200 OK
    }
    
    [HttpPost]
    public ActionResult<ProductDto> CreateProduct([FromBody] CreateProductRequest request)
    {
        // POST /api/products
        if (!ModelState.IsValid)
            return BadRequest(ModelState); // 400 Bad Request
        
        var product = _repository.Create(request);
        
        return CreatedAtAction(
            nameof(GetProduct),
            new { id = product.Id },
            product); // 201 Created with Location header
    }
    
    [HttpPut("{id}")]
    public ActionResult UpdateProduct(int id, [FromBody] ProductDto product)
    {
        // PUT /api/products/123
        if (!_repository.Exists(id))
            return NotFound(); // 404 Not Found
        
        _repository.Update(product);
        return NoContent(); // 204 No Content
    }
    
    [HttpDelete("{id}")]
    public ActionResult DeleteProduct(int id)
    {
        // DELETE /api/products/123
        if (!_repository.Exists(id))
            return NotFound(); // 404 Not Found
        
        _repository.Delete(id);
        return NoContent(); // 204 No Content
    }
}

// Improvements:
// ✅ Correct HTTP methods
// ✅ Proper status codes
// ✅ Idempotency where appropriate
// ✅ Can leverage HTTP features (caching GET, etc.)
// ✅ Standard tooling support

// Still missing:
// ❌ Not discoverable
// ❌ Clients need out-of-band documentation
// ❌ Tight coupling between client and server

// Note: Most REST APIs stop at Level 2!
// This is often called "RESTful" but not truly REST according to Roy Fielding
```

### Level 3: Hypermedia Controls (HATEOAS)

```csharp
// Level 3: Resources + HTTP + Hypermedia

// Link model
public class Link
{
    public string Href { get; set; }
    public string Rel { get; set; }
    public string Method { get; set; }
}

// Resource with links
public class ProductResource
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public string Status { get; set; }
    public List<Link> Links { get; set; } = new();
}

[ApiController]
[Route("api/products")]
public class Level3Controller : ControllerBase
{
    [HttpGet("{id}")]
    public ActionResult<ProductResource> GetProduct(int id)
    {
        var product = _repository.GetById(id);
        
        if (product == null)
            return NotFound();
        
        // Create resource with hypermedia links
        var resource = new ProductResource
        {
            Id = product.Id,
            Name = product.Name,
            Price = product.Price,
            Status = product.Status,
            Links = new List<Link>
            {
                // Self link
                new Link
                {
                    Href = Url.Action(nameof(GetProduct), new { id = product.Id }),
                    Rel = "self",
                    Method = "GET"
                },
                // Update link
                new Link
                {
                    Href = Url.Action(nameof(UpdateProduct), new { id = product.Id }),
                    Rel = "update",
                    Method = "PUT"
                },
                // Delete link
                new Link
                {
                    Href = Url.Action(nameof(DeleteProduct), new { id = product.Id }),
                    Rel = "delete",
                    Method = "DELETE"
                }
            }
        };
        
        // State-dependent links
        if (product.Status == "draft")
        {
            resource.Links.Add(new Link
            {
                Href = Url.Action(nameof(PublishProduct), new { id = product.Id }),
                Rel = "publish",
                Method = "POST"
            });
        }
        
        if (product.Status == "published")
        {
            resource.Links.Add(new Link
            {
                Href = Url.Action(nameof(UnpublishProduct), new { id = product.Id }),
                Rel = "unpublish",
                Method = "POST"
            });
        }
        
        // Related resources
        resource.Links.Add(new Link
        {
            Href = Url.Action(nameof(GetProductReviews), new { id = product.Id }),
            Rel = "reviews",
            Method = "GET"
        });
        
        return Ok(resource);
    }
    
    [HttpPost("{id}/publish")]
    public ActionResult PublishProduct(int id) { /* ... */ }
    
    [HttpPost("{id}/unpublish")]
    public ActionResult UnpublishProduct(int id) { /* ... */ }
    
    [HttpGet("{id}/reviews")]
    public ActionResult GetProductReviews(int id) { /* ... */ }
}

// Response example:
{
  "id": 123,
  "name": "Laptop",
  "price": 999.99,
  "status": "draft",
  "links": [
    {
      "href": "/api/products/123",
      "rel": "self",
      "method": "GET"
    },
    {
      "href": "/api/products/123",
      "rel": "update",
      "method": "PUT"
    },
    {
      "href": "/api/products/123",
      "rel": "delete",
      "method": "DELETE"
    },
    {
      "href": "/api/products/123/publish",
      "rel": "publish",
      "method": "POST"
    },
    {
      "href": "/api/products/123/reviews",
      "rel": "reviews",
      "method": "GET"
    }
  ]
}

// Benefits:
// ✅ API is discoverable
// ✅ Clients can navigate by following links
// ✅ Available actions clear from response
// ✅ Loose coupling (URLs can change)
// ✅ State transitions explicit

// Trade-offs:
// ⚠️ More complex implementation
// ⚠️ Larger response payloads
// ⚠️ Clients must be hypermedia-aware
// ⚠️ Not widely adopted
```

### HAL (Hypertext Application Language)

```csharp

// More standardized than custom link format

public class HalResource<T>
{
    [JsonProperty("_links")]
    public Dictionary<string, HalLink> Links { get; set; } = new();
    
    [JsonProperty("_embedded")]
    public Dictionary<string, object>? Embedded { get; set; }
    
    [JsonExtensionData]
    public T Data { get; set; }
}

public class HalLink
{
    public string Href { get; set; }
    public bool Templated { get; set; }
    public string? Type { get; set; }
}

[ApiController]
[Route("api/orders")]
public class OrdersHalController : ControllerBase
{
    [HttpGet("{id}")]
    public ActionResult GetOrder(int id)
    {
        var order = _repository.GetById(id);
        
        if (order == null)
            return NotFound();
        
        var resource = new HalResource<OrderDto>
        {
            Data = order,
            Links = new Dictionary<string, HalLink>
            {
                ["self"] = new HalLink
                {
                    Href = $"/api/orders/{id}"
                },
                ["customer"] = new HalLink
                {
                    Href = $"/api/customers/{order.CustomerId}"
                },
                ["cancel"] = new HalLink
                {
                    Href = $"/api/orders/{id}/cancel"
                }
            },
            Embedded = new Dictionary<string, object>
            {
                ["items"] = order.Items
            }
        };
        
        return Ok(resource);
    }
}
```

### Practical HATEOAS Implementation

```csharp
// Helper service for generating links
public interface ILinkGenerator
{
    Link CreateLink(string action, object? routeValues, string rel, string method);
    List<Link> CreateLinksForResource<T>(T resource, string resourceName);
}

public class LinkGenerator : ILinkGenerator
{
    private readonly IUrlHelper _urlHelper;
    
    public LinkGenerator(IUrlHelper urlHelper)
    {
        _urlHelper = urlHelper;
    }
    
    public Link CreateLink(string action, object? routeValues, string rel, string method)
    {
        return new Link
        {
            Href = _urlHelper.Action(action, routeValues),
            Rel = rel,
            Method = method
        };
    }
    
    public List<Link> CreateLinksForResource<T>(T resource, string resourceName)
    {
        var links = new List<Link>();
        var id = resource.GetType().GetProperty("Id")?.GetValue(resource);
        
        // Self link
        links.Add(CreateLink($"Get{resourceName}", new { id }, "self", "GET"));
        
        // Update link
        links.Add(CreateLink($"Update{resourceName}", new { id }, "update", "PUT"));
        
        // Delete link
        links.Add(CreateLink($"Delete{resourceName}", new { id }, "delete", "DELETE"));
        
        return links;
    }
}

// Base controller with HATEOAS support
public abstract class HateoasController : ControllerBase
{
    protected ILinkGenerator LinkGenerator { get; }
    
    protected HateoasController(ILinkGenerator linkGenerator)
    {
        LinkGenerator = linkGenerator;
    }
    
    protected ActionResult<T> OkWithLinks<T>(T resource, string resourceName)
        where T : IHaveLinks
    {
        resource.Links = LinkGenerator.CreateLinksForResource(resource, resourceName);
        return Ok(resource);
    }
}

public interface IHaveLinks
{
    List<Link> Links { get; set; }
}

// Usage
[ApiController]
[Route("api/customers")]
public class CustomersController : HateoasController
{
    public CustomersController(ILinkGenerator linkGenerator) : base(linkGenerator) { }
    
    [HttpGet("{id}")]
    public ActionResult<CustomerResource> GetCustomer(int id)
    {
        var customer = _repository.GetById(id);
        
        if (customer == null)
            return NotFound();
        
        var resource = new CustomerResource
        {
            Id = customer.Id,
            Name = customer.Name,
            Email = customer.Email
        };
        
        return OkWithLinks(resource, "Customer");
    }
}
```

### When to Use HATEOAS

```
Use HATEOAS when:
✅ Building a public API for broad consumption
✅ API needs to be highly discoverable
✅ You want loose coupling between client/server
✅ URLs may change over time
✅ State transitions are complex
✅ API is long-lived and needs to evolve
✅ Multiple client types with different capabilities

Skip HATEOAS when:
❌ Building internal APIs with known clients
❌ Performance is critical (larger payloads)
❌ Clients are simple and don't need discovery
❌ Team lacks experience with hypermedia
❌ Time/budget constraints
❌ Clients want simple JSON responses
❌ Mobile apps with bandwidth constraints

Pragmatic approach:
- Most APIs work well at Level 2
- Add links for key navigation points
- Use hypermedia for complex workflows
- Document your API regardless of level
- Consider hybrid: Level 2 with selective links
```

```csharp
// Standardized link relations (IANA registry)
public static class LinkRelations
{
    public const string Self = "self";
    public const string First = "first";
    public const string Last = "last";
    public const string Next = "next";
    public const string Prev = "prev";
    public const string Edit = "edit";
    public const string Delete = "delete";
    
    // Custom relations (use namespaced URIs)
    public const string Cancel = "https://api.example.com/rels/cancel";
    public const string Approve = "https://api.example.com/rels/approve";
}

[ApiController]
[Route("api/orders")]
public class OrdersWithStandardRelsController : ControllerBase
{
    [HttpGet("{id}")]
    public ActionResult<OrderResource> GetOrder(int id)
    {
        var order = _repository.GetById(id);
        
        if (order == null)
            return NotFound();
        
        var resource = new OrderResource
        {
            Id = order.Id,
            Status = order.Status,
            Links = new List<Link>
            {
                new Link { Href = Url.Action(nameof(GetOrder), new { id }), Rel = LinkRelations.Self },
                new Link { Href = Url.Action(nameof(UpdateOrder), new { id }), Rel = LinkRelations.Edit },
                new Link { Href = Url.Action(nameof(DeleteOrder), new { id }), Rel = LinkRelations.Delete }
            }
        };
        
        if (order.Status == "pending")
        {
            resource.Links.Add(new Link
            {
                Href = Url.Action(nameof(CancelOrder), new { id }),
                Rel = LinkRelations.Cancel
            });
        }
        
        return Ok(resource);
    }
}
```

### Pagination with HATEOAS

```csharp
// HATEOAS pagination
public class PagedResourceResponse<T>
{
    public List<T> Items { get; set; }
    public int Page { get; set; }
    public int PageSize { get; set; }
    public int TotalCount { get; set; }
    public PaginationLinks Links { get; set; }
}

[ApiController]
[Route("api/products")]
public class PaginatedHateoasController : ControllerBase
{
    [HttpGet]
    public ActionResult<PagedResourceResponse<ProductResource>> GetProducts(
        [FromQuery] int page = 1,
        [FromQuery] int pageSize = 20)
    {
        var products = _repository.GetPage(page, pageSize);
        var total = _repository.Count();
        var totalPages = (int)Math.Ceiling(total / (double)pageSize);
        
        var baseUrl = Url.Action(nameof(GetProducts));
        var links = new PaginationLinks
        {
            Self = $"{baseUrl}?page={page}&pageSize={pageSize}",
            First = $"{baseUrl}?page=1&pageSize={pageSize}",
            Last = $"{baseUrl}?page={totalPages}&pageSize={pageSize}"
        };
        
        if (page > 1) links.Previous = $"{baseUrl}?page={page - 1}&pageSize={pageSize}";
        if (page < totalPages) links.Next = $"{baseUrl}?page={page + 1}&pageSize={pageSize}";
        
        return Ok(new PagedResourceResponse<ProductResource>
        {
            Items = products.Select(p => new ProductResource { Id = p.Id, Name = p.Name }).ToList(),
            Page = page,
            PageSize = pageSize,
            TotalCount = total,
            Links = links
        });
    }
}
```

### HATEOAS for Workflows

```csharp
// Workflow with state-driven links
public enum OrderStatus { Draft, Submitted, Approved, Processing, Shipped, Cancelled }

[ApiController]
[Route("api/orders")]
public class WorkflowController : ControllerBase
{
    [HttpGet("{id}")]
    public ActionResult<OrderWorkflowResource> GetOrder(int id)
    {
        var order = _repository.GetById(id);
        if (order == null) return NotFound();
        
        var resource = new OrderWorkflowResource
        {
            Id = order.Id,
            Status = order.Status.ToString(),
            Links = new List<Link>
            {
                new Link { Href = Url.Action(nameof(GetOrder), new { id }), Rel = "self" }
            }
        };
        
        // Add available actions based on current state
        var actions = _workflowEngine.GetAvailableActions(order.Status);
        foreach (var action in actions)
        {
            resource.Links.Add(new Link
            {
                Href = Url.Action($"{action}Order", new { id }),
                Rel = action.ToLower(),
                Title = $"{action} order"
            });
        }
        
        return Ok(resource);
    }
}
// Client discovers available actions from links - no hardcoded workflow
```

## Self-Check Questions

1. **What are the four levels of the Richardson Maturity Model?**
   - Level 0: Single URI, single method (POX - Plain Old XML over HTTP)
   - Level 1: Multiple URIs, single method (resources introduced)
   - Level 2: Multiple URIs, multiple HTTP methods (HTTP verbs)
   - Level 3: Level 2 + Hypermedia controls (HATEOAS)

2. **What does HATEOAS stand for?**
   - Hypermedia As The Engine Of Application State
   - Means: server drives client state through hypermedia links
   - Client doesn't need to know URLs upfront

3. **What's the difference between Level 2 and Level 3 REST?**
   - Level 2: Uses HTTP methods and status codes correctly, but clients know URLs
   - Level 3: Adds hypermedia links, clients discover URLs from responses
   - Level 3 enables loose coupling and API evolution

4. **Why don't most APIs implement HATEOAS?**
   - Added complexity (implementation and client-side)
   - Larger response payloads
   - Limited tooling support
   - Steep learning curve
   - Overkill for simple, internal APIs
   - Level 2 is "good enough" for most use cases

5. **What are the benefits of hypermedia controls?**
   - Self-documenting API
   - Loose coupling (URLs can change)
   - State-driven workflows
   - Clients can be generic
   - Available actions clear from response
   - Non-breaking evolution

6. **When would you choose Level 2 over Level 3?**
   - Internal APIs with known clients
   - Simple CRUD operations
   - Performance-critical applications
   - Limited development time
   - Team lacks hypermedia experience
   - Mobile apps (bandwidth concerns)

7. **How do you test HATEOAS APIs?**
   - Client should follow links, not construct URLs
   - Test link presence based on state
   - Verify link rel values
   - Test workflow transitions via links
   - Check that clients work when URLs change
