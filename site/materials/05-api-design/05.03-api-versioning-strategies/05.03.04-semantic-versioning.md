## Introduction

Semantic Versioning (SemVer) provides a clear system for version numbers: MAJOR.MINOR.PATCH. While originally designed for software libraries, these principles apply to APIs: major versions introduce breaking changes, minor versions add features backward-compatibly, and patches fix bugs without changing the contract. Understanding what constitutes a breaking change is crucial for maintaining API stability.

## Key Concepts Summary

### Semantic Versioning Format

```
API Version: MAJOR.MINOR.PATCH

Examples:
1.0.0 - Initial release
1.0.1 - Bug fix (patch)
1.1.0 - New feature, backward compatible (minor)
2.0.0 - Breaking change (major)

Version increment rules:
MAJOR: Breaking changes (incompatible API changes)
MINOR: New features (backward compatible)
PATCH: Bug fixes (backward compatible)
```

### Breaking Changes

```csharp
// ❌ BREAKING CHANGES (require major version bump)

// 1. Removing an endpoint
// v1.0
[HttpGet("products")]
public ActionResult GetProducts() { }

// v2.0 - BREAKING: Removed endpoint
// [HttpGet("products")]  // Removed!

// 2. Removing a field from response
// v1.0
public class ProductDto
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}

// v2.0 - BREAKING: Removed Price field
public class ProductDto
{
    public int Id { get; set; }
    public string Name { get; set; }
    // Price removed!
}

// 3. Changing field type
// v1.0
public class OrderDto
{
    public string OrderDate { get; set; }  // String
}

// v2.0 - BREAKING: Changed type
public class OrderDto
{
    public DateTime OrderDate { get; set; }  // DateTime
}

// 4. Renaming a field
// v1.0
public class UserDto
{
    public string Email { get; set; }
}

// v2.0 - BREAKING: Renamed field
public class UserDto
{
    public string EmailAddress { get; set; }  // Renamed from Email
}

// 5. Making optional field required
// v1.0
public class CreateProductRequest
{
    public string Name { get; set; }
    public string? Category { get; set; }  // Optional
}

// v2.0 - BREAKING: Now required
public class CreateProductRequest
{
    public string Name { get; set; }
    public string Category { get; set; }  // Required!
}

// 6. Changing URL structure
// v1.0: GET /api/products/{id}
// v2.0: GET /api/catalog/products/{id}  // BREAKING

// 7. Changing HTTP method
// v1.0: POST /api/products/search
// v2.0: GET /api/products/search  // BREAKING

// 8. Changing status codes
// v1.0: Returns 200 on success
// v2.0: Returns 201 on success  // BREAKING

// 9. Changing error response format
// v1.0
{
  "error": "Product not found"
}

// v2.0 - BREAKING: New structure
{
  "errors": [
    { "code": "NOT_FOUND", "message": "Product not found" }
  ]
}

// 10. Changing authentication mechanism
// v1.0: API Key auth
// v2.0: OAuth2 only  // BREAKING
```

### Non-Breaking Changes

```csharp
// ✅ NON-BREAKING CHANGES (minor or patch version)

// 1. Adding new optional field to response
// v1.0
public class ProductDto
{
    public int Id { get; set; }
    public string Name { get; set; }
}

// v1.1 - NON-BREAKING: Added optional field
public class ProductDto
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string? Description { get; set; }  // New optional field
}

// 2. Adding new optional query parameter
// v1.0
[HttpGet]
public ActionResult GetProducts()
{
    // Implementation
}

// v1.1 - NON-BREAKING: Added optional parameter
[HttpGet]
public ActionResult GetProducts([FromQuery] string? category = null)
{
    // Implementation with optional filter
}

// 3. Adding new endpoint
// v1.0: GET /api/products
// v1.1: GET /api/products/featured  // NEW endpoint, non-breaking

// 4. Adding new optional request field
// v1.0
public class CreateProductRequest
{
    public string Name { get; set; }
    public decimal Price { get; set; }
}

// v1.1 - NON-BREAKING: Added optional field
public class CreateProductRequest
{
    public string Name { get; set; }
    public decimal Price { get; set; }
    public string? Description { get; set; }  // Optional
}

// 5. Making required field optional
// v1.0
public class UpdateUserRequest
{
    public string Phone { get; set; }  // Required
}

// v1.1 - NON-BREAKING: Now optional
public class UpdateUserRequest
{
    public string? Phone { get; set; }  // Optional (less restrictive)
}

// 6. Relaxing validation
// v1.0: Email must be exactly "user@domain.com"
// v1.1: Email can be "user@domain.com" or "user+tag@domain.com"  // NON-BREAKING

// 7. Improving performance (same contract)
// v1.0: Returns in 500ms
// v1.0.1: Returns in 100ms  // PATCH: performance improvement

// 8. Bug fixes that don't change contract
// v1.0.1: Fixed pagination bug  // PATCH

// 9. Adding response headers
// v1.1: Added X-RateLimit-Remaining header  // NON-BREAKING

// 10. Deprecation warnings (before removal)
// v1.1: Mark field as deprecated, still functional
[Obsolete("Use EmailAddress instead")]
public string Email { get; set; }
public string EmailAddress { get; set; }  // New field
```

### Gradual Migration Strategies

```csharp
// Strategy 1: Add field as optional, then make required later
// v1.0: No category field
public class ProductV1
{
    public int Id { get; set; }
    public string Name { get; set; }
}

// v1.5: Category added as optional (MINOR version)
public class ProductV15
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string? Category { get; set; }  // Optional
}

// v2.0: Category now required (MAJOR version)
public class ProductV2
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Category { get; set; }  // Required
}

// Strategy 2: Parallel fields during transition
// v1.5: Both old and new field (deprecate old)
public class ProductTransition
{
    public int Id { get; set; }
    public string Name { get; set; }
    
    [Obsolete("Use Authors instead")]
    public string Author { get; set; }        // Deprecated but functional
    
    public List<string> Authors { get; set; } // New field
}

// v2.0: Remove old field
public class ProductV2
{
    public int Id { get; set; }
    public string Name { get; set; }
    public List<string> Authors { get; set; } // Only new field
}

// Strategy 3: Version negotiation for clients
[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpPost]
    public ActionResult CreateProduct([FromBody] JObject request, ApiVersion version)
    {
        if (version.MajorVersion == 1)
        {
            // Accept v1 format, store internally with defaults
            var product = new Product
            {
                Name = request["name"]?.ToString() ?? throw new ArgumentException(),
                Category = "Uncategorized"  // Default for v1 clients
            };
            
            return Ok(MapToV1(product));
        }
        else
        {
            // v2 requires category
            if (request["category"] == null)
                return BadRequest("Category is required in v2");
            
            var product = new Product
            {
                Name = request["name"]?.ToString() ?? throw new ArgumentException(),
                Category = request["category"]?.ToString() ?? throw new ArgumentException()
            };
            
            return Ok(MapToV2(product));
        }
    }
}

### Automated Breaking Change Detection

```csharp
// Use OpenAPI/Swagger diff to detect breaking changes

public class ApiBreakingChangeDetector
{
    public async Task<List<BreakingChange>> DetectBreakingChanges(
        string oldSwaggerUrl,
        string newSwaggerUrl)
    {
        var oldSpec = await LoadOpenApiSpec(oldSwaggerUrl);
        var newSpec = await LoadOpenApiSpec(newSwaggerUrl);
        
        var breakingChanges = new List<BreakingChange>();
        
        // Check for removed endpoints
        foreach (var oldPath in oldSpec.Paths)
        {
            if (!newSpec.Paths.ContainsKey(oldPath.Key))
            {
                breakingChanges.Add(new BreakingChange
                {
                    Type = "RemovedEndpoint",
                    Path = oldPath.Key,
                    Severity = "Critical",
                    Message = $"Endpoint {oldPath.Key} was removed"
                });
            }
        }
        
        // Check for changed response schemas
        foreach (var path in oldSpec.Paths)
        {
            if (newSpec.Paths.TryGetValue(path.Key, out var newPath))
            {
                var oldSchema = GetResponseSchema(path.Value);
                var newSchema = GetResponseSchema(newPath);
                
                // Check for removed fields
                foreach (var oldProperty in oldSchema.Properties)
                {
                    if (!newSchema.Properties.ContainsKey(oldProperty.Key))
                    {
                        breakingChanges.Add(new BreakingChange
                        {
                            Type = "RemovedField",
                            Path = path.Key,
                            Field = oldProperty.Key,
                            Severity = "High",
                            Message = $"Field {oldProperty.Key} removed from {path.Key}"
                        });
                    }
                }
                
                // Check for type changes
                foreach (var property in oldSchema.Properties)
                {
                    if (newSchema.Properties.TryGetValue(property.Key, out var newProp))
                    {
                        if (property.Value.Type != newProp.Type)
                        {
                            breakingChanges.Add(new BreakingChange
                            {
                                Type = "TypeChange",
                                Path = path.Key,
                                Field = property.Key,
                                Severity = "Critical",
                                Message = $"Field {property.Key} type changed from {property.Value.Type} to {newProp.Type}"
                            });
                        }
                    }
                }
            }
        }
        
        return breakingChanges;
    }
}

// CI/CD integration
// Run this in your build pipeline to catch breaking changes
public class BuildPipelineCheck
{
    public async Task<bool> ValidateNoBreakingChanges()
    {
        var detector = new ApiBreakingChangeDetector();
        var changes = await detector.DetectBreakingChanges(
            "https://api.example.com/swagger/v1/swagger.json",  // Production
            "http://localhost:5000/swagger/v1/swagger.json"     // Build
        );
        
        var breakingChanges = changes.Where(c => 
            c.Severity == "Critical" || c.Severity == "High");
        
        if (breakingChanges.Any())
        {
            Console.WriteLine("⚠️ BREAKING CHANGES DETECTED:");
            foreach (var change in breakingChanges)
            {
                Console.WriteLine($"  - {change.Type}: {change.Message}");
            }
            
            Console.WriteLine("\n❌ Build failed: Breaking changes in minor/patch version");
            return false;
        }
        
        return true;
    }
}
```

## Practice Exercise

Plan version evolution for an Orders API:

**Current version 1.0.0:**
```json
GET /api/orders/123
{
  "id": 123,
  "customerId": 456,
  "items": ["item1", "item2"],
  "total": 59.99,
  "status": "pending"
}
```

**Planned changes:**
1. Add `orderDate` field
2. Change `items` from string array to object array
3. Add pagination to list endpoint
4. Require `shippingAddress` on creation
5. Add new endpoint for order tracking
6. Change `id` from number to string
7. Fix bug in total calculation
8. Add optional `notes` field

**Categorization:**

**MAJOR version (2.0.0) - Breaking changes:**
- #2: Change `items` from string[] to object[] - BREAKING (type change)
- #4: Require `shippingAddress` on creation - BREAKING (new required field)
- #6: Change `id` from number to string - BREAKING (type change)

**MINOR version (1.X.0) - Backward-compatible additions:**
- #1: Add `orderDate` field - NON-BREAKING (new optional field in response)
- #3: Add pagination to list endpoint - NON-BREAKING (new optional query params)
- #5: Add new endpoint for tracking - NON-BREAKING (new endpoint)
- #8: Add optional `notes` field - NON-BREAKING (optional field)

**PATCH version (1.0.X) - Bug fixes:**
- #7: Fix bug in total calculation - NON-BREAKING (bug fix, same contract)

**Version sequence:**

1. **v1.0.1** (Patch)
   - Fix total calculation bug
   - No contract changes

2. **v1.1.0** (Minor)
   - Add optional `orderDate` field in response
   - Add optional `notes` field in request/response
   - Add pagination support (optional query params)
   - Add new GET /api/orders/{id}/tracking endpoint
   - All changes backward-compatible

3. **v2.0.0** (Major)
   - Change `items` from string[] to OrderItem[]
   - Change `id` from number to string (GUID)
   - Require `shippingAddress` in POST requests
   - Include all v1.1.0 features

**Migration Guide for v1.0 → v2.0:**

```markdown
# Breaking Changes in v2.0.0

## 1. Order ID is now string (GUID)
**v1.0:**
```json
{ "id": 123 }
```

**v2.0:**
```json
{ "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890" }
```

**Migration:** Update your code to handle string IDs instead of integers.

## 2. Items structure changed
**v1.0:**
```json
{ "items": ["item1", "item2"] }
```

**v2.0:**
```json
{
  "items": [
    { "productId": "abc", "name": "item1", "quantity": 2, "price": 29.99 },
    { "productId": "def", "name": "item2", "quantity": 1, "price": 19.99 }
  ]
}
```

**Migration:** Parse items as objects instead of strings.

## 3. Shipping address now required
**v1.0 (optional):**
```json

{ "customerId": 456, "items": [...] }
```

**v2.0 (required):**
```json
POST /api/orders
{ 
  "customerId": 456,
  "items": [...],
  "shippingAddress": {
    "street": "123 Main St",
    "city": "Portland",
    "state": "OR",
    "zip": "97201"
  }
}
```

**Migration:** Ensure all order creation requests include `shippingAddress`.

## Self-Check Questions

1. **What's the difference between MAJOR, MINOR, and PATCH versions?**
   - MAJOR (X.0.0): Breaking changes (incompatible API changes)
   - MINOR (1.X.0): New features (backward compatible)
   - PATCH (1.0.X): Bug fixes (backward compatible)

2. **Name 5 types of breaking changes in APIs**
   - Removing an endpoint or field
   - Changing field type (string → int)
   - Renaming a field
   - Making optional field required
   - Changing URL structure

3. **Name 5 types of non-breaking changes**
   - Adding new optional field to response
   - Adding new optional query parameter
   - Adding new endpoint
   - Making required field optional
   - Relaxing validation rules

4. **When should you increment the major version?**
   - Any change that breaks existing clients
   - Removed fields/endpoints
   - Type changes
   - New required fields
   - Changed error formats

5. **How do you maintain backward compatibility?**
   - Only add new optional fields
   - Never remove or rename existing fields
   - Use parallel fields during transitions
   - Provide default values for new fields
   - Document deprecations before removal

6. **What information should be in a changelog?**
   - Version number and release date
   - Breaking changes (with migration guide)
   - New features (added)
   - Bug fixes (fixed)
   - Deprecated features (will be removed)
   - Dependencies/requirements changes
