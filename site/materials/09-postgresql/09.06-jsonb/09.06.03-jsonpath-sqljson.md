- Apply filter expressions in JSONPath queries
- Extract and transform data using path-based queries
- Understand when to use JSONPath vs simple operators

---

## Introduction

JSONPath is a query language for JSON, similar to XPath for XML. PostgreSQL implements the SQL/JSON path language standard, which provides powerful capabilities for querying complex, nested JSON structures. While simple operators (`->`, `->>`) work well for straightforward access patterns, JSONPath expressions excel at complex queries involving filters, predicates, and conditional logic.

Understanding JSONPath is essential for working with deeply nested JSON documents and performing sophisticated queries that would be difficult or impossible with basic operators alone.

## Key Concepts Summary

### JSONPath Basics

JSONPath expressions are passed as strings to SQL/JSON functions:

```sql
-- Basic pattern
SELECT jsonb_path_query(column, '$.path.to.value') 
FROM table_name;
```

### Core JSONPath Operators

| Operator | Description | Example |
|----------|-------------|---------|
| `$` | Root element | `$` |
| `.key` | Object field access | `$.user.name` |
| `.*` | All object fields | `$.user.*` |
| `[n]` | Array element by index | `$.tags[0]` |
| `[*]` | All array elements | `$.tags[*]` |
| `[start:end]` | Array slice | `$.items[0:3]` |
| `..key` | Recursive descent | `$..name` |
| `@` | Current element in filter | `$.prices[?(@>10)]` |
| `?()` | Filter expression | `$.users[?(@.age > 18)]` |

### SQL/JSON Path Functions

**`jsonb_path_query()` - Return All Matches**

Returns all JSON items matching the path as a set of rows:

```sql
-- Extract all emails from nested structure
SELECT jsonb_path_query(
    data,
    '$.users[*].email'
) AS emails
FROM organizations;

-- Get all product prices
SELECT jsonb_path_query(
    inventory,
    '$.products[*].price'
) AS prices
FROM stores;
```

**`jsonb_path_query_first()` - Return First Match**

Returns only the first match:

```sql
-- Get first user's email
SELECT jsonb_path_query_first(
    data,
    '$.users[*].email'
) AS first_email
FROM organizations;
```

**`jsonb_path_exists()` - Check If Path Exists**

Returns boolean indicating whether path returns any items:

```sql
-- Check if user has admin role
SELECT 
    user_id,
    jsonb_path_exists(
        profile,
        '$.roles[*] ? (@ == "admin")'
    ) AS is_admin
FROM users;

-- Find orders with high-value items
SELECT * FROM orders
WHERE jsonb_path_exists(
    items,
    '$[*].price ? (@ > 1000)'
);
```

**`jsonb_path_match()` - Evaluate Boolean Expression**

Returns result of predicate evaluation:

```sql
-- Check if all items are in stock
SELECT 
    order_id,
    jsonb_path_match(
        items,
        '$[*].in_stock ? (@ == true)'
    ) AS all_in_stock
FROM orders;
```

### Path Expressions

**Simple Property Access**

```sql
-- Single level
SELECT jsonb_path_query('{"name": "Alice"}', '$.name');
-- Result: "Alice"

-- Nested
SELECT jsonb_path_query(
    '{"user": {"profile": {"city": "NYC"}}}',
    '$.user.profile.city'
);
-- Result: "NYC"

-- All properties at level
SELECT jsonb_path_query(
    '{"a": 1, "b": 2, "c": 3}',
    '$.*'
);
-- Results: 1, 2, 3 (three rows)
```

**Array Access**

```sql
-- Specific index
SELECT jsonb_path_query('[10, 20, 30, 40]', '$[1]');
-- Result: 20

-- All elements
SELECT jsonb_path_query('[10, 20, 30, 40]', '$[*]');
-- Results: 10, 20, 30, 40 (four rows)

-- Array slice
SELECT jsonb_path_query('[10, 20, 30, 40]', '$[1:3]');
-- Results: 20, 30

-- Last element (negative index)
SELECT jsonb_path_query('[10, 20, 30, 40]', '$[last]');
-- Result: 40
```

**Recursive Descent**

Find all occurrences of a key at any depth:

```sql
-- Find all "name" fields anywhere in structure
SELECT jsonb_path_query(
    '{
        "name": "Company",
        "employees": [
            {"name": "Alice", "dept": {"name": "Engineering"}},
            {"name": "Bob", "dept": {"name": "Sales"}}
        ]
    }',
    '$..name'
);
-- Results: "Company", "Alice", "Engineering", "Bob", "Sales"
```

### Filter Expressions

**Comparison Operators**

```sql
-- Greater than
SELECT jsonb_path_query(
    '[{"price": 10}, {"price": 20}, {"price": 30}]',
    '$[*] ? (@.price > 15)'
);
-- Results: {"price": 20}, {"price": 30}

-- Equality
SELECT jsonb_path_query(
    '[{"status": "active"}, {"status": "inactive"}]',
    '$[*] ? (@.status == "active")'
);
-- Result: {"status": "active"}

-- Less than or equal
SELECT jsonb_path_query(
    '[{"age": 18}, {"age": 25}, {"age": 30}]',
    '$[*] ? (@.age <= 25)'
);
-- Results: {"age": 18}, {"age": 25}
```

**Logical Operators**

```sql
-- AND (&&)
SELECT jsonb_path_query(
    '[
        {"price": 100, "in_stock": true},
        {"price": 50, "in_stock": false},
        {"price": 150, "in_stock": true}
    ]',
    '$[*] ? (@.price > 75 && @.in_stock == true)'
);
-- Results: {"price": 100, "in_stock": true}, {"price": 150, "in_stock": true}

-- OR (||)
SELECT jsonb_path_query(
    '[
        {"type": "premium"},
        {"type": "standard"},
        {"type": "trial"}
    ]',
    '$[*] ? (@.type == "premium" || @.type == "trial")'
);
-- Results: {"type": "premium"}, {"type": "trial"}

-- NOT (!)
SELECT jsonb_path_query(
    '[{"active": true}, {"active": false}]',
    '$[*] ? (!(@.active == false))'
);
-- Result: {"active": true}
```

**String Matching**

```sql
-- starts with
SELECT jsonb_path_query(
    '[{"email": "alice@example.com"}, {"email": "bob@test.com"}]',
    '$[*] ? (@.email starts with "alice")'
);
-- Result: {"email": "alice@example.com"}

-- like_regex
SELECT jsonb_path_query(
    '[{"code": "ABC123"}, {"code": "XYZ789"}]',
    '$[*] ? (@.code like_regex "^[A-Z]{3}")'
);
-- Results: {"code": "ABC123"}, {"code": "XYZ789"}
```

**Existence Checks**

```sql
-- Check if key exists
SELECT jsonb_path_query(
    '[{"name": "Alice", "age": 30}, {"name": "Bob"}]',
    '$[*] ? (exists(@.age))'
);
-- Result: {"name": "Alice", "age": 30}

-- Check if key doesn't exist
SELECT jsonb_path_query(
    '[{"name": "Alice", "age": 30}, {"name": "Bob"}]',
    '$[*] ? (!exists(@.age))'
);
-- Result: {"name": "Bob"}
```

### Complex Queries

**Nested Filtering**

```sql
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    data JSONB
);

INSERT INTO orders (data) VALUES 
('{
    "customer": {"name": "Alice", "vip": true},
    "items": [
        {"product": "Laptop", "price": 1200, "qty": 1},
        {"product": "Mouse", "price": 25, "qty": 2}
    ],
    "total": 1250
}'),
('{
    "customer": {"name": "Bob", "vip": false},
    "items": [
        {"product": "Keyboard", "price": 80, "qty": 1}
    ],
    "total": 80
}');

-- Find VIP customers with high-value items
SELECT 
    id,
    jsonb_path_query(data, '$.customer.name') AS customer
FROM orders
WHERE jsonb_path_exists(
    data,
    '$ ? (@.customer.vip == true && exists(@.items[*] ? (@.price > 1000)))'
);
```

**Aggregating Path Results**

```sql
-- Sum all prices in nested structure
SELECT 
    id,
    SUM((jsonb_path_query(data, '$.items[*].price'))::numeric) AS total_price
FROM orders
GROUP BY id;

-- Count items per order
SELECT 
    id,
    COUNT(jsonb_path_query(data, '$.items[*]')) AS item_count
FROM orders
GROUP BY id;
```

**Extracting to Rows**

```sql
-- Expand all items across all orders
SELECT 
    o.id AS order_id,
    item->>'product' AS product,
    (item->>'price')::numeric AS price,
    (item->>'qty')::integer AS quantity
FROM orders o,
     jsonb_path_query(data, '$.items[*]') AS item;
```

### When to Use JSONPath vs Simple Operators

**Use Simple Operators when:**
- Accessing known, fixed paths (`->`, `->>`)
- Simple containment checks (`@>`, `<@`)
- Key existence (`?`)
- Better performance for simple cases

```sql
-- Simple operator (faster)
SELECT * FROM users WHERE profile->>'city' = 'NYC';
```

**Use JSONPath when:**
- Complex filtering conditions
- Need to work with unknown structure
- Recursive descent required
- Multiple predicates combined
- Working with variable-depth nesting

```sql
-- JSONPath (more powerful)
SELECT * FROM users 
WHERE jsonb_path_exists(
    profile,
    '$ ? (@.address.city == "NYC" && @.age > 25)'
);
```

## Practice Exercise

After completing the materials, try this exercise (do not spend more than 25 minutes):

1. Create sample data:

```sql
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    catalog JSONB
);

INSERT INTO products (catalog) VALUES 
('{
    "category": "Electronics",
    "items": [
        {"name": "Laptop", "price": 1299, "specs": {"ram": "16GB", "cpu": "i7"}, "in_stock": true},
        {"name": "Mouse", "price": 29, "specs": {"wireless": true}, "in_stock": true},
        {"name": "Monitor", "price": 399, "specs": {"size": "27inch", "resolution": "4K"}, "in_stock": false}
    ]
}'),
('{
    "category": "Books",
    "items": [
        {"name": "PostgreSQL Guide", "price": 45, "author": "John Doe", "in_stock": true},
        {"name": "SQL Mastery", "price": 39, "author": "Jane Smith", "in_stock": true}
    ]
}');
```

2. Practice path queries:

```sql
-- Get all item names
SELECT jsonb_path_query(catalog, '$.items[*].name') AS item_name
FROM products;

-- Get all prices
SELECT jsonb_path_query(catalog, '$.items[*].price') AS prices
FROM products;

-- Get all spec keys (nested)
SELECT DISTINCT jsonb_path_query(catalog, '$.items[*].specs.*') AS spec_values
FROM products;
```

3. Practice filtering:

```sql
-- Find expensive items (price > 100)
SELECT 
    id,
    jsonb_path_query(catalog, '$.items[*] ? (@.price > 100)') AS expensive_items
FROM products;

-- Find in-stock items
SELECT 
    id,
    jsonb_path_query(catalog, '$.items[*] ? (@.in_stock == true).name') AS available
FROM products;

-- Find items with specific specs
SELECT 
    id,
    jsonb_path_query(catalog, '$.items[*] ? (exists(@.specs.wireless))') AS wireless_items
FROM products;
```

4. Practice complex queries:

```sql
-- Find products with any high-value in-stock items
SELECT id, catalog->>'category' AS category
FROM products
WHERE jsonb_path_exists(
    catalog,
    '$.items[*] ? (@.price > 100 && @.in_stock == true)'
);

-- Find electronics with i7 CPU
SELECT 
    id,
    jsonb_path_query(catalog, '$.items[*] ? (@.specs.cpu starts with "i7")') AS i7_products
FROM products
WHERE catalog->>'category' = 'Electronics';

-- Count items per category
SELECT 
    catalog->>'category' AS category,
    COUNT(jsonb_path_query(catalog, '$.items[*]')) AS item_count
FROM products
GROUP BY catalog->>'category';
```

5. Practice recursive descent:

```sql
-- Find all "name" fields at any level
SELECT jsonb_path_query(catalog, '$..name') AS all_names
FROM products;

-- Find all numeric values
SELECT jsonb_path_query(catalog, '$..**? (@.type() == "number")') AS numbers
FROM products;
```
