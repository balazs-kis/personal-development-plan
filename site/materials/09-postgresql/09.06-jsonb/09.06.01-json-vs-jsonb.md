## Introduction

PostgreSQL provides two data types for storing JSON: `json` and `jsonb`. While they may seem similar, they have significant differences in storage format, performance characteristics, and capabilities. Understanding these differences is crucial for making the right design decisions.

JSONB (Binary JSON) is almost always the better choice for production applications. It offers faster querying, indexing support, and better overall performance at the cost of slightly slower inserts.

## Key Concepts Summary

### JSON vs JSONB: Key Differences

| Aspect | JSON | JSONB |
|--------|------|-------|
| Storage | Plain text | Binary (parsed) |
| Whitespace | Preserved | Removed |
| Key Order | Preserved | Sorted alphabetically |
| Duplicate Keys | Kept | Last value wins |
| Insert Speed | Faster | Slightly slower (parsing overhead) |
| Query Speed | 3-10x slower (must reparse) | Fast (pre-parsed) |
| Indexing | Functional indexes only | GIN indexes supported |
| Use Case | Exact text preservation | Production queries |

### When to Use JSON vs JSONB

**Use JSON when:**
- You need to preserve exact text formatting
- You must maintain original key order
- You need duplicate keys
- Data is write-once, rarely queried
- Example: Logging exact API responses for audit

**Use JSONB when (most cases):**
- You'll query the data
- Performance matters
- You need indexing
- You want operator support
- Example: User preferences, product attributes, metadata

### Creating Tables with JSONB

```sql
-- Simple JSONB column
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email TEXT NOT NULL,
    profile JSONB
);

-- Multiple JSONB columns
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    price NUMERIC(10,2),
    attributes JSONB,  -- Flexible product attributes
    metadata JSONB     -- Internal metadata
);

-- JSONB with constraints
CREATE TABLE events (
    id SERIAL PRIMARY KEY,
    event_type TEXT NOT NULL,
    payload JSONB NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    CHECK (payload ? 'user_id')  -- Ensure key exists
);
```

### Inserting JSONB Data

```sql
-- Insert JSONB literal
INSERT INTO users (email, profile)
VALUES ('alice@example.com', '{"age": 30, "city": "New York"}');

-- Insert from variable (application code)
INSERT INTO users (email, profile)
VALUES ('bob@example.com', $1);  -- Pass JSONB from application

-- Insert nested JSONB
INSERT INTO products (name, price, attributes)
VALUES (
    'Laptop',
    999.99,
    '{
        "brand": "TechCorp",
        "specs": {
            "cpu": "Intel i7",
            "ram": "16GB",
            "storage": "512GB SSD"
        },
        "colors": ["silver", "black"]
    }'
);

-- Build JSONB from SQL
INSERT INTO events (event_type, payload)
VALUES (
    'user_signup',
    jsonb_build_object(
        'user_id', 123,
        'email', 'charlie@example.com',
        'timestamp', NOW()
    )
);
```

### Retrieving JSONB Data

```sql
-- Select entire JSONB column
SELECT id, profile FROM users;

-- Extract specific field as JSONB
SELECT id, profile->'city' AS city FROM users;

-- Extract specific field as TEXT
SELECT id, profile->>'city' AS city FROM users;

-- Extract nested field
SELECT 
    name,
    attributes->'specs'->>'cpu' AS cpu,
    attributes->'specs'->>'ram' AS ram
FROM products;
```

### JSON vs JSONB Example

```sql
-- Create test table with both types
CREATE TABLE json_test (
    id SERIAL PRIMARY KEY,
    data_json JSON,
    data_jsonb JSONB
);

-- Insert same data to both
INSERT INTO json_test (data_json, data_jsonb)
VALUES (
    '{"name": "Alice", "age": 30, "name": "Bob"}',  -- Duplicate key
    '{"name": "Alice", "age": 30, "name": "Bob"}'
);

-- Observe differences
SELECT 
    data_json,   -- {"name": "Alice", "age": 30, "name": "Bob"}
    data_jsonb   -- {"age": 30, "name": "Bob"} - last value wins, keys sorted
FROM json_test;

-- Query performance difference
EXPLAIN ANALYZE
SELECT * FROM json_test WHERE data_json->>'age' = '30';
-- Must parse JSON text for every row

EXPLAIN ANALYZE
SELECT * FROM json_test WHERE data_jsonb->>'age' = '30';
-- No parsing needed, faster
```

### Validation

PostgreSQL automatically validates JSON syntax:

```sql
-- Valid JSON - succeeds
INSERT INTO users (email, profile)
VALUES ('valid@example.com', '{"age": 30}');

-- Invalid JSON - fails
INSERT INTO users (email, profile)
VALUES ('invalid@example.com', '{age: 30}');  -- Missing quotes
-- ERROR: invalid input syntax for type json

-- Malformed JSON - fails
INSERT INTO users (email, profile)
VALUES ('bad@example.com', '{"age": 30');  -- Missing closing brace
-- ERROR: invalid input syntax for type json
```

### Common Use Cases for JSONB

**1. User Preferences and Settings**
```sql
CREATE TABLE user_preferences (
    user_id INTEGER PRIMARY KEY,
    settings JSONB DEFAULT '{}'
);

INSERT INTO user_preferences (user_id, settings)
VALUES (1, '{
    "theme": "dark",
    "notifications": {
        "email": true,
        "push": false
    },
    "language": "en"
}');
```

**2. Product Attributes (E-commerce)**
```sql
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    category TEXT NOT NULL,
    name TEXT NOT NULL,
    attributes JSONB
);

-- Different products have different attributes
INSERT INTO products (category, name, attributes) VALUES
    ('laptop', 'MacBook Pro', '{"cpu": "M2", "ram": "16GB", "screen": "14-inch"}'),
    ('phone', 'iPhone 14', '{"storage": "128GB", "color": "black", "carrier": "unlocked"}'),
    ('book', '1984', '{"author": "George Orwell", "pages": 328, "isbn": "978-0451524935"}');
```

**3. API Response Storage**
```sql
CREATE TABLE api_logs (
    id SERIAL PRIMARY KEY,
    endpoint TEXT NOT NULL,
    response JSONB,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Store entire API response for debugging
INSERT INTO api_logs (endpoint, response)
VALUES ('/api/users', '{
    "status": 200,
    "data": [
        {"id": 1, "name": "Alice"},
        {"id": 2, "name": "Bob"}
    ],
    "meta": {"total": 2, "page": 1}
}');
```

**4. Event Logging**
```sql
CREATE TABLE events (
    id SERIAL PRIMARY KEY,
    event_type TEXT NOT NULL,
    user_id INTEGER,
    payload JSONB,
    occurred_at TIMESTAMP DEFAULT NOW()
);

INSERT INTO events (event_type, user_id, payload) VALUES
    ('login', 123, '{"ip": "192.168.1.1", "device": "Chrome/Mac"}'),
    ('purchase', 456, '{"order_id": 789, "amount": 99.99, "items": [{"id": 1, "qty": 2}]}'),
    ('signup', 789, '{"referral_code": "FRIEND10", "source": "google"}');
```

### Type Casting

```sql
-- Text to JSONB
SELECT '{"name": "Alice"}'::JSONB;

-- JSONB to Text
SELECT profile::TEXT FROM users;

-- Check if text is valid JSON
SELECT pg_typeof('{"valid": true}'::JSONB);  -- jsonb
```

## Practice Exercise

After completing the materials, try this exercise (do not spend more than 20 minutes):

1. Create a table for storing user profiles:

```sql
CREATE TABLE user_profiles (
    id SERIAL PRIMARY KEY,
    username TEXT UNIQUE NOT NULL,
    email TEXT UNIQUE NOT NULL,
    profile_data JSONB DEFAULT '{}'::JSONB,
    created_at TIMESTAMP DEFAULT NOW()
);
```

2. Insert various profiles:

```sql
-- Simple profile
INSERT INTO user_profiles (username, email, profile_data)
VALUES ('alice', 'alice@example.com', '{
    "first_name": "Alice",
    "last_name": "Smith",
    "age": 30,
    "city": "New York"
}');

-- Nested profile with arrays
INSERT INTO user_profiles (username, email, profile_data)
VALUES ('bob', 'bob@example.com', '{
    "first_name": "Bob",
    "last_name": "Jones",
    "age": 25,
    "interests": ["hiking", "photography", "coding"],
    "social": {
        "twitter": "@bobtweets",
        "linkedin": "bob-jones"
    }
}');

-- Profile with missing fields (flexible schema)
INSERT INTO user_profiles (username, email, profile_data)
VALUES ('charlie', 'charlie@example.com', '{
    "first_name": "Charlie",
    "company": "TechCorp"
}');
```

3. Query the data:

```sql
-- Get all profiles
SELECT username, profile_data FROM user_profiles;

-- Extract specific fields
SELECT 
    username,
    profile_data->>'first_name' AS first_name,
    profile_data->>'age' AS age
FROM user_profiles;

-- Extract nested field
SELECT 
    username,
    profile_data->'social'->>'twitter' AS twitter
FROM user_profiles
WHERE profile_data ? 'social';  -- Only users with social data

-- Extract array elements
SELECT 
    username,
    jsonb_array_elements_text(profile_data->'interests') AS interest
FROM user_profiles
WHERE profile_data ? 'interests';
```

4. Compare JSON vs JSONB:

```sql
-- Create comparison table
CREATE TABLE json_comparison (
    id SERIAL PRIMARY KEY,
    data_json JSON,
    data_jsonb JSONB
);

-- Insert data with duplicate keys and spacing
INSERT INTO json_comparison (data_json, data_jsonb)
VALUES (
    '{ "name" : "Alice" , "age" : 30 , "name" : "Bob" }',
    '{ "name" : "Alice" , "age" : 30 , "name" : "Bob" }'
);

-- Observe differences
SELECT 
    data_json AS json_preserved,
    data_jsonb AS jsonb_normalized
FROM json_comparison;
```
