## Introduction

Finding documents that match a search query is only half the battle—presenting results in order of relevance is equally important. PostgreSQL provides ranking functions that score documents based on how well they match the search query. This lesson covers how to use these functions effectively to create a high-quality search experience.

## Key Concepts Summary

### Ranking Functions

PostgreSQL provides two main ranking functions:

#### 1. ts_rank
Calculates relevance based on term frequency and document length.

```sql
ts_rank([ weights, ] tsvector, tsquery [, normalization ])
```

**Basic usage:**
```sql
SELECT 
    id,
    title,
    ts_rank(search_vector, query) AS rank
FROM articles, plainto_tsquery('english', 'postgresql database') query
WHERE search_vector @@ query
ORDER BY rank DESC;
```

#### 2. ts_rank_cd (Cover Density)
Calculates relevance based on proximity of matching terms.

```sql
ts_rank_cd([ weights, ] tsvector, tsquery [, normalization ])
```

**Basic usage:**
```sql
SELECT 
    id,
    title,
    ts_rank_cd(search_vector, query) AS rank
FROM articles, plainto_tsquery('english', 'postgresql database') query
WHERE search_vector @@ query
ORDER BY rank DESC;
```

### ts_rank vs ts_rank_cd

| Feature | ts_rank | ts_rank_cd |
|---------|---------|------------|
| Algorithm | Frequency-based | Proximity-based (cover density) |
| Considers | How many times terms appear | How close terms are to each other |
| Best for | Single-term searches | Multi-term phrase-like searches |
| Performance | Faster | Slightly slower |
| Most common | ✓ | Less common |

## Document Weighting

### Weight Labels

PostgreSQL supports four weight labels for tsvector entries:
- **A**: Highest importance (default weight: 1.0)
- **B**: High importance (default weight: 0.4)
- **C**: Medium importance (default weight: 0.2)
- **D**: Lowest importance (default weight: 0.1)

### Setting Weights

```sql
-- Weight individual parts differently
SELECT setweight(to_tsvector('english', 'Important title'), 'A') ||
       setweight(to_tsvector('english', 'Less important body'), 'B');

-- Result includes weight labels
-- 'bodi':5B 'import':1A,3B 'less':4B 'titl':2A
```

### Weighted Search Vector Column

```sql
-- Create weighted search vector
ALTER TABLE articles
ADD COLUMN search_vector tsvector
GENERATED ALWAYS AS (
    setweight(to_tsvector('english', COALESCE(title, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(abstract, '')), 'B') ||
    setweight(to_tsvector('english', COALESCE(body, '')), 'C')
) STORED;

CREATE INDEX articles_search_idx ON articles USING GIN (search_vector);

-- Ranking automatically considers weights
SELECT id, title, ts_rank(search_vector, query) AS rank
FROM articles, plainto_tsquery('english', 'search terms') query
WHERE search_vector @@ query
ORDER BY rank DESC;
```

### Custom Weight Arrays

```sql
-- Default weights: {1.0, 0.4, 0.2, 0.1} for {A, B, C, D}
-- Custom weights: {A, B, C, D}
SELECT ts_rank(
    '{0.5, 0.3, 0.1, 0.1}',  -- Custom weights
    search_vector,
    query
) AS rank
FROM articles, plainto_tsquery('english', 'search') query
WHERE search_vector @@ query;

-- Example: Title-heavy weighting
SELECT ts_rank(
    '{1.0, 0.2, 0.1, 0.0}',  -- A: 1.0, B: 0.2, C: 0.1, D: 0.0
    search_vector,
    query
) AS rank
FROM articles, plainto_tsquery('english', 'search') query
WHERE search_vector @@ query
ORDER BY rank DESC;
```

## Normalization Options

Normalization adjusts ranking based on document length to prevent bias toward longer documents.

```sql
ts_rank(tsvector, tsquery, normalization)
```

**Normalization values (can be combined with bitwise OR):**
- `0` (default): No normalization
- `1`: Divide by (1 + log of document length)
- `2`: Divide by document length
- `4`: Divide by mean harmonic distance between extents
- `8`: Divide by number of unique words
- `16`: Divide by (1 + log of unique words)
- `32`: Divide by (rank + 1)

**Examples:**
```sql
-- No normalization (longer docs rank higher)
SELECT ts_rank(search_vector, query, 0) AS rank
FROM articles, plainto_tsquery('english', 'search') query
WHERE search_vector @@ query;

-- Normalize by document length
SELECT ts_rank(search_vector, query, 2) AS rank
FROM articles, plainto_tsquery('english', 'search') query
WHERE search_vector @@ query;

-- Combine normalizations: 1 + 2 = 3
SELECT ts_rank(search_vector, query, 3) AS rank
FROM articles, plainto_tsquery('english', 'search') query
WHERE search_vector @@ query;

-- Common: normalize by log of length (prevents extreme bias)
SELECT ts_rank(search_vector, query, 1) AS rank
FROM articles, plainto_tsquery('english', 'search') query
WHERE search_vector @@ query
ORDER BY rank DESC;
```

## Practical Examples

### Example 1: Basic Ranking

```sql
CREATE TABLE blog_posts (
    id SERIAL PRIMARY KEY,
    title TEXT,
    content TEXT,
    search_vector tsvector GENERATED ALWAYS AS (
        to_tsvector('english', title || ' ' || content)
    ) STORED
);

CREATE INDEX blog_posts_search_idx ON blog_posts USING GIN (search_vector);

-- Insert sample data
INSERT INTO blog_posts (title, content) VALUES
    ('PostgreSQL Full-Text Search', 'Learn how PostgreSQL handles full-text search...'),
    ('Introduction to Databases', 'Databases store and manage data. PostgreSQL is one option...'),
    ('PostgreSQL Performance Tips', 'Optimize your PostgreSQL queries for better performance...');

-- Search with ranking
SELECT 
    id,
    title,
    ts_rank(search_vector, query) AS rank
FROM blog_posts, 
     plainto_tsquery('english', 'postgresql search') query
WHERE search_vector @@ query
ORDER BY rank DESC;

-- Results ordered by relevance
-- Post 1 ranks highest (contains both 'postgresql' and 'search')
```

### Example 2: Weighted Ranking (Title > Content)

```sql
-- Add weighted search vector
ALTER TABLE blog_posts
ADD COLUMN weighted_search_vector tsvector
GENERATED ALWAYS AS (
    setweight(to_tsvector('english', COALESCE(title, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(content, '')), 'B')
) STORED;

CREATE INDEX blog_posts_weighted_idx ON blog_posts 
USING GIN (weighted_search_vector);

-- Search with weighted ranking
SELECT 
    id,
    title,
    ts_rank(weighted_search_vector, query) AS rank
FROM blog_posts, 
     plainto_tsquery('english', 'postgresql') query
WHERE weighted_search_vector @@ query
ORDER BY rank DESC;

-- Posts with 'postgresql' in title rank higher than those with it only in content
```

### Example 3: Custom Ranking Formula

```sql
-- Combine multiple factors for ranking
SELECT 
    id,
    title,
    created_at,
    -- Custom ranking: 60% relevance, 40% recency
    (
        0.6 * ts_rank(search_vector, query) +
        0.4 * (EXTRACT(EPOCH FROM NOW() - created_at) / 86400.0)::numeric
    ) AS custom_rank
FROM blog_posts, 
     plainto_tsquery('english', 'postgresql') query
WHERE search_vector @@ query
ORDER BY custom_rank DESC;
```

### Example 4: Boosting Specific Fields

```sql
-- Multi-field weighted search
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name TEXT,
    description TEXT,
    category TEXT,
    brand TEXT
);

ALTER TABLE products
ADD COLUMN search_vector tsvector
GENERATED ALWAYS AS (
    setweight(to_tsvector('english', COALESCE(name, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(brand, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(category, '')), 'B') ||
    setweight(to_tsvector('english', COALESCE(description, '')), 'C')
) STORED;

-- Name and brand have equal highest weight
-- Category has medium weight
-- Description has lowest weight
```

### Example 5: Combining ts_rank with Business Logic

```sql
-- E-commerce search: relevance + popularity + rating
SELECT 
    p.id,
    p.name,
    p.price,
    p.rating,
    p.sales_count,
    -- Complex ranking algorithm
    (
        ts_rank(p.search_vector, query) * 10 +              -- Relevance (scaled)
        ln(p.sales_count + 1) * 2 +                         -- Popularity (log scale)
        p.rating                                            -- Rating (1-5)
    ) AS relevance_score
FROM products p,
     plainto_tsquery('english', 'laptop') query
WHERE p.search_vector @@ query
  AND p.is_available = true
ORDER BY relevance_score DESC
LIMIT 20;
```

### Example 6: Highlighting with Ranking

```sql
-- Show snippets with ranking
SELECT 
    id,
    title,
    ts_rank(search_vector, query) AS rank,
    ts_headline(
        'english',
        content,
        query,
        'MaxWords=50, MinWords=25'
    ) AS snippet
FROM blog_posts,
     plainto_tsquery('english', 'postgresql full-text search') query
WHERE search_vector @@ query
ORDER BY rank DESC
LIMIT 10;
```

## Performance Optimization

### 1. Materialized Ranking

For expensive ranking calculations, pre-compute and store:

```sql
-- Add ranking column updated on content changes
ALTER TABLE articles ADD COLUMN base_rank REAL;

-- Update via trigger or batch job
UPDATE articles
SET base_rank = ts_rank(search_vector, 
                        to_tsquery('english', 'common terms'));

-- Fast query-time ranking
SELECT id, title, 
       base_rank * ts_rank(search_vector, query) AS final_rank
FROM articles, plainto_tsquery('english', 'specific query') query
WHERE search_vector @@ query
ORDER BY final_rank DESC;
```

### 2. Limit Ranking to Top Results

```sql
-- Rank only after filtering with CTE
WITH matched_docs AS (
    SELECT id, title, search_vector
    FROM articles
    WHERE search_vector @@ query
    LIMIT 1000  -- Limit before ranking
)
SELECT 
    id,
    title,
    ts_rank(search_vector, query) AS rank
FROM matched_docs, plainto_tsquery('english', 'search') query
ORDER BY rank DESC
LIMIT 20;
```

### 3. Index-Only Scans with Ranking

```sql
-- Include ranking columns in covering index
CREATE INDEX articles_covering_idx ON articles 
USING GIN (search_vector)
INCLUDE (title, created_at);

-- Query can use index-only scan for filtering
-- Then compute ranking on fewer rows
```

## Common Patterns

### Pattern 1: Pagination with Ranking

```sql
-- Efficient pagination
WITH ranked_results AS (
    SELECT 
        id,
        title,
        ts_rank(search_vector, query) AS rank
    FROM articles,
         plainto_tsquery('english', 'search terms') query
    WHERE search_vector @@ query
)
SELECT id, title, rank
FROM ranked_results
ORDER BY rank DESC
LIMIT 20 OFFSET 0;  -- Page 1
```

### Pattern 2: Category-Specific Ranking

```sql
-- Different ranking for different categories
SELECT 
    id,
    title,
    category,
    CASE category
        WHEN 'tutorial' THEN ts_rank('{1.0, 0.5, 0.2, 0.1}', search_vector, query)
        WHEN 'reference' THEN ts_rank('{0.5, 1.0, 0.5, 0.1}', search_vector, query)
        ELSE ts_rank(search_vector, query)
    END AS rank
FROM articles, plainto_tsquery('english', 'search') query
WHERE search_vector @@ query
ORDER BY rank DESC;
```

### Pattern 3: Minimum Rank Threshold

```sql
-- Filter out low-quality matches
WITH ranked AS (
    SELECT 
        id,
        title,
        ts_rank(search_vector, query, 1) AS rank
    FROM articles, plainto_tsquery('english', 'search') query
    WHERE search_vector @@ query
)
SELECT id, title, rank
FROM ranked
WHERE rank > 0.1  -- Minimum relevance threshold
ORDER BY rank DESC;
```

## Debugging Ranking

### Inspect Ranking Components

```sql
-- See weight distribution
SELECT search_vector
FROM articles
WHERE id = 123;

-- Example output: 'databas':5A,12B 'postgresql':1A,8C
-- Shows where terms appear and their weights
```

### Compare Ranking Functions

```sql
-- Compare ts_rank vs ts_rank_cd
SELECT 
    id,
    title,
    ts_rank(search_vector, query) AS frequency_rank,
    ts_rank_cd(search_vector, query) AS proximity_rank,
    ts_rank(search_vector, query, 1) AS normalized_rank
FROM articles, plainto_tsquery('english', 'postgresql database') query
WHERE search_vector @@ query
ORDER BY frequency_rank DESC;
```

### Understand Why Documents Rank

```sql
-- Break down ranking factors
SELECT 
    id,
    title,
    length(search_vector::text) AS vector_size,
    ts_rank(search_vector, query, 0) AS raw_rank,
    ts_rank(search_vector, query, 1) AS normalized_rank
FROM articles, plainto_tsquery('english', 'search') query
WHERE search_vector @@ query
ORDER BY raw_rank DESC;
```

## Practice Exercise

Build a ranked search system for a Q&A platform like Stack Overflow:

1. Create a `questions` table with title, body, views, score, and answer count
2. Create a weighted search vector (title has highest weight)
3. Implement a ranking algorithm that combines:
   - Text relevance (ts_rank)
   - Question score
   - View count
   - Recency
4. Test with sample queries

**Example solution:**

```sql
-- Step 1: Create table
CREATE TABLE questions (
    id SERIAL PRIMARY KEY,
    title TEXT NOT NULL,
    body TEXT NOT NULL,
    score INT DEFAULT 0,
    view_count INT DEFAULT 0,
    answer_count INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Step 2: Add weighted search
ALTER TABLE questions
ADD COLUMN search_vector tsvector
GENERATED ALWAYS AS (
    setweight(to_tsvector('english', COALESCE(title, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(body, '')), 'B')
) STORED;

CREATE INDEX questions_search_idx ON questions USING GIN (search_vector);

-- Step 3: Insert sample data
INSERT INTO questions (title, body, score, view_count, answer_count) VALUES
    ('How to use PostgreSQL full-text search?', 
     'I want to implement search in my application using PostgreSQL...', 
     45, 1200, 3),
    ('PostgreSQL vs MySQL for full-text search', 
     'Which database is better for implementing full-text search?', 
     12, 350, 1),
    ('Optimizing PostgreSQL queries', 
     'My PostgreSQL queries are slow. How can I optimize them?', 
     78, 2500, 5);

-- Step 4: Ranked search query
WITH search_results AS (
    SELECT 
        id,
        title,
        score,
        view_count,
        answer_count,
        created_at,
        ts_rank(search_vector, query, 1) AS text_rank
    FROM questions, 
         plainto_tsquery('english', 'postgresql search') query
    WHERE search_vector @@ query
)
SELECT 
    id,
    title,
    score,
    view_count,
    -- Combined relevance score
    (
        text_rank * 100 +                                   -- Text relevance (base)
        score * 0.5 +                                       -- Question score
        ln(view_count + 1) * 2 +                           -- View popularity
        answer_count * 3 +                                  -- Answered questions boost
        (1.0 / (EXTRACT(EPOCH FROM NOW() - created_at) / 86400.0 + 1)) * 5  -- Recency
    ) AS relevance_score
FROM search_results
ORDER BY relevance_score DESC;
```

## Key Takeaways

- `ts_rank` uses term frequency for ranking (most common)
- `ts_rank_cd` uses term proximity for ranking (multi-term queries)
- Weight labels (A, B, C, D) allow prioritizing different document sections
- Custom weight arrays provide fine-grained control over field importance
- Normalization prevents bias toward longer documents
- Combine text ranking with business logic (popularity, recency, ratings)
- Limit ranking operations to filtered result sets for performance
- Use weighted search vectors for title/content prioritization
- Test and tune ranking algorithms based on user feedback
