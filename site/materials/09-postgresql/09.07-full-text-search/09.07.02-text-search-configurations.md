## Introduction

Text search configurations control how PostgreSQL processes text during full-text search. They determine which parser breaks text into tokens and which dictionaries transform those tokens into lexemes. Understanding configurations and dictionaries allows you to customize search behavior for specific languages, domains, or business requirements.

## Key Concepts Summary

### Text Search Configurations

A text search configuration specifies:
1. **Parser**: How to break text into tokens
2. **Dictionaries**: How to convert tokens into lexemes for each token type

**Listing available configurations:**
```sql
-- View all text search configurations
SELECT cfgname FROM pg_ts_config;
-- Common configurations: english, spanish, french, german, simple

-- See the default configuration
SHOW default_text_search_config;
-- Usually: pg_catalog.english
```

**Using different configurations:**
```sql
-- English configuration (default)
SELECT to_tsvector('english', 'The running cats');
-- Result: 'cat':3 'run':2

-- Spanish configuration
SELECT to_tsvector('spanish', 'Los gatos corriendo');
-- Result: 'corriendo':3 'gato':2

-- Simple configuration (no stemming, no stop words)
SELECT to_tsvector('simple', 'The running cats');
-- Result: 'cats':3 'running':2 'the':1
```

### Configuration Components

**Viewing configuration details:**
```sql
-- See how 'english' configuration processes tokens
\dF+ english

-- Or query the catalog
SELECT * FROM pg_ts_config_map WHERE mapcfgname = 'english';
```

**Token types include:**
- `asciiword`: ASCII letters
- `word`: Non-ASCII letters
- `numword`: Numbers with letters
- `email`: Email addresses
- `url`: URLs
- `host`: Hostnames
- `file`: File paths
- And more...

### Dictionary Types

#### 1. Simple Dictionary
Converts tokens to lowercase and checks against a stop word list.

```sql
-- View simple dictionary
SELECT * FROM pg_ts_dict WHERE dictname = 'simple';
```

#### 2. Synonym Dictionary
Maps words to their canonical forms.

**Create a synonym file** (`pg_synonyms.syn`):
```
postgres        postgresql
pgsql           postgresql
db              database
rdbms           database
```

**Configure the dictionary:**
```sql
-- Create synonym dictionary
CREATE TEXT SEARCH DICTIONARY syn_dict (
    TEMPLATE = synonym,
    SYNONYMS = pg_synonyms  -- file name without .syn extension
);

-- Test the dictionary
SELECT ts_lexize('syn_dict', 'postgres');
-- Result: {postgresql}

SELECT ts_lexize('syn_dict', 'db');
-- Result: {database}
```

#### 3. Thesaurus Dictionary
Maps phrases to replacement terms for semantic search.

**Create a thesaurus file** (`pg_thesaurus.ths`):
```
# Format: phrase : replacement [: replacement]
machine learning : ml ai
artificial intelligence : ai
natural language processing : nlp
```

**Configure the dictionary:**
```sql
CREATE TEXT SEARCH DICTIONARY thesaurus_dict (
    TEMPLATE = thesaurus,
    DictFile = pg_thesaurus,
    Dictionary = english_stem  -- base dictionary for individual words
);
```

#### 4. Ispell Dictionary
Uses linguistic rules for stemming and normalization.

```sql
CREATE TEXT SEARCH DICTIONARY english_ispell (
    TEMPLATE = ispell,
    DictFile = en_us,
    AffFile = en_us,
    StopWords = english
);
```

#### 5. Snowball Dictionary
Stemming using Snowball algorithms (default for most languages).

```sql
CREATE TEXT SEARCH DICTIONARY english_stem (
    TEMPLATE = snowball,
    Language = english,
    StopWords = english
);
```

## Creating Custom Configurations

### Step 1: Create the Configuration

```sql
-- Copy an existing configuration
CREATE TEXT SEARCH CONFIGURATION my_english (COPY = english);

-- Or create from scratch
CREATE TEXT SEARCH CONFIGURATION custom_config (PARSER = default);
```

### Step 2: Configure Token Mappings

```sql
-- See current mappings
SELECT * FROM pg_ts_config_map 
WHERE mapcfgname = 'my_english';

-- Add or modify mappings
ALTER TEXT SEARCH CONFIGURATION my_english
    ALTER MAPPING FOR asciiword, asciihword, hword_asciipart
    WITH english_stem;

-- Remove mappings
ALTER TEXT SEARCH CONFIGURATION my_english
    DROP MAPPING FOR url, url_path, host;
```

### Step 3: Add Custom Dictionary

```sql
-- Create synonym dictionary
CREATE TEXT SEARCH DICTIONARY my_synonyms (
    TEMPLATE = synonym,
    SYNONYMS = my_synonyms
);

-- Add to configuration (chain multiple dictionaries)
ALTER TEXT SEARCH CONFIGURATION my_english
    ALTER MAPPING FOR asciiword
    WITH my_synonyms, english_stem;
```

**Dictionary chaining:** When multiple dictionaries are specified, PostgreSQL tries them in order until one recognizes the word (returns a non-NULL result).

## Practical Examples

### Example 1: Product Search with Synonyms

```sql
-- Create synonym file: product_synonyms.syn
-- phone : smartphone mobile
-- laptop : notebook computer
-- tv : television

-- Create dictionary
CREATE TEXT SEARCH DICTIONARY product_synonyms (
    TEMPLATE = synonym,
    SYNONYMS = product_synonyms
);

-- Create custom configuration
CREATE TEXT SEARCH CONFIGURATION product_search (COPY = english);

ALTER TEXT SEARCH CONFIGURATION product_search
    ALTER MAPPING FOR asciiword, asciihword, hword_asciipart
    WITH product_synonyms, english_stem;

-- Test it
SELECT to_tsvector('product_search', 'mobile phone for sale');
-- Result includes: 'smartphon':1,2

SELECT to_tsvector('product_search', 'Looking for a notebook');
-- Result includes: 'comput':4 'laptop':4 'notebook':4
```

### Example 2: Technical Documentation Search

```sql
-- Create thesaurus for technical terms
-- File: tech_thesaurus.ths
-- sql server : mssql sqlserver
-- object relational mapping : orm
-- continuous integration : ci

CREATE TEXT SEARCH DICTIONARY tech_thesaurus (
    TEMPLATE = thesaurus,
    DictFile = tech_thesaurus,
    Dictionary = english_stem
);

CREATE TEXT SEARCH CONFIGURATION tech_docs (COPY = english);

ALTER TEXT SEARCH CONFIGURATION tech_docs
    ALTER MAPPING FOR asciiword, word
    WITH tech_thesaurus, english_stem;

-- Search documentation
SELECT title FROM documentation
WHERE to_tsvector('tech_docs', content) 
      @@ plainto_tsquery('tech_docs', 'sql server');
-- Also matches: 'mssql', 'sqlserver'
```

### Example 3: Multi-Language Support

```sql
-- Store language per document
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    title TEXT,
    content TEXT,
    language TEXT DEFAULT 'english'
);

-- Search using document's language
SELECT id, title
FROM documents
WHERE to_tsvector(language::regconfig, content) 
      @@ plainto_tsquery(language::regconfig, 'search terms');
```

### Example 4: Custom Stop Words

```sql
-- Create custom stop word file: my_stopwords.stop
-- Contents: custom stop words, one per line
-- the
-- and
-- custom_word

CREATE TEXT SEARCH DICTIONARY my_stopwords (
    TEMPLATE = simple,
    STOPWORDS = my_stopwords
);

CREATE TEXT SEARCH CONFIGURATION custom_stop (COPY = english);

ALTER TEXT SEARCH CONFIGURATION custom_stop
    ALTER MAPPING FOR asciiword
    WITH my_stopwords, english_stem;
```

## Dictionary File Locations

Dictionary files must be placed in the PostgreSQL shared directory:

```sql
-- Find the shared directory
SHOW data_directory;
-- Dictionary files go in: [data_directory]/tsearch_data/

-- Or check with:
SELECT * FROM pg_file_settings 
WHERE name = 'data_directory';
```

**Common locations:**
- Linux: `/usr/share/postgresql/[version]/tsearch_data/`
- macOS: `/usr/local/share/postgresql/tsearch_data/`
- Windows: `C:\Program Files\PostgreSQL\[version]\share\tsearch_data\`

## Testing Dictionaries

### Test Individual Dictionary

```sql
-- Test how a dictionary processes a word
SELECT ts_lexize('english_stem', 'running');
-- Result: {run}

SELECT ts_lexize('english_stem', 'the');
-- Result: {} (empty - stop word)

-- Test synonym dictionary
SELECT ts_lexize('my_synonyms', 'phone');
```

### Test Full Configuration


## Performance Considerations

### 1. Dictionary Ordering
```sql
-- Fast dictionary first, expensive last
ALTER TEXT SEARCH CONFIGURATION my_config
    ALTER MAPPING FOR asciiword
    WITH simple_dict, synonym_dict, ispell_dict, snowball_dict;
```

### 2. Limit Dictionary Scope
```sql
-- Only apply expensive dictionaries to specific token types
ALTER TEXT SEARCH CONFIGURATION my_config
    ALTER MAPPING FOR asciiword WITH ispell_dict, english_stem,
    ALTER MAPPING FOR numword WITH simple;
```

### 3. Dictionary File Size
- Keep synonym files small and focused
- Split large thesauri into multiple dictionaries
- Remove unused entries

## Common Patterns

### Pattern 1: Domain-Specific Synonyms

```sql
-- E-commerce: product variants
-- medical: medical terminology
-- legal: legal terms
CREATE TEXT SEARCH DICTIONARY domain_synonyms (
    TEMPLATE = synonym,
    SYNONYMS = domain_specific
);
```

### Pattern 2: Case-Sensitive Search

```sql
-- Use simple configuration to preserve case
SELECT to_tsvector('simple', 'iPhone iPad iPod');
-- Preserves exact capitalization
```

### Pattern 3: Acronym Handling

```sql
-- Synonym file for acronyms
-- ai : "artificial intelligence"
-- ml : "machine learning"
-- nlp : "natural language processing"
```

## Practice Exercise

Create a custom search configuration for a blog:

1. Create a synonym dictionary for common abbreviations:
   - js → javascript
   - py → python
   - db → database
2. Create a custom stop word list that includes "blog", "post"
3. Create a text search configuration that uses both
4. Test it with sample blog content

**Example solution:**

```sql
-- Step 1: Create synonym file (blog_synonyms.syn)
-- js        javascript
-- py        python
-- db        database

-- Step 2: Create stop words file (blog_stopwords.stop)
-- blog
-- post

-- Step 3: Create dictionaries
CREATE TEXT SEARCH DICTIONARY blog_synonyms (
    TEMPLATE = synonym,
    SYNONYMS = blog_synonyms
);

CREATE TEXT SEARCH DICTIONARY blog_stopwords (
    TEMPLATE = simple,
    STOPWORDS = blog_stopwords
);

-- Step 4: Create configuration
CREATE TEXT SEARCH CONFIGURATION blog_search (COPY = english);

ALTER TEXT SEARCH CONFIGURATION blog_search
    ALTER MAPPING FOR asciiword
    WITH blog_synonyms, blog_stopwords, english_stem;

-- Step 5: Test
SELECT to_tsvector('blog_search', 'This blog post covers js and py');
-- 'js' becomes 'javascript', 'py' becomes 'python'
-- 'blog' and 'post' are filtered as stop words
```

## Key Takeaways

- Text search configurations control parsing and normalization behavior
- Dictionaries transform tokens into searchable lexemes
- Multiple dictionary types support different use cases (synonyms, thesaurus, stemming)
- Custom configurations enable domain-specific search behavior
- Dictionary chaining allows flexible processing pipelines
- Dictionary files must be placed in PostgreSQL's tsearch_data directory
- Use `ts_debug()` to understand how text is processed
- Choose appropriate dictionaries based on performance and functionality needs
