## Introduction

Beyond basic full-text search, PostgreSQL offers advanced features that enhance the search experience. Phrase search enables exact multi-word matching, ts_headline highlights matched terms in results, and the pg_trgm extension provides fuzzy matching for typo tolerance. These features combine to create a robust, user-friendly search system.

## Key Concepts Summary

### Phrase Search and Proximity Operators

#### The <-> Operator (Adjacent Words)

```sql
-- Basic phrase search: words must be adjacent
SELECT * FROM articles
WHERE to_tsvector('english', content) 
      @@ to_tsquery('english', 'full <-> text');
-- Matches: "full text" but not "full featured text"

-- Multiple adjacent words
SELECT * FROM articles
WHERE to_tsvector('english', content) 
      @@ to_tsquery('english', 'full <-> text <-> search');
-- Matches: "full text search" (exact phrase)
```

#### The <N> Operator (Distance)

```sql
-- Words within N positions apart
SELECT * FROM articles
WHERE to_tsvector('english', content) 
      @@ to_tsquery('english', 'postgresql <2> search');
-- Matches: "PostgreSQL full-text search" (2 words between)
-- Also matches: "PostgreSQL search" (0 words between)

-- Specific distance
SELECT * FROM articles
WHERE to_tsvector('english', content) 
      @@ to_tsquery('english', 'database <3> performance');
-- Matches if words are within 3 positions
```

#### Using phraseto_tsquery

```sql
-- Easier phrase query creation
SELECT phraseto_tsquery('english', 'full text search');
-- Result: 'full' <-> 'text' <-> 'search'

-- Compare with:
SELECT to_tsquery('english', 'full <-> text <-> search');
-- Same result but more manual

-- In queries
SELECT title FROM articles
WHERE search_vector @@ phraseto_tsquery('english', 'machine learning');
-- Finds exact phrase "machine learning"
```

### Result Highlighting with ts_headline

#### Basic Usage

```sql
-- Highlight matching terms in text
SELECT 
    id,
    title,
    ts_headline(
        'english',           -- Configuration
        content,             -- Text to highlight
        query               -- Search query
    ) AS snippet
FROM articles,
     plainto_tsquery('english', 'postgresql database') query
WHERE search_vector @@ query;

-- Default output: "...match <b>PostgreSQL</b> <b>database</b> more text..."
```

#### Customizing Highlights

```sql
-- Custom options
SELECT ts_headline(
    'english',
    content,
    query,
    'StartSel=<mark>, StopSel=</mark>, MaxWords=50, MinWords=20'
) AS snippet
FROM articles, plainto_tsquery('english', 'search terms') query
WHERE search_vector @@ query;

-- Uses <mark> tags instead of <b>
-- Shows 20-50 words around matches
```

#### ts_headline Options

| Option | Default | Description |
|--------|---------|-------------|
| StartSel | `<b>` | Opening tag for highlighted terms |
| StopSel | `</b>` | Closing tag for highlighted terms |
| MaxWords | 35 | Maximum words in headline |
| MinWords | 15 | Minimum words in headline |
| ShortWord | 3 | Drop short words from edges |
| HighlightAll | false | Show all matches or just first |
| MaxFragments | 0 | Number of fragments (0 = auto) |
| FragmentDelimiter | `...` | Separator between fragments |

#### Practical Highlighting Examples

```sql
-- Google-style snippets
SELECT 
    id,
    title,
    ts_headline(
        'english',
        content,
        query,
        'MaxWords=30, MinWords=15, MaxFragments=1, FragmentDelimiter= ... '
    ) AS snippet
FROM articles,
     plainto_tsquery('english', 'postgresql full-text search') query
WHERE search_vector @@ query;

-- Multiple fragments for long documents
SELECT 
    id,
    title,
    ts_headline(
        'english',
        content,
        query,
        'MaxFragments=3, MaxWords=20, FragmentDelimiter= <br>...<br> '
    ) AS snippets
FROM articles,
     plainto_tsquery('english', 'database indexing') query
WHERE search_vector @@ query;

-- Custom HTML highlighting
SELECT 
    id,
    title,
    ts_headline(
        'english',
        content,
        query,
        'StartSel=<span class="highlight">, StopSel=</span>'
    ) AS snippet
FROM articles,
     plainto_tsquery('english', 'search') query
WHERE search_vector @@ query;
```

### Fuzzy Matching with pg_trgm

#### Installing the Extension

```sql
-- Enable the pg_trgm extension
CREATE EXTENSION IF NOT EXISTS pg_trgm;

-- Verify installation
SELECT * FROM pg_extension WHERE extname = 'pg_trgm';
```

#### Understanding Trigrams

```sql
-- See trigrams for a word
SELECT show_trgm('postgresql');
-- Result: {"  p"," po",gre,pos,qls,res,esi,esq,gre,ost,"l  ",ql ,res,sql,stg,tgr}

-- Each group of 3 consecutive characters
-- Padded with spaces at start/end
```

#### Similarity Function

```sql
-- Calculate similarity score (0 to 1)
SELECT similarity('postgresql', 'postgrasql');  -- typo
-- Result: ~0.7 (fairly similar)

SELECT similarity('postgresql', 'mysql');
-- Result: ~0.2 (not similar)

-- Find similar product names
SELECT name, similarity(name, 'iphone') AS sim
FROM products
WHERE similarity(name, 'iphone') > 0.3
ORDER BY sim DESC;
-- Finds: 'iPhone', 'iPhones', 'iphon', 'i phone', etc.
```

#### Similarity Operators

```sql
-- % operator: similar to (uses similarity threshold)
SELECT name FROM products
WHERE name % 'postgres';
-- Finds similar names based on threshold

-- Set similarity threshold (default 0.3)
SET pg_trgm.similarity_threshold = 0.4;

-- <-> operator: distance (1 - similarity)
SELECT name, name <-> 'postgresql' AS distance
FROM databases
ORDER BY distance
LIMIT 10;
-- Returns closest matches first
```

#### Trigram Indexes

```sql
-- GIN index for similarity searches
CREATE INDEX products_name_trgm_idx ON products 
USING GIN (name gin_trgm_ops);

-- GiST index (alternative)
CREATE INDEX products_name_trgm_gist_idx ON products 
USING GiST (name gist_trgm_ops);

-- Now similarity queries use the index
SELECT * FROM products
WHERE name % 'search term';
-- Fast, even on large tables
```

## Combining Full-Text Search and Fuzzy Matching

### Pattern 1: Fallback to Fuzzy Search

```sql
-- Try exact full-text search first, fallback to fuzzy
WITH exact_matches AS (
    SELECT id, name, 1.0 AS relevance
    FROM products
    WHERE search_vector @@ plainto_tsquery('english', 'postgresl')  -- typo
),
fuzzy_matches AS (
    SELECT id, name, similarity(name, 'postgresl') AS relevance
    FROM products
    WHERE NOT EXISTS (SELECT 1 FROM exact_matches)
      AND name % 'postgresl'
)
SELECT * FROM exact_matches
UNION ALL
SELECT * FROM fuzzy_matches
ORDER BY relevance DESC
LIMIT 10;
```

### Pattern 2: Combined Ranking

```sql
-- Combine text search and similarity
SELECT 
    id,
    title,
    -- Combined score
    (
        ts_rank(search_vector, query) * 0.7 +
        similarity(title, 'search term') * 0.3
    ) AS combined_score
FROM articles,
     plainto_tsquery('english', 'search term') query
WHERE search_vector @@ query
   OR title % 'search term'
ORDER BY combined_score DESC;
```

## Practical Examples

### Example 1: Article Search with Highlighting

```sql
CREATE TABLE articles (
    id SERIAL PRIMARY KEY,
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    author TEXT,
    published_at TIMESTAMP DEFAULT NOW()
);

ALTER TABLE articles
ADD COLUMN search_vector tsvector
GENERATED ALWAYS AS (
    setweight(to_tsvector('english', COALESCE(title, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(content, '')), 'B')
) STORED;

CREATE INDEX articles_search_idx ON articles USING GIN (search_vector);

-- Search with highlighting
SELECT 
    a.id,
    a.title,
    a.author,
    ts_rank(a.search_vector, query) AS rank,
    ts_headline(
        'english',
        a.content,
        query,
        'StartSel=<mark>, StopSel=</mark>, MaxWords=50, MinWords=25'
    ) AS snippet
FROM articles a,
     plainto_tsquery('english', 'PostgreSQL full-text search') query
WHERE a.search_vector @@ query
ORDER BY rank DESC
LIMIT 10;
```

### Example 2: E-commerce with Fuzzy Search

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    description TEXT,
    brand TEXT,
    price DECIMAL(10,2)
);

-- Full-text search index
ALTER TABLE products
ADD COLUMN search_vector tsvector
GENERATED ALWAYS AS (
    setweight(to_tsvector('english', COALESCE(name, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(brand, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(description, '')), 'B')
) STORED;

CREATE INDEX products_search_idx ON products USING GIN (search_vector);

-- Trigram index for fuzzy matching
CREATE INDEX products_name_trgm_idx ON products USING GIN (name gin_trgm_ops);

-- Hybrid search: full-text + fuzzy
WITH fts_results AS (
    SELECT 
        id, name, price,
        ts_rank(search_vector, query) AS fts_rank,
        0 AS similarity_rank
    FROM products,
         plainto_tsquery('english', 'samsng galxy') query  -- typos
    WHERE search_vector @@ query
),
fuzzy_results AS (
    SELECT 
        id, name, price,
        0 AS fts_rank,
        similarity(name, 'samsng galxy') AS similarity_rank
    FROM products
    WHERE name % 'samsng galxy'
      AND id NOT IN (SELECT id FROM fts_results)
)
SELECT 
    id, name, price,
    (fts_rank + similarity_rank) AS final_rank
FROM (
    SELECT * FROM fts_results
    UNION ALL
    SELECT * FROM fuzzy_results
) combined
ORDER BY final_rank DESC
LIMIT 20;
```

### Example 3: Autocomplete with Trigrams

```sql
-- Product name autocomplete
SELECT DISTINCT name
FROM products
WHERE name ILIKE 'iph%'  -- prefix match
   OR name % 'iph'       -- similarity match
ORDER BY 
    CASE WHEN name ILIKE 'iph%' THEN 1 ELSE 2 END,  -- prefix first
    similarity(name, 'iph') DESC
LIMIT 10;

-- More sophisticated version
SELECT 
    name,
    CASE 
        WHEN name ILIKE 'search%' THEN 1.0
        ELSE similarity(name, 'search')
    END AS relevance
FROM products
WHERE name ILIKE 'search%'
   OR name % 'search'
ORDER BY relevance DESC
LIMIT 10;
```

### Example 4: Did You Mean? Suggestions

```sql
-- Find similar terms when no results
CREATE FUNCTION suggest_corrections(search_term TEXT)
RETURNS TABLE(suggestion TEXT, similarity_score REAL) AS $$
BEGIN
    RETURN QUERY
    SELECT DISTINCT name, similarity(name, search_term) AS score
    FROM products
    WHERE similarity(name, search_term) > 0.3
    ORDER BY score DESC
    LIMIT 5;
END;
$$ LANGUAGE plpgsql;

-- Usage
WITH search_results AS (
    SELECT * FROM products
    WHERE search_vector @@ plainto_tsquery('english', 'postgressql')  -- typo
)
SELECT 
    CASE 
        WHEN EXISTS (SELECT 1 FROM search_results) 
        THEN 'Results found'
        ELSE 'Did you mean: ' || string_agg(suggestion, ', ')
    END AS message
FROM suggest_corrections('postgressql')
GROUP BY 1;
```

## Performance Considerations

### 1. ts_headline Performance

```sql
-- ts_headline is expensive - only call on displayed results
WITH ranked_results AS (
    SELECT id, title, search_vector
    FROM articles
    WHERE search_vector @@ query
    ORDER BY ts_rank(search_vector, query) DESC
    LIMIT 20  -- Limit before highlighting
)
SELECT 
    id,
    title,
    ts_headline('english', content, query) AS snippet
FROM ranked_results, plainto_tsquery('english', 'search') query;
```

### 2. Trigram Index Size

```sql
-- Trigram indexes are larger than regular indexes
-- Monitor size
SELECT 
    indexname,
    pg_size_pretty(pg_relation_size(indexrelid)) AS size
FROM pg_stat_user_indexes
WHERE indexname LIKE '%trgm%';
```

### 3. Similarity Threshold Tuning

```sql
-- Lower threshold = more matches but less precise
SET pg_trgm.similarity_threshold = 0.2;  -- More permissive

-- Higher threshold = fewer matches but more precise
SET pg_trgm.similarity_threshold = 0.5;  -- More strict

-- Test different thresholds
SELECT 
    threshold,
    COUNT(*) as match_count
FROM (VALUES (0.2), (0.3), (0.4), (0.5)) AS t(threshold)
CROSS JOIN LATERAL (
    SELECT * FROM products
    WHERE similarity(name, 'test') > threshold
) matches
GROUP BY threshold;
```

## Common Patterns

### Pattern 1: Tiered Search

```sql
-- Search with fallbacks: exact → full-text → fuzzy
WITH exact AS (
    SELECT id, name, 1.0 AS score FROM products WHERE name = 'search'
),
fulltext AS (
    SELECT id, name, 0.8 AS score FROM products 
    WHERE NOT EXISTS (SELECT 1 FROM exact)
      AND search_vector @@ plainto_tsquery('english', 'search')
),
fuzzy AS (
    SELECT id, name, 0.5 * similarity(name, 'search') AS score 
    FROM products
    WHERE NOT EXISTS (SELECT 1 FROM exact UNION SELECT 1 FROM fulltext)
      AND name % 'search'
)
SELECT * FROM exact
UNION ALL SELECT * FROM fulltext
UNION ALL SELECT * FROM fuzzy
ORDER BY score DESC;
```

### Pattern 2: Multi-Field Highlighting

```sql
-- Highlight in multiple fields
SELECT 
    id,
    ts_headline('english', title, query) AS highlighted_title,
    ts_headline('english', description, query) AS highlighted_description,
    ts_rank(search_vector, query) AS rank
FROM products,
     plainto_tsquery('english', 'search terms') query
WHERE search_vector @@ query
ORDER BY rank DESC;
```

## Practice Exercise

Build a comprehensive search system for a documentation site:

1. Create a `docs` table with title, content, and category
2. Implement full-text search with ranking
3. Add phrase search support
4. Implement result highlighting
5. Add fuzzy search fallback for typos
6. Create autocomplete suggestions

**Example solution:**

```sql
-- Step 1: Create table
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE TABLE docs (
    id SERIAL PRIMARY KEY,
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    category TEXT,
    url TEXT
);

ALTER TABLE docs
ADD COLUMN search_vector tsvector
GENERATED ALWAYS AS (
    setweight(to_tsvector('english', COALESCE(title, '')), 'A') ||
    setweight(to_tsvector('english', COALESCE(content, '')), 'B') ||
    setweight(to_tsvector('english', COALESCE(category, '')), 'C')
) STORED;

CREATE INDEX docs_search_idx ON docs USING GIN (search_vector);
CREATE INDEX docs_title_trgm_idx ON docs USING GIN (title gin_trgm_ops);

-- Step 2-5: Comprehensive search function
CREATE FUNCTION search_docs(
    search_term TEXT,
    is_phrase BOOLEAN DEFAULT false
)
RETURNS TABLE(
    id INT,
    title TEXT,
    category TEXT,
    url TEXT,
    snippet TEXT,
    relevance REAL
) AS $$
DECLARE
    query tsquery;
BEGIN
    -- Build query
    IF is_phrase THEN
        query := phraseto_tsquery('english', search_term);
    ELSE
        query := plainto_tsquery('english', search_term);
    END IF;
    
    -- Full-text search with highlighting
    RETURN QUERY
    WITH fts_results AS (
        SELECT 
            d.id, d.title, d.category, d.url,
            ts_headline('english', d.content, query,
                'MaxWords=50, MinWords=25, StartSel=<mark>, StopSel=</mark>'
            ) AS snippet,
            ts_rank(d.search_vector, query) AS relevance
        FROM docs d
        WHERE d.search_vector @@ query
    ),
    fuzzy_results AS (
        SELECT 
            d.id, d.title, d.category, d.url,
            substring(d.content, 1, 100) || '...' AS snippet,
            similarity(d.title, search_term) * 0.5 AS relevance
        FROM docs d
        WHERE NOT EXISTS (SELECT 1 FROM fts_results WHERE fts_results.id = d.id)
          AND d.title % search_term
    )
    SELECT * FROM fts_results
    UNION ALL
    SELECT * FROM fuzzy_results
    ORDER BY relevance DESC
    LIMIT 20;
END;
$$ LANGUAGE plpgsql;

-- Step 6: Autocomplete
CREATE FUNCTION autocomplete_docs(prefix TEXT)
RETURNS TABLE(suggestion TEXT) AS $$
BEGIN
    RETURN QUERY
    SELECT DISTINCT d.title
    FROM docs d
    WHERE d.title ILIKE prefix || '%'
       OR d.title % prefix
    ORDER BY 
        CASE WHEN d.title ILIKE prefix || '%' THEN 1 ELSE 2 END,
        similarity(d.title, prefix) DESC
    LIMIT 10;
END;
$$ LANGUAGE plpgsql;

-- Test the system
SELECT * FROM search_docs('PostgreSQL full-text search');
SELECT * FROM search_docs('full text search', true);  -- phrase search
SELECT * FROM autocomplete_docs('postg');
```

## Key Takeaways

- Phrase search with `<->` enables exact multi-word matching
- `ts_headline` generates highlighted search snippets automatically
- `pg_trgm` extension provides fuzzy matching for typo tolerance
- Combine full-text search with trigram similarity for robust search
- Use tiered search strategies: exact → full-text → fuzzy
- Highlight results only after filtering and limiting
- Trigram indexes enable fast similarity searches
- Adjust similarity thresholds based on your use case
- Consider performance when using expensive features like ts_headline
