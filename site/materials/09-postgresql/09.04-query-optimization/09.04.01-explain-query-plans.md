## Introduction

EXPLAIN is PostgreSQL's primary tool for understanding how queries execute. It shows the query plan the optimizer chose, including which operations will be performed, in what order, and at what estimated cost. EXPLAIN ANALYZE goes further by actually executing the query and showing real runtime statistics, allowing you to compare estimates against reality.

Learning to read EXPLAIN output is essential for query optimization. Most performance problems can be diagnosed by examining the query plan and identifying inefficient operations.

## Key Concepts Summary

### Basic EXPLAIN Syntax

```sql
-- Show the query plan without executing
EXPLAIN SELECT * FROM users WHERE age > 25;

-- Execute the query and show actual statistics
EXPLAIN ANALYZE SELECT * FROM users WHERE age > 25;

-- Best practice: include BUFFERS for I/O information
EXPLAIN (ANALYZE, BUFFERS) 
SELECT * FROM users WHERE age > 25;

-- For visualization tools, use JSON format
EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) 
SELECT * FROM users WHERE age > 25;
```

### Understanding Query Plan Structure

Query plans are tree structures where:
- **Leaf nodes** (bottom): Scan operations that retrieve raw data from tables
- **Inner nodes** (middle): Join, sort, aggregate operations
- **Root node** (top): Final result returned to the client

Example plan:

```
Nested Loop  (cost=0.29..16.38 rows=1 width=72)
  ->  Seq Scan on orders  (cost=0.00..8.00 rows=1 width=36)
        Filter: (status = 'pending')
  ->  Index Scan using users_pkey on users  (cost=0.29..8.31 rows=1 width=36)
        Index Cond: (id = orders.user_id)
```

**Reading this plan:**
1. Bottom-up: Start with leaf nodes (Seq Scan, Index Scan)
2. Sequential scan on `orders` filters rows where status='pending'
3. For each matching order, an index scan looks up the user
4. Nested Loop joins the results

### Cost Estimates

```
cost=0.29..16.38 rows=1 width=72
```

- **Startup cost** (0.29): Time to fetch the first row (arbitrary units, not milliseconds)
- **Total cost** (16.38): Time to fetch all rows
- **rows**: Estimated number of rows returned
- **width**: Average row size in bytes

### EXPLAIN Options

| Option | Purpose |
|--------|---------|
| `ANALYZE` | Actually execute the query and show real statistics (includes actual time and rows) |
| `BUFFERS` | Show I/O statistics (shared blocks hit/read, temp blocks) |
| `VERBOSE` | Show output column list and other detailed information |
| `SETTINGS` | Show non-default configuration parameters (PostgreSQL 12+) |
| `WAL` | Show WAL generation statistics for data-modifying queries (PostgreSQL 13+) |
| `FORMAT` | Output format: TEXT (default), JSON, XML, or YAML |

**Recommended usage:**

```sql
-- For development and debugging
EXPLAIN (ANALYZE, BUFFERS, VERBOSE) SELECT ...;

-- For sharing/visualization (PostgreSQL 12+)
EXPLAIN (ANALYZE, BUFFERS, SETTINGS, FORMAT JSON) SELECT ...;
```

### Common Node Types

| Node Type | Description |
|-----------|-------------|
| Seq Scan | Sequential scan - reads entire table |
| Index Scan | Uses index to find specific rows, then fetches from table |
| Index Only Scan | Gets all data from index without table access |
| Bitmap Index Scan | Scans index to create bitmap of matching rows |
| Bitmap Heap Scan | Uses bitmap to fetch rows from table in order |
| Nested Loop | Join algorithm - for each outer row, scan inner relation |
| Hash Join | Join algorithm - builds hash table of one input |
| Merge Join | Join algorithm - merges two sorted inputs |
| Sort | Sorts rows (uses work_mem) |
| Aggregate | Performs aggregation (SUM, COUNT, etc.) |
| Limit | Limits result set (LIMIT clause) |

## Practice Exercise

After completing the materials, try this exercise (do not spend more than 15 minutes):

1. Create a simple table with sample data:
```sql
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name TEXT,
    category TEXT,
    price NUMERIC
);

INSERT INTO products (name, category, price)
SELECT 
    'Product ' || i,
    CASE (i % 3) 
        WHEN 0 THEN 'Electronics'
        WHEN 1 THEN 'Books'
        ELSE 'Clothing'
    END,
    random() * 100
FROM generate_series(1, 1000) i;
```

2. Run and compare these queries:
```sql
-- Without ANALYZE (plan only)
EXPLAIN SELECT * FROM products WHERE category = 'Books';

-- With ANALYZE (actual execution)
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM products WHERE category = 'Books';

-- Add an index and compare
CREATE INDEX idx_products_category ON products(category);
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM products WHERE category = 'Books';
```

3. Paste the EXPLAIN output into https://explain.dalibo.com/ or https://explain.depesz.com/
