# Lesson 4: Set Operations

## Learning Objectives

By the end of this lesson, you will be able to:
- Use UNION and UNION ALL to combine result sets
- Apply INTERSECT to find common rows
- Use EXCEPT to find differences between result sets
- Understand the performance implications of each operator

---

## Introduction

Set operations allow you to combine, compare, and contrast the results of multiple queries. PostgreSQL provides UNION, INTERSECT, and EXCEPT operators that treat query results as mathematical sets, enabling powerful data analysis and reporting scenarios.

## Key Concepts Summary

### UNION - Combine and Remove Duplicates

Combines results from two queries, removing duplicate rows:

```sql
-- Find all customers from current and archived systems
SELECT customer_id, name, email
FROM active_customers
UNION
SELECT customer_id, name, email
FROM archived_customers;
```

### UNION ALL - Combine and Keep Duplicates

Faster than UNION because it doesn't check for duplicates:

```sql
-- Combine sales from multiple regions (duplicates OK)
SELECT order_id, amount, 'North' as region
FROM north_sales
UNION ALL
SELECT order_id, amount, 'South' as region
FROM south_sales
UNION ALL
SELECT order_id, amount, 'East' as region
FROM east_sales;
```

**Performance Note:** Always prefer UNION ALL over UNION when you know duplicates don't exist or duplicates are acceptable. UNION requires sorting and duplicate elimination, which is expensive.

### INTERSECT - Find Common Rows

Returns only rows that appear in both query results:

```sql
-- Find customers who placed orders in both 2023 AND 2024
SELECT customer_id
FROM orders
WHERE EXTRACT(YEAR FROM order_date) = 2023
INTERSECT
SELECT customer_id
FROM orders
WHERE EXTRACT(YEAR FROM order_date) = 2024;
```

### EXCEPT - Find Differences

Returns rows from the first query that don't appear in the second:

```sql
-- Find customers who haven't placed orders in 2024
SELECT customer_id
FROM customers
EXCEPT
SELECT DISTINCT customer_id
FROM orders
WHERE EXTRACT(YEAR FROM order_date) = 2024;
```

### Requirements for Set Operations

All queries must be "union compatible":
- Same number of columns
- Corresponding columns must have compatible data types
- Column names come from the first query

```sql
-- Valid: same column count and compatible types
SELECT product_id, name FROM products
UNION
SELECT supplier_id, company_name FROM suppliers;

-- Invalid: different column counts
SELECT product_id, name FROM products
UNION
SELECT supplier_id FROM suppliers;  -- ERROR!
```

### Combining Multiple Set Operations

Use parentheses to control evaluation order:

```sql
-- Find customers active in 2023 or 2024, but not in both
(
    SELECT customer_id FROM orders WHERE EXTRACT(YEAR FROM order_date) = 2023
    UNION
    SELECT customer_id FROM orders WHERE EXTRACT(YEAR FROM order_date) = 2024
)
EXCEPT
(
    SELECT customer_id FROM orders WHERE EXTRACT(YEAR FROM order_date) = 2023
    INTERSECT
    SELECT customer_id FROM orders WHERE EXTRACT(YEAR FROM order_date) = 2024
);
```

### Operator Precedence

Without parentheses:
- `INTERSECT` binds more tightly than `UNION` and `EXCEPT`
- `UNION` and `EXCEPT` are left-associative

```sql
-- These are equivalent:
query1 UNION query2 INTERSECT query3
query1 UNION (query2 INTERSECT query3)
```

### Set Operations with ORDER BY and LIMIT

Apply ORDER BY and LIMIT to the final result:

```sql
-- Correct: ORDER BY applies to the combined result
SELECT name, created_at FROM products
UNION ALL
SELECT name, created_at FROM archived_products
ORDER BY created_at DESC
LIMIT 10;

-- To apply LIMIT to individual queries, use parentheses:
(SELECT name FROM products ORDER BY price DESC LIMIT 5)
UNION ALL
(SELECT name FROM archived_products ORDER BY price DESC LIMIT 5);
```
