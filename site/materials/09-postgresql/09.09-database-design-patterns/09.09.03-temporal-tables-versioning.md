---

## Introduction

Temporal tables track how data changes over time, maintaining complete history of all modifications. Unlike simple audit logs, temporal tables enable querying data "as it was" at any point in time. PostgreSQL doesn't have native SQL:2011 temporal support, but we can implement these patterns using triggers, ranges, and proper indexing.

## Key Concepts Summary

### Types of Temporal Data

#### 1. System Time (Transaction Time)
**When the database recorded the change**

- Managed automatically by database
- Immutable once written
- Used for audit compliance
- Answers: "What did the database know at time T?"

#### 2. Business Time (Valid Time)
**When the data was/will be valid in real world**

- Managed by application
- Can be future or past dates
- Used for scheduling and planning
- Answers: "What was/will be true at time T?"

#### 3. Bi-Temporal (Both System and Business Time)
**Tracks both when recorded and when valid**

- Complete audit trail
- Can track corrections to historical data
- Answers: "What did we know at time T1 about time T2?"

## System-Versioned Tables

### Basic Implementation

```sql
-- Current state table
CREATE TABLE employees (
    employee_id SERIAL PRIMARY KEY,
    employee_name TEXT NOT NULL,
    department TEXT NOT NULL,
    salary DECIMAL(10,2) NOT NULL,
    email TEXT NOT NULL
);

-- History table
CREATE TABLE employees_history (
    history_id SERIAL PRIMARY KEY,
    employee_id INT NOT NULL,
    employee_name TEXT NOT NULL,
    department TEXT NOT NULL,
    salary DECIMAL(10,2) NOT NULL,
    email TEXT NOT NULL,
    sys_period TSTZRANGE NOT NULL,
    CONSTRAINT employees_history_sys_period_excl 
        EXCLUDE USING GIST (employee_id WITH =, sys_period WITH &&)
);

-- Create index for temporal queries
CREATE INDEX employees_history_sys_period_idx 
    ON employees_history USING GIST (sys_period);
CREATE INDEX employees_history_employee_id_idx 
    ON employees_history (employee_id);
```

### Trigger to Maintain History

```sql
CREATE OR REPLACE FUNCTION employees_version_trigger()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'UPDATE' THEN
        -- Archive old version
        INSERT INTO employees_history (
            employee_id, employee_name, department, salary, email, sys_period
        ) VALUES (
            OLD.employee_id, OLD.employee_name, OLD.department, OLD.salary, OLD.email,
            TSTZRANGE(
                CURRENT_TIMESTAMP,
                NULL,  -- Open-ended (current version)
                '[)'
            )
        )
        -- Close previous version's range
        ON CONFLICT (employee_id) WHERE sys_period @> CURRENT_TIMESTAMP
        DO UPDATE SET sys_period = TSTZRANGE(
            LOWER(employees_history.sys_period),
            CURRENT_TIMESTAMP,
            '[)'
        );
    ELSIF TG_OP = 'DELETE' THEN
        -- Archive deleted row
        INSERT INTO employees_history (
            employee_id, employee_name, department, salary, email, sys_period
        ) VALUES (
            OLD.employee_id, OLD.employee_name, OLD.department, OLD.salary, OLD.email,
            TSTZRANGE(
                CURRENT_TIMESTAMP,
                'infinity'::TIMESTAMP,
                '[)'
            )
        );
    END IF;
    
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER employees_versioning
AFTER UPDATE OR DELETE ON employees
FOR EACH ROW EXECUTE FUNCTION employees_version_trigger();
```

### Temporal Queries

```sql
-- Current state
SELECT * FROM employees WHERE employee_id = 1;

-- Historical state at specific time
SELECT * FROM employees_history
WHERE employee_id = 1
  AND sys_period @> '2024-01-15 10:00:00'::TIMESTAMP;

-- All versions of an employee
SELECT 
    employee_id,
    employee_name,
    department,
    salary,
    LOWER(sys_period) AS valid_from,
    UPPER(sys_period) AS valid_to
FROM employees_history
WHERE employee_id = 1
ORDER BY LOWER(sys_period);

-- Changes during a time period
SELECT 
    h.employee_id,
    h.employee_name,
    h.department AS old_department,
    e.department AS current_department,
    h.salary AS old_salary,
    e.salary AS current_salary
FROM employees_history h
JOIN employees e ON h.employee_id = e.employee_id
WHERE h.sys_period && TSTZRANGE('2024-01-01', '2024-02-01')
  AND (h.department != e.department OR h.salary != e.salary);
```

## Bi-Temporal Tables

### Implementation

```sql
-- Bi-temporal employee table
CREATE TABLE employees_bitemporal (
    employee_id INT NOT NULL,
    employee_name TEXT NOT NULL,
    department TEXT NOT NULL,
    salary DECIMAL(10,2) NOT NULL,
    valid_time TSTZRANGE NOT NULL,  -- Business time (when valid)
    sys_time TSTZRANGE NOT NULL,    -- System time (when recorded)
    
    -- Prevent overlapping valid times for same employee
    CONSTRAINT employees_bitemporal_valid_time_excl
        EXCLUDE USING GIST (employee_id WITH =, valid_time WITH &&),
    
    -- Track versions in system time
    CONSTRAINT employees_bitemporal_sys_time_excl
        EXCLUDE USING GIST (employee_id WITH =, valid_time WITH =, sys_time WITH &&)
);

-- Indexes
CREATE INDEX employees_bitemporal_valid_time_idx 
    ON employees_bitemporal USING GIST (valid_time);
CREATE INDEX employees_bitemporal_sys_time_idx 
    ON employees_bitemporal USING GIST (sys_time);
CREATE INDEX employees_bitemporal_employee_id_idx 
    ON employees_bitemporal (employee_id);
```

### Bi-Temporal Operations

```sql
-- Insert employee (valid from now)
INSERT INTO employees_bitemporal VALUES (
    1,
    'Alice Johnson',
    'Engineering',
    85000.00,
    TSTZRANGE(CURRENT_TIMESTAMP, 'infinity', '[)'),  -- Valid from now
    TSTZRANGE(CURRENT_TIMESTAMP, 'infinity', '[)')   -- Recorded now
);

-- Update employee (close old version, insert new)
-- Application logic handles closing/opening ranges
UPDATE employees_bitemporal
SET sys_time = TSTZRANGE(LOWER(sys_time), CURRENT_TIMESTAMP, '[)')
WHERE employee_id = 1 AND UPPER(sys_time) = 'infinity';

INSERT INTO employees_bitemporal VALUES (
    1,
    'Alice Johnson',
    'Management',  -- Changed department
    95000.00,      -- Raised salary
    TSTZRANGE(CURRENT_TIMESTAMP, 'infinity', '[)'),
    TSTZRANGE(CURRENT_TIMESTAMP, 'infinity', '[)')
);

-- Correct historical data (retroactive change)
-- Close incorrect historical record
UPDATE employees_bitemporal
SET sys_time = TSTZRANGE(LOWER(sys_time), CURRENT_TIMESTAMP, '[)')
WHERE employee_id = 1 
  AND valid_time @> '2024-01-15'::TIMESTAMP
  AND UPPER(sys_time) = 'infinity';

-- Insert corrected version
INSERT INTO employees_bitemporal VALUES (
    1,
    'Alice Johnson',
    'Engineering',  -- Corrected department
    82000.00,       -- Corrected salary
    TSTZRANGE('2024-01-01', '2024-02-01', '[)'),  -- Valid period being corrected
    TSTZRANGE(CURRENT_TIMESTAMP, 'infinity', '[)')  -- Recorded now (correction)
);
```

### Bi-Temporal Queries

```sql
-- Current truth (now valid, most recent system time)
SELECT * FROM employees_bitemporal
WHERE employee_id = 1
  AND valid_time @> CURRENT_TIMESTAMP
  AND UPPER(sys_time) = 'infinity';

-- What we knew at 2024-01-20 about salary at 2024-01-15
SELECT * FROM employees_bitemporal
WHERE employee_id = 1
  AND valid_time @> '2024-01-15'::TIMESTAMP
  AND sys_time @> '2024-01-20'::TIMESTAMP;

-- Show all corrections/versions of a specific time period
SELECT 
    employee_id,
    department,
    salary,
    valid_time,
    sys_time AS recorded_period
FROM employees_bitemporal
WHERE employee_id = 1
  AND valid_time && TSTZRANGE('2024-01-01', '2024-02-01')
ORDER BY LOWER(sys_time);
```

## Practical Examples

### Example 1: Employee Salary History

```sql
-- View salary changes over time
CREATE VIEW employee_salary_history AS
SELECT 
    h.employee_id,
    e.employee_name,
    h.salary AS historical_salary,
    e.salary AS current_salary,
    LOWER(h.sys_period) AS change_date,
    CURRENT_TIMESTAMP - LOWER(h.sys_period) AS time_since_change
FROM employees e
LEFT JOIN employees_history h ON e.employee_id = h.employee_id
WHERE h.salary != e.salary
ORDER BY h.employee_id, LOWER(h.sys_period) DESC;

-- Query usage
SELECT * FROM employee_salary_history WHERE employee_id = 1;
```

### Example 2: Tracking Contract Validity

```sql
-- Insurance policies with business time
CREATE TABLE insurance_policies (
    policy_id INT NOT NULL,
    customer_id INT NOT NULL,
    coverage_amount DECIMAL(12,2),
    premium DECIMAL(10,2),
    valid_period TSTZRANGE NOT NULL,  -- Coverage period (business time)
    sys_time TSTZRANGE NOT NULL,      -- When recorded
    
    CONSTRAINT policy_valid_period_excl
        EXCLUDE USING GIST (policy_id WITH =, valid_period WITH &&)
);

-- Query: Which policies cover a specific incident date?
SELECT * FROM insurance_policies
WHERE customer_id = 123
  AND valid_period @> '2024-06-15'::TIMESTAMP  -- Incident date
  AND UPPER(sys_time) = 'infinity';  -- Current version

-- Query: What did we think was covered on incident date when claim was filed?
SELECT * FROM insurance_policies
WHERE customer_id = 123
  AND valid_period @> '2024-06-15'::TIMESTAMP     -- Incident date
  AND sys_time @> '2024-07-01'::TIMESTAMP;  -- Claim filing date
```

## Performance Optimization

### Indexes for Temporal Queries

```sql
-- GiST indexes for range queries
CREATE INDEX ON temporal_table USING GIST (valid_time);
CREATE INDEX ON temporal_table USING GIST (sys_time);

-- Composite index for common queries
CREATE INDEX ON temporal_table USING GIST (entity_id, valid_time);

-- Partial index for current versions
CREATE INDEX current_versions_idx ON temporal_table (entity_id)
WHERE UPPER(sys_time) = 'infinity';
```

### Partitioning Historical Data

```sql
-- Partition history by year
CREATE TABLE employees_history_2024 PARTITION OF employees_history
    FOR VALUES FROM ('2024-01-01') TO ('2025-01-01');

CREATE TABLE employees_history_2023 PARTITION OF employees_history
    FOR VALUES FROM ('2023-01-01') TO ('2024-01-01');
```

## Best Practices

### 1. Use TSTZRANGE for Time Periods

```sql
-- Always use timestamp with timezone ranges
-- Provides overlap checking and atomic operations
valid_time TSTZRANGE NOT NULL
```

### 2. Implement Constraints

```sql
-- Prevent overlapping valid periods
CONSTRAINT no_overlap
    EXCLUDE USING GIST (entity_id WITH =, valid_time WITH &&)
```

### 3. Document Time Semantics

```sql
COMMENT ON COLUMN contracts.valid_time IS 
    'Business time: when the contract is/was/will be valid';
COMMENT ON COLUMN contracts.sys_time IS 
    'System time: when this record was inserted into the database';
```

### 4. Create Helper Views

```sql
-- Current state view
CREATE VIEW employees_current AS
SELECT * FROM employees_bitemporal
WHERE UPPER(sys_time) = 'infinity'
  AND valid_time @> CURRENT_TIMESTAMP;

-- Historical point-in-time view
CREATE FUNCTION employees_at(point_in_time TIMESTAMP)
RETURNS TABLE (LIKE employees_bitemporal) AS $$
    SELECT * FROM employees_bitemporal
    WHERE valid_time @> point_in_time
      AND UPPER(sys_time) = 'infinity';
$$ LANGUAGE SQL;
```

## Key Takeaways

- Temporal tables track how data changes over time
- System time tracks when database recorded changes
- Business time tracks when data is/was/will be valid in real world
- Bi-temporal tables combine both for complete audit trail
- Use TSTZRANGE for efficient range queries and overlap checking
- GiST indexes essential for temporal query performance
- Exclude constraints prevent overlapping time periods
- Implement with triggers or application logic
- Create views/functions for common temporal queries
- Consider partitioning for large historical datasets
