## Key Concepts Summary

### What are PostgreSQL Extensions?

Extensions are packaged sets of database objects (functions, data types, operators, etc.) that can be loaded into PostgreSQL with a simple command. They extend PostgreSQL's capabilities without modifying the core codebase.

**Benefits:**
- Add functionality without upgrading PostgreSQL
- Modular design (install only what you need)
- Community-developed solutions for common problems
- Easy to install and remove
- Maintained separately from core PostgreSQL

## Managing Extensions

### Discovering Available Extensions

```sql
-- List all available extensions
SELECT * FROM pg_available_extensions
ORDER BY name;

-- Check if specific extension is available
SELECT * FROM pg_available_extensions
WHERE name = 'pg_trgm';
```

### Installing Extensions

```sql
-- Install extension in current database
CREATE EXTENSION extension_name;

-- Install with specific schema
CREATE EXTENSION extension_name SCHEMA my_schema;

-- Install if not exists (idempotent)
CREATE EXTENSION IF NOT EXISTS extension_name;

-- Install specific version
CREATE EXTENSION extension_name VERSION '1.5';
```

### Viewing Installed Extensions

```sql
-- List installed extensions
SELECT * FROM pg_extension
ORDER BY extname;

-- View in psql
\dx

-- Detailed view with objects
\dx+ extension_name
```

### Updating Extensions

```sql
-- Update to latest version
ALTER EXTENSION extension_name UPDATE;

-- Update to specific version
ALTER EXTENSION extension_name UPDATE TO '2.0';
```

### Removing Extensions

```sql
-- Remove extension
DROP EXTENSION extension_name;

-- Remove with cascade (drops dependent objects)
DROP EXTENSION extension_name CASCADE;
```

## Essential Extensions

### 1. pg_trgm (Trigram Similarity)

**Purpose:** Text similarity and fuzzy matching using trigrams.

**Installation:**
```sql
CREATE EXTENSION pg_trgm;
```

**Key Functions:**
```sql
-- Calculate similarity (0 to 1)
SELECT similarity('PostgreSQL', 'Postgres');
-- Result: ~0.5

SELECT similarity('PostgreSQL', 'MySQL');
-- Result: ~0.2

-- Show trigrams
SELECT show_trgm('PostgreSQL');
-- Result: {" p"," po",gre,ost,pos,qls,res,esi,esq,gre,ost,"l ",ql ,res,sql,stg,tgr}

-- Word similarity (best match of substring)
SELECT word_similarity('PostgreSQL', 'I love PostgreSQL databases');
-- Result: 1.0 (exact match found)
```

**Operators:**
```sql
-- % operator: similar to
SELECT * FROM products
WHERE name % 'iPhone';
-- Finds: 'iPhone', 'iPhones', 'iphon', etc.

-- <-> operator: distance (1 - similarity)
SELECT name, name <-> 'laptop' AS distance
FROM products
ORDER BY distance
LIMIT 5;
-- Returns closest matches first
```

**Practical Example:**
```sql
-- Fuzzy product search
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    name TEXT NOT NULL
);

-- Create trigram index for fast similarity searches
CREATE INDEX products_name_trgm_idx ON products USING GIN (name gin_trgm_ops);

-- Insert test data
INSERT INTO products (name) VALUES
    ('iPhone 15 Pro'),
    ('Samsung Galaxy S24'),
    ('iPad Air'),
    ('MacBook Pro');

-- Fuzzy search with typo
SELECT name, similarity(name, 'iphon') AS sim
FROM products
WHERE name % 'iphon'
ORDER BY sim DESC;
-- Finds 'iPhone 15 Pro' despite typo
```

### 2. uuid-ossp (UUID Generation)

**Purpose:** Generate universally unique identifiers (UUIDs).

**Installation:**
```sql
CREATE EXTENSION "uuid-ossp";
```

**UUID Generation Functions:**
```sql
-- UUID v4 (random)
SELECT uuid_generate_v4();
-- Result: 123e4567-e89b-12d3-a456-426614174000

-- UUID v1 (timestamp + MAC address)
SELECT uuid_generate_v1();

-- UUID v1mc (timestamp + random multicast MAC)
SELECT uuid_generate_v1mc();

-- UUID v3 (MD5 hash of namespace + name)
SELECT uuid_generate_v3(uuid_ns_url(), 'https://example.com');

-- UUID v5 (SHA-1 hash of namespace + name)
SELECT uuid_generate_v5(uuid_ns_url(), 'https://example.com');
```

**Practical Example:**
```sql
-- Use UUID as primary key
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    username TEXT NOT NULL UNIQUE,
    email TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);

INSERT INTO users (username, email)
VALUES ('john_doe', 'john@example.com');

SELECT * FROM users;
-- user_id is automatically generated UUID
```

### 3. hstore (Key-Value Store)

**Purpose:** Store key-value pairs in a single column.

**Installation:**
```sql
CREATE EXTENSION hstore;
```

**Basic Operations:**
```sql
-- Create hstore
SELECT 'name=>John, age=>30, city=>NYC'::hstore;

-- Access values
SELECT 'name=>John, age=>30'::hstore -> 'name';
-- Result: 'John'

-- Check key existence
SELECT 'name=>John, age=>30'::hstore ? 'name';
-- Result: true

-- Get all keys
SELECT akeys('name=>John, age=>30'::hstore);
-- Result: {name, age}

-- Get all values
SELECT avals('name=>John, age=>30'::hstore);
-- Result: {John, 30}

-- Convert to JSON
SELECT hstore_to_json('name=>John, age=>30'::hstore);
-- Result: {"name": "John", "age": "30"}
```

**Practical Example:**
```sql
-- Store flexible user attributes
CREATE TABLE user_profiles (
    user_id INT PRIMARY KEY,
    username TEXT NOT NULL,
    attributes hstore
);

-- Insert with various attributes
INSERT INTO user_profiles (user_id, username, attributes) VALUES
    (1, 'alice', 'theme=>dark, language=>en, notifications=>true'),
    (2, 'bob', 'theme=>light, timezone=>PST'),
    (3, 'charlie', 'language=>es, beta_features=>true, theme=>dark');

-- Query by attribute
SELECT username FROM user_profiles
WHERE attributes -> 'theme' = 'dark';
-- Returns: alice, charlie

-- GIN index for fast queries
CREATE INDEX user_attributes_idx ON user_profiles USING GIN (attributes);

-- Update specific key
UPDATE user_profiles
SET attributes = attributes || 'notifications=>false'::hstore
WHERE user_id = 1;
```

### 4. PostGIS (Geographic Data)

**Purpose:** Add support for geographic objects and spatial queries.

**Installation:**
```sql
CREATE EXTENSION postgis;

-- Verify version
SELECT PostGIS_Version();
```

**Basic Operations:**
```sql
-- Create point (longitude, latitude)
SELECT ST_GeomFromText('POINT(-73.935242 40.730610)');  -- NYC

-- Calculate distance between two points (in meters)
SELECT ST_Distance(
    ST_GeomFromText('POINT(-73.935242 40.730610)')::geography,  -- NYC
    ST_GeomFromText('POINT(-118.243683 34.052235)')::geography  -- LA
);
-- Result: ~3935749 meters (~3936 km)

-- Check if point is within polygon
SELECT ST_Within(
    ST_GeomFromText('POINT(-73.935242 40.730610)'),
    ST_GeomFromText('POLYGON((-74 40, -74 41, -73 41, -73 40, -74 40))')
);
-- Result: true
```

**Practical Example:**
```sql
-- Store locations with spatial indexing
CREATE TABLE locations (
    location_id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    coordinates GEOGRAPHY(POINT, 4326)
);

-- Create spatial index (dramatically improves query performance)
CREATE INDEX locations_coordinates_idx 
    ON locations USING GIST (coordinates);

-- Insert locations
INSERT INTO locations (name, coordinates) VALUES
    ('Central Park', ST_GeomFromText('POINT(-73.968285 40.785091)', 4326)),
    ('Times Square', ST_GeomFromText('POINT(-73.985130 40.758896)', 4326)),
    ('Brooklyn Bridge', ST_GeomFromText('POINT(-73.996826 40.706086)', 4326));

-- Find locations within 2km radius
SELECT 
    name,
    ST_Distance(
        coordinates,
        ST_GeomFromText('POINT(-73.935242 40.730610)', 4326)::geography
    ) / 1000 AS distance_km
FROM locations
WHERE ST_DWithin(
    coordinates,
    ST_GeomFromText('POINT(-73.935242 40.730610)', 4326)::geography,
    2000  -- 2km in meters
)
ORDER BY distance_km;
```

### 5. pgcrypto (Cryptography)

**Purpose:** Cryptographic functions for encryption, hashing, and more.

**Installation:**
```sql
CREATE EXTENSION pgcrypto;
```

**Key Functions:**
```sql
-- Hash password (bcrypt)
SELECT crypt('my_password', gen_salt('bf'));
-- Result: $2a$06$randomsalt...hashedpassword

-- Verify password
SELECT crypt('my_password', '$2a$06$stored_hash') = '$2a$06$stored_hash';
-- Returns true if password matches

-- Generate random UUID (alternative to uuid-ossp)
SELECT gen_random_uuid();

-- Generate random bytes
SELECT encode(gen_random_bytes(16), 'hex');

-- SHA256 hash
SELECT encode(digest('my_data', 'sha256'), 'hex');

-- MD5 hash
SELECT encode(digest('my_data', 'md5'), 'hex');
```

**Practical Example:**
```sql
-- Secure password storage
CREATE TABLE user_accounts (
    user_id SERIAL PRIMARY KEY,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Function to create user with hashed password
CREATE FUNCTION create_user(p_username TEXT, p_password TEXT)
RETURNS INT AS $$
DECLARE
    new_user_id INT;
BEGIN
    INSERT INTO user_accounts (username, password_hash)
    VALUES (p_username, crypt(p_password, gen_salt('bf')))
    RETURNING user_id INTO new_user_id;
    
    RETURN new_user_id;
END;
$$ LANGUAGE plpgsql;

-- Function to authenticate user
CREATE FUNCTION authenticate_user(p_username TEXT, p_password TEXT)
RETURNS BOOLEAN AS $$
DECLARE
    stored_hash TEXT;
BEGIN
    SELECT password_hash INTO stored_hash
    FROM user_accounts
    WHERE username = p_username;
    
    IF stored_hash IS NULL THEN
        RETURN FALSE;
    END IF;
    
    RETURN crypt(p_password, stored_hash) = stored_hash;
END;
$$ LANGUAGE plpgsql;

-- Usage
SELECT create_user('alice', 'secure_password123');
SELECT authenticate_user('alice', 'secure_password123');  -- true
SELECT authenticate_user('alice', 'wrong_password');      -- false
```

### 7. pg_cron (Job Scheduling)

**Purpose:** Schedule PostgreSQL commands using cron syntax.

**Installation:**
```sql
-- Add to postgresql.conf
shared_preload_libraries = 'pg_cron'
-- Restart PostgreSQL

CREATE EXTENSION pg_cron;
```

**Usage:**
```sql
-- Schedule daily vacuum at 3 AM
SELECT cron.schedule('nightly-vacuum', '0 3 * * *', 'VACUUM ANALYZE;');

-- Delete old data weekly
SELECT cron.schedule(
    'weekly-cleanup',
    '0 0 * * 0',
    $$DELETE FROM logs WHERE created_at < NOW() - INTERVAL '90 days'$$
);

-- Refresh materialized view hourly
SELECT cron.schedule(
    'refresh-mv',
    '0 * * * *',
    'REFRESH MATERIALIZED VIEW CONCURRENTLY sales_summary;'
);

-- List scheduled jobs
SELECT * FROM cron.job;

-- Unschedule job
SELECT cron.unschedule('nightly-vacuum');
```

### 8. citext (Case-Insensitive Text)

**Purpose:** Case-insensitive text comparison.

**Installation:**
```sql
CREATE EXTENSION citext;
```

**Usage:**
```sql
-- Create table with case-insensitive column
CREATE TABLE users (
    user_id SERIAL PRIMARY KEY,
    email CITEXT NOT NULL UNIQUE
);

-- Inserts are case-insensitive
INSERT INTO users (email) VALUES ('John@Example.com');

-- ERROR: duplicate key (case-insensitive comparison)
-- INSERT INTO users (email) VALUES ('john@example.com');

-- Queries are case-insensitive
SELECT * FROM users WHERE email = 'JOHN@EXAMPLE.COM';
-- Returns: John@Example.com

-- Unique constraint is case-insensitive
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    name CITEXT NOT NULL UNIQUE
);
```

## Other Notable Extensions

### fuzzystrmatch (String Similarity)

```sql
CREATE EXTENSION fuzzystrmatch;

-- Levenshtein distance (edit distance)
SELECT levenshtein('PostgreSQL', 'Postgres');
-- Result: 2 (2 edits needed)

-- Soundex (phonetic matching)
SELECT soundex('PostgreSQL'), soundex('Postgres');
-- Same soundex = sound similar

-- Metaphone
SELECT metaphone('PostgreSQL', 10);
```

### ltree (Hierarchical Data)

```sql
CREATE EXTENSION ltree;

-- Store tree paths
CREATE TABLE categories (
    category_id SERIAL PRIMARY KEY,
    path LTREE NOT NULL
);

INSERT INTO categories (path) VALUES
    ('Electronics'),
    ('Electronics.Computers'),
    ('Electronics.Computers.Laptops'),
    ('Electronics.Phones');

-- Query descendants
SELECT * FROM categories
WHERE path <@ 'Electronics.Computers';
-- Returns: Computers and Laptops

-- Query ancestors
SELECT * FROM categories
WHERE path @> 'Electronics.Computers.Laptops';
-- Returns: Electronics, Computers, Laptops
```

### pg_partman (Partition Management)

```sql
CREATE EXTENSION pg_partman;

-- Automates partition creation and maintenance
-- Useful for time-series data partitioning
```

## Practical Integration Example

```sql
-- Comprehensive product database with multiple extensions

-- Install extensions
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS hstore;
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- Products table with UUID primary key
CREATE TABLE products (
    product_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    name TEXT NOT NULL,
    description TEXT,
    attributes hstore,  -- Flexible key-value attributes
    created_at TIMESTAMP DEFAULT NOW()
);

-- Trigram index for fuzzy search
CREATE INDEX products_name_trgm_idx ON products USING GIN (name gin_trgm_ops);

-- GIN index for hstore attributes
CREATE INDEX products_attributes_idx ON products USING GIN (attributes);

-- Insert sample data
INSERT INTO products (name, description, attributes) VALUES
    (
        'MacBook Pro 16"',
        'Professional laptop',
        'color=>Silver, ram=>32GB, storage=>1TB, processor=>M3 Max'
    ),
    (
        'iPhone 15 Pro',
        'Latest smartphone',
        'color=>Titanium, storage=>256GB, camera=>48MP'
    );

-- Fuzzy search with typo
SELECT 
    name,
    similarity(name, 'macbok') AS sim
FROM products
WHERE name % 'macbok'
ORDER BY sim DESC;

-- Query by attribute
SELECT name, attributes
FROM products
WHERE attributes -> 'storage' = '1TB';

-- Generate shareable product link
SELECT 
    product_id,
    name,
    'https://example.com/product/' || product_id AS share_url
FROM products;
```

## Practice Exercise

Set up a multi-extension database for a location-based app:

1. Install uuid-ossp, PostGIS, pg_trgm, and hstore extensions
2. Create a locations table with UUID, geographic coordinates, and flexible attributes
3. Add indexes for spatial and text search
4. Insert sample data
5. Perform fuzzy name search and distance calculations

**Example solution:**

```sql
-- Step 1: Install extensions
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS hstore;

-- Step 2: Create table
CREATE TABLE locations (
    location_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    name TEXT NOT NULL,
    description TEXT,
    coordinates GEOGRAPHY(POINT, 4326),
    metadata hstore,  -- hours, phone, website, etc.
    created_at TIMESTAMP DEFAULT NOW()
);

-- Step 3: Create indexes
CREATE INDEX locations_name_trgm_idx ON locations USING GIN (name gin_trgm_ops);
CREATE INDEX locations_coordinates_idx ON locations USING GIST (coordinates);
CREATE INDEX locations_metadata_idx ON locations USING GIN (metadata);

-- Step 4: Insert sample data
INSERT INTO locations (name, description, coordinates, metadata) VALUES
    (
        'Central Coffee Shop',
        'Cozy coffee shop in Manhattan',
        ST_GeomFromText('POINT(-73.968285 40.785091)', 4326),
        'hours=>8:00-20:00, wifi=>true, parking=>false'
    ),
    (
        'Downtown Cafe',
        'Modern cafe with great ambiance',
        ST_GeomFromText('POINT(-73.985130 40.758896)', 4326),
        'hours=>7:00-22:00, wifi=>true, parking=>true'
    ),
    (
        'Brooklyn Roasters',
        'Artisan coffee roastery',
        ST_GeomFromText('POINT(-73.996826 40.706086)', 4326),
        'hours=>9:00-18:00, wifi=>false, parking=>false'
    );

-- Step 5: Fuzzy search with typo
SELECT 
    name,
    similarity(name, 'cofee') AS sim,
    metadata -> 'hours' AS hours
FROM locations
WHERE name % 'cofee'
ORDER BY sim DESC;

-- Distance search (within 3km of point)
WITH search_point AS (
    SELECT ST_GeomFromText('POINT(-73.980000 40.750000)', 4326)::geography AS point
)
SELECT 
    name,
    description,
    ROUND(ST_Distance(coordinates, search_point.point) / 1000, 2) AS distance_km,
    metadata -> 'hours' AS hours,
    metadata -> 'wifi' AS has_wifi
FROM locations, search_point
WHERE ST_DWithin(coordinates, search_point.point, 3000)
ORDER BY distance_km;

-- Combined: fuzzy search + distance + attributes
SELECT 
    name,
    similarity(name, 'cafe') AS name_similarity,
    ROUND(ST_Distance(
        coordinates,
        ST_GeomFromText('POINT(-73.980000 40.750000)', 4326)::geography
    ) / 1000, 2) AS distance_km,
    metadata -> 'wifi' AS has_wifi
FROM locations
WHERE name % 'cafe'
  AND metadata -> 'wifi' = 'true'
  AND ST_DWithin(
      coordinates,
      ST_GeomFromText('POINT(-73.980000 40.750000)', 4326)::geography,
      5000
  )
ORDER BY name_similarity DESC, distance_km ASC;
```

## Key Takeaways

- PostgreSQL extensions add functionality without modifying the core database
- Use `CREATE EXTENSION` to install extensions in your database
- pg_trgm enables fuzzy text matching and similarity searches
- uuid-ossp provides UUID generation for distributed systems
- hstore allows flexible key-value storage within rows
- PostGIS adds powerful geographic and spatial capabilities
- pgcrypto provides cryptographic functions for secure password storage
- pg_cron enables scheduling of database tasks
- Combine multiple extensions to solve complex problems
- Always create appropriate indexes for extension-specific data types
- Extensions are database-specific; install in each database where needed
