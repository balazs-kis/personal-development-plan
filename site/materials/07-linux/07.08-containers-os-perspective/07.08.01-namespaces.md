## Introduction

Linux namespaces are the foundation of container isolation. They allow multiple processes to have independent views of system resources—each container can have its own process tree, network stack, filesystem hierarchy, and more, without interfering with other containers or the host. Understanding namespaces is essential for troubleshooting container issues and understanding how containerization works at the kernel level.

## Key Concepts Summary

### What Are Namespaces?

**Definition:**
- Kernel feature for process isolation
- Wraps global system resources in an abstraction
- Makes processes appear to have isolated instances
- Changes visible only within namespace

**Purpose:**
```
Without namespaces:
- All processes share same PID space
- Single network configuration
- Shared filesystem hierarchy
- Processes can interfere with each other

With namespaces:
- Each container has isolated PID tree
- Independent network stacks
- Separate filesystem views
- Strong isolation between containers
```

### History

**Timeline:**
```
2002 - Mount namespaces (kernel 2.4.19)
2006 - UTS and IPC namespaces (kernel 2.6.19)
2008 - PID namespaces (kernel 2.6.24)
2009 - Network namespaces (kernel 2.6.29)
2013 - User namespaces (kernel 3.8)
2013 - Docker released, popularizing containers
2016 - Cgroup namespaces (kernel 4.6)
2020 - Time namespaces (kernel 5.6)
```

**Impact:**
- Docker (2013) made containers mainstream
- Combined namespaces with cgroups
- Democratized containerization
- Foundation for Kubernetes, Podman, containerd

### Seven Types of Namespaces

**1. PID Namespace (Process IDs):**
```
Isolates: Process ID numbers
Created: Linux 2.6.24 (2008)

What it does:
- Each namespace has own process tree
- Container's init process is PID 1
- Processes can't see outside namespace
- Host can see all processes

Example:
In container: PID 1, 2, 3, 4...
On host:      PID 12345, 12346, 12347...
```

**2. Mount Namespace (Filesystem):**
```
Isolates: Filesystem mount points
Created: Linux 2.4.19 (2002) - first namespace

What it does:
- Each namespace has own mount hierarchy
- Container sees its own filesystem tree
- Changes don't affect other namespaces
- Enables per-container filesystem views

Example:
Container sees: /app, /lib, /usr
Host sees: /var/lib/docker/overlay2/...
```

**3. UTS Namespace (Hostname):**
```
Isolates: Hostname and domain name
Created: Linux 2.6.19 (2006)

What it does:
- Each container has own hostname
- Independent from host
- UTS = Unix Time-Sharing

Example:
Container: hostname = "web-server-01"
Host:      hostname = "production-node-5"
```

**4. IPC Namespace (Inter-Process Communication):**
```
Isolates: System V IPC, POSIX message queues
Created: Linux 2.6.19 (2006)

What it does:
- Isolates shared memory segments
- Separate message queues
- Independent semaphores
- Prevents cross-container IPC

Resources isolated:
- Shared memory (shm)
- Message queues
- Semaphore arrays
```

**5. Network Namespace:**
```
Isolates: Network stack
Created: Linux 2.6.29 (2009)

What it does:
- Each container has own network stack
- Independent IP addresses
- Separate routing tables
- Isolated firewall rules
- Own network interfaces

Example:
Container: eth0 (10.0.0.2)
Host:      eth0 (192.168.1.100)
           veth123 (bridge to container)
```

**6. User Namespace:**
```
Isolates: User and group IDs
Created: Linux 3.8 (2013)

What it does:
- Map UIDs/GIDs between namespaces
- Root in container ≠ root on host
- Enables rootless containers
- Enhanced security

Example:
In container:  UID 0 (root)
On host:       UID 1000 (regular user)
```

**7. Cgroup Namespace:**
```
Isolates: Cgroup hierarchy view
Created: Linux 4.6 (2016)

What it does:
- Virtualizes /proc/self/cgroup
- Containers see relative cgroup path
- Prevents escaping resource limits
- Security isolation
```

### How Namespaces Work

**System calls:**
```c
// Create new namespaces
clone(flags)     - Create child process with new namespaces
unshare(flags)   - Move current process to new namespace
setns(fd, flags) - Join existing namespace

// Flags:
CLONE_NEWPID    - New PID namespace
CLONE_NEWNET    - New network namespace
CLONE_NEWNS     - New mount namespace
CLONE_NEWUTS    - New UTS namespace
CLONE_NEWIPC    - New IPC namespace
CLONE_NEWUSER   - New user namespace
CLONE_NEWCGROUP - New cgroup namespace
```

**Namespace hierarchy:**
```
Parent namespace
└── Child namespace 1
    └── Child namespace 1.1
    └── Child namespace 1.2
└── Child namespace 2
```

### Viewing Namespaces

**List namespaces:**
```bash
# View current process namespaces
ls -la /proc/self/ns/

# Output:
lrwxrwxrwx 1 user user 0 Jan 26 12:00 cgroup -> 'cgroup:[4026531835]'
lrwxrwxrwx 1 user user 0 Jan 26 12:00 ipc -> 'ipc:[4026531839]'
lrwxrwxrwx 1 user user 0 Jan 26 12:00 mnt -> 'mnt:[4026531840]'
lrwxrwxrwx 1 user user 0 Jan 26 12:00 net -> 'net:[4026531992]'
lrwxrwxrwx 1 user user 0 Jan 26 12:00 pid -> 'pid:[4026531836]'
lrwxrwxrwx 1 user user 0 Jan 26 12:00 user -> 'user:[4026531837]'
lrwxrwxrwx 1 user user 0 Jan 26 12:00 uts -> 'uts:[4026531838]'
```

**View process namespaces:**
```bash
# For specific PID
ls -la /proc/1234/ns/

# Compare namespaces
ls -la /proc/{1,$$}/ns/ | grep net
```

**Check if processes share namespace:**
```bash
# Same inode number = same namespace
readlink /proc/PID1/ns/net
readlink /proc/PID2/ns/net
```

### Working with unshare

**Create new namespace:**
```bash
# New PID namespace
unshare --pid --fork bash

# New network namespace
unshare --net bash

# Multiple namespaces
unshare --pid --net --mount --uts --ipc --fork bash

# Check hostname isolation
unshare --uts bash
hostname container-test
hostname  # Shows: container-test
exit
hostname  # Shows: original hostname
```

**Common options:**
```bash
--pid       - New PID namespace
--net       - New network namespace
--mount     - New mount namespace
--uts       - New UTS namespace
--ipc       - New IPC namespace
--user      - New user namespace
--fork      - Fork before executing
--map-root-user - Map to root in new user namespace
```

### Working with nsenter

**Enter namespace:**
```bash
# Enter all namespaces of process
nsenter --target PID --all bash

# Enter specific namespace
nsenter --target PID --net bash

# Enter network namespace by name
nsenter --net=/var/run/netns/myns bash
```

**Docker container namespaces:**
```bash
# Get container PID
PID=$(docker inspect -f '{{.State.Pid}}' container_name)

# Enter container namespaces
nsenter --target $PID --mount --uts --ipc --net --pid bash
```

### Namespaces in Docker

**How Docker uses namespaces:**
```
1. Create new namespaces:
   - PID: Container has own process tree
   - Mount: Container has own filesystem view
   - Network: Container has own network stack
   - UTS: Container has own hostname
   - IPC: Container has isolated IPC
   - User: (optional) UID/GID mapping

2. Set up container environment:
   - Mount overlay filesystem
   - Configure network interfaces
   - Set hostname
   - Map user IDs

3. Execute container process:
   - Process runs in isolated namespaces
   - Sees only its own resources
   - Can't interfere with host or other containers
```

**View Docker container namespaces:**
```bash
# Get container PID
docker inspect -f '{{.State.Pid}}' container_name

# View namespaces
ls -la /proc/<PID>/ns/

# Compare with host
ls -la /proc/1/ns/
```

### Namespace Security

**Security benefits:**
```
PID namespace:
- Processes can't kill other containers' processes
- Can't see other processes with ps

Network namespace:
- Isolated network stack
- Can't sniff other containers' traffic
- Independent firewall rules

Mount namespace:
- Can't access other containers' filesystems
- Limited host filesystem access

User namespace:
- Root in container ≠ root on host
- Reduced privilege escalation risk
```

**Security considerations:**
```
Shared namespaces:
- --net=host: Container uses host network (risky)
- --pid=host: Container sees all processes (very risky)
- --ipc=host: Shared memory access (risky)

Privileged containers:
- Disables many security features
- Should be avoided in production

User namespaces:
- Not enabled by default in Docker
- Significantly improves security
- Some features incompatible
```

### Practical Examples

**Example 1: PID namespace isolation**
```bash
# Terminal 1: Create new PID namespace
unshare --pid --fork --mount-proc bash
ps aux  # Only shows processes in namespace

# Terminal 2: Check from host
ps aux | grep unshare  # Can see the process
```

**Example 2: Network namespace**
```bash
# Create network namespace
unshare --net bash

# Check interfaces
ip link show  # Only shows loopback

# Exit and check host
exit
ip link show  # Shows all host interfaces
```

**Example 3: Compare container and host**
```bash
# Start container
docker run -d --name test nginx

# Get container PID
PID=$(docker inspect -f '{{.State.Pid}}' test)

# Compare namespaces
echo "Host NET namespace:"
readlink /proc/self/ns/net

echo "Container NET namespace:"
readlink /proc/$PID/ns/net

# Cleanup
docker rm -f test
```
