## Introduction

While namespaces provide isolation, cgroups (control groups) provide resource management. They allow you to limit, prioritize, and account for system resources like CPU, memory, disk I/O, and network bandwidth. Understanding cgroups is essential for configuring container resource limits, preventing resource starvation, and ensuring fair resource allocation in multi-tenant environments.

## Key Concepts Summary

### What Are Cgroups?

**Definition:**
- Kernel feature for resource management
- Organize processes into hierarchical groups
- Limit and monitor resource usage
- Essential for containerization

**History:**
```
2006 - Developed by Google engineers
2008 - Merged into Linux kernel 2.6.24
2016 - Cgroups v2 released (kernel 4.5)
2021 - Cgroups v2 becomes default in many distros
```

**Purpose:**
```
Without cgroups:
- Process can use 100% CPU
- Can consume all memory
- Can saturate disk I/O
- No resource guarantees

With cgroups:
- Limit resource usage per container
- Guarantee minimum resources
- Fair resource sharing
- Prevent resource starvation
```

### Core Functions

**1. Resource Limiting:**
```
Set maximum resource usage:
- CPU: "Use max 50% of one core"
- Memory: "Use max 2GB RAM"
- I/O: "Read max 100 MB/s"
- Processes: "Max 100 processes"
```

**2. Prioritization:**
```
Allocate shares when contention occurs:
- High priority: More CPU when busy
- Low priority: Less CPU when busy
- Fair sharing by default
```

**3. Accounting:**
```
Measure resource usage:
- CPU time consumed
- Memory used
- I/O operations
- Network bandwidth
```

**4. Control:**
```
Manage process groups:
- Freeze/thaw processes
- Checkpoint/restart
- Migrate between hosts
```

### Cgroups v1 vs v2

**Cgroups v1:**
```
Features:
- Multiple hierarchies (one per controller)
- Flexible but complex
- Inconsistent between controllers

Issues:
- Each controller has own hierarchy
- Hard to manage consistently
- Conflicts between controllers
- Complex delegation model
```

**Cgroups v2:**
```
Improvements:
- Single unified hierarchy
- Consistent interface
- Better delegation
- Simplified design

Advantages:
- Easier to use
- More predictable
- Better container support
- Active development
```

**Checking version:**
```bash
# Check cgroup version
stat -fc %T /sys/fs/cgroup

# cgroup2fs = v2
# tmpfs = v1 (or hybrid)

# Check mount
mount | grep cgroup

# Modern systems use v2
```

### Cgroup Controllers

**Available controllers:**
```
cpu       - CPU time distribution
memory    - Memory usage limits
io        - Block I/O limits
pids      - Process number limits
cpuset    - CPU and memory node assignment
devices   - Device access control
freezer   - Suspend/resume cgroups (v1)
net_cls   - Network class tagging (v1)
net_prio  - Network priority (v1)
```

**Enabling controllers:**
```bash
# View available controllers
cat /sys/fs/cgroup/cgroup.controllers

# Enable controllers in subtree
echo "+cpu +memory +io" > /sys/fs/cgroup/cgroup.subtree_control
```

### Cgroup Filesystem

**Location:**
```bash
# Cgroups v2 mount point
/sys/fs/cgroup/

# Example hierarchy:
/sys/fs/cgroup/
├── cgroup.controllers
├── cgroup.procs
├── cgroup.subtree_control
├── cpu.max
├── memory.max
├── io.max
├── user.slice/
│   └── user-1000.slice/
│       └── session-3.scope/
└── system.slice/
    └── docker-123abc.scope/
```

**Key files:**
```
cgroup.procs            - PIDs in this cgroup
cgroup.controllers      - Available controllers
cgroup.subtree_control  - Enabled controllers
cgroup.events           - Events (populated, frozen)
cgroup.max.depth        - Max hierarchy depth
cgroup.max.descendants  - Max child cgroups
```

### CPU Controller

**Limit CPU usage:**
```bash
# Create cgroup
mkdir /sys/fs/cgroup/myapp

# Enable CPU controller
echo "+cpu" > /sys/fs/cgroup/cgroup.subtree_control

# Set CPU limit: 50% of one CPU
# Format: $MAX $PERIOD (microseconds)
echo "50000 100000" > /sys/fs/cgroup/myapp/cpu.max

# Add process to cgroup
echo $PID > /sys/fs/cgroup/myapp/cgroup.procs
```

**CPU shares (weight):**
```bash
# Set CPU weight (1-10000, default 100)
echo 500 > /sys/fs/cgroup/myapp/cpu.weight

# Higher weight = more CPU when contention
# 500 weight = 5x more CPU than 100 weight
```

**View CPU usage:**
```bash
# CPU statistics
cat /sys/fs/cgroup/myapp/cpu.stat

# Output:
usage_usec 1234567
user_usec 1000000
system_usec 234567
```

### Memory Controller

**Limit memory:**
```bash
# Set memory limit: 512MB
echo "512M" > /sys/fs/cgroup/myapp/memory.max

# Set swap limit: 1GB
echo "1G" > /sys/fs/cgroup/myapp/memory.swap.max

# Soft limit (try to reclaim above this)
echo "256M" > /sys/fs/cgroup/myapp/memory.high

# Disable swap
echo "0" > /sys/fs/cgroup/myapp/memory.swap.max
```

**View memory usage:**
```bash
# Current memory usage
cat /sys/fs/cgroup/myapp/memory.current

# Memory statistics
cat /sys/fs/cgroup/myapp/memory.stat

# Key metrics:
anon        - Anonymous memory (heap, stack)
file        - Page cache
kernel      - Kernel memory
shmem       - Shared memory
```

**OOM behavior:**
```bash
# Configure OOM killer
# 0 = kill processes, 1 = kill cgroup
echo "1" > /sys/fs/cgroup/myapp/memory.oom.group

# View OOM events
cat /sys/fs/cgroup/myapp/memory.events
```

### I/O Controller

**Limit I/O:**
```bash
# Set read limit: 100 MB/s on sda
echo "8:0 rbps=104857600" > /sys/fs/cgroup/myapp/io.max

# Set write limit: 50 MB/s
echo "8:0 wbps=52428800" > /sys/fs/cgroup/myapp/io.max

# Set IOPS limit
echo "8:0 riops=1000 wiops=500" > /sys/fs/cgroup/myapp/io.max

# Device numbers: major:minor (8:0 = sda)
ls -l /dev/sda
```

**I/O priority:**
```bash
# Set I/O weight (1-10000, default 100)
echo "8:0 500" > /sys/fs/cgroup/myapp/io.weight
```

**View I/O stats:**
```bash
# I/O statistics
cat /sys/fs/cgroup/myapp/io.stat

# Output per device:
8:0 rbytes=1048576 wbytes=524288 rios=100 wios=50
```

### PID Controller

**Limit processes:**
```bash
# Set max processes: 100
echo "100" > /sys/fs/cgroup/myapp/pids.max

# View current process count
cat /sys/fs/cgroup/myapp/pids.current

# View events
cat /sys/fs/cgroup/myapp/pids.events
```

### Working with systemd

**systemd manages cgroups:**
```bash
# View cgroup hierarchy
systemd-cgls

# View resource usage
systemd-cgtop

# Run command in new cgroup
systemd-run --scope -p MemoryMax=512M -p CPUQuota=50% \
  ./my-application
```

**Service limits:**
```ini
# /etc/systemd/system/myapp.service
[Service]
MemoryMax=1G
CPUQuota=100%
IOReadBandwidthMax=/dev/sda 100M
TasksMax=50
```

**View service cgroup:**
```bash
# Show service cgroup path
systemctl status myapp.service

# View cgroup files
ls -la /sys/fs/cgroup/system.slice/myapp.service/
```

### Cgroups in Docker

**How Docker uses cgroups:**
```
1. Create cgroup for container
2. Configure resource limits
3. Add container processes to cgroup
4. Monitor resource usage
5. Enforce limits
```

**Docker cgroup location:**
```bash
# Docker cgroups (v2)
/sys/fs/cgroup/system.slice/docker-<container-id>.scope/

# View container cgroup
docker inspect -f '{{.HostConfig.CgroupParent}}' container_name
```

**Setting limits:**
```bash
# CPU limits
docker run --cpus="1.5" nginx       # Max 1.5 CPUs
docker run --cpu-shares=512 nginx   # CPU weight

# Memory limits
docker run -m 512m nginx            # Max 512MB
docker run --memory-swap 1g nginx   # Total memory+swap

# I/O limits
docker run --device-read-bps /dev/sda:100mb nginx
docker run --device-write-bps /dev/sda:50mb nginx

# Process limits
docker run --pids-limit 100 nginx
```

**View container resources:**
```bash
# Real-time stats
docker stats

# Container cgroup
docker exec container cat /proc/self/cgroup
```

### Practical Examples

**Example 1: Limit CPU**
```bash
# Create cgroup
mkdir /sys/fs/cgroup/cpulimit
echo "+cpu" > /sys/fs/cgroup/cgroup.subtree_control

# Limit to 25% CPU
echo "25000 100000" > /sys/fs/cgroup/cpulimit/cpu.max

# Run CPU-intensive task
stress --cpu 1 &
PID=$!

# Add to cgroup
echo $PID > /sys/fs/cgroup/cpulimit/cgroup.procs

# Monitor with top
top -p $PID

# Cleanup
kill $PID
rmdir /sys/fs/cgroup/cpulimit
```

**Example 2: Limit memory**
```bash
# Create cgroup
mkdir /sys/fs/cgroup/memlimit
echo "+memory" > /sys/fs/cgroup/cgroup.subtree_control

# Limit to 100MB
echo "100M" > /sys/fs/cgroup/memlimit/memory.max

# Try to allocate 200MB
stress --vm 1 --vm-bytes 200M &
PID=$!
echo $PID > /sys/fs/cgroup/memlimit/cgroup.procs

# Process will be OOM killed
# Check events
cat /sys/fs/cgroup/memlimit/memory.events

# Cleanup
rmdir /sys/fs/cgroup/memlimit
```

**Example 3: Docker with limits**
```bash
# Run with limits
docker run -d --name limited \
  --cpus="0.5" \
  -m 256m \
  --pids-limit 50 \
  nginx

# View stats
docker stats limited

# Check cgroup
docker exec limited cat /sys/fs/cgroup/memory.max
docker exec limited cat /sys/fs/cgroup/cpu.max

# Cleanup
docker rm -f limited
```
