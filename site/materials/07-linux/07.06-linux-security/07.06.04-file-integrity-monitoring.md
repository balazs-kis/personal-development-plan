## Introduction

File Integrity Monitoring (FIM) detects unauthorized changes to critical system files by comparing current file states against a known-good baseline. FIM is essential for security compliance (PCI-DSS, HIPAA), detecting breaches, and forensic analysis. Tripwire is a popular open-source FIM tool that provides cryptographic verification of file integrity.

## Key Concepts Summary

### File Integrity Monitoring Concepts

**What is FIM?**
- Detects unauthorized file changes
- Compares current state to baseline
- Uses cryptographic hashes
- Alerts on modifications
- Essential for security compliance

**Why use FIM?**
```
Detect:
- Malware installation
- Unauthorized configuration changes
- Rootkit installation
- Insider threats
- Compromised accounts

Compliance:
- PCI-DSS requirement 11.5
- HIPAA security requirements
- NIST cybersecurity framework
- SOC 2 controls
```

**How FIM works:**
```
1. Initialize: Create baseline database
2. Monitor: Regular integrity checks
3. Compare: Current vs baseline
4. Alert: Report detected changes
5. Update: Reconcile legitimate changes
```

### Tripwire Overview

**What is Tripwire?**
- Open-source FIM tool
- Cryptographic file verification
- Policy-based monitoring
- Detailed change reports
- Cross-platform support

**Key features:**
- Multiple hash algorithms
- Flexible policy language
- Encrypted databases
- Secure key management
- Email notifications
- Report generation

**Components:**
```
Policy file      - What to monitor
Configuration    - How to monitor
Database         - Baseline snapshot
Reports          - Change detection results
Keys             - Encryption (site-key, local-key)
```

### Installing Tripwire

**Ubuntu/Debian:**
```bash
sudo apt update
sudo apt install tripwire
```

**CentOS/Red Hat:**
```bash
sudo yum install tripwire
```

**During installation:**
```
- Creates site-key (protects policy/config)
- Creates local-key (protects database)
- Prompts for passphrases
- Initializes configuration
```

**Post-installation setup:**
```bash
# Generate keys (if not done during install)
sudo tripwire-setup-keyfiles

# Creates:
# /etc/tripwire/site.key
# /etc/tripwire/<hostname>-local.key
```

### Tripwire Configuration

**Key files:**
```
/etc/tripwire/twpol.txt          - Policy file (plain text)
/etc/tripwire/tw.pol              - Compiled policy
/etc/tripwire/twcfg.txt          - Configuration (plain text)
/etc/tripwire/tw.cfg              - Compiled configuration
/var/lib/tripwire/<hostname>.twd - Database
/var/lib/tripwire/report/        - Reports
```

**Edit policy file:**
```bash
sudo nano /etc/tripwire/twpol.txt
```

**Policy file structure:**
```
# Comments start with #

# Variables
@@section GLOBAL

# Rules
(
  rulename = "System Files",
  severity = 100
)
{
  /bin                    -> $(ReadOnly);
  /sbin                   -> $(ReadOnly);
  /usr/bin                -> $(ReadOnly);
  /etc                    -> $(Dynamic);
}
```

**Property masks:**
```
ReadOnly = +pinugsamc12-r
Dynamic  = +pinusgamCM-r
Growing  = +pinlusgamC-r

p - permissions
i - inode
n - number of links
u - user (owner)
g - group
s - size
a - access time
m - modification time
c - inode change time
1 - md5 hash
2 - sha256 hash
r - device
```

**Compile policy:**
```bash
sudo twadmin --create-polfile /etc/tripwire/twpol.txt
```

### Initialize Database

**Create baseline:**
```bash
sudo tripwire --init

# Enters local-key passphrase
# Creates database in /var/lib/tripwire/
```

**Database file:**
```
/var/lib/tripwire/<hostname>.twd
```

**View database:**
```bash
sudo twprint --print-dbfile
```

### Running Integrity Checks

**Manual check:**
```bash
sudo tripwire --check

# Interactive mode (slower, more detail)
sudo tripwire --check --interactive
```

**Check specific files:**
```bash
sudo tripwire --check --rule-name "System Files"
```

**Output:**
```
Parsing policy file: /etc/tripwire/tw.pol
Performing integrity check...

Rule Name: System Files (/bin)
Severity Level: 100

Modified:
"/bin/test_modified"

Added:
"/bin/new_file"

Removed:
"/bin/deleted_file"
```

**Generate report:**
```bash
# Latest report
ls -lt /var/lib/tripwire/report/ | head -5

# View report
sudo twprint --print-report -r /var/lib/tripwire/report/report-20260126.twr
```

### Updating Database

**After legitimate changes:**
```bash
# Update database interactively
sudo tripwire --update -r /var/lib/tripwire/report/latest.twr

# Opens editor with detected changes
# Select which changes to accept
# Save and exit
# Enters passphrase to update database
```

**Update specific files:**
```bash
sudo tripwire --update-policy /etc/tripwire/twpol.txt
```

**Automated update (accept all):**
```bash
sudo tripwire --update --accept-all -r /var/lib/tripwire/report/latest.twr
```

### Custom Monitoring Policy

**Example policy:**
```
(
  rulename = "Web Application",
  severity = 90
)
{
  /var/www/html           -> $(ReadOnly);
  /var/www/uploads        -> $(Dynamic);
}

(
  rulename = "Application Config",
  severity = 100
)
{
  /etc/nginx              -> $(ReadOnly);
  /etc/myapp              -> $(ReadOnly);
}

(
  rulename = "SSH Security",
  severity = 100
)
{
  /etc/ssh/sshd_config    -> $(ReadOnly);
  /root/.ssh              -> $(ReadOnly);
  /home/*/.ssh            -> $(ReadOnly) (recurse = 1);
}
```

**Exclude files:**
```
(
  rulename = "System Files",
  severity = 100
)
{
  /etc                    -> $(Dynamic);
  !/etc/mtab
  !/etc/resolv.conf
}
```

### Email Notifications

**Configure in twcfg.txt:**
```
MAILMETHOD = SMTP
SMTPHOST = localhost
SMTPPORT = 25
MAILPROGRAM = /usr/sbin/sendmail -oi -t
```

**Send report via email:**
```bash
sudo tripwire --check --email-report \
  --email-report-level 3 \
  --mailmethod SMTP
```

**Email report levels:**
```
0 - No email
1 - Only if violations
2 - Always send
3 - Detailed report
```

### Automation with Cron

**Daily integrity check:**
```bash
# Create script
sudo nano /etc/cron.daily/tripwire-check

#!/bin/bash
/usr/sbin/tripwire --check --email-report \
  --email-report-level 1 > /dev/null 2>&1

# Make executable
sudo chmod +x /etc/cron.daily/tripwire-check
```

**Crontab example:**
```bash
# Edit crontab
sudo crontab -e

# Run daily at 2 AM
0 2 * * * /usr/sbin/tripwire --check --email-report
```

**Weekly report:**
```bash
# Run every Sunday at 3 AM
0 3 * * 0 /usr/sbin/tripwire --check --email-report
```

### Responding to Changes

**Investigate detected changes:**
```bash
# View detailed report
sudo twprint --print-report -r /var/lib/tripwire/report/latest.twr

# Check file details
ls -la /path/to/changed/file
stat /path/to/changed/file

# Check who modified
sudo ausearch -f /path/to/changed/file
sudo grep "changed_file" /var/log/auth.log
```

**Determine if change is authorized:**
```
1. Was it a scheduled update?
2. Was it performed by authorized user?
3. Is there a change ticket?
4. Does it match expected changes?
```

**If authorized:**
```bash
# Update database
sudo tripwire --update -r /var/lib/tripwire/report/latest.twr
```

**If unauthorized:**
```bash
# Incident response:
1. Isolate affected system
2. Preserve evidence
3. Restore from known-good backup
4. Investigate breach
5. Update database after remediation
```

### Best Practices

**Policy configuration:**
- Monitor critical system files
- Monitor application files
- Monitor configuration files
- Exclude frequently changing files
- Use appropriate severity levels
- Regular policy reviews

**Operations:**
- Run checks regularly (daily minimum)
- Review reports promptly
- Update database after authorized changes
- Keep keys secure and backed up
- Test restore procedures
- Document baseline dates

**Security:**
- Store keys securely (offline backup)
- Protect database integrity
- Use strong passphrases
- Limit tripwire access
- Monitor tripwire logs
- Integrate with SIEM

### Troubleshooting

**Policy errors:**
```bash
# Test policy syntax
sudo twadmin --create-polfile --cfgfile /etc/tripwire/tw.cfg \
  /etc/tripwire/twpol.txt

# Check for errors in output
```

**Database initialization fails:**
```bash
# Check policy file
sudo twadmin --print-polfile

# Verify file paths exist
# Remove non-existent paths from policy
```

**False positives:**
```bash
# Use Dynamic or Growing properties
# Exclude frequently changing files
# Adjust monitoring rules
```

**Performance issues:**
```bash
# Reduce monitored files
# Use less frequent checks
# Exclude large directories
# Optimize policy rules
```
