## Introduction

SELinux and AppArmor provide mandatory access control (MAC) - an additional security layer beyond traditional Linux permissions. MAC enforces system-wide security policies that restrict what processes can access, regardless of user permissions. Understanding these tools is essential for securing production systems, especially on Red Hat/Ubuntu-based distributions.

## Key Concepts Summary

### Mandatory Access Control (MAC)

**Traditional DAC (Discretionary Access Control):**
```
- Owner controls access
- File permissions (rwx)
- Users can change permissions
- Root bypasses all restrictions
```

**MAC (Mandatory Access Control):**
```
- System-wide security policy
- Enforced by kernel
- Users cannot override
- Even root is restricted
- Process-based restrictions
```

**Benefits of MAC:**
- Limits damage from compromised processes
- Prevents privilege escalation
- Enforces least privilege at kernel level
- Protects against zero-day exploits
- Compliance requirements (PCI-DSS, HIPAA)

### SELinux vs AppArmor

**SELinux (Security-Enhanced Linux):**
```
Used by: Red Hat, CentOS, Fedora, Rocky Linux
Developed by: NSA
Approach: Label-based (security contexts)
Complexity: More complex, more powerful
Learning curve: Steeper
Policy language: Complex rule syntax
```

**AppArmor:**
```
Used by: Ubuntu, SUSE, Debian
Developed by: Immunix/Novell/Canonical
Approach: Path-based profiles
Complexity: Simpler, easier to learn
Learning curve: Gentler
Policy language: Human-readable profiles
```

### SELinux Overview

**How SELinux works:**
```
Every object has a security context:
- Files: user:role:type:level
- Processes: user:role:type:level
- Ports: type

Policy rules define what's allowed:
- Which types can access which types
- What operations are permitted
```

**SELinux modes:**
```
Enforcing   - Policy enforced, violations blocked
Permissive  - Policy not enforced, violations logged
Disabled    - SELinux turned off (not recommended)
```

**Check SELinux status:**
```bash
# Current status
sestatus
getenforce

# Detailed status
sestatus -v
```

**Example output:**
```bash
$ sestatus
SELinux status:                 enabled
Current mode:                   enforcing
Mode from config file:          enforcing
Policy version:                 33
Policy from config file:        targeted
```

**Change mode temporarily:**
```bash
# Set to permissive
sudo setenforce 0

# Set to enforcing
sudo setenforce 1

# Check current mode
getenforce
```

**Change mode permanently:**
```bash
# Edit /etc/selinux/config
SELINUX=enforcing    # or permissive or disabled
```

**Note:** Changing from disabled to enforcing requires reboot and filesystem relabeling.

### SELinux Contexts

**View contexts:**
```bash
# File contexts
ls -Z file.txt
ls -lZ /var/www/

# Process contexts
ps -eZ
ps -eZ | grep nginx

# User contexts
id -Z

# Port contexts
sudo semanage port -l | grep http
```

**Example context:**
```
system_u:object_r:httpd_sys_content_t:s0

system_u        - SELinux user
object_r        - SELinux role
httpd_sys_content_t - SELinux type (most important)
s0              - Security level
```

**Change file context:**
```bash
# Temporary (until relabel)
sudo chcon -t httpd_sys_content_t /var/www/html/index.html

# Permanent (survives relabel)
sudo semanage fcontext -a -t httpd_sys_content_t "/var/www/html(/.*)?"
sudo restorecon -Rv /var/www/html
```

**Restore default context:**
```bash
sudo restorecon -v /path/to/file
sudo restorecon -Rv /path/to/directory
```

### SELinux Booleans

**What are booleans?**
- Runtime switches for SELinux policies
- Enable/disable specific behaviors
- No policy recompilation needed

**List booleans:**
```bash
# All booleans
sudo getsebool -a

# Specific boolean
sudo getsebool httpd_can_network_connect

# Search for booleans
sudo getsebool -a | grep httpd
```

**Set boolean:**
```bash
# Temporary
sudo setsebool httpd_can_network_connect on

# Permanent
sudo setsebool -P httpd_can_network_connect on
```

**Common booleans:**
```bash
# Allow httpd to connect to network
httpd_can_network_connect

# Allow httpd to connect to database
httpd_can_network_connect_db

# Allow httpd to send mail
httpd_can_sendmail

# Allow ftpd full access
ftpd_full_access
```

### Troubleshooting SELinux

**Check for denials:**
```bash
# View audit log
sudo tail -f /var/log/audit/audit.log

# Filter for denials
sudo ausearch -m AVC -ts recent

# Use audit2why for explanations
sudo ausearch -m AVC -ts recent | audit2why
```

**Common issues and solutions:**

**1. Permission denied errors:**
```bash
# Check for AVC denials
sudo ausearch -m AVC -ts recent

# Generate allow rules (for testing)
sudo ausearch -m AVC -ts recent | audit2allow -M mymodule
sudo semodule -i mymodule.pp

# Better: fix the context
sudo restorecon -Rv /path
```

**2. Web server can't access files:**
```bash
# Set correct context
sudo semanage fcontext -a -t httpd_sys_content_t "/srv/www(/.*)?"
sudo restorecon -Rv /srv/www

# Or temporarily to test
sudo setenforce 0
# Test if it works
sudo setenforce 1
```

**3. Service can't bind to port:**
```bash
# Check allowed ports
sudo semanage port -l | grep http

# Add port to policy
sudo semanage port -a -t http_port_t -p tcp 8080
```

### AppArmor Overview

**How AppArmor works:**
```
- Path-based mandatory access control
- Profiles define what programs can access
- Two modes: enforce and complain
- Simpler than SELinux for most users
```

**Check AppArmor status:**
```bash
# Status
sudo apparmor_status
sudo aa-status

# Is it enabled?
systemctl status apparmor
```

**AppArmor modes:**
```
Enforce mode     - Profile enforced, violations blocked
Complain mode    - Profile not enforced, violations logged
Unconfined       - No profile loaded
```

**View loaded profiles:**
```bash
sudo aa-status

# Example output:
apparmor module is loaded.
16 profiles are loaded.
14 profiles are in enforce mode.
2 profiles are in complain mode.
```

### AppArmor Profiles

**Profile locations:**
```
/etc/apparmor.d/          - Profiles
/etc/apparmor.d/disable/  - Disabled profiles
```

**List profiles:**
```bash
sudo aa-status
ls /etc/apparmor.d/
```

**Profile modes:**
```bash
# Set to complain mode (learning)
sudo aa-complain /etc/apparmor.d/usr.sbin.nginx

# Set to enforce mode
sudo aa-enforce /etc/apparmor.d/usr.sbin.nginx

# Disable profile
sudo aa-disable /etc/apparmor.d/usr.sbin.nginx

# Enable profile
sudo aa-enforce /etc/apparmor.d/usr.sbin.nginx
```

**Basic profile structure:**
```
#include <tunables/global>

/usr/sbin/program {
  #include <abstractions/base>
  
  # Capabilities
  capability net_bind_service,
  
  # File access
  /etc/program/** r,
  /var/log/program/* w,
  /var/lib/program/** rw,
  
  # Network
  network tcp,
  network udp,
}
```

### Working with AppArmor

**Reload profiles:**
```bash
sudo systemctl reload apparmor
sudo apparmor_parser -r /etc/apparmor.d/profile
```

**View profile status:**
```bash
sudo aa-status | grep profile_name
```

**Check logs:**
```bash
# AppArmor denials
sudo dmesg | grep -i apparmor
sudo journalctl -xe | grep -i apparmor

# In syslog
sudo grep -i apparmor /var/log/syslog
```

**Generate profile:**
```bash
# Auto-generate profile
sudo aa-genprof /path/to/program

# Update existing profile
sudo aa-logprof
```

### SELinux vs AppArmor: When to Use

**Use SELinux when:**
- Using Red Hat/CentOS/Fedora/Rocky Linux
- Need fine-grained, label-based control
- Compliance requires SELinux
- Managing complex server infrastructure
- Have time to learn complex policies

**Use AppArmor when:**
- Using Ubuntu/Debian/SUSE
- Want simpler, path-based control
- Need quick profile creation
- Prefer learning mode for policy development
- Want easier troubleshooting

**Both provide:**
- Mandatory access control
- Kernel-level enforcement
- Protection against exploits
- Compliance support
- Active communities

### Practical Examples

**SELinux: Allow nginx to connect to database:**
```bash
# Check if boolean exists
sudo getsebool -a | grep httpd.*connect

# Enable permanently
sudo setsebool -P httpd_can_network_connect_db on

# Verify
sudo getsebool httpd_can_network_connect_db
```

**SELinux: Custom document root:**
```bash
# Set context for /srv/www
sudo semanage fcontext -a -t httpd_sys_content_t "/srv/www(/.*)?"
sudo restorecon -Rv /srv/www

# Verify
ls -lZ /srv/www
```

**AppArmor: Put nginx in complain mode:**
```bash
# Set to learning/complain mode
sudo aa-complain /etc/apparmor.d/usr.sbin.nginx

# Test application
# ...

# Check what was logged
sudo aa-logprof

# Set to enforce mode
sudo aa-enforce /etc/apparmor.d/usr.sbin.nginx
```

**AppArmor: Disable profile temporarily:**
```bash
# Disable
sudo aa-disable /etc/apparmor.d/usr.bin.program

# Test
# ...

# Re-enable
sudo aa-enforce /etc/apparmor.d/usr.bin.program
```
