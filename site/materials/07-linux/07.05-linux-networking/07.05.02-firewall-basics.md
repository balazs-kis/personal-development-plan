## Introduction

Firewalls are your first line of defense against network attacks. Linux provides powerful packet filtering through iptables (traditional) and nftables (modern replacement). Understanding how to configure firewall rules is essential for securing servers, especially those exposed to the internet.

This lesson covers both iptables (still widely used) and nftables (the future), giving you the skills to work with any Linux system.

## Key Concepts Summary

### Firewall Fundamentals

**What is a firewall?**
- Security system monitoring and controlling network traffic
- Uses predefined rules to allow or block packets
- Operates at network layer (Layer 3) and transport layer (Layer 4)
- Can filter based on IP, port, protocol, state

**Packet filtering:**
```
Incoming packet → Firewall rules → Accept/Drop/Reject
```

**Firewall decisions:**
```
ACCEPT  - Allow packet through
DROP    - Silently discard packet
REJECT  - Discard and send error back
```

### iptables Overview

**What is iptables?**
- Traditional Linux firewall tool
- Uses netfilter framework in kernel
- Organizes rules in tables, chains, and rules
- Still widely used in production

**Tables:**
```
filter  - Default table, packet filtering
nat     - Network address translation
mangle  - Packet alteration
raw     - Connection tracking exceptions
```

**Chains (in filter table):**
```
INPUT    - Incoming packets to local system
OUTPUT   - Outgoing packets from local system
FORWARD  - Packets routed through system
```

**Rule structure:**
```bash
iptables -A CHAIN -p PROTOCOL --dport PORT -j ACTION
```

### Basic iptables Commands

**View current rules:**
```bash
sudo iptables -L
sudo iptables -L -v        # Verbose (with packet counts)
sudo iptables -L -n        # Numeric (no DNS resolution)
sudo iptables -L -v -n     # Verbose and numeric
sudo iptables -L INPUT     # Specific chain
```

**List with line numbers:**
```bash
sudo iptables -L --line-numbers
```

**View nat table:**
```bash
sudo iptables -t nat -L
```

**Flush all rules (dangerous!):**
```bash
sudo iptables -F
```

### Creating iptables Rules

**Allow SSH (port 22):**
```bash
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

**Allow HTTP (port 80):**
```bash
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
```

**Allow HTTPS (port 443):**
```bash
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
```

**Allow specific IP:**
```bash
sudo iptables -A INPUT -s 192.168.1.100 -j ACCEPT
```

**Block specific IP:**
```bash
sudo iptables -A INPUT -s 203.0.113.0 -j DROP
```

**Allow established connections:**
```bash
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
```

**Allow loopback:**
```bash
sudo iptables -A INPUT -i lo -j ACCEPT
```

### Rule Options

**Protocol:**
```bash
-p tcp      # TCP protocol
-p udp      # UDP protocol
-p icmp     # ICMP protocol
```

**Ports:**
```bash
--dport 80          # Destination port
--sport 1024:65535  # Source port range
-m multiport --dports 80,443  # Multiple ports
```

**Source/Destination:**
```bash
-s 192.168.1.0/24   # Source IP/network
-d 10.0.0.5         # Destination IP
```

**Interface:**
```bash
-i eth0     # Input interface
-o eth1     # Output interface
```

**State:**
```bash
-m state --state NEW,ESTABLISHED
-m conntrack --ctstate NEW,ESTABLISHED,RELATED
```

### Deleting Rules

**Delete by specification:**
```bash
sudo iptables -D INPUT -p tcp --dport 80 -j ACCEPT
```

**Delete by line number:**
```bash
# List with numbers
sudo iptables -L INPUT --line-numbers

# Delete line 3
sudo iptables -D INPUT 3
```

**Insert rule at position:**
```bash
sudo iptables -I INPUT 1 -p tcp --dport 22 -j ACCEPT
```

### Default Policies

**View default policy:**
```bash
sudo iptables -L | head -n 3
```

**Set default policy:**
```bash
sudo iptables -P INPUT DROP      # Drop all incoming by default
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT   # Allow all outgoing
```

**WARNING:** Setting INPUT to DROP without allowing SSH can lock you out!

### Complete iptables Example

**Secure web server firewall:**
```bash
#!/bin/bash
# Flush existing rules
sudo iptables -F
sudo iptables -X

# Default policies
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# Allow loopback
sudo iptables -A INPUT -i lo -j ACCEPT

# Allow established connections
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# Allow SSH
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Allow HTTP and HTTPS
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Allow ping
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT

# Log dropped packets
sudo iptables -A INPUT -j LOG --log-prefix "iptables-dropped: "

# List rules
sudo iptables -L -v -n
```

### Persisting iptables Rules

**Ubuntu/Debian:**
```bash
# Install iptables-persistent
sudo apt install iptables-persistent

# Save rules
sudo netfilter-persistent save
sudo netfilter-persistent reload

# Or manually
sudo iptables-save > /etc/iptables/rules.v4
sudo iptables-restore < /etc/iptables/rules.v4
```

**Red Hat/CentOS:**
```bash
# Save rules
sudo service iptables save

# Or
sudo iptables-save > /etc/sysconfig/iptables

# Restore
sudo iptables-restore < /etc/sysconfig/iptables
```

**Systemd service:**
```bash
# Enable iptables service
sudo systemctl enable iptables
sudo systemctl start iptables
```

### nftables Overview

**What is nftables?**
- Modern replacement for iptables
- Single framework for IPv4, IPv6, ARP, bridge
- More consistent syntax
- Better performance (built-in lookup tables)
- Transactional rule updates

**Advantages over iptables:**
- Unified tool for all protocols
- Faster rule processing
- More flexible rule syntax
- Native set and map support
- Better scripting capabilities

**Basic structure:**
```
Tables
  └─ Chains
      └─ Rules
```

### nftables Basics

**View current rules:**
```bash
sudo nft list ruleset
```

**List tables:**
```bash
sudo nft list tables
```

**List chains in table:**
```bash
sudo nft list chains inet filter
```

**Flush all rules:**
```bash
sudo nft flush ruleset
```

### Creating nftables Rules

**Create table:**
```bash
sudo nft add table inet filter
```

**Create chain:**
```bash
sudo nft add chain inet filter input { type filter hook input priority 0 \; policy drop \; }
```

**Add rules:**
```bash
# Allow loopback
sudo nft add rule inet filter input iif lo accept

# Allow established/related
sudo nft add rule inet filter input ct state established,related accept

# Allow SSH
sudo nft add rule inet filter input tcp dport 22 accept

# Allow HTTP/HTTPS
sudo nft add rule inet filter input tcp dport { 80, 443 } accept

# Allow ping
sudo nft add rule inet filter input icmp type echo-request accept
```

### nftables Configuration File

**File location: /etc/nftables.conf**

**Example configuration:**
```bash
#!/usr/sbin/nft -f

flush ruleset

table inet filter {
    chain input {
        type filter hook input priority 0; policy drop;

        # Allow loopback
        iif lo accept

        # Allow established/related
        ct state established,related accept

        # Allow SSH
        tcp dport 22 accept

        # Allow HTTP/HTTPS
        tcp dport { 80, 443 } accept

        # Allow ping
        icmp type echo-request accept
        icmpv6 type { nd-neighbor-solicit, nd-neighbor-advert, nd-router-advert } accept

        # Count dropped packets
        counter drop
    }

    chain forward {
        type filter hook forward priority 0; policy drop;
    }

    chain output {
        type filter hook output priority 0; policy accept;
    }
}
```

**Apply configuration:**
```bash
sudo nft -f /etc/nftables.conf
```

**Enable nftables service:**
```bash
sudo systemctl enable nftables
sudo systemctl start nftables
```

### Firewall Management Tools

**firewalld (high-level):**
```bash
# Check status
sudo firewall-cmd --state

# List zones
sudo firewall-cmd --get-zones

# List services in zone
sudo firewall-cmd --list-all

# Add service
sudo firewall-cmd --add-service=http --permanent
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --reload

# Add port
sudo firewall-cmd --add-port=8080/tcp --permanent
sudo firewall-cmd --reload

# Remove service
sudo firewall-cmd --remove-service=http --permanent
sudo firewall-cmd --reload
```

**ufw (Ubuntu):**
```bash
# Enable firewall
sudo ufw enable

# Allow service
sudo ufw allow ssh
sudo ufw allow http
sudo ufw allow https

# Allow specific port
sudo ufw allow 8080/tcp

# Allow from IP
sudo ufw allow from 192.168.1.100

# Deny
sudo ufw deny 23

# Status
sudo ufw status verbose

# Delete rule
sudo ufw delete allow 8080/tcp
```

### Troubleshooting

**Check if firewall is blocking:**
```bash
# Test connection
telnet server_ip 80
nc -zv server_ip 80

# Check firewall rules
sudo iptables -L -v -n
sudo nft list ruleset

# Temporarily disable firewall (testing only!)
sudo iptables -P INPUT ACCEPT
sudo iptables -F
```

**View dropped packets:**
```bash
# With iptables logging
sudo tail -f /var/log/syslog | grep iptables
sudo dmesg | grep iptables

# Count dropped packets
sudo iptables -L -v -n | grep DROP
```

**Common issues:**
- Locked out after setting default DROP policy
- Rules in wrong order (specific before general)
- Forgot to allow established connections
- Forgot to save rules (lost after reboot)
- Rules not persisted correctly
