# Lesson 3: Managing Services with systemctl

## Learning Objectives

By the end of this lesson, you will be able to:
- Start, stop, and restart services with systemctl
- Enable and disable services for automatic startup
- Check service status and troubleshoot issues
- Reload service configuration without restarting
- Mask and unmask services
- Use systemctl to manage system state

---

## Introduction

The `systemctl` command is your primary tool for interacting with systemd. It controls services, checks their status, enables them at boot, and manages system state. Mastering systemctl is essential for day-to-day system administration, deploying applications, and troubleshooting service issues.

## Key Concepts Summary

### Basic Service Control

**Start a service:**
```bash
sudo systemctl start nginx.service
sudo systemctl start nginx          # .service is optional

# Multiple services
sudo systemctl start nginx postgresql redis
```

**Stop a service:**
```bash
sudo systemctl stop nginx.service
sudo systemctl stop nginx postgresql redis
```

**Restart a service:**
```bash
# Stop then start
sudo systemctl restart nginx.service

# Use when: configuration changes, major updates
```

**Reload configuration:**
```bash
# Reload without stopping (if service supports it)
sudo systemctl reload nginx.service

# Use when: minor config changes, no downtime needed
```

**Reload or restart (try reload first):**
```bash
sudo systemctl reload-or-restart nginx.service
```

### Checking Service Status

**View detailed status:**
```bash
systemctl status nginx.service

# Example output:
● nginx.service - A high performance web server
   Loaded: loaded (/usr/lib/systemd/system/nginx.service; enabled)
   Active: active (running) since Mon 2026-01-26 10:00:00 UTC; 2h ago
  Process: 1234 ExecStart=/usr/sbin/nginx (code=exited, status=0/SUCCESS)
 Main PID: 1235 (nginx)
   CGroup: /system.slice/nginx.service
           ├─1235 nginx: master process
           └─1236 nginx: worker process
```

**Status indicators:**
```bash
● Green - Active (running)
● Red   - Failed or inactive
● - Service is stopped or doesn't exist
```

**Quick status checks:**
```bash
# Is service active?
systemctl is-active nginx
# Output: active or inactive

# Is service enabled?
systemctl is-enabled nginx
# Output: enabled, disabled, or masked

# Did service fail?
systemctl is-failed nginx
# Output: failed or active
```

### Enable and Disable Services

**Enable at boot (persistent):**
```bash
sudo systemctl enable nginx.service

# What it does:
# Creates symlink in /etc/systemd/system/multi-user.target.wants/
```

**Disable at boot:**
```bash
sudo systemctl disable nginx.service

# What it does:
# Removes symlink from target.wants directory
```

**Enable and start immediately:**
```bash
sudo systemctl enable --now nginx.service

# Equivalent to:
sudo systemctl enable nginx.service
sudo systemctl start nginx.service
```

**Disable and stop immediately:**
```bash
sudo systemctl disable --now nginx.service
```

**Check if enabled:**
```bash
systemctl is-enabled nginx.service
```

### Masking Services

**What is masking?**
- Completely prevents service from starting
- Stronger than disable
- Links service to /dev/null
- Prevents accidental or automatic start

**Mask a service:**
```bash
sudo systemctl mask nginx.service

# What it creates:
# Symlink: /etc/systemd/system/nginx.service -> /dev/null
```

**Unmask a service:**
```bash
sudo systemctl unmask nginx.service
```

**Use cases for masking:**
- Prevent conflicting services from starting
- Disable services that keep auto-starting
- Security hardening (disable unnecessary services)

### Listing Services

**List all loaded units:**
```bash
systemctl list-units
```

**List all services:**
```bash
systemctl list-units --type=service

# With state filter
systemctl list-units --type=service --state=running
systemctl list-units --type=service --state=failed
```

**List all installed unit files:**
```bash
systemctl list-unit-files
systemctl list-unit-files --type=service
```

**List failed units:**
```bash
systemctl --failed
```

### Service Dependencies

**Show what a service requires:**
```bash
systemctl list-dependencies nginx.service
```

**Show what requires a service:**
```bash
systemctl list-dependencies --reverse nginx.service
```

**Show dependency tree:**
```bash
systemctl list-dependencies nginx.service --all
```

### System State Management

**Reboot system:**
```bash
sudo systemctl reboot
```

**Shutdown system:**
```bash
sudo systemctl poweroff
```

**Suspend system:**
```bash
sudo systemctl suspend
```

**Hibernate:**
```bash
sudo systemctl hibernate
```

**Rescue mode (single user):**
```bash
sudo systemctl rescue
```

**Emergency mode:**
```bash
sudo systemctl emergency
```

### Advanced Commands

**Kill all processes of a service:**
```bash
sudo systemctl kill nginx.service

# Specific signal
sudo systemctl kill -s SIGKILL nginx.service
```

**View service properties:**
```bash
systemctl show nginx.service
systemctl show nginx.service -p MainPID
systemctl show nginx.service -p FragmentPath
```

**Reset failed state:**
```bash
sudo systemctl reset-failed
sudo systemctl reset-failed nginx.service
```

**Daemon reload (after editing unit files):**
```bash
sudo systemctl daemon-reload
```

### Practical Workflows

**Deploy new service:**
```bash
# 1. Install application
sudo cp myapp /usr/local/bin/

# 2. Create service file
sudo systemctl edit --full --force myapp.service

# 3. Reload systemd
sudo systemctl daemon-reload

# 4. Enable and start
sudo systemctl enable --now myapp.service

# 5. Check status
systemctl status myapp.service
```

**Troubleshoot failing service:**
```bash
# 1. Check status
systemctl status myapp.service

# 2. View recent logs
journalctl -u myapp.service -n 50

# 3. View logs since last boot
journalctl -u myapp.service -b

# 4. Check configuration
systemctl cat myapp.service

# 5. Verify dependencies
systemctl list-dependencies myapp.service

# 6. Try starting manually
sudo systemctl start myapp.service

# 7. Check for errors
systemctl status myapp.service
journalctl -xe
```

**Update service configuration:**
```bash
# 1. Edit service (creates override file)
sudo systemctl edit nginx.service

# 2. Reload systemd
sudo systemctl daemon-reload

# 3. Restart service
sudo systemctl restart nginx.service

# 4. Verify
systemctl status nginx.service
```

**Maintenance window:**
```bash
# Stop services
sudo systemctl stop nginx postgresql redis

# Perform maintenance
# ...

# Start services
sudo systemctl start redis postgresql nginx

# Verify all running
systemctl is-active nginx postgresql redis
```

### Common Patterns

**Web server management:**
```bash
# Start web server
sudo systemctl start nginx

# Enable at boot
sudo systemctl enable nginx

# Reload config after changes
sudo systemctl reload nginx

# Check if running
systemctl is-active nginx
```

**Database service:**
```bash
# Start database
sudo systemctl start postgresql

# Enable at boot
sudo systemctl enable postgresql

# Restart after config change
sudo systemctl restart postgresql

# Check status
systemctl status postgresql
```

**Application service:**
```bash
# Deploy app
sudo systemctl enable --now myapp

# Update app
sudo systemctl restart myapp

# View logs
journalctl -u myapp -f

# Stop app
sudo systemctl stop myapp
```
