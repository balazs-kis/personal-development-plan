## Introduction

Every running program on Linux is a process. Understanding process states and lifecycle is fundamental to system administration and troubleshooting. Processes transition through different states during their execution—running, sleeping, stopped, or zombie. Knowing these states helps you diagnose performance issues, identify stuck processes, and understand system behavior.

This knowledge is essential when troubleshooting hung applications, investigating high CPU usage, or understanding why a process won't terminate.

## Key Concepts Summary

### What is a Process?

**Definition:**
- A process is a running instance of a program
- Has a unique Process ID (PID)
- Has its own memory space
- Owns system resources (CPU time, memory, file handles)
- Has a state indicating its current activity

**Process attributes:**
```bash
PID     - Process ID (unique identifier)
PPID    - Parent Process ID
UID     - User ID (owner)
GID     - Group ID
STATE   - Current state
NICE    - Priority value
CPU%    - CPU usage
MEM%    - Memory usage
```

### The Five Process States

**1. Running or Runnable (R)**
- **Description:** Process is either executing on CPU or waiting in run queue
- **Indicators:** Actively using CPU or ready to use CPU
- **Example scenarios:**
  - CPU-intensive calculations
  - Active web server handling requests
  - Program in tight loop

```bash
# View running processes
ps aux | awk '$8 == "R"'
```

**2. Interruptible Sleep (S)**
- **Description:** Waiting for an event or resource (can be interrupted by signals)
- **Common reasons:**
  - Waiting for I/O operations (disk, network)
  - Waiting for user input
  - Sleeping (via sleep() system call)
- **Most common state** - majority of processes are in this state

```bash
# View sleeping processes
ps aux | awk '$8 == "S"'
```

**3. Uninterruptible Sleep (D)**
- **Description:** Waiting for hardware/I/O (cannot be interrupted)
- **Common reasons:**
  - Direct disk I/O operations
  - Hardware waiting states
  - Critical kernel operations
- **Troubleshooting:** Many processes in D state indicate I/O bottleneck

```bash
# View processes in uninterruptible sleep
ps aux | awk '$8 == "D"'
```

**4. Stopped (T)**
- **Description:** Process execution is paused/suspended
- **Common reasons:**
  - SIGSTOP signal received
  - Job control (Ctrl+Z in terminal)
  - Debugger breakpoint
- **Can be resumed:** SIGCONT signal

```bash
# View stopped processes
ps aux | awk '$8 == "T"'

# Example: stop and continue a process
sleep 100 &          # Start background process
kill -STOP $!        # Stop it
kill -CONT $!        # Continue it
```

**5. Zombie (Z)**
- **Description:** Process has terminated but parent hasn't read exit status
- **Characteristics:**
  - No resources consumed (except process table entry)
  - Cannot be killed (already dead)
  - Waiting for parent to call wait()
- **Problem indicator:** Many zombies suggest parent process issue

```bash
# View zombie processes
ps aux | awk '$8 == "Z"'

# Alternative
ps aux | grep 'Z'
```

### Process State Codes in ps Output

**STAT column codes:**
```
R    - Running or runnable
S    - Interruptible sleep
D    - Uninterruptible sleep
T    - Stopped
Z    - Zombie

Additional modifiers:
<    - High priority (not nice)
N    - Low priority (nice)
L    - Has pages locked in memory
s    - Session leader
l    - Multi-threaded
+    - Foreground process group
```

**Example:**
```bash
$ ps aux
USER   PID %CPU %MEM    VSZ   RSS TTY  STAT START   TIME COMMAND
alice 1234  0.0  0.1 123456  8912 ?    Ss   10:00   0:01 nginx
bob   5678  2.5  1.2 892456 99123 ?    Sl   10:15   1:23 node app.js
root  9012  0.0  0.0      0     0 ?    Z    10:30   0:00 [defunct]
```

### Process Lifecycle

**1. Process Creation (fork)**
```
Parent Process
     |
     | fork() - Creates copy of parent
     |
     v
Child Process (new PID)
     |
     | exec() - Replaces with new program
     |
     v
New Program Running
```

**2. Running Phase**
- Process executes code
- Transitions between Running (R) and Sleep (S) states
- May be stopped (T) by signals or debugging

**3. Termination**
```
Process completes
     |
     | exit() - Terminates process
     |
     v
Zombie State (Z) - Waiting for parent
     |
     | Parent calls wait() - Reads exit status
     |
     v
Process removed from process table
```

### Parent-Child Relationships

**Process hierarchy:**
```bash
# View process tree
pstree
pstree -p          # With PIDs
ps -ejH            # Hierarchical view
ps axjf            # ASCII art tree
```

**init/systemd (PID 1):**
- First process started by kernel
- Parent of all orphaned processes
- Adopts zombie processes when parent dies

**Example hierarchy:**
```
systemd(1)───sshd(1234)───sshd(1235)───bash(1236)───python(1237)
```

### Zombie Processes

**What causes zombies?**
1. Child process exits (calls exit())
2. Becomes zombie - releases resources but keeps process table entry
3. Waits for parent to call wait() and read exit status
4. If parent doesn't call wait(), remains zombie

**Finding zombie parent:**
```bash
# Find zombies
ps aux | grep Z

# Find parent of zombie
ps -o ppid= -p <zombie_PID>

# View parent details
ps -fp <parent_PID>
```

**Cleaning up zombies:**
```bash
# Option 1: Wait for parent to exit (zombies adopted by init/systemd)
kill <parent_PID>

# Option 2: Fix parent process to properly handle child termination

# Option 3: Restart parent service if it's misbehaving
systemctl restart service_name
```

**Note:** You cannot kill a zombie (it's already dead). You must deal with the parent.

### Monitoring Process States

**Using ps:**
```bash
# All processes with state
ps aux
ps -eo pid,stat,cmd

# Count processes by state
ps aux | awk '{print $8}' | sort | uniq -c

# Find specific state
ps aux | awk '$8 ~ /^D/' # Uninterruptible sleep
ps aux | awk '$8 ~ /^Z/' # Zombies
```

**Using top:**
```bash
top

# In top display:
Tasks:  245 total,   2 running, 243 sleeping,   0 stopped,   0 zombie
```

**Using /proc filesystem:**
```bash
# Process state for PID 1234
cat /proc/1234/status | grep State

# Example output:
State:	S (sleeping)
```

### Practical Examples

**Identify I/O bottleneck:**
```bash
#!/bin/bash
# Count processes in uninterruptible sleep
d_count=$(ps aux | awk '$8 ~ /^D/' | wc -l)

if [ $d_count -gt 10 ]; then
    echo "WARNING: $d_count processes in uninterruptible sleep"
    echo "Possible I/O bottleneck"
    ps aux | awk '$8 ~ /^D/'
fi
```

**Monitor for zombies:**
```bash
#!/bin/bash
# Find and report zombie processes with parents

zombies=$(ps aux | awk '$8 ~ /^Z/' | awk '{print $2}')

if [ -n "$zombies" ]; then
    echo "Found zombie processes:"
    for zpid in $zombies; do
        ppid=$(ps -o ppid= -p $zpid)
        parent_cmd=$(ps -o cmd= -p $ppid)
        echo "  Zombie PID: $zpid, Parent PID: $ppid ($parent_cmd)"
    done
fi
```

**Process state distribution:**
```bash
#!/bin/bash
# Show distribution of process states

echo "Process State Distribution:"
ps aux | awk 'NR>1 {print $8}' | sed 's/[^A-Z]//g' | sort | uniq -c | sort -rn
```

### Signals and State Transitions

**Common signals affecting state:**
```bash
SIGSTOP (19)  - Stop process (T state)
SIGCONT (18)  - Continue stopped process (back to R/S)
SIGTERM (15)  - Request termination (graceful)
SIGKILL (9)   - Force termination (immediate)
SIGINT (2)    - Interrupt (Ctrl+C)
```

**State transitions:**
```
Created → Running (R)
Running → Sleeping (S) [waiting for resource]
Running → Stopped (T) [SIGSTOP received]
Stopped → Running (R) [SIGCONT received]
Running/Sleeping → Zombie (Z) [process exits]
Zombie → Removed [parent calls wait()]
```
