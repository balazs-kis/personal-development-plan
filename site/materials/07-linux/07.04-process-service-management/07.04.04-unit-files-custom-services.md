# Lesson 4: systemd Unit Files and Custom Services

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand systemd unit file syntax and sections
- Create custom service unit files for your applications
- Configure service behavior (restart, timeouts, environment)
- Use systemd timers as cron alternatives
- Override existing service configurations
- Write robust service files for production applications

---

## Introduction

Creating custom systemd service files allows you to manage your applications like any other system service. You can configure automatic restarts, set resource limits, define dependencies, and integrate your applications into the system's lifecycle. This lesson teaches you to write production-ready service files.

## Key Concepts Summary

### Service Unit File Structure

**Three main sections:**
```ini
[Unit]
# Metadata and dependencies

[Service]
# Service-specific configuration

[Install]
# Installation instructions
```

### [Unit] Section

**Common directives:**
```ini
[Unit]
Description=My Application Server
Documentation=https://example.com/docs
After=network.target
Requires=postgresql.service
Wants=redis.service
Before=nginx.service
Conflicts=other-app.service
```

**Directives explained:**
- `Description` - Human-readable name
- `Documentation` - URL to documentation
- `After` - Start after these units
- `Before` - Start before these units
- `Requires` - Hard dependency (fails if required fails)
- `Wants` - Soft dependency (preferred)
- `Conflicts` - Cannot run with these units

### [Service] Section

**Service type:**
```ini
[Service]
Type=simple    # Default: ExecStart is main process
Type=forking   # Process forks, parent exits
Type=oneshot   # Runs once and exits
Type=notify    # Sends notification when ready
Type=dbus      # Acquires D-Bus name when ready
Type=idle      # Delays execution
```

**Execution directives:**
```ini
ExecStart=/usr/bin/myapp --config /etc/myapp/config.yml
ExecStartPre=/usr/bin/setup.sh
ExecStartPost=/usr/bin/notify.sh
ExecReload=/bin/kill -HUP $MAINPID
ExecStop=/usr/bin/myapp-stop
ExecStopPost=/usr/bin/cleanup.sh
```

**Restart behavior:**
```ini
Restart=no              # Never restart
Restart=on-failure      # Restart if exits non-zero
Restart=on-abnormal     # Restart if killed by signal
Restart=on-abort        # Restart if core dump
Restart=on-watchdog     # Restart on watchdog timeout
Restart=always          # Always restart

RestartSec=5s          # Wait 5 seconds before restart
StartLimitBurst=5      # Max 5 restarts
StartLimitIntervalSec=10min  # In 10 minute window
```

**User and permissions:**
```ini
User=myapp
Group=myapp
WorkingDirectory=/opt/myapp
```

**Environment:**
```ini
Environment="NODE_ENV=production"
Environment="PORT=3000"
EnvironmentFile=/etc/myapp/environment
```

**Security options:**
```ini
PrivateTmp=yes
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/myapp
```

### [Install] Section

**Installation directives:**
```ini
[Install]
WantedBy=multi-user.target    # Enable for this target
RequiredBy=some-other.service  # Hard requirement
Also=myapp-worker.service      # Enable together
```

### Complete Service Example

**Simple web application:**
```ini
[Unit]
Description=My Node.js Application
Documentation=https://docs.example.com
After=network.target

[Service]
Type=simple
User=nodeapp
Group=nodeapp
WorkingDirectory=/opt/myapp
Environment="NODE_ENV=production"
Environment="PORT=3000"
ExecStart=/usr/bin/node /opt/myapp/server.js
Restart=on-failure
RestartSec=10s
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

**Python application with virtual environment:**
```ini
[Unit]
Description=My Python FastAPI Application
After=network.target

[Service]
Type=simple
User=pythonapp
Group=pythonapp
WorkingDirectory=/opt/myapp
Environment="PATH=/opt/myapp/venv/bin"
ExecStart=/opt/myapp/venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5s

[Install]
WantedBy=multi-user.target
```

### Creating a Custom Service

**Step-by-step process:**

**1. Create service file:**
```bash
sudo nano /etc/systemd/system/myapp.service
```

**2. Write service configuration:**
```ini
[Unit]
Description=My Custom Application
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/myapp
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

**3. Reload systemd:**
```bash
sudo systemctl daemon-reload
```

**4. Enable and start:**
```bash
sudo systemctl enable --now myapp.service
```

**5. Check status:**
```bash
systemctl status myapp.service
```

### Overriding Service Configuration

**Method 1: Edit command (recommended):**
```bash
sudo systemctl edit nginx.service
```

Creates: `/etc/systemd/system/nginx.service.d/override.conf`

**Override example:**
```ini
[Service]
Environment="DEBUG=true"
Restart=always
```

**Method 2: Full override:**
```bash
sudo systemctl edit --full nginx.service
```

Copies entire file to `/etc/systemd/system/nginx.service`

**View overrides:**
```bash
systemctl cat nginx.service
```

**Remove overrides:**
```bash
sudo rm -rf /etc/systemd/system/nginx.service.d/
sudo systemctl daemon-reload
```

### systemd Timers

**Timer as cron alternative:**

**1. Create service file (mybackup.service):**
```ini
[Unit]
Description=Backup Database

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
User=backup
```

**2. Create timer file (mybackup.timer):**
```ini
[Unit]
Description=Run backup daily
Requires=mybackup.service

[Timer]
OnCalendar=daily
OnCalendar=*-*-* 02:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

**3. Enable and start timer:**
```bash
sudo systemctl enable --now mybackup.timer
```

**4. Check timer status:**
```bash
systemctl list-timers
systemctl status mybackup.timer
```

**Timer directives:**
```ini
OnBootSec=15min        # 15 min after boot
OnUnitActiveSec=1h     # 1 hour after last activation
OnCalendar=daily       # Every day at midnight
OnCalendar=weekly      # Every Monday at midnight
OnCalendar=*-*-* 02:00:00  # Daily at 2 AM
OnCalendar=Mon *-*-* 09:00:00  # Every Monday at 9 AM
Persistent=true        # Catch up missed runs
RandomizedDelaySec=10min  # Random delay
```

### Practical Examples

**Web server:**
```ini
[Unit]
Description=Custom Web Server
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/var/www/myapp
ExecStart=/usr/bin/gunicorn -w 4 -b 0.0.0.0:8000 app:app
Restart=always
RestartSec=3s
StandardOutput=journal
StandardError=journal

# Security
PrivateTmp=yes
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/www/myapp/uploads

[Install]
WantedBy=multi-user.target
```

**Background worker:**
```ini
[Unit]
Description=Job Queue Worker
After=network.target redis.service
Requires=redis.service

[Service]
Type=simple
User=worker
Group=worker
WorkingDirectory=/opt/worker
Environment="REDIS_URL=redis://localhost:6379"
ExecStart=/opt/worker/venv/bin/celery -A tasks worker --loglevel=info
Restart=always
RestartSec=10s

[Install]
WantedBy=multi-user.target
```

**Monitoring script:**
```ini
[Unit]
Description=System Monitor
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/monitor.sh
Restart=always
RestartSec=60s

[Install]
WantedBy=multi-user.target
```

**Database backup timer:**

**Service (db-backup.service):**
```ini
[Unit]
Description=Database Backup

[Service]
Type=oneshot
User=postgres
ExecStart=/usr/local/bin/backup-database.sh
```

**Timer (db-backup.timer):**
```ini
[Unit]
Description=Database Backup Timer

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

### Testing and Debugging

**Test service file syntax:**
```bash
sudo systemd-analyze verify myapp.service
```

**Check service logs:**
```bash
journalctl -u myapp.service
journalctl -u myapp.service -f  # Follow
journalctl -u myapp.service -n 50  # Last 50 lines
```

**Debug service start:**
```bash
sudo systemctl start myapp.service
systemctl status myapp.service
journalctl -xe  # Recent logs with explanation
```

**Common issues:**
- Wrong file permissions on ExecStart script
- User doesn't exist
- Working directory doesn't exist
- Environment variables not set
- Dependencies not met

After completing the materials, try these exercises (spend 20 minutes):

```bash
# Exercise 1: Create a simple test service
sudo tee /etc/systemd/system/test.service > /dev/null << 'EOF'
[Unit]
Description=Test Service

[Service]
Type=simple
ExecStart=/bin/bash -c 'while true; do echo "Test running"; sleep 5; done'

[Install]
WantedBy=multi-user.target
EOF

# Exercise 2: Load and start it
sudo systemctl daemon-reload
sudo systemctl start test.service

# Exercise 4: View logs
```
