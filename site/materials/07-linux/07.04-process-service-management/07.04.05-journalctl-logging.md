- Export and manage journal logs
- Troubleshoot services using journal logs

---

## Introduction

The systemd journal (journald) collects and stores logs from the kernel, services, and applications in a structured, indexed format. The `journalctl` command queries these logs, offering powerful filtering and search capabilities. Mastering journalctl is essential for troubleshooting services, monitoring system activity, and investigating issues.

Unlike traditional text-based logs, the journal stores structured metadata, enabling precise queries and efficient searches.

## Key Concepts Summary

### Basic journalctl Usage

**View all logs:**
```bash
journalctl
# Shows all logs, oldest first (like less pager)
# Press 'q' to quit
```

**Recent logs:**
```bash
journalctl -n 50    # Last 50 entries
journalctl -n 100   # Last 100 entries
```

**Follow logs (real-time):**
```bash
journalctl -f       # Like tail -f
journalctl -f -n 20 # Follow, starting with last 20
```

**Reverse order (newest first):**
```bash
journalctl -r
journalctl -r -n 50
```

### Filtering by Unit

**View logs for specific service:**
```bash
journalctl -u nginx.service
journalctl -u nginx            # .service optional
```

**Multiple services:**
```bash
journalctl -u nginx -u postgresql
```

**Follow service logs:**
```bash
journalctl -u myapp.service -f
```

**Service logs with details:**
```bash
journalctl -u nginx.service -n 100 --no-pager
```

### Filtering by Time

**Since/until specific time:**
```bash
# Relative times
journalctl --since "1 hour ago"
journalctl --since "30 minutes ago"
journalctl --since "2 days ago"
journalctl --since today
journalctl --since yesterday

# Absolute times
journalctl --since "2026-01-26 10:00:00"
journalctl --since "2026-01-26" --until "2026-01-27"

# Combinations
journalctl -u nginx --since "2026-01-26 09:00" --until "2026-01-26 17:00"
```

**Time ranges:**
```bash
# Today's logs
journalctl --since today

# Yesterday's logs
journalctl --since yesterday --until today

# This week
journalctl --since "1 week ago"

# Between specific times
journalctl --since "2026-01-26 08:00" --until "2026-01-26 12:00"
```

### Filtering by Boot

**Current boot:**
```bash
journalctl -b
journalctl -b 0      # Same as -b
```

**Previous boots:**
```bash
journalctl -b -1     # Last boot
journalctl -b -2     # Two boots ago
```

**List all boots:**
```bash
journalctl --list-boots

# Example output:
-2 a1b2c3d4... Mon 2026-01-20 08:15:22 UTC—Mon 2026-01-20 18:30:45 UTC
-1 e5f6g7h8... Tue 2026-01-25 09:00:15 UTC—Tue 2026-01-25 23:45:30 UTC
 0 i9j0k1l2... Mon 2026-01-26 10:00:00 UTC—Mon 2026-01-26 15:30:20 UTC
```

**Specific boot:**
```bash
journalctl -b a1b2c3d4...    # Use boot ID
```

### Filtering by Priority

**Priority levels:**
```
0: emerg   - Emergency
1: alert   - Alert
2: crit    - Critical
3: err     - Error
4: warning - Warning
5: notice  - Notice
6: info    - Information
7: debug   - Debug
```

**Filter by priority:**
```bash
# Only errors and above
journalctl -p err

# Only warnings and above
journalctl -p warning

# Specific priority
journalctl -p 3      # err
journalctl -p debug  # All messages
```

**Service-specific priorities:**
```bash
journalctl -u nginx.service -p err
journalctl -u myapp.service -p warning --since today
```

### Advanced Filtering

**By process ID:**
```bash
journalctl _PID=1234
```

**By user ID:**
```bash
journalctl _UID=1000
```

**By executable:**
```bash
journalctl /usr/bin/nginx
journalctl _EXE=/usr/bin/python3
```

**By kernel messages:**
```bash
journalctl -k           # Kernel messages only
journalctl _TRANSPORT=kernel
```

**Custom field matching:**
```bash
journalctl FIELD=value
journalctl _SYSTEMD_UNIT=nginx.service
journalctl SYSLOG_IDENTIFIER=nginx
```

### Output Formats

**JSON format:**
```bash
journalctl -u nginx -n 10 -o json
journalctl -u nginx -n 10 -o json-pretty
```

**Short format (default):**
```bash
journalctl -o short
```

**Verbose (all fields):**
```bash
journalctl -o verbose -n 5
```

**Export format (binary):**
```bash
journalctl -o export
```

**Cat (no metadata):**
```bash
journalctl -o cat
```

### Disk Usage and Management

**Check journal disk usage:**
```bash
journalctl --disk-usage
```

**Vacuum by size:**
```bash
sudo journalctl --vacuum-size=500M
```

**Vacuum by time:**
```bash
sudo journalctl --vacuum-time=7d    # Keep 7 days
sudo journalctl --vacuum-time=1month
```

**Vacuum by files:**
```bash
sudo journalctl --vacuum-files=5
```

**Verify journal integrity:**
```bash
sudo journalctl --verify
```

### Journal Configuration

**Configuration file: /etc/systemd/journald.conf**

**Key settings:**
```ini
[Journal]
Storage=persistent       # Store on disk
SystemMaxUse=500M       # Max disk space
SystemKeepFree=1G       # Keep this much free
MaxRetentionSec=7day    # Max retention time
ForwardToSyslog=no      # Forward to syslog
Compress=yes            # Compress logs
```

**Restart journald after config changes:**
```bash
sudo systemctl restart systemd-journald
```

### Practical Use Cases

**Troubleshoot service failure:**
```bash
# 1. Check service status
systemctl status myapp.service

# 2. View recent logs
journalctl -u myapp.service -n 50

# 3. View logs since last boot
journalctl -u myapp.service -b

# 4. View errors only
journalctl -u myapp.service -p err

# 5. View logs around failure time
journalctl -u myapp.service --since "10 minutes ago"
```

**Monitor application in real-time:**
```bash
# Terminal 1: Follow logs
journalctl -u myapp.service -f

# Terminal 2: Test application
curl http://localhost:8000
```

**Investigate system boot:**
```bash
# View boot logs
journalctl -b

# Check boot time
systemd-analyze

# Check slow services
systemd-analyze blame

# View kernel messages during boot
journalctl -b -k
```

**Find recent errors:**
```bash
# All errors in last hour
journalctl -p err --since "1 hour ago"

# Errors for specific service
journalctl -u nginx.service -p err --since today

# Critical errors across system
journalctl -p crit --since yesterday
```

**Audit user activity:**
```bash
# View user's actions
journalctl _UID=1000 --since today

# View sudo commands
journalctl _COMM=sudo

# View authentication logs
journalctl -u sshd.service
```

**Export logs for analysis:**
```bash
# Export to file
journalctl -u myapp.service --since today > myapp-logs.txt

# Export JSON for processing
journalctl -u myapp.service -o json --since today > myapp-logs.json

# Export specific time range
journalctl --since "2026-01-26 09:00" --until "2026-01-26 17:00" > business-hours.log
```

### Tips and Tricks

**Combine filters:**
```bash
# Service + priority + time
journalctl -u nginx.service -p warning --since "1 hour ago"

# Multiple services + boot
journalctl -u nginx -u postgresql -b

# User activity + time
journalctl _UID=1000 --since yesterday -p notice
```

**Search with grep:**
```bash
journalctl -u myapp.service | grep "ERROR"
journalctl --since today | grep -i "failed"
```

**Page through logs:**
```bash
# Use less pager (default)
journalctl -u nginx.service

# No pager
journalctl -u nginx.service --no-pager

# In less:
# / to search
# n for next match
# q to quit
```

**Count log entries:**
```bash
journalctl -u myapp.service --since today | wc -l
```

**Find specific patterns:**
```bash
# Find connection errors
journalctl -u nginx.service | grep -i "connection refused"

# Find memory issues
journalctl -p err | grep -i "out of memory"

# Find authentication failures
journalctl -u sshd.service | grep "Failed password"
```

### Troubleshooting Workflows

**Service won't start:**
```bash
sudo systemctl start myapp.service
systemctl status myapp.service
journalctl -xe  # Expanded recent logs
journalctl -u myapp.service -n 100
```

**Service keeps restarting:**
```bash
journalctl -u myapp.service -f
# Watch for restart pattern and error messages
```

**Performance issues:**
```bash
# Check for errors during peak time
journalctl --since "14:00" --until "15:00" -p err

# Look for resource issues
journalctl -k | grep -i "out of memory"
```

**Security audit:**
```bash
# Failed login attempts
journalctl -u sshd.service | grep "Failed password"

# Sudo usage
journalctl _COMM=sudo --since "1 week ago"

# Service failures
journalctl -p crit --since yesterday
```
