## Introduction

Linux is fundamentally a multi-user system. Every file and directory is owned by a specific user and group. This ownership system works hand-in-hand with permissions to control access—you need to understand both to manage system security effectively.

User and group management is crucial for collaboration, security isolation, and proper application deployment. Web servers, databases, and applications often run under specific user accounts to limit their access to the system.

## Key Concepts Summary

### Users and Groups

**Every file has two owners:**
- **User owner** - A single user who owns the file
- **Group owner** - A group that owns the file

**Why groups matter:**
- Enable collaboration (multiple users in same group share access)
- Simplify permission management (change group permissions instead of individual users)
- Security isolation (applications run under specific users/groups)

### Viewing Ownership

Use `ls -l` to see ownership:

```bash
ls -l /var/www/html/index.html
-rw-r--r-- 1 www-data www-data 1234 Jan 26 10:00 index.html
              ↑        ↑
              user     group
```

View numeric IDs:
```bash
ls -n /var/www/html/index.html
-rw-r--r-- 1 33 33 1234 Jan 26 10:00 index.html
              ↑  ↑
              UID GID
```

### Changing Ownership with chown

**Change user owner:**
```bash
sudo chown alice file.txt        # Change owner to alice
```

**Change both user and group:**
```bash
sudo chown alice:developers file.txt    # Owner: alice, Group: developers
sudo chown alice: file.txt              # Owner: alice, Group: alice's primary group
```

**Recursive ownership change:**
```bash
sudo chown -R www-data:www-data /var/www/html/   # Change directory and all contents
```

**Change only group with chgrp:**
```bash
sudo chgrp developers project/    # Change group to developers
sudo chgrp -R developers project/ # Recursive group change
```

### Common Ownership Patterns

**Web server files:**
```bash
sudo chown -R www-data:www-data /var/www/html/
sudo chmod -R 755 /var/www/html/
```
- Owner: www-data (web server process runs as this user)
- Group: www-data
- Permissions: 755 (owner can write, others can read)

**Application configuration:**
```bash
sudo chown root:appgroup /etc/myapp/config.yml
sudo chmod 640 /etc/myapp/config.yml
```
- Owner: root (only admin can modify)
- Group: appgroup (application can read)
- Permissions: 640 (owner read+write, group read, others nothing)

**Shared project directory:**
```bash
sudo chown -R :developers /projects/webapp/
sudo chmod -R 775 /projects/webapp/
```
- User: Leave as is (various owners)
- Group: developers (team group)
- Permissions: 775 (group can write, enabling collaboration)

### User Information Commands

```bash
# View your user info
whoami                # Current username
id                    # UID, GID, and groups
groups                # Groups you belong to

# View other users
id alice              # Alice's user info
groups bob            # Bob's groups

# View all users
cat /etc/passwd | grep bash  # Users with bash shells

# View all groups
cat /etc/group        # All groups
```

### Practical Ownership Scenarios

**Deploying an application:**
```bash
# Create app user
sudo useradd -r -s /bin/false myapp

# Set ownership
sudo chown -R myapp:myapp /opt/myapp/
sudo chmod 755 /opt/myapp/

# Config files readable only by app
sudo chown myapp:myapp /etc/myapp/config.json
sudo chmod 600 /etc/myapp/config.json
```

**Team collaboration directory:**
```bash
# Create shared directory
sudo mkdir /shared/team-project
sudo chgrp developers /shared/team-project
sudo chmod 775 /shared/team-project

# Set setgid so new files inherit group
sudo chmod g+s /shared/team-project
```

**Fixing permissions after file transfer:**
```bash
# After copying files as root, fix ownership
sudo chown -R alice:alice /home/alice/imported-files/
sudo chmod -R 644 /home/alice/imported-files/*.txt
sudo chmod -R 755 /home/alice/imported-files/*.sh
```

## Practice Exercise

After completing the materials, try these exercises (spend 10 minutes):

```bash
# Create a test file
touch myfile.txt
ls -l myfile.txt

# View your user info
whoami
id
groups

# Create a test directory
mkdir testdir
ls -ld testdir

# Try viewing ownership with numeric IDs
ls -n myfile.txt

# Check ownership of system directories
ls -ld /var/log
ls -ld /var/www

# Check ownership of your home directory
ls -ld ~
ls -l ~/
```

If you have sudo access on your system, try:
```bash
sudo chown nobody:nogroup myfile.txt
ls -l myfile.txt
sudo chown $USER:$USER myfile.txt
ls -l myfile.txt
```
