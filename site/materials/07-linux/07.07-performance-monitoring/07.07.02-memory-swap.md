- Interpret swap usage and identify memory pressure

- Understand OOM (Out of Memory) killer
- Troubleshoot memory-related performance issues

---

## Introduction

Memory management is critical for system performance. Understanding the difference between actual memory pressure and normal Linux memory behavior prevents false alarms. Linux aggressively uses available RAM for caching, which is beneficial—not problematic. This lesson teaches you to distinguish between healthy memory usage and actual memory issues.

## Key Concepts Summary

### Memory Types

**Physical memory:**
```
Total RAM installed in system
Divided into: used + available
```

**Memory categories:**
```
Used      - Memory actively used by processes
Free      - Completely unused (rare)
Available - Memory that can be used by new processes
Buffers   - Metadata about filesystems
Cached    - File data cached from disk
Shared    - Shared between processes
Swap      - Disk space used as virtual memory
```

**Important:** Available ≠ Free!

### The free Command

**Basic usage:**
```bash
free
free -h     # Human-readable
free -m     # In MB
free -g     # In GB
free -s 2   # Update every 2 seconds
```

**Example output:**
```bash
$ free -h
              total        used        free      shared  buff/cache   available
Mem:           15Gi       5.0Gi       2.0Gi       200Mi       8.0Gi        9.5Gi
Swap:         2.0Gi       100Mi       1.9Gi
```

**Understanding columns:**
```
total      - Total installed RAM
used       - RAM used by processes
free       - Completely unused RAM (can be very low!)
shared     - Memory shared between processes (tmpfs)
buff/cache - Memory used for buffers and disk cache
available  - Memory available for new apps (most important!)
```

**Key insight:**
```
Low "free" is NORMAL and GOOD
Linux uses free RAM for caching
Focus on "available" column instead
```

### Memory Calculation

**Old calculation (incorrect):**
```
Free memory = free column
```

**Correct calculation:**
```
Available memory = available column
Available = free + reclaimable cache/buffers
```

**Why cache/buffers matter:**
```
Linux caches disk reads in RAM
Makes repeated access much faster
Cache is automatically freed when needed
NOT wasted memory!
```

### Swap Space

**What is swap?**
- Disk space used as virtual memory
- Allows system to handle more processes
- Much slower than RAM (disk speed vs RAM speed)
- Used for:
  - Infrequently accessed memory pages
  - Hibernation
  - Emergency overflow

**Viewing swap:**
```bash
free -h
swapon --show
cat /proc/swaps
```

**Swap is NOT always bad:**
```
Swap usage < 25% with available RAM = NORMAL
Kernel swaps out inactive pages to use RAM for cache
Improves overall performance

Swap problem indicators:
- Constant swap in/out (thrashing)
- High swap with no available RAM
- System becomes unresponsive
```

### Swappiness

**What is swappiness?**
- Kernel parameter controlling swap behavior
- Range: 0-100
- Higher = more aggressive swapping

**Check swappiness:**
```bash
cat /proc/sys/vm/swappiness
```

**Typical values:**
```
60  - Default (balanced)
10  - Prefer keeping things in RAM
100 - Aggressively swap
```

**Adjust swappiness:**
```bash
# Temporary
sudo sysctl vm.swappiness=10

# Permanent
echo "vm.swappiness=10" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

### Monitoring with vmstat

**Basic usage:**
```bash
vmstat
vmstat 2 5    # Every 2 seconds, 5 times
vmstat -S M 2  # In MB
```

**Memory columns:**
```
swpd  - Virtual memory used (KB)
free  - Idle memory
buff  - Buffer memory
cache - Cache memory
si    - Swap in (from disk) per second
so    - Swap out (to disk) per second
```

**Warning signs:**
```
High si/so values = Memory pressure!
Consistent swap activity = Thrashing
```

**Example:**
```bash
$ vmstat 1
procs memory          swap          io
 r  b   swpd   free si so    bi    bo
 2  0 102400 500000  5 10   100   50
                     ↑  ↑
                  Swap in/out
```

### Finding Memory-Hungry Processes

**Using top:**
```bash
top
# Press 'M' to sort by memory
# Press 'E' to cycle memory units
```

**Using ps:**
```bash
# Top memory consumers
ps aux --sort=-%mem | head -10

# Memory RSS (Resident Set Size)
ps -eo pid,user,rss,cmd --sort=-rss | head -10

# Convert to MB
ps -eo pid,user,rss,cmd --sort=-rss | awk 'NR==1{print $0} NR>1{$3=int($3/1024)"M"; print $0}' | head -10
```

**Using pidstat:**
```bash
# Memory usage by process
pidstat -r 1
```

### Memory Information Files

**/proc/meminfo:**
```bash
cat /proc/meminfo

# Key fields:
MemTotal:     - Total usable RAM
MemFree:      - Free RAM
MemAvailable: - Available for new apps
Buffers:      - Buffer cache
Cached:       - Page cache
SwapTotal:    - Total swap
SwapFree:     - Free swap
Dirty:        - Modified pages waiting to be written
```

**/proc/<pid>/status:**
```bash
# Memory for specific process
cat /proc/1234/status | grep -i mem

VmSize:  - Virtual memory size
VmRSS:   - Resident set size (actual RAM)
VmSwap:  - Swapped out
```

### OOM (Out of Memory) Killer

**What is OOM killer?**
- Kernel mechanism when RAM is exhausted
- Kills processes to free memory
- Selects victim based on oom_score
- Last resort to prevent system crash

**View OOM scores:**
```bash
# Higher score = more likely to be killed
ps -eo pid,comm,oom_score | sort -k3 -rn | head -10
```

**OOM killer logs:**
```bash
dmesg | grep -i "out of memory"
journalctl -k | grep -i "oom"
grep -i "killed process" /var/log/kern.log
```

**OOM example:**
```
Out of memory: Kill process 12345 (process_name) score 850
```

**Prevent OOM killing specific process:**
```bash
# Set oom_score_adj (-1000 to 1000)
echo -1000 | sudo tee /proc/<PID>/oom_score_adj

# -1000 = never kill
# 0 = default
# 1000 = first to kill
```

### Memory Leaks

**Signs of memory leak:**
```
- Memory usage constantly increases
- Never released back to system
- Eventually causes OOM
```

**Detecting leaks:**
```bash
# Monitor process memory over time
while true; do
    ps aux | grep process_name | grep -v grep
    sleep 60
done

# Or use pidstat
pidstat -r -p PID 10
```

**Memory leak investigation:**
```bash
# Track memory usage
/usr/bin/time -v ./program

# Use valgrind (for developers)
valgrind --leak-check=full ./program
```

### Troubleshooting Memory Issues

**Symptom: Low available memory**
```bash
# 1. Check memory
free -h

# 2. Find memory hogs
ps aux --sort=-%mem | head -10

# 3. Check for leaks
# Monitor top consumers over time

# 4. Check OOM killer activity
dmesg | grep -i oom
```

**Symptom: High swap usage**
```bash
# 1. Check swap
free -h
swapon --show

# 2. Check swap activity (si/so)
vmstat 1 5

# 3. If constant swapping:
#    - Add more RAM
#    - Reduce memory usage
#    - Adjust swappiness
```

**Symptom: System becoming slow**
```bash
# Check for thrashing
vmstat 1

# Look for:
# - High si/so (swap in/out)
# - Many blocked processes (b column)
# - High I/O wait

# Solutions:
# - Kill memory-hungry processes
# - Add RAM
# - Optimize applications
```

### Practical Examples

**Memory monitoring script:**
```bash
#!/bin/bash
# Monitor memory every 10 seconds

while true; do
    echo "=== $(date) ==="
    free -h
    echo "Top 5 memory consumers:"
    ps aux --sort=-%mem | head -6
    echo ""
    sleep 10
done
```

**Alert on low memory:**
```bash
#!/bin/bash
# Alert if available memory < 500MB

AVAILABLE=$(free -m | awk 'NR==2{print $7}')
THRESHOLD=500

if [ $AVAILABLE -lt $THRESHOLD ]; then
    echo "WARNING: Only ${AVAILABLE}MB available!"
    ps aux --sort=-%mem | head -6
fi
```

**Check for swap thrashing:**
```bash
#!/bin/bash
# Check swap activity

vmstat 1 5 | awk '
NR>2 {
    if ($7 > 1000 || $8 > 1000) {
        print "WARNING: High swap activity detected"
        print "Swap In:", $7, "Swap Out:", $8
    }
}'
```
