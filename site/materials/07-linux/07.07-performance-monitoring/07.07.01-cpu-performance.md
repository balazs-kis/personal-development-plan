## Learning Objectives

By the end of this lesson, you will be able to:
- Understand CPU metrics and load averages

## Introduction

CPU performance directly impacts application responsiveness and system capacity. Understanding how to monitor CPU usage, interpret load averages, and identify bottlenecks is fundamental to performance troubleshooting. This lesson covers the essential tools and metrics for CPU performance analysis.

## Key Concepts Summary

### CPU Basics

**What CPU does:**
- Executes program instructions
- Manages processes and threads
- Handles interrupts
- Context switches between processes

**CPU time types:**
```
User (us)    - Time spent in user space
System (sy)  - Time spent in kernel space
Nice (ni)    - Time spent on low-priority processes
Idle (id)    - Time spent idle
I/O Wait (wa) - Time waiting for I/O
Hardware IRQ (hi) - Time handling hardware interrupts
Software IRQ (si) - Time handling software interrupts
Steal (st)   - Time stolen by hypervisor (VMs)
```

### Load Average

**What is load average?**
- Average number of processes waiting for CPU
- Shows 1, 5, and 15 minute averages
- NOT a percentage
- Includes runnable AND uninterruptible processes

**Viewing load average:**
```bash
uptime
w
top
cat /proc/loadavg
```

**Example:**
```bash
$ uptime
10:30:15 up 5 days,  2:15,  3 users,  load average: 2.50, 1.80, 1.20
                                                     1min  5min  15min
```

**Interpreting load:**
```
Single CPU system:
0.00 - Completely idle
1.00 - Fully utilized
> 1.00 - Overloaded (processes waiting)

Multi-CPU system (4 CPUs):
0.00 - All CPUs idle
4.00 - All CPUs fully utilized
> 4.00 - Overloaded

Rule of thumb:
Load < number of CPUs = OK
Load > number of CPUs = Potential bottleneck
```

**Check CPU count:**
```bash
nproc
grep -c processor /proc/cpuinfo
lscpu | grep "^CPU(s):"
```

### Monitoring with top

**Basic usage:**
```bash
top
```

**Key metrics:**
```
%Cpu(s): 25.0 us,  5.0 sy,  0.0 ni, 65.0 id,  5.0 wa
         |USER   |SYS    |NICE |IDLE  |IO WAIT

Load average: 2.50, 1.80, 1.20
Tasks: 250 total, 3 running, 247 sleeping
```

**Interactive commands in top:**
```
1    - Show per-CPU breakdown
P    - Sort by CPU usage
M    - Sort by memory usage
k    - Kill a process
r    - Renice a process
h    - Help
q    - Quit
```

**Understanding columns:**
```
PID   - Process ID
USER  - Owner
PR    - Priority
NI    - Nice value
%CPU  - CPU usage
%MEM  - Memory usage
TIME+ - Total CPU time
COMMAND - Process name
```

**High CPU indicators:**
```
High %CPU in processes
High load average
Low idle percentage
High system/user time
```

### Monitoring with htop

**Install htop:**
```bash
sudo apt install htop  # Ubuntu/Debian
sudo dnf install htop  # Red Hat/Fedora
```

**Advantages over top:**
- Color-coded output
- Mouse support
- Visual CPU/memory bars
- Tree view of processes
- Easier to kill processes
- Scrollable process list

**Interactive keys:**
```
F1   - Help
F2   - Setup
F3   - Search
F4   - Filter
F5   - Tree view
F6   - Sort by column
F9   - Kill process
F10  - Quit
```

### mpstat (Multiple Processor Statistics)

**Install (part of sysstat):**
```bash
sudo apt install sysstat  # Ubuntu/Debian
sudo dnf install sysstat  # Red Hat/Fedora
```

**Basic usage:**
```bash
# Current stats
mpstat

# Monitor every 2 seconds, 5 times
mpstat 2 5
```

**Per-CPU statistics:**
```bash
# Show all CPUs separately
mpstat -P ALL

# Monitor specific CPU
mpstat -P 0

# Monitor every second
mpstat -P ALL 1
```

**Output columns:**
```
%usr  - User level (applications)
%nice - User level with nice priority
%sys  - System level (kernel)
%iowait - Waiting for I/O
%irq  - Hardware interrupt time
%soft - Software interrupt time
%steal - Stolen by hypervisor
%guest - Running virtual CPU
%idle - Idle time
```

**Ideal values:**
```
%usr + %sys < 80%  - Healthy
%iowait < 10%      - Good I/O performance
%idle > 20%        - Capacity available
%steal < 5%        - VM not oversubscribed
```

### Context Switches

**What are context switches?**
- CPU switches from one process/thread to another
- Saves/restores CPU state
- Has overhead
- Too many = performance degradation

**View context switches:**
```bash
# With vmstat
vmstat 1

# Output shows:
# cs = context switches per second

# Detailed
pidstat -w 1
```

**Normal vs problematic:**
```
< 1000/s per CPU   - Normal
1000-10000/s       - Moderate
> 10000/s          - High (investigate)
```

### Finding High-CPU Processes

**Using top:**
```bash
top
# Press 'P' to sort by CPU
# Press '1' to see per-CPU breakdown
```

**Using ps:**
```bash
# Top CPU consumers
ps aux --sort=-%cpu | head -10

# Specific user
ps -u username --sort=-%cpu
```

**Using pidstat:**
```bash
# CPU usage by process
pidstat 1

# Top processes
pidstat -u 1 5
```

### CPU Affinity

**View process CPU affinity:**
```bash
taskset -p PID
```

**Set CPU affinity:**
```bash
# Run on CPUs 0 and 1
taskset -c 0,1 command

# Pin existing process
taskset -p -c 0,1 PID
```

### Nice and Renice

**Priority levels:**
```
Nice value: -20 to 19
-20 = Highest priority
0   = Default
19  = Lowest priority
```

**Start with nice:**
```bash
# Lower priority
nice -n 10 command

# Higher priority (requires root)
sudo nice -n -10 command
```

**Change priority:**
```bash
# Renice running process
renice -n 5 -p PID

# Renice all user processes
renice -n 10 -u username
```

### Troubleshooting CPU Issues

**Symptom: High load average**
```bash
# 1. Check load
uptime

# 2. Identify top CPU consumers
top
ps aux --sort=-%cpu | head -10

# 3. Check for I/O wait
iostat -x 1 5

# 4. Look for many processes in R state
ps -eo state,pid,cmd | grep "^R"
```

**Symptom: High %iowait**
```bash
# Not CPU problem - it's I/O
# Check disk I/O:
iostat -x 1 5
iotop

# See disk I/O lesson for details
```

**Symptom: One CPU at 100%**
```bash
# Single-threaded application bottleneck
# Options:
# 1. Optimize application
# 2. Use multi-threading
# 3. Run multiple instances
```

**Symptom: Uneven CPU distribution**
```bash
# Check with mpstat
mpstat -P ALL 1

# May need CPU affinity tuning
# Or check for interrupt handling
cat /proc/interrupts
```

### Practical Examples

**Monitor CPU in real-time:**
```bash
# Simple monitoring
watch -n 1 'uptime; mpstat'

# Detailed
htop
```

**Find process causing high CPU:**
```bash
#!/bin/bash
# Find top 5 CPU consumers

echo "Top 5 CPU Consumers:"
ps aux --sort=-%cpu | head -6

echo -e "\nLoad Average:"
uptime

echo -e "\nCPU Breakdown:"
mpstat -P ALL | head -n 10
```

**Log CPU usage:**
```bash
# Log every 5 seconds to file
while true; do
    echo "$(date): $(uptime)" >> cpu_log.txt
    mpstat 1 1 >> cpu_log.txt
    sleep 5
done
```
