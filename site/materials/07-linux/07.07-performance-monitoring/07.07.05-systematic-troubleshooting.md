## Key Concepts Summary

### The USE Method

**USE stands for:**
```
Utilization - How busy is the resource?
Saturation  - Is there more work than it can handle?
Errors      - Are there error conditions?
```

**Apply to each resource:**
```
CPU         - Utilization, saturation, errors
Memory      - Utilization, saturation, errors
Disk        - Utilization, saturation, errors
Network     - Utilization, saturation, errors
```

**USE Method Checklist:**

**CPU:**
```
Utilization: mpstat 1, top (%CPU)
Saturation:  uptime (load average), vmstat (r)
Errors:      dmesg | grep -i error
```

**Memory:**
```
Utilization: free -h (used vs total)
Saturation:  vmstat (si/so), dmesg | grep -i oom
Errors:      dmesg | grep -i memory
```

**Disk:**
```
Utilization: iostat -x (%util)
Saturation:  iostat -x (avgqu-sz), iotop
Errors:      dmesg | grep -i error, smartctl
```

**Network:**
```
Utilization: ip -s link, iftop, nethogs
Saturation:  ifconfig (overruns), netstat -s
Errors:      ip -s link (errors, dropped)
```

### 60-Second Performance Check

**Quick diagnosis in 1 minute:**
```bash
# 1. Load average (10 seconds)
uptime
w

# 2. Kernel messages (10 seconds)
dmesg | tail -20

# 3. Overall CPU stats (10 seconds)
vmstat 1 5

# 4. Per-CPU stats (10 seconds)
mpstat -P ALL 1 3

# 5. Per-process CPU (10 seconds)
pidstat 1 3

# 6. Disk I/O (10 seconds)
iostat -x 1 3

# 7. Memory stats (5 seconds)
free -h

# 8. Network stats (5 seconds)
ip -s link
```

**What to look for:**
```
uptime          → High load?
dmesg           → OOM kills? Disk errors?
vmstat          → High wa? High swap?
mpstat          → Unbalanced CPUs?
pidstat         → CPU hogs?
iostat          → Saturated disks?
free            → Low available memory?
ip -s link      → Network errors?
```

### Performance Troubleshooting Workflow

**Step 1: Define the problem**
```
- What is slow?
- When did it start?
- Has anything changed?
- How slow (metrics)?
- Consistent or intermittent?
```

**Step 2: Check system resources**
```bash
# Quick overview
top
htop

# CPU
uptime
mpstat -P ALL 1

# Memory
free -h
vmstat 1

# Disk
iostat -x 1

# Network
ip -s link
```

**Step 3: Identify bottleneck**
```
CPU bottleneck:
- High load average
- Low idle %
- Processes in R state

Memory bottleneck:
- Low available memory
- High swap usage
- Constant si/so activity

Disk bottleneck:
- High I/O wait
- High disk utilization
- Large I/O queues

Network bottleneck:
- High throughput
- Dropped packets
- High errors
```

**Step 4: Find the culprit**
```bash
# CPU
ps aux --sort=-%cpu | head -10
pidstat -u 1

# Memory
ps aux --sort=-%mem | head -10
pidstat -r 1

# Disk I/O
sudo iotop -o
pidstat -d 1

# Network
sudo nethogs
sudo iftop
```

**Step 5: Analyze and resolve**
```
- Is it application issue?
- Is it configuration issue?
- Is it resource limitation?
- Is it external dependency?
```

**Step 6: Verify fix**
```
- Monitor metrics
- Compare to baseline
- Load test if possible
- Document solution
```

### Common Bottleneck Patterns

**Pattern 1: High load, high CPU**
```
Symptom: Load > CPU count, high %CPU
Cause:   CPU-bound workload
Check:   top, ps aux --sort=-%cpu
Fix:     
- Optimize application
- Add more CPU
- Use caching
- Distribute load
```

**Pattern 2: High load, high I/O wait**
```
Symptom: Load > CPU count, high %wa
Cause:   Disk I/O bottleneck
Check:   iostat -x, iotop
Fix:     
- Optimize queries
- Add faster storage
- Increase cache
- Fix slow queries
```

**Pattern 3: Low memory, high swap**
```
Symptom: Low available, constant swap
Cause:   Memory pressure
Check:   free -h, vmstat (si/so)
Fix:     
- Add more RAM
- Kill memory hogs
- Optimize applications
- Fix memory leaks
```

**Pattern 4: Application slow, system OK**
```
Symptom: System metrics normal, app slow
Cause:   Application or external issue
Check:   
- Application logs
- Database slow queries
- External API latency
- Network to dependencies
Fix:     
- Fix application code
- Optimize database
- Add caching
- Fix external services
```

### Performance Baselines

**Why baselines matter:**
- Know what "normal" looks like
- Detect anomalies quickly
- Measure improvement
- Capacity planning

**Creating baselines:**
```bash
# CPU baseline
mpstat 1 60 > baseline_cpu.txt

# Memory baseline
vmstat 1 60 > baseline_memory.txt

# Disk baseline
iostat -x 1 60 > baseline_disk.txt

# Network baseline
ifstat 1 60 > baseline_network.txt
```

**Automated baseline script:**
```bash
#!/bin/bash
# Collect performance baseline

DATE=$(date +%Y%m%d_%H%M%S)
DIR="baseline_$DATE"
mkdir -p $DIR

echo "Collecting baseline for 5 minutes..."

# System info
uname -a > $DIR/system_info.txt
lscpu > $DIR/cpu_info.txt
free -h > $DIR/memory_info.txt
df -h > $DIR/disk_info.txt

# 5-minute samples
mpstat 1 300 > $DIR/cpu_stats.txt &
vmstat 1 300 > $DIR/memory_stats.txt &
iostat -x 1 300 > $DIR/disk_stats.txt &
ifstat 1 300 > $DIR/network_stats.txt &

wait
echo "Baseline collected in $DIR/"
```

### Monitoring Tools Summary

**Real-time monitoring:**
```
top/htop     - Overall system view
mpstat       - CPU per-core
iotop        - Disk I/O by process
nethogs      - Network by process
iftop        - Network by connection
```

**Historical data:**
```
sar          - System activity reporter
atop         - System activity logger
```

**Detailed analysis:**
```
perf         - Performance profiling
strace       - System call tracing
ltrace       - Library call tracing
```

### Practical Troubleshooting Examples

**Example 1: Website slow**
```bash
# 1. Check load
uptime  # Load average: 8.50, 7.20, 5.10 (4 CPU system)

# 2. Check what's using CPU
ps aux --sort=-%cpu | head -5
# apache2 processes using 80% CPU each

# 3. Check connections
ss -s
# 500 established connections

# Diagnosis: Too many connections
# Solution: Increase workers, add caching, load balancer
```

**Example 2: Database queries slow**
```bash
# 1. Check I/O wait
top  # %wa: 45.0

# 2. Check disk utilization
iostat -x 1
# sda: %util 98%, await 150ms

# 3. Check what's doing I/O
sudo iotop -o
# postgres processes doing heavy I/O

# Diagnosis: Disk bottleneck
# Solution: Optimize queries, add indexes, faster storage
```

**Example 3: Application crashes**
```bash
# 1. Check OOM
dmesg | grep -i oom
# "Out of memory: Killed process 1234 (myapp)"

# 2. Check memory
free -h
# available: 50M / 16G

# 3. Check memory hogs
ps aux --sort=-%mem | head -5
# myapp using 15G

# Diagnosis: Memory leak
# Solution: Fix application, add more RAM temporarily
```
