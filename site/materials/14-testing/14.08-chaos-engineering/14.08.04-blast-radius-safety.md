## Learning Objectives

By the end of this lesson, you will be able to:
- Define and calculate blast radius for chaos experiments
- Implement safety measures for chaos experiments
- Design progressive experiment strategies
- Create abort criteria and rollback plans
- Use monitoring and observability during experiments
- Balance learning with safety

---

## Introduction

The most dangerous chaos experiments are those run without proper safety measures. Blast radius management and safety practices are what separate chaos engineering from randomly breaking production. This lesson teaches you how to experiment safely, learn from controlled failures, and avoid turning experiments into actual incidents.

## Key Concepts Summary

### What is Blast Radius?

**Blast radius** is the potential impact of a chaos experiment - the worst-case scenario if everything goes wrong.

**Measured by:**
- **User impact:** Percentage of users affected
- **Service impact:** Number of services/components affected
- **Duration:** How long the impact could last
- **Geographic scope:** Regions or data centers affected
- **Business impact:** Revenue, reputation, or SLA impact

**Example:**
```
Experiment: Terminate one API instance

Small blast radius:
- Users: 0-1% (other instances handle traffic)
- Services: 1 (only API affected)
- Duration: Seconds (auto-recovery)
- Region: Single availability zone
- Business: Minimal (redundancy covers it)

Large blast radius:
- Users: 100% (no redundancy)
- Services: 5+ (cascading failures)
- Duration: Hours (manual recovery needed)
- Region: All regions (global failure)
- Business: Significant (SLA breach, revenue loss)
```

---

### Calculating Blast Radius

#### Formula

```
Blast Radius = (Affected Users / Total Users) × Impact Severity

Where Impact Severity:
- 1 = No noticeable impact
- 2 = Slight degradation
- 3 = Significant degradation
- 4 = Service unavailable
- 5 = Data loss or corruption
```

**Examples:**

```
Experiment 1: Kill 1 out of 10 instances
- Affected Users: 10% (traffic to that instance)
- Impact: 1 (no impact due to load balancing)
- Blast Radius: 10% × 1 = 0.1 (Very Low)

Experiment 2: Disable database replication
- Affected Users: 0% (reads still work)
- Impact: 4 (if primary fails, no writes)
- Blast Radius: 0% × 4 = 0 (Low, but high risk)

Experiment 3: Partition network in one AZ
- Affected Users: 33% (one of three AZs)
- Impact: 4 (those users can't access service)
- Blast Radius: 33% × 4 = 1.32 (High)
```

#### Progressive Blast Radius Strategy

```
Phase 1: Development
  - Blast Radius: 0% users
  - Impact: Development team only
  - Risk: None

Phase 2: Staging
  - Blast Radius: 0% users (separate environment)
  - Impact: QA and test users
  - Risk: Very Low

Phase 3: Production - Single Instance
  - Blast Radius: <1% users
  - Impact: Minimal due to redundancy
  - Risk: Low

Phase 4: Production - 10% Traffic
  - Blast Radius: 10% users
  - Impact: Moderate if issues occur
  - Risk: Medium

Phase 5: Production - Critical Path
  - Blast Radius: 50-100% users
  - Impact: High if issues occur
  - Risk: High (only after confidence built)
```

### Safety Measures

#### 1. Pre-Experiment Validation

**Health check before starting:**

```csharp
public class ChaosExperiment
{
    private readonly IHealthCheck _healthCheck;
    private readonly ILogger<ChaosExperiment> _logger;

    public async Task<bool> RunExperiment()
    {
        // 1. Verify system is healthy before starting
        var healthResult = await _healthCheck.CheckHealthAsync();
        
        if (healthResult.Status != HealthStatus.Healthy)
        {
            _logger.LogWarning("System not healthy, aborting experiment");
            return false;
        }

        // 2. Check all preconditions
        if (!await ValidatePreconditions())
        {
            _logger.LogWarning("Preconditions not met, aborting experiment");
            return false;
        }

        // 3. Proceed with experiment
        return await ExecuteChaos();
    }

    private async Task<bool> ValidatePreconditions()
    {
        // Verify:
        // - Monitoring is working
        // - Alerting is enabled
        // - Rollback mechanisms are ready
        // - Team is aware and on standby
        return true;
    }
}
```

#### 2. Real-Time Monitoring

**Monitor critical metrics during experiment:**

```csharp
public class ExperimentMonitor
{
    private readonly IMetricsClient _metrics;
    private readonly Dictionary<string, Threshold> _thresholds;

    public async Task<MonitoringResult> MonitorDuringExperiment(
        Func<Task> chaosAction,
        TimeSpan duration)
    {
        var result = new MonitoringResult();
        var cts = new CancellationTokenSource();

        // Start monitoring in background
        var monitoringTask = Task.Run(async () =>
        {
            while (!cts.Token.IsCancellationRequested)
            {
                var metrics = await _metrics.GetCurrentMetrics();
                
                // Check each threshold
                foreach (var threshold in _thresholds)
                {
                    if (metrics[threshold.Key] > threshold.Value.MaxValue)
                    {
                        result.ThresholdBreached = true;
                        result.BreachedMetric = threshold.Key;
                        cts.Cancel();
                        break;
                    }
                }
                
                await Task.Delay(TimeSpan.FromSeconds(5), cts.Token);
            }
        }, cts.Token);

        try
        {
            // Execute chaos
            await chaosAction();
            await Task.Delay(duration, cts.Token);
        }
        catch (OperationCanceledException)
        {
            result.AutoAborted = true;
        }
        finally
        {
            cts.Cancel();
            await monitoringTask;
        }

        return result;
    }
}

public class Threshold
{
    public string MetricName { get; set; }
    public double MaxValue { get; set; }
}

public class MonitoringResult
{
    public bool ThresholdBreached { get; set; }
    public string BreachedMetric { get; set; }
    public bool AutoAborted { get; set; }
}
```

#### 3. Automatic Abort Criteria

**Stop experiment if things go wrong:**

```csharp
public class ChaosExperimentRunner
{
    public async Task RunWithSafetyChecks(ChaosExperiment experiment)
    {
        var cts = new CancellationTokenSource();
        
        // Define abort criteria
        var abortCriteria = new[]
        {
            new AbortCriterion
            {
                Name = "High Error Rate",
                Check = async () => await GetErrorRate() > 0.05, // 5%
                Priority = AbortPriority.Immediate
            },
            new AbortCriterion
            {
                Name = "Low Availability",
                Check = async () => await GetAvailability() < 0.95, // 95%
                Priority = AbortPriority.Immediate
            },
            new AbortCriterion
            {
                Name = "Customer Complaints",
                Check = async () => await GetSupportTickets() > 10,
                Priority = AbortPriority.Immediate
            },
            new AbortCriterion
            {
                Name = "Response Time Degradation",
                Check = async () => await GetP95ResponseTime() > 1000, // 1s
                Priority = AbortPriority.High
            }
        };

        // Monitor abort criteria
        var monitorTask = Task.Run(async () =>
        {
            while (!cts.Token.IsCancellationRequested)
            {
                foreach (var criterion in abortCriteria)
                {
                    if (await criterion.Check())
                    {
                        _logger.LogWarning($"Abort criterion met: {criterion.Name}");
                        
                        if (criterion.Priority == AbortPriority.Immediate)
                        {
                            cts.Cancel();
                            await experiment.Rollback();
                            return;
                        }
                    }
                }
                
                await Task.Delay(TimeSpan.FromSeconds(10), cts.Token);
            }
        });

        try
        {
            await experiment.Execute(cts.Token);
        }
        catch (OperationCanceledException)
        {
            _logger.LogWarning("Experiment aborted due to safety criteria");
        }
        finally
        {
            cts.Cancel();
            await monitorTask;
        }
    }
}

public class AbortCriterion
{
    public string Name { get; set; }
    public Func<Task<bool>> Check { get; set; }
    public AbortPriority Priority { get; set; }
}

public enum AbortPriority
{
    Low,
    Medium,
    High,
    Immediate
}
```

#### 4. Manual Abort Button

**Big red button to stop experiment:**

```csharp
public class ChaosController
{
    private static CancellationTokenSource _currentExperiment;
    private readonly object _lock = new object();

    [HttpPost("experiments/start")]
    public async Task<IActionResult> StartExperiment([FromBody] ExperimentRequest request)
    {
        lock (_lock)
        {
            if (_currentExperiment != null)
            {
                return BadRequest("Experiment already running");
            }
            
            _currentExperiment = new CancellationTokenSource();
        }

        try
        {
            await RunExperiment(request, _currentExperiment.Token);
            return Ok("Experiment completed");
        }
        catch (OperationCanceledException)
        {
            return Ok("Experiment aborted");
        }
        finally
        {
            lock (_lock)
            {
                _currentExperiment?.Dispose();
                _currentExperiment = null;
            }
        }
    }

    [HttpPost("experiments/abort")]
    public IActionResult AbortExperiment()
    {
        lock (_lock)
        {
            if (_currentExperiment == null)
            {
                return BadRequest("No experiment running");
            }

            _currentExperiment.Cancel();
            _logger.LogWarning("Experiment manually aborted");
            
            return Ok("Experiment aborted");
        }
    }

    [HttpGet("experiments/status")]
    public IActionResult GetStatus()
    {
        lock (_lock)
        {
            return Ok(new
            {
                Running = _currentExperiment != null,
                CanAbort = _currentExperiment != null
            });
        }
    }
}
```

#### 5. Automatic Rollback

**Undo changes after experiment:**

```csharp
public abstract class ChaosExperiment
{
    protected abstract Task ExecuteChaos();
    protected abstract Task RollbackChaos();

    public async Task Run(TimeSpan duration)
    {
        try
        {
            _logger.LogInformation("Starting chaos experiment");
            
            // Execute chaos
            await ExecuteChaos();
            
            // Wait for duration
            await Task.Delay(duration);
            
            _logger.LogInformation("Chaos experiment completed, rolling back");
        }
        finally
        {
            // Always rollback, even if exception occurs
            try
            {
                await RollbackChaos();
                _logger.LogInformation("Rollback completed");
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Rollback failed - manual intervention required!");
                await SendAlert("URGENT: Chaos rollback failed!");
            }
        }
    }
}

// Example implementation
public class LatencyChaosExperiment : ChaosExperiment
{
    private bool _chaosEnabled = false;

    protected override async Task ExecuteChaos()
    {
        _chaosEnabled = true;
        _logger.LogInformation("Latency chaos enabled");
        await Task.CompletedTask;
    }

    protected override async Task RollbackChaos()
    {
        _chaosEnabled = false;
        _logger.LogInformation("Latency chaos disabled");
        await Task.CompletedTask;
    }

    public async Task<string> CallApi()
    {
        if (_chaosEnabled)
        {
            await Task.Delay(5000); // Inject 5s latency
        }
        
        return await _httpClient.GetStringAsync("https://api.example.com");
    }
}
```

    OnCall = "Not required"

var experiment = new ChaosExperiment
{
    Environment = "Staging",
    BlastRadius = "QA team only",

    Monitoring = "Full metrics dashboard",
    OnCall = "Team aware, not on-call"

var experiment = new ChaosExperiment

### Safety Checklist

**Before Every Experiment:**

```markdown
## Pre-Experiment Checklist

### System Health
- [ ] All systems are healthy (green dashboards)
- [ ] No ongoing incidents
- [ ] Recent deployments have stabilized
- [ ] Load is normal (not peak hours for first runs)

### Monitoring
- [ ] Metrics are being collected
- [ ] Dashboards are accessible
- [ ] Alerts are enabled
- [ ] Logs are aggregating correctly

### Team Readiness
- [ ] Team is aware of experiment
- [ ] On-call engineer is available
- [ ] Key stakeholders notified
- [ ] Communication channel is open (Slack, Teams)

### Safety Mechanisms
- [ ] Rollback procedure documented and tested
- [ ] Abort criteria defined
- [ ] Manual abort mechanism available
- [ ] Blast radius calculated and acceptable

### Experiment Details
- [ ] Hypothesis clearly stated
- [ ] Expected behavior documented
- [ ] Unexpected behavior (what to look for) documented
- [ ] Duration is reasonable (start small)

### Permissions & Compliance
- [ ] Experiment approved by necessary parties
- [ ] Doesn't violate SLAs or contracts
- [ ] Complies with regulatory requirements
- [ ] Customer impact assessed and acceptable
```

### Common Pitfalls and How to Avoid Them

#### Pitfall 1: No Rollback Plan

**Problem:** Chaos injected but no way to undo it.

**Solution:**
```csharp
// Always use try-finally for rollback
try
{
    await InjectChaos();
    await Task.Delay(experimentDuration);
}
finally
{
    await Rollback(); // Always executes
}
```

#### Pitfall 2: Insufficient Monitoring

**Problem:** Can't tell if experiment caused issues.

**Solution:**
```csharp
// Capture metrics before, during, and after
var before = await CaptureMetrics();
await RunExperiment();
var after = await CaptureMetrics();

CompareMetrics(before, after);
```

#### Pitfall 3: Too Large Initial Blast Radius

**Problem:** First experiment affects too many users.

**Solution:**
```csharp
// Start with smallest possible scope
var experiment = new ChaosExperiment
{
    Target = "1 instance out of 100", // 1%
    Duration = TimeSpan.FromMinutes(5), // Short
    InjectionRate = 0.1 // 10% of requests
};
```

#### Pitfall 4: No Abort Mechanism

**Problem:** Experiment causing issues but can't stop it.

**Solution:**
```csharp
// Always use cancellation tokens
public async Task RunExperiment(CancellationToken cancellationToken)
{
    while (!cancellationToken.IsCancellationRequested)
    {
        await InjectChaos();
        await Task.Delay(1000, cancellationToken);
    }
}
```

#### Pitfall 5: Running During Peak Hours

**Problem:** Experiment during high load amplifies issues.

**Solution:**
```csharp
// Schedule experiments carefully
if (DateTime.Now.Hour >= 2 && DateTime.Now.Hour <= 5)
{
    // Off-peak: safe to experiment
    await RunExperiment();
}
else
{
    _logger.LogWarning("Not running experiment during peak hours");
}
```

## Best Practices Summary

### ✅ Do's

1. **Always calculate blast radius** before experimenting
2. **Start small** and progressively increase scope
3. **Define abort criteria** before starting
4. **Monitor in real-time** during experiments
5. **Have rollback plans** that are tested
6. **Run off-peak initially** until confidence is built
7. **Communicate with team** before, during, and after
8. **Document everything** - hypothesis, results, learnings

### ❌ Don'ts

1. **Don't experiment without monitoring**
2. **Don't skip the rollback mechanism**
3. **Don't start with production** (dev/staging first)
4. **Don't use large blast radius initially**
5. **Don't run experiments during incidents**
6. **Don't forget to notify stakeholders**
7. **Don't continue experiments that are causing real issues**
8. **Don't experiment on systems you don't understand**
