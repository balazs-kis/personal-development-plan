## Learning Objectives

By the end of this lesson, you will be able to:

- Avoid common pitfalls that cause flaky tests

---

## Introduction

Test isolation is critical for reliable integration tests. Each test should run independently without affecting others, and all resources should be properly cleaned up afterward. Testcontainers provides powerful mechanisms for managing container lifecycle, but you need to understand best practices to avoid flaky tests, resource leaks, and performance issues.

## Key Concepts Summary

### The Resource Reaper

Testcontainers uses **Moby Ryuk** (Resource Reaper) to automatically clean up Docker resources:
- Removes containers after tests complete (success or failure)
- Cleans up networks and volumes
- Monitors the test process and cleans up if it crashes

**Important:** Never disable the Resource Reaper in production test suites. It's essential for keeping your environment clean.

### Test Isolation Best Practices

**1. Avoid Static Resource Names**

❌ **Bad:**
```csharp
var container = new ContainerBuilder()
    .WithImage("postgres:16")
    .WithName("test-db") // Static name causes conflicts
    .Build();
```

✅ **Good:**
```csharp
var container = new ContainerBuilder()
    .WithImage("postgres:16")
    // Let Testcontainers generate random names
    .Build();
```

**2. Use Random Port Bindings**

❌ **Bad:**
```csharp
var container = new ContainerBuilder()
    .WithImage("redis:7")
    .WithPortBinding(6379, 6379) // Fixed host port
    .Build();
```

✅ **Good:**
```csharp
var container = new ContainerBuilder()
    .WithImage("redis:7")
    .WithPortBinding(6379, true) // Random host port
    .Build();

// Get the mapped port
var port = container.GetMappedPublicPort(6379);
```

**3. Pin Container Image Versions**

❌ **Bad:**
```csharp
.WithImage("postgres:latest") // Unpredictable
```

✅ **Good:**
```csharp
.WithImage("postgres:16-alpine") // Specific version
```

**4. Use Container Hostname for Connections**

❌ **Bad:**
```csharp
var connectionString = $"Host=localhost;Port={port};...";
```

✅ **Good:**
```csharp
var connectionString = $"Host={container.Hostname};Port={port};...";
```

### Container Lifecycle Strategies

**Strategy 1: Container Per Test Class (Recommended for Most Cases)**

```csharp
public class ProductTests : IClassFixture<DatabaseFixture>, IAsyncLifetime
{
    private readonly DatabaseFixture _fixture;
    
    public ProductTests(DatabaseFixture fixture)
    {
        _fixture = fixture;
    }

    public Task InitializeAsync() => Task.CompletedTask;

    public async Task DisposeAsync()
    {
        // Clean database between tests
        await _fixture.ResetDatabaseAsync();
    }

    [Fact]
    public async Task Test1() { /* ... */ }

    [Fact]
    public async Task Test2() { /* ... */ }
}

public class DatabaseFixture : IAsyncLifetime
{
    private readonly PostgreSqlContainer _container = new PostgreSqlBuilder()
        .WithImage("postgres:16-alpine")
        .Build();
    
    public string ConnectionString => _container.GetConnectionString();

    public async Task InitializeAsync()
    {
        await _container.StartAsync();
        await ApplyMigrationsAsync();
    }

    public async Task DisposeAsync()
    {
        await _container.DisposeAsync();
    }

    public async Task ResetDatabaseAsync()
    {
        // Use Respawn or truncate tables
        await _respawner.ResetAsync(ConnectionString);
    }
}
```

**Strategy 2: Shared Container Across Test Classes (Faster, Less Isolation)**

```csharp
[CollectionDefinition("Database")]
public class DatabaseCollection : ICollectionFixture<DatabaseFixture>
{
    // This class has no code, and is never created
}

[Collection("Database")]
public class ProductTests
{
    private readonly DatabaseFixture _fixture;
    
    public ProductTests(DatabaseFixture fixture)
    {
        _fixture = fixture;
    }
    
    // Tests run with shared container
}

[Collection("Database")]
public class OrderTests
{
    // Also uses the same container
}
```

**Strategy 3: Container Per Test (Maximum Isolation, Slowest)**

```csharp
public class ProductTests
{
    [Fact]
    public async Task CreateProduct_SavesToDatabase()
    {
        // Arrange - New container for this test only
        await using var container = new PostgreSqlBuilder()
            .WithImage("postgres:16-alpine")
            .Build();
        
        await container.StartAsync();
        
        // Act & Assert
        // ...
    }
}
```

### Database Cleanup Strategies

**Option 1: Respawn (Fast, Recommended)**

```bash
dotnet add package Respawn
```

```csharp
private Respawner _respawner = null!;

public async Task InitializeAsync()
{
    await _container.StartAsync();
    
    _respawner = await Respawner.CreateAsync(
        _container.GetConnectionString(),
        new RespawnerOptions
        {
            DbAdapter = DbAdapter.Postgres,
            SchemasToInclude = new[] { "public" }
        });
}

public async Task ResetDatabaseAsync()
{
    await _respawner.ResetAsync(_container.GetConnectionString());
}
```

**Option 2: Transactions (Limited Use Cases)**

```csharp
public class TransactionalTests : IAsyncLifetime
{
    private DbTransaction? _transaction;
    
    public async Task InitializeAsync()
    {
        var connection = new NpgsqlConnection(_connectionString);
        await connection.OpenAsync();
        _transaction = await connection.BeginTransactionAsync();
    }
    
    public async Task DisposeAsync()
    {
        if (_transaction != null)
        {
            await _transaction.RollbackAsync();
            await _transaction.DisposeAsync();
        }
    }
}
```

**Option 3: Recreate Container (Slowest, Most Isolated)**

```csharp
public async Task DisposeAsync()
{
    await _container.DisposeAsync();
    _container = new PostgreSqlBuilder().Build();
    await _container.StartAsync();
}
```

### Container Reuse Pattern

For very fast test execution, you can reuse containers:

```csharp
private readonly PostgreSqlContainer _container = new PostgreSqlBuilder()
    .WithImage("postgres:16-alpine")
    .WithReuse(true) // Keep container running
    .WithLabel("testcontainers.reuse.id", "my-reusable-db")
    .Build();
```

**⚠️ Warning:** Reusable containers require manual cleanup and can cause issues if not managed carefully. Use with caution.

### Common Pitfalls

**1. Not Waiting for Container Readiness**

```csharp
// Bad - Container might not be ready
await container.StartAsync();
// Immediately use container - may fail!

// Good - Use wait strategies
var container = new PostgreSqlBuilder()
    .WithWaitStrategy(Wait.ForUnixContainer()
        .UntilPortIsAvailable(5432)
        .UntilCommandIsCompleted("pg_isready"))
    .Build();
```

**2. Hardcoding Connection Details**

Always get connection strings dynamically from the container.

**3. Not Cleaning Up Between Tests**

Each test should have a clean state. Use Respawn, transactions, or container recreation.
