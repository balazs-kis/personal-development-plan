## Introduction

Eventual consistency means that system state may not be immediately updated after an operation. Testing eventually consistent systems requires special techniques to wait for conditions without flaky tests or excessive delays.

## Key Concepts Summary

### Understanding Eventual Consistency

```
Synchronous (Strong Consistency):
Write → [Wait] → Read = Latest Value
✓ Simple to test
✗ Higher latency
✗ Lower availability

Eventually Consistent:
Write → Read = Old or New Value
✓ Lower latency
✓ Higher availability
✗ Complex to test ← This lesson addresses this
```

### The Polling Pattern

**Basic Polling Implementation:**
```csharp
public static async Task<T> WaitUntilAsync<T>(
    Func<Task<T>> check,
    Func<T, bool> condition,
    TimeSpan? timeout = null,
    TimeSpan? pollInterval = null,
    CancellationToken cancellationToken = default)
{
    timeout ??= TimeSpan.FromSeconds(30);
    pollInterval ??= TimeSpan.FromMilliseconds(100);

    using var cts = CancellationTokenSource
        .CreateLinkedTokenSource(cancellationToken);
    cts.CancelAfter(timeout.Value);

    var stopwatch = Stopwatch.StartNew();

    while (!cts.Token.IsCancellationRequested)
    {
        try
        {
            var result = await check();
            if (condition(result))
            {
                return result;
            }
        }
        catch (Exception) when (stopwatch.Elapsed < timeout)
        {
            // Ignore exceptions until timeout
        }

        await Task.Delay(pollInterval.Value, cts.Token);
    }

    throw new TimeoutException(
        $"Condition was not met within {timeout.Value.TotalSeconds}s");
}
```

### Using the Polling Pattern


### Enhanced Polling with Exponential Backoff

```csharp
public static async Task<T> WaitUntilWithBackoffAsync<T>(
    Func<Task<T>> check,
    Func<T, bool> condition,
    TimeSpan? timeout = null,
    TimeSpan? initialDelay = null,
    TimeSpan? maxDelay = null,
    double backoffMultiplier = 2.0,
    CancellationToken cancellationToken = default)
{
    timeout ??= TimeSpan.FromSeconds(30);
    initialDelay ??= TimeSpan.FromMilliseconds(100);
    maxDelay ??= TimeSpan.FromSeconds(5);

    using var cts = CancellationTokenSource
        .CreateLinkedTokenSource(cancellationToken);
    cts.CancelAfter(timeout.Value);

    var delay = initialDelay.Value;
    var stopwatch = Stopwatch.StartNew();

    while (!cts.Token.IsCancellationRequested)
    {
        try
        {
            var result = await check();
            if (condition(result))
            {
                return result;
            }
        }
        catch (Exception) when (stopwatch.Elapsed < timeout)
        {
            // Ignore exceptions until timeout
        }

        await Task.Delay(delay, cts.Token);

        // Exponential backoff with cap
        delay = TimeSpan.FromMilliseconds(
            Math.Min(delay.TotalMilliseconds * backoffMultiplier, 
                     maxDelay.Value.TotalMilliseconds));
    }

    throw new TimeoutException(
        $"Condition was not met within {timeout.Value.TotalSeconds}s");
}
```

### Fluent Assertion Helpers

```csharp
public static class EventualAssertions
{
    public static async Task ShouldEventuallyBe<T>(
        this Task<T> getValueTask,
        T expectedValue,
        TimeSpan? timeout = null,
        string because = null)
    {
        timeout ??= TimeSpan.FromSeconds(10);

        var result = await WaitUntilAsync(
            check: async () => await getValueTask,
            condition: value => EqualityComparer<T>.Default.Equals(value, expectedValue),
            timeout: timeout);

        Assert.Equal(expectedValue, result);
    }

    public static async Task ShouldEventuallySatisfy<T>(
        this Func<Task<T>> getValue,
        Func<T, bool> predicate,
        TimeSpan? timeout = null,
        string because = null)
    {
        timeout ??= TimeSpan.FromSeconds(10);

        var result = await WaitUntilAsync(
            check: getValue,
            condition: predicate,
            timeout: timeout);

        Assert.True(predicate(result), 
            because ?? "Expected condition was not satisfied");
    }

    public static async Task ShouldEventuallyNotBeNull<T>(
        this Func<Task<T>> getValue,
        TimeSpan? timeout = null)
        where T : class
    {
        timeout ??= TimeSpan.FromSeconds(10);

        var result = await WaitUntilAsync(
            check: getValue,
            condition: value => value != null,
            timeout: timeout);

        Assert.NotNull(result);
    }
}
```

### Using Polly for Retry Logic

```csharp
using Polly;
using Polly.Retry;

public class PollyTestHelpers
{
    public static async Task<T> WaitForAsync<T>(
        Func<Task<T>> operation,
        Func<T, bool> condition,
        TimeSpan? timeout = null,
        int maxRetries = 50)
    {
        timeout ??= TimeSpan.FromSeconds(30);
        var delayPerAttempt = timeout.Value.TotalMilliseconds / maxRetries;

        var pipeline = new ResiliencePipelineBuilder<T>()
            .AddRetry(new RetryStrategyOptions<T>
            {
                MaxRetryAttempts = maxRetries,
                Delay = TimeSpan.FromMilliseconds(delayPerAttempt),
                BackoffType = DelayBackoffType.Constant,
                ShouldHandle = new PredicateBuilder<T>()
                    .HandleResult(result => !condition(result))
            })
            .Build();

        return await pipeline.ExecuteAsync(async ct => await operation(), 
            CancellationToken.None);
    }
}

// Usage
[Fact]
public async Task ProcessOrder_EventuallyCompletes_UsingPolly()
{
    var orderId = Guid.NewGuid();
    await _orderService.CreateOrderAsync(orderId);
    await _orderProcessor.ProcessAsync(orderId);

    var order = await PollyTestHelpers.WaitForAsync(
        operation: async () => await _orderRepository.GetByIdAsync(orderId),
        condition: order => order?.Status == "Processed",
        timeout: TimeSpan.FromSeconds(10));

    Assert.Equal("Processed", order.Status);
}
```

### Best Practices

**1. Use Appropriate Timeouts:**
```csharp
// ✓ Good - Reasonable timeout
timeout: TimeSpan.FromSeconds(10)

// ✗ Bad - Too short, flaky tests
timeout: TimeSpan.FromMilliseconds(100)

// ✗ Bad - Too long, slow tests
timeout: TimeSpan.FromMinutes(5)
```

**2. Choose Appropriate Poll Intervals:**
```csharp
// ✓ Good - Fast operations
pollInterval: TimeSpan.FromMilliseconds(50)

// ✓ Good - Slow operations
pollInterval: TimeSpan.FromMilliseconds(500)

// ✗ Bad - Too frequent
pollInterval: TimeSpan.FromMilliseconds(1)

// ✗ Bad - Too infrequent
pollInterval: TimeSpan.FromSeconds(5)
```

**3. Handle Exceptions During Polling:**
```csharp
// ✓ Good - Ignore transient errors
try
{
    var result = await check();
    if (condition(result))
        return result;
}
catch (Exception) when (stopwatch.Elapsed < timeout)
{
    // Continue polling
}

// ✗ Bad - Fail on first exception
var result = await check(); // May throw before consistency
```

**4. Make Assertions Clear:**
```csharp
// ✓ Good - Clear intent
await WaitUntilAsync(
    check: async () => await GetOrder(id),
    condition: order => order.Status == "Processed",
    timeout: TimeSpan.FromSeconds(10));

// ✗ Bad - Hidden intent
await Task.Delay(5000);
var order = await GetOrder(id);
Assert.Equal("Processed", order.Status);
```

**5. Test Both Success and Timeout Cases:**
```csharp
// ✓ Good - Test timeout scenario
[Fact]
public async Task SlowOperation_TimesOut()
{
    await Assert.ThrowsAsync<TimeoutException>(async () =>
        await WaitUntilAsync(
            check: async () => await GetOrder(id),
            condition: order => order.Status == "NeverReached",
            timeout: TimeSpan.FromSeconds(1)));
}
```

### Common Pitfalls

**Pitfall 1: Fixed Delays**
```csharp
// ✗ Bad - Flaky and slow
await Task.Delay(5000); // Hope it's done
var result = await GetResult();

// ✓ Good - Poll until done
var result = await WaitUntilAsync(
    check: GetResult,
    condition: r => r.IsComplete);
```

**Pitfall 2: Insufficient Timeout**
```csharp
// ✗ Bad - May fail in CI
timeout: TimeSpan.FromMilliseconds(500)

// ✓ Good - Generous but not excessive
timeout: TimeSpan.FromSeconds(30)
```

**Pitfall 3: Not Handling Null**
```csharp
// ✗ Bad - NullReferenceException
condition: order => order.Status == "Processed"

// ✓ Good - Null-safe
condition: order => order?.Status == "Processed"
```
