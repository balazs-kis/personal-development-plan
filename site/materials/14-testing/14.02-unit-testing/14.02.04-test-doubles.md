## Learning Objectives

By the end of this lesson, you will be able to:
- Understand the different types of test doubles (mocks, stubs, fakes, dummies, spies)
- Use NSubstitute to create test doubles in .NET
- Know when to use mocks vs stubs vs fakes
- Write unit tests with external dependencies isolated
- Understand the sociable vs solitary testing debate

---

## Introduction

Unit tests should be fast, isolated, and reliable. But what do you do when the code you're testing depends on databases, external APIs, or other complex systems? Test doubles are the answer. They replace real dependencies with controlled substitutes, letting you test your code in isolation. This lesson covers what test doubles are, when to use each type, and how to implement them with NSubstitute.

## Key Concepts Summary

### What are Test Doubles?

**Test Double** is a generic term for any replacement of a production object for testing purposes. Think of them like stunt doubles in movies - they stand in for the real actor in certain scenes.

The five types of test doubles:
1. **Dummy** - Passed around but never used
2. **Stub** - Returns predefined responses
3. **Spy** - Records information about calls
4. **Mock** - Verifies behavior (method calls)
5. **Fake** - Working implementation, but simplified

### The Types Explained

**Dummy Objects**
```csharp
// Dummy - just to fill a parameter, never actually used
public void SendEmail(string to, string from, string subject, string body, 
    ILogger logger) // logger is never called in this test
{
    // Send email logic
}

[Fact]
public void SendEmail_ValidData_SendsSuccessfully()
{
    var emailService = new EmailService();
    var dummyLogger = Substitute.For<ILogger>(); // Won't be used
    
    emailService.SendEmail("to@test.com", "from@test.com", 
        "Subject", "Body", dummyLogger);
    
    // Assert email was sent (logger wasn't needed)
}
```

**Stubs**
```csharp
// Stub - provides canned answers to calls
public interface IWeatherService
{
    WeatherData GetWeather(string city);
}

[Fact]
public void DisplayWeather_SunnyDay_ShowsSunIcon()
{
    // Arrange - Stub returns predefined data
    var weatherStub = Substitute.For<IWeatherService>();
    weatherStub.GetWeather("London").Returns(new WeatherData 
    { 
        Condition = "Sunny", 
        Temperature = 25 
    });
    
    var display = new WeatherDisplay(weatherStub);
    
    // Act
    var result = display.Show("London");
    
    // Assert - Focus on state, not behavior
    result.Icon.Should().Be("☀️");
}
```

**Mocks**
```csharp
// Mock - verifies interactions (behavior verification)
public interface IEmailSender
{
    void SendEmail(string to, string subject, string body);
}

[Fact]
public void CreateOrder_Success_SendsConfirmationEmail()
{
    // Arrange
    var emailMock = Substitute.For<IEmailSender>();
    var orderService = new OrderService(emailMock);
    var order = new Order { CustomerEmail = "customer@test.com" };
    
    // Act
    orderService.CreateOrder(order);
    
    // Assert - Verify the interaction happened
    emailMock.Received(1).SendEmail(
        "customer@test.com",
        "Order Confirmation",
        Arg.Any<string>());
}
```

**Fakes**
```csharp
// Fake - working implementation, but simplified
public class FakeDatabase : IDatabase
{
    private Dictionary<int, User> _users = new();
    private int _nextId = 1;
    
    public void Add(User user)
    {
        user.Id = _nextId++;
        _users[user.Id] = user;
    }
    
    public User Get(int id)
    {
        return _users.TryGetValue(id, out var user) ? user : null;
    }
    
    public IEnumerable<User> GetAll()
    {
        return _users.Values;
    }
}

[Fact]
public void UserService_CreateUser_SavesUserToDatabase()
{
    // Arrange
    var fakeDb = new FakeDatabase();
    var service = new UserService(fakeDb);
    
    // Act
    service.CreateUser("Alice", "alice@test.com");
    
    // Assert
    fakeDb.GetAll().Should().ContainSingle();
}
```

**Spies**
```csharp
// Spy - records information about calls for later verification
public class SpyLogger : ILogger
{
    public List<string> LoggedMessages { get; } = new();
    
    public void Log(string message)
    {
        LoggedMessages.Add(message);
    }
}

[Fact]
public void ProcessOrder_LogsProcessingStep()
{
    // Arrange
    var loggerSpy = new SpyLogger();
    var service = new OrderService(loggerSpy);
    
    // Act
    service.ProcessOrder(order);
    
    // Assert
    loggerSpy.LoggedMessages.Should().Contain("Processing order");
}
```

### When to Use Each Type

| Type | Use When | Example |
|------|----------|---------|
| **Stub** | You need to control what a dependency returns | Test how your code handles different API responses |
| **Mock** | You need to verify a method was called | Verify an email was sent after registration |
| **Fake** | You need a working but simplified implementation | In-memory database for testing |
| **Spy** | You need to record interactions for later verification | Capture all log messages |
| **Dummy** | You need to pass a parameter that won't be used | Required constructor param that's not relevant |

**Most commonly used: Stubs and Mocks**

### NSubstitute Basics

**Installation:**
```bash
dotnet add package NSubstitute
```

**Creating a Substitute:**
```csharp
using NSubstitute;

// Create substitute for an interface
var calculator = Substitute.For<ICalculator>();

// Create substitute for a class with virtual members
var service = Substitute.For<OrderService>();

// Create substitute for multiple interfaces
var mock = Substitute.For<IDisposable, IComparable>();
```

**Setting Return Values (Stub Behavior):**
```csharp
// Simple return value
calculator.Add(1, 2).Returns(3);

// Return different values for different arguments
calculator.Add(1, 2).Returns(3);
calculator.Add(10, 20).Returns(30);

// Return value based on arguments
calculator.Add(Arg.Any<int>(), Arg.Any<int>())
    .Returns(x => (int)x[0] + (int)x[1]);

// Throw exception
calculator.Divide(Arg.Any<int>(), 0)
    .Returns(x => { throw new DivideByZeroException(); });

// Return sequence of values
calculator.GetNext()
    .Returns(1, 2, 3);  // First call returns 1, second returns 2, etc.
```

**Argument Matching:**
```csharp
// Any value
calculator.Add(Arg.Any<int>(), Arg.Any<int>()).Returns(5);

// Specific value
calculator.Add(1, 2).Returns(3);

// Conditional matching
calculator.Add(Arg.Is<int>(x => x > 0), Arg.Any<int>()).Returns(10);

// Matching with expressions
calculator.Add(Arg.Is<int>(x => x > 10 && x < 20), Arg.Any<int>());

// Custom matcher
calculator.Add(Arg.Is<int>(IsEven), Arg.Any<int>());

bool IsEven(int value) => value % 2 == 0;
```

**Verifying Calls (Mock Behavior):**
```csharp
// Verify method was called
calculator.Received().Add(1, 2);

// Verify method was called specific number of times
calculator.Received(2).Add(1, 2);

// Verify method was not called
calculator.DidNotReceive().Subtract(Arg.Any<int>(), Arg.Any<int>());

// Verify with argument matching
calculator.Received().Add(Arg.Any<int>(), Arg.Is<int>(x => x > 0));

// Verify call order
Received.InOrder(() =>
{
    calculator.Add(1, 2);
    calculator.Multiply(3, 4);
});
```

**Properties:**
```csharp
// Set property value
calculator.Mode.Returns("DEC");

// Or use property setter
calculator.Mode = "HEX";

// Verify property was set
calculator.Received().Mode = "DEC";
```

### Complete Examples

**Example 1: Testing with Stubs**
```csharp
public interface IUserRepository
{
    User GetById(int id);
}

public class UserService
{
    private readonly IUserRepository _repository;
    
    public UserService(IUserRepository repository)
    {
        _repository = repository;
    }
    
    public string GetUserGreeting(int userId)
    {
        var user = _repository.GetById(userId);
        return user != null 
            ? $"Hello, {user.Name}!" 
            : "User not found";
    }
}

public class UserServiceTests
{
    [Fact]
    public void GetUserGreeting_UserExists_ReturnsGreeting()
    {
        // Arrange
        var repositoryStub = Substitute.For<IUserRepository>();
        repositoryStub.GetById(1).Returns(new User { Id = 1, Name = "Alice" });
        
        var service = new UserService(repositoryStub);
        
        // Act
        var greeting = service.GetUserGreeting(1);
        
        // Assert
        greeting.Should().Be("Hello, Alice!");
    }
    
    [Fact]
    public void GetUserGreeting_UserDoesNotExist_ReturnsNotFound()
    {
        // Arrange
        var repositoryStub = Substitute.For<IUserRepository>();
        repositoryStub.GetById(999).Returns((User)null);
        
        var service = new UserService(repositoryStub);
        
        // Act
        var greeting = service.GetUserGreeting(999);
        
        // Assert
        greeting.Should().Be("User not found");
    }
}
```

**Example 2: Testing with Mocks**
```csharp
public interface IEmailService
{
    void SendEmail(string to, string subject, string body);
}

public interface IUserRepository
{
    void Add(User user);
}

public class RegistrationService
{
    private readonly IUserRepository _repository;
    private readonly IEmailService _emailService;
    
    public RegistrationService(IUserRepository repository, 
        IEmailService emailService)
    {
        _repository = repository;
        _emailService = emailService;
    }
    
    public void RegisterUser(string name, string email)
    {
        var user = new User { Name = name, Email = email };
        _repository.Add(user);
        _emailService.SendEmail(email, "Welcome!", $"Welcome, {name}!");
    }
}

public class RegistrationServiceTests
{
    [Fact]
    public void RegisterUser_ValidData_SavesUserAndSendsEmail()
    {
        // Arrange
        var repositoryMock = Substitute.For<IUserRepository>();
        var emailMock = Substitute.For<IEmailService>();
        var service = new RegistrationService(repositoryMock, emailMock);
        
        // Act
        service.RegisterUser("Alice", "alice@test.com");
        
        // Assert - Verify interactions
        repositoryMock.Received(1).Add(Arg.Is<User>(u => 
            u.Name == "Alice" && u.Email == "alice@test.com"));
        emailMock.Received(1).SendEmail(
            "alice@test.com",
            "Welcome!",
            "Welcome, Alice!");
    }
}
```

**Example 3: Combining Stubs and Mocks**
```csharp
[Fact]
public void ProcessOrder_OutOfStock_DoesNotChargeCustomer()
{
    // Arrange
    var inventoryStub = Substitute.For<IInventoryService>();
    inventoryStub.IsInStock("PROD-123").Returns(false);  // Stub behavior
    
    var paymentMock = Substitute.For<IPaymentService>();  // Mock for verification
    
    var orderService = new OrderService(inventoryStub, paymentMock);
    var order = new Order { ProductId = "PROD-123", Amount = 99.99m };
    
    // Act
    orderService.ProcessOrder(order);
    
    // Assert - Verify payment was NOT called
    paymentMock.DidNotReceive().Charge(Arg.Any<decimal>());
}
```

### Sociable vs Solitary Tests

**Solitary (London School)**
- Mock all dependencies
- Pure isolation
- Tests only one class

```csharp
[Fact]
public void Solitary_Example()
{
    var mockA = Substitute.For<IDependencyA>();
    var mockB = Substitute.For<IDependencyB>();
    var mockC = Substitute.For<IDependencyC>();
    
    var sut = new SystemUnderTest(mockA, mockB, mockC);
    // Test with all dependencies mocked
}
```

**Sociable (Detroit School)**
- Use real collaborators when practical
- Mock only slow/unstable dependencies
- Tests multiple classes together

```csharp
[Fact]
public void Sociable_Example()
{
    var realDependencyA = new DependencyA();
    var realDependencyB = new DependencyB();
    var mockExternalApi = Substitute.For<IExternalApi>(); // Mock only external
    
    var sut = new SystemUnderTest(realDependencyA, realDependencyB, mockExternalApi);
    // Test with mix of real and mocked dependencies
}
```

**Which approach?**
- Use sociable tests by default
- Mock when:
  - Dependency is slow (database, network)
  - Dependency is non-deterministic (random, time)
  - Dependency is hard to set up
  - You need to test error scenarios

### Best Practices

**✅ DO: Mock Interfaces, Not Concrete Classes**
```csharp
// ✅ Good
var mock = Substitute.For<IRepository>();

// ❌ Avoid (requires virtual members)
var mock = Substitute.For<ConcreteRepository>();
```

**✅ DO: Keep Test Setups Simple**
```csharp
// ✅ Good - Clear and simple
userRepository.GetById(1).Returns(new User { Name = "Alice" });

// ❌ Bad - Too complex
userRepository.GetById(Arg.Any<int>())
    .Returns(x => 
    {
        var id = (int)x[0];
        if (id > 100) throw new Exception();
        return new User { Id = id, Name = $"User{id}" };
    });
```

**✅ DO: Verify Important Interactions**
```csharp
// Verify critical side effects
emailService.Received().SendConfirmation(order.CustomerEmail);
```

**❌ DON'T: Over-Verify**
```csharp
// ❌ Bad - Testing implementation details
logger.Received().Log("Starting process");
logger.Received().Log("Step 1 complete");
logger.Received().Log("Step 2 complete");
logger.Received().Log("Process complete");
// Brittle - breaks if logging changes
```

**✅ DO: Use Arg.Any for Irrelevant Parameters**
```csharp
emailService.Received().SendEmail(
    "user@test.com",
    Arg.Any<string>(),  // Subject doesn't matter
    Arg.Any<string>());  // Body doesn't matter
```

```csharp
public interface IProductRepository
{
    Product GetById(int id);
    void Save(Product product);
}

public class ProductService
{
    private readonly IProductRepository _repository;
    
    public ProductService(IProductRepository repository)
    {
        _repository = repository;
    }
    
    public void UpdatePrice(int productId, decimal newPrice)
    {
        var product = _repository.GetById(productId);
        if (product == null)
            throw new NotFoundException($"Product {productId} not found");
            
        product.Price = newPrice;
        _repository.Save(product);
    }
}
```

Write tests for:
1. Happy path (product exists)
2. Product not found
3. Verify Save is called with correct product
