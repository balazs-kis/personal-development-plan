## Introduction

WebApplicationFactory is a testing utility in ASP.NET Core that creates an in-memory test server, allowing you to send real HTTP requests to your API without deploying it or starting a web server. This approach provides high-fidelity integration tests that verify your entire request/response pipeline—middleware, routing, authentication, controllers, and database interactions—while maintaining the speed and isolation benefits of unit tests.

## Key Concepts Summary

### What is WebApplicationFactory?

WebApplicationFactory is part of the `Microsoft.AspNetCore.Mvc.Testing` namespace and provides:
- **In-memory TestServer:** Runs your entire ASP.NET Core application within the test process
- **HttpClient integration:** Use standard HttpClient to make requests to your API
- **Dependency override capability:** Swap production dependencies with test doubles
- **Full pipeline testing:** Tests middleware, routing, model binding, validation, and authorization

### Setting Up WebApplicationFactory

Install the testing package:
```bash
dotnet add package Microsoft.AspNetCore.Mvc.Testing
```

Basic test class setup with xUnit:
```csharp
using Microsoft.AspNetCore.Mvc.Testing;

public class ApiTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly WebApplicationFactory<Program> _factory;

    public ApiTests(WebApplicationFactory<Program> factory)
    {
        _factory = factory;
    }

    [Fact]
    public async Task GetWeatherForecast_ReturnsSuccessStatusCode()
    {
        // Arrange
        var client = _factory.CreateClient();

        // Act
        var response = await client.GetAsync("/weatherforecast");

        // Assert
        response.EnsureSuccessStatusCode();
    }
}
```

**Important:** Your `Program` class must be accessible to tests. In .NET 6+, add this to your API project's `.csproj`:

```xml
<ItemGroup>
  <InternalsVisibleTo Include="YourTestProject" />
</ItemGroup>
```

Or make `Program` class public at the end of `Program.cs`:

```csharp
public partial class Program { }
```

### Customizing the Test Environment

Create a custom factory to override services:

```csharp
public class CustomWebApplicationFactory : WebApplicationFactory<Program>
{
    protected override void ConfigureWebHost(IWebHostBuilder builder)
    {
        builder.ConfigureServices(services =>
        {
            // Remove the production database
            var descriptor = services.SingleOrDefault(
                d => d.ServiceType == typeof(DbContextOptions<AppDbContext>));
            
            if (descriptor != null)
            {
                services.Remove(descriptor);
            }

            // Add in-memory database for testing
            services.AddDbContext<AppDbContext>(options =>
            {
                options.UseInMemoryDatabase("TestDb");
            });

            // Initialize the database
            var sp = services.BuildServiceProvider();
            using var scope = sp.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
            db.Database.EnsureCreated();
        });
    }
}
```

Use the custom factory in tests:

```csharp
public class ApiTests : IClassFixture<CustomWebApplicationFactory>
{
    private readonly CustomWebApplicationFactory _factory;

    public ApiTests(CustomWebApplicationFactory factory)
    {
        _factory = factory;
    }
}
```

### Making HTTP Requests

WebApplicationFactory provides an HttpClient configured to communicate with the in-memory test server:

```csharp
[Fact]
public async Task GetProducts_ReturnsProducts()
{
    // Arrange
    var client = _factory.CreateClient();

    // Act
    var response = await client.GetAsync("/api/products");

    // Assert
    response.EnsureSuccessStatusCode();
    
    var content = await response.Content.ReadAsStringAsync();
    var products = JsonSerializer.Deserialize<List<Product>>(
        content, 
        new JsonSerializerOptions { PropertyNameCaseInsensitive = true });
    
    products.Should().NotBeNull();
    products.Should().HaveCountGreaterThan(0);
}
```

### Testing Different HTTP Methods

**POST Request:**
```csharp
[Fact]
public async Task CreateProduct_ReturnsCreated()
{
    var client = _factory.CreateClient();
    
    var newProduct = new { Name = "Test Product", Price = 10.99 };
    var content = new StringContent(
        JsonSerializer.Serialize(newProduct),
        Encoding.UTF8,
        "application/json");

    var response = await client.PostAsync("/api/products", content);

    response.StatusCode.Should().Be(HttpStatusCode.Created);
}
```

**PUT Request:**
```csharp
[Fact]
public async Task UpdateProduct_ReturnsNoContent()
{
    var client = _factory.CreateClient();
    
    var updatedProduct = new { Id = 1, Name = "Updated", Price = 15.99 };
    var content = new StringContent(
        JsonSerializer.Serialize(updatedProduct),
        Encoding.UTF8,
        "application/json");

    var response = await client.PutAsync("/api/products/1", content);

    response.StatusCode.Should().Be(HttpStatusCode.NoContent);
}
```

**DELETE Request:**
```csharp
[Fact]
public async Task DeleteProduct_ReturnsNoContent()
{
    var client = _factory.CreateClient();

    var response = await client.DeleteAsync("/api/products/1");

    response.StatusCode.Should().Be(HttpStatusCode.NoContent);
}
```

### Configuration Override

Override configuration values for testing:

```csharp
protected override void ConfigureWebHost(IWebHostBuilder builder)
{
    builder.ConfigureAppConfiguration((context, config) =>
    {
        config.AddInMemoryCollection(new Dictionary<string, string>
        {
            ["ConnectionStrings:DefaultConnection"] = "TestConnectionString",
            ["ApiSettings:BaseUrl"] = "https://test-api.example.com",
            ["Features:EnableNewFeature"] = "true"
        });
    });
}
```

### Advantages and Trade-offs

**Advantages:**
- Tests the entire request/response pipeline
- Catches integration issues that unit tests miss
- No network overhead (in-memory test server)
- Easier to write than end-to-end tests
- Can customize the test environment

**Trade-offs:**
- Slower than unit tests (but much faster than E2E tests)
- More complex setup than unit tests
- Requires managing test data and state
- Can't test JavaScript/frontend behavior (use Playwright for that)

1. Sets up a custom WebApplicationFactory with an in-memory database
2. Tests GET /api/todos returns an empty list initially
