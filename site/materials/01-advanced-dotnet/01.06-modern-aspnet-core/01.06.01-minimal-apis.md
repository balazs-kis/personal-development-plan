## Introduction

Minimal APIs represent a simplified approach to building HTTP APIs in ASP.NET Core. Introduced in .NET 6, they allow you to create fully functioning REST endpoints with significantly less code and ceremony than traditional controller-based APIs. This makes them ideal for microservices, small applications, and scenarios where you want to minimize dependencies and configuration overhead.

## Key Concepts Summary

### What are Minimal APIs?

Minimal APIs are a simplified approach for building HTTP APIs with ASP.NET Core:

**Traditional Controller-Based API:**
```csharp
// Requires:
// - Controller class
// - Action methods
// - Routing attributes
// - Model binding
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public ActionResult<IEnumerable<Product>> GetProducts()
    {
        return Ok(products);
    }
}
```

**Minimal API:**
```csharp
// Simple, direct approach
var app = WebApplication.Create(args);

app.MapGet("/api/products", () => products);

app.Run();
```

**Key Characteristics:**
- No controllers or action methods
- Minimal boilerplate code
- Fluent route definition
- Built-in Swagger/OpenAPI support
- Full dependency injection support

### Why Use Minimal APIs?

**Benefits:**

**1. Simplicity**
- Less ceremony, less code
- Faster to prototype
- Easier for beginners

**2. Performance**
- Lower memory footprint
- Faster startup time
- Reduced allocations

**3. Microservices-Friendly**
- Perfect for small, focused services
- Minimal dependencies
- Easier to containerize

**4. Modern C# Features**
- Leverages top-level statements
- Uses lambda expressions
- Supports modern patterns

**When to Choose Minimal APIs:**
```
✅ Use Minimal APIs when:
   - Building microservices
   - Creating small, focused APIs
   - Rapid prototyping
   - Learning web development
   - Performance is critical
   - Want minimal dependencies

❌ Stick with Controllers when:
   - Large, complex applications
   - Need advanced features (filters, model validation)
   - Team prefers traditional structure
   - Existing controller-based codebase
   - Need separation of concerns at class level
```

### Basic Minimal API Structure

**Minimal Program Structure:**

```csharp
var builder = WebApplication.CreateBuilder(args);

// Add services to DI container
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

// Configure middleware pipeline
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

app.UseHttpsRedirection();

// Define endpoints
app.MapGet("/", () => "Hello World!");

app.Run();
```

**Three Main Sections:**
1. **Builder** - Configure services
2. **App** - Configure middleware
3. **Endpoints** - Define routes

### Creating CRUD Endpoints

#### GET - Retrieve Data

```csharp
// Get all items
app.MapGet("/api/todos", async (TodoDb db) =>
{
    return await db.Todos.ToListAsync();
});

// Get single item
app.MapGet("/api/todos/{id}", async (int id, TodoDb db) =>
{
    var todo = await db.Todos.FindAsync(id);
    return todo is not null ? Results.Ok(todo) : Results.NotFound();
});
```

#### POST - Create Data

```csharp
app.MapPost("/api/todos", async (Todo todo, TodoDb db) =>
{
    db.Todos.Add(todo);
    await db.SaveChangesAsync();
    
    return Results.Created($"/api/todos/{todo.Id}", todo);
});
```

#### PUT - Update Data

```csharp
app.MapPut("/api/todos/{id}", async (int id, Todo inputTodo, TodoDb db) =>
{
    var todo = await db.Todos.FindAsync(id);
    
    if (todo is null) return Results.NotFound();
    
    todo.Title = inputTodo.Title;
    todo.IsComplete = inputTodo.IsComplete;
    
    await db.SaveChangesAsync();
    
    return Results.NoContent();
});
```

#### DELETE - Remove Data

```csharp
app.MapDelete("/api/todos/{id}", async (int id, TodoDb db) =>
{
    var todo = await db.Todos.FindAsync(id);
    
    if (todo is null) return Results.NotFound();
    
    db.Todos.Remove(todo);
    await db.SaveChangesAsync();
    
    return Results.NoContent();
});
```

### Results Helpers

Minimal APIs provide `Results` class for typed responses:

```csharp
// Success responses
Results.Ok(data)                    // 200 OK
Results.Created(uri, data)          // 201 Created
Results.Accepted(uri, data)         // 202 Accepted
Results.NoContent()                 // 204 No Content

// Client error responses
Results.BadRequest(error)           // 400 Bad Request
Results.NotFound()                  // 404 Not Found
Results.Conflict()                  // 409 Conflict
Results.UnprocessableEntity(error)  // 422 Unprocessable Entity

// Can also return data directly
return data;                        // Implicit 200 OK
```

### Parameter Binding

Minimal APIs automatically bind parameters from various sources:

#### Automatic Binding Sources

```csharp
app.MapGet("/api/products/{id}", 
    (int id,                        // From route
     int page,                      // From query string (?page=1)
     IProductService service) =>    // From DI container
{
    return service.GetProducts(id, page);
});
```

**Binding Rules:**
- Route values: `{id}` in route template
- Query string: Not in route, simple types
- Headers: Complex types with `[FromHeader]`
- Body: Complex types (JSON) for POST/PUT
- Services: Registered in DI container
- Special types: `HttpContext`, `HttpRequest`, `HttpResponse`, `ClaimsPrincipal`, `CancellationToken`

#### Explicit Binding

```csharp
using Microsoft.AspNetCore.Mvc;

app.MapPost("/api/products",
    ([FromBody] Product product,        // Explicit: from body
     [FromHeader(Name = "X-Api-Key")] string apiKey,  // From header
     [FromServices] IProductService service) =>       // From DI
{
    return service.CreateProduct(product);
});
```

### Dependency Injection

Services are injected directly into route handlers:

```csharp
// Register service
builder.Services.AddScoped<IProductRepository, ProductRepository>();

// Inject into handler
app.MapGet("/api/products", (IProductRepository repo) =>
{
    return repo.GetAll();
});

// Multiple services
app.MapPost("/api/products", 
    (Product product, 
     IProductRepository repo,
     ILogger<Program> logger) =>
{
    logger.LogInformation("Creating product");
    repo.Add(product);
    return Results.Created($"/api/products/{product.Id}", product);
});
```

### Route Patterns and Constraints

```csharp
// Basic route
app.MapGet("/api/products", () => products);

// Route parameter
app.MapGet("/api/products/{id}", (int id) => GetProduct(id));

// Multiple parameters
app.MapGet("/api/categories/{category}/products/{id}", 
    (string category, int id) => GetProduct(category, id));

// Route constraints
app.MapGet("/api/products/{id:int}", (int id) => GetProduct(id));
app.MapGet("/api/products/{name:alpha}", (string name) => GetByName(name));
app.MapGet("/api/products/{id:range(1,100)}", (int id) => GetProduct(id));

// Optional parameters
app.MapGet("/api/products/{id:int?}", (int? id) => 
    id.HasValue ? GetProduct(id.Value) : GetAllProducts());
```

### Grouping Routes

**Route Groups** help organize related endpoints:

```csharp
var todos = app.MapGroup("/api/todos");

todos.MapGet("/", GetAllTodos);
todos.MapGet("/{id}", GetTodo);
todos.MapPost("/", CreateTodo);
todos.MapPut("/{id}", UpdateTodo);
todos.MapDelete("/{id}", DeleteTodo);

// With common configuration
var todos = app.MapGroup("/api/todos")
    .RequireAuthorization()
    .WithOpenApi();

todos.MapGet("/", GetAllTodos);
todos.MapPost("/", CreateTodo);
```

### OpenAPI/Swagger Integration

Minimal APIs have built-in Swagger support:

```csharp
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

// Endpoints are automatically documented
app.MapGet("/api/todos", () => todos)
    .WithName("GetAllTodos")
    .WithOpenApi();

app.MapPost("/api/todos", (Todo todo) => CreateTodo(todo))
    .WithName("CreateTodo")
    .WithOpenApi(operation =>
    {
        operation.Summary = "Create a new todo item";
        operation.Description = "Creates a new todo item in the system";
        return operation;
    });
```

### Validation

Basic validation approaches in Minimal APIs:

#### Manual Validation

```csharp
app.MapPost("/api/todos", (Todo todo, TodoDb db) =>
{
    if (string.IsNullOrWhiteSpace(todo.Title))
    {
        return Results.BadRequest("Title is required");
    }
    
    if (todo.Title.Length > 100)
    {
        return Results.BadRequest("Title too long");
    }
    
    db.Todos.Add(todo);
    db.SaveChanges();
    
    return Results.Created($"/api/todos/{todo.Id}", todo);
});
```

#### Using Data Annotations

```csharp
using System.ComponentModel.DataAnnotations;

public record Todo
{
    [Required]
    [StringLength(100)]
    public string Title { get; init; } = string.Empty;
    
    public bool IsComplete { get; init; }
}

// Validation in handler
app.MapPost("/api/todos", (Todo todo, TodoDb db) =>
{
    var validationResults = new List<ValidationResult>();
    var context = new ValidationContext(todo);
    
    if (!Validator.TryValidateObject(todo, context, validationResults, true))
    {
        return Results.ValidationProblem(
            validationResults.ToDictionary(
                r => r.MemberNames.First(),
                r => new[] { r.ErrorMessage! }
            ));
    }
    
    db.Todos.Add(todo);
    db.SaveChanges();
    
    return Results.Created($"/api/todos/{todo.Id}", todo);
});
```

### Error Handling

```csharp
// Global exception handler (middleware)
app.UseExceptionHandler(exceptionHandlerApp =>
{
    exceptionHandlerApp.Run(async context =>
    {
        context.Response.StatusCode = StatusCodes.Status500InternalServerError;
        context.Response.ContentType = "application/json";
        
        var error = context.Features.Get<IExceptionHandlerFeature>();
        
        if (error != null)
        {
            await context.Response.WriteAsJsonAsync(new
            {
                error = "An error occurred processing your request",
                detail = error.Error.Message
            });
        }
    });
});

// Per-endpoint error handling
app.MapGet("/api/todos/{id}", async (int id, TodoDb db) =>
{
    try
    {
        var todo = await db.Todos.FindAsync(id);
        return todo is not null ? Results.Ok(todo) : Results.NotFound();
    }
    catch (Exception ex)
    {
        return Results.Problem(ex.Message);
    }
});
```

public class TodoApiTests : IClassFixture<WebApplicationFactory<Program>>

### Best Practices

**1. Keep Handlers Simple**
```csharp
❌ Don't: Put complex logic in handlers
app.MapGet("/api/products", async (ProductDb db) =>
{
    // Complex business logic here...
    // Data transformation...
    // Multiple database calls...
});

✅ Do: Extract to services
app.MapGet("/api/products", async (IProductService service) =>
{
    return await service.GetProductsAsync();
});
```

**2. Use Route Groups for Organization**
```csharp
✅ Good: Organized with groups
var api = app.MapGroup("/api");
var products = api.MapGroup("/products");
var orders = api.MapGroup("/orders");

products.MapGet("/", GetProducts);
orders.MapGet("/", GetOrders);
```

**3. Leverage Dependency Injection**
```csharp
✅ Good: Services from DI
app.MapGet("/api/products", 
    (IProductRepository repo, ILogger<Program> logger) =>
{
    logger.LogInformation("Fetching products");
    return repo.GetAll();
});
```

**4. Return Typed Results**
```csharp
✅ Good: Explicit results
app.MapGet("/api/products/{id}", async (int id, ProductDb db) =>
{
    var product = await db.Products.FindAsync(id);
    return product is not null 
        ? Results.Ok(product) 
        : Results.NotFound();
});
```

**5. Document with OpenAPI**
```csharp
✅ Good: Well-documented API
app.MapPost("/api/products", CreateProduct)
    .WithName("CreateProduct")
    .WithTags("Products")
    .Produces<Product>(StatusCodes.Status201Created)
    .Produces(StatusCodes.Status400BadRequest)
    .WithOpenApi();
```

public record Book(int Id, string Title, string Author, int Year);
