## Introduction

Endpoint filters and rate limiting are essential features for building production-ready APIs. Filters allow you to execute common logic before and after endpoint handlers, enabling cross-cutting concerns like validation, logging, and authorization. Rate limiting protects your API from abuse by controlling how many requests clients can make. Together, these features help you build secure, reliable, and maintainable APIs.

## Key Concepts Summary

### What are Endpoint Filters?

Endpoint filters allow you to run code before and after route handlers execute:

```
Request → Middleware → [Endpoint Filter 1] → [Endpoint Filter 2] → Handler
                                                                       ↓
Response ← Middleware ← [Endpoint Filter 2] ← [Endpoint Filter 1] ← Return
```

**Key Characteristics:**
- Run per-endpoint (unlike middleware which runs for all requests)
- Have context about the specific endpoint
- Can inspect and modify parameters
- Can short-circuit the pipeline
- Can modify the response

### Filters vs. Middleware

| Feature | Middleware | Endpoint Filters |
|---------|-----------|------------------|
| **Scope** | Global (all requests) | Per-endpoint |
| **Context** | General HTTP context | Endpoint-specific context |
| **Registration** | Pipeline-level | Endpoint-level |
| **Use Case** | Cross-cutting (logging, CORS) | Endpoint-specific (validation) |
| **Order** | Fixed pipeline order | Configurable per endpoint |

**When to Use Each:**
```
Use Middleware for:
✅ Authentication/Authorization (app-wide)
✅ CORS
✅ Response compression
✅ Request logging (all requests)

Use Endpoint Filters for:
✅ Input validation (specific endpoints)
✅ Request/response transformation
✅ Endpoint-specific logging
✅ Parameter preprocessing
```

### Creating Inline Filters

**Basic Inline Filter:**

```csharp
app.MapGet("/api/todos/{id}", (int id) => GetTodo(id))
    .AddEndpointFilter(async (context, next) =>
    {
        // Before handler
        var id = context.GetArgument<int>(0);
        
        if (id <= 0)
        {
            return Results.BadRequest("ID must be positive");
        }
        
        // Call next filter or handler
        var result = await next(context);
        
        // After handler (modify response if needed)
        return result;
    });
```

**Key Components:**
- `context` - `EndpointFilterInvocationContext` with request details and arguments
- `next` - Delegate to call the next filter or handler
- Return value - The response to send to client

### Creating Class-Based Filters

**Implement IEndpointFilter:**

```csharp
public class ValidationFilter : IEndpointFilter
{
    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext context,
        EndpointFilterDelegate next)
    {
        // Access arguments
        var todo = context.GetArgument<Todo>(0);
        
        // Validation logic
        if (string.IsNullOrEmpty(todo.Title))
        {
            return Results.ValidationProblem(new Dictionary<string, string[]>
            {
                { "Title", new[] { "Title is required" } }
            });
        }
        
        // Continue pipeline
        return await next(context);
    }
}

// Apply the filter
app.MapPost("/api/todos", (Todo todo) => CreateTodo(todo))
    .AddEndpointFilter<ValidationFilter>();
```

**Benefits of Class-Based Filters:**
- Reusable across multiple endpoints
- Supports dependency injection
- Easier to test
- Better organization

### Filters with Dependency Injection

```csharp
public class LoggingFilter : IEndpointFilter
{
    private readonly ILogger<LoggingFilter> _logger;

    public LoggingFilter(ILogger<LoggingFilter> logger)
    {
        _logger = logger;
    }

    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext context,
        EndpointFilterDelegate next)
    {
        var endpoint = context.HttpContext.GetEndpoint()?.DisplayName;
        _logger.LogInformation("Executing endpoint: {Endpoint}", endpoint);
        
        var sw = Stopwatch.StartNew();
        var result = await next(context);
        sw.Stop();
        
        _logger.LogInformation("Endpoint {Endpoint} completed in {Ms}ms", 
            endpoint, sw.ElapsedMilliseconds);
        
        return result;
    }
}

// Services are injected automatically
app.MapGet("/api/todos", GetTodos)
    .AddEndpointFilter<LoggingFilter>();
```

### Chaining Multiple Filters

Filters execute in the order they're added:

```csharp
app.MapPost("/api/todos", CreateTodo)
    .AddEndpointFilter<AuthorizationFilter>()   // 1st: Check auth
    .AddEndpointFilter<ValidationFilter>()      // 2nd: Validate input
    .AddEndpointFilter<LoggingFilter>();        // 3rd: Log request

// Execution flow:
// Request → Auth → Validation → Logging → Handler → Logging → Validation → Auth → Response
```

### Practical Filter Examples

#### 1. Validation Filter

```csharp
public class ModelValidationFilter : IEndpointFilter
{
    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext context,
        EndpointFilterDelegate next)
    {
        // Find the first parameter that's not a service
        var modelArgument = context.Arguments
            .FirstOrDefault(arg => arg?.GetType().IsClass == true 
                && !arg.GetType().Namespace?.StartsWith("Microsoft") == true);
        
        if (modelArgument == null)
            return await next(context);
        
        // Validate using DataAnnotations
        var validationContext = new ValidationContext(modelArgument);
        var validationResults = new List<ValidationResult>();
        
        if (!Validator.TryValidateObject(modelArgument, validationContext, 
            validationResults, validateAllProperties: true))
        {
            return Results.ValidationProblem(
                validationResults.ToDictionary(
                    vr => vr.MemberNames.First(),
                    vr => new[] { vr.ErrorMessage! }
                ));
        }
        
        return await next(context);
    }
}
```

#### 2. API Key Authorization Filter

```csharp
public class ApiKeyFilter : IEndpointFilter
{
    private const string ApiKeyHeader = "X-Api-Key";
    private readonly IConfiguration _configuration;

    public ApiKeyFilter(IConfiguration configuration)
    {
        _configuration = configuration;
    }

    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext context,
        EndpointFilterDelegate next)
    {
        if (!context.HttpContext.Request.Headers.TryGetValue(ApiKeyHeader, out var extractedApiKey))
        {
            return Results.Unauthorized();
        }

        var apiKey = _configuration.GetValue<string>("ApiKey");
        
        if (!apiKey.Equals(extractedApiKey))
        {
            return Results.Unauthorized();
        }

        return await next(context);
    }
}
```

#### 3. Response Caching Filter

```csharp
public class CachingFilter : IEndpointFilter
{
    private readonly IMemoryCache _cache;

    public CachingFilter(IMemoryCache cache)
    {
        _cache = cache;
    }

    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext context,
        EndpointFilterDelegate next)
    {
        var cacheKey = context.HttpContext.Request.Path.ToString();
        
        if (_cache.TryGetValue(cacheKey, out object? cachedResult))
        {
            return cachedResult;
        }

        var result = await next(context);
        
        _cache.Set(cacheKey, result, TimeSpan.FromMinutes(5));
        
        return result;
    }
}
```

### Applying Filters to Route Groups

```csharp
// Apply to all endpoints in a group
var securedApi = app.MapGroup("/api/admin")
    .AddEndpointFilter<AuthorizationFilter>()
    .AddEndpointFilter<LoggingFilter>();

securedApi.MapGet("/users", GetUsers);
securedApi.MapGet("/settings", GetSettings);
// Both endpoints have auth and logging filters
```

## Rate Limiting

### What is Rate Limiting?

Rate limiting controls the number of requests a client can make to your API within a time period:

**Without Rate Limiting:**
```
Client → Unlimited Requests → API → Server Overload 💥
```

**With Rate Limiting:**
```
Client → Rate Limiter → [Allowed] → API
                      → [Denied] → 429 Too Many Requests
```

**Benefits:**
1. **Security** - Protect against DDoS and brute force attacks
2. **Fairness** - Ensure all users get fair access
3. **Cost Control** - Limit resource consumption
4. **Quality of Service** - Maintain performance under load

### Built-in Rate Limiting (ASP.NET Core 7+)

ASP.NET Core includes native rate limiting middleware:

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddFixedWindowLimiter("fixed", options =>
    {
        options.Window = TimeSpan.FromSeconds(10);
        options.PermitLimit = 5;
        options.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
        options.QueueLimit = 2;
    });
});

var app = builder.Build();

app.UseRateLimiter();

app.MapGet("/api/todos", GetTodos)
    .RequireRateLimiting("fixed");
```

### Rate Limiting Algorithms

#### 1. Fixed Window

Allows X requests per fixed time window:

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddFixedWindowLimiter("fixed", options =>
    {
        options.Window = TimeSpan.FromMinutes(1);
        options.PermitLimit = 100;  // 100 requests per minute
    });
});
```

**Behavior:**
```
Window 1 (0-60s):   100 requests allowed
Window 2 (60-120s): 100 requests allowed (counter resets)

Problem: Burst at boundary
- 100 requests at t=59s ✅
- 100 requests at t=61s ✅
- Total: 200 requests in 2 seconds!
```

**Best for:** Simple scenarios, low traffic

#### 2. Sliding Window

Smoother distribution over time:

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddSlidingWindowLimiter("sliding", options =>
    {
        options.Window = TimeSpan.FromMinutes(1);
        options.PermitLimit = 100;
        options.SegmentsPerWindow = 6;  // 6 segments of 10 seconds each
    });
});
```

**Behavior:**
```
Continuously checks the last 60 seconds
Each segment tracks requests independently
Prevents boundary burst issues

Time windows overlap and slide forward
```

**Best for:** Production APIs, fair distribution

#### 3. Token Bucket

Allows bursts while maintaining average rate:

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddTokenBucketLimiter("token", options =>
    {
        options.TokenLimit = 100;              // Bucket capacity
        options.ReplenishmentPeriod = TimeSpan.FromSeconds(10);
        options.TokensPerPeriod = 20;          // Refill 20 tokens every 10s
        options.AutoReplenishment = true;
    });
});
```

**Behavior:**
```
Bucket holds 100 tokens
Each request consumes 1 token
Tokens refill at steady rate (20 every 10s)

Allows bursts up to bucket capacity
Then rate-limited to refill rate
```

**Best for:** APIs that need to allow bursts

#### 4. Concurrency Limiter

Limits simultaneous requests:

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddConcurrencyLimiter("concurrent", options =>
    {
        options.PermitLimit = 10;              // Max 10 concurrent requests
        options.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
        options.QueueLimit = 5;                // Queue up to 5 more
    });
});
```

**Behavior:**
```
Allows 10 simultaneous requests
11th request waits in queue
Once a request completes, next in queue proceeds

Different from rate limiting by time
```

**Best for:** Resource-intensive endpoints, preventing overload

### Per-Endpoint Rate Limiting

```csharp
// Different limits for different endpoints
builder.Services.AddRateLimiter(options =>
{
    options.AddFixedWindowLimiter("strict", opt =>
    {
        opt.Window = TimeSpan.FromMinutes(1);
        opt.PermitLimit = 10;
    });
    
    options.AddFixedWindowLimiter("lenient", opt =>
    {
        opt.Window = TimeSpan.FromMinutes(1);
        opt.PermitLimit = 100;
    });
});

// Apply different policies
app.MapPost("/api/auth/login", Login)
    .RequireRateLimiting("strict");     // 10 per minute

app.MapGet("/api/products", GetProducts)
    .RequireRateLimiting("lenient");    // 100 per minute
```

### Global Rate Limiting

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(
        httpContext =>
        {
            // Partition by IP address
            var ipAddress = httpContext.Connection.RemoteIpAddress?.ToString() ?? "unknown";
            
            return RateLimitPartition.GetFixedWindowLimiter(
                partitionKey: ipAddress,
                factory: _ => new FixedWindowRateLimiterOptions
                {
                    PermitLimit = 100,
                    Window = TimeSpan.FromMinutes(1)
                });
        });
});
```

### Partitioning Strategies

Rate limit by different criteria:

#### 1. By IP Address

```csharp
options.AddPolicy("byIp", httpContext =>
{
    var ip = httpContext.Connection.RemoteIpAddress?.ToString() ?? "unknown";
    
    return RateLimitPartition.GetSlidingWindowLimiter(ip, _ =>
        new SlidingWindowRateLimiterOptions
        {
            PermitLimit = 100,
            Window = TimeSpan.FromMinutes(1),
            SegmentsPerWindow = 6
        });
});
```

#### 2. By User ID

```csharp
options.AddPolicy("byUser", httpContext =>
{
    var userId = httpContext.User.FindFirst("sub")?.Value ?? "anonymous";
    
    return RateLimitPartition.GetTokenBucketLimiter(userId, _ =>
        new TokenBucketRateLimiterOptions
        {
            TokenLimit = 1000,
            ReplenishmentPeriod = TimeSpan.FromHours(1),
            TokensPerPeriod = 1000,
            AutoReplenishment = true
        });
});
```

#### 3. By API Key

```csharp
options.AddPolicy("byApiKey", httpContext =>
{
    var apiKey = httpContext.Request.Headers["X-Api-Key"].ToString();
    var tier = GetApiTier(apiKey);  // free, pro, enterprise
    
    return tier switch
    {
        "free" => RateLimitPartition.GetFixedWindowLimiter("free", _ =>
            new FixedWindowRateLimiterOptions
            {
                PermitLimit = 100,
                Window = TimeSpan.FromHours(1)
            }),
        "pro" => RateLimitPartition.GetFixedWindowLimiter("pro", _ =>
            new FixedWindowRateLimiterOptions
            {
                PermitLimit = 1000,
                Window = TimeSpan.FromHours(1)
            }),
        _ => RateLimitPartition.GetNoLimiter("enterprise")
    };
});
```

### Configuring Rate Limit Responses

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
    
    options.OnRejected = async (context, cancellationToken) =>
    {
        context.HttpContext.Response.StatusCode = StatusCodes.Status429TooManyRequests;
        
        if (context.Lease.TryGetMetadata(MetadataName.RetryAfter, out var retryAfter))
        {
            context.HttpContext.Response.Headers.RetryAfter = 
                retryAfter.TotalSeconds.ToString();
        }
        
        await context.HttpContext.Response.WriteAsJsonAsync(new
        {
            error = "Too many requests",
            message = "Please try again later",
            retryAfter = retryAfter?.TotalSeconds
        }, cancellationToken);
    };
});
```

### Combining Filters and Rate Limiting

```csharp
var api = app.MapGroup("/api");

// Apply filters and rate limiting together
api.MapPost("/todos", CreateTodo)
    .AddEndpointFilter<ValidationFilter>()
    .AddEndpointFilter<LoggingFilter>()
    .RequireRateLimiting("strict");

// Order matters:
// 1. Rate limiting (reject if limit exceeded)
// 2. Filters (validation, logging)
// 3. Handler
```
