## Introduction

Dependency Injection (DI) and configuration management are foundational to building maintainable ASP.NET Core applications. ASP.NET Core has DI built into its core, making it easy to manage dependencies, test code, and follow SOLID principles. The Options pattern provides a clean, type-safe way to work with configuration data. Understanding these concepts deeply will help you build applications that are testable, maintainable, and follow industry best practices.

## Key Concepts Summary

### Dependency Injection Fundamentals

**What is Dependency Injection?**

Dependency Injection is a design pattern where objects receive their dependencies from external sources rather than creating them:

```csharp
❌ Without DI (tight coupling):
public class OrderService
{
    private readonly EmailService _emailService;
    
    public OrderService()
    {
        _emailService = new EmailService();  // Creates dependency directly
    }
}

✅ With DI (loose coupling):
public class OrderService
{
    private readonly IEmailService _emailService;
    
    public OrderService(IEmailService emailService)  // Dependency injected
    {
        _emailService = emailService;
    }
}
```

**Benefits:**
1. **Loose Coupling** - Depend on abstractions, not concrete types
2. **Testability** - Easy to inject mock dependencies
3. **Maintainability** - Change implementations without changing consumers
4. **Lifetime Management** - Framework handles object creation and disposal

### Service Lifetimes

ASP.NET Core provides three service lifetimes:

#### 1. Transient

**Created every time they're requested**

```csharp
builder.Services.AddTransient<IEmailService, EmailService>();
```

**Characteristics:**
- New instance for each request/injection
- Best for lightweight, stateless services
- No shared state between uses

**When to Use:**
```
✅ Use Transient for:
   - Lightweight services
   - Stateless operations
   - Services used briefly
   - Thread-safety not a concern (each gets own instance)
```

**Example:**
```csharp
public interface IEmailService
{
    Task SendEmailAsync(string to, string subject, string body);
}

public class EmailService : IEmailService
{
    public async Task SendEmailAsync(string to, string subject, string body)
    {
        // Send email - stateless operation
        await Task.CompletedTask;
    }
}

// Registration
builder.Services.AddTransient<IEmailService, EmailService>();

// Usage: New instance each time
public class OrderService
{
    private readonly IEmailService _emailService;  // New instance
    
    public OrderService(IEmailService emailService)
    {
        _emailService = emailService;
    }
}
```

#### 2. Scoped

**Created once per request (or scope)**

```csharp
builder.Services.AddScoped<IOrderService, OrderService>();
```

**Characteristics:**
- One instance per HTTP request
- Shared within the same request
- Disposed at end of request

**When to Use:**
```
✅ Use Scoped for:
   - Database contexts (DbContext)
   - Repository pattern implementations
   - Per-request data or state
   - Services that should be consistent within a request
```

**Example:**
```csharp
// DbContext is always scoped
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(connectionString));

builder.Services.AddScoped<IOrderRepository, OrderRepository>();
builder.Services.AddScoped<IOrderService, OrderService>();

// Within a single request:
public class OrderController : ControllerBase
{
    private readonly IOrderService _orderService;
    private readonly IOrderRepository _orderRepository;
    
    // Both get the SAME DbContext instance within this request
    public OrderController(
        IOrderService orderService,
        IOrderRepository orderRepository)
    {
        _orderService = orderService;
        _orderRepository = orderRepository;
    }
}
```

#### 3. Singleton

**Created once for the application lifetime**

```csharp
builder.Services.AddSingleton<ICacheService, CacheService>();
```

**Characteristics:**
- One instance for entire application
- Created on first request (or at startup if eager)
- Lives until application shuts down
- Must be thread-safe

**When to Use:**
```
✅ Use Singleton for:
   - Stateless services
   - Configuration
   - Caching
   - Logging
   - Services expensive to create
   
⚠️ MUST be thread-safe!
```

**Example:**
```csharp
public interface ICacheService
{
    void Set(string key, object value);
    object Get(string key);
}

public class MemoryCacheService : ICacheService
{
    private readonly ConcurrentDictionary<string, object> _cache = new();
    
    public void Set(string key, object value)
    {
        _cache[key] = value;  // Thread-safe
    }
    
    public object Get(string key)
    {
        _cache.TryGetValue(key, out var value);
        return value;
    }
}

builder.Services.AddSingleton<ICacheService, MemoryCacheService>();
```

### Service Lifetime Comparison

| Lifetime | Instance Per | Disposed | Best For | Thread-Safety |
|----------|-------------|----------|----------|---------------|
| **Transient** | Each injection | Immediately after use | Lightweight, stateless | Not required |
| **Scoped** | HTTP request | End of request | DbContext, repositories | Not required |
| **Singleton** | Application | App shutdown | Caching, configuration | Required |

### Common Lifetime Mistakes

#### ❌ Mistake 1: Injecting Scoped into Singleton

```csharp
❌ WRONG:
builder.Services.AddSingleton<MySingletonService>();
builder.Services.AddScoped<AppDbContext>();

public class MySingletonService
{
    private readonly AppDbContext _db;  // Scoped injected into Singleton!
    
    public MySingletonService(AppDbContext db)
    {
        _db = db;  // This will fail or cause issues
    }
}

✅ CORRECT: Use IServiceProvider to resolve scoped services
public class MySingletonService
{
    private readonly IServiceProvider _serviceProvider;
    
    public MySingletonService(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }
    
    public async Task DoWorkAsync()
    {
        using var scope = _serviceProvider.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        // Use db
    }
}
```

#### ❌ Mistake 2: Forgetting Thread-Safety in Singleton

```csharp
❌ NOT thread-safe:
public class CounterService
{
    private int _count = 0;
    
    public void Increment()
    {
        _count++;  // Race condition!
    }
}

✅ Thread-safe:
public class CounterService
{
    private int _count = 0;
    
    public void Increment()
    {
        Interlocked.Increment(ref _count);
    }
}
```

### Service Registration Methods

#### 1. Basic Registration

```csharp
// Interface → Implementation
builder.Services.AddTransient<IEmailService, EmailService>();
builder.Services.AddScoped<IOrderService, OrderService>();
builder.Services.AddSingleton<ICacheService, CacheService>();

// Concrete type only
builder.Services.AddTransient<EmailService>();
```

#### 2. Factory Registration

```csharp
builder.Services.AddScoped<IOrderService>(provider =>
{
    var db = provider.GetRequiredService<AppDbContext>();
    var logger = provider.GetRequiredService<ILogger<OrderService>>();
    return new OrderService(db, logger);
});

// With configuration
builder.Services.AddSingleton<IEmailService>(provider =>
{
    var config = provider.GetRequiredService<IConfiguration>();
    var smtpServer = config["Email:SmtpServer"];
    return new EmailService(smtpServer);
});
```

#### 3. Instance Registration (Singleton Only)

```csharp
var cacheService = new CacheService();
builder.Services.AddSingleton<ICacheService>(cacheService);

// Or
builder.Services.AddSingleton(new CacheService());
```

#### 4. TryAdd Methods (Register if Not Already Registered)

```csharp
builder.Services.TryAddTransient<IEmailService, EmailService>();
// If IEmailService is already registered, this does nothing

builder.Services.TryAddScoped<IOrderService, OrderService>();
builder.Services.TryAddSingleton<ICacheService, CacheService>();
```

#### 5. Multiple Implementations

```csharp
builder.Services.AddTransient<INotificationService, EmailNotificationService>();
builder.Services.AddTransient<INotificationService, SmsNotificationService>();
builder.Services.AddTransient<INotificationService, PushNotificationService>();

// Resolve all
public class NotificationManager
{
    private readonly IEnumerable<INotificationService> _services;
    
    public NotificationManager(IEnumerable<INotificationService> services)
    {
        _services = services;  // All three implementations
    }
    
    public async Task NotifyAllAsync(string message)
    {
        foreach (var service in _services)
        {
            await service.SendAsync(message);
        }
    }
}
```

### Configuration Fundamentals

**Configuration Sources (in order of precedence):**

```
1. Command-line arguments (highest priority)
2. Environment variables
3. appsettings.{Environment}.json
4. appsettings.json
5. User secrets (Development only)
6. Default values (lowest priority)
```

**Basic Configuration Access:**

```csharp
// Directly from IConfiguration
var connectionString = builder.Configuration.GetConnectionString("DefaultConnection");
var apiKey = builder.Configuration["ApiSettings:ApiKey"];
var timeout = builder.Configuration.GetValue<int>("ApiSettings:Timeout");
```

**appsettings.json:**
```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=..."
  },
  "ApiSettings": {
    "ApiKey": "abc123",
    "Timeout": 30,
    "BaseUrl": "https://api.example.com"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information"
    }
  }
}
```

### The Options Pattern

Instead of accessing configuration directly, use strongly-typed options:

#### Define Options Class

```csharp
public class ApiSettings
{
    public const string SectionName = "ApiSettings";
    
    public string ApiKey { get; set; } = string.Empty;
    public int Timeout { get; set; }
    public string BaseUrl { get; set; } = string.Empty;
}
```

#### Register Options

```csharp
builder.Services.Configure<ApiSettings>(
    builder.Configuration.GetSection(ApiSettings.SectionName));
```

#### Use Options in Services

```csharp
public class ApiClient
{
    private readonly ApiSettings _settings;
    
    public ApiClient(IOptions<ApiSettings> options)
    {
        _settings = options.Value;  // Get settings
    }
    
    public async Task<string> CallApiAsync()
    {
        var client = new HttpClient
        {
            BaseAddress = new Uri(_settings.BaseUrl),
            Timeout = TimeSpan.FromSeconds(_settings.Timeout)
        };
        
        client.DefaultRequestHeaders.Add("X-Api-Key", _settings.ApiKey);
        
        return await client.GetStringAsync("/endpoint");
    }
}
```

### IOptions vs IOptionsSnapshot vs IOptionsMonitor

#### IOptions<T>

**Characteristics:**
- Singleton (computed once)
- No reload on configuration changes
- Cannot be used in singleton services to read scoped config

```csharp
public class MyService
{
    private readonly ApiSettings _settings;
    
    public MyService(IOptions<ApiSettings> options)
    {
        _settings = options.Value;  // Read once
    }
}

✅ Use when:
   - Configuration doesn't change at runtime
   - Service is singleton
   - Simple scenarios
```

#### IOptionsSnapshot<T>

**Characteristics:**
- Scoped (recomputed per request)
- Reloads on configuration changes
- Cannot be injected into singleton services

```csharp
public class MyService
{
    private readonly IOptionsSnapshot<ApiSettings> _options;
    
    public MyService(IOptionsSnapshot<ApiSettings> options)
    {
        _options = options;
    }
    
    public void DoWork()
    {
        var settings = _options.Value;  // Fresh per request
    }
}

✅ Use when:
   - Need config changes within request boundaries
   - Service is scoped or transient
   - Want config to reload
```

#### IOptionsMonitor<T>

**Characteristics:**
- Singleton (but retrieves current value each time)
- Reloads immediately on configuration changes
- Can be used in singleton services
- Supports change notifications

```csharp
public class MyService : IDisposable
{
    private readonly IOptionsMonitor<ApiSettings> _options;
    private readonly IDisposable _changeToken;
    
    public MyService(IOptionsMonitor<ApiSettings> options)
    {
        _options = options;
        
        // React to config changes
        _changeToken = _options.OnChange(settings =>
        {
            Console.WriteLine("Configuration changed!");
            // React to change
        });
    }
    
    public void DoWork()
    {
        var settings = _options.CurrentValue;  // Always current
    }
    
    public void Dispose()
    {
        _changeToken?.Dispose();
    }
}

✅ Use when:
   - Need real-time config changes
   - Service is singleton
   - Need change notifications
   - Most flexible option
```

**Comparison Table:**

| Feature | IOptions | IOptionsSnapshot | IOptionsMonitor |
|---------|----------|------------------|-----------------|
| **Lifetime** | Singleton | Scoped | Singleton |
| **Reloads** | No | Per request | Immediately |
| **Use in Singleton** | Yes | No | Yes |
| **Change Notifications** | No | No | Yes |
| **Performance** | Best | Medium | Good |
| **Use Case** | Static config | Per-request config | Real-time config |

### Options Validation

#### Data Annotations Validation

```csharp
using System.ComponentModel.DataAnnotations;

public class ApiSettings
{
    public const string SectionName = "ApiSettings";
    
    [Required]
    [MinLength(10)]
    public string ApiKey { get; set; } = string.Empty;
    
    [Range(1, 300)]
    public int Timeout { get; set; }
    
    [Required]
    [Url]
    public string BaseUrl { get; set; } = string.Empty;
}

// Register with validation
builder.Services.AddOptions<ApiSettings>()
    .Bind(builder.Configuration.GetSection(ApiSettings.SectionName))
    .ValidateDataAnnotations()
    .ValidateOnStart();  // Validate at startup, not first use
```

#### Custom Validation

```csharp
builder.Services.AddOptions<ApiSettings>()
    .Bind(builder.Configuration.GetSection(ApiSettings.SectionName))
    .Validate(settings =>
    {
        if (settings.Timeout <= 0)
            return false;
        
        if (string.IsNullOrWhiteSpace(settings.ApiKey))
            return false;
        
        return true;
    }, "Invalid API settings")
    .ValidateOnStart();
```

#### IValidateOptions<T>

```csharp
public class ApiSettingsValidator : IValidateOptions<ApiSettings>
{
    public ValidateOptionsResult Validate(string name, ApiSettings options)
    {
        var failures = new List<string>();
        
        if (string.IsNullOrWhiteSpace(options.ApiKey))
            failures.Add("ApiKey is required");
        
        if (options.Timeout <= 0)
            failures.Add("Timeout must be positive");
        
        if (string.IsNullOrWhiteSpace(options.BaseUrl))
            failures.Add("BaseUrl is required");
        
        if (failures.Any())
            return ValidateOptionsResult.Fail(failures);
        
        return ValidateOptionsResult.Success;
    }
}

// Register
builder.Services.AddSingleton<IValidateOptions<ApiSettings>, ApiSettingsValidator>();
```

### Named Options

Configure multiple instances of the same options type:

```csharp
public class ApiSettings
{
    public string ApiKey { get; set; } = string.Empty;
    public string BaseUrl { get; set; } = string.Empty;
}

// appsettings.json
{
  "PaymentApi": {
    "ApiKey": "payment-key",
    "BaseUrl": "https://payment.api.com"
  },
  "ShippingApi": {
    "ApiKey": "shipping-key",
    "BaseUrl": "https://shipping.api.com"
  }
}

// Registration
builder.Services.Configure<ApiSettings>("Payment",
    builder.Configuration.GetSection("PaymentApi"));
    
builder.Services.Configure<ApiSettings>("Shipping",
    builder.Configuration.GetSection("ShippingApi"));

// Usage
public class OrderService
{
    private readonly ApiSettings _paymentSettings;
    private readonly ApiSettings _shippingSettings;
    
    public OrderService(IOptionsSnapshot<ApiSettings> options)
    {
        _paymentSettings = options.Get("Payment");
        _shippingSettings = options.Get("Shipping");
    }
}
```

### Post-Configuration

Modify options after they're configured:

```csharp
builder.Services.PostConfigure<ApiSettings>(settings =>
{
    // Ensure trailing slash
    if (!settings.BaseUrl.EndsWith("/"))
        settings.BaseUrl += "/";
    
    // Trim whitespace
    settings.ApiKey = settings.ApiKey.Trim();
});
```

### Dependency Injection Best Practices

**1. Depend on Abstractions**
```csharp
✅ Good:
public class OrderService
{
    private readonly IOrderRepository _repository;  // Interface
}

❌ Bad:
public class OrderService
{
    private readonly OrderRepository _repository;  // Concrete class
}
```

**2. Use Constructor Injection**
```csharp
✅ Good:
public class OrderService
{
    private readonly IOrderRepository _repository;
    
    public OrderService(IOrderRepository repository)
    {
        _repository = repository ?? throw new ArgumentNullException(nameof(repository));
    }
}

❌ Bad: Property injection, service locator pattern
```

**3. Avoid Static State**
```csharp
❌ Bad:
public class OrderService
{
    private static int _orderCount;  // Static state - bad for DI
}

✅ Good:
public class OrderService
{
    private int _orderCount;  // Instance state
}
```

**4. Keep Services Small and Focused**
```csharp
✅ Good: Single Responsibility
public class EmailService : IEmailService { }
public class SmsService : ISmsService { }

❌ Bad: Too many responsibilities
public class NotificationService
{
    public void SendEmail() { }
    public void SendSms() { }
    public void SendPush() { }
    public void LogNotification() { }
    public void ValidateRecipient() { }
}
```

**5. Validate Options at Startup**
```csharp
✅ Good:
builder.Services.AddOptions<ApiSettings>()
    .Bind(builder.Configuration.GetSection("ApiSettings"))
    .ValidateDataAnnotations()
    .ValidateOnStart();  // Fail fast

❌ Bad: Discover invalid config at runtime
```
