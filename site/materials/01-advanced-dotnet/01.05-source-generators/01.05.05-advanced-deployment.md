By the end of this lesson, you will be able to:
- Package source generators as NuGet packages for distribution

- Implement advanced caching strategies for incremental generators
- Monitor generator behavior in production builds

## Introduction

Taking your source generator from a working prototype to a production-ready, distributable tool requires understanding packaging, performance optimization, and troubleshooting. This lesson covers the advanced techniques and best practices needed to deploy generators confidently, measure their impact, and maintain them over time. Whether you're building internal tooling or publishing to NuGet.org, these patterns will help you create robust, performant generators.

## Key Concepts Summary

### Packaging Source Generators

#### Project Configuration for NuGet

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <!-- Target netstandard2.0 for maximum compatibility -->
    <TargetFramework>netstandard2.0</TargetFramework>
    <LangVersion>latest</LangVersion>
    <EnforceExtendedAnalyzerRules>true</EnforceExtendedAnalyzerRules>
    <IsRoslynComponent>true</IsRoslynComponent>
    
    <!-- NuGet Package Metadata -->
    <PackageId>MyCompany.SourceGenerator</PackageId>
    <Version>1.0.0</Version>
    <Authors>Your Name</Authors>
    <Company>Your Company</Company>
    <Description>Source generator for automatically generating boilerplate code</Description>
    <PackageTags>source-generator;roslyn;codegen</PackageTags>
    <PackageProjectUrl>https://github.com/yourcompany/generator</PackageProjectUrl>
    <RepositoryUrl>https://github.com/yourcompany/generator</RepositoryUrl>
    <PackageLicenseExpression>MIT</PackageLicenseExpression>
    <PackageReadmeFile>README.md</PackageReadmeFile>
    <PackageIcon>icon.png</PackageIcon>
    
    <!-- Critical for source generators -->
    <IncludeBuildOutput>false</IncludeBuildOutput>
    <GeneratePackageOnBuild>true</GeneratePackageOnBuild>
    <DevelopmentDependency>true</DevelopmentDependency>
  </PropertyGroup>

  <ItemGroup>
    <!-- Roslyn dependencies (PrivateAssets=all) -->
    <PackageReference Include="Microsoft.CodeAnalysis.CSharp" 
                      Version="4.3.0" 
                      PrivateAssets="all" />
    <PackageReference Include="Microsoft.CodeAnalysis.Analyzers" 
                      Version="3.3.3" 
                      PrivateAssets="all">
      <IncludeAssets>runtime; build; native; contentfiles; analyzers; buildtransitive</IncludeAssets>
    </PackageReference>
    
    <!-- Include generator DLL as analyzer -->
    <None Include="$(OutputPath)\$(AssemblyName).dll" 
          Pack="true" 
          PackagePath="analyzers/dotnet/cs" 
          Visible="false" />
    
    <!-- Include README and icon -->
    <None Include="README.md" Pack="true" PackagePath="\" />
    <None Include="icon.png" Pack="true" PackagePath="\" />
  </ItemGroup>
</Project>
```

**Key Properties Explained:**

| Property | Value | Why |
|----------|-------|-----|
| `TargetFramework` | netstandard2.0 | Required for generator compatibility |
| `IncludeBuildOutput` | false | Don't include DLL in `lib/` folder |
| `DevelopmentDependency` | true | Generator doesn't flow to transitive dependencies |
| `PrivateAssets` | all | Roslyn deps don't leak to consumers |
| `PackagePath` | analyzers/dotnet/cs | Special folder for analyzers/generators |

#### Creating the Package

```bash
# Build and pack in one command
dotnet pack -c Release

# Output: bin/Release/MyCompany.SourceGenerator.1.0.0.nupkg

# Test locally before publishing
dotnet nuget push bin/Release/MyCompany.SourceGenerator.1.0.0.nupkg \
  --source https://api.nuget.org/v3/index.json \
  --api-key YOUR_API_KEY
```

### Performance Measurement

#### Method 1: MSBuild Binary Log

**Enable Reporting:**
```xml
<PropertyGroup>
  <ReportAnalyzer>true</ReportAnalyzer>
</PropertyGroup>
```

**Generate Binary Log:**
```bash
dotnet build /binaryLogger
# Creates: msbuild.binlog
```

**Analyze with MSBuild Structured Log Viewer:**
```bash
# Download from: https://msbuildlog.com/
MSBuildStructuredLogViewer.exe msbuild.binlog

# Look for:
# - "Analyzers" section
# - Individual generator execution times
# - Total analyzer/generator overhead
```

**What to Look For:**
```
✅ Good:  < 100ms per generator
⚠️ Okay: 100-500ms per generator
❌ Bad:   > 500ms per generator
```

#### Method 2: Visual Studio ETW Tracing

**Using PerfView:**
```bash
# Capture ETW trace while using Visual Studio
PerfView.exe collect -CircularMB:1000 -ThreadTime -Providers:*Microsoft-CodeAnalysis-General

# Analyze in PerfView:
# - Filter to your generator
# - Look for "Execute" method timing
# - Check incremental caching effectiveness
```

#### Method 3: Stopwatch in Generator (Dev Only)

```csharp
#if DEBUG
using System.Diagnostics;
#endif

[Generator]
public class MyGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
#if DEBUG
        var sw = Stopwatch.StartNew();
#endif

        // Generator logic...

#if DEBUG
        sw.Stop();
        Debug.WriteLine($"Generator execution: {sw.ElapsedMilliseconds}ms");
#endif
    }
}
```

### Advanced Performance Optimization

#### 1. Use ForAttributeWithMetadataName (.NET 7+)

```csharp
❌ Slow - Manual attribute checking:
var classes = context.SyntaxProvider
    .CreateSyntaxProvider(
        predicate: (node, _) => node is ClassDeclarationSyntax,
        transform: (ctx, _) =>
        {
            var classDecl = (ClassDeclarationSyntax)ctx.Node;
            // Expensive: Check every class for attribute
            foreach (var attr in classDecl.AttributeLists.SelectMany(al => al.Attributes))
            {
                var symbol = ctx.SemanticModel.GetSymbolInfo(attr).Symbol;
                if (symbol?.ContainingType.Name == "MyAttribute")
                    return classDecl;
            }
            return null;
        }
    );

✅ Fast - Built-in attribute indexing:
var classes = context.SyntaxProvider
    .ForAttributeWithMetadataName(
        "MyNamespace.MyAttribute",  // Indexed lookup!
        predicate: (node, _) => node is ClassDeclarationSyntax,
        transform: (ctx, _) => GetClassInfo(ctx)
    );

// Performance gain: 5-10x faster for attribute-based generators
```

#### 2. Efficient Filtering

```csharp
❌ Processes too much:
var nodes = context.SyntaxProvider.CreateSyntaxProvider(
    predicate: (node, _) => node is ClassDeclarationSyntax,  // All classes!
    transform: ExpensiveTransform
);

✅ Filter early:
var nodes = context.SyntaxProvider.CreateSyntaxProvider(
    predicate: (node, _) => 
        node is ClassDeclarationSyntax { AttributeLists.Count: > 0 },  // Only attributed
    transform: ExpensiveTransform
);
```

#### 3. Minimize Semantic Model Queries

```csharp
❌ Multiple semantic queries:
static ClassInfo GetClassInfo(GeneratorSyntaxContext context)
{
    var classDecl = (ClassDeclarationSyntax)context.Node;
    
    // Each property access = semantic query
    var className = context.SemanticModel.GetDeclaredSymbol(classDecl)?.Name;
    var baseType = context.SemanticModel.GetDeclaredSymbol(classDecl)?.BaseType;
    var interfaces = context.SemanticModel.GetDeclaredSymbol(classDecl)?.Interfaces;
    
    return new ClassInfo(className, baseType, interfaces);
}

✅ Single semantic query:
static ClassInfo GetClassInfo(GeneratorSyntaxContext context)
{
    // Get symbol once
    var classSymbol = context.SemanticModel.GetDeclaredSymbol((ClassDeclarationSyntax)context.Node);
    
    if (classSymbol == null)
        return null;
    
    // Extract all info from symbol
    return new ClassInfo(
        classSymbol.Name,
        classSymbol.BaseType,
        classSymbol.Interfaces
    );
}
```

#### 4. Use Value Types for Data Transfer

```csharp
❌ Classes create GC pressure:
class ClassInfo  // Heap allocated
{
    public string Name { get; set; }
    public List<string> Properties { get; set; }
}

✅ Records/structs reduce allocations:
readonly record struct ClassInfo(  // Stack/immutable
    string Name,
    ImmutableArray<string> Properties
);
```

#### 5. Leverage Caching with WithTrackingName

```csharp
public void Initialize(IncrementalGeneratorInitializationContext context)
{
    // Add tracking names for debugging
    var classes = context.SyntaxProvider
        .ForAttributeWithMetadataName("MyAttribute")
        .WithTrackingName("FindClasses")  // Track this step
        .Select((ctx, _) => ExtractInfo(ctx))
        .WithTrackingName("ExtractInfo")  // Track transformation
        .Where(c => c != null)
        .WithTrackingName("FilterNulls"); // Track filtering

    context.RegisterSourceOutput(classes, Generate);
}

// Benefits:
// 1. Better diagnostics (see what gets cached)
// 2. Easier debugging (identify slow steps)
// 3. Verify incremental caching works
```

### Troubleshooting Production Issues

#### Common Issue 1: Generator Not Running

**Symptoms:**
- No generated code appearing
- No diagnostics from generator

**Diagnosis:**
```xml
<!-- Check consumer project has correct reference -->
<ItemGroup>
  <PackageReference Include="MyGenerator" Version="1.0.0">
    <!-- Must have these properties -->
    <PrivateAssets>all</PrivateAssets>
    <IncludeAssets>runtime; build; native; contentfiles; analyzers</IncludeAssets>
  </PackageReference>
</ItemGroup>
```

**Fix:**
```bash
# Clean and rebuild
dotnet clean
dotnet build -v detailed

# Look for: "Found generator 'MyGenerator'"
```

#### Common Issue 2: Slow IDE Performance

**Symptoms:**
- Visual Studio slow when typing
- High CPU usage
- Delays when editing files

**Diagnosis:**
```xml
<!-- Enable performance reporting -->
<PropertyGroup>
  <ReportAnalyzer>true</ReportAnalyzer>
</PropertyGroup>
```

```bash
dotnet build /binaryLogger
# Check msbuild.binlog for slow generators
```

**Fix:**
- Use `ForAttributeWithMetadataName` instead of manual filtering
- Add better predicate filters
- Ensure incremental caching works
- Reduce semantic model queries

#### Common Issue 3: Generator Errors in CI/CD

**Symptoms:**
- Build succeeds locally, fails in CI
- "Generator failed" errors

**Common Causes:**
```bash
# 1. Missing Roslyn version
# Fix: Ensure SDK version matches

# 2. Multi-targeting issues
# Fix: Test with exact SDK versions from CI

# 3. File path issues (case sensitivity on Linux)
# Fix: Use Path.Combine, not string concatenation
```

**Debugging:**
```xml
<!-- Add detailed logging in CI -->
<PropertyGroup>
  <GeneratorVerbosity>detailed</GeneratorVerbosity>
</PropertyGroup>
```

#### Common Issue 4: Generated Code Not Compiling

**Symptoms:**
- Generator runs successfully
- Generated code has compilation errors

**Prevention:**
```csharp
static string GenerateCode(ClassInfo info)
{
    // Always validate generated code
    var source = $$"""
        #nullable enable
        namespace {{SanitizeNamespace(info.Namespace)}}
        {
            partial class {{SanitizeIdentifier(info.Name)}}
            {
                // Generated code
            }
        }
        #nullable restore
        """;
    
    // Optionally: Parse and validate
#if DEBUG
    var tree = CSharpSyntaxTree.ParseText(source);
    var diagnostics = tree.GetDiagnostics();
    if (diagnostics.Any(d => d.Severity == DiagnosticSeverity.Error))
    {
        throw new InvalidOperationException("Generated invalid code");
    }
#endif
    
    return source;
}

static string SanitizeIdentifier(string name) =>
    name.Replace("<", "").Replace(">", "");  // Handle generics
    
static string SanitizeNamespace(string ns) =>
    string.IsNullOrEmpty(ns) ? "Generated" : ns;
```

### Multi-Targeting and Compatibility

#### Supporting Multiple .NET Versions

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <!-- Generator targets netstandard2.0 -->
    <TargetFramework>netstandard2.0</TargetFramework>
    
    <!-- Generated code can target multiple frameworks -->
    <SupportedTargetFrameworks>
      net6.0;net7.0;net8.0
    </SupportedTargetFrameworks>
  </PropertyGroup>
</Project>
```

#### Conditional Code Generation

```csharp
static string GenerateCode(ClassInfo info, Compilation compilation)
{
    // Check target framework
    var isNet7OrLater = compilation.ReferencedAssemblyNames
        .Any(a => a.Name == "System.Runtime" && a.Version >= new Version(7, 0));
    
    if (isNet7OrLater)
    {
        // Use .NET 7+ features
        return GenerateNet7Code(info);
    }
    else
    {
        // Fallback for older versions
        return GenerateCompatibleCode(info);
    }
}
```

### Versioning and Breaking Changes

#### Semantic Versioning for Generators

```
1.0.0 - Initial release
1.1.0 - Add new optional features (minor)
1.1.1 - Bug fixes (patch)
2.0.0 - Breaking changes (major)
```

**Breaking Changes:**
- Changing diagnostic IDs
- Removing generated members
- Changing generated code signatures
- Changing attribute requirements

**Non-Breaking Changes:**
- Adding new optional features
- Adding new diagnostics (warnings/info)
- Performance improvements
- Bug fixes in generation

#### Versioning Strategy

```xml
<!-- In generator project -->
<PropertyGroup>
  <Version>1.2.0</Version>
  <AssemblyVersion>1.0.0.0</AssemblyVersion>  <!-- Only major version -->
  <FileVersion>1.2.0.0</FileVersion>
</PropertyGroup>
```

### Monitoring in Production

```csharp
// Add telemetry (be mindful of performance)
[Generator]
public class MyGenerator : IIncrementalGenerator
{
    private static int _executionCount = 0;
    
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        context.RegisterSourceOutput(
            context.SyntaxProvider.ForAttributeWithMetadataName(/* ... */),
            (spc, source) =>
            {
                Interlocked.Increment(ref _executionCount);
                
                try
                {
                    Generate(source, spc);
                }
                catch (Exception ex)
                {
                    // Log to file (not console - causes build issues)
                    File.AppendAllText(
                        Path.Combine(Path.GetTempPath(), "generator-errors.log"),
                        $"{DateTime.Now}: {ex}\n"
                    );
                    throw;
                }
            }
        );
    }
}
```
