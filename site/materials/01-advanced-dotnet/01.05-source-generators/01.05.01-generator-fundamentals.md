## Introduction

Source generators are one of the most powerful features added to modern C#. They allow you to analyze your code during compilation and generate additional C# files that are compiled alongside your code. This enables scenarios that traditionally required reflection, IL weaving, or manual boilerplate code—but with better performance, IDE support, and AOT compatibility.

## Key Concepts Summary

### What are Source Generators?

Source generators are compile-time code generation tools that run during compilation:

```
Your Source Code → Compiler → Source Generator → Generated Code → Final Assembly
                      ↓
                 Analyzer API
```

**Key Characteristics:**
- Run at **compile time**, not runtime
- Generate **additional C# files** that are compiled with your code
- Have **read-only access** to your source code
- Cannot modify existing code, only add new code
- Generated code is **visible in IDE** (IntelliSense support)

### Why Source Generators?

#### Problem: Runtime Reflection is Slow

```csharp
// Traditional reflection-based approach
❌ Runtime Cost:
public void Serialize(object obj)
{
    Type type = obj.GetType();  // Runtime type lookup
    foreach (var prop in type.GetProperties())  // Runtime reflection
    {
        var value = prop.GetValue(obj);  // Slow property access
        // ... serialization logic
    }
}
```

#### Solution: Compile-Time Generation

```csharp
// Source generator creates specific code at compile time
✅ Zero Runtime Cost:
public void Serialize(Person person)
{
    // Generated code - no reflection!
    var name = person.Name;
    var age = person.Age;
    // ... serialization logic
}
```

### Benefits of Source Generators

**1. Performance**
```
Reflection:           100-1000x slower
Source Generators:    Same speed as hand-written code
```

**2. AOT Compatibility**
- Native AOT doesn't support reflection
- Source generators work perfectly with AOT
- Used by `System.Text.Json` for AOT serialization

**3. IDE Support**
- Generated code appears in IntelliSense
- Navigate to generated code
- Find all references works
- Compile-time errors in generated code

**4. Maintainability**
- Eliminates repetitive boilerplate
- Single source of truth
- Changes propagate automatically
- Type-safe code generation

**5. Discoverability**
- Generated files visible in IDE
- Can debug generated code
- Easier to understand what's happening

### Common Use Cases

**1. Eliminating Boilerplate**
```csharp
// Instead of writing this manually for every class:
public class Person : INotifyPropertyChanged
{
    private string _name;
    public string Name
    {
        get => _name;
        set
        {
            _name = value;
            PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(nameof(Name)));
        }
    }
    
    public event PropertyChangedEventHandler PropertyChanged;
}

// Write this:
[AutoNotify]
public partial class Person
{
    private string _name;
}

// Generator creates the rest!
```

**2. Serialization**
```csharp
// System.Text.Json uses source generators for AOT
[JsonSerializable(typeof(Person))]
public partial class MyJsonContext : JsonSerializerContext { }

// Generator creates optimized serialization code
```

**3. Dependency Injection Registration**
```csharp
// Mark services for registration
[RegisterService(ServiceLifetime.Scoped)]
public class MyService { }

// Generator creates:
services.AddScoped<MyService>();
```

**4. DTO Mapping**
```csharp
[MapFrom(typeof(PersonDto))]
public partial class Person { }

// Generator creates mapping methods
```

**5. External DSLs**
```csharp
// Define math expressions in a DSL file
// Generator creates C# implementation
```

### Traditional vs Incremental Generators

#### Traditional Source Generators (ISourceGenerator)

**Introduced:** .NET 5 / C# 9.0

```csharp
[Generator]
public class MyGenerator : ISourceGenerator
{
    public void Initialize(GeneratorInitializationContext context)
    {
        // Setup
    }

    public void Execute(GeneratorExecutionContext context)
    {
        // Every edit = full regeneration
        // Can be slow for large projects
    }
}
```

**Characteristics:**
- Runs on every compilation
- Processes all files every time
- Can cause sluggish IDE experience in large projects
- Simple to implement

#### Incremental Source Generators (IIncrementalGenerator)

**Introduced:** .NET 6 / C# 10

```csharp
[Generator]
public class MyIncrementalGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // Build a pipeline that caches results
        var provider = context.SyntaxProvider
            .CreateSyntaxProvider(/* filter */)
            .Select(/* transform */);
            
        context.RegisterSourceOutput(provider, /* generate */);
    }
}
```

**Characteristics:**
- Caches results intelligently
- Only regenerates when inputs change
- Much faster in large projects
- More complex to implement
- **Recommended for new generators**

**Performance Comparison:**
```
Traditional:  Edit file → Regenerate everything → Slow
Incremental:  Edit file → Check cache → Only regenerate changed → Fast
```

### How Source Generators Work

**The Compilation Pipeline:**

```
1. User writes code
   ↓
2. Compiler parses code → Syntax Trees
   ↓
3. Source Generator runs:
   - Receives syntax trees
   - Analyzes code structure
   - Generates new C# code
   ↓
4. Generated code added to compilation
   ↓
5. Everything compiled together
   ↓
6. Final assembly with generated code
```

### Roslyn API Basics

Source generators use the Roslyn compiler APIs:

#### Syntax Trees

**What:** Immutable tree representation of source code structure

```csharp
// This code:
public class Person
{
    public string Name { get; set; }
}

// Becomes this tree:
CompilationUnit
  └─ ClassDeclaration ("Person")
      └─ PropertyDeclaration ("Name")
          ├─ Type: string
          └─ Accessors: get, set
```

**Key Properties:**
- Full fidelity (includes whitespace, comments)
- Immutable (can't modify, only create new trees)
- Lightweight (fast to create and traverse)

**Usage in Generators:**
```csharp
// Access syntax tree
SyntaxTree tree = context.Compilation.SyntaxTrees.First();

// Get root node
SyntaxNode root = tree.GetRoot();

// Find class declarations
var classes = root.DescendantNodes()
    .OfType<ClassDeclarationSyntax>();
```

#### Semantic Model

**What:** Provides meaning to syntax (types, symbols, etc.)

```csharp
// Syntax tells you there's an identifier "Person"
// Semantic model tells you what "Person" means:
// - Is it a class, struct, or interface?
// - What namespace is it in?
// - What are its members?
// - What types do those members have?
```

**Usage in Generators:**
```csharp
SemanticModel model = context.Compilation.GetSemanticModel(tree);

// Get symbol information
var classSymbol = model.GetDeclaredSymbol(classDeclaration);

// Get type information
TypeInfo typeInfo = model.GetTypeInfo(expression);
```

### Source Generator Architecture

**Inputs:**
- `Compilation` - All syntax trees, references, options
- `AdditionalFiles` - Extra files from project (JSON, XML, etc.)
- `AnalyzerConfigOptions` - MSBuild properties

**Processing:**
1. Filter relevant syntax nodes
2. Extract information via semantic model
3. Build model of what to generate
4. Generate C# code as strings

**Output:**
- C# source files added to compilation
- Diagnostics (warnings/errors)

### Constraints and Limitations

**1. Read-Only Access**
```
✅ Can: Read existing code, add new files
❌ Cannot: Modify existing code
```

**2. No Side Effects**
```
✅ Can: Generate code, emit diagnostics
❌ Cannot: Write files to disk, make network calls
```

**3. Deterministic**
- Same inputs must produce same outputs
- Cannot use random values, DateTime.Now, etc.
- Must be reproducible

**4. Performance Conscious**
- Generators run in IDE on every edit
- Must be fast (< 100ms target)
- Use incremental generators for caching

### When to Use Source Generators

**✅ Good Use Cases:**
- Eliminating reflection for performance
- AOT-compatible alternatives to dynamic code
- Reducing repetitive boilerplate
- Type-safe code generation
- Cross-cutting concerns (logging, validation)

**❌ Not Suitable For:**
- Modifying existing code (use analyzers + code fixes)
- Complex business logic generation
- Anything requiring side effects
- One-off code generation (use T4 templates)

**Decision Matrix:**

| Need | Solution |
|------|----------|
| Generate code based on attributes | ✅ Source Generator |
| Modify existing code | ❌ Analyzer + Code Fix |
| One-time code scaffolding | ❌ T4 Template or CLI tool |
| Runtime dynamic behavior | ❌ Reflection or expression trees |
| Replace reflection for perf | ✅ Source Generator |

**Conceptual Exercise: Identify Generator Opportunities**

Review a recent project and identify three places where you could use a source generator:

1. **Boilerplate Code**: Find classes where you write repetitive patterns

   - Example: Similar constructors or factory methods

2. **Reflection Usage**: Find places where you use reflection

   - Dependency injection registration
   - Plugin discovery

   - API client generation from OpenAPI specs
   - Database entity generation

- What currently causes the problem (manual code, reflection, etc.)
- What the generator would analyze (attributes, types, external files)
- What code the generator would produce
