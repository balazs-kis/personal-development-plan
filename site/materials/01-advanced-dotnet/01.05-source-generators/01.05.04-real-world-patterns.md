# Lesson 4: Real-World Generator Patterns and Use Cases

## Learning Objectives

By the end of this lesson, you will be able to:
- Understand how System.Text.Json uses source generators for serialization
- Implement source-generated regular expressions with RegexGenerator
- Create compile-time logging with LoggerMessage source generation
- Recognize common patterns used by production source generators
- Identify opportunities to replace reflection with source generation
- Apply patterns from real-world generators to your own projects
- Understand the performance benefits of source generation in practice

---

## Introduction

The best way to learn source generators is to study how they're used in production .NET libraries. System.Text.Json, RegexGenerator, and LoggerMessage are three excellent examples shipped by Microsoft that demonstrate different generator patterns and use cases. Understanding how these work gives you a proven blueprint for building your own generators that provide similar benefits: better performance, AOT compatibility, and improved developer experience.

## Key Concepts Summary

### Pattern 1: JSON Serialization (System.Text.Json)

#### The Problem: Reflection-Based Serialization

```csharp
// Traditional approach (uses reflection at runtime)
var json = JsonSerializer.Serialize(person);
var person = JsonSerializer.Deserialize<Person>(json);

// Problems:
// - Slow first-time use (reflection overhead)
// - Higher memory usage
// - Not compatible with Native AOT
// - Slower startup
```

#### The Solution: Source-Generated Serialization

**Step 1: Create a JsonSerializerContext**

```csharp
using System.Text.Json.Serialization;

[JsonSerializable(typeof(Person))]
[JsonSerializable(typeof(List<Person>))]
[JsonSourceGenerationOptions(
    WriteIndented = true,
    PropertyNamingPolicy = JsonKnownNamingPolicy.CamelCase,
    GenerationMode = JsonSourceGenerationMode.Metadata | JsonSourceGenerationMode.Serialization
)]
public partial class MyJsonContext : JsonSerializerContext
{
    // Generator fills in the implementation
}
```

**Step 2: Use the Context**

```csharp
// Serialize with generated code
var json = JsonSerializer.Serialize(person, MyJsonContext.Default.Person);

// Deserialize with generated code
var person = JsonSerializer.Deserialize<Person>(json, MyJsonContext.Default.Person);
```

**ASP.NET Core Integration:**

```csharp
var builder = WebApplication.CreateBuilder(args);

// Configure JSON options to use source generation
builder.Services.ConfigureHttpJsonOptions(options =>
{
    options.SerializerOptions.TypeInfoResolverChain.Insert(0, MyJsonContext.Default);
});

var app = builder.Build();

// API endpoints automatically use generated serialization
app.MapGet("/person/{id}", (int id) => 
    new Person { Id = id, Name = "John" });

app.Run();
```

#### Generation Modes

**Metadata Mode (Default):**
```
What it does:
- Generates metadata about types at compile time
- Uses runtime serialization logic
- Reduces startup overhead

Benefits:
- Faster startup (no reflection for metadata)
- Smaller memory footprint
- Still relatively fast serialization

When to use:
- General-purpose applications
- When flexibility is needed
```

**Serialization Mode:**
```
What it does:
- Generates complete serialization logic at compile time
- No runtime reflection at all

Benefits:
- Absolute best performance
- Smallest possible size
- Full Native AOT support
- Zero reflection

When to use:
- Performance-critical scenarios
- Native AOT applications
- Microservices with high throughput
```

**Combined Mode (Both):**
```csharp
[JsonSourceGenerationOptions(
    GenerationMode = JsonSourceGenerationMode.Metadata | JsonSourceGenerationMode.Serialization
)]
public partial class MyJsonContext : JsonSerializerContext { }

// Gets benefits of both:
// - Fast startup (metadata)
// - Fast throughput (serialization)
// - Native AOT compatible
```

#### Performance Impact

```
Startup Time:     Up to 40% faster
Memory Usage:     20-30% lower
Serialization:    10-30% faster (Serialization mode)
App Size:         Smaller (with trimming)
```

**Real-World Results:**
```csharp
// Benchmark comparison
// Traditional (Reflection): 1000ms
// Source Generated:          600ms
// Improvement: 40%
```

### Pattern 2: Regular Expressions (RegexGenerator)

#### The Problem: Runtime Regex Compilation

```csharp
// Option 1: Interpreted (slowest)
private static readonly Regex EmailRegex = new(@"^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$");

// Option 2: Compiled (faster but slow startup)
private static readonly Regex EmailRegex = new(
    @"^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$",
    RegexOptions.Compiled
);

// Problems:
// - Compiled = slow startup (JIT compiles regex at runtime)
// - Interpreted = slow execution
// - Both use reflection internally
// - Not AOT compatible
```

#### The Solution: Source-Generated Regex

```csharp
using System.Text.RegularExpressions;

public partial class Validators
{
    [GeneratedRegex(@"^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$", 
        RegexOptions.IgnoreCase | RegexOptions.CultureInvariant)]
    private static partial Regex EmailRegex();
    
    [GeneratedRegex(@"^\d{3}-\d{2}-\d{4}$")]
    private static partial Regex SsnRegex();
    
    [GeneratedRegex(@"^#(?:[0-9a-fA-F]{3}){1,2}$")]
    private static partial Regex HexColorRegex();
}

// Usage (same as before)
if (Validators.EmailRegex().IsMatch(email))
{
    // Valid email
}

// Extract groups
var match = Validators.EmailRegex().Match(email);
if (match.Success)
{
    var user = match.Groups[1].Value;
    var domain = match.Groups[2].Value;
}
```

**What Gets Generated:**

```csharp
// Generator creates optimized code like this:
partial class Validators
{
    [GeneratedCode("RegexGenerator", "...")]
    private static partial Regex EmailRegex()
    {
        return _emailRegex ??= new Regex(/* generated code */, RunnerFactory, 
            TimeSpan.FromMilliseconds(-1));
    }
    
    private static Regex? _emailRegex;
    
    // Highly optimized matching logic generated at compile time
    private static class RunnerFactory
    {
        // ... generated implementation ...
    }
}
```

#### Key Requirements

```csharp
✅ Must be partial method
[GeneratedRegex("pattern")]
private static partial Regex MyRegex();

❌ Cannot be field
private static readonly Regex MyRegex = new("pattern");  // Won't work with generator

✅ RegexOptions.Compiled is automatic (don't specify it)
[GeneratedRegex("pattern", RegexOptions.IgnoreCase)]  // Compiled is implicit

❌ Don't use RegexOptions.Compiled
[GeneratedRegex("pattern", RegexOptions.Compiled)]  // Unnecessary and ignored
```

#### Performance Benefits

```
Startup Time:     As fast as interpreted regex
Execution Time:   Same as RegexOptions.Compiled
Best of Both:     Fast startup + fast execution
Code Size:        Visible and debuggable
AOT Compatible:   ✅ Yes
```

**When It Helps Most:**
- Applications with many regex patterns
- Short-lived processes (CLI tools, Lambda functions)
- Native AOT scenarios
- Performance-sensitive regex operations

### Pattern 3: High-Performance Logging (LoggerMessage)

#### The Problem: Traditional Logging Overhead

```csharp
// Traditional logging
_logger.LogInformation("User {UserId} logged in from {IpAddress}", userId, ipAddress);

// Problems:
// - Boxing of value types (userId → object)
// - String formatting at runtime
// - Allocations for string interpolation
// - Closure allocations
// - Reflection to read parameters
```

#### The Solution: Source-Generated Logging

```csharp
public partial class MyService
{
    private readonly ILogger<MyService> _logger;
    
    public MyService(ILogger<MyService> logger)
    {
        _logger = logger;
    }
    
    [LoggerMessage(
        EventId = 1001,
        Level = LogLevel.Information,
        Message = "User {userId} logged in from {ipAddress}")]
    private partial void LogUserLogin(int userId, string ipAddress);
    
    [LoggerMessage(
        EventId = 2001,
        Level = LogLevel.Warning,
        Message = "Failed login attempt for user {userId} from {ipAddress}")]
    private partial void LogFailedLogin(int userId, string ipAddress);
    
    [LoggerMessage(
        EventId = 3001,
        Level = LogLevel.Error,
        Message = "Database query failed: {errorMessage}")]
    private partial void LogDatabaseError(string errorMessage, Exception exception);
    
    public void ProcessLogin(int userId, string ipAddress)
    {
        // Use generated method (no runtime overhead!)
        LogUserLogin(userId, ipAddress);
        
        // ... login logic ...
    }
}
```

**What Gets Generated:**

```csharp
partial class MyService
{
    [GeneratedCode("LoggerMessageGenerator", "...")]
    private partial void LogUserLogin(int userId, string ipAddress)
    {
        if (_logger.IsEnabled(LogLevel.Information))
        {
            // Highly optimized code with:
            // - No boxing
            // - No allocations
            // - Pre-formatted strings
            // - Efficient parameter handling
            __LogUserLoginCallback(_logger, userId, ipAddress, null);
        }
    }
    
    private static readonly Action<ILogger, int, string, Exception?> __LogUserLoginCallback =
        LoggerMessage.Define<int, string>(
            LogLevel.Information,
            new EventId(1001),
            "User {userId} logged in from {ipAddress}");
}
```

#### Advanced Patterns

**With Exception:**
```csharp
[LoggerMessage(
    EventId = 4001,
    Level = LogLevel.Error,
    Message = "Failed to process order {orderId}")]
private partial void LogOrderProcessingError(int orderId, Exception exception);

// Usage
catch (Exception ex)
{
    LogOrderProcessingError(orderId, ex);
    throw;
}
```

**Dynamic Log Level (not recommended but possible):**
```csharp
[LoggerMessage(
    EventId = 5001,
    Message = "Operation completed in {duration}ms")]
private partial void LogOperationCompleted(LogLevel level, int duration);

// Usage
LogOperationCompleted(duration < 100 ? LogLevel.Debug : LogLevel.Warning, duration);
```

**Static Methods:**
```csharp
public static partial class Log
{
    [LoggerMessage(
        EventId = 1,
        Level = LogLevel.Information,
        Message = "Application started at {startTime}")]
    public static partial void ApplicationStarted(this ILogger logger, DateTime startTime);
}

// Usage
logger.ApplicationStarted(DateTime.UtcNow);
```

#### Performance Impact

```
Allocations:    ~70% fewer
Speed:          2-3x faster
Boxing:         Eliminated
Memory:         Significantly less GC pressure
```

**Benchmark Example:**
```
Traditional Logging:     1000 logs/ms, 25KB allocated
Generated Logging:       3000 logs/ms, 7KB allocated
```

### Common Generator Patterns

#### Pattern 1: Attribute-Based Configuration

```csharp
// User marks code with attributes
[GenerateToString]
[GenerateEquality]
public partial class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}

// Generator reads attributes and generates implementations
```

**Examples:**
- `[JsonSerializable]` - JSON serialization
- `[GeneratedRegex]` - Regular expressions
- `[LoggerMessage]` - Logging
- `[MemoryPackable]` - Binary serialization (community)

#### Pattern 2: Partial Class/Method Extension

```csharp
// User defines partial signature
public partial class MyContext : JsonSerializerContext { }

private static partial Regex MyRegex();

// Generator provides implementation
```

**Why Partial:**
- Generator can't modify existing code
- Partial allows extending user-defined types
- Clean separation between user code and generated code

#### Pattern 3: Context/Factory Pattern

```csharp
// User creates a context type
[JsonSerializable(typeof(Person))]
public partial class AppJsonContext : JsonSerializerContext { }

// Generator creates metadata and factory methods
var person = JsonSerializer.Deserialize<Person>(json, 
    AppJsonContext.Default.Person);  // Generated property
```

**Benefits:**
- Centralized configuration
- Type-safe access to generated code
- Clear API surface

#### Pattern 4: Replace Reflection with Generation

**Before (Reflection):**
```csharp
// Runtime cost
var properties = typeof(Person).GetProperties();
foreach (var prop in properties)
{
    var value = prop.GetValue(person);  // Slow reflection
    Console.WriteLine($"{prop.Name} = {value}");
}
```

**After (Generated):**
```csharp
[GeneratePrintMembers]
public partial class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}

// Generated code (no reflection):
partial class Person
{
    public void PrintMembers()
    {
        Console.WriteLine($"Name = {Name}");
        Console.WriteLine($"Age = {Age}");
    }
}
```

### Identifying Generation Opportunities

**Look for these patterns in your codebase:**

**1. Repetitive Boilerplate**
```csharp
// If you're writing this pattern repeatedly:
public class Person : INotifyPropertyChanged
{
    private string _name;
    public string Name
    {
        get => _name;
        set { _name = value; OnPropertyChanged(); }
    }
    // ... repeat for every property
}

// Consider: Property generator
```

**2. Runtime Reflection**
```csharp
// If you're doing this at runtime:
var type = obj.GetType();
foreach (var prop in type.GetProperties())
{
    // ... expensive reflection
}

// Consider: Source generator
```

**3. Performance-Critical Serialization**
```csharp
// If this is a bottleneck:
JsonConvert.SerializeObject(obj);  // Newtonsoft.Json with reflection

// Use: System.Text.Json with source generation
```

**4. Configuration-Driven Code**
```csharp
// If you have config files driving behavior:
// swagger.json → API client
// schema.json → Database entities
// localization.json → Resource strings

// Consider: Generator that reads config files
```

**5. Cross-Cutting Concerns**
```csharp
// If you're manually adding similar code everywhere:
// - Logging
// - Validation
// - Mapping
// - Equality

// Consider: Attribute-based generator
```

**Minimal APIs + JSON Source Generation:**
```csharp
var builder = WebApplication.CreateSlimBuilder(args);

{
    options.SerializerOptions.TypeInfoResolverChain.Insert(0, 
        AppJsonContext.Default);

    new User { Id = id, Name = "John" });  // Uses generated serialization
```

**Dependency Injection + Logging:**
```csharp
public class OrderService
{
    private readonly ILogger<OrderService> _logger;
    private readonly IRepository _repo;

    {
        _logger = logger;
        _repo = repo;
    }
    
    [LoggerMessage(Level = LogLevel.Information, Message = "Processing order {orderId}")]
    private partial void LogProcessingOrder(int orderId);
    
    public async Task ProcessOrder(int orderId)
    {
        LogProcessingOrder(orderId);  // Generated, fast logging
        // ... implementation
    }
}
```
