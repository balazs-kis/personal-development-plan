## Learning Objectives

By the end of this lesson, you will be able to:
- Identify and avoid common async/await mistakes

- Debug async applications effectively using Visual Studio tools
- Apply async best practices consistently
- Handle exceptions properly in async methods

## Introduction

Async/await makes asynchronous programming much easier, but it also introduces new ways to write problematic code. Deadlocks, unhandled exceptions, performance issues, and subtle bugs can all result from improper async usage. This lesson covers the most common mistakes developers make with async/await and teaches you how to debug and fix them effectively.

## Key Concepts Summary

### The 8 Critical Async Mistakes

#### 1. Using async void

**❌ The Problem:**
```csharp
// Exceptions can't be caught, can't be awaited
public async void ProcessDataAsync()
{
    await Task.Delay(1000);
    throw new Exception("Unhandled!"); // Crashes the application
}

// Caller has no way to know when this completes or if it failed
ProcessDataAsync(); // Fire and forget - dangerous!
```

**✅ The Solution:**
```csharp
// Return Task so callers can await and handle exceptions
public async Task ProcessDataAsync()
{
    await Task.Delay(1000);
    // Exceptions can be caught by awaiting code
}

// Caller can await and handle errors
try
{
    await ProcessDataAsync();
}
catch (Exception ex)
{
    // Handle error
}

// ✅ Only exception: Event handlers
private async void Button_Click(object sender, EventArgs e)
{
    try
    {
        await ProcessDataAsync();
    }
    catch (Exception ex)
    {
        // Must handle exceptions here - can't propagate
        MessageBox.Show($"Error: {ex.Message}");
    }
}
```

#### 2. Using .Result or .Wait()

**❌ The Problem:**
```csharp
public void LoadData()
{
    // DEADLOCK in UI or ASP.NET contexts!
    var data = GetDataAsync().Result;
    
    // Or using .Wait()
    GetDataAsync().Wait();
}

private async Task<string> GetDataAsync()
{
    await Task.Delay(1000); // Tries to resume on captured context
    return "data";          // But calling thread is blocked!
}
```

**Why Deadlock Occurs:**
1. `GetDataAsync()` captures the synchronization context
2. Calling thread blocks on `.Result` or `.Wait()`
3. When `await` completes, it tries to resume on the captured context
4. The context is blocked waiting for the result
5. Neither can proceed → deadlock

**✅ The Solution:**
```csharp
// Make the calling code async
public async Task LoadDataAsync()
{
    var data = await GetDataAsync(); // No deadlock!
}

// If you MUST block (rare), use Task.Run
public void LoadData()
{
    // Runs on thread pool - no context to deadlock on
    var data = Task.Run(() => GetDataAsync()).Result;
}
```

#### 3. Not Using ConfigureAwait(false) in Libraries

**❌ The Problem:**
```csharp
// Library code
public async Task<string> FetchDataAsync()
{
    var response = await _httpClient.GetStringAsync(url);
    return response.ToUpper();
}
// Captures context unnecessarily - slower, deadlock risk for callers
```

**✅ The Solution:**
```csharp
// Library code
public async Task<string> FetchDataAsync()
{
    var response = await _httpClient.GetStringAsync(url)
        .ConfigureAwait(false);
    return response.ToUpper();
}
// Doesn't capture context - faster, safer
```

**When to Use:**
- ✅ Always in library code
- ✅ In ASP.NET Core for better scalability
- ❌ Never before updating UI elements
- ⚠️ Apply to every await in the method

#### 4. Preferring Task.Run Over Task.FromResult

**❌ The Problem:**
```csharp
// Unnecessarily schedules work on thread pool
public Task<int> GetCachedValueAsync()
{
    return Task.Run(() => _cachedValue);
}
```

**✅ The Solution:**
```csharp
// Returns completed Task without thread pool overhead
public Task<int> GetCachedValueAsync()
{
    return Task.FromResult(_cachedValue);
}

// Or for void operations
public Task DoNothingAsync()
{
    return Task.CompletedTask;
}
```

#### 5. Not Passing CancellationToken

**❌ The Problem:**
```csharp
public async Task<List<Data>> FetchAllDataAsync()
{
    var result = new List<Data>();
    for (int i = 0; i < 1000; i++)
    {
        // No way to cancel this long-running operation
        var data = await _repository.GetAsync(i);
        result.Add(data);
    }
    return result;
}
```

**✅ The Solution:**
```csharp
public async Task<List<Data>> FetchAllDataAsync(
    CancellationToken cancellationToken = default)
{
    var result = new List<Data>();
    for (int i = 0; i < 1000; i++)
    {
        cancellationToken.ThrowIfCancellationRequested();
        
        var data = await _repository.GetAsync(i, cancellationToken);
        result.Add(data);
    }
    return result;
}

// Usage with timeout
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
try
{
    var data = await FetchAllDataAsync(cts.Token);
}
catch (OperationCanceledException)
{
    Console.WriteLine("Operation timed out");
}
```

#### 6. Using ContinueWith Instead of await

**❌ The Problem:**
```csharp
public Task ProcessDataAsync()
{
    return GetDataAsync().ContinueWith(task =>
    {
        // More verbose, doesn't respect sync context
        var data = task.Result;
        return ProcessData(data);
    });
}
```

**✅ The Solution:**
```csharp
public async Task ProcessDataAsync()
{
    // Cleaner, respects sync context, better exception handling
    var data = await GetDataAsync();
    return ProcessData(data);
}
```

#### 7. Unnecessary async/await

**❌ The Problem:**
```csharp
// Unnecessary state machine allocation
public async Task<User> GetUserAsync(int id)
{
    return await _repository.GetUserAsync(id);
}
```

**✅ The Solution:**
```csharp
// Return Task directly - no state machine overhead
public Task<User> GetUserAsync(int id)
{
    return _repository.GetUserAsync(id);
}

// ⚠️ But keep async/await if you need try/catch or using
public async Task<User> GetUserAsync(int id)
{
    try
    {
        return await _repository.GetUserAsync(id);
    }
    catch (NotFoundException)
    {
        return null;
    }
}
```

#### 8. Sync-Over-Async in Constructors

**❌ The Problem:**
```csharp
public class DataService
{
    private readonly Data _data;
    
    // Constructors can't be async
    public DataService()
    {
        // Deadlock risk!
        _data = LoadDataAsync().Result;
    }
}
```

**✅ The Solution:**
```csharp
public class DataService
{
    private Data? _data;
    
    // Lazy initialization
    public async Task<Data> GetDataAsync()
    {
        _data ??= await LoadDataAsync();
        return _data;
    }
    
    // Or use a factory pattern
    public static async Task<DataService> CreateAsync()
    {
        var service = new DataService();
        service._data = await service.LoadDataAsync();
        return service;
    }
}
```

### Debugging Async Code

#### Visual Studio Tools

**1. Parallel Stacks Window (Tasks View)**
```
Debug → Windows → Parallel Stacks
Switch to "Tasks" view
```
- Shows all running tasks and their call stacks
- Identifies deadlocked tasks
- Visualizes task dependencies

**2. Tasks Window**
```
Debug → Windows → Tasks
```
- Lists all Task instances
- Shows status (Running, Waiting, Completed, Faulted)
- Allows switching to task context

**3. Async Call Stacks**
- Enhanced call stacks showing async transitions
- Displays `[Async]` markers
- Shows state machine transitions

#### Debugging Techniques

**1. Detect Deadlocks**
```csharp
// Set breakpoint and check:
// - Is thread blocked on .Result or .Wait()?
// - Is there a captured SynchronizationContext?
// - Are tasks waiting for each other?
```

**2. Track Unhandled Exceptions**
```csharp
// In Program.cs or startup
TaskScheduler.UnobservedTaskException += (sender, args) =>
{
    Console.WriteLine($"Unobserved exception: {args.Exception}");
    args.SetObserved(); // Prevent app crash
};
```

**3. Use Async-Friendly Logging**
```csharp
public async Task ProcessAsync()
{
    _logger.LogInformation("Starting process on thread {ThreadId}", 
        Environment.CurrentManagedThreadId);
    
    await Task.Delay(100);
    
    _logger.LogInformation("Resumed on thread {ThreadId}", 
        Environment.CurrentManagedThreadId);
}
```

### Best Practices Summary

```csharp
// ✅ DO: Use async/await throughout
public async Task<Result> ProcessAsync(CancellationToken ct)
{
    try
    {
        var data = await FetchDataAsync(ct).ConfigureAwait(false);
        return await ProcessDataAsync(data, ct).ConfigureAwait(false);
    }
    catch (OperationCanceledException)
    {
        return Result.Cancelled();
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Processing failed");
        throw;
    }
}

// ❌ DON'T: Mix sync and async, block on async code
public Result Process()
{
    var data = FetchDataAsync().Result; // DEADLOCK!
    return ProcessData(data);
}
```

### Exception Handling Patterns

**Pattern 1: Let Exceptions Propagate**
```csharp
public async Task<User> GetUserAsync(int id)
{
    // Let exceptions propagate to caller
    return await _repository.GetUserAsync(id);
}
```

**Pattern 2: Handle and Return Result**
```csharp
public async Task<Result<User>> TryGetUserAsync(int id)
{
    try
    {
        var user = await _repository.GetUserAsync(id);
        return Result<User>.Success(user);
    }
    catch (NotFoundException)
    {
        return Result<User>.NotFound();
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Failed to get user {Id}", id);
        return Result<User>.Error(ex.Message);
    }
}
```

**Pattern 3: Handle and Log**
```csharp
public async Task ProcessUserAsync(int id)
{
    try
    {
        var user = await GetUserAsync(id);
        await ProcessAsync(user);
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Error processing user {Id}", id);
        // Re-throw or handle appropriately
        throw;
    }
}
```

### Progress Reporting

```csharp
public async Task ProcessLargeDatasetAsync(
    IProgress<ProgressReport> progress,
    CancellationToken cancellationToken)
{
    var items = await GetItemsAsync();
    int total = items.Count;
    
    for (int i = 0; i < total; i++)
    {
        cancellationToken.ThrowIfCancellationRequested();
        
        await ProcessItemAsync(items[i]);
        
        // Report progress
        progress?.Report(new ProgressReport
        {
            Current = i + 1,
            Total = total,
            Message = $"Processed {i + 1} of {total}"
        });
    }
}

// Usage in UI
var progress = new Progress<ProgressReport>(report =>
{
    progressBar.Value = (report.Current * 100) / report.Total;
    statusLabel.Text = report.Message;
});

await ProcessLargeDatasetAsync(progress, cts.Token);
```
