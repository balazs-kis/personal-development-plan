## Introduction

Object pooling is a performance optimization technique that reuses objects instead of constantly creating and destroying them. ArrayPool<T>, introduced in .NET Core, provides a high-performance pool for arrays, dramatically reducing allocations in scenarios where temporary buffers are frequently needed. This lesson explores how to use pooling effectively to minimize garbage collection overhead in performance-critical applications.

## Key Concepts Summary

### The Problem ArrayPool Solves

**Without Pooling:**
```csharp
public void ProcessData()
{
    for (int i = 0; i < 10000; i++)
    {
        byte[] buffer = new byte[4096]; // ❌ 10,000 allocations!
        ReadData(buffer);
        ProcessBuffer(buffer);
        // buffer becomes garbage
    }
    // GC pressure: ~40 MB allocated, frequent collections
}
```

**With Pooling:**
```csharp
public void ProcessData()
{
    for (int i = 0; i < 10000; i++)
    {
        byte[] buffer = ArrayPool<byte>.Shared.Rent(4096); // ✅ Reuses arrays
        try
        {
            ReadData(buffer);
            ProcessBuffer(buffer);
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(buffer); // Return to pool
        }
    }
    // GC pressure: Minimal, arrays are reused
}
```

### ArrayPool<T> Basics

**Getting an Array:**
```csharp
// Rent an array from the shared pool
byte[] buffer = ArrayPool<byte>.Shared.Rent(minimumLength: 1024);

// Array may be larger than requested
Console.WriteLine($"Requested: 1024, Got: {buffer.Length}"); // Might be 2048 or 4096
```

**Returning an Array:**
```csharp
// Always return to pool when done
ArrayPool<byte>.Shared.Return(buffer);

// Optionally clear the array before returning
ArrayPool<byte>.Shared.Return(buffer, clearArray: true);
```

### Critical Rules

1. **Always Return Arrays**
   ```csharp
   // ❌ Bad - array never returned, memory leak
   public byte[] GetBuffer()
   {
       return ArrayPool<byte>.Shared.Rent(1024);
   }
   
   // ✅ Good - caller responsible for returning
   public void ProcessWithBuffer(Action<byte[]> action)
   {
       byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
       try
       {
           action(buffer);
       }
       finally
       {
           ArrayPool<byte>.Shared.Return(buffer);
       }
   }
   ```

2. **Don't Use After Returning**
   ```csharp
   byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
   ProcessData(buffer);
   ArrayPool<byte>.Shared.Return(buffer);
   
   // ❌ Buffer may have been given to another thread!
   Console.WriteLine(buffer[0]); // Undefined behavior
   ```

3. **Use try-finally Pattern**
   ```csharp
   byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
   try
   {
       ProcessData(buffer);
   }
   finally
   {
       ArrayPool<byte>.Shared.Return(buffer); // Always returns, even on exception
   }
   ```

4. **Be Aware of Array Size**
   ```csharp
   byte[] buffer = ArrayPool<byte>.Shared.Rent(100);
   
   // ❌ Wrong - using Length of pooled array
   for (int i = 0; i < buffer.Length; i++) // Might iterate 128 or 256 times!
   {
       buffer[i] = 0;
   }
   
   // ✅ Correct - use the size you need
   int requestedSize = 100;
   for (int i = 0; i < requestedSize; i++)
   {
       buffer[i] = 0;
   }
   ```

### Common Patterns

#### 1. File I/O
```csharp
public async Task<byte[]> ReadFileAsync(string path)
{
    using var stream = File.OpenRead(path);
    using var memoryStream = new MemoryStream();
    
    byte[] buffer = ArrayPool<byte>.Shared.Rent(81920); // 80 KB buffer
    try
    {
        int bytesRead;
        while ((bytesRead = await stream.ReadAsync(buffer, 0, buffer.Length)) > 0)
        {
            await memoryStream.WriteAsync(buffer, 0, bytesRead);
        }
        return memoryStream.ToArray();
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer);
    }
}
```

#### 2. JSON Serialization
```csharp
public string SerializeToJson<T>(T obj)
{
    var bufferWriter = new ArrayBufferWriter<byte>();
    using var writer = new Utf8JsonWriter(bufferWriter);
    
    JsonSerializer.Serialize(writer, obj);
    
    return Encoding.UTF8.GetString(bufferWriter.WrittenSpan);
}
```

#### 3. String Building
```csharp
public string BuildLargeString(IEnumerable<string> parts)
{
    char[] buffer = ArrayPool<char>.Shared.Rent(4096);
    try
    {
        int position = 0;
        foreach (var part in parts)
        {
            if (position + part.Length > buffer.Length)
            {
                // Resize if needed
                char[] newBuffer = ArrayPool<char>.Shared.Rent(buffer.Length * 2);
                Array.Copy(buffer, newBuffer, position);
                ArrayPool<char>.Shared.Return(buffer);
                buffer = newBuffer;
            }
            
            part.CopyTo(0, buffer, position, part.Length);
            position += part.Length;
        }
        
        return new string(buffer, 0, position);
    }
    finally
    {
        ArrayPool<char>.Shared.Return(buffer);
    }
}
```

#### 4. Middleware in ASP.NET Core
```csharp
public class ResponseBufferingMiddleware
{
    private readonly RequestDelegate _next;
    
    public async Task InvokeAsync(HttpContext context)
    {
        var originalBodyStream = context.Response.Body;
        
        byte[] buffer = ArrayPool<byte>.Shared.Rent(4096);
        try
        {
            using var memoryStream = new MemoryStream();
            context.Response.Body = memoryStream;
            
            await _next(context);
            
            memoryStream.Position = 0;
            await memoryStream.CopyToAsync(originalBodyStream);
        }
        finally
        {
            context.Response.Body = originalBodyStream;
            ArrayPool<byte>.Shared.Return(buffer);
        }
    }
}
```

### Custom ArrayPool

Create a custom pool for specialized scenarios:

```csharp
// Create a pool with specific limits
var customPool = ArrayPool<byte>.Create(
    maxArrayLength: 1024 * 1024,  // 1 MB max
    maxArraysPerBucket: 50         // Keep up to 50 arrays per size bucket
);

byte[] buffer = customPool.Rent(4096);
try
{
    // Use buffer
}
finally
{
    customPool.Return(buffer);
}
```

**When to use custom pools:**
- Different size requirements than shared pool
- Want to limit memory usage
- Need per-component isolation
- Specific workload characteristics

### ObjectPool<T> for Custom Types

For pooling custom objects:

```csharp
using Microsoft.Extensions.ObjectPool;

public class ExpensiveObject
{
    public byte[] Buffer { get; private set; }
    
    public ExpensiveObject()
    {
        Buffer = new byte[10000];
    }
    
    public void Reset()
    {
        Array.Clear(Buffer, 0, Buffer.Length);
    }
}

// Create a pooled object policy
public class ExpensiveObjectPolicy : PooledObjectPolicy<ExpensiveObject>
{
    public override ExpensiveObject Create()
    {
        return new ExpensiveObject();
    }
    
    public override bool Return(ExpensiveObject obj)
    {
        obj.Reset(); // Clean up before returning to pool
        return true; // true = add to pool, false = don't pool
    }
}

// Use the pool
public class MyService
{
    private readonly ObjectPool<ExpensiveObject> _pool;
    
    public MyService()
    {
        var policy = new ExpensiveObjectPolicy();
        _pool = new DefaultObjectPool<ExpensiveObject>(policy, maximumRetained: 10);
    }
    
    public void ProcessData()
    {
        ExpensiveObject obj = _pool.Get();
        try
        {
            // Use obj
        }
        finally
        {
            _pool.Return(obj);
        }
    }
}
```

### When to Use Pooling

**✅ Use pooling when:**
- Creating/destroying many short-lived arrays or objects
- Hot path with high allocation rates
- Profiling shows GC pressure from temporary buffers
- Objects are expensive to construct
- Application is throughput-sensitive (web servers, data processing)

**❌ Don't use pooling when:**
- Objects live for a long time
- Low allocation rate
- Objects can't be safely reused (hold sensitive data)
- Complexity outweighs benefits
- Memory usage is more important than speed

### Performance Considerations

**Benchmark Results (typical scenario):**

```
| Method          | Mean     | Allocated |
|---------------- |---------:|----------:|
| NoPooling       | 245.3 μs | 40.97 MB  |
| WithArrayPool   |  89.7 μs |  0.12 MB  |
```

**Benefits:**
- 60-90% reduction in allocations
- 2-3x speed improvement (less GC)
- Reduced Gen 2 collections
- More predictable latency

**Costs:**
- Code complexity (rent/return pattern)
- Risk of use-after-return bugs
- Memory held by pool (not freed to OS immediately)
- Thread synchronization overhead

### Common Pitfalls

#### 1. Forgetting to Return
```csharp
// ❌ Memory leak
public void Process()
{
    byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
    DoWork(buffer);
    // Forgot to return!
}

// ✅ Use try-finally
public void Process()
{
    byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
    try
    {
        DoWork(buffer);
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer);
    }
}
```

#### 2. Not Clearing Sensitive Data
```csharp
// ❌ Password data might leak to other code
byte[] passwordBuffer = ArrayPool<byte>.Shared.Rent(256);
try
{
    GetPasswordBytes(passwordBuffer);
}
finally
{
    ArrayPool<byte>.Shared.Return(passwordBuffer); // Not cleared!
}

// ✅ Clear sensitive data
finally
{
    ArrayPool<byte>.Shared.Return(passwordBuffer, clearArray: true);
}
```

#### 3. Incorrect Benchmarking
```csharp
// ❌ Bad benchmark - dead code elimination
[Benchmark]
public void RentAndReturn()
{
    byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
    ArrayPool<byte>.Shared.Return(buffer);
    // JIT might optimize this away!
}

// ✅ Good benchmark - actually use the buffer
[Benchmark]
public void RentUseReturn()
{
    byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
    try
    {
        BlackBox(buffer[0]); // Prevent optimization
        buffer[0] = 42; // Actual usage
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer);
    }
}

[MethodImpl(MethodImplOptions.NoInlining)]
private static void BlackBox<T>(T value) { }
```

### Best Practices

1. **Always use try-finally**
2. **Clear arrays containing sensitive data**
3. **Track the requested size, not array.Length**
4. **Don't store references to returned arrays**
5. **Return as soon as possible to minimize pool contention**
6. **Profile before and after to validate improvements**
7. **Consider custom pools for specific scenarios**
8. **Document that callers must return pooled arrays**
