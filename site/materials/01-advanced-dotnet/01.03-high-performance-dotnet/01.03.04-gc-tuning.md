## Introduction

The .NET garbage collector is a sophisticated automatic memory management system that handles allocation and cleanup of managed objects. While the GC works well by default, understanding its internals and configuration options allows you to optimize performance for specific workloads. This lesson covers GC fundamentals, configuration strategies, and techniques to minimize garbage collection overhead.

## Key Concepts Summary

### How the GC Works

The .NET GC uses a **generational, compacting, tracing** algorithm:

**Generations:**
```
┌─────────────────────────────────────┐
│ Gen 0: Young objects (< 1 MB)      │ ← Collected frequently
│ - Short-lived allocations          │
│ - Temporary buffers                │
├─────────────────────────────────────┤
│ Gen 1: Medium-lived objects        │ ← Buffer generation
│ - Survived one Gen 0 collection    │
├─────────────────────────────────────┤
│ Gen 2: Long-lived objects          │ ← Collected infrequently
│ - Static fields, caches            │
│ - Large application state          │
├─────────────────────────────────────┤
│ LOH: Large Object Heap (≥85 KB)   │ ← Special handling
│ - Large arrays and buffers         │
└─────────────────────────────────────┘
```

**GC Phases:**
1. **Mark**: Find all live objects by tracing references
2. **Relocate**: Update references to compacted locations
3. **Compact**: Move objects together to eliminate fragmentation (except LOH)

### Workstation vs Server GC

#### Workstation GC
```csharp
// Default for standalone apps and desktop applications
<ServerGarbageCollection>false</ServerGarbageCollection>
```

**Characteristics:**
- Single-threaded or concurrent background GC
- Optimized for low latency and UI responsiveness
- Lower memory usage
- Smaller heap sizes
- Good for desktop apps, development machines

**Memory Usage:**
- More conservative allocation
- Can reduce memory by 50-95% compared to Server GC
- Example: 1.9 GB → 85 MB in minimal APIs

#### Server GC
```csharp
// Default for ASP.NET Core hosted applications
<ServerGarbageCollection>true</ServerGarbageCollection>
```

**Characteristics:**
- Multi-threaded collection (one thread per CPU)
- Optimized for high throughput
- Higher memory usage
- Larger heap sizes
- Good for web servers, high-throughput apps

**Performance:**
- 2-3x better throughput than Workstation GC
- Parallelizes collection across cores
- Better for CPU-bound workloads

### Configuring GC Mode

**In .csproj:**
```xml
<PropertyGroup>
  <!-- Choose GC mode -->
  <ServerGarbageCollection>true</ServerGarbageCollection>
  
  <!-- Enable concurrent GC (default: true) -->
  <ConcurrentGarbageCollection>true</ConcurrentGarbageCollection>
  
  <!-- Retain VM (better for apps with fluctuating memory) -->
  <RetainVMGarbageCollection>true</RetainVMGarbageCollection>
</PropertyGroup>
```

**Via runtime configuration (runtimeconfig.json):**
```json
{
  "configProperties": {
    "System.GC.Server": true,
    "System.GC.Concurrent": true,
    "System.GC.RetainVM": true,
    "System.GC.HeapCount": 8
  }
}
```

**Via environment variables:**
```bash
# Windows
set COMPlus_gcServer=1
set COMPlus_GCHeapCount=8

# Linux/Mac
export COMPlus_gcServer=1
export COMPlus_GCHeapCount=8
```

### GC Latency Modes

Control GC behavior for time-sensitive operations:

```csharp
using System.Runtime;

public class LatencySensitiveOperation
{
    public void CriticalOperation()
    {
        // Store original mode
        var oldMode = GCSettings.LatencyMode;
        
        try
        {
            // Suppress blocking Gen 2 collections during critical work
            GCSettings.LatencyMode = GCLatencyMode.LowLatency;
            
            // Perform time-sensitive work
            ProcessRealtimeData();
        }
        finally
        {
            // Restore original mode
            GCSettings.LatencyMode = oldMode;
            
            // Optional: force cleanup after critical section
            GC.Collect();
        }
    }
}
```

**Available Latency Modes:**

| Mode | Description | Use Case |
|------|-------------|----------|
| **Batch** | Disables concurrent GC | Throughput-critical batch processing |
| **Interactive** | Default for Workstation GC | Desktop applications |
| **LowLatency** | Suppresses blocking Gen 2 collections | Short-duration critical sections |
| **SustainedLowLatency** | Background Gen 2 collections | Longer low-latency requirements |
| **NoGCRegion** | Prevents any GC | Ultra-low latency (use carefully) |

### Reducing GC Pressure

#### 1. Object Pooling
```csharp
// ❌ Creates garbage
public void ProcessRequests()
{
    for (int i = 0; i < 10000; i++)
    {
        var buffer = new byte[4096]; // 10,000 allocations!
        ProcessRequest(buffer);
    }
}

// ✅ Reuses objects
public void ProcessRequests()
{
    byte[] buffer = ArrayPool<byte>.Shared.Rent(4096);
    try
    {
        for (int i = 0; i < 10000; i++)
        {
            ProcessRequest(buffer);
        }
    }
    finally
    {
        ArrayPool<byte>.Shared.Return(buffer);
    }
}
```

#### 2. Use Value Types
```csharp
// ❌ Heap allocation
public class Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

// ✅ Stack allocation (if used as local)
public struct Point
{
    public int X { get; set; }
    public int Y { get; set; }
}
```

#### 3. Avoid Boxing
```csharp
// ❌ Boxing allocation
int value = 42;
object obj = value; // Boxes to heap

// ✅ Generic to avoid boxing
public void Process<T>(T value) where T : struct
{
    // No boxing
}
```

#### 4. Use Span<T> and stackalloc
```csharp
// ❌ Allocates array
byte[] buffer = new byte[256];

// ✅ Stack allocation
Span<byte> buffer = stackalloc byte[256];
```

#### 5. Manage Large Objects Carefully
```csharp
// ❌ Goes to LOH (Large Object Heap) - never compacted
byte[] large = new byte[100_000]; // ≥85 KB

// ✅ Use ArrayPool for large buffers
byte[] large = ArrayPool<byte>.Shared.Rent(100_000);
try
{
    // Use large buffer
}
finally
{
    ArrayPool<byte>.Shared.Return(large);
}
```

### Monitoring GC Performance

#### Using GC API
```csharp
public class GCMonitor
{
    public void PrintGCInfo()
    {
        Console.WriteLine($"GC Mode: {(GCSettings.IsServerGC ? "Server" : "Workstation")}");
        Console.WriteLine($"Latency Mode: {GCSettings.LatencyMode}");
        Console.WriteLine($"Total Memory: {GC.GetTotalMemory(false):N0} bytes");
        
        for (int gen = 0; gen <= GC.MaxGeneration; gen++)
        {
            Console.WriteLine($"Gen {gen} collections: {GC.CollectionCount(gen)}");
        }
    }
    
    public void MonitorGCDuringOperation()
    {
        int gen0Before = GC.CollectionCount(0);
        int gen1Before = GC.CollectionCount(1);
        int gen2Before = GC.CollectionCount(2);
        
        // Perform operation
        DoWork();
        
        int gen0After = GC.CollectionCount(0);
        int gen1After = GC.CollectionCount(1);
        int gen2After = GC.CollectionCount(2);
        
        Console.WriteLine($"Gen 0: {gen0After - gen0Before} collections");
        Console.WriteLine($"Gen 1: {gen1After - gen1Before} collections");
        Console.WriteLine($"Gen 2: {gen2After - gen2Before} collections");
    }
}
```

#### Using Performance Counters
```csharp
using System.Diagnostics;

public class GCPerformanceMonitor
{
    private PerformanceCounter _gen0Counter;
    private PerformanceCounter _gen1Counter;
    private PerformanceCounter _gen2Counter;
    private PerformanceCounter _timeInGCCounter;
    
    public GCPerformanceMonitor()
    {
        string processName = Process.GetCurrentProcess().ProcessName;
        
        _gen0Counter = new PerformanceCounter(".NET CLR Memory", "# Gen 0 Collections", processName);
        _gen1Counter = new PerformanceCounter(".NET CLR Memory", "# Gen 1 Collections", processName);
        _gen2Counter = new PerformanceCounter(".NET CLR Memory", "# Gen 2 Collections", processName);
        _timeInGCCounter = new PerformanceCounter(".NET CLR Memory", "% Time in GC", processName);
    }
    
    public void PrintCounters()
    {
        Console.WriteLine($"Gen 0 Collections: {_gen0Counter.NextValue()}");
        Console.WriteLine($"Gen 1 Collections: {_gen1Counter.NextValue()}");
        Console.WriteLine($"Gen 2 Collections: {_gen2Counter.NextValue()}");
        Console.WriteLine($"% Time in GC: {_timeInGCCounter.NextValue():F2}%");
    }
}
```

### Best Practices

#### 1. Choose the Right GC Mode
```csharp
// ASP.NET Core web API - use Server GC
<ServerGarbageCollection>true</ServerGarbageCollection>

// Desktop WPF app - use Workstation GC
<ServerGarbageCollection>false</ServerGarbageCollection>

// Console app processing files - try both, measure
```

#### 2. Minimize Allocations
```csharp
// ✅ Reuse objects
private readonly StringBuilder _builder = new();

public string BuildString()
{
    _builder.Clear();
    _builder.Append("Hello");
    _builder.Append(" World");
    return _builder.ToString();
}
```

#### 3. Be Careful with Finalizers
```csharp
// ❌ Finalizer slows down GC
public class BadClass
{
    ~BadClass() // Finalizer
    {
        Cleanup();
    }
}

// ✅ IDisposable pattern instead
public class GoodClass : IDisposable
{
    public void Dispose()
    {
        Cleanup();
        GC.SuppressFinalize(this); // Don't need finalizer
    }
}
```

#### 4. Avoid Gen 2 Collections
```csharp
// Gen 2 collections are expensive
// Strategies:
// - Use object pooling
// - Reduce long-lived allocations
// - Keep Gen 0/1 small
// - Profile and optimize hot paths
```

#### Real-Time Processing
```csharp
public void ProcessRealTimeData()
{
    var oldMode = GCSettings.LatencyMode;
    try
    {
        // Minimize GC pauses during processing
        GCSettings.LatencyMode = GCLatencyMode.SustainedLowLatency;
        
        while (ProcessNextFrame())
        {
            // Real-time work
        }
    }
    finally
    {
        GCSettings.LatencyMode = oldMode;
    }
}
```
