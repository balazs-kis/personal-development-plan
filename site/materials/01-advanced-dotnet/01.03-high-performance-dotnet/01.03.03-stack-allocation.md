## Learning Objectives

By the end of this lesson, you will be able to:

---

## Introduction

Stack allocation (`stackalloc`) allows you to allocate memory directly on the call stack rather than the heap, eliminating garbage collection overhead entirely. Combined with Span<T> and ref structs, stack allocation enables writing allocation-free code for performance-critical hot paths. This lesson explores how to leverage the stack safely and effectively for maximum performance.

## Key Concepts Summary

### Stack vs Heap Allocation

**Heap Allocation (Traditional):**
```csharp
byte[] buffer = new byte[1024]; // ❌ Heap allocation
// - Requires GC to clean up
// - Slower allocation
// - Lives beyond method scope
// - Can be stored in fields
```

**Stack Allocation:**
```csharp
Span<byte> buffer = stackalloc byte[1024]; // ✅ Stack allocation
// - No GC needed (auto-freed when method returns)
// - Extremely fast allocation
// - Only lives during method execution
// - Cannot escape method scope
```

### Basic stackalloc Usage

#### Simple Example
```csharp
public void ProcessData()
{
    // Allocate 256 bytes on the stack
    Span<byte> buffer = stackalloc byte[256];
    
    // Use like an array
    buffer[0] = 42;
    buffer[1] = 100;
    
    // Fill with data
    for (int i = 0; i < buffer.Length; i++)
    {
        buffer[i] = (byte)i;
    }
    
    ProcessBuffer(buffer);
    
    // Automatically freed when method returns
}
```

#### With ReadOnlySpan
```csharp
public int CountOccurrences(string text, char target)
{
    ReadOnlySpan<char> span = text.AsSpan();
    int count = 0;
    
    foreach (char c in span)
    {
        if (c == target) count++;
    }
    
    return count;
}
```

### Safe Stack Allocation Sizes

Stack space is limited (typically 1 MB for 64-bit apps), so stack allocation must be bounded:

```csharp
// ✅ Safe - small, fixed size
Span<int> small = stackalloc int[10];

// ⚠️ Risky - large allocation
Span<byte> large = stackalloc byte[100_000]; // Might overflow!

// ✅ Safe - conditional allocation
const int MaxStackSize = 512;
Span<byte> buffer = size <= MaxStackSize
    ? stackalloc byte[size]
    : new byte[size];
```

**Common Pattern:**
```csharp
public void ProcessData(int size)
{
    const int StackThreshold = 512;
    
    // Use stack for small buffers, heap for large
    byte[]? rentedArray = null;
    Span<byte> buffer = size <= StackThreshold
        ? stackalloc byte[size]
        : (rentedArray = ArrayPool<byte>.Shared.Rent(size));
    
    try
    {
        // Use buffer regardless of source
        ProcessBuffer(buffer.Slice(0, size));
    }
    finally
    {
        if (rentedArray != null)
        {
            ArrayPool<byte>.Shared.Return(rentedArray);
        }
    }
}
```

### Ref Structs

Ref structs are value types that must live on the stack:

```csharp
public ref struct StackOnlyStruct
{
    public int Value;
    public Span<byte> Buffer;
    
    public StackOnlyStruct(int value)
    {
        Value = value;
        Buffer = stackalloc byte[256];
    }
}

// Usage
public void UseRefStruct()
{
    var s = new StackOnlyStruct(42);
    s.Buffer[0] = 1;
}
```

**Why ref structs?**
- Can contain other stack-only types (Span<T>)
- Cannot escape to heap
- Zero allocation overhead
- Compiler enforces stack-only semantics

### Ref Struct Constraints

**Cannot be:**
```csharp
// ❌ Can't be boxed
object obj = myRefStruct; // Won't compile

// ❌ Can't be fields in regular classes/structs
public class MyClass
{
    private Span<byte> _buffer; // Won't compile
}

// ❌ Can't be array elements
Span<byte>[] array = new Span<byte>[10]; // Won't compile

// ❌ Can't be captured in lambdas
Span<byte> buffer = stackalloc byte[10];
Action action = () => buffer[0] = 1; // Won't compile

// ❌ Can't be used in async methods (mostly)
public async Task ProcessAsync()
{
    Span<byte> buffer = stackalloc byte[10]; // Won't compile
    await Task.Delay(100);
}
```

**Can be:**
```csharp
// ✅ Can be local variables
Span<byte> local = stackalloc byte[10];

// ✅ Can be method parameters
void Process(Span<byte> buffer) { }

// ✅ Can be method return values
Span<int> GetSpan() => _array.AsSpan();

// ✅ Can implement interfaces (C# 13+)
public ref struct MyRefStruct : IDisposable
{
    public void Dispose() { }
}
```

### Common Patterns

#### 1. String Manipulation
```csharp
public string ReverseString(string input)
{
    if (input.Length <= 128)
    {
        // Use stack for small strings
        Span<char> buffer = stackalloc char[input.Length];
        input.AsSpan().CopyTo(buffer);
        buffer.Reverse();
        return new string(buffer);
    }
    else
    {
        // Use heap for large strings
        char[] array = input.ToCharArray();
        Array.Reverse(array);
        return new string(array);
    }
}
```

#### 2. Number Formatting
```csharp
public string FormatNumber(int value)
{
    Span<char> buffer = stackalloc char[11]; // Max digits for int + sign
    
    if (value.TryFormat(buffer, out int charsWritten))
    {
        return new string(buffer.Slice(0, charsWritten));
    }
    
    return value.ToString(); // Fallback
}
```

#### 3. Data Transformation
```csharp
public void TransformData(ReadOnlySpan<byte> input, Span<byte> output)
{
    // Temporary lookup table on stack
    Span<byte> lookup = stackalloc byte[256];
    
    // Initialize lookup
    for (int i = 0; i < 256; i++)
    {
        lookup[i] = (byte)((i * 2) % 256);
    }
    
    // Apply transformation
    for (int i = 0; i < input.Length; i++)
    {
        output[i] = lookup[input[i]];
    }
}
```

#### 4. Parsing
```csharp
public (int x, int y) ParseCoordinates(ReadOnlySpan<char> input)
{
    // Parse "123,456" without allocations
    int commaIndex = input.IndexOf(',');
    
    ReadOnlySpan<char> xSpan = input.Slice(0, commaIndex);
    ReadOnlySpan<char> ySpan = input.Slice(commaIndex + 1);
    
    int x = int.Parse(xSpan);
    int y = int.Parse(ySpan);
    
    return (x, y);
}
```

#### 5. Buffering for Performance
```csharp
public void WriteData(Stream stream, ReadOnlySpan<byte> data)
{
    const int BufferSize = 512;
    Span<byte> buffer = stackalloc byte[BufferSize];
    
    int offset = 0;
    while (offset < data.Length)
    {
        int chunkSize = Math.Min(BufferSize, data.Length - offset);
        data.Slice(offset, chunkSize).CopyTo(buffer);
        
        stream.Write(buffer.Slice(0, chunkSize));
        offset += chunkSize;
    }
}
```

### Creating Custom Ref Structs

```csharp
public ref struct BufferWriter
{
    private readonly Span<byte> _buffer;
    private int _position;
    
    public BufferWriter(Span<byte> buffer)
    {
        _buffer = buffer;
        _position = 0;
    }
    
    public void WriteByte(byte value)
    {
        if (_position >= _buffer.Length)
            throw new InvalidOperationException("Buffer full");
            
        _buffer[_position++] = value;
    }
    
    public void WriteInt32(int value)
    {
        Span<byte> slice = _buffer.Slice(_position, 4);
        BitConverter.TryWriteBytes(slice, value);
        _position += 4;
    }
    
    public ReadOnlySpan<byte> WrittenBytes => _buffer.Slice(0, _position);
}

// Usage
public void UseBufferWriter()
{
    Span<byte> buffer = stackalloc byte[1024];
    var writer = new BufferWriter(buffer);
    
    writer.WriteByte(42);
    writer.WriteInt32(12345);
    
    ReadOnlySpan<byte> written = writer.WrittenBytes;
    Console.WriteLine($"Wrote {written.Length} bytes");
}
```

### Performance Considerations

**Benefits:**
- Zero heap allocations
- No GC pressure
- Extremely fast allocation/deallocation
- Ideal for hot paths
- Better cache locality

**Costs:**
- Limited stack space
- Can cause stack overflow if misused
- Cannot be used in async methods
- More restrictive than heap allocation

**Benchmark Example:**
```
| Method          | Mean      | Allocated |
|---------------- |----------:|----------:|
| HeapAllocation  | 125.0 ns  |     152 B |
| StackAllocation |  45.2 ns  |       0 B |
```

### Safety Features

C# prevents dangerous stack allocation patterns:

```csharp
// ❌ Can't return stackalloc'd memory
public Span<byte> GetBuffer()
{
    Span<byte> buffer = stackalloc byte[10];
    return buffer; // Compiler error!
}

// ❌ Can't store in heap
private Span<byte> _field;
public void Initialize()
{
    _field = stackalloc byte[10]; // Compiler error!
}

// ✅ Can pass to methods
public void UseBuffer()
{
    Span<byte> buffer = stackalloc byte[10];
    ProcessBuffer(buffer); // OK - stays on stack
}

private void ProcessBuffer(Span<byte> buffer)
{
    buffer[0] = 42;
}
```

### C# 13 Improvements

C# 13 relaxed some ref struct restrictions:

```csharp
// ✅ Can implement interfaces
public ref struct MyRefStruct : IDisposable
{
    public void Dispose() { }
}

// ✅ Limited async support
public async Task ProcessAsync()
{
    // Can use ref structs if they don't cross await boundaries
    Span<byte> buffer = stackalloc byte[10];
    buffer[0] = 42; // Use before await
    
    await Task.Delay(100); // OK - buffer not used after
}
```

### Best Practices

1. **Keep stack allocations small**
   - Use ≤512 bytes as rule of thumb
   - Fallback to heap for larger sizes

2. **Use const for size limits**
   ```csharp
   const int MaxStackSize = 512;
   Span<byte> buffer = size <= MaxStackSize
       ? stackalloc byte[size]
       : new byte[size];
   ```

3. **Prefer stackalloc for temporary buffers**
   - String operations
   - Parsing
   - Data transformations
   - Encoding/decoding

4. **Don't over-optimize**
   - Profile first
   - Only use in hot paths
   - Heap allocation is fine for most code

5. **Document stack usage**
   ```csharp
   /// <summary>
   /// Uses stack allocation for buffers up to 512 bytes.
   /// </summary>
   public void ProcessData(int size) { }
   ```
