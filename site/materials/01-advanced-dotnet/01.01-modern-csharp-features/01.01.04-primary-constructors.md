## Introduction

C# continues to evolve with features that reduce boilerplate code and improve expressiveness. Primary constructors (C# 12) bring the concise syntax from records to all classes and structs. Collection expressions (C# 12) provide a unified, terse syntax for creating collections. This lesson covers these modern features and explores what's coming next in the C# ecosystem.

## Key Concepts Summary

### Primary Constructors

Primary constructors allow you to declare constructor parameters directly in the class or struct declaration:

#### Basic Syntax

```csharp
// Traditional class
public class TraditionalPerson
{
    private readonly string _firstName;
    private readonly string _lastName;
    
    public TraditionalPerson(string firstName, string lastName)
    {
        _firstName = firstName;
        _lastName = lastName;
    }
}

// With primary constructor
public class Person(string firstName, string lastName)
{
    // Parameters are available throughout the class
    public string FullName => $"{firstName} {lastName}";
}
```

#### Important Differences from Records

| Feature | Record Primary Constructor | Class Primary Constructor |
|---------|---------------------------|--------------------------|
| **Parameter Capture** | Automatic public properties | Parameters stay as parameters |
| **Accessibility** | Can access via `this.FirstName` | Cannot use `this.firstName` |
| **Storage** | Always stored | Only stored if used |
| **Primary Use** | Data modeling | Dependency injection |

```csharp
// Record - parameters become properties
public record PersonRecord(string FirstName, string LastName);
var person = new PersonRecord("John", "Doe");
Console.WriteLine(person.FirstName); // ✅ Works

// Class - parameters remain parameters
public class PersonClass(string firstName, string lastName)
{
    public string FullName => $"{firstName} {lastName}";
}
var person2 = new PersonClass("John", "Doe");
// Console.WriteLine(person2.firstName); // ❌ Doesn't compile
```

#### Dependency Injection Pattern

Primary constructors shine with dependency injection:

```csharp
// Before
public class OrderService
{
    private readonly IOrderRepository _repository;
    private readonly ILogger<OrderService> _logger;
    private readonly IEmailService _emailService;
    
    public OrderService(
        IOrderRepository repository, 
        ILogger<OrderService> logger,
        IEmailService emailService)
    {
        _repository = repository;
        _logger = logger;
        _emailService = emailService;
    }
}

// After
public class OrderService(
    IOrderRepository repository, 
    ILogger<OrderService> logger,
    IEmailService emailService)
{
    public async Task<Order> GetOrderAsync(int id)
    {
        logger.LogInformation("Fetching order {OrderId}", id);
        return await repository.GetByIdAsync(id);
    }
}
```

#### Initializing Fields and Properties

```csharp
public class ConfigService(string apiKey, int maxRetries = 3)
{
    // Capture to fields for external access
    private readonly string _apiKey = apiKey;
    public int MaxRetries { get; } = maxRetries;
    
    // Use directly in methods
    public void LogConfiguration()
    {
        Console.WriteLine($"API Key length: {apiKey.Length}");
        Console.WriteLine($"Max retries: {maxRetries}");
    }
}
```

#### Calling Base Constructors

```csharp
public class BaseService(ILogger logger)
{
    protected void Log(string message) => logger.LogInformation(message);
}

// Derived class must call base primary constructor
public class OrderService(ILogger<OrderService> logger, IOrderRepository repository) 
    : BaseService(logger)
{
    public void ProcessOrder() => repository.Save();
}
```

#### All Other Constructors Must Chain

```csharp
public class Person(string firstName, string lastName)
{
    // Additional constructors must call primary constructor
    public Person(string firstName) : this(firstName, string.Empty)
    {
    }
    
    // ❌ This won't compile - must call primary constructor
    // public Person() { }
    
    // ✅ This works
    public Person() : this("Unknown", "Unknown")
    {
    }
}
```

### Collection Expressions (C# 12)

Collection expressions provide a unified syntax for creating collections using square brackets:

#### Basic Syntax

```csharp
// Arrays
int[] numbers = [1, 2, 3, 4, 5];

// Lists
List<string> names = ["Alice", "Bob", "Charlie"];

// Spans
Span<int> span = [1, 2, 3];
ReadOnlySpan<char> chars = ['a', 'b', 'c'];
```

#### Spread Operator (`..`)

```csharp
int[] first = [1, 2, 3];
int[] second = [4, 5, 6];

// Combine collections
int[] combined = [..first, ..second]; // [1, 2, 3, 4, 5, 6]

// Insert elements
int[] withExtra = [0, ..first, 7, ..second]; // [0, 1, 2, 3, 7, 4, 5, 6]

// Flatten nested collections
List<int> nested = [[1, 2], [3, 4]].SelectMany(x => x).ToList();
```

#### Type Inference Limitation

```csharp
// ❌ Cannot use with var
// var numbers = [1, 2, 3]; // Error: Cannot infer type

// ✅ Must specify type
int[] numbers = [1, 2, 3];
List<int> list = [1, 2, 3];
IEnumerable<int> enumerable = [1, 2, 3];
```

#### Refactoring Example

```csharp
// Before
var list = new List<string>();
list.Add("one");
list.Add("two");
list.Add("three");

// After
List<string> list = ["one", "two", "three"];

// Before
var combined = new List<int>();
combined.AddRange(firstList);
combined.AddRange(secondList);

// After
List<int> combined = [..firstList, ..secondList];
```

### C# 13 Features

#### params Collections

C# 13 extends `params` to work with more collection types:

```csharp
// C# 12 - only arrays
public void LogMessages(params string[] messages) { }

// C# 13 - any collection type
public void LogMessages(params IEnumerable<string> messages) { }
public void LogNumbers(params ReadOnlySpan<int> numbers) { }
public void ProcessItems(params List<Item> items) { }

// Call with collection expression
LogMessages(["Hello", "World"]);
LogNumbers([1, 2, 3, 4, 5]);
```

#### New Lock Type

```csharp
// C# 13 - new Lock type for better performance
private readonly Lock _lock = new();

public void ThreadSafeOperation()
{
    lock (_lock)
    {
        // Thread-safe code
    }
}
```

### Best Practices

#### When to Use Primary Constructors

**✅ Use primary constructors for:**
- Dependency injection scenarios
- Simple initialization logic
- Passing parameters to base constructors
- Reducing boilerplate in service classes

**❌ Avoid primary constructors when:**
- You need public properties (use records instead)
- Constructor has complex validation logic
- You need multiple constructors with different logic
- Team members are unfamiliar with the syntax

#### When to Use Collection Expressions

**✅ Use collection expressions for:**
- Creating collections with known elements
- Combining multiple collections
- Initializing readonly collections
- Improving code readability

**❌ Avoid collection expressions when:**
- Type inference is critical (must specify type explicitly)
- Working with very large collections (use builders/capacity hints)
- Legacy codebase where consistency matters
