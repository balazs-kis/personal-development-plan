## Introduction

The Open-Closed Principle (OCP) states that **software entities should be open for extension but closed for modification**. This powerful principle, first articulated by Bertrand Meyer in 1988 and later refined by Robert C. Martin, is fundamental to building flexible, maintainable systems.

But what does "open for extension, closed for modification" actually mean?

**Open for extension** means you can add new behavior to your system when requirements change. Your system should be designed to accommodate new features easily.

**Closed for modification** means you shouldn't have to change existing, tested code to add those new features. Your working code remains untouched, reducing the risk of introducing bugs.

### The Core Problem OCP Solves

Consider this scenario: You build a payment system that processes credit cards. Later, you need to add PayPal support. Then Stripe. Then Apple Pay. Then cryptocurrency...

**Without OCP:** You modify the payment processing code every time, risking bugs in the existing credit card logic. Testing becomes exponential—every new payment method requires retesting all existing methods.

**With OCP:** You design an extensible payment system where new payment methods plug in without touching existing code. Credit card logic remains unchanged and stable when you add PayPal.

### Real-World Analogy

Think about USB ports on your computer:
- **Closed for modification**: The USB port specification doesn't change
- **Open for extension**: New USB devices (keyboards, mice, drives, phones) can plug in without modifying the port

This is the essence of OCP: create "ports" (abstractions) in your system where new functionality can "plug in" without changing the port itself.

## Key Concepts Summary

### The Problem: Code that Violates OCP

**Classic Anti-Pattern: The ever-growing switch/if-else statement**

```csharp
// Violates OCP - must modify this code every time we add a new report type
public class ReportGenerator
{
    public string GenerateReport(string type, Data data)
    {
        if (type == "PDF")
        {
            // PDF generation logic
            var pdf = new PdfDocument();
            pdf.AddPage(data.Title);
            pdf.AddContent(data.Body);
            return pdf.Save();
        }
        else if (type == "Excel")
        {
            // Excel generation logic
            var excel = new ExcelWorkbook();
            excel.AddSheet("Data");
            excel.AddRows(data.Rows);
            return excel.Save();
        }
        else if (type == "HTML")
        {
            // HTML generation logic
            var html = new StringBuilder();
            html.Append($"<h1>{data.Title}</h1>");
            html.Append($"<div>{data.Body}</div>");
            return html.ToString();
        }
        else if (type == "XML")  // New requirement - must modify this method!
        {
            // XML generation logic
            var xml = new XmlDocument();
            // ...
            return xml.ToString();
        }
        // Adding JSON requires modifying this method AGAIN!
        // This violates OCP: modification required for extension
        return string.Empty;
    }
}
```

**Problems with this approach:**
- ❌ **Must modify working code** to add new report types
- ❌ **Risk of introducing bugs** in existing report types
- ❌ **Violation of SRP** - one method knows about all report types
- ❌ **Testing nightmare** - must retest all report types after each change
- ❌ **Merge conflicts** - multiple developers adding report types edit the same method
- ❌ **Can't extend at runtime** - all types must be known at compile time
- ❌ **Tight coupling** - report type details leak into orchestration logic

### The Solution: OCP Through Abstraction

**Design Pattern: Strategy Pattern**

```csharp
// Define the abstraction - this is our "extension point"
public interface IReportGenerator
{
    string Generate(Data data);
    string SupportedFormat { get; }
}

// Implementation 1: PDF Reports (closed for modification)
public class PdfReportGenerator : IReportGenerator
{
    public string SupportedFormat => "PDF";
    
    public string Generate(Data data)
    {
        var pdf = new PdfDocument();
        pdf.AddPage(data.Title);
        pdf.AddContent(data.Body);
        
        // Add charts if data has them
        if (data.Charts?.Any() == true)
        {
            foreach (var chart in data.Charts)
            {
                pdf.AddChart(chart);
            }
        }
        
        return pdf.Save();
    }
}

// Implementation 2: Excel Reports (closed for modification)
public class ExcelReportGenerator : IReportGenerator
{
    public string SupportedFormat => "Excel";
    
    public string Generate(Data data)
    {
        var excel = new ExcelWorkbook();
        excel.AddSheet("Data");
        excel.AddRows(data.Rows);
        
        // Add formatting
        excel.ApplyHeaderFormatting();
        excel.AutoFitColumns();
        
        return excel.Save();
    }
}

// Implementation 3: HTML Reports (closed for modification)
public class HtmlReportGenerator : IReportGenerator
{
    private readonly ITemplateEngine _templateEngine;
    
    public HtmlReportGenerator(ITemplateEngine templateEngine)
    {
        _templateEngine = templateEngine;
    }
    
    public string SupportedFormat => "HTML";
    
    public string Generate(Data data)
    {
        var template = _templateEngine.Load("ReportTemplate.html");
        return template.Render(new
        {
            Title = data.Title,
            Body = data.Body,
            Timestamp = DateTime.UtcNow
        });
    }
}

// NEW: Add XML without modifying existing code! (open for extension)
public class XmlReportGenerator : IReportGenerator
{
    public string SupportedFormat => "XML";
    
    public string Generate(Data data)
    {
        var xml = new XmlDocument();
        var root = xml.CreateElement("Report");
        
        var title = xml.CreateElement("Title");
        title.InnerText = data.Title;
        root.AppendChild(title);
        
        var body = xml.CreateElement("Body");
        body.InnerText = data.Body;
        root.AppendChild(body);
        
        xml.AppendChild(root);
        return xml.OuterXml;
    }
}

// NEW: Add JSON without modifying existing code! (open for extension)
public class JsonReportGenerator : IReportGenerator
{
    public string SupportedFormat => "JSON";
    
    public string Generate(Data data)
    {
        return JsonSerializer.Serialize(new
        {
            Title = data.Title,
            Body = data.Body,
            GeneratedAt = DateTime.UtcNow,
            Format = "JSON"
        }, new JsonSerializerOptions { WriteIndented = true });
    }
}

// Orchestrator - also follows OCP!
public class ReportService
{
    private readonly IEnumerable<IReportGenerator> _generators;
    
    // Dependency injection brings in ALL registered generators
    public ReportService(IEnumerable<IReportGenerator> generators)
    {
        _generators = generators;
    }
    
    public string GenerateReport(string format, Data data)
    {
        // Find the appropriate generator
        var generator = _generators.FirstOrDefault(g => 
            g.SupportedFormat.Equals(format, StringComparison.OrdinalIgnoreCase));
        
        if (generator == null)
            throw new NotSupportedException($"Report format '{format}' is not supported");
        
        return generator.Generate(data);
    }
    
    public IEnumerable<string> GetSupportedFormats()
    {
        return _generators.Select(g => g.SupportedFormat);
    }
}

// Registration (in Startup.cs or Program.cs)
public void ConfigureServices(IServiceCollection services)
{
    // Register all report generators
    services.AddTransient<IReportGenerator, PdfReportGenerator>();
    services.AddTransient<IReportGenerator, ExcelReportGenerator>();
    services.AddTransient<IReportGenerator, HtmlReportGenerator>();
    services.AddTransient<IReportGenerator, XmlReportGenerator>();
    services.AddTransient<IReportGenerator, JsonReportGenerator>();
    
    // ReportService automatically gets all registered generators
    services.AddScoped<ReportService>();
}
```

**Benefits of OCP implementation:**
- ✅ **No modification needed** - existing report generators never change
- ✅ **Easy to extend** - just implement `IReportGenerator` and register it
- ✅ **No risk to existing code** - PDF generator can't break when adding JSON
- ✅ **Independent testing** - each generator tested separately
- ✅ **No merge conflicts** - developers work on separate files
- ✅ **Runtime extensibility** - can add generators via configuration
- ✅ **Clear separation** - each generator has single responsibility

### OCP with Strategy Pattern (Payment Processing)

The Strategy pattern is one of the most common ways to achieve OCP. Let's see a comprehensive payment processing example:

```csharp
// Extension point for payment processing
public interface IPaymentProcessor
{
    Task<PaymentResult> ProcessPayment(PaymentRequest request);
    bool CanProcess(PaymentMethod method);
    string ProcessorName { get; }
}

// Payment request model
public class PaymentRequest
{
    public decimal Amount { get; set; }
    public PaymentMethod Method { get; set; }
    public string Currency { get; set; }
    public Dictionary<string, string> Metadata { get; set; }
}

// Payment result
public class PaymentResult
{
    public bool Success { get; set; }
    public string TransactionId { get; set; }
    public string ErrorMessage { get; set; }
    public DateTime ProcessedAt { get; set; }
}

// Enum for payment methods
public enum PaymentMethod
{
    CreditCard,
    PayPal,
    Stripe,
    ApplePay,
    Cryptocurrency
}

// Implementation 1: Credit Card Processor
public class CreditCardProcessor : IPaymentProcessor
{
    private readonly ICreditCardGateway _gateway;
    private readonly ILogger<CreditCardProcessor> _logger;
    
    public string ProcessorName => "Credit Card";
    
    public CreditCardProcessor(
        ICreditCardGateway gateway,
        ILogger<CreditCardProcessor> logger)
    {
        _gateway = gateway;
        _logger = logger;
    }
    
    public async Task<PaymentResult> ProcessPayment(PaymentRequest request)
    {
        try
        {
            _logger.LogInformation("Processing credit card payment of {Amount}", request.Amount);
            
            // Extract credit card details from metadata
            var cardNumber = request.Metadata["CardNumber"];
            var cvv = request.Metadata["CVV"];
            var expiryDate = request.Metadata["ExpiryDate"];
            
            // Process through gateway
            var gatewayResult = await _gateway.ChargeCard(
                cardNumber, cvv, expiryDate, request.Amount);
            
            return new PaymentResult
            {
                Success = gatewayResult.Approved,
                TransactionId = gatewayResult.AuthCode,
                ProcessedAt = DateTime.UtcNow
            };
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Credit card processing failed");
            return new PaymentResult
            {
                Success = false,
                ErrorMessage = "Credit card payment failed"
            };
        }
    }
    
    public bool CanProcess(PaymentMethod method) 
        => method == PaymentMethod.CreditCard;
}

// Implementation 2: PayPal Processor
public class PayPalProcessor : IPaymentProcessor
{
    private readonly IPayPalClient _paypalClient;
    private readonly ILogger<PayPalProcessor> _logger;
    
    public string ProcessorName => "PayPal";
    
    public PayPalProcessor(
        IPayPalClient paypalClient,
        ILogger<PayPalProcessor> logger)
    {
        _paypalClient = paypalClient;
        _logger = logger;
    }
    
    public async Task<PaymentResult> ProcessPayment(PaymentRequest request)
    {
        try
        {
            _logger.LogInformation("Processing PayPal payment of {Amount}", request.Amount);
            
            var paypalEmail = request.Metadata["PayPalEmail"];
            
            // Create PayPal payment
            var payment = await _paypalClient.CreatePayment(
                paypalEmail,
                request.Amount,
                request.Currency);
            
            // Execute payment
            var result = await _paypalClient.ExecutePayment(payment.Id);
            
            return new PaymentResult
            {
                Success = result.State == "approved",
                TransactionId = result.Id,
                ProcessedAt = DateTime.UtcNow
            };
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "PayPal processing failed");
            return new PaymentResult
            {
                Success = false,
                ErrorMessage = "PayPal payment failed"
            };
        }
    }
    
    public bool CanProcess(PaymentMethod method) 
        => method == PaymentMethod.PayPal;
}

// Implementation 3: Stripe Processor
public class StripeProcessor : IPaymentProcessor
{
    private readonly IStripeService _stripeService;
    private readonly ILogger<StripeProcessor> _logger;
    
    public string ProcessorName => "Stripe";
    
    public StripeProcessor(
        IStripeService stripeService,
        ILogger<StripeProcessor> logger)
    {
        _stripeService = stripeService;
        _logger = logger;
    }
    
    public async Task<PaymentResult> ProcessPayment(PaymentRequest request)
    {
        try
        {
            _logger.LogInformation("Processing Stripe payment of {Amount}", request.Amount);
            
            var paymentIntentId = request.Metadata["PaymentIntentId"];
            
            var intent = await _stripeService.ConfirmPaymentIntent(paymentIntentId);
            
            return new PaymentResult
            {
                Success = intent.Status == "succeeded",
                TransactionId = intent.Id,
                ProcessedAt = DateTime.UtcNow
            };
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Stripe processing failed");
            return new PaymentResult
            {
                Success = false,
                ErrorMessage = "Stripe payment failed"
            };
        }
    }
    
    public bool CanProcess(PaymentMethod method) 
        => method == PaymentMethod.Stripe;
}

// NEW: Cryptocurrency Processor (added without modifying existing code!)
public class CryptoProcessor : IPaymentProcessor
{
    private readonly ICryptoWallet _wallet;
    private readonly ILogger<CryptoProcessor> _logger;
    
    public string ProcessorName => "Cryptocurrency";
    
    public CryptoProcessor(
        ICryptoWallet wallet,
        ILogger<CryptoProcessor> logger)
    {
        _wallet = wallet;
        _logger = logger;
    }
    
    public async Task<PaymentResult> ProcessPayment(PaymentRequest request)
    {
        try
        {
            _logger.LogInformation("Processing crypto payment of {Amount}", request.Amount);
            
            var walletAddress = request.Metadata["WalletAddress"];
            var cryptoCurrency = request.Metadata["CryptoCurrency"]; // BTC, ETH, etc.
            
            // Convert fiat to crypto
            var cryptoAmount = await _wallet.ConvertAmount(
                request.Amount, 
                request.Currency, 
                cryptoCurrency);
            
            // Send cryptocurrency
            var txHash = await _wallet.SendPayment(
                walletAddress,
                cryptoAmount,
                cryptoCurrency);
            
            return new PaymentResult
            {
                Success = !string.IsNullOrEmpty(txHash),
                TransactionId = txHash,
                ProcessedAt = DateTime.UtcNow
            };
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Crypto processing failed");
            return new PaymentResult
            {
                Success = false,
                ErrorMessage = "Cryptocurrency payment failed"
            };
        }
    }
    
    public bool CanProcess(PaymentMethod method) 
        => method == PaymentMethod.Cryptocurrency;
}

// Service that uses the strategy
public class PaymentService
{
    private readonly IEnumerable<IPaymentProcessor> _processors;
    private readonly ILogger<PaymentService> _logger;
    
    public PaymentService(
        IEnumerable<IPaymentProcessor> processors,
        ILogger<PaymentService> logger)
    {
        _processors = processors;
        _logger = logger;
    }
    
    public async Task<PaymentResult> ProcessPayment(PaymentRequest request)
    {
        _logger.LogInformation(
            "Processing {Method} payment for {Amount}",
            request.Method,
            request.Amount);
        
        // Find the appropriate processor
        var processor = _processors.FirstOrDefault(p => p.CanProcess(request.Method));
        
        if (processor == null)
        {
            _logger.LogWarning("No processor found for {Method}", request.Method);
            throw new InvalidOperationException(
                $"No processor found for payment method: {request.Method}");
        }
        
        _logger.LogInformation("Using processor: {ProcessorName}", processor.ProcessorName);
        
        // Delegate to the specific processor
        return await processor.ProcessPayment(request);
    }
    
    public IEnumerable<string> GetAvailableProcessors()
    {
        return _processors.Select(p => p.ProcessorName);
    }
}

// Usage in a controller
[ApiController]
[Route("api/[controller]")]
public class PaymentController : ControllerBase
{
    private readonly PaymentService _paymentService;
    
    public PaymentController(PaymentService paymentService)
    {
        _paymentService = paymentService;
    }
    
    [HttpPost]
    public async Task<IActionResult> ProcessPayment([FromBody] PaymentRequest request)
    {
        try
        {
            var result = await _paymentService.ProcessPayment(request);
            
            if (result.Success)
                return Ok(result);
            else
                return BadRequest(result);
        }
        catch (Exception ex)
        {
            return StatusCode(500, new { error = ex.Message });
        }
    }
    
    [HttpGet("processors")]
    public IActionResult GetProcessors()
    {
        var processors = _paymentService.GetAvailableProcessors();
        return Ok(processors);
    }
}
```

**Key advantages of this design:**
- ✅ Adding Apple Pay, Google Pay, or any new method doesn't touch existing processors
- ✅ Each processor can be developed, tested, and deployed independently
- ✅ Can enable/disable processors via configuration
- ✅ Easy to add processor-specific logic without affecting others
- ✅ Clear ownership - different teams can own different processors

### Plugin Architecture

Plugin architectures are the ultimate expression of OCP at the system level. They allow completely new functionality to be added without any changes to the core system.

**Complete Plugin System Example:**

```csharp
// 1. Define extension point
public interface IOrderValidator
{
    Task<ValidationResult> Validate(Order order);
    int Priority { get; }  // Lower numbers run first
    string ValidatorName { get; }
}

public class ValidationResult
{
    public bool IsValid { get; set; }
    public List<string> Errors { get; set; } = new();
    public string ValidatorName { get; set; }
    
    public static ValidationResult Success(string validatorName) => 
        new() { IsValid = true, ValidatorName = validatorName };
    
    public static ValidationResult Failure(string validatorName, params string[] errors) => 
        new() { IsValid = false, Errors = errors.ToList(), ValidatorName = validatorName };
}

// 2. Core validation (always present)
public class CoreOrderValidator : IOrderValidator
{
    public int Priority => 0;  // Runs first
    public string ValidatorName => "Core Validation";
    
    public async Task<ValidationResult> Validate(Order order)
    {
        var errors = new List<string>();
        
        if (order == null)
            errors.Add("Order cannot be null");
        
        if (order.Items == null || !order.Items.Any())
            errors.Add("Order must contain at least one item");
        
        if (order.Total <= 0)
            errors.Add("Order total must be greater than zero");
        
        if (string.IsNullOrEmpty(order.CustomerEmail))
            errors.Add("Customer email is required");
        
        return errors.Any()
            ? ValidationResult.Failure(ValidatorName, errors.ToArray())
            : ValidationResult.Success(ValidatorName);
    }
}

// 3. Plugin: Business rules (can be added without modifying core)
public class BusinessRulesValidator : IOrderValidator
{
    private readonly IBusinessRulesEngine _rulesEngine;
    
    public int Priority => 10;
    public string ValidatorName => "Business Rules";
    
    public BusinessRulesValidator(IBusinessRulesEngine rulesEngine)
    {
        _rulesEngine = rulesEngine;
    }
    
    public async Task<ValidationResult> Validate(Order order)
    {
        var errors = new List<string>();
        
        // Check minimum order value
        if (order.Total < 10)
            errors.Add("Minimum order value is $10");
        
        // Check maximum items
        if (order.Items.Count > 100)
            errors.Add("Maximum 100 items per order");
        
        // Custom business rules from configuration
        var customRules = await _rulesEngine.GetRulesFor(order.CustomerSegment);
        foreach (var rule in customRules)
        {
            if (!rule.Validate(order))
                errors.Add(rule.ErrorMessage);
        }
        
        return errors.Any()
            ? ValidationResult.Failure(ValidatorName, errors.ToArray())
            : ValidationResult.Success(ValidatorName);
    }
}

// 4. Plugin: Fraud detection (separate module)
public class FraudDetectionValidator : IOrderValidator
{
    private readonly IFraudDetectionService _fraudService;
    private readonly ILogger<FraudDetectionValidator> _logger;
    
    public int Priority => 20;  // Runs after business rules
    public string ValidatorName => "Fraud Detection";
    
    public FraudDetectionValidator(
        IFraudDetectionService fraudService,
        ILogger<FraudDetectionValidator> logger)
    {
        _fraudService = fraudService;
        _logger = logger;
    }
    
    public async Task<ValidationResult> Validate(Order order)
    {
        try
        {
            _logger.LogInformation("Running fraud detection for order {OrderId}", order.Id);
            
            var riskScore = await _fraudService.CalculateRiskScore(order);
            
            if (riskScore > 0.8m)
            {
                _logger.LogWarning(
                    "High risk order detected: {OrderId}, Risk: {RiskScore}",
                    order.Id,
                    riskScore);
                
                return ValidationResult.Failure(
                    ValidatorName,
                    $"Order flagged for manual review (Risk: {riskScore:P0})");
            }
            
            return ValidationResult.Success(ValidatorName);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Fraud detection failed for order {OrderId}", order.Id);
            // Don't block order if fraud detection fails
            return ValidationResult.Success(ValidatorName);
        }
    }
}

// 5. Plugin: Inventory check (separate module)
public class InventoryValidator : IOrderValidator
{
    private readonly IInventoryService _inventoryService;
    
    public int Priority => 15;
    public string ValidatorName => "Inventory Check";
    
    public InventoryValidator(IInventoryService inventoryService)
    {
        _inventoryService = inventoryService;
    }
    
    public async Task<ValidationResult> Validate(Order order)
    {
        var errors = new List<string>();
        
        foreach (var item in order.Items)
        {
            var available = await _inventoryService.GetAvailableStock(item.ProductId);
            
            if (available < item.Quantity)
            {
                errors.Add(
                    $"Insufficient stock for {item.ProductName}. " +
                    $"Requested: {item.Quantity}, Available: {available}");
            }
        }
        
        return errors.Any()
            ? ValidationResult.Failure(ValidatorName, errors.ToArray())
            : ValidationResult.Success(ValidatorName);
    }
}

// 6. Service that orchestrates validators
public class OrderValidationService
{
    private readonly IEnumerable<IOrderValidator> _validators;
    private readonly ILogger<OrderValidationService> _logger;
    
    public OrderValidationService(
        IEnumerable<IOrderValidator> validators,
        ILogger<OrderValidationService> logger)
    {
        // Automatically order by priority
        _validators = validators.OrderBy(v => v.Priority);
        _logger = logger;
    }
    
    public async Task<OrderValidationReport> ValidateOrder(Order order)
    {
        var report = new OrderValidationReport();
        var allResults = new List<ValidationResult>();
        
        _logger.LogInformation(
            "Validating order {OrderId} with {Count} validators",
            order.Id,
            _validators.Count());
        
        foreach (var validator in _validators)
        {
            _logger.LogDebug("Running validator: {ValidatorName}", validator.ValidatorName);
            
            var result = await validator.Validate(order);
            allResults.Add(result);
            
            if (!result.IsValid)
            {
                _logger.LogWarning(
                    "Validation failed: {ValidatorName}, Errors: {Errors}",
                    result.ValidatorName,
                    string.Join(", ", result.Errors));
                
                report.IsValid = false;
                report.Errors.AddRange(result.Errors);
                
                // Stop on first failure (optional - can continue if needed)
                break;
            }
        }
        
        if (report.IsValid)
        {
            _logger.LogInformation("Order {OrderId} validation succeeded", order.Id);
        }
        
        report.ValidationResults = allResults;
        return report;
    }
    
    public IEnumerable<string> GetRegisteredValidators()
    {
        return _validators.Select(v => v.ValidatorName);
    }
}

public class OrderValidationReport
{
    public bool IsValid { get; set; } = true;
    public List<string> Errors { get; set; } = new();
    public List<ValidationResult> ValidationResults { get; set; } = new();
}

// 7. Registration (in Startup.cs)
public void ConfigureServices(IServiceCollection services)
{
    // Register core validator (always present)
    services.AddScoped<IOrderValidator, CoreOrderValidator>();
    
    // Register plugin validators (can be conditional)
    services.AddScoped<IOrderValidator, BusinessRulesValidator>();
    services.AddScoped<IOrderValidator, InventoryValidator>();
    
    // Register fraud detection only if configured
    if (Configuration.GetValue<bool>("Features:FraudDetection:Enabled"))
    {
        services.AddScoped<IOrderValidator, FraudDetectionValidator>();
    }
    
    // Orchestration service automatically gets all registered validators
    services.AddScoped<OrderValidationService>();
}
```

**Benefits of plugin architecture:**
- ✅ Core system never changes when adding new validators
- ✅ Validators can be enabled/disabled via configuration
- ✅ Different teams can own different validators
- ✅ Easy to test each validator in isolation
- ✅ Can load validators from separate assemblies (true plugins)
- ✅ Priority system allows controlling execution order

### Middleware Pipeline (ASP.NET Core)

ASP.NET Core's middleware pipeline is a perfect example of OCP in action. You can add new middleware without modifying existing middleware or the core framework.

```csharp
// Custom middleware example - adds new behavior without modifying existing code
public class RequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestLoggingMiddleware> _logger;
    
    public RequestLoggingMiddleware(
        RequestDelegate _next,
        ILogger<RequestLoggingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }
    
    public async Task InvokeAsync(HttpContext context)
    {
        // Pre-processing
        var stopwatch = Stopwatch.StartNew();
        var requestPath = context.Request.Path;
        
        _logger.LogInformation(
            "Request started: {Method} {Path}",
            context.Request.Method,
            requestPath);
        
        try
        {
            // Call next middleware
            await _next(context);
        }
        finally
        {
            // Post-processing
            stopwatch.Stop();
            _logger.LogInformation(
                "Request completed: {Method} {Path} - {StatusCode} in {ElapsedMs}ms",
                context.Request.Method,
                requestPath,
                context.Response.StatusCode,
                stopwatch.ElapsedMilliseconds);
        }
    }
}

// Another middleware - performance monitoring
public class PerformanceMonitoringMiddleware
{
    private readonly RequestDelegate _next;
    private readonly IMetricsCollector _metrics;
    
    public PerformanceMonitoringMiddleware(
        RequestDelegate next,
        IMetricsCollector metrics)
    {
        _next = next;
        _metrics = metrics;
    }
    
    public async Task InvokeAsync(HttpContext context)
    {
        var stopwatch = Stopwatch.StartNew();
        
        await _next(context);
        
        stopwatch.Stop();
        
        _metrics.RecordRequestDuration(
            context.Request.Path,
            stopwatch.ElapsedMilliseconds);
    }
}

// Registration - pipeline is extended without modifying existing middleware
public void Configure(IApplicationBuilder app)
{
    // Each middleware is added without modifying others
    app.UseMiddleware<RequestLoggingMiddleware>();
    app.UseMiddleware<PerformanceMonitoringMiddleware>();
    app.UseRouting();
    app.UseAuthentication();
    app.UseAuthorization();
    app.UseEndpoints(endpoints => { /* ... */ });
}
```

## When NOT to Apply OCP

Not every part of your system needs to be extensible. Premature abstraction can lead to unnecessary complexity.

### Scenarios Where OCP Might Be Wrong

| Scenario | Why OCP Might Be Wrong | Better Approach |
|----------|------------------------|-----------------|
| **Stable, simple code** | Over-engineering with abstractions | Keep it simple - add abstraction when needed |
| **Performance-critical paths** | Abstraction overhead (virtual calls, indirection) | Direct implementation for hot paths |
| **Internal implementation details** | Unnecessary complexity | Encapsulate, don't abstract |
| **Rapidly changing requirements** | Premature abstraction | Wait for patterns to emerge (Rule of Three) |
| **Single implementation unlikely to change** | No value in extensibility | Concrete implementation |
| **Prototype/MVP** | Need speed over flexibility | Build it, learn, then refactor |

### Example: When NOT to use OCP

```csharp
// DON'T: Over-engineered for simple case
public interface ITaxCalculator { }
public class StateTaxCalculator : ITaxCalculator { }
public class CountyTaxCalculator : ITaxCalculator { }
public class CityTaxCalculator : ITaxCalculator { }
public interface ITaxCalculatorFactory { }
public class TaxCalculatorFactory : ITaxCalculatorFactory { }

// DO: Simple is fine when you're only calculating one type of tax
public class TaxCalculator
{
    public decimal CalculateTax(Order order)
    {
        // Simple, direct calculation
        return order.Subtotal * 0.08m;
    }
}

// Later, if you need multiple tax types, THEN refactor to OCP pattern
```

## Key Takeaways

🎯 **OCP = Extensibility without modification**
- Add new behavior by adding new code, not changing existing code
- Existing, tested code remains stable
- Reduces regression risk

🎯 **Abstractions are the key**
- Interfaces define extension points
- Implementations provide specific behavior
- Orchestrators coordinate implementations

🎯 **Common implementation patterns**
- Strategy Pattern: Interchangeable algorithms
- Plugin Architecture: Loadable extensions
- Middleware Pipeline: Chained processing
- Template Method: Hook points for customization

🎯 **Benefits of OCP**
- Stable core system
- Easy to add features
- Reduced testing burden
- Independent development of extensions
- Runtime configurability

🎯 **When NOT to use OCP**
- Simple, stable code
- Performance-critical paths
- Rapidly changing requirements (wait for patterns)
- Single implementation unlikely to change

🎯 **Warning signs of OCP violations**
- Growing switch/if-else statements
- Modifying same method repeatedly
- Can't add features without changing core code
- High regression risk when adding features
