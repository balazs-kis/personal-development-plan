## Key Concepts Summary

### What is CQRS?

CQRS stands for Command Query Responsibility Segregation. It's a pattern that separates read and write operations into different models.

**Commands** = Write operations (change state, no return value or simple acknowledgment)
**Queries** = Read operations (return data, never modify state)

### Why CQRS?

| Without CQRS | With CQRS |
|--------------|-----------|
| Single model for reads and writes | Separate optimized models |
| Complex queries on write model | Simple, fast read models |
| Difficult to scale reads independently | Scale reads and writes separately |
| Write validations complicate reads | Clean separation of concerns |

**Common Scenarios for CQRS:**
- **High read-to-write ratio:** Most applications read data far more often than they write (e.g., e-commerce product catalogs, news sites)
- **Complex domains:** Business logic for commands differs significantly from query requirements
- **Performance requirements:** Need to optimize reads and writes independently
- **Multiple read representations:** Same data needs different views (mobile vs. desktop, detailed vs. summary)
- **Scalability needs:** Read and write loads scale differently

**When NOT to use CQRS:**
- Simple CRUD applications
- Small applications with low complexity
- Teams unfamiliar with the pattern (without training time)
- When eventual consistency is unacceptable

### Commands in Detail
```csharp
// Command - changes state
public record CreateOrderCommand(
    Guid CustomerId,
    List<OrderLineDto> Lines) : IRequest<Guid>;

// Command Handler - processes the command
public class CreateOrderCommandHandler : IRequestHandler<CreateOrderCommand, Guid>
{
    private readonly IOrderRepository _orderRepository;
    private readonly IProductRepository _productRepository;
    
    public CreateOrderCommandHandler(
        IOrderRepository orderRepository,
        IProductRepository productRepository)
    {
        _orderRepository = orderRepository;
        _productRepository = productRepository;
    }
    
    public async Task<Guid> Handle(CreateOrderCommand request, CancellationToken cancellationToken)
    {
        // Create domain entity
        var order = Order.Create(request.CustomerId);
        
        // Apply business rules
        foreach (var line in request.Lines)
        {
            var product = await _productRepository.GetById(line.ProductId);
            order.AddLine(product, line.Quantity);
        }
        
        // Persist
        await _orderRepository.Add(order);
        await _orderRepository.SaveChanges();
        
        return order.Id;
    }
}

// Validation for commands
public class CreateOrderCommandValidator : AbstractValidator<CreateOrderCommand>
{
    public CreateOrderCommandValidator()
    {
        RuleFor(x => x.CustomerId)
            .NotEmpty()
            .WithMessage("Customer ID is required");
        
        RuleFor(x => x.Lines)
            .NotEmpty()
            .WithMessage("Order must have at least one line");
        
        RuleForEach(x => x.Lines).ChildRules(line =>
        {
            line.RuleFor(x => x.Quantity)
                .GreaterThan(0)
                .WithMessage("Quantity must be positive");
        });
    }
}
```

### Queries in Detail
```csharp
// Query - returns data
public record GetOrderQuery(Guid OrderId) : IRequest<OrderDto>;

// Query Handler - retrieves data
public class GetOrderQueryHandler : IRequestHandler<GetOrderQuery, OrderDto>
{
    private readonly IApplicationDbContext _context;
    
    public GetOrderQueryHandler(IApplicationDbContext context)
    {
        _context = context;
    }
    
    public async Task<OrderDto> Handle(GetOrderQuery request, CancellationToken cancellationToken)
    {
        // Query optimized for reading
        var order = await _context.Orders
            .AsNoTracking()  // Read-only, faster
            .Include(o => o.Lines)
            .ThenInclude(l => l.Product)
            .Where(o => o.Id == request.OrderId)
            .Select(o => new OrderDto
            {
                Id = o.Id,
                CustomerName = o.Customer.Name,
                OrderDate = o.CreatedAt,
                TotalAmount = o.TotalAmount,
                Lines = o.Lines.Select(l => new OrderLineDto
                {
                    ProductName = l.Product.Name,
                    Quantity = l.Quantity,
                    UnitPrice = l.UnitPrice,
                    LineTotal = l.LineTotal
                }).ToList()
            })
            .FirstOrDefaultAsync(cancellationToken);
        
        if (order == null)
            throw new NotFoundException(nameof(Order), request.OrderId);
        
        return order;
    }
}
```

### MediatR Pipeline
```csharp
// Request flows through pipeline behaviors
[Request] 
   ↓
[Logging Behavior] 
   ↓
[Validation Behavior] 
   ↓
[Authorization Behavior]
   ↓
[Handler]
   ↓
[Response]

// Logging Behavior example
public class LoggingBehavior<TRequest, TResponse> 
    : IPipelineBehavior<TRequest, TResponse>
    where TRequest : IRequest<TResponse>
{
    private readonly ILogger<LoggingBehavior<TRequest, TResponse>> _logger;
    
    public LoggingBehavior(ILogger<LoggingBehavior<TRequest, TResponse>> logger)
    {
        _logger = logger;
    }
    
    public async Task<TResponse> Handle(
        TRequest request,
        RequestHandlerDelegate<TResponse> next,
        CancellationToken cancellationToken)
    {
        var requestName = typeof(TRequest).Name;
        
        _logger.LogInformation("Handling {RequestName}", requestName);
        
        var response = await next();
        
        _logger.LogInformation("Handled {RequestName}", requestName);
        
        return response;
    }
}
```

### Separate Read and Write Models
```csharp
// Write Model (Domain Entity)
public class Order
{
    public Guid Id { get; private set; }
    public Guid CustomerId { get; private set; }
    private readonly List<OrderLine> _lines = new();
    public OrderStatus Status { get; private set; }
    
    // Rich behavior
    public void AddLine(Product product, int quantity)
    {
        // Business rules
        if (quantity <= 0)
            throw new InvalidQuantityException();
        if (Status != OrderStatus.Draft)
            throw new InvalidOperationException("Cannot modify non-draft order");
        
        var line = new OrderLine(product.Id, product.Price, quantity);
        _lines.Add(line);
    }
    
    public void Submit()
    {
        if (!_lines.Any())
            throw new InvalidOperationException("Cannot submit empty order");
        Status = OrderStatus.Submitted;
    }
    
    public decimal GetTotal() => _lines.Sum(l => l.Quantity * l.UnitPrice);
}

// Read Model (DTO - optimized for queries)
public class OrderListDto
{
    public Guid Id { get; set; }
    public string CustomerName { get; set; }
    public DateTime OrderDate { get; set; }
    public decimal TotalAmount { get; set; }
    public int ItemCount { get; set; }
    public string Status { get; set; }
}

// Detailed Read Model
public class OrderDetailDto
{
    public Guid Id { get; set; }

    public List<OrderLineDto> Lines { get; set; }

public class OrderReadModel  // Denormalized for fast queries
```

### Advanced Query Patterns

**Pagination:**
```csharp
public record GetOrdersQuery(
    int PageNumber = 1,
    int PageSize = 20,
    string? SearchTerm = null,
    OrderStatus? Status = null) : IRequest<PagedResult<OrderListDto>>;

public class GetOrdersQueryHandler : IRequestHandler<GetOrdersQuery, PagedResult<OrderListDto>>
{
    private readonly IApplicationDbContext _context;
    
    public async Task<PagedResult<OrderListDto>> Handle(
        GetOrdersQuery request,
        CancellationToken cancellationToken)
    {
        var query = _context.Orders.AsNoTracking();
        
        // Apply filters
        if (!string.IsNullOrEmpty(request.SearchTerm))
        {
            query = query.Where(o => 
                o.Customer.Name.Contains(request.SearchTerm) ||
                o.Id.ToString().Contains(request.SearchTerm));
        }
        
        if (request.Status.HasValue)
        {
            query = query.Where(o => o.Status == request.Status.Value);
        }
        
        var totalCount = await query.CountAsync(cancellationToken);
        
        var items = await query
            .OrderByDescending(o => o.CreatedAt)
            .Skip((request.PageNumber - 1) * request.PageSize)
            .Take(request.PageSize)
            .Select(o => new OrderListDto
            {
                Id = o.Id,
                CustomerName = o.Customer.Name,
                OrderDate = o.CreatedAt,
                TotalAmount = o.TotalAmount,
                ItemCount = o.Lines.Count,
                Status = o.Status.ToString()
            })
            .ToListAsync(cancellationToken);
        
        return new PagedResult<OrderListDto>
        {
            Items = items,
            TotalCount = totalCount,
            PageNumber = request.PageNumber,
            PageSize = request.PageSize
        };
    }
}

public class PagedResult<T>
{
    public List<T> Items { get; set; }
    public int TotalCount { get; set; }
    public int PageNumber { get; set; }
    public int PageSize { get; set; }
    public int TotalPages => (int)Math.Ceiling(TotalCount / (double)PageSize);
    public bool HasPreviousPage => PageNumber > 1;
    public bool HasNextPage => PageNumber < TotalPages;
}
```

**Sorting and Filtering:**
```csharp
public record GetProductsQuery(
    string? Category = null,
    decimal? MinPrice = null,
    decimal? MaxPrice = null,
    string? SortBy = "name",
    bool SortDescending = false) : IRequest<List<ProductDto>>;

public class GetProductsQueryHandler : IRequestHandler<GetProductsQuery, List<ProductDto>>
{
    private readonly IApplicationDbContext _context;
    
    public async Task<List<ProductDto>> Handle(
        GetProductsQuery request,
        CancellationToken cancellationToken)
    {
        var query = _context.Products.AsNoTracking();
        
        // Apply filters
        if (!string.IsNullOrEmpty(request.Category))
            query = query.Where(p => p.Category == request.Category);
        
        if (request.MinPrice.HasValue)
            query = query.Where(p => p.Price >= request.MinPrice.Value);
        
        if (request.MaxPrice.HasValue)
            query = query.Where(p => p.Price <= request.MaxPrice.Value);
        
        // Apply sorting
        query = request.SortBy?.ToLower() switch
        {
            "price" => request.SortDescending 
                ? query.OrderByDescending(p => p.Price)
                : query.OrderBy(p => p.Price),
            "name" => request.SortDescending
                ? query.OrderByDescending(p => p.Name)
                : query.OrderBy(p => p.Name),
            _ => query.OrderBy(p => p.Name)
        };
        
        return await query
            .Select(p => new ProductDto
            {
                Id = p.Id,
                Name = p.Name,
                Price = p.Price,
                Category = p.Category
            })
            .ToListAsync(cancellationToken);
    }
}
```

### Benefits and Trade-offs

**Benefits:**
- **Optimized paths:** Read and write operations optimized separately
- **Scalability:** Scale reads and writes independently (e.g., 10 read replicas, 1 write instance)
- **Flexibility:** Different data models for different needs (normalized writes, denormalized reads)
- **Security:** Easier authorization per operation type (separate read/write permissions)
- **Performance:** Queries don't lock write database, no complex joins needed
- **Multiple representations:** Same data, multiple optimized views

**Trade-offs:**
- **Increased complexity:** More code, more moving parts
- **More code to maintain:** Separate handlers, models, and potentially databases
- **Eventual consistency:** Read models may lag behind writes (milliseconds to seconds)
- **Learning curve:** Team needs to understand the pattern
- **Development overhead:** Initial setup takes more time

**Complexity Comparison:**

```
Simple CRUD:
Request → Controller → Entity → Database → Response
(4 components)

CQRS:
Command → Validator → Handler → Domain → Write DB → Event → Projection → Read DB
Query → Handler → Read DB → DTO → Response
(10+ components per feature)
```

### CQRS Maturity Levels

**Level 1: Simple CQRS**
- Separate commands and queries in code
- Same database, same models
- MediatR for organization

**Level 2: Separate Models**
- Different DTOs for reads vs domain entities for writes
- Same database
- Some denormalization in queries

**Level 3: Separate Databases**
- Write database (normalized)
- Read database (denormalized)
- Event-driven synchronization
- True eventual consistency

## Real-World Example: E-Commerce Product Catalog

### Write Side (Commands)
```csharp
// Heavy write validation and business logic
public class UpdateProductPriceHandler : IRequestHandler<UpdateProductPriceCommand>
{
    public async Task Handle(UpdateProductPriceCommand request, CancellationToken ct)
    {
        var product = await _repository.GetById(request.ProductId);
        
        // Business rules
        if (product.HasActiveOrders())
            throw new BusinessException("Cannot change price with active orders");
        
        if (request.NewPrice < product.Cost)
            throw new BusinessException("Price cannot be below cost");
        
        product.UpdatePrice(request.NewPrice);
        await _repository.Save(product);
        
        // Raise event for read side
        await _eventBus.Publish(new ProductPriceChanged(product.Id, request.NewPrice));
    }
}
```

### Read Side (Queries)
```csharp
// Optimized for browsing - no business logic, just fast reads
public class GetProductCatalogHandler : IRequestHandler<GetProductCatalogQuery, List<ProductCatalogDto>>
{

                ReviewCount = p.ReviewCount,
                InStock = p.InStock
```

## Self-Check Questions

1. **What's the key difference between a Command and a Query?**
   - Answer: Commands modify state and return void or simple acknowledgments. Queries return data but never modify state. This is the core of CQS (Command Query Separation).

2. **Why might you use different data models for reads vs writes?**
   - Answer: Write models need business rules and validation (domain entities). Read models need speed and specific shapes (denormalized DTOs). Optimizing each separately improves performance.

3. **How does MediatR help implement CQRS?**
   - Answer: MediatR provides request/response messaging, decouples controllers from handlers, enables pipeline behaviors (validation, logging), and makes testing easier.

4. **When should you NOT use CQRS?**
   - Answer: Simple CRUD apps, small projects, when team lacks experience, when eventual consistency is unacceptable, or when complexity outweighs benefits.

5. **What is eventual consistency?**
   - Answer: The read model may be slightly behind the write model (milliseconds to seconds). Reads might not immediately reflect recent writes.

6. **How do you scale reads independently from writes?**
   - Answer: Use separate databases or read replicas. Write to one database, replicate to multiple read databases. Scale read infrastructure independently.

7. **What's the purpose of pipeline behaviors?**
   - Answer: Cross-cutting concerns (validation, logging, authorization, transactions) applied to all commands/queries without duplicating code in handlers.
