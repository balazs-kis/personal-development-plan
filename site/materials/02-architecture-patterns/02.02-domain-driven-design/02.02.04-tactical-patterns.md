# Lesson 4: Entities, Value Objects, and Domain Events

## Learning Objectives

By the end of this lesson, you will be able to:
- Distinguish between entities and value objects
- Implement value objects using C# records
- Design and raise domain events
- Use domain events for decoupling and eventual consistency

---

## Introduction

Entities have identity and lifecycle, while value objects are defined by their attributes. Domain events represent significant occurrences in the domain and are the key to achieving loose coupling and eventual consistency in distributed systems.

These tactical patterns are the building blocks of domain models. Understanding when to use entities versus value objects is critical—choosing wrong can lead to subtle bugs and conceptual confusion. Similarly, domain events transform your domain model from a passive data structure into an active, event-driven system that can react to changes and coordinate complex workflows.

Value objects are often underutilized in domain models. Many developers default to creating entities for everything, missing the power of immutability and value semantics. C# records make value objects trivial to implement, yet their potential remains largely untapped. This lesson will show you when and how to use value objects effectively.

Domain events are perhaps the most powerful pattern in tactical DDD. They enable loose coupling between aggregates, provide a natural audit log, drive reactive business processes, and make eventual consistency manageable. Once you start thinking in events, you'll find cleaner solutions to problems that previously seemed intractable.

## Key Concepts Summary

### Entities vs Value Objects

**Entity:** Has identity that persists over time
```csharp
public class Customer  // Entity - has identity
{
    public CustomerId Id { get; private set; }  // Identity
    public string Name { get; private set; }
    public Email Email { get; private set; }
    
    // Same ID = same customer, even if properties differ
    public override bool Equals(object obj)
    {
        if (obj is not Customer other) return false;
        return Id.Equals(other.Id);
    }
}
```

**Value Object:** Defined by attributes, no identity
```csharp
public record Email(string Value)  // Value Object - no identity
{
    public Email
    {
        if (string.IsNullOrWhiteSpace(Value))
            throw new ArgumentException("Email cannot be empty");
        if (!Value.Contains("@"))
            throw new ArgumentException("Invalid email format");
    }
}

public record Money(decimal Amount, Currency Currency)  // Value Object
{
    public Money
    {
        if (Amount < 0)
            throw new ArgumentException("Amount cannot be negative");
    }
    
    public static Money operator +(Money left, Money right)
    {
        if (left.Currency != right.Currency)
            throw new InvalidOperationException("Currency mismatch");
        return new Money(left.Amount + right.Amount, left.Currency);
    }
}

public record Address(  // Value Object
    string Street,
    string City,
    string State,
    string PostalCode,
    string Country)
{
    // Two addresses with same values are equal
}
```

### When to Use Value Objects

| Characteristic | Entity | Value Object |
|----------------|--------|--------------|
| Identity | Yes | No |
| Mutable | Usually | No (immutable) |
| Equality | By ID | By value |
| Lifespan | Tracked over time | Replaceable |
| Examples | Customer, Order, Product | Money, Email, Address, DateRange |

### Implementing Value Objects with Records
```csharp
// C# records are perfect for value objects
public record ProductCode(string Value)
{
    public ProductCode
    {
        if (string.IsNullOrWhiteSpace(Value))
            throw new ArgumentException("Product code cannot be empty");
        if (!Regex.IsMatch(Value, @"^[A-Z]{3}\d{4}$"))
            throw new ArgumentException("Invalid product code format");
    }
}

public record Quantity(int Value)
{
    public Quantity
    {
        if (Value <= 0)
            throw new ArgumentException("Quantity must be positive");
    }
    
    public static Quantity operator +(Quantity left, Quantity right)
        => new(left.Value + right.Value);
}

public record DateRange(DateTime Start, DateTime End)
{
    public DateRange
    {
        if (End < Start)
            throw new ArgumentException("End date must be after start date");
    }
    
    public bool Contains(DateTime date) => date >= Start && date <= End;
    
    public int DurationInDays => (End - Start).Days;
}
```

### Domain Events

Domain events represent something significant that happened in the domain. They're the backbone of event-driven architecture and eventual consistency.

**Why Domain Events Matter:**

1. **Decouple aggregates** - Aggregates don't call each other directly
2. **Audit trail** - Natural history of what happened
3. **Eventual consistency** - Coordinate changes across aggregates
4. **Integration** - Notify other bounded contexts
5. **Reactive workflows** - Trigger side effects (send email, update analytics, etc.)

### Designing Domain Events

```csharp
// Base domain event
public abstract record DomainEvent
{
    public DateTime OccurredAt { get; init; } = DateTime.UtcNow;
    public Guid EventId { get; init; } = Guid.NewGuid();
}

// Specific domain events
public record OrderSubmitted(OrderId OrderId, CustomerId CustomerId) : DomainEvent;

public record OrderConfirmed(OrderId OrderId) : DomainEvent;

public record PaymentReceived(
    OrderId OrderId,
    Money Amount,
    string TransactionId) : DomainEvent;

// Aggregate raises events
public class Order
{
    private readonly List<DomainEvent> _domainEvents = new();
    public IReadOnlyCollection<DomainEvent> DomainEvents => _domainEvents.AsReadOnly();
    
    public void Submit()
    {
        if (Status != OrderStatus.Draft)
            throw new InvalidOrderStateException();
        
        Status = OrderStatus.Submitted;
        
        // Raise domain event
        _domainEvents.Add(new OrderSubmitted(Id, CustomerId));
    }
    
    public void ClearEvents() => _domainEvents.Clear();
}

// Repository publishes events
public class OrderRepository : IOrderRepository
{
    private readonly DbContext _context;
    private readonly IDomainEventDispatcher _eventDispatcher;
    
    public async Task SaveChanges()
    {
        // Collect events from aggregates
        var entities = _context.ChangeTracker
            .Entries<Order>()
            .Where(e => e.Entity.DomainEvents.Any())
            .Select(e => e.Entity);
        
        var events = entities.SelectMany(e => e.DomainEvents).ToList();
        
        // Clear events before saving
        foreach (var entity in entities)
            entity.ClearEvents();
        
        // Save changes
        await _context.SaveChangesAsync();
        
        // Dispatch events AFTER successful save
        foreach (var @event in events)
            await _eventDispatcher.Dispatch(@event);
    }
}

// Event handlers
public class OrderSubmittedHandler : IDomainEventHandler<OrderSubmitted>
{
    private readonly IInventoryService _inventory;
    private readonly IEmailService _email;
    
    public async Task Handle(OrderSubmitted @event)
    {
        // Reserve inventory
        await _inventory.ReserveItems(@event.OrderId);
        
        // Send confirmation email
        await _email.SendOrderConfirmation(@event.OrderId);
    }
}
```

### Event-Driven Saga Pattern
```csharp
// Coordinate across aggregates using events
public class OrderFulfillmentSaga
{
    private readonly IOrderRepository _orders;
    private readonly IPaymentService _payment;
    private readonly IShippingService _shipping;
    
    public async Task Handle(OrderSubmitted @event)
    {
        // Step 1: Process payment
        var paymentResult = await _payment.ProcessPayment(@event.OrderId);
        if (!paymentResult.Success)
        {
            // Compensation: Cancel order
            await CancelOrder(@event.OrderId, "Payment failed");
            return;
        }
        
        // Step 2: Arrange shipping
        var shippingResult = await _shipping.CreateShipment(@event.OrderId);
        if (!shippingResult.Success)
        {
            // Compensation: Refund payment
            await _payment.RefundPayment(paymentResult.TransactionId);
            await CancelOrder(@event.OrderId, "Shipping unavailable");
            return;
        }
        
        // All steps successful
        var order = await _orders.GetById(@event.OrderId);
        order.MarkAsFulfilled();
        await _orders.SaveChanges();
    }
}
```

## Advanced Domain Events Patterns

### Pattern 1: Event Versioning

As your system evolves, event schemas change. Handle this gracefully:

```csharp
// V1
public record OrderSubmittedV1(OrderId OrderId, CustomerId CustomerId) : DomainEvent
{
    public int Version => 1;
}

// V2 - Added order amount
public record OrderSubmittedV2(
    OrderId OrderId,
    CustomerId CustomerId,
    Money TotalAmount) : DomainEvent
{
    public int Version => 2;
}

// Upcaster - Convert old events to new format
public class OrderSubmittedUpcaster
{
    public DomainEvent Upcast(DomainEvent @event)
    {
        return @event switch
        {
            OrderSubmittedV1 v1 => new OrderSubmittedV2(
                v1.OrderId,
                v1.CustomerId,
                Money.Zero),  // Default value for missing field
            OrderSubmittedV2 v2 => v2,
            _ => @event
        };
    }
}
```

### Pattern 2: Event Sourcing

Store aggregates as sequence of events rather than current state:

```csharp
public class Order
{
    private List<DomainEvent> _uncommittedEvents = new();
    private List<DomainEvent> _appliedEvents = new();
    
    public IReadOnlyList<DomainEvent> UncommittedEvents => _uncommittedEvents.AsReadOnly();
    
    // Reconstitute from event stream
    public static Order FromEvents(IEnumerable<DomainEvent> events)
    {
        var order = new Order();
        
        foreach (var @event in events)
        {
            order.Apply(@event, isNew: false);
        }
        
        return order;
    }
    
    // Apply event to state (replay logic)
    private void Apply(DomainEvent @event, bool isNew = true)
    {
        switch (@event)
        {
            case OrderCreated e:
                Id = e.OrderId;
                CustomerId = e.CustomerId;
                Status = OrderStatus.Draft;
                break;
                
            case OrderLineAdded e:
                _lines.Add(new OrderLine(e.ProductId, e.Quantity, e.Price));
                RecalculateTotal();
                break;
                
            case OrderSubmitted e:
                Status = OrderStatus.Submitted;
                SubmittedAt = e.OccurredAt;
                break;
                
            case OrderConfirmed e:
                Status = OrderStatus.Confirmed;
                PaymentId = e.PaymentId;
                break;
        }
        
        if (isNew)
            _uncommittedEvents.Add(@event);
        
        _appliedEvents.Add(@event);
    }
    
    // Public methods raise events
    public void AddLine(ProductId productId, Quantity quantity, Money price)
    {
        if (Status != OrderStatus.Draft)
            throw new InvalidOrderStateException();
        
        var @event = new OrderLineAdded(Id, productId, quantity, price);
        Apply(@event);
    }
    
    public void Submit()
    {
        if (_lines.Count == 0)
            throw new EmptyOrderException();
        
        if (Status != OrderStatus.Draft)
            throw new InvalidOrderStateException();
        
        var @event = new OrderSubmitted(Id, CustomerId);
        Apply(@event);
    }
    
    public void ClearUncommittedEvents() => _uncommittedEvents.Clear();
}

// Event Store Repository
public class EventSourcedOrderRepository
{
    private readonly IEventStore _eventStore;
    
    public async Task<Order> GetById(OrderId id)
    {
        // Load all events for this order
        var events = await _eventStore.GetEvents(id.Value);
        
        // Reconstitute order from events
        return Order.FromEvents(events);
    }
    
    public async Task Save(Order order)
    {
        // Save only new events
        await _eventStore.SaveEvents(
            order.Id.Value,
            order.UncommittedEvents);
        
        order.ClearUncommittedEvents();
    }
}
```

### Pattern 3: Domain Event Pub/Sub

Decouple event producers from consumers:

```csharp
// Event bus interface
public interface IEventBus
{
    Task Publish<TEvent>(TEvent @event) where TEvent : DomainEvent;
    void Subscribe<TEvent>(IEventHandler<TEvent> handler) where TEvent : DomainEvent;
}

// In-memory implementation
public class InMemoryEventBus : IEventBus
{
    private readonly Dictionary<Type, List<object>> _handlers = new();
    
    public void Subscribe<TEvent>(IEventHandler<TEvent> handler) where TEvent : DomainEvent
    {
        var eventType = typeof(TEvent);
        
        if (!_handlers.ContainsKey(eventType))
            _handlers[eventType] = new List<object>();
        
        _handlers[eventType].Add(handler);
    }
    
    public async Task Publish<TEvent>(TEvent @event) where TEvent : DomainEvent
    {
        var eventType = @event.GetType();
        
        if (!_handlers.ContainsKey(eventType))
            return;
        
        var handlers = _handlers[eventType].Cast<IEventHandler<TEvent>>();
        
        foreach (var handler in handlers)
        {
            await handler.Handle(@event);
        }
    }
}

// Usage
public class Startup
{
    public void ConfigureServices(IServiceCollection services)
    {
        var eventBus = new InMemoryEventBus();
        
        // Subscribe handlers
        eventBus.Subscribe(new OrderSubmittedHandler(/* dependencies */));
        eventBus.Subscribe(new SendConfirmationEmailHandler(/* dependencies */));
        eventBus.Subscribe(new UpdateAnalyticsHandler(/* dependencies */));
        
        services.AddSingleton<IEventBus>(eventBus);
    }
}
```

### Pattern 4: Outbox Pattern for Reliable Publishing

Ensure events are published even if the message broker is down:

```csharp
// Outbox table
public class OutboxMessage
{
    public Guid Id { get; set; }
    public string EventType { get; set; }
    public string EventData { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? ProcessedAt { get; set; }
}

// Save events to outbox in same transaction as aggregate
public class OrderRepository
{
    private readonly DbContext _dbContext;
    
    public async Task SaveChanges()
    {
        // Collect events
        var aggregates = _dbContext.ChangeTracker
            .Entries<IAggregateRoot>()
            .Select(e => e.Entity)
            .ToList();
        
        var events = aggregates.SelectMany(a => a.DomainEvents).ToList();
        
        // Save events to outbox (same transaction as aggregate)
        foreach (var @event in events)
        {
            var outboxMessage = new OutboxMessage
            {
                Id = Guid.NewGuid(),
                EventType = @event.GetType().Name,
                EventData = JsonSerializer.Serialize(@event),
                CreatedAt = DateTime.UtcNow
            };
            
            await _dbContext.OutboxMessages.AddAsync(outboxMessage);
        }
        
        // Clear domain events
        foreach (var aggregate in aggregates)
        {
            aggregate.ClearEvents();
        }
        
        // Single transaction commits everything
        await _dbContext.SaveChangesAsync();
    }
}

// Background processor publishes from outbox
public class OutboxProcessor : BackgroundService
{
    private readonly IServiceProvider _services;
    private readonly IMessageBroker _broker;
    
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _services.CreateScope();
            var dbContext = scope.ServiceProvider.GetRequiredService<DbContext>();
            
            // Get unprocessed messages
            var messages = await dbContext.OutboxMessages
                .Where(m => m.ProcessedAt == null)
                .OrderBy(m => m.CreatedAt)
                .Take(100)
                .ToListAsync();
            
            foreach (var message in messages)
            {
                try
                {
                    // Deserialize and publish
                    var eventType = Type.GetType(message.EventType);
                    var @event = JsonSerializer.Deserialize(message.EventData, eventType);
                    
                    await _broker.Publish(@event);
                    
                    // Mark as processed
                    message.ProcessedAt = DateTime.UtcNow;
                    await dbContext.SaveChangesAsync();
                }
                catch (Exception ex)
                {
                    // Log error and continue (will retry on next iteration)
                    _logger.LogError(ex, "Failed to process outbox message {MessageId}", message.Id);
                }
            }
            
            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }
}
```

Here's a comprehensive example showing entities, value objects, and domain events working together:

```csharp
// Value Objects
public record Money(decimal Amount, Currency Currency)
{
    public static Money Zero => new(0, Currency.USD);
    public static Money operator +(Money a, Money b) => new(a.Amount + b.Amount, a.Currency);
    public static Money operator -(Money a, Money b) => new(a.Amount - b.Amount, a.Currency);
}

public record Email(string Value)
{
    public Email
    {
        if (!Regex.IsMatch(Value, @"^[^@]+@[^@]+\.[^@]+$"))
            throw new ArgumentException("Invalid email");
    }
}

public record ShippingAddress(string Street, string City, string PostalCode, string Country);

public record PaymentMethodToken(string Value);

// Domain Events
public record OrderPlaced(OrderId OrderId, CustomerId CustomerId, Money TotalAmount) : DomainEvent;
public record PaymentProcessed(OrderId OrderId, PaymentId PaymentId, Money Amount) : DomainEvent;
public record OrderShipped(OrderId OrderId, TrackingNumber TrackingNumber) : DomainEvent;

// Aggregate Root
public class Order
{
    public OrderId Id { get; private set; }
    public CustomerId CustomerId { get; private set; }
    public OrderStatus Status { get; private set; }
    
    private readonly List<OrderLine> _lines = new();
    public IReadOnlyCollection<OrderLine> Lines => _lines.AsReadOnly();
    
    public Money SubTotal { get; private set; }
    public Money TaxAmount { get; private set; }
    public Money ShippingCost { get; private set; }
    public Money TotalAmount { get; private set; }
    
    public ShippingAddress ShippingAddress { get; private set; }
    public PaymentId? PaymentId { get; private set; }
    public TrackingNumber? TrackingNumber { get; private set; }
    
    private readonly List<DomainEvent> _domainEvents = new();
    public IReadOnlyCollection<DomainEvent> DomainEvents => _domainEvents.AsReadOnly();
    
    // Factory method
    public static Order CreateNew(
        CustomerId customerId,
        ShippingAddress shippingAddress)
    {
        var order = new Order
        {
            Id = OrderId.Generate(),
            CustomerId = customerId,
            ShippingAddress = shippingAddress,
            Status = OrderStatus.Draft,
            SubTotal = Money.Zero,
            TaxAmount = Money.Zero,
            ShippingCost = Money.Zero,
            TotalAmount = Money.Zero
        };
        
        return order;
    }
    
    // Business operations
    public void AddLine(ProductId productId, string productName, Money price, int quantity)
    {
        if (Status != OrderStatus.Draft)
            throw new OrderCannotBeModifiedException();
        
        var line = new OrderLine(productId, productName, price, quantity);
        _lines.Add(line);
        
        RecalculateTotals();
    }
    
    public void PlaceOrder()
    {
        if (_lines.Count == 0)
            throw new EmptyOrderException();
        
        if (Status != OrderStatus.Draft)
            throw new InvalidOrderStateException();
        
        Status = OrderStatus.Placed;
        _domainEvents.Add(new OrderPlaced(Id, CustomerId, TotalAmount));
    }
    
    public void ConfirmPayment(PaymentId paymentId)
    {
        if (Status != OrderStatus.Placed)
            throw new InvalidOrderStateException();
        
        PaymentId = paymentId;
        Status = OrderStatus.PaymentConfirmed;
        
        _domainEvents.Add(new PaymentProcessed(Id, paymentId, TotalAmount));
    }
    
    public void Ship(TrackingNumber trackingNumber)
    {
        if (Status != OrderStatus.PaymentConfirmed)
            throw new InvalidOrderStateException();
        
        TrackingNumber = trackingNumber;
        Status = OrderStatus.Shipped;
        
        _domainEvents.Add(new OrderShipped(Id, trackingNumber));
    }
    
    private void RecalculateTotals()
    {
        SubTotal = _lines
            .Select(l => l.LineTotal)
            .Aggregate(Money.Zero, (sum, total) => sum + total);
        
        TaxAmount = SubTotal * 0.10m;
        ShippingCost = CalculateShipping();
        TotalAmount = SubTotal + TaxAmount + ShippingCost;
    }
    
    private Money CalculateShipping()
    {
        if (SubTotal.Amount >= 50)
            return Money.Zero;
        
        return new Money(9.99m, Currency.USD);
    }
    
    public void ClearEvents() => _domainEvents.Clear();
}

// Entity within aggregate
public class OrderLine
{
    internal OrderLine(ProductId productId, string productName, Money price, int quantity)
    {
        ProductId = productId;
        ProductName = productName;
        Price = price;
        Quantity = quantity;
    }
    
    public ProductId ProductId { get; private set; }
    public string ProductName { get; private set; }
    public Money Price { get; private set; }
    public int Quantity { get; private set; }
    
    public Money LineTotal => new(Price.Amount * Quantity, Price.Currency);
}
```

## Self-Check Questions

1. **What's the key difference between an entity and a value object?**
   - Entity: Has identity that persists over time; equality is by ID
   - Value Object: No identity; defined by attributes; equality is structural
   - Entity: Usually mutable (through controlled methods)
   - Value Object: Always immutable
   - Examples: Customer is entity, Email is value object

2. **Why are value objects immutable?**
   - Thread-safety: Can be safely shared without synchronization
   - No defensive copying needed
   - Can be safely used as dictionary keys
   - Simplifies reasoning about code (no hidden state changes)
   - Reflects real-world nature (the number 5 doesn't change)

3. **When should you raise a domain event?**
   - When something significant happens in the domain
   - When other parts of the system need to react
   - For audit trail purposes
   - To coordinate changes across aggregates
   - Use past tense names: `OrderPlaced`, not `PlaceOrder`

4. **How do domain events help with eventual consistency?**
   - Allow one aggregate to notify others without direct coupling
   - Changes propagate asynchronously via events
   - Each aggregate maintains its own consistency in separate transactions
   - Avoids distributed transactions and long-running locks
   - Saga pattern coordinates multi-aggregate workflows

5. **When should you use an entity vs. a value object?**
   - Use Entity when: Identity matters, lifecycle is tracked, needs to be mutable
   - Use Value Object when: Only the values matter, immutability is desired, no lifecycle
   - Rule of thumb: If you care about "which one" → Entity; If you only care about "what value" → Value Object

6. **What's the purpose of making value object properties validate themselves?**
   - Impossible to create invalid value objects
   - Validation happens once at construction
   - Type system enforces correctness
   - No need for defensive checks everywhere
   - Self-documenting code

## Common Mistakes and Anti-Patterns

### Mistake 1: Mutable Value Objects

```csharp
// ❌ BAD - Mutable value object
public class Email
{
    public string Value { get; set; }  // Mutable!
}

// Problems:
var email = new Email { Value = "test@example.com" };
var dict = new Dictionary<Email, Customer>();
dict[email] = customer;
email.Value = "changed@example.com";  // Now dictionary is broken!

// ✓ GOOD - Immutable
public record Email(string Value);
```

### Mistake 2: Using Primitives Instead of Value Objects

```csharp
// ❌ BAD - Primitive obsession
public class Customer
{
    public string Email { get; set; }  // Any string!
    public decimal CreditLimit { get; set; }  // Any decimal!
}

customer.Email = "not-an-email";  // Compiles!
customer.CreditLimit = -1000;  // Compiles!

// ✓ GOOD - Type-safe value objects
public class Customer
{
    public Email Email { get; private set; }  // Validated
    public Money CreditLimit { get; private set; }  // Validated
}
```

### Mistake 3: Events That Are Too Generic

```csharp
// ❌ BAD - Generic event
public record EntityUpdated(Guid EntityId, string EntityType) : DomainEvent;

// ✓ GOOD - Specific events
public record CustomerEmailChanged(CustomerId CustomerId, Email OldEmail, Email NewEmail) : DomainEvent;
public record OrderShipped(OrderId OrderId, TrackingNumber Tracking, DateTime ShippedAt) : DomainEvent;
```

### Mistake 4: Not Clearing Events After Publishing

```csharp
// ❌ BAD - Events accumulate
public class Order
{
    private readonly List<DomainEvent> _domainEvents = new();
    // No ClearEvents method!
}

// Result: Events get published multiple times

// ✓ GOOD - Clear after publishing
public class Order
{
    public void ClearEvents() => _domainEvents.Clear();
}

// In repository
await _dbContext.SaveChangesAsync();
PublishEvents();
aggregate.ClearEvents();  // Clear after publishing
```

### Mistake 5: Value Objects with Identity

```csharp
// ❌ BAD - Value object shouldn't have ID
public record Address
{
    public Guid Id { get; init; }  // Why does an address have an ID?
    public string Street { get; init; }
    public string City { get; init; }
}

// If it needs identity, it's an entity, not a value object!

// ✓ GOOD - Pure value object
public record Address(string Street, string City, string PostalCode);

// Or if you need to track addresses
public class CustomerAddress  // Entity
{
    public AddressId Id { get; private set; }
    public CustomerId CustomerId { get; private set; }
    public Address Address { get; private set; }  // Embedded value object
    public AddressType Type { get; private set; }  // Billing, Shipping, etc.
}
```

## Key Takeaways

1. **Identity matters for entities, values matter for value objects** - Choose based on what's important

2. **Value objects should be immutable** - Makes them thread-safe, shareable, and predictable

3. **C# records are perfect for value objects** - Structural equality and immutability built-in

4. **Validate value objects at construction** - Impossible states become unrepresentable

5. **Domain events decouple aggregates** - No direct dependencies between aggregates

6. **Events are past tense** - They describe what happened, not what should happen

7. **Publish events after successful persistence** - Ensures consistency

8. **One event handler = one responsibility** - Keep handlers focused and composable

9. **Use value objects liberally** - Replace primitives with domain-specific types

10. **Events provide audit trail** - Natural history of what happened in the system
