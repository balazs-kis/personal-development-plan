## Introduction

An Aggregate is a cluster of domain objects that can be treated as a single unit for data changes. An Aggregate Root is the entry point to the aggregate, responsible for maintaining the aggregate's invariants. Aggregates define consistency boundaries—transactions should not cross aggregate boundaries.

Aggregates are perhaps the most powerful tactical pattern in Domain-Driven Design because they solve one of the hardest problems in software development: how to maintain consistency in a complex domain model without creating a tangled mess of dependencies. By clustering related objects together and controlling all access through a root, aggregates enforce business rules automatically and make impossible states impossible to represent.

The key insight is that not all objects need to be independently accessible. In fact, allowing direct access to every entity in your system creates chaos—anyone can modify anything, and invariants are impossible to enforce. Aggregates restore sanity by establishing clear boundaries and making the root responsible for all changes within that boundary.

Think of an aggregate as a fortress protecting your business rules. The aggregate root is the only gate into that fortress. This means you can enforce invariants with confidence because you control all the ways the aggregate can be modified. No more defensive programming checking constraints everywhere—the aggregate's public interface is designed so that every operation leaves the aggregate in a valid state.

## Key Concepts Summary

### What is an Aggregate?

```
Order Aggregate
┌──────────────────────────────────────┐
│  Order (Aggregate Root)              │
│  ├─ OrderId                          │
│  ├─ CustomerId                       │
│  ├─ Status                           │
│  ├─ TotalAmount                      │
│  │                                   │
│  └─ OrderLines (Entities)            │
│     ├─ OrderLine 1                   │
│     │  ├─ ProductId                  │
│     │  ├─ Quantity                   │
│     │  └─ Price                      │
│     ├─ OrderLine 2                   │
│     └─ OrderLine 3                   │
└──────────────────────────────────────┘

All access goes through Order (root)
Consistency boundary = entire aggregate
```

### Aggregate Implementation
```csharp
public class Order  // Aggregate Root
{
    public OrderId Id { get; private set; }
    public CustomerId CustomerId { get; private set; }
    public OrderStatus Status { get; private set; }
    
    // Encapsulated collection - no public setter!
    private readonly List<OrderLine> _lines = new();
    public IReadOnlyCollection<OrderLine> Lines => _lines.AsReadOnly();
    
    // Calculated value - maintained by aggregate
    public Money TotalAmount { get; private set; }
    
    // All modifications go through the aggregate root
    public void AddLine(ProductId productId, Money price, Quantity quantity)
    {
        // Enforce invariants
        if (Status != OrderStatus.Draft)
            throw new OrderCannotBeModifiedException();
        
        // Check business rules
        if (_lines.Count >= 50)
            throw new TooManyOrderLinesException();
        
        var line = new OrderLine(Guid.NewGuid(), productId, price, quantity);
        _lines.Add(line);
        
        // Maintain consistency
        RecalculateTotalAmount();
    }
    
    public void RemoveLine(Guid lineId)
    {
        if (Status != OrderStatus.Draft)
            throw new OrderCannotBeModifiedException();
        
        var line = _lines.FirstOrDefault(l => l.Id == lineId)
            ?? throw new OrderLineNotFoundException();
        
        _lines.Remove(line);
        RecalculateTotalAmount();
    }
    
    public void Submit()
    {
        // Invariant: Order must have at least one line
        if (_lines.Count == 0)
            throw new EmptyOrderException();
        
        // Invariant: Draft orders can be submitted
        if (Status != OrderStatus.Draft)
            throw new InvalidOrderStateException();
        
        Status = OrderStatus.Submitted;
    }
    
    private void RecalculateTotalAmount()
    {
        TotalAmount = _lines
            .Select(l => l.LineTotal)
            .Aggregate(Money.Zero, (sum, total) => sum + total);
    }
}

// Entity within the aggregate - not directly accessible
public class OrderLine
{
    internal OrderLine(Guid id, ProductId productId, Money price, Quantity quantity)
    {
        Id = id;
        ProductId = productId;
        Price = price;
        Quantity = quantity;
    }
    
    public Guid Id { get; private set; }
    public ProductId ProductId { get; private set; }
    public Money Price { get; private set; }
    public Quantity Quantity { get; private set; }
    
    public Money LineTotal => new(Price.Amount * Quantity.Value, Price.Currency);
}
```

### Rules for Aggregate Design

These rules are foundational to effective aggregate design. Following them prevents common pitfalls and ensures your aggregates remain maintainable.

**Rule 1: Protect Business Invariants**

An invariant is a rule that must always be true. The aggregate root is the guardian of these rules.

```csharp
public class BankAccount  // Aggregate Root
{
    public AccountId Id { get; private set; }
    public Money Balance { get; private set; }
    public Money OverdraftLimit { get; private set; }
    public AccountStatus Status { get; private set; }
    
    // Invariant: Cannot withdraw more than balance + overdraft limit
    public void Withdraw(Money amount)
    {
        if (Status == AccountStatus.Frozen)
            throw new AccountFrozenException();
        
        var availableFunds = Balance.Amount + OverdraftLimit.Amount;
        if (amount.Amount > availableFunds)
            throw new InsufficientFundsException(
                $"Available: {availableFunds}, Requested: {amount.Amount}");
        
        Balance = new Money(Balance.Amount - amount.Amount, Balance.Currency);
        
        // Domain event
        DomainEvents.Raise(new MoneyWithdrawn(Id, amount, Balance));
    }
    
    // Invariant: Cannot close account with positive balance
    public void Close()
    {
        if (Balance.Amount > 0)
            throw new CannotCloseAccountWithBalanceException(
                "Account must have zero balance before closing");
        
        if (Balance.Amount < 0)
            throw new CannotCloseAccountWithDebtException(
                "Outstanding debt must be paid before closing");
        
        Status = AccountStatus.Closed;
        DomainEvents.Raise(new AccountClosed(Id));
    }
    
    public void Freeze()
    {
        if (Status == AccountStatus.Closed)
            throw new InvalidOperationException("Cannot freeze closed account");
        
        Status = AccountStatus.Frozen;
        DomainEvents.Raise(new AccountFrozen(Id));
    }
}

public enum AccountStatus
{
    Active,
    Frozen,
    Closed
}
```

**Why This Works:**
- All modifications go through the aggregate root
- Private setters prevent external tampering
- Business rules are enforced in one place
- Impossible to create invalid state

**Rule 2: Design Small Aggregates**

Large aggregates cause performance problems and increase contention. Keep aggregates as small as possible while still protecting invariants.

```csharp
// ❌ BAD - Too large
public class Customer
{
    public CustomerId Id { get; set; }
    public string Name { get; set; }
    
    // Including all orders is too much!
    public List<Order> Orders { get; set; }  // Could be thousands
    
    // Including all addresses might be OK
    public List<Address> Addresses { get; set; }
    
    // Payment methods might be OK
    public List<PaymentMethod> PaymentMethods { get; set; }
    
    // Full order history? Definitely too much
    public OrderHistory OrderHistory { get; set; }
}

// ✓ GOOD - Right-sized aggregates
public class Customer  // Small aggregate
{
    public CustomerId Id { get; private set; }
    public string Name { get; private set; }
    public Email Email { get; private set; }
    
    // Only includes data that must be consistent with customer
    private List<Address> _addresses = new();
    public IReadOnlyCollection<Address> Addresses => _addresses.AsReadOnly();
    
    public void AddAddress(Address address)
    {
        // Invariant: Customer can have max 5 addresses
        if (_addresses.Count >= 5)
            throw new TooManyAddressesException();
        
        _addresses.Add(address);
    }
}

public class Order  // Separate aggregate
{
    public OrderId Id { get; private set; }
    
    // Reference by ID only, not object reference
    public CustomerId CustomerId { get; private set; }
    
    private List<OrderLine> _lines = new();
    // ... order logic
}
```

**How to Decide What to Include:**

Ask these questions:
1. Must this data always be consistent with the root? → Include it
2. Does this data have independent lifecycle? → Separate aggregate
3. Does this collection grow unbounded? → Separate aggregate
4. Would loading this data cause performance issues? → Separate aggregate

**Examples:**

```
Order + OrderLines → Same aggregate
  Why? Lines must be consistent with order total; bounded collection

Customer + Orders → Different aggregates
  Why? Orders have independent lifecycle; unbounded collection

Product + Reviews → Different aggregates
  Why? Reviews grow unbounded; independent lifecycle; different change frequency
```

**Rule 3: Reference Other Aggregates by ID Only**

Aggregates should reference each other by identity, not by direct object reference. This enforces loose coupling and clear boundaries.

```csharp
// ❌ BAD - Direct object reference
public class Order
{
    public OrderId Id { get; private set; }
    
    // Direct reference to another aggregate
    public Customer Customer { get; private set; }  // ❌
    
    // Now Order must load Customer
    // Coupling aggregates together
    // Can't save Order without Customer
}

// ✓ GOOD - Reference by ID
public class Order
{
    public OrderId Id { get; private set; }
    
    // Reference by ID only
    public CustomerId CustomerId { get; private set; }  // ✓
    
    // If you need customer data, load separately
}

// When you need customer information
public class OrderService
{
    private readonly IOrderRepository _orderRepo;
    private readonly ICustomerRepository _customerRepo;
    
    public async Task ProcessOrder(OrderId orderId)
    {
        // Load aggregates separately
        var order = await _orderRepo.GetById(orderId);
        var customer = await _customerRepo.GetById(order.CustomerId);
        
        // Use both
        if (!customer.IsEligibleForPurchase())
            throw new CustomerNotEligibleException();
        
        order.Confirm();
        await _orderRepo.SaveChanges();
    }
}
```

**Benefits:**
- Clear boundaries between aggregates
- Can persist aggregates independently
- Lazy loading is possible
- Reduced coupling
- Better performance (don't load unnecessary data)

**Rule 4: One Transaction = One Aggregate**

A transaction should modify only one aggregate instance. If you need to update multiple aggregates, use eventual consistency via domain events.

```csharp
// ❌ BAD - Multiple aggregates in one transaction
public async Task PlaceOrder(OrderId orderId)
{
    using var transaction = await _dbContext.Database.BeginTransactionAsync();
    
    // Modifying Order aggregate
    var order = await _orderRepo.GetById(orderId);
    order.Submit();
    
    // Modifying Product aggregates (different aggregates!)
    foreach (var line in order.Lines)
    {
        var product = await _productRepo.GetById(line.ProductId);
        product.DecreaseStock(line.Quantity);  // ❌ Cross-aggregate transaction
    }
    
    await _dbContext.SaveChangesAsync();
    await transaction.CommitAsync();
    
    // Problems:
    // - Long-running transaction
    // - Locks multiple aggregates
    // - Scalability bottleneck
    // - Distributed transaction nightmare in microservices
}

// ✓ GOOD - One aggregate per transaction, use events for coordination
public async Task PlaceOrder(OrderId orderId)
{
    // Transaction only touches Order aggregate
    var order = await _orderRepo.GetById(orderId);
    order.Submit();  // Raises OrderSubmitted domain event
    
    await _orderRepo.SaveChanges();
    // Transaction committed, event dispatched
}

// Separate handler updates inventory (eventual consistency)
public class OrderSubmittedHandler : IEventHandler<OrderSubmitted>
{
    public async Task Handle(OrderSubmitted @event)
    {
        // Separate transaction for inventory
        foreach (var line in @event.OrderLines)
        {
            var product = await _productRepo.GetById(line.ProductId);
            product.ReserveStock(line.Quantity);
            await _productRepo.SaveChanges();
        }
    }
}
```

**Eventual Consistency Pattern:**

```csharp
// Aggregate raises events
public class Order
{
    private readonly List<DomainEvent> _domainEvents = new();
    
    public void Submit()
    {
        Status = OrderStatus.Submitted;
        _domainEvents.Add(new OrderSubmitted(Id, CustomerId, Lines));
    }
    
    public void Confirm()
    {
        Status = OrderStatus.Confirmed;
        _domainEvents.Add(new OrderConfirmed(Id));
    }
}

// Repository dispatches events after successful save
public class OrderRepository
{
    public async Task SaveChanges()
    {
        // Collect events
        var events = GetDomainEvents();
        
        // Save to database (single aggregate transaction)
        await _dbContext.SaveChangesAsync();
        
        // Dispatch events AFTER successful save
        foreach (var @event in events)
        {
            await _eventDispatcher.Dispatch(@event);
        }
    }
}

// Other aggregates react to events
public class InventoryAllocationHandler : IEventHandler<OrderConfirmed>
{
    public async Task Handle(OrderConfirmed @event)
    {
        // Separate transaction, different aggregate
        foreach (var line in @event.OrderLines)
        {
            await AllocateInventory(line.ProductId, line.Quantity);
        }
    }
}
```

**When to Break This Rule:**

Very rarely! Only when:
- True ACID guarantees are legally required
- Business explicitly demands immediate consistency
- System is small and won't scale
- Performance impact is acceptable

Even then, consider if domain events with compensation logic might work instead.

**Rule 5: Update Aggregates in Isolation**

Don't navigate from one aggregate to another in the same operation.

```csharp
// ❌ BAD - Navigating between aggregates
public class Order
{
    public Customer Customer { get; set; }  // Object reference
    
    public void ApplyLoyaltyDiscount()
    {
        // Navigating to Customer aggregate
        if (Customer.LoyaltyStatus == LoyaltyStatus.Gold)  // ❌
        {
            // Applying discount based on other aggregate's state
            ApplyDiscount(0.15m);
        }
    }
}

// ✓ GOOD - Pass necessary information
public class Order
{
    public CustomerId CustomerId { get; private set; }
    
    public void ApplyLoyaltyDiscount(LoyaltyStatus customerLoyaltyStatus)
    {
        // Using passed-in value, not navigating
        if (customerLoyaltyStatus == LoyaltyStatus.Gold)
        {
            ApplyDiscount(0.15m);
        }
    }
}

// Service coordinates
public class OrderService
{
    public async Task ApplyCustomerDiscount(OrderId orderId)
    {
        var order = await _orderRepo.GetById(orderId);
        var customer = await _customerRepo.GetById(order.CustomerId);
        
        // Pass needed info
        order.ApplyLoyaltyDiscount(customer.LoyaltyStatus);
        
        await _orderRepo.SaveChanges();
    }
}
```

## Advanced Aggregate Patterns

### Pattern 1: Aggregate Factories

Control aggregate creation with factories that enforce creation invariants.

```csharp
public class Order
{
    // Private constructor - can't be created directly
    private Order() { }
    
    // Factory method enforces creation rules
    public static Order CreateNew(
        CustomerId customerId,
        ShippingAddress address)
    {
        // Validate inputs
        if (customerId == null)
            throw new ArgumentNullException(nameof(customerId));
        if (address == null)
            throw new ArgumentNullException(nameof(address));
        if (!address.IsComplete())
            throw new IncompleteAddressException();
        
        // Create in valid state
        var order = new Order
        {
            Id = OrderId.Generate(),
            CustomerId = customerId,
            ShippingAddress = address,
            Status = OrderStatus.Draft,
            CreatedAt = DateTime.UtcNow,
            _lines = new List<OrderLine>()
        };
        
        // Raise creation event
        order._domainEvents.Add(new OrderCreated(order.Id, customerId));
        
        return order;
    }
    
    // Factory for recreating from persistence
    internal static Order Reconstitute(
        OrderId id,
        CustomerId customerId,
        OrderStatus status,
        List<OrderLine> lines,
        Money total)
    {
        return new Order
        {
            Id = id,
            CustomerId = customerId,
            Status = status,
            _lines = lines,
            TotalAmount = total
        };
    }
}
```

### Pattern 2: Aggregate Versioning for Optimistic Concurrency

```csharp
public class Order
{
    public OrderId Id { get; private set; }
    public int Version { get; private set; }  // Concurrency token
    
    // EF Core configuration
    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Order>()
            .Property(o => o.Version)
            .IsConcurrencyToken();
    }
}

// Usage
public async Task UpdateOrder(OrderId orderId, int expectedVersion)
{
    var order = await _orderRepo.GetById(orderId);
    
    if (order.Version != expectedVersion)
        throw new ConcurrencyException("Order was modified by another user");
    
    order.AddLine(/* ... */);
    
    try
    {
        await _orderRepo.SaveChanges();
    }
    catch (DbUpdateConcurrencyException)
    {
        throw new ConcurrencyException("Order was modified during your update");
    }
}
```

### Pattern 3: Aggregate Snapshots for Event Sourcing

```csharp
public class Order
{
    private List<DomainEvent> _uncommittedEvents = new();
    
    // Reconstitute from events
    public static Order FromEvents(IEnumerable<DomainEvent> events)
    {
        var order = new Order();
        
        foreach (var @event in events)
        {
            order.Apply(@event);
        }
        
        return order;
    }
    
    // Apply event to state
    private void Apply(DomainEvent @event)
    {
        switch (@event)
        {
            case OrderCreated e:
                Id = e.OrderId;
                CustomerId = e.CustomerId;
                Status = OrderStatus.Draft;
                break;
                
            case OrderLineAdded e:
                _lines.Add(new OrderLine(e.ProductId, e.Quantity, e.Price));
                RecalculateTotal();
                break;
                
            case OrderSubmitted e:
                Status = OrderStatus.Submitted;
                break;
        }
    }
    
    // Public methods raise events
    public void AddLine(ProductId productId, Quantity quantity, Money price)
    {
        var @event = new OrderLineAdded(Id, productId, quantity, price);
        Apply(@event);  // Update state
        _uncommittedEvents.Add(@event);  // Record for persistence
    }
}
```

## Repository Pattern for Aggregates

Repositories provide collection-like interface for aggregates. They operate at aggregate boundaries, never exposing internal entities.

```csharp
// ✓ GOOD - Repository for aggregate root only
public interface IOrderRepository
{
    // Basic CRUD on aggregate root
    Task<Order> GetById(OrderId id);
    Task Add(Order order);
    Task Update(Order order);
    Task Remove(OrderId id);
    
    // Query methods return complete aggregates
    Task<IEnumerable<Order>> GetOrdersByCustomer(CustomerId customerId);
    Task<IEnumerable<Order>> GetPendingOrders();
    Task<Order> GetOrderWithLines(OrderId id);  // Explicit eager loading
}

// ❌ BAD - Methods that break aggregate boundary
public interface IBadOrderRepository
{
    Task<OrderLine> GetOrderLine(Guid lineId);  // ❌ Exposes internal entity
    Task UpdateOrderLine(OrderLine line);  // ❌ Bypasses aggregate root
    Task<List<OrderLine>> GetAllOrderLines();  // ❌ Lines without context
}
```

**Repository Implementation:**

```csharp
public class OrderRepository : IOrderRepository
{
    private readonly DbContext _dbContext;
    private readonly IDomainEventDispatcher _eventDispatcher;
    
    public async Task<Order> GetById(OrderId id)
    {
        return await _dbContext.Orders
            .Include(o => o.Lines)  // Load full aggregate
            .FirstOrDefaultAsync(o => o.Id == id);
    }
    
    public async Task Add(Order order)
    {
        await _dbContext.Orders.AddAsync(order);
    }
    
    public async Task SaveChanges()
    {
        // Collect domain events from aggregates
        var aggregatesWithEvents = _dbContext.ChangeTracker
            .Entries<IAggregateRoot>()
            .Where(e => e.Entity.DomainEvents.Any())
            .Select(e => e.Entity)
            .ToList();
        
        var events = aggregatesWithEvents
            .SelectMany(a => a.DomainEvents)
            .ToList();
        
        // Clear events before saving (avoid re-raising)
        foreach (var aggregate in aggregatesWithEvents)
        {
            aggregate.ClearEvents();
        }
        
        // Save changes (single transaction for aggregate)
        await _dbContext.SaveChangesAsync();
        
        // Dispatch events AFTER successful save
        foreach (var @event in events)
        {
            await _eventDispatcher.Dispatch(@event);
        }
    }
}

// Base aggregate interface
public interface IAggregateRoot
{
    IReadOnlyCollection<DomainEvent> DomainEvents { get; }
    void ClearEvents();
}
```

**Querying Across Aggregates:**

```csharp
// Use application services to coordinate multiple aggregates
public class OrderQueryService
{
    private readonly IOrderRepository _orders;
    private readonly ICustomerRepository _customers;
    private readonly IProductRepository _products;
    
    public async Task<OrderDetailsDto> GetOrderDetails(OrderId id)
    {
        // Load multiple aggregates
        var order = await _orders.GetById(id);
        var customer = await _customers.GetById(order.CustomerId);
        
        // Load product details for each line
        var productIds = order.Lines.Select(l => l.ProductId).ToList();
        var products = await _products.GetByIds(productIds);
        
        // Compose DTO from multiple aggregates
        return new OrderDetailsDto
        {
            OrderId = order.Id.Value,
            OrderDate = order.CreatedAt,
            Status = order.Status.ToString(),
            Customer = new CustomerDto
            {
                Id = customer.Id.Value,
                Name = customer.Name,
                Email = customer.Email.Value
            },
            Lines = order.Lines.Select(line =>
            {
                var product = products.First(p => p.Id == line.ProductId);
                return new OrderLineDto
                {
                    ProductName = product.Name,
                    Quantity = line.Quantity.Value,
                    Price = line.PriceAtTimeOfOrder.Amount
                };
            }).ToList(),
            TotalAmount = order.TotalAmount.Amount
        };
    }
}
```

## Real-World Examples

### Example 1: Shopping Cart Aggregate

```csharp
public class ShoppingCart  // Aggregate Root
{
    public CartId Id { get; private set; }
    public CustomerId CustomerId { get; private set; }
    
    private readonly List<CartItem> _items = new();
    public IReadOnlyCollection<CartItem> Items => _items.AsReadOnly();
    
    private DiscountCode _appliedDiscount;
    public Money SubTotal { get; private set; }
    public Money DiscountAmount { get; private set; }
    public Money Total { get; private set; }
    
    private readonly List<DomainEvent> _domainEvents = new();
    public IReadOnlyCollection<DomainEvent> DomainEvents => _domainEvents.AsReadOnly();
    
    // Factory
    public static ShoppingCart CreateNew(CustomerId customerId)
    {
        var cart = new ShoppingCart
        {
            Id = CartId.Generate(),
            CustomerId = customerId,
            SubTotal = Money.Zero,
            DiscountAmount = Money.Zero,
            Total = Money.Zero
        };
        
        cart._domainEvents.Add(new CartCreated(cart.Id, customerId));
        return cart;
    }
    
    // Business operations
    public void AddItem(ProductId productId, string productName, Money price, Quantity quantity)
    {
        // Invariant: Cannot add more than 50 items
        if (_items.Count >= 50)
            throw new CartFullException("Cart cannot contain more than 50 items");
        
        // Invariant: Quantity must be positive
        if (quantity.Value <= 0)
            throw new InvalidQuantityException();
        
        // Check if item already in cart
        var existingItem = _items.FirstOrDefault(i => i.ProductId == productId);
        
        if (existingItem != null)
        {
            // Update quantity of existing item
            existingItem.IncreaseQuantity(quantity);
            _domainEvents.Add(new CartItemQuantityChanged(Id, productId, existingItem.Quantity));
        }
        else
        {
            // Add new item
            var item = new CartItem(productId, productName, price, quantity);
            _items.Add(item);
            _domainEvents.Add(new CartItemAdded(Id, productId, quantity, price));
        }
        
        RecalculateTotals();
    }
    
    public void RemoveItem(ProductId productId)
    {
        var item = _items.FirstOrDefault(i => i.ProductId == productId)
            ?? throw new ItemNotFoundException();
        
        _items.Remove(item);
        _domainEvents.Add(new CartItemRemoved(Id, productId));
        
        RecalculateTotals();
    }
    
    public void UpdateItemQuantity(ProductId productId, Quantity newQuantity)
    {
        if (newQuantity.Value <= 0)
            throw new InvalidQuantityException();
        
        var item = _items.FirstOrDefault(i => i.ProductId == productId)
            ?? throw new ItemNotFoundException();
        
        item.SetQuantity(newQuantity);
        _domainEvents.Add(new CartItemQuantityChanged(Id, productId, newQuantity));
        
        RecalculateTotals();
    }
    
    public void ApplyDiscountCode(DiscountCode code)
    {
        // Invariant: Only one discount code at a time
        if (_appliedDiscount != null)
            throw new DiscountAlreadyAppliedException();
        
        // Validate discount
        if (!code.IsValid(DateTime.UtcNow))
            throw new InvalidDiscountCodeException("Discount code has expired");
        
        if (SubTotal < code.MinimumOrderAmount)
            throw new MinimumOrderAmountNotMetException(
                $"Minimum order of {code.MinimumOrderAmount} required");
        
        _appliedDiscount = code;
        _domainEvents.Add(new DiscountApplied(Id, code.Code));
        
        RecalculateTotals();
    }
    
    public void RemoveDiscount()
    {
        if (_appliedDiscount == null)
            return;
        
        _domainEvents.Add(new DiscountRemoved(Id, _appliedDiscount.Code));
        _appliedDiscount = null;
        
        RecalculateTotals();
    }
    
    public void Clear()
    {
        _items.Clear();
        _appliedDiscount = null;
        _domainEvents.Add(new CartCleared(Id));
        
        RecalculateTotals();
    }
    
    public Order Checkout(ShippingAddress address, PaymentMethodToken paymentMethod)
    {
        // Invariant: Cart must have items to checkout
        if (_items.Count == 0)
            throw new EmptyCartException("Cannot checkout empty cart");
        
        // Create order from cart
        var order = Order.CreateFromCart(this, address, paymentMethod);
        
        // Clear cart after checkout
        _items.Clear();
        _appliedDiscount = null;
        RecalculateTotals();
        
        _domainEvents.Add(new CartCheckedOut(Id, order.Id));
        
        return order;
    }
    
    private void RecalculateTotals()
    {
        SubTotal = _items
            .Select(i => i.LineTotal)
            .Aggregate(Money.Zero, (sum, total) => sum + total);
        
        if (_appliedDiscount != null)
        {
            DiscountAmount = _appliedDiscount.CalculateDiscount(SubTotal);
        }
        else
        {
            DiscountAmount = Money.Zero;
        }
        
        Total = SubTotal - DiscountAmount;
    }
    
    public void ClearEvents() => _domainEvents.Clear();
}

// Entity within aggregate (not directly accessible)
public class CartItem
{
    internal CartItem(ProductId productId, string productName, Money price, Quantity quantity)
    {
        ProductId = productId;
        ProductName = productName;
        Price = price;
        Quantity = quantity;
    }
    
    public ProductId ProductId { get; private set; }
    public string ProductName { get; private set; }
    public Money Price { get; private set; }
    public Quantity Quantity { get; private set; }
    
    public Money LineTotal => new(Price.Amount * Quantity.Value, Price.Currency);
    
    internal void IncreaseQuantity(Quantity additionalQuantity)
    {
        Quantity = new Quantity(Quantity.Value + additionalQuantity.Value);
    }
    
    internal void SetQuantity(Quantity newQuantity)
    {
        Quantity = newQuantity;
    }
}

// Value object
public class DiscountCode
{
    public string Code { get; private set; }
    public decimal PercentageOff { get; private set; }
    public Money MinimumOrderAmount { get; private set; }
    public DateTime ExpiresAt { get; private set; }
    
    public bool IsValid(DateTime date) => date <= ExpiresAt;
    
    public Money CalculateDiscount(Money orderAmount)
    {
        if (orderAmount < MinimumOrderAmount)
            return Money.Zero;
        
        var discountAmount = orderAmount.Amount * PercentageOff;
        return new Money(discountAmount, orderAmount.Currency);
    }
}
```

### Example 2: Hotel Reservation Aggregate

```csharp
public class Reservation  // Aggregate Root
{
    public ReservationId Id { get; private set; }
    public GuestId GuestId { get; private set; }
    public RoomId RoomId { get; private set; }
    
    public DateRange StayPeriod { get; private set; }
    public ReservationStatus Status { get; private set; }
    
    private readonly List<ReservationService> _services = new();
    public IReadOnlyCollection<ReservationService> Services => _services.AsReadOnly();
    
    public Money TotalAmount { get; private set; }
    
    private readonly List<DomainEvent> _domainEvents = new();
    public IReadOnlyCollection<DomainEvent> DomainEvents => _domainEvents.AsReadOnly();
    
    // Factory
    public static Reservation Create(
        GuestId guestId,
        RoomId roomId,
        DateRange stayPeriod,
        Money roomRate)
    {
        // Invariant: Stay must be in future
        if (stayPeriod.Start <= DateTime.UtcNow.Date)
            throw new InvalidReservationDateException("Check-in must be in the future");
        
        // Invariant: Minimum stay of 1 night
        if (stayPeriod.DurationInDays < 1)
            throw new InvalidStayDurationException("Minimum stay is 1 night");
        
        var reservation = new Reservation
        {
            Id = ReservationId.Generate(),
            GuestId = guestId,
            RoomId = roomId,
            StayPeriod = stayPeriod,
            Status = ReservationStatus.Provisional,
            TotalAmount = roomRate * stayPeriod.DurationInDays
        };
        
        reservation._domainEvents.Add(
            new ReservationCreated(reservation.Id, guestId, roomId, stayPeriod));
        
        return reservation;
    }
    
    // Business operations
    public void Confirm(PaymentId paymentId)
    {
        // Invariant: Only provisional reservations can be confirmed
        if (Status != ReservationStatus.Provisional)
            throw new InvalidReservationStateException();
        
        Status = ReservationStatus.Confirmed;
        _domainEvents.Add(new ReservationConfirmed(Id, paymentId));
    }
    
    public void CheckIn()
    {
        // Invariant: Must be confirmed
        if (Status != ReservationStatus.Confirmed)
            throw new InvalidReservationStateException();
        
        // Invariant: Cannot check in before check-in date
        if (DateTime.UtcNow.Date < StayPeriod.Start.Date)
            throw new EarlyCheckInException();
        
        Status = ReservationStatus.CheckedIn;
        _domainEvents.Add(new GuestCheckedIn(Id, GuestId, RoomId));
    }
    
    public void CheckOut()
    {
        // Invariant: Must be checked in
        if (Status != ReservationStatus.CheckedIn)
            throw new InvalidReservationStateException();
        
        Status = ReservationStatus.CheckedOut;
        _domainEvents.Add(new GuestCheckedOut(Id, GuestId, RoomId, TotalAmount));
    }
    
    public void Cancel(CancellationReason reason)
    {
        // Invariant: Cannot cancel after check-in
        if (Status == ReservationStatus.CheckedIn || Status == ReservationStatus.CheckedOut)
            throw new CannotCancelReservationException("Cannot cancel after check-in");
        
        // Calculate cancellation fee based on cancellation policy
        var cancellationFee = CalculateCancellationFee();
        
        Status = ReservationStatus.Cancelled;
        _domainEvents.Add(new ReservationCancelled(Id, reason, cancellationFee));
    }
    
    public void AddService(ServiceType service, Money price)
    {
        // Invariant: Can only add services before checkout
        if (Status == ReservationStatus.CheckedOut || Status == ReservationStatus.Cancelled)
            throw new CannotModifyCompletedReservationException();
        
        var reservationService = new ReservationService(service, price);
        _services.Add(reservationService);
        
        RecalculateTotalAmount();
        
        _domainEvents.Add(new ServiceAdded(Id, service, price));
    }
    
    private void RecalculateTotalAmount()
    {
        var serviceTotal = _services
            .Select(s => s.Price)
            .Aggregate(Money.Zero, (sum, price) => sum + price);
        
        TotalAmount = TotalAmount + serviceTotal;
    }
    
    private Money CalculateCancellationFee()
    {
        var daysUntilCheckIn = (StayPeriod.Start - DateTime.UtcNow.Date).Days;
        
        return daysUntilCheckIn switch
        {
            < 7 => TotalAmount * 0.50m,  // 50% fee if less than 7 days
            < 14 => TotalAmount * 0.25m,  // 25% fee if less than 14 days
            _ => Money.Zero  // No fee if 14+ days
        };
    }
    
    public void ClearEvents() => _domainEvents.Clear();
}

// Entity within aggregate
public class ReservationService
{
    internal ReservationService(ServiceType service, Money price)
    {
        Service = service;
        Price = price;
        AddedAt = DateTime.UtcNow;
    }
    
    public ServiceType Service { get; private set; }
    public Money Price { get; private set; }
    public DateTime AddedAt { get; private set; }
}

public enum ServiceType
{
    RoomService,
    LaundryService,
    Parking,
    Spa,
    LatecheckOut
}

public enum ReservationStatus
{
    Provisional,
    Confirmed,
    CheckedIn,
    CheckedOut,
    Cancelled
}
```

## Common Aggregate Design Mistakes

### Mistake 1: Aggregates That Are Too Large

**Problem:** Including everything related in one aggregate

```csharp
// ❌ BAD - Way too large
public class Customer
{
    public CustomerId Id { get; set; }
    public string Name { get; set; }
    
    // All orders - could be thousands!
    public List<Order> Orders { get; set; }
    
    // All payments
    public List<Payment> Payments { get; set; }
    
    // All support tickets
    public List<SupportTicket> Tickets { get; set; }
    
    // All addresses
    public List<Address> Addresses { get; set; }
    
    // Loyalty program
    public LoyaltyAccount Loyalty { get; set; }
}
```

**Problems:**
- Loading one customer loads thousands of related objects
- Any operation requires loading entire object graph
- Concurrency issues (whole customer locked)
- Can't scale (single point of contention)

**Solution:** Split into appropriately-sized aggregates

```csharp
// ✓ GOOD - Separate aggregates
public class Customer
{
    public CustomerId Id { get; private set; }
    public string Name { get; private set; }
    private List<Address> _addresses;  // Bounded, part of identity
}

public class Order
{
    public OrderId Id { get; private set; }
    public CustomerId CustomerId { get; private set; }  // Reference by ID
}

public class LoyaltyAccount
{
    public LoyaltyAccountId Id { get; private set; }
    public CustomerId CustomerId { get; private set; }  // Reference by ID
}
```

### Mistake 2: Exposing Internal Collections

**Problem:** Allowing direct manipulation of collections

```csharp
// ❌ BAD - Exposed collection
public class Order
{
    public List<OrderLine> Lines { get; set; }  // Public setter!
}

// Caller can bypass aggregate root
order.Lines.Add(new OrderLine(...));  // No validation!
order.Lines.Clear();  // Breaks invariants!
```

**Solution:** Encapsulate collections with methods

```csharp
// ✓ GOOD - Encapsulated collection
public class Order
{
    private readonly List<OrderLine> _lines = new();
    public IReadOnlyCollection<OrderLine> Lines => _lines.AsReadOnly();
    
    public void AddLine(Product product, Quantity quantity)
    {
        // All validation here
        // Invariants enforced
        // Events raised
    }
}
```

### Mistake 3: Anemic Aggregates

**Problem:** Aggregate root is just a data bag

```csharp
// ❌ BAD - Anemic aggregate
public class Order
{
    public OrderId Id { get; set; }
    public OrderStatus Status { get; set; }
    public List<OrderLine> Lines { get; set; }
    public Money Total { get; set; }
}

// Logic in service
public class OrderService
{
    public void AddLineToOrder(Order order, Product product, int quantity)
    {
        order.Lines.Add(new OrderLine { ... });
        order.Total = order.Lines.Sum(l => l.Price * l.Quantity);
    }
}
```

**Solution:** Put behavior in the aggregate

```csharp
// ✓ GOOD - Rich aggregate
public class Order
{
    public void AddLine(Product product, Quantity quantity)
    {
        // Business logic here
        // Invariants enforced
        // State managed internally
    }
}
```

### Mistake 4: Navigating Between Aggregates

**Problem:** Traversing from one aggregate to another

```csharp
// ❌ BAD - Object references between aggregates
public class Order
{
    public Customer Customer { get; set; }  // Object reference
    
    public void ApplyDiscount()
    {
        if (Customer.Loyalty.Status == LoyaltyStatus.Gold)  // ❌
        {
            // Navigating through aggregates
        }
    }
}
```

**Solution:** Pass needed values, don't navigate

```csharp
// ✓ GOOD - Pass required values
public class Order
{
    public CustomerId CustomerId { get; private set; }
    
    public void ApplyLoyaltyDiscount(LoyaltyStatus customerStatus)
    {
        if (customerStatus == LoyaltyStatus.Gold)
        {
            // Use passed value
        }
    }
}

// Service coordinates
public class OrderService
{
    public async Task ApplyDiscount(OrderId orderId)
    {
        var order = await _orderRepo.GetById(orderId);
        var customer = await _customerRepo.GetById(order.CustomerId);
        var loyalty = await _loyaltyRepo.GetByCustomer(customer.Id);
        
        order.ApplyLoyaltyDiscount(loyalty.Status);
    }
}
```

### Mistake 5: Modifying Multiple Aggregates in One Transaction

**Problem:** Long transactions locking multiple aggregates

```csharp
// ❌ BAD - Multi-aggregate transaction
public async Task TransferFunds(AccountId fromId, AccountId toId, Money amount)
{
    using var tx = _db.BeginTransaction();
    
    var fromAccount = await _repo.GetById(fromId);
    fromAccount.Withdraw(amount);
    
    var toAccount = await _repo.GetById(toId);
    toAccount.Deposit(amount);
    
    await _db.SaveChanges();
    await tx.Commit();
    
    // Problems:
    // - Locks both accounts
    // - What if toAccount.Deposit fails?
    // - Doesn't scale
}
```

**Solution:** Use eventual consistency with sagas

```csharp
// ✓ GOOD - Saga with compensation
public async Task TransferFunds(AccountId fromId, AccountId toId, Money amount)
{
    // Step 1: Withdraw from source
    var fromAccount = await _repo.GetById(fromId);
    fromAccount.Withdraw(amount);  // Raises MoneyWithdrawn event
    await _repo.SaveChanges();
}

// Event handler
public class MoneyWithdrawnHandler
{
    public async Task Handle(MoneyWithdrawn @event)
    {
        try
        {
            // Step 2: Deposit to destination
            var toAccount = await _repo.GetById(@event.TargetAccountId);
            toAccount.Deposit(@event.Amount);
            await _repo.SaveChanges();
        }
        catch (Exception)
        {
            // Compensation: Refund source account
            var fromAccount = await _repo.GetById(@event.SourceAccountId);
            fromAccount.Deposit(@event.Amount);  // Refund
            await _repo.SaveChanges();
        }
    }
}
```

## Self-Check Questions

1. **What is the difference between an entity and an aggregate root?**
   - An entity is any object with identity that persists over time
   - An aggregate root is a special entity that serves as the entry point to an aggregate
   - The aggregate root is responsible for maintaining invariants for the entire aggregate
   - All modifications to the aggregate must go through the root
   - Not all entities are aggregate roots, but all aggregate roots are entities

2. **Why should transactions not cross aggregate boundaries?**
   - Crossing boundaries creates long-running transactions that lock multiple aggregates
   - Reduces scalability and increases contention
   - Makes it difficult to distribute the system (microservices)
   - Eventual consistency via domain events is usually sufficient
   - Only use multi-aggregate transactions when absolutely necessary for business requirements

3. **How do you reference other aggregates from within an aggregate?**
   - By ID only, never by direct object reference
   - Example: `Order` has `CustomerId`, not `Customer` object
   - If you need data from another aggregate, load it separately in the application service
   - This enforces loose coupling and clear boundaries

4. **What are the key invariants your aggregate must protect?**
   - Business rules that must always be true
   - Examples: "Order must have at least one line", "Balance cannot be negative"
   - Aggregate root enforces these through method logic
   - Private setters prevent external violation

5. **How do you decide what belongs in an aggregate?**
   - What data must be consistent together? → Include in aggregate
   - What has independent lifecycle? → Separate aggregate
   - Does the collection grow unbounded? → Separate aggregate
   - Would including it cause performance problems? → Separate aggregate

6. **What is the role of domain events in aggregates?**
   - Communicate changes to other aggregates without direct coupling
   - Enable eventual consistency across aggregate boundaries
   - Provide audit trail of what happened
   - Drive reactive workflows (sagas, process managers)

## Key Takeaways

1. **Aggregates are consistency boundaries** - They define what must be consistent in a single transaction

2. **One aggregate = One transaction** - Don't lock multiple aggregates; use eventual consistency instead

3. **Design small aggregates** - Only include what absolutely must be consistent together

4. **Aggregate root controls access** - All modifications go through the root; no direct access to internal entities

5. **Reference by ID, not by object** - Aggregates reference each other by identity, maintaining loose coupling

6. **Protect invariants** - The aggregate root's job is to ensure business rules are never violated

7. **Private setters are your friend** - Prevent external code from bypassing business logic

8. **Domain events for coordination** - Use events to update other aggregates, not direct calls

9. **Repositories work at aggregate level** - Load and save complete aggregates, not internal parts

10. **Keep it practical** - Don't over-engineer; start simple and refactor as you learn the domain
