# Lesson 1: Strategy and Template Method Patterns

## Learning Objectives
- Implement Strategy pattern for algorithm selection
- Use Template Method for algorithmic skeletons
- Apply these patterns in business logic scenarios
- Choose between Strategy and Template Method appropriately
- Combine both patterns when beneficial

---

## Introduction

Strategy and Template Method are behavioral patterns that define how algorithms are structured and selected. Strategy encapsulates algorithms in separate classes making them interchangeable at runtime, while Template Method defines the skeleton of an algorithm in a base class, allowing subclasses to override specific steps without changing the algorithm's structure.

Both patterns promote code reuse and adherence to the Open-Closed Principle, but they achieve this through different mechanisms—composition vs inheritance.

## Key Concepts Summary

### Strategy Pattern

**Problem:** Different algorithms that need to be selected at runtime

```csharp
// Without Strategy - rigid and hard to extend
public class PaymentProcessor
{
    public void ProcessPayment(decimal amount, string paymentType)
    {
        if (paymentType == "CreditCard")
        {
            // Credit card logic
        }
        else if (paymentType == "PayPal")
        {
            // PayPal logic
        }
        else if (paymentType == "Crypto")
        {
            // Crypto logic
        }
    }
}
```

**Solution: Strategy Pattern**

```csharp
// Strategy interface
public interface IPaymentStrategy
{
    Task<PaymentResult> ProcessPayment(decimal amount);
    bool CanProcess(PaymentMethod method);
}

// Concrete strategies
public class CreditCardStrategy : IPaymentStrategy
{
    private readonly ICreditCardGateway _gateway;
    
    public CreditCardStrategy(ICreditCardGateway gateway)
    {
        _gateway = gateway;
    }
    
    public async Task<PaymentResult> ProcessPayment(decimal amount)
    {
        var result = await _gateway.Charge(amount);
        return new PaymentResult 
        { 
            Success = result.Success,
            TransactionId = result.Id
        };
    }
    
    public bool CanProcess(PaymentMethod method) 
        => method == PaymentMethod.CreditCard;
}

public class PayPalStrategy : IPaymentStrategy
{
    private readonly IPayPalService _paypal;
    
    public PayPalStrategy(IPayPalService paypal)
    {
        _paypal = paypal;
    }
    
    public async Task<PaymentResult> ProcessPayment(decimal amount)
    {
        var result = await _paypal.ProcessTransaction(amount);
        return new PaymentResult 
        { 
            Success = result.IsSuccessful,
            TransactionId = result.TransactionId
        };
    }
    
    public bool CanProcess(PaymentMethod method) 
        => method == PaymentMethod.PayPal;
}

// Context
public class PaymentService
{
    private readonly IEnumerable<IPaymentStrategy> _strategies;
    
    public PaymentService(IEnumerable<IPaymentStrategy> strategies)
    {
        _strategies = strategies;
    }
    
    public async Task<PaymentResult> ProcessPayment(
        decimal amount, 
        PaymentMethod method)
    {
        var strategy = _strategies.FirstOrDefault(s => s.CanProcess(method))
            ?? throw new InvalidOperationException($"No strategy for {method}");
        
        return await strategy.ProcessPayment(amount);
    }
}

// Registration
services.AddScoped<IPaymentStrategy, CreditCardStrategy>();
services.AddScoped<IPaymentStrategy, PayPalStrategy>();
services.AddScoped<IPaymentStrategy, CryptoStrategy>();
services.AddScoped<PaymentService>();
```

### Real-World Strategy: Sorting Algorithms

```csharp
public interface ISortStrategy<T>
{
    IEnumerable<T> Sort(IEnumerable<T> items);
}

public class QuickSortStrategy<T> : ISortStrategy<T> where T : IComparable<T>
{
    public IEnumerable<T> Sort(IEnumerable<T> items)
    {
        // QuickSort implementation
        return items.OrderBy(x => x);
    }
}

public class BubbleSortStrategy<T> : ISortStrategy<T> where T : IComparable<T>
{
    public IEnumerable<T> Sort(IEnumerable<T> items)
    {
        // BubbleSort implementation
        return items.OrderBy(x => x);
    }
}

public class DataProcessor<T> where T : IComparable<T>
{
    private ISortStrategy<T> _sortStrategy;
    
    public void SetSortStrategy(ISortStrategy<T> strategy)
    {
        _sortStrategy = strategy;
    }
    
    public IEnumerable<T> ProcessData(IEnumerable<T> data)
    {
        return _sortStrategy.Sort(data);
    }
}
```

### Template Method Pattern

**Problem:** Algorithm steps are similar but some vary

```csharp
// Template Method - defines skeleton
public abstract class DataImporter
{
    // Template method - defines algorithm structure
    public async Task<ImportResult> ImportData(string source)
    {
        try
        {
            ValidateSource(source);           // Common
            var data = await ReadData(source); // Varies by type
            var validated = ValidateData(data); // Common
            var transformed = Transform(validated); // Varies by type
            await SaveData(transformed);       // Common
            
            return ImportResult.Success();
        }
        catch (Exception ex)
        {
            HandleError(ex);                  // Common
            return ImportResult.Failure(ex.Message);
        }
    }
    
    // Common steps
    private void ValidateSource(string source)
    {
        if (string.IsNullOrEmpty(source))
            throw new ArgumentException("Source cannot be empty");
    }
    
    private IEnumerable<DataRow> ValidateData(RawData data)
    {
        return data.Rows.Where(r => !string.IsNullOrEmpty(r.Id));
    }
    
    private async Task SaveData(IEnumerable<DataRow> data)
    {
        // Save to database
    }
    
    private void HandleError(Exception ex)
    {
        // Log error
    }
    
    // Abstract steps - must be implemented by subclasses
    protected abstract Task<RawData> ReadData(string source);
    protected abstract IEnumerable<DataRow> Transform(IEnumerable<DataRow> data);
}

// Concrete implementations
public class CsvDataImporter : DataImporter
{
    protected override async Task<RawData> ReadData(string source)
    {
        var lines = await File.ReadAllLinesAsync(source);
        return new RawData 
        { 
            Rows = lines.Select(l => ParseCsvLine(l)).ToList() 
        };
    }
    
    protected override IEnumerable<DataRow> Transform(IEnumerable<DataRow> data)
    {
        return data.Select(row => new DataRow
        {
            Id = row.Id,
            Name = row.Name.Trim().ToUpper()
        });
    }
}

public class JsonDataImporter : DataImporter
{
    protected override async Task<RawData> ReadData(string source)
    {
        var json = await File.ReadAllTextAsync(source);
        return JsonSerializer.Deserialize<RawData>(json);
    }
    
    protected override IEnumerable<DataRow> Transform(IEnumerable<DataRow> data)
    {
        return data.Select(row => new DataRow
        {
            Id = row.Id,
            Name = row.Name // JSON names are already clean
        });
    }
}

// Usage
DataImporter importer = new CsvDataImporter();
var result = await importer.ImportData("data.csv");
```

### Template Method with Hook Methods

```csharp
// Template with optional hooks
public abstract class ReportGenerator
{
    // Template method
    public async Task<Report> GenerateReport(ReportRequest request)
    {
        ValidateRequest(request);
        
        // Hook - can be overridden but has default behavior
        if (ShouldGenerateTableOfContents())
        {
            await GenerateTableOfContents();
        }
        
        var data = await FetchData(request);
        var processed = ProcessData(data);
        var formatted = FormatReport(processed);
        
        // Hook
        await OnReportCompleted(formatted);
        
        return formatted;
    }
    
    // Concrete methods - same for all subclasses
    private void ValidateRequest(ReportRequest request)
    {
        if (request == null)
            throw new ArgumentNullException(nameof(request));
    }
    
    // Abstract methods - must be implemented
    protected abstract Task<RawData> FetchData(ReportRequest request);
    protected abstract ProcessedData ProcessData(RawData data);
    protected abstract Report FormatReport(ProcessedData data);
    
    // Hook methods - optional to override
    protected virtual bool ShouldGenerateTableOfContents() => false;
    protected virtual Task GenerateTableOfContents() => Task.CompletedTask;
    protected virtual Task OnReportCompleted(Report report) => Task.CompletedTask;
}

// Concrete implementation
public class FinancialReportGenerator : ReportGenerator
{
    private readonly IFinancialDataService _dataService;
    
    public FinancialReportGenerator(IFinancialDataService dataService)
    {
        _dataService = dataService;
    }
    
    protected override async Task<RawData> FetchData(ReportRequest request)
    {
        return await _dataService.GetFinancialData(
            request.StartDate,
            request.EndDate);
    }
    
    protected override ProcessedData ProcessData(RawData data)
    {
        // Financial-specific processing
        return new ProcessedData
        {
            TotalRevenue = data.Transactions.Sum(t => t.Amount),
            AverageTransaction = data.Transactions.Average(t => t.Amount)
        };
    }
    
    protected override Report FormatReport(ProcessedData data)
    {
        return new Report
        {
            Title = "Financial Report",
            Sections = new[]
            {
                new Section("Revenue", $"${data.TotalRevenue:N2}"),
                new Section("Avg Transaction", $"${data.AverageTransaction:N2}")
            }
        };
    }
    
    // Override hook to enable TOC
    protected override bool ShouldGenerateTableOfContents() => true;
    
    // Override hook to send notification
    protected override async Task OnReportCompleted(Report report)
    {
        // Send notification that report is ready
        await Task.CompletedTask;
    }
}
```

### Advanced Strategy: Strategy Factory Pattern

```csharp
// Strategy factory for complex selection logic
public interface IShippingStrategy
{
    decimal Calculate(Order order);
    bool CanHandle(ShippingMethod method, Order order);
}

public class ShippingStrategyFactory
{
    private readonly IEnumerable<IShippingStrategy> _strategies;
    
    public ShippingStrategyFactory(IEnumerable<IShippingStrategy> strategies)
    {
        _strategies = strategies;
    }
    
    public IShippingStrategy GetStrategy(ShippingMethod method, Order order)
    {
        var strategy = _strategies.FirstOrDefault(s => s.CanHandle(method, order));
        
        if (strategy == null)
            throw new InvalidOperationException(
                $"No shipping strategy found for {method}");
        
        return strategy;
    }
}

// DI registration
services.AddScoped<IShippingStrategy, StandardShippingStrategy>();
services.AddScoped<IShippingStrategy, ExpressShippingStrategy>();
services.AddScoped<ShippingStrategyFactory>();
```

### Strategy Pattern with Async Operations

```csharp
public interface INotificationStrategy
{
    Task<NotificationResult> SendAsync(NotificationMessage message);
}

public class FallbackNotificationStrategy : INotificationStrategy
{
    private readonly IEnumerable<INotificationStrategy> _strategies;
    
    public async Task<NotificationResult> SendAsync(NotificationMessage message)
    {
        foreach (var strategy in _strategies)
        {
            var result = await strategy.SendAsync(message);
            if (result.Success)
                return result;
        }
        
        return NotificationResult.Failure("All strategies failed");
    }
}
```

### Combining Strategy and Template Method

```csharp
// Template Method for workflow structure
public abstract class OrderProcessingWorkflow
{
    protected IPaymentStrategy _paymentStrategy;
    
    // Template method
    public async Task<ProcessingResult> ProcessOrder(Order order)
    {
        try
        {
            await ValidateOrder(order);
            
            var paymentResult = await _paymentStrategy.ProcessPayment(
                order.TotalAmount,
                order.PaymentMethod);
            
            if (!paymentResult.Success)
                return ProcessingResult.Failure("Payment failed");
            
            await ReserveInventory(order);
            await CreateShipment(order);
            await SendConfirmation(order);
            
            return ProcessingResult.Success(order.Id);
        }
        catch (Exception ex)
        {
            await HandleError(order, ex);
            return ProcessingResult.Failure(ex.Message);
        }
    }
    
    // Common steps
    private async Task ValidateOrder(Order order)
    {
        if (order.Items.Count == 0)
            throw new InvalidOperationException("Order has no items");
    }
    
    private async Task SendConfirmation(Order order)
    {
        // Send email confirmation
        await Task.CompletedTask;
    }
    
    // Abstract steps - vary by order type
    protected abstract Task ReserveInventory(Order order);
    protected abstract Task CreateShipment(Order order);
    protected abstract Task HandleError(Order order, Exception ex);
}

// Concrete workflow for retail orders
public class RetailOrderWorkflow : OrderProcessingWorkflow
{
    private readonly IInventoryService _inventory;
    private readonly IShippingService _shipping;
    
    public RetailOrderWorkflow(
        IPaymentStrategy paymentStrategy,
        IInventoryService inventory,
        IShippingService shipping)
    {
        _paymentStrategy = paymentStrategy;
        _inventory = inventory;
        _shipping = shipping;
    }
    
    protected override async Task ReserveInventory(Order order)
    {
        foreach (var item in order.Items)
        {
            await _inventory.ReserveAsync(item.ProductId, item.Quantity);
        }
    }
    
    protected override async Task CreateShipment(Order order)
    {
        await _shipping.CreateShipmentAsync(order);
    }
    
    protected override async Task HandleError(Order order, Exception ex)
    {
        // Release inventory reservations
        await _inventory.ReleaseReservationsAsync(order.Id);
    }
}

// Concrete workflow for digital orders
public class DigitalOrderWorkflow : OrderProcessingWorkflow
{
    private readonly ILicenseService _licenseService;
    
    public DigitalOrderWorkflow(
        IPaymentStrategy paymentStrategy,
        ILicenseService licenseService)
    {
        _paymentStrategy = paymentStrategy;
        _licenseService = licenseService;
    }
    
    protected override async Task ReserveInventory(Order order)
    {
        // Digital products don't need inventory reservation
        await Task.CompletedTask;
    }
    
    protected override async Task CreateShipment(Order order)
    {
        // Generate and send license keys instead of physical shipment
        foreach (var item in order.Items)
        {
            await _licenseService.GenerateLicenseAsync(item.ProductId, order.CustomerId);
        }
    }
    
    protected override async Task HandleError(Order order, Exception ex)
    {
        // Revoke any generated licenses
        await _licenseService.RevokeLicensesAsync(order.Id);
    }
}
```

### Real-World Example: Export Strategy

```csharp
public interface IExportStrategy
{
    Task<byte[]> ExportAsync<T>(IEnumerable<T> data);
    string ContentType { get; }
}

public class CsvExportStrategy : IExportStrategy
{
    public string ContentType => "text/csv";
    
    public async Task<byte[]> ExportAsync<T>(IEnumerable<T> data)
    {
        // CSV export logic
        using var memoryStream = new MemoryStream();
        using var writer = new StreamWriter(memoryStream);
        using var csv = new CsvWriter(writer, CultureInfo.InvariantCulture);
        await csv.WriteRecordsAsync(data);
        return memoryStream.ToArray();
    }
}

public class ExportService
{
    private readonly IEnumerable<IExportStrategy> _strategies;
    
    public async Task<ExportResult> ExportAsync<T>(
        IEnumerable<T> data,
        ExportFormat format)
    {
        var strategy = GetStrategy(format);
        var bytes = await strategy.ExportAsync(data);
        
        return new ExportResult
        {
            Data = bytes,
            ContentType = strategy.ContentType
        };
    }
}
```

### Strategy vs Template Method

| Aspect | Strategy | Template Method |
|--------|----------|-----------------|
| **Structure** | Composition | Inheritance |
| **Flexibility** | Change algorithm at runtime | Fixed at compile time |
| **Coupling** | Loose (interface-based) | Tight (inheritance) |
| **Algorithm location** | Separate classes | Base class + subclasses |
| **When to use** | Multiple algorithms, runtime selection | Fixed structure, varying steps |
| **Testing** | Easy to test in isolation | Harder to test (inheritance) |
| **Dependencies** | Can inject via constructor | Limited to what base class provides |

```csharp
public abstract class DataImporter

    {
        ValidateSource(source);
        await OpenConnection(source);
        
        var rawData = await ReadData(source);      // Abstract
        var transformed = TransformData(rawData);  // Abstract

        await CloseConnection();

    protected abstract TransformedData TransformData(RawData data);
    protected virtual Task OnImportCompleted() => Task.CompletedTask;
```

```csharp
public class PricingService
```

## Common Pitfalls

**1. Strategy Explosion**
```csharp
// BAD - Too many strategies
public class MondayShippingStrategy : IShippingStrategy { }
public class TuesdayShippingStrategy : IShippingStrategy { }

// GOOD - Parameterize
public class WeekdayShippingStrategy : IShippingStrategy
{
    private readonly DayOfWeek _dayOfWeek;
}
```

**2. Breaking Template Structure**
```csharp
// BAD - Subclass changes expected behavior
public class BrokenProcessor : DataProcessor
{
    public override void Process()
    {
        // Doesn't call base.Process()!
        DoCustomThing();
    }
}
```

## Self-Check Questions

1. **When should you choose Strategy over Template Method?**
   - Use Strategy when: algorithms need to change at runtime, prefer composition over inheritance, need to test algorithms in isolation
   - Use Template Method when: have a fixed algorithm structure, variations are in specific steps, inheritance is acceptable

2. **Can Strategy and Template Method be combined? How?**
   - Yes! Template Method can use Strategy for specific steps that need runtime selection
   - Example: Template defines workflow, Strategy handles payment/shipping selection

3. **How does Strategy support the Open-Closed Principle?**
   - New strategies can be added without modifying existing code
   - Context (service) doesn't change when adding strategies
   - Strategies are closed for modification, open for extension

4. **What are the downsides of Template Method?**
   - Tight coupling through inheritance
   - Can't change template structure at runtime
   - May violate Single Responsibility if template has too many responsibilities
   - Subclasses are coupled to parent's implementation details

5. **How do you make strategies testable?**
   - Each strategy implements same interface - test in isolation
   - Mock dependencies injected into strategies
   - Test context/service with mock strategies
   - Test strategy selection logic separately

6. **What's the difference between Template Method and Strategy?**
   - Template Method: inheritance-based, compile-time binding, algorithm structure in base class
   - Strategy: composition-based, runtime binding, algorithm in separate classes

---

## Key Takeaways

1. **Strategy Pattern** encapsulates algorithms in separate classes, enabling runtime selection through composition
2. **Template Method** defines algorithm skeleton in base class, allowing subclasses to override specific steps
3. Strategy promotes **loose coupling** and testability through interfaces
4. Template Method provides **code reuse** but creates inheritance coupling
5. **Hooks** in Template Method allow optional customization without requiring subclass implementation
6. Both patterns support the **Open-Closed Principle** in different ways
7. Consider **combining** both patterns: Template for structure, Strategy for variable steps
8. Prefer Strategy when **flexibility** is important, Template when structure is stable
